Depth-First Search (DFS)

AI Search - Complete Guide for 20/20 Exam

DFS Algorithm

Depth-first search expands the deepest unexpanded node first. It uses a LIFO stack so that the most recently added node is expanded next, following one branch as deep as possible before backtracking.

function DFS(problem) returns solution or failure
fringe ← Stack(Make-Node(Initial-State[problem]))
loop do
if Empty?(fringe) then return failure
node ← Pop(fringe)
if Goal-Test[problem](State[node]) then return Solution(node)
fringe ← Push-All(Expand(node, problem), fringe)
Stack Behavior:
Last In, First Out (LIFO)
New children are pushed onto the top of the stack. The topmost child is always popped next, causing deep exploration before breadth.

Time and Space Complexity

DFS only needs to store the current path from root to the current node plus the siblings of nodes on that path. This makes it memory-efficient compared to BFS.

Time Complexity:
O(b^m)
m = maximum depth of the search tree. In the worst case, DFS explores every node in the entire tree.
Space Complexity:
O(b * m)
Only the current path (length m) plus siblings at each level need to be stored. For b = 10 and m = 12, this is only 120 nodes.
Example - Memory Savings

For the same problem where BFS needs 10 petabytes at depth 8, DFS needs only b*m = 10*8 = 80 nodes. This is why DFS is called "space-efficient" despite its poor worst-case time.

Properties

Property DFS
Complete? No - can loop forever on infinite paths
Optimal? No - finds first goal encountered, not cheapest
Time Complexity O(b^m)
Space Complexity O(b*m)
Queue Type LIFO Stack
Major Flaws: DFS can get stuck going down an infinite path while a shallow goal exists nearby. It is neither complete nor optimal in the general case. In state spaces with cycles, DFS loops forever without repeated-state detection.
When It Works: DFS is useful when the maximum depth m is known and much smaller than the solution depth, or when memory is severely constrained.

Worked Examples

Example 1 - Binary Tree Search

Root S has children A, B. DFS pops B first (LIFO), then explores B's children before ever visiting A. If the goal is A, DFS explores the entire right subtree first, wasting time.

Lesson: DFS order depends entirely on child ordering. Bad ordering can lead to exploring huge irrelevant subtrees.

Example 2 - Romania Problem

From Arad, DFS might go Arad → Sibiu → Oradea → ... deep into the northwest branch before considering the route toward Bucharest via Fagaras.

Example 3 - Infinite Branch

If a state has an action that generates a child with the same state (cycle), and cycle detection is absent, DFS will loop forever. Example: State A with action "stay" producing state A again.

Example 4 - Space Advantage

On a tree with b=1000 and m=20, BFS needs 1000^20 nodes in memory. DFS needs only 1000*20 = 20,000 nodes. When memory is the bottleneck, DFS can explore deeper than BFS.
