Syntax and Semantics

Every logic has two fundamental components: syntax defines what sentences are well-formed, and semantics defines what those sentences mean — specifically, their truth in each possible world.

Syntax
The rules for constructing legal sentences in the language. Example: "x + 2 = y" is well-formed in arithmetic; "x2+ = y" is not.
Semantics
The rules for determining the truth of a sentence in each possible world. Example: "x + 2 = y" is true when x=2, y=4, but false when x=1, y=1.
Formal Definition
A logic = (Syntax, Semantics)
Syntax defines the set of well-formed sentences. Semantics defines the truth value of each sentence in each possible world (model).

Model

A model is a possible world — an abstract mathematical entity that assigns truth values to every propositional atom. In propositional logic, a model is simply an assignment of True or False to each propositional symbol.

Model Count
Number of models = 2n
Where n is the number of distinct propositional symbols. Each symbol can be True or False independently.
Example: Models for Two Symbols

With symbols P and Q, there are 2² = 4 possible models:

ModelPQ
m₁TrueTrue
m₂TrueFalse
m₃FalseTrue
m₄FalseFalse

Important Distinction

A "model" in logic has two related meanings:

  • Model as world: A possible world — an assignment of truth values to symbols (e.g., x=2, y=2 makes x+y=4 true)
  • Model of a sentence: "m is a model of sentence α" means α is true in world m

The term is related to constraint satisfaction (Chapter 3) — constraint languages are logics, and constraint solving is a form of logical inference.

Entailment (استلزام)

Entailment is the relationship between sentences such that one sentence follows logically from another. If sentence α entails sentence β, then whenever α is true, β must also be true.

Definition of Entailment
α ⊧ β iff in every model where α is true, β is also true
"α entails β" means α is a logical consequence that β is true. The truth of β is "contained within" the truth of α.

The Haystack and Needle Analogy

Analogy: Finding a Needle in a Haystack

The Knowledge Base (KB) is the haystack. The query α is the needle.

KB ⊧ α means: if we search through the haystack (all models where KB is true), we will find the needle (α is true in all those models).

For a finite haystack, systematic search can determine if the needle exists. But for most real KBs, the "haystack" of possible models is infinite — so a complete inference procedure is crucial.

Entailment in Wumpus World

Example: Pit Entailment

Consider the situation from the Wumpus World walkthrough. The agent has been to [1,1] (no percept) and [2,1] (breeze).

KB:

  • ¬Breeze₁,₁
  • Breeze₂,₁
  • Rules: Breeze₁,₁ ⇔ (Pit₁,₂ ∨ Pit₂,₁)
  • Rules: Breeze₂,₁ ⇔ (Pit₁,₁ ∨ Pit₂,₂ ∨ Pit₃,₁)

Query: Does KB ⊧ Pit₁,₂? (Is there a pit in [1,2]?)

Consider all models where KB is true (8 possible pit configurations for squares [1,2], [2,2], [3,1]). In all of them, Pit₁,₂ = False. So KB ⊧ ¬Pit₁,₂.

Query: Does KB ⊧ Pit₂,₂? (Is there a pit in [2,2]?)

Pit₂,₂ is True in some models and False in others. So KB ⊭ Pit₂,₂ (KB does NOT entail Pit₂,₂).

The agent knows [1,2] is safe but is uncertain about [2,2].

Key Entailment Properties

PropertyDefinitionExample
KB ⊧ α KB entails α — α is true in all models where KB is true (P ∧ Q) ⊧ P
KB ⊭ α KB does NOT entail α — there is at least one model where KB is true but α is false (P ∨ Q) ⊭ P (when P=False, Q=True)
α ≡ β α and β are logically equivalent — same set of models (P ∧ Q) ≡ (Q ∧ P)
Satisfiability A sentence is satisfiable if it is true in at least one model P ∧ ¬Q is satisfiable (m₂)
Validity A sentence is valid if it is true in ALL models (a tautology) P ∨ ¬P is valid

Inference

Inference is the process of deriving new sentences from existing ones. An inference algorithm implements this process — it takes KB as input and produces new sentences as output.

Relationship Between Entailment and Inference
Inference Algorithm i is sound if: KB ⊢i α ⇒ KB ⊧ α
Inference Algorithm i is complete if: KB ⊧ α ⇒ KB ⊢i α
⊢ means "derives" (syntactic symbol manipulation), ⊧ means "entails" (semantic truth relationship)

Soundness vs Completeness

PropertyDefinitionIntuitionConsequence if violated
Sound Everything derived is entailed Never lies — only produces true conclusions Invention of false "needles" that don't exist
Complete Everything entailed can be derived Never misses a true conclusion Missing true consequences — incomplete reasoning

Model Checking

Model checking is the simplest inference algorithm: enumerate all possible models and check whether α is true in all models where KB is true.

Model Checking Algorithm (TT-Entails)
function TT-Entails(KB, α) returns true or false symbols = list of propositional symbols in KB and α return TT-Check-All(KB, α, symbols, {}) function TT-Check-All(KB, α, symbols, model) if empty(symbols) then if PL-True(KB, model) then return PL-True(α, model) else return true // KB false in this model → irrelevant else P = First(symbols) rest = Rest(symbols) return TT-Check-All(KB, α, rest, model ∪ {P=true}) AND TT-Check-All(KB, α, rest, model ∪ {P=false})
Model checking is sound and complete for finite model spaces, but has O(2n) worst-case time.
Example: Model Checking for Wumpus World

With 7 relevant propositional symbols (B₁,₁, B₁,₂, P₁,₁, P₁,₂, P₂,₁, P₂,₂, P₃,₁), there are 2⁷ = 128 possible models.

KB (from the [1,1] and [2,1] visits) is true in only 3 of these 128 models (see Figure 6-9).

Checking P₁,₂ (pit in [1,2]): in all 3 models where KB is true, P₁,₂ is False → KB ⊧ ¬P₁,₂ ✓

Checking P₂,₂ (pit in [2,2]): in 2 of the 3 models, P₂,₂ is True; in 1 model it's False → KB ⊭ P₂,₂ and KB ⊭ ¬P₂,₂

Model checking confirms: [1,2] is safe, but [2,2] is uncertain.

Limitation: Model checking works only when the model space is finite. In arithmetic (e.g., x + y = 4), the model space is infinite (all pairs of integers). Complete inference on infinite domains requires more sophisticated methods.

Grounding

Grounding refers to the connection between the agent's logical reasoning processes and the real environment in which the agent operates. How do we know that the sentences in the KB correctly represent the real world?

Grounding Principle
Sensor → Sentence → Knowledge Base → Inference → Action
Sensors provide the bridge: when a sensor detects something, the agent creates a corresponding sentence. The truth of that sentence in the KB corresponds to truth in the real world.

How Grounding Works

Example: Wumpus World Grounding

Real world event: Stench molecules reach the agent's sensor at location [1,2].

Sensor: Stench detector outputs True.

Sentence: The agent creates the sentence Stench₁,₂ and TELLs it to the KB.

Grounding: The sentence Stench₁,₂ is "grounded" because it was produced by a causal chain from the actual environment through the sensor.

When the agent later reasons: "Stench₁,₂ ⇒ Wumpus₁,₃ ∨ Wumpus₂,₂ ∨ Wumpus₁,₁", the conclusion is grounded because the premise was grounded.

Grounding Diagram

The Correspondence Chain
Real World ──sensor──> Percept ──TELL──> KB Sentence ↑ │ │ │ inference │ ▼ Action <──execution── Decision <──ASK── Derived Sentence
If KB is true in the real world, sound inference guarantees derived sentences are also true in the real world.
Key Insight: Grounding is why logical reasoning works for AI agents. Without it, the KB would be a disconnected symbol system with no relationship to reality. The sensors (and the program that constructs sentences from sensor readings) provide this essential connection.

Worked Examples

Example 1: Arithmetic Entailment

Given: α = "x + y = 4" and β = "y = 4 - x"

Question: Does α ⊧ β?

Analysis: In every model where x + y = 4 (e.g., x=1,y=3; x=2,y=2; x=0,y=4; etc.), we can algebraically derive y = 4 - x. So yes, α ⊧ β.

Note: The model space is infinite here (all integer pairs). Model checking would not terminate, but algebraic reasoning can prove entailment.

Answer: Yes, x + y = 4 ⊧ y = 4 - x

Example 2: Propositional Entailment

Given: KB = {(P ⇒ Q), P}

Question: Does KB ⊧ Q?

Truth table:

PQP ⇒ QKB
TrueTrueTrue✓
TrueFalseFalse✗
FalseTrueTrue✗
FalseFalseTrue✗

KB is true only in model {P=True, Q=True}. In this model, Q is True. Therefore, KB ⊧ Q.

Answer: Yes, (P ⇒ Q) ∧ P ⊧ Q (Modus Ponens)

Example 3: Non-Entailment

Given: KB = {(P ∨ Q)}

Question: Does KB ⊧ P?

Analysis: Consider the model m = {P=False, Q=True}. In m, P ∨ Q = True ∨ False = True, so KB is true. But P is False. Since there exists a model where KB is true and P is false, KB does NOT entail P.

Answer: No, (P ∨ Q) ⊭ P

Example 4: KB as Conjunction

Given: KB contains two sentences: "It is raining" (R) and "If it is raining, the ground is wet" (R ⇒ W).

KB as conjunction: KB = R ∧ (R ⇒ W)

Question: Does KB ⊧ W?

Analysis: In any model where R is True and R ⇒ W is True, we must have W = True (by the truth table of implication). So KB ⊧ W.

Answer: Yes, from "raining" and "rain ⇒ wet ground", we can conclude "ground is wet".

Example 5: Soundness in Action

Scenario: A medical diagnosis KB contains: "If patient has fever AND rash, consider measles" (F ∧ R ⇒ M).

KB: (F ∧ R ⇒ M), F (patient has fever), R (patient has rash)

Sound inference: Using Modus Ponens: from (F ∧ R) and (F ∧ R ⇒ M), we derive M.

Grounding: The sentences F and R were TELL'd based on thermometer and visual inspection sensors. The derived sentence M is grounded through this chain.

What if inference were unsound? An unsound algorithm might conclude M even when F or R is false — inventing a "needle" that doesn't exist (false diagnosis).

Sound inference guarantees: if sensor data is accurate, the diagnosis follows logically.
