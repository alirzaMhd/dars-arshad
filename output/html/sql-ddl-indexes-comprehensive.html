SQL DDL FOR INDEXES

Database Indexing — Complete Guide for 20/20 Exam

Basic CREATE INDEX Syntax

Standard Syntax:
CREATE [UNIQUE] [CLUSTERED | NONCLUSTERED] INDEX index_name ON table_name (column1 [ASC|DESC], column2 [ASC|DESC], ...);
Creates an index on specified columns with optional uniqueness and clustering
-- Simple index CREATE INDEX IX_Employees_Name ON Employees(LastName); -- Unique index CREATE UNIQUE INDEX IX_Employees_Email ON Employees(Email); -- Clustered index CREATE CLUSTERED INDEX IX_Orders_Date ON Orders(OrderDate); -- Nonclustered index CREATE NONCLUSTERED INDEX IX_Products_Category ON Products(CategoryID); -- Descending order CREATE INDEX IX_Logs_Timestamp ON AuditLogs(CreatedAt DESC); -- Composite index CREATE INDEX IX_Orders_Cust_Date ON Orders(CustomerID, OrderDate); -- Multiple columns with mixed order CREATE INDEX IX_Reports ON Sales(Region ASC, Year DESC, Amount ASC);

Index Options

INCLUDE Clause

Add non-key columns to leaf level

• Avoids key lookups

• Creates covering index

Not part of search key

WHERE Clause

Filter rows included in index

• Partial/filtered index

• Smaller index size

Only useful for filtered queries

FILLFACTOR

Percentage of page to fill

• 100 = no free space (default)

• 70-90 =留 space for inserts

Reduces page splits

PAD_INDEX

Apply FILLFACTOR to intermediate pages

• Default OFF (only leaf)

• ON = all pages partially filled

More space, less splits

INCLUDE Example
-- Without INCLUDE (needs key lookup) CREATE INDEX IX_Orders_Cust ON Orders(CustomerID); SELECT CustomerID, OrderDate, Total FROM Orders WHERE CustomerID = 42; -- Index Seek + Key Lookup for OrderDate, Total -- With INCLUDE (covering index) CREATE INDEX IX_Orders_Cust_Cover ON Orders(CustomerID) INCLUDE (OrderDate, Total); SELECT CustomerID, OrderDate, Total FROM Orders WHERE CustomerID = 42; -- Index Seek only, no key lookup!
Filtered Index Example
-- Only index active orders (smaller index) CREATE INDEX IX_Orders_Active ON Orders(CustomerID, OrderDate) WHERE Status = 'Active'; -- Query must match filter for index to be used SELECT * FROM Orders WHERE CustomerID = 42 AND Status = 'Active'; -- Uses filtered index ✓ SELECT * FROM Orders WHERE CustomerID = 42 AND Status = 'Shipped'; -- Cannot use filtered index ✗

UNIQUE Index

Create Unique Index:
CREATE UNIQUE INDEX index_name ON table_name (column1, column2, ...);
Ensures no duplicate values exist in the indexed column(s)
-- Single column unique CREATE UNIQUE INDEX IX_Users_Email ON Users(Email); -- Composite unique CREATE UNIQUE INDEX IX_Users_Name_Birth ON Users(LastName, FirstName, DateOfBirth); -- Unique with ASC/DESC CREATE UNIQUE INDEX IX_Products_SKU ON Products(SKU ASC);
UNIQUE vs PRIMARY KEY: Both enforce uniqueness, but: - PRIMARY KEY automatically creates clustered index (usually) - UNIQUE creates nonclustered by default - Table can have multiple UNIQUE constraints - Table can have only one PRIMARY KEY

UNIQUE Index Examples

Example 1: Email Uniqueness
-- Ensure no duplicate emails CREATE TABLE Users ( UserID INT PRIMARY KEY, Email VARCHAR(100) NOT NULL, Username VARCHAR(50) NOT NULL ); CREATE UNIQUE INDEX IX_Users_Email ON Users(Email); -- This works INSERT INTO Users VALUES (1, 'alice@ex.com', 'alice'); -- This FAILS (duplicate email) INSERT INTO Users VALUES (2, 'alice@ex.com', 'alice2'); -- Error: Duplicate key violation
Example 2: Composite Unique Constraint
-- Ensure unique combination CREATE TABLE Enrollments ( EnrollmentID INT PRIMARY KEY, StudentID INT, CourseID INT, Semester VARCHAR(20) ); CREATE UNIQUE INDEX IX_Enroll_Unique ON Enrollments(StudentID, CourseID, Semester); -- Student can enroll in same course in different semesters INSERT INTO Enrollments VALUES (1, 101, 201, 'Fall2024'); -- OK INSERT INTO Enrollments VALUES (2, 101, 201, 'Spring2025'); -- OK -- But NOT same student, course, AND semester INSERT INTO Enrollments VALUES (3, 101, 201, 'Fall2024'); -- Error: Duplicate key violation
Example 3: UNIQUE with NULL
-- SQL Server: allows one NULL in unique index CREATE TABLE Employees ( EmployeeID INT PRIMARY KEY, BadgeNumber VARCHAR(20) UNIQUE ); INSERT INTO Employees VALUES (1, 'B001'); -- OK INSERT INTO Employees VALUES (2, NULL); -- OK (SQL Server) INSERT INTO Employees VALUES (3, NULL); -- FAILS (SQL Server) -- PostgreSQL: allows multiple NULLs -- MySQL: allows multiple NULLs -- Oracle: allows multiple NULLs -- Note: Behavior varies by database system!

DROP INDEX Syntax

SQL Server:
DROP INDEX table_name.index_name;
Or: DROP INDEX index_name ON table_name;
MySQL:
DROP INDEX index_name ON table_name;
Or ALTER TABLE table_name DROP INDEX index_name;
PostgreSQL:
DROP INDEX index_name;
Schema-qualified: DROP INDEX IF EXISTS schema.index_name;
-- SQL Server DROP INDEX IX_Employees_Email ON Employees; -- MySQL DROP INDEX IX_Employees_Email ON Employees; -- or ALTER TABLE Employees DROP INDEX IX_Employees_Email; -- PostgreSQL DROP INDEX IX_Employees_Email; -- or with safety DROP INDEX IF EXISTS IX_Employees_Email; -- Drop multiple indexes DROP INDEX IX_Emp_Email, IX_Emp_Dept ON Employees; -- MySQL DROP INDEX IX_Emp_Email, IX_Emp_Dept; -- PostgreSQL
Cannot Drop: - PRIMARY KEY index (must drop constraint first) - UNIQUE constraint (must drop constraint first) - Index used by FOREIGN KEY (must drop FK first)

ALTER INDEX (SQL Server)

Rebuild Index:
ALTER INDEX index_name ON table_name REBUILD;
Rebuilds index from scratch, removes fragmentation
Reorganize Index:
ALTER INDEX index_name ON table_name REORGANIZE;
Defragments leaf level, less resource intensive than rebuild
-- Disable index (makes it unusable) ALTER INDEX IX_Employees_Email ON Employees DISABLE; -- Rebuild to re-enable ALTER INDEX IX_Employees_Email ON Employees REBUILD; -- Reorganize (lightweight defrag) ALTER INDEX IX_Employees_Email ON Employees REORGANIZE; -- Rebuild all indexes on table ALTER INDEX ALL ON Employees REBUILD; -- Rebuild with options ALTER INDEX IX_Employees_Email ON Employees REBUILD WITH (FILLFACTOR = 90, SORT_IN_TEMPDB = ON);

Index Naming Conventions

Standard Naming Pattern:
IX_TableName_ColumnName[_ColumnName2]
IX = Index, followed by table and column(s)

Prefix Conventions

IX_ = Standard index

UQ_ = Unique index

PK_ = Primary key

FK_ = Foreign key

Naming Examples

IX_Employees_Email

UQ_Users_Email

IX_Orders_Cust_Date

PK_Employees_ID

Good vs Bad Naming
BAD: CREATE INDEX idx1 ON Employees(Email); CREATE INDEX my_index ON Orders(CustomerID); CREATE INDEX IX_E ON Products(CategoryID); GOOD: CREATE INDEX IX_Employees_Email ON Employees(Email); CREATE INDEX IX_Orders_CustomerID ON Orders(CustomerID); CREATE INDEX IX_Products_CategoryID ON Products(CategoryID); -- Self-documenting, consistent, easy to find

Best Practices

DO

• Index columns in WHERE clauses

• Index FK columns

• Use covering indexes

• Keep indexes narrow

• Monitor unused indexes

DON'T

• Over-index (slow writes)

• Index low-cardinality columns

• Duplicate indexes

• Index rarely-queried columns

• Forget to maintain indexes

Rule of Thumb: Maximum 5-10 indexes per table. Each index speeds reads but slows writes. Find the right balance for your workload.

Complete Database Schema Example

E-Commerce Database with Indexes
-- Customers table CREATE TABLE Customers ( CustomerID INT PRIMARY KEY, -- clustered by default Email VARCHAR(100) NOT NULL, FirstName VARCHAR(50), LastName VARCHAR(50), Phone VARCHAR(20), CreatedAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP ); -- Unique index on email CREATE UNIQUE INDEX UQ_Customers_Email ON Customers(Email); -- Nonclustered for name searches CREATE INDEX IX_Customers_Name ON Customers(LastName, FirstName); -- Nonclustered for phone lookup CREATE INDEX IX_Customers_Phone ON Customers(Phone); -- Products table CREATE TABLE Products ( ProductID INT PRIMARY KEY, SKU VARCHAR(50) NOT NULL, Name VARCHAR(200), CategoryID INT, Price DECIMAL(10,2), Stock INT DEFAULT 0, INDEX IX_Products_Category (CategoryID), UNIQUE INDEX UQ_Products_SKU (SKU), INDEX IX_Products_Price (Price) ); -- Orders table CREATE TABLE Orders ( OrderID INT PRIMARY KEY, CustomerID INT, OrderDate TIMESTAMP, Status VARCHAR(20), TotalAmount DECIMAL(10,2), FOREIGN KEY (CustomerID) REFERENCES Customers(CustomerID) ); -- Clustered index on OrderDate for range queries CREATE CLUSTERED INDEX IX_Orders_Date ON Orders(OrderDate); -- Covering index for customer orders CREATE INDEX IX_Orders_Customer_Cover ON Orders(CustomerID) INCLUDE (OrderDate, TotalAmount, Status); -- Filtered index for active orders CREATE INDEX IX_Orders_Active ON Orders(CustomerID, OrderDate) WHERE Status = 'Active';
