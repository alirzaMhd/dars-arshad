B+ Tree Properties & Formulas

Data Structures — Complete Guide for 20/20 Exam

Parameter Definitions

All B+ Tree properties are expressed in terms of the parameter t (order). Understanding these variables is essential for all formulas.

VariableMeaning
tOrder of the B+ Tree — determines min/max keys per node
nTotal number of keys in the tree
hHeight of the tree (root at height 0)
NTotal number of nodes in the tree
pPage size (disk block size) in bytes
qSize of a key pointer pair in bytes
STotal storage space required in bytes

Node Key Constraints

Root Node (Internal)
1 ≤ keys ≤ 2t
The root is special — it can have as few as 1 key (unlike other internal nodes which need at least t).
Intermediate (Internal) Nodes
t ≤ keys ≤ 2t
Every non-root internal node must have at least t keys and at most 2t keys.
Leaf Nodes
t - 1 ≤ keys ≤ 2t - 1
Each leaf holds between t-1 and 2t-1 keys (data records). Note: leaves have one fewer max key than internal nodes.
Leaf vs Internal — Off by One

Internal nodes: max 2t keys. Leaf nodes: max 2t - 1 keys. This difference exists because leaf keys include data pointers while internal keys are just routing copies.

Node Children Constraints

Root Node Children
2 ≤ children ≤ 2t
A node with k keys has k+1 children. Root has min 1 key → min 2 children.
Intermediate Node Children
t + 1 ≤ children ≤ 2t + 1
A node with t keys has t+1 children (minimum). A node with 2t keys has 2t+1 children (maximum).

Tree Height Formula

The height of a B+ Tree determines how many node accesses are needed for any operation. A shorter tree means fewer disk reads.

h = log_t(⌈(n + 1) / (2t + 1)⌉)
Height h of a B+ Tree with n keys and parameter t. This is the minimum height.
Maximum Height (worst case)
h = ⌈log_t((n+1)/2)⌉
When nodes are minimally filled (t-1 keys per leaf, t keys per internal).
Minimum Height (best case)
h = ⌈log_{2t}((n+1)/2)⌉
When nodes are maximally filled (2t-1 keys per leaf, 2t keys per internal).
Height Formula Convention

Some textbooks define root at height 1, others at height 0. The formulas above use root at height 0 (number of edges from root to deepest leaf).

Why Height Matters

Disk I/O

Each level = 1 disk read

Height 3 → 3 disk reads

Height 2 → 2 disk reads

Search Complexity

Time: O(h) = O(log_t(n))

t越大 → tree shorter → faster

Usually h = 3-4 for millions of keys

Practical Impact

With t=100, height 3 can hold

~2 billion keys!

That's only 3 disk reads

Height Examples

Example 1: Height with t=2, n=7
// t = 2, n = 7 keys h = log_2(⌈(7 + 1) / (2×2 + 1)⌉) h = log_2(⌈8 / 5⌉) h = log_2(⌈1.6⌉) h = log_2(2) h = 1 // Tree has 2 levels: root + leaves
Example 2: Height with t=3, n=50
// t = 3, n = 50 keys h = log_3(⌈(50 + 1) / (2×3 + 1)⌉) h = log_3(⌈51 / 7⌉) h = log_3(⌈7.29⌉) h = log_3(8) h = ln(8) / ln(3) h ≈ 2.096 → h = 3 (ceiling) // Tree has 3 levels: root + intermediate + leaves
Example 3: Height with t=100, n=1,000,000
// t = 100, n = 1,000,000 keys h = log_100(⌈(1,000,000 + 1) / (201)⌉) h = log_100(⌈4975.1⌉) h = log_100(4976) h = ln(4976) / ln(100) h ≈ 1.65 → h = 2 (ceiling) // Only 2 levels for 1 million keys!
Example 4: Minimum Height (max filled)
// t = 2, n = 15, all nodes maximally filled h_min = ⌈log_{2×2}((15+1)/2)⌉ h_min = ⌈log_4(8)⌉ h_min = ⌈1.5⌉ h_min = 2 // 3 levels: root + internal + leaves
Example 5: Maximum Height (min filled)
// t = 2, n = 15, all nodes minimally filled h_max = ⌈log_2((15+1)/2)⌉ h_max = ⌈log_2(8)⌉ h_max = ⌈3⌉ h_max = 3 // 4 levels: root + 2 internal + leaves

Minimum Number of Nodes

The number of nodes N depends on how full each node is. We derive bounds for N based on the node fill constraints.

N ≥ 1 + (n - 1) / (2t - 1)
Minimum number of nodes in a B+ Tree with n keys and parameter t. This occurs when nodes are maximally filled.
Maximum Number of Nodes
N ≤ 1 + (n - 1) / (t - 1)
Maximum number of nodes when nodes are minimally filled. Occurs when leaves have only t-1 keys each.
Derivation: Minimum Nodes
n = keys in leaves = N_leaf × (2t - 1) [max fill] N_leaf = n / (2t - 1) N_internal ≥ N_leaf / (2t) [each internal has max 2t children]
Simplifying gives the formula N ≥ 1 + (n-1)/(2t-1).

Number of Leaf Nodes

Leaf Nodes (minimum)
N_leaf ≥ ⌈n / (2t - 1)⌉
Minimum leaf nodes when each is maximally filled with 2t-1 keys.
Leaf Nodes (maximum)
N_leaf ≤ ⌈n / (t - 1)⌉
Maximum leaf nodes when each has only t-1 keys.
Example: n = 20, t = 3
// Minimum leaf nodes: N_leaf_min = ⌈20 / (2×3 - 1)⌉ = ⌈20/5⌉ = 4 // Maximum leaf nodes: N_leaf_max = ⌈20 / (3 - 1)⌉ = ⌈20/2⌉ = 10 // Minimum total nodes: N_min = 1 + (20 - 1)/(2×3 - 1) = 1 + 19/5 = 1 + 3.8 = 5 (at least 5 nodes)

Fanout and Branching Factor

Maximum Fanout
fanout_max = 2t + 1
Maximum number of children per internal node. Each child pointer takes about log₂(2t+1) bits.
Average Fanout
fanout_avg ≈ n / (n/(2t+1)) = 2t + 1
In a well-filled tree, average fanout approaches maximum.
Higher t → higher fanout → shorter tree → fewer disk I/O. This is why database systems use large t values (typically t = 100-500).

Storage Formula

The total storage space S required for a B+ Tree depends on the page size, key size, and number of nodes.

S = N × ⌈(p - 1) / q⌉ × q
Total storage S in bytes. Each node occupies one page. The ⌈(p-1)/q⌉ term calculates how many keys fit per page.
Keys Per Page
k = ⌊(p - 1) / q⌋
Number of key-pointer pairs that fit in one page of size p bytes, where each pair is q bytes. The -1 accounts for the page header.
Maximum Keys in Tree
n = k × N_leaf
Total keys = keys per leaf × number of leaves. Where k = ⌊(p-1)/q⌋.

Lower Bound on Storage

Combining the minimum node count with the storage formula gives a lower bound on total storage.

S ≥ (p - 1)/p × n × q × (1/(2t) + 1/(2t²))
Lower bound on storage. This shows how storage scales with n, p, q, and t.
Derivation
N ≥ 1 + (n - 1)/(2t - 1) S = N × p S ≥ [1 + (n-1)/(2t-1)] × p S ≈ n × p / (2t - 1) [for large n]
Simplifying with n >> 1 gives the asymptotic bound.

Storage Examples

Example 1: Calculate keys per page
// p = 4096 bytes (4KB page), q = 24 bytes (key + pointer) k = ⌊(4096 - 1) / 24⌋ k = ⌊4095 / 24⌋ k = ⌊170.625⌋ k = 170 keys per page // So t ≈ 170/2 = 85 for this page size
Example 2: Storage for n = 1,000,000 keys
// t = 85, p = 4096, q = 24 k = 170 keys per page // Minimum leaf nodes: N_leaf = ⌈1,000,000 / (2×85 - 1)⌉ = ⌈1,000,000/169⌉ = 5918 // Total storage (leaf nodes only): S_leaf = 5918 × 4096 = 24,239,328 bytes ≈ 24 MB // With internal nodes (~5918/170 ≈ 35 internal nodes): S_total ≈ 24.4 MB
Example 3: Storage lower bound formula
// Using: S ≥ (p-1)/p × n × q × (1/(2t) + 1/(2t²)) // t = 85, n = 1,000,000, p = 4096, q = 24 S ≥ (4095/4096) × 1,000,000 × 24 × (1/170 + 1/170²) S ≥ 0.99976 × 1,000,000 × 24 × (0.005882 + 0.0000346) S ≥ 0.99976 × 1,000,000 × 24 × 0.005917 S ≥ 0.99976 × 142,008 S ≥ 141,974 bytes ≈ 142 KB // Actual storage is larger because of page alignment

Worked Example 1: Complete Analysis (t=2)

Analyze a B+ Tree with t=2 and n=15 keys.

Full Analysis
// Given: t = 2, n = 15 // Step 1: Node constraints Root: min 1 key, max 4 keys Internal: min 2 keys, max 4 keys Leaf: min 1 key, max 3 keys // Step 2: Height h = log_2(⌈(15+1)/(2×2+1)⌉) = log_2(⌈16/5⌉) = log_2(4) = 2 // Step 3: Min leaf nodes N_leaf = ⌈15/(2×2-1)⌉ = ⌈15/3⌉ = 5 // Step 4: Min total nodes N ≥ 1 + (15-1)/(2×2-1) = 1 + 14/3 = 1 + 4.67 = 6 // Step 5: Max leaf nodes N_leaf_max = ⌈15/(2-1)⌉ = 15 (each leaf has only 1 key)

Worked Example 2: Storage Calculation

Calculate storage for a database with 10 million records, p=8KB, q=32 bytes.

Storage Analysis
// Given: n = 10,000,000, p = 8192, q = 32 // Step 1: Keys per page k = ⌊(8192-1)/32⌋ = ⌊8191/32⌋ = 255 keys per page // Step 2: Order t t ≈ k/2 = 127 (approximate, since max leaf = 2t-1 ≈ 255) // Step 3: Minimum leaf nodes N_leaf = ⌈10,000,000/255⌉ = 39,216 leaf pages // Step 4: Total leaf storage S_leaf = 39,216 × 8192 = 321,253,376 bytes ≈ 306 MB // Step 5: Internal nodes (fanout ≈ 256) Level 1: ⌈39,216/256⌉ = 154 nodes Level 0 (root): 1 node Total internal: 155 nodes S_internal = 155 × 8192 = 1,269,760 bytes ≈ 1.2 MB // Step 6: Total storage S_total = 306 + 1.2 = ≈ 307 MB // Height: log_127(⌈(10M+1)/255⌉) = log_127(39216) ≈ 2.2 → h = 3

Worked Example 4: Deletion Rebalancing

After deleting keys, nodes may underflow. Calculate minimum keys after deletion.

Deletion Rules
// Given: t = 3 // If leaf has 2 keys and we delete 1 → underflow (min = t-1 = 2) // Actually 2 - 1 = 1 < 2 → UNDERFLOW! // Fix: borrow from sibling or merge // Borrow (redistribute): // Sibling has 4 keys (≥ t+1 = 4): Before: [A,B] [C,D,E,F] // left leaf underflows After: [A,B,C] [D,E,F] // C moved from right to left // Merge (if sibling also has t keys = 3): Before: [A] [B,C,D] // left has 1 key (< min 2) After: [A,B,C,D] // merge into one leaf // Remove B from parent (it was separating these two)

Worked Example 5: Exam-Style Problem

A B+ Tree has t=4, page size p=512 bytes, key+pointer size q=16 bytes, and 50,000 records. Find: height, number of leaf nodes, total storage.

Solution
// Given: t=4, p=512, q=16, n=50,000 // Step 1: Keys per page k = ⌊(512-1)/16⌋ = ⌊511/16⌋ = 31 // Max leaf keys = 2t-1 = 7 (actual constraint) // But page can hold 31 → use min(31, 2t-1) = 7 // Step 2: Height h = log_4(⌈(50000+1)/9⌉) h = log_4(⌈5555.7⌉) h = log_4(5556) h = ln(5556)/ln(4) h ≈ 6.14 → h = 7 // Step 3: Min leaf nodes N_leaf = ⌈50000/7⌉ = 7,143 // Step 4: Total nodes N ≥ 1 + 49999/7 = 1 + 7142.7 = 7,144 // Step 5: Total storage S = 7144 × 512 = 3,657,728 bytes ≈ 3.5 MB

Quick Reference Card — All Formulas

  • ▸ Root keys: 1 ≤ k ≤ 2t | Internal keys: t ≤ k ≤ 2t | Leaf keys: t-1 ≤ k ≤ 2t-1
  • ▸ Root children: 2 ≤ c ≤ 2t | Internal children: t+1 ≤ c ≤ 2t+1
  • ▸ Height: h = log_t(⌈(n+1)/(2t+1)⌉)
  • ▸ Min nodes: N ≥ 1 + (n-1)/(2t-1)
  • ▸ Max nodes: N ≤ 1 + (n-1)/(t-1)
  • ▸ Leaf nodes: ⌈n/(2t-1)⌉ ≤ N_leaf ≤ ⌈n/(t-1)⌉
  • ▸ Keys per page: k = ⌊(p-1)/q⌋
  • ▸ Storage: S = N × p ≈ n × p / (2t-1)
  • ▸ Search: O(log_t(n)) | Insert: O(log_t(n)) | Delete: O(log_t(n))
  • ▸ Range query: O(log_t(n) + k) where k = results

Exam Tips

1. Always check if the question uses root at height 0 or 1 — formulas differ.

2. Remember: leaf max = 2t-1, internal max = 2t (off by one!).

3. Root is special: min 1 key, min 2 children (not t).

4. Copy Up for leaf splits, Push Up for internal splits.

5. Storage formulas depend on whether you count the root as a separate node.
