DISJOINT SETS (UNION-FIND)

Data Structures — Complete Guide for 20/20 Exam

Disjoint Sets Definition

A disjoint-set data structure (also called union-find) maintains a collection of disjoint dynamic sets. Each set is identified by a representative (usually the root of the tree).

Key Properties:
Each element belongs to exactly one set; sets have no elements in common
Two sets are either identical or disjoint (no partial overlap)

Tree Representation

Each set is represented as a rooted tree. Each node points to its parent. The root is the representative of the set.

Example: Sets {1,3,5} and {2,4,6,7}

Tree 1:       Tree 2:
   3             5
  / \          / | \
 1  5        2  4  6
                    7

Set[1]=3, Set[3]=3 (root), Set[5]=3
Set[2]=5, Set[4]=5, Set[6]=5, Set[7]=6

Array Representation

The standard implementation uses an array where Set[i] stores the parent pointer of element i.

Array Representation:
Set[i] = parent of i (if i is root, Set[i] = i)
Root nodes are identified by Set[i] == i
// For the trees above:
i:    1  2  3  4  5  6  7
Set[i]: 3  5  3  5  3  5  6

// Element 3 and 5 are roots (Set[3]=3, Set[5]=5)
WARNING: Don't confuse Set[i] with "set membership." Set[i] gives the PARENT of i, not which set i belongs to. To find which set i is in, follow parent pointers to the root.

FIND(x)

Returns the representative (root) of the set containing element x. Follows parent pointers until reaching a root.

FIND(x):
  while x != Set[x]:
    x = Set[x]
  return x
Time Complexity:
O(n) worst case (without path compression)
May need to traverse entire chain of parent pointers

UNION(a, b)

Merges the sets containing elements a and b. Makes one root point to the other.

UNION(a, b):
  rootA = FIND(a)
  rootB = FIND(b)
  if rootA != rootB:
    Set[rootA] = rootB
WARNING: Naive union can create very tall trees. Without optimization, a sequence of n unions can produce a tree of height n, making all subsequent finds O(n).

Applications

Connected Components

Find if two nodes are in same connected component of an undirected graph

Kruskal's MST

Check if adding an edge creates a cycle

Equivalence Relations

Maintain equivalence classes as elements are grouped

Union by Rank / Height

Always attach the smaller tree under the root of the larger tree. The rank is an upper bound on the height.

// Initialize:
MAKE-SET(x):
  Set[x] = x
  Rank[x] = 0

UNION(a, b):
  rootA = FIND(a)
  rootB = FIND(b)
  if rootA == rootB: return
  if Rank[rootA] < Rank[rootB]:
    Set[rootA] = rootB
  elif Rank[rootA] > Rank[rootB]:
    Set[rootB] = rootA
  else:
    Set[rootB] = rootA
    Rank[rootA]++
Union by Rank Guarantee:
Tree height is at most O(lg n)
Each union either keeps same rank or increases rank of root by 1. Rank can increase at most lg n times.

Path Compression

During FIND, make every node on the path point directly to the root. This flattens the tree structure.

FIND(x):
  if x != Set[x]:
    Set[x] = FIND(Set[x])  // path compression
  return Set[x]

Before and After Path Compression

BEFORE FIND(7):   AFTER FIND(7):
   1                 1
  / \             / | \
 2  3           2  3  5
 / \           / \
 4  5         4  7
   / \
  6  7

// All nodes 4,5,6,7 now point directly to root 1
WARNING: Path compression is applied only during FIND, not during UNION. After path compression, all nodes on the find path point directly to the root.

Amortized Analysis

With both union by rank and path compression, the amortized cost per operation is essentially constant.

Inverse Ackermann Function:
α(m, n) = min{i ≥ 1 : A(i, 1) ≥ n}
A(i, j) is the Ackermann function. For all practical values, α(m, n) ≤ 4.
Amortized Complexity:
O(α(m, n)) per operation = essentially O(1)
For m operations on n elements, total time is O(m * α(m, n))

Example 1: Sequence of Unions (Naive)

Problem: Perform UNION(1,2), UNION(2,3), UNION(3,4), UNION(4,5) with naive union.

Solution:

Initial: Set = [1,2,3,4,5] (each is its own root)

UNION(1,2): Set[1] = 2. Set = [2,2,3,4,5]

UNION(2,3): Set[2] = 3. Set = [2,3,3,4,5]

UNION(3,4): Set[3] = 4. Set = [2,3,4,4,5]

UNION(4,5): Set[4] = 5. Set = [2,3,4,5,5]

FIND(1) traverses: 1→2→3→4→5. O(n) time!

Without optimization, tree becomes a chain.

Example 2: Union by Rank

Problem: Same unions with union by rank.

Solution:

Initial: Set = [1,2,3,4,5], Rank = [0,0,0,0,0]

UNION(1,2): Rank[1]==Rank[2]==0, so Set[2]=1, Rank[1]++. Set=[1,1,3,4,5]

UNION(2,3): Root(2)=1, Rank[1]=1, Rank[3]=0. Rank[1]>Rank[3], so Set[3]=1. Set=[1,1,1,4,5]

UNION(3,4): Root(3)=1, Rank[1]=1, Rank[4]=0. Set[4]=1. Set=[1,1,1,1,5]

UNION(4,5): Root(4)=1, Rank[1]=1, Rank[5]=0. Set[5]=1. Set=[1,1,1,1,1]

FIND(1) = 1 (O(1)). FIND(5) = 1 (one step). Much better!

Example 3: Path Compression

Problem: After Example 1, perform FIND(1). Show array after path compression.

Solution:

Before FIND: Set = [2,3,4,5,5] (chain: 1→2→3→4→5)

FIND(1): follows 1→2→3→4→5 (root)

Path compression: Set[1]=5, Set[2]=5, Set[3]=5, Set[4]=5

After: Set = [5,5,5,5,5]. All nodes point to root!

Example 4: Complete Operation Sequence

Problem: Process unions and finds with both optimizations.

Start: 8 elements {0,1,2,3,4,5,6,7}, all separate.

UNION(0,1): 0 and 1 both rank 0. Set[1]=0, Rank[0]=1.

UNION(2,3): 2 and 3 both rank 0. Set[3]=2, Rank[2]=1.

UNION(4,5): Set[5]=4, Rank[4]=1.

UNION(6,7): Set[7]=6, Rank[6]=1.

UNION(0,2): Root(0)=0 rank 1, Root(2)=2 rank 1. Set[2]=0, Rank[0]=2.

UNION(4,6): Root(4)=4 rank 1, Root(6)=6 rank 1. Set[6]=4, Rank[4]=2.

UNION(0,4): Root(0)=0 rank 2, Root(4)=4 rank 2. Set[4]=0, Rank[0]=3.

FIND(7): 7→6→4→0 (root). After path compression: Set[7]=0, Set[6]=0, Set[4]=0.

Example 5: Cycle Detection (Kruskal's)

Problem: Using disjoint sets, detect if edges create a cycle.

Edges: (0,1), (2,3), (0,2), (1,3)

UNION(0,1): 0 and 1 now in same set. No cycle.

UNION(2,3): 2 and 3 now in same set. No cycle.

UNION(0,2): FIND(0)!=FIND(2), so merge. No cycle.

Edge (1,3): FIND(1)==FIND(3)? Root(1)=0, Root(3)=0. Yes! CYCLE DETECTED!

If both endpoints are in the same set, adding the edge creates a cycle.
