TREE SORT

BST-Based Sorting Algorithm | Comprehensive Learning Guide

What is Tree Sort?

Tree Sort is a sorting algorithm that uses a Binary Search Tree (BST) as intermediate storage. It works in two phases:

Phase 1: Insertion

Insert all n elements of the input array into a BST one by one.

Phase 2: Traversal

Perform inorder traversal of the BST to retrieve elements in sorted order.

The Algorithm

function treeSort(arr):
  root = null
  for each element x in arr:
    root = BST_insert(root, x)
  sorted = []
  inorder(root, sorted)
  return sorted

function BST_insert(root, key):
  if root == null:
    return new Node(key)
  if key < root.val:
    root.left = BST_insert(root.left, key)
  else:
    root.right = BST_insert(root.right, key)
  return root

function inorder(node, result):
  if node == null: return
  inorder(node.left, result)
  result.append(node.val)
  inorder(node.right, result)

O(n log n)

Time for insertion is O(log n) per element on average. Inorder traversal is always O(n). Total = O(n) insertions × O(log n) each + O(n) traversal = O(n log n) average.

Properties

NOT In-Place

Requires O(n) auxiliary space for tree nodes. Each element is stored in a tree node, so the algorithm cannot sort in-place.

Unstable

BST insertion does not guarantee that equal elements retain their original relative order. The algorithm is not a stable sort.

Why It Works

The BST property ensures that for every node, all values in its left subtree are smaller and all values in its right subtree are larger. An inorder traversal visits nodes in left-root-right order, which naturally produces ascending order.

Inorder Traversal Property
For any BST node N:
  inorder(N.left) → all values < N.val (visited first)
  visit(N) → N.val (visited second)
  inorder(N.right) → all values > N.val (visited third)

This guarantees: left subtree (smaller) → node → right subtree (larger)
Result: ascending sorted order

BST vs AVL Tree: Why It Matters

Plain BSTs are vulnerable to input order. AVL trees are self-balancing and guarantee O(log n) height, eliminating the worst case.

Plain BST

Height: O(n) worst case
Insert: O(n) worst case
Sort worst: O(n²)
Sort avg: O(n log n)
Space: O(n)

Degenerates to a linked list when input is sorted or nearly sorted.

Vulnerable to input order No balancing

AVL Tree

Height: O(log n) guaranteed
Insert: O(log n) guaranteed
Sort worst: O(n log n)
Sort avg: O(n log n)
Space: O(n)

Rotations keep tree balanced. Height never exceeds 1.44 log₂(n).

Input-order independent Self-balancing

The Degenerate BST Problem

When elements are inserted in sorted order into a plain BST, the tree becomes a linked list, making each insertion O(n) instead of O(log n).

Degenerate BST: Inserting [1, 2, 3, 4, 5] into plain BST
1 \ 2 \ 3 \ 4 \ 5

Height = 5 = n. Each insert traverses the entire chain. Total cost: 1+2+3+4+5 = O(n²).

Same Data with AVL: Inserting [1, 2, 3, 4, 5] into AVL tree
2 / \ 1 4 / \ 3 5

Height = 3 ≈ log₂(5). Each insert is O(log n). Total cost: O(n log n).

When to Use Each

Use Plain BST Tree Sort when:
  • Input is known to be random
  • Simplicity is preferred
  • Constant factors matter (AVL has rotation overhead)
  • Learning/educational purposes
Use AVL Tree Sort when:
  • Input may be sorted or nearly sorted
  • Worst-case guarantee is needed
  • Data comes from untrusted source
  • Production/competitive programming

Rotation Cost Detail

AVL trees perform at most 2 rotations per insertion (at most 1 double rotation). Total rotation cost over n insertions is O(n log n) — the same asymptotic as the insertions themselves.

AVL Total Cost
n × O(log n) insertions + n × O(log n) rotations + O(n) traversal = O(n log n)
The rotation overhead is absorbed into the O(n log n) bound.

Example 1: Random Input [5, 3, 7, 1, 4]

Step-by-Step BST Construction
Step 1: Insert 5 → Tree is empty, 5 becomes root.
Step 2: Insert 3 → 3 < 5, goes left. 3 is left child of 5.
Step 3: Insert 7 → 7 > 5, goes right. 7 is right child of 5.
Step 4: Insert 1 → 1 < 5 (left), 1 < 3 (left). 1 is left child of 3.
Step 5: Insert 4 → 4 < 5 (left), 4 > 3 (right). 4 is right child of 3.
Final BST
5 / \ 3 7 / \ 1 4
Inorder Traversal → Sorted Output
inorder(5)
 → inorder(3)
   → inorder(1)
     → inorder(null) → visit 1
   → visit 3
   → inorder(4)
     → inorder(null) → visit 4
 → visit 5
 → inorder(7)
   → inorder(null) → visit 7

Result: [1, 3, 4, 5, 7]

Example 2: Worst-Case Sorted Input [1, 2, 3, 4, 5]

Warning: Sorted input causes a degenerate BST with plain BST tree sort. The tree becomes a right-skewed linked list with height n.
Step-by-Step BST Construction (Degenerate)
Step 1: Insert 1 → 1 becomes root.
Step 2: Insert 2 → 2 > 1 (right). 2 is right child of 1.
Step 3: Insert 3 → 3 > 1 (right), 3 > 2 (right). 3 is right child of 2.
Step 4: Insert 4 → 4 > 1, 4 > 2, 4 > 3. 4 is right child of 3.
Step 5: Insert 5 → 5 > 1, 5 > 2, 5 > 3, 5 > 4. 5 is right child of 4.
Degenerate BST (Linked List)
1 \ 2 \ 3 \ 4 \ 5

Height = 5 = n. Each insertion traverses the entire chain. Insertion cost: 1+2+3+4+5 = 15 = O(n²).

Inorder Traversal → Sorted Output
inorder(1)
 → inorder(null) → visit 1
 → inorder(2)
   → inorder(null) → visit 2
   → inorder(3)
     → inorder(null) → visit 3
     → inorder(4)
       → inorder(null) → visit 4
       → inorder(5)
         → inorder(null) → visit 5

Result: [1, 2, 3, 4, 5] ✓ Sorted
But cost: O(n²) — same as Bubble Sort!
Lesson: Tree sort with plain BST on sorted input is no better than Bubble Sort. Always consider worst-case behavior for BST-based algorithms.

Example 3: Same Sorted Input with AVL Tree [1, 2, 3, 4, 5]

Step-by-Step AVL Construction with Rotations
Step 1: Insert 1 → 1 becomes root. Balanced (height 1).
Step 2: Insert 2 → 2 > 1 (right). No imbalance.
1 \ 2
Step 3: Insert 3 → 3 > 1, 3 > 2. Imbalance at node 1! Left rotation on 1.
2 / \ 1 3
Step 4: Insert 4 → 4 > 2, 4 > 3. No imbalance.
2 / \ 1 3 \ 4
Step 5: Insert 5 → 5 > 2, 5 > 3, 5 > 4. Imbalance at node 2! Left rotation on 3.
2 / \ 1 4 / \ 3 5
Final AVL Tree
2 / \ 1 4 / \ 3 5

Height = 3 ≈ log₂(5). All nodes balanced. Each insertion O(log n). Total: O(n log n) even on sorted input!

Inorder Traversal → Sorted Output
inorder(2)
 → inorder(1) → visit 1
 → visit 2
 → inorder(4)
   → inorder(3) → visit 3
   → visit 4
   → inorder(5) → visit 5

Result: [1, 2, 3, 4, 5] ✓ Sorted
Cost: O(n log n) — rotations kept the tree balanced!

Example 4: Reverse-Sorted Input [5, 4, 3, 2, 1]

Warning: Reverse-sorted input also causes a degenerate BST — a left-skewed linked list.
Degenerate BST (Left-Skewed)
5 / 4 / 3 / 2 / 1

Mirror image of sorted input. Same O(n²) worst case.

AVL Tree Handles This
4 / \ 2 5 / \ 1 3

AVL rotations produce a balanced tree regardless of input order. O(n log n) guaranteed.

Example 5: Duplicates [3, 1, 4, 1, 5, 9, 2, 6]

BST with Duplicates
3 / \ 1 4 \ \ 1 5 \ 9 / \ 2 6

Note: Both 1's exist in the tree but in different positions. BST does not preserve the original order of equal elements → Unstable.

Inorder Traversal
Sorted: [1, 1, 2, 3, 4, 5, 6, 9]
The two 1's are both present, but their relative order from the original array is NOT preserved.
Original: 3, 1, 4, 1, 5, 9, 2, 6
Tree output: 1, 1, 2, 3, 4, 5, 6, 9
(In this case it happens to match, but it's NOT guaranteed.)

Key Takeaways:
1. Tree Sort = BST insert all + inorder traversal
2. Plain BST: O(n log n) average, O(n²) worst case
3. AVL Tree: O(n log n) guaranteed — always prefer in production
4. NOT in-place (needs O(n) tree space) and NOT stable
5. The inorder traversal property of BSTs naturally gives sorted order
