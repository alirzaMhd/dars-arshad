Knowledge-Based Agents

Artificial Intelligence — Logical Agents Chapter (6.1)

What is a Knowledge-Based Agent?

A knowledge-based agent (KB-agent) is an agent that uses a knowledge base (KB) to reason about its environment and decide what actions to take. Unlike reactive agents that follow fixed rules, KB-agents can combine general knowledge with current observations to handle complex, partially observable environments.

Core Definition
KB = {s₁, s₂, ..., sₙ}
A Knowledge Base is a collection of sentences, where each sentence is expressed in a knowledge representation language.

Key Components

Knowledge Base (KB)
Collection of sentences

Stores all facts and rules about the environment. Initially contains background knowledge (domain rules), then grows with new observations.

TELL Operation
Add sentences to KB

The agent TELLs the KB what it has observed. Also used to record that an action was executed.

ASK Operation
Query the KB

The agent ASKs the KB what action to perform. This may involve inference — deriving new sentences from existing ones.

Inference
Derive new sentences

The process of deriving new sentences from old ones. In logical agents, answers must follow from what was previously TELLed to the KB.

Why Knowledge-Based Agents?

Reactive Agents

Follow fixed stimulus-response rules. Example: navigating from Arad to Bucharest on a map — no knowledge needed.

Problem-Solving Agents

Use search algorithms with domain-specific knowledge. Example: chess program knows legal moves but doesn't know a piece can't be in two squares at once.

Knowledge-Based Agents

Use general, combinable, decomposable knowledge. Can handle new tasks by accepting new goals and updating their knowledge.

Key Insight: A successful agent should use both declarative elements (explicit knowledge representation) and procedural elements (efficient execution). Purely declarative approaches can be inefficient; purely procedural approaches lack flexibility.

The KB-Agent Algorithm

The KB-Agent is a simple but powerful algorithm that operates in a continuous loop of perceiving, reasoning, and acting.

KB-Agent Function (Pseudocode)
function KB-AGENT(percept) returns an action static: KB, a knowledge base t, a counter, initially 0, indicating time TELL(KB, MAKE-PERCEPT-SENTENCE(percept, t)) action ← ASK(KB, MAKE-ACTION-QUERY(t)) TELL(KB, MAKE-ACTION-SENTENCE(action, t)) t ← t + 1 return action
Each time the agent is called, it receives a percept, updates the KB, queries for the best action, records the action, increments time, and returns the action.

Three Hidden Functions

MAKE-PERCEPT-SENTENCE

Constructs a sentence stating what the agent perceived at time t. Example: Stench ∧ Breeze at time 3.

MAKE-ACTION-QUERY

Constructs a sentence asking what action should be taken at time t. The ASK operation uses inference to answer this.

MAKE-ACTION-SENTENCE

Constructs a sentence stating that the chosen action was executed at time t. This keeps the KB consistent with reality.

How the Algorithm Works (Step by Step)

Step 1: TELL the percept

The agent receives a percept (e.g., "Stench at [1,1]"). It creates a sentence representing this observation and adds it to the KB using TELL.

Step 2: ASK for an action

The agent asks the KB what action to perform. The inference mechanism examines the KB — including background rules, past percepts, and past actions — to determine the best action.

Step 3: TELL the action

After executing the action, the agent tells the KB what it did. This is essential so the KB knows what actually happened (not just what was planned).

Important: The details of the knowledge representation language are hidden in the three MAKE-* functions. The details of the inference mechanism are hidden in TELL and ASK. This separation of concerns makes the architecture modular.

Knowledge Level vs Implementation Level

Knowledge Level

The level of description that specifies what the agent knows and what its goals are. This is independent of how the knowledge is implemented in code.

Implementation Level

The actual code and data structures used to implement the agent — linked lists, neural networks, bit manipulation, etc.

Example: Autonomous Taxi

Knowledge level: The taxi wants to deliver a passenger to Marin County. It knows it is in San Francisco and that the Golden Gate Bridge is the only connection between the two.

Implementation level: The geographic knowledge might be stored as a photo, a linked list, or as noisy signals in a neural network. The inference might use bit manipulation or neural propagation.

Conclusion: At the knowledge level, we can predict the agent will cross the Golden Gate Bridge — regardless of the implementation.

Declarative vs Procedural Approach

Aspect Declarative Approach Procedural Approach
Knowledge Explicitly represented as sentences Encoded directly in procedures
Reasoning Inference engine derives conclusions Code executes step by step
Flexibility High — new knowledge easily added Low — changes require code rewrite
Efficiency May be slower (inference overhead) Generally faster
Transparency Reasoning is inspectable Hard to understand decisions
Example "If stench, then wumpus is nearby" if (stench) { turn_left(); }
Tradeoff Warning: Pure declarative systems can be inefficient for real-time tasks. Pure procedural systems are efficient but inflexible. A successful agent should combine both approaches — declarative for knowledge representation and procedural for efficient execution.

Worked Example 1: Building a KB

Scenario: Wumpus World Background Knowledge

The designer TELLs the KB the rules of the Wumpus world before the agent starts perceiving:

TELL(KB, "For every cell with stench, wumpus is in adjacent cell") TELL(KB, "For every cell with breeze, pit is in adjacent cell") TELL(KB, "Agent starts at [1,1], facing right") TELL(KB, "[1,1] is safe") TELL(KB, "Agent has one arrow")

This background knowledge is always true in the environment and gives the agent a starting point for reasoning.

Worked Example 2: Processing a Percept

Step-by-step KB-Agent execution

Time t=0: Agent at [1,1], perceives [None, None, None, None, None]

TELL(KB, MAKE-PERCEPT-SENTENCE([None,None,None,None,None], 0)) // Equivalent to: TELL(KB, "At t=0: no stench, no breeze, no glitter, no bump, no scream") action ← ASK(KB, MAKE-ACTION-QUERY(0)) // Inference: Since no stench/breeze at [1,1], adjacent cells [1,2] and [2,1] are safe // Returns: "Go Forward" (move to [2,1]) TELL(KB, MAKE-ACTION-SENTENCE("Go Forward", 0))

The KB now knows the agent has moved to [2,1].

Worked Example 3: Inference in Action

Combining old and new knowledge

Time t=1: Agent at [2,1], perceives [None, Breeze, None, None, None]

TELL(KB, "At t=1: Breeze at [2,1]") // KB now contains: // 1. Background rules about breeze → pit // 2. "No breeze at [1,1]" (from t=0) // 3. "Breeze at [2,1]" (from t=1) // Inference: Breeze at [2,1] means pit in [2,2] or [3,1] // No breeze at [1,1] means [1,2] and [2,1] have no adjacent pit // Therefore: [2,2] is dangerous, [3,1] is dangerous // [1,2] is still safe (no breeze at [1,1] rules out pit at [2,1] and [1,2]) action ← ASK(KB, MAKE-ACTION-QUERY(1)) // Returns: "Go Back to [1,1]" (only safe unvisited option)

This demonstrates how combining information from different times and locations leads to powerful conclusions that many animals cannot make.

Key Takeaway: In every case where the agent derives a sentence using inference, if the existing information is correct, the derived sentence is guaranteed to be correct. This is the fundamental property of logical inference.
