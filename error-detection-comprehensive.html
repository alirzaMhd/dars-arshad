Error Detection Methods

Computer Networks — Complete Guide for Exam Preparation

Parity Checking

Parity checking is the simplest error detection method. An extra bit (parity bit) is added to make the total number of 1-bits either even (even parity) or odd (odd parity).

Even Parity:
Total 1-bits (including parity) must be even
If data has odd number of 1s, parity bit = 1; otherwise parity bit = 0
Odd Parity:
Total 1-bits (including parity) must be odd
If data has even number of 1s, parity bit = 1; otherwise parity bit = 0

Parity Bit Calculation

Data: 1011001 (four 1s - even) Even Parity: 1011001 0 (parity = 0, total 1s = 4, even) Odd Parity: 1011001 1 (parity = 1, total 1s = 5, odd)
Example 1: Parity Calculation

Data: 1101011. Calculate even and odd parity bits.

Answer:

Count of 1s = 5 (odd)

Even parity bit = 1 (makes total 6, even)

Odd parity bit = 0 (keeps total 5, odd)

Example 2: Error Detection

Received data with even parity: 1011011 0. Verify if it's correct.

Answer:

Count of 1s = 5 (odd) + parity 0 = 5 total (odd)

Error detected! Total should be even for even parity.

Limitation: Parity checking can only detect odd number of bit errors. If 2 bits flip, the parity remains valid and the error goes undetected. It cannot correct errors.

Checksum

Checksum is a more robust error detection method. The data is divided into segments, which are added together using 1's complement arithmetic. The result is complemented to form the checksum.

Checksum Calculation:
Sum of all segments → Complement → Checksum
At receiver: Sum of all segments + Checksum should equal all 1s (no error).

Checksum Process

Sender: 1. Divide data into k-bit segments 2. Add all segments (with wraparound) 3. Complement the sum → Checksum Receiver: 1. Add all segments + Checksum 2. If result = all 1s → No error 3. Otherwise → Error detected
Example 3: Checksum Calculation

Calculate checksum for data: 10101001 01110011 (8-bit segments)

Answer:

Sum: 10101001 + 01110011 = 100011100

Wraparound: 00011100 + 1 = 00011101

Complement: 11100010 (checksum)

Example 4: Verification

Verify: Data 10101001 01110011, Checksum 11100010

Answer:

Sum: 10101001 + 01110011 + 11100010 = 111111110

Wraparound: 11111110 + 1 = 11111111

All 1s = No error

Example 5: Error Detection

Data: 10101001 01110011, Received checksum: 11100011 (1 bit error)

Answer:

Sum: 10101001 + 01110011 + 11100011 = 111111111

Wraparound: 11111111 + 1 = 100000000 → 00000000

Not all 1s = Error detected!

Cyclic Redundancy Check (CRC)

CRC is a powerful error detection method based on polynomial division. The data is treated as a polynomial and divided by a predetermined generator polynomial. The remainder becomes the CRC value.

CRC Division:
Data × X^n ÷ Generator = Quotient + Remainder (CRC)
n = degree of generator polynomial. CRC is appended to data before transmission.

CRC Process

Sender: 1. Append n zeros to data (n = degree of generator) 2. Divide (data + zeros) by generator polynomial 3. Remainder = CRC 4. Transmit: data + CRC Receiver: 1. Divide received (data + CRC) by generator polynomial 2. If remainder = 0 → No error 3. Otherwise → Error detected
Common CRC Standards:
CRC-8: x^8+x^2+x+1, CRC-16: x^16+x^15+x^2+1, CRC-32: x^32+x^26+x^23+...
CRC-32 is used in Ethernet (FCS field). CRC-16 is used in HDLC.
Example 6: CRC Calculation

Data: 1101011, Generator: 10011 (degree 4). Calculate CRC.

Answer:

Append 4 zeros: 11010110000

Divide by 10011 using XOR division:

Remainder = 1110

Transmitted: 11010111110

Example 7: CRC Verification

Received: 11010111110, Generator: 10011. Verify.

Answer:

Divide by 10011:

Remainder = 0000

No error detected

Example 8: Error Pattern Detection

What error patterns can CRC detect?

Answer:

• All single-bit errors

• All double-bit errors (if generator has ≥ 3 terms)

• All odd number of errors

• All burst errors up to degree of generator

Key Advantage: CRC can detect burst errors, which parity and simple checksum cannot. A CRC-32 can detect all burst errors of length ≤ 32 bits.

Worked Examples

Example 9: Parity Block Code

Use 2D parity for data: 1011 0110 1101. Can it detect 2-bit errors?

Answer:

Row parities: 1, 0, 1 (even parity)

Column parities: 0, 1, 0, 0

2D parity can detect most 2-bit errors but not all (same row/column).

Example 10: Checksum for IPv4

How does IPv4 header checksum work?

Answer:

• 16-bit one's complement checksum

• Covers only IPv4 header (not payload)

• Recomputed at each hop (TTL changes)

Example 11: CRC Polynomial

Convert generator polynomial x^4 + x + 1 to binary.

Answer:

x^4 + x + 1 = 10011

(x^4=1, x^3=0, x^2=0, x^1=1, x^0=1)

Example 12: CRC Strength

What is the error detection capability of CRC-32?

Answer:

• All single-bit errors

• All double-bit errors

• All burst errors up to 32 bits

• 99.99999995% of burst errors longer than 32 bits

Example 13: Method Selection

Choose the best error detection method for: (a) Wireless LAN, (b) Storage devices, (c) Simple sensors

Answer:

(a) CRC-32 (high error rates in wireless)

(b) CRC-32 or stronger (data integrity critical)

(c) Parity (low cost, simple implementation)

Error Detection vs Correction

Error Detection

• Detects errors only

• Requires retransmission

• Lower overhead

• Used in most protocols

Error Correction

• Detects AND corrects errors

• No retransmission needed

• Higher overhead

• Used in noisy channels

Common Mistake: CRC does NOT correct errors, it only detects them. When CRC detects an error, the frame is discarded and retransmitted (using ARQ protocols). Error correction requires additional codes like Hamming codes.
Redundancy Relationship:
Redundancy = (Total bits - Data bits) / Data bits × 100%
Higher redundancy provides better error detection but reduces throughput.

Forward Error Correction (FEC) vs Backward Error Correction (BEC)

Feature Forward Error Correction (FEC) Backward Error Correction (BEC)
Definition Receiver corrects errors without retransmission Receiver detects errors and requests retransmission
Redundancy High (extra bits for correction) Low (only detection bits)
Retransmission Not required Required
Latency Low (immediate correction) High (等待 retransmission)
Examples Hamming code, Reed-Solomon, Convolutional codes CRC + ARQ, Parity + retransmission
Applications Satellite, deep space, real-time audio/video Ethernet, TCP, file transfer
Error Types Corrects single/multiple bit errors Only detects errors
Example: FEC vs BEC Choice

Which method is better for: (a) Live satellite TV, (b) Email transmission?

Answer:

(a) FEC - Real-time data cannot wait for retransmission

(b) BEC - Email can tolerate retransmission delay for guaranteed delivery

Key Insight: FEC is used when retransmission is impractical (real-time, long delays). BEC is used when retransmission is feasible and data integrity is critical.
