Depth-Limited Search (DLS)

DFS with a Depth Cutoff — Avoiding Infinite Paths

DLS Algorithm Overview

Depth-Limited Search is a variant of DFS that imposes a depth limit l. Any node at depth l is treated as if it has no children (cutoff). This solves the infinite-path problem of standard DFS.

Core Principle:
DFS with depth cutoff l — nodes at depth l have no children
DLS = DFS + depth bound. If l = ∞, DLS reduces to standard DFS.

Three Possible Outcomes

Solution Found

Goal reached within depth l

Return SOLUTION

Cutoff

No goal found, but cutoff occurred (node at depth l could not be expanded)

Return CUTOFF

Failure

No goal found, no cutoff occurred (entire tree exhausted within limit)

Return FAILURE

Pseudocode: DEPTH-LIMITED-SEARCH

function DEPTH-LIMITED-SEARCH(problem, limit) returns solution/failure/cutoff return RECURSIVE-DLS(Node(problem.INITIAL), problem, limit) function RECURSIVE-DLS(node, problem, limit) returns solution/failure/cutoff if problem.GOAL-TEST(node.State) then return SOLUTION(node) else if limit = 0 then return CUTOFF else cutoff-occurred? ← false for each action in problem.ACTIONS(node.State) do child ← CHILD-NODE(problem, node, action) result ← RECURSIVE-DLS(child, problem, limit - 1) if result = CUTOFF then cutoff-occurred? ← true else if result ≠ failure then return result if cutoff-occurred? then return CUTOFF else return failure
Relationship to DFS:
DFS = DLS with l = ∞
Standard DFS never limits depth. DLS generalizes DFS by adding a cutoff parameter. When the limit is infinite, DLS behaves identically to DFS.
DLS returns a special CUTOFF signal (not FAILURE) when the limit prevents expansion. This distinction is crucial for Iterative Deepening DFS (IDDFS), which calls DLS repeatedly with increasing limits.

Completeness of DLS

Completeness Condition:
DLS is complete if l ≥ d
Where l = depth limit, d = depth of shallowest goal. If the cutoff is at least as deep as the shallowest goal, DLS will eventually find a solution.
When l < d: Incomplete

If the depth limit is smaller than the goal depth, DLS will cut off before reaching the goal. All nodes at depth l are treated as leaves, so the goal at depth l+1 is never generated. DLS returns CUTOFF, and we know a goal might exist beyond the limit.

Warning: l < d = Incomplete Search

Choosing a limit l that is too small guarantees incompleteness. However, DLS returns CUTOFF (not FAILURE) in this case, alerting us that a deeper search might succeed. This is the foundation of Iterative Deepening DFS.

Optimality of DLS

Optimality:
DLS is NOT optimal, even when l ≥ d
Like DFS, DLS returns the first solution found based on the order of exploration, not the cheapest. The depth limit does not make it cost-aware.

Not Optimal

• First found ≠ cheapest

• No cost consideration

• Same issue as DFS

DLS vs DFS vs BFS

• DLS fixes DFS infinite paths

• But not optimal like BFS

• Space: O(bl) — better than BFS

Choosing the Depth Limit

The depth limit l is a critical parameter. Setting it correctly requires domain knowledge.

Strategies for Choosing l

StrategyDescriptionExample
Domain knowledgeUse known properties of the problemMax 19 steps between any two cities on a map with 20 cities
Diameter of state spaceMaximum path length between any two statesRomanian map: diameter = 9 (max 9 steps between any two cities)
Physical constraintsReal-world limits on path lengthRobot with battery for 100 steps

Romanian Map Example

Consider the Romanian road map problem with 20 cities:

Naive Bound

• 20 cities total

• Max path length: 19

• l = 19 (all cities visited)

Works but wasteful

Diameter Bound

• Max steps between any 2 cities: 9

• l = 9 (state space diameter)

More efficient, still complete

State Space Diameter:
l = maxs,t ∈ S shortest-path-length(s, t)
The diameter is the maximum shortest-path distance between any two states. Setting l to the diameter guarantees all states are reachable without wasteful deep exploration.

Warning: Choosing l is Critical

Too small (l < d): Incomplete — goals beyond the cutoff are missed.

Too large (l >> d): DLS wastes time exploring useless deep branches, approaching the inefficiency of DFS.

Solution: Use domain knowledge to estimate a good bound, or use Iterative Deepening DFS (IDDFS) which adaptively increases the limit.

Worked Examples

Example 1: DLS with Different Limits — Finding the Sweet Spot

Problem: A tree with b = 3, goals at depths 4 and 7. Run DLS with l = 3, l = 5, and l = 8.

l = 3:

• Nodes at depth 0,1,2,3 explored. Cutoff at depth 3.

• Both goals (depth 4 and 7) are missed.

• Result: CUTOFF (no goal found due to limit)

Total nodes explored: 1 + 3 + 9 + 27 = 40. Incomplete.

l = 5:

• Nodes up to depth 5 explored.

• Goal at depth 4 found! (assuming goal is reached before exploring deeper)

Total nodes explored: up to 1 + 3 + 9 + 27 + 81 + 243 = 364 (worst case if goal is last at depth 4). Complete for depth 4 goal.

l = 8:

• Both goals (depth 4 and 7) reachable.

Total nodes explored: up to 9,841 (39-3/2). More nodes but both goals reachable.

Example 2: Calculate the State Space Diameter

Problem: A state space has states A, B, C, D, E, F. Edges: A-B, A-C, B-D, C-D, D-E, E-F. What is the diameter? What depth limit should DLS use?

Step 1: Find all-pairs shortest paths:

• A to F: A-C-D-E-F = 4 steps

• B to F: B-D-E-F = 3 steps

• A to D: A-B-D = 2 steps or A-C-D = 2 steps

• B to E: B-D-E = 2 steps

• F to any: F-E-D-... maximum 4 steps

Step 2: Find the maximum shortest path:

• The farthest pair is A-F or B-F with path length 4.

Diameter = 4. Set l = 4 for DLS to guarantee complete coverage.

Example 3: DLS Trace with l = d (Perfect Limit)

Problem: Binary tree (b = 2), goal at depth 3 node "RLR". Run DLS with l = 3 (equal to goal depth).
