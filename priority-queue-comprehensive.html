What is a Priority Queue?

A priority queue is a collection of elements, each associated with a key (priority value). The element with the highest priority is served before elements with lower priority.

Formal Definition:
PQ = {(k1, d1), (k2, d2), ..., (kn, dn)}
Where ki = key (priority), di = data. The element with maximum key is returned first in a max-priority queue.
Key Distinction: A priority queue differs from a regular queue (FIFO). In a priority queue, the element with the highest key value is dequeued first, regardless of insertion order.

Max-Priority Queue

• Highest key = highest priority

• MAXIMUM returns largest key

• Used in scheduling, Dijkstra's

Min-Priority Queue

• Lowest key = highest priority

• FIND-MIN returns smallest key

• Used in Prim's, Huffman's

Binary Heap as Priority Queue

A binary heap is a nearly complete binary tree that satisfies the heap property. It is the most common implementation of a priority queue.

Max-Heap Property:
For every node i other than the root: A[PARENT(i)] >= A[i]
The value of each node is at most the value of its parent. The maximum element is always at the root.
Min-Heap Property:
For every node i other than the root: A[PARENT(i)] <= A[i]
The value of each node is at least the value of its parent. The minimum element is always at the root.

Heap Representation

Heaps are stored as arrays. For a node at index i:

Index Formulas

PARENT(i): floor(i / 2)

LEFT(i): 2 * i

RIGHT(i): 2 * i + 1

Properties

• Root at A[1]

• Heap of n nodes: height = floor(lg n)

• Complete binary tree

Example: Heap stored as array

Tree: 16 (root) → left: 14, right: 10 → 14's children: 8, 7; 10's children: 9, 3

Array A: [_, 16, 14, 10, 8, 7, 9, 3]

A[1] = 16 (root/max). PARENT(4) = 2, LEFT(2) = 4, RIGHT(2) = 5

Maximum Element:
MAXIMUM(S) = return A[1]
Just return the root. Time: Θ(1) — constant time, no search needed.

HEAPIFY — Core Algorithm

HEAPIFY assumes the binary trees at LEFT(i) and RIGHT(i are max-heaps, but A[i] might be smaller than its children. It floats A[i] down to restore the heap property.

HEAPIFY(A, i)
1 l = LEFT(i)
2 r = RIGHT(i)
3 largest = i
4 if l <= A.heap-size and A[l] > A[i]
5 largest = l
6 if r <= A.heap-size and A[r] > A[largest]
7 largest = r
8 if largest != i
9 exchange A[i] with A[largest]
10 HEAPIFY(A, largest)
Complexity: HEAPIFY runs in O(lg n) time. Each level does O(1) comparisons, and the element can sink at most h levels (h = floor(lg n)).

EXTRACT-MAX Algorithm

Removes and returns the element with the highest key (the root).

EXTRACT-MAX(A)
1 if A.heap-size < 1
2 error "heap underflow"
3 max = A[1]
4 A[1] = A[A.heap-size]
5 A.heap-size = A.heap-size - 1
6 HEAPIFY(A, 1)
7 return max
Steps:
Save max → Replace root with last → Decrease size → HEAPIFY
Time: O(lg n) due to HEAPIFY at root.

HEAP-INSERT Algorithm

Adds a new element to the heap by placing it at the end and bubbling up (sifting up) to restore the heap property.

HEAP-INSERT(A, key)
1 A.heap-size = A.heap-size + 1
2 A[A.heap-size] = -∞
3 HEAP-INCREASE-KEY(A, A.heap-size, key)

HEAP-INCREASE-KEY Algorithm

Increases the key of element at index i to the new key value k (k must be >= current key).

HEAP-INCREASE-KEY(A, i, key)
1 if key < A[i]
2 error "new key is smaller"
3 A[i] = key
4 while i > 1 and A[PARENT(i)] < A[i]
5 exchange A[i] with A[PARENT(i)]
6 i = PARENT(i)
Bubble-Up Logic:
While parent < new key: swap with parent, move up
Stops when parent >= key or root is reached. Time: O(lg n) worst case.
Common Mistake: HEAP-INCREASE-KEY only increases a key. It will not work if you try to decrease a key — the while loop condition checks if the parent is smaller, so decreasing would violate this.

Worked Example 1: Build a Heap from Array

Given array A = [4, 1, 3, 2, 16, 9, 10, 14, 8, 7], build a max-heap.

Step-by-Step (BUILD-MAX-HEAP)

Start: A = [4, 1, 3, 2, 16, 9, 10, 14, 8, 7], heap-size = 10

n/2 = 5: Process nodes 5 down to 1

Step 1: HEAPIFY(A, 5) → A[5]=16, children 2i=10(no), 2i+1=11(x) → [4, 1, 3, 2, 16, 9, 10, 14, 8, 7]

Step 2: HEAPIFY(A, 4) → A[4]=2, children: A[8]=14 > 2 → swap → [4, 1, 3, 14, 16, 9, 10, 2, 8, 7]

Step 3: HEAPIFY(A, 3) → A[3]=3, children: A[6]=9, A[7]=10 → 10 > 3 → swap → [4, 1, 10, 14, 16, 9, 3, 2, 8, 7]

Step 4: HEAPIFY(A, 2) → A[2]=1, children: A[4]=14, A[5]=16 → 16 > 1 → swap → [4, 16, 10, 14, 1, 9, 3, 2, 8, 7]

Step 5: HEAPIFY(A, 1) → A[1]=4, children: A[2]=16, A[3]=10 → 16 > 4 → swap → [16, 4, 10, 14, 1, 9, 3, 2, 8, 7]

→ Continue: A[2]=4, children A[4]=14, A[5]=1 → 14 > 4 → swap → [16, 14, 10, 4, 1, 9, 3, 2, 8, 7]

→ A[4]=4, children A[8]=2, A[9]=8 → 8 > 4 → swap → [16, 14, 10, 8, 1, 9, 3, 2, 4, 7]

Final max-heap: Root = 16. Every parent >= its children.

Worked Example 2: EXTRACT-MAX

Extract max from heap: [16, 14, 10, 8, 1, 9, 3, 2, 4, 7]

Step-by-Step

1. Save max = 16

2. Replace root with last element: [7, 14, 10, 8, 1, 9, 3, 2, 4, _]

3. Decrease heap-size to 9

4. HEAPIFY(A, 1):

→ A[1]=7, children: A[2]=14, A[3]=10 → 14 > 7 → swap

→ [14, 7, 10, 8, 1, 9, 3, 2, 4]

→ A[2]=7, children: A[4]=8, A[5]=1 → 8 > 7 → swap

→ [14, 8, 10, 7, 1, 9, 3, 2, 4]

→ A[4]=7, children: A[8]=2, A[9]=4 → 7 > both → done

Returned: 16

New heap: [14, 8, 10, 7, 1, 9, 3, 2, 4]

Worked Example 3: INSERT Operations

Example 3a: Insert 18 into [16, 14, 10, 8, 1, 9, 3, 2, 4, 7]

1. heap-size becomes 11

2. Place 18 at A[11]: [16, 14, 10, 8, 1, 9, 3, 2, 4, 7, 18]

3. Bubble up: A[11]=18, PARENT(11)=5, A[5]=1 < 18 → swap

→ [16, 14, 10, 8, 18, 9, 3, 2, 4, 7, 1]

→ A[5]=18, PARENT(5)=2, A[2]=14 < 18 → swap

→ [16, 18, 10, 8, 14, 9, 3, 2, 4, 7, 1]

→ A[2]=18, PARENT(2)=1, A[1]=16 < 18 → swap

→ [18, 16, 10, 8, 14, 9, 3, 2, 4, 7, 1]

Example 3b: Insert 5 into [18, 16, 10, 8, 14, 9, 3, 2, 4, 7, 1]

1. Place 5 at A[12]: [..., 1, 5]

2. PARENT(12)=6, A[6]=9 > 5 → No swap needed!

Result: [18, 16, 10, 8, 14, 9, 3, 2, 4, 7, 1, 5] — heap property maintained

Worked Example 4: EXTRACT-MAX from Small Heap

Extract max from [18, 16, 10, 8, 14, 9, 3, 2, 4, 7, 1, 5]

1. Save max = 18, replace with last (5): [5, 16, 10, 8, 14, 9, 3, 2, 4, 7, 1, _]

2. HEAPIFY(A, 1):

→ A[1]=5, children A[2]=16, A[3]=10 → 16 > 5 → swap

→ A[2]=5, children A[4]=8, A[5]=14 → 14 > 5 → swap

→ A[5]=5, children A[10]=7, A[11]=1 → 7 > 5 → swap

→ A[10]=5, no children → Done

Final: [16, 14, 10, 8, 7, 9, 3, 2, 4, 5, 1]

Worked Example 5: HEAP-INCREASE-KEY

Increase key at index 8 from 2 to 20

Heap: [16, 14, 10, 8, 1, 9, 3, 2, 4, 7]

1. Set A[8] = 20: [16, 14, 10, 8, 1, 9, 3, 20, 4, 7]

2. Bubble up: A[8]=20, PARENT(8)=4, A[4]=8 < 20 → swap

→ [16, 14, 10, 20, 1, 9, 3, 8, 4, 7]

→ A[4]=20, PARENT(4)=2, A[2]=14 < 20 → swap

→ [16, 20, 10, 14, 1, 9, 3, 8, 4, 7]

→ A[2]=20, PARENT(2)=1, A[1]=16 < 20 → swap

→ [20, 16, 10, 14, 1, 9, 3, 8, 4, 7]

Time Complexity Summary

MAXIMUMΘ(1)Return A[1], root is always max
EXTRACT-MAXO(lg n)Replace root, HEAPIFY down at most h levels
INSERTO(lg n)Add at end, bubble up at most h levels
INCREASE-KEYO(lg n)Bubble up at most h levels
BUILD-MAX-HEAPO(n)n/2 calls to HEAPIFY, but total is O(n), not O(n lg n)
HEAPSORTO(n lg n)Build heap O(n) + n × EXTRACT-MAX O(lg n)
Key Insight — Why BUILD-MAX-HEAP is O(n):
Sum over all nodes: O(n/4 * 1 + n/8 * 2 + ... + 1 * lg n) = O(n)
Most nodes are near the bottom (height 0 or 1). Only O(n/lg n) nodes have height lg n. The geometric sum converges to O(n).

Space Complexity

Space: O(n)

In-place: Yes

Extra: O(1) for HEAPIFY (iterative)

Recursive HEAPIFY

Stack space: O(lg n)
