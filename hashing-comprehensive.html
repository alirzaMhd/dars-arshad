HASHING

Data Structures — Complete Guide for 20/20 Exam

What is Hashing?

Hashing aims to achieve O(1) time for search, insert, and delete operations. Each element has a key k, which is passed to a hash function h that generates an address h(k) indicating where to store the element in hash table T[0..m-1].

Hash Function:
h(k) = address in T[0..m-1]
Maps key k to a position in the hash table
Collision:
k₁ ≠ k₂ but h(k₁) = h(k₂)
Two different keys map to same address

Direct Hashing

• Element with key k stored at T[k]

• Problem: wastes memory if keys are sparse

• Example: keys 10, 20, 300, 1000 need T[0..1000]

Hash Table

• Array T[0..m-1] with m slots

• n elements stored in m slots

• Need collision resolution when m < max key

⚠ Key Concept: The goal is O(1) operations, but collisions can degrade performance!

Chaining (Open Hashing)

How Chaining Works:
Each slot T[i] points to a linked list
Elements with same hash are added to the same list
Insert Operation:
insert_chaining(k) { address = h(k) // Insert at beginning of list T[address] new_node = create_node(k) new_node.next = T[address] T[address] = new_node }
Always insert at beginning of list - O(1)

Advantages

• Simple to implement

• No overflow (table never "full")

• n can be > m (more elements than slots)

• Insert is O(1)

Disadvantages

• Uses extra memory for pointers

• Cache performance poor (linked lists)

• Worst case O(n) if all elements hash to same slot

Open Addressing (Closed Hashing)

How Open Addressing Works:
All elements stored in the table itself
When collision occurs, find another empty slot
Linear Probing:
insert_linear_probing(k) { address = h(k) while (T[address] is not empty) { address = (address + 1) mod m if (all slots checked) overflow! } T[address] = k }
Check next slot sequentially until empty found

Linear Probing

• Check T[address], T[address+1], ...

• Wrap around to T[0] if needed

• Problem: primary clustering

Other Probing Methods

• Quadratic: address = (address + i²) mod m

• Double hashing: h₁(k) + i·h₂(k)

• Reduce clustering

⚠ Important: In open addressing, n ≤ m (number of elements ≤ table size)!

Worked Examples

Example 1: Chaining with h(k) = k mod 5

Keys: 24, 32, 47, 51, 60, 27, 76

Hash table T[0..4]

h(24) = 24 mod 5 = 4 → T[4]

h(32) = 32 mod 5 = 2 → T[2]

h(47) = 47 mod 5 = 2 → T[2] (collision! add to list)

h(51) = 51 mod 5 = 1 → T[1]

h(60) = 60 mod 5 = 0 → T[0]

h(27) = 27 mod 5 = 2 → T[2] (collision! add to list)

h(76) = 76 mod 5 = 1 → T[1] (collision! add to list)

Final table:

T[0] → [60]

T[1] → [76] → [51]

T[2] → [27] → [47] → [32]

T[3] → empty

T[4] → [24]

Example 2: Linear Probing with h(k) = k mod 5

Keys: 23, 42, 37, 26, 41

Hash table T[0..4]

h(23) = 23 mod 5 = 3 → T[3]

h(42) = 42 mod 5 = 2 → T[2]

h(37) = 37 mod 5 = 2 → T[2] full, try T[3] full, try T[4] → T[4]

h(26) = 26 mod 5 = 1 → T[1]

h(41) = 41 mod 5 = 1 → T[1] full, try T[0] → T[0]

Final table:

T[0] = 41

T[1] = 26

T[2] = 42

T[3] = 23

T[4] = 37

Example 3: Collision Probability

Probability that 2 elements collide = 1/m

For m = 5 slots: probability = 1/5 = 0.2 = 20%

For m = 100 slots: probability = 1/100 = 0.01 = 1%

More slots → fewer collisions!

Time & Space Complexity

Load Factor:
α = n/m
n = number of elements, m = number of slots. Average elements per slot.

Chaining Complexity

Insert: Θ(1)

Search (average): Θ(1 + α)

Search (worst): Θ(n) if all in one list

Open Addressing Complexity

Insert: Θ(1/(1-α)) average

Search (unsuccessful): Θ(1/(1-α))

Search (successful): Θ((1/α)ln(1/(1-α)))
