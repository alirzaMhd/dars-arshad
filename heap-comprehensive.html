Binary Heaps

Data Structures — Complete Guide for 20/20 Exam

Binary Heap Definition

A binary heap is a complete binary tree that satisfies the heap property. It is stored as an array, not as linked nodes.

Complete Binary Tree:
Every level is fully filled, except possibly the last level, which is filled from left to right.
This property ensures the tree can be represented as a contiguous array with no gaps.

Max-Heap Property

Max-Heap:
A[parent(i)] ≥ A[i] for all nodes i except root
Every parent node is greater than or equal to its children. The maximum element is always at the root A[1].

Min-Heap Property

Min-Heap:
A[parent(i)] ≤ A[i] for all nodes i except root
Every parent node is less than or equal to its children. The minimum element is always at the root A[1].
The heap property only guarantees order between parent and child. Two children of the same parent are unordered relative to each other. A heap is NOT a sorted array!

Key Properties

Height

h = ⌊lg n⌋

• n = number of nodes

• Tree is as balanced as possible

Leaf Nodes

• Range: ⌊n/2⌋+1 to n

• Have no children

• Count: ⌈n/2⌉ leaves

Internal Nodes

• Range: 1 to ⌊n/2⌋

• Have at least one child

• Processed in BUILD-HEAP

Structure

• Complete binary tree

• Left-filled at each level

• No gaps in array

Example: Identifying Nodes

n = 10 nodes

Height = ⌊lg 10⌋ = 3

Internal nodes: indices 1 to 5 (have children)

Leaf nodes: indices 6 to 10 (no children)

Count of leaves = ⌈10/2⌉ = 5

Array Representation (1-indexed)

A binary heap is stored as an array. The level-order traversal of the tree gives the array indices.

Tree: Array: 1 Index: 1 2 3 4 5 6 7 / \ Value: [1, 2, 3, 4, 5, 6, 7] 2 3 / \ / \ 4 5 6 7
PARENT(i):
parent(i) = ⌊i/2⌋
For i = 2, 3, ..., n. The root at index 1 has no parent.
LEFT(i):
left(i) = 2i
For i = 1, 2, ..., ⌊n/2⌋. Returns value > n if no left child exists.
RIGHT(i):
right(i) = 2i + 1
For i = 1, 2, ..., ⌊n/2⌋. Returns value > n if no right child exists.
Most textbooks (CLRS) use 1-indexed arrays. If using 0-indexed arrays: parent(i) = ⌊(i-1)/2⌋, left(i) = 2i+1, right(i) = 2i+2. Be consistent with your indexing convention!

Array A = [_, 16, 14, 10, 8, 7, 9, 3, 2, 4, 1] (indices 1-10)

• Node at i=2: value=14, parent=⌊2/2⌋=1 (value=16), left=4 (value=8), right=5 (value=7)

• Node at i=5: value=7, parent=⌊5/2⌋=2 (value=14), left=10 (value=1), right=11 (out of bounds)

MAX-HEAPIFY (Sift-Down)

Restores the max-heap property at index i, assuming the subtrees at left(i) and right(i) are already max-heaps.

Precondition:
left(i) and right(i) are valid max-heaps, but A[i] may be smaller than its children
MAX-HEAPIFY lets A[i] "float down" (sift down) to its correct position by swapping with the larger child.
MAX-HEAPIFY(A, i) l ← left(i) r ← right(i) largest ← i if l ≤ A.heap-size and A[l] > A[i] largest ← l if r ≤ A.heap-size and A[r] > A[largest] largest ← r if largest ≠ i exchange A[i] ↔ A[largest] MAX-HEAPIFY(A, largest)
Complexity:
Time: O(lg n) — at most 2 comparisons per level, height = ⌊lg n⌋
Space: O(lg n) recursive, O(1) iterative. Each recursive call moves one level down the tree.
Example: MAX-HEAPIFY on A[2]
Array: [_, 16, 4, 10, 14, 7, 9, 3, 2, 8, 1]
Step 0: 16 ← A[2]=4 violates max-heap / \ [4] 10 ← 4 < 14 and 4 < 7 / \ / \ 14 7 9 3 / \ / \ 2 8 1 -

l=4 (A[4]=14), r=5 (A[5]=7). largest = 4 (since 14 > 4 and 14 > 7).

Exchange A[2]=4 ↔ A[4]=14. Recurse on i=4.

Step 1: 16 / \ [14] 10 ← 4 now at index 4 / \ / \ [4] 7 9 3 ← 4 < 2? No. 4 < 8? Yes. / \ / \ 2 8 1 -

l=8 (A[8]=2), r=9 (A[9]=8). largest = 9 (since 8 > 4 and 8 > 2).

Exchange A[4]=4 ↔ A[9]=8. Recurse on i=9 (leaf). Done.

Final: 16 / \ 14 10 / \ / \ 8 7 9 3 / \ / \ 2 4 1 -
Example 2: No Swap Needed
Array: [_, 20, 15, 8, 10, 5, 3]
20 / \ [15] 8 A[2]=15 / \ / left=10, right=5 10 [5] 3 15 > 10 and 15 > 5 → no swap needed

MAX-HEAPIFY checks: 15 > 10 ✓ and 15 > 5 ✓. Heap property already holds. Returns immediately.

MIN-HEAPIFY (Symmetric):
Same logic but swap with the SMALLER child instead of larger
Restores min-heap property. A[i] sifts down by swapping with the child that has the smaller value.

BUILD-MAX-HEAP

Converts an arbitrary array into a max-heap. Two methods exist.

Method 1: Repeated Insertion

BUILD-MAX-HEAP-INSERT(A) A.heap-size ← 1 for i ← 2 to A.length do MAX-HEAP-INSERT(A, A[i])
Complexity (Method 1):
O(n lg n) — n insertions, each O(lg n)
Each INSERT sifts up the element. Worst case O(lg n) per insertion.

Method 2: Bottom-Up Construction (Optimal)

BUILD-MAX-HEAP(A) A.heap-size ← A.length for i ← ⌊A.length/2⌋ downto 1 do MAX-HEAPIFY(A, i)
Complexity (Method 2):
O(n) — Linear time!
Process internal nodes from bottom to top. Most nodes are near the bottom with small heights, so total work sums to O(n).
BUILD-MAX-HEAP is O(n), NOT O(n lg n). This is a very common exam question! The proof: a node of height h has at most ⌈n/2^(h+1)⌉ nodes. Sum: Σ(h=0 to lg n) h·n/2^(h+1) = O(n).
Example: Build Max-Heap Step by Step
Array: [_, 4, 1, 3, 2, 16, 9, 10, 14, 8, 7] (n = 10)

Internal nodes: i = 5, 4, 3, 2, 1 (from ⌊10/2⌋ downto 1)

i=5: A[5]=16. Child: A[10]=7. 16 > 7 → no change

i=4: A[4]=2. Children: A[8]=14, A[9]=8. largest=8. Swap 2↔14.

After i=4: [_, 4, 1, 3, 14, 16, 9, 10, 2, 8, 7]

i=3: A[3]=3. Children: A[6]=9, A[7]=10. largest=7. Swap 3↔10.

After i=3: [_, 4, 1, 10, 14, 16, 9, 3, 2, 8, 7]

i=2: A[2]=1. Children: A[4]=14, A[5]=16. largest=5. Swap 1↔16. Recurse on i=5: A[5]=1, child A[10]=7. 1 < 7, swap. Done.

After i=2: [_, 4, 16, 10, 14, 7, 9, 3, 2, 8, 1]

i=1: A[1]=4. Children: A[2]=16, A[3]=10. largest=2. Swap 4↔16. Recurse on i=2: A[2]=4, children A[4]=14, A[5]=7. largest=4. Swap 4↔14. Done.

After i=1: [_, 16, 14, 10, 4, 7, 9, 3, 2, 8, 1]
Final Max-Heap: 16 / \ 14 10 / \ / \ 4 7 9 3 / \ / 2 8 1
Example 2: Why Bottom-Up is O(n)

n = 7 nodes. Heights of all nodes:

h=2 1 ← 1 node of height 2 / \ h=1 h=1 2, 3 ← 2 nodes of height 1 / \ / \ h=0 h=0 h=0 h=0 4,5,6,7 ← 4 nodes of height 0

Total work = 1×2 + 2×1 + 4×0 = 4 operations.

For n nodes: Σ(h=0 to ⌊lg n⌋) ⌈n/2^(h+1)⌉ × h = O(n).

Most nodes are leaves (height 0), contributing zero work!

Comparison of Build Methods

Method Algorithm Time When to Use
Method 1 Repeated INSERT O(n lg n) When elements arrive one at a time (streaming)
Method 2 Bottom-up HEAPIFY O(n) When all elements available upfront (preferred)

O(1)

O(1)

O(n)

O(n)

Must check all ⌈n/2⌉ leaves

n = 1000 → Height = ⌊lg 1000⌋ = ⌊9.97⌋ = 9

Algorithms at a Glance

MAX-HEAPIFY(A, i): Compare A[i] with children, swap with largest, recurse if swapped BUILD-MAX-HEAP(A): for i = ⌊n/2⌋ downto 1: MAX-HEAPIFY(A, i) MIN-HEAPIFY(A, i): Compare A[i] with children, swap with smallest, recurse if swapped BUILD-MIN-HEAP(A): for i = ⌊n/2⌋ downto 1: MIN-HEAPIFY(A, i)
BUILD-MAX-HEAP Analysis:
Σ(h=0 to ⌊lg n⌋) ⌈n/2^(h+1)⌉ × h = O(n)
Sum of heights of all internal nodes. Most nodes have height 0 or 1.
Exam Tips:
  • BUILD-MAX-HEAP is O(n), NOT O(n lg n) — most common exam question!
  • Process internal nodes from ⌊n/2⌋ downto 1 (bottom-up)
  • MAX-HEAPIFY assumes children are already heaps
  • Heap is NOT sorted — only parent-child ordering guaranteed
  • Leaves are indices ⌊n/2⌋+1 to n
  • Height is ⌊lg n⌋, not ⌈lg n⌉
  • Confusing min-heap and max-heap properties is a frequent mistake
  • Using 0-indexed formulas with 1-indexed array (or vice versa)
