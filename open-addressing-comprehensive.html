OPEN ADDRESSING

Data Structures — Complete Guide for 20/20 Exam

What is Open Addressing?

In open addressing, all elements are stored in the hash table itself. No linked lists are used. When a collision occurs, we probe (search) for alternative slots until an empty slot is found.

Probe Sequence:
h(k, 0), h(k, 1), h(k, 2), ..., h(k, m-1)
Every slot is tried in sequence until an empty slot is found
Open addressing requires the load factor α ≤ 1 (table cannot be full). Deletion is complex - we use "deleted" markers instead of NIL.
Example: Open Addressing vs Chaining

Keys: {10, 22, 31, 4, 15, 28, 17, 88, 59}

Table size: m = 11

Chaining: Each slot has a linked list

Open Addressing: All elements stored directly in slots

Probing Methods

Linear Probing

Formula:
h(k, i) = (h'(k) + i) mod m
i = 0, 1, 2, ..., m-1. Check consecutive slots.

Quadratic Probing

Formula:
h(k, i) = (h'(k) + c₁i + c₂i²) mod m
c₁ and c₂ are constants, i = 0, 1, 2, ..., m-1

Double Hashing

Formula:
h(k, i) = (h₁(k) + i·h₂(k)) mod m
h₁ and h₂ are two different hash functions

Algorithms

Insert Algorithm

Insert(T, k): i = 0 repeat j = h(k, i) if T[j] == NIL: T[j] = k return j else: i = i + 1 until i == m error "hash table overflow"

Search Algorithm

Search(T, k): i = 0 repeat j = h(k, i) if T[j] == k: return j else: i = i + 1 until T[j] == NIL or i == m return NIL
Deletion is tricky! We cannot simply set T[j] = NIL because it would break probe sequences. Instead, we use a special "deleted" marker.

Worked Examples

Example 1: Linear Probing Insert

Keys: {10, 22, 31, 4, 15, 28, 17, 88, 59}

Hash function: h'(k) = k, h(k,i) = (k + i) mod 11

Insert 10: h(10,0) = 10 mod 11 = 10 → T[10] = 10

Insert 22: h(22,0) = 22 mod 11 = 0 → T[0] = 22

Insert 31: h(31,0) = 31 mod 11 = 9 → T[9] = 31

Insert 4: h(4,0) = 4 mod 11 = 4 → T[4] = 4

Insert 15: h(15,0) = 15 mod 11 = 4 → Collision! h(15,1) = 5 → T[5] = 15

Insert 28: h(28,0) = 28 mod 11 = 6 → T[6] = 28

Insert 17: h(17,0) = 17 mod 11 = 6 → Collision! h(17,1) = 7 → T[7] = 17

Insert 88: h(88,0) = 88 mod 11 = 0 → Collision! h(88,1) = 1 → T[1] = 88

Insert 59: h(59,0) = 59 mod 11 = 4 → Collision! h(59,1) = 5 → Collision! h(59,2) = 6 → Collision! h(59,3) = 7 → Collision! h(59,4) = 8 → T[8] = 59

T = [22, 88, _, _, 4, 15, 28, 17, 59, 31, 10]

Example 2: Search in Open Addressing

Search for key 59 in the table above

h(59,0) = 4 → 4 ≠ 59

h(59,1) = 5 → 15 ≠ 59

h(59,2) = 6 → 28 ≠ 59

h(59,3) = 7 → 17 ≠ 59

h(59,4) = 8 → 59 = 59 (found!)

Search(59) takes 5 probes

Example 3: Quadratic Probing

Keys: {10, 22, 31, 4, 15, 28, 17, 88, 59}

h(k,i) = (k + i + 3i²) mod 11

Insert 10: h(10,0) = 10 → T[10] = 10

Insert 22: h(22,0) = 0 → T[0] = 22

Insert 31: h(31,0) = 9 → T[9] = 31

Insert 4: h(4,0) = 4 → T[4] = 4

Insert 15: h(15,0) = 4 → Collision! h(15,1) = (4+1+3) mod 11 = 8 → T[8] = 15

Different probe sequence than linear probing

Example 4: Double Hashing

h₁(k) = k mod 13, h₂(k) = 1 + (k mod 11)

Insert key 14: h₁(14) = 1, h₂(14) = 1 + (14 mod 11) = 4

h(14,0) = 1, h(14,1) = 5, h(14,2) = 9, h(14,3) = 0

Double hashing produces different probe sequences for different keys

Example 5: Unsuccessful Search

Search for key 99 in the linear probing table

h(99,0) = 0 → 22 ≠ 99

h(99,1) = 1 → 88 ≠ 99

h(99,2) = 2 → NIL (stop)

Search(99) takes 3 probes, returns NIL

Complexity Analysis

Expected Probes

Successful Search: O(1/α ln(1/(1-α)))

Unsuccessful Search: O(1/(1-α))

Insert: O(1/(1-α))

Constraints

Load Factor: α ≤ 1

Table must not be full

Deletion requires tombstones

Load Factor Impact:
α close to 0 → O(1), α close to 1 → O(n)
Performance degrades as table fills up

Comparison of Probing Methods

Method Probe Pattern Clustering Performance
Linear Sequential Primary clustering Simple but poor
Quadratic Quadratic jumps Secondary clustering Better than linear
Double Hashing Depends on second hash Minimal clustering Best performance
