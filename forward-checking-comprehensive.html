Forward Checking

Constraint Propagation During Search

What is Forward Checking?

Forward checking is a method that propagates constraints during search. Whenever a variable X is assigned a value, forward checking looks at each unassigned variable Y that is connected to X by a constraint, and removes from Y's domain any values that are inconsistent with X's assignment.

Core Idea:
When X = v → ∀Y connected to X: DY ← DY \ {values inconsistent with X=v}
Remove values from neighbor domains that conflict with the new assignment

Key Properties

Advantages

• Detects dead-ends earlier

• Reduces branching factor

• Works perfectly with MRV

• Computes domain sizes for free

Limitations

• Doesn't detect all inconsistencies

• Limited lookahead (1-step)

• Arc consistency is more powerful

Key Limitation: Forward checking only looks at direct neighbors. It misses inconsistencies that require 2-step propagation. For example, if NT and SA both have the same single value left, forward checking won't detect that they conflict with each other.

Worked Examples

Example 1: Forward Checking with Binary CSP

Variables: A, B, C with domains {1, 2, 3}

Constraints: A < B, B < C

Step 1: Assign A=1. Forward checking: B must be > 1 → DB = {2, 3}. C unaffected.

Step 2: Assign B=2. Forward checking: C must be > 2 → DC = {3}.

Step 3: Assign C=3. All assigned, all consistent.

✓ Solution found with immediate constraint checks

Example 2: Forward Checking Discovers Inconsistency Early

Same CSP: A < B, B < C

Step 1: Assign A=3. Forward checking: B must be > 3 → EMPTY! (B's domain {1,2,3} has no values > 3).

Immediate backtrack — no need to even try B.

Without forward checking, the algorithm would assign B (try 1, 2, 3) before discovering the inconsistency.

Example 3: Limit of Forward Checking

Variables: X, Y, Z with domains {a, b}

Constraints: X ≠ Y, Y ≠ Z, X ≠ Z

After assigning X=a: Forward checking removes 'a' from Y → DY = {b}. Z unchanged (Z not directly constrained by X... wait, it is in this case).

Actually, all pairs are constrained here. Let's consider a case where FC fails:

Constraints: X ≠ Y, Y ≠ Z (no direct X-Z constraint)

After X=a, Y=b: Forward checking from Y=b removes 'b' from Z → DZ = {a}. This is consistent with X=a.

But if X=a and Y=b and Z=a: X=Z (no direct constraint), but through Y... actually this is fine with these constraints.

Forward checking would detect issues with ternary constraints after all three are partially assigned.

Example 4: MRV + Forward Checking Synergy

Forward checking efficiently computes exactly the domain size information that MRV needs.

After each assignment, the updated domain sizes are immediately available:

  • • No extra computation needed for MRV
  • • MRV naturally selects variables with smallest remaining domains
  • • Forward checking provides the data; MRV uses it

This combination is consistently among the best CSP solvers in practice.

Forward Checking + MRV is a powerful combination
