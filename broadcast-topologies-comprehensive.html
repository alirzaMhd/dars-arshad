BROADCAST TOPOLOGIES

Computer Networks — Complete Guide for Exam Preparation

What is a Broadcast Topology?

Definition:
A broadcast topology is a network layout where all devices share a single communication channel, and every transmitted message is received by all connected nodes simultaneously.
The term "broadcast" refers to the fact that signals sent by any node reach all other nodes on the network.

Types of Broadcast Topologies

Bus Topology

• Single backbone cable

• All devices attach to one line

• Signals propagate both directions

Ring Topology

• Devices form a closed loop

• Data travels in one direction

• Token-passing access method

Wireless Topology

• No physical cables

• Uses radio waves / infrared

• Star or mesh configurations

Key Concepts

Broadcast Domain:
A logical division of a network where all nodes can reach each other by broadcast at the data link layer.
A broadcast frame sent by any node is received by every other node in the same broadcast domain.
Collision Domain:
A network segment where data packets (frames) can collide with one another when being sent on a shared medium.
In bus networks, two nodes transmitting simultaneously cause a collision that corrupts both frames.
Warning: "Broadcast" here refers to the signal propagation behavior, NOT to the act of sending a broadcast message. In all three topologies, unicast messages are also received by all nodes — the NIC filters them based on destination address.

Bus Topology

Definition:
A bus topology connects all devices to a single central cable called the backbone (bus). Signals travel in both directions from the transmitting node and are absorbed by terminators at each end.
The simplest and oldest network topology — one cable, many devices.

Visual Diagram

┌─────────────────────────────────────────────────────────┐ │ BACKBONE CABLE │ └──┬──────────┬──────────┬──────────┬──────────┬─────────┘ │ │ │ │ │ ┌──┴──┐ ┌──┴──┐ ┌──┴──┐ ┌──┴──┐ ┌──┴──┐ │ PC1 │ │ PC2 │ │ PC3 │ │ PC4 │ │ PC5 │ └─────┘ └─────┘ └─────┘ └─────┘ └─────┘ ◄──Term Term──► (absorbs (absorbs signal) signal) Signal flow: PC2 transmits → signal goes BOTH ways along backbone → received by ALL nodes

How It Works

Signal Propagation:
Node transmits → signal travels in BOTH directions along backbone → terminators absorb the signal
Every node on the bus sees every frame. The NIC checks the destination MAC address and discards frames not addressed to it.

Access Method: CSMA/CD

Carrier Sense Multiple Access with Collision Detection:
1. Listen (Carrier Sense) → 2. Transmit if idle → 3. Detect collision → 4. Send jam signal → 5. Wait random backoff → Retry
Before transmitting, a node checks if the cable is idle. If two nodes transmit simultaneously, a collision occurs.
Backoff Time (Binary Exponential Backoff):
τ = random(0, 2^n - 1) × slot_time
Where n = number of collision attempts (capped at 10), slot_time = 2 × propagation delay. After 16 collisions, the frame is dropped.

Key Formulas

Maximum Cable Length:
L_max = (slot_time × c) / 2
Where c = speed of signal in cable (~2/3 speed of light for copper). For Ethernet, slot_time = 51.2 μs, so L_max ≈ 2500 meters.
Maximum Number of Nodes:
N_max = L_max / L_segment
Where L_segment is the minimum cable distance between two nodes (typically 2.5m for 10BASE-T).
Efficiency (Simplified):
η = 1 / (1 + 2 × B × L / (F × P))
Where B = bandwidth, L = cable length, F = frame size, P = number of active stations. As P increases, efficiency drops due to more collisions.

Advantages and Disadvantages

Advantages

• Simple and easy to install

• Requires less cable than other topologies

• Low cost for small networks

• Easy to extend with repeaters

• Works well for temporary setups

Disadvantages

• Single point of failure (backbone)

• Difficult to troubleshoot

• Performance degrades with more nodes

• Collision rate increases with load

• Not suitable for large networks

• Cable length limit constrains size

Common Mistake: A break anywhere in the backbone cable brings down the ENTIRE network, not just the segment after the break. This is because the signal reflections are disrupted, causing all transmissions to fail.

Ring Topology

Definition:
A ring topology connects each device to exactly two other devices, forming a closed loop. Data travels in one direction (unidirectional) or both directions (bidirectional), passing through every intermediate node.
Each node acts as a repeater, regenerating the signal and forwarding it to the next node.

Visual Diagram — Unidirectional Ring

Access Method: Token Passing

Token Passing Protocol:
1. Token circulates → 2. Node with data captures token → 3. Sends frame → 4. Frame circulates → 5. Destination copies data → 6. Frame returns to sender → 7. Sender releases token
Only the node holding the token can transmit. This eliminates collisions entirely.
Token Hold Time (THT):
THT_max = maximum time a node can hold the token
Limits how long a node can transmit before releasing the token. Prevents any single node from monopolizing the network.

Key Formulas

Ring Latency:
D_ring = N × d_node + L / c
Where N = number of nodes, d_node = delay per node (typically 1 μs for regeneration), L = total ring cable length, c = signal propagation speed.
Maximum Ring Length:
L_max = (T_token - N × d_node) × c
Where T_token = token circulation time. Must ensure the token returns before the next transmission window.
Throughput:
Throughput = (Frame_size × N_active) / (T_token + T_frame × N_active)
Under light load, throughput is lower than bus (token overhead). Under heavy load, throughput is BETTER because there are no collisions.

Advantages and Disadvantages

Advantages

• No collisions (deterministic access)

• Equal access for all nodes

• Performs well under heavy load

• Easy to install and reconfigure

• No need for central hub/switch

Disadvantages

• Single node failure breaks the ring

• Difficult to troubleshoot

• Latency increases with more nodes

• Token overhead under light load

• Adding/removing nodes disrupts ring

• More expensive than bus

Dual Ring Self-Healing (FDDI):
If node fails → adjacent nodes wrap the ring → connect primary to secondary → ring remains operational
FDDI (Fiber Distributed Data Interface) uses dual rings for fault tolerance. The ring can survive one cable or node failure.
Common Mistake: In a single ring, if ANY node fails (not just the cable), the entire ring goes down. This is because every node must regenerate and forward the signal. A failed node acts like a broken wire.

Wireless Topology

Definition:
A wireless topology uses radio waves, infrared, or satellite signals to connect devices without physical cables. Devices communicate through access points (APs) or directly with each other.
The most flexible topology — nodes can move freely within range of the signal.

Key Concepts

Basic Service Set (BSS):
BSS = one AP + all associated stations within range
The fundamental building block of 802.11 wireless networks. All communication within a BSS goes through the AP.
Extended Service Set (ESS):
ESS = multiple BSSs connected via a Distribution System (DS)
Allows seamless roaming across multiple access points. The DS is typically a wired Ethernet backbone.
Signal Range:
Range = f(P_tx, G_ant, f_freq, obstacles)
Where P_tx = transmit power, G_ant = antenna gain, f_freq = frequency (2.4 GHz or 5 GHz), obstacles = walls, interference.

Access Method: CSMA/CA

Carrier Sense Multiple Access with Collision Avoidance:
1. Listen → 2. If idle, wait DIFS → 3. Still idle? → 4. Send RTS → 5. Receive CTS → 6. Transmit data → 7. Receive ACK
Unlike wired Ethernet (CSMA/CD), wireless uses collision AVOIDANCE because collisions cannot be detected during transmission over radio.
Hidden Node Problem:
Node A and Node C both hear the AP but NOT each other → both transmit to AP simultaneously → collision at the AP
Solved by RTS/CTS (Request to Send / Clear to Send) handshake. AP grants exclusive access to one sender at a time.

Advantages and Disadvantages

Advantages

• Mobility — move freely within range

• Easy to install — no cables

• Scalable — add devices easily

• Cost-effective for large areas

• Supports roaming (ESS)

Disadvantages

• Lower speed than wired

• Signal interference issues

• Security concerns (eavesdropping)

• Limited range per AP

• Shared medium → contention

• Weather/atmospheric interference

Common Mistake: Wireless is NOT truly broadcast — it uses directional or omnidirectional antennas with limited range. A frame sent by an AP is NOT received by ALL devices on the network, only those within radio range. This is different from bus topology where the electrical signal reaches every device.

Exam Tip: When asked "which topology has no collisions?" → answer Ring (token passing). When asked "which topology degrades under heavy load?" → answer Bus or Wireless (contention-based). When asked "which is most flexible?" → answer Wireless.

Worked Examples

Example 1: Bus Topology — Maximum Length Calculation

Problem: An Ethernet bus network uses coaxial cable with a signal propagation speed of 2 × 10⁸ m/s. The slot time is 51.2 μs. What is the maximum cable length?

Solution:

Formula:
L_max = (slot_time × c) / 2

Calculation:

L_max = (51.2 × 10⁻⁶ s × 2 × 10⁸ m/s) / 2 = (10240 m) / 2 = 5120 m

Maximum cable length ≈ 5120 meters (with proper cable specifications)

In practice, 10BASE5 (thick Ethernet) limits to 500m, and repeaters extend this to 2500m total. The formula gives the theoretical limit.

Example 2: Bus Topology — Collision Analysis

Problem: A bus network has 20 active stations. Each station has a 5% probability of transmitting in any given slot. What is the probability of a collision?

Solution:

Formula:
P(collision) = 1 - P(exactly one transmits) - P(none transmits)
P(collision) = 1 - (1-p)^n - n×p×(1-p)^(n-1)

Calculation:

p = 0.05, n = 20 P(none) = (1 - 0.05)^20 = 0.95^20 ≈ 0.3585 P(exactly one) = 20 × 0.05 × 0.95^19 = 1.0 × 0.3774 ≈ 0.3774 P(collision) = 1 - 0.3585 - 0.3774 = 1 - 0.7359 = 0.2641

Probability of collision ≈ 26.4%

With 20 stations at 5% transmit probability, roughly 1 in 4 slots will have a collision. This is why bus networks perform poorly under load.

Example 3: Ring Topology — Ring Latency

Problem: A token ring network has 15 nodes. Each node introduces a 1 μs delay for signal regeneration. The total cable length is 500 m with a propagation speed of 2 × 10⁸ m/s. Calculate the ring latency.

Solution:

Formula:
D_ring = N × d_node + L / c

Calculation:

N = 15, d_node = 1 μs = 1 × 10⁻⁶ s, L = 500 m, c = 2 × 10⁸ m/s D_ring = 15 × 1 × 10⁻⁶ + 500 / (2 × 10⁸) = 15 × 10⁻⁶ + 2.5 × 10⁻⁶ = 17.5 × 10⁻⁶ s = 17.5 μs

Ring latency = 17.5 μs

This is the time for a signal to traverse the entire ring. It determines the minimum token circulation time.

Example 4: Ring Topology — Maximum Stations

Problem: In a token ring network, the token circulation time must not exceed 1 ms. Each station adds 1 μs delay. The cable length is 1 km (speed = 2 × 10⁸ m/s). What is the maximum number of stations?

Solution:

Formula:
T_token = N × d_node + L / c ≤ T_max

Calculation:

T_max = 1 ms = 1000 μs d_node = 1 μs L = 1000 m, c = 2 × 10⁸ m/s → L/c = 5 μs N × 1 μs + 5 μs ≤ 1000 μs N × 1 μs ≤ 995 μs N ≤ 995

Maximum stations = 995

In practice, the limit is much lower due to other factors like frame size, timeout values, and performance requirements.

Example 5: Wireless — Hidden Node Problem

Problem: In a wireless network, Station A and Station C are both within range of the Access Point (AP) but NOT within range of each other. Both stations want to transmit to the AP simultaneously. Explain what happens and how it is solved.

Solution:

A ◄──(can hear)──► AP ◄──(can hear)──► C │ │ └────(CANNOT hear each other)──────────┘ Scenario: 1. A senses the medium → idle → starts transmitting 2. C senses the medium → idle (cannot hear A) → starts transmitting 3. COLLISION at AP → both frames are corrupted This is the HIDDEN NODE PROBLEM

Solution — RTS/CTS Handshake:

Step 1: A sends RTS (Request to Send) to AP Step 2: AP sends CTS (Clear to Send) to A → C hears the CTS → knows medium is busy → waits Step 3: A transmits data Step 4: AP sends ACK to A Step 5: C can now send RTS when medium is free

RTS/CTS solves the hidden node problem by reserving the medium through the AP.

Example 6: Topology Selection

Problem: A company needs to set up a network for the following scenarios. Which topology should they choose and why?

Scenario A: A temporary art exhibition with 5 laptops for 3 days.

Scenario B: A factory floor with 50 machines that need deterministic communication for real-time control.

Scenario C: A university campus where students need internet access while moving between buildings.

Solution:

Scenario A → WIRELESS (Ad-Hoc mode) Reason: Temporary setup, no cables needed, easy to deploy and remove Scenario B → RING (Token Ring / FDDI) Reason: Deterministic access (no collisions), guaranteed latency, reliable under constant heavy load — ideal for real-time systems Scenario C → WIRELESS (Infrastructure mode with ESS) Reason: Mobility required, seamless roaming between APs, scalable coverage across campus buildings

Match the topology to the application requirements: simplicity for temporary, determinism for real-time, flexibility for mobile.
