Network Protocols

Computer Networks — Complete Guide for Exam Preparation

What is a Network Protocol?

Definition:
A network protocol is a set of rules and conventions that govern how data is formatted, transmitted, and received across a network.
Protocols define the syntax, semantics, and timing of communication between two or more devices.

Three Essential Elements of a Protocol

Syntax

• The structure and format of data

• Order of fields in a message

• Binary encoding rules

Example: An HTTP request has method, URL, headers in a specific order

Semantics

• The meaning of each section of bits

• What action to take when a field is received

• Error handling procedures

Example: A TCP ACK means "I received your data successfully"

Timing

• When and how fast data is sent

• Response time requirements

• Synchronization rules

Example: TCP retransmits after a timeout if no ACK is received

Common Mistake: A protocol is NOT just about data format. It also defines timing (when to send), semantics (what each message means), and error recovery (what to do on failure). All three elements are required.

Protocol Classification

Criterion Types Examples
By Function Data Transfer, Routing, Error Detection, Security FTP, OSPF, CRC, SSL/TLS
By Layer Physical, Data Link, Network, Transport, Application Ethernet, IP, TCP, HTTP
By Connection Connection-oriented, Connectionless TCP, UDP
By Communication Synchronous, Asynchronous TCP, UDP
Connection-Oriented vs Connectionless:
Connection-oriented: 3-way handshake → Data Transfer → Connection Termination
Connectionless: Each packet is sent independently without prior setup (e.g., UDP, IP).
3-Way Handshake (TCP Connection Setup):
Step 1: Client → SYN → Server
Step 2: Server → SYN-ACK → Client
Step 3: Client → ACK → Server
After these three steps, a reliable connection is established.

OSI Reference Model (7 Layers)

Definition:
The OSI (Open Systems Interconnection) Model is a conceptual framework that standardizes network communication into seven distinct layers.
Developed by ISO in 1984 to enable interoperability between different systems and vendors.

Seven Layers Overview

Layer # Name PDU (Data Unit) Key Protocols Functions
7 Application Data HTTP, FTP, SMTP, DNS, SNMP User interface, network services
6 Presentation Data SSL/TLS, JPEG, ASCII, MPEG Data formatting, encryption, compression
5 Session Data NetBIOS, RPC, PPTP Session management, synchronization
4 Transport Segment / Datagram TCP, UDP End-to-end delivery, flow control, error recovery
3 Network Packet IP, ICMP, ARP, OSPF, RIP Routing, logical addressing (IP)
2 Data Link Frame Ethernet, PPP, HDLC, ARP Physical addressing (MAC), error detection
1 Physical Bits RS-232, USB, Bluetooth, DSL Bit transmission over physical medium

Detailed Layer Descriptions

Layer 7 — Application Layer:
Provides network services directly to end-user applications.
Protocols: HTTP (web), FTP (file transfer), SMTP (email), DNS (name resolution), SNMP (management), Telnet (remote access).
Layer 6 — Presentation Layer:
Translates, encrypts, and compresses data between the application and the network.
Functions: Data translation (ASCII ↔ EBCDIC), encryption/decryption (SSL/TLS), compression (ZIP, JPEG).
Layer 5 — Session Layer:
Establishes, manages, and terminates sessions between applications.
Controls: Dialog control (half-duplex/full-duplex), synchronization (checkpoints for recovery), session restoration.
Layer 4 — Transport Layer:
Provides reliable (TCP) or unreliable (UDP) end-to-end data delivery.
Key functions: Segmentation & reassembly, flow control (windowing), error detection & correction, port addressing.
Layer 3 — Network Layer:
Handles logical addressing and routing of packets across multiple networks.
Key protocols: IP (IPv4/IPv6), ICMP, OSPF, RIP, BGP. Devices: Routers.
Layer 2 — Data Link Layer:
Provides node-to-node data transfer and handles error detection at the frame level.
Sub-layers: LLC (Logical Link Control) and MAC (Media Access Control). Devices: Switches, Bridges. Address: MAC (48-bit).
Layer 1 — Physical Layer:
Transmits raw binary bits over a physical medium.
Defines: Voltage levels, cable specifications, pin layouts, data rates, encoding (NRZ, Manchester).
Common Mistake: ARP operates at Layer 2 (Data Link) because it maps IP addresses to MAC addresses using broadcast frames. It is NOT a Layer 3 protocol despite dealing with IP addresses.
Common Mistake: The OSI model is a reference framework — real-world networks primarily use the TCP/IP model. OSI is for understanding and standardization, not direct implementation.

TCP/IP Model (4 Layers)

Definition:
The TCP/IP Model is a practical, 4-layer networking model that serves as the foundation of the modern Internet.
Unlike OSI's 7 layers, TCP/IP combines some layers for simplicity and is the model actually used in real-world networking.

Four Layers of TCP/IP

Layer OSI Equivalent PDU Protocols & Technologies Description
Application Layers 7, 6, 5 Data HTTP, FTP, SMTP, DNS, SSH, Telnet, SNMP All application-level communication combined into one layer
Transport Layer 4 Segment / Datagram TCP, UDP End-to-end data delivery and flow control
Internet Layer 3 Packet IP (v4/v6), ICMP, ARP, IGMP Logical addressing and routing across networks
Network Access Layers 2, 1 Frame / Bits Ethernet, Wi-Fi, PPP, DSL, Token Ring Physical transmission and data link framing combined

Common Mistake: Do not confuse the TCP/IP "Internet" layer with the OSI "Network" layer. They serve similar functions (routing, logical addressing) but are not identical. The TCP/IP Internet layer includes ICMP and ARP, which OSI places at different layers.
Encapsulation Process (Sending Data):
Application Data → Transport Header (+ Segment) → IP Header (+ Packet) → Frame Header/Trailer (+ Frame) → Bits
Each layer adds its own header (and sometimes trailer) as data moves down the stack. The reverse process (decapsulation) happens at the receiver.
PDU Names per Layer:
Application: Data → Transport: Segment (TCP) / Datagram (UDP) → Network: Packet → Data Link: Frame → Physical: Bits
Each layer wraps the upper layer's PDU inside its own PDU. This is called encapsulation.
SENDER: ┌──────────────┐ │ Application │ Data └──────┬───────┘ ▼ ┌──────────────┐ │ Transport │ +TCP/UDP Header → Segment └──────┬───────┘ ▼ ┌──────────────┐ │ Internet │ +IP Header → Packet └──────┬───────┘ ▼ ┌──────────────┐ │ Network Access │ +Frame Header/Trailer → Frame → Bits └──────────────┘

Port Numbers & Socket Addresses

Definition — Port Number:
A 16-bit number (0–65535) that identifies a specific process or service on a host.
Ports allow multiple applications on the same host to share a single IP address for network communication.

Port Number Ranges

Range Category Usage
0 – 1023 Well-Known Ports Reserved for standard services (HTTP=80, FTP=21, SSH=22, SMTP=25, DNS=53)
1024 – 49151 Registered Ports Assigned to vendor applications (MySQL=3306, RDP=3389)
49152 – 65535 Dynamic / Private Ports Temporarily assigned to client processes by the OS
Socket Address Definition:
Socket = IP Address + Port Number
A socket uniquely identifies one endpoint of a connection. Example: 192.168.1.1:80 identifies a web server process.
Full TCP Connection (5-Tuple):
(Source IP, Source Port, Destination IP, Destination Port, Protocol)
This 5-tuple uniquely identifies every TCP/UDP connection. Example: (192.168.1.5, 49152, 93.184.216.34, 80, TCP)

Worked Examples & Practice Problems

Example 1: Identify the Protocol Layer

Question: A router forwards packets based on IP addresses. At which OSI layer does the router operate?

Solution:

• Routers use IP addresses to make forwarding decisions

• IP is a Layer 3 (Network Layer) protocol

• Routers examine the IP header to determine the next hop

Answer: Layer 3 (Network Layer)

Example 2: TCP vs UDP Selection

Question: You are designing a real-time video conferencing application. Should you use TCP or UDP? Justify your answer.

Solution:

• Real-time video cannot tolerate delays from retransmissions

• UDP provides lower latency (no connection setup, no retransmission waits)

• Losing a few video frames is acceptable; delays are not

• TCP's reliability mechanisms add unacceptable latency for live streaming

Answer: UDP — because real-time applications prioritize speed over reliability. Lost packets cause minor glitches, but TCP retransmissions cause lag.

Example 3: DNS Resolution Process

Question: When a user types "www.example.com" in a browser, trace the DNS resolution process step by step.

Solution:

1. Browser checks local cache for "www.example.com"

2. If not found, OS checks its DNS cache

3. If still not found, query is sent to the configured DNS resolver (ISP's DNS server)

4. Resolver checks its cache; if miss, it queries the Root DNS server

5. Root server directs to the .com TLD (Top-Level Domain) server

6. TLD server directs to example.com's authoritative DNS server

7. Authoritative server returns the IP address (e.g., 93.184.216.34)

8. Resolver caches the result and returns it to the client

9. Browser initiates TCP connection to 93.184.216.34 on port 80 (HTTP) or 443 (HTTPS)

Answer: Browser → Local Cache → DNS Resolver → Root → TLD (.com) → Authoritative → IP returned → TCP connection established

Example 4: Port Number Identification

Question: A server has IP 10.0.0.5. A client connects to it for web browsing (HTTP). Write the full socket address for both ends of the connection.

Solution:

• Server socket: 10.0.0.5:80 (IP + HTTP port)

• Client socket: 10.0.0.12:49200 (client IP + ephemeral port from dynamic range)

• Full connection 5-tuple: (10.0.0.12, 49200, 10.0.0.5, 80, TCP)

Answer: Server = 10.0.0.5:80, Client = 10.0.0.12:49200 (dynamic port)

Example 5: Encapsulation Walkthrough

Question: When an email is sent via SMTP, trace the data through the TCP/IP layers. What is the PDU at each layer?

Solution:

1. Application Layer: Email content is formatted as an SMTP message → PDU: Data

2. Transport Layer: Data is segmented and wrapped with TCP header (port 25) → PDU: Segment

3. Internet Layer: Segment is wrapped with IP header (source & destination IP) → PDU: Packet

4. Network Access Layer: Packet is wrapped with Ethernet header (MAC addresses) and trailer (FCS) → PDU: Frame

5. Physical Layer: Frame is converted to electrical/optical signals → PDU: Bits

Answer: Data → Segment → Packet → Frame → Bits (encapsulation at each layer)

Exam Tip: When asked about protocol layers, always think: "What is the device/protocol primarily concerned with?" If it's about IP addresses → Layer 3. MAC addresses → Layer 2. Ports → Layer 4. Application data → Layer 7.
Exam Tip: For the 3-way handshake question, remember: SYN → SYN-ACK → ACK. The connection teardown is 4-way: FIN → ACK → FIN → ACK.
