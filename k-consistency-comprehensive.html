K-Consistency

Node Consistency, Arc Consistency, Path Consistency & Beyond

The Consistency Hierarchy

K-consistency is a family of consistency properties organized by the number of variables considered simultaneously.

General Definition:
A CSP is K-consistent if for any (K-1) variables and any consistent assignment to those variables, there exists a value for any k-th variable such that all constraints are satisfied.
Higher K means stronger consistency but more expensive to enforce
KNameMeaning
1Node ConsistencyEach variable is consistent with itself (no unary violations)
2Arc ConsistencyEach pair of variables is consistent (binary constraints)
3Path ConsistencyEach triple of variables is mutually consistent
.........
nn-ConsistencyStrong enough to solve without backtracking
Key Tradeoff: Higher K-consistency reduces search but the algorithm to enforce K-consistency has exponential complexity in K. In practice, K between 2 and 3 (arc consistency or path consistency) gives the best balance.

Consistency Levels Explained

1-Consistency (Node Consistency)

Each variable's domain is consistent with itself. Simply remove any values that violate unary constraints.

1-Consistent: ∀Xi, ∀x ∈ Di: x satisfies all unary constraints on Xi

2-Consistency (Arc Consistency)

For every pair of variables connected by a constraint, each value in one domain has a compatible value in the other.

2-Consistent = Arc Consistent

3-Consistency (Path Consistency)

For every triple of variables (Xi, Xj, Xk), every consistent assignment to (Xi, Xj) can be extended to a consistent assignment with Xk.

Path Consistency:
For any consistent (xi, xj), ∃xk such that (xi, xk) and (xj, xk) are also consistent

Strongly K-Consistent

A CSP is strongly K-consistent if it is consistent for all levels 1 through K (i.e., 1-consistent, 2-consistent, ..., K-consistent).

Strongly K-Consistent:
Strongly K-Consistent = 1-Consistent ∧ 2-Consistent ∧ ... ∧ K-Consistent
Key Theorem: If a CSP with n variables is strongly n-consistent, it can be solved without backtracking. Simply assign values in any order — there will always be a compatible value for the next variable. But achieving n-consistency is exponential.

Worked Examples

Example 1: Node Consistency — Preprocessing

Original: Variable SA with domain {red, green, blue}, Unary constraint: SA ≠ green

Node consistency removes green from SA's domain.

After: DSA = {red, blue}

Node consistency achieved with O(d) work

Example 2: Path Consistency Detects Subtle Conflict

Variables: X, Y, Z with domains {a, b}

Constraints: X=Y, Y≠Z, X≠Z

Arc consistency check:

• (X,Y): X=a → Y=a, X=b → Y=b ✓

• (Y,Z): Y=a → Z=b, Y=b → Z=a ✓

• (X,Z): X=a → Z=b, X=b → Z=a ✓

Arc consistency says it's fine! But is there actually a solution?

No! X=Y means X and Y are the same, but X≠Z and Y≠Z means both differ from Z. This is impossible with 2 values. Path consistency (3-consistency) would detect this.

Path consistency catches what arc consistency misses!

Example 3: Solving Without Backtracking with n-Consistency

Variables: A, B, C with DA={1,2}, DB={1,2}, DC={1,2}

Constraints: A≠B, B≠C, A≠C

If we achieve 3-consistency (path) but not strong 3-consistency:

After arc consistency: all domains remain {1,2}. But there's no solution (3 variables, 2 values, all must be different).

True path consistency would detect: (A=1, B=2) cannot be extended to C (C would need a 3rd value).

n-consistency would detect this, but is expensive (exponential for n).

Example 4: Practical Level Selection

In practice, we choose a specific K based on:

  • • K=1 (Node): Trivial preprocessing, always worth doing
  • • K=2 (Arc): Best cost-benefit ratio; standard in most CSP solvers
  • • K=3 (Path): Used for harder problems, but O(n³·d³+) cost
  • • K>3: Usually too expensive; better to use search with heuristics

There's a spectrum from arc consistency to n-consistency. The right level depends on the problem.

Key Insight

Strong K-consistency means consistency at all levels ≤ K. A strongly n-consistent CSP with n variables can be solved without any backtracking.

Practical Advice

• Always do node consistency

• Always do arc consistency

• Consider path consistency for hard problems

• Use search for the rest
