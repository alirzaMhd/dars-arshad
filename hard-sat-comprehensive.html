Phase Transition in Random k-CNF

When studying satisfiability of random CNF formulas, we fix the number of symbols n and vary the number of clauses m. The ratio m/n (clauses-to-symbols ratio) controls difficulty.

Critical Ratio Formula
m/n ≈ 4.267 for random 3-CNF
For 3-CNF formulas with n = 50 symbols, the phase transition occurs near m/n ≈ 4.3. Below this ratio, formulas are almost always satisfiable; above it, almost always unsatisfiable.

Phase Transition Behavior

Small m/n (under-constrained)

Few clauses relative to variables. Most random assignments satisfy the formula. Probability of satisfiability ≈ 1.

Easy to solve

Critical m/n (phase transition)

Near m/n ≈ 4.3 for 3-CNF. Probability of satisfiability drops sharply from ~1 to ~0. This is where the hardest problems occur.

Hardest problems

Large m/n (over-constrained)

Many clauses relative to variables. Almost all assignments violate some clause. Probability of satisfiability ≈ 0.

Easy to prove unsatisfiable

Phase Transition Graph Description

Imagine a graph where:

  • X-axis: Ratio m/n (clauses per symbol), ranging from 0 to 10+
  • Y-axis: Probability that a random 3-CNF formula is satisfiable, ranging from 0 to 1
  • The curve stays near 1.0 for small m/n values
  • Drops sharply near m/n ≈ 4.267 (the critical point)
  • Approaches 0 for large m/n values
The sharpness of the transition increases with n. For n = 50, the transition is quite steep; for n = 1000, it is nearly a step function.

Why Does This Happen?

Each clause rules out roughly 1/8 of all possible assignments (for 3-CNF with random literals). When m/n is small, clauses rule out a small fraction of the space, leaving many solutions. When m/n is large, the clauses collectively rule out nearly all assignments. The critical point is where the "exclusion power" of clauses exactly matches the "solution density."

Under-Constrained Problems (Easy to Solve)

Example: N-Queens with Small N

For the N-Queens problem with small N (e.g., N = 8), solutions are densely distributed in the search space. For any partial assignment, a solution is likely nearby. WalkSAT finds solutions quickly because the minimum-conflicts heuristic always has a good move available.

In random SAT terms: when m/n is small, many satisfying assignments exist. A random initial assignment is likely close to a solution, and local search converges rapidly.

Over-Constrained Problems (Hard to Determine)

Example: Proving Unsatisfiability

When m/n is large, almost no satisfying assignments exist. WalkSAT will fail to find a model, but it cannot prove the formula is unsatisfiable — it simply reports failure. To prove unsatisfiability, you need a complete search algorithm like DPLL.

Proving unsatisfiability requires examining the entire search space (or a proof tree). DPLL can do this by exhaustively exploring all branches and showing each one leads to a contradiction.

Warning: WalkSAT returning "failure" does NOT prove unsatisfiability. The agent might say "I thought about it for an hour and couldn't find a world where this square is unsafe," but this is not a proof. For safety-critical decisions, use DPLL.

Critical Region: The Hardest Problems

Key Result
DPLL average steps < 1000 vs Truth Table 2^50 ≈ 10^15
Even at the critical point (hardest problems), DPLL performs remarkably well — averaging fewer than 1000 steps, compared to 2^50 steps needed for exhaustive truth table enumeration.

Three key observations about the critical region:

  1. Problems near the critical point are much harder than random problems elsewhere
  2. Even the hardest problems are tractable for DPLL (average < 1000 steps)
  3. WalkSAT is much faster than DPLL in this region (local search excels)

Real-World vs Random Problems

Important Caveat: The phase transition results apply to randomly generated SAT problems. Real-world problems have very different structure — they are not random.

Structural Differences

Property Random SAT Real-World SAT
Clause structure Random literals, uniform distribution Structured, domain-specific patterns
Positive/negative literal ratio ~50/50 Varies by domain
Clause density Uniform across formula Clustered (some variables appear in many clauses)
Scale Typically n < 1000 n can be millions

Industrial SAT Solvers

CHAFF

One of the first industrial-strength SAT solvers. Handles problems with millions of variables and millions of clauses. Uses clever indexing, unit propagation, and conflict-driven clause learning.

Modern Solvers

MiniSAT, Glucose, Z3, and others. Combine DPLL with clause learning, restarts, and clever variable heuristics. Used in hardware verification, planning, and scheduling.

Why Real Problems Are Easier Than Random

Real-world SAT instances often have hidden structure that solvers can exploit:

  • Community structure: Variables cluster into loosely connected groups
  • Backbone variables: Some variables have the same value in all solutions
  • Symmetry: Problem symmetries can be detected and exploited
  • Clause learning: Solvers learn from conflicts to prune future search
Practical Impact
CHAFF: millions of variables, millions of clauses
Industrial SAT solvers combining minimum conflicts heuristics with random walk and clause learning provide general-purpose capability for combinatorial reasoning.

3-CNF: The Standard Form

3-CNF means each clause has exactly 3 literals. This is the most studied case because:

  • 3-SAT is the simplest NP-complete SAT variant
  • Any k-SAT can be reduced to 3-SAT (introducing auxiliary variables)
  • 3-CNF has clean theoretical properties (phase transition at m/n ≈ 4.267)
  • Practical solvers handle 3-CNF efficiently

Worked Examples

Example 1: Analyzing a Random 3-CNF Formula

Consider a random 3-CNF with n = 5 symbols and m = 5 clauses:

(-D ∨ -B ∨ C) ∧ (B ∨ -A ∨ -C) ∧ (-C ∨ -B ∨ E) ∧ (E ∨ -D ∨ B) ∧ (B ∨ E ∨ -C)

Step 1: Calculate the ratio m/n = 5/5 = 1.0. This is well below the critical ratio of 4.3, so the formula is likely satisfiable.

Step 2: Number of possible assignments = 2^5 = 32. The text states 16 of these 32 assignments are models (satisfying assignments).

Step 3: With 16 out of 32 assignments being solutions, a random guess has a 50% chance of finding a model. On average, only 2 random guesses are needed.

Conclusion: This is an under-constrained problem — very easy to solve.
