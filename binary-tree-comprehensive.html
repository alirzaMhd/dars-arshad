Binary Trees & Array Representation

Data Structures — Complete Guide for 20/20 Exam

What is a Binary Tree?

A binary tree is a rooted tree where every node has at most 2 children, called the left child and right child. The left and right children are distinguished — they are NOT interchangeable.

⚠ Key distinction: A binary tree is NOT the same as a general tree. In a binary tree, order matters — left child ≠ right child even if they contain the same data.
a ← Root / \ b c ← b is left child, c is right child / \ \ d e f ← d is left child of b, e is right child of b ← f is right child of c (no left child)

Formal Definition

A binary tree is either:

1. Empty (null/nil), or

2. A node with a left subtree (binary tree) and a right subtree (binary tree)

Recursive Definition:
BinaryTree = ∅ | Node(Data, BinaryTree, BinaryTree)
A binary tree is either empty or a node containing data and two binary tree subtrees.

Number of Possible Binary Trees

Unlabeled Binary Trees (Structural):
Catalan(n) = C(2n, n) / (n+1) = (2n)! / ((n+1)! · n!)
The number of structurally different binary trees with n nodes.
Labeled Binary Trees:
n! × Catalan(n)
The number of binary trees with n distinct keys (labeled nodes).
Example: Binary Trees with 3 Nodes

With 3 nodes, there are Catalan(3) = 5 structural forms:

a a a a a / / \ \ \ b b b b b \ \ / \ / c c c c c

If nodes are labeled {a, b, c}, there are 3! × 5 = 30 different trees.

Example: Binary Trees with 4 Nodes

Catalan(4) = 14 structural forms.

Labeled: 4! × 14 = 336 different trees.

Special Types of Binary Trees

Full Binary Tree

A binary tree where every internal node has exactly 2 children. All nodes are either leaves or have 2 children.

a ← Full: both children present / \ b c ← b: 2 children, c: leaf / \ d e ← d,e: both leaves
Full Binary Tree Properties:
n₀ = n₂ + 1 (leaves = 2-children + 1)
n₀ = leaves, n₂ = nodes with 2 children. Total nodes = 2·n₂ + 1 (always odd).

Complete Binary Tree

A binary tree where all levels are completely filled except possibly the last level, which is filled from left to right.

a ← Complete: levels 0,1 full / \ b c ← Level 1 full / \ / \ d e f g ← Level 2 full ↑ Last level filled left-to-right
⚠ Every full binary tree is complete, but NOT every complete tree is full. The last level doesn't need to be full in a complete tree.
Complete Binary Tree with n nodes:
Height = ⌊log₂(n)⌋
The height is the floor of log base 2 of n. Number of levels = ⌊log₂(n)⌋ + 1.
Nodes in Last Level:
leaves = n - (2^h - 1) = n - 2^h + 1
Where h = ⌊log₂(n)⌋. The last level has between 1 and 2^h nodes.

Perfect Binary Tree

A binary tree that is both full and complete. All levels are completely filled.

a ← Perfect: all levels full / \ b c / \ / \ d e f g

Skewed Binary Tree

A binary tree where every node has only one child (either always left or always right). This is the worst case for most operations.

Left-Skewed

a \ b \ c \ d

Right-Skewed

d / c / b / a
⚠ For a skewed binary tree with n nodes: height = n - 1 (maximum possible). This is the worst case for search, insertion, and deletion — essentially a linked list!

Array Representation of Binary Trees

Binary trees (especially complete binary trees) can be efficiently stored in an array using level-order indexing.

Index Formulas (1-based indexing):
Parent(i) = ⌊i/2⌋
LeftChild(i) = 2i (if 2i ≤ n)
RightChild(i) = 2i + 1 (if 2i + 1 ≤ n)
For a node at index i: parent is at ⌊i/2⌋, left child at 2i, right child at 2i+1.
Example: Complete Binary Tree → Array

Tree Structure

a (1) / \ b(2) c(3) / \ / d(4) e(5) f(6)

Array Storage

Index123456
Valueabcdef

Verification:

• Parent(4) = ⌊4/2⌋ = 2 → d's parent is b ✓

• LeftChild(2) = 2×2 = 4 → b's left child is d ✓

• RightChild(2) = 2×2+1 = 5 → b's right child is e ✓

• LeftChild(3) = 2×3 = 6 → c's left child is f ✓

⚠ Array representation is efficient for COMPLETE binary trees (no gaps). For skewed or incomplete trees, it wastes space because we must allocate for the maximum possible index.
Array Size Requirements:
Complete tree with n nodes: array size = n
Left-skewed tree with n nodes: array size = 2^n - 1
Right-skewed tree with n nodes: array size = 2^n - 1
Example: Minimum Array Size for Non-Complete Tree

Given a binary tree that is NOT complete, what is the minimum array size needed?

a / b \ c / \ d e

Solution:

Assign indices: a=1, b=2, (c=5 since b's right child), d=10, e=11

Minimum array size = 11 (to accommodate index 11)

This is much worse than storing just 5 nodes!

Example: Array for Left-Skewed Tree

A left-skewed tree with n=4 nodes:

a (index 1) \ b (index 3) \ c (index 7) \ d (index 15)

Minimum array size: 15 (2^4 - 1 = 15)

Only 4 out of 15 positions used → 73% wasted space!

Example: Finding Tree from Array

Given array: [_, a, b, c, d, e, _, f] (index 0 unused)

Solution:

a (1) / \ b(2) c(3) / \ \ d(4) e(5) f(7)

Index 6 is empty, so c has no left child but has right child f at index 7.

Linked Representation of Binary Trees

The most common representation uses a linked structure where each node has three fields: data, left pointer, and right pointer.

Node Structure (C/C++):
struct node {
  int data;
  struct node *left;
  struct node *right;
};
Node Structure (Pascal):
type TTree = ^Node;
Node = record
  data: integer;
  left: TTree;
  right: TTree;
end;
Memory Layout: ┌─────────────┐ │ data: 'a' │ │ left: ──────┼──→ [Node b] │ right: ─────┼──→ [Node c] └─────────────┘ Node b: Node c: ┌─────────────┐ ┌─────────────┐ │ data: 'b' │ │ data: 'c' │ │ left: ──────┼──→ d │ left: NULL │ │ right: ─────┼──→ e │ right: ─────┼──→ f └─────────────┘ └─────────────┘

Advantages of Linked Representation

✓ Advantages

• No wasted memory

• Easy to insert/delete nodes

• Works for any tree structure

• Dynamic size

✗ Disadvantages

• Extra memory for pointers

• No random access

• Pointer overhead

Memory Usage:
n nodes → n × (data_size + 2 × pointer_size)
For 4-byte int and 8-byte pointers: n × (4 + 16) = 20n bytes.

Parent Pointer Representation

Another linked approach: each node stores a pointer to its parent instead of children.

Node with Parent Pointer:
struct node {
  int data;
  struct node *parent;
};
⚠ With parent pointers, finding children requires traversing the entire tree — O(n). Finding parent is O(1). This representation is rarely used alone but is useful in union-find data structures.

Worked Examples

Example 1: Counting Structural Binary Trees

How many structurally different binary trees exist with 4 nodes?

Solution:

Catalan(4) = C(8,4) / 5 = 70 / 5 = 14

Example 2: Array for Complete Binary Tree

A complete binary tree has 10 nodes. What is the minimum array size?

Solution:

For a complete tree with n nodes, array size = n = 10

All indices 1 through 10 are used.

Example 3: Array for Non-Complete Tree

What is the minimum array size for this tree?

a / \ b c / d

Solution:

Indices: a=1, b=2, c=3, d=4

This IS a complete tree! Array size = 4

Example 4: Finding Missing Nodes

Given array [_, A, B, _, C, _, D], which nodes are missing?

Solution:

Index 1: A (root), Index 2: B (left child of A)

Index 3: _ (A has no right child)

Index 4: _ (B has no left child)

Index 5: C (right child of B)

Index 6: _ (C has no left child)

Index 7: D (right child of C)

A / B \ C \ D
Example 5: Space Efficiency Comparison

Compare array vs linked storage for a complete binary tree with 15 nodes.

Solution:

Array (1-based)

Size: 15 slots

Wasted: 0%

Very efficient!

Linked

15 nodes × (4 + 16) = 300 bytes

No wasted space

Pointer overhead

Example 6: Skewed Tree Array Size

A right-skewed tree with 5 nodes: a → b → c → d → e. What array size is needed?

Solution:

Indices: a=1, b=3, c=7, d=15, e=31

Array size: 31 (2^5 - 1)

Only 5/31 = 16% utilized!

Example 7: Complete Tree Height Calculation

A complete binary tree has 1000 nodes. What is its height?

Solution:

Height = ⌊log₂(1000)⌋

Since 2^9 = 512 and 2^10 = 1024: ⌊log₂(1000)⌋ = 9

Height = 9, so 10 levels needed

Level 0: 1 node, Level 1: 2, ..., Level 9: 512 nodes (total 1023)

Actual: 1000 nodes, so 1000 - 511 = 489 nodes at level 9

Example 8: Number of Trees with 4 Nodes

How many structurally different binary trees with 4 nodes? How many labeled trees?

Solution:

Catalan(4) = C(8,4)/5 = 70/5 = 14 structural forms

Labeled trees: 4! × 14 = 24 × 14 = 336 labeled trees

Example 9: Null Pointer Derivation

Why does a binary tree with n nodes have exactly n+1 null pointers?

Derivation:

1. Total pointers in tree = 2n (each node has left and right)

2. Non-null pointers = n - 1 (only parent-to-child links, root has no parent)

3. Null pointers = 2n - (n-1) = n + 1

Example: Tree with 5 nodes → 6 null pointers

When to Use Each Representation

Use Array When:

• Tree is complete/nearly complete

• Need random access

• Memory is not a concern

Use Linked When:

• Tree is incomplete/skewed

• Need frequent insertions/deletions

• Tree size changes dynamically
