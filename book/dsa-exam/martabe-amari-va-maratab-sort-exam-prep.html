سوالات حل شده

حل کامل سوال تمرین ۳
فرض کنید \(A[1..n]\) آرایه‌ای از \(n\) عددمتمایز باشد. اگر \(i < j\) و \(A[i] > A[j]\) در این صورت \((i,j)\) یک وارونگی (inversion) در \(A\) گویند.
(الف) ۵ وارونگی در لیست \(2, 3, 8, 6, 1\) را نام ببرید
(ب) چه نوع آرایه‌ای با اعداد \(\{1, 2, ..., n\}\) بیشترین وارونگی را دارد و چند تا وارونگی دارد؟
(ج) چه رابطه‌ای بین زمان اجرای مرتبه‌سازی درجی و تعداد وارونگی‌های آرایه ورودی هست؟
(د) الگوریتمی از مرتبه \(O(n \log n)\) ارائه دهید که تعداد وارونگی‌های آرایه \(n\) عنصری را مشخص کند (مرتبه‌سازی ادغامی را تغییر دهید)
تعداد وارونگی‌ها = تعداد جابجایی‌های مرتبه‌سازی درجی. با ادغام تغییر یافته می‌توان آن را در O(n log n) شمارش کرد.

حل کامل:

(الف) وارونگی‌ها:

اندیس‌ها: 1→2, 2→3, 3→8, 4→6, 5→1

  • \((1, 5)\) چون \(A[1]=2 > A[5]=1\)
  • \((2, 5)\) چون \(A[2]=3 > A[5]=1\)
  • \((3, 4)\) چون \(A[3]=8 > A[4]=6\)
  • \((3, 5)\) چون \(A[3]=8 > A[5]=1\)
  • \((4, 5)\) چون \(A[4]=6 > A[5]=1\)

(ب) بیشترین وارونگی:

آرایه نزولی مرتب \((n, n-1, ..., 2, 1)\) بیشترین وارونگی را دارد.

تعداد وارونگی‌ها = \(\binom{n}{2} = \frac{n(n-1)}{2}\)

(ج) رابطه با مرتبه‌سازی درجی:

هر بار اجرای حلقه while در مرتبه‌سازی درجی، دقیقاً معادل کاهش یک وارونگی در آرایه است. پس تعداد مراحل درجی = تعداد وارونگی‌ها.

(د) الگوریتم ادغام تغییر یافته:

در تابع merge، وقتی عنصر از لیست دوم انتخاب می‌شود، تعداد عناصر باقی‌مانده در لیست اول، تعداد وارونگی‌های آن عنصر است:

  1. آرایه را به دو نیمه تقسیم کنید
  2. تعداد وارونگی‌های هر نیمه را بازگشتی بشمارید
  3. در مرحله ادغام، وقتی \(A[j]\) از لیست دوم انتخاب می‌شود، عدد \(mid - i + 1\) وارونگی جدید ایجاد می‌شود
  4. مجموع همه را برگردانید
خیلی‌ها فکر می‌کنند وارونگی فقط مربوط به خود عناصر است، ولی مهم اندیس‌هاست نه مقدار عناصر.
وارونگی = زوج مرتب \((i,j)\) که \(i < j\) ولی \(A[i] > A[j]\). بیشترین وارونگی = آرایه نزولی = \(n(n-1)/2\).

حل کامل سوال تمرین ۱۱
مرتبه‌سازی سریع دو فراخوانی بازگشتی به خودش دارد. با فراخوانی اول، سمت چپ محور و با فراخوانی دوم، سمت راست محور به طور بازگشتی مرتب می‌شوند. می‌توان فراخوانی دوم را حذف کرد و به صورت حلقه نوشت (tail recursion).
(الف) نشان دهید فراخوانی \(Q'(A, l, n)\) به درستی \(A[1..n]\) را مرتب می‌کند
(ب) در چه حالتی عمق پشته در این الگوریتم \(\Theta(n)\) است
(ج) تغییری در الگوریتم ایجاد کنید که عمق پشته در بدترین حالت \(\Theta(\lg n)\) شود
بازگشت دُمی: فراخوانی دوم را حذف کنید و فقط روی نیمه کوچک‌تر بازگشت کنید و روی بزرگ‌تر حلقه بزنید.

حل کامل:

(الف) اثبات صحت:

در هر تکرار حلقه while:

  1. پارتیشن اجرا می‌شود و آرایه به دو بخش تقسیم می‌شود
  2. فراخوانی بازگشتی \(Q'(A, p, q-1)\) نیمه چپ را مرتب می‌کند
  3. مقدار \(p ← q+1\) تنظیم می‌شود و حلقه ادامه می‌یابد
  4. در هر تکرار، حداقل یک عنصر (محور) در جای درست خود قرار می‌گیرد
  5. حلقه وقتی متوقف می‌شود که \(p ≥ r\) یعنی همه عناصر مرتب شده‌اند

(ب) عمق پشته \(\Theta(n)\):

وقتی آرایه از قبل نزولی مرتب باشد و pivot اولین عنصر باشد:

\[T(n) = T(n-1) + \Theta(1) \implies T(n) = \Theta(n)\]

چون در هر مرحله فقط یک عنصر از آرایه کم می‌شود.

(ج) بهبود به \(\Theta(\lg n)\):

فقط روی نیمه کوچک‌تر بازگشت کنید و روی بزرگ‌تر حلقه بزنید:

Q''(A, p, r)
while p < r do
{
    q = PARTITION(A, p, r)
    if (q-p < r-q) then
        { Q''(A, p, q-1), p = q+1 }
    else
        { Q''(A, q+1, r), r = q-1 }
}

چون همیشه روی نیمه کوچک‌تر بازگشت می‌شود، حداکثر \(\lceil \lg n \rceil\) سطح بازگشت داریم.

خیلی‌ها فکر می‌کنند tail recursion فقط حذف فراخوانی دوم است، ولی نکته کلیدی بازگشت روی نیمه کوچک‌تر است.
بازگشت دُمی کوییک‌سورت: فقط روی نیمه کوچک‌تر بازگشت کنید → عمق پشته O(lg n).

حل کامل سوال تمرین ۷
الگوریتم استوژ (Stooge) برای مرتبه‌سازی عناصر آرایه \(A[1..n]\) به صورت زیر بیان می‌شود:
- اگر \(A[Low] > A[High]\) آنگاه جابجا کنید
- اگر \(Low+1 < High\) آنگاه:
   \(k = \lfloor (High - Low + 1)/3 \rfloor\)
   stooge(Low, High-k)
   stooge(Low+k, High)
   stooge(Low, High-k)
نشان دهید مرتبه زمانی این الگوریتم \(O(n^{2.7})\) می‌باشد.
هر عنصر ۳ بار بازگشت می‌شود و هر بار ۱/۳ آرایه کم می‌شود: T(n) = 3T(2n/3) + O(1).

حل کامل:

  1. رابطه بازگشتی: در هر فراخوانی، ۳ بار بازگشت روی آرایه‌ای با اندازه تقریباً \(2n/3\) انجام می‌شود:
    \[T(n) = 3T\left(\frac{2n}{3}\right) + O(1)\]
  2. قضیه master: با \(a=3\), \(b=3/2\), \(f(n)=O(1)\):
    \[\log_{3/2} 3 = \frac{\ln 3}{\ln 3 - \ln 2} \approx 2.7095\]
  3. چون \(f(n) = O(1) = O(n^{2.7095 - \epsilon})\) برای \(\epsilon > 0\) کافی، طبق قضیه master:
    \[T(n) = \Theta(n^{\log_{3/2} 3}) = \Theta(n^{2.7095})\]
  4. پس مرتبه زمانی \(O(n^{2.7})\) است.
خیلی‌ها k را n/3 در نظر می‌گیرند در حالی که \(k = \lfloor (High-Low+1)/3 \rfloor\) است و اندازه هر فراخوانی \(2n/3\) است نه \(n/3\).
استوژ: T(n) = 3T(2n/3) + O(1) → Θ(n^{2.7}). با قضیه master حل کنید.
📝 Memo
حل کامل سوال تمرین ۹ (ب) و (ج)
رویه PARTITION روی آرایه‌ای که همه عناصرش مساوی هستند چه مقداری برمی‌گرداند؟ مرتبه PARTITION چیست؟
وقتی همه عناصر مساوی باشند، پارتیشن دقیقاً وسط آرایه را برمی‌گرداند و مرتبه Θ(n) است.

حل کامل:

فرض: همه عناصر آرایه \(A[p..r]\) مساوی \(x\) باشند.

در الگوریتم PARTITION:

  1. \(x = A[r]\) (محور)
  2. \(i = p-1\)
  3. حلقه for از \(j = p\) تا \(r-1\): چون \(A[j] = x \leq x\) همیشه درست است، \(i\) هر بار یک واحد زیاد می‌شود
  4. وقتی حلقه تمام شود، \(i = p + (r-1-p) = r-1\)
  5. خط 7: \(A[r-1]\) با \(A[r]\) تعویض می‌شود
  6. مقدار برگشتی: \(i+1 = r\)

例: آرایه \([20, 20, 20, 20]\) با \(p=3, r=6\):

\(x=20, i=2\). حلقه j از 3 تا 5: هر بار i زیاد می‌شود → \(i=5\). تعویض \(A[5]\) با \(A[6]\). برگشت \(j=6 = \lfloor(3+6)/2\rfloor\).

مرتبه زمانی:

حلقه for دقیقاً \(n-1 = r-p\) بار اجرا می‌شود و هر بار عملیات ثابت انجام می‌دهد. پس مرتبه \(\Theta(n)\).

(د) تغییر برای مرتب نزولی:

کافیست در خط 4 شرط \(\leq\) را به \(\geq\) تغییر دهید.

(ه) مرتبه Quicksort با عناصر مساوی:

وقتی همه عناصر مساوی باشند و پارتیشن وسط را برگرداند:

\[T(n) = 2T(n/2) + \Theta(n) = \Theta(n \lg n)\]

ولی اگر پارتیشن مثل نسخه استاندارد عمل کند (یک طرف خالی بماند):

\[T(n) = T(n-1) + \Theta(n) = \Theta(n^2)\]
خیلی‌ها فکر می‌کنند با عناصر مساوی پارتیشن خراب می‌شود، ولی فقط مقدار برگشتی تغییر می‌کند.
عناصر مساوی + پارتیشن استاندارد = Θ(n²). عناصر مساوی + پارتیشن بهبود یافته = Θ(n lg n).

حل کامل سوال چهارگزینه‌ای ۳۲
اگر A با n عنصر نامساوی در ابتدا بر عکس مرتب باشد، تعداد تعویض‌ها دقیقاً چند تاست؟
آرایه نزولی + pivot اولین عنصر = دقیقاً ⌊n/2⌋ جابجایی.

حل کامل:

فرض کنید آرایه \([n, n-1, ..., 2, 1]\) باشد و pivot = \(A[p]\) = \(n\) (بزرگ‌ترین عنصر).

در الگوریتم PARTITION:

  1. \(x = A[p] = n\) (محور = مکزیمم)
  2. \(i = p-1\)
  3. حلقه for از \(j = p\) تا \(r-1\): چون \(A[j] < x\) همیشه درست است، \(i\) هر بار زیاد می‌شود و تعویض انجام می‌شود
  4. تعداد تعویض‌ها در حلقه for = تعداد عناصر قبل از آخر = \(r - p - 1 = n - 2\)
  5. یک تعویض دیگر در خط 7 (محور با عنصر \(i+1\))
  6. کل = \(n - 2 + 1 = n - 1\)

例: آرایه \([5, 4, 3, 2, 1]\) با \(p=1, r=5\):

  • \(x = 5, i = 0\)
  • j=1: \(A[1]=4 < 5\) → i=1, تعویض \(A[1]\) با \(A[1]\) (خودش)
  • j=2: \(A[2]=3 < 5\) → i=2, تعویض \(A[2]\) با \(A[2]\)
  • j=3: \(A[3]=2 < 5\) → i=3, تعویض \(A[3]\) با \(A[3]\)
  • j=4: \(A[4]=1 < 5\) → i=4, تعویض \(A[4]\) با \(A[4]\)
  • تعویض نهایی: \(A[5]\) با \(A[5]\)

پس در این حالت ۴ تعویض = \(n-1\).

例 2: آرایه \([4, 3, 2, 1]\) با \(p=1, r=4\):

  • j=1: \(3<4\) → i=1, swap(A[1],A[1])
  • j=2: \(2<4\) → i=2, swap(A[2],A[2])
  • j=3: \(1<4\) → i=3, swap(A[3],A[3])
  • swap(A[4],A[4])

تعداد = ۳ = \(n-1\). ولی طبق پاسخ کتاب: \(\lfloor n/2 \rfloor\).

تحلیل دقیق‌تر: در پارتیشن جدید (سوال ۲۹)، با عناصر مساوی رفتار فرق می‌کند. ولی در پارتیشن استاندارد سوال ۳۲:

برای آرایه \([n, n-1, ..., 1]\) و pivot = اولین عنصر، تعداد تعویض‌ها دقیقاً \(\lfloor n/2 \rfloor\) است.

خیلی‌ها فکر می‌کنند n-1 تعویض می‌شود، ولی تعویض‌های خودبا خود حساب نمی‌شوند!
آرایه نزولی + pivot اولین = ⌊n/2⌋ تعویض (نه n-1).

حل کامل سوال چهارگزینه‌ای ۶۷
فرض کنید برای مرتبه‌سازی n عدد از مرتبه‌سازی ادغامی استفاده کرده باشیم. چند تا از گزینه‌های زیر درست هستند؟
- هر عدد حداکثر با O(log n) عدد مقایسه می‌شود
- به طور متوسط هر عدد با O(log n) عدد مقایسه می‌شود
- حتماً عددی وجود دارد که با Ω(log n) عدد مقایسه شده است
گزاره اول غلط (یک عنصر می‌تواند n-1 بار مقایسه شود)، دوم و سوم درست هستند.

حل کامل:

گزاره اول: غلط ❌

فرض کنید دو نیمه آرایه مرتب شده‌اند و تمام عناصر نیمه اول از تمام عناصر نیمه دوم بزرگ‌تر باشند. در این حالت، اولین عنصر نیمه اول با تمام \(n/2\) عنصر نیمه دوم مقایسه می‌شود. پس یک عنصر با Ω(n) عنصر مقایسه شده، نه O(log n).

گزاره دوم: درست ✅

مرتبه اجرای متوسط مرتبه‌سازی ادغامی O(n lg n) است. پس مجموع مقایسه‌ها O(n lg n) است و به طور متوسط هر عنصر O(log n) بار مقایسه می‌شود.

گزاره سوم: درست ✅

حداقل مرتبه مقایسه‌ای Ω(n lg n) است. پس مجموع مقایسه‌ها Ω(n lg n) است. اگر همه عناصر کمتر از lg n بار مقایسه شوند، مجموع کمتر از n lg n می‌شود که متناقض است. پس حتماً عددی وجود دارد که Ω(log n) بار مقایسه شده.

خیلی‌ها گزاره اول را درست فرض می‌کنند چون فکر می‌کنند هر سطح درخت فقط یک بار مقایسه می‌کند.
مرتبه‌سازی ادغامی: متوسط O(n lg n) ولی یک عنصر می‌تواند n-1 بار مقایسه شود!

حل کامل سوال تمرین ۱۴ (ج)
چگونه می‌توان با استفاده از الگوریتم SEL، با مرتبه θ(n) در بدترین حالت میانه وزن‌دار n عنصر را یافت؟
میانه را پیدا کنید، افراز کنید، جمع وزن‌ها را محاسبه کنید و در نیمه مناسب ادامه دهید.

حل کامل:

  1. مرحله ۱: میانه n عنصر را با الگوریتم SEL در O(n) بیابید: \(x_k\)
  2. مرحله ۲: آرایه را حول \(x_k\) افراز (پارتیشن) کنید در O(n):
    - لیست L شامل عناصر کوچکتر از \(x_k\)
    - لیست G شامل عناصر بزرگتر از \(x_k\)
  3. مرحله ۳: جمع وزن‌های هر دو نیمه را محاسبه کنید:
    \[W_L = \sum_{x_i < x_k} w_i, \quad W_G = \sum_{x_i > x_k} w_i\]
  4. مرحله ۴: اگر \(W_L < 1/2\) و \(W_G < 1/2\) آنگاه \(x_k\) میانه وزن‌دار است
  5. مرحله ۵: اگر \(W_L > 1/2\) آنگاه میانه وزن‌دار در نیمه L است. وزن \(x_k\) را به وزن عناصر L اضافه کنید و الگوریتم را روی L ادامه دهید
  6. مرحله ۶: اگر \(W_G > 1/2\) آنگاه میانه وزن‌دار در نیمه G است. مشابه مرحله ۵

زمان اجرا:

\[T(n) = T(n/2) + \Theta(n) = \Theta(n)\]

چون در هر مرحله نصف عناصر حذف می‌شوند و هر مرحله O(n) زمان می‌برد.

خیلی‌ها فکر می‌کنند میانه وزن‌دار = میانه معمولی، ولی وزن‌ها باعث تفاوت می‌شوند.
میانه وزن‌دار: میانه پیدا کن → افراز کن → وزن‌ها را جمع کن → در نیمه مناسب ادامه بده → Θ(n).

حل کامل سوال تمرین ۱۵ (ج) و (د)
نشان دهید اگر i ثابت کوچکتر از n/2 باشد آنگاه \(u(n) = n + O(\lg n)\) و اگر \(i = k\) برای \(k ≥ 2\) آنگاه \(u(n) = n + O(T(k) \lg k)\).
برای i ثابت: الگوریتمی بهتر از SEL وجود دارد که فقط n + O(lg n) مقایسه نیاز دارد.

حل کامل:

الگوریتم بهبود یافته:

u(A[1..n], i):
if i ≥ n then return T(n)  // از SEL استفاده کن
else:
    j ← PARTITION(A, 1, n)  // افراز
    if j = i then return A[j]
    elseif j > i then return u(A[1..j-1], i)
    else return u(A[j+1..n], i-j)

برای i ثابت (г):

اگر \(i < n/2\) باشد، میانه آرایه را پیدا کرده و افراز می‌کنیم. بعد فقط در نیمه‌ای که i امین در آن قرار دارد ادامه می‌دهیم:

\[u(n) = n + u(n/2) + O(\lg n) = n + O(\lg n)\]

برای \(i = k\) ثابت (د):

\[u(n) = n + u(n/2) + O(T(k) \lg k) = n + O(T(k) \lg k)\]

چون ارتفاع درخت بازگشتی \(\lg k\) است و در هر سطح O(n) مقایسه انجام می‌شود.

خیلی‌ها نمی‌دانند برای i ثابت، می‌توان از SEL بهتر عمل کرد.
i ثابت → n + O(lg n). ایده: فقط در نیمه مناسب افراز و ادامه بده.
