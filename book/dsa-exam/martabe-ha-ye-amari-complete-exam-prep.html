حل کاملتمرین ۱تمرین
رابطه بازگشتی مرتب‌سازی درجی بازگشتی را بنویسید و پیچیدگی زمانی آن را تعیین کنید.
مرتب‌سازی درجی بازگشتی آرایه \(A[1..n]\) را با فراخوانی بازگشتی مرتب‌سازی \(A[1..n-1]\) و سپس درج \(A[n]\) در جایگاه مناسب مرتب می‌کند.

حل کامل:

  1. مرحله ۱: اگر \(n = 1\) باشد، آرایه مرتب است و \(T(1) = \Theta(1)\).
  2. مرحله ۲: در غیر این صورت، \(T(n) = T(n-1) + \Theta(n)\) (فراخوانی بازگشتی + درج).
  3. مرحله ۳: با استفاده از روش جایگذاری مستقیم: \(T(n) = \Theta(1) + \sum_{i=2}^{n} \Theta(i) = \Theta(n^2)\).
  4. مرحله ۴: یا با قضیه Master: \(a=1, b=1, f(n)=\Theta(n)\) → \(T(n) = \Theta(n^2)\).
اشتباه رایج: فراموش کردن اینکه درج \(A[n]\) در بدترین حالت \(n-1\) مقایسه و جابجایی نیاز دارد.
نکته حفظی: \(T(n) = T(n-1) + \Theta(n) \Rightarrow T(n) = \Theta(n^2)\).

حل کاملتمرین ۲تمرین
مرتب‌سازی ادغامی با استفاده از مرتب‌سازی درجی برای زیرلیست‌های کوچکتر از آستانه \(k\). (الف) پیچیدگی زمانی (ب) بهترین \(k\) (ج) مزیت عملی (د) تحلیل ریاضی
ترکیب merge sort با insertion sort برای زیرلیست‌های کوچک سربار فراخوانی بازگشتی را کاهش می‌دهد.

حل کامل:

بخش (الف):

  1. وقتی \(n \leq k\) از insertion sort استفاده می‌شود: \(\Theta(k^2)\).
  2. تعداد سطوح تقسیم: \(\log(n/k)\).
  3. در هر سطح: \(O(n)\) عملیات merge.
  4. کل: \(O(n \log(n/k) + nk)\).

بخش (ب):

  1. مشتق‌گیری از \(n \log(n/k) + nk\) نسبت به \(k\).
  2. بهترین \(k = \Theta(\log n)\).

بخش (ج):

  1. کاهش فراخوانی‌های بازگشتی برای زیرلیست‌های کوچک.
  2. بهبود عملی ۲۰-۳۰٪ در پیاده‌سازی‌های واقعی.

بخش (د):

  1. برای \(k = \Theta(\log n)\): کل \(O(n \log n)\) با ثابت بهتر.
اشتباه رایج: فراموش کردن اینکه insertion sort برای زیرلیست‌های کوچک بهینه‌تر است زیرا سربار بازگشتی ندارد.
نکته حفظی: بهترین آستانه \(k = \Theta(\log n)\) و پیچیدگی کل \(O(n \log n)\) با ثابت کوچکتر.

حل کاملتمرین ۳تمرین
وارونگی‌ها در آرایه‌ها: (الف) تعریف وارونگی (ب) حداکثر تعداد (ج) ارتباط با مرتب‌سازی (د) الگوریتم شمارش وارونگی‌ها
وارونگی معیاری برای اندازه‌گیری مرتب‌بودن آرایه است و با تعداد عملیات مقایسه در merge sort ارتباط دارد.

حل کامل:

بخش (الف): وارونگی زمانی است که \(i < j\) ولی \(A[i] > A[j]\).

بخش (ب): حداکثر تعداد وارونگی \(\binom{n}{2} = \frac{n(n-1)}{2}\) (وقتی آرایه معکوس مرتب باشد).

بخش (ج):

  1. آرایه مرتب: ۰ وارونگی.
  2. آرایه معکوس: حداکثر وارونگی.
  3. تعداد مقایسه‌ها در merge sort دقیقاً برابر تعداد وارونگی‌هاست.

بخش (د):

  1. الگوریتم شمارش وارونگی‌ها با merge sort اصلاح شده: \(O(n \log n)\).
  2. در مرحله merge، وقتی \(A[j] < A[i]\) از هر دو آرایه باقی‌مانده، تعداد عناصر باقی‌مانده در \(A[i..mid]\) برابر تعداد وارونگی‌هاست.
اشتباه رایج: فکر کردن اینکه تعداد وارونگی‌ها همیشه \(\Theta(n^2)\) است (فقط در بدترین حالت).
نکته حفظی: تعداد وارونگی‌ها از ۰ تا \(n(n-1)/2\) متغیر است و با merge sort قابل شمارش است.

حل کاملتمرین ۷تمرین
مرتب‌سازی استوج (Stooge Sort) را بنویسید و ثابت کنید پیچیدگی آن \(O(n^{2.7})\) است.
Stooge Sort اگر \(A[n] < A[1]\) باشد ۲/۳ اول و آخر را جابجا می‌کند، سپس بازگشتی ۲/۳ اول و ۲/۳ آخر را مرتب می‌کند.

حل کامل:

  1. الگوریتم: اگر \(A[lo] > A[hi]\) آنگاه جابجا کن.
  2. اگر \(hi - lo + 1 > 1\):
  3. \(k = \lfloor (hi - lo + 1) / 3 \rfloor\).
  4. StoogeSort(A, lo, hi-k) — دو سوم اول.
  5. StoogeSort(A, lo+k, hi) — دو سوم آخر.
  6. StoogeSort(A, lo, hi-k) — دو سوم اول دوباره.
  7. رابطه بازگشتی: \(T(n) = 3T(2n/3) + \Theta(1)\).
  8. با قضیه Master: \(a=3, b=3/2, f(n)=\Theta(1)\).
  9. \(\log_{3/2} 3 \approx 2.7\) پس \(T(n) = O(n^{2.7})\).
اشتباه رایج: فکر کردن \(T(n) = 3T(n/3)\) (باید \(2n/3\) باشد).
نکته حفظی: \(T(n) = 3T(2n/3) + \Theta(1) \Rightarrow O(n^{\log_{3/2} 3}) \approx O(n^{2.7})\).

حل کاملتمرین ۹تمرین
کوئیک‌سورت و تفکیک (Partition): (الف) الگوریتم تفکیک لوموتو (ب) تفکیک هور (ج) تحلیل پیچیدگی (د) پیوت مناسب (ه) تضمین جایگاه نهایی پیوت
تفکیک عملیات کلیدی quicksort است که عنصر پیوت را در جایگاه نهایی قرار می‌دهد.

حل کامل:

بخش (الف) - Lomuto Partition:

  1. پیوت = آخرین عنصر \(A[r]\).
  2. شاخص \(i = lo - 1\).
  3. برای \(j = lo\) تا \(r-1\): اگر \(A[j] \leq\) پیوت آنگاه \(i++\) و جابجایی \(A[i], A[j]\).
  4. در پایان: جابجایی \(A[i+1], A[r]\) و return \(i+1\).

بخش (ب) - Hoare Partition:

  1. پیوت = اولین عنصر (یا عنصر تصادفی).
  2. دو شاخص از دو انتها حرکت می‌کنند.
  3. وقتی شاخص چپ عنصری > پیوت و شاخص راست عنصری < پیوت یافت، جابجا کن.
  4. وقتی شاخص‌ها از هم عبور کردند، برگردان.

بخش (ج): هر دو تفکیک \(O(n)\) هستند.

بخش (د): پیوت مناسب = پیوتی که تقریباً وسط باشد (median).

بخش (ه): در Lomuto: \(A[i+1]\) جایگاه نهایی پیوت است. در Hoarge: برگردانده شده index.

اشتباه رایج: فکر کردن Hoare partition دقیقاً مشابه Lomuto است (متفاوتند).
نکته حفظی: Lomuto ساده‌تر، Hoare کارآمدتر (کمتر مقایسه).
