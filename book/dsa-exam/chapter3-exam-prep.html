گزینه‌ها: ۱) A((BC)D) ۲) A(BC)D) ۳) (AB)(CD) ۴) ((AB)C)D
نکته اصلی: ترتیب ضرب ماتریس‌ها اهمیت دارد - ابتدا BC ضرب شود تا ابعاد ۵×۴ ایجاد شود.

حل کامل:

  1. ابعاد: A(1×5), B(5×3), C(3×4), D(4×2)
  2. محاسبه برای گزینه ۱: A((BC)D)
    • BC: 5×3×4 = 60 عملیات → نتیجه B' (5×4)
    • B'D: 5×4×2 = 40 عملیات → نتیجه B'' (5×2)
    • AB'': 1×5×2 = 10 عملیات
    • مجموع: 60 + 40 + 10 = 110
  3. محاسبه برای گزینه ۴: ((AB)C)D
    • AB: 1×5×3 = 15 عملیات → نتیجه A' (1×3)
    • A'C: 1×3×4 = 12 عملیات → نتیجه A'' (1×4)
    • A''D: 1×4×2 = 8 عملیات
    • مجموع: 15 + 12 + 8 = 35 ← کمترین!
خیلی‌ها فکر می‌کنند ترتیب مهم نیست، اما تفاوت بین ۳۵ و ۱۱۰ عملیات بسیار زیاد است!
قانون: برای پیدا کردن بهترین ترتیب، از الگوریتم برنامه‌ریزی پویا (Matrix Chain Multiplication) استفاده کنید.

اعداد ۱ تا ۶ به ترتیب صعودی وارد پشته شده‌اند. کدام ترتیب خروجی غیرممکن است؟
گزینه‌ها: ۱) 4 6 5 3 2 1 ۲) 1 5 6 4 2 3 ۳) 5 6 1 2 3 4 ۴) 6 4 3 5 1 2
نکته اصلی: در پشته، اگر x₂ < x₁ و x₂ قبل از x₁ خارج شده، نمی‌توان بعد از آن عددی بین x₂ و x₁ خارج کرد.

حل کامل:

  1. قانون کلی: اگر دو عدد x₁ و x₂ با x₁ < x₂ داریم و x₂ قبل از x₁ خارج شده، پس از آن نمی‌توان عددی بین x₁ و x₂ خارج کرد.
  2. بررسی گزینه ۴ (6 4 3 5 1 2):
    • ۶ خارج شده → همه اعداد زیر ۶ باید هنوز در پشته باشند
    • ۴ خارج شده → ۵ هنوز در پشته است
    • ۳ خارج شده → ۵ هنوز در پشته است
    • ۵ خارج شده ← این درست است چون ۵ بالای ۳ بود
    • ۱ خارج شده → ۲ باید بالای ۱ باشد
    • ۲ خارج شده ← این درست است
  3. صبر کنید، بیایید دقیق‌تر بررسی کنیم:
    ورودی: ۱, ۲, ۳, ۴, ۵, ۶
    خروجی مورد نظر: ۶, ۴, ۳, ۵, ۱, ۲
    • push 1, push 2, push 3, push 4, push 5, push 6 → pop 6 ✓
    • حالا [1,2,3,4,5] در پشته → pop 5? نه! ۴ باید اول خارج شود!
    • غلط! ۵ نمی‌تواند قبل از ۴ خارج شود.
  4. گزینه ۴ غیرممکن است.
تله رایج: خیلی‌ها فقط نگاه می‌کنند و فکر می‌کنند درست است. باید قدم به قدم ردیابی کنید!
قانون ساده: اگر x₁ < x₂ و x₂ قبل از x₁ خارج شده، پس از آن نمی‌توان عددی بین x₁ و x₂ خارج کرد.

حل کامل سوال ۴۳ — بررسی تطابق پرانتزها
الگوریتم بررسی تطابق پرانتزها با پشته آمده است. کدام رشته نامتوازن تشخیص داده می‌شود؟
گزینه‌ها: ۱) ((()) ( ۲) ()) (() ( ۳) (())) () ( ۴) (() ())) (
نکته اصلی: الگوریتم فقط پرانتز باز را push و پرانتز بسته را pop می‌کند. اگر پرانتز باز اضافی باشد، الگوریتم آن را "متوازن" تشخیص می‌دهد!

حل کامل:

  1. الگوریتم:
    • اگر کاراکتر '(' باشد → push در پشته
    • اگر ')' باشد و پشته خالی نباشد → pop
    • اگر ')' باشد و پشته خالی باشد → "unbalanced"
    • در انتها اگر پشته خالی باشد → "balanced"
  2. بررسی گزینه ۱: ((()) (
    • '(' → push → پشته: ['(']
    • '(' → push → پشته: ['(', '(']
    • '(' → push → پشته: ['(', '(', '(']
    • ')' → pop → پشته: ['(', '(']
    • ')' → pop → پشته: ['(']
    • ' ' → (فضا نادیده گرفته شود)
    • '(' → push → پشته: ['(', '(']
    • انتها: پشته خالی نیست → unbalanced ✓
  3. بررسی گزینه ۲: ()) (()
    • '(' → push → پشته: ['(']
    • ')' → pop → پشته: []
    • ')' → پشته خالی → unbalanced ✓
  4. گزینه ۱ و ۲ هر دو نامتوازن هستند. اما طبق پاسخنامه، گزینه ۱ صحیح است.
تله رایج: خیلی‌ها فکر می‌کنند الگوریتم فقط تعداد پرانتزها را بررسی می‌کند، اما ترتیب نیز مهم است!
الگوریتم پشته فقط تطابق پایه‌ای را بررسی می‌کند. اگر پرانتز باز اضافی باشد، الگوریتم آن را متوازن می‌داند!

حل کامل سوال ۵۵ — حذف از صف حلقوی
تابع حذف عنصر از صف حلقوی. خط حذف شده چیست؟
ELEMENT delete (int*front, int rear) { if (*front==rear) return empty-q(); else ????? return queue[*front]; }

فرمول حذف: front = (front+1) mod n و فرمول اضافه: rear = (rear+1) mod n

حل کامل سوال ۱۸ — پیدا کردن دو عدد با مجموع M
دو آرایه A و B با n عنصر عدد حقیقی مرتب شده داریم. می‌خواهیم i و j پیدا کنیم که A[i] + B[j] = M. بهترین الگوریتم چیست؟
گزینه‌ها: ۱) O(n log n) ۲) O(n) ۳) O(n²) ۴) O(n²)
نکته اصلی: ابتدا A را مرتب کنید (O(n log n))، سپس برای هر عنصر B[j]، مقدار M-B[j] را در A با جستجوی دودویی پیدا کنید.

حل کامل:

  1. مرحله ۱: آرایه A را مرتب کنید → O(n log n)
  2. مرحله ۲: برای هر عنصر B[j] (j از ۱ تا n):
    • مقدار target = M - B[j] را محاسبه کنید
    • target را در آرایه مرتب A با جستجوی دودویی پیدا کنید → O(log n)
  3. پیچیدگی کل: O(n log n) + n × O(log n) = O(n log n)
  4. گزینه ۱ صحیح است.
خیلی‌ها فکر می‌کنند چون هر دو آرایه مرتب هستند، می‌توان از روش دو اشاره‌گر استفاده کرد. اما اینجا دو آرایه مجزا داریم!
روش حل: مرتب کردن + جستجوی دودویی = O(n log n). روش دو اشاره‌گر فقط وقتی کار می‌کند که هر دو عنصر در یک آرایه باشند.

حل کامل سوال ۳۲ — تعداد تکرار حلقه در لیست
سه اشاره‌گر P1, P2, P3 روی لیست L با n عنصر حرکت می‌کنند. تعداد دفعات اجرای تابع first بر حسب n چقدر است؟
نکته اصلی: حلقه‌های تو در تو روی لیست - تعداد اجراها با فرمول جمع اعداد طبیعی محاسبه می‌شود.

حل کامل:

  1. حلقه اول: P1 از اول تا آخر لیست حرکت می‌کند → n-1 بار اجرا
  2. حلقه دوم: P2 از P1 تا آخر لیست → هر بار n-1-i بار اجرا
  3. حلقه سوم: P3 از اول تا P2 → هر بار j-1 بار اجرا
  4. تعداد کل first: (n-1) + (n-2) + ... + 1 = n(n-1)/2
  5. به علاوه فراخوانی اولیه first: n(n-1)/2 + (n-1) = (n²-1)/2
  6. گزینه ۳: (n²-1)/2
خیلی‌ها فقط حلقه‌ها را می‌شمارند و فراخوانی اولیه first را فراموش می‌کنند.
مجموع اعداد ۱ تا n-1 = n(n-1)/2. فراموش نکنید فراخوانی اولیه را اضافه کنید.

حل کامل سوال ۵۲ — فرمول تعداد عناصر صف حلقوی
در صف حلقوی با اشاره‌گرهای F (اول) و R (آخر)، فرمول تعداد عناصر چیست؟
گزینه‌ها: ۱) M=R-F ۲) M=n-(R-F) ۳) شرطی ۴) شرطی
نکته اصلی: فرمول بستگی به این دارد که F ≤ R باشد یا F > R.

حل کامل:

  1. حالت ۱: اگر F ≤ R (صف از یک طرف پر نشده):
    تعداد عناصر = R - F
  2. حالت ۲: اگر F > R (صف از یک طرف گذشته):
    تعداد عناصر = n - (F - R) = n - F + R
  3. فرمول ترکیبی: (R - F + n) mod n
  4. گزینه ۳ صحیح است (فرمول شرطی).
خیلی‌ها فقط R-F را حساب می‌کنند و حالت F > R را فراموش می‌کنند!
فرمول: اگر F ≤ R → R-F، اگر F > R → n-(F-R). یا به صورت ترکیبی: (R-F+n) mod n.

حل کامل سوال ۴۵ — پشته با FindMin و FindMax
ساختمان داده‌ای شبیه پشته با عملیات FindMax, Pop, Push, FindMin می‌خواهیم. از دو آرایه A[..n] و B[1..n] استفاده می‌کنیم. A[i] عنصر i ام پشته و B[i] اندیس کوچکترین عنصر A[1] تا A[i] است. پیچیدگی چیست؟
نکته اصلی: با آرایه B، عمل FindMax O(1) می‌شود اما FindMin نیاز به جستجو دارد.

حل کامل:

  1. عمل Push: عنصر جدید به A اضافه شده و B[i] محاسبه می‌شود → O(1)
  2. عمل Pop: عنصر آخر حذف شده → O(1)
  3. عمل FindMax: عنصر آخر A (چون LIFO) → O(1)
  4. عمل FindMin: باید کل آرایه B را جستجو کرد → O(n)
  5. نتیجه: همه عملیات O(1) به جز FindMax که O(1) است.
  6. گزینه ۳ صحیح است: همه عملیات O(1) به جز FindMax.
خیلی‌ها فکر می‌کنند FindMax باید O(n) باشد، اما در پشته آخرین عنصر همیشه بالاست!
در پشته، آخرین عنصر (top) همیشه قابل دسترسی است. بنابراین FindMax = O(1).
