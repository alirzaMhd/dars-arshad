Intelligent Agents & PEAS Design

Core concepts for Chapter 1 — agents, sensors, actuators, and task environments

What Is an Agent?

An agent is anything that perceives its environment through sensors and acts through actuators.

Agent Function:
f : P* → A
Maps the entire percept history to an action: agent function is the mathematical ideal.
Agent Program:
Agent = Program + Architecture
The program implements the agent function on a physical hardware or software architecture.

Autonomy means the agent improves its behavior using its own experience, not only designer-supplied prior knowledge. An autonomous agent must be able to learn from its percept sequence and adapt when conditions change.

Performance Measure vs Utility Function

A performance measure is assigned by an external observer to judge success. A utility function is internal to the agent and maps states to satisfaction numbers.

Key Distinction:
Performance measure evaluates actual success. Utility function estimates how desirable each state is for planning.

Multiple Programs Per Function

A single agent function can be implemented by different agent programs on the same architecture. Different programs may trade off speed, robustness, and optimality.

PEAS Task Environment

Before designing an agent, specify:

  • P: Performance measure
  • E: Environment characteristics
  • A: Actuators available
  • S: Sensors available

Agent Program Structure

An agent program runs on an architecture. Sensors feed percepts to the program, which chooses actions that actuators execute.

function SKELETON-AGENT(percept) returns action memory ← UPDATE-MEMORY(memory, percept) action ← CHOOSE-BEST-ACTION(memory) memory ← UPDATE-MEMORY(memory, action) return action

Key Points

  • The agent receives one percept at a time; the percept sequence must be maintained in memory.
  • In complex environments, storing the full percept sequence may be infeasible.
  • The performance measure is external to the program and not hardcoded inside it.

Table-Driven Agent

A table-driven agent is theoretically possible but practically impossible because the table size grows exponentially with percept history.

PEAS Examples

Example 1 - Satellite Image Analyzer

Performance: Correct classification accuracy.

Environment: Raw satellite pixels, lighting conditions, atmospheric distortion.

Actuators: Classification labels, reports.

Sensors: Image input, metadata.

Example 2 - Refinery Controller

Performance: Maximize production, maximize safety, maximize purity.

Actuators: Valves, temperature controls, pressure controls.

Sensors: Temperature, pressure, flow sensors.

Example 3 - Part-Picking Robot

Performance: Correct parts picked, no damage, high throughput.

Actuators: Gripper, arm joints.

Sensors: Camera, touch sensors, position encoders.
