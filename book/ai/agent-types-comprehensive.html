Agent Types

Reflex, model-based, goal-based, utility-based, and learning agents

Simple Reflex Agent

The simplest agent type ignores percept history and selects an action purely from the current percept via condition-action rules.

function SIMPLE-REFLEX-AGENT(percept) returns action state ← INTERPRET-INPUT(percept) rule ← RULE-MATCH(state, rules) action ← RULE-ACTION(rule) return action

When It Works

  • Environment is fully observable.
  • Correct action depends only on current percept.
This agent is brittle in partially observable environments because it cannot distinguish states with the same percept but different histories.
Example

If front car brake lights are on → apply brakes.

This rule is fragile if the car ahead has no brake lights because of a bulb failure.

Model-Based Reflex Agent

This agent keeps internal state so it can handle partial observability. The internal state is updated using both the current percept and the previous action.

function REFLEX-AGENT-WITH-STATE(percept) returns action static: state state ← UPDATE-STATE(state, action, percept) rule ← RULE-MATCH(state, rules) action ← RULE-ACTION(rule) return action

World Model

The update function needs knowledge about:

  • How the world evolves: environmental dynamics independent of the agent.
  • How actions affect the world: transition model of the agent's impact.
Example

A taxi keeps track of the lane-change it made 5 minutes ago so it knows a gap temporarily exists behind it, even if not visible through current sensors.

Goal-Based Agent

Unlike reflex agents, a goal-based agent knows what outcome it wants and searches or plans a sequence of actions.

Key Idea

Current state + goal description → action choice. If the goal cannot be reached with one action, the agent uses search and planning.

Flexibility:
Goal: Reach destination → choose turn left/right/go straight adaptively
New behavior only needs a new goal, not rewritten condition-action rules.
The goal does not have to be hardcoded into the program's performance mechanism; it is part of the decision procedure.
Example

If the destination changes because a road is closed, the goal-based taxi can replan. A reflex agent would need many new rules.

Utility-Based Agent

Goals alone may be insufficient. Utility maps state preferences to real numbers so the agent can compare competing outcomes.

Utility Function:
U: States → Real Numbers
Higher utility means greater agent satisfaction with that outcome.

When to Use

CaseWhy Goal FailsWhy Utility Helps
Conflicting goalsSpeed vs safety cannot both be fully achievedTrade-off via weighted trade-off
Uncertain outcomeMultiple paths may failChoose path with highest expected utility
Multiple acceptable outcomesAny valid route acceptedCompare travel time, cost, risk
Example

Taxi routes: many paths reach the destination. Utility combines time, safety, passenger comfort, and fuel cost into a single ranking.

Learning Agents

A learning agent improves over time. It has four interacting parts:

Performance Element

The existing decision-making system using current knowledge.

Critic

Evaluates actual performance and sends feedback.

Learning Element

Modifies the knowledge or rules based on feedback.

Problem Generator

Suggests exploration actions that may improve long-term performance.

Feedback Loop

Feedback from the critic modifies the performance element, and the problem generator probes behaviors that might generalize better, especially under changing conditions.

Types of Learning

TypeWhat It LearnsDifficulty
Direct percept learningHow the environment state evolvesLow
State-sequence learningNotice changes in successive statesMedium
Action-effect learningWhat results from the agent's own actionsMedium
Utility learningWhich outcomes are desirableHigh
Example - Utility Learning in Taxi

If passengers stop tipping, the external performance standard must tell the agent that fewer tips reduces overall utility. The agent then learns to avoid behaviors that irritate passengers.

Performance Element + Critic + Problem Generator + Learning Element = Learning Agent
Example - Taxi

After sharp turns, passenger complaints trigger rule changes. Problem generator may ask the taxi to try gentler turns on different road grades to improve generalization.
