AI Environments

Artificial Intelligence — Chapter 1: AI and Intelligent Agents

Six Dimensions of Environment Properties

Every AI task environment can be classified along these six binary dimensions. Understanding where an environment falls on each axis determines which agent architecture is appropriate.

Dimension 1

Fully vs Partially Observable

Fully observable: The agent's sensors give it access to the complete state of the environment at every point in time. No hidden information — the agent knows everything relevant to the decision.

Partially observable: Sensors are limited — the agent receives only partial information. It may need to maintain internal state (memory) to infer what it cannot perceive directly.

Example: A taxi driver cannot know the destination or intentions of other drivers — partially observable. A chess board is fully visible — fully observable.

Dimension 2

Deterministic vs Stochastic

Deterministic: The next state of the environment is completely determined by the current state and the agent's action. No randomness — given the same state and action, the outcome is always identical.

Stochastic: The next state is not uniquely determined — there is randomness or uncertainty in the outcome. The agent must deal with probabilistic transitions.

Example: Chess is deterministic (a move always produces the same board). Taxi driving is stochastic because traffic and pedestrian behavior are unpredictable.

Dimension 3

Episodic vs Sequential

Episodic: The agent's experience is divided into independent episodes. Each episode is self-contained — actions in one episode do not affect the next. The agent can treat each episode in isolation.

Sequential: Current decisions affect all future decisions. The agent must think ahead — short-term sacrifices may be necessary for long-term gain. This introduces the credit-assignment problem.

Example: Parts inspection in a factory is episodic (each part is independent). Chess is sequential — every move changes the board for the rest of the game.

Dimension 4

Static vs Dynamic vs Semidynamic

Static: The environment does not change while the agent is deliberating (thinking). The agent can take as long as it needs to decide.

Dynamic: The environment changes continuously while the agent is deciding. The agent must sense and act in real time.

Semidynamic: The environment itself is static, but the agent's performance score changes over time (e.g., a timer counts down). The agent is under time pressure even though the world is not changing.

Example: Chess without a clock is static. Taxi driving is dynamic. Chess with a clock is semidynamic.

Dimension 5

Discrete vs Continuous

Discrete: There is a finite (or countably infinite) set of distinct percepts and actions. The agent operates on a well-defined set of possibilities.

Continuous: Percepts and actions can take on a continuous range of values (real numbers, angles, velocities, positions). The state space is uncountably infinite.

Example: Chess has discrete moves (64 squares, finite piece types). Taxi driving involves continuous steering angles, velocities, and positions.

Dimension 6

Single vs Multi-Agent

Single-agent: Only one agent operates in the environment. No other agents affect the world.

Multi-agent: Multiple agents coexist. This can be competitive (zero-sum, one agent's gain is another's loss), cooperative (agents share goals), or partially competitive (mixed motives — sometimes cooperate, sometimes compete).

Examples: Competitive — chess. Partially cooperative — taxi drivers avoiding accidents. Partially competitive — two drivers racing for the same parking spot.

Strategic Environments

A strategic environment arises in multi-agent settings. The environment may appear deterministic from one agent's perspective — but because other agents are also acting, the overall outcome is not deterministic. Each agent's action changes the world for others, introducing unpredictability that is not stochastic (random) but strategic (caused by other intentional agents).

Strategic Environment — Chess

Chess is deterministic: if White moves a knight, the knight moves exactly as expected. But from White's perspective, the next state depends on Black's response — which is not under White's control. The environment is deterministic in its physics but strategically non-deterministic because of the opponent's choices.

⚠ Warning: Do not confuse "strategic non-determinism" with "stochastic." Stochastic = randomness in the environment (dice, weather). Strategic = intentional actions by other agents that the current agent cannot predict with certainty.

Hardest Case

The most challenging environment for an AI agent combines the hardest end of every dimension:

⚠ Hardest Environment Type: Inaccessible (partially observable) + Non-episodic (sequential) + Dynamic + Continuous + Multi-agent

The agent must reason under uncertainty, plan for long-term consequences, react in real time, handle infinite state spaces, and contend with other agents that have their own goals — all simultaneously.

Real-World Hardest Case: Autonomous Taxi Driving

Partially observable (can't read other drivers' minds), sequential (every turn affects later traffic), dynamic (traffic keeps moving), continuous (steering, speed, position), multi-agent (other drivers, pedestrians). This is why fully autonomous driving remains an open research problem.

Detailed Classification Notes

Chess (no clock)

Fully observable: entire board visible. Deterministic: pieces move predictably. Sequential: each move affects the game. Static: board doesn't change while you think. Discrete: 64 squares, finite moves. Multi-agent: two players.

Chess (with clock)

Same as above except semidynamic: the board is static but your remaining time decreases while you think — a timer scores your performance even though the world stands still.

Poker

Partially observable: opponent's cards hidden. Stochastic: shuffled deck introduces randomness. Sequential: each hand depends on previous bets/bluffs. Static: cards don't change while you act. Discrete: finite cards and bets. Multi-agent.

Backgammon

Fully observable: all pieces visible on board. Stochastic: dice rolls determine possible moves. Sequential: long-term strategy matters. Static: board frozen while you decide. Discrete: finite positions. Multi-agent.

Taxi Driving

Partially observable: hidden intentions of others. Stochastic: unpredictable traffic/weather. Sequential: each route choice affects future traffic position. Dynamic: world keeps moving. Continuous: steering, speed, position. Multi-agent.

Medical Diagnosis

Partially observable: cannot see inside body directly — tests give incomplete info. Stochastic: symptoms do not guarantee disease. Sequential: test results guide further tests. Static: patient condition stable during consultation. Discrete: finite set of diseases/symptoms. Single-agent if doctor is the only agent (patient is passive).

Satellite Image Analysis

Fully observable: the image is the complete input. Deterministic: same image always produces same analysis. Episodic: each image is independent. Static: image doesn't change during analysis. Continuous: pixel values are continuous. Single-agent.

Part-Picking Robot

Partially observable: camera may not see all parts or they may be occluded. Stochastic: parts may slip or fall. Episodic: each pick is an independent action. Dynamic: conveyor belt moves. Continuous: arm positions, angles, velocities. Single-agent.

Refinery Controller

Partially observable: sensor readings are noisy/incomplete. Stochastic: chemical reactions have random fluctuations. Sequential: temperature/pressure changes propagate. Dynamic: process runs continuously. Continuous: temperature, pressure, flow rates. Single-agent (typically).

Crossword Puzzle

Fully observable: all clues and grid visible. Deterministic: each letter either fits or doesn't. Sequential: filling one word constrains others. Static: the puzzle doesn't change. Discrete: letters and grid cells. Single-agent.

English Tutor

Partially observable: cannot read student's mind. Stochastic: student responses are unpredictable. Sequential: each lesson builds on previous. Dynamic: student learns and forgets over time. Discrete: exercises are discrete items. Multi-agent: tutor and student.

Quick Reference Card

Key Patterns in Environment Classification

▸ Physical games (chess, go, checkers): Fully observable, deterministic, sequential, static/discrete, multi-agent

▸ Card games (poker, bridge): Partially observable, stochastic, sequential, static/discrete, multi-agent

▸ Dice games (backgammon, monopoly): Fully observable, stochastic, sequential, static/discrete, multi-agent

▸ Real-world control (taxi, refinery, robot): Partially observable, stochastic, sequential, dynamic, continuous

▸ Pure analysis (satellite images, medical scans): Fully or partially observable, deterministic or stochastic, episodic, static, continuous

▸ Puzzles (crossword, sudoku): Fully observable, deterministic, sequential, static, discrete, single-agent

Environment Simulators

In AI research, environments are simulated to test agent designs. Two fundamental procedures govern how agents interact with environments.

Procedure: RUN-ENVIRONMENT
procedure RUN-ENVIRONMENT(state, UPDATE-FN, agents, termination) inputs: state — initial environment state UPDATE-FN — function(state, actions) returns new state agents — list of agent programs termination — predicate on state that determines when to stop repeat for each agent i in agents: percept[i] ← get-percept(state, i) for each agent i in agents: action[i] ← agent[i](percept[i]) state ← UPDATE-FN(state, action) until termination(state)
The core interaction loop: sense → think → act → update.
Function: RUN-EVAL-ENVIRONMENT
function RUN-EVAL-ENVIRONMENT(state, UPDATE-FN, agents, termination, PERFORMANCE-FN) returns: list of performance scores (one per agent) scores ← [0, 0, ..., 0] // one per agent repeat for each agent i in agents: percept[i] ← get-percept(state, i) for each agent i in agents: action[i] ← agent[i](percept[i]) state ← UPDATE-FN(state, action) for each agent i in agents: scores[i] ← PERFORMANCE-FN(state, scores[i]) until termination(state) return scores
Same as RUN-ENVIRONMENT, but also tracks and updates each agent's performance score at every step.
Key Difference

RUN-ENVIRONMENT simply runs the simulation — it only cares about state transitions. RUN-EVAL-ENVIRONMENT additionally computes a performance metric. In a chess simulation, RUN-ENVIRONMENT would just update the board; RUN-EVAL-ENVIRONMENT would also track captures, checks, and eventually declare a winner based on the performance function.

⚠ Warning: The get-percept function is what determines observability. In a fully observable environment, get-percept returns the entire state. In a partially observable environment, it returns only a filtered or noisy subset. Changing get-percept changes the environment type without changing the underlying state dynamics.

Simulator Use Cases

Training

Simulators allow agents to practice millions of trials without real-world cost or risk. Used extensively in reinforcement learning (e.g., game engines, robotic simulators like MuJoCo, CARLA for driving).

Evaluation

RUN-EVAL-ENVIRONMENT is the standard for comparing agents. By controlling the environment (UPDATE-FN, percept function, termination), researchers ensure fair comparison. Performance scores are aggregated across runs.

Testing Edge Cases

Simulators can instantiate rare or dangerous scenarios (e.g., a pedestrian suddenly crossing, a sensor failure) that would be impractical or unsafe to test in the real world.

Example 3: Poker — Deterministic vs Stochastic Depends on Card Tracking

Poker's classification on the deterministic/stochastic axis depends on the agent's capabilities:

PerspectiveClassificationExplanation
Without card tracking Stochastic The deck is shuffled — the next card drawn is random. The agent cannot predict which card will appear. The environment appears fundamentally non-deterministic.
With perfect card tracking Deterministic If the agent tracks every card that has been played (e.g., a computer with perfect memory using a known deck), then the remaining cards are fully known. The next card is determined by the known order — no randomness remains.
⚠ Insight: This illustrates how a property is not always intrinsic to the environment — it depends on what the agent can perceive and remember. A partially observable environment often appears stochastic even when the underlying process is deterministic.
Example 4: Medical Diagnosis — Single vs Multi-Agent Depending on Modeling

Medical diagnosis can be classified differently on the agent-count axis depending on how we model the patient:

ModelAgent CountExplanation
Patient as passive environment Single-agent The patient is treated as part of the environment — they respond predictably to tests and treatments. The doctor (AI) is the only intentional agent. The patient's state changes, but not through strategic choice.
Patient as intentional agent Multi-agent If the patient can deliberately conceal symptoms, choose non-compliance, or make lifestyle choices that affect outcomes, they become a second agent. The diagnosis problem becomes a game-theoretic interaction.
⚠ Insight: The textbook definition generally treats the patient as part of the environment (single-agent), but advanced medical AI systems increasingly model patient adherence and behavior explicitly — making it a multi-agent problem.

Common Mistakes — Warning Boxes

⚠ Mistake 1: "Chess has randomness because you don't know what your opponent will do."
Correction: Not knowing your opponent's move does not make chess stochastic. The transition function is deterministic — the board state after a move is uniquely determined. The opponent's choice is strategic non-determinism, not randomness.
⚠ Mistake 2: "Taxi driving is deterministic because physics is deterministic."
Correction: While physics itself is deterministic in principle, the environment includes other agents (drivers, pedestrians) whose behavior is unpredictable. From the agent's perspective, the same action can lead to different outcomes — this is stochastic.
⚠ Mistake 3: "Continuous means the agent has infinite time."
Correction: Continuous refers to the state/action space (infinite real-valued possibilities), not time. Time is related to the static/dynamic dimension. A continuous environment can be static (e.g., satellite images with continuous pixel values).
⚠ Mistake 4: "Episodic and deterministic mean the same thing."
Correction: They are independent dimensions. Episodic means each trial is independent; deterministic means the outcome of an action is uniquely determined. A deterministic environment can be sequential (chess) and a stochastic environment can be episodic (part-picking robot).
⚠ Mistake 5: "All card games are partially observable."
Correction: While most card games (poker, bridge) are partially observable, some like war are fully observable if you track all cards played. The classification depends on the specific game rules and what information is hidden.
