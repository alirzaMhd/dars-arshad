Utility-Based Agents

Artificial Intelligence — Chapter 1: AI and Intelligent Agents

What Are Utility-Based Agents?

Goal-based agents know what to achieve, but they have no mechanism to distinguish between different ways of achieving it. When multiple action sequences all lead to the goal, which one should the agent choose?

Key Insight: Goals alone are insufficient for high-quality behavior. Many action sequences achieve the goal but differ dramatically in speed, safety, reliability, and cost. A utility-based agent adds a quantitative measure of how good a state is.
Taxi Agent Scenario

A goal-based taxi agent knows its goal: get the passenger to the airport. But should it take:

  • The shortest route (fast, but through bad neighborhoods)?
  • The safest route (longer, but secure)?
  • The cheapest route (no tolls, but heavy traffic)?
  • The most comfortable route (highway, scenic)?

All four sequences reach the airport. A utility function lets the agent trade off these competing considerations.

Core Definition

Utility Function:
U : S → ℝ
Maps a state (or state sequence) to a real number indicating the degree of satisfaction or happiness.

    When Is Utility Needed?

    Utility-based decision-making becomes essential in two broad scenarios:

    1. Conflicting Goals

    An agent faces goals that push in opposite directions:

    Taxi example: "Drive safely" → go slow, take well-lit roads.
    "Arrive quickly" → speed, take shortcuts.
    These conflict directly. Utility creates a trade-off surface.

    2. Uncertainty

    Multiple goals with probabilistic outcomes:

    Medical example: Treatment A has 90% success but severe side effects.
    Treatment B has 60% success but mild side effects.
    Utility tells you which expected value is higher.

    3. Multiple Criteria

    Goals that cannot be directly compared:

    College choice: Reputation vs cost vs location vs program strength.
    Utility provides a common currency to compare.

    Utility Function — Formal Definition

    Definition:
    U(s) ∈ ℝ
    The utility function maps a state s to a real number. Higher values indicate more preferred states.

    A utility function represents the agent's preference ordering over states. If the agent prefers state s₁ over state s₂, then:

    Preference Ordering:
    U(s₁) > U(s₂) ⇔ s₁ ⊥ s₂
    The preference relation ⊥ is captured by the real-valued utility function.

    Expected Utility Principle

    When outcomes are uncertain, the agent should choose the action that maximizes the expected utility of the resulting state:

    Expected Utility Maximization:
    a* = argmaxa ∈ A Σs' P(s' | s, a) · U(s')
    Choose action a* that maximizes the sum of utilities of all possible next states, weighted by their probabilities.
    Important: The expected utility principle assumes utility is cardinal (not just ordinal) — the magnitude of the difference matters, not just the ranking.

    Properties of Utility Functions

    PropertyDescriptionExample
    CompletenessAgent can compare any two statesU(A) > U(B) or U(B) > U(A) or U(A) = U(B)
    TransitivityPreferences are logically consistentIf U(A) > U(B) and U(B) > U(C) then U(A) > U(C)
    ContinuitySmall changes in state produce small changes in utilitySmooth preference landscape
    MonotonicityMore of a good thing is always betterHigher speed (within limits) = higher utility
    Multi-Attribute Utility

    For problems involving multiple independent criteria, utility can be decomposed:

    Additive Utility:
    U(s) = w₁ · U₁(s) + w₂ · U₂(s) + ... + wn · Un(s)
    Where wi are weights indicating the importance of each dimension, and Σ wi = 1.

    Advantages

  • Expressive preference modeling
  • Principled trade-off analysis
  • Handles uncertainty naturally
  • Comparable across domains

    • Disadvantages

  • Difficult to determine correct weights
  • Assumes rational preferences
  • Computationally expensive
  • Subject to framing effects

    • Design Considerations

  • Normalize utility values
  • Validate weights with domain experts
  • Test sensitivity to weight changes
  • Consider risk attitude (risk-neutral, risk-averse, risk-seeking)

    Conflicting Goals — Detailed Analysis

    In the real world, agents almost always face trade-offs. No single action optimally satisfies all goals simultaneously. Utility functions resolve this by placing all goals on a common scale.

    Case 1: Conflicting Goals

    Taxi: Speed vs Safety

    A taxi agent has two explicit goals:

    • Goal A: Arrive at destination as quickly as possible
    • Goal B: Ensure passenger safety and comfort

    These conflict because:

    • Fast routes may go through high-crime areas or involve dangerous maneuvers
    • Safe routes may take detours that add 20+ minutes

    A goal-based agent has no way to decide which route to take — both achieve the goal "reach the airport."

    A utility-based agent assigns weights:

    U(route) = wspeed · Uspeed(time) + wsafety · Usafety(risk)
    With, for example, wspeed = 0.4 and wsafety = 0.6 for a cautious driver.

    The agent now selects the route that maximizes the weighted sum — balancing both concerns.

    Case 2: Multiple Goals Under Uncertainty

    Medical Decision Making

    A doctor must choose a treatment for a patient. Multiple goals exist:

    • Maximize probability of cure
    • Minimize side effects
    • Minimize cost
    • Minimize recovery time

    Each treatment has uncertain outcomes. The agent computes expected utility for each option:

    EU(Treatment) = Σi P(outcomei) · U(outcomei)

    The agent picks the treatment with the highest expected utility.

    General Framework for Resolving Conflicts

    1. Identify Goals

    List all objectives the agent must satisfy. Be explicit — hidden goals produce bad behavior.

    2. Define Metrics

    For each goal, define a measurable sub-utility function (e.g., travel time, accident probability).

    3. Assign Weights

    Determine the relative importance of each goal. Weights should sum to 1 and reflect domain priorities.

    4. Compute Combined Utility

    Use additive utility or more complex combinations (e.g., multiplicative if goals are interdependent).

    5. Sensitivity Analysis

    Test how weight changes affect decisions. Robust solutions work for a range of reasonable weights.

    6. Select & Execute

    Choose the action that maximizes expected utility. Monitor actual utility and adjust weights over time.

    Warning: Weight selection is the hardest part of utility-based design. Poor weights lead to unexpected, undesirable behavior. For example, setting speed weight too high in a taxi agent could cause reckless driving.

    Worked Examples

    Five detailed examples showing utility-based reasoning in action.

    Example 1: Taxi Route Selection

    Scenario: A taxi must take a passenger from downtown to the airport. Three routes:

    RouteTime (min)Safety Score (0–10)Cost ($)Comfort (0–10)
    Route A (Highway)259158
    Route B (City)35755
    Route C (Shortcut)20302

    Step 1: Normalize each attribute to [0,1].

    Step 2: Define weights — Time: 0.3, Safety: 0.4, Cost: 0.2, Comfort: 0.1

    Step 3: Compute weighted utility for each route:

    Route A: 0.3(0.67) + 0.4(1.0) + 0.2(0.0) + 0.1(1.0) = 0.201 + 0.400 + 0.000 + 0.100 = 0.701
    Route B: 0.3(0.0) + 0.4(0.57) + 0.2(0.67) + 0.1(0.50) = 0.000 + 0.228 + 0.134 + 0.050 = 0.412
    Route C: 0.3(1.0) + 0.4(0.0) + 0.2(1.0) + 0.1(0.0) = 0.300 + 0.000 + 0.200 + 0.000 = 0.500

    Route A (Highway) has the highest utility (0.701) and is selected. Safety dominates the decision because it has the highest weight.

    Example 2: Medical Diagnosis — Treatment Selection

    Scenario: A patient has a serious condition. Three treatments exist with different success probabilities and side-effect profiles:

    TreatmentSuccess Prob.Side Effect Severity (0–10)Recovery Time (days)Cost ($1000)
    Surgery0.9083050
    Radiation0.7551420
    Medication0.50275

    Step 1: Define utility function over outcomes. A successful cure with mild side effects is best.

    Step 2: For each treatment, compute expected utility:

    U(Surgery) = 0.90 × U(success,sev.8) + 0.10 × U(failure,sev.8)
    U(Radiation) = 0.75 × U(success,sev.5) + 0.25 × U(failure,sev.5)
    U(Medication) = 0.50 × U(success,sev.2) + 0.50 × U(failure,sev.2)

    Step 3: Suppose U(success,sev.8)=70, U(failure,sev.8)=10, U(success,sev.5)=85, U(failure,sev.5)=30, U(success,sev.2)=60, U(failure,sev.2)=40.

    Surgery: 0.90(70) + 0.10(10) = 63 + 1 = 64
    Radiation: 0.75(85) + 0.25(30) = 63.75 + 7.5 = 71.25
    Medication: 0.50(60) + 0.50(40) = 30 + 20 = 50

    Treatment with highest expected utility: Radiation (EU = 71.25). Despite surgery having higher success probability, its severe side effects reduce its overall utility.

    Example 3: Speed vs Safety Trade-Off in Taxi Driving

    Scenario: A self-driving taxi must decide its driving policy. It can drive at different speeds, each affecting arrival time and accident risk:

    Speed (km/h)Arrival Time (min)Accident ProbabilityUtility if Arrive SafeUtility if Accident
    40 (Slow)450.00160-100
    60 (Moderate)300.0185-100
    80 (Fast)220.0590-100
    100 (Very Fast)180.1580-100

    Step 1: Compute expected utility: EU(speed) = (1 - P(acc)) × U(safe) + P(acc) × U(accident)

    Slow (40): 0.999(60) + 0.001(-100) = 59.94 - 0.1 = 59.84
    Moderate (60): 0.99(85) + 0.01(-100) = 84.15 - 1.0 = 83.15
    Fast (80): 0.95(90) + 0.05(-100) = 85.5 - 5.0 = 80.50
    Very Fast (100): 0.85(80) + 0.15(-100) = 68.0 - 15.0 = 53.00

    Optimal speed: 60 km/h (EU = 83.15). Going faster increases accident probability too much, ruining expected utility. Going slower is too safe but unsatisfyingly slow.

    Example 4: College Admission — Choosing Between Universities

    Scenario: A student is accepted to three universities and must choose based on multiple criteria:

    UniversityReputation (0–100)Annual Cost ($K)Location Score (0–10)Program Strength (0–10)Job Placement (%)
    University A (Ivy League)98709995
    University B (State School)75257782
    University C (Local College)60125570

    Step 1: Normalize each attribute. Step 2: Assign weights based on student priorities (Reputation: 0.3, Cost: 0.25, Location: 0.1, Program: 0.2, Placement: 0.15).

    Step 3: Compute weighted utility.

    A: 0.3(1.0)+0.25(0.0)+0.1(1.0)+0.2(1.0)+0.15(1.0) = 0.30+0.00+0.10+0.20+0.15 = 0.75
    B: 0.3(0.39)+0.25(0.78)+0.1(0.50)+0.2(0.50)+0.15(0.48) = 0.118+0.195+0.050+0.100+0.072 = 0.535
    C: 0.3(0.00)+0.25(1.0)+0.1(0.00)+0.2(0.00)+0.15(0.00) = 0.00+0.25+0.00+0.00+0.00 = 0.25

    University A has the highest utility (0.75). However, if the student prioritizes cost (wcost = 0.5), University B may win — demonstrating weight sensitivity.

    Sensitivity Check: If cost weight increases to 0.5 (reducing reputation to 0.1):
    A: 0.1(1.0)+0.5(0.0)+0.1(1.0)+0.2(1.0)+0.1(1.0) = 0.10+0.00+0.10+0.20+0.10 = 0.50
    B: 0.1(0.39)+0.5(0.78)+0.1(0.50)+0.2(0.50)+0.1(0.48) = 0.039+0.390+0.050+0.100+0.048 = 0.627
    Now University B is optimal! This shows how utility functions encode values — change the weights, change the decision.
    Example 5: Investment Portfolio — Balancing Risk vs Return

    Scenario: An investor must allocate capital across three assets. Each has different expected return and risk (variance):

    AssetExpected Return (%)Risk (Std Dev %)Liquidity (0–10)
    Stocks12209
    Bonds558
    Real Estate8103

    Step 1: The utility function must incorporate risk aversion. Use a mean-variance utility:

    Mean-Variance Utility:
    U(asset) = μ - γ σ²
    Where μ = expected return, σ² = variance, γ = risk aversion coefficient.

    Step 2: With γ = 0.5 (moderate risk aversion), compute utilities:

    Stocks: 12 - 0.5(400) = 12 - 200 = -188
    Bonds: 5 - 0.5(25) = 5 - 12.5 = -7.5
    Real Estate: 8 - 0.5(100) = 8 - 50 = -42

    Step 3: Including liquidity with weight 0.1 (return weight 0.6, risk weight 0.3):

    Stocks: 0.6(-188) + 0.3(0) + 0.1(9) = -112.8 + 0 + 0.9 = -111.9
    Bonds: 0.6(-7.5) + 0.3(1.0) + 0.1(8) = -4.5 + 0.3 + 0.8 = -3.4
    Real Estate: 0.6(-42) + 0.3(0.75) + 0.1(3) = -25.2 + 0.225 + 0.3 = -24.675

    Bonds have the highest utility (-3.4). The high risk of stocks (large variance) dominates, even though its expected return is highest. A risk-seeking investor (low γ) would choose stocks instead.

    Quick Reference Card

    Core Formula

    U: S → ℝ
    a* = argmax Σ P(s')U(s')

    When to Use

  • Multiple paths to goal
  • Conflicting objectives
  • Uncertain outcomes
  • Quality matters, not just completion

    • Key Distinction

    Goal-based: Binary satisfaction

    Utility-based: Continuous degree of satisfaction

    Common Pitfalls

    Pitfall 1: Ill-Defined Weights
    Using arbitrary weights produces arbitrary decisions. Always derive weights from domain knowledge or preference elicitation.
    Pitfall 2: Ignoring Interactions
    Additive utility assumes independence between attributes. When attributes interact (e.g., safety and cost), use multiplicative or more complex utility structures.
    Pitfall 3: Over-Optimization
    Maximizing utility on a single criterion while ignoring robustness can lead to brittle behavior. Always test under different scenarios.

    Summary: Utility-Based Agent Architecture

    Sensor Input → [ Perceive ] → [ Model World ] → [ Predict Outcomes ] → [ Compute Expected Utility ] → [ Select Action ] → Actuator Output ↑ Utility Function U(s)
    Exam Tip: The key difference between goal-based and utility-based agents is that goals provide a binary evaluation (satisfied/not satisfied), while utility provides a continuous measure. This lets utility-based agents make fine-grained trade-offs and handle uncertainty through expected value maximization.
