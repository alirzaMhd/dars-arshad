Artificial Intelligence — Chapter 1: AI and Intelligent Agents

What is an Agent?

An agent is anything that can perceive its environment through sensors and act upon that environment through actuators (effectors).

Human Agent
Sensors: eyes, ears, skin, etc.
Actuators: hands, legs, mouth
Robotic Agent
Sensors: cameras, IR range finders, microphones
Actuators: motors, grippers, speakers
Software Agent
Sensors: bit strings (keyboard input, file contents, network packets)
Actuators: bit strings (screen output, file writes, network transmissions)

The Agent Cycle

  1. Perceive: Agent receives percepts from the environment via sensors.
  2. Process: Agent uses its agent function to decide which action to take.
  3. Act: Agent performs the chosen action via actuators, affecting the environment.
  4. Repeat: The cycle continues — each action changes the environment, leading to new percepts.
Common Mistake: An agent is NOT just a program. A program becomes an agent only when it is embedded in an environment with sensors and actuators — i.e., it can perceive and act. A standalone function is merely a component, not an agent.

Abstract Agent Definition

The behavior of an agent is formally defined by its agent function, which maps any percept history to an action:

Agent Function
f : P* → A
The agent function f maps every possible sequence of percepts (P*) to an action (A)
P*
The set of all possible percept sequences (including the empty sequence)
A
The set of all possible actions the agent can perform
Agent Program
The concrete implementation of the abstract agent function (runs on physical hardware)

Percept History

The percept history is the complete record of everything the agent has ever perceived. At any point in time, the agent's decision depends on this entire history — not just the current percept. However, storing the full history is impractical, which is why agents maintain an internal state (a summary of relevant past percepts).

Percept History Notation
h(t) = (p₁, p₂, ..., pₜ)
The percept history at time t is the sequence of all percepts from time 1 to t
Key Insight: The agent function is an ideal mathematical abstraction. The actual behavior we observe is the agent program running on the agent's architecture. Two agents with the same agent function but different programs/architectures may behave identically in principle, but differ in speed, memory, or feasibility.

Performance Measure

A performance measure is an external standard that evaluates how successful an agent is in achieving its objectives. It must be defined from the designer's perspective, not the agent's internal goals.

Evaluation
Performance = Evaluation(Agent Behavior, Environment, Time Horizon)
Performance is measured over a time horizon (e.g., an 8-hour cleaning shift for a vacuum cleaner)
Example: Vacuum Cleaner Performance

Consider an autonomous vacuum cleaner. What metrics measure its success?

  • Amount of dirt cleaned — primary measure of effectiveness
  • Time taken — how long to finish the job
  • Power consumption — energy efficiency over the shift
  • Noise level — disturbance to occupants
  • Coverage area — percentage of floor cleaned
  • Number of collisions — safety measure
Critical: Performance must be measured over the entire operating period. A vacuum cleaner that cleans dirt quickly but damages furniture is not successful. A long-term view (e.g., an 8-hour shift) prevents the agent from optimizing short-term gains at the expense of long-term costs.

Designing Performance Measures

  • Must be objective and quantifiable
  • Should reflect the long-term consequences of actions
  • Avoid proxy metrics that can be gamed (e.g., "lines of code written" != "productivity")
  • Consider multiple criteria — rarely a single number captures success

Rationality vs Omniscience

Rationality
Maximizing expected performance given the available percept sequence and built-in knowledge
Omniscience
Knowing the actual outcome of actions — impossible in the real world
Perfection
Achieving the best actual outcome (only possible with omniscience)
Rational Agent Definition
Action = argmaxa ∈ A E[ Performance | PerceptHistory, Knowledge ]
A rational agent chooses the action that maximizes the expected value of the performance measure, given the percept history and what the agent knows

Example 2: Crossing the Champs-Elysees

Scenario: You need to cross a busy street in Paris (the Champs-Elysees). You look both ways, see no cars coming, and step into the street.

  • Rational? YES — Given the information available (no cars visible), crossing is the action that maximizes expected safety and efficiency.
  • Omniscient? NO — You cannot know if a speeding motorcycle hidden behind a large truck will hit you mid-crossing.
  • Perfect? Depends on outcome — If you cross safely, perfection matches rationality. If a falling object hits you, your rational choice still led to an imperfect outcome.
Critical Distinction: A rational action can lead to a bad outcome, and an irrational action can lead to a good outcome. Rationality is about the decision process, not the outcome. Do not confuse rationality with success — an agent can be rational and still fail due to bad luck.

The Four Rationality Conditions

An agent is rational if, for each possible percept sequence:

  1. Performance measure defines success criteria
  2. Built-in knowledge of the environment is used (prior knowledge)
  3. Actions available to the agent are considered
  4. Percept history to date informs the decision

Information Gathering

Information gathering is the act of seeking knowledge that improves future decisions. A rational agent must be willing to explore — even at a short-term cost — if the information gained leads to better long-term performance.

Example 4: Taxi Driver Information Gathering

Scenario: A self-driving taxi approaches an intersection. It sees a green light, but also notices a construction crane partially blocking the road ahead.

  • Without information gathering: The taxi simply drives through the green light and risks collision with the crane.
  • With information gathering: The taxi slows down and uses its sensors to gather more information — zooming the camera, checking LIDAR data for the crane's position, possibly waiting to see if the crane moves.

Information gathering is rational when the expected value of the information exceeds the cost of obtaining it. By spending 2 seconds gathering data, the taxi may avoid a collision — a clear net benefit.

Value of Information
VoI = E[Performance | Information] - E[Performance | No Information] - Cost(Gathering)
An information-gathering action is rational when the expected improvement in performance exceeds the cost of gathering the information
Looking Both Ways
Before crossing a street — costs 2 seconds, may save your life
Reading Reviews
Before buying a product — costs minutes, prevents bad purchases
Medical Tests
Before treatment — costs money/time, prevents incorrect diagnosis

Autonomy

Autonomy is the degree to which an agent's behavior depends on its own experience rather than built-in knowledge from the designer.

Autonomy Spectrum
Fully Reactive ← — — — Autonomous → — — — Fully Self-Sufficient
More autonomy = less reliance on built-in knowledge, more reliance on learning from experience
Low Autonomy
Agent follows fixed rules; cannot adapt to new situations. E.g., a clock that always assumes it is in California.
High Autonomy
Agent learns from experience; adjusts behavior to new environments. E.g., a clock that uses GPS to detect time zone changes.
Ideal Agent
Initial built-in knowledge + ability to learn from experience to compensate for gaps and adapt.
Example 3: The Clock Traveling from California to Australia

Scenario: A standard alarm clock is manufactured in California, then shipped to Sydney, Australia.

  • Initial state: Clock displays 12:00 PM PST (California time).
  • After travel: Clock still shows 12:00 PM PST — it has no sensors to detect that it has moved time zones.
  • User sets it: User manually adjusts the time to 6:00 AM AEDT (Australia time).
  • Problem: A month later, Daylight Saving Time begins in Sydney (Oct 1, AEDT→AEDT+1). The clock fails to adjust.

Result: This clock has low autonomy. Its behavior depends entirely on the designer's built-in knowledge (assumption: "this clock is used in California"). It cannot detect or adapt to its actual environment.

Key Insight: An agent that relies entirely on built-in knowledge might perform well in the designer's expected environment but will fail catastrophically when the environment changes. The designer cannot anticipate every possible scenario — learning is essential for robust behavior.

Ideal Agent Design
Autonomous Agent = Built-in Knowledge + Learning Ability
Start with useful priors, then learn from experience to fill gaps and adapt to changing environments

The ideal agent strikes a balance: it starts with enough built-in knowledge to perform reasonably from the beginning, but has the capacity to learn from experience to improve and adapt. A purely learning agent (no built-in knowledge) would start from scratch and might take too long to become competent. A purely built-in agent (no learning) would be inflexible.

A learning agent has four conceptual components:

  • Performance Element: The agent itself — selects actions based on percepts
  • Learning Element: Responsible for making improvements (learning from feedback)
  • Critic: Provides feedback on the agent's performance (e.g., "that action was bad")
  • Problem Generator: Suggests exploratory actions to gain new information

Autonomy and Rationality

Autonomy and rationality are closely linked. An agent that cannot learn (no autonomy) will eventually make irrational decisions when its built-in knowledge becomes outdated or the environment changes. Conversely, an agent that can learn can maintain rationality over time by updating its knowledge.

Rationality Over Time
Rational(t+1) = f(Rational(t), Experience(t), Learning)
Rationality is not static — a learning agent can maintain rationality as the environment evolves

Worked Example 1: Vacuum Cleaner Agent

Domain: A simple two-square vacuum cleaner world (Square A and Square B). The vacuum cleaner can perceive its current square and whether there is dirt present.

Agent Specification
Percepts: [Location, Content]    Location ∈ {A, B}    Content ∈ {Dirty, Clean}
Actions: {Left, Right, Suck, NoOp}
The agent senses its location and whether the current square is dirty, then chooses an action

Agent Function Table

LocationContentActionRationale
ADirtySuckClean the dirty square
ACleanRightMove to the other square
BDirtySuckClean the dirty square
BCleanLeftMove to the other square

Performance Analysis

If we define the performance measure as "percentage of squares cleaned per 8-hour shift", this agent achieves 100% in this simple world. However, consider:

  • If dirt appears while the agent is in the other square, the agent won't detect it until it returns — partial observability
  • If we add a third square C, the agent needs a new action or the table grows — scalability issue
  • If the agent's Suck action consumes 50% battery per use, the agent should minimize Suck actions — resource constraint
Common Mistake: Students often think this agent is rational in all environments. It is only rational under the specific performance measure "maximize cleanliness." If the performance measure were "minimize power consumption," the rational action for a clean square would be NoOp, not moving.

Worked Example 4: Taxi Driver Information Gathering

Scenario: A self-driving taxi navigating an urban environment.

Without Information Gathering
"Green light means go" — drives through intersection.
Risk: collision with crane/pedestrian/emergency vehicle.
With Information Gathering
"Green light but cross-check sensors" — slows, scans.
Benefit: avoids collision, adapts to unexpected events.

Information gathering actions the taxi should perform:

  1. Scan cross-traffic — even with a green light, check for running red lights
  2. Check pedestrian crossings — look for jaywalkers or pedestrians on phone
  3. Check road surface — look for ice, potholes, debris
  4. Check blind spots — use side cameras/mirrors

Each information-gathering action has a cost (time, computation) but yields valuable data. The rational taxi performs information gathering when the expected value of the information exceeds the cost. For example, slowing from 50 km/h to 30 km/h for 2 seconds at an intersection costs ~11 meters of distance but may prevent a fatal collision.

Expected Value of Information Gathering
EV(Scan) = P(Obstacle) × Cost(Collision) - Cost(Scan)
If P(Obstacle) = 0.001, Cost(Collision) = 100, Cost(Scan) = 0.1
EV(Scan) = 0.001 × 100 - 0.1 = 0 → break-even
In practice, the probability of an obstacle at an intersection is much higher than 0.001, making scanning clearly rational.

Worked Example 5: Performance Measure Comparison

Scenario: A warehouse robot must organize boxes. Compare four different performance measures:

MeasureDefinitionBehaviorFailure Mode
Boxes moved per hourCount boxes relocatedGrab nearest box, move quicklyDrops boxes, breaks fragile items
Accuracy score% of boxes at correct locationMove slowly, verify locationVery slow, low throughput
Energy efficiencyBoxes moved per kWhOptimize path, batch movesComplex planning, may miss deadlines
Customer satisfactionSurvey score (speed + accuracy + safety)Balanced approachHard to measure; requires user feedback

Optimal approach: A weighted utility function combining multiple measures: U = w₁·Throughput + w₂·Accuracy - w₃·EnergyCost - w₄·BreakagePenalty. The weights reflect the designer's true priorities.

Important: Choosing the wrong performance measure is one of the most common AI design mistakes. If you measure "boxes moved per hour," the agent will move lightweight boxes rapidly and ignore heavy ones — it optimizes the proxy, not the true goal.

Exam Tips

Most Common Exam Mistakes:
  • Confusing rationality with success: A rational agent can fail due to bad luck. An irrational agent can succeed by chance. Rationality is about the process, not the outcome.
  • Confusing autonomy with intelligence: An autonomous agent (high learning ability) may initially perform worse than a non-autonomous agent with excellent built-in knowledge — but will adapt better to change.
  • Forgetting the percept history: The agent function maps percept sequences (not just current percepts) to actions. History matters.
  • Thinking all agents need learning: Simple reflex agents are perfectly appropriate for fully observable, deterministic environments.
  • Ignoring information gathering costs: Every information-gathering action consumes resources — it must be justified by expected value.
