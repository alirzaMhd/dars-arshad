Agent Structure & Design

Artificial Intelligence — Chapter 1: AI and Intelligent Agents

Agent = Program + Architecture

An intelligent agent is composed of two inseparable parts:

Core Formula:
Agent = Architecture + Agent Program
An agent is the combination of its physical/sensory architecture and the program that runs on it.

Architecture

The hardware/software infrastructure:

• Sensors → receive percepts from the environment

• Effectors → perform actions in the environment

The architecture delivers percepts from sensors to the agent program and transmits chosen actions to effectors.

Agent Program

The decision-making algorithm:

• Maps percepts to actions

• Runs on the architecture

• Implements the agent function

The agent program is the “mind” — it chooses what to do next.

⚠ Warning: Architecture and program are interdependent. A program that assumes infinite memory will fail on a resource-constrained device. Always specify both when designing an agent.

How They Work Together

Sensors → [percepts] → Architecture → [percepts] → Agent Program | Effectors ← [actions] ← Architecture ← [actions] ←+

The architecture is the bridge between the agent program and the environment.

Agent Function vs Agent Program

Agent Function f

A mathematical mapping from percept sequences to actions:

Agent Function:
f : P* → A
Where P* is the set of all possible percept sequences, A is the set of all possible actions.

• Abstract — describes what the agent should do

• Independent of implementation details

• Used for theoretical analysis of ideal behavior

Agent Program

A concrete implementation that runs on the architecture:

• Written in a programming language

• Executes on real hardware

• May use approximations, heuristics, or learned models

• Has time and memory constraints

The agent program approximates the ideal agent function as closely as the architecture permits.

Key Insight:
Agent Function (ideal) ≠ Agent Program (actual)
The program is a practical approximation of the function. The same function can be implemented by many different programs.
Example: Vacuum-Cleaner Agent

Agent function: “If the current square is dirty, suck; otherwise move to the other square.”

Agent program: A Python class with if percept == 'dirty': return 'suck' running on a Roomba-like microcontroller with a dirt sensor and wheels.

The function specifies the ideal rule. The program implements that rule using the architecture’s specific sensors and actuators.

⚠ Warning: A single agent function may map to infinitely many equivalent programs, and a single program may approximate multiple functions. Exam questions often test that you distinguish between the mathematical ideal (function) and the practical implementation (program).

PEAS Framework

PEAS is the standard framework for describing and designing intelligent agents. It specifies four dimensions:

Performance Measure

The evaluation criteria — how do we know the agent is doing well?

Examples: accuracy, speed, safety, profit, user satisfaction.

Environment

The context the agent operates in.

Properties: fully/partially observable, deterministic/stochastic, dynamic/static, discrete/continuous, single/multi-agent.

Actuators

The actions the agent can perform (also called effectors).

Examples: robotic arms, display screens, speakers, wheels.

Sensors

The means by which the agent perceives the environment.

Examples: cameras, microphones, keyboards, network sockets, thermometers.

⚠ Historical Note: In the first edition of Russell & Norvig, the framework was called PAGE (Percepts, Actions, Goals, Environment). The current PEAS framework replaced PAGE starting with the second edition. PEAS separates sensors from the data they produce (percepts) and actuators from the effects they produce.
PEAS Design Process:
Define P → Define E → Define A → Define S
Always start with the performance measure, since it shapes what the agent should optimize for.

Environment Properties

Environments along each binary dimension:

DimensionPossible ValuesDefinition
ObservabilityFully / PartiallyCan sensors access the complete state of the environment?
DeterminismDeterministic / StochasticDoes the next state depend only on current state + action?
DynamismDynamic / StaticDoes the environment change while the agent deliberates?
DiscretenessDiscrete / ContinuousAre there a finite number of distinct states and actions?
EpisodicityEpisodic / SequentialDoes each percept-action pair constitute an independent episode?
Agent CountSingle-agent / Multi-agentAre there other agents in the environment?
Tip: Most real-world environments are partially observable, stochastic, dynamic, continuous, sequential, and multi-agent. Designing agents under these constraints is the central challenge of AI.

Skeleton Agent Program

The skeleton agent is the canonical abstract framework for any reactive agent. Every specific agent (simple reflex, model-based, goal-based, utility-based) is a specialization of this skeleton.

Pseudocode

function SKELETON-AGENT(percept) returns action static: memory // agent's memory of the world memory ← UPDATE-MEMORY(memory, percept) action ← CHOOSE-BEST-ACTION(memory) memory ← UPDATE-MEMORY(memory, action) return action

Step-by-Step Execution

StepCode LineDescription
1 Receive percept The architecture delivers the latest sensor reading to the agent program.
2 UPDATE-MEMORY(memory, percept) Integrate the new percept into the internal state — updates the agent’s knowledge of the world.
3 CHOOSE-BEST-ACTION(memory) Select the best action based on current memory. This is where the core intelligence resides.
4 UPDATE-MEMORY(memory, action) Update memory to reflect the action about to be taken (e.g., for planning or tracking own state).
5 Return action Deliver the chosen action back to the architecture for execution by effectors.
⚠ Warning: The UPDATE-MEMORY call appears twice: once after perceiving and once before returning the action. The first updates world knowledge; the second updates the agent's own state (e.g., that it is about to act). Forgetting the second update is a common implementation bug.

Specializations of the Skeleton

Simple Reflex Agent

Memory = empty. Action depends only on current percept.

CHOOSE-BEST-ACTION → condition-action rules.

Model-Based Agent

Memory stores a model of the world.

UPDATE-MEMORY maintains internal model.

Goal-Based Agent

Memory includes goal states.

CHOOSE-BEST-ACTION searches for actions reaching goals.

Utility-Based Agent

Memory includes utility function.

CHOOSE-BEST-ACTION maximizes expected utility.

Worked Examples — PEAS in Practice

Each example applies the PEAS framework to a concrete AI agent.

Example 1 — Medical Diagnosis System

Scenario: An AI system assists doctors by analyzing patient symptoms, lab results, and medical history to suggest possible diagnoses and treatments.

P — Diagnostic accuracy, speed (minutes vs hours), patient recovery rate, cost per diagnosis, false-positive and false-negative rates.

E — Hospital ward, electronic health records (EHR), lab results database, doctor’s consultation room, potentially noisy or incomplete patient data.

A — Display screen (showing diagnosis and treatment options), printer (reports), alert system (critical conditions), integration interface with hospital management system.

S — Keyboard (manual symptom entry), network interface (EHR database queries), lab equipment data feeds, microphone (voice input for hands-free operation).

Key insight: The environment is partially observable (symptoms may not capture the full pathology) and stochastic (same symptoms can indicate different illnesses). The system must handle uncertainty.

Example 2 — Satellite Image Analysis System

Scenario: An AI agent analyzes satellite imagery to classify land use (urban, forest, water, agricultural), detect changes over time, and generate annotated maps for environmental monitoring.

P — Classification accuracy (% correct), false-alarm rate (e.g., misclassifying forest as urban), coverage (km² processed per day), timeliness (hours from image capture to annotated output).

E — Satellite orbit, multi-spectral image feeds (visible, infrared, radar), cloud cover (noise), seasonal changes, different geographic regions with varying lighting.

A — Display screen (classified map overlay), data export API (GeoJSON, shapefiles), report generator, alert system (flood detection, deforestation).

S — Multi-spectral cameras (visible + IR bands), synthetic aperture radar, infrared thermometers, GPS coordinate receiver, time-stamping system.

Key insight: The environment is continuous (images are pixel arrays) and partially observable (clouds occlude ground features). The agent must fuse data from multiple spectral bands to improve classification.

Example 3 — Part-Picking Robot

Scenario: A robotic arm on an assembly line picks parts of varying shapes from a moving conveyor belt and places them into bins for packaging.

P — Parts picked per minute (throughput), placement accuracy (±mm), breakage rate (dropped or damaged parts), energy consumption, downtime due to errors.

E — Factory floor, conveyor belt (moving), bins, parts with different sizes/shapes/materials, variable lighting, vibration, noise from machinery.

A — Robotic arm joints (6-axis movement), gripper (open/close), suction cup (on/off), conveyor belt stop signal, sorting mechanism.

S — RGB cameras (part identification), depth sensors (position estimation), force sensors in gripper (grasp quality), joint encoders (arm position), proximity sensors.

Key insight: This is a dynamic environment (conveyor keeps moving) requiring real-time decisions. The robot must predict where the part will be by the time the arm reaches it.

Example 4 — Refinery Controller

Scenario: An AI system controls a petrochemical refinery: managing valves, heaters, and pumps to optimize fuel yield while maintaining safe temperature and pressure levels.

P — Yield percentage (output/input), energy efficiency (BTU per barrel), safety incidents (zero is ideal), uptime percentage, emissions compliance.

E — Oil refinery with interconnected pipes, distillation columns, catalytic crackers; changing crude oil composition; temperature and pressure zones; strict safety regulations.

A — Motorized valve actuators (open/close/partial), heater elements (temperature control), pump motors (flow rate), emergency shutoff switches, alarm systems.

S — Thermocouples (temperature), pressure transducers, flow meters, chemical composition analyzers (gas chromatographs), vibration sensors, level sensors in tanks.

Key insight: The environment is continuous and highly stochastic (crude oil composition varies). Safety constraints are hard boundaries — the agent must never exceed pressure limits even if it reduces yield.

Example 5 — English Tutor

Scenario: An AI tutoring system teaches English to non-native speakers. It adapts lessons, provides exercises, and gives personalized feedback based on the learner’s progress.

P — Student test score improvement, engagement time (minutes per session), learning speed (lessons completed per week), student retention rate, user satisfaction surveys.

E — Online learning platform (web/mobile), students with varying proficiency levels (A1-CEFR to C2), different native languages, differing learning paces, internet connectivity issues.

A — Screen display (lessons, exercises, flashcards), audio output (pronunciation examples), text feedback (corrections), progress report generation, adaptive difficulty adjustment.

S — Keyboard (typed answers), mouse/touch (UI interactions), microphone (spoken answer recording), webcam (optional eye gaze/engagement tracking), quiz response database.

Key insight: This is a multi-agent environment (student + teacher/parents). The tutor must model the student’s knowledge state (partially observable) and select exercises that are neither too easy nor too hard.

Example 6 — Autonomous Taxi Driver

Scenario: A fully self-driving taxi navigates city streets, picks up passengers, and transports them to their destination safely and efficiently.

P — Safety (zero collisions), travel time, fuel/energy efficiency, passenger comfort (smooth acceleration/braking), earnings per hour, customer ratings.

E — City roads, traffic lights, pedestrians, other vehicles, weather conditions (rain, snow, fog), road construction, GPS zones, varying speed limits.

A — Steering wheel (angle control), accelerator pedal, brake pedal, turn signals, horn, headlights, interior display (route info), door locks.

S — Cameras (360° vision), LIDAR (3D depth mapping), radar (distance/speed), GPS (location), inertial measurement unit (acceleration), microphones (passenger voice), speedometer, odometer.

Key insight: The taxi driver operates in a partially observable, stochastic, dynamic, continuous, multi-agent environment — the hardest category. It must predict the behavior of pedestrians and other drivers while maintaining safety in real-time.

Practice Questions

Q1: What is the difference between an agent function and an agent program?

A: An agent function is an abstract mathematical mapping f: P* → A, while an agent program is a concrete implementation that runs on a specific architecture to approximate that function.

Q2: Why do we design agents starting with the performance measure?

A: The performance measure determines what the agent should optimize for. All subsequent design decisions (environment understanding, actuator capabilities, sensor requirements) follow from what we want the agent to achieve.

Q3: In the skeleton agent, why is UPDATE-MEMORY called twice?

A: The first call updates the world model with the new percept. The second call records the chosen action in memory so that the agent can track what it is about to do — essential for planning, execution monitoring, and learning from outcomes.
