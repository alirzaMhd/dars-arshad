Artificial Intelligence — Chapter 1: AI and Intelligent Agents

What is a Simple Reflex Agent?

A simple reflex agent is the most basic type of intelligent agent. It selects actions based only on the current percept — it has no memory of past percepts and no internal model of how the world evolves.

Percept → State Description → Rule Match → Action

The agent's decision-making follows a simple pipeline: the raw percept from sensors is interpreted into a description of the current state, which is matched against a set of condition-action rules. The first matching rule determines the action.

Agent Function (Mathematically):
f : P → A
The agent function maps every possible percept directly to an action, with no intermediate state or memory.

Pseudocode: SIMPLE-REFLEX-AGENT

function SIMPLE-REFLEX-AGENT(percept) returns action -- persistent: rules, a set of condition-action rules state ← INTERPRET-INPUT(percept) rule ← RULE-MATCH(state, rules) action ← RULE-ACTION[rule] return action

Key Characteristics

• Responds only to current percept

• No memory of past states

• No internal world model

• Uses condition-action (IF-THEN) rules

• Fast and efficient

Complexity

Time: O(n) (n = number of rules)

Space: O(r) (r = number of rules)

Rule Matching: O(n·m)

m = complexity of matching condition

Condition-Action Rules

Condition-action rules are the core decision mechanism of simple reflex agents. They take the form:

Condition-Action Rule Template:
IF <condition> THEN <action>
If the current state matches the condition, execute the specified action.
DomainCondition (IF)Action (THEN)
DrivingCar in front is brakingApply brakes
Vacuum cleaningCurrent square is dirtySuck dirt
ThermostatTemperature < 18°CTurn on heater
Blinking reflexObject approaching eyeClose eyelid
Ping-pong robotBall approaching on leftMove paddle left

These rules can be either innate (hardwired, like biological reflexes) or acquired (learned, like driving skills).

Interpret-Input and Rule-Match Process

The two key functions that bridge sensors to actions:

• INTERPRET-INPUT

Converts the raw, high-bandwidth percept into a compact state description. For example, a camera feed (50 MB/s for a typical visual camera) is reduced to a symbolic description like "car ahead is braking".

• RULE-MATCH

Searches the set of condition-action rules to find one whose condition matches the current state description. Returns the first matching rule (or the best match).

INTERPRET-INPUT

Input: Raw sensor data (percept)

Output: Abstract state description

E.g., 50 MB camera frame → "object approaching"

RULE-MATCH

Input: State description + rule set

Output: Matching rule

E.g., matches "object approaching" → "blink"

Table-Driven Agent

A table-driven agent is an even simpler (but impractical) approach where the entire agent function is stored in a lookup table indexed by percept sequences, rather than by matching rules against an interpreted state.

Table-Driven Agent Function:
action = TABLE[percept1, percept2, ..., perceptt]
Every possible percept sequence has a pre-defined action in the table.

Pseudocode: TABLE-DRIVEN-AGENT

function TABLE-DRIVEN-AGENT(percept) returns action -- persistent: percepts, a sequence, initially empty -- table, indexed by percept sequences, initially fully specified append percept to the end of percepts action ← LOOKUP(percepts, table) return action

The Four Fatal Flaws of Table-Driven Agents

1. Enormous Table Size

For chess, the table would need ~35100 entries — more atoms than in the observable universe.

Size grows as PT where P = percepts, T = time steps.

2. Prohibitively Long Build Time

Filling the table correctly for every possible percept sequence is infeasible for any non-trivial environment.

3. High Error Rate

With billions of entries, the probability of an incorrect or suboptimal action in at least one entry approaches certainty.

4. No Autonomy

The agent has no ability to handle novel situations. If the environment behaves differently from what the table encodes, the agent fails.

⚠ Common Mistake: The table-driven agent is NOT the same as a simple reflex agent. A table-driven agent stores actions for every possible percept sequence (exponential growth), while a simple reflex agent uses general rules matched against the current percept only. The table-driven approach is a straw-man that demonstrates why we need better agent architectures.

Key Insight

The table-driven approach is mathematically infeasible for any realistic environment. Simple reflex agents solve this by generalizing from specific percept sequences to condition-action rules, reducing the infinite space of percept histories to a finite set of relevant conditions.

Limitations of Simple Reflex Agents

⚠ Core Limitation: Simple reflex agents work only when the correct action can be determined from the current percept alone. They cannot reason about unobserved parts of the world, past states, or future consequences.

No Memory

Cannot use past percepts to inform decisions. If the current percept is ambiguous, the agent has no way to disambiguate it using history.

Partial Observability Failure

In partially observable environments, the current percept may not contain enough information to determine the correct action. Example: a card player cannot see opponents' cards.

No Look-Ahead

Cannot evaluate future consequences of actions. The agent reacts, but never plans. This makes it unsuitable for strategic tasks like chess or negotiation.

Rule Coverage Gap

If a situation arises that no condition-action rule covers, the agent has no fallback. It simply fails to act or acts randomly.

Worked Examples

Example 1: Vacuum Cleaner Simple Reflex Agent

Environment: A vacuum cleaner in a two-square world (squares A and B). Each square can be clean or dirty.

Sensors: Location sensor (A or B) and dirt sensor (clean or dirty at current location).

Actuators: MoveLeft, MoveRight, Suck.

Percept (Location, Dirt Status)State DescriptionAction
[A, Dirty]Current square dirtySuck
[A, Clean]Current square cleanMoveRight
[B, Dirty]Current square dirtySuck
[B, Clean]Current square cleanMoveLeft
-- Rule set for the vacuum cleaner agent rule 1: IF location=A AND dirty=yes THEN Suck rule 2: IF location=A AND dirty=no THEN MoveRight rule 3: IF location=B AND dirty=yes THEN Suck rule 4: IF location=B AND dirty=no THEN MoveLeft

Trace: Start in square A (dirty). Percept = [A, Dirty] → INTERPRET = "current square dirty" → matches rule 1 → action = Suck. After sucking, percept = [A, Clean] → matches rule 2 → action = MoveRight...

This agent works perfectly because the environment is fully observable (it always knows both location and dirt status) and the correct action depends only on the current percept.

Example 2: Car Braking Reflex Agent

Environment: A car driving on a highway. The car ahead may brake at any time.

Sensors: Camera (to detect brake lights of the car ahead), radar (to measure distance).

Actuators: Accelerate, Brake, Steer.

-- Rule set for car following rule 1: IF brake_lights_ahead=ON AND distance=close THEN Brake(hard) rule 2: IF brake_lights_ahead=ON AND distance=moderate THEN Brake(gentle) rule 3: IF brake_lights_ahead=ON AND distance=far THEN ReleaseAccelerator rule 4: IF brake_lights_ahead=OFF AND distance=close THEN Brake(gentle) rule 5: IF brake_lights_ahead=OFF AND distance=far THEN Accelerate

Trace: Percept = [brake_lights=ON, distance=5m] → INTERPRET-INPUT produces "car ahead braking, close" → RULE-MATCH matches rule 1 → action = Brake(hard).

This works because braking is a purely reactive task. However, this simple reflex agent would fail if the car ahead's brake lights were broken (partial observability) — it wouldn't know to brake.

Example 3: Human Blinking Reflex (Innate Simple Reflex)

Environment: A person walking outdoors. Debris (dust, insects) may fly toward the eye.

Sensors: Optic nerve (visual input), trigeminal nerve (touch sensation on cornea).

Actuators: Orbicularis oculi muscle (closes eyelid).

-- Innate reflex rule (hardwired in brainstem) rule: IF object_approaching_eye=TRUE THEN CloseEyelid(immediate)

Trace: A speck of dust flies toward the eye. Visual cortex detects rapid expansion of an object on a collision course. INTERPRET-INPUT converts raw visual data to "object approaching eye." RULE-MATCH finds the matching innate reflex. Action: eyelid closes in ~100 ms.

Reflex Arc Path

Stimulus (dust) → Sensory neuron → Brainstem → Motor neuron → Muscle contraction

Total time: ~100 ms (faster than conscious processing)

Why Simple Reflex?

No memory needed. No reasoning about consequences. The reflex is purely reactive. Evolution hardwired this as a condition-action rule because the mapping is direct and unambiguous.

Example 4: Chess Table Size Calculation

Problem: Estimate the number of entries needed for a table-driven chess agent that stores an action for every possible percept sequence up to 100 moves (50 moves per player).

Known Values:
Average branching factor ≈ 35
Game length ≈ 100 ply (half-moves)
Number of possible percept sequences = 35100

Calculation:

35100 = 10100 · log10(35) ≈ 10100 · 1.544 = 10154.4 ≈ 2.5 × 10154 entries

ComparisonValue
Table entries for chess~2.5 × 10154
Atoms in the observable universe~1080
Ratio (chess entries / atoms)2.5 × 1074
Time to fill table (1 ns per entry)2.5 × 10145 seconds (far longer than universe age)

Conclusion: A table-driven chess agent is impossible. Even storing one bit per entry would require more memory than all matter in the universe can provide.

This is why simple reflex agents use general rules (like "IF opponent's king is in check THEN protect own king") instead of enumerating all possible board states. Even a simple reflex agent for chess would still be inadequate because chess requires look-ahead, but it avoids the combinatorial explosion of the table-driven approach.

Example 5: Taxi Driving — Where Simple Reflex Fails

Scenario: An autonomous taxi using only a simple reflex agent.

Rule set for the taxi:

rule 1: IF traffic_light=RED THEN Stop rule 2: IF traffic_light=GREEN THEN Go rule 3: IF obstacle_ahead=YES THEN Brake rule 4: IF passenger_wants_stop=YES THEN PullOver

Scenario: The taxi is at an intersection. The traffic light is green. There is a pedestrian who is about to jaywalk but is not yet in the crosswalk. The simple reflex agent sees: [traffic_light=GREEN, obstacle_ahead=NO, pedestrian_visible=YES].

None of the rules handle the case "pedestrian about to jaywalk at a green light." The agent proceeds through the intersection — and hits the pedestrian.

⚠ Failure Analysis: The simple reflex agent fails because:
  1. Partial observability: The current percept doesn't capture the pedestrian's intention to cross.
  2. No model of consequences: The agent cannot reason "if I continue, the pedestrian might step into the road."
  3. No memory of past behavior: The agent doesn't know that the pedestrian has been standing at the curb for 30 seconds (which would indicate they're about to cross).

What architecture would work? A model-based reflex agent that maintains an internal model of the world (predicting pedestrian behavior) combined with a goal-based agent that reasons about the goal "arrive safely" and plans accordingly.
