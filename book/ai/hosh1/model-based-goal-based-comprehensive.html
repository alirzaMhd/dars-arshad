Model-Based & Goal-Based Agents

Artificial Intelligence — Chapter 1: AI and Intelligent Agents

Why Internal State is Needed

A simple reflex agent makes decisions based only on the current percept. This works when the current sensor reading provides enough information to select the correct action. However, in many real-world scenarios, a single percept does not capture the full state of the environment.

Example: In older cars, brake lights and turn signals may look identical from a single camera frame. The agent cannot tell whether the car is braking or signaling without comparing consecutive frames.

To handle such cases, the agent must maintain an internal state — a representation of the world that gets updated over time.

Model-Based Agent Core Idea:
internal_state = UPDATE_STATE(previous_state, action, percept)
The agent combines current percept with stored internal state to decide the next action

Two Types of Knowledge Required

How the world evolves

Knowledge about how the environment changes independently of the agent. Example: a car overtaking the taxi will be closer now than it was a minute ago.

How actions affect the world

Knowledge about the consequences of the agent's own actions. Example: after changing lanes, a gap temporarily opens in the previous lane.

The Model Concept

The knowledge of how the world works and how it changes is called a model of the world. An agent that uses such a model is called a model-based agent. These agents are also known as "agents that keep track of the world".

Pseudocode: Model-Based Reflex Agent

function REFLEX-AGENT-WITH-STATE(percept) returns an action static: state, a description of the current world state rules, a set of condition-action rules action, the most recent action, initially none state ← UPDATE-STATE(state, action, percept) rule ← RULE-MATCH(state, rules) action ← RULE-ACTION(rule) return action

How UPDATE-STATE Works

The UPDATE-STATE function creates a new internal state description by combining:

  • The previous internal state
  • The most recent action taken
  • The new percept from sensors

This allows the agent to track parts of the world that are not directly visible through sensors.

Model-Based Agent Architecture

Components

Sensors → Percepts

State → Internal world model

Model Knowledge → How world evolves + action effects

Rules → Condition-action rules

Effectors → Actions on environment

Data Flow

1. Percept from sensors

2. Combine with internal state + model knowledge

3. Update state via UPDATE-STATE

4. Match state against condition-action rules

5. Execute selected action

Beyond Reflex: Introducing Goals

Knowledge about the current state is not always enough for decision making. Consider a taxi at an intersection — it could turn left, turn right, or go straight. The correct decision depends on the destination, which is a goal.

Key Insight: Goals describe desirable states of the world. The agent must reason about which actions lead to goal states.

How Goal-Based Agents Work

The agent combines:

  • Current state (from percepts + internal model)
  • Goal information (description of desired states)
  • Action outcome knowledge (how actions change the world)

It then selects actions that are expected to achieve the goals.

Search and Planning

When a single action achieves the goal, the problem is simple. But often the agent needs to explore long sequences of actions. This is where search and planning come in — subfields of AI that find action sequences leading to goal states.

Goal-Based Decision Making:
action = argmax_{a ∈ Actions} [ GOAL-ACHIEVED(RESULT(state, a)) ]
Choose the action whose outcome best satisfies the goal

Flexibility Advantage

Goal-based agents are more flexible than reflex agents, though less efficient:

Reflex Agent (Fixed)

Rules pre-programmed by designer

Changing behavior requires rewriting rules

Fast but brittle

Goal-Based Agent (Flexible)

Can reason about new situations

Changing goal = new behavior automatically

Slower but adaptable

Example: Rain Adaptation

If rain starts, a goal-based taxi agent can update its knowledge about brake performance in wet conditions. All behaviors automatically adjust. A reflex agent would require rewriting many condition-action rules.

Goal-Based Agent Architecture

Components

State → Current world description

Model → How world evolves + action effects

Goals → Desired world states

Reasoning → Search & planning

Data Flow

1. Percept → update state

2. Consult model: "What if I do action A?"

3. Check if outcome satisfies goals

4. Search for sequence if needed

5. Execute the action that leads to goal

Comparison of Agent Types

Property Simple Reflex Model-Based Reflex Goal-Based
Uses current percept only Yes No No
Maintains internal state No Yes Yes
Uses world model No Yes Yes
Has explicit goals No No Yes
Performs search/planning No No Yes
Efficiency Highest High Moderate
Flexibility Lowest Low High
Autonomy None Limited Moderate
Key Distinction: In reflex agents, the designer pre-computes the correct action for each situation. In goal-based agents, the agent itself reasons about what action leads to the goal — asking "what happens if I do this?" and "does that satisfy my goal?"

Quick Reference

Model-Based Reflex

• Tracks unobserved world parts

• Uses UPDATE-STATE function

• Requires model of evolution

• Still uses condition-action rules

Goal-Based Agent

• Has explicit goal states

• Performs search & planning

• More flexible, less efficient

• Can adapt to new goals easily

When to Use Each

• Reflex: Simple, fully observable

• Model-Based: Partial observability

• Goal-Based: Multiple destinations/tasks

Worked Examples

Example 1: Old Car Brake vs. Turn Signal

Scenario: A model-based taxi agent observes the rear of a car from an older model. In a single frame, the illuminated lights could be either brake lights or turn signals.

Simple Reflex Fails: The current percept alone is ambiguous — both actions (brake or ignore) could be wrong.

Model-Based Solution: The agent stores the previous frame in internal state. By comparing consecutive frames, it detects whether the lights were on before (braking) or blinking (turn signal).

Outcome: The agent correctly identifies braking despite ambiguous single-frame input.

Example 2: Taxi Lane-Change Decision

Scenario: A taxi wants to change lanes. The driver checks the side mirror.

Why Internal State Matters: If the driver does not look at the mirror, the current frame may show no vehicle in the adjacent lane. However, a truck might be approaching fast from behind but not yet visible in the current frame.

Model-Based Approach: The agent maintains an internal model that tracks vehicles it has seen before, predicts their movement (how the world evolves), and keeps this information even when vehicles are temporarily out of sensor range.

Outcome: The agent waits for the truck to pass before changing lanes.

Example 3: Goal-Based Taxi at Intersection

Scenario: A taxi arrives at a four-way intersection. It can go left, right, or straight.

Current State: All three routes are clear and legal.

Goal: The passenger's destination is to the north.

Reasoning: The agent consults its model: "If I turn left, I go west — away from destination. If I go straight, I continue north — toward destination. If I turn right, I go east — away."

Outcome: The agent selects "go straight" because that action leads to the destination.

Key Point: The same agent with a different passenger (different goal) would choose a different action without reprogramming.

Example 4: Rain Adaptation

Scenario: Rain starts while a goal-based taxi is driving.

Reflex Agent Problem: All condition-action rules for braking were designed for dry roads. "If obstacle ahead → brake at pressure P" now causes skidding. Every rule involving braking must be rewritten.

Goal-Based Solution: The agent updates its model: "Brake performance = 60% on wet roads." It now reasons: "My goal is to reach destination safely. On wet roads, braking at pressure P is insufficient. I should brake earlier and with less pressure." All behaviors automatically adjust.

Outcome: Safe driving in rain without rule rewriting.

Example 5: Search and Planning for Long Trips

Scenario: A goal-based taxi agent in San Francisco must take a passenger to Los Angeles. No single action reaches LA.

Search: The agent explores possible sequences: "Take Highway 101" → "Continue to Santa Barbara" → "Continue to LA" is one path. "Take I-5" → "Continue to Bakersfield" → "Continue to LA" is another.

Planning: The agent evaluates which sequence is faster, evaluating each sub-goal along the way.

Outcome: The agent selects the optimal route based on current traffic conditions, constructing a multi-step plan from initial state to goal state.
