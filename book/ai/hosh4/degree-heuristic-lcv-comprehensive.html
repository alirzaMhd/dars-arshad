Degree Heuristic & Least Constraining Value

Variable Selection Tie-Breaker & Value Ordering Heuristic

Degree Heuristic

The Degree Heuristic selects the variable involved in the largest number of constraints with other unassigned variables. It is primarily used as a tie-breaker when MRV gives equal values.

Selection Criterion:
var = argmaxXi Degree(Xi)
Choose the variable with the highest degree (most constraints) among unassigned variables

Australia Map Example

In the Australia map coloring problem, the degrees of variables are:

VariableDegreeConstrains
SA5WA, NT, Q, NSW, V
NT3WA, SA, Q
Q3NT, SA, NSW
NSW3Q, SA, V
WA2NT, SA
V2SA, NSW
T0None (isolated)

The degree heuristic selects SA first (highest degree = 5). In fact, choosing SA first allows the Australia problem to be solved without any backtracking!

Least Constraining Value (LCV)

Once a variable is chosen, LCV determines the order in which values are tried. It prefers the value that rules out the fewest choices for neighboring unassigned variables.

Selection Criterion:
value = argminv (choices removed from neighbors)
Pick the value that leaves the most flexibility for other variables

Why LCV Makes Sense

Unlike MRV (which is "fail-first" for variables), LCV is "succeed-first" for values:

  • • We only need one solution (typically)
  • • Choosing a value that preserves options for neighbors increases the chance of success
  • • LCV tries the most promising value first
Important: LCV only matters when finding a single solution. If we need all solutions (or detect unsatisfiability), the value order is irrelevant since all values must be tried anyway.

Worked Examples

Example 1: Australia — Degree Heuristic Tie-Breaker

Situation: All domains initially have size 3. MRV gives no guidance.

Degree heuristic: SA (degree 5) > NT/Q/NSW (degree 3) > WA/V (degree 2) > T (degree 0)

Select SA first. Assign SA=red. Now NT, Q, NSW, V, WA all lose red from domains.

After SA assignment: MRV now guides effectively (NT, Q, NSW, V have 2 values remaining).

With SA first, the problem solves without backtracking!

Example 2: Australia — LCV for Q

Situation: WA=red, NT=green assigned. Selecting value for Q.

Q can be: red, blue (green conflicts with NT)

LCV analysis:

• Q=red: SA's domain becomes {blue} (loses red and green from neighbors) → removes 1 option for SA

• Q=blue: SA's domain becomes {red, green} (loses blue only) → removes no additional options

LCV prefers Q=blue because it leaves more options for SA.

LCV correctly avoids prematurely constraining SA

Example 3: 8-Queens — LCV for Row Selection

Variable: Q3 (queen in column 3), with Q1=1, Q2=3 already placed.

Possible rows: {5, 6, 7, 8} (rows 1-4 conflict with Q1 or Q2)

LCV analysis: Which row removes the fewest options for Q4-Q8?

• Row 5: conflicts with Q4 rows {2, 4, 5, 6} → removes 4 options

• Row 6: conflicts with Q4 rows {3, 5, 6, 7} → removes 4 options

• Row 7: conflicts with Q4 rows {4, 6, 7, 8} → removes 4 options

• Row 8: conflicts with Q4 rows {5, 7, 8} → removes only 3 options

LCV selects row 8 first for Q3.

Example 4: Degree Heuristic for Global Impact

Graph: A small constraint graph with variables {A, B, C, D}.

A connected to B, C
B connected to A, C, D
C connected to A, B, D
D connected to B, C

Degrees: A=2, B=3, C=3, D=2

Degree heuristic picks: B or C (tied at degree 3).

Degree counts only unassigned neighboring variables, so it's dynamic.

Quick Reference

Degree Heuristic

Variable ordering

• Selects most constrained variable

• Tie-breaker for MRV

• Based on constraint graph degree

• SA (degree 5) best for Australia

LCV Heuristic

Value ordering

• Selects least constraining value

• Preserves neighbor flexibility

• "Succeed-first" approach

• Irrelevant when finding all solutions

Combined Strategy

1. MRV (fail-first for variables)

2. Degree (tie-break)

3. LCV (succeed-first for values)

This is the standard heuristic set for CSP!
