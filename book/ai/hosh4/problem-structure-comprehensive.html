Problem Structure in CSP

Independent Subproblems, Tree Structure & Complexity Analysis

Independent Subproblems

The constraint graph reveals the structure of the problem. Disconnected components represent independent subproblems that can be solved separately.

Example: Australia — Tasmania is Independent

Tasmania (T) has no connections to any other region in the constraint graph.

This means the problem decomposes into:

• Mainland CSP: {WA, NT, SA, Q, NSW, V} — 6 variables

• Tasmania CSP: {T} — 1 variable (trivially solvable)

Any solution for the mainland combined with any color for T gives a full solution!

Complexity with Independent Subproblems:
Without decomposition: O(dn)
With decomposition: O(dC · n/C)
Where C = size of largest component, n/C = number of components

Dramatic Speedup Example

Boolean CSP (d=2) with n=80, decomposed into 4 components of C=20:
Without: 280 ≈ 1024 (thousands of years)
With: 4 · 220 ≈ 4 million (< 1 second)

Decomposition can reduce exponential complexity to linear in the number of components!

Tree-Structured CSP

A CSP whose constraint graph is a tree (no cycles) can be solved in linear time — a remarkable result!

Tree CSP Complexity:
O(n · d²) = O(E · D²)
Where E = number of edges (n-1 for trees), D = max domain size. Linear in the number of variables n.

Tree CSP Algorithm

function SOLVE-TREE-CSP(csp) // Input: CSP with tree-structured constraint graph // Step 1: Pick root, order vars (topological order) root ← any variable order ← TOPOLOGICAL-SORT(csp, root) // parents before children // Step 2: Backward propagation (leaf to root) for j = n down to 2 do Xj ← order[j] Xi ← parent of Xj in tree REMOVE-INCONSISTENT-VALUES(Xi, Xj) // make arc (Xi, Xj) consistent // Step 3: Forward assignment (root to leaf) for j = 1 to n do Xj ← order[j] assign any value for Xj consistent with parent's assignment return assignment

Why It Works

  • 1. Arc consistency propagation ensures: after step 2, every parent has a compatible child value
  • 2. Forward assignment in step 3 then never gets stuck
  • 3. No cycles = no need for backtracking!
Key Insight: Many real-world CSPs have nearly tree-like structure. Even when cycles exist, techniques like cutset conditioning can remove variables to create a tree, trading off between tree size and number of cuts.

Worked Examples

Example 1: Independent Subproblem — Australia

Full problem: 7 variables, 37 = 2187 possible assignments

Decomposition:

• Component 1 (Mainland): 6 variables, 36 = 729 assignments

• Component 2 (Tasmania): 1 variable, 31 = 3 assignments

Combined: 729 × 3 = 2187 (same count, but we can solve components independently)

The benefit isn't in fewer total assignments but in smaller search space at any one time — we solve two small problems instead of one large one.

Example 2: Tree-Structured CSP — A Chain

Variables: A → B → C → D (chain: A connected to B, B to C, C to D)

Constraints: A < B, B < C, C < D

Domains: {1, 2, 3, 4}

Tree CSP algorithm:

1. Pick root A. Order: A, B, C, D (topological).

2. Backward: Make arc (C,D) consistent, then (B,C), then (A,B).

3. Forward: Assign A=1, then B=2, then C=3, then D=4.

Solution found in O(n·d²) time without any backtracking!

Example 3: Cutset Conditioning — Handling Cycles

Problem: Constraint graph has a cycle (e.g., Australia minus T still has cycles).

Approach — Cutset Conditioning:

1. Choose a cutset of variables that, when removed, breaks all cycles.

2. For each assignment to the cutset variables, solve the remaining tree CSP.

3. If any assignment works, return the full solution.

Complexity: O(dcutset_size · n · d²)

Trade-off: larger cutset = more assignments to try, but smaller remaining tree.

Example 4: Real-World Decomposition

Factory scheduling: Different production lines are independent → separate CSPs.

University timetabling: Different departments have limited interaction → nearly independent.

Circuit design: Different modules connected only at boundaries → tree-like structure.

Recognizing problem structure is the single most effective optimization for real-world CSPs. Exponential in component size, but linear in number of components!

Quick Reference

Independent Subproblems

• Graph components = independent CSPs

• Solutions can be combined freely

• Complexity: O(dC · n/C)

• Example: Tasmania (isolated)

Tree-Structured CSP

• Constraint graph = tree (no cycles)

• Solvable in O(n · d²) time

• Algorithm: propagate then assign

• No backtracking needed!

Cutset Conditioning

• Break cycles by removing variables

• Try all values for cutset variables

• Complexity: O(dk · n · d²)

• k = cutset size, trade-off involved

Key Principle

Structure is the key to efficiency:

• Unstructured: O(dn)

• Tree-structured: O(n · d²)

• Decomposed: O(dC) per component
