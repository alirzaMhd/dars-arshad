Constraint Types in CSP

Unary, Binary, Higher-Order, Absolute & Preference Constraints

Unary Constraints

A unary constraint restricts the value of a single variable. It is the simplest type of constraint.

Example (Australia):
SA ≠ green
"South Australians don't like green" — restricts SA to {red, blue}

Handling Unary Constraints

Unary constraints can be eliminated through preprocessing:

  • 1. Identify the constrained variable
  • 2. Remove all values that violate the constraint from its domain
  • 3. The problem is now unary-constraint-free
Example: Preprocessing a Unary Constraint

Before: DSA = {red, green, blue}, Constraint: SA ≠ green

After preprocessing: DSA = {red, blue}

The constraint is now implicit in the domain

Key Point: Unary constraints never cause complex reasoning — they are always handled by domain reduction before search begins.

Binary Constraints

A binary constraint relates exactly two variables. It specifies which pairs of values are allowed.

Example (Australia):
SA ≠ NSW
A binary inequality constraint between South Australia and New South Wales

Binary CSP

A CSP that contains only binary constraints is called a Binary CSP. The constraint graph (where edges connect constrained variables) naturally represents binary CSPs.

Allowed pairs for (SA, NSW):
{(R,G), (R,B), (G,R), (G,B), (B,R), (B,G)}
6 out of 9 possible pairs; same-color pairs excluded

Binary Constraint Examples

• X ≠ Y (inequality)

• X = Y (equality)

• X + Y ≤ 10 (arithmetic)

• X < Y (ordering)

Properties

• Represented as edges in constraint graph

• Can be tabular or functional

• Most CSP algorithms focus on binary

Important: Any higher-order CSP with finite domains can be converted to a binary CSP by introducing auxiliary variables. That's why most algorithms focus on binary constraints.

Higher-Order Constraints

Higher-order constraints involve three or more variables. They are also called n-ary constraints.

Cryptarithmetic Example

Each letter represents a distinct digit, and the column additions must hold:

Column Constraints (FORT + TOWER = FORTY):
O + O = R + 10·X1
X1 + W + W = U + 10·X2
X2 + T + T = O + 10·X3
X3 = F
X1, X2, X3 are carry digits (0 or 1)

Alldiff Constraint

The Alldiff constraint requires all variables in a set to take distinct values. It involves n variables (n ≥ 3 typically).

Alldiff:
Alldiff(F, T, U, W, R, O)
All six letters must have different digit values

Reduction to Binary Constraints

Higher-order constraints with finite domains can be reduced to binary constraints by introducing auxiliary variables (like the carry digits X1, X2, X3). The Alldiff constraint can be converted to a set of binary inequalities (F≠T, F≠U, F≠W, ..., etc.).

Example: Alldiff Inference

Given 3 variables with domains {1, 2} and an Alldiff constraint:

3 variables, only 2 distinct values → m > n → constraint cannot be satisfied!

✗ This Alldiff constraint is impossible to satisfy

Absolute vs Preference Constraints

Absolute Constraints

Also called hard constraints. These must be satisfied by any valid solution. Violating an absolute constraint means the assignment is not a solution.

Preference Constraints (Soft Constraints)

In real-world problems, many constraints are preferences rather than absolutes. A solution that violates a preference is still valid, but suboptimal.

Example: University Timetabling

Absolute: No two classes can occupy the same room at the same time.

Preference: Professor X prefers to teach in the morning; Professor Y prefers the afternoon.

If Prof X teaches at 2 PM, it's still a valid schedule — just less preferred.

Handling Preferences

Preferences are modeled by assigning costs to assignments:

Cost-based Modeling:
Cost(Prof X, morning) = 1
Cost(Prof X, afternoon) = 2
Lower cost = higher preference. We then search for minimum-cost solutions.
