Local Search — Min-Conflicts Heuristic

Complete-State Formulation for CSP

Complete-State Formulation

Unlike incremental search (start with ∅, add one var at a time), local search for CSP uses the complete-state formulation:

  • • Initial state: Assign all variables (may violate constraints)
  • • Successor function: Change one variable's value
  • • Goal test: No constraints violated

Advantages of Local Search for CSP

Speed

Can solve million-queen problems in constant time (≈50 steps)!

Online Adaptation

Can adapt to changing constraints without restarting

Memory

Only stores current state, not the search tree

Optimization

Naturally handles preference constraints via cost minimization

Min-Conflicts Algorithm

The Min-Conflicts heuristic selects a value for a variable that minimizes the number of constraint violations.

Heuristic:
value = argminv ∈ Domain Conflicts(var, v, current, csp)
Pick the value that causes the fewest conflicts with other variables
function MIN-CONFLICTS(csp, max_steps) returns a solution or failure inputs: csp, a constraint satisfaction problem max_steps, number of steps allowed before giving up current ← an initial complete assignment for csp for i = 1 to max_steps do if current is a solution for csp then return current var ← a randomly chosen conflicted variable from VARIABLES[csp] value ← the value v for var that minimizes CONFLICTS(var, v, current, csp) set var = value in current return failure

Initial Assignment Strategies

  • • Random: Assign random values to all variables
  • • Greedy: Assign values that minimize conflicts one by one

Worked Examples

Example 1: 8-Queens with Min-Conflicts

Initial state: Random placement of 8 queens in 8 columns (one per column).

Step 1: Count conflicts for each queen. Pick a random conflicted queen.

Step 2: For the chosen queen, try each row (1-8) in its column and count how many other queens it attacks.

Step 3: Move the queen to the row with the fewest conflicts.

Step 4: Repeat until no conflicts remain.

Remarkably, for N-Queens with N up to 1,000,000, Min-Conflicts finds a solution in approximately 50 steps (independent of N)!

The million-queen problem is solved in roughly 50 iterations!

Example 2: Min-Conflicts Trace on 4-Queens

Initial: Q1=1, Q2=1, Q3=1, Q4=1 (all in row 1)

Conflicts: Q1 attacks 3 others, Q2 attacks 3, etc.

Pick Q1 (random conflicted var):

• Row 1: 3 conflicts (current) • Row 2: 1 conflict • Row 3: 1 conflict • Row 4: 2 conflicts

Move Q1 to row 2 (fewest conflicts = 1).

Continue until solution found or max_steps reached.

Example 3: Hubble Telescope Scheduling

Problem: Schedule observations on the Hubble Space Telescope.

Constraints: Time windows (celestial availability), no overlapping observations, instrument setup times.

Preference: Maximize scientific value.

Traditional backtracking: Took 3 weeks to schedule 1 week of observations.

Min-Conflicts local search: Reduced to 10 minutes!

A dramatic improvement — from weeks to minutes!

Example 4: Online Adaptation — Airline Scheduling

Scenario: Weekly airline schedule with thousands of flights and crew assignments.

Problem: Bad weather at one airport makes the schedule impossible.

Local search approach:

  • • Start from the existing schedule (which was a solution before weather changed)
  • • Apply min-conflicts to fix violations incrementally
  • • Find solution with minimal changes to the original schedule

Backtracking would start from scratch and potentially change everything.

Local search naturally supports online adaptation with minimal disruption!

Quick Reference

Min-Conflicts

• Start with complete assignment

• Pick random conflicted variable

• Choose value with fewest conflicts

• Repeat until solved

Performance

• 8-Queens: ~4 steps avg

• Million-Queens: ~50 steps avg

• Hubble: 3 weeks → 10 minutes

• Nearly constant in problem size!

When to Use

• Large problems where BT fails

• Online/adaptive problems

• Optimization variants

• Dense solution spaces

Limitations

• Not complete (may not find solution)

• Needs restart on failure

• Not good for proving unsatisfiability

• Depends on quality of initial state
