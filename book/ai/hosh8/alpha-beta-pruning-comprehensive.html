Alpha-Beta Pruning

Optimizing Minimax Search — Complete Guide for 20/20 Exam

Alpha-Beta Pruning Concept

Alpha-beta pruning is an optimization technique that eliminates branches of the game tree that cannot affect the final decision, without changing the result.

Pruning Principle:
If we know a move is worse than a previously examined move, we can skip it
The pruned branches cannot influence the minimax decision.
Example 1: Why Prune?

Consider MAX evaluating moves:

  • Move A leads to value 5
  • Move B is being evaluated
  • First child of B gives value 3
  • Since MIN will choose 3 or lower, B cannot beat A
  • No need to check remaining children of B
Example 2: Key Insight

Pruning is safe because:

  • We only prune when we're certain the branch is irrelevant
  • The minimax value remains exactly the same
  • We save computational time
  • No information is lost about the optimal move

Without Pruning

• Explore entire tree

• O(b^m) complexity

• Redundant work

• Wasted computation

With Pruning

• Skip irrelevant branches

• O(b^(m/2)) typical

• No redundant work

• Significant savings

Alpha and Beta Parameters

Alpha and beta are bounds that track the best options found so far for MAX and MIN respectively.

Alpha (α):
α = best (highest) value found so far for MAX along the path
MAX's best alternative at any point along the path to the current state.
Beta (β):
β = best (lowest) value found so far for MIN along the path
MIN's best alternative at any point along the path to the current state.
Example 3: Alpha-Beta Bounds
Initial: α = -∞, β = +∞ At MAX node: - Update α = max(α, value found) - If value ≥ β, prune remaining children At MIN node: - Update β = min(β, value found) - If value ≤ α, prune remaining children
Example 4: Pruning Conditions

Alpha Pruning (at MIN node):

  • MIN finds a value ≤ α
  • MAX already has a better option (α)
  • MIN will never choose this branch
  • Prune remaining children

Beta Pruning (at MAX node):

  • MAX finds a value ≥ β
  • MIN already has a better option (β)
  • MIN will never allow this branch
  • Prune remaining children
Important: Alpha starts at -∞ (worst for MAX) and increases. Beta starts at +∞ (worst for MIN) and decreases. When α ≥ β, pruning occurs.

Alpha-Beta Algorithm Pseudocode

function ALPHA-BETA-SEARCH(state) returns an action inputs: state, current state in game v ← MAX-VALUE(state, -∞, +∞) return the action in SUCCESSORS(state) with value v function MAX-VALUE(state, α, β) returns a utility value inputs: state, current state in game α, the value of the best alternative for MAX along the path to state β, the value of the best alternative for MIN along the path to state if TERMINAL-TEST(state) then return UTILITY(state) v ← -∞ for each (a, s) in SUCCESSORS(state) do v ← MAX(v, MIN-VALUE(s, α, β)) if v ≥ β then return v α ← MAX(α, v) return v function MIN-VALUE(state, α, β) returns a utility value inputs: state, current state in game α, the value of the best alternative for MAX along the path to state β, the value of the best alternative for MIN along the path to state if TERMINAL-TEST(state) then return UTILITY(state) v ← +∞ for each (a, s) in SUCCESSORS(state) do v ← MIN(v, MAX-VALUE(s, α, β)) if v ≤ α then return v β ← MIN(β, v) return v
Example 5: Algorithm Trace

Key differences from basic minimax:

  • Additional α, β parameters passed recursively
  • Early termination when pruning condition met
  • Updating α at MAX nodes, β at MIN nodes
  • Same result as minimax, but faster

Worked Example: Alpha-Beta Pruning

Example 6: Step-by-Step Pruning
Game Tree: MAX (root) / | \ A B C /|\ /|\ /|\ 3 12 8 2 4 6 14 5 2 Step 1: MAX evaluates A - MIN节点 A: min(3, 12, 8) = 3 - α becomes 3 Step 2: MAX evaluates B - MIN节点 B: first child = 2 - 2 < α (3), so B cannot be better than A - PRUNE remaining children of B (4, 6) - α remains 3 Step 3: MAX evaluates C - MIN节点 C: first child = 14 - 14 > α (3), so C might be better - Continue evaluating C - min(14, 5, 2) = 2 - Final: max(3, 2) = 3 Result: Same as minimax, but saved 2 evaluations

Without Pruning

• Evaluate all 9 leaf nodes

• Complete exploration

With Pruning

• Evaluate only 7 leaf nodes

Complexity Improvement

Best Case Complexity:
O(b^(m/2))
With perfect move ordering, alpha-beta examines b^(m/2) nodes instead of b^m.
Worst Case Complexity:
O(b^m)
With poor move ordering, no pruning occurs and complexity remains the same.
Example 8: Practical Improvement

For chess (b=35, m=80):

Without pruning: 35^80 ≈ 10^123 nodes With perfect pruning: 35^40 ≈ 10^62 nodes Improvement factor: 10^61 times faster! Still too large for brute force, but: - Allows deeper search - Enables heuristic pruning - Makes practical game-playing possible
Example 9: Move Ordering Effect

Pruning efficiency depends heavily on move ordering:

  • Perfect ordering: Best move examined first → maximum pruning
  • Random ordering: Little pruning → complexity near b^m
  • Heuristic ordering: Good pruning → significant improvement

In practice, we use heuristics to guess good move order.
