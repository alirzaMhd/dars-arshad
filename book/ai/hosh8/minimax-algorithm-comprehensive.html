Minimax Algorithm

Optimal Decision Making in Two-Player Games — Complete Guide for 20/20 Exam

Minimax Core Concept

Minimax is a decision rule for minimizing the maximum possible loss (or maximizing the minimum possible gain). It assumes both players play optimally.

Minimax Principle:
MAX chooses move with highest value, MIN chooses move with lowest value
MAX wants to maximize utility, MIN wants to minimize MAX's utility.
Example 1: The Game of Life

Consider a simple game where:

  • MAX wants to achieve the highest score possible
  • MIN wants to keep MAX's score as low as possible
  • Both players alternate moves
  • Game ends at terminal states with utility values

Minimax finds the best move for MAX assuming MIN plays perfectly against them.

Example 2: Why "Min" and "Max"?

The name comes from the two players' objectives:

  • MAX: The player trying to maximize the utility score
  • MIN: The opponent trying to minimize MAX's utility (or maximize their own)
  • In zero-sum games, MIN's gain = MAX's loss

MAX Player

• First to move

• Chooses highest value child

• Wants to win

• Maximizes utility

MIN Player

• Second to move

• Chooses lowest value child

• Wants MAX to lose

• Minimizes utility

Minimax Values

The minimax value of a node is the utility value of that state assuming both players play optimally from that point forward.

Minimax Value Definition:
MINIMAX-VALUE(n) = UTILITY(n) if n is terminal
For non-terminal nodes, values propagate up from leaves.
Recursive Definition:
MINIMAX-VALUE(n) = max{MINIMAX-VALUE(s) | s ∈ successors(n)} if n is MAX node
MINIMAX-VALUE(n) = min{MINIMAX-VALUE(s) | s ∈ successors(n)} if n is MIN node
MAX nodes take maximum of children, MIN nodes take minimum.
Example 3: Computing Minimax Values
Game Tree: MAX / | \ A B C /|\ /|\ /|\ 3 12 8 2 4 6 Step 1: Terminal values are given Step 2: MIN nodes (A, B, C) take minimum: A: min(3, 12, 8) = 3 B: min(2, 4, 6) = 2 Step 3: MAX node takes maximum: Root: max(3, 2) = 3 Minimax value of root = 3
Example 4: Tic-Tac-Toe Minimax

For a specific Tic-Tac-Toe position:

  • Terminal states: Win (+1), Loss (-1), Draw (0)
  • MIN values: Opponent chooses worst for MAX
  • MAX values: Player chooses best for themselves

With perfect play from both sides, Tic-Tac-Toe always ends in a draw (value = 0).

Minimax Algorithm Pseudocode

function MINIMAX-DECISION(state) returns an action inputs: state, current state in game v ← MAX-VALUE(state) return the action in SUCCESSORS(state) with value v function MAX-VALUE(state) returns a utility value if TERMINAL-TEST(state) then return UTILITY(state) v ← -∞ for each (a, s) in SUCCESSORS(state) do v ← MAX(v, MIN-VALUE(s)) return v function MIN-VALUE(state) returns a utility value if TERMINAL-TEST(state) then return UTILITY(state) v ← +∞ for each (a, s) in SUCCESSORS(state) do v ← MIN(v, MAX-VALUE(s)) return v
Example 5: Algorithm Trace

Tracing through a simple game tree:

  • Start at root (MAX node)
  • For each child, call MIN-VALUE
  • MIN-VALUE calls MAX-VALUE for its children
  • Continue until terminal states reached
  • Values propagate back up
  • Root chooses action with maximum value
Key Insight: This is a depth-first search that explores the entire game tree. It's optimal but computationally expensive.

  • MAX: Has Queen (trying to checkmate)

Example 8: Nim Game

Nim is a mathematical game of strategy:

  • Setup: Several piles of objects
  • Moves: Remove any number from one pile
  • Goal: Take the last object (normal play)
  • Minimax: Can compute perfect play
  • Result: First player wins with optimal play if XOR of pile sizes ≠ 0

Optimal Play

• Both players play perfectly

• No mistakes allowed

• Deterministic outcome

• Game value is fixed

Real Games

• Players make mistakes

• Exploiting errors wins

• Psychological factors

• Time constraints matter

Complexity Analysis

Time Complexity:
O(b^m)
Where b = branching factor, m = maximum depth of game tree.
Space Complexity:
O(bm) if generating children incrementally
O(b^m) if generating all children at once
Depth-first search allows linear space if we generate children one at a time.

Example 10: Why Minimax is Impractical

For chess:

  • 35^80 ≈ 10^123 nodes to explore
  • Even at 10^9 nodes/second
  • Would take 10^104 seconds
  • Universe age is only ~10^17 seconds

This is why we need heuristics and pruning.

Theoretical

• Optimal solution

• Complete search

• Exponential time

• Impractical for complex games

Practical

• Use heuristics

• Limit search depth

• Alpha-beta pruning

• Evaluation functions

Critical Point: Minimax is the foundation, but practical game-playing programs use modifications like alpha-beta pruning and heuristic evaluation to handle complex games.
