Extending Minimax to Multiple Players

While most famous games involve two players, many real-world scenarios involve three or more agents. We can extend the minimax algorithm to handle multi-player games.

Multi-player Minimax:
Players: A, B, C, ... (take turns in fixed order)
Each player chooses moves to maximize their own utility.
Example 1: Three-Player Game Setup

Consider a game with three players A, B, and C:

  • Turn Order: A → B → C → A → B → C → ...
  • Each Player: Tries to maximize their own score
  • Terminal States: Have utility for all three players
Example 2: Why Not Just Two-Player Minimax?

Two-player minimax assumes:

  • Zero-sum: One player's gain is other's loss
  • Only two utility values (opposite signs)

In multi-player games:

  • Non-zero-sum: All players can win or lose together
  • Multiple independent utility values
  • Complex strategic interactions
Key Difference: In two-player zero-sum games, we only need one utility value. In multi-player games, we need a vector of utilities—one for each player.

Utility Vectors

For multi-player games, each terminal state has a utility vector rather than a single value.

Utility Vector:
UTILITY(state) =
Each component represents the utility for that specific player.
Example 3: Three-Player Utility Vector
Terminal State Utilities: Player A: +10 Player B: +5 Player C: -3 Utility Vector: <10, 5, -3> Interpretation: - Player A gains 10 points - Player B gains 5 points - Player C loses 3 points
Example 4: Decision at Non-Terminal Node

When player C must choose at a non-terminal node:

Node X (Player C to move): ├── Move 1 → Terminal: <2, 7, 6> └── Move 2 → Terminal: <4, 5, 2> Player C chooses Move 1 because 6 > 2 (C maximizes their own utility component)

The chosen utility vector <2, 7, 6> is passed to the parent node.

Two-Player

• Single utility value

• Zero-sum property

• Simpler minimax

• Utility(A) = -Utility(B)

Multi-player

• Utility vector

• Non-zero-sum possible

• Complex interactions

• Each player independent

Alliances in Multi-player Games

Multi-player games often involve temporary alliances between players to defeat stronger opponents.

Alliance Formation:
If Players(A,B) < Strength(C), then A and B may ally against C
Alliances form when weaker players unite against stronger ones.
Example 5: Strategic Alliance

Three players with different strengths:

  • Player A: Medium strength
  • Player B: Medium strength
  • Player C: Strongest player

Alliance Strategy:

  • A and B ally against C initially
  • They attack C instead of each other
  • Once C is weakened, alliance breaks
  • A and B then compete against each other
Example 6: Diplomacy Board Game

Diplomacy is a classic multi-player game:

  • 7 Players: Control European great powers
  • Alliances: Temporary and shifting
  • Negotiation: Players can make deals
  • Betrayal: Alliances can be broken
  • Complexity: Requires psychological modeling
Key Challenge: Alliances make multi-player games computationally intractable because players must model not just individual strategies but also relationship dynamics.

Comprehensive Examples

Example 7: Three-Player Tic-Tac-Toe

Modified Tic-Tac-Toe with three players (X, O, Δ):

  • Board: 4×4 grid (larger for three players)
  • Goal: Get 3 in a row
  • Turn Order: X → O → Δ → X → ...
  • Utilities: Winner gets +1, others get 0

Minimax must consider all three players' perspectives.

Example 8: Poker with Multiple Players

Poker demonstrates multi-player complexity:

  • Players: 2-10 players
  • Information: Imperfect (hidden cards)
  • Betting: Sequential decisions
  • Utility: Chips won/lost
  • Alliances: Temporary, against leader
Example 9: Multi-player Video Games

Real-time strategy games like StarCraft:

  • Players: 2-8 players
  • Actions: Continuous, real-time
  • Alliances: Form and break dynamically
  • Victory: Last player/team standing
  • AI Challenge: Must handle multiple opponents
