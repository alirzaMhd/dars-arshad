KNOWLEDGE REPRESENTATION LANGUAGES

First-Order Logic — Why We Need Better Languages for AI

Why Knowledge Representation?

An AI agent must represent what it knows about the world and reason over that knowledge. The language used to represent knowledge determines how effectively an agent can:

  • Express facts about the world
  • Infer new facts from existing ones
  • Handle incomplete or uncertain information
  • Communicate knowledge between agents
Core Problem: Traditional programming languages were designed for computation, not for representing knowledge about the world.

Limitations of Programming Languages

Languages like Java and Lisp are procedural — they describe HOW to do things step by step. This creates fundamental problems for AI:

✗ Problems

  • No built-in inference mechanism
  • Cannot handle incomplete information
  • Knowledge is embedded in code logic
  • Difficult to reason about what is true
  • Must enumerate all cases explicitly

✓ What They Do Well

  • Efficient execution
  • Type safety
  • Well-tested libraries
  • Good for implementing algorithms
Procedural vs Declarative

Procedural (Java):

for (int i = 0; i < students.length; i++) { if (students[i].grade >= 90) { students[i].status = "honor"; } }

Declarative (Logic):

∀x: Student(x) ∧ Grade(x, g) ∧ g ≥ 90 → Honor(x)

The declarative version states WHAT is true, not HOW to compute it.

Declarative vs Procedural Knowledge

Declarative Knowledge:
Describes WHAT is true about the world
Facts and relationships that hold regardless of how they are used. Example: "All humans are mortal."
Procedural Knowledge:
Describes HOW to accomplish tasks
Step-by-step instructions. Example: "To find a mortal, check if someone is human."
Common Mistake: Confusing the representation of knowledge with the procedure to use it. Declarative knowledge can be used by multiple inference procedures.

Compositionality

A language is compositional if the meaning of a complex expression is determined by the meanings of its parts and the rules used to combine them.

Compositionality Principle:
Meaning(A ∧ B) = f(Meaning(A), Meaning(B), ∧)
The meaning of a conjunction depends on the meanings of its conjuncts and the conjunction operator.
Compositionality in Action

"The cat is on the mat" has meaning derived from:

  • "the cat" → a specific entity
  • "the mat" → a specific entity
  • "on" → a spatial relation
  • Syntax rules combine these into a proposition
Natural language is only partially compositional. Idioms like "kick the bucket" (meaning "die") violate compositionality.

Why Propositional Logic Falls Short

Propositional logic uses simple propositions (P, Q, R) as atomic units. This works for simple cases but fails in complex environments:

The Proposition Explosion Problem

To represent facts about 100 objects and their relationships, you need propositions like:

On(A,B), On(B,C), Color(A,Red), Color(B,Blue)... (thousands of propositions)

There is no way to say "For all x" or "There exists an x" — you must enumerate every single fact.

Propositional Logic Limitation:
Cannot express: ∀x ∀y: On(x,y) → ¬On(y,x)
"If x is on y, then y is not on x" — this general rule requires first-order quantifiers.

Why Natural Language Falls Short for AI

Natural language is incredibly expressive but problematic for formal reasoning:

Ambiguity

"I saw the man with the telescope" — Who has the telescope?

Vagueness

"She is tall" — How tall is tall? No precise boundary.

Context Dependence

"It's cold in here" — Different meanings in different situations.

Non-Compositionality

"Kick the bucket" — Meaning cannot be derived from parts.

Ontology vs Epistemology

Ontology (What Exists):
The set of objects, relations, and properties that exist in the world
Defines the vocabulary: What things are there? What properties do they have? What relations hold between them?
Epistemology (What is Believed):
The agent's knowledge or beliefs about the facts in the ontology
Defines what the agent knows: Is it certain? Is it incomplete? Is it uncertain?
Ontology vs Epistemology Example

Ontology: The world contains objects like {Alice, Bob, Paris, France}, relations like {LivesIn, ParentOf}, and properties like {IsHappy}.

Epistemology: The agent believes "LivesIn(Alice, Paris)" is true, but is uncertain about "LivesIn(Bob, Paris)" — it might be true or false.

Comparison of 5 Logic Types

Logic Type Ontology (What it can represent) Epistemology (What it can express about beliefs)
Propositional Logic Simple facts: P, Q, R Certainty only — a proposition is either true or false
First-Order Logic Objects, relations, functions, quantifiers (∀, ∃) Certainty with incomplete knowledge (unknown facts via partial models)
Temporal Logic Objects and relations that change over time Certainty about sequences of states
Probability Logic Any domain with likelihoods attached Degrees of belief: P(H) ∈ [0, 1]
Fuzzy Logic Vague properties with gradual membership Truth values in [0, 1] representing degree of truth
Common Mistake: Confusing "I don't know if X is true" (epistemological uncertainty) with "X is partially true" (ontological vagueness). These are fundamentally different!

Formal Definitions

Propositional Logic Syntax:
φ ::= P | ¬φ | φ ∧ φ | φ ∨ φ | φ → φ | φ ↔ φ
Where P is an atomic proposition, and connectives build complex formulas.
First-Order Logic Syntax:
φ ::= P(t₁,...,tₙ) | ¬φ | φ ∧ φ | φ ∨ φ | φ → φ | ∀x: φ | ∃x: φ
Where tᵢ are terms (variables, constants, function applications), and ∀/∃ are quantifiers over variables.
Probability Logic:
P(A|B) = P(A ∧ B) / P(B)
Bayes' theorem allows updating beliefs given new evidence.
Fuzzy Logic Membership:
μ_Tall(x) ∈ [0, 1]
Each object has a degree of membership in a vague set, rather than strict in/out.

Worked Examples: Representing Knowledge

Example 1: "All humans are mortal" in different languages

Propositional Logic:

P = "All humans are mortal" We can only assert P or ¬P — no internal structure.

First-Order Logic:

∀x: Human(x) → Mortal(x)

This captures the universal quantification over all objects that are human.

Java (Procedural):

for (Person p : people) { if (p.isHuman()) p.setMortal(true); }

Requires iterating over a list — not a general statement about all humans everywhere.

Example 2: "Some student passed the exam"

First-Order Logic:

∃x: Student(x) ∧ Passed(x, Exam)

Uses existential quantifier to say "there exists at least one x such that..."

Natural Language Ambiguity:

"Some students passed the exam"

Does "some" mean "at least one" or "more than one"? Natural language is vague.

Example 3: Handling Incomplete Information

Scenario:

We know it is raining or snowing, but not which one.

Propositional Logic:

Raining ∨ Snowing

The disjunction captures incomplete knowledge — we know one is true but not which.

First-Order Logic:

Weather(x, Rain) ∨ Weather(x, Snow)

Same idea, but now x can refer to a specific location and time.

Example 4: Relational Knowledge

Scenario:

"Alice is Bob's mother" and "Everyone's mother loves them."

First-Order Logic:

Mother(Alice, Bob) ∀x ∀y: Mother(x, y) → Loves(x, y)

Functions and relations let us express complex relational knowledge naturally.

Propositional Logic Attempt:

P = "Alice is Bob's mother" Q = "Alice loves Bob" We need separate propositions for every pair — doesn't scale!
Example 5: Temporal vs Static Knowledge

Static Fact (First-Order Logic):

Location(Paris, France)

Temporal Fact (Temporal Logic):

□(Location(Paris, France))

□ means "always" — Paris is in France at all times. Compare with:

◊(Raining)

◊ means "eventually" — at some point, it will rain.

Summary Cards

Declarative Languages

State WHAT is true, not HOW to compute it. First-order logic is declarative — knowledge is separate from reasoning procedures.

Compositionality

Meaning of complex expressions = function of meanings of parts + combination rules. FOL and programming languages are fully compositional.

Expressiveness

FOL handles objects, relations, and quantifiers — far more expressive than propositional logic but less ambiguous than natural language.

Ontology

Defines what EXISTS in the world: objects, properties, and relations. Shared across all agents reasoning about the same domain.

Epistemology

Defines what an agent BELIEVES about the world. Can be certain, incomplete (unknown), or uncertain (probabilistic).

Five Logics

Propositional → FOL → Temporal → Probability → Fuzzy. Each extends expressiveness or handles different types of uncertainty.

Key Formulas to Remember

Universal Quantifier:
∀x: P(x) → Q(x)
"For all x, if P(x) then Q(x)" — makes a universal claim.
Existential Quantifier:
∃x: P(x) ∧ Q(x)
"There exists an x such that P(x) and Q(x)" — asserts existence.
Negation of Quantifiers:
¬∀x: P(x) ≡ ∃x: ¬P(x)
"Not all x satisfy P" is equivalent to "There exists an x that does not satisfy P."
Converse Error Warning:
∀x: P(x) → Q(x) ⊭ ∀x: Q(x) → P(x)
The converse is NOT logically equivalent! "All humans are mortal" ≠ "All mortal things are human."

Common Mistakes

Mistake 1: Using ∀ when you mean ∃. "Everyone loves pizza" (∀) is different from "Someone loves pizza" (∃).
Mistake 2: Confusing P → Q with Q → P. "If it rains, the ground is wet" ≠ "If the ground is wet, it rained."
Mistake 3: Assuming propositional logic can represent object relationships. Use FOL for anything involving objects and their relations.
Mistake 4: Confusing epistemic uncertainty (I don't know) with ontological vagueness (the concept itself is vague). Probability handles the former; fuzzy logic handles the latter.

When to Use What

Programming Languages

Use when implementing algorithms, efficient computation, or when knowledge is complete and procedures are known.

Propositional Logic

Use for simple true/false reasoning, circuit design, or when the domain has no object structure.

First-Order Logic

Use for general knowledge with objects and relations, theorem proving, knowledge bases, and AI planning.

Natural Language

Use for human communication, but formalize into FOL for machine reasoning.
