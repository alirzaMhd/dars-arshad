TELL and ASK Operations

In First-Order Logic (FOL), knowledge bases (KB) interact with the outside world through two fundamental operations: TELL (adding sentences) and ASK (querying the KB).

TELL Operation

TELL adds a new sentence (axiom or fact) to the knowledge base. Think of it as "teaching" the system a fact.

Syntax:
TELL(KB, sentence)
Adds 'sentence' to the knowledge base. The sentence must be a valid FOL expression.
Example: TELL Operations
TELL(KB, King(John))
TELL(KB, King(Richard))
TELL(KB, ∀x King(x) → Person(x))
TELL(KB, ∀y Person(y) → Likes(y, IceCream))

Each TELL call adds a new fact or rule to the KB. The KB grows over time.

ASK Operation

ASK queries the KB to determine if a sentence can be inferred. If the sentence contains variables, ASK returns substitutions (binding lists) that make the query true.

Syntax:
ASK(KB, sentence)
Returns true if the sentence is entailed by KB, or returns a list of binding lists (substitutions) if the sentence has variables.

Boolean Query

ASK(KB, King(John))

Result: true

No variables, returns yes/no

Variable Query

ASK(KB, ∃x Person(x))

Result: {x/John}

Returns substitution making it true

Warning: ASK does not return all possible answers — it returns the first proof found. For complete results, you may need to explore all inference paths.

Binding Lists (Substitutions)

When ASK encounters a variable, it returns a binding list: a set of variable-value pairs {x₁/v₁, x₂/v₂, ...} that makes the query true under the given KB.

Example: Variable Queries with Bindings
ASK(KB, Likes(x, IceCream))
→ {x/John}, {x/Richard}, ...

ASK(KB, ∀x Likes(x, Pizza))
→ true (if all individuals like pizza)
Operation Purpose Input Output
TELL Add knowledge FOL sentence Updated KB
ASK (no variables) Check entailment FOL sentence true / false
ASK (with variables) Find instances FOL sentence with vars Binding lists

Kinship Domain — Family Relationships

The kinship domain is a classic application of FOL for modeling family relationships. We define axioms (basic rules) that capture how family members are related.

Basic Predicates

Parent(p, c)

p is a parent of c

Male(x)

x is male

Female(x)

x is female

Spouse(x, y)

x is married to y

Axioms (Basic Definitions)

Axiom 1 — Mother:
Mother(m, c) = Female(m) ∧ Parent(m, c)
m is a mother of c if m is female and m is a parent of c.
Axiom 2 — Husband:
Husband(h, w) = Male(h) ∧ Spouse(h, w)
h is a husband of w if h is male and h is married to w.
Axiom 3 — Mutual Exclusivity:
∀x Male(x) → ¬Female(x)
If x is male, then x is not female. Males and females are disjoint sets.
Axiom 4 — Inverse Relations:
∀p ∀c Parent(p, c) → Child(c, p)
If p is a parent of c, then c is a child of p. These are inverse relations.
Axiom 5 — Grandparent:
Grandparent(g, c) = ∃p Parent(g, p) ∧ Parent(p, c)
g is a grandparent of c if there exists some p such that g is a parent of p and p is a parent of c.
Axiom 6 — Sibling:
Sibling(x, y) = (x ≠ y) ∧ ∃p Parent(p, x) ∧ Parent(p, y)
x and y are siblings if they are different people and share at least one parent.

Derived Relationships (Theorems)

Once we have axioms, we can derive new relationships (theorems) using logical inference.

Example: Deriving Relationships
Given:
Parent(Jack, Tom)
Parent(Jack, Sue)
Male(Tom)
Female(Sue)

Derived:
Sibling(Tom, Sue)
— because ∃p Parent(p, Tom) ∧ Parent(p, Sue) with p=Jack
— and Tom ≠ Sue
Axiom Type Purpose Example
Definition Defines a concept in terms of simpler ones Mother(m,c) = Female(m) ∧ Parent(m,c)
Rule Expresses a logical constraint Male(x) → ¬Female(x)
Inverse Relates two symmetric concepts Parent(p,c) → Child(c,p)
Existential Requires at least one witness ∃p Parent(g,p) ∧ Parent(p,c)

Numbers, Sets, and Lists

FOL provides a formal foundation for mathematics. We can define natural numbers (Peano axioms), sets, and lists using first-order logic.

Peano Axioms — Natural Numbers

The Peano axioms define natural numbers using two primitives: the constant 0 and the successor function S.

Axiom 1 — Zero is a natural number:
NatNum(0)
0 is a natural number.
Axiom 2 — Successor:
∀n NatNum(n) → NatNum(S(n))
If n is a natural number, then S(n) (the successor of n) is also a natural number. S(n) represents n+1.
Axiom 3 — Distinctness:
∀n ¬(S(n) = 0)
No natural number has 0 as its successor. 0 is not the successor of any number.
Axiom 4 — Injectivity:
∀m ∀n S(m) = S(n) → m = n
The successor function is injective (one-to-one). Different numbers have different successors.

Addition (Recursive Definition)

Base case:
∀m +(m, 0) = m
Adding 0 to any number m gives m.
Recursive case:
∀m ∀n +(m, S(n)) = S(+(m, n))
Adding the successor of n to m is the successor of adding n to m.
Example: Computing 2 + 1
+(S(S(0)), S(0))
= S(+(S(S(0)), 0)) [recursive case]
= S(S(S(0))) [base case]
= 3

Set Theory Axioms

Membership:
x ∈ S
Element x belongs to set S.
Subset:
∀x (x ∈ A → x ∈ B) ↔ A ⊆ B
A is a subset of B if every element of A is also in B.
Set Equality:
A = B ↔ (A ⊆ B) ∧ (B ⊆ A)
Two sets are equal if each is a subset of the other.
Union:
x ∈ A ∪ B ↔ (x ∈ A) ∨ (x ∈ B)
x belongs to A union B if x is in A or in B (or both).

Lists (Lisp-style)

Empty list:
List([])
The empty list is a list.
Cons (prepend):
∀x ∀l List(l) → List(Cons(x, l))
Prepending element x to list l creates a new list.
Head and Tail:
Head(Cons(x, l)) = x
Tail(Cons(x, l)) = l
Head returns the first element; Tail returns the rest of the list.
Concept Constants Functions Predicates
Numbers 0 S(n) NatNum(n)
Addition — +(m, n) —
Sets ∅ {x | P(x)} x ∈ S, A ⊆ B
Lists [] Cons(x, l) List(l)

Worked Examples

Example 1: TELL and ASK with Knowledge Base
TELL(KB, King(John))
TELL(KB, King(Richard))
TELL(KB, ∀x King(x) → Person(x))
TELL(KB, ∀y Person(y) → Knows(y, AI))

ASK(KB, King(John))
→ true

ASK(KB, King(Alice))
→ false (Alice not in KB)

ASK(KB, Knows(x, AI))
→ {x/John}, {x/Richard}

The KB entails that John and Richard know AI because: King → Person → Knows(AI).

Example 2: Grandparent Inference in Kinship Domain
Given facts:
Parent(Grandpa, Dad)
Parent(Dad, Me)
Parent(Dad, Sister)

Axiom: Grandparent(g, c) = ∃p Parent(g, p) ∧ Parent(p, c)

Query: ASK(KB, Grandparent(Grandpa, Me))
→ true (with p = Dad)

Query: ASK(KB, Grandparent(Grandpa, x))
→ {x/Me}, {x/Sister}

The existential variable p is bound to Dad, linking Grandpa to Me and Sister through two levels of parenthood.

Example 3: Sibling Deduction
Given facts:
Parent(Bob, Alice)
Parent(Bob, Charlie)
Alice ≠ Charlie

Axiom: Sibling(x, y) = (x ≠ y) ∧ ∃p Parent(p, x) ∧ Parent(p, y)

Query: ASK(KB, Sibling(Alice, Charlie))
→ true
(x=Alice, y=Charlie, p=Bob)
Conditions: Alice ≠ Charlie ✓
Parent(Bob, Alice) ✓
Parent(Bob, Charlie) ✓
Example 4: Peano Arithmetic — Computing 3 + 2
+(S(S(S(0))), S(S(0)))
= S(+(S(S(S(0))), S(0))) [recursive]
= S(S(+(S(S(S(0))), 0))) [recursive]
= S(S(S(S(S(0))))) [base case: +(m,0) = m]
= 5

Each recursive call peels off one successor from the second argument, then applies the successor to the result.

Example 5: Set Operations in FOL
Given sets:
A = {1, 2, 3}
B = {2, 3, 4}

Query: ASK(KB, ∀x (x ∈ A ∪ B))
→ Returns binding list: {x/1}, {x/2}, {x/3}, {x/4}

Query: ASK(KB, 2 ∈ A ∩ B)
→ true (2 is in both A and B)

Query: ASK(KB, A ⊆ B)
→ false (1 ∈ A but 1 ∉ B)

Key Points — Axioms vs Theorems

Axioms

Axioms are the basic sentences that are explicitly added to the knowledge base using TELL. They are accepted as true without proof within the system.

Characteristics

• Explicitly asserted

• No proof needed

• Foundation of reasoning

• Added via TELL

Examples

• King(John)

• Parent(Bob, Alice)

• NatNum(0)

• +(m, 0) = m

Theorems

Theorems are sentences that can be derived from axioms using inference rules. They are not directly stated but follow logically from the axioms.

Characteristics

• Derived from axioms

• Requires proof (inference)

• Obtained via ASK

• Logically entailed by KB

Examples

• Person(John) — from King axiom

• Child(Alice, Bob) — from Parent

• NatNum(S(0)) — from Peano axioms

• Sibling(Alice, Charlie)

Comparison: Axioms vs Theorems

Property Axioms Theorems
Source Given (via TELL) Derived (via inference)
Proof Required No Yes
Role Starting point Consequence
Example (Kinship) Parent(Bob, Alice) Sibling(Alice, Charlie)
Example (Numbers) NatNum(0) NatNum(S(S(0)))

Summary of Applications

1. Knowledge Bases:
TELL adds facts, ASK retrieves knowledge
FOL provides a complete framework for storing and querying structured knowledge.
2. Kinship Domain:
Complex relationships built from simple predicates
Family relationships are defined compositionally using Parent, Male, Female, Spouse.
3. Mathematics:
Peano axioms → arithmetic; Set theory → collections
FOL can formalize all of elementary number theory and set theory.
4. Lists:
Cons, Head, Tail — recursive data structures in FOL
Lists are defined recursively, enabling formal reasoning about data structures.
Exam Tip: Always distinguish between what is given (axioms) and what is derived (theorems). When solving problems, clearly state which axioms you are using for each inference step.
Key insight: FOL allows us to express infinite knowledge with finite axioms. For example, the two Peano axioms for addition capture infinitely many addition facts through recursion.
