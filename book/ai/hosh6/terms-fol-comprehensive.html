TERMS IN FIRST-ORDER LOGIC

Artificial Intelligence — Complete Guide for Exam Preparation

What is a Term?

Definition
A term is a logical expression that refers to an object in the domain.
Terms are the building blocks that name things — they denote objects, not truth values.

In FOL, terms always refer to objects. Predicates refer to truth values. Never confuse the two.

Constants

Rule
Constant symbols are terms
A constant symbol names a specific object in the domain.

Examples

Richard

John

A

B

Key Point

Constants always refer to the same object throughout a knowledge base.

They are ground terms (no variables).

Function Symbols

Rule
Function symbols applied to terms are terms
If f is a function symbol and t₁, t₂, ..., tₙ are terms, then f(t₁, t₂, ..., tₙ) is also a term.

Single-Argument Functions

LeftLeg(John)

Father(Richard)

Mother(x)

Multi-Argument Functions

Plus(x, y)

Date(d, m, y)

Between(A, B, C)

Complex Terms

Rule
Complex terms are formed by nesting function applications
A function can take other terms (including other function terms) as arguments.
Building Complex Terms
LeftLeg(John) → John's left leg (simple term)
Father(LeftLeg(John)) → father of John's left leg (complex term)
LeftLeg(Father(John)) → left leg of John's father (complex term)
Head(LeftLeg(John)) → head of John's left leg (complex term)

The number of arguments a function takes is called its arity. LeftLeg has arity 1, Plus has arity 2, Date has arity 3.

Ground Terms

Definition
A ground term is a term that contains no variables
Ground terms are completely specific — they refer to one definite object.

Ground Terms ✓

Richard

LeftLeg(John)

Father(Mother(Richard))

Non-Ground Terms ✗

x

LeftLeg(y)

Father(x, y)

Variables as Terms

Rule
Variables (x, y, z) are also terms
Variables represent unknown or unspecified objects. They can stand in place of any term.
Variables in Context
∀x Likes(x, IceCream) → x is a term (universally quantified)
∃y Likes(Bob, y) → y is a term (existentially quantified)
Likes(x, y) → both x and y are terms

Terms as Arguments to Predicates

Key Relationship
Predicates take terms as arguments
The predicate relates terms (objects) to each other, producing a truth value.
Terms Inside Predicates
Likes(John, IceCream) → John and IceCream are terms
Loves(Father(John), Mary) → Father(John) and Mary are terms
Married(Richard, Elizabeth) → both are terms
Greater(Plus(x, 1), y) → Plus(x, 1) and y are terms

Example 1: Simple Constant Terms

Identifying Constant Terms
Given Knowledge Base
Constants: Richard, John, A, B
Each constant names a distinct individual.
Knows(Richard, John) → terms: Richard, John
King(Richard) → term: Richard
Lives(A, London) → terms: A, London
Friend(B, A) → terms: B, A

All arguments in these predicates are ground terms (constants).

Example 2: Function Terms

Building Terms with Functions
Function Symbols
LeftLeg, Father, Mother, Plus
Each function maps one or more objects to another object.
LeftLeg(John) → names "John's left leg"
Father(Richard) → names "Richard's father"
Mother(Father(John)) → names "the mother of John's father"
LeftLeg(LeftLeg(John)) → names "the left leg of John's left leg"

Each function application produces a new term that refers to a single object.

Example 3: Mixed Terms in Predicates

Complex Predicates with Various Terms
Knows(John, Father(Richard))
  → John is a constant term
  → Father(Richard) is a function term
  → Reading: "John knows Richard's father"

Likes(Father(John), Mother(Mary))
  → Father(John) is a function term
  → Mother(Mary) is a function term
  → Reading: "John's father likes Mary's mother"

Greater(Plus(x, 1), 10)
  → Plus(x, 1) is a function term
  → x is a variable term
  → 10 is a constant term
  → Reading: "x + 1 is greater than 10"

Example 4: Variables and Terms

Using Variables in Quantified Statements
∀x Likes(x, IceCream)
  → x is a variable term
  → IceCream is a constant term
  → Reading: "Everyone likes ice cream"

∃y Knows(y, Father(John))
  → y is a variable term
  → Father(John) is a function term
  → Reading: "Someone knows John's father"

∀x ∃y Loves(x, y)
  → x and y are both variable terms
  → Reading: "Everyone loves someone"

Example 5: Nested Function Terms

Deeply Nested Terms
Head(LeftLeg(John))
  → Inner: LeftLeg(John) → John's left leg
  → Outer: Head(...) → head of that leg
  → Reading: "the head of John's left leg"

Father(Mother(LeftLeg(Richard)))
  → Level 1: LeftLeg(Richard) → Richard's left leg
  → Level 2: Mother(...) → mother of that leg
  → Level 3: Father(...) → father of that
  → Reading: "the father of the mother of Richard's left leg"

No matter how deep the nesting, a term always evaluates to a single object.

Common Mistakes in Terms

⚠ Mistake 1: Confusing Functions with Procedures

Wrong thinking: "LeftLeg(John) computes John's left leg by running some algorithm."

Correct understanding: LeftLeg(John) is a naming mechanism — it simply names the object that is John's left leg. There is no computation, no procedure, no algorithm involved.

Analogy

Think of function terms like nicknames. "My brother" doesn't compute your brother — it just refers to the person who is your brother. Similarly, LeftLeg(John) doesn't compute anything — it refers to the object that is John's left leg.

⚠ Mistake 2: Confusing Terms with Predicates

Wrong thinking: "Loves(John, Mary) is a term."

Correct understanding: Loves(John, Mary) is a sentence (it has a truth value), not a term. Terms refer to objects; sentences refer to truth values.

Terms (Objects) ✓

John

Father(John)

LeftLeg(Mary)

Sentences (Truth Values) ✗

Loves(John, Mary)

Knows(x, y)

Greater(3, 5)

⚠ Mistake 3: Assuming Functions Must Be Computable

Wrong thinking: "LeftLeg is a function, so it must be something you can compute from data."

Correct understanding: In FOL, function symbols are simply part of the naming system. LeftLeg(John) names an object. Whether that object exists or can be physically located is irrelevant to its role as a term.

LeftLeg(John) names an object → the thing that is John's left leg
Father(John) names an object → the person who is John's father
Head(x) names an object → the thing that is x's head

These are NAMES, not computations.

⚠ Mistake 4: Mixing Up Arity

Wrong thinking: "LeftLeg takes two arguments: LeftLeg(John, left)."

Correct understanding: Each function has a fixed arity (number of arguments). LeftLeg has arity 1 — it takes exactly one argument.

FunctionArityCorrect UsageWrong Usage
LeftLeg1LeftLeg(John)LeftLeg(John, left)
Plus2Plus(x, y)Plus(x)
Date3Date(1, 1, 2024)Date(1, 1)
King—King(Richard) [predicate]King [not a term]

⚠ Mistake 5: Forgetting Variables Are Terms

Wrong thinking: "Only constants and functions are terms."

Correct understanding: Variables (x, y, z) are also terms. They represent unspecified objects and can appear anywhere a term can appear.

Likes(x, IceCream) → x is a term (variable)
Father(x) → x is a term (variable)
Plus(x, y) → x and y are both terms (variables)
∀z Knows(z, Father(x)) → z and x are both variable terms

RuleDescriptionExample

These rules are recursive — functions can contain other functions, which can contain other functions, and so on.

Formula Summary

Term (recursive definition)
1. A constant symbol c is a term
2. A variable x is a term
3. If f is a function symbol of arity n, and t₁, ..., tₙ are terms,
   then f(t₁, ..., tₙ) is a term
These three rules generate all possible terms in FOL.
Key Properties
• Terms refer to objects, not truth values
• Functions are naming mechanisms, not procedures
• Ground terms contain no variables
• Terms can be nested arbitrarily deep
• Terms appear as arguments to predicates
