First-Order Logic Syntax and Semantics

Artificial Intelligence — Complete Guide for Exam Preparation

What Is a Model?

A model (also called a structure) is a mathematical object that represents a possible world. It provides the raw materials — the objects and relationships — that give meaning to the symbols in first-order logic.

Definition:
M = ⟨D, I⟩
A model M consists of a domain D (set of objects) and an interpretation I that assigns meaning to symbols.

The Domain

The domain (also called the universe or discourse) is the set of all objects that exist in a given model. Every constant symbol must refer to an object in the domain, and every relation and function is defined over objects in the domain.

Key Point: The domain is non-empty — every model must contain at least one object.

Example Model: The Royal Court

Consider a model with 5 objects representing people and body parts:

Domain Elements
King John
A person
Richard
A person (John's brother)
Crown
An object
Left Leg of Richard
A body part
Left Leg of John
A body part
Relations in This Model

Brother relation (binary):

Brother = {⟨Richard, KingJohn⟩, ⟨KingJohn, Richard⟩}
Richard is brother of King John, and King John is brother of Richard.

Person relation (unary):

Person = {KingJohn, Richard}
Only King John and Richard are persons in this domain.

LeftLeg relation (binary, function):

LeftLeg(KingJohn) = Left Leg of John
LeftLeg(Richard) = Left Leg of Richard
The LeftLeg function maps each person to their left leg.

Relations: Unary vs Binary

Unary Relations (Properties)

Takes one argument

Maps objects to true/false

Example: Person(x) — is x a person?

Can be visualized as a circle enclosing all objects with that property.

Binary Relations

Takes two arguments

Maps pairs of objects to true/false

Example: Brother(x,y) — is x brother of y?

Can be visualized as a set of directed edges in a graph.

Functions

A function maps one or more objects to exactly one object. Functions are a special kind of relation — they are total and deterministic.

Function Property:
f: D^n → D
An n-ary function maps n objects from the domain to exactly one object in the domain.
Function Example

In our Royal Court model:

  • LeftLeg(KingJohn) = Left Leg of John
  • LeftLeg(Richard) = Left Leg of Richard

Note: Crown and the leg objects have no images under LeftLeg — the function is only defined for persons in this model.

Formal Grammar of First-Order Logic

The grammar defines exactly which strings of symbols are syntactically valid sentences in FOL. Every valid sentence is built recursively from atomic sentences using connectives and quantifiers.

Top-Level Rule:
Sentence → AtomicSentence | (Sentence Connective Sentence) | Quantifier Variable, ..., Variable Sentence | ¬Sentence
A sentence is either atomic, a compound with connectives, a quantified sentence, or a negation.

Production Rules in Detail

AtomicSentence → Predicate(Term, ..., Term)
An atomic sentence applies a predicate symbol to one or more terms.
Term → Constant | Function(Term, ..., Term) | Variable
A term is a constant, a variable, or a function applied to terms (recursively).
AtomicSentence → Term = Term
Equality is a special binary predicate built into FOL.
Sentence → (Sentence ∧ Sentence)
Conjunction — both sentences must be true.
Sentence → (Sentence ∨ Sentence)
Disjunction — at least one sentence must be true.
Sentence → (Sentence → Sentence)
Implication — if the first is true, the second must be true.
Sentence → (Sentence ↔ Sentence)
Biconditional — both sentences have the same truth value.
Sentence → ∀ Variable Sentence
Universal quantification — the sentence holds for all values of the variable.
Sentence → ∃ Variable Sentence
Existential quantification — the sentence holds for at least one value of the variable.
Sentence → ¬Sentence
Negation — the sentence is false.
Recursive Structure: Notice that terms can contain functions which contain terms, and sentences can contain sentences. This recursive structure allows FOL to express arbitrarily complex statements.

Concrete Grammar Examples

Valid Sentences
Person(KingJohn)
Brother(Richard, KingJohn)
LeftLeg(KingJohn) = LeftLeg(Richard)
∀x Person(x) → ∃y Brother(y, x)
¬Brother(Crown, KingJohn)
(Person(KingJohn) ∧ Brother(Richard, KingJohn)) → ¬Brother(Crown, KingJohn)
Invalid Sentences
Person() ← Missing argument
∀ ∀ x Sentence ← Double quantifier syntax error
→ Person(x) ← Connective at wrong position
Person(x, y) ← Arity mismatch (Person is unary)

Quantifier Scope and Binding

The scope of a quantifier is the sentence it quantifies over. A variable is bound by a quantifier if it appears within that quantifier's scope; otherwise it is free.

Bound vs Free Variables:
∀x P(x) ∧ Q(x)
The first x is bound by ∀x; the second x is free (not in scope of ∀x due to operator precedence).
Precedence Rule: Quantifiers bind more tightly than connectives. So ∀x P(x) ∧ Q(x) means (∀x P(x)) ∧ Q(x), not ∀x (P(x) ∧ Q(x)). To quantify over both, write: ∀x (P(x) ∧ Q(x)).

Three Types of Symbols

First-order logic uses three distinct types of symbols, each serving a different purpose:

Constant Symbols

Refer to specific objects in the domain

Examples: KingJohn, Richard, Crown

Analogous to proper nouns in English.

Predicate Symbols

Refer to relations or properties

Examples: Person(·), Brother(·,·), Left(·,·)

Each predicate has a fixed arity (number of arguments).

Function Symbols

Refer to functions mapping objects to objects

Examples: LeftLeg(·), Mother(·), Father(·)

Functions produce terms (which can be arguments to predicates).

Variable Symbols

In addition to the three symbol types above, FOL uses variable symbols (x, y, z, ...) that range over domain objects. Variables are not assigned fixed objects — they are placeholders used with quantifiers.

Variable Usage:
∀x Person(x) → ∃y Brother(y, x)
x and y are variables bound by quantifiers. They take on values from the domain during evaluation.

Interpretations

An interpretation maps the symbols in a sentence to actual objects, relations, and functions in a model. Without an interpretation, symbols are just meaningless strings.

Interpretation I:
I: Constants → Domain Objects
Each constant symbol is mapped to a specific object in the domain.
Relation Interpretation:
I: Predicate P(n-ary) → Subset of D^n
Each predicate is mapped to a set of n-tuples from the domain (the "true" cases).
Function Interpretation:
I: Function f(n-ary) → Mapping from D^n to D
Each function symbol is mapped to an actual function over domain objects.

Intended vs Other Interpretations

The intended interpretation is the one the author had in mind — where "KingJohn" really refers to King John, and "Brother" really means brother. However, a sentence can have many different interpretations in the same model.

Multiple Interpretations of the Same Sentence

Sentence: Brother(Richard, KingJohn)

Intended interpretation: Richard is the brother of King John.

Alternative interpretation 1: "Brother" means "same height as" — then the sentence says Richard is the same height as King John.

Alternative interpretation 2: "Richard" refers to the Crown, "KingJohn" refers to the Left Leg — the sentence makes a claim about those objects.

Important: The truth of a sentence depends on both the model AND the interpretation. The same sentence can be true under one interpretation and false under another, even in the same model.

When Is a Sentence True?

A sentence is true in a model (written M ⊨ φ) when, given the model and the interpretation, the sentence evaluates to true. This is determined recursively:

Atomic Sentences

P(t₁, ..., tₙ) is true if the tuple of objects denoted by t₁,...,tₙ is in the relation denoted by P.

Connectives

Use the standard truth tables for ∧, ∨, →, ↔, ¬ applied to sub-sentences.

Universal ∀

∀x φ is true if φ is true for every assignment of x to objects in the domain.

Existential ∃

∃x φ is true if φ is true for at least one assignment of x to objects in the domain.

Evaluating Sentences in a Model

We use the Royal Court model throughout. Recall the domain:

D = {KingJohn, Richard, Crown, LeftLeg(KingJohn), LeftLeg(Richard)}
Brother = {⟨Richard, KingJohn⟩, ⟨KingJohn, Richard⟩}
Person = {KingJohn, Richard}
LeftLeg(KingJohn) = LeftLeg(KingJohn), LeftLeg(Richard) = LeftLeg(Richard)

Example 1: Atomic Sentence

Evaluating Person(KingJohn)

Sentence: Person(KingJohn)

Step 1: Interpret KingJohn as the object KingJohn in the domain.

Step 2: Check if KingJohn ∈ Person.

Step 3: Person = {KingJohn, Richard}, so KingJohn ∈ Person is true.

Result: TRUE

Example 2: Negation

Evaluating ¬Brother(Crown, KingJohn)

Sentence: ¬Brother(Crown, KingJohn)

Step 1: Evaluate Brother(Crown, KingJohn) first.

Step 2: Check if ⟨Crown, KingJohn⟩ ∈ Brother.

Step 3: Brother = {⟨Richard, KingJohn⟩, ⟨KingJohn, Richard⟩}. The pair ⟨Crown, KingJohn⟩ is NOT in this set.

Step 4: So Brother(Crown, KingJohn) is false, and ¬false = true.

Result: TRUE

Example 3: Conjunction

Evaluating Person(KingJohn) ∧ Brother(Richard, KingJohn)

Sentence: Person(KingJohn) ∧ Brother(Richard, KingJohn)

Step 1: Evaluate Person(KingJohn) → TRUE (from Example 1).

Step 2: Evaluate Brother(Richard, KingJohn) → Check if ⟨Richard, KingJohn⟩ ∈ Brother → TRUE.

Step 3: TRUE ∧ TRUE = TRUE.

Result: TRUE

Example 4: Universal Quantifier

Evaluating ∀x Person(x) → ∃y Brother(y, x)

Sentence: ∀x (Person(x) → ∃y Brother(y, x))

Meaning: "For every person x, there exists someone y who is x's brother."

Step 1: Check for x = KingJohn: Person(KingJohn) is TRUE. Is there a y with Brother(y, KingJohn)? Yes: y = Richard. So TRUE → TRUE = TRUE.

Step 2: Check for x = Richard: Person(Richard) is TRUE. Is there a y with Brother(y, Richard)? Yes: y = KingJohn. So TRUE → TRUE = TRUE.

Step 3: Check for x = Crown: Person(Crown) is FALSE. So FALSE → ... = TRUE (vacuously true).

Step 4: Check for x = LeftLeg(KingJohn): Person(LeftLeg(KingJohn)) is FALSE. So TRUE.

Step 5: Check for x = LeftLeg(Richard): Person(LeftLeg(Richard)) is FALSE. So TRUE.

All cases are TRUE.

Result: TRUE

Example 5: Existential Quantifier

Evaluating ∃x Person(x) ∧ ∀y Brother(y, x)

Sentence: ∃x (Person(x) ∧ ∀y Brother(y, x))

Meaning: "There exists a person x such that everyone y is x's brother."

Step 1: Try x = KingJohn: Person(KingJohn) is TRUE. Is ∀y Brother(y, KingJohn) true? We need Brother(Crown, KingJohn) to be true — but it is FALSE. So this fails.

Step 2: Try x = Richard: Person(Richard) is TRUE. Is ∀y Brother(y, Richard) true? We need Brother(Crown, Richard) to be true — but it is FALSE. So this fails.

Step 3: No person x satisfies the condition.

Result: FALSE

Example 6: Implication with Quantifiers

Evaluating ∀x Person(x) → Brother(KingJohn, x)

Sentence: ∀x (Person(x) → Brother(KingJohn, x))

Meaning: "King John is the brother of every person."

Step 1: x = KingJohn: Person(KingJohn) TRUE → Brother(KingJohn, KingJohn)? Is ⟨KingJohn, KingJohn⟩ ∈ Brother? No — it is FALSE. So TRUE → FALSE = FALSE.

Step 2: We found a counterexample. No need to check further.

Result: FALSE

FOL vs Propositional Logic

Propositional Logic

  • Atomic units: propositions (P, Q, R)
  • No internal structure in atoms
  • No quantifiers
  • No variables
  • Truth values assigned to propositions
  • Cannot express "all" or "some"

First-Order Logic

  • Atomic units: predicates applied to terms
  • Terms have internal structure (constants, functions, variables)
  • Universal (∀) and existential (∃) quantifiers
  • Variables range over domain objects
  • Truth determined by model + interpretation
  • Can express "all objects have property P"

Entailment and Validity

Entailment (⊨):
KB ⊨ α
KB entails α if in every model where KB is true, α is also true. The knowledge base logically implies α.
Validity (Tautology):
⊨ α
α is valid (a tautology) if it is true in EVERY possible model and EVERY possible interpretation.
Satisfiability:
∃M such that M ⊨ α
α is satisfiable if there exists at least one model and interpretation where α is true.
Contrast with Propositional Logic: In propositional logic, entailment is checked over all 2^n truth assignments. In FOL, entailment requires checking ALL possible models (which can be infinite), making the problem undecidable in general.

Core Concepts Summary

Model

A structure = ⟨D, I⟩ containing a domain and interpretation.

Domain

The set of all objects in a model. Non-empty.

Interpretation

Maps symbols to objects/relations/functions in the domain.

Intended Interpretation

The interpretation the author had in mind.

Truth

Determined by model + interpretation, evaluated recursively.

Entailment

True in ALL models where premises are true.

Validity

True in ALL models under ALL interpretations.

Satisfiability

True in at least one model under some interpretation.

Common Exam Traps

1. Scope of Quantifiers: ∀x P(x) ∧ Q(x) ≠ ∀x (P(x) ∧ Q(x)). The first only binds x in P(x). Always use parentheses to be explicit.
2. Order of Quantifiers: ∀x ∃y Brother(x, y) ≠ ∃y ∀x Brother(x, y). The first says everyone has a brother (possibly different ones); the second says there is one person who is everyone's brother.
3. Negation Placement: ¬∀x P(x) ≡ ∃x ¬P(x). Negation moves inside and flips the quantifier.
4. Vacuous Truth: ∀x Person(x) → Brother(x, Crown) is TRUE if no x is a person. The implication is vacuously true when the antecedent is false.
5. Functions vs Relations: A function maps each input to EXACTLY ONE output. A relation maps inputs to true/false. LeftLeg is a function; Brother is a relation.
