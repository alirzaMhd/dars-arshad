Depth-First Search (DFS)

Uninformed Search — Deep-First Strategy

DFS Algorithm Overview

Depth-First Search expands the deepest unexpanded node first. It explores one branch completely before backtracking to try alternative paths.

Core Principle:
Expand deepest unexpanded node first
DFS follows a single branch to its maximum depth before backtracking, unlike BFS which explores level by level.

Two Implementations

Iterative (LIFO Stack)

• New successors go to front of stack

• Explicit frontier management

• Space: O(bm)

Recursive (Backtracking)

• Uses call stack implicitly

• Generates one child at a time

• Space: O(m) — very efficient

Tree-Search Pseudocode

function DFS(problem) returns solution or failure node ← Node(State: problem.INITIAL, Parent: nil, Action: nil, Path-Cost: 0) frontier ← LIFO-stack containing node explored ← empty set loop do if EMPTY?(frontier) then return failure node ← POP(frontier) if problem.GOAL-TEST(node.State) then return SOLUTION(node) add node.State to explored for each action in problem.ACTIONS(node.State) do child ← CHILD-NODE(problem, node, action) if child.State not in explored and child.State not in frontier then frontier ← INSERT(child, frontier) // add to front (LIFO)

Recursive Backtracking Pseudocode

function RECURSIVE-DFS(problem, node) returns solution or failure if problem.GOAL-TEST(node.State) then return SOLUTION(node) for each action in problem.ACTIONS(node.State) do child ← CHILD-NODE(problem, node, action) result ← RECURSIVE-DFS(problem, child) if result ≠ failure then return result return failure
Recursive DFS generates only one child at a time, reducing space from O(bm) to O(m). It is the basis for backtracking search algorithms in constraint satisfaction.

Completeness of DFS

Completeness:
DFS is NOT complete in infinite state spaces
DFS can get stuck going down an infinite path (a branch that never reaches a goal and has no leaf nodes). It will never backtrack to explore alternative branches.
Warning: Infinite Path Problem

Consider a state space with a cycle: A → B → C → A → B → ... If DFS enters this cycle, it will follow it forever, never exploring other parts of the tree that might contain the goal. This is why DFS without cycle detection is incomplete.

When DFS CAN Be Complete

DFS is complete in finite state spaces. If the state space is finite (no infinite branches), DFS will eventually exhaust every branch. However, even in finite spaces, DFS may be practically infeasible if the maximum depth is very large.

Optimality of DFS

Optimality:
DFS is NOT optimal
DFS returns the first solution it finds, which is determined by the order of expansion and the structure of the search tree — not by solution cost. The first solution may be arbitrarily expensive.

Why DFS is Not Optimal

• Explores deep branches first

• Deep solution found before shallow

• No cost consideration

When It Might Be OK

• All solutions equally costly

• Only need any solution

• Solutions are dense (many goals)

Time & Space Complexity

Time Complexity:
O(bm)
Where m = maximum depth of the state space (could be infinite). In the worst case, DFS explores the entire tree, visiting every node.
Space Complexity (Stack-based):
O(bm)
The LIFO stack stores at most one path from root to deepest node (m nodes) plus the siblings of each node on that path (b-1 siblings at each of m levels).
Space Complexity (Backtracking):
O(m)
Recursive backtracking generates only one child at a time, so only the current path is stored. This is DFS's key advantage over BFS.

The Impact of m vs d

If the maximum depth m is much larger than the shallowest goal depth d, DFS time complexity becomes far worse than BFS.

ScenarioBFS (b=10, d=6)DFS (b=10, m=20)

When DFS is Efficient

DFS works well when:

• Solutions are dense (many goal states near leaves)

• m is close to d (maximum depth ≈ goal depth)

• Memory is limited (space-critical applications)

• We only need any solution, not the best one

Repeated State Detection

In cyclic state spaces, DFS without an explored set can loop indefinitely. Adding an explored set (graph-search) prevents this but requires O(bm) memory in the worst case — eliminating DFS's space advantage.

Warning: m Matters

When m >> d: DFS can waste enormous time exploring a deep path that leads nowhere while the goal is just a few levels away. The time complexity O(bm) is exponential in m, not d. A small increase in m makes DFS infeasible.

Worked Examples

Example 1: Trace DFS on a Binary Tree

Problem: Binary tree (b = 2), depth 3. Nodes: Root → L, R → LL, LR, RL, RR. Goal is "LR" (left-right child). Trace DFS using LIFO stack.

Order: left children pushed first (left-to-right).

StepStack (top → bottom)ExpandedAction
1[Root]—Initialize
2[L, R]RootPop Root, push L, R (L on top)
3[LL, LR, R]LPop L, push LL, LR (LL on top)
4[LR, R]LLPop LL (leaf), no children
5[R]LR ✓Pop LR — goal! Return solution.

DFS found goal at step 5, expanding only 4 nodes. BFS would have taken more steps (expanding Root, L, R first). DFS wins here because goal is deep on the left side.

Example 2: Backtracking DFS vs Full DFS Space

Problem: Tree with b = 10, m = 1000. Compare space usage.

Full DFS (LIFO stack):

Space = O(bm) = O(10 × 1000) = 10,000 nodes
Stores entire path (1000 nodes) + up to 9 siblings at each level = 9 × 1000 = 9000 sibling nodes. Total ≈ 10,000 nodes.

Backtracking DFS (recursive):

Space = O(m) = O(1000) = 1,000 nodes
Only stores the current path of 1000 nodes. No sibling storage needed.

Backtracking uses 10× less space. At 1KB per node, that's 10MB vs 1MB — a critical difference in memory-constrained environments.

Example 3: DFS Infinite Path Problem

Problem: A graph has a cycle: S → A → B → A (loop). There is also a branch S → C → G (goal at G). DFS starts with S, explores left-to-right (A before C).

StepStackAction
1[S]Initialize
2[A, C]Pop S, push A, C (A on top)
3[B, C]Pop A, push B
4[A, C]Pop B, push A (back to A!)
5[B, C]Pop A, push B — cycle repeats

DFS never reaches C or G. It oscillates between A and B forever. The goal at G (just one step from C) is never found. Solution: use an explored set (graph search) or depth limit (DLS).

Cycle Detection Essential

Without an explored set, DFS fails on cyclic graphs. Always use graph-search DFS (with explored set) or DLS for cyclic state spaces.

Example 4: DFS vs BFS on Dense Solutions

Problem: A tree with b = 3, d = 5, m = 10. Goal states exist at every leaf at depth 5 (27 leaves). Also all nodes at depth 10 (59,049 leaves) are goals.

BFS: Explores 3 + 9 + 27 + 81 + 243 = 363 nodes to reach depth 5. Time OK, space = 243 nodes in fringe ≈ O(bd).

DFS (backtracking): Explores one path of length 10 (worst case). 10 nodes in memory. Finds a goal at depth 5 or 10. Space = O(m) = 10 nodes.

When solutions are dense, DFS is far more efficient in space. Only when the solution is at depth 10 does DFS explore more nodes (worst case 310 ≈ 59,000) — but still only O(m) = 10 nodes in memory.
