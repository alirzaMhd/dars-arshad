Iterative Deepening Search (IDS)

Artificial Intelligence — Chapter 2: Problem Solving Using Search

Iterative Deepening Search Concept

IDS combines the benefits of BFS (completeness) and DFS (linear memory) by repeatedly running depth-limited search with increasing depth limits. It starts at l=0, then l=1, l=2, and so on until the goal is found.

Core Idea
For l = 0, 1, 2, ... do DLS(root, l)
Repeated Depth-Limited Search with increasing limit until goal found

How IDS Works

The algorithm performs a series of depth-first searches. After the l-th iteration fails (no goal within depth l), the search begins again from scratch with depth limit l+1. This means nodes are regenerated at each level, which appears wasteful but is actually efficient because most nodes live at the deepest level.

Pseudocode: ITERATIVE-DEEPENING-SEARCH

function ITERATIVE-DEEPENING-SEARCH(problem) returns solution or failure for depth = 0 to ∞ do result ← DEPTH-LIMITED-SEARCH(problem, depth) if result ≠ cutoff then return result function DEPTH-LIMITED-SEARCH(problem, limit) returns solution or failure/cutoff return RECURSIVE-DLS(MAKE-NODE(problem.INITIAL-STATE), problem, limit) function RECURSIVE-DLS(node, problem, limit) returns solution or failure/cutoff if problem.GOAL-TEST(node.STATE) then return SOLUTION(node) if limit = 0 then return cutoff cutoff-occurred? ← false for each action in problem.ACTIONS(node.STATE) do child ← CHILD-NODE(problem, node, action) result ← RECURSIVE-DLS(child, problem, limit - 1) if result = cutoff then cutoff-occurred? ← true else if result ≠ failure then return result if cutoff-occurred? then return cutoff else return failure

Key Characteristics

• Repeated DLS calls with l=0,1,2,...

• Nodes regenerated each iteration

• Memory-efficient like DFS

• Complete like BFS

• Preferred uninformed search for large state spaces

When to Use IDS

• State space is large

• Depth of goal is unknown

• Memory is limited

• Step costs are uniform

⚠ Common Mistake

Students often think IDS is wasteful because it regenerates nodes. In reality, the regeneration cost is small because most nodes are at the deepest level. IDS is actually faster than BFS for large search spaces despite regenerating nodes!

Time Complexity Analysis

In IDS, nodes at depth d are generated once (in the last iteration). Nodes at depth d-1 are generated twice (last iteration + previous). In general, a node at depth k is generated (d - k + 1) times.

Total Nodes Generated by IDS
N(IDS) = (d)b + (d-1)b² + (d-2)b³ + ... + (1)bd
where d = goal depth, b = branching factor
Asymptotic Complexity
N(IDS) = O(bd)
Same asymptotic complexity as BFS
Nodes Generated by BFS (for comparison)
N(BFS) = 1 + b + b² + b³ + ... + bd = (bd+1 - 1) / (b - 1)
BFS generates all nodes down to depth d

Why Regeneration is Efficient

The key insight: most nodes are at the deepest level d. The cost of regenerating shallow nodes is negligible compared to the cost of generating the deepest level.

Numerical Comparison (b=10, d=5)
N(IDS) = 123,450 < N(BFS) = 1,111,100
IDS generates 9x fewer nodes than BFS!

⚠ Efficiency Insight

IDS generates N(IDS) = (d)b + (d-1)b² + ... + (1)bd nodes. The last term (1)bd dominates — nodes at the deepest level contribute the most. Shallower levels are regenerated but their count is tiny relative to bd.

Completeness of IDS

IDS is complete when the branching factor b is finite. Since IDS explores all nodes at depth 0, then all at depth 1, then all at depth 2, etc., it will eventually reach any finite-depth goal node.

Complete if:

• Branching factor b is finite

• Goal exists at some finite depth

Not complete if:

• Infinite branching factor

• No finite-depth solution exists

Optimality of IDS

IDS is optimal when step costs are uniform (i.e., all actions have the same cost). This is because IDS finds the shallowest goal first — it explores all nodes at depth l before moving to depth l+1.

Optimality Condition
cost(step) = constant  →  IDS is optimal
When all step costs are equal, shallowest = cheapest

Optimal if:

• Step costs are uniform

• Path cost is non-decreasing with depth

Not optimal if:

• Step costs vary (need UCS)

• Some costly shallow paths and cheap deep paths exist

⚠ Key Exam Point

IDS is the preferred uninformed search method when the state space is large and the depth of the solution is unknown. It offers BFS's completeness and optimality with DFS's linear memory requirement.

Worked Examples

Example 1: Trace IDS on a Simple Tree

Tree: Root A has children B, C. B has child D. C has child E. Goal = E at depth 2.

Trace:

l=0: Expand A (cutoff, not goal)
l=1: DLS from A at limit 1
A → B (cutoff, not goal) → backtrack
A → C (cutoff, not goal) → backtrack
l=2: DLS from A at limit 2
A → B → D (leaf, not goal) → backtrack
A → C → E (goal!)

Result: Found at l=2. Nodes generated: l=0:1, l=1:3, l=2:5 = total 9 nodes.

Example 2: Calculate N(IDS) vs N(BFS)

Given: b = 3, goal depth d = 4

N(IDS) calculation:

N(IDS) = (4)(3) + (3)(3²) + (2)(3³) + (1)(3⁴)

= 12 + 27 + 54 + 81 = 174 nodes

N(BFS) calculation:

N(BFS) = 1 + 3 + 9 + 27 + 81 = 121 nodes

Comparison: BFS generates fewer nodes here because b is small. For b=10, IDS becomes more efficient.

Ratio for b=10, d=5
N(IDS) / N(BFS) = 123,450 / 1,111,100 = 0.111
IDS generates only 11% of BFS nodes!
Example 3: IDS with Large Branching Factor

Given: b = 8, goal depth d = 6

N(IDS):

= 6(8) + 5(64) + 4(512) + 3(4096) + 2(32768) + 1(262144)

= 48 + 320 + 2048 + 12288 + 65536 + 262144 = 342,384 nodes

N(BFS):

= 1 + 8 + 64 + 512 + 4096 + 32768 + 262144 = 299,593 nodes

Observation: For b=8, BFS still generates fewer nodes. The crossover where IDS wins depends on the specific values of b and d. IDS memory advantage (O(bd) vs O(bd)) is the bigger win.

⚠ Exam Tip

When asked to trace IDS, always show each iteration (l=0, l=1, l=2, ...) separately. For each iteration, show the DLS path and which nodes are cutoff. The last iteration finds the goal.
