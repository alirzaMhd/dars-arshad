Problem Formulation & Abstraction

AI Search Foundations — Complete Guide

The Five Components of a Problem

Every search problem in AI is defined by exactly five components. Understanding these is the foundation for all search algorithms.

1. Initial State

The state where the agent starts. Denoted s0.

Example: "At home with no packages delivered"

2. Actions / Successor Function

Given a state s, defines the set of actions available and their resulting states: Actions(s) → {(a1, s1), ...}

3. Transition Model

Describes what each action does: Result(s, a) = s'

4. Goal Test

Determines if a state is a goal. Can be a single state or a set of states.

5. Path Cost Function

Assigns a numeric cost to each path. Denoted c(s, a, s') for the step cost.

Path Cost Formula
Path Cost = ∑ c(si, ai, si+1)
The total cost of a path is the sum of step costs for each action taken along the path.
Step Cost Function
c(x, y) = cost of action from state x to state y
A positive number representing the effort, distance, or time required for a single action.
Example: Delivering Packages

Initial State: Robot at warehouse (W), packages P1 and P2 at warehouse.

Actions: Move(destination), PickUp(package), DropOff(package)

Goal Test: P1 delivered to A, P2 delivered to B, robot anywhere.

Path Cost: Move=2 per step, PickUp=1, DropOff=1. Total = sum of all steps.

What is Abstraction?

Abstraction is the process of removing irrelevant details from the state description while keeping the essence of the problem. Without abstraction, real-world problems have infinitely many states and the agent is overwhelmed.

Valid Abstraction

Every abstract solution can be expanded into a concrete solution.

Useful Abstraction

The abstract actions are easier to perform than solving the original problem directly.

Good Abstraction

Removes as many details as possible while keeping all actions feasible.

Abstraction Quality Criteria
Valid ∧ Useful ∧ Good ⇒ Effective Abstraction
An abstraction must satisfy all three properties to be effective for an AI agent.
Example: Route Planning Abstraction Levels

Concrete: "Move left foot 30cm forward, shift weight, move right foot..." — too many details.

Valid Abstraction: "Walk from (x, y) to (x+1, y)" — every walk step can expand to foot movements.

Better Abstraction: "Drive from city A to city B via highway" — removes road-level turns.

Bad Abstraction: "Teleport to destination" — not expandable to real actions (invalid).

Comparison: Types of Abstraction

A common mistake is over-abstraction: removing so many details that the abstract solution no longer corresponds to a valid concrete solution. Always verify the abstraction is valid first, then optimize for usefulness and goodness.

The Problem-Solving Agent Cycle

A goal-based (problem-solving) agent follows a four-phase cycle to achieve its objectives in the world.

Phase 1: Goal Formulation

Define what success looks like. Goals can be single-state or set-based.

Agent asks: "What do I want to achieve?"

Phase 2: Problem Formulation

Define the 5 components: initial state, actions, transition model, goal test, path cost.

Agent asks: "How do I represent the world?"

Phase 3: Search

Explore the state space to find a sequence of actions from start to goal.

Agent asks: "Which actions lead to the goal?"

Phase 4: Execution

Execute the found solution in the real environment.

Agent asks: "Now act!"

Agent Cycle Pseudocode
function Simple-Problem-Solving-Agent(percept): persistent: goal, problem, solution, state state ← Update-State(state, percept) if not Is-Goal(goal, state): goal ← Formulate-Goal(state) problem ← Formulate-Problem(goal, state) solution ← Search(problem) return Execute(solution, state)
Example: Coffee Delivery Agent

Goal Formulation: "Deliver a hot coffee to my desk."

Problem Formulation: State = (my_location, coffee_location, coffee_temp). Actions = Walk(to), PickUp(), Deliver(). Goal = coffee_at_desk ∧ temp > 60°C. Path cost = time in minutes.

Search: Find shortest path from current location to coffee shop, then to desk.

Execution: Walk to shop, pick up coffee, walk to desk.

Performance Measure & Path Cost

Path cost is always derived from the agent's performance measure. A rational agent chooses actions that maximize expected performance.

Rationality Principle
Agent chooses action a = argmina [ PathCost(Result(s, a)) ]
The agent selects the action that minimizes the expected path cost to a goal.
Do NOT confuse path cost with execution cost. Path cost is assigned before execution during the problem formulation phase. Some steps may cost differently in reality than in the abstract model.

Worked Examples

Example 1: Automated Vacuum Cleaner in a Three-Room House

Scenario: A robot vacuum must clean rooms A, B, C. Each room starts dirty. The robot starts in room A.

Problem Formulation:

Initial state: (A, dirty, dirty, dirty) — agent at A, all rooms dirty.

Actions: MoveLeft (A→B, B→C), MoveRight (C→B, B→A), Suck (cleans current room).

Goal test: (_, clean, clean, clean) — all rooms clean, agent anywhere.

Path cost: Each move costs 1, each suck costs 1.

Solution: Suck (A), MoveRight (to B), Suck (B), MoveRight (to C), Suck (C). Total cost = 5.

Example 2: Maze Navigation Robot

Scenario: A robot starts at cell (1,1) in a 5x5 grid maze. The goal is cell (5,5). Walls block certain cells.

Problem Formulation:

Initial state: (1, 1). Actions: Move_Up, Move_Down, Move_Left, Move_Right (only if no wall).

Transition model: Result((x, y), Move_Up) = (x, y+1) if clear.

Goal test: (5, 5). Path cost: 1 per move.

State space: Up to 25 states (but fewer if walls block cells). Branching factor = 2-4 depending on walls.

Example 3: Package Delivery with Time Windows

Scenario: A drone must deliver 3 packages to locations L1, L2, L3. Each location has a delivery time window: L1 [9:00-10:00], L2 [10:00-11:00], L3 [11:00-12:00]. The drone starts at depot D at 8:00. Travel between any two locations takes 30 minutes. Each drop-off takes 5 minutes.

Initial state: (D, 8:00, {P1, P2, P3})

Actions: Fly(L), Drop(P). Transition: Fly(L) updates location and time (+30min). Drop(P) removes from cargo.

Goal test: Cargo empty ∧ all times within windows.

Path cost: Total time = sum of flight + drop-off times. Optimal solution must respect time windows.

Example 4: Chess Endgame (Multiple Goal States)

Scenario: White king and rook vs black king. White wants to checkmate black.

Initial state: (WK=e1, WR=h1, BK=e8, turn=white)

Actions: All legal chess moves for the current player.

Goal test: Is state a checkmate? (Many possible checkmate configurations.)

Path cost: Not used here — any checkmate is acceptable (breadth-first or depth-first search, not optimal).

State space abstraction: Abstract away piece identities beyond K, R, K. Abstract away 50-move rule and other advanced rules initially.

Key insight: Not all problems need path costs — the problem formulation adapts to the agent's needs.
