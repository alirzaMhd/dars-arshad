Three Types of Incomplete Information Problems

So far we assumed fully observable, deterministic, single-agent environments. Real-world problems often violate these assumptions, leading to three important categories.

Sensorless Problems

Agent has no sensors. It knows only the set of possible initial states. After any action, it knows the resulting state is one of several possibilities, but not which one.

Contingency Problems

Environment is partially observable or actions are nondeterministic. The agent receives new observations after each action and must plan for different branches based on what it observes.

Exploration Problems

Both states and actions are unknown. The agent must explore to discover the environment. This is the most general form and subsumes contingency problems.

Classification Summary:
Sensorless: no sensors, deterministic actions
Contingency: some sensors, nondeterministic actions
Exploration: no sensors, unknown actions/states

Belief States

A belief state is a set of physical states the agent considers possible. In a fully observable world, each belief state contains exactly one physical state. In a sensorless world, belief states can contain many.

Belief State Size:
If physical state space has s states, belief space has 2^s states
Each subset of physical states is a potential belief state. For the 8-state vacuum world, there are 2^8 = 256 possible belief states, though not all are reachable.
Example - Vacuum Without Sensors

Agent knows it is in one of {1,2,3,4,5,6,7,8}. After action Right, it knows it is in one of {2,4,6,8}. After [Right, Suck], it knows it is in one of {4,8}. After [Right, Suck, Left, Suck], it knows it is in state {7} for sure - the goal.

Key insight: A guaranteed plan exists without any sensors: [Right, Suck, Left, Suck] always reaches the goal regardless of starting state.

Example - Murphy's Law Vacuum

Suck sometimes fails and leaves dirt if there was none. Starting from belief state {1,2,3,4,5,6,7,8}, after Suck the belief state becomes {1,2,3,4,5,6,7,8} again - no information gained. The problem becomes unsolvable without sensors.

Contingency Problems

In contingency problems, the agent must create a conditional plan: a tree of actions where each branch corresponds to a different possible observation. The solution is not a sequence but a decision tree.

# Example conditional plan structure
if [Right, Dirty] then Suck
else if [Right, Clean] then Left
else Noop
Example - Murphy's Law with Sensors

Agent has location and local dirt sensors. Plan: [Suck, Right, if [Dirty] then Suck]. The agent first sucks at current square (may succeed or fail), moves right, then checks if dirty and sucks conditionally.

This plan succeeds with high probability but not certainty. The agent interleaves search and execution.

Key Difference: Deterministic search produces a linear sequence of actions. Contingency search produces a tree of actions where branches are selected based on runtime observations.

Worked Examples

Example 1 - Belief State Search

Initial belief: {1,3,5,7}. Apply Right: belief becomes {2,4,6,8}. Apply Suck: belief becomes {2,4,6,8} (suck may fail or succeed, belief unchanged). Apply Left: belief becomes {1,3,5,7}. We loop without progress.

Example 2 - Guaranteed Plan

Plan [R, S, L, S] from initial belief {1..8} reaches goal belief {7} in 4 steps regardless of initial state. The agent does not need to know where it starts.

Example 3 - Nondeterministic Action

Action Move has two possible outcomes: move forward 1m with 0.9 probability, or stay in place with 0.1 probability. Agent must plan for both branches. A contingent plan might be: Move, then check position, then Move again if needed.

Example 4 - Web Crawler (Exploration)

An agent exploring the web does not know what pages exist or what links they contain. It must explore links, observe new pages, and update its model of the web graph. This is an exploration problem.
