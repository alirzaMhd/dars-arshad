Artificial Intelligence — Chapter 2: Problem Solving Using Search

NP and NP-Complete Problems

NP stands for Non-deterministic Polynomial time. These are problems where a candidate solution can be verified in polynomial time, even if finding the solution may be exponential.

P (Polynomial)

Problems solvable in polynomial time. Example: sorting, shortest path.

NP

Problems verifiable in polynomial time. Example: 8-puzzle, SAT.

NP-Complete

The hardest problems in NP. If any NP-complete problem is solvable in polynomial time, then P = NP.

8-Puzzle: Disjoint State Sets

The 8-puzzle has a fascinating property: its 181,440 reachable states are divided into two disjoint sets with no transitions between them. The parity of the permutation determines which set a state belongs to:

8-Puzzle Parity Invariant
(number of inversions + row of blank) mod 2 = constant
Half the permutations are unreachable — they have the wrong parity

Practical implication: Before solving an 8-puzzle instance, check parity. If start and goal have different parity, no solution exists — saves wasted search time.

Problem-Solving Agent

The search algorithms in this chapter are used by a goal-based agent — an agent that acts to achieve a specified goal state. The agent:

  • Formulates a goal (set of goal states)
  • Formulates the problem (actions, transition model, step costs)
  • Searches for a solution (path from initial state to goal)
  • Executes the solution
⚠ Exam Trap: 8-Puzzle Parity

Students often assume all permutations of the 8-puzzle are solvable. In reality, exactly half (181,440 of 362,880) are reachable from any given start state. Always check parity before attempting to solve an 8-puzzle instance!

Iterative Lengthening Search (ILS)

ILS is the cost-based analog of IDS. Instead of depth limits, ILS uses increasing cost limits. It performs UCS-like search but with a cost bound that increases each iteration.

ILS Cost Limit
Start with l = 0, then l = ε, l = 2ε, l = 3ε, ...
where ε = smallest positive step cost
ILS Iterations
C* / ε  iterations
where C* = optimal solution cost, ε = minimum cost increment

ILS Properties

  • Complete: Yes (if costs are non-negative and finite)
  • Optimal: Yes (finds cheapest solution first)
  • Space: Less than UCS (doesn't need to store all nodes)
  • Time: Significant overhead due to restarts — may be much slower than UCS

Negative Costs and Pruning

If actions can have negative costs, the optimal algorithm may need to search the entire space:

Negative Costs: Worst Case
If any cost < 0: must explore entire space for optimality
Cycles with negative total cost can lead to arbitrarily cheap paths
Bounded Negative Costs
If ∀ a: -C ≤ cost(a) and max depth = m, prune if path cost < -Cm
Even with negative costs, UCS can prune paths that can't possibly improve the solution

ILS vs IDS

IDS uses depth as limit. ILS uses path cost as limit. When all steps cost 1, they are equivalent.

ILS vs UCS

UCS expands in order of cost and terminates. ILS restarts from scratch with increasing cost bounds — similar to how IDS restarts with increasing depth bounds.

⚠ ILS Time Cost

When costs are fractional (e.g., in [0,1]), ILS may need C*/ε iterations. If ε = 0.001 and C* = 10, that's 10,000 iterations — each restarting from scratch! ILS is rarely used in practice due to this overhead.

Key Takeaways

Best Time

Bidirectional

O(bd/2) — exponentially faster than others

Best Space

DFS / DLS / IDS

O(bd) or O(bl) — linear in depth

Best Overall

IDS

Complete + optimal (uniform) + O(bd) space

Best Optimality

UCS

Works with non-uniform positive costs

⚠ No Free Lunch

No algorithm dominates all criteria. Bidirectional has best time but needs O(bd/2) space. DFS has best space but isn't complete. IDS balances both but regenerates nodes. UCS is optimal but expensive with small cost increments. Choose based on your problem's constraints!

Example 2: ILS Iteration Count

Problem: Search with step costs in [0.01, 0.05, 0.10]. Optimal path cost C* = 3.42.

Minimum cost increment: ε = 0.01

ILS iterations:

l = 0, 0.01, 0.02, 0.03, ..., up to 3.42

Number of iterations = C*/ε = 3.42 / 0.01 = 342 iterations

Compare with IDS: If depth d = 10, IDS needs only 10 iterations (l=0 to 9, then l=10 finds goal).

Observation: ILS is impractical for small cost increments. UCS would solve this in a single pass without restarts.

Example 3: 8-Puzzle Parity Check

Start state: [1, 2, 3; 4, 5, 6; 8, 7, _] (blank = bottom-right, 8 and 7 swapped)

Goal state: [1, 2, 3; 4, 5, 6; 7, 8, _]

Count inversions: Pairs (i, j) where i < j but value at i > value at j.

Start: [1,2,3,4,5,6,8,7]. Inversions: only (8,7) = 1 inversion.

Blank row = 3 (counting from 1). Parity: (1 + 3) mod 2 = 0.

Goal: [1,2,3,4,5,6,7,8]. Inversions: 0. Blank row = 3. Parity: (0 + 3) mod 2 = 1.

Result: Parity differs (0 vs 1). This puzzle is unsolvable!

Swapping 7 and 8 changes the parity. The start state must be changed to match parity with the goal.

Example 4: Determine Problem Class

Scenario A: Mars rover exploring unknown terrain. No map. Sensors detect nearby obstacles but not what's over the hill. Actions: move forward, turn, take sample.

Classification: Exploration — the environment (terrain, obstacles) is unknown, and the agent must discover it.

Scenario B: Robot arm assembling a phone from known components. Camera tracks every component's position. Gripper always succeeds. Each step has known outcome.

Classification: Single-State — fully observable + deterministic.

Scenario C: Robot vacuum cleaner with no battery sensor. It may run out of battery at any time (non-deterministic). The robot can't observe battery level.

Classification: Contingency — partial observability (no battery info) + non-deterministic (random battery death). Solution needs conditional plan: [Clean until no response, then dock and charge].

Scenario D: Automatic car parking system. Camera sees the entire parking lot. But the steering may slip on wet surfaces (non-deterministic).

Classification: Contingency — fully observable but non-deterministic actions (steering slip). Solution needs sensing after actions to correct for slip.

⚠ Final Exam Tips

1. Memorize the big comparison table (Tab 3) — it's the most common exam question.

2. Know parity check for 8-puzzle — saves 50% wasted search.

3. IDS preferred for large/unknown depth spaces — appears wasteful but is efficient.

4. Bidirectional needs O(bd/2) space — its main weakness.

5. Graph search changes space complexity — DFS's advantage vanishes with closed list.

6. Sensorless problems use belief states — 2|S| possible belief states.
