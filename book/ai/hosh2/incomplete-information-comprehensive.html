Problems with Incomplete Information

Artificial Intelligence — Chapter 2: Problem Solving Using Search

Problem Types Based on Information Completeness

Search problems are classified by the agent's knowledge of the environment. When information is complete (fully observable + deterministic), we have a single-state problem. When information is incomplete, we get more complex problem types.

Single-State Problem (Fully Observable + Deterministic)

The agent knows exactly the current state. Every action has a known, predictable result. The agent simply finds a sequence of actions from start to goal.

Single-State Problem
Agent knows s = current state exactly
Result(s, a) is known and unique for each action

Three Problem Types with Incomplete Information

Problem Type Observability Determinism Solution
Single-State Full Deterministic Sequence of actions
Sensorless (Conformant) None Deterministic Sequence (works for all possibilities)
Contingency Partial Non-deterministic Conditional plan (tree)
Exploration Unknown Unknown Agent must discover environment

Example: Vacuum World

Single-State

Agent sees both squares. Knows dirt locations. Action: go to dirty square and Suck.

Solution: [Right, Suck]

Sensorless

Agent sees nothing. Could be in any of 8 states. Needs a plan that works everywhere.

Solution: [Right, Suck, Left, Suck]

Contingency

Agent sees current square only. Actions may fail (Murphy's Law).

Solution: if-then-else plan

⚠ Classification Rule

The problem type depends on what the agent knows and can observe, not on the environment itself. A partially observable environment with a sensorless agent is a sensorless problem. The same environment with a fully-sensing agent is single-state.

Sensorless (Conformant) Problems

In sensorless problems, the agent has no sensors — it cannot observe the environment. However, actions are deterministic. The agent must reason over belief states (sets of possible physical states).

Belief State
b = {s₁, s₂, ..., sk}
Set of all physical states the agent could be in
Number of Possible Belief States
|B| = 2|S|
Where |S| = number of physical states

Action on Belief States

When the agent performs an action on a belief state, the result is the union of applying the action to each possible physical state:

Result of Action in Belief State
Result(b, a) = { Result(s, a) | s ∈ b }
Apply action to every state in the belief set and take the union

Vacuum World Without Sensors

Physical states: 2 squares × each can be clean/dirty × agent in A or B = 2 × 2 × 2 = 8 states.

Belief states: 2⁸ = 256 possible belief states.

Initial belief state (no sensors): all 8 states.

Vacuum World State Count
n locations × 2n dirt patterns
For n locations: n × 2n physical states

Sample Sensorless Plan

In the vacuum world with no sensors, the plan [Right, Suck, Left, Suck] guarantees all squares are clean regardless of the initial state.

⚠ Belief State Explosion

Belief state space is exponential in the number of physical states (2|S|). For the vacuum world: 256 belief states is manageable. For a robot with 100 sensors each reading 10 values: 10100 belief states — completely intractable!

Contingency Problems

Contingency problems involve partial observability or non-deterministic actions. The agent receives observations after each action and uses them to refine its belief state.

Conditional Plans (Trees)

Unlike single-state problems where the solution is a simple sequence, contingency problems require conditional plans with branching based on observations:

if perception = dirty then Suck else if perception = clean then if location = A then Right else Left

Murphy's Law in the Vacuum World

In the standard vacuum world, Suck always cleans the current square. In Murphy's version: Suck cleans a dirty square but may deposit dirt if the square was already clean! Actions are non-deterministic.

Murphy's Suck Action
Suck: if dirty → clean; if clean → may become dirty!
Non-deterministic outcome — agent must handle both possibilities

Conditional Plan for Murphy's Vacuum: [Suck, Right, if Dirty then Suck]

Adversarial Problems

When uncertainty comes from another agent trying to defeat you, it's an adversarial problem. For example, chess — the opponent's moves are unpredictable. These require game-tree search (minimax).

Exploration Problems

In exploration problems, the agent doesn't know the states and actions of the environment. It must actively discover them. This is the most general and hardest type:

  • Agent doesn't know what actions are available
  • Agent doesn't know the effects of actions
  • Agent may not know the goal condition
  • A special case of contingency problems
Property Sensorless Contingency Exploration
Sensors None Partial Unknown
Actions Deterministic Non-deterministic Unknown
Solution type Fixed sequence Conditional plan Learned through interaction
Difficulty Medium Hard Very Hard
⚠ Key Distinction

In sensorless problems, the solution is still a fixed sequence of actions (no branching needed) — the same action sequence must work for all possible states. In contingency problems, the solution branches based on observations because different situations require different responses.

Worked Examples

Example 1: Belief State Computation in Vacuum World

Setup: 2-location vacuum world, 8 physical states. Labeled as (location, A-dirt, B-dirt).

Possible states: (A, D, D), (A, D, C), (A, C, D), (A, C, C), (B, D, D), (B, D, C), (B, C, D), (B, C, C)

Initial belief state (no sensors): b₀ = {all 8 states}

Action: Right

Apply Right to each state in b₀:

Right(A, D, D) = (B, D, D), Right(A, D, C) = (B, D, C), Right(A, C, D) = (B, C, D), Right(A, C, C) = (B, C, C)

Right(B, ...) — already at B, stays same: (B, D, D), (B, D, C), (B, C, D), (B, C, C)

Result belief state: b₁ = {(B, D, D), (B, D, C), (B, C, D), (B, C, C)} — 4 states

Action: Suck on b₁:

Suck(B, D, D) = (B, C, D), Suck(B, D, C) = (B, C, C), Suck(B, C, D) = (B, C, D), Suck(B, C, C) = (B, C, C)

Result belief state: b₂ = {(B, C, D), (B, C, C)} — 2 states

After Left, Suck, the belief state becomes {(A, C, C), (A, C, C)} = {(A, C, C)} — goal state!

Example 2: Sensorless Plan Verification

Plan: [Right, Suck, Left, Suck] — verify it works for all 8 initial states.

(A, D, D)(B, D, D)(B, C, D)(A, C, D)(A, C, C) ✓
(A, D, C)(B, D, C)(B, C, C)(A, C, C)(A, C, C) ✓
(A, C, D)(B, C, D)(B, C, D)(A, C, D)(A, C, C) ✓
(A, C, C)(B, C, C)(B, C, C)(A, C, C)(A, C, C) ✓
(B, D, D)(B, D, D)(B, C, D)(A, C, D)(A, C, C) ✓
(B, D, C)(B, D, C)(B, C, C)(A, C, C)(A, C, C) ✓
(B, C, D)(B, C, D)(B, C, D)(A, C, D)(A, C, C) ✓
(B, C, C)(B, C, C)(B, C, C)(A, C, C)(A, C, C) ✓

Result: All 8 initial states end in (A, C, C) — both squares clean. Plan verified!

Example 3: Conditional Plan for Murphy's Vacuum

Setup: Agent starts at A, sees only current square. Murphy's Suck: may deposit dirt if clean. Goal: both squares clean.

Plan:

1. Suck (clean A if dirty; may dirty A if clean) 2. Right 3. if B is dirty then Suck 4. Left 5. if A is dirty then Suck 6. if A is dirty then Suck (repeat until clean)

Trace for each possible scenario:

Scenario 1: A dirty, B dirty. Step 1: clean A. Step 3: clean B. Step 5: A clean. Done after 3 actions.

Scenario 2: A clean, B dirty. Step 1: may stay clean or get dirty (Murphy!). If clean: step 3 cleans B, step 5 checks A. If Murphy dirtied A: step 5 cleans A.

Scenario 3: A clean, B clean. Step 1: may stay clean or get dirty. Continue checking... The plan handles all cases through conditional branching.

Example 4: Belief State Size Calculation

Problem: A robot in a 5-room building. Each room may have a person present or not. The robot knows its own location (current room) but not where people are.

Physical states: Robot in 5 rooms × 2⁵ person locations = 5 × 32 = 160 states.

Belief states (no sensors for people): 2¹⁶⁰ = a number with 48 digits!

With room-occupancy sensor: Agent sees current room's occupancy. Each observation eliminates some states. Still, the belief state space is extraordinarily large.

Moral: Real-world belief state spaces are typically too large for exhaustive search. Practical agents use approximations and heuristics.

⚠ Exam Tip

When asked to classify a problem: (1) Is it fully observable? (2) Is it deterministic? (3) If both → single-state. If no sensors → sensorless. If partially observable or non-deterministic → contingency. If environment unknown → exploration.
