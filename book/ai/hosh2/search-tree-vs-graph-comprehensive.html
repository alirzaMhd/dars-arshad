Search Tree vs Search Graph

AI Search - Complete Guide for 20/20 Exam

Search Node Structure

A node in a search tree is a data structure containing five fields that track the path taken to reach that state.

STATE

Corresponds to a state in the problem's state space. This is the configuration the node represents.

PARENT-NODE

The node in the search tree that generated this node. Used for backtracking the solution path.

ACTION

The action applied to the parent node's state that produced this node's state.

PATH-COST

The total cost of the path from the initial state to this node.

DEPTH

Number of actions in the path from the initial state to this node.

Critical Distinction: A node is a bookkeeping structure for the search algorithm. A state is a position in the problem's world. Multiple nodes can represent the same state if that state was reached through different paths.

Tree Search vs Graph Search

When multiple paths can reach the same state, the search structure is a graph rather than a tree. Handling repeated states correctly determines whether the algorithm explores a tree or a graph.

Data Structure Tree Graph
Repeated States Not detected Detected via closed list
Memory Usage Lower Higher
Completeness Risk Infinite loops possible Safer with cycle detection

Example - Romania

The state space has 20 states (one per city). The search tree has infinitely many nodes because paths like Arad → Sibiu → Arad → Sibiu can loop forever. The search graph has 20 nodes with edges representing direct routes.

The Fringe

The fringe is the set of all leaf nodes that have been generated but not yet expanded. The search strategy determines which node from the fringe gets expanded next.

Queue Operations:
Make-Queue(elements) → new queue containing elements
Empty?(queue) → true if no elements
First(queue) → front element without removal
Remove-First(queue) → remove and return front element
Insert(element, queue) → add element according to queue ordering
Insert-All(elements, queue) → add all elements at once
Example - FIFO for BFS

If fringe = [A, B, C] (FIFO), then Remove-First returns A, leaving [B, C]. New successors are appended at the end.

Example - LIFO for DFS

If fringe = [A, B, C] (LIFO/stack), then Remove-First returns C, leaving [A, B]. New successors are pushed to the front.

Worked Examples

Example 1 - Tracking Path

Start at Arad. Expand Arad, generating children Sibiu, Timisoara, Zerind. Each child stores Arad as PARENT-NODE and the action that led to it.

To reconstruct solution when goal is found, follow PARENT-NODE pointers back to root.

Example 2 - Same State, Different Paths

Path 1: Arad → Sibiu → Oradea. Path 2: Arad → Zerind → Oradea. Both end in state In(Oradea) but are different nodes because their PARENT-NODE and PATH-COST differ.

Example 3 - Fringe Evolution in BFS

Initially: fringe = [Arad]. Expand Arad: fringe = [Sibiu, Timisoara, Zerind]. Expand Sibiu: fringe = [Timisoara, Zerind, Oradea, Fagaras, Rimnicu].

Example 4 - Fringe Evolution in DFS

Initially: fringe = [Arad]. Expand Arad: fringe = [Sibiu, Timisoara, Zerind] (newest first). Expand Sibiu: fringe = [Oradea, Fagaras, Rimnicu, Timisoara, Zerind].
