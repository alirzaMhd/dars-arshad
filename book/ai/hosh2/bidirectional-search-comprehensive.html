Bidirectional Search

Artificial Intelligence — Chapter 2: Problem Solving Using Search

Bidirectional Search Concept

Bidirectional search runs two simultaneous searches: one forward from the start state and one backward from the goal state. The search stops when the two frontiers meet in the middle.

Key Insight
bd/2 + bd/2 < bd (for d > 2)
Two half-depth searches explore far fewer nodes than one full-depth search

How It Works

Forward Search

Start from the initial state. Use successor function (actions) to expand toward the goal.

Backward Search

Start from the goal state. Use predecessor function (reverse actions) to expand toward the start.

Meet Condition

Before expanding a node, check if it exists in the other search's frontier. If yes, we have found a solution.

Visual Representation

Start →→→→→ [Meet Point] ←←←←← Goal

The forward search explores bd/2 nodes from start, the backward search explores bd/2 nodes from goal. Together they cover depth d but each only goes halfway.

⚠ Visualizing the Savings

Imagine a full circle radius d. BFS explores the entire circle (area ∝ d²). Bidirectional explores two circles radius d/2 each (total area ∝ 2(d/2)² = d²/2) — half the area!

Time Complexity

Time Complexity
O(bd/2)
Each search reaches depth d/2, so time grows as bd/2
Space Complexity
O(bd/2)
At least one frontier must be stored to check for intersections

⚠ Memory Wall

Bidirectional search's main weakness is its O(bd/2) space requirement. While much smaller than BFS's O(bd), it's still exponential. For very deep searches, even bd/2 may exceed available memory.

Implementation Challenges

1. The Predecessor Function

Backward search requires a predecessor function that computes what states can lead to a given state. This is not always easy to define:

  • Easy: Romania pathfinding (reverse actions are the same edges), 8-puzzle (reverse moves)
  • Hard: Chess (what moves could have led to this position?)
  • Implicit goals: "Checkmate" — no single state to go backward from

2. Multiple Goal States

When there are multiple possible goal states, we can create a dummy super-goal state with zero-cost actions from each actual goal. The backward search starts from this super-goal.

Handling Multiple Goals
G' = {g₁, g₂, ..., gk}  →  Super-goal S with predecessor(s) = G'
Create a dummy super-goal that connects to all actual goals

3. Intersection Detection

Before expanding a node, check if it exists in the other search's frontier. This requires efficient membership testing.

Hash Table for O(1) Frontier Check
if node.state in frontier_backward: return SOLUTION(node)
Use a hash table to store visited states of at least one frontier

4. When Both Searches Use BFS

If both forward and backward searches use BFS:

  • The algorithm is complete (if b is finite)
  • The algorithm is optimal (if step costs are uniform)
  • First meeting point gives the shortest path

Easy Cases

• Single known goal state

• Actions are reversible

• 8-puzzle, route finding

Hard Cases

• Implicit goal description

• Irreversible actions

• Chess checkmate, theorem proving

⚠ Common Implementation Pitfall

The check for intersection must happen before expansion — check if the current node is in the other frontier, not after expanding. Otherwise you may miss the meeting point!

Worked Examples

Example 1: Trace Bidirectional Search on a Graph

Graph: Nodes A through J. Start = A, Goal = J. Each node connects to 2-3 neighbors. Depth from A to J = 6.

Forward search (from A):

Level 0: {A}
Level 1: {B, C, D} (neighbors of A)
Level 2: {E, F, G} (neighbors of B, C, D excluding A)
Level 3: {H, I}

Backward search (from J):

Level 0: {J}
Level 1: {I, K, L} (predecessors of J)
Level 2: {H, M} (predecessors of I, K, L excluding J)

Meet: At level 3 forward = {H, I} and level 2 backward = {H, M}. Node H is in both! Path: A → ... → H → ... → J, total depth 5 (3 forward + 2 backward).

Result: Each search explored ~3 layers instead of 6. Nodes visited: forward 10 + backward 8 = 18, vs BFS would visit ~50+ nodes.

Example 2: Node Savings Calculation

Given: b = 6, d = 8. Calculate nodes visited by BFS vs Bidirectional.

BFS nodes (worst case, complete tree):

N(BFS) = 1 + 6 + 36 + 216 + 1,296 + 7,776 + 46,656 + 279,936 + 1,679,616

= 2,015,539 nodes

Bidirectional nodes (each to d/2 = 4):

N(Bidirectional) = 2 × (1 + 6 + 36 + 216 + 1,296)

= 2 × 1,555 = 3,110 nodes

Savings factor: 2,015,539 / 3,110 = 648x fewer nodes!

Bidirectional search explores less than 1% of BFS nodes.

Example 3: Multiple Goal States

Problem: Robot navigation in a warehouse. Start at loading dock. Goal is any of 4 exits (E1, E2, E3, E4) at different locations. Pathfinding on a grid of 20 × 20 cells.

Solution with Bidirectional:

  • Create a super-goal node S with edges to E1, E2, E3, E4 (each with cost 0)
  • Forward search from start uses standard grid successor function
  • Backward search from S uses predecessor function on grid
  • When forward search reaches any cell adjacent to any exit, the super-goal check triggers

Result: Without super-goal, we'd need 4 separate backward searches. With super-goal, one backward search covers all exits.

Nodes searched: Grid has 400 cells. Forward from start explores ~100 cells (half grid), backward from exits explores ~100 cells. 200 total vs 400 for BFS.

⚠ Exam Tip

When comparing BFS and Bidirectional on an exam, always show the formula bd/2 + bd/2 vs bd and compute specific numeric values. The savings factor grows exponentially with d!
