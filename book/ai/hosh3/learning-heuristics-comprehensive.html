Learning Heuristic Functions

Rather than hand-crafting heuristics, an agent can learn a heuristic function by solving many problems and extracting patterns from the solutions.

The Learning Loop

Experience-Based Heuristic Learning
Solve → Extract features → Record true cost → Learn coefficients
  1. Solve: Run an optimal search on many training problems
  2. Record: For each state n encountered, store its actual remaining cost to goal
  3. Extract features: Identify measurable properties of states that correlate with cost
  4. Learn: Use regression or other inductive learning to approximate h(n) from features

Linear Combination Model

The most common learned heuristic form is a linear combination of features:

Linear Heuristic Function
h(n) = c1 · x1(n) + c2 · x2(n) + ... + ck · xk(n)
xi = feature values, ci = learned coefficients

The coefficients are learned from training data via regression (e.g., linear regression, ridge regression). The goal is to minimize the error between predicted h(n) and actual remaining cost.

Features
Must be computable from state alone. Should correlate with remaining cost.
Training Data
Each optimal solution produces many (state, actual_cost) pairs.
Generalization
Goal: predict costs for unseen states accurately.
Non-Linear
Neural networks, decision trees, etc. can also be used.
Example 1: Simple 8-Puzzle Features

Two features for the 8-puzzle:

  • x1(n): number of misplaced tiles
  • x2(n): number of adjacent tile pairs that are also adjacent in the goal state

Model: h(n) = c1 · x1 + c2 · x2. After training on solved instances, we might get c1 = 3, c2 = −1 (since having adjacent pairs reduces remaining cost).

Example 2: Training Data Generation

Solve 100 random 8-puzzles optimally. For each state encountered during search, record (x1, x2, actual_cost). With 500 states per solution, we get 50,000 training examples. Use 80% for training and 20% for validation.

Example 4: Scaling to Larger Problems

For the 24-puzzle, hand-crafted heuristics like Manhattan become very weak. Learned heuristics using more sophisticated features (e.g., pattern database values as features) can achieve much lower EBF. By training on 1,000 solved 24-puzzle instances, a neural network heuristic achieved b* ≈ 1.15, compared to 1.50 for Manhattan distance.

Feature Engineering for Heuristic Learning

The quality of a learned heuristic depends heavily on the choice of features. Good features capture aspects of the state that correlate with the remaining solution cost.

Common Feature Types

Feature TypeExampleDomain
Distance-basedManhattan distance, Euclidean distanceAny puzzle/grid
Count-basedMisplaced tiles, inversionsPuzzles
TopologicalAdjacency of correct pairs8-puzzle, 15-puzzle
Subproblem-basedPattern database valuesSliding puzzles
Domain-specificNumber of wrong row/column tiles15-puzzle
StatisticalVariance of tile distancesGeneral

Example Features for 8-Puzzle

  • x1(n): Misplaced tiles count (0-8)
  • x2(n): Sum of Manhattan distances
  • x3(n): Number of tiles in correct row but wrong column
  • x4(n): Number of tiles in correct column but wrong row
  • x5(n): Number of adjacent tile pairs that are also adjacent in goal (negative correlation)
  • x6(n): Manhattan distance of the blank from its goal

The Learning Pipeline

Regression Objective
minimize Σi ( hactual(ni) − hpredicted(ni) )2
Standard least-squares regression over the training set
Overfitting Warning: Using too many features or too few training examples can cause overfitting. The learned heuristic performs well on training states but poorly on unseen states. Always test on a held-out validation set.
Example 1: Linear Regression for 8-Puzzle

Features: x1 = Manhattan distance, x2 = misplaced tiles.

After solving 200 problems (100,000 state-cost pairs):

h(n) = 1.12 · x1(n) + 0.34 · x2(n)

The coefficient for Manhattan is near 1 (it is already a good estimator). The misplaced tiles coefficient is small (it adds marginal information beyond Manhattan).

Example 2: Feature Selection

Starting with 10 candidate features, use forward selection:

  1. Train with each single feature. Best: xmanhattan (R² = 0.82)
  2. Add each remaining feature. Best addition: xadjacent_pairs (R² = 0.87)
  3. Continue until R² improvement < 0.01. Final model: 4 features selected out of 10.

This yields a compact, generalizable heuristic.

Example 3: Using Pattern DB as a Feature

A powerful feature for learning: the pattern database value itself.

Feature vector: x1 = hDB1, x2 = hDB2, x3 = Manhattan.

Learned: h(n) = 0.95 · hDB1 + 0.92 · hDB2 + 0.10 · Manhattan.

The learned weights are close to 1 for the pattern DB values, meaning the DB is already near-optimal. The small Manhattan term adds a slight correction.

Example 4: Non-Linear Feature Interactions

Sometimes feature interactions matter. Example: xproduct = Manhattan × misplaced_tiles.

Training a model with interaction terms:

h(n) = 0.9 · xman + 0.3 · xmis + 0.05 · xman · xmis

The interaction term captures the effect that when both features are high, the state is especially far from goal.

Example 1: From Data to Coefficients

Using linear regression: the model h = c1 · x1 + c2 · x2 is fitted.

For 100 samples: h(n) = 2.8 · x1 − 0.5 · x2

Interpretation: each misplaced tile adds ~2.8 to estimated cost. Each correct adjacent pair reduces it by ~0.5 (because adjacent tiles in correct relative order are easier to solve).

Example 3: Learning for Route Planning

For road network navigation, features for a learned heuristic:

  • x1: Straight-line (Euclidean) distance to destination
  • x2: Estimated traffic time (from historical data)
  • x3: Number of traffic lights on the straight-line path
  • x4: Road type index (highway vs local)

Learned: h(n) = 0.7 · x1 + 1.2 · x2 + 0.1 · x3 + 0.3 · x4

The traffic component has the highest weight — it correlates most with travel time.

Example 4: Overfitting Detection

Training on 500 states: training error (RMSE) = 0.5. Validation error (RMSE) = 2.8. This large gap indicates overfitting.

Solutions:

  • Reduce number of features (e.g., from 20 to 5)
  • Add regularization (L1 or L2)
  • Increase training data size

After regularization (L2, λ = 0.1): training RMSE = 1.2, validation RMSE = 1.5. Much better generalization.

Check: Always monitor the gap between training and validation error. A large gap means your learned heuristic will perform poorly on new problems.
