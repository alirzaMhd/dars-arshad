Best-First Search

Artificial Intelligence — Informed Search

Definition of Best-First Search

Best-first search is an informed search algorithm that selects which node to expand based on an evaluation function f(n). It is an instance of the TREE-SEARCH and GRAPH-SEARCH algorithms where nodes are selected for expansion based on f(n) — the node with the lowest f(n) value is expanded first.

Evaluation Function
f(n)
The evaluation function that determines which node is expanded next. The node with the smallest f(n) value is selected first.
⚠ Misleading Name: The name "best-first" is misleading. If we truly expanded the best node first, there would be no need to search — we would already have found the direct path to the goal. In reality, we select the node that appears to be best based on the evaluation function.

Priority Queue Implementation

The fringe (frontier) is implemented as a priority queue where nodes are sorted by their f(n) values in ascending order. The node with the smallest f(n) is always at the front and is dequeued for expansion next.

Algorithm Structure

function BEST-FIRST-SEARCH(problem) returns a solution node ← MAKE-NODE(INITIAL-STATE[problem]) frontier ← priority queue ordered by f(n) (ascending) explored ← empty set add node to frontier loop do if frontier is empty then return failure node ← POP(frontier) // node with lowest f(n) if GOAL-TEST(node) then return SOLUTION(node) add node to explored for each successor in SUCCESSORS(node) do if successor not in explored and not in frontier then add successor to frontier

Special Cases of Best-First Search

Different choices of the evaluation function f(n) yield different well-known search algorithms:

Algorithm Evaluation Function f(n) Description
Breadth-First Search f(n) = depth(n) Expands nodes level by level; shallowest node first
Uniform-Cost Search f(n) = g(n) Expands node with lowest path cost from start
Greedy Best-First Search f(n) = h(n) Expands node closest to goal (by heuristic)
A* Search f(n) = g(n) + h(n) Combines cost-so-far and estimated cost-to-go

Key Insights

BFS is a special case where f(n) = depth(n)

UCS is a special case where f(n) = g(n)

Greedy is a special case where f(n) = h(n)

A* is a special case where f(n) = g(n) + h(n)

When to Use Each Variant

Situation Recommended Algorithm Reason
All actions have equal cost; need shortest path BFS Finds shallowest solution optimally
Actions have varying costs; need optimal solution UCS or A* UCS works without heuristic; A* is faster with good heuristic
Need a quick solution; optimality not required Greedy Best-First Fast but not optimal or complete
Need optimal solution; good heuristic available A* Complete, optimal, and efficient with good heuristic
Memory is severely constrained IDA* or RBFS Memory-bounded variants of A*

Summary

General Form
Best-First Search: expand node n with smallest f(n)
The choice of f(n) determines the specific algorithm. All best-first search variants use a priority queue for the frontier.
⚠ Important: The effectiveness of best-first search depends critically on the quality of the evaluation function. A poor f(n) can lead to exponential time and space complexity, making the search no better than uninformed methods.
