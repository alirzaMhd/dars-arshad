Greedy Best-First Search Algorithm

Greedy best-first search is a form of best-first search that expands the node that appears to be closest to the goal. It evaluates nodes using only the heuristic function:

Evaluation Function
f(n) = h(n)
The node with the smallest h(n) is expanded first. It ignores the cost already incurred (g(n)) and focuses purely on estimated remaining distance to goal.

Pseudocode

function GREEDY-BEST-FIRST-SEARCH(problem) returns a solution node ← MAKE-NODE(INITIAL-STATE[problem]) frontier ← priority queue ordered by h(n) (ascending) explored ← empty set add node to frontier loop do if frontier is empty then return failure node ← POP(frontier) // node with lowest h(n) if GOAL-TEST(node) then return SOLUTION(node) add node to explored for each successor in SUCCESSORS(node) do if successor not in explored and not in frontier then add successor to frontier

How It Works

At each step, greedy best-first search selects the node that the heuristic says is closest to the goal. It acts "greedily" by making the locally optimal choice, hoping it leads to the globally optimal solution.

⚠ Greedy is NOT Optimal: Because it only considers the estimated distance to the goal and ignores the cost incurred so far, greedy search can easily be led astray. It may take a path that seems promising initially but turns out to be much more expensive overall.

Romania Pathfinding Example

Goal: Bucharest. Start: Arad. Heuristic: hSLD = straight-line distance to Bucharest.

The Dead-End Problem

Consider the case where the start is Iasi and the goal is Fagaras. The heuristic suggests expanding Neamt first because it appears closer to Fagaras. But Neamt is a dead end!

📌 Dead-End Scenario: Iasi → Neamt → Fagaras
StepCityhSLD to FagarasAction
1Iasi226Initial
2Neamt234 (but Vaslui is only reachable neighbor)Greedy picks Neamt — but it's a dead end!
3Neamt234No successors except Iasi (already explored). Backtrack needed.
4Vaslui199Must backtrack to Iasi and expand Vaslui instead

If repeated states are not tracked, the search may oscillate between Iasi and Neamt forever — making greedy search incomplete.

Completeness and Optimality Analysis

Property Status Explanation
Complete (finite spaces) Yes (with graph-search) If the state space is finite and repeated states are tracked, greedy search will eventually explore all reachable states.
Complete (infinite spaces) No Can get stuck in infinite paths, especially if the heuristic misleads into a deep dead-end branch.
Optimal No Ignores g(n) — only considers h(n). Can find paths that are much longer than the optimal.
Time Complexity O(bm) Worst case is exponential. With a good heuristic, can be greatly reduced to O(bm).
Space Complexity O(bm) Keeps all generated nodes in memory (frontier + explored).

m = maximum depth of state space (could be infinite). b = branching factor.

Example 1: Shortest-Path in a Graph with a Detour

📌 Greedy Picks Wrong Path Due to Local Optimum

Graph: S (h=10) → A (h=8) → B (h=5) → G (h=0) with costs: S-A=10, A-B=10, B-G=10. Alternative: S → C (h=4) → D (h=2) → G (h=0) with costs: S-C=1, C-D=1, D-G=20.

Greedy picks S→C (h=4 is best). Path cost: 1+1+20 = 22. Optimal: S→A→B→G, cost: 10+10+10 = 20.

Greedy cost = 22, Optimal cost = 20. Greedy fails due to deceptive heuristic.

Example 2: Maze Solving

📌 Maze with Manhattan Heuristic

In a grid maze with obstacles, greedy search using Manhattan distance may charge into a corridor that heads toward the goal but dead-ends behind an obstacle, forcing massive backtracking.

Example: 5×5 maze, S at (1,1), G at (5,5). A wall in row 3 blocks direct access. Greedy expands toward (3,3) directly, hits wall, must backtrack to (1,2) to go around.

Greedy expands 14 nodes including backtracking. A* with same heuristic expands only 8 nodes by considering path cost.
