Relaxed Problems for Deriving Heuristics

Artificial Intelligence — Informed Search

What is a Relaxed Problem?

A relaxed problem is a version of the original problem with fewer constraints on the actions. By removing constraints, we make the problem easier to solve optimally. The cost of the optimal solution to the relaxed problem is always a lower bound on the cost of the optimal solution to the original problem.

Key Property
Costrelaxed(n) ≤ Costoriginal(n)
The relaxed problem's optimal cost is an admissible heuristic for the original.

If the relaxed problem satisfies the triangle inequality, the resulting heuristic is also consistent (monotonic).

Formal Approach

If the problem is formalized in a formal language (e.g., STRIPS), relaxed problems can be derived automatically by dropping preconditions from action definitions. This is a powerful technique for generating heuristics without manual design.

Admissibility
Relaxed problem cost ≤ original cost → admissible heuristic
Consistency
Triangle inequality in relaxed problem → consistent heuristic
Automation
Formal problem descriptions allow automatic relaxation
Trade-off
More relaxation = cheaper to compute but weaker bound
Example 1: 8-Puzzle Action Definition

An action in the 8-puzzle: "Tile A can move to square B if A is adjacent to B AND B is empty."

Two preconditions: adjacency and emptiness. Removing either (or both) yields relaxed versions of the puzzle.

Example 2: General Framework

Consider a planning problem where an action requires 3 preconditions (P1, P2, P3). Relaxed problems could ignore P1, or P2, or P1 & P2 together. Each relaxation yields a heuristic. The best choice depends on the trade-off between heuristic accuracy and computation time.

Example 3: Real-World Analogy

Navigation: "You can drive from A to B if roads exist AND traffic is light AND no road closures." Relaxing to just "roads exist" gives the straight-line heuristic (Manhattan or Euclidean distance). Relaxing further to "no constraints" gives h=0 (trivial, useless).

Example 4: Automatic Relaxation in STRIPS

In STRIPS planning, an action is defined by: Preconditions, Add effects, Delete effects. Relaxation example: ignore delete lists (drop the delete effects). The resulting relaxed problem is solvable in polynomial time, and its solution cost is an admissible heuristic for the original planning problem (the "hadd" or "hmax" family).

Key Insight: The art of heuristic design via relaxation is choosing which constraints to remove. Remove too few → relaxed problem is still hard to solve. Remove too many → heuristic becomes weak.

Three Relaxations of the 8-Puzzle

The 8-puzzle action precondition is: "Tile A can move to square B if A is adjacent to B AND B is empty." By removing one or both conditions, we get three relaxed problems:

Relaxation (a): Remove "B is empty"

Rule: Tile A can move to B if A is adjacent to B (emptiness no longer required).

Resulting heuristic: Manhattan Distance (h2).

Each tile can move freely among adjacent squares regardless of other tiles' positions. The optimal cost to move a tile to its goal is its Manhattan distance. Since tiles don't interfere, the sum of individual distances is the total optimal cost.

Relaxation (b): Remove "A is adjacent to B"

Rule: Tile A can move to B if B is empty (adjacency no longer required).

Resulting heuristic: Gaschnig Heuristic.

Any tile can teleport to any empty square. This is equivalent to counting how many moves are needed to get the blank to each tile's goal. Gaschnig's heuristic is computed by simulating a modified puzzle where the blank can swap with any tile.

Relaxation (c): Remove Both Conditions

Rule: Tile A can move to B any time (no adjacency or emptiness required).

Resulting heuristic: Misplaced Tiles (h1).

Each tile can instantly teleport to its goal position. The cost is simply the count of tiles not already in their goal positions. This is the weakest of the three.

Gaschnig Heuristic Explained

The Gaschnig heuristic counts the minimum moves when only the blank moves and any tile can swap into it. It is computed by:

  • If the blank is not in its goal position, swap it with a tile that belongs in the blank's current position (greedy choice).
  • If the blank is in its goal position, swap it with any misplaced tile.
  • Count the swaps until all tiles are correct.

Gaschnig's heuristic is often better than both h1 and h2 for certain configurations, such as the two-tile swap case.

Trade-off: Computing Gaschnig's heuristic requires simulating the relaxed puzzle state, which is more expensive per node than simple h1 or h2. The improved accuracy must justify the extra computation time.

Example 4: Relaxation Trade-off in Practice

Consider a state where h1 = 4, h2 = 8, Gaschnig = 9, actual cost = 11.

Gaschnig provides the tightest bound (82% of true cost), but takes more time per node. The best choice depends on whether the search tree is deep enough that the extra pruning justifies the per-node cost.

Rule of thumb: For problems with deep search spaces and expensive node expansions, invest more computation per node for a better heuristic. For shallow problems, use simpler heuristics.
