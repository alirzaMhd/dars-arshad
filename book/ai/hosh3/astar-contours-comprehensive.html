Contours in A* Search

Artificial Intelligence — Informed Search

Contour Concept in A*

Evaluation Function
f(n) = g(n) + h(n)
With a consistent heuristic h(n), f(n) is non-decreasing along any path
Contour Definition
Contour(c) = { n | f(n) ≤ c }
The closed region containing all nodes with f-cost at most c

Key Properties

Non-Decreasing f
If h is consistent, f never decreases along any path from the start
Concentric Contours
Contours form nested bands around the start state. Each band has a higher f-cost
Optimal Cutoff
A* expands all nodes with f(n) < C*. May expand some with f(n) = C* before finding the goal
Never Wasteful
A* never expands nodes with f(n) > C*. Such nodes lie outside the C* contour
Optimally Efficient
No other optimal algorithm guarantees expanding strictly fewer nodes than A*
Complete
A* will eventually reach contour f = C* and find the goal (if a solution exists)

Warning: The number of nodes inside a contour can grow exponentially with the contour's radius. A* is optimal in nodes expanded, but the contour itself may still contain a huge number of nodes for large problems.

Optimal Efficiency Proof

Claim: A* is optimally efficient — no other optimal search algorithm using the same heuristic can guarantee expanding fewer nodes than A*.

Proof Sketch
Any optimal algorithm must expand every node with f(n) < C*, because such a node might be on an optimal path. A* expands exactly those nodes (plus possibly some with f(n)=C*). Therefore no optimal algorithm can guarantee expanding strictly fewer nodes.
Key Insight
If some node n has f(n) < C* and is not expanded, then in some problem instance the optimal path could go through n. Since the algorithm didn't expand n, it would miss the optimal solution — violating optimality.

Why Timisoara Is Not Expanded

Node: Timisoara
g(Timisoara) = 118
h(Timisoara) = 329 (straight-line distance to Bucuresti)
f(Timisoara) = 118 + 329 = 447
Optimal path cost C* = 418 (via Sibiu→Rimnicu→Pitesti→Bucuresti)
f(Timisoara) = 447 > C* = 418 → Timisoara is outside the C* contour and never expanded

Warning: Contour sizes grow exponentially with the search depth for problems with high branching factor. Even though A* is optimally efficient, the number of nodes with f(n) < C* may still be astronomically large for hard problems. This is why memory-bounded variants (IDA*, RBFS, SMA*) are necessary.
