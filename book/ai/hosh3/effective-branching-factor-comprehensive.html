Effective Branching Factor (EBF)

Artificial Intelligence — Informed Search

What is Effective Branching Factor?

The Effective Branching Factor (EBF), denoted b*, is a measure of the quality of a heuristic function. It describes how many branches a search tree effectively explores per level, on average.

Definition

If A* expands N nodes to find a solution at depth d, then b* is the branching factor that a uniform tree of depth d would need to have to contain exactly N + 1 nodes:

Effective Branching Factor Equation
N + 1 = 1 + b* + (b*)² + ... + (b*)d
N = total nodes expanded, d = solution depth, b* = effective branching factor

This is a geometric series. Using the closed-form formula:

Closed Form
N + 1 = ( (b*)d+1 − 1 ) / (b* − 1)
Must be solved numerically for b* (e.g., by binary search or Newton's method)

A well-designed heuristic keeps b* as close to 1 as possible. For hard problems, b* tends to be nearly constant across instances, making it a reliable quality metric.

Important: EBF varies across individual problem instances but for hard problems it is typically constant. Comparing b* values across different search algorithms reveals which heuristic is more informed.
Example 1: Computing b* Given N and d

Suppose A* expands N = 52 nodes to find a solution at depth d = 5.

53 = 1 + b* + (b*)² + (b*)³ + (b*)4 + (b*)5

Solving: try b* = 1.9 → (1.96-1)/0.9 = 55.4. try b* = 1.92 → (1.926-1)/0.92 = 57.2. The closest to 53 gives b* ≈ 1.92.

Example 2: Interpreting b*

For IDS on the 8-puzzle, b* ≈ 2.8 (near the true branching factor of ~3). This means IDS explores almost all children at each node — it has no guidance.

For A* with Manhattan distance, b* drops to ~1.3 at depth 10, meaning the search is highly focused, exploring only slightly more than 1 child per node on average.

Example 3: Comparing Two Heuristics

At depth 8: h1 gives b* = 1.33, h2 gives b* = 1.24. Since 1.24 < 1.33, h2 is more informed. The lower b* directly translates to fewer nodes expanded: for a depth-8 search, the total nodes expanded by h2 is significantly less than h1.

Note: EBF is a post-hoc measure. You cannot know b* before running the search. It is useful for comparing heuristics after experiments on benchmark problems.

Key Observations

  • IDS: b* stays near 2.7–2.9 at all depths, close to the raw branching factor of ~3. IDS cannot guide search, so it explores nearly every branch.
  • A* with h1 (misplaced tiles): b* starts at 1.79 at depth 2, drops to ~1.33 at depth 8, then rises to ~1.48 at depth 24. The initial dip reflects how h1 helps for easy problems, but for deeper problems the heuristic becomes less effective.
  • A* with h2 (Manhattan): b* stabilizes around 1.22–1.27 for depths 8+. Manhattan distance provides consistently high-quality guidance.

Example 1: Node Count Projection

At d = 10: IDS b* = 2.79 expands about (2.7911-1)/(2.79-1) ≈ 93,000 nodes. A* with h2 b* = 1.22 expands only (1.2211-1)/(1.22-1) ≈ 38 nodes. Improvement factor ≈ 2,400.

Example 2: Comparing h1 vs h2 Node Growth

At d = 24: h1 b* = 1.48 → N ≈ (1.4825-1)/(0.48) ≈ 210,000 nodes. h2 b* = 1.26 → N ≈ (1.2625-1)/(0.26) ≈ 470 nodes. h2 expands about 450 times fewer nodes.

Example 3: What If b* = 1.0?

A perfect heuristic would give b* = 1.0. Then N + 1 = d + 1, so N = d. A* would expand exactly d nodes — the optimal path with no branching. Real heuristics approach but never reach this ideal.

Caution: The table values are averages. Individual instances may deviate. EBF is most informative when averaged over many random instances at the same depth.

Detailed EBF Calculation Examples

Example 1: Finding b* by Binary Search

Given: N = 100 nodes expanded, solution depth d = 6.

101 = 1 + b* + (b*)² + (b*)³ + (b*)4 + (b*)5 + (b*)6

Binary search iterations:

  • b* = 2.0: (27-1)/(2-1) = 127. Too high.
  • b* = 1.7: (1.77-1)/(1.7-1) = (41.1-1)/0.7 = 57.3. Too low.
  • b* = 1.85: (1.857-1)/(1.85-1) = (59.6-1)/0.85 = 69.0. Still low.
  • b* = 1.93: (1.937-1)/(1.93-1) = (82.3-1)/0.93 = 87.4. Getting close.
  • b* = 2.0 gave 127, so b* = 1.97: (1.977-1)/(1.97-1) = (95.4-1)/0.97 = 97.4. Close.
  • b* = 1.99: (1.997-1)/(1.99-1) = (100.7-1)/0.99 = 100.7. Very close.

b* ≈ 1.99. This is a relatively poor heuristic (almost 2 branches per node).

Example 2: High-Quality Heuristic

Given: N = 30 nodes expanded, solution depth d = 20.

31 = 1 + b* + (b*)² + ... + (b*)20

This is a tiny N for such a large depth, so b* must be very close to 1.

  • b* = 1.1: (1.121-1)/(1.1-1) = (7.4-1)/0.1 = 64. Too high.
  • b* = 1.05: (1.0521-1)/(1.05-1) = (2.79-1)/0.05 = 35.8. Slightly high.
  • b* = 1.04: (1.0421-1)/(1.04-1) = (2.28-1)/0.04 = 32.0. Close.
  • b* = 1.03: (1.0321-1)/(1.03-1) = (1.86-1)/0.03 = 28.7. Slightly low.

b* ≈ 1.035. Excellent heuristic! Almost perfect guidance.

Example 3: Poor Heuristic (Almost IDS-Level)

Given: N = 1,000,000 nodes expanded, solution depth d = 12.

For a depth-12 problem, 1M nodes is huge. Let us compare: the geometric sum for b* = 2.8 (IDS-level) at d = 12 gives about (2.813-1)/(1.8) ≈ 180,000. So 1M is even worse than IDS average. The heuristic is actively misleading (not admissible or poorly designed).

  • b* = 3.0: (313-1)/(3-1) = (1,594,323-1)/2 = 797,161. Less than 1M.
  • b* = 3.2: (3.213-1)/(3.2-1) = (2.7M-1)/2.2 ≈ 1.24M. Close.

b* ≈ 3.1. Worse than uninformed search — the heuristic is counterproductive.

An EBF higher than the raw branching factor indicates a non-admissible or misleading heuristic.
Example 4: b* as Design Target

Suppose you are designing a heuristic for a new puzzle. You test on 100 random instances. Results:

  • d = 10: average N = 50 → b* ≈ 1.33
  • d = 20: average N = 500 → b* ≈ 1.26
  • d = 30: average N = 5,000 → b* ≈ 1.23

The b* is stable and actually improving with depth. This is characteristic of a well-designed heuristic that captures the problem's structure. You can confidently deploy this heuristic for larger instances.
