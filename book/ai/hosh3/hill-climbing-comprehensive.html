Hill Climbing Algorithm

Hill climbing is a local search algorithm that continuously moves to a higher-valued neighbor (climbs uphill) and stops when it reaches a peak where no neighbor has a higher value. It does not maintain a search tree.

Analogy: It is like Climbing Mount Everest in thick fog with amnesia — you can only feel the slope beneath your feet, cannot see the whole mountain, and do not remember where you have been.

Pseudocode

function HILL-CLIMBING(problem) returns a state current ← MAKE-NODE(INITIAL-STATE[problem]) loop do neighbor ← highest-valued successor of current if VALUE[neighbor] ≤ VALUE[current] then return STATE[current] current ← neighbor

At each iteration:

  • Generate all successors of the current state
  • Select the successor with the highest evaluation value
  • If it is better than current, move to it; otherwise stop and return current

Failure Modes

Local Maxima
A peak that is higher than all neighboring states but lower than the global maximum. The algorithm thinks it has reached the summit when it has not.
Ridges
A sequence of local maxima that form a narrow elevated line. The algorithm cannot traverse it because all immediate moves go downhill.
Plateaux
Flat regions where no neighbor offers improvement. The algorithm wanders randomly with no direction. Two types: flat local maximum (flat peak) and shoulder (flat area leading uphill).
Hill climbing is greedy — it always takes the best immediate move. This makes it efficient but prone to all three failure modes.

Algorithm Behavior

PropertyValue
CompletenessNo — can get stuck in local optima
OptimalityNo — may return local instead of global optimum

Time per stepO(b) where b = branching factor
Search treeNone maintained

8-Queens with Hill Climbing

The 8-queens problem is formulated using the complete-state approach: place one queen per column. The state is an 8-element vector where each element (1-8) is the row of the queen in that column.

Heuristic Function
h(state) = number of attacking pairs of queens
Goal: minimize h. Maximum non-attacking pairs = 28 (all queens safe). Minimum h = 0 (solution).

Walkthrough: Initial State h = 17

Consider the initial state: [5 6 7 8 1 2 3 4] — queens placed on a diagonal.

[5 6 7 4 1 2 3 8]12Move queen in column 7 from row 3 to row 7
[5 6 7 4 1 2 7 8]9Move queen in column 2 from row 6 to row 4
[5 4 7 4 1 2 7 8]7Continue improving...

State space size: 8⁸ = 16,777,216 possible states.

Branching factor: 56 successors (7 alternative rows × 8 columns).

Example: Sideways Moves on Plateaux

Starting from a plateau state where all successors have h = 8 (same as current):

  • Basic HC stops immediately, declaring a local optimum at h = 8 (failure)
  • HC with sideways move allows moving to a neighbor with h = 8, continuing the search
  • After 3 sideways moves, the algorithm finds a successor with h = 6 and proceeds downhill
  • Eventually reaches h = 0 (solution)

Sideways moves significantly improve success rate (14% → 94%) but require more steps and must be limited to avoid infinite loops.

Variants of Hill Climbing

1. Stochastic Hill Climbing

Instead of deterministically picking the best successor, stochastic hill climbing randomly selects among uphill moves, with probability proportional to the steepness of the improvement.

  • Advantage: Can escape local optima by occasionally taking non-optimal uphill paths
  • Disadvantage: Slower convergence — more iterations needed

2. First-Choice Hill Climbing

Generates successors one by one (randomly) and accepts the first one that is better than the current state. Useful when the branching factor is very large and generating all successors is expensive.

  • Advantage: Much faster when B is huge (e.g., continuous optimization)
  • Disadvantage: May miss the best immediate move

3. Random-Restart Hill Climbing

Run hill climbing multiple times from random initial states. Each trial is independent. If the probability of success per trial is p, the expected number of trials is 1/p.

Expected Restarts
E[trials] = 1 / p
Where p = probability of a single random trial finding a global optimum
Example: 8-Queens Random Restart

For 8-queens, p ≈ 0.14 (14% of random states lead to a solution via hill climbing).

Expected number of trials = 1 / 0.14 ≈ 7.14 trials.

If each trial takes ~4 steps on average, total expected steps = 7 × 4 = 28 steps — vastly less than 16,777,216 states.

4. Hill Climbing with Sideways Moves

Allow the algorithm to move to a neighbor with equal value (sideways move) on plateaux. A limit must be set to prevent infinite loops.

Example: Plateaux Traversal

Consider a landscape with a 10-state-wide shoulder before an upward slope:

  • Basic HC: stops immediately (no uphill move available)
  • Sideways limit = 10: traverses the shoulder in 10 steps, then climbs uphill to the peak
  • Sideways limit = 5: only gets halfway across the shoulder before stopping (still fails)
