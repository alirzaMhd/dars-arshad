Heuristic Functions for the 8-Puzzle

Artificial Intelligence — Informed Search

The 8-Puzzle Problem

The 8-puzzle was one of the first heuristic search problems studied in AI. It consists of a 3×3 grid with tiles numbered 1 through 8 and one blank space. A tile adjacent to the blank can slide into the blank position.

Comparison: 15-Puzzle

The 15-puzzle (4×4 grid) has about 1013 reachable states — making uninformed search infeasible. A good heuristic is essential.

Example 1: Average Solution Cost

The average solution cost for a random 8-puzzle instance is 22 steps. With branching factor ~3, a brute-force search to depth 22 would explore roughly 3.1 × 1010 nodes. By detecting repeated states, the true reachable state space is only 181,440 — but uninformed BFS/DFS still explores a large fraction of those before finding the goal.

Example 2: Why Heuristics Matter

Without a heuristic, IDS solving a depth-22 8-puzzle would expand roughly 322 ≈ 3.1 × 1010 nodes. With a good heuristic like Manhattan distance, A* expands only a few thousand nodes — a speedup factor of over 10 million.

Example 3: 15-Puzzle Scaling

The 15-puzzle has 16! / 2 ≈ 1013 reachable states. Even with repeated state detection, uninformed search cannot find optimal solutions. However, with a well-designed heuristic (e.g., Manhattan distance or pattern databases), A* can solve random 15-puzzle instances in seconds.

Example 4: Heuristic Cost vs Search Effort

For the standard start state above, the true optimal solution cost is 26 steps. h1 (misplaced tiles) = 8 and h2 (Manhattan) = 18. A* with h2 expands far fewer nodes because h2 gives a much tighter lower bound, pruning more of the search tree.

h1 — Misplaced Tiles

Definition: Count the number of tiles not in their goal position. The blank is not counted.

h1(n) = number of misplaced tiles
Admissible: each misplaced tile requires at least 1 move to reach its goal position.

Limitation: h1 ignores the distance each tile must travel. It only counts whether the tile is in the right place or not, making it a weak heuristic for complex states.

h2 — Manhattan Distance

Definition: Sum of the horizontal and vertical distances from each tile's current position to its goal position. The blank is not counted.

h2(n) = Σ |xi − xigoal| + |yi − yigoal|
Admissible: each move reduces the Manhattan distance of exactly one tile by at most 1.

h2 Dominates h1

Dominance: h2(n) ≥ h1(n) for all states n
If a tile is misplaced, its Manhattan distance is at least 1. If it is correct, both are 0. Therefore every misplaced tile contributes 1 to h1 but potentially ≥1 to h2.

A* with h2 expands fewer nodes than A* with h1 because h2 is more informed.

Example 4: 15-Puzzle Manhattan Distance

For the 15-puzzle (4×4), Manhattan distance is computed identically. For a state where tile 14 is at (1,1) instead of (4,3): Δx=3, Δy=2, distance=5. Summing over all 15 tiles yields h2. Manhattan for the 15-puzzle is still admissible and typically reduces search by many orders of magnitude compared to h1.

Warning: While h2 dominates h1, it is not always the best possible heuristic. More sophisticated heuristics (pattern databases, linear conflict) can be even more informed, at the cost of additional computation per node.
