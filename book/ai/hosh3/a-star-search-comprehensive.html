Informed Search Algorithms — Chapter 3

A* Algorithm Definition

A* combines actual cost from start, g(n), and estimated cost to goal, h(n), using evaluation function f(n) = g(n) + h(n). It always expands the frontier node with the smallest f-value.

Evaluation Function:
f(n) = g(n) + h(n)
g(n) = cost from start to n. h(n) = estimated cost from n to goal. f(n) estimates total cost of cheapest path through n.
function A*(problem) returns a solution path node ← MAKE-NODE(INITIAL-STATE[problem]) OPEN ← priority queue ordered by f(n); INSERT(node, OPEN) CLOSED ← empty set loop do if OPEN is empty then return FAILURE n ← POP-MIN-F(OPEN) if GOAL-TEST[problem](STATE[n]) then return n add STATE[n] to CLOSED for each action a in ACTIONS[problem] do m ← RESULT(STATE[n], a) if m not in CLOSED and m not registered in n.path then child ← MAKE-NODE(m, n, ACTION(n, a), g(n)+c(n,a,m)) INSERT(child, OPEN) else if cheaper path found to existing node then update its g-value and parent

Heuristic Path Search

Heuristic Path Search generalizes A* by weighting the heuristic more aggressively. Its evaluation function is:

Weighted A* / Heuristic Path Search:
f(n) = (2 - W) g(n) + W h(n)
W controls the tradeoff between exploring cheap paths and moving toward the goal. Special cases: W=1 gives standard A*. W=0 gives uniform-cost search. W=2 gives greedy best-first search. W>1 trades optimality for fewer node expansions. With W>1 the solution cost is bounded by W*C*.
Warning: Only W=1 guarantees optimality with an admissible heuristic. For W>1, the algorithm is not optimal, but can expand far fewer nodes. In practice W=1.2 to W=2 is common when fast approximate answers are needed.

Admissibility & Optimality Proofs

Admissibility Condition:
h(n) ≤ h*(n)
An admissible heuristic never overestimates the true cheapest cost h*(n) to reach a goal from node n.
Proof Sketch: A* Tree-Search is Optimal

Assume A* returns a suboptimal solution G2 with cost C2 > C*. Let n be a node on the optimal path that is an ancestor of G2 (or equal to the optimal goal). Because h is admissible, h(n) ≤ h*(n). Thus f(n) = g(n) + h(n) ≤ g(n) + h*(n) = C*. Since f(n) ≤ C* < C2 = f(G2), node n must be selected before G2. Expanding n leads to the optimal goal, so A* cannot return G2 first.

Worked Example: Admissibility Check

Graph: S--5--A--3--B--2--G. h(S)=4, h(A)=2, h(B)=1, h(G)=0. True optimal costs: h*(S)=6, h*(A)=5, h*(B)=2, h*(G)=0. Check: 4≤6, 2≤5, 1≤2, 0=0. All satisfied. Heuristic is admissible.

Consistency & Non-decreasing f-values

Consistency Condition:
h(n) ≤ c(n, a, n') + h(n')
For every node n and successor n' generated by action a, the estimated cost to goal from n is no more than the step cost plus estimate from n'. Also called monotonicity.

Every consistent heuristic is admissible. With a consistent heuristic, A* Graph-Search guarantees optimality. Without consistency, Graph-Search may prune optimal paths.

Worked Example: Consistency Verification

Path S--2--A--3--B--4--G. h(S)=5, h(A)=3, h(B)=1, h(G)=0. Checks: 5 ≤ 2+3=5, 3 ≤ 3+1=4, 1 ≤ 4+0=4. All pass. f-values: S=5, A=5, B=6, G=9. Non-decreasing along path.

When Consistency May Fail with SLD

Straight-line distance is consistent in Euclidean space but can violate consistency when action costs (road distances) do not match geometric distances. Example: if c(Sibiu,Bucharest)=180 but h_SLD(Sibiu)=253, then 253 ≤ 180+0 fails. In road network problems, admissible is easier to ensure than perfectly consistent.

Contours & Memory Issues

Contour Definition:
Contour C_k = { n | f(n) ≤ k }
Contours are nested sets around the goal. A* expands all nodes with f(n) < C* first, where C* is the optimal solution cost.
Romania Example: A* Contours

A* from Arad to Bucharest with h_SLD. Optimal cost C* = 417. The algorithm expands nodes with f<417 first: Arad(366), Sibiu(393), Rim.Vilcea(413), then Pitesti(417) is the first goal. Nodes with higher f are never expanded.

Memory Problem

Memory Complexity:
Space = O(b^d)
A* must store all generated nodes in OPEN and CLOSED. On large problems (e.g., 24-puzzle, robotics), this is infeasible.

Optimal Efficiency

A* is optimallly efficient: no other optimal algorithm using the same heuristic is guaranteed to expand fewer nodes. It expands all nodes with f(n) < C* and possibly some with f(n) = C*.

Exponential Growth

If heuristic error grows with heuristic value, nodes expanded grow exponentially. Effective branching factor b* measures heuristic quality: b* near 1 is excellent. For the 8-puzzle, h_Manhattan gives b* ≈ 1.3-1.4.

Online Search

In online search, the agent has no prior model of its environment. It does not know the states, actions, or results in advance. It must discover them by acting and sensing. This contrasts with the standard A* assumption that the problem is fully known beforehand.

When Online Search Is Needed

  • The environment is not known in advance, e.g., a robot in an unknown maze.
  • No action model is available; the agent must try actions to learn what they do.
  • There is no heuristic function available; the agent must learn heuristics online.

Heuristic Path Search with Online Learning

When online exploration is necessary, the agent can use online heuristic path search. The evaluation function still guides exploration, but the heuristic h(n) is updated as new information arrives.

Online Heuristic Update:
h_new(n) = min( h_old(n), actual_cost_to_goal_from_n )
As the agent reaches goal states or terminal states, it backpropagates real costs to update heuristic estimates. This is similar to learning from experience but happens during a single search.

Online A* and LRTA*

Learning Real-Time A* (LRTA*) is an online variant that updates the heuristic at each step and commits to the best neighbor. It guarantees finding the goal under certain conditions, but may not be optimal.

function LRTA*(problem, initial_state) h ← initial heuristic values state ← initial_state while GOAL-TEST(problem, state) is false do for each successor s of state do h(s) ← min(h(s), actual_cost(state, s) + h(s)) n ← successor with minimum h(s) take action to n state ← n

Worked Example: Online Search in a Maze

Unknown Grid Maze

An agent starts at (0,0) in an unknown grid. It does not know the maze walls. It uses Manhattan distance as a rough initial heuristic, then updates h values as it discovers dead ends.

At (0,0), h=7 toward goal at (3,4). Agent tries moving east, discovers a wall. Updates h((0,0)) = 7. Backtracks, tries south. Eventually explores a path to goal. Final cost may exceed optimal because of explored dead ends, but the agent will find the goal.
