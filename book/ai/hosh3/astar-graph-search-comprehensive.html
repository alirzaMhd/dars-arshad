A* with Graph-Search and Consistency

Artificial Intelligence — Informed Search

The Problem with Graph-Search and A*

When A* uses GRAPH-SEARCH (which tracks explored states to avoid revisiting them) instead of TREE-SEARCH, the optimality proof fails. The issue is that GRAPH-SEARCH may discard a state because it was previously reached via a different path — but that different path might be the only way to reach the optimal solution.

⚠ Key Problem: In A* with GRAPH-SEARCH, repeated states may cause the algorithm to discard the optimal path. When a state is first reached, it is added to the explored set. If a better path to that same state is found later, the state is already marked as explored and the better path is ignored.

Two Solutions

Solution 1: Modify GRAPH-SEARCH to keep the more expensive path. When a state is reached again via a cheaper path, the old entry in the explored set is replaced with the new cheaper path. This adds computational overhead but guarantees optimality.

Solution 2: Ensure the heuristic is consistent (monotonic). If h is consistent, then the first time a state is reached, it is guaranteed to be via the optimal path. No re-exploration is needed.

Consistency Definition

A heuristic h(n) is consistent (also called monotonic) if for every node n and every successor n' of n generated by action a:

Consistency Condition
h(n) ≤ c(n, a, n') + h(n')
This is a form of the triangle inequality. The heuristic estimate from n cannot exceed the cost of going to successor n' plus the estimate from n'.
Triangle Inequality (Visualized)
h(n) ≤ c(n→n') + h(n')
The direct estimate h(n) is bounded by the sum of the action cost and the successor's estimate. This ensures the heuristic is "locally consistent."

All admissible heuristics discussed in this chapter (hSLD, Manhattan distance, misplaced tiles) are also consistent.

Proof: Non-Decreasing f(n) with Consistent Heuristic

If h is consistent, then f(n) is non-decreasing along any path in the search tree. This is the crucial property that makes GRAPH-SEARCH work correctly with A*.

Non-Decreasing f(n) Proof
Let n' be a successor of n generated by action a.

g(n') = g(n) + c(n, a, n')

f(n') = g(n') + h(n')
      = g(n) + c(n, a, n') + h(n')
      ≥ g(n) + h(n)   (by consistency: h(n) ≤ c(n,a,n') + h(n'))
      = f(n)

Therefore: f(n') ≥ f(n)
The f-value never decreases as we go deeper along any path. This means A* with GRAPH-SEARCH expands nodes in order of increasing f-cost.

Why This Proves Optimality

Because f(n) is non-decreasing along any path:

  • The first goal node selected for expansion must have the minimum f-value among all nodes.
  • Since f(G) = g(G) + 0 = g(G) for any goal, the first goal expanded has the minimum path cost.
  • Therefore, the first goal found is the optimal goal.

Proof: Consistent ⇒ Admissible

Theorem: Every Consistent Heuristic is Admissible
Let n be any node, and let n → n₁ → n₂ → ... → nₖ = G be the optimal path from n to goal G.

By consistency: h(n) ≤ c(n, n₁) + h(n₁)
  h(n₁) ≤ c(n₁, n₂) + h(n₂)
  ...
  h(nₖ₋₁) ≤ c(nₖ₋₁, G) + h(G) = c(nₖ₋₁, G)  (since h(G)=0)

Chaining all inequalities:
h(n) ≤ c(n,n₁) + c(n₁,n₂) + ... + c(nₖ₋₁,G) = h*(n)

Therefore: h(n) ≤ h*(n)  → admissible.
Consistency is a stronger condition than admissibility. Every consistent heuristic is automatically admissible.

Contours in A* Search

With a consistent heuristic, f(n) is non-decreasing, which allows us to define f-contours — regions of the state space where f(n) ≤ constant. A* expands nodes in concentric f-contours:

A* Contour Properties
A* expands all nodes with f(n) < C* (surely expanded)
A* may expand some nodes with f(n) = C* (goal contour)
A* expands NO nodes with f(n) > C* (pruned)
C* = cost of optimal solution. Nodes with f(n) < C* are guaranteed to be on some optimal path candidate.
⚠ Without Consistency: If h is not consistent, f(n) may decrease along a path. This means a later-discovered path to a goal might have a lower f-value than an earlier one, and GRAPH-SEARCH would have already discarded the nodes needed for this better path.

Is h consistent? Check: h(S)=3 ≤ cost(S→A)+h(A)=1+50=51 ✓, but h(B)=1 ≤ cost(B→G)+h(G)=2+0=2 ✓. Check if h(S) ≤ cost(S→B)+h(B): 3 ≤ 1+1=2? No! h is inconsistent.

A* Graph-Search expands S (f=3), then B (f=2, lowest f). G is found via B with cost 3. But the optimal path S→A→G (cost=101) has f(S→A)=51 which would be expanded later if at all — but G is already found!

A* Graph-Search returns path S→B→G with cost 3, but the actual optimal is S→A→G with cost... wait, that's not right. Let me re-examine.

Actually, with h(S)=3 (admissible since 3≤3), h(A)=50 (admissible since 50≤100), h(B)=1 (admissible since 1≤2). Each h is admissible. But h is inconsistent because h(S)=3 > cost(S→B)+h(B)=1+1=2.

With Tree-Search, A* would explore correctly: S(3), B(2→found G at 3), A(51→found G at 101). Optimal path S→B→G (cost 3) would be returned as optimal.

In this example, inconsistency doesn't cause a problem because the first path found happens to be optimal. But in more complex graphs, the first path to a state might NOT be optimal.
