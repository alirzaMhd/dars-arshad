SMA* — Simplified Memory-Bounded A*

Artificial Intelligence — Informed Search

Algorithm Overview

SMA* uses all available memory efficiently. It behaves like A* (expanding the best leaf first) until the memory is full. Once full, it drops the worst leaf (highest f-value), "forgetting" it but propagating its f-value back to the parent, so the parent remembers the quality of the best path in that subtree.

Pseudocode

function SMA*(problem) returns a solution Queue ← MAKE-QUEUE(MAKE-NODE(INITIAL-STATE[problem])) loop do if Queue is empty then return failure n ← deepest least-f-cost node in Queue if GOAL-TEST(n) then return success s ← NEXT-SUCCESSOR(n) if s is not goal and at max depth then f(s) ← ∞ else f(s) ← MAX(f(n), g(s)+h(s)) if all successors of n generated then update n's f-cost and ancestors if memory is full then delete shallowest highest-f-cost leaf in Queue remove it from parent's successor list insert parent on Queue if necessary insert s on Queue if all successors of n in memory then remove n from Queue

Key Properties

Complete
Yes — if depth of shallowest goal ≤ memory capacity (in nodes)
Optimal
Yes — if memory can store the shallowest optimal solution path
Space
User-specified: uses all available memory
Best for
General-purpose optimal search with limited RAM, non-uniform step costs, graph state spaces

Memory Management Strategy

When Memory is Full

  Memory Full! Decision Process:
  ┌────────────────────────────────────────────────────────┐
  │  Queue (sorted by f-cost, deepest first for tiebreak) │
  │                                                        │
  │  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐    │
  │  │best  │→│  ... │→│ ...  │→│ worst│→│worst │   │
  │  │leaf  │  │      │  │      │  │ leaf │  │ leaf │   │
  │  │f=10  │  │f=15  │  │f=20  │  │f=30  │  │f=35  │   │
  │  └──────┘  └──────┘  └──────┘  └──────┘  └──────┘    │
  │                                    ↑                   │
  │                          DELETE this leaf              │
  │                          (shallowest highest-f)        │
  │                                                        │
  │  1. Remove worst leaf from queue                       │
  │  2. Remove it from parent's successor list             │
  │  3. Update parent's f = min(parent's f, deleted f)    │
  │  4. Reinsert parent on queue if it was removed         │
  │  5. Insert new successor s on queue                    │
  └────────────────────────────────────────────────────────┘

f-Value Propagation

Parent Update Rule
f(parent) = min(f(child₁), f(child₂), ..., f(childₖ))
When all successors of a node are generated, the node's f is updated to the minimum f of its children. This is propagated up to ancestors.
Parent Remembers
When a leaf is deleted, its f-value is stored in the parent. If all children of a node are eventually forgotten, the node still "knows" the best cost through that subtree. This allows SMA* to regenerate the subtree later if all other paths become more expensive.

Tie-Breaking Rules

Expansion: Newest Best Leaf
When multiple leaves have the same f-cost, SMA* expands the newest best leaf
Deletion: Oldest Worst Leaf
When deleting, SMA* drops the oldest worst leaf (shallowest highest-f)

Thrashing Problem

Thrashing: SMA* may expand and delete the same node repeatedly, similar to page faults in virtual memory. This happens when:
• Memory is too small to hold the critical path
• Heuristic values are close together, causing frequent swaps
The algorithm regenerates a subtree, but before it finds the goal, the subtree is evicted again.

Examples

Example 1: SMA* Tree with Memory Limit = 3 Nodes
  Tree:
         A (f=5)
       /     \
    B(7)      C(8)
    /  \      /  \
  D(9) E(10) F(9) G(11)

  Memory limit: 3 nodes. Goal: F.

  Step 1: Queue = [A(5)]. Expand A.
     Generate B(7), C(8). Queue = [B(7), C(8)]. Memory: 3/3 full.

  Step 2: Expand B(7) (best leaf).
     Generate D(9), E(10). Queue = [C(8), D(9), E(10)].
     Memory full (4 nodes)! Delete shallowest highest-f leaf.
     Candidates: D(9) depth=2, E(10) depth=2, C(8) depth=1.
     Shallowest highest-f = C(8) depth=1? No — C(8) has f=8, lower than D(9), E(10).
     Delete E(10) — highest f among deepest? Shallowest highest-f: E(10) depth 2.

  Step 3: Delete E. f[B] = min(D(9), E(10)) = 9. Queue = [C(8), D(9)].
     But wait — D(9) is also pending. Expand C(8).

  Step 4: Expand C(8). Generate F(9), G(11). Queue full again.
     Current: D(9) f=9, F(9) f=9. Delete shallowest highest-f: both same f.
     Delete D(9) (oldest). f[C] = min(F(9), G(11)) = 9.

  Step 5: Queue = [F(9), G(11)]. Expand F(9) → goal found!

  SMA* found the optimal path (A→C→F) using only 3 memory slots.

Example 3: Thrashing Scenario
  Memory = 3 nodes. Problem: Goal reachable only through path of length 5.

  Tree:
      A (f=5)
     /     \
   B(6)    C(6)
   /        \
  D(7)      E(7)
   \        /
    F(8)   G(8)
     \    /
      H(9)   ← goal

  With memory=3, SMA* must traverse A→B→D→F→H but only remembers 3 nodes.

  Trace:
  1. Queue: [A]. Expand A → [B, C]
  2. Queue: [B, C]. Expand B → [C, D]. Delete C (shallowest)
  3. Queue: [D]. → B remembers f(B)=7, C is gone
  4. Expand D → [F]. Delete? Queue has room.
  5. Expand F → [H]. Goal found!
  
  But if tree were bushier (many siblings at each level), SMA* would
  constantly swap nodes in and out:

  Frustrating case:
  - Expand A → [B(6), C(6), D(6)] (memory full)
  - Expand B(6) → [C(6), D(6), E(7)] (delete deepest? f=7 > rest)
  - Delete E(7), f[B]=E(7)
  - Now best leaf is C(6) → expand → G(7) → delete deepest
  - Eventually revisit B, but E(7) was deleted, so re-expand B→E
  - This cycle repeats — thrashing!
Thrashing Warning: When memory is severely limited, SMA* can "thrash" — repeatedly deleting and regenerating the same subtree. This is analogous to thrashing in virtual memory systems where the working set doesn't fit in physical memory. Increasing the memory limit or improving the heuristic can mitigate this.
