Local Search & Optimization Problems

Artificial Intelligence — Informed Search

What is Local Search?

Local search algorithms operate on a single current state and move only to neighboring states. Unlike systematic search (BFS, DFS, A*), they do not maintain multiple paths or keep track of where they have been. They are also called iterative improvement algorithms because they continuously improve the current state until a stopping condition is met.

No path memory is maintained — the algorithm only knows its current position in the state space.

Key Advantages

Very Little Memory
Constant memory usage — only stores current state, not a search tree or frontier. Suitable for large state spaces where systematic search would exhaust memory.
Finds Good Solutions Quickly
In large or continuous state spaces, local search can find reasonable solutions where exhaustive methods are impractical.
Pure Optimization
Useful when the goal is not a specific state but the best state according to an objective function (e.g., minimize cost, maximize profit).

Local search is not complete — it can get trapped in local optima and fail to find the global best solution. It trades guarantees for efficiency.

State-Space Landscape

The performance of local search is best understood by visualizing the state-space landscape. The x-axis represents all possible states, and the y-axis represents the evaluation function value (cost or objective).

Cost Function
If the evaluation is a cost (to minimize), the goal is the global minimum — the lowest valley in the landscape.
Objective Function
If the evaluation is an objective (to maximize), the goal is the global maximum — the highest peak in the landscape.
Global Optimum
The absolute best point in the entire state space — either the highest peak (max) or lowest valley (min).
Local Optimum
A point that is better than all its neighbors but worse than the global optimum. Local search can get stuck here.

Landscape Features

Terminology
global optimum = maxₛ f(s)  or  minₛ f(s)
Where f(s) is the evaluation function at state s

Completeness vs Optimality

Complete Local Search
Always finds a goal state if one exists. Standard local search (hill climbing) is NOT complete.
Optimal Local Search
Always finds the global maximum or minimum. Standard local search is NOT optimal.
Trade-off
More exploration (randomness) improves completeness but reduces efficiency.
In real-world problems, the landscape is often highly rugged with many local optima. Choosing the right local search variant depends on the landscape structure.

Worked Examples

Example 1: 8-Queens Problem

Objective: Place 8 queens on a chessboard so that no two queens attack each other.

Complete-State Formulation: Place one queen per column. The state is an 8-digit vector where each digit (1-8) is the row of the queen in that column.

Evaluation Function: Number of attacking pairs (goal = 0 attacks).

StateAttacking PairsInterpretation
[5 6 7 8 1 2 3 4]17Initial state — many attacks
[5 6 7 4 1 2 3 8]12After moving queen in col 4 from row 8 to row 4
[2 4 7 4 8 5 5 2]4Partial improvement — still has conflicts
Solution0No queens attack each other

Each state has 56 successors (7 possible row moves × 8 columns). The algorithm picks the successor with the fewest attacking pairs.

Example 2: VLSI Circuit Floorplanning

Objective: Arrange 12 rectangular circuit blocks on a chip to minimize total wire length and chip area.

State: A placement configuration specifying (x,y) coordinates and orientation for each block.

Successor: Swap two blocks, move one block, or rotate a block.

ConfigurationChip Area (mm²)Wire Length (mm)Total Cost
Random initial24.5187211.5
After 100 moves18.2124142.2
After 500 moves14.889103.8
After 2000 moves12.36779.3

Local search iteratively adjusts block positions, accepting moves that reduce weighted cost (area + wire length). The search may get stuck in local minima where no single move improves the design.

Local search algorithms are not a replacement for systematic search — they are complementary. Use local search when the state space is too large for systematic search or when an approximately optimal solution is acceptable.
