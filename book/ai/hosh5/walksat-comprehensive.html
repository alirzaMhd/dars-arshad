WalkSAT Algorithm

Artificial Intelligence — Logical Agents Chapter

Local Search for SAT

WalkSAT is a local search algorithm for satisfiability. Unlike DPLL, it is not complete but is often very fast for finding satisfying assignments when they exist.

Key Insight
Evaluate: number of unsatisfied clauses
WalkSAT uses the min-conflicts heuristic - it tries to minimize the number of unsatisfied clauses at each step.

Algorithm Steps

Step 1
Random initialization

Start with a random assignment of true/false to all symbols.

Step 2
Check satisfaction

If current model satisfies all clauses, return it as the solution.

Step 3
Select unsatisfied clause

Pick a random clause that is false in current model.

Step 4
Flip a symbol

With probability p: flip random symbol (random walk). With probability (1-p): flip symbol that minimizes unsatisfied clauses (min-conflicts).

Step 5
Repeat or fail

Repeat for max-flips iterations. If no solution found, return failure.

Critical Limitation: WalkSAT is NOT complete. It cannot prove unsatisfiability. If it returns failure, the sentence might still be satisfiable - you just didn't find it.

WalkSAT Pseudocode

function WALKSAT(clauses, p, max-flips) returns a satisfying model or failure
inputs: clauses, a set of clauses in propositional logic
p, the probability of choosing to do a "random walk" move
max-flips, number of flips allowed before giving up

model ← a random assignment of true/false to the symbols in clauses
for i = 1 to max-flips do
if model satisfies clauses then return model
clause ← a randomly selected clause from clauses that is false in model
with probability p
flip the value in model of a randomly selected symbol from clause
else
flip whichever symbol in clause maximizes the number of satisfied clauses
return failure

Key Parameters

p (random walk probability)
Typically ~0.5

Balances exploitation (greedy min-conflicts) with exploration (random walk). Higher p = more exploration, lower p = more greediness.

max-flips
Iteration limit

Maximum number of flips before giving up. If set to ∞ and sentence is satisfiable, WalkSAT will eventually find a model (if p > 0).

Worked Examples

Example 1: Simple Satisfiable Sentence
CNF: (A ∨ B) ∧ (¬A ∨ C) ∧ (¬B ∨ ¬C)

WalkSAT Trace (p=0.5, max-flips=10):

Iteration 1:
- Random assignment: {A=true, B=true, C=true}
- Check clauses:
(A ∨ B) = true ✓
(¬A ∨ C) = true ✓
(¬B ∨ ¬C) = false ✗
- Select unsatisfied clause: (¬B ∨ ¬C)
- Random walk (p=0.5): flip C
- New model: {A=true, B=true, C=false}

Iteration 2:
- Check clauses:
(A ∨ B) = true ✓
(¬A ∨ C) = false ✗
(¬B ∨ ¬C) = true ✓
- Select unsatisfied clause: (¬A ∨ C)
- Min-conflicts: flip A (satisfies clause, keeps others satisfied)
- New model: {A=false, B=true, C=false}

Iteration 3:
- All clauses satisfied!
- Return model: {A=false, B=true, C=false}

Result: Satisfiable ✓
Example 2: Min-Conflicts vs Random Walk
CNF: (A ∨ B ∨ C) ∧ (¬A ∨ ¬B) ∧ (¬C)

Current model: {A=true, B=true, C=true}
Unsatisfied clause: (¬C) - C is true but should be false

Option 1: Random Walk (probability p)
- Pick random symbol from clause: C
- Flip C to false
- New model: {A=true, B=true, C=false}
- Check: (A ∨ B ∨ C) = true, (¬A ∨ ¬B) = false, (¬C) = true
- Still 1 unsatisfied clause

Option 2: Min-Conflicts (probability 1-p)
- For each symbol in clause, count satisfied clauses after flip:
Flip A: (A ∨ B ∨ C)=false, (¬A ∨ ¬B)=true, (¬C)=false → 1 satisfied
Flip B: (A ∨ B ∨ C)=false, (¬A ∨ ¬B)=true, (¬C)=false → 1 satisfied
Flip C: (A ∨ B ∨ C)=true, (¬A ∨ ¬B)=false, (¬C)=true → 2 satisfied ✓
- Choose C (maximizes satisfied clauses)
- New model: {A=true, B=true, C=false}

Both options chose C in this case, but min-conflicts guarantees the best choice.
Example 3: Escape from Local Optimum
CNF: (A ∨ B) ∧ (¬A ∨ B) ∧ (A ∨ ¬B) ∧ (¬A ∨ ¬B)

This is UNSATISFIABLE (no model satisfies all 4 clauses)

WalkSAT Trace (p=0.5, max-flips=6):

Start: {A=false, B=false}
Satisfied: (¬A ∨ ¬B)=true
Unsatisfied: (A ∨ B), (¬A ∨ B), (A ∨ ¬B)

Flip 1: Select (A ∨ B), min-conflicts → flip A
Model: {A=true, B=false}
Satisfied: (¬A ∨ B)=true, (A ∨ ¬B)=true
Unsatisfied: (A ∨ B)=true? No: A=true,B=false → (A ∨ B)=true ✓
Wait, let me recalculate...

Actually: {A=true, B=false}
(A ∨ B) = true ✓
(¬A ∨ B) = false ✗
(A ∨ ¬B) = true ✓
(¬A ∨ ¬B) = true ✓
→ 3 satisfied, 1 unsatisfied

Flip 2: Select (¬A ∨ B), min-conflicts → flip B
Model: {A=true, B=true}
(A ∨ B) = true ✓
(¬A ∨ B) = true ✓
(A ∨ ¬B) = true ✓
(¬A ∨ ¬B) = false ✗
→ 3 satisfied, 1 unsatisfied

Flip 3: Select (¬A ∨ ¬B), min-conflicts → flip A
Model: {A=false, B=true}
(A ∨ B) = true ✓
(¬A ∨ B) = true ✓
(A ∨ ¬B) = false ✗
(¬A ∨ ¬B) = true ✓
→ 3 satisfied, 1 unsatisfied

... continues cycling forever (local optimum)
Random walk helps escape but this is UNSAT - will never find solution

WalkSAT vs DPLL Comparison

Feature DPLL WalkSAT
Type Complete backtracking Incomplete local search
Guarantee Finds solution or proves none exists Finds solution if given enough time
Unsatisfiable Detection Yes - can prove unsatisfiability No - cannot prove unsatisfiability
Time Complexity O(2ⁿ) worst case Often fast, no worst-case guarantee
Memory Usage O(n) - keeps track of assignments O(1) - only current assignment
Best For Proving satisfiability/unsatisfiability Finding solutions quickly
Typical Use Formal verification, planning Configuration, constraint solving
Parameter Tuning Variable ordering heuristics p probability, max-flips limit
Performance on Random 3-SAT
WalkSAT often 10-100x faster than DPLL near phase transition
At the critical clause/variable ratio (~4.3 for 3-SAT), WalkSAT finds solutions much faster than DPLL for satisfiable instances.

When to Use WalkSAT vs DPLL

Use WalkSAT When:
Solution likely exists

• Problems from CSPs, planning
• Need fast answer, not proof
• Large problems with many solutions
• Time-critical applications
• "Good enough" solution acceptable

Use DPLL When:
Need guarantees

• Must prove unsatisfiability
• Formal verification
• Safety-critical systems
• Need certainty, not probability
• Problems with few/no solutions

Hybrid Approach
Best of both worlds

• Use WalkSAT first for quick attempt
• If fails, try DPLL for guarantee
• Or use WalkSAT with time limit
• "I thought about it for an hour"

Example 4: Practical Decision
Scenario: Wumpus World Agent

Question: Is square [2,2] safe?

Using WalkSAT:
- Try to find model where [2,2] has pit
- Run WalkSAT for 10,000 flips
- If no model found: "I couldn't find a world where it's unsafe"
- This is NOT a proof, but strong evidence

Using DPLL:
- Check if KB ⊨ ¬P₂,₂
- DPLL will return true or false with certainty
- Complete proof of safety or danger

Decision: Use DPLL for safety-critical decisions.
Use WalkSAT for quick exploration and planning.
Warning about Incompleteness: WalkSAT cannot be used to prove that a square is safe in the wumpus world. The agent can only say "I thought about it for an hour and couldn't find a counterexample." This is empirical evidence, not a logical proof.

Quick Reference

Algorithm
WALKSAT

1. Random initialization
2. Check if satisfied
3. Pick random unsatisfied clause
4. Flip symbol (random or min-conflicts)
5. Repeat until found or max-flips

Parameters
Tune carefully

• p ≈ 0.5 (balance exploration/exploitation)
• max-flips depends on problem size
• More flips = higher chance of success
• But returns failure if unsatisfiable

Heuristics
Two strategies

• Min-conflicts: Greedy, minimizes unsatisfied
• Random walk: Helps escape local optima
• Random choice between them (p parameter)
• Empirically effective combination
