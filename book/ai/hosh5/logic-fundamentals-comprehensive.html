Logic as a Tool for Knowledge Representation

Logic provides a formal framework for representing knowledge and reasoning. A logical agent's knowledge base (KB) is always definite — every proposition is either true or false in any given world, even though the agent may not have complete belief about which propositions hold.

The Role of Logic
Logic = Syntax + Semantics + Inference Rules
Logic defines what sentences are valid (syntax), what they mean (semantics), and how to derive new conclusions (inference).

Syntax

Syntax defines which sentences are well-formed in the language. It specifies what symbols can be used and how they can be combined.

Atomic Sentences

The smallest indivisible units. In propositional logic, these are propositional symbols like P, Q, R, W₁,₃ (representing "Wumpus is at [1,3]").

Complex Sentences

Built from atomic sentences using logical connectives: ¬ (not), ∧ (and), ∨ (or), → (implies), ↔ (biconditional).

Special Symbols

True — always true
False — always false

BNF Grammar for Propositional Logic
Sentence → AtomicSentence | ComplexSentence AtomicSentence → True | False | Symbol Symbol → P | Q | R | ... ComplexSentence → (Sentence) | (Sentence ∧ Sentence) | (Sentence ∨ Sentence) | (Sentence → Sentence) | (Sentence ↔ Sentence) | ¬Sentence

Connective Precedence (highest to lowest)

Operator Precedence
¬ > ∧ > ∨ > → > ↔
Example: ¬P ∧ Q → R ∨ S is parsed as ((¬P) ∧ Q) → (R ∨ S). Always parenthesize binary connectives to avoid ambiguity.

Semantics

Semantics defines the truth value of each sentence in each possible world (model).

Model
m = {P₁: true, P₂: false, P₃: true, ...}
A model is a complete assignment of true/false to every propositional symbol. With n symbols, there are 2ⁿ possible models.

Truth Tables for Connectives

P Q ¬P P ∧ Q P ∨ Q P → Q P ↔ Q
T T F T T T T
T F F F T F F
F T T F T T F
F F T F F T T
Note: P → Q is false only when P is true and Q is false. This is the material implication — it says nothing about causation, only that the truth of P guarantees the truth of Q.
Finite vs Infinite Models: Propositional logic always has a finite (but potentially exponential) number of models. First-order logic can have infinite model spaces. Model checking works efficiently only for finite model spaces.

Entailment (⊨)

Entailment is the fundamental relationship in logic. It says that one sentence logically follows from another.

Formal Definition of Entailment
α ⊨ β iff in every model where α is true, β is also true
α entails β (written α ⊨ β) means: the truth of α in any world guarantees the truth of β in that same world. Informally, the truth of α contains the truth of β.
Mathematical Example

The sentence x + y = 4 entails 4 = x + y.

Proof: In every model (assignment of values to x and y) where x + y = 4 is true, the equation 4 = x + y is also true. For example, in the model {x=2, y=2}, both are true.

Wumpus World Example

The KB contains rules about stench, breeze, and the observations at [1,1] and [2,1].

We write: KB ⊨ "no pit at [1,2]"

This means: in every model where the KB is true, the statement "no pit at [1,2]" is also true. We verified this by checking all 8 possible models.

Inference (⊢)

Inference is the mechanical process of deriving new sentences from existing ones.

Derivation Notation
KB ⊢ᵢ α
"i derives α from KB" — meaning there exists an inference procedure i that can produce α from the sentences in KB.

Relationship Between Entailment and Inference

Entailment (⊨)
Semantic relationship

A property of sentences. About what is true in all possible worlds. The "needle" that exists in the haystack.

Inference (⊢)
Syntactic process

An algorithm that searches for the "needle." An inference procedure that mechanically derives new sentences.

Analogy: Haystack and Needle

Think of all sentences in KB as a haystack and the entailed sentences as needles. Entailment means needles exist in the haystack. Inference is the process of finding them.

If an inference algorithm can derive α from KB, we write KB ⊢ α.

Model Checking Algorithm

One approach to inference: enumerate all models and check if the query is true whenever the KB is true.

function MODEL-CHECKING(KB, α) returns true/false // Enumerate all possible models for each model m in all models: if KB is true in m: if α is NOT true in m: return false // Found a counterexample return true // α is true in every model where KB is true
Model checking is sound (only derives entailed sentences) and complete for finite model spaces. However, with n propositional symbols, there are 2ⁿ models — exponential time complexity.
Grounding: The connection between logic and the real world is established through sensing. When an agent's sensor detects stench, the program creates a corresponding sentence in the KB. The meaning and truth of sentences is defined by this sensing process.

Properties of Inference Algorithms

Property Definition Why It Matters
Sound Only derives entailed sentences: if KB ⊢ᵢ α, then KB ⊨ α Guarantees correctness — no false conclusions
Complete Derives all entailed sentences: if KB ⊨ α, then KB ⊢ᵢ α Can find every conclusion that logically follows
Sound but Incomplete

Safe but may miss some conclusions. Model checking is sound and complete for finite spaces. Some inference procedures (like forward chaining on certain KBs) may be incomplete.

Unsound

Dangerous — may derive false conclusions! An unsound procedure is like finding "needles" that don't actually exist in the haystack.

Complete and Sound

The ideal: always finds every true conclusion and never finds a false one. Fortunately, complete procedures exist for propositional logic.

Correspondence Between World and Representation

The Fundamental Mapping
Real World ←→ Representation
Aspects of the real world correspond to sentences in the KB. Logical entailment (⊨) mirrors the real-world "follows" relationship. If KB correctly represents reality, then logical inference gives correct conclusions about reality.
Why This Works

If the KB is true in the real world (grounded through sensors), and the inference procedure is sound, then every sentence derived from the KB is also true in the real world.

This is the bridge between abstract logic and practical AI: the KB represents reality, and inference discovers truths about reality.

Key Challenge: The KB must accurately represent the real world. If the KB is wrong (due to sensor errors, incomplete rules, etc.), even sound inference will produce conclusions that don't match reality. The grounding problem — connecting logic to the real world via sensors — remains a fundamental challenge.

Worked Example 1: Entailment in Propositional Logic

Does (P ∧ Q) ⊨ P hold?

Claim: If P ∧ Q is true, then P must be true.

All models for symbols P, Q: Model 1: {P=T, Q=T} → P∧Q = T → P = T ✓ Model 2: {P=T, Q=F} → P∧Q = F → (KB false, skip) Model 3: {P=F, Q=T} → P∧Q = F → (KB false, skip) Model 4: {P=F, Q=F} → P∧Q = F → (KB false, skip) In every model where KB (P∧Q) is true, P is also true. ∴ (P ∧ Q) ⊨ P ✓

This is obvious intuitively: if both P and Q are true, then P alone is certainly true.

Worked Example 2: Non-Entailment

Does (P ∨ Q) ⊨ P hold?

Claim: If P ∨ Q is true, then P must be true.

All models for symbols P, Q: Model 1: {P=T, Q=T} → P∨Q = T → P = T ✓ Model 2: {P=T, Q=F} → P∨Q = T → P = T ✓ Model 3: {P=F, Q=T} → P∨Q = T → P = F ✗ COUNTEREXAMPLE! Model 4: {P=F, Q=F} → P∨Q = F → (KB false, skip) Model 3 is a counterexample: KB is true but P is false. ∴ (P ∨ Q) ⊭ P ✗

Just because P or Q is true doesn't mean P specifically is true — Q alone could be making the disjunction true.

Worked Example 3: Model Checking for Wumpus World

KB ⊨ "no pit at [1,2]"?

KB contains:

KB = {¬B₁₁, B₂₁, ¬P₁₁} where B₁₁ = "breeze at [1,1]", B₂₁ = "breeze at [2,1]", P₁₁ = "pit at [1,1]" Breeze rules: B₁₁ ↔ (P₁₂ ∨ P₂₁) B₂₁ ↔ (P₂₂ ∨ P₃₁ ∨ P₁₁) 3 unknown pits: P₁₂, P₂₂, P₃₁ → 2³ = 8 models

Checking models where KB is true:

Only 3 models survive KB (where ¬B₁₁ and B₂₁): m1: P₁₂=F, P₂₂=F, P₃₁=T → "¬P₁₂" = T ✓ m2: P₁₂=F, P₂₂=T, P₃₁=F → "¬P₁₂" = T ✓ m3: P₁₂=F, P₂₂=T, P₃₁=T → "¬P₁₂" = T ✓ In ALL models where KB is true, ¬P₁₂ is true. ∴ KB ⊨ "no pit at [1,2]" ✓

Worked Example 4: Sound vs Complete Inference

Classifying an Inference Procedure

Consider a procedure that only checks the FIRST model and reports a conclusion based on that single model.

Scenario: KB = {P ∨ Q, ¬Q} Correct answer: KB ⊨ P (since ¬Q eliminates the Q=T possibility) Broken procedure: Checks only m1 = {P=F, Q=F} KB is false in m1, so skips it. Never finds the real models. Returns "P is NOT entailed" — WRONG! This procedure is UNSOUND (derives false conclusions) and INCOMPLETE (misses the real entailed sentence).

A sound procedure might be incomplete (miss some conclusions) but never gives wrong answers. An incomplete procedure is still useful if it's sound — it just doesn't find everything.

Exam Tip: To check if α ⊨ β, enumerate all models. If in every model where α is true, β is also true, then α ⊨ β. If you find even ONE model where α is true but β is false, then α ⊭ β.
