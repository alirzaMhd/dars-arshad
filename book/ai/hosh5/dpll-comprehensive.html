DPLL: Complete Backtracking SAT Solver

DPLL (Davis-Putnam-Logemann-Loveland) is a complete backtracking algorithm for checking satisfiability of propositional logic sentences in CNF. It improves upon TT-ENTAILS with three key heuristics.

Input/Output
Input: Sentence s in CNF → Output: true (satisfiable) or false (unsatisfiable)
DPLL operates over partial models, unlike TT-ENTAILS which requires complete models.

Three Key Improvements over TT-ENTAILS

1. Early Termination
Detect truth/falsity early

A clause is true if any literal is true. A clause is false if all literals are false. Can judge entire sentence before model is complete.

2. Pure Symbol Heuristic
Same sign in all clauses

If a symbol appears only positively (or only negatively), assign it to make all clauses containing it true.

3. Unit Clause Heuristic
Single unassigned literal

If a clause has only one unassigned literal, assign it to make the clause true. Creates cascading assignments (unit propagation).

Warning: While DPLL is much faster in practice, its worst-case time complexity is still O(2ⁿ). However, it is exponentially faster on average than TT-ENTAILS.

DPLL Algorithm Pseudocode

function DPLL-SATISFIABLE?(s) returns true or false
inputs: s, a sentence in propositional logic
clauses ← the set of clauses in the CNF representation of s
symbols ← a list of the proposition symbols in s
return DPLL(clauses, symbols, {})

function DPLL(clauses, symbols, model) returns true or false
if every clause in clauses is true in model then return true
if some clause in clauses is false in model then return false
P, value ← FIND-PURE-SYMBOL(symbols, clauses, model)
if P is non-null then return DPLL(clauses, symbols – P, model ∪ {P=value})
P, value ← FIND-UNIT-CLAUSE(clauses, model)
if P is non-null then return DPLL(clauses, symbols – P, model ∪ {P=value})
P ← FIRST(symbols); rest ← REST(symbols)
return DPLL(clauses, rest, model ∪ {P=true}) or
DPLL(clauses, rest, model ∪ {P=false})

Helper Functions

FIND-PURE-SYMBOL(symbols, clauses, model):
For each symbol in symbols:
Check if it appears only positively or only negatively in remaining clauses
Ignore clauses already true in model
Return (symbol, value) if pure, else return null

FIND-UNIT-CLAUSE(clauses, model):
For each clause in clauses:
Count unassigned literals
If exactly one unassigned literal, return (literal, value that makes it true)
Else return null

Worked Examples

Example 1: Early Termination
CNF: (A ∨ B) ∧ (A ∨ C)

DPLL Trace:
1. No clause is true or false yet
2. Check pure symbols: A appears only positively → pure!
3. Set A = true
4. Both clauses now true (A is true in each)
5. Return true

Model: {A = true, B = ?, C = ?}
Result: Satisfiable ✓

Without early termination, we'd need to check 4 models.
With early termination, we only check 1 partial model.
Example 2: Pure Symbol Heuristic
CNF: (A ∨ ¬B) ∧ (¬B ∨ ¬C) ∧ (C ∨ A)

Analysis:
- Symbol A: appears as A (positive) in clauses 1 and 3 → pure positive
- Symbol B: appears as ¬B (negative) in clauses 1 and 2 → pure negative
- Symbol C: appears as C (positive) in clause 3, ¬C (negative) in clause 2 → NOT pure

DPLL Trace:
1. Find pure symbols: A is pure positive → set A = true
2. Clause 1 (A ∨ ¬B) true, Clause 3 (C ∨ A) true
3. Remaining: (¬B ∨ ¬C)
4. Find pure: B appears only as ¬B → pure negative → set B = false
5. Clause (¬B ∨ ¬C) true
6. All clauses satisfied

Model: {A = true, B = false, C = ?}
Result: Satisfiable ✓
Example 3: Unit Clause & Propagation
CNF: (A) ∧ (¬A ∨ B) ∧ (¬B ∨ C)

DPLL Trace:
1. Clause (A) is a unit clause → must set A = true
2. Unit propagation: (¬A ∨ B) becomes (B) → unit clause!
3. Must set B = true
4. Unit propagation: (¬B ∨ C) becomes (C) → unit clause!
5. Must set C = true
6. All clauses satisfied

Model: {A = true, B = true, C = true}
Result: Satisfiable ✓

Note: Unit propagation cascaded through all three clauses automatically.

Complex Trace Example

Example 4: Full DPLL with Backtracking
CNF: (A ∨ B) ∧ (¬A ∨ C) ∧ (¬B ∨ ¬C)

DPLL Trace:
1. No pure symbols (A appears ±, B appears ±, C appears ±)
2. No unit clauses
3. Pick A = true (try true first)
4. Clause 1 (A ∨ B) true
5. Remaining: (¬A ∨ C) → becomes (C) [unit!]
(¬B ∨ ¬C)
6. Set C = true (unit propagation)
7. Clause (¬B ∨ ¬C) → becomes (¬B) [unit!]
8. Set B = false
9. All clauses satisfied

Model: {A = true, B = false, C = true}
Result: Satisfiable ✓

If step 3 had failed, DPLL would backtrack and try A = false.

DPLL vs TT-ENTAILS Comparison

Feature TT-ENTAILS DPLL
Approach Complete enumeration Backtracking with pruning
Model Type Complete models only Partial models allowed
Worst-case Time O(2ⁿ) O(2ⁿ) but much faster in practice
Average Case O(2ⁿ) always Often polynomial for many problems
Early Termination No Yes - detects truth/falsity early
Pure Symbol No Yes - assigns pure symbols greedily
Unit Propagation No Yes - cascading forced assignments
Sound & Complete Yes Yes
Practical Speed Very slow for n > 20 Can handle thousands of variables
Complexity Comparison
TT-ENTAILS: O(2ⁿ) always | DPLL: O(2ⁿ) worst, much better average
For n=50 variables, TT-ENTAILS needs 2⁵⁰ ≈ 10¹⁵ operations. DPLL often solves similar problems in milliseconds.

Modern Enhancements to DPLL

Clause Learning
Record conflicts

When a conflict is detected, learn a new clause that prevents similar conflicts. This is the key innovation of modern SAT solvers (CDCL - Conflict-Driven Clause Learning).

Variable Selection
Smart ordering

Instead of arbitrary ordering, choose variables that appear most frequently (degree heuristic) or are involved in recent conflicts (VSIDS heuristic).

Random Restarts
Escape plateaus

If progress stalls, restart from scratch with different random choices. Learned clauses are retained and help prune future search.

Clever Indexing
Fast data structures

Use efficient indexing to quickly find clauses containing specific variables. Dynamic updates as computation proceeds.

Important Properties

Worst-Case Complexity: Despite enhancements, DPLL remains O(2ⁿ) in the worst case. SAT is NP-complete, so no known algorithm can do better in the worst case. However, practical performance is often excellent.
Key Insight
If CNF contains only Horn clauses → DPLL replicates forward chaining
Unit propagation in DPLL behaves identically to forward chaining for definite clauses. This shows the deep connection between the algorithms.
Soundness
Always correct

If DPLL returns true, the sentence is satisfiable. If false, it's unsatisfiable. No false positives or negatives.

Completeness
Finds all solutions

DPLL will find a satisfying model if one exists, or correctly report unsatisfiability. Guaranteed to terminate.

Optimality
Best known for many problems

With modern enhancements, DPLL-based solvers are the fastest known algorithms for many practical SAT problems.
