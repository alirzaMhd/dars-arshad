Resolution Theorem Proving

Artificial Intelligence — Logical Agents

What is Resolution?

Resolution is a single inference rule that, combined with refutation (proof by contradiction), yields a sound and complete inference procedure for propositional logic. It operates on clauses (disjunctions of literals) and works by detecting complementary literals.

Unit Resolution Rule
(l₁ ∨ l₂ ∨ ... ∨ lₖ), m ⊢ l₁ ∨ ... ∨ lᵢ₋₁ ∨ lᵢ₊₁ ∨ ... ∨ lₖ
where m is the negation of literal lᵢ. That is: m = ¬lᵢ (or lᵢ = ¬m). Remove the complementary pair.
Full Resolution Rule
(l₁ ∨ ... ∨ lₖ), (m₁ ∨ ... ∨ mₙ) ⊢ (l₁ ∨ ... ∨ lᵢ₋₁ ∨ lᵢ₊₁ ∨ ... ∨ lₖ ∨ m₁ ∨ ... ∨ mⱼ₋₁ ∨ mⱼ₊₁ ∨ ... ∨ mₙ)
where lᵢ and mⱼ are complementary (one negates the other). Combine both clauses, removing the complementary pair.

Refutation Completeness: Resolution is refutation complete — if a set of clauses is unsatisfiable, resolution will eventually derive the empty clause. This means we can always determine whether KB ⊧ α by checking if (KB ∧ ¬α) leads to a contradiction.

PL-RESOLUTION Algorithm

Overall Strategy: Refutation (Proof by Contradiction)
KB ⊧ α ⟺ (KB ∧ ¬α) is unsatisfiable ⟺ Resolution derives empty clause
function PL-RESOLUTION(KB, α) returns true/false // Convert KB ∧ ¬α to CNF, then to set of clauses clauses ← the set of clauses in the CNF representation of KB ∧ ¬α new ← {} loop do for each Cᵢ, Cⱼ in clauses do resolvents ← PL-RESOLVE(Cᵢ, Cⱼ) if resolvents contains the empty clause then return true new ← new ∪ resolvents if new ⊆ clauses then return false clauses ← clauses ∪ new

How It Works Step by Step

  1. Convert to CNF: Transform KB ∧ ¬α into Conjunctive Normal Form — a conjunction of clauses
  2. Initialize clause set: Break CNF into individual clauses
  3. Repeat: Generate all pairwise resolvents of current clauses
  4. Check for empty: If empty clause (contradiction) is derived, α is entailed
  5. Check for fixpoint: If no new clauses can be generated, α is not entailed
  6. Iterate: Add new clauses to the set and continue
PL-RESOLVE(C₁, C₂)
Res(C₁, C₂) = (C₁ \ {l}) ∪ (C₂ \ {¬l})
where l ∈ C₁ and ¬l ∈ C₂. Remove both complementary literals, keep the rest as a disjunction.

Factoring

After resolution, a clause might contain duplicate literals (e.g., P ∨ ¬Q ∨ P). Factoring removes duplicates: P ∨ ¬Q ∨ P ≡ P ∨ ¬Q. This is necessary for completeness in some cases.

Visualizing Resolution: The Resolution Lattice

Given clauses {P∨Q, ¬P∨R, ¬Q∨R, ¬R}:

Step 0: clauses = {P∨Q, ¬P∨R, ¬Q∨R, ¬R} Resolve: P∨Q with ¬P∨R → Q∨R Resolve: P∨Q with ¬Q∨R → P∨R Resolve: ¬P∨R with ¬R → ¬P Resolve: ¬Q∨R with ¬R → ¬Q Resolve: ¬P with P∨Q → Q Resolve: ¬Q with Q∨R → R Resolve: R with ¬R → □ (empty!) → Entailment confirmed.

Worked Examples

Example 1: Modus Ponens via Resolution

KB: {A ⇒ B, A}
α: B

Step 1: Form KB ∧ ¬α = (A⇒B) ∧ A ∧ ¬B

Step 2: Convert to CNF:

A ⇒ B ≡ ¬A ∨ B (implication elimination) A is already a unit clause ¬B is already a unit clause CNF: (¬A ∨ B) ∧ A ∧ ¬B Clauses: {¬A ∨ B, A, ¬B}

Step 3: Apply resolution:

Resolve ¬A ∨ B with A → B (complementary: ¬A and A) Resolve B with ¬B → □ (complementary: B and ¬B) → Empty clause derived! KB ∧ ¬α is unsatisfiable. → KB ⊧ B ✓
Example 2: Non-Entailment

KB: {A ∨ B}
α: A

Step 1: KB ∧ ¬α = (A ∨ B) ∧ ¬A

Step 2: Clauses: {A ∨ B, ¬A}

Step 3: Resolution:

Resolve A ∨ B with ¬A → B Clauses now: {A ∨ B, ¬A, B} No more resolvents possible (no complementary pairs in any remaining pair) No empty clause! → KB ⊭ A ✗

This matches our intuition: from "A or B" alone we cannot conclude A (B might be true instead).

Example 3: Resolution with Multiple Complementary Pairs

Clauses: (P ∨ Q) and (¬P ∨ ¬Q)

Resolving these: P complements ¬P → result: Q ∨ ¬Q. This is a tautology! After factoring? No factoring needed (different literals). But Q ∨ ¬Q is valid — it's always true. In resolution, we typically discard tautological clauses (they add no information).

This demonstrates that resolution can produce tautologies, which are harmless but unhelpful. Many implementations discard them.

Example 4: Deriving the Empty Clause from Contradiction

Clauses: {P, ¬P}

Resolve P with ¬P → □ (empty clause) → Immediate contradiction.

This is why resolution can detect inconsistency in a single step for simple cases.

Example 5: Complex Entailment

KB: {(P ⇒ Q), (Q ⇒ R), (R ⇒ S)}
α: (P ⇒ S)

CNF of KB ∧ ¬(P⇒S):

(P⇒Q) → ¬P ∨ Q (Q⇒R) → ¬Q ∨ R (R⇒S) → ¬R ∨ S ¬(P⇒S) → ¬(¬P ∨ S) → P ∧ ¬S Clauses: {¬P ∨ Q, ¬Q ∨ R, ¬R ∨ S, P, ¬S} Resolution trace: ¬P ∨ Q, P → Q ¬Q ∨ R, Q → R ¬R ∨ S, R → S S, ¬S → □ → Entailed! (Hypothetical syllogism proved by resolution)

Theoretical Properties

Ground Resolution Theorem
If S is an unsatisfiable set of clauses, then the resolution closure of S contains the empty clause.
The resolution closure = all clauses derivable by repeated application of the resolution rule. This guarantees completeness.

When Resolution Shines

  • Automated theorem proving
  • SAT solvers (which are essentially optimized resolution)
  • Problem domains where CNF is natural (constraint satisfaction, planning)
  • Verification and formal methods
Key Limitation: Resolution can generate many irrelevant clauses. Refinements like set-of-support, unit preference, and linear resolution improve efficiency by restricting which clause pairs are resolved.
Clause Explosion Example

For a KB about the Wumpus World with just 7 symbols, the full resolution closure might contain dozens of clauses. For n symbols, there are at most 3ⁿ distinct clauses (each literal can be absent, present positively, or present negatively). This exponential bound means resolution terminates but can be slow.
