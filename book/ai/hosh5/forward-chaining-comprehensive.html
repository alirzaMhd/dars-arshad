PL-FC-ENTAILS Algorithm

Forward chaining is a data-driven inference algorithm for Horn clauses. It starts from known facts and derives new facts by applying rules whose premises are all satisfied.

Algorithm: PL-FC-ENTAILS(KB, q)
function PL-FC-ENTAILS?(KB, q) returns true or false
inputs: KB — knowledge base (set of Horn clauses)
          q — query (proposition symbol)
local variables: count — table, indexed by clause, initially the number of premises
                  inferred — table, indexed by symbol, initially false
                  agenda — list of symbols, initially the facts in KB

while agenda is not empty do
  p ← Pop(agenda)
  unless inferred[p] do
    inferred[p] ← true
    for each Horn clause c in whose premise p appears do
      decrement count[c]
      if count[c] = 0 then
        head ← the head of c
        if head = q then return true
        add head to agenda
return false

Key Data Structures

Count Table

Tracks remaining premises

For each Horn clause, stores how many of its premises have NOT yet been proven. When count reaches 0, the rule fires.

Agenda

Symbols to process

A queue of symbols that have been newly inferred but not yet processed. Popped one at a time.

Inferred Table

Tracks processed symbols

Boolean array marking which symbols have already been popped from the agenda. Prevents re-processing.

Head Lookup

Reverse index

For each symbol, which clauses have it in their premise. Allows efficient rule firing when a new fact is derived.

How It Works (Intuition)

1. Initialize:

Put all known facts (positive literals with no premises) into the agenda.

2. Pop & Process:

Remove a symbol p from the agenda. For every rule where p appears in the body, decrement its remaining premise count.

3. Fire Rules:

When a rule's count reaches 0, ALL its premises are satisfied. Add its head to the agenda (new fact derived!).

4. Repeat:

Continue until the query q is found (return true) or the agenda is empty (return false).

KB:
R₁,₁ (agent at [1,1])
¬B₁,₁ (no breeze at [1,1])
R₁,₁ ∧ ¬B₁,₁ → OK₁,₂ (safe at [1,2])

Trace:

Agenda starts with: [R₁,₁, ¬B₁,₁]

Pop R₁,₁ → decrements count of rules 3 and 4 (both now 1)

Pop ¬B₁,₁ → decrements count of rules 3 and 4 (both now 0)

Rule 3 fires: OK₁,₂ added to agenda

Rule 4 fires: OK₂,₁ added to agenda

Both OK₁,₂ and OK₂,₁ are inferred as safe squares!

Example 3: No Inference Possible

KB:
A (fact)
B ∧ C → D (CNF: ¬B ∨ ¬C ∨ D)
D → E (CNF: ¬D ∨ E)
Trace:

Agenda: [A]

Pop A → no rules have A in premise → no count changes

Agenda empty → return false

E is NOT entailed because B and C are unknown, so D cannot be derived.

AND-OR Graph Visualization

Forward chaining can be visualized as exploring an AND-OR graph. In this graph:

AND Links (Arcs)

Connected by arc

Represent conjunction (all must be true). These correspond to the premises of a rule that ALL must be satisfied.

OR Links (No Arc)

Not connected by arc

Represent disjunction (at least one true). Multiple rules can derive the same conclusion — any one suffices.

Leaf Nodes

Known facts

The bottom nodes are the initial facts. Forward chaining propagates upward from known leaves.

Root Node

Query / Conclusion

The top node is what we want to prove. If reachable from leaves via AND-OR paths, the query is entailed.

AND-OR Graph Example

For the KB: {A, B, A∧B→C, B∧C→D, C→E}

Graph Structure (Bottom-Up)
Level 0 (leaves): A, B [known facts]
                 |  |
              arc+arc   |
                 \ /    |
Level 1:          C    |
                 / \   |
              arc  arc+arc
Level 2:         D    E

AND links shown with arcs: A,B→C (both needed), B,C→D (both needed). OR: C can come from A∧B→C only. C→E is a single-premise AND link.

Key Insight: Forward chaining proves nodes bottom-up. It starts at the known leaves (A, B) and fires rules when all premises of an AND node are satisfied. This is equivalent to proving the root is reachable in the AND-OR graph.

Soundness of Forward Chaining

Soundness Theorem:
Forward chaining is sound: every inference is an application of modus ponens
If forward chaining derives a symbol, it is logically entailed by the KB
Completeness Theorem:
Forward chaining is complete for Horn clauses
If KB ⊨ q (query entailed), forward chaining will eventually infer q

Time Complexity Analysis

Complexity:
O(n) where n = size of KB
Each clause's count is decremented at most once per premise. Each symbol is popped from agenda at most once. Total work is proportional to the sum of clause sizes.

Why Linear?

• Each clause is "fired" at most once

• Each symbol is processed at most once

• Count decrements total = total premises = O(n)

Space Complexity

O(n)

• Count table: one entry per clause

• Agenda: at most n symbols

• Inferred table: one entry per symbol

Warning: Non-Horn Limitations

Forward chaining ONLY works for Horn clauses! If the KB contains clauses with multiple positive literals (non-Horn), forward chaining cannot be directly applied. For general CNF, use resolution or DPLL instead.
Non-Horn Example That Forward Chaining Cannot Handle
(A ∨ B) — two positive literals, not Horn

Forward chaining has no rule to fire here. Resolution can handle this clause.
