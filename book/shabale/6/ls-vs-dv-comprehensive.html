Message Complexity Comparison

LS Link-State

Messages: O(|N|·|E|)

Each node floods LSP to all nodes

Each LSP traverses |E| links

|N| nodes each send LSP

Total: |N| × |E| messages

DV Distance-Vector

Messages: depends on convergence

Exchange only between neighbors

At each iteration: 2·|E| messages

Number of iterations varies

Only sends when changes occur

Detailed Message Complexity Analysis

Criterion Link-State (LS) Distance-Vector (DV)
Initialization Each node broadcasts LSP to ALL nodes → O(|N|·|E|) messages Each node sends DV to only neighbors → O(|E|) messages per iteration
When link cost changes New cost must be sent to ALL nodes → O(|E|) messages per change Propagated only if least-cost path changes. Can be local or global.
Periodic updates Periodic LSP flooding (e.g., OSPF: every 30 min) Periodic DV exchange (e.g., RIP: every 30 sec)
Message size Small — only contains link costs of directly attached links Large — contains entire distance vector (cost to ALL destinations)
Scalability concern Flooding overhead in large networks — mitigated by hierarchical routing (OSPF areas) Slow convergence and potential loops in large networks — mitigated by path-vector (BGP)
Key Insight: LS sends fewer but larger messages per node (one LSP to all) while DV sends more but smaller messages (per neighbor). The total message count for LS is O(|N|·|E|) which can be prohibitive for very large networks, whereas DV messages are limited to neighbor exchanges but may require many iterations to converge.
Message Complexity Example

Consider a network with 100 nodes and average degree of 3 (|E| ≈ 150).

LS Messages

O(|N|·|E|) = 100 × 150 = 15,000 messages

Each node sends LSP once

Then converged — no more messages until change

DV Messages

Per iteration: 2 × 150 = 300 messages

If convergence takes d iterations (e.g., d = 10):

Total ≈ 3,000 messages

LS has higher initial overhead but fast convergence. DV has lower per-iteration overhead but may need many iterations.

Convergence Example: Good News vs Bad News

Scenario: Network X—4—Y—1—Z, Z—50—X.

Good News: c(Y,X): 4→1

DV converges in 2 iterations

Y detects cost drop, updates DY(X)=1

Z receives, updates DZ(X)=min(50, 1+1)=2

Done! Good news propagates fast.

Bad News: c(Y,X): 4→60

DV converges in 44 iterations!

Y computes DY(X)=min(60, 1+5)=6 (incorrect — via Z!)

Z computes DZ(X)=min(50, 1+6)=7

... continues until cost exceeds 50

Bad news travels slowly!

LS convergence: Both scenarios require running Dijkstra once → O(|N|²) = 9 operations for 3-node network in both cases.

Robustness Comparison

LS Robustness

• Router can only advertise incorrect link costs for its own links

• Each node computes its own forwarding table

• Damage is contained

• Corrupted LSPs affect only that node's computation

DV Robustness

• Router can advertise incorrect paths to ANY destination

• Incorrect DV propagates to neighbors, then their neighbors...

• Damage can spread through entire network

• 1997 Internet outage caused by one malfunctioning BGP router

Robustness Comparison Table

Failure Scenario Link-State (LS) Distance-Vector (DV)
Router advertises wrong cost Only affects that router's directly attached links — other routers compute their own paths correctly Wrong DV entry for ANY destination can mislead neighbors, propagating through the network
Router fails Neighbors detect failure via HELLO, flood updated LSPs, all recompute Neighbors detect failure, update DVs, propagate — may create temporary loops
Corrupted/ malicious data Only corrupts LS database of receiving node — other nodes have independent computations. A node could also corrupt or drop LSPs it receives, but damage is limited to its own forwarding table. False DV propagates hop-by-hop — entire network can adopt incorrect routes. At each iteration, the incorrect calculation passes to neighbors, then to their neighbors.
Self-healing Fast — complete recomputation with updated topology Slow — may require many iterations to converge after failure
Real-world incident Less prone to widespread routing failures 1997: Single misconfigured router caused multi-hour Internet disruption [Neumann 1997]
Critical: Under DV, an incorrect node calculation can be diffused through the entire network. Each iteration passes the incorrect information to the next hop, then indirectly to its neighbor's neighbor on the next iteration, creating a cascading effect. Under LS, route calculations are somewhat separated — each node computes its own forwarding table independently, providing a degree of robustness. An LS node can only corrupt its own forwarding table; other nodes perform their own independent calculations.
Robustness Scenario Comparison

A misconfigured router R incorrectly claims it can reach subnet S with cost 1 (when actually S is not reachable).

LS Reaction: R broadcasts LSP claiming c(R,S)=1. Other routers may compute paths through R to S (incorrect), but only paths that go through R. If S truly doesn't exist, packets get dropped at R. Damage limited to R's neighborhood.

DV Reaction: R tells neighbor N that DR(S)=1. N believes it, sets DN(S)=1+c(N,R), tells its neighbors. This propagates across the network. Every node now has an entry for S pointing toward R. Traffic from the entire network may converge on R. Damage spreads globally.

LS provides better containment of routing errors.

Final Verdict:
Neither algorithm is an obvious winner over the other — both are used in the Internet.
LS: Best for fast convergence, loop-free paths, and robustness. DV: Best for low per-iteration message overhead and distributed operation. The choice depends on the specific requirements of the network.

Conceptual Examples

Example 1: Network with Path to S via A vs B

Network: S——A——D——T and S——B——E——T. LS vs DV approach.

LS: S knows entire topology. Computes both paths, picks the cheaper one (e.g., via A if c(S,A)+c(A,D)+c(D,T) < c(S,B)+c(B,E)+c(E,T)). One-shot calculation.

DV: S knows only c(S,A) and c(S,B). A knows D(S), D(D), D(T). B knows D(S), D(E), D(T). They exchange iteratively. S may initially think T is unreachable until D and E's info propagates to A and B, then to S. Takes 3 iterations.

LS converges faster (1 step) while DV takes iterations proportional to path length.

Example 2: Link Failure Impact

In a 10-node linear chain A—B—C—D—E—F—G—H—I—J, the link F—G fails.

LS: F and G detect failure, flood LSPs. All nodes receive within O(|E|) time. Each reruns Dijkstra. Convergence time ≈ flood time + O(10²).

DV: F updates its DV (can't reach G). Tells E. E recomputes (no alternative), tells D. Propagates back through the chain. Each hop = 1 iteration. Convergence takes 5 iterations (F→E→D→C→B→A).

For long paths, DV convergence time scales with path length, while LS convergence is nearly independent of topology size (depends on flooding time).

Example 3: Malicious Router Scenario

A router R in a 6-node mesh is compromised. It starts advertising false information.

LS: R can only lie about costs of its own links (e.g., claim c(R,A)=1 instead of 10). This may attract traffic to R, but only affects paths using those links. Other nodes' computations remain correct for the rest of the network.

DV: R can claim DR(X)=1 for any destination X, even if X is nowhere near R. Neighbors believe it, update their DVs, and propagate. Within a few iterations, the entire network may route to X through R — effectively a routing black hole attracting all traffic for X.

LS is more robust against malicious or misconfigured routers.

Exam Tips

• LS: O(n²) comp, O(n·e) msg

• DV: min formula with neighbors

• Count-to-infinity: ∞ for poisoned

• DV good news = fast, bad = slow

• LS oscillations = avoid by randomization

• Both used in today's Internet

Key Formulas

LS Update:

D(v) = min(D(v), D(w)+c(w,v))

DV Update:

Dx(y) = minv{c(x,v)+Dv(y)}

Bellman-Ford:

dx(y) = minv{c(x,v)+dv(y)}
