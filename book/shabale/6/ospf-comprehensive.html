OSPF — Open Shortest Path First

Computer Networks — Link-State Routing Protocol & Autonomous Systems

Autonomous Systems Concept

An Autonomous System (AS) is a collection of routers and networks under a single administrative domain with a unified routing policy. Each AS is identified by a globally unique 16-bit or 32-bit AS Number (ASN). AS numbers, like IP addresses, are assigned by ICANN regional registries [ICANN 2020].

AS Numbers

• Public ASNs: 1–64511 (globally routable)

• Private ASNs: 64512–65535 (internal use)

• 32-bit ASNs: 65536–4294967295 (newer format)

AS Types

• Stub AS: Single connection to one ISP

• Multihomed AS: Connected to multiple ISPs

• Transit AS: Carries traffic between other ASs

The Internet is a network of ASs. Intra-AS routing (e.g., OSPF) operates inside an AS, while inter-AS routing (e.g., BGP) connects ASs together.

OSPF Protocol Overview

OSPF (Open Shortest Path First) is a link-state routing protocol used for intra-AS routing. It uses Dijkstra's algorithm to compute the shortest path tree from every router to every other router.

"Open" in OSPF indicates the routing protocol specification is publicly available (as opposed to Cisco's proprietary EIGRP protocol, which remained closed for ~20 years). OSPF version 2 is defined in RFC 2328 [RFC 2328].

Dijkstra's Algorithm
SPT(v) = { v } with dist(v) = 0
while unvisited nodes remain:
  pick u with smallest dist(u)
  for each neighbor w of u:
    dist(w) = min(dist(w), dist(u) + cost(u,w))
Each router builds a complete topology map and computes shortest paths independently.

Key Properties

• Link-State: Each router knows full topology

• Fast Convergence: Changes detected via HELLO

• Classless: Supports VLSM and CIDR

• Loop-Free: Always computes loop-free paths

OSPF vs RIP

Metric: Cost (configurable) vs Hop Count

Convergence: Fast vs Slow (30s updates)

Scalability: Very Large vs Small networks

Algorithm: Dijkstra vs Bellman-Ford

How OSPF Works

  1. Each router sends HELLO messages (every 10s) to discover neighbors.
  2. Routers construct Link State Advertisements (LSAs) describing their interfaces, neighbors, and link costs.
  3. LSAs are flooded to all routers in the area.
  4. Each router builds a complete Link State Database (LSDB).
  5. Dijkstra's algorithm computes the Shortest Path Tree (SPT).
  6. The routing table is populated with the best paths.
OSPF sends periodic link-state updates every 30 minutes even when no changes occur. This ensures database reliability through refresh mechanisms.

OSPF Core Features

Flooding of Link-State Information

When a router detects a change (link up/down, cost change), it immediately generates a new LSA and floods it to all neighbors. Each neighbor forwards it to all other neighbors except the incoming interface. The flooding is reliable — routers must acknowledge LSAs. This ensures all routers converge to the same topology view.

Flooding Behavior
LSA received → Check LSDB → Newer? → Flood out all interfaces (except incoming) → Send ACK
Flooding stops when all routers have identical LSDBs.

OSPF Transport: Direct over IP (Protocol 89)

OSPF messages are carried directly over IP, using upper-layer protocol 89 (not TCP or UDP). Because OSPF does not rely on TCP, the OSPF protocol must itself implement reliable message transfer and link-state broadcast functionality, including acknowledgment mechanisms for LSAs.

By default, OSPF packets between routers are not authenticated and could be forged. Authentication must be explicitly configured.

Security: Authentication

OSPF supports two authentication methods to prevent routing attacks:

MethodTypeSecurity Level
NullType 0No authentication (default)
Simple PasswordType 1Weak — same password configured on each router, included in OSPF packet in plaintext
MD5 CryptographicType 2Strong — router computes MD5 hash of packet content + shared secret key; receiver recomputes and compares
Simple password authentication is vulnerable to sniffing. MD5 authentication is strongly recommended for production networks.

Replay Attack Protection

When using MD5 authentication, OSPF includes sequence numbers in each packet to protect against replay attacks. A captured OSPF packet cannot be replayed later because the sequence number will be stale and rejected by the receiving router.

Multiple Same-Cost Paths

OSPF supports Equal-Cost Multi-Path (ECMP) routing. When multiple paths have identical cost, OSPF can load-balance traffic across up to 16 (or more) equal-cost paths simultaneously. This improves throughput and redundancy.

ECMP Example

Router R1 has three paths to 10.0.0.0/16, each with cost 20. With ECMP enabled, traffic is distributed across all three paths using per-packet or per-flow load balancing.

MOSPF — Multicast Extensions

MOSPF (Multicast OSPF) extends OSPF to support IP multicast routing. It uses the existing LSDB to compute multicast distribution trees. When a router receives a multicast packet, it uses the link-state database to determine which downstream routers have group members.

MOSPF Features

• Uses OSPF LSDB for multicast tree computation

• Computes source-based trees (Shortest Path Trees per source)

• Efficient for dense multicast groups

• Periodic flooding of group membership LSAs

MOSPF Limitations

• Scalability: CPU-intensive for many groups

• Intermittent traffic: Periodic flooding wastes bandwidth if groups are sparse

• Largely superseded by PIM (Protocol Independent Multicast)

Link Weight Configuration

OSPF allows manual link weight (cost) configuration. The default cost = 10⁸ / bandwidth (bps). Network operators can adjust costs to:

  • Inverse capacity: Higher-bandwidth links get lower costs (e.g., 10 Gbps → cost 10, 1 Gbps → cost 100).
  • Traffic engineering: Manually set costs to influence path selection, avoid congestion, or implement traffic steering policies.
Link Weight Configuration

An operator wants traffic to prefer a 10 Gbps link over a 1 Gbps link:

interface GigabitEthernet0/1
 ip ospf cost 10
!
interface GigabitEthernet0/2
 ip ospf cost 100

Result: Dijkstra's algorithm will route traffic via the lower-cost (higher-bandwidth) path.

Setting OSPF Weights — Cause & Effect Reversal. In theory, link weights are given first and Dijkstra's algorithm produces routing paths as a result. In practice, the cause-and-effect relationship is often reversed: network operators first determine the desired routing of flows (e.g., minimizing the maximum link utilization across the network) and then must find the set of link weights that causes OSPF to produce that desired routing [Fortz 2000, Fortz 2002]. This is a key traffic engineering insight — the operator's main "knob" for tuning flows is the link weight configuration.

OSPF Hierarchy and Areas

OSPF supports two-level hierarchy to improve scalability. Large networks are divided into areas to reduce LSDB size, CPU overhead, and flooding traffic.

Area Structure
Backbone Area (Area 0) — connects all other areas
  ├── Area 1 (Standard Area)
  ├── Area 2 (Standard Area)
  └── Area 3 (Standard Area)
All traffic between areas must traverse Area 0.

Inter-Area Routing (3-Step Path)

When a packet must travel between two different areas within an AS, the routing follows a precise three-step sequence:

  1. Step 1 — Intra-area routing: Packet is routed from the source router to an area border router (ABR) within the source area.
  2. Step 2 — Backbone transit: The ABR forwards the packet through the backbone area (Area 0) to the ABR in the destination area.
  3. Step 3 — Intra-area routing: The destination ABR routes the packet within its area to the final destination.

The backbone area's primary role is to route traffic between all other areas in the AS. The backbone always contains all area border routers in the AS.

Router Types

Backbone Router

Router with at least one interface in Area 0.

Area Border Router (ABR)

Router with interfaces in multiple areas, including Area 0. Summarizes routes between areas.

Internal Router

Router with all interfaces in a single area.

AS Boundary Router (ASBR)

Router that injects external routes into OSPF (e.g., from BGP or static routes).

Benefits of Hierarchical OSPF

  • Smaller LSDBs: Each area only knows its own topology.
  • Faster SPF computations: Dijkstra runs only on the area's topology.
  • Reduced LSA flooding: LSAs stay within area boundaries.
  • Route summarization: ABRs can summarize multiple routes into a single advertisement.
  • Fault isolation: A problem in one area does not affect other areas.
Hierarchical OSPF in a Large Enterprise

An enterprise with 500 routers divides the network into:

  • Area 0 (Backbone): 10 core routers in the data center.
  • Area 1: 100 routers in North America.
  • Area 2: 150 routers in Europe.
  • Area 3: 120 routers in Asia-Pacific.
  • Area 4: 120 routers in South America.

Each area has ~100–150 routers with manageable LSDB sizes. Each ABR connects its area to Area 0 and summarizes area routes.

HELLO Messages

HELLO messages (Type 1) are sent periodically (every 10s by default) on all interfaces to:

  • Discover OSPF neighbors
  • Verify bidirectional communication (2-way state)
  • Elect Designated Router (DR) and Backup DR (BDR) on broadcast networks
  • Maintain neighbor adjacency (Dead Interval = 4 × HELLO Interval = 40s)
If a router does not receive a HELLO from a neighbor within the Dead Interval, it declares the neighbor as dead and floods updated LSAs.

Worked Examples

Example 1: Basic OSPF Configuration

Configure OSPF on a simple 3-router network (R1, R2, R3) with all routers in Area 0.

! Router R1
router ospf 1
 network 192.168.1.0 0.0.0.255 area 0
 network 10.0.0.0 0.0.0.3 area 0
!
! Router R2
router ospf 1
 network 192.168.2.0 0.0.0.255 area 0
 network 10.0.0.0 0.0.0.3 area 0
!
! Router R3
router ospf 1
 network 192.168.3.0 0.0.0.255 area 0
 network 10.0.0.4 0.0.0.3 area 0

Result: R1, R2, and R3 form adjacencies, exchange LSAs, and learn routes to all networks. Each router computes the shortest path to 192.168.1.0/24, 192.168.2.0/24, and 192.168.3.0/24.

R1's routing table after convergence:

O 192.168.2.0/24 [110/2] via 10.0.0.2
O 192.168.3.0/24 [110/3] via 10.0.0.2
Example 2: Multi-Area OSPF with ABR

Four routers across two areas. R1 and R2 are in Area 0. R3 and R4 are in Area 1. R2 is the ABR connecting both areas.

! R2 (ABR)
router ospf 1
 network 10.0.0.0 0.0.0.255 area 0
 network 10.0.1.0 0.0.0.255 area 1
!
! R3 (Area 1 Internal)
router ospf 1
 network 10.0.1.0 0.0.0.255 area 1
 network 192.168.10.0 0.0.0.255 area 1

Route propagation:

  • R4 advertises 192.168.20.0/24 via an LSA in Area 1.
  • R2 (ABR) receives the LSA, installs the route, and creates a Type 3 Summary LSA for Area 0.
  • R1 learns 192.168.20.0/24 as an inter-area route (O IA) with cost = cost_to_ABR + cost_in_Area_1.

R1's routing table:

O IA 192.168.20.0/24 [110/5] via 10.0.0.2
Example 3: OSPF Cost Calculation with Traffic Engineering

An OSPF network has three paths between router A and router B:

  • Path 1: A → R1 → B (10 Gbps link, default cost = 10)
  • Path 2: A → R2 → B (1 Gbps link, default cost = 100)
  • Path 3: A → R3 → R4 → B (10 Gbps + 10 Gbps, cost = 10 + 10 = 20)

Question: Which path does OSPF choose?

Calculation: Path 1 has cost 10, Path 2 has cost 100, Path 3 has cost 20. Dijkstra selects Path 1 (lowest total cost = 10).

Traffic Engineering: If Path 1 is congested, the operator can increase its cost:

interface TenGigE0/1
 ip ospf cost 50

Now Path 3 (cost 20) becomes the preferred route. This demonstrates how OSPF cost manipulation enables traffic engineering without changing physical topology.

Example 4: OSPF Authentication Configuration

Configure MD5 authentication between two OSPF neighbors.

! R1
interface GigabitEthernet0/0
 ip ospf authentication message-digest
 ip ospf message-digest-key 1 md5 MySecretKey
!
! R2
interface GigabitEthernet0/0
 ip ospf authentication message-digest
 ip ospf message-digest-key 1 md5 MySecretKey

Key points:

  • Both routers must use the same key ID and password.
  • MD5 authentication adds a cryptographic hash to each OSPF packet.
  • Without matching authentication, routers will not form adjacencies.
Change MD5 passwords regularly. Use key chains for zero-downtime password transitions.
Example 5: ECMP Load Balancing with OSPF

Router R1 has four equal-cost paths to destination 172.16.0.0/16 (cost = 30 each). With OSPF ECMP, traffic is distributed:

  • Per-packet: Packets are round-robined across paths. May cause out-of-order delivery.
  • Per-flow: Flows (identified by 5-tuple) are hashed to a specific path. Preserves packet ordering.

Configuration:

router ospf 1
 maximum-paths 4

With maximum-paths set to 4, OSPF installs up to 4 equal-cost next hops in the routing table for 172.16.0.0/16:

O 172.16.0.0/16 [110/30] via 10.0.1.1, via 10.0.2.1, via 10.0.3.1, via 10.0.4.1
