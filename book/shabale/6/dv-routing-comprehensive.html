Distance-Vector Routing Overview

The Distance-Vector (DV) routing algorithm is distributed, iterative, and asynchronous. Unlike LS which requires global knowledge, each node in DV only knows the costs to its directly attached neighbors and exchanges information only with those neighbors.

Key Properties

• Distributed — no central authority

• Iterative — repeats until convergence

• Asynchronous — nodes operate independently

• Self-terminating — stops when no changes

Information Stored

• Own distance vector Dx

• Neighbors' distance vectors Dv

• Cost to each neighbor c(x,v)

• Forwarding table entries

Real-World Usage

• RIP (Routing Information Protocol)

• BGP (Border Gateway Protocol)

• Original ARPAnet routing

• Novell IPX, ISO IDRP

The Bellman-Ford Equation

The fundamental relationship that governs DV routing is the Bellman-Ford equation. Let dx(y) be the cost of the least-cost path from node x to node y. Then:

Bellman-Ford Equation (Equation 5.1):
dx(y) = minv { c(x, v) + dv(y) }
The least cost from x to y = minimum over all neighbors v of (cost to neighbor v + least cost from v to y)
Verification of Bellman-Ford

Consider the network in Figure 5.3 with nodes u, v, w, x, y, z.

For source u and destination z: dv(z)=5, dx(z)=3, dw(z)=3.

Edge costs: c(u,v)=2, c(u,x)=1, c(u,w)=5.

du(z) = min{2+5, 1+3, 5+3} = min{7, 4, 8} = 4
This matches Dijkstra's result! The minimum is achieved through neighbor x.

Therefore, the next-hop for u to reach z is node x.

Distance Vector Definition

Each node x maintains:

Distance Vector:
Dx = [ Dx(y) : y ∈ N ]
A vector of cost estimates from node x to all destinations y in the network

The update rule when a node receives a new distance vector from a neighbor:

DV Update Rule:
Dx(y) = minv { c(x, v) + Dv(y) }   for each node y ∈ N
After updating, if Dx changed, send copy to all neighbors
Convergence Guarantee:
As long as all nodes continue to exchange their distance vectors asynchronously, Dx(y) → dx(y)
Each cost estimate Dx(y) converges to dx(y), the actual least cost [Bertsekas 1991]

Distance-Vector Algorithm — Pseudocode

DV Algorithm (at each node x): 1 Initialization: 2 for all destinations y in N: 3 Dx(y) = c(x,y) /* if y not neighbor: c(x,y)=∞ */ 4 for each neighbor w: 5 Dw(y) = ? for all y in N /* unknown */ 6 for each neighbor w: 7 send distance vector Dx = [Dx(y): y in N] to w 8 9 loop (forever): 10 wait (until link cost change to neighbor w OR 11 until receive DV from neighbor w) 12 13 for each y in N: 14 Dx(y) = min_v { c(x,v) + Dv(y) } 15 16 if Dx(y) changed for any destination y: 17 send distance vector Dx = [Dx(y): y in N] 18 to all neighbors 19 forever
Important: The algorithm is self-terminating — there is no explicit signal to stop. It simply reaches a quiescent state where no node sends updates because no distances have changed. It remains in the "wait" state (Lines 10-11) until a link cost change or topology event occurs.

Forwarding Table Update

When updating Dx(y), node x also determines the next-hop router v*(y) — the neighbor v that achieves the minimum in Line 14. This next-hop is stored in the forwarding table for destination y.

Step 1 — Exchange and Update

Each node sends its distance vector to neighbors. After receiving updates:

Node x computes:

Dx(x) = 0

Dx(y) = min{ c(x,y)+Dy(y), c(x,z)+Dz(y) } = min{2+0, 7+1} = 2

Dx(z) = min{ c(x,y)+Dy(z), c(x,z)+Dz(z) } = min{2+1, 7+0} = 3

Node x's Dx changed: [0, 2, 3]. Neighbor y achieves the minima: v*(y) = y and v*(z) = y. x sends update to y and z.

Node y computes:

Dy(x) = min{ c(y,x)+Dx(x), c(y,z)+Dz(x) } = min{2+0, 1+7} = 2

Dy(z) = min{ c(y,x)+Dx(z), c(y,z)+Dz(z) } = min{2+7, 1+0} = 1

Node y's Dy unchanged: [2, 0, 1]. No update sent.

Node z computes:

Dz(x) = min{ c(z,y)+Dy(x), c(z,x)+Dx(x) } = min{1+2, 7+0} = 3

Dz(y) = min{ c(z,y)+Dy(y), c(z,x)+Dx(y) } = min{1+0, 7+2} = 1

Node z's Dz changed: [3, 1, 0]. It sends update to x and y.

Step 2 — Final Convergence

After receiving z's update, x recomputes (no change). After receiving x's update, z recomputes (no change). Algorithm reaches quiescent state.

Link-Cost Changes: Decrease (Fast!)

Consider the network x—y—z where c(y,x) changes from 4 to 1 (decrease).

Scenario: c(y,x): 4 → 1

At t₀: y detects cost decrease. Dy(x) = min{1+0, 1+5} = 1. Dy changed, so y sends update to z.

At t₁: z receives update. Dz(x) = min{50+0, 1+1} = 2. Dz changed, so z sends update to y.

At t₂: y receives update. Dy(x) = min{1+0, 1+2} = 1. No change, algorithm quiesces.

Good news travels fast! Only 2 iterations needed.

Link-Cost Changes: Increase (Slow!)

Now consider c(y,x) changing from 4 to 60 (increase). This reveals the count-to-infinity problem.

Scenario: c(y,x): 4 → 60

Before change: Dy(x)=4, Dy(z)=1, Dz(y)=1, Dz(x)=5.

At t₀: y detects increase. y computes: Dy(x) = min{60+0, 1+5} = 6.

Problem! y thinks z can reach x with cost 5, but z's path to x goes through y! This creates a routing loop: y→z→y→z→... Packets destined for x bounce back and forth forever.

y sends Dz=[60,0,1,...], Dy(x)=6 to z.

At t₁: z receives y's update. Dz(x) = min{50+0, 1+6} = 7. z sends to y.

At t₂: y receives. Dy(x) = min{60+0, 1+7} = 8. y sends to z.

... This continues for 44 iterations before Dy(x) exceeds 50 (the direct cost z→x).

Bad news travels slowly! The count-to-infinity problem causes slow convergence.

Thought experiment: What if c(y,x) changed from 4 to 10,000 and c(z,x) had been 9,999? The same count-to-infinity loop would persist for thousands of iterations — the cost would increment from 10,000 up past 9,999 before z finally uses its direct link. This extreme case shows why count-to-infinity is so problematic in practice.

Poisoned Reverse

A technique to prevent routing loops between two neighboring nodes:

Poisoned Reverse Rule:
If z routes to x via y, then z advertises Dz(x) = ∞ to y
z tells y a "little white lie" — that it has no path to x — to prevent y from routing through z. z continues telling this lie as long as it routes to x via y [Kurose 2021].
Poisoned Reverse in Action

Before the cost change, z routes to x via y (Dz(x)=5 via y). With poisoned reverse, z tells y: Dz(x)=∞.

When c(y,x) changes to 60:

• y computes: Dy(x) = min{60+0, 1+∞} = 60 (cannot use z since Dz(x)=∞)

• y sends Dy(x)=60 to z.

• z computes: Dz(x) = min{50+0, 1+60} = 50 (direct link is now cheaper)

• z switches to direct path, sends Dz(x)=50 to y.

• y computes: Dy(x) = min{60+0, 1+50} = 51.

Only a few iterations needed! No routing loop.

Limitation: Poisoned reverse does NOT solve the count-to-infinity problem for loops involving THREE or more nodes. It only prevents loops between two directly neighboring nodes. More complex loops (e.g., triangular loops through 3 nodes) are not detected.

Worked Examples & Practice Problems

Example 1: 4-Node DV Convergence

Network: A—1—B—1—C—1—D, with A—4—D.

Initial vectors: DA=[0,1,∞,4], DB=[1,0,1,∞], DC=[∞,1,0,1], DD=[4,∞,1,0]

After first exchange:

DA(C) = min{A→B+ DB(C), A→D+ DD(C)} = min{1+1, 4+1} = 2 → via B

DA(D) = min{1+∞, 4+0} = 4 → via D (direct)

DB(D) = min{1+4, 1+1} = 2 → via C

DC(A) = min{1+1, 1+4} = 2 → via B

DD(B) = min{4+1, 1+1} = 2 → via C

DD(A) = min{4+0, 1+2} = 3 → via C

After second exchange (final):

DA(D) = min{1+2, 4+0} = 3 → via B-C-D (better!)

Final vectors: DA=[0,1,2,3], DB=[1,0,1,2], DC=[2,1,0,1], DD=[3,2,1,0]

Example 2: Link Cost Decrease Propagation

Network: P—5—Q—3—R—2—S. Initially all use direct links.

Suppose c(Q,R) drops from 3 to 1.

Step 1: Q detects change. DQ(S) = min{3+2, 1+2} = 3 → unchanged (was 3+2=5 via direct wait — initially DQ(S) = ∞? Let me compute properly.

Initial: DP=[0,5,∞,∞], DQ=[5,0,3,∞], DR=[∞,3,0,2], DS=[∞,∞,2,0]

After 1st exchange: DQ(S) = min{3+2, ∞} = 5 via R. DR(P) = min{3+5, ∞} = 8 via Q.

After 2nd exchange: DP(S) = min{5+5, ∞} = 10 via Q. DR(S) = 2 (direct).

Now c(Q,R) = 1: Q recomputes: DQ(S) = min{1+2, 5+0} → wait, DQ(S) = min(1+R's cost to S, 5+0) = min(1+2, 5) = 3. DQ changed, sends to P and R.

P receives: DP(S) = min(5+3, ∞) = 8 via Q.

Cost decrease propagates quickly (2 iterations).

Example 3: Count-to-Infinity Scenario (3-Node Triangle)

Network: A—1—B—1—C—10—A. Initial: DA(C)=2 via B.

Suppose c(A,B) increases from 1 to 20.

Without poisoned reverse:

t₀: DA(B) becomes 20. DA(C) = min{20+1, 10+0} = 10 (direct). A sends.

But wait — initially DA(C)=2 via B. After cost increase: DA(B)=20, so DA(C)=min(20+1,10+0)=10. A sends DA(C)=10 to B.

B receives: DB(C) = min{1+10, 1+∞} = 11. B sends to A.

A receives: DA(C) = min{20+11, 10+0} = 10. No change.

Converges directly to DA(C)=10 (via direct A→C). No loop in this case because A has a direct alternative.

Example 4: Poisoned Reverse with Triangle Loop

Network: X—1—Y—1—Z—1—X. All link costs = 1.

Initially: DX=[0,1,2], DY=[1,0,1], DZ=[2,1,0] (X→Z via Y).

With poisoned reverse: Z advertises DZ(X)=∞ to Y (since Z reaches X via Y).

Now c(Y,X) changes from 1 to 20.

Y computes: DY(X) = min{20+0, 1+∞} = 20. Sends to Z.

Z computes: DZ(X) = min{1+20, 1+0} = 1 (direct). Z switches. Now Z no longer routes via Y, so Z sends DZ(X)=1 to Y (truthful now).

Y receives: DY(X) = min{20+0, 1+1} = 2 (via Z). Y converges.

Poisoned reverse prevented the loop! Only 3 iterations.
