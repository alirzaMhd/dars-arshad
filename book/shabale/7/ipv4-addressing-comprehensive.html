IPv4 Addressing & Subnets

Computer Networking (Kurose & Ross) — Chapter 4

IP Addresses Are Associated with Interfaces, Not Hosts

In IP terminology, every IP address is bound to an interface — the physical or logical connection point between a host/router and a link. A router with multiple links has multiple interfaces, each with its own IP address. A host typically has one interface (its Ethernet or Wi-Fi NIC), but can have multiple.

+---------------------------+ +---------------------------+ | Host A (223.1.1.1) | | Host B (223.1.1.2) | | Interface: eth0 | | Interface: eth0 | +-----|---------------------+ +-----|---------------------+ | | | 223.1.1.0/24 LAN | +--------------------------------------+ | +-------------|---------------------+ | Router R1 | | eth0: 223.1.1.4 | | eth1: 223.1.2.9 | | eth2: 223.1.3.7 | +----------------------------------+ Each interface of the router has a distinct IP.
Fundamental Size:
2³² = 4,294,967,296 ≈ 4.3 billion addresses
IPv4 uses 32-bit addresses, giving roughly 4.3 billion possible values.
Dotted-Decimal Notation:
193.32.216.9
Each 32-bit address is written as four decimal octets (8 bits each), separated by dots.
Common Mistake: Thinking an IP address "belongs to" a computer. An IP address is assigned to an interface, not the device itself. A router with 3 links has 3 different IP addresses — one per interface.

Example 1 — Identify All Interfaces

Consider a network with: Host A connects to switch S1, S1 connects to Router R1 via port eth0, R1 also has eth1 to Router R2, and R2 has eth0 to Host B.

Interfaces: Host A (1), S1 is a switch (no IP — Layer 2), R1 eth0 (1), R1 eth1 (1), R2 eth0 (1), Host B (1). Total: 5 IP interfaces.

Example 2 — Binary to Dotted-Decimal

Convert 11000000 10101000 00001111 00000001 to dotted-decimal.

11000000 = 192, 10101000 = 168, 00001111 = 15, 00000001 = 1.

Result: 192.168.15.1

Example 3 — Dotted-Decimal to Binary

Convert 10.0.0.255 to binary.

10 = 00001010, 0 = 00000000, 0 = 00000000, 255 = 11111111.

Result: 00001010.00000000.00000000.11111111

Broadcast Address:
255.255.255.255
Packets sent to this address are delivered to every host on the local subnet. All 32 bits set to 1.

Key Points

• IP address → interface, not host

• 32 bits total

• Dotted-decimal: 4 octets

• Broadcast: 255.255.255.255

• Routers have multiple IPs

Subnets — Grouping Interfaces by Network Prefix

A subnet is a group of interfaces that share the same network prefix and can communicate directly with each other without going through a router. Each subnet is isolated — crossing subnet boundaries requires an IP router.

A subnet is also called an IP network or simply a network in Internet literature [RFC 950].

Point-to-point links between routers also form subnets. For example, the interfaces connecting router R1 and router R2 on a link such as 223.1.9.0/24 constitute a subnet of their own, even though only two interfaces are attached.

Subnet Notation:
223.1.1.0/24
The /24 indicates that the first 24 bits are the network prefix. The remaining 8 bits identify hosts within that subnet.

Procedure to Identify Subnets

PROCEDURE DetermineSubnets(network_topology): FOR each router interface: DETACH the interface from the router FOR each attached switch or link: COLLECT all interfaces connected to that link IF those interfaces share a common prefix: DECLARE them as one subnet END FOR END FOR RETURN list of all discovered subnets END PROCEDURE

Rule of thumb: Replace each router with a cloud. Count the number of isolated network segments (clouds) — that's your subnet count.

Common Mistake: Assuming two hosts on the same Ethernet switch are always in the same subnet. They are only in the same subnet if they share the same network prefix AND their interfaces can reach each other without a router.
Example 1 — Three Router Network

Network: Host A (223.1.1.1) ↔ Switch S1 ↔ Router R1 (223.1.1.4 eth0). R1 eth1 (223.1.2.9) ↔ Router R2 (223.1.2.8 eth0). R2 eth1 (223.1.3.7) ↔ Switch S2 ↔ Host B (223.1.3.1).

Subnets:

• Subnet 1: 223.1.1.0/24 (Host A, R1 eth0)

• Subnet 2: 223.1.2.0/24 (R1 eth1, R2 eth0) — point-to-point link

• Subnet 3: 223.1.3.0/24 (R2 eth1, Host B)

Total: 3 subnets

Example 2 — House Analogy

Imagine 3 houses on the same street. Each house has its own router. Within a house, all devices (phones, laptops) share the same subnet (e.g., 192.168.1.0/24). Devices in different houses are on different subnets (192.168.2.0/24, 192.168.3.0/24) and must go through their respective routers to communicate.

3 subnets — one per house

Example 3 — Campus Network

A university has: Admin building (10.0.1.0/24), CS department (10.0.2.0/24), Library (10.0.3.0/24). Each building has its own router connected to a campus backbone. Each building's internal switch connects its own hosts.

3 subnets — each building is a separate broadcast domain

CIDR — Classless Inter-Domain Routing

CIDR (pronounced "cider") replaced the rigid classful addressing scheme in the mid-1990s. It generalizes the notion of subnetting by allowing any prefix length, expressed as a.b.c.d/x where x is the number of bits in the network prefix.

CIDR Notation:
a.b.c.d/x
The first x bits are the network prefix; the remaining (32 − x) bits identify the host within that network.
Example:
200.23.16.0/20
Network prefix is 20 bits. Host identifier is 12 bits. This gives 2¹² = 4096 total addresses, of which 4094 are usable.

Algorithm: Determine Network Prefix from CIDR Notation

PROCEDURE GetNetworkAddress(ip, prefix_len): subnet_mask = (0xFFFFFFFF << (32 - prefix_len)) & 0xFFFFFFFF network = ip & subnet_mask broadcast = ip | (~subnet_mask & 0xFFFFFFFF) RETURN (network, broadcast, subnet_mask) END PROCEDURE PROCEDURE IsSameSubnet(ip1, ip2, prefix_len): mask = (0xFFFFFFFF << (32 - prefix_len)) & 0xFFFFFFFF RETURN (ip1 & mask) == (ip2 & mask) END PROCEDURE
Example 1 — Find Network and Broadcast

Given 192.168.10.50/24:

Prefix length = 24 → mask = 255.255.255.0

Network = 192.168.10.0 (AND ip with mask)

Broadcast = 192.168.10.255 (OR ip with inverted mask)

Usable range: 192.168.10.1 – 192.168.10.254

Example 2 — Same Subnet Check

Are 10.20.30.1/20 and 10.20.40.1/20 on the same subnet?

Mask = 255.255.240.0 (20 bits)

10.20.30.1 AND mask = 10.20.16.0

10.20.40.1 AND mask = 10.20.32.0

No — they are on different subnets (10.20.16.0/20 vs 10.20.32.0/20)

Example 3 — CIDR Block Allocation

An ISP is allocated 200.23.16.0/20. How many /24 subnets can it create?

/20 prefix = 12 bits for hosts (32−20 = 12).

Each /24 uses 8 bits for hosts (32−24 = 8).

Number of /24 subnets = 2^(24−20) = 2⁴ = 16 subnets

Each /24 subnet has 254 usable addresses.

Classful Addressing — The Original Scheme

The original IP design divided the 32-bit address space into fixed-size classes. The first few bits of an address determined its class, which in turn dictated the split between network prefix and host identifier. This rigid scheme led to severe address depletion.

Class A:
/8 prefix (255.0.0.0)
First bit = 0. Range: 0.0.0.0 – 127.255.255.255. 128 networks, ~16M hosts each.
Class B:
/16 prefix (255.255.0.0)
First bits = 10. Range: 128.0.0.0 – 191.255.255.255. ~16K networks, ~65K hosts each.
Class C:
/24 prefix (255.255.255.0)
First bits = 110. Range: 192.0.0.0 – 223.255.255.255. ~2M networks, 254 hosts each.

Comparison: Classful vs CIDR

Common Mistake: Confusing a Class C address (which always starts with bits "110") with a /24 CIDR prefix. Under CIDR, any address can have any prefix length. A 10.0.0.0/24 is a valid CIDR block even though 10.x.x.x would be Class A under the old scheme.
Example 1 — Identify Class

What class does 130.50.20.1 belong to?

First octet = 130. In binary: 10000010. The first two bits are "10" → Class B (/16).

Example 2 — Waste Illustration

A company needs 300 IP addresses. Under classful: Class C (/24) gives 254 (too few), Class B (/16) gives 65,534 (massive over-allocation). They'd waste 65,234 addresses.

Under CIDR: They get a /23 block with 510 usable addresses — only 210 wasted instead of 65,234.

Example 3 — The 2,000-Host Problem

Consider an organization that needs 2,000 IP addresses. Under classful addressing:

• Class C (/24) provides only 254 addresses — too few.

• Class B (/16) provides 65,534 addresses — gross over-allocation.

The organization would be assigned a Class B block, wasting more than 63,000 addresses. This kind of waste across many organizations led to rapid depletion of the Class B address space and was a key motivation for CIDR.

Example 4 — Classful Range Detection

Classify each: 15.0.0.1, 172.16.0.1, 200.1.1.1, 224.0.0.1.

• 15 → 0xxxxxxx → Class A

• 172 → 10xxxxxx → Class B

• 200 → 110xxxxx → Class C

• 224 → 1110xxxx → Class D (multicast)

Class Detection

Class A: 0xxx | 0–127

Class B: 10xx | 128–191

Class C: 110x | 192–223

Class D: 1110 | 224–239

Class E: 1111 | 240–255

Why Classful Failed

• Too few Class Bs (16K)

• Too many small Class Cs (2M)

• Organizations hoarded Class Bs

• Routing tables exploded

→ CIDR fixed all this

Route Aggregation (Summarization)

Route aggregation (aka route summarization or prefix aggregation) allows a single CIDR prefix to represent a block of multiple more-specific prefixes. This shrinks routing tables dramatically — a core design goal of CIDR.

Aggregation Principle:
200.23.16.0/20 → aggregates 8 × /23 blocks
An ISP holding 200.23.16.0/20 can subdivide it into 8 equal /23 blocks and still advertise just one /20 route.

Algorithm: Longest Prefix Matching

PROCEDURE LongestPrefixMatch(routing_table, destination_ip): best_match = null best_len = 0 FOR EACH entry IN routing_table: IF (destination_ip & entry.mask) == entry.network: IF entry.prefix_len > best_len: best_len = entry.prefix_len best_match = entry END IF END FOR RETURN best_match.next_hop END PROCEDURE

An ISP owns 200.23.16.0/20. It divides this into 8 equal /23 blocks:

Example 3 — Aggregating Discontiguous Blocks

Can 10.1.0.0/24 and 10.2.0.0/24 be aggregated?

Check: 10.1.0.0 in binary = 00001010.00000001.00000000.00000000

10.2.0.0 in binary = 00001010.00000010.00000000.00000000

First 15 bits match (00001010.0000000), but bit 16 differs (1 vs 2).

They can be aggregated as 10.0.0.0/13 plus specific /24 routes within, but the minimal single block covering both is 10.0.0.0/14 (which also includes 10.0.0.0/24 and 10.3.0.0/24).

Best aggregation: 10.0.0.0/14 — though this may include unintended ranges.

Example 4 — Fly-By-Night-ISP and ISPs-R-Us Merger

Suppose Fly-By-Night-ISP owns CIDR block 200.23.16.0/20 and has allocated 200.23.18.0/23 to Organization 1. ISPs-R-Us owns block 199.31.0.0/16. When Fly-By-Night-ISP acquires ISPs-R-Us, Organization 1 (still using 200.23.18.0/23) is now a customer of ISPs-R-Us.

ISPs-R-Us must advertise both its own block (199.31.0.0/16) and Organization 1's block (200.23.18.0/23) to the rest of the Internet.

Other routers use longest prefix matching: the /23 route for Organization 1 is more specific than Fly-By-Night-ISP's /20 route. Packets destined for Organization 1 are forwarded to ISPs-R-Us, not Fly-By-Night-ISP, because the /23 prefix (23 bits) is longer than the /20 prefix (20 bits).

Common Mistake: Thinking aggregation requires contiguous address blocks within the parent prefix. The blocks must be contiguous and aligned to power-of-2 boundaries. You cannot aggregate 200.23.17.0/24 and 200.23.19.0/24 into 200.23.16.0/22 without also covering 200.23.16.0/24 and 200.23.18.0/24.
The broadcast address 255.255.255.255 delivers packets to all hosts on the same subnet. When a host sends a packet to 255.255.255.255, every host on the local subnet receives it. This address has all 32 bits set to 1.
