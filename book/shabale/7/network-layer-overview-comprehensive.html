Network Layer Overview

Computer Networking (Kurose & Ross) — Chapter 4

Forwarding vs Routing

The network layer has two core functions: forwarding (data plane) and routing (control plane). Although they work together, they operate at different timescales and involve different mechanisms.

Forwarding Definition:
packet arrives → lookup forwarding table → send to output port
Router-local action: moving a packet from an input link interface to the appropriate output link interface based on the destination address.
Routing Definition:
graph G(N,E) → compute paths → populate forwarding tables
Network-wide logic: determining the route taken by packets from source to destination using routing algorithms.

Terminology Note: Among networking researchers and practitioners, forwarding and switching are used interchangeably.

Packet Switch Definition:
packet switch = router (L3) ∪ link-layer switch (L2)
Packet switch is a general term encompassing both routers (network-layer / Layer 3 devices) and link-layer switches (Layer 2 devices). Routers make forwarding decisions based on network-layer header fields (e.g., IP destination address); link-layer switches forward based on link-layer frame fields (e.g., MAC address).

Worked Examples

Example 1: Table Lookup

A router receives a packet with destination IP 192.168.1.57. Its forwarding table contains:

Destination Range          Output Port
192.168.1.0/24             Port 3
10.0.0.0/8                 Port 1
0.0.0.0/0                  Port 2 (default)

Forwarding decision: The router performs a longest prefix match. The destination 192.168.1.57 falls within 192.168.1.0/24 (24-bit prefix matches). The router forwards the packet to Port 3.

Note: The /24 prefix is more specific than /0, so it takes priority.

Example 2: Routing Algorithm — Distance Vector

Three routers A, B, C are connected in a line: A—B—C. Link costs: A→B = 2, B→C = 3. Using the Bellman-Ford equation:

Bellman-Ford Equation:
dₓ(y) = minᵥ { c(x,v) + dᵥ(y) }
The least-cost path from x to y is the minimum over all neighbors v of (cost to v + cost from v to y).

Compute: dA(C) = min{ c(A,B) + dB(C) } = 2 + 3 = 5. Path: A → B → C.

Forwarding table at A: destination C → output port toward B.

Example 3: Longest Prefix Match

Forwarding table entries:

Prefix            Output Port
200.10.0.0/16     Port 1
200.10.1.0/24     Port 2
200.10.1.128/25   Port 3

Incoming packet: destination 200.10.1.130

Binary check: 200.10.1.130 = 11001000.00001010.00000001.10000010

/25 prefix 200.10.1.128 = ...10000000 — first 25 bits match. /24 and /16 also match, but /25 is longest.

Forward to Port 3. This illustrates why longest prefix match is used — it gives the most specific route.

Common Mistake: Students often assume the router checks entries in order and takes the first match. In practice, routers evaluate ALL matching prefixes and select the longest (most specific) one, not the first listed.

Key Points

• Forwarding = per-packet, local

• Routing = path computation, global

• Forwarding table = input for forwarding

• Routing algorithm = input for routing table

Complexity

Forwarding: O(log n) (binary search on prefix)

Forwarding (TCAM): O(1)

Routing (LS): O(n²) (Dijkstra)

Routing (DV): O(n · k) per iteration

Data Plane & Control Plane

The network layer is logically split into two planes. The data plane handles per-packet processing (fast path). The control plane handles routing logic and forwarding table population (slow path).

Data Plane Function:
input port → lookup & switching → output port
Every router performs data plane functions locally on each arriving packet.
Control Plane Function:
routing protocol ←→ neighbors → compute routes → update forwarding table
Determines how routing tables are computed and maintained.
Routing Algorithm Communication:
routerₐ ←[routing messages (routing protocol)]→ routerᵦ
The routing algorithm function in one router communicates with the routing algorithm function in other routers by exchanging routing messages containing routing information according to a routing protocol. This distributed exchange is how routers collectively build a consistent view of the network topology and compute forwarding tables.

Worked Examples

Example 1: Traditional Router — OSPF

Routers R1, R2, R3 run OSPF (link-state routing). Each router:

  1. Broadcasts its link-state advertisements (LSAs) to all neighbors via flooding
  2. Builds a complete topology map of the network (link-state database)
  3. Runs Dijkstra's algorithm locally to compute shortest paths
  4. Populates its own forwarding table based on computed paths

Each router independently computes the same routes — this is the per-router control approach.

Common Mistake: Many think the control plane is "one thing." In the traditional approach, the control plane runs inside each router, not on a separate server. Each router is both a data plane and control plane device.

Example 2: SDN — Remote Controller

In an SDN network with 4 switches and a remote controller:

Controller computes forwarding tables:
  - Receives topology info from switches
  - Runs routing algorithm centrally
  - Installs flow entries via OpenFlow protocol

Switch behavior:
  - Match packet header fields vs flow table
  - If match: apply action (forward, drop, modify)
  - If no match: query controller (or drop)

Switch S1 forwards packets without running any routing protocol. It simply follows the controller's instructions. This separates the control plane (in the controller) from the data plane (in the switches).

Example 3: Hybrid Scenario — Failure Handling

Link between R2 and R3 fails. Compare behavior:

StageTraditional (OSPF)SDN
1. DetectionR2 and R3 detect via hello timeoutSwitch detects link down
2. NotificationFlood LSA to all routersSend status to controller
3. RecomputeEach router runs DijkstraController recomputes once
4. UpdateEach router updates its own tableController pushes new flow entries
5. ConvergencePropagation delay × N routersController latency + switch updates

SDN convergence can be faster because only one node (the controller) recomputes routes, but it introduces a single point of failure risk.

Key Points

• Data plane = fast path, HW accelerated

• Control plane = slow path, SW based

• Traditional = distributed control plane

• SDN = centralized control plane

• OpenFlow: standard protocol for SDN

Complexity

Traditional convergence: O(n · d) (flooding delay)

SDN convergence: O(c + n)

Dijkstra (per-router): O(n²)

Dijkstra (centralized): O(n²) once

Network Service Models

A network service model defines the end-to-end delivery characteristics that the network guarantees for packets sent between hosts. Different architectures offer different service models.

Best-Effort Service (Internet):
P(delivery) < 1, no delay bound, no bandwidth guarantee, no ordering guarantee
The Internet's network layer provides no guarantees at all — packets may be lost, delayed arbitrarily, arrive out of order, or be duplicated. There is no reservation or admission control.

Kurose & Ross: "It might appear that best-effort service is a euphemism for no service at all." Yet the combination of the Internet's basic best-effort service with adequate bandwidth provisioning and bandwidth-adaptive application-level protocols like DASH (Dynamic Adaptive Streaming over HTTP, Section 2.6.2) has proven to be "good enough" for amazing applications including Netflix, Skype, and FaceTime.

ATM Service Categories:
CBR: constant bit rate | VBR: variable bit rate | ABR: available bit rate | UBR: unspecified bit rate
ATM (Asynchronous Transfer Mode) provides multiple service classes with different guarantee levels.
ATM Guarantees [Black 1995]:
guaranteed in-order delivery ∧ bounded delay ∧ guaranteed minimal bandwidth
The ATM network architecture [Black 1995, ATM: Foundation for Broadband Networks] provides per-connection guarantees including in-order delivery of cells, bounded end-to-end delay, and guaranteed minimal bandwidth through connection admission control and resource reservation.

Worked Examples

Example 1: Best-Effort Packet Delivery

A video streaming application sends 1000 packets per second over the Internet. The network provides best-effort service.

Scenario: During congestion at router R, the buffer overflows. 30 packets are dropped in one second. The remaining 970 packets experience varying delays: some arrive in 10 ms, some in 200 ms, and 5 arrive out of order.

Analysis: This behavior is completely acceptable under best-effort service. The network made no promises about delivery, delay, ordering, or bandwidth. The application must handle all of these at the transport or application layer (e.g., using TCP for reliability, buffering for delay jitter).

Common Mistake: Students often think "best-effort" means "the network tries hard to deliver." In networking, best-effort means the network provides no guarantees whatsoever. A best-effort network is allowed to drop every packet — the name refers to lack of commitment, not effort level.

Example 2: ATM CBR — Circuit Emulation

A telephone company uses ATM CBR to carry a T1 (1.544 Mbps) voice trunk over an ATM network.

Parameters:
  Peak Cell Rate (PCR) = 3642 cells/sec (≈ 1.544 Mbps / 424 bits per cell)
  Cell Delay Variation Tolerance (CDVT) = small
  Service class: CBR

Guarantees:
  - Bandwidth: 1.544 Mbps (cells arrive at constant rate)
  - Delay bound: end-to-end delay < 5 ms (for voice quality)
  - Cell loss ratio: < 10⁻⁶
  - Ordering: cells delivered in sequence

Result: The ATM network reserves resources along the path to ensure these guarantees. Admission control blocks new flows if resources are insufficient.

CBR provides circuit-like quality over a packet-switched network.

Example 3: Intserv Guaranteed Service — Token Bucket

A flow has a token bucket with rate r = 2 Mbps and bucket size b = 10 KB. It reserves R = 4 Mbps on a router. Packets have max size M = 1500 bytes, peak rate p = 6 Mbps.

Delay Bound Calculation:
d_max = (b - M) / R * (p - R) / (p - r) + M / R
Where b = bucket size, M = max packet, R = reserved rate, p = peak rate, r = token rate.

Compute:

b - M = 10000 - 1500 = 8500 bytes = 68000 bits

(p - R) / (p - r) = (6 - 4) / (6 - 2) = 2 / 4 = 0.5

First term: 68000 / 4Mbps × 0.5 = 0.017 × 0.5 = 0.0085 s = 8.5 ms

Second term: M / R = 1500 × 8 / 4Mbps = 12000 / 4000000 = 0.003 s = 3 ms

d_max = 8.5 + 3 = 11.5 ms — this is the worst-case queuing delay guaranteed by Intserv for this flow.

Service Model Selection Guide

Use Best-Effort (Internet)

• Web browsing, email, file transfer

• Applications that can tolerate delay/loss

• When simplicity & scalability matter

Use CBR (ATM) or Intserv

• Real-time voice/video

• Circuit emulation

• When delay bounds are critical

Use ABR (ATM)

• Data applications needing min rate

• Adaptive applications

• When feedback-based flow control helps

Use Controlled Load (Intserv)

• Adaptive real-time applications

• When "good as best-effort under light load" is sufficient

Key Points

• Internet = best-effort only

• ATM offers 4 service categories

• Intserv adds guaranteed + controlled load

• Best-effort: no guarantees at all

• Guaranteed service: delay-bound math

Complexity

Best-effort: O(1) per packet

ATM per-flow: O(n) flows

Intserv RSVP: O(f) state per router

Admission control: O(k) checks

Forwarding vs Routing

Forwarding: packet → port lookup (data plane, ns scale)

Routing: compute path = forwarding table (control plane, s scale)

Key quote: "Forwarding is like a train switching tracks; routing is like planning the railway network."

Traditional vs SDN

Traditional: each router runs its own routing algorithm → populates own forwarding table

SDN: remote controller computes routes → pushes forwarding tables to switches via OpenFlow

Best-Effort Service

No guarantees on: delivery ✓ delay ✓ bandwidth ✓ ordering ✓

All five dimensions are best-effort only

Used by the global Internet

CBR: constant rate, tight guarantees (voice)

VBR: variable rate, avg guarantees (video)

ABR: min rate guaranteed, feedback control

UBR: no guarantees (like best-effort)

Intserv Service Models

Guaranteed: bounded delay, no loss, firm reservation

Controlled Load: emulates unloaded network behavior, softer guarantees
