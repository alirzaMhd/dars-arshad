Switching Techniques

Computer Networking (Kurose & Ross) — Chapter 4: The Network Layer

Switching via Memory

Core Concept: The earliest routers used switching via memory, where the CPU controlled the entire switching process. When a packet arrives at an input port, it is copied into the processor memory via an interrupt, and the CPU then forwards it to the appropriate output port.
Throughput Limit:
Maximum Throughput = Bus Speed / 2
The shared system bus must carry each packet twice (input port → memory → output port), halving the effective throughput.

How It Works

  • Step 1: Packet arrives at input port line card.
  • Step 2: Input port signals the CPU via an interrupt.
  • Step 3: CPU copies the packet from the input port into processor memory.
  • Step 4: CPU performs lookup to determine output port.
  • Step 5: CPU copies the packet from memory to the output port buffer.
  • Step 6: Output port transmits the packet onto the outgoing link.
⚠ Common Mistake: In switching-via-memory, the packet crosses the system bus twice (input → memory, then memory → output). Many students incorrectly assume it crosses the bus only once. This "double crossing" limits throughput to half the bus bandwidth.

Quick Reference Card

Scalability Poor — CPU becomes bottleneck

Worked Examples

Example 1: Throughput Calculation (64-byte packets)

Given: A router uses switching via memory. The system bus speed is 800 Mbps. Packets are 64 bytes each.

Find: Maximum throughput and maximum packet rate.

Solution:

1. Throughput limit = B/2 = 800 / 2 = 400 Mbps

2. Packet size = 64 bytes × 8 = 512 bits

3. Max packet rate = 400 Mbps / 512 bits = 781,250 pps

Note: The actual rate is lower because CPU lookup time adds overhead not captured in raw throughput.

Example 2: Impact of Packet Size on Efficiency

Given: Two scenarios with B = 1 Gbps bus — Scenario A uses 40-byte packets, Scenario B uses 1500-byte packets.

Find: Maximum throughput for each scenario (bus crossing limit).

Solution:

1. B/2 limit = 500 Mbps for both (bus speed, not packet-size dependent)

2. Max packet rate (40-byte): 500 Mbps / (40×8) = 500e6 / 320 = 1,562,500 pps

3. Max packet rate (1500-byte): 500 Mbps / (1500×8) = 500e6 / 12000 = 41,667 pps

Small packets dominate CPU overhead (per-packet processing cost).

Example 3: Modern Hybrid Approach

Scenario: A modern router uses switching-via-memory but lookup is performed on the line card (not the central CPU).

Given: Line card takes 1 μs for lookup. Memory copy into CPU memory takes 2 μs per 1000 bytes. Bus speed is 10 Gbps.

Find: Maximum throughput for 1000-byte packets.

Solution:

1. Time to copy into memory: 2 μs (per 1000 bytes)

2. Time to copy out to output: 2 μs

3. Time per packet = 1 + 2 + 2 = 5 μs

4. Max packet rate = 1 / 5e-6 = 200,000 pps

5. Throughput = 200,000 × 1000 × 8 = 1.6 Gbps

The B/2 = 5 Gbps bus limit is not the bottleneck here — CPU copy overhead dominates in this design.

Modern RAM-Based Switching

Key Concept: Some modern routers switch via memory, but a major difference from early routers is that the lookup of the destination address and the storing of the packet into the appropriate memory location are performed by processing on the input line cards. In some ways, routers that switch via memory look very much like shared-memory multiprocessors, with the processing on a line card switching (writing) packets into the memory of the appropriate output port. For example, Cisco's Catalyst 8500 series switches internally switch packets via a shared memory.

Key Takeaways

• Throughput capped at B/2

• CPU handles every packet

• Bus is shared between all I/O

Exam Tips

• Remember: 2 bus crossings

• B/2 is theoretical max

• Lookup overhead adds latency

Switching via Bus

Core Concept: In switching via a shared bus, the input port transfers the packet directly to the output port over a common bus — without involving the CPU. The input port prepends an internal header label to identify the output port, and only one packet can traverse the bus at a time.
Bus Throughput Limit:
Maximum Throughput ≤ Bus Bandwidth
Unlike switching-via-memory, the packet crosses the bus only once. However, the bus is shared — only one transfer at a time.

How It Works

  • Step 1: Packet arrives at input port line card.
  • Step 2: Input port performs lookup (locally on line card or distributed).
  • Step 3: Input port prepends an internal label identifying the target output port.
  • Step 4: Input port places the labeled packet on the shared bus.
  • Step 5: All output ports receive the packet; only the matching output port accepts it.
  • Step 6: Output port strips the label and transmits the packet.
⚠ Common Mistake: Many students think switching-via-bus supports parallel transfers. In reality, the shared bus is a single resource — only one packet at a time can use it. The prepended label is NOT a routing/forwarding table — it's the output port identifier. Do not confuse the two.

Quick Reference Card

Speed Medium (bus bandwidth limit)

CPU Role Minimal (lookup on line card)

Scalability Moderate — bus bandwidth plateaus

Real Example Cisco 6500 (32 Gbps backplane)

Worked Examples

Example 1: Cisco 6500 Backplane Utilization

Given: Cisco 6500 switch has a 32 Gbps shared backplane (bus). It services 16 ports, each capable of 1 Gbps full-duplex.

Find: Can all 16 ports simultaneously transmit at full line rate? What is the maximum aggregate throughput?

Solution:

1. Full line rate aggregate = 16 × 1 Gbps = 16 Gbps

2. Backplane capacity = 32 Gbps

3. Since the bus is shared (one packet at a time), maximum switching throughput = 32 Gbps

4. 16 Gbps < 32 Gbps → Yes, all ports can run at full line rate simultaneously

But if the ports were upgraded to 10 Gbps each, aggregate demand would be 160 Gbps, exceeding the 32 Gbps backplane — the bus would become the bottleneck.

Example 2: One-Packet-at-a-Time Constraint

Given: A bus-based router with bus speed 10 Gbps. Three input ports (A, B, C) each have a 1000-byte packet to send to three different output ports (X, Y, Z).

Find: Total time to switch all three packets through the bus.

Solution:

1. Packet size = 1000 bytes × 8 = 8000 bits

2. Time per packet on bus = 8000 / 10e9 = 0.8 μs

3. Packets must go one at a time: A→X, then B→Y, then C→Z

4. Total time = 3 × 0.8 = 2.4 μs

Even though they go to different outputs, they cannot be transmitted in parallel over the shared bus.

Example 3: Bus Speed Bottleneck — Interface Upgrade

Given: A router has 8 line cards, each connected to a 40 Gbps link. The shared backplane bus runs at 160 Gbps. All 8 ports attempt to send at line rate simultaneously.

Find: What fraction of traffic can the backplane handle? What is the drop rate?

Solution:

1. Aggregate input demand = 8 × 40 = 320 Gbps

2. Bus capacity = 160 Gbps

3. Fraction served = 160 / 320 = 50%

4. Drop rate = 50% (the remaining 160 Gbps must be buffered or dropped)

This illustrates why high-end routers moved to crossbar switches — the shared bus cannot scale to terabit capacities.

Key Takeaways

• One packet at a time on bus

• Internal label identifies destination port

• Bus speed is the limiting factor

Exam Tips

• Only 1 bus crossing (unlike memory)

• No CPU involvement in data path

• Label is NOT routing table entry

Bus Speed Limitations — Deep Dive

Maximum Bus Length (Electrical Constraint):
L_max = c / (2 × f × √ε_r)
Where c = speed of light, f = clock frequency, ε_r = dielectric constant of PCB material.

Practical limitations of bus-based switching:

  • Signal integrity: Higher frequencies require shorter traces — limits physical backplane size.
  • Fan-out: Every line card loads the bus electrically, degrading signal quality.
  • Arbitration delay: A bus arbiter must grant access; this adds latency as more ports contend.
  • Power consumption: Driving a shared bus at high frequencies consumes significant power.
  • Clock skew: Synchronizing all line cards on a shared bus becomes impractical beyond ~10 GHz.
⚠ Common Mistake: Students sometimes think bus speed can be increased indefinitely. Electrical constraints (trace length, signal integrity, clock skew) impose hard physical limits — typically topping out around 30–40 Gbps for practical router backplanes.

Commercial Implementation: Cisco 6500

The Cisco 6500 router [Cisco 6500 2020] internally switches packets over a 32-Gbps-backplane bus. This illustrates the practical limits of bus-based switching: while adequate for its era, the 32 Gbps shared backplane becomes a bottleneck as port speeds increase beyond 1 Gbps per port.

Switching via Interconnection Network (Crossbar)

Core Concept: A crossbar switch consists of 2N buses forming a grid connecting N input ports to N output ports. At each intersection, a crosspoint switch can be opened or closed. This design is non-blocking — any input can reach any output without interfering with other transfers, as long as no two inputs target the same output.
Crossbar Structure:
N × N Crossbar = N horizontal buses + N vertical buses = 2N buses total
Each input connects to a horizontal bus; each output connects to a vertical bus. Crosspoint switches at N² intersections.

How It Works

  • Step 1: Packet arrives at input port, lookup determines output port.
  • Step 2: The scheduling algorithm configures crosspoint switches.
  • Step 3: The crosspoint at the intersection of input bus i and output bus j is closed.
  • Step 4: Multiple input-output pairs can transfer simultaneously (no shared bus contention).
  • Step 5: After transfer, crosspoints are opened.
⚠ Common Mistake: "Non-blocking" does NOT mean every possible set of transfers can proceed simultaneously. If two inputs both want to send to the same output, only one can proceed — this is "output contention" or "head-of-line blocking." The non-blocking property applies to the switch fabric itself, not the output ports.

Worked Examples

Example 1: Parallel Transfers in a 4×4 Crossbar

Given: A 4×4 crossbar switch. The following packets are queued:

Input 1 → Output 3, Input 2 → Output 1, Input 3 → Output 4, Input 4 → Output 2

Find: Can all four transfers proceed simultaneously?

Solution:

1. Check output contention: outputs are 3, 1, 4, 2 — all distinct.

2. Check input contention: inputs are 1, 2, 3, 4 — all distinct.

3. Since no output is targeted by more than one input, all four transfers can proceed in parallel.

Achieving 4× the throughput of a bus-based switch in the same time!

Example 2: Head-of-Line Blocking (Output Contention)

Given: A 4×4 crossbar. Queue state:

Input 1: [→ Output 2, → Output 3]
Input 2: [→ Output 2]
Input 3: [→ Output 1]
Input 4: [→ Output 4]

Find: Show which transfers happen in the first time slot and which are blocked.

Solution:

1. Both Input 1 and Input 2 want Output 2 → only one can go.

2. A possible schedule:

  • Input 1 → Output 2 (wins arbitration)

  • Input 3 → Output 1

  • Input 4 → Output 4

3. Input 2 is blocked (head-of-line blocking — its packet for Output 2 cannot proceed)

4. Simultaneous transfers: 3 out of 4

Virtual Output Queues (VOQs) solve this by maintaining separate queues per destination at each input.

Example 3: Cisco 12000 Crossbar Scaling

Given: Cisco 12000 (GSR) uses a crossbar switch fabric [Cisco 12000 2020] with per-line-card speed of 2.5 Gbps. The chassis supports up to 15 line cards.

Find: Total aggregate switching capacity and the number of crosspoint switches required.

Solution:

1. Each line card: 2.5 Gbps × 2 (bi-directional) = 5 Gbps per card

2. Maximum switching capacity = 15 × 2.5 Gbps × 2 (full duplex) = 75 Gbps

3. Crosspoint switches = N² = 15² = 225 crosspoints

4. Total buses = 2N = 30 buses

Modern routers like Cisco CRS use three-stage Clos networks to scale to multi-terabit capacities while remaining non-blocking.

Advanced: Three-Stage Non-Blocking (Clos Network)

Concept: More sophisticated interconnection networks use multiple stages of switching elements. For example, the Cisco CRS router employs a three-stage non-blocking Clos architecture [Tobagi 1990]. A three-stage non-blocking network can support far more ports than a single crossbar by breaking the fabric into smaller crossbar stages, keeping the overall design strictly non-blocking (any input to any output without rearranging existing connections).
Clos Network Parameters:
r × (m × k) — r middle-stage switches, each with m inputs and k outputs
A three-stage Clos (r, m, k) is strictly non-blocking if m ≥ 2n - 1 where n = number of inputs per first-stage switch.

Parallel Switching Fabrics

Concept: To exceed single-fabric throughput limits, a router's switching capacity can be scaled by running multiple switching fabrics in parallel. An input port breaks a packet into K smaller chunks, and sends ("sprays") the chunks through K of these N switching fabrics to the selected output port, which reassembles the K chunks back into the original packet. This technique multiplies throughput by the number of parallel fabrics.
Parallel Fabric Spraying

Mechanism: Input port divides a 1500-byte packet into K = 4 chunks of 375 bytes each. These 4 chunks are sprayed across 4 different parallel switch fabrics to the same output port. The output port reassembles the chunks in order, reconstructing the original packet.

Benefit: Throughput multiplier = N (number of parallel fabrics). For example, 4 parallel fabrics yield 4× the throughput of a single fabric, assuming even load distribution.

Parallel Fabric Throughput:
Total Throughput = N × Throughput_per_fabric
Where N = number of parallel switch fabrics. Each fabric handles a portion of the traffic in a round-robin or load-balanced manner.

⚠ Exam Warning: When asked "Why did routers move from bus to crossbar?", the three key reasons are: (1) Parallelism — crossbar allows multiple simultaneous transfers, (2) Scalability — bus speeds hit physical limits (~30-40 Gbps), (3) Non-blocking property — crossbar avoids single-bus contention. Formula Summary

Switching via Memory:
R_max = B / 2
B = system bus bandwidth (bps). The factor of 1/2 comes from crossing the bus twice.
Switching via Bus:
R_max = B
B = bus bandwidth. Single bus crossing per packet, but sequentially.
Switching via Crossbar (ideal):
R_max = N × R_port
N = number of input ports. All N inputs can simultaneously transmit to N distinct outputs at port line rate.
Clos Non-Blocking Condition:
m ≥ 2n − 1
For a three-stage Clos network, the middle stage must have at least 2n−1 switches to guarantee strict non-blocking, where n = number of first-stage inputs.
Parallel Fabric Throughput:
R_total = M × R_single_fabric
M = number of parallel switch fabrics. Packet is divided into cells and sprayed across fabrics.
