Principles of Congestion Control

Transport Layer — Section 3.6 | Causes, Costs & Approaches

Scenario 1: Two Senders, Infinite Buffers, Shared Link

Two hosts (A and B) each send at rate lin through a router with infinite buffers over a shared outgoing link of capacity R.

Per-Connection Throughput Limit
lout = min(lin, R/2)
Throughput is capped at R/2 because the two connections equally share the link capacity.

Key Behaviors

• When lin < R/2: throughput = lin

• When lin > R/2: throughput = R/2

• Aggregate throughput ≤ R

• Infinite buffers → no packet loss

Cost: Queuing Delay

• As lin → R/2, delay grows without bound

• When lin > R/2, queue length → ∞

• Average delay → ∞

First cost of congestion: large delays

Key Insight: Even with infinite buffers (no loss), congestion is costly because it causes massive queuing delays. High throughput does not imply good performance.

Scenario 2: Finite Buffers + Retransmissions

Same as Scenario 1 but with finite router buffers and reliable connections that retransmit lost packets. The offered load l'in includes both original data and retransmissions.

Offered Load
l'in = lin + retransmissions
The actual load placed on the network exceeds the original data rate due to retransmissions.

Three Cases

Case Description Max Throughput
Perfect Knowledge Sender knows when buffer is free; never loses packets R/2
Retransmit Only Lost Sender retransmits only when loss is certain (large timeout) R/3 (0.333R original + 0.166R retransmissions)
Premature Timeout Sender retransmits before ACK arrives (duplicate packets) R/4

Costs of Congestion

1. Retransmissions waste bandwidth

2. Duplicate packets consume link capacity

3. Throughput degrades from R/2 → R/3 → R/4

4. At λ′in = R/2: only 0.333R is original data; 0.166R is wasted retransmissions

Premature Timeout Penalty

Each packet forwarded ~2x on average

Effective capacity halved for useful data

As l'in → R/2, throughput → R/4

Common Mistake: Premature timeouts are worse than waiting longer for ACKs. Aggressive retransmission in congestion exacerbates the problem rather than solving it.

Scenario 3: Four Senders, Multihop Paths

Four hosts transmit over overlapping two-hop paths with finite buffers. Connections compete for buffer space at multiple routers.

Throughput Collapse
lout → 0 as l'in → ∞
Unlike Scenario 2, throughput can actually decrease as offered load increases, leading to congestion collapse.

Why Throughput Decreases

• A–C traffic must traverse R1 then R2

• B–D traffic competes at both R1 and R2

• A–C arrival rate at R2 is bounded by R (R1→R2 link capacity)

• At high load, B–D packets crowd out A–C at R2

• In the limit as λin → ∞: an empty buffer at R2 is immediately filled by B–D, starving A–C

• A–C throughput goes to zero in limit of heavy traffic

Cost: Wasted Upstream Work

• R1 forwards A–C packets to R2

• R2 drops them (buffer full with B–D)

• All work done by R1 was wasted

• Transmission capacity used at each upstream link to forward the dropped packet is wasted — cascading inefficiency

• That capacity could have carried other traffic

Critical Point: Scenario 3 shows that uncoordinated senders can cause congestion collapse — adding more traffic reduces useful throughput. This is why congestion control is essential for network health.

Approaches to Congestion Control

Feature End-to-End Network-Assisted
Network layer support None required Routers provide explicit feedback
Congestion detection Inferred from loss/delay Explicit signals (ECN, choke packets)
Example protocols TCP Tahoe, Reno, CUBIC, Vegas, BBR ECN, DCTCP, DCQCN, ATM ABR (router informs sender of max supportable rate)

Feedback pathway ACKs and timeouts Direct choke or receiver-indicated

"Classic TCP" — End-to-End Congestion Control

Classic TCP [RFC 2581, RFC 5681] uses pure end-to-end congestion control based only on observed network behavior — no router support needed. Congestion is inferred from packet loss (timeout or three duplicate ACKs), and TCP decreases its window accordingly. This approach works in any network but reacts slowly since loss must occur before action is taken.

End-to-End Principle
Congestion inferred from observed behavior (loss/delay)
"Even the presence of network congestion must be inferred by the end systems based only on observed network behavior (for example, packet loss and delay)."

Network-Assisted Feedback Methods

Direct Feedback

Router sends choke packet directly to sender

"I'm congested!"

Used in: IBM SNA, DECnet

Fast but router must know sender's address

Receiver-Indicated

Router marks packet in transit

Receiver notifies sender via ACK

Used in: ECN (IP/TCP)

Takes 1 RTT for feedback loop

Evolution: While classic TCP uses pure end-to-end, modern protocols (ECN, DCTCP) blend both approaches for faster, more precise congestion response.

Worked Examples & Summary

Example 1 — Throughput Calculation (Scenario 1)

Setup: Link capacity R = 100 Mbps. Two senders. Infinite buffers.

Question: If each sender transmits at 40 Mbps, what is per-connection throughput?

Answer: lout = min(40, 50) = 40 Mbps. Total = 80 Mbps. All traffic delivered. Delay is moderate.

Question: If each sender transmits at 70 Mbps, what happens?

Answer: lout = min(70, 50) = 50 Mbps each. Total = 100 Mbps (full link utilization). But delay grows without bound because queues build up at R/2.

Example 2 — Retransmission Overhead (Scenario 2)

Setup: Link R = 10 Mbps. Original data rate lin = 4 Mbps. Because of premature timeouts, each packet is transmitted 1.5 times on average.

Question: What is the offered load l'in?

Answer: l'in = 4 × 1.5 = 6 Mbps. Throughput = 4 Mbps (original data). 2 Mbps (33%) is wasted on retransmissions.

If lin = 6 Mbps with same 1.5 factor, l'in = 9 Mbps. lout ≈ 3.33 Mbps (from R/3 curve). Only 3.33/9 = 37% efficiency.

Example 3 — Congestion Collapse (Scenario 3)

Setup: Four connections over two routers (Figure 3.47). All links R = 1 Gbps. lin = 500 Mbps per connection.

Question: Will the A–C connection achieve 500 Mbps throughput?

Answer: No. At R2, B–D traffic competes with A–C. A–C's arrival rate at R2 is at most 1 Gbps (the R1→R2 link), but B–D also sends up to 500 Mbps. With finite buffers, A–C gets squeezed. In the limit of high offered load, A–C throughput → 0.

Moral: Sending faster can actually reduce delivered throughput — the congestion collapse problem.

Example 4 — ECN vs End-to-End Latency

Setup: RTT = 100ms. A router becomes congested at t=0.

End-to-end approach: Buffer fills, packets drop. TCP sender detects loss at t=RTT (ACK timeout or duplicate ACKs). Not before t=100-200ms.

ECN approach: Router marks packet at t=0. Receiver sets ECE bit in ACK. Sender halves cwnd at t=RTT = 100ms. But congestion was signaled before loss, so no retransmission needed.

Advantage: ECN avoids retransmissions, saving both time and bandwidth. Critical for latency-sensitive applications.
