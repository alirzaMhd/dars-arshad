IEEE 802.11 Overview

The IEEE 802.11 standard, published in 1997, defines the specifications for Wireless Local Area Networks (WLANs). It operates in the 2.4 GHz ISM band and provides data rates of 1-2 Mbps.

Network Modes

Infrastructure Mode

In infrastructure mode, all wireless stations connect to a central Access Point (AP). The AP acts as a bridge between the wireless network and the wired network (typically Ethernet). All communication flows through the AP.

Example: Infrastructure Mode Setup

Scenario: An office with 5 laptops and 1 AP

Configuration: All laptops associate with the AP

Data Flow: Laptop A → AP → Laptop B

Range: Limited by AP coverage area

Ad-hoc Mode (Peer-to-Peer)

In ad-hoc mode, stations connect directly to each other without any AP. This is useful for temporary, spontaneous communication between devices in close proximity.

Example: Ad-hoc Mode Setup

Scenario: 3 laptops sharing files at a coffee shop

Configuration: No AP needed, direct connections

Data Flow: Laptop A ↔ Laptop B (direct)

Limitation: Limited range, no wired network access

Half-Duplex Operation

Wireless stations operate in half-duplex mode, meaning they cannot send and receive simultaneously. This is a fundamental limitation of wireless communication due to the shared medium.

Half-Duplex Constraint
Station cannot TX and RX at the same time
This is why collision detection (CSMA/CD) doesn't work in wireless
Key Point: Half-duplex operation is the primary reason CSMA/CA is used instead of CSMA/CD in wireless networks.

Terminal Problems

Hidden Terminal Problem

Occurs when two stations are both in range of an AP but out of range of each other. They cannot detect each other's transmissions, leading to collisions at the AP.

Example: Hidden Terminal

Setup: Station A and Station C are both within range of AP B, but A and C cannot hear each other

Problem: A and C transmit simultaneously → collision at B

Solution: RTS/CTS mechanism (covered in CSMA/CA section)

Exposed Terminal Problem

Occurs when a station is blocked from transmitting because it hears another station's transmission, even though its own transmission would not cause interference.

Example: Exposed Terminal

Setup: Station B transmits to AP A. Station C hears B and defers transmission

Problem: C could transmit to AP D without interfering, but defers unnecessarily

Impact: Reduced network throughput due to unnecessary waiting

Comparison
Hidden Terminal → Collision at Receiver
Exposed Terminal → Unnecessary Deferment at Sender

Why CSMA/CD Doesn't Work in Wireless

In wired Ethernet, CSMA/CD (Collision Detection) is used because stations can detect collisions while transmitting. However, in wireless networks, collision detection is impossible due to several reasons:

Half-Duplex
Cannot TX and RX simultaneously
Signal Strength
Transmitted signal drowns out incoming
Hidden Terminal
Cannot hear all other stations
Dynamic Range
Difficult to detect weak collisions
Key Insight: CSMA/CD relies on detecting collisions during transmission. In wireless, the transmitted signal is much stronger than any incoming signal, making collision detection impractical.

CSMA/CA (Collision Avoidance)

Instead of detecting collisions, wireless networks use collision avoidance. The goal is to prevent collisions before they occur rather than detecting and recovering from them.

CSMA/CA Mechanism

1. Listen to channel (Carrier Sense)
2. If channel is IDLE:
- Wait for DIFS (Distributed Inter-Frame Space)
- If still idle → Transmit
3. If channel is BUSY:
- Defer transmission
- After channel becomes idle → Wait DIFS
- Enter random backoff period
- Decrement backoff counter when channel idle
- Transmit when counter reaches 0
Example: CSMA/CA Process

Step 1: Station A wants to transmit, listens to channel

Step 2: Channel is idle, waits DIFS (50 μs)

Step 3: Channel still idle, starts transmission

Step 4: Station B also wants to transmit, hears A → defers

Step 5: After A finishes, B waits DIFS, then random backoff, then transmits

RTS/CTS Mechanism

The RTS/CTS (Request to Send / Clear to Send) mechanism helps solve the hidden terminal problem by reserving the channel before data transmission.

How RTS/CTS Works

Station A → RTS frame → AP
AP → CTS frame → Station A (and all other stations)
Station A → Data frame → AP
AP → ACK frame → Station A
Example: RTS/CTS Solves Hidden Terminal

Setup: Station A and Station C are hidden from each other but both in range of AP B

Without RTS/CTS: A and C transmit simultaneously → collision at B

With RTS/CTS:

1. A sends RTS to B

2. B sends CTS (heard by both A and C)

3. C hears CTS, defers transmission

4. A transmits data safely

RTS/CTS Overhead
RTS (20 bytes) + CTS (14 bytes) + Data + ACK
Worthwhile for large data frames (> threshold), adds overhead for small frames

NAV (Network Allocation Vector)

The NAV is a timer that indicates how long the channel will be busy. It is set using the duration field in RTS and CTS frames.

How NAV Works

1. Station A sends RTS with Duration = 300 μs
2. Station B (not the intended receiver) hears RTS
3. B sets its NAV timer to 300 μs
4. B will NOT transmit for 300 μs
5. Even if B cannot hear the CTS, it defers
Example: NAV Calculation

Given: RTS frame with Duration field = 200 μs

CTS frame: Duration = 200 μs - (RTS transmission time) - SIFS

Data frame: Duration = remaining time after CTS

Result: All stations in range set NAV and defer for the entire transaction

NAV Timer
NAV = Duration field value (in μs)
Stations cannot transmit while NAV > 0, providing virtual carrier sensing

Inter-Frame Spacing (IFS)

Different IFS values provide priority-based access to the channel. Higher priority traffic waits less time.

IFS Duration Use Case Priority
SIFS Shortest ACK, CTS Highest
PIFS Medium AP polling Medium
DIFS Longest Data frames Lowest
IFS Hierarchy
SIFS < PIFS < DIFS
Shorter IFS → Higher priority channel access
Example: ACK Priority

Why SIFS for ACK: ACK must be sent immediately after data reception

Process: Data received → Wait SIFS → Send ACK

Result: ACK gets channel before any other station can transmit

Backoff Algorithm

When the channel is busy, stations use a random backoff to reduce collision probability.

Backoff Time = Random(0, CW) × Slot Time

Where:
- CW = Contention Window (initially CWmin)
- Slot Time = Fixed time slot (typically 20 μs)
- Random() = Uniform random integer
Example: Backoff Calculation

Given: CWmin = 15, Slot Time = 20 μs

Random backoff: Choose random number from 0 to 15

If random = 7: Backoff time = 7 × 20 μs = 140 μs

After collision: Double CW (up to CWmax), re-randomize

Exponential Backoff
CW_new = min(CW_old × 2, CWmax)
After each collision, contention window doubles to reduce collision probability
