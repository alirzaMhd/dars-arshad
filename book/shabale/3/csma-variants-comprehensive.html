CSMA Variants

Carrier Sense Multiple Access — Complete Guide for 20/20 Exam

1-Persistent CSMA

In 1-persistent CSMA, a station with data to send first senses the channel. If the channel is idle, it transmits immediately with probability 1. If the channel is busy, it continuously senses until the channel becomes idle, then transmits immediately without delay.

Key Principle:
If idle → transmit (p=1)
If busy → wait, then transmit immediately when idle
Aggressive approach: always transmit when channel becomes free

Algorithm (Step-by-Step):

1
Station has data to send
2
Sense channel status
3
If idle → transmit immediately (probability = 1)
4
If busy → continuously sense until channel becomes idle
5
When channel becomes idle → transmit immediately
6
If collision detected → wait random backoff time, repeat from step 1
Example 1: Light Load Scenario

Station A wants to send data at time t=0

• Channel is idle → Station A transmits immediately

• Station B arrives at t=2 (during A's transmission)

• B senses channel → busy → waits continuously

• A finishes at t=5 → channel becomes idle

• B immediately transmits (probability = 1)

Result: No collision, B transmits at t=5

Example 2: Collision Scenario

Stations A and B both have data at t=0

• Both sense channel → idle

• Both transmit simultaneously → collision occurs

• Both detect collision after propagation delay

• Both wait random backoff time

• A waits 3 time units, B waits 7 time units

• A senses at t=3 → idle → transmits

• B senses at t=7 → idle → transmits

Result: Collisions resolved via random backoff

Example 3: Multiple Stations

4 stations (A, B, C, D) all have data at t=0

• All sense channel → idle

• All transmit simultaneously → collision

• Random backoff times: A=2, B=5, C=3, D=8

• t=2: A senses → idle → transmits

• t=3: C senses → busy (A transmitting) → waits

• t=5: B senses → busy (A transmitting) → waits

• t=5: A finishes → C and B sense idle → collision again

Result: Multiple collisions before all transmit successfully

Advantages

• Simple to implement

• Low delay when channel is idle

• High utilization under light load

• No wasted idle time

Disadvantages

• High collision rate under heavy load

• Multiple stations may transmit simultaneously

• Wasted bandwidth during collisions

• Performance degrades rapidly with load

Best Use Case

• Light network load

• Few active stations

• Simple network topology

• When low delay is critical

Complexity

Time: O(1) per transmission

Space: O(1)

Implementation: Simple

Overhead: Minimal

Exam Tip: 1-persistent is the most aggressive variant. Under heavy load, multiple stations waiting will all transmit simultaneously when the channel becomes free, causing repeated collisions. Remember: "1-persistent" means probability = 1 when idle.

Non-Persistent CSMA

In non-persistent CSMA, if the channel is busy when a station wants to transmit, the station does not continuously sense. Instead, it waits a random amount of time before sensing again. This reduces the probability of multiple stations colliding when the channel becomes free.

Key Principle:
If idle → transmit
If busy → wait random time, then sense again
Less aggressive: random wait reduces collision probability

Algorithm (Step-by-Step):

1
Station has data to send
2
Sense channel status
3
If idle → transmit immediately
4
If busy → generate random backoff time T
5
Wait time T, then sense channel again (go to step 2)
6
If collision detected → wait random backoff time, repeat from step 1
Example 1: Reduced Collision

Stations A and B both have data at t=0

• Both sense channel → idle

• Both transmit simultaneously → collision

• Both detect collision

• A generates random wait: 5 time units

• B generates random wait: 8 time units

• t=5: A senses → idle → transmits

• t=8: B senses → busy (A transmitting) → waits again

• B generates new random wait: 3 time units

• t=11: B senses → idle → transmits

Result: Only 1 collision (vs potentially multiple in 1-persistent)

Example 2: Channel Idle While Stations Wait

Station A transmits from t=0 to t=5

• Station B wants to send at t=2 → senses busy → waits 4 units

• Station C wants to send at t=3 → senses busy → waits 6 units

• A finishes at t=5 → channel idle

• B still waiting until t=6, C until t=9

• Channel idle from t=5 to t=6 → wasted time

Result: Channel idle while stations wait (trade-off for fewer collisions)

Example 3: Heavy Load Performance

10 stations all have data at t=0

• All sense channel → idle → all transmit → collision

• Each generates random wait time (1-10 units)

• Spread out over time → staggered transmissions

• Fewer simultaneous collisions than 1-persistent

Result: Better performance than 1-persistent under heavy load

Advantages

• Lower collision rate than 1-persistent

• Better performance under heavy load

• More efficient channel usage

• Staggered transmissions reduce collisions

Disadvantages

• Higher delay when channel becomes free

• Channel may be idle while stations wait

• More complex backoff mechanism

• Unpredictable response time

Best Use Case

• Heavy network load

• Many active stations

• When collision reduction is priority

• When delay tolerance is high

Complexity

Time: O(random) per wait

Space: O(1)

Implementation: Medium

Overhead: Moderate

Exam Tip: Non-persistent trades delay for fewer collisions. The channel may be idle while stations are in their random wait period. This is acceptable when collision reduction is more important than immediate response. Remember: "Non-persistent" means not persistently sensing.

P-Persistent CSMA

P-persistent CSMA is a compromise between 1-persistent and non-persistent. When the channel is idle, the station transmits with probability p and defers with probability (1-p). This probabilistic approach balances between aggressive and conservative transmission strategies.

Key Principle:
If idle → transmit with probability p, defer with (1-p)
If busy → wait until idle, then apply same probability
Probabilistic approach: p controls aggressiveness

Algorithm (Step-by-Step):

1
Station has data to send
2
Sense channel status
3
If idle → generate random number r ∈ [0,1]
4
If r ≤ p → transmit; otherwise → wait one time slot, go to step 2
5
If busy → wait until channel is idle, then go to step 3
6
If collision detected → wait random backoff time, repeat from step 1
Probability Values:
p = 0.5 → balanced approach
p = 0.1 → conservative (fewer collisions, higher delay)
p = 0.9 → aggressive (more collisions, lower delay)
Adjust p based on network load and requirements
Example 1: p = 0.5 (Balanced)

Station A senses idle channel at t=0

• Generates random r = 0.3

• 0.3 ≤ 0.5 → transmits

Station B senses idle channel at t=0

• Generates random r = 0.7

• 0.7 > 0.5 → defers, waits 1 slot

• t=1: B senses channel

• If A still transmitting → B waits

Result: 50% chance of deferral reduces collision probability

Example 2: p = 0.1 (Conservative)

5 stations all sense idle channel

• Each generates random r ∈ [0,1]

• Probability any single station transmits: 0.1

• Probability all 5 defer: (0.9)^5 ≈ 0.59

• Probability exactly 1 transmits: 5 × 0.1 × (0.9)^4 ≈ 0.33

• Probability 2+ transmit: 1 - 0.59 - 0.33 = 0.08

Result: Only 8% collision probability (vs ~100% in 1-persistent)

Example 3: p = 0.9 (Aggressive)

3 stations sense idle channel

• Each generates random r ∈ [0,1]

• Probability any single station transmits: 0.9

• Probability all 3 transmit: (0.9)^3 ≈ 0.73

• High collision probability under load

Result: Similar to 1-persistent but with slight reduction

Advantages

• Adjustable aggressiveness via p

• Better than 1-persistent under load

• Flexible for different network conditions

• Tunable performance trade-off

Disadvantages

• More complex implementation

• Requires careful p selection

• Still has some collisions

• Random number generation overhead

Best Use Case

• Variable network load

• When tunable behavior is needed

• Slotted systems (time slots)

• When balance is required

Complexity

Time: O(random) per decision

Space: O(1)

Implementation: Complex

Overhead: Higher

Exam Tip: P-persistent is most flexible but requires choosing the right p value. For slotted systems, p is typically set based on the number of active stations. Remember: "p-persistent" means probability p of transmitting when idle.

Example: Choosing the Right Variant

Scenario 1: Office with 5 computers, occasional file transfers

• Light traffic, few active stations → Use 1-Persistent CSMA

Scenario 2: University lab with 30 computers, constant traffic

• Heavy traffic, many active stations → Use Non-Persistent CSMA

Scenario 3: Data center with variable load throughout day

• Variable traffic → Use P-Persistent CSMA with adjustable p

Worked Example: Throughput Calculation

Given: 10 stations, each transmitting with probability 0.1 per slot

For 1-Persistent:

• Probability at least one transmits: 1 - (0.9)^10 ≈ 0.65

• Probability exactly one transmits: 10 × 0.1 × (0.9)^9 ≈ 0.39

• Throughput ≈ 0.39 (39%)

For P-Persistent (p=0.1):

• Same calculation as above

• Throughput ≈ 0.39 (39%)

For Non-Persistent:

• Fewer collisions but more idle time

• Throughput ≈ 0.35-0.45 depending on backoff

All variants have similar maximum throughput but different delay characteristics

Quick Reference: When to Use Each

• 1-Persistent: Light load, low delay needed, simple implementation

• Non-Persistent: Heavy load, collision reduction priority, delay tolerance

• P-Persistent: Variable load, tunable behavior, slotted systems

Exam Tip: All CSMA variants have collisions because they don't detect collisions during transmission (unlike CSMA/CD). Remember: CSMA senses before transmitting, but collisions can still occur due to propagation delay. The variants differ only in how they handle the "busy" case.
