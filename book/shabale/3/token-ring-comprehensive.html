TOKEN RING (IEEE 802.5)

Comprehensive Networking Exam Prep Guide

What is Token Ring?

Token Ring is a LAN protocol defined by the IEEE 802.5 standard. It uses a physical ring topology where stations are connected in a circular loop, and data travels in one direction only (clockwise).

Physical Ring

Token Passing

Physical Ring Topology

In a Token Ring network, all stations are connected in a closed loop. Each station acts as a repeater, receiving data and passing it to the next station.

Station 1 ← Station 2 ↓ ↑ Station 4 ← Station 3 ↓ ↑ Station 5 ← Station 6
Key Point: Data travels in ONE direction only (clockwise). The ring is physically closed, but logically, data flows in one direction.

Token Passing Mechanism

A special control frame called a token circulates around the ring. A station can transmit data only when it captures the free token.

How Token Passing Works:

Step 1: Token Circulation

A free token (T=0) circulates continuously around the ring when no station is transmitting.

Step 2: Token Capture

When a station wants to transmit, it waits for the free token and captures it by changing T=0 to T=1 (busy).

Step 3: Frame Transmission

The station appends its data frame (with destination address) and sends it around the ring.

Step 4: Frame Reception

The destination station copies the frame but does NOT remove it. It continues circulating.

Step 5: Frame Removal

The originating station removes the frame when it returns and releases a new free token.

Data Flow Direction

Token Ring (IEEE 802.5)

  • Unidirectional (clockwise)
  • Single ring
  • Data and token flow same direction

FDDI (Comparison)

  • Dual counter-rotating rings
  • Backup ring for fault tolerance
  • Higher speed (100 Mbps)

Monitor Station

One station is designated as the Active Monitor. Its responsibilities include:

  • Token Recovery: If a token is lost (e.g., station crashes while holding token), the monitor detects it and generates a new token.
  • Ring Cleaning: Removes orphaned frames that circulate indefinitely.
  • Clock Synchronization: Provides master clock for the ring.
  • Priority Management: Ensures priority mechanism works correctly.
The monitor station is elected dynamically. If the current monitor fails, another station takes over.

Access Control (AC) Field

The Access Control field is 8 bits (1 byte) that controls access to the ring. It is part of both the token and data frames.

AC Field Structure (8 bits):
P P P T M R R R
P = Priority (3 bits) | T = Token (1 bit) | M = Monitor (1 bit) | R = Reservation (3 bits)
Bits Field Size Description
0-2 P (Priority) 3 bits Priority level (0-7)
3 T (Token) 1 bit 0 = Free token, 1 = Busy token
4 M (Monitor) 1 bit 0 = Normal, 1 = Monitor detected issue
5-7 R (Reservation) 3 bits Used to reserve next token

Token Types

Null Token (T=0)

Free token - any station can capture it to transmit. When a station wants to send data, it changes T from 0 to 1.

Data Token (T=1)

Busy token - indicates data is being transmitted. Stations can only listen, not transmit, while T=1.

Key Difference: T=0 means the ring is free to use. T=1 means someone is already transmitting. Stations must wait for T=0 to transmit.

Priority Mechanism

Token Ring supports 8 priority levels (0-7), where 7 = highest priority and 0 = lowest priority.

How Priority Works:

Step 1: Priority Request

A station with high-priority data sets the Reservation (R) bits in any passing frame to its priority level.

Step 2: Token Upgrade

When the token becomes free, the station holding it creates a new token with priority = max(current priority, reservation).

Step 3: Priority Capture

Only stations with priority >= token priority can capture the token. Lower priority stations must wait.

Step 4: Priority Restoration

After transmission, the token priority returns to the previous level (unless a higher priority is reserved).

Priority Levels:
0 (lowest) → 1 → 2 → 3 → 4 → 5 → 6 → 7 (highest)
Higher number = higher priority. Stations with priority 7 always get access first.

Reservation System

The Reservation field (R bits) allows stations to reserve the next token for high-priority traffic.

R = 000 (0)
No reservation or lowest priority
R = 111 (7)
Highest priority reservation
Reservation works by stations setting R bits in passing frames. The highest R value seen determines the next token's priority.

AC Field Values Comparison

Scenario P (Priority) T (Token) M (Monitor) R (Reservation)

Token Ring Frame Format

The IEEE 802.5 frame structure includes special delimiters and control fields:

SD | AC | FC | DA (6) | SA (6) | Data (0-33133) | FCS (4) | ED | FS
Field Name Size (bytes) Description
SD Starting Delimiter 1 Non-data symbols (J, K) - marks frame start
AC Access Control 1 Priority, Token, Monitor, Reservation
FC Frame Control 1 Frame type and control info
DA Destination Address 6 48-bit MAC address of destination
SA Source Address 6 48-bit MAC address of sender
Data Data 0 - 33,133 Payload (variable length)
FCS Frame Check Sequence 4 CRC error detection
ED Ending Delimiter 1 Non-data symbols - marks frame end
FS Frame Status 1 Address recognized, frame copied bits

Starting Delimiter (SD) & Ending Delimiter (ED)

SD and ED use Non-Data Symbols:
J K 0 J K 0 0 J K (SD) | J K 1 J K 1 I E (ED)
J and K are special non-data symbols that cannot appear in normal data. This ensures frame boundaries are always detectable.
Key Point: SD and ED use non-data symbols (J, K) to avoid confusion with actual data. This is different from Ethernet which uses preamble bytes.

Frame Control (FC) Field

The FC field determines the frame type:

Token Frame
AC field only (no FC, DA, SA, Data, FCS, ED, FS)
SD | AC | ED
Data Frame
Full frame with all fields
SD | AC | FC | DA | SA | Data | FCS | ED | FS
A token is just 3 bytes: SD + AC + ED. A data frame is much larger and includes all the fields listed above.

Frame Status (FS) Field

The FS field provides feedback about frame delivery:

FS Field Bits:
A C 0 0 A C 0 0
A = Address Recognized | C = Frame Copied | 0 = Reserved
Bit Name Value Meaning
A Address Recognized 0 or 1 1 = Destination recognized its address
C Frame Copied 0 or 1 1 = Destination successfully copied frame
These bits are set by the destination station. When the frame returns to the sender, it can verify successful delivery.

Frame Size Calculation

Minimum Frame Size (Token):
SD(1) + AC(1) + ED(1) = 3 bytes = 24 bits
A token is just 3 bytes with no data payload.
Minimum Data Frame Size:
SD(1) + AC(1) + FC(1) + DA(6) + SA(6) + FCS(4) + ED(1) + FS(1) = 21 bytes = 168 bits
Minimum frame with 0 bytes of data.
Maximum Data Frame Size:
21 + 33,133 = 33,154 bytes = 265,232 bits
Maximum frame with full data payload.

Ring Delay Formula

The total ring delay consists of propagation delay plus station delays:

Ring Delay (D_ring):
D_ring = D + M × b
D = Cable propagation delay (km × m for cable delay) | M = Number of stations | b = Station processing delay
Propagation Delay Component:
D_propagation = (Ring Length in meters) / V
V = Propagation speed (typically 2 × 10^8 m/s for copper)
Station Delay Component:
D_stations = M × b
Each station adds delay b while processing/repeating the signal

Throughput Formula

For continuous transmission (steady state), throughput is the ratio of useful data time to total time:

Throughput (Efficiency):
Throughput = F/R = L / (L + D_ring)
F = Frame transmission time | R = Data rate | L = Frame length (bits) | D_ring = Ring delay (bits)
Key Insight: Throughput approaches 100% as L → ∞ (very large frames). This is because the fixed overhead (D_ring) becomes negligible compared to large L.

Token Passing Time

Token Time (Token_T):
Token_T = 3 × 8 / R = 24 / R (microseconds for R in Mbps)
A token is 3 bytes = 24 bits. At 1 Mbps, token time = 24 μs (but actual is ~31 μs with overhead)
Example: Token Time Calculation

For R = 1 Mbps:

Token_T = 24 bits / 1 Mbps = 24 μs
Note: Actual token time is ~31 μs when including inter-frame gaps and other overhead.

Frame Transmission Time

Frame Transmission Time (T_frame):
T_frame = (L + Overhead) / R
L = Data bits | Overhead = SD+AC+FC+DA+SA+FCS+ED+FS = 21 bytes = 168 bits
Total Bits per Frame:
Total = L + 168 bits
168 bits overhead (21 bytes) + L bits of data

Processing Delay at Each Station

Each station on the ring introduces a small delay while processing the incoming signal:

Station Delay (b)
Typically 1 μs (microsecond) per station
Bit Delay
b × R bits of delay per station
Total Station Delay
M × b × R bits for M stations
Station delay includes: signal regeneration, bit buffering, and address recognition. This is why b is specified in time units (μs) and must be converted to bits using R.

Example 1: Basic Ring Delay Calculation

Problem:

A Token Ring network has R = 1 Mbps, M = 1 station, D = 1 km cable, V = 2 × 10^8 m/s, b = 1 μs per station. Calculate:

  • a) Ring Delay (D_ring)
  • b) Throughput when L = 4000 bits
Solution:
Step 1: Calculate Propagation Delay
D_propagation = D / V = 1000 m / (2 × 10^8 m/s) = 5 × 10^-6 s = 5 μs
Step 2: Calculate Station Delay (in time)
D_station = M × b = 1 × 1 μs = 1 μs
Step 3: Calculate Total Ring Delay (time)
D_ring_time = 5 μs + 1 μs = 6 μs
Step 4: Convert to Bits
D_ring_bits = D_ring_time × R = 6 μs × 1 Mbps = 6 bits
Step 5: Calculate Throughput
Throughput = L / (L + D_ring_bits) = 4000 / (4000 + 6) = 4000 / 4006 ≈ 0.9985 ≈ 99.85%
Answer: Throughput ≈ 99.85% (nearly 100%)

Example 2: Throughput Calculation

Problem:

Given R = 1 Mbps, M = 1, D = 1 km, V = 2 × 10^8 m/s, b = 1 μs. Calculate throughput when L = 4000 bits.

Solution:
Step 1: Calculate Ring Delay
D_ring = D + M × b = 1000 + 1 × 1 = 1001 meters (in time: 1001 / (2×10^8) = 5.005 μs)
Step 2: Convert to Bits
D_ring_bits = 5.005 μs × 1 Mbps = 5.005 bits ≈ 6 bits
Step 3: Calculate Throughput
Throughput = L / (L + D_ring) = 4000 / (4000 + 6) = 4000 / 4006 ≈ 0.9985
Answer: Throughput ≈ 99.85%

Example 3: Token Time Calculation

Problem:

Calculate the token passing time for a Token Ring network with R = 4 Mbps and 10 stations.

Solution:
Step 1: Token Size
Token = 3 bytes = 24 bits
Step 2: Token Transmission Time
Token_T = 24 bits / 4 Mbps = 6 μs
Step 3: Station Delays
D_stations = M × b = 10 × 1 μs = 10 μs
Step 4: Total Token Passing Time
Total = Token_T + D_stations = 6 + 10 = 16 μs
Answer: Total token passing time = 16 μs

Example 4: Frame Transmission Time

Problem:

A station transmits a frame with L = 1000 bits of data on a 16 Mbps Token Ring. Calculate the frame transmission time including overhead.

Solution:
Step 1: Calculate Overhead
Overhead = SD + AC + FC + DA + SA + FCS + ED + FS = 1 + 1 + 1 + 6 + 6 + 4 + 1 + 1 = 21 bytes = 168 bits
Step 2: Total Frame Size
Total = L + Overhead = 1000 + 168 = 1168 bits
Step 3: Frame Transmission Time
T_frame = 1168 bits / 16 Mbps = 73 μs
Answer: Frame transmission time = 73 μs

Example 5: Multi-Station Ring Delay

Problem:

A Token Ring has 20 stations, each 500 meters apart. Data rate is 4 Mbps, propagation speed is 2 × 10^8 m/s, and each station has 2 μs delay. Calculate:

  • a) Total ring length
  • b) Propagation delay
  • c) Total ring delay in bits
Solution:
Step 1: Total Ring Length
Ring Length = 20 × 500 = 10,000 meters = 10 km
Step 2: Propagation Delay
D_propagation = 10,000 / (2 × 10^8) = 50 × 10^-6 s = 50 μs
Step 3: Station Delays
D_stations = M × b = 20 × 2 μs = 40 μs
Step 4: Total Ring Delay (time)
D_ring = 50 + 40 = 90 μs
Step 5: Convert to Bits
D_ring_bits = 90 μs × 4 Mbps = 360 bits
Answer: Ring length = 10 km, Propagation delay = 50 μs, Total ring delay = 360 bits

Example 6: Throughput Comparison

Problem:

Compare throughput for different frame lengths on a Token Ring with D_ring = 100 bits:

  • L = 100 bits
  • L = 1000 bits
  • L = 10,000 bits
  • L = 100,000 bits
Solution:
Throughput Formula
Throughput = L / (L + D_ring)
L (bits) Throughput Percentage
100 100 / (100 + 100) = 0.5 50%
1,000 1000 / (1000 + 100) = 0.909 90.9%
10,000 10000 / (10000 + 100) = 0.990 99.0%
100,000 100000 / (100000 + 100) = 0.999 99.9%
As frame length increases, throughput approaches 100%. This demonstrates why Token Ring is highly efficient under heavy load.
