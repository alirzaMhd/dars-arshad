Token Bus (IEEE 802.4)

Networking Exam Prep — Complete Guide for 20/20

What is Token Bus?

Token Bus is a IEEE 802.4 standard that implements a token-passing access method on a physically shared bus topology. Unlike Ethernet (802.3) which uses contention, Token Bus organizes stations into a logical ring where each station knows its successor and predecessor.

Standard

IEEE 802.4

Developed by General Motors for MAP

Physical Topology

Bus

All stations on single coaxial cable

Logical Topology

Ring

Virtual token-passing ring

Signaling

Broadband

Multiple channels on coaxial cable

Key Distinction: Token Bus appears as a bus physically, but stations communicate using a logical ring where a token circulates in a defined order.

Physical Bus vs Logical Ring

Physical Bus Topology

All stations are connected to a single coaxial cable (bus). When a station transmits, the signal propagates in both directions along the cable. Any station can access the medium when it holds the token.

Physical Structure:
Station — Station — Station — Station — Station
All stations share the same physical medium (coaxial bus)

Logical Ring Topology

Despite the physical bus, stations maintain a logical ring structure. Each station has a successor (next station to receive token) and a predecessor (station that passes token to it).

Logical Structure:
Station 1 → Station 2 → Station 3 → Station 4 → Station 1
Token passes in a circular sequence, not in physical order
Example: Station Ordering

Physical cable order: A — B — C — D — E

Logical ring order (by address): A → B → C → D → E → A

Token moves from A to B to C to D to E, then back to A, regardless of physical cable distance.

The logical ring order is based on station addresses (highest to lowest, wrapping around). This ensures deterministic access.

How Token Passing Works

The token-passing mechanism follows these steps:

Step 1: Token Available

Token circulates on the bus. When a station receives the token and has data to send, it seizes the token.

Step 2: Data Transmission

The sending station transmits one or more data frames while holding the token. Other stations must wait.

Step 3: Token Release

After transmission (or timer expires), the station releases the token by sending it to its successor.

Step 4: Cycle Continues

The successor receives the token. If it has data, it transmits; otherwise, it passes the token to its own successor.

Critical Rule: Only ONE station holds the token at any time. This eliminates collisions entirely, unlike Ethernet's CSMA/CD.
Example: 5-Station Token Passing

Stations: A (address 100), B (address 80), C (address 60), D (address 40), E (address 20)

Logical ring order: A → B → C → D → E → A (highest to lowest address)

Timeline:

• A holds token, sends data frame → B

• B receives token, has no data → passes to C

• C receives token, sends data frame → D

• D receives token, sends data frame → E

• E receives token, has no data → passes to A

Result: 3 frames transmitted in one complete cycle

Forming the Logical Ring

Stations dynamically form a logical ring using a ring initialization process. The station with the highest address becomes the Ring Monitor and orchestrates the ring formation.

Ring Formation Process:
Highest Address Station → Beaconing → Neighbors Respond → Ring Established
The ring monitor sends WHO_FOLLOW messages to discover neighbors
Example: Ring Initialization

Stations A(100), B(80), C(60), D(40) are connected to the bus.

1. A (highest address) declares itself Ring Monitor

2. A sends "WHO_FOLLOW_ME?" to find successor with address < 100

3. B(80) responds: "I follow you (address 80)"

4. A sets B as successor; B sets A as predecessor

5. Process repeats until ring is closed

Result: A → B → C → D → A (complete logical ring)

Token Passing Rules

Station Responsibilities

Predecessor

The station that passes the token TO you. You listen for tokens from this station.

Successor

The station you pass the token TO. You send tokens to this station's address.

Ring Monitor

Highest-address station. Handles token recovery and ring maintenance.

Token Holding Rules

Token Holding Time (THT): A station can hold the token for a maximum time before releasing it. This prevents any single station from monopolizing the bus.
Token Holding Formula:
THT = Number_of_frames × Frame_transmission_time
Station can transmit multiple frames per token hold, bounded by THT
Example: Token Holding Time

Given: THT_max = 10ms, Frame transmission time = 1ms

Station has 15 frames to send

Maximum frames per token hold = THT_max / Frame_time = 10ms / 1ms = 10 frames

Station sends 10 frames, releases token, waits for next token to send remaining 5

Result: 2 token cycles needed for 15 frames

Station Addition & Removal

Adding a Station

When a new station joins the bus, it sends a Solicit Successor message to find its place in the ring.

Station sends: SOLICIT_SUCCESSOR with its address
Stations with address between new station and its successor respond
New station integrates into the logical ring

Removing a Station

When a station leaves (or fails), the ring must reconfigure. The predecessor of the departing station must update its successor pointer.

Fault Tolerance: If the Ring Monitor fails, the next highest address station takes over. The ring automatically recovers from single-point failures.
Example: Station Removal

Ring: A(100) → B(80) → C(60) → D(40) → A

If C(60) fails:

1. B detects token not passed back by C

2. B sends "WHO_FOLLOW_ME" to find new successor

3. D(40) responds to B's query

4. B updates successor to D

New ring: A(100) → B(80) → D(40) → A

Priority Classes

Token Bus supports 4 priority levels for different types of traffic. Higher priority stations get the token first.

Priority Level Class Use Case Description
7 (Highest) Network Control Ring maintenance Token recovery, ring initialization
6 Real-Time Data Time-critical control Industrial control signals
4-5 Regular Data Normal communication Standard data transfer
0-3 Low Priority Background tasks File transfers, non-urgent data
Priority Access:
Higher priority stations get token before lower priority
When token arrives, high-priority stations seize it first
Example: Priority Handling

Station A has priority 7 (control), Station B has priority 4 (regular data)

Token arrives at A first (highest address)

A has priority 7 data → transmits immediately

A passes token to B

B has priority 4 data → transmits

If both had data at same priority, address order determines who goes first

Token Bus Frame Structure

Token Bus frames differ from Ethernet and Token Ring frames. The standard defines specific frame types for data and token passing.

Field Size Description
Preamble 1+ bytes Synchronization pattern
SD (Start Delimiter) 1 byte Signals start of frame
Frame Control 1 byte Frame type identifier
DA (Destination Address) 2 or 6 bytes Target station address
SA (Source Address) 2 or 6 bytes Sender station address
Data 0-8182 bytes Payload data
FCS (Frame Check Sequence) 4 bytes CRC error detection
ED (End Delimiter) 1 byte Signals end of frame
Maximum Frame Size:
Max Data = 8182 bytes (with 2-byte addresses)
Larger than Ethernet's 1500 bytes MTU

Frame Types

Data Frame

Frame Control = 01xxxxxx

Carries user data

Token Frame

Frame Control = 00001000

Passes token between stations

Control Frame

Frame Control = 00xxxxxx

Ring maintenance messages

Example: When to Use Each

Ethernet (802.3): Best for low-traffic LANs, office environments, cost-effective

Token Ring (802.5): Better for moderate traffic, predictable performance needed

Token Bus (802.4): Best for high-traffic industrial environments, real-time control systems

Token Bus excels when deterministic timing is critical (factories, process control)

Practice Problems

Question 1: Basic Concept

Q: What is the IEEE standard for Token Bus?

A: IEEE 802.4

Token Bus was developed by General Motors for the Manufacturing Automation Protocol (MAP).

Question 2: Topology

Q: What is the physical topology of Token Bus? What is its logical topology?

A: Physical: Bus | Logical: Ring

Stations are connected to a shared coaxial bus, but communicate using a virtual token-passing ring.

Question 3: Token Passing

Q: In a Token Bus network with stations A(100), B(80), C(60), D(40), what is the logical ring order?

A: A(100) → B(80) → C(60) → D(40) → A(100)

Token passes from highest address to lowest, wrapping around to highest.

Question 4: Collision Avoidance

Q: How does Token Bus avoid collisions?

A: Only ONE station holds the token at any time. A station can only transmit when it holds the token. This eliminates collisions entirely.

Unlike Ethernet (CSMA/CD) where collisions can occur, token passing guarantees collision-free access.

Question 5: Priority

Q: How many priority levels does Token Bus support? What are they used for?

A: 4 priority levels (0-7)

• Level 7: Network control (ring maintenance)

• Level 6: Real-time data (time-critical control)

• Level 4-5: Regular data transfer

• Level 0-3: Background/low-priority tasks

Question 6: Comparison

Q: Compare Token Bus (802.4) with Ethernet (802.3). Give 3 differences.

A:

1. Access method: Token Bus uses token passing, Ethernet uses CSMA/CD

2. Collisions: Token Bus has no collisions, Ethernet can have collisions

3. Determinism: Token Bus is deterministic, Ethernet is non-deterministic

Question 7: Maximum Frame Size

Q: What is the maximum data payload size in a Token Bus frame?

A: 8182 bytes (with 2-byte addresses)

This is significantly larger than Ethernet's 1500 bytes MTU.

Question 8: Application

Q: Why was Token Bus primarily used in industrial automation rather than general networking?

A: Token Bus provides deterministic access with guaranteed maximum latency. Industrial control systems require real-time guarantees — a control signal must arrive within a specific time window. Ethernet's CSMA/CD cannot guarantee timing under heavy load.

Question 9: Ring Formation

Q: How is the logical ring formed in Token Bus?

A: The station with the highest address becomes the Ring Monitor. It sends "WHO_FOLLOW_ME" messages to discover neighbors. Stations respond with their addresses, and the ring is built in descending address order, wrapping from lowest back to highest.

Question 10: Fault Tolerance

Q: What happens if the Ring Monitor in a Token Bus network fails?

A: The next highest address station automatically takes over as Ring Monitor. The ring self-heals by detecting the monitor's absence and reconfiguring. This provides fault tolerance for critical industrial environments.
