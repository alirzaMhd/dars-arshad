What is FDDI?

FDDI (Fiber Distributed Data Interface) is a high-speed networking standard that operates at 100 Mbps over fiber optic cable. It was developed in the 1980s by ANSI X3T9.5 as a backbone technology to connect multiple smaller networks.

Data Rate
100 Mbps
Max Stations
1000
Max Ring Circumference
200 km
Medium
Fiber Optic
FDDI is often used as a backbone network to interconnect multiple LANs, not as a direct end-user access network.

Dual Ring Architecture

FDDI's key differentiator is its dual counter-rotating ring topology, which provides built-in fault tolerance.

Primary and Secondary Rings

The two rings operate in opposite directions (counter-rotating). The primary ring carries data under normal operation. The secondary ring serves as a backup and remains idle during normal operation.

Dual Ring Layout
Station A ←—— Primary Ring (data flow) ——→ Station B
Station A ——→ Secondary Ring (backup) ←—— Station B

Both rings rotate in opposite directions

Fault Tolerance: Ring Wrapping

When the primary ring fails (cable cut or station failure), the network performs ring wrapping. The stations adjacent to the failure connect the primary ring to the secondary ring, forming a single logical ring that bypasses the damaged segment.

Ring Wrapping
Normal: Primary Ring → Data Flow
On failure, adjacent stations wrap primary to secondary, maintaining connectivity at reduced capacity (50% bandwidth).
After wrapping, the effective data rate drops to 50 Mbps because traffic must traverse both rings.

FDDI uses 4B/5B encoding to ensure sufficient transitions for clock recovery, then applies NRZI for transmission on the fiber.

Token Passing Mechanism

FDDI uses a token passing access method, similar to Token Ring (IEEE 802.5). A special frame called a token circulates around the ring. A station must capture the token before transmitting data.

Basic Operation

Token Passing Sequence
1. Token circulates on the ring
2. Station with data to send captures the token
3. Station transmits its frame(s)
4. Frame circulates and returns to sender
5. Sender removes frame from ring
6. Sender releases token for next station

Early Token Release (ETR)

Unlike standard Token Ring, FDDI supports Early Token Release. With ETR, a station releases the token immediately after placing its frame on the ring, rather than waiting for the frame to return.

ETR Benefit
Without ETR: Wait for frame return → Release token
With ETR: Release token immediately after transmission → Higher utilization
ETR vs No-ETR Comparison
WITHOUT ETR:
Station A sends frame → Frame traverses ring → Returns to A → Token released
Token idle time: Propagation delay of entire ring

WITH ETR:
Station A sends frame → Token released immediately
Token idle time: Only A's transmission time
ETR significantly improves performance on large rings where propagation delay is significant.

Target Token Rotation Time (TTRT)

TTRT is the target time for a token to complete one full rotation around the ring. Each station negotiates a TTRT value during ring initialization. Typical value is 5 ms.

TTRT
TTRT = Target Token Rotation Time (typically 5 ms)
Used to determine how much bandwidth each station can use for synchronous and asynchronous traffic.

Token Rotation Timer (TRT)

Each station maintains a TRT (Token Rotation Timer). When the token arrives, the station checks if TRT ≤ TTRT. If so, the station can transmit asynchronous traffic. If TRT > TTRT, only synchronous traffic is permitted.

Synchronous vs Asynchronous Service

FDDI supports two classes of service based on TTRT:

Feature Synchronous Asynchronous
Bandwidth Guarantee Yes No
Based on Allocated time per station Remaining bandwidth
Latency Bounded (deterministic) Variable
Use Case Voice, real-time data Bulk data, file transfers
Token Check Always allowed Only if TRT ≤ TTRT
Synchronous Bandwidth Allocation
DSi = (TTRT × Ring Latency) / (Number of stations)
Each station i is allocated a synchronous holding time DSi derived from TTRT.

FDDI Frame Format

FDDI frames have a well-defined structure. Below is the complete frame layout with field sizes:

Frame Structure
| Preamble | SD | FC | DA | SA | Data | FCS | ED | FS |
| 16 bytes | 1B | 1B | 6B | 6B | 0-4500B | 4B | 1B | 1B |

Field Descriptions

Field Size Description
Preamble 16 bytes Clock synchronization; allows receiver to lock onto signal
SD (Start Delimiter) 1 byte 0x53 — JK symbols (non-data symbols)
FC (Frame Control) 1 byte Frame type, priority, and control info
DA (Destination Address) 6 bytes Destination MAC address
SA (Source Address) 6 bytes Source MAC address
Data 0–4500 bytes Upper-layer protocol data (max 4500 bytes)
FCS (Frame Check Sequence) 4 bytes CRC-32 for error detection
ED (End Delimiter) 1 byte 0x55 — T symbols (non-data symbols)
FS (Frame Status) 1 byte Error, Address Recognized, Frame Copied indicators

Key Fields in Detail

Start Delimiter (SD) = 0x53

SD Encoding
JK symbols (non-data symbols on the ring)
Uses B5/B4 coding violations to distinguish delimiters from data.

End Delimiter (ED) = 0x55

ED Encoding
T symbols (non-data symbols on the ring)
Marks end of frame. Also uses coding violations.

Frame Control (FC) Field

FC bits: [PPP] [T] [RR] [00]

PPP = Priority bits
T = Token bit (1 = token frame, 0 = data frame)
RR = Reserved bits

AC Field (Token Frame)

In token frames, the FC field encodes access control information:

AC bits: [T] [R] [M] [PP]

T = Token (1 = token present)
R = Reservation (station requests priority)
M = Monitor (used by active monitor)
PP = Priority (2-bit priority level)

Frame Status (FS) Field

FS bits: [E] [A] [C] (repeated 3 times for reliability)

E = Error detected (set by any station detecting CRC error)
A = Address Recognized (set by destination station)
C = Frame Copied (set by destination after copying frame)
The FS field is repeated 3 times in the actual frame to ensure reliability, as it is not covered by the FCS.

Frame Types

Type FC Value Purpose
Unclaimed Token 1000 0000 Circulates when no station is transmitting
Claim Token 1100 0000 Used during ring initialization to claim token
Beacon 1000 0001 Indicates serious ring fault (used in recovery)
Abort 1100 0010 Aborts current transmission
Active Monitor 0101 0001 Control frame from active monitor
Station Report 0100 0001 Station status report

Example 1: Ring Distance Calculation

Problem

An FDDI ring has a radius of 25 km. Calculate the ring circumference and determine if it meets the FDDI maximum limit.

Formula
D = 2 × π × radius
D = ring circumference (total cable length)
Solution

Given: radius = 25 km

D = 2 × π × 25

D = 2 × 3.14159 × 25

D = 157.08 km

Since 157.08 km ≤ 200 km (FDDI maximum), this ring is within specification.

Example 2: Maximum Stations on a Ring

Problem

An FDDI ring has a circumference of 160 km. What is the maximum number of stations that can be supported, assuming each station is placed at equal intervals?

Formula
Max Stations = 1000 (FDDI standard limit)
FDDI supports up to 1000 stations regardless of ring size (as long as circumference ≤ 200 km).
Solution

Given: ring circumference = 160 km

Since 160 km ≤ 200 km, the ring is valid.

Maximum stations = 1000

The station density would be: 1000 stations / 160 km = 6.25 stations per km

Average distance between stations: 160 km / 1000 = 0.16 km = 160 meters

Example 3: Token Rotation Time Analysis

Problem

An FDDI ring has 50 stations. The TTRT is 5 ms. If a station's TRT reads 4 ms when the token arrives, can it transmit asynchronous traffic? What if TRT reads 6 ms?

Rule
If TRT ≤ TTRT → Asynchronous allowed
If TRT > TTRT → Only synchronous traffic permitted
Solution

Case 1: TRT = 4 ms

4 ms ≤ 5 ms (TTRT) → Yes, asynchronous traffic is allowed

The token arrived faster than expected, so the station has spare bandwidth for async data.


Case 2: TRT = 6 ms

6 ms > 5 ms (TTRT) → No, only synchronous traffic is allowed

The token took longer than expected; the station must wait for the next rotation to send async data.

Example 4: Throughput Calculation

Problem

An FDDI ring operates at 100 Mbps. There are 30 active stations, each transmitting 1000-byte frames. The ring circumference is 100 km. Calculate the effective throughput assuming Early Token Release is used and propagation velocity is 2 × 108 m/s.

Formulas
Propagation Delay = Distance / Velocity
Tprop = Ring length / Signal velocity
Transmission Time
Ttrans = Frame Size / Data Rate
Time to place one frame on the ring
Solution

Step 1: Calculate propagation delay

Tprop = 100 km / (2 × 108 m/s)

Tprop = 100,000 m / 200,000,000 m/s

Tprop = 0.5 ms

Step 2: Calculate transmission time per frame

Ttrans = (1000 bytes × 8 bits/byte) / 100 Mbps

Ttrans = 8000 bits / 100,000,000 bps

Ttrans = 0.08 ms

Step 3: With ETR, token is released immediately

Time for one token rotation ≈ Tprop + Ttrans

≈ 0.5 ms + 0.08 ms = 0.58 ms per station

Step 4: Effective throughput

In 5 ms (TTRT), the ring can transmit approximately:

5 ms / 0.58 ms ≈ 8.6 rotations

Each rotation allows 30 stations × 1000 bytes = 30,000 bytes

Total in 5 ms ≈ 8.6 × 30,000 = 258,000 bytes = 2,064,000 bits

Effective throughput ≈ 2,064,000 bits / 5 ms = 412.8 Mbps aggregate

Note: This is aggregate throughput across all stations. Individual station throughput is lower.

Example 5: Synchronous Bandwidth Allocation

Problem

An FDDI ring has 20 stations and TTRT = 5 ms. Calculate the synchronous holding time allocated to each station.

Formula
DS = TTRT / Number of Stations
Synchronous bandwidth per station (simplified allocation)
Solution

Given: TTRT = 5 ms, Number of stations = 20

DS = 5 ms / 20

DS = 0.25 ms per station

Each station can transmit synchronously for up to 0.25 ms per token rotation.

In bits: 0.25 ms × 100 Mbps = 25,000 bits = 3125 bytes per rotation
