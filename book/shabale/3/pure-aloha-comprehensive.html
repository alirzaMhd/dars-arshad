Pure ALOHA Protocol Overview

Pure ALOHA (P-ALOHA) is the simplest random access protocol in computer networking. Developed at the University of Hawaii in the 1970s, it allows multiple stations to share a single communication channel without any centralized control. The protocol is "pure" because stations transmit whenever they have data, without checking if the channel is busy.

Core Principle:
Transmit → Collision → Wait Random Time → Retransmit
Stations transmit freely without carrier sensing, leading to potential collisions

Key Characteristics

Protocol Features

• No carrier sensing — stations don't check channel before transmitting

• No collision detection — collisions detected only by lack of ACK

• Simple to implement — minimal hardware requirements

• High collision rate — efficiency decreases with load

Vulnerable Period

• 2 × T_frame — twice the frame transmission time

• Collisions can occur within this window

• Much larger than S-ALOHA's vulnerable period

• Key factor in throughput analysis

Historical Context

The ALOHA protocol was developed at the University of Hawaii to connect computers on different islands. It was the first random access protocol and paved the way for Ethernet and modern wireless networks. Pure ALOHA demonstrated that simple protocols could work effectively for shared medium communication.

Why "Pure" ALOHA?

The name "Pure" distinguishes it from Slotted ALOHA (S-ALOHA). In Pure ALOHA, transmissions can start at any time (continuous time), while in Slotted ALOHA, transmissions must align with time slots. This makes Pure ALOHA simpler but less efficient.

How Pure ALOHA Works

Step-by-Step Process

1. Data Generation

A station has data to send and prepares a frame for transmission. The frame includes destination address, data, and error detection bits.

2. Immediate Transmission

The station transmits the frame immediately without checking if the channel is busy. This is the key difference from carrier-sensing protocols.

3. Collision Detection

After transmission, the station waits for an ACK (acknowledgment). If no ACK arrives within timeout, a collision is assumed to have occurred.

4. Random Backoff

The station waits a random amount of time (backoff time) before attempting retransmission. This randomization helps reduce repeated collisions.

5. Retransmission

After the backoff period, the station retransmits the frame. Steps 2-5 repeat until successful transmission.

Collision Scenario

Example: Two Stations Collide

Station A starts transmitting at time t₁. Station B starts transmitting at time t₂ where t₁ < t₂ < t₁ + T (T = frame time). Both frames overlap and collide. Neither station receives an ACK, so both wait random backoff times and retransmit.

Critical Point: In Pure ALOHA, a frame of duration T can be corrupted by any other frame that overlaps with it during the interval [t-T, t+T], where t is the start time of the frame. This creates a vulnerable period of 2T.

Backoff Algorithm

Binary Exponential Backoff:
Backoff = random(0, 2^n - 1) × T_slot
Where n = collision number (1, 2, 3, ...), T_slot = slot time

After each collision, the range of random backoff times doubles exponentially. This reduces the probability of repeated collisions as the number of attempts increases.

First Collision (n=1)

Random wait: 0 or 1 slot

Second Collision (n=2)

Random wait: 0, 1, 2, or 3 slots

Third Collision (n=3)

Random wait: 0 to 7 slots

Throughput Analysis

Throughput Formula:
S = G × e^(-2G)
Where S = throughput (successful transmissions per frame time), G = offered load (total transmission attempts per frame time)
Maximum Throughput:
S_max = 1/(2e) ≈ 0.184 (18.4%)
Occurs at G = 0.5 (optimal offered load)
Success Probability:
P_success = e^(-2G)
Probability that a frame is transmitted successfully without collision

Understanding the Variables

S (Throughput)

• Successful transmissions per frame time

• Range: 0 to 0.184

• Represents channel efficiency

G (Offered Load)

• Total transmission attempts per frame time

• Includes new frames and retransmissions

• Can exceed 1.0 (unlimited)

Vulnerable Period Analysis

The vulnerable period for Pure ALOHA is 2T (twice the frame transmission time). This is because a frame can collide with any other frame that starts transmission within T seconds before or T seconds after the start of the first frame.

Vulnerable Period:
T_vulnerable = 2 × T_frame
Any frame starting in this window will cause a collision
Key Insight: The factor of 2 in the exponent (e^(-2G)) comes directly from the vulnerable period being 2T. If the vulnerable period were T (as in S-ALOHA), the formula would be S = G × e^(-G).

Worked Examples

Example 1: Calculate Throughput at Optimal Load

Given: G = 0.5 (offered load)

Solution:

S = G × e^(-2G) = 0.5 × e^(-2×0.5) = 0.5 × e^(-1)

S = 0.5 × 0.3679 = 0.184 (18.4%)

This is the maximum throughput for Pure ALOHA

Example 2: Success Probability at High Load

Given: G = 1.0 (offered load)

Solution:

P_success = e^(-2×1) = e^(-2) = 0.135 (13.5%)

Only 13.5% of transmissions succeed without collision at this load

Example 3: Throughput at Multiple Loads

Given: Calculate S for G = 0.25, 0.5, 1.0, 2.0

Solution:

G = 0.25: S = 0.25 × e^(-0.5) = 0.25 × 0.6065 = 0.152 (15.2%)

G = 0.5: S = 0.5 × e^(-1) = 0.5 × 0.3679 = 0.184 (18.4%)

G = 1.0: S = 1.0 × e^(-2) = 1.0 × 0.1353 = 0.135 (13.5%)

G = 2.0: S = 2.0 × e^(-4) = 2.0 × 0.0183 = 0.037 (3.7%)

Example 4: Network Capacity Calculation

Given: Channel data rate = 100 kbps, frame size = 1000 bits

Solution:

Frame transmission time T = 1000 bits / 100 kbps = 10 ms

Maximum throughput = 18.4% × 100 kbps = 18.4 kbps

Only 18.4 kbps of useful data can be transmitted at maximum efficiency

Example 5: Finding Optimal G for Target Throughput

Given: Find G when S = 0.15 (15% throughput)

Solution:

Using S = G × e^(-2G), solve numerically:

At G = 0.3: S = 0.3 × e^(-0.6) = 0.3 × 0.5488 = 0.165

At G = 0.25: S = 0.25 × e^(-0.5) = 0.25 × 0.6065 = 0.152

G ≈ 0.25 gives approximately 15% throughput

Example 6: Throughput Comparison with S-ALOHA

Given: Compare maximum throughput of P-ALOHA vs S-ALOHA

Solution:

P-ALOHA: S_max = 1/(2e) = 0.184 (18.4%)

S-ALOHA: S_max = 1/e = 0.368 (36.8%)

S-ALOHA is twice as efficient as P-ALOHA

This is because S-ALOHA reduces the vulnerable period from 2T to T
