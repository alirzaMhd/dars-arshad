TCP Connection & Segment Structure

Computer Networking — Comprehensive Guide for 20/20 Exam

TCP Connection Overview

Connection-Oriented

Before data flows, sender and receiver exchange control segments (handshake) to initialize state variables.

Full-Duplex

Data flows in both directions simultaneously. Each side has its own send and receive buffer.

Point-to-Point

Exactly one sender and one receiver. No multicasting — "two hosts are company, three is a crowd."

Send and Receive Buffers

Each side allocates a send buffer (for data from the application not yet sent/acknowledged) and a receive buffer (for data arrived from network not yet read by the application).

Maximum Segment Size (MSS)
MSS = MTU - (TCP Header + IP Header)
Typical MTU = 1500 bytes (Ethernet); TCP/IP header ≈ 40 bytes → MSS ≈ 1460 bytes
⚠ Common Mistake: MSS refers to the application data payload, not the total segment size. A segment with MSS=1460 bytes has total size ≈ 1500 bytes including headers.
MSS is negotiated during the SYN/SYNACK handshake via the TCP options field. Each end advertises its MSS; the minimum of the two values is used.

Three-Way Handshake (Intro)

Step Sender Receiver Purpose
1 Client → Server SYN=1, seq=client_isn Client requests connection, sends initial seq number
2 Server → Client SYN=1, seq=server_isn, ack=client_isn+1 Server acknowledges, sends own ISN
3 Client → Server SYN=0, ack=server_isn+1 (may carry data) Client acknowledges; connection established

Key Properties

• No connection state in intermediate routers (routers see IP datagrams, not TCP connections)

• Buffers and variables exist only at end systems

• TCP is logical, not a physical circuit

TCP Segment Header Structure

The TCP segment header is typically 20 bytes (without options) and can be up to 60 bytes with options. Each header field has a specific role in reliable data transfer, flow control, and connection management.

Flag Bits Detail

ACK — Acknowledgment field is valid
SYN — Synchronize sequence numbers (connection setup)
FIN — Sender finished sending (connection teardown)
RST — Reset connection (error/refuse)
PSH — Push data to application immediately
URG — Urgent data pointer is valid
CWR — Congestion window reduced
ECE — ECN-Echo (explicit congestion notification)
⚠ Common Mistake: The header length field counts in 32-bit words, not bytes. A value of 5 means 5 × 4 = 20 bytes. The minimum is 5 (no options).

Sequence Numbers & Acknowledgment Numbers

TCP views data as an unstructured but ordered stream of bytes. Sequence numbers are applied to bytes, not segments.

Sequence Number of a Segment
seq = byte-stream number of the first data byte in the segment
If a file has 500,000 bytes and MSS = 1000, segment 1 has seq=0, segment 2 has seq=1000, etc.
Acknowledgment Number
ack = sequence number of the next expected byte (cumulative)
If Host A received bytes 0-535 and 900-1000 but not 536-899, ack = 536 (first missing byte)

Key Properties

Cumulative ACK

ACK y acknowledges all bytes up to but not including y.

Random ISN

Initial sequence numbers are chosen randomly to prevent confusion with old connections.

Out-of-Order Handling

TCP RFCs leave it to implementers: discard or buffer. Modern TCP buffers out-of-order data.

32-bit Sequence Space

Sequence number field is 32 bits (range 0 to 232−1) and wraps around back to 0 after reaching the maximum.

Telnet Case Study

User types 'C' at client. Client ISN = 42, Server ISN = 79.

SegmentDirectionSeq #ACK #DataMeaning
1Client → Server4279'C'Client sends character, waiting for server byte 79
2Server → Client7943'C' (echo)Server ACKs byte 42, echoes 'C', piggyback ACK
3Client → Server4380(empty)Client ACKs echoed byte 79, now waiting for byte 80

Piggybacking: ACK for client data is carried inside a server data segment (segment 2).

Worked Examples

Example 1: Telnet Scenario with Character 'Z'

Setup: Client ISN = 100, Server ISN = 200. User types 'Z' (ASCII 90).

Step 1: Client sends seq=100, ack=200, data='Z'. Expects byte 200 from server.

Step 2: Server sends seq=200, ack=101, data='Z' (echo). ACKs receipt of bytes up to 100, now wants byte 101.

Step 3: Client sends seq=101, ack=201, data empty. ACKs server byte 200, now wants byte 201.

Each character traverses the network twice (echo).

Example 2: File Transfer Segment Numbering

Setup: File size = 120,000 bytes, MSS = 1460 bytes, initial seq = 0.

Number of segments = ceil(120,000 / 1460) = 83 segments.

Segment boundaries:

Seg 1: seq = 0, bytes 0-1459

Seg 2: seq = 1460, bytes 1460-2919

Seg 10: seq = 13140, bytes 13140-14599

Seg 83: seq = 119720, bytes 119720-119999 (only 280 bytes)

Last segment is smaller than MSS — typical for the final chunk of a file.

Example 3: Out-of-Order Handling and Cumulative ACK

Setup: Sender transmits segments with seq=1000 (200 bytes), seq=1200 (200 bytes), seq=1400 (200 bytes).

Arrival at Receiver: Segment seq=1000 arrives, then seq=1400 arrives (seq=1200 lost).

Receiver actions:

• On receiving seq=1000: delivers bytes 1000-1199, ACK=1200

• On receiving seq=1400 (out of order): buffers bytes 1400-1599, sends duplicate ACK=1200

Sender receives duplicate ACK: Knows receiver still waiting for byte 1200.

The cumulative ACK of 1200 tells the sender that all bytes before 1200 are received, but nothing beyond.

Example 4: MSS Calculation with Different MTUs

Case A — Ethernet: MTU = 1500 bytes. TCP header = 20 bytes, IP header = 20 bytes.

MSS = 1500 - 40 = 1460 bytes.

Case B — PPP: MTU = 1500 bytes. Same header overhead.

MSS = 1500 - 40 = 1460 bytes.

Case C — Jumbo Frames: MTU = 9000 bytes.

MSS = 9000 - 40 = 8960 bytes.

Case D — Path MTU Discovery: If the smallest MTU along the path is 576 bytes:

MSS = 576 - 40 = 536 bytes.

⚠ Important: The MSS is negotiated during the TCP handshake via the options field. Both ends advertise their MSS; the minimum is used.
