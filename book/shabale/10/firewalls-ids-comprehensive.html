فایروال چیست؟

فایروال یک دستگاه سخت‌افزاری یا نرم‌افزاری است که در مرز بین شبکه داخلی و اینترنت قرار می‌گیرد. سرآیند دیتاگرام و segment تمام ترافیک ورودی و خروجی را بررسی کرده و بسته‌های مشکوک را بر اساس مجموعه قوانین پیکربندی‌شده رد می‌کند.

اصل اصلی:
Firewall(بازرسی سرآیندها) → { ALLOW اگر مطابقت با قانون، در غیر این صورت DENY }
هر بسته در برابر یک لیست مرتب از قوانین ارزیابی می‌شود؛ اولین قانون مطابقت‌یافته اقدام را تعیین می‌کند.

کارکردهای کلیدی

• بازرسی سرآیندهای IP/TCP/UDP/ICMP

• فیلتر بر اساس IP مبدأ، IP مقصد، پورت، پروتکل

• ردیابی وضعیت اتصال

• مسدود کردن بسته‌های بدفرمت

قوانین فیلتر بسته

یک قانون فایروال معمولاً شامل: اقدام، پروتکل، IP مبدأ، پورت مبدأ، IP مقصد، پورت مقصد است. قوانین از بالا به پایین ارزیابی می‌شوند.

پروتکل : TCP | UDP | ICMP

مبدأ : آدرس IP / ماسک زیرشبکه

مقصد : آدرس IP / ماسک زیرشبکه

پورت : عدد یا محدوده

مثال ۱: جلوگیری از پویش Ping

سناریو: مهاجم ۱۰۰۰ درخواست ICMP echo به 192.168.1.0/24 ارسال می‌کند تا میزبان‌های فعال را کشف کند.

گام ۱: فایروال بسته ICMP با type=8 (درخواست echo) دریافت می‌کند.

گام ۲: قانون B مطابقت دارد — ICMP، dst 192.168.1.0/24، اقدام DENY.

گام ۳: بسته رها می‌شود. هیچ پاسخی ارسال نمی‌شود. مهاجم هیچ پاسخی نمی‌بیند.

گام ۴: مهاجم نمی‌تواند میزبان‌های مرده را از میزبان‌های فایروال‌شده تشخیص دهد.

نتیجه: پویش Ping شکست می‌خورد. توپولوژی شبکه داخلی پنهان می‌ماند.

مثال ۲: فیلتر اسکن پورت

سناریو: مهاجم پورت‌های TCP 1–1024 را روی 192.168.1.5 از 203.0.113.5 آزمایش می‌کند.

گام ۱: آزمایش به پورت 22 ← قانون D مطابقت دارد (مبدأ خارجی، پورت مقصد 22) ← DENY.

گام ۲: آزمایش به پورت 80 ← هیچ قانون صریحی TCP/80 ورودی به 192.168.1.5 را مجاز نمی‌کند. پیش‌فرض-رد آن را رد می‌کند.

گام ۳: فقط پورت 443 با قانون C مطابقت دارد اگر dst=192.168.1.10 — اما dst=192.168.1.5 است، پس مطابقت ندارد، DENY.

گام ۴: مهاجم هیچ SYN-ACK از هیچ پورتی دریافت نمی‌کند — همه پورت‌ها بسته/فیلترشده به نظر می‌رسند.

نتیجه: اسکن پورت هیچ پورت بازی را آشکار نمی‌کند. تلاش اسکن هدر می‌رود.

مثال ۳: ردیابی اتصال حالت‌مند

سناریو: میزبان داخلی 192.168.1.20 یک درخواست HTTP به 93.184.216.34:80 می‌کند.

گام ۱: بسته SYN خروجی (src:192.168.1.20:40000, dst:93.184.216.34:80) ← قانون A مطابقت دارد ← ALLOW. فایروال یک ورودی حالت ایجاد می‌کند.

گام ۲: پاسخ SYN-ACK (src:93.184.216.34:80, dst:192.168.1.20:40000) — با جدول حالت مطابقت دارد ← ALLOW.

گام ۳: SYN درخواست‌نشده (src:5.5.5.5:9999, dst:192.168.1.20:40000) — ورودی حالتی وجود ندارد ← DENY.

نتیجه: فایروال حالت‌مند از تزریق بسته‌های درخواست‌نشده توسط میزبان‌های خارجی به جریان‌های اتصال برقرار شده جلوگیری می‌کند.

اشتباه رایج: قرار دادن قوانین allow قبل از قوانین deny برای ترافیک یکسان. اگر یک قانون ALLOW گسترده قبل از یک قانون DENY خاص قرار گیرد، deny هرگز فعال نمی‌شود. همیشه از خاص‌ترین به عمومی‌ترین مرتب کنید.

اشتباه رایج: مسدود کردن فقط درخواست‌های ICMP echo ورودی اما فراموش کردن مسدود کردن درخواست‌های echo خروجی. یک میزبان داخلی آلوده همچنان می‌تواند در حملات DDoS شرکت کند. همچنین، پیام‌های ICMP unreachable (Type 3) برای Path MTU Discovery لازم هستند — مسدود کردن کورکورانه می‌تواند اتصال را قطع کند.

اصول طراحی قوانین فایروال

اصل ۱: پیش‌فرض-رد

با یک قانون رد همه‌چیز در پایین شروع کنید. فقط به صراحت ترافیک ضروری را مجاز کنید. این کار سطح حمله را به حداقل می‌رساند.

اصل ۲: کمترین امتیاز

فقط حداقل مجموعه پورت‌ها، پروتکل‌ها و IPهای لازم برای عملکرد قانونی را مجاز کنید. بقیه را رد کنید.

اصل ۳: ترتیب قوانین

قوانین خاص را قبل از قوانین عمومی قرار دهید. قوانینی که بیشتر مطابقت دارند باید برای عملکرد بهتر در بالاترین لیست باشند.

ALLOW خروجی TCP/80 (مرور وب)
ALLOW خروجی TCP/443 (HTTPS)
ALLOW خروجی UDP/53 (DNS به سرور مورد اعتماد)
DENY ورودی ICMP echo-request
DENY ورودی TCP پورت‌های <1024 (اسکن پورت‌های شناخته‌شده)
DENY هر (catch-all پیش‌فرض)
↑ مجموعه قوانین فایروال معمولی دفتر کار کوچک (مرتب‌شده از بالا به پایین)

سیستم‌های تشخیص نفوذ (IDS)

برخلاف فایروال‌ها که فقط سرآیندهای بسته را بررسی می‌کنند، یک IDS بازرسی عمیق بسته (DPI) را انجام می‌دهد — هم سرآیندها و هم بار (payload) را بررسی می‌کند. IDS محتویات بسته را با یک پایگاه داده امضا (signature) از الگوهای حمله شناخته‌شده مقایسه می‌کند.

عملیات IDS:
Score(بسته) = max { match(بسته, signature_i) } برای i در پایگاه داده
اگر Score ≥ threshold ← ALERT. اگر Score < threshold ← PASS.

تطبیق امضا

هر امضا یک الگو (regex، دنباله بایت یا ابتکار) است که ترافیک مخرب را شناسایی می‌کند. منابع رایج: مجموعه قوانین Snort، Suricata.

محل استقرار

IDS به صورت خارج از مسیر (out-of-band) از طریق یک شبکهtap یا port mirroring (SPAN) مستقر می‌شود. ترافیک را در خط مسدود نمی‌کند — فقط نظارت و هشدار می‌دهد.

انواع هشدار

True Positive — حمله واقعی شناسایی شد

False Positive — ترافیک بی‌خطر علامت‌گذاری شد

False Negative — حمله از قلم افتاد (بدترین حالت)

تشخیص مبتنی بر امضا — مثال‌های عملی

مثال ۱: تشخیص تزریق SQL

بار بسته: GET /login.php?user=' OR 1=1 -- HTTP/1.1

گام ۱: IDS بار درخواست HTTP را از جریان TCP می‌خواند.

گام ۲: پایگاه داده امضا شامل الگو است: ' OR 1=1 --

گام ۳: بار با امضای تزریق SQL مطابقت دارد.

گام ۴: IDS هشدار تولید می‌کند: اولویت HIGH — تلاش تزریق SQL به /login.php از 10.0.0.5.

نتیجه: مدیر هشدار دریافت می‌کند. حتی اگر فایروال ترافیک HTTP را مجاز کند، IDS بار مخرب درون آن را می‌گیرد.

مثال ۲: تشخیص اسکن پورت

سناریو: میزبان 203.0.113.50 TCP SYN به ۱۰ پورت روی 192.168.1.1 در عرض ۲۰۰ میلی‌ثانیه ارسال می‌کند.

گام ۱: IDS همه اتصالات را از طریق پورت SPAN نظارت می‌کند.

گام ۲: امضا: "بیش از ۵ بسته SYN به پورت‌های مختلف از یک منبع در عرض ۱ ثانیه" ← اسکن پورت.

گام ۳: IDS تعداد SYNها را به ازای IP مبدأ شمارش می‌کند. 203.0.113.50 از آستانه فراتر می‌رود.

گام ۴: هشدار: MEDIUM — اسکن پورت افقی از 203.0.113.50 به هدف 192.168.1.1.

نتیجه: رفتار اسکن پورت حتی اگر فایروال ممکن است اسکن‌ها را بی‌صدا مسدود کند، شناسایی می‌شود.

مثال ۳: تشخیص beacon بدافزار C2

سناریو: میزبان داخلی 192.168.1.77 هر ۶۰ ثانیه یک HTTP POST 1KB به 198.51.100.99 با بار حاوی داده رمزگذاری‌شده ارسال می‌کند.

گام ۱: IDS پست‌های HTTP خروجی دوره‌ای به همان IP خارجی را می‌بیند.

گام ۲: امضا: "HTTP POST منظم به IP ناشناخته با آنتروپی > ۰٫۸" مطابقت دارد.

گام ۳: بار رمزگشایی می‌شود — شامل اطلاعات سیستم رمزگذاری‌شده با base64 است.

گام ۴: هشدار: HIGH — beacon C2 شناسایی شد. 192.168.1.77 احتمالاً آلوده است.

نتیجه: beaconing باتنت با وجود اینکه برای فایروال شبیه ترافیک معمولی HTTPS است، شناسایی می‌شود.

اشتباه رایج: اتکا فقط به تشخیص مبتنی بر امضا. حملات روز-صفر (بدون امضای موجود) باعث false negative می‌شوند. پایگاه‌های داده امضا باید به طور مداوم به‌روزرسانی شوند — امضاهای قدیمی تهدیدهای مدرن را از دست می‌دهند.

محدودیت‌های IDS

• نمی‌تواند بار رمزگذاری‌شده (TLS) را بازرسی کند

• نرخ false positive بالا

• نیاز به به‌روزرسانی منظم امضا

• بدون محافظت برای بهره‌برداری روز-صفر

مزایای IPS

• مسدود کردن حملات در زمان واقعی

• استقرار درون‌خطی ترافیک را متوقف می‌کند

• می‌تواند بسته‌های تکه‌تکه را بازسازی کند

معایب IPS

• می‌تواند ترافیک قانونی را رد کند (FP)

• نیاز به تنظیم دقیق

• نقطه شکست واحد

• افزایش تأخیر

تشخیص مبتنی بر ناهنجاری

فراتر از امضاها، IDS/IPS مدرن از تشخیص ناهنجاری استفاده می‌کند: ایجاد یک خط پایه از ترافیک "عادی" و علامت‌گذاری انحرافات. این می‌تواند حملات جدید را شناسایی کند اما false positive بیشتری تولید می‌کند.

ناهنجاری آماری

خط پایه: میانگین ۱۰۰ اتصال/دقیقه. افزایش به ۱۰۰۰۰/دقیقه ← هشدار. تشخیص DDoS، انتشار کرم.

ناهنجاری پروتکل

سرآیندهای TCP بدفرمت، ترکیبات پرچم غیرعادی (مثلاً SYN-FIN همزمان) ← هشدار.

ناهنجاری رفتاری

کاربر در عرض ۵ دقیقه از ۲ موقعیت جغرافیایی وارد می‌شود ← هشدار. تشخیص سرقت اعتبار.

دفاع در عمق: معماری امنیتی لایه‌ای

هیچ دستگاه امنیتی به تنهایی کافی نیست. یک دفاع شبکه جامع، فایروال، IDS/IPS و سایر کنترلها را در یک معماری لایه‌ای ترکیب می‌کند.

اینترنت ← مسیریاب ← فایروال ← IPS (درون‌خطی) ← سوئیچ ← IDS (منفعل از طریق SPAN) ← LAN داخلی
↑ معماری امنیتی شبکه سازمانی معمولی

لایه ۱: فایروال محیطی

پروتکل‌ها، پورت‌ها، IPهای ناخواسته را مسدود می‌کند. خط اول دفاع. بخش عمده ترافیک مخرب (۹۰٪+) را فیلتر می‌کند.

لایه ۲: IPS (درون‌خطی)

بارها را بازرسی کرده و حملات شناخته‌شده را در زمان واقعی مسدود می‌کند. آنچه را که فایروال از دست می‌دهد (حملات لایه برنامه) می‌گیرد.

لایه ۳: IDS (منفعل)

ناهنجاری‌ها، حملات ناشناخته و نقض سیاست را نظارت می‌کند. داده‌های پزشکی قانونی و تحلیل پس از حادثه را فراهم می‌کند.

اشتباه رایج: استقرار فقط یک فایروال و باور اینکه شبکه امن است. فایروال‌ها نمی‌توانند بار را بازرسی کنند — بدافزار در ترافیک HTTPS، تزریق SQL در بدنه HTTP POST و بهره‌برداری‌های روز-صفر همه از فایروال‌های ساده عبور می‌کنند. IDS/IPS ضروری است.

موارد استفاده — مثال‌های عملی

مثال ۱: مسدود کردن دانلود بدافزار

سناریو: کاربر در 192.168.1.50 روی یک لینک فیشینگ کلیک کرده و مرورگر GET /malware.exe را از evil.com درخواست می‌کند.

گام ۱: فایروال TCP/443 (HTTPS) به evil.com را می‌بیند — HTTPS خروجی توسط قانون مجاز است. عبور می‌کند.

گام ۲: IPS دست‌دهی TLS را بازرسی می‌کند — گواهی evil.com خود-امضا و در فید اطلاعات تهدید شناخته‌شده-بد است ← BLOCK.

گام ۳: حتی اگر IPS از دست بدهد (مثلاً CA مورد اعتماد)، فایل دانلودشده از IDS عبور می‌کند که هش فایل را با پایگاه داده امضای بدافزار مقایسه می‌کند.

گام ۴: IDS با هش مطابقت دارد ← ALERT. فایل توسط حفاظت نقطه پایانی قرنطینه می‌شود.

نتیجه: دفاع در عمق بدافزار را در چندین لایه می‌گیرد. هیچ نقطه شکست واحدی وجود ندارد.

مثال ۲: جلوگیری از شناسایی داخلی

سناریو: مهاجم 192.168.1.100 را آلوده کرده و زیرشبکه داخلی 10.0.0.0/8 را اسکن می‌کند.

گام ۱: فایروال هیچ قانونی علیه ترافیک داخلی-به-داخلی ندارد — عبور می‌کند.

گام ۲: IDS در پورت SPAN داخلی می‌بیند 192.168.1.100 بسته‌های SYN به 10.0.0.0/8 پورت‌های ۲۲، ۸۰، ۴۴۳ ارسال می‌کند.

گام ۳: IDS هشدار ناهنجاری را فعال می‌کند: "میزبان داخلی در حال اسکن محدوده‌های خصوصی — احتمال حرکت جانبی."

گام ۴: SOC 192.168.1.100 را ایزوله می‌کند. میزبان آلوده قبل از خروج داده مهار می‌شود.

نتیجه: IDS داخلی حرکت جانبی نامرئی برای فایروال محیطی را شناسایی می‌کند. پاسخ به حادثه باعث مهار می‌شود.

مثال ۳: تشخیص تونل DNS

سناریو: میزبان آلوده داده‌های دزدیده‌شده را در پرس‌وجوهای DNS رمزگذاری می‌کند: base64encodeddata.evil.com

گام ۱: فایروال UDP/53 (DNS) به سرورهای خارجی را مجاز می‌کند — نیاز تجاری قانونی.

گام ۲: IDS طول پرس‌وجوهای DNS را نظارت می‌کند. پرس‌وجوهای معمولی DNS: ۲۰–۵۰ کاراکتر. این پرس‌وجوها: ۲۰۰+ کاراکتر.

گام ۳: امضا: "طول پرس‌وجو DNS > ۱۰۰ کاراکتر با آنتروپی زیردامنه بالا" ← خروج داده.

گام ۴: هشدار: CRITICAL — تونل DNS شناسایی شد. منبع 192.168.1.77 در حال خروج داده به evil.com.

نتیجه: خروج داده از طریق تونل DNS (نامرئی برای فایروال) توسط تحلیل امضای IDS گرفته می‌شود.

اشتباه رایج: عدم نظارت بر ترافیک داخلی. بسیاری از سازمان‌ها همه امنیت را در محیط متمرکز کرده و فرض می‌کنند ترافیک داخلی ایمن است. وقتی یک مهاجم از محیط عبور کند، حرکت جانبی در صورت نبود نظارت داخلی شناسایی نمی‌شود. همیشه IDS را در بخش‌های داخلی نیز مستقر کنید.

محدودیت‌های فایروال‌ها و IDS

نمی‌تواند همه چیز را متوقف کند

حملات جدید بدون امضا به طور کامل از IDS عبور می‌کنند. فایروال‌ها نمی‌توانند حملات روی پورت‌های مجاز را مسدود کنند (مثلاً تزریق SQL روی TCP/80).

نابینایی ترافیک رمزگذاری‌شده

با TLS فراگیر، فایروال‌ها و IDS نمی‌توانند محتویات بار را بدون رهگیری SSL/TLS (پراکسی MITM) بازرسی کنند که نگرانی‌های حریم خصوصی ایجاد می‌کند.

محدودیت منابع

بازرسی عمیق بسته نیاز به CPU/حافظه قابل توجهی دارد. در نرخ خط ۱۰ گیگابیت بر ثانیه و بالاتر، بسیاری از دستگاه‌های IDS/IPS نمی‌توانند همراهی کنند و ممکن است بسته‌ها را رها کنند.

مرجع سریع بهترین شیوه‌ها

بهترین شیوه‌های فایروال

• سیاست پیش‌فرض-رد

• مسدود کردن ICMP echo ورودی/خروجی

• محدود کردن پورت‌های بالا (>1023)

• ثبت ترافیک ردشده برای تحلیل

• بازبینی فصلی قوانین

بهترین شیوه‌های IDS/IPS

• به‌روزرسانی روزانه امضاها

• تنظیم قوانین برای کاهش FP

• استقرار هم درون‌خطی و هم منفعل

• نظارت بر بخش‌های داخلی نیز

• همبستگی با لاگ‌های فایروال

امنیت عمومی

• دفاع در عمق ضروری است

• رمزگذاری همه چیز (TLS 1.3)

• بخش‌بندی شبکه (VLAN)

• خودکارسازی پاسخ به حادثه

• انجام تست نفوذ دوره‌ای
