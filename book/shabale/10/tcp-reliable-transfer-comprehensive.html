فرستنده TCP — سه رویداد اصلی

TCP یک سرویس انتقال داده قابل اطمینان بر روی سرویس غیرقابل اطمینان IP ایجاد می‌کند. فرستنده دو متغیر کلیدی را مدیریت می‌کند:

SendBase

شماره توالی قدیمی‌ترین بایت تأییدنشده. SendBase - 1 آخرین بایتی است که به ترتیب دریافت تأیید شده است.

NextSeqNum

شماره توالی بایت بعدی که باید ارسال شود.

سه رویداد (فرستنده TCP ساده‌شده)

رویدادعمل
۱. داده از برنامه بالا ایجاد سگمنت با seq = NextSeqNum; اگر تایمر در حال اجرا نیست، آن را شروع کن; ارسال به IP; NextSeqNum += length(data)
۲. Timeout ارسال مجدد قدیمی‌ترین سگمنت تأییدنشده; راه‌اندازی مجدد تایمر
۳. دریافت ACK (مقدار y) اگر y > SendBase: SendBase = y; اگر سگمنت‌های تأییدنشده باقی مانده، تایمر را مجدداً راه‌اندازی کن

شبه‌کد فرستنده

NextSeqNum = InitialSeqNumber; SendBase = InitialSeqNumber; loop forever { switch (event) { case data from application: create segment with seq = NextSeqNum; if (timer not running) start timer; pass segment to IP; NextSeqNum += length(data); break; case timeout: retransmit oldest unacknowledged segment; start timer; break; case ACK received (value y): if (y > SendBase) { SendBase = y; if (unacknowledged segments remain) start timer; } break; } }
⚠ نکته کلیدی: TCP از یک تایمر واحد برای قدیمی‌ترین سگمنت تأییدنشده استفاده می‌کند، نه یک تایمر به ازای هر سگمنت. این کار مدیریت تایمر را ساده می‌کند.

سناریوهای ارسال مجدد

سناریو ۱: ACK گم‌شده

میزبان A seq=92 (۸ بایت) می‌فرستد. سگمنت می‌رسد، اما ACK=100 B گم می‌شود.

عمل: Timeout رخ می‌دهد. A seq=92 را دوباره ارسال می‌کند. B کپی تکراری را دریافت می‌کند، دور می‌ریزد، دوباره ACK=100 می‌فرستد.

هیچ آسیبی — تشخیص تکراری از طریق شماره‌های توالی از خرابی داده جلوگیری می‌کند.

سناریو ۲: ACK تجمعی از ارسال‌های مجدد غیرضروری جلوگیری می‌کند

میزبان A دو سگمنت می‌فرستد: seq=92 (۸ بایت) و seq=100 (۲۰ بایت).

هر دو به B می‌رسند. B ACK=100 و ACK=120 می‌فرستد.

ACK=100 گم می‌شود، اما قبل از timeout، A ACK=120 را دریافت می‌کند.

عمل: از آنجا که ACK=120 > SendBase=92، SendBase = 120. نیازی به ارسال مجدد نیست!

ACKهای تجمعی استحکام فراهم می‌کنند: یک ACK بعدی تمام داده‌های قبلی را به طور ضمنی تأیید می‌کند.

سناریو ۳: دوبرابر شدن فاصله Timeout

قانون عقب‌نشینی نمایی
On timeout: TimeoutInterval = TimeoutInterval × 2
هر timeout متوالی فاصله را دوبرابر می‌کند: ۰.۷۵s → ۱.۵s → ۳.۰s → ۶.۰s

این یک شکل محدود از کنترل ازدحام فراهم می‌کند. Timeout احتمالاً به معنای ازدحام است; ارسال مجدد persistent آن را بدتر می‌کند.

ارسال مجدد سریع

دوره‌های Timeout می‌توانند نسبتاً طولانی باشند. فرستنده می‌تواند با مشاهده ACKهای تکراری زودتر گم‌شدگی بسته را تشخیص دهد.

چگونگی ایجاد ACKهای تکراری

وقتی گیرنده یک شکاف (سگمنت خارج‌ازترتیب) تشخیص می‌دهد، یک ACK تکراری برای آخرین بایت به‌ترتیب دریافت‌شده می‌فرستد.

رویدادعمل گیرنده [RFC 5681]
سگمنت به‌ترتیب می‌رسد، ACK در انتظار نیستACK تأخیری (تا ۵۰۰ میلی‌ثانیه برای سگمنت بعدی صبر کن)
سگمنت به‌ترتیب می‌رسد، یک ACK در انتظار استفوراً ACK تجمعی بفرست
سگمنت خارج‌ازترتیب (شکاف تشخیص داده شد)فوراً ACK تکراری بفرست (seq بایت مورد انتظار بعدی)
سگمنت شکاف را جزئی/کامل پر می‌کندفوراً ACK بفرست (انتهای پایینی شکاف)

الگوریتم ارسال مجدد سریع

event: ACK received, value y if (y > SendBase) { SendBase = y; if (unacknowledged segments remain) start timer; } else { // duplicate ACK dupACKcount[y]++; if (dupACKcount[y] == 3) { // 3 duplicate ACKs → fast retransmit resend segment with seq = y; } }
⚠ چرا ۳ ACK تکراری؟ یک ACK تکراری تنها می‌تواند ناشی از تغییر ترتیب بسته باشد، نه گم‌شدگی. سه ACK تکراری به شدت نشان می‌دهد که سگمنت گم شده است.

در نمودار ارسال مجدد سریع (شکل ۳.۳۷)، سگمنت seq=100 گم می‌شود. فرستنده ۴ ACK برای seq=100 دریافت می‌کند (یک اصلی + سه تکراری)، که باعث ارسال مجدد seq=100 قبل از انقضای تایمر آن می‌شود.

GBN در مقابل SR در TCP

TCP نه کاملاً GBN است و نه کاملاً SR — یک ترکیبی است که ویژگی‌های هر دو را ترکیب می‌کند.

ویژگیGo-Back-NSelective RepeatTCP
نوع ACKتجمعیفردی (انتخابی)تجمعی (مشابه GBN)

بافر خارج‌ازترتیبخیر (دور می‌ریزد)بلهبله (مشابه SR، در عمل)
اندازه پنجرهN ثابتN ثابتپویا (rwnd, cwnd)
تایمرهای متعددتکیبه ازای هر بستهتکی (مشابه GBN)

چرا TCP یک ترکیبی است

ویژگی‌های مشابه GBN

• ACKهای تجمعی — یک ACK تمام بایت‌های قبلی را پوشش می‌دهد

• تایمر واحد برای قدیمی‌ترین سگمنت تأییدنشده

• مدیریت پنجره SendBase + NextSeqNum

ویژگی‌های مشابه SR

• بافر سگمنت‌های خارج‌ازترتیب (پیاده‌سازی‌های مدرن)

• فقط یک سگمنت را در timeout ارسال مجدد می‌کند (نه همه N تا)

• ACK انتخابی (SACK، RFC 2018) تأیید صریح انتخابی اضافه می‌کند

مکانیزم بازیابی خطای TCP به بهترین شکل به عنوان یک ترکیبی از پروتکل‌های GBN و SR دسته‌بندی می‌شود. SACK [RFC 2018] TCP را حتی بیشتر شبیه SR می‌کند با اجازه به گیرندگان برای تأیید انتخابی سگمنت‌های خارج‌ازترتیب.

مثال‌های عملی

مثال ۱: Timeout و ارسال مجدد

تنظیمات: میزبان A سگمنت seq=500 (۱۰۰ بایت) می‌فرستد. TimeoutInterval = ۲۰۰ میلی‌ثانیه.

توالی:

t=0 ms: A seq=500 را می‌فرستد، تایمر را شروع می‌کند.

t=10 ms: سگمنت به B می‌رسد. B ACK=600 می‌فرستد.

t=20 ms: ACK=600 گم می‌شود (سرریز بافر مسیریاب).

t=200 ms: تایمر فعال می‌شود (هیچ ACK دریافت نشد). A seq=500 را دوباره ارسال می‌کند، تایمر را مجدداً راه‌اندازی می‌کند (دوبرابر شده به ۴۰۰ میلی‌ثانیه).

t=210 ms: سگمنت دوباره ارسال شده می‌رسد. B seq=500 (تکراری) را می‌بیند، داده را دور می‌ریزد، ACK=600 می‌فرستد.

t=220 ms: ACK=600 به A می‌رسد. SendBase = 600. تایمر متوقف می‌شود.

تأخیر کل ناشی از گم‌شدگی: ~۲۲۰ میلی‌ثانیه (شامل ارسال مجدد و انتشار).

مثال ۲: ACK تجمعی از ارسال مجدد جلوگیری می‌کند

تنظیمات: A seq=200 (۵۰ بایت) و seq=250 (۶۰ بایت) می‌فرستد.

توالی:

t=0: ارسال seq=200. t=1: ارسال seq=250.

t=10: B seq=200 را دریافت می‌کند، ACK=250 می‌فرستد.

t=12: B seq=250 را دریافت می‌کند، ACK=310 می‌فرستد.

t=20: ACK=250 گم می‌شود. t=22: ACK=310 می‌رسد.

A بررسی می‌کند: ACK=310 > SendBase(200). SendBase = 310. تایمر متوقف می‌شود.

حتی اگر ACK=250 گم شد، نیازی به ارسال مجدد نبود زیرا ACK=310 تمام داده تا بایت ۳۱۰ را تأیید می‌کند.

مثال ۳: تشخیص ارسال مجدد سریع

تنظیمات: A ۴ سگمنت می‌فرستد: seq=1000 (100B), seq=1100 (100B), seq=1200 (100B), seq=1300 (100B).

گم‌شدگی: سگمنت seq=1100 در یک مسیریاب رها می‌شود.

رویدادهای گیرنده:

• دریافت seq=1000 → ACK=1100

• دریافت seq=1200 (خارج‌ازترتیب) → ACK=1100 تکراری (شکاف همچنان در ۱۱۰۰)

• دریافت seq=1300 (خارج‌ازترتیب) → ACK=1100 تکراری

رویدادهای فرستنده:

• دریافت ACK=1100 (اصلی) → SendBase = 1100

• دریافت dup ACK=1100 (از seq=1200) → dupCount=1

• دریافت dup ACK=1100 (از seq=1300) → dupCount=2

• دریافت dup ACK=1100 (از seq=1400، اگر فرستاده شود) → dupCount=3 → ارسال مجدد سریع seq=1100!

ارسال مجدد سریع از انتظار برای timeout (که می‌تواند صدها میلی‌ثانیه باشد) جلوگیری می‌کند.

مثال ۴: ACK تکراری ناشی از تغییر ترتیب بسته

تنظیمات: A seq=500 (80B), seq=580 (80B), seq=660 (80B) می‌فرستد.

شبکه تغییر ترتیب می‌دهد: seq=580 قبل از seq=500 می‌رسد (غیرمعمول اما ممکن).

گیرنده:

• ابتدا seq=580 را دریافت می‌کند (خارج‌ازترتیب، منتظر ۵۰۰) → ACK=500 تکراری

• seq=500 را دریافت می‌کند (اکنون به‌ترتیب) → بایت‌های ۵۰۰-۵۷۹ را تحویل می‌دهد، ACK=660 (تجمعی)

• seq=660 را دریافت می‌کند → ACK=740

فرستنده: یک ACK=500 تکراری دریافت می‌کند اما نه سه تا. هیچ ارسال مجدد سریعی فعال نمی‌شود.

TCP تغییر ترتیب بسته را تحمل می‌کند — یک ACK تکراری برای فعال کردن ارسال مجدد کافی نیست. این از ارسال مجدد غیرضروری وقتی بسته‌ها فقط تأخیر دارند/تغییر ترتیب یافته‌اند جلوگیری می‌کند.

مثال ۵: رفتار GBN در مقابل TCP با گم‌شدگی‌های متعدد

تنظیمات: پنجره ۵ سگمنت ارسال شده: seq=1,2,3,4,5. سگمنت ۲ گم می‌شود.

رفتار GBN: وقتی فرستنده روی سگمنت ۲ timeout می‌شود، همه سگمنت‌های تأییدنشده را دوباره ارسال می‌کند: ۲,۳,۴,۵.

رفتار TCP: وقتی timeout رخ می‌دهد، TCP فقط سگمنت با کوچکترین شماره توالی (seq=2) را دوباره ارسال می‌کند.

سگمنت‌های ۳,۴,۵ ممکن است قبلاً در گیرنده بافر شده باشند. وقتی ACKهای ۳,۴,۵ می‌رسند (احتمالاً بعد از ارسال مجدد ۲)، برای پیشبرد SendBase استفاده می‌شوند.

TCP از GBN خالص پهنای‌باند-کارآمدتر است; از ارسال مجدد سگمنت‌هایی که قبلاً دریافت شده‌اند جلوگیری می‌کند.
