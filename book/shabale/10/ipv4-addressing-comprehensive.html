آدرس‌دهی IPv4 و زیرشبکه‌ها

شبکه‌های کامپیوتری (کروس و راس) — فصل ۴

آدرس‌های IP به رابط‌ها مرتبط هستند، نه به میزبان‌ها

در اصطلاحات IP، هر آدرس IP به یک رابط گره خورده است — نقطه اتصال فیزیکی یا منطقی بین یک میزبان/مسیریاب و یک لینک. یک مسیریاب با چندین لینک دارای چندین رابط است که هرکدام آدرس IP خود را دارند. یک میزبان معمولاً یک رابط دارد (Ethernet یا Wi-Fi NIC آن)، اما می‌تواند چندین داشته باشد.

+---------------------------+ +---------------------------+ | Host A (223.1.1.1) | | Host B (223.1.1.2) | | Interface: eth0 | | Interface: eth0 | +-----|---------------------+ +-----|---------------------+ | | | 223.1.1.0/24 LAN | +--------------------------------------+ | +-------------|---------------------+ | Router R1 | | eth0: 223.1.1.4 | | eth1: 223.1.2.9 | | eth2: 223.1.3.7 | +----------------------------------+ Each interface of the router has a distinct IP.
اندازه بنیادی:
2³² = ۴,۲۹۴,۹۶۷,۲۹۶ ≈ ۴.۳ میلیارد آدرس
IPv4 از آدرس‌های ۳۲ بیتی استفاده می‌کند که تقریباً ۴.۳ میلیارد مقدار ممکن را می‌دهد.
نماد نقطه-دهدهی:
193.32.216.9
هر آدرس ۳۲ بیتی به صورت چهار عدد دهدهی (هرکدام ۸ بیت) نوشته می‌شود که با نقطه از هم جدا شده‌اند.
اشتباه رایج: فکر کردن اینکه یک آدرس IP "متعلق به" یک کامپیوتر است. یک آدرس IP به یک رابط تخصیص داده می‌شود، نه خود دستگاه. یک مسیریاب با ۳ لینک دارای ۳ آدرس IP مختلف — یکی به ازای هر رابط است.

شبکه‌ای را در نظر بگیرید: میزبان A به سوئیچ S1 متصل است، S1 به مسیریاب R1 از طریق پورت eth0 متصل است، R1 همچنین eth1 به مسیریاب R2 دارد، و R2 eth0 به میزبان B دارد.

زیرشبکه‌ها — گروه‌بندی رابط‌ها بر اساس پیشوند شبکه

یک زیرشبکه گروهی از رابط‌ها است که پیشوند شبکه یکسانی دارند و می‌توانند بدون عبور از یک مسیریاب مستقیماً با یکدیگر ارتباط برقرار کنند. هر زیرشبکه ایزوله است — عبور از مرزهای زیرشبکه نیاز به یک مسیریاب IP دارد.

یک زیرشبکه همچنین IP network یا به سادگی network در ادبیات اینترنت نامیده می‌شود [RFC 950].

لینک‌های نقطه-به-نقطه بین مسیریاب‌ها نیز زیرشبکه تشکیل می‌دهند. برای مثال، رابط‌هایی که مسیریاب R1 و مسیریاب R2 را روی یک لینک مانند 223.1.9.0/24 متصل می‌کنند، یک زیرشبکه جداگانه را تشکیل می‌دهند، حتی اگر فقط دو رابط متصل باشند.

نماد زیرشبکه:
223.1.1.0/24
/24 نشان می‌دهد که ۲۴ بیت اول پیشوند شبکه هستند. ۸ بیت باقی‌مانده میزبان‌های درون آن زیرشبکه را شناسایی می‌کنند.

روش شناسایی زیرشبکه‌ها

PROCEDURE DetermineSubnets(network_topology): FOR each router interface: DETACH the interface from the router FOR each attached switch or link: COLLECT all interfaces connected to that link IF those interfaces share a common prefix: DECLARE them as one subnet END FOR END FOR RETURN list of all discovered subnets END PROCEDURE

قاعده سرانگشتی: هر مسیریاب را با یک ابر جایگزین کنید. تعداد بخش‌های شبکه ایزوله (ابرها) را بشمارید — این تعداد زیرشبکه شماست.

اشتباه رایج: فرض اینکه دو میزبان روی یک سوئیچ Ethernet همیشه در یک زیرشبکه هستند. آن‌ها فقط در یک زیرشبکه هستند اگر پیشوند شبکه یکسانی داشته باشند و رابط‌هایشان بتوانند بدون مسیریاب به یکدیگر برسند.
مثال ۱ — شبکه سه مسیریابه

شبکه: میزبان A (223.1.1.1) ↔ سوئیچ S1 ↔ مسیریاب R1 (223.1.1.4 eth0). R1 eth1 (223.1.2.9) ↔ مسیریاب R2 (223.1.2.8 eth0). R2 eth1 (223.1.3.7) ↔ سوئیچ S2 ↔ میزبان B (223.1.3.1).

زیرشبکه‌ها:

• زیرشبکه ۱: 223.1.1.0/24 (میزبان A, R1 eth0)

• زیرشبکه ۲: 223.1.2.0/24 (R1 eth1, R2 eth0) — لینک نقطه-به-نقطه

• زیرشبکه ۳: 223.1.3.0/24 (R2 eth1, میزبان B)

مجموع: ۳ زیرشبکه

مثال ۲ — تشبیه خانه

۳ خانه در یک خیابان را تصور کنید. هر خانه مسیریاب خود را دارد. درون یک خانه، همه دستگاه‌ها (تلفن‌ها، لپ‌تاپ‌ها) زیرشبکه یکسانی را به اشتراک می‌گذارند (مثلاً 192.168.1.0/24). دستگاه‌های خانه‌های مختلف در زیرشبکه‌های متفاوتی هستند (192.168.2.0/24، 192.168.3.0/24) و باید از طریق مسیریاب‌های مربوطه خود ارتباط برقرار کنند.

۳ زیرشبکه — یکی به ازای هر خانه

مثال ۳ — شبکه دانشگاهی

یک دانشگاه دارای: ساختمان اداری (10.0.1.0/24)، دپارتمان CS (10.0.2.0/24)، کتابخانه (10.0.3.0/24). هر ساختمان مسیریاب خود را دارد که به یک ستون فقرات دانشگاهی متصل است. سوئیچ داخلی هر ساختمان میزبان‌های خود را متصل می‌کند.

شبکه ایزوله

CIDR — مسیریابی بین دامنه‌ای بدون کلاس

CIDR (تلفظ "cider") در اواسط دهه ۱۹۹۰ جایگزین طرح آدرس‌دهی کلاسی سفت و سخت شد. با اجازه دادن به هر طول پیشوند، مفهوم زیرشبکه‌بندی را تعمیم می‌دهد که به صورت a.b.c.d/x بیان می‌شود که در آن x تعداد بیت‌های پیشوند شبکه است.

نماد CIDR:
a.b.c.d/x
x بیت اول پیشوند شبکه هستند؛ (32 − x) بیت باقی‌مانده میزبان را در آن شبکه شناسایی می‌کنند.
مثال:
200.23.16.0/20
پیشوند شبکه ۲۰ بیت است. شناسه میزبان ۱۲ بیت است. این 2¹² = 4096 آدرس کل می‌دهد که 4094 تای آن قابل استفاده هستند.

الگوریتم: تعیین پیشوند شبکه از نماد CIDR

PROCEDURE GetNetworkAddress(ip, prefix_len): subnet_mask = (0xFFFFFFFF << (32 - prefix_len)) & 0xFFFFFFFF network = ip & subnet_mask broadcast = ip | (~subnet_mask & 0xFFFFFFFF) RETURN (network, broadcast, subnet_mask) END PROCEDURE PROCEDURE IsSameSubnet(ip1, ip2, prefix_len): mask = (0xFFFFFFFF << (32 - prefix_len)) & 0xFFFFFFFF RETURN (ip1 & mask) == (ip2 & mask) END PROCEDURE
مثال ۱ — یافتن شبکه و Broadcast

با فرض 192.168.10.50/24:

طول پیشوند = 24 → ماسک = 255.255.255.0

شبکه = 192.168.10.0 (AND ip با ماسک)

Broadcast = 192.168.10.255 (OR ip با ماسک معکوس)

محدوده قابل استفاده: 192.168.10.1 – 192.168.10.254

مثال ۲ — بررسی زیرشبکه یکسان

آیا 10.20.30.1/20 و 10.20.40.1/20 در یک زیرشبکه هستند؟

ماسک = 255.255.240.0 (۲۰ بیت)

10.20.30.1 AND ماسک = 10.20.16.0

10.20.40.1 AND ماسک = 10.20.32.0

خیر — آن‌ها در زیرشبکه‌های متفاوتی هستند (10.20.16.0/20 در مقابل 10.20.32.0/20)

مثال ۳ — تخصیص بلوک CIDR

یک ISP بلوک 200.23.16.0/20 را دریافت کرده است. چند زیرشبکه /24 می‌تواند ایجاد کند؟

پیشوند /20 = ۱۲ بیت برای میزبان‌ها (32−20 = 12).

هر /24 از ۸ بیت برای میزبان‌ها استفاده می‌کند (32−24 = 8).

تعداد زیرشبکه‌های /24 = 2^(24−20) = 2⁴ = ۱۶ زیرشبکه

هر زیرشبکه /24 دارای ۲۵۴ آدرس قابل استفاده است.

ICANN — مرجع تخصیص آدرس IP

مزایای CIDR

• طول پیشوند انعطاف‌پذیر

• استفاده کارآمد از آدرس

• تجمیع مسیر

• کاهش سرعت depletion آدرس

آدرس‌دهی کلاسی — طرح اصلی

طراحی اصلی IP فضای آدرس ۳۲ بیتی را به کلاس‌های با اندازه ثابت تقسیم کرد. چند بیت اول یک آدرس کلاس آن را تعیین می‌کرد، که به نوبه خود تقسیم بین پیشوند شبکه و شناسه میزبان را مشخص می‌کرد. این طرح سفت و سخت منجر به کاهش شدید آدرس شد.

کلاس A:
پیشوند /8 (255.0.0.0)
بیت اول = 0. محدوده: 0.0.0.0 – 127.255.255.255. ۱۲۸ شبکه، ~۱۶ میلیون میزبان هرکدام.
کلاس B:
پیشوند /16 (255.255.0.0)
بیت‌های اول = 10. محدوده: 128.0.0.0 – 191.255.255.255. ~۱۶ هزار شبکه، ~۶۵ هزار میزبان هرکدام.
کلاس C:
پیشوند /24 (255.255.255.0)
بیت‌های اول = 110. محدوده: 192.0.0.0 – 223.255.255.255. ~۲ میلیون شبکه، ۲۵۴ میزبان هرکدام.

مثال ۱ — شناسایی کلاس

130.50.20.1 به کدام کلاس تعلق دارد؟

اولین octet = 130. در دودویی: 10000010. دو بیت اول "10" هستند → کلاس B (/16).

مثال ۲ — تصویر هدررفت

یک شرکت به ۳۰۰ آدرس IP نیاز دارد. تحت کلاسی: کلاس C (/24) 254 آدرس می‌دهد (خیلی کم)، کلاس B (/16) 65,534 آدرس می‌دهد (تخصیص بیش از حد عظیم). آن‌ها ۶۵,۲۳۴ آدرس را هدر می‌دادند.

تحت CIDR: آن‌ها یک بلوک /23 با ۵۱۰ آدرس قابل استفاده دریافت می‌کنند — فقط ۲۱۰ آدرس هدر می‌رود به جای ۶۵,۲۳۴.

مثال ۳ — مشکل ۲,۰۰۰ میزبانه

سازمانی را در نظر بگیرید که به ۲,۰۰۰ آدرس IP نیاز دارد. تحت آدرس‌دهی کلاسی:

• کلاس C (/24) فقط ۲۵۴ آدرس ارائه می‌دهد — خیلی کم.

• کلاس B (/16) ۶۵,۵۳۴ آدرس ارائه می‌دهد — تخصیص بیش از حد شدید.

به سازمان یک بلوک کلاس B تخصیص داده می‌شد که بیش از ۶۳,۰۰۰ آدرس را هدر می‌داد. این نوع هدررفت در بسیاری از سازمان‌ها منجر به کاهش سریع فضای آدرس کلاس B شد و یک انگیزه کلیدی برای CIDR بود.

مثال ۴ — تشخیص محدوده کلاسی

هرکدام را طبقه‌بندی کنید: 15.0.0.1، 172.16.0.1، 200.1.1.1، 224.0.0.1.

• 15 → 0xxxxxxx → کلاس A

• 172 → 10xxxxxx → کلاس B

• 200 → 110xxxxx → کلاس C

• 224 → 1110xxxx → کلاس D (multicast)

تشخیص کلاس

کلاس A: 0xxx | 0–127

کلاس B: 10xx | 128–191

کلاس C: 110x | 192–223

کلاس D: 1110 | 224–239

کلاس E: 1111 | 240–255

چرا کلاسی شکست خورد

• تعداد کلاس B کم (۱۶ هزار)

• تعداد کلاس C زیاد (۲ میلیون)

• سازمان‌ها کلاس B را احتکار کردند

• جداول مسیریابی منفجر شد

→ CIDR همه اینها را رفع کرد

تجمیع مسیر (Summarization)

تجمیع مسیر (خلاصه‌سازی مسیر یا تجمیع پیشوند) به یک پیشوند CIDR واحد اجازه می‌دهد یک بلوک از چندین پیشوند خاص‌تر را نشان دهد. این کار جداول مسیریابی را به طور چشمگیری کوچک می‌کند — یک هدف طراحی اصلی CIDR.

اصل تجمیع:
200.23.16.0/20 → ۸ بلوک /23 را تجمیع می‌کند
یک ISP که 200.23.16.0/20 را در اختیار دارد می‌تواند آن را به ۸ بلوک مساوی /23 تقسیم کرده و همچنان فقط یک مسیر /20 را اعلام کند.

الگوریتم: تطبیق طولانی‌ترین پیشوند

PROCEDURE LongestPrefixMatch(routing_table, destination_ip): best_match = null best_len = 0 FOR EACH entry IN routing_table: IF (destination_ip & entry.mask) == entry.network: IF entry.prefix_len > best_len: best_len = entry.prefix_len best_match = entry END IF END FOR RETURN best_match.next_hop END PROCEDURE

مثال ۳ — تجمیع بلوک‌های ناپیوسته

آیا 10.1.0.0/24 و 10.2.0.0/24 قابل تجمیع هستند؟

بررسی: 10.1.0.0 در دودویی = 00001010.00000001.00000000.00000000

10.2.0.0 در دودویی = 00001010.00000010.00000000.00000000

۱۵ بیت اول مطابقت دارند (00001010.0000000)، اما بیت ۱۶ متفاوت است (1 در مقابل 2).

آن‌ها می‌توانند به عنوان 10.0.0.0/13 به علاوه مسیرهای /24 خاص درون آن تجمیع شوند، اما حداقل بلوک واحد پوشش‌دهنده هر دو 10.0.0.0/14 است (که همچنین شامل 10.0.0.0/24 و 10.3.0.0/24 می‌شود).

بهترین تجمیع: 10.0.0.0/14 — اگرچه这可能 شامل محدوده‌های ناخواسته شود.

مثال ۴ — ادغام Fly-By-Night-ISP و ISPs-R-Us

فرض کنید Fly-By-Night-ISP مالک بلوک CIDR 200.23.16.0/20 است و 200.23.18.0/23 را به سازمان ۱ تخصیص داده است. ISPs-R-Us مالک بلوک 199.31.0.0/16 است. وقتی Fly-By-Night-ISP، ISPs-R-Us را خریداری می‌کند، سازمان ۱ (که هنوز از 200.23.18.0/23 استفاده می‌کند) اکنون مشتری ISPs-R-Us است.

ISPs-R-Us باید هم بلوک خود (199.31.0.0/16) و بلوک سازمان ۱ (200.23.18.0/23) را به بقیه اینترنت اعلام کند.

سایر مسیریاب‌ها از تطبیق طولانی‌ترین پیشوند استفاده می‌کنند: مسیر /23 برای سازمان ۱ خاص‌تر از مسیر /20 Fly-By-Night-ISP است. بسته‌های مقصد سازمان ۱ به ISPs-R-Us ارسال می‌شوند، نه Fly-By-Night-ISP، زیرا پیشوند /23 (۲۳ بیت) طولانی‌تر از پیشوند /20 (۲۰ بیت) است.

اشتباه رایج: فکر کردن اینکه تجمیع به بلوک‌های آدرس پیوسته درون پیشوند والد نیاز دارد. بلوک‌ها باید پیوسته و هم‌تراز با مرزهای توان ۲ باشند. شما نمی‌توانید 200.23.17.0/24 و 200.23.19.0/24 را به 200.23.16.0/22 تجمیع کنید بدون اینکه 200.23.16.0/24 و 200.23.18.0/24 را نیز پوشش دهید.
