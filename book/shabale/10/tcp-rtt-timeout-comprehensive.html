تخمین RTT و Timeout در TCP

شبکه‌های کامپیوتری — راهنمای جامع برای آزمون ۲۰/۲۰

تخمین زمان رفت و برگشت (RTT)

TCP از یک مکانیزم timeout/ارسال مجدد برای بازیابی از سگمنت‌های گم‌شده استفاده می‌کند. فاصله timeout باید بزرگتر از RTT اتصال باشد، اما تخمین RTT به دلیل تغییرپذیری ازدحام شبکه چالش‌برانگیز است.

SampleRTT

SampleRTT
SampleRTT = زمان از ارسال سگمنت → دریافت ACK
SampleRTT فقط برای یک سگمنت در یک زمان اندازه‌گیری می‌شود (نه همزمان برای چندین سگمنت برجسته). این به عنوان اندازه‌گیری "یک بار در هر RTT" شناخته می‌شود. هرگز برای سگمنت‌های دوباره ارسال شده محاسبه نمی‌شود.

یک نمونه در هر بار

در هر نقطه، فقط یک سگمنت در حال زمان‌بندی است. یک SampleRTT جدید تقریباً هر RTT یک بار به دست می‌آید.

الگوریتم Karn

هرگز SampleRTT را برای سگمنت‌های دوباره ارسال شده محاسبه نکن — مبهم است که ACK برای نسخه اصلی است یا ارسال مجدد.

EstimatedRTT (میانگین متحرک موزون نمایی)

فرمول EstimatedRTT (EWMA)
EstimatedRTT = (1 - α) × EstimatedRTT + α × SampleRTT
α = ۰.۱۲۵ (۱/۸). نمونه‌های اخیر وزن بیشتری می‌گیرند; نمونه‌های قدیمی به صورت نمایی تحلیل می‌روند.
// شبه‌کد بروزرسانی EstimatedRTT // α = 0.125 EstimatedRTT = 0.875 * EstimatedRTT + 0.125 * SampleRTT;

EWMA نوسانات کوتاه‌مدت را هموار می‌کند. α کوچک تخمین را نسبت به جهش‌های گذرا کمتر حساس می‌کند.

محاسبه Timeout

DevRTT — تغییرپذیری RTT

فرمول DevRTT
DevRTT = (1 - β) × DevRTT + β × |SampleRTT - EstimatedRTT|
β = ۰.۲۵. معیاری از میزان انحراف SampleRTT از EstimatedRTT.

نوسان کم

اگر SampleRTT به طور مداوم نزدیک EstimatedRTT باشد، DevRTT کوچک است.

نوسان زیاد

اگر SampleRTT به طور گسترده تغییر کند، DevRTT بزرگ است و به حاشیه ایمنی بزرگتری نیاز دارد.

TimeoutInterval

فرمول TimeoutInterval
TimeoutInterval = EstimatedRTT + 4 × DevRTT
۴ انحراف معیار از devRTT را به عنوان حاشیه ایمنی اضافه می‌کند.

قوانین مدیریت Timeout

قانونمقداردلیل
TimeoutInterval اولیه۱ ثانیه (RFC 6298)شروع محافظه‌کارانه قبل از هر نمونه RTT
بعد از timeout (عقب‌نشینی نمایی)Timeout × 2جلوگیری از طوفان ارسال مجدد در طول ازدحام
بعد از رسیدن ACK جدیدمحاسبه مجدد از EstimatedRTT + ۴×DevRTTبازنشانی به شرایط جاری شبکه
⚠ اشتباه رایج: دوبرابر کردن TimeoutInterval در timeout جدا از فرمول بالاست. عقب‌نشینی نمایی توسط رویداد timeout فعال می‌شود، نه توسط پردازش معمولی ACK.

شبه‌کد الگوریتم

// وقتی یک SampleRTT جدید به دست می‌آید: EstimatedRTT = 0.875 * EstimatedRTT + 0.125 * SampleRTT; DevRTT = 0.75 * DevRTT + 0.25 * |SampleRTT - EstimatedRTT|; TimeoutInterval = EstimatedRTT + 4 * DevRTT; // وقتی timeout رخ می‌دهد: TimeoutInterval = TimeoutInterval * 2; // (قدیمی‌ترین سگمنت تأییدنشده را دوباره ارسال کن، تایمر را مجدداً راه‌اندازی کن) // در دریافت ACK (غیر تکراری): // TimeoutInterval را از جدیدترین EstimatedRTT و DevRTT محاسبه مجدد کن

مثال‌های عملی

مثال ۱: توالی تخمین RTT اولیه

داده شده: EstimatedRTT اولیه = ۱۰۰ ms، DevRTT = ۱۰ ms.

مقادیر SampleRTT: ۱۲۰ ms، ۹۰ ms، ۱۱۰ ms، ۱۳۰ ms.

مرحله ۱ — SampleRTT = ۱۲۰ ms:

EstimatedRTT = 0.875 × 100 + 0.125 × 120 = 87.5 + 15 = ۱۰۲.۵ ms

DevRTT = 0.75 × 10 + 0.25 × |120 - 102.5| = 7.5 + 4.375 = ۱۱.۸۷۵ ms

Timeout = 102.5 + 4 × 11.875 = 102.5 + 47.5 = ۱۵۰ ms

مرحله ۲ — SampleRTT = ۹۰ ms:

EstimatedRTT = 0.875 × 102.5 + 0.125 × 90 = 89.6875 + 11.25 = ۱۰۰.۹۳۷۵ ms

DevRTT = 0.75 × 11.875 + 0.25 × |90 - 100.9375| = 8.90625 + 2.734 = ۱۱.۶۴ ms

Timeout = 100.9375 + 4 × 11.64 = 100.9375 + 46.56 = ۱۴۷.۵ ms

مرحله ۳ — SampleRTT = ۱۱۰ ms:

EstimatedRTT = 0.875 × 100.9375 + 0.125 × 110 = 88.32 + 13.75 = ۱۰۲.۰۷ ms

DevRTT = 0.75 × 11.64 + 0.25 × |110 - 102.07| = 8.73 + 1.98 = ۱۰.۷۱ ms

Timeout = 102.07 + 4 × 10.71 = 102.07 + 42.84 = ۱۴۴.۹۱ ms

مرحله ۴ — SampleRTT = ۱۳۰ ms:

EstimatedRTT = 0.875 × 102.07 + 0.125 × 130 = 89.31 + 16.25 = ۱۰۵.۵۶ ms

DevRTT = 0.75 × 10.71 + 0.25 × |130 - 105.56| = 8.03 + 6.11 = ۱۴.۱۴ ms

Timeout = 105.56 + 4 × 14.14 = 105.56 + 56.56 = ۱۶۲.۱۲ ms

توجه کنید timeout چگونه تطبیق می‌یابد: وقتی RTT افزایش می‌یابد، DevRTT رشد می‌کند و حاشیه timeout را بزرگتر می‌کند.

مثال ۲: عقب‌نشینی نمایی در Timeout

داده شده: EstimatedRTT = ۸۰ ms، DevRTT = ۵ ms.

TimeoutInterval = 80 + 4 × 5 = ۱۰۰ ms

Timeout رخ می‌دهد: هیچ ACK در ۱۰۰ ms دریافت نشد.

TCP دوباره ارسال می‌کند و تنظیم می‌کند: TimeoutInterval = 100 × 2 = ۲۰۰ ms

دومین timeout رخ می‌دهد: ۲۰۰ ms بعد، هنوز ACK نیست.

TimeoutInterval = 200 × 2 = ۴۰۰ ms

سومین timeout: TimeoutInterval = 400 × 2 = ۸۰۰ ms

نهایتاً ACK می‌رسد: TimeoutInterval از جدیدترین EstimatedRTT و DevRTT محاسبه مجدد می‌شود (به مقدار مبتنی بر فرمول بازنشانی می‌شود).

عقب‌نشینی از غرق شدن شبکه با ارسال‌های مجدد در طول ازدحام جلوگیری می‌کند.

مثال ۳: تأثیر یک جهش در RTT

داده شده: EstimatedRTT = ۵۰ ms، DevRTT = ۸ ms، Timeout = 50 + 32 = ۸۲ ms.

شبکه دچار ازدحام می‌شود: SampleRTT به ۲۰۰ ms می‌پرد.

EstimatedRTT جدید = 0.875 × 50 + 0.125 × 200 = 43.75 + 25 = ۶۸.۷۵ ms

DevRTT جدید = 0.75 × 8 + 0.25 × |200 - 68.75| = 6 + 32.81 = ۳۸.۸۱ ms

Timeout جدید = 68.75 + 4 × 38.81 = 68.75 + 155.24 = ۲۲۴ ms

timeout به طور چشمگیری افزایش می‌یابد تا تغییرپذیری جدید را در خود جای دهد. بدون DevRTT، timeout فقط ~۶۸.۷۵ + حاشیه کوچک می‌بود و باعث timeoutهای زودرس می‌شد.

DevRTT از ارسال مجدد غیرضروری وقتی RTT ناگهان افزایش می‌یابد جلوگیری می‌کند.
