بررسی اجمالی پردازش پورت ورودی

وقتی یک بسته به پورت ورودی یک مسیریاب می‌رسد، سه تابع متوالی در لایه‌های فیزیکی، پیوند و شبکه قبل از ارسال بسته اجرا می‌شوند.

خط لوله پورت ورودی:

هر مرحله باید قبل از شروع مرحله بعد کامل شود؛ جستجو گلوگاه است.

مکانیزم کپی سایه

پردازنده مسیریابی جدول ارسال را در نرم‌افزار محاسبه می‌کند. یک کپی سایه به هر کارت خط ارسال می‌شود تا جستجوها بدون درگیر کردن پردازنده مرکزی در نرخ خط انجام شوند.

جدول ارسال را از طریق پروتکل‌های مسیریابی (OSPF, BGP) با تعامل با سایر مسیریاب‌ها محاسبه می‌کند

ملاحظات حافظه جستجوی سریع

⚡ زمان‌های دسترسی حافظه:

جستجوهای ارسال باید در عرض نانوثانیه کامل شوند تا با نرخ‌های خط هماهنگ باشند. مسیریاب‌ها از DRAM روی تراشه و SRAM سریع‌تر (که به عنوان حافظه نهان DRAM استفاده می‌شود) برای ذخیره جداول ارسال و فعال‌سازی جستجوهای سریع استفاده می‌کنند. باید به زمان‌های دسترسی حافظه توجه ویژه شود — یک دسترسی DRAM واحد (~50 ns) می‌تواند بیشتر بودجه جستجو را در نرخ‌های خط بالا مصرف کند. حافظه‌های نهان SRAM با ذخیره‌سازی پیشوندهای پرتطبیق این مشکل را کاهش می‌دهند. برای بررسی الگوریتم‌های جستجوی سریع، به [Gupta 2001, Ruiz-Sanchez 2001] مراجعه کنید.

مثال ۱: بسته ورودی به مسیریاب R1

یک دیتاگرام IP 1500 بایتی روی پورت ورودی ۲ مسیریاب R1 از طریق یک لینک ۱ گیگابیت بر ثانیه می‌رسد.

نتیجه: بسته در کمتر از ۱ μs زمان جستجو از پورت ۱ ارسال شد.

مثال ۲: انتشار به‌روزرسانی جدول مسیریابی

یک به‌روزرسانی BGP به پردازنده مسیریابی می‌رسد و گام بعدی برای پیشوند 200.23.18.0/23 را تغییر می‌دهد.

زمان t=0: پردازنده مسیریابی جدول ارسال را دوباره محاسبه می‌کند.

مثال ۳: غیرعملی بودن روش brute-force

مثال ۳: چرا ۲32 ورودی شکست می‌خورد

یک جدول ارسال ساده‌لوحانه که یک ورودی به ازای هر آدرس IP فهرست می‌کند، شامل ۴,۲۹۴,۹۶۷,۲۹۶ ورودی خواهد بود.

در نرخ خط ۱ گیگابیت بر ثانیه با بسته‌های ۶۴ بایتی (~1.49 Mpps)، بودجه جستجو ۶۷۲ ns به ازای هر بسته است.

اسکن خطی ۴ میلیارد ورودی با ۱۰ ns به ازای هر ورودی ~۴۳ ثانیه طول می‌کشد — ۶۴ میلیون بار کندتر.

راه‌حل: تجمیع مبتنی بر پیشوند، جدول را به حدود ۹۰۰ هزار ورودی کاهش می‌دهد (جدول کامل BGP).

⚠ اشتباه رایج:

دانشجویان اغلب فکر می‌کنند پردازنده مسیریابی جستجوهای هر بسته را انجام می‌دهد. در عمل، پردازنده مسیریابی فقط جدول را محاسبه می‌کند؛ جستجوها روی کارت‌های خط از طریق کپی‌های سایه انجام می‌شوند.

⚡ مرجع سریع: پردازش پورت ورودی

خط لوله: خاتمه خط ← لایه پیوند ← جستجو

کپی سایه: جدول ارسال به کارت‌های خط تکثیر می‌شود؛ CPU مرکزی در مسیر داده نیست

بودجه جستجو: ~۱ μs به ازای هر بسته در نرخ خط ۱۰ گیگابیت بر ثانیه

اندازه جدول پیشوند: ~۹۰۰K–۱M ورودی (در مقابل ۴B brute-force)

تطبیق طولانی‌ترین پیشوند (LPM)

وقتی چندین پیشوند جدول ارسال با یک آدرس مقصد مطابقت دارند، مسیریاب ورودی با طولانی‌ترین ماسک زیرشبکه (خاص‌ترین تطبیق) را انتخاب می‌کند.

قانون تطبیق طولانی‌ترین پیشوند:
output = argmax ( mask_leni ) روی i که در آن addr & maski = prefixi
در میان همه ورودی‌های مطابقت‌یافته، یکی با بیشترین طول پیشوند را انتخاب کن.

شبه‌کد الگوریتم LPM

Algorithm LongestPrefixMatch(FIB table T, IP address D): best_len = -1 best_port = null for each entry E = (prefix, mask_len, port) in T: // Apply mask: keep only first mask_len bits if (D AND generate_mask(mask_len)) == prefix: if mask_len > best_len: best_len = mask_len best_port = port if best_len == -1: return default_port return best_port Function generate_mask(len): if len == 0: return 0 return (~0) << (32 - len)

TCAM — جستجوی زمان ثابت

حافظه‌های سه‌حالته قابل آدرس‌دهی محتوا (TCAM) یک کلید جستجو را به صورت موازی با همه ورودی‌ها مقایسه می‌کنند. هر سلول TCAM 0، 1 یا X (اهمیتی نمی‌دهد) را ذخیره می‌کند. طولانی‌ترین پیشوند با مرتب‌سازی ورودی‌ها بر اساس طول پیشوند حل می‌شود.

TCAM در مقابل SRAM

TCAM: جستجوی O(1)، توان بالاتر، ~$350/Mb

SRAM + الگوریتم: O(log N)، توان کمتر

Cisco Catalyst: تا ۱M ورودی TCAM

محدودیت ترتیب TCAM

ورودی‌ها باید به ترتیب طولانی‌ترین پیشوند ابتدا ذخیره شوند

اولین تطبیق = طولانی‌ترین پیشوند

بدون نیاز به محاسبه ماسک

⚠ اشتباه رایج:

LPM از نظر عددی بزرگترین آدرس مطابقت‌یافته را انتخاب نمی‌کند؛ ورودی با طولانی‌ترین ماسک را انتخاب می‌کند. یک /24 همیشه بر /20 برنده می‌شود، حتی اگر محدوده آدرس /20 شامل آدرس‌های بیشتری باشد.

⚡ مرجع سریع: تطبیق طولانی‌ترین پیشوند

قانون: در میان تطبیق‌ها، طولانی‌ترین ماسک برنده است

پیاده‌سازی‌ها: درخت دودویی (O(32))، TCAM (O(1))

ظرفیت TCAM: تا ۱M ورودی (Cisco Catalyst)

مسیر پیش‌فرض: 0.0.0.0/0 با همه مطابقت دارد (طول ۰ — کمترین اولویت)

انتزاع تطبیق-به-علاوه-اقدام

مسیریاب‌های مدرن ارسال را فراتر از جستجوهای ساده مبتنی بر مقصد تعمیم می‌دهند. پارادایم تطبیق-به-علاوه-اقدام تطبیق الگو را از عملیات‌های انجام‌شده روی بسته‌های مطابقت‌یافته جدا می‌کند.

مدل تطبیق-به-علاوه-اقدام:
∀ بسته p : (matchi(p)) ⇒ actioni(p)
اگر بسته p شرط تطبیق i را برآورده کند، مجموعه اقدام مرتبط را اجرا کن.

⚠ اشتباه رایج:

تطبیق-به-علاوه-اقدام محدود به IP مقصد نیست. شرط تطبیق می‌تواند L2 (MAC)، L3 (IP، پروتکل)، L4 (پورت‌ها، پرچم‌ها) یا حتی فیلدهای L7 را بازرسی کند. فکر کردن "تطبیق = فقط IP مقصد" عمومیت انتزاع را از دست می‌دهد.

⚡ مرجع سریع: تطبیق-به-علاوه-اقدام

تطبیق: هر ترکیبی از فیلدهای سرآیند (IP، پورت‌های TCP/UDP، پروتکل، پرچم‌ها)

اقدام: ارسال، رها، کاهش TTL، محاسبه مجدد Checksum، شمارش، NAT، آینه

کاربردها: فایروال‌ها، NAT، توازن‌دهنده بار، SDN (OpenFlow)، مهندسی ترافیک
