TRANSMISSION MODES

Physical Layer — Complete Guide for Exam

What is Simplex?

Simplex is a one-way only communication mode where data flows in a single direction. The sender can only send, and the receiver can only receive — there is no way to send data back.

[SENDER] ───────────▶ [RECEIVER]
Key Characteristic:
Data flows in ONE direction only — permanently
The channel capacity is fully used for one-way transmission. No feedback channel exists.
⚠ Simplex is NOT just "sometimes one-way." It is ALWAYS one-way. The receiver has NO capability to send any data back to the sender.

How Simplex Works

Transmission

The sender transmits data continuously on the channel. There is no waiting for acknowledgment.

Reception

The receiver passively listens and receives data. It cannot signal errors or request retransmission.

No Feedback

Since there's no return path, error control must be handled by the application layer or redundant coding.

Bandwidth Usage

100% of channel bandwidth is used for one-way data flow — maximum efficiency for broadcast.

Real-World Examples of Simplex

TV Broadcasting

Tower sends signal → Your TV receives. Your TV cannot send data back to the broadcast tower.

Radio Broadcasting

AM/FM radio stations broadcast to all receivers. Receivers cannot transmit back to the station.

Keyboard → Computer

Keyboard sends keystrokes to computer. The computer does not send data back through the keyboard cable (for basic PS/2 keyboards).

Smoke Signals

Historical example: signals are sent visually in one direction. The sender cannot receive a response via smoke signals.

Pager Systems

Messages are sent to pagers. The pager receives but cannot send messages back.

USB (some modes)

In certain low-speed configurations, USB operates in simplex mode for specific device classes.

Advantages & Disadvantages

✅ Advantages

• Simple to implement

• No collision management needed

• Maximum bandwidth for one direction

• Lower cost (fewer wires/channels)

• No complexity of bidirectional control

❌ Disadvantages

• No error acknowledgment possible

• No feedback from receiver

• Cannot request retransmission

• Limited to one-way applications only

• Receiver must trust data integrity

Simplex in the OSI Model

Since simplex has no return path, error detection and correction must be handled at higher layers:

Layer-by-Layer Impact

• Physical Layer: One-directional signal only

• Data Link: Cannot use ARQ (Automatic Repeat Request)

• Transport: TCP cannot function — no ACKs possible

• Application: Must use Forward Error Correction (FEC)

⚠ Simplex systems MUST use Forward Error Correction (FEC) or redundant data to ensure reliability, since there is no retransmission mechanism.

What is Half Duplex?

Half duplex allows two-way communication, but only in one direction at a time. Both parties can send and receive, but not simultaneously — they must take turns.

[DEVICE A] ◀──────────▶ [DEVICE B]

(Both directions possible, but NOT at the same time)
Key Characteristic:
Two-way communication, one direction at a time
When Device A is transmitting, Device B must wait. When A finishes, B can transmit. Only one direction is active at any moment.
⚠ Half duplex is NOT "slow full duplex." It's a fundamentally different protocol — devices must actively switch direction. There is a "turnaround time" penalty when switching.

How Half Duplex Works

Shared Channel

Both devices share the same communication channel. Only one device can use it at a time.

Direction Switching

After one device finishes sending, it releases the channel and the other device can begin transmitting.

Turnaround Time

There's a delay when switching direction. This "turnaround time" reduces overall throughput.

Collision Risk

If both devices try to transmit simultaneously, a collision occurs. A protocol is needed to manage access.

Real-World Examples of Half Duplex

Walkie-Talkie

Classic example: press "Push-to-Talk" to transmit, release to listen. Only one person can talk at a time.

CB Radio

Citizens Band radio uses half duplex. Users share a channel and take turns communicating.

Ethernet (Classic)

Early Ethernet (10BASE5, 10BASE2) used half duplex with CSMA/CD to manage collisions on shared media.

IEEE 802.11 (Wi-Fi)

Wi-Fi uses half duplex because a device cannot send and receive on the same frequency at the same time.

Hub-based Networks

Network hubs create a shared collision domain, forcing all connected devices into half duplex mode.

Walkie-Talkie Apps

Modern push-to-talk apps (Zello, etc.) simulate half duplex behavior over full duplex networks.

Advantages & Disadvantages

✅ Advantages

• Two-way communication possible

• Simpler than full duplex

• Lower cost than full duplex

• Uses single channel efficiently

• Supports bidirectional protocols

❌ Disadvantages

• Cannot send and receive simultaneously

• Turnaround time reduces throughput

• Collisions can occur (needs CSMA/CD)

• Less efficient than full duplex

• Not suitable for real-time applications

Throughput Calculation

Half duplex throughput is reduced by turnaround time:

Effective Throughput:
Throughput = Data Rate × (1 - Turnaround Penalty)
Where Turnaround Penalty accounts for the time lost when switching direction. Typically 5-15% overhead.
Example: Half Duplex vs Full Duplex

• Full Duplex: 100 Mbps in both directions = 200 Mbps total throughput

• Half Duplex: 100 Mbps shared = ~85-95 Mbps effective (due to turnaround overhead)

• Half duplex effectively halves the available bandwidth for simultaneous use.

What is Full Duplex?

Full duplex allows simultaneous two-way communication. Both devices can send and receive data at the same time, using separate channels or frequencies for each direction.

[DEVICE A] ──────────▶ [DEVICE B]
[DEVICE A] ◀────────── [DEVICE B]

(Both directions active SIMULTANEOUSLY)
Key Characteristic:
Simultaneous two-way communication
Data can flow in both directions at the same time. This requires either two separate channels or frequency division to separate the directions.
⚠ Full duplex requires either: (1) two physical channels, (2) frequency division (different frequencies for each direction), or (3) echo cancellation to separate simultaneous signals.

How Full Duplex Works

Two Separate Channels

One channel for sending, one for receiving. Both operate independently and simultaneously.

Frequency Division

Same wire/cable but different frequency bands for each direction. Signals don't interfere.

Echo Cancellation

DSP technology removes the outgoing signal from the incoming path, allowing same-frequency full duplex.

No Turnaround Time

Since both directions are always active, there's no delay when switching. Maximum throughput achieved.

Real-World Examples of Full Duplex

Telephone System

Both parties can talk and listen simultaneously. The most intuitive example of full duplex.

Modern Ethernet

100BASE-TX, 1000BASE-T use full duplex with separate wire pairs for TX and RX.

Mobile Phones

Cellular phones use full duplex — you can talk and hear at the same time using frequency division.

Fiber Optic

Fiber uses two wavelengths (1310nm/1550nm) for simultaneous bidirectional transmission.

USB

USB 3.0+ uses full duplex with separate TX/RX pairs for simultaneous data transfer.

Video Calls

Zoom, Teams, etc. send and receive video/audio simultaneously over full duplex connections.

Advantages & Disadvantages

✅ Advantages

• Maximum throughput (both directions)

• No turnaround delay

• Supports real-time applications

• Better user experience (phone, video)

• No collision management needed

❌ Disadvantages

• More expensive to implement

• Requires more bandwidth or channels

• More complex hardware

• Higher power consumption

• Not always necessary for all applications

Full Duplex Implementation Methods

Three Ways to Achieve Full Duplex

1. Two Physical Channels: Separate wires for each direction (e.g., Ethernet uses 2 pairs out of 4)

2. Frequency Division Duplex (FDD): Different frequencies for uplink and downlink (e.g., cellular, satellite)

3. Time Division Duplex (TDD): Rapidly switching direction in time slots — appears simultaneous but is technically interleaved

⚠ Modern Ethernet cables have 4 pairs (8 wires). In full duplex mode, 2 pairs are used for sending and 2 pairs for receiving, enabling simultaneous communication.

Analog vs Digital Channels

Transmission modes can be implemented over both analog and digital channels:

Analog Channel

• Carries continuous signal

• Signal varies smoothly over time

• Used in: radio, TV, old telephone

• Susceptible to noise and distortion

• Bandwidth measured in Hz

Digital Channel

• Carries discrete signals (0s and 1s)

• Signal has defined voltage levels

• Used in: Ethernet, USB, fiber

• More resistant to noise

• Bandwidth measured in bps

Voice Frequency Band:
300 Hz – 3400 Hz
The standard voice frequency band used in traditional telephone systems. This 3100 Hz bandwidth is sufficient for intelligible speech, though it does not capture the full range of human hearing (20 Hz – 20,000 Hz).
⚠ The telephone voice band (300-3400 Hz) is narrower than the full human hearing range (20-20,000 Hz). This is why telephone audio sounds "tinny" — high frequencies are cut off.

Worked Examples

Example 1: Identifying Transmission Modes

Q: Classify each as Simplex, Half Duplex, or Full Duplex:

a) TV broadcast → Simplex (one-way only, tower to TV)

b) Walkie-talkie → Half Duplex (two-way, one direction at a time)

c) Telephone call → Full Duplex (simultaneous two-way)

d) FM Radio → Simplex (station to receiver only)

e) Ethernet (switch-based) → Full Duplex (simultaneous TX/RX)

Example 2: Bandwidth Calculation

Q: A half duplex link operates at 10 Mbps with 10% turnaround overhead. What is the effective throughput?

Effective Throughput = 10 Mbps × (1 - 0.10) = 10 × 0.90 = 9 Mbps

The same link in full duplex would provide 10 Mbps in EACH direction = 20 Mbps total.

Example 3: Channel Capacity in Voice Band

Q: Using Shannon's theorem, what is the maximum capacity of a telephone line with SNR = 30 dB and voice band 300-3400 Hz?

B = 3400 - 300 = 3100 Hz

SNR (linear) = 10^(30/10) = 1000

C = 3100 × log₂(1 + 1000) = 3100 × log₂(1001) ≈ 3100 × 9.97 ≈ 30,907 bps ≈ 30.9 kbps

This shows why dial-up internet was limited to ~33.6 kbps — the voice band is narrow!

Example 4: Full Duplex Ethernet

Q: A Cat5e cable has 4 pairs. In full duplex Ethernet, how are they used?

Pairs 1 & 2: Used for Transmitting (TX+ and TX-)

Pairs 3 & 6: Used for Receiving (RX+ and RX-)

Pairs 4 & 5: Available for PoE or additional functions

This allows simultaneous 100 Mbps in both directions = 200 Mbps total throughput.

Example 5: Comparing Modes for a Specific Scenario

Q: You need to design a sensor network where 1000 temperature sensors report data to a central server every 5 seconds. Which transmission mode is best?

Answer: Simplex

Why?

• Sensors only need to SEND data (one-way)

• No need for the server to send data back to sensors

• Simplex maximizes bandwidth efficiency for this unidirectional flow

• Lower cost and complexity than duplex solutions

• If acknowledgment is needed, a separate simplex channel can carry responses

Key Formulas

Shannon-Hartley Theorem:
C = B × log₂(1 + SNR)
C = channel capacity (bps), B = bandwidth (Hz), SNR = signal-to-noise ratio (linear)
SNR in dB:
SNR(dB) = 10 × log₁₀(P_signal / P_noise)
Converts power ratio to decibels for easier comparison
Voice Band Bandwidth:
B = 3400 Hz - 300 Hz = 3100 Hz
Standard telephone voice frequency range
Half Duplex Throughput:
Effective = Data Rate × (1 - Turnaround Penalty)
Turnaround penalty is typically 5-15% of total time

Key Concepts to Remember

Exam Essentials

• Simplex = one-way ALWAYS (not just sometimes)

• Half Duplex = two-way, one direction at a time

• Full Duplex = simultaneous two-way

• Voice frequency band: 300-3400 Hz

• Simplex needs FEC for error recovery (no retransmission)

• Half duplex needs collision detection (CSMA/CD)

• Full duplex needs either separate channels, FDD, or echo cancellation

• Ethernet switched networks = full duplex; hub networks = half duplex

⚠ Common Exam Mistake: Do NOT confuse Half Duplex with "slow Full Duplex." Half duplex is a protocol where devices must take turns. Full duplex is truly simultaneous. The key difference is SIMULTANEITY.
⚠ Don't forget: The telephone voice band (300-3400 Hz) is NOT the same as human hearing range (20-20,000 Hz). This narrower band limits telephone data rates.
