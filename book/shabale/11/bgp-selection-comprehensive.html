BGP Route Selection & Hot Potato Routing

Computer Networks — The BGP Decision Process & Forwarding Table Construction

Hot Potato Routing

Hot potato routing is a BGP route selection policy where a router prefers to minimize the intra-AS cost to the NEXT-HOP. The idea is simple: get the traffic out of your AS as quickly as possible — like a hot potato you want to drop.

Hot potato routing is a selfish algorithm — it tries to reduce the cost in its own AS while ignoring the other components of the end-to-end costs outside the AS. With hot potato routing, two routers in the same AS may choose two different AS paths to the same prefix.

Hot Potato Rule
Select the route whose NEXT-HOP has the smallest IGP cost from the current router.
Among routes with equal local preference and equal AS-PATH length, pick the one closest to you.

Why "Selfish"?

Hot potato routing is considered selfish because each AS independently minimizes its own internal costs without considering the overall network efficiency. The AS passes traffic to the next AS as quickly as possible, shifting the burden outward.

Forwarding Table Construction (Figure 5.11)

Adding an outside-AS prefix to a router's forwarding table involves both BGP (inter-AS) and the IGP (intra-AS) protocol:

1. Learn from inter-AS protocol (BGP) that subnet x is reachable via multiple gateways.
2. Use routing info from intra-AS protocol (OSPF/etc.) to determine costs of least-cost paths to each gateway.
3. Hot potato routing: choose the gateway that has the smallest least cost.
4. Determine from forwarding table the interface I that leads to the least-cost gateway.
5. Enter (x, I) in the forwarding table.

Because each router independently applies this procedure, two routers in the same AS may choose different AS paths to the same prefix. For example, in Figure 5.10, router 1b sends packets through AS2 to reach x, while router 1d would bypass AS2 and send packets directly to AS3.

Advantages

• Minimizes internal bandwidth: Traffic exits at the closest point.

• Simple to implement: Uses existing IGP metrics.

• Decentralized: Each router decides independently.

Disadvantages

• Global suboptimality: May choose a path that is longer overall.

• No cooperation: Each AS acts in its own interest.

• Unpredictable end-to-end paths.

Hot Potato: Textbook Example (Figure 5.10)

Router 1b in AS1 learns about prefix x. The two BGP routes to x are:

Route via AS2 (through gateway 1c):
 NEXT-HOP = IP of router 2a's left interface; AS-PATH: AS2 AS3; destination: x
Route via AS3 (direct, through gateway 1d):
 NEXT-HOP = IP of router 3d's left interface; AS-PATH: AS3; destination: x

Router 1b consults its intra-AS routing to find the least-cost path to each NEXT-HOP:

  • Cost to NEXT-HOP 2a (via gateway 1c): 2
  • Cost to NEXT-HOP 3d (via gateway 1d): 3

Under hot potato routing alone, router 1b selects the route via AS2 (gateway 1c → 2a) because cost 2 < cost 3. The traffic leaves AS1 sooner.

Important: With the full BGP route-selection algorithm (Rule 2 — shortest AS-PATH — comes before Rule 3), the direct AS3 route (AS-PATH = [3], length 1) wins because it has a shorter AS-PATH than the AS2 route (AS-PATH = [2,3], length 2). The full algorithm thus overrides the hot potato result.

Hot potato routing is applied as the third rule in the BGP route selection algorithm, after local preference and AS-PATH length. It is only decisive when the first two rules produce a tie.

BGP Route Selection: The 4-Rule Algorithm

When a BGP router has multiple routes to the same prefix, it selects the best route using the following tie-breaking rules, applied in order:

BGP Best Route Selection (4 Rules)
1. Highest LOCAL_PREF
2. Shortest AS-PATH
3. Closest NEXT-HOP (Hot Potato)
4. Lowest BGP Router ID
Rules are evaluated sequentially. The first rule that produces a unique winner determines the best route.

Rule 1: Highest Local Preference

LOCAL_PREF is a policy attribute set by AS administrators to influence outbound traffic. Higher values are preferred. Default is 100.

  • Used to prefer certain paths (e.g., prefer customer routes over peer routes).
  • Propagated throughout the AS via iBGP.
  • Set using route maps or BGP community policies.
Local Preference Example

AS1 has two upstream ISPs: ISP-A (LOCAL_PREF = 150) and ISP-B (LOCAL_PREF = 100). Both advertise 0.0.0.0/0 (default route). Router 1a prefers ISP-A because LOCAL_PREF 150 > 100.

Rule 2: Shortest AS-PATH

Among routes with equal LOCAL_PREF, the router prefers the shortest AS-PATH (fewest AS hops).

  • This is the closest BGP gets to "shortest path" routing.
  • AS-PATH length counts the number of ASs in the path, not router hops.
  • Operators can artificially inflate AS-PATH length (AS-PATH prepending) to make a path less preferred.
AS-PATH Length Example

Router receives two routes for 10.1.0.0/16:

  • Route A: AS-PATH = [100, 200] (length 2)
  • Route B: AS-PATH = [300, 400, 500] (length 3)

Route A is preferred (shorter AS-PATH).

Rule 3: Closest NEXT-HOP (Hot Potato)

SAME as the hot potato rule — pick the route with the lowest IGP cost to the NEXT-HOP.

  • This rule is decisive only when rules 1 and 2 tie.
  • The IGP cost comes from the intra-AS routing protocol (OSPF, etc.).
  • This is the "hot potato" step.

Rule 4: Lowest BGP Router ID

If all previous rules tie, the route from the BGP router with the lowest Router ID is preferred.

  • The Router ID is a 32-bit number (usually the highest loopback IP).
  • This is the ultimate tie-breaker — it is deterministic.

Why BGP Is No Longer "Selfish"

With the full route-selection algorithm, BGP is no longer a purely selfish algorithm. Rule 2 (shortest AS-PATH) is applied before Rule 3 (hot potato). This means BGP first looks for routes with short AS paths (thereby likely reducing end-to-end delay), and only falls back to hot potato when AS-PATH lengths are equal. This is a fundamental difference from pure hot potato routing.

There are additional BGP tie-breaking rules (e.g., eBGP over iBGP, lower MED, oldest route) that may be considered in full implementations, but the 4-rule algorithm above covers the core exam material.
BGP routing tables in tier-1 ISP routers often contain over half a million routes (prefixes and corresponding attributes). Live BGP table data is available at http://www.routeviews.org. Statistics on BGP table size and characteristics are maintained in [Huston 2019b].

Worked Examples: Route Selection Decisions

Example 1: Router 1b Choosing Between AS2 and AS3 Paths

Topology: AS1 has routers 1a, 1b, 1c, 1d. 1c peers with AS2 (router 2a), 1d peers with AS3 (router 3a). Router 1b learns about prefix 10.5.0.0/16 from both entry points.

Route A (via 1c → AS2): LOCAL_PREF = 100, AS-PATH = [2, 4], NEXT-HOP = 2a (IGP cost from 1b to 1c = 5)

Route B (via 1d → AS3): LOCAL_PREF = 100, AS-PATH = [3, 4], NEXT-HOP = 3a (IGP cost from 1b to 1d = 3)

Decision Process:

  1. Rule 1 (LOCAL_PREF): Both = 100 → tie.
  2. Rule 2 (AS-PATH): Both = 2 → tie.
  3. Rule 3 (Hot Potato): Cost to 1c = 5, Cost to 1d = 3 → Route B wins.

Result: Router 1b installs the route via 1d → AS3, because the NEXT-HOP is closer (hot potato).

Example 2: Local Preference Overrides Shorter AS-PATH

Scenario: Router receives two routes for 172.16.0.0/16:

  • Route A: LOCAL_PREF = 200, AS-PATH = [300, 400, 500] (length 3)
  • Route B: LOCAL_PREF = 100, AS-PATH = [100] (length 1)

Decision Process:

  1. Rule 1 (LOCAL_PREF): Route A = 200 > Route B = 100 → Route A wins immediately.

Key takeaway: LOCAL_PREF is always evaluated first. Even though Route B has a much shorter AS-PATH, the locally configured preference overrides. This is how ASs implement routing policies (e.g., prefer customer-learned routes).

Example 3: AS-PATH Prepending and Its Effect

Scenario: ISP-A wants to make its path less preferred for backup use only. It configures AS-PATH prepending on its primary competitor ISP-B's prefix.

Prefix: 10.0.0.0/16

  • Via ISP-A (primary): LOCAL_PREF = 100, AS-PATH = [100] (length 1), NEXT-HOP cost = 10
  • Via ISP-B (backup): LOCAL_PREF = 100, AS-PATH = [200, 200, 200] (length 3, prepended), NEXT-HOP cost = 5

Decision Process:

  1. Rule 1 (LOCAL_PREF): Both = 100 → tie.
  2. Rule 2 (AS-PATH): Length 1 < Length 3 → Via ISP-A wins.

Key takeaway: AS-PATH prepending makes ISP-B's path appear longer, causing traffic to prefer ISP-A. If ISP-A fails, ISP-B's route becomes the best. This is a common technique for implementing primary/backup BGP peering.

Example 4: Four-Way Tie Broken by Router ID

Scenario: Router receives four routes for 192.168.0.0/16, all with identical:

  • LOCAL_PREF = 100
  • AS-PATH = [100, 200] (length 2)
  • IGP cost to NEXT-HOP = 10

The four BGP peers have Router IDs: 10.0.0.1, 10.0.0.2, 10.0.0.3, 10.0.0.4

Decision Process:

  1. Rules 1–3: All tie.
  2. Rule 4 (Router ID): Lowest = 10.0.0.1 → Route from peer 10.0.0.1 wins.

Key takeaway: Router ID is the ultimate tie-breaker. It ensures deterministic route selection when all other attributes are equal.

Example 5: Forwarding Table Construction (Figure 5.11)

Topology: AS1 with routers 1a, 1b, 1c, 1d. AS2 interconnects via 2a, 2b. AS3 via 3a.

Router 1b learns about prefix 10.3.0.0/16. It has two possible paths:

  • Path 1: 1b → 1c → (eBGP) → 2a → ... (NEXT-HOP = 2a, IGP cost = 5)
  • Path 2: 1b → 1d → (eBGP) → 2b → ... (NEXT-HOP = 2b, IGP cost = 15)

Step-by-step forwarding table construction:

  1. 1b learns both paths via iBGP from 1c and 1d.
  2. Both have LOCAL_PREF = 100 → tie.
  3. Both have AS-PATH = [2, 3] → tie.
  4. IGP cost to NEXT-HOP: 5 vs 15 → Path 1 wins.
  5. 1b installs: destination 10.3.0.0/16 → interface to 1c → NEXT-HOP 2a.

The forwarding table entry at 1b:

Prefix | Next Hop | Interface | IGP Cost
10.3.0.0/16 | 2a | Gi0/0 | 5

BGP Route Selection — Complete Summary

The 4-Rule Algorithm (Memorize This)
1. Highest LOCAL_PREF — Policy preference
2. Shortest AS-PATH — Fewest AS hops
3. Lowest IGP cost to NEXT-HOP — Hot potato
4. Lowest BGP Router ID — Ultimate tie-breaker

Forwarding Table Construction Summary

The forwarding table is populated by taking the best BGP route (after the 4-rule algorithm) and combining it with the IGP next-hop information:

  1. Learn all BGP routes for a prefix via UPDATE messages.
  2. Apply the 4-rule algorithm to select the single best route.
  3. Resolve the NEXT-HOP via the IGP routing table (find the outgoing interface).
  4. Install the prefix + next-hop + interface into the forwarding table.
The forwarding table (FIB) is the final output used for actual packet forwarding. A BGP route that cannot resolve its NEXT-HOP (e.g., no IGP route) will not be installed, even if it wins the BGP selection.
