Network Topologies

Computer Networks — Complete Guide for Exam Preparation

What is a Network Topology?

Definition:
Network topology is the arrangement or layout of nodes (computers, devices) and links (connections) in a network.
It describes how devices are physically or logically interconnected to form a communication network.

Two Types of Topology

Physical Topology

• Actual physical layout of cables and devices

• How wires are arranged and routed

• Can be seen and touched

Logical Topology

• How data flows through the network

• The path data travels between nodes

• May differ from physical layout

Common Mistake: Physical and logical topologies are NOT always the same. A network can be physically wired as a star but logically operate as a bus (e.g., early Ethernet hubs).

Key Metrics for Evaluating Topologies

Metric What It Measures
Cost Total amount of cable and hardware required
Reliability Network behavior when a link or node fails
Scalability Ease of adding new nodes without disruption
Performance Throughput and latency characteristics
Fault Isolation Ability to locate and isolate failures quickly

Five Main Topology Types

1. Point-to-Point

Two devices connected directly

2. Star

All devices connect to a central hub/switch

3. Tree

Hierarchical structure of star networks

4. Mesh

Every device connects to every other device

5. Hybrid

Combination of two or more topologies

Point-to-Point Topology

Definition:
A dedicated link between exactly two devices (nodes) for exclusive communication.
The simplest form of network topology — a single, permanent connection between two endpoints.

Visual Diagram

┌────────┐ Dedicated Link ┌────────┐ │ Node A ├──────────────────────────────────┤ Node B │ └────────┘ (cable / wireless) └────────┘ Example: Two computers connected via a serial cable Example: A home computer connected to an ISP via a single DSL line

Characteristics

Advantages

• Simple to install and configure

• Dedicated bandwidth — no contention

• Easy fault isolation

• Full-duplex communication possible

Disadvantages

• Only connects two devices

• Does not scale well

• Costly for connecting many devices (n(n-1)/2 links)

• Single point of failure on the link

Number of Links for N devices (full point-to-point):
Links = N × (N - 1) / 2
Each pair of devices gets a dedicated link. This is the formula for a full mesh built from point-to-point links.

Real-World Examples

Example 1: Serial Connection

Two routers connected via a T1 leased line at a branch office.

• Each router has a serial interface

• The line provides 1.544 Mbps dedicated bandwidth

1 link, 2 nodes, 0 intermediate devices

Example 2: VPN Tunnel

A remote employee's laptop connects to the company server via a point-to-point VPN tunnel over the internet.

• Logically appears as a direct connection

• Physically routes through the internet

Logical point-to-point over a complex physical topology

Example 3: Bluetooth Pairing

Your phone paired with wireless headphones creates a point-to-point link.

• Dedicated 2.4 GHz frequency band

• Only those two devices communicate on that link

1 connection, limited range (~10 meters)

Important: In point-to-point, there is no contention for bandwidth — both endpoints get the full capacity of the link. This is why it is ideal for high-throughput connections between two critical nodes.

Star Topology

Definition:
All nodes connect to a single central device (hub, switch, or router) via individual point-to-point links.
The central node acts as a repeater — data sent from any node passes through the hub/switch to reach the destination.

Visual Diagram

┌────────┐ ┌──────────┤ Node 1 │ │ └────────┘ │ │ ┌────────┐ ┌────────┐│ ┌──────┤ Node 2 │ │ Node 4 ├┤ │ └────────┘ └────────┘│ │ │ │ ┌────────┐ │ │ ┌───┤ Node 3 │ │ │ │ └────────┘ ▼ ▼ ▼ ┌──────────────┐ │ Central Hub │ │ (Switch) │ └──────────────┘ │ ┌───┴────┐ │ Node 5 │ └────────┘ Each node has a dedicated cable to the central hub. The hub manages all data traffic between nodes.

Characteristics

Advantages

• Easy to install and wire

• Easy to detect faults and remove parts

• Failure of one node does not affect others

• Easy to add/remove nodes

• Centralized management

Disadvantages

• Central hub is a single point of failure

• More cable required than bus

• Hub failure brings down entire network

• Performance depends on hub capacity

• Higher cost than bus topology

Number of cables required:
Cables = N
One cable per node connecting to the central hub. N = number of devices (nodes).
Number of ports at central device:
Ports = N
The hub/switch must have at least N ports to accommodate all nodes.
Maximum cable length (depends on cable type):
Limit depends on transmission medium
e.g., Cat6 Ethernet: 100m; Fiber: up to several km.

Worked Examples

Example 1: Office LAN with 8 PCs

An office has 8 computers all connected to a single 16-port switch.

• Number of cables = 8

• Switch ports used = 8 out of 16

• If 1 PC fails, the other 7 continue working

• If the switch fails, all 8 PCs lose network access

Example 2: Adding a New Node

A star network has 5 nodes. You want to add a 6th node.

• Add 1 new cable from the new node to the central switch

• Plug into one of the remaining ports

Total cables: 5 → 6. No disruption to existing nodes.

Example 3: Hub vs Switch

In a 10-node star network using a hub, all 10 nodes share the same bandwidth. If the hub has 100 Mbps capacity, each node effectively gets 100 Mbps but must share it.

With a switch, each node gets a dedicated 100 Mbps connection to the switch, and the switch handles simultaneous communications.

Example 4: Fault Isolation

In a star network of 12 nodes, Node 7's cable is cut.

• Only Node 7 loses connectivity

• The other 11 nodes remain unaffected

• Easy to identify the fault: check Node 7's cable

Fault isolation is trivial — one port goes dark on the switch.

Critical Point: The biggest risk in a star topology is the central hub. Always consider redundancy for the hub in mission-critical networks. Redundant switches or stacked configurations mitigate this single point of failure.

Tree Topology (Hierarchical / Extended Star)

Definition:
A tree topology is a hierarchical structure where groups of star-configured nodes are connected to a root node or backbone, forming a parent-child tree structure.
Also called a "hierarchical topology" or "extended star." It combines characteristics of star and bus topologies.

Visual Diagram

┌────────────┐ │ Root Node │ (Main Server / Core Switch) │ (Level 0) │ └─────┬──────┘ │ ┌─────────────┼─────────────┐ │ │ │ ┌─────┴─────┐ ┌────┴────┐ ┌─────┴─────┐ │ Switch A │ │Switch B │ │ Switch C │ (Level 1) └──┬──┬──┬──┘ └─┬───┬──┘ └──┬───┬──┬──┘ │ │ │ │ │ │ │ │ ┌─┘ │ └─┐ ┌┘ └┐ ┌─┘ │ └─┐ ▼ ▼ ▼ ▼ ▼ ▼ ▼ ▼ PC1 PC2 PC3 PC4 PC5 PC6 PC7 PC8 (Level 2) • Root node at the top (core switch or main server) • Branches divide into groups via intermediate switches • Leaf nodes are end devices (PCs, printers, etc.)

Key Concepts

Root Node

• Top-level node (core switch)

• All traffic between branches passes through it

• Single point of failure for the entire network

Intermediate Nodes

• Switches or routers at each branch

• Connect sub-groups of devices

• Act as local distribution points

Leaf Nodes

• End devices (PCs, printers)

• Located at the bottom of the hierarchy

• Do not route traffic for others

Number of cables in a balanced tree:
Cables = (N - 1) + (S - 1)
N = number of end devices, S = number of switches (intermediate nodes). Each device and switch needs one link to its parent.
Maximum depth of a tree:
Depth = logb(N) + 1
b = branching factor (number of children per node), N = total leaf nodes. Depth increases logarithmically with network size.

Worked Examples

Example 1: University Campus Network

A university has 3 buildings. Each building has a floor switch connecting 20 PCs.

• Root: Core router in data center

• Level 1: 3 building switches

• Level 2: 60 PCs (20 per building)

• Total cables = 60 + 3 = 63 cables

• Depth = 3 levels (root → building → PC)

Example 2: Fault Propagation

In the tree above, if Building 2's switch fails:

• All 20 PCs in Building 2 lose connectivity

• Buildings 1 and 3 are unaffected

• The root node and other branches continue operating

If the root node fails, the entire network goes down.

Example 3: Scalability

A company adds a 4th building with 15 PCs.

• Add 1 new switch at Level 1

• Connect switch to root node (1 cable)

• Connect 15 PCs to the new switch (15 cables)

New total: 63 + 16 = 79 cables. No changes to existing branches.

Example 4: Traffic Flow

PC1 (Building 1) sends data to PC5 (Building 2):

• PC1 → Switch A → Root Node → Switch B → PC5

• The data traverses 4 links (3 hops through switches)

All inter-branch communication must pass through the root node.

Common Mistake: Students often confuse tree topology with mesh. In a tree, there is exactly ONE path between any two nodes. In a mesh, there are MULTIPLE paths. If you need redundancy, tree alone is insufficient — add redundant links.

Mesh Topology

Definition:
Every node has a dedicated point-to-point link to every other node in the network.
Provides maximum redundancy and fault tolerance. Each node acts as a relay for other nodes.

Two Types of Mesh

Full Mesh

• Every node connects to every other node

• Maximum redundancy

• Costly for large networks

• Used in backbone networks

Partial Mesh

• Some nodes connect to all others, some only to select nodes

• Balance of cost and redundancy

• More practical for larger networks

• Used in WANs and the internet

Visual Diagram — Full Mesh

┌────────┐ ┌────────┐ │ Node A ├────────────────────┤ Node B │ └───┬──┬─┘╲ ╱ └─┬──┬───┘ │ │ ╲ ╱ │ │ │ │ ╲ ╱ │ │ │ │ ╲ ╱ │ │ │ │ ╲╱ │ │ │ │ ╱╲ │ │ │ │ ╱ ╲ │ │ │ │ ╱ ╲ │ │ │ │ ╱ ╲ │ │ ┌───┴──┴─╱─┐ ┌───╲──┴──┴───┐ │ Node C ├────────────────────┤ Node D │ └────────┘ └────────┘ Every node has a direct link to every other node. 4 nodes → 4×3/2 = 6 links (full mesh) A─────────B │╲ ╱│ │ ╲ ╱ │ │ ╳ │ │ ╱ ╲ │ │╱ ╲│ C─────────D Links: A-B, A-C, A-D, B-C, B-D, C-D = 6 links

Visual Diagram — Partial Mesh

┌────────┐ ┌────────┐ │ Node A ├──────────────┤ Node B │ └───┬────┘ └───┬────┘ │ │ │ ┌─────┤ │ │ │ ┌───┴────┐ ┌───┴───┐ ┌┴────────┐ │ Node C ├────────┤ Node D │ │ Node E │ └────────┘ └───────┘ └─────────┘ Not all nodes connect to all others. A-D is missing. B-C is missing. Cheaper than full mesh, still provides some redundancy.
Number of links in Full Mesh:
Links = N × (N - 1) / 2
N = number of nodes. Each pair requires one dedicated link.
Number of ports per node in Full Mesh:
Ports per node = N - 1
Each node must have a port for every other node in the network.
Bandwidth per link:
Each link has dedicated bandwidth B
Unlike shared media, each link provides full bandwidth B between its two endpoints.

Worked Examples

Example 1: Full Mesh with 5 Nodes

A data center has 5 core routers in a full mesh configuration.

• Number of links = 5 × (5 - 1) / 2 = 10 links

• Each router needs 4 ports (one for each other router)

• Total ports across all routers = 5 × 4 = 20

• If any 1 link fails, data reroutes through remaining paths

Example 2: Scaling Cost

Compare cable cost for Full Mesh: 5 nodes vs 10 nodes.

• 5 nodes: 5×4/2 = 10 links

• 10 nodes: 10×9/2 = 45 links

• Doubling nodes increases links by 4.5x — cost grows quadratically!

This is why full mesh is impractical for large networks.

Example 3: Fault Tolerance

In a 6-node full mesh, links A-B and C-D both fail simultaneously.

• A→B traffic reroutes: A→D→B or A→E→B

• C→D traffic reroutes: C→A→D or C→F→D

Network continues operating despite 2 simultaneous link failures.

Example 4: Internet as Partial Mesh

The global internet is a partial mesh at the ISP level.

• Major ISPs (Tier 1) connect to many other ISPs

• Smaller ISPs connect to only 1-2 upstream providers

• Redundant paths exist between major hubs

The internet's resilience comes from its partial mesh backbone.

Example 5: Partial Mesh Calculation

A WAN has 8 routers. 3 core routers are fully connected; 5 edge routers each connect to 2 core routers.

• Core mesh links: 3×2/2 = 3 links

• Edge-to-core links: 5 × 2 = 10 links

• Total: 13 links (vs 28 for full mesh)

Key Exam Point: Full mesh provides the highest fault tolerance but is only practical for small networks (typically ≤ 10 nodes). Beyond that, use partial mesh or hierarchical topologies. The formula N(N-1)/2 grows quadratically — memorize this!

Hybrid Topology

Definition:
A hybrid topology combines two or more different topologies to form a network that leverages the strengths of each.
It is NOT a new topology type itself — it is any network that mixes existing topologies (e.g., star-mesh, bus-star).

Visual Diagram — Star-Mesh Hybrid

Department A (Star) Department B (Mesh) Department C (Star) ┌──────────────┐ ┌──────────────┐ ┌──────────────┐ │ ┌──┐ ┌──┐ │ │ A ──── B │ │ ┌──┐ ┌──┐ │ │ │P1│ │P2│ │ │ │╲ ╱│ │ │ │P5│ │P6│ │ │ └──┘ └──┘ │ │ │ ╳ │ │ │ └──┘ └──┘ │ │ │ │ │ │╱ ╲│ │ │ │ │ │ ┌──┐│┌──┐ │ │ C ──── D │ │ ┌──┐│┌──┐ │ │ │P3│││P4│ │ │ │ │ │P7│││P8│ │ │ └──┘└─┴──┘ │ └──────┬───────┘ │ └──┘└─┴──┘ │ └───────┬───────┘ │ └───────┬───────┘ │ │ │ └────────────────┬────────┘──────────────────────────┘ │ ┌──────┴──────┐ │ Backbone │ │ (Bus/Ring) │ └─────────────┘ • Left wing: star topology (PCs → switch) • Right wing: mesh topology (routers interconnected) • Bottom: star topology (workstations → hub) • Backbone: bus connecting all wings together

Common Hybrid Combinations

Combination Structure Typical Use
Star-Star Multiple star networks connected via a root switch Office buildings, campus LANs
Star-Bus Star groups connected by a bus backbone Large office floors
Star-Ring Star groups connected by a ring backbone IBM Token Ring networks
Star-Mesh Star access networks with mesh backbone WAN core + LAN edges
Tree-Mesh Hierarchical tree with mesh at the core layer Large enterprise networks

Characteristics

Advantages

• Flexible and scalable design

• Can optimize for specific needs

• Combines strengths of multiple topologies

• Easier to expand than rigid topologies

Disadvantages

• Complex design and management

• More difficult to troubleshoot

• Higher cost (multiple types of equipment)

• Requires careful planning

Total links in a hybrid:
Total = Σ(links in each sub-topology) + (backbone links)
Sum the links of each individual topology segment plus the links connecting them together.

Worked Examples

Example 1: Enterprise Campus Network

A company has 4 departments, each using a star topology with 10 PCs per star. The 4 star switches connect to a central core router (mesh backbone).

• Star links: 4 × 10 = 40 cables

• Mesh backbone: 4 switches → 4×3/2 = 6 backbone links

Total = 40 + 6 = 46 links

Example 2: Internet Service Provider

An ISP uses a mesh backbone between 3 data centers. Each data center runs a star network connecting 50 customer routers.

• Mesh links: 3×2/2 = 3 backbone links

• Star links per DC: 50 cables each

• Total star links: 3 × 50 = 150

Total = 150 + 3 = 153 links

Example 3: Fault in a Hybrid

In the enterprise campus above (Example 1), the mesh backbone link between switches A and B fails.

• Traffic from Dept A to Dept B reroutes: A→C→B or A→D→B

• If ALL backbone links failed, inter-department traffic stops

Mesh backbone provides redundancy for inter-star communication.

Design Tip: When designing hybrid topologies, always identify which topology is used at each layer. The core/backbone layer usually uses mesh for redundancy, while the access layer uses star for simplicity. This "core-distribution-access" model is the industry standard.

Comprehensive Worked Examples

Example 1: Choosing the Right Topology

A small business has 6 employees who all need to share a printer and file server. Budget is limited. Which topology?

• Star topology — one cable per PC to a central switch

• 6 cables total, one switch (6 ports minimum)

• If one PC's cable breaks, only that PC is affected

Mesh would need 15 cables — too expensive for 6 PCs.

Example 2: Calculating Mesh Requirements

A telecom company needs to connect 7 cities with maximum reliability. How many fiber links are needed?

• Full mesh: 7 × 6 / 2 = 21 fiber links

• Each city needs 6 ports (one per other city)

• Total port count: 7 × 6 = 42

Cost-prohibitive. Consider partial mesh with 10-12 links instead.

Example 3: Tree Topology Bandwidth

In a 3-level tree: root → 3 switches → 15 PCs (5 per switch). Each PC generates 10 Mbps traffic. What bandwidth does the root link need?

• Each switch handles 5 PCs × 10 Mbps = 50 Mbps

• Root link must handle all 3 switches: 3 × 50 = 150 Mbps minimum

The root link is always the bottleneck — oversize it!

Example 4: Hybrid Network Cost Analysis

A company needs 30 PCs connected in 3 departments (10 each). Each department uses a star. The 3 star switches connect via mesh.

• Star cables: 3 × 10 = 30

• Mesh between switches: 3 × 2/2 = 3

• Total cables: 33

• Switches: 3 (one per dept) + 1 core = 4 switches

• If full mesh were used for all 30 PCs: 30×29/2 = 435 cables (13x more!)

Example 5: Topology Migration

A company starts with 5 PCs in a bus topology. They grow to 25 PCs and need better reliability.

• Bus: 1 backbone cable, shared bandwidth, hard to troubleshoot

• Star migration: 25 cables + one 24-port switch (+ expansion)

• Future: Add a second floor → switch to tree (star + backbone)

Bus → Star → Tree as the network grows.

Common Exam Pitfalls

1. Confusing Physical and Logical Topology: A network can be physically wired as a star (cables to a hub) but logically operate as a bus (hub broadcasts to all). Exam questions often ask about this distinction.
2. Forgetting the N-1 Rule for Mesh: In full mesh, each node needs N-1 ports. Don't forget that ports = N-1, not N. Total links = N(N-1)/2, not N².
3. Hub vs Switch in Star: A hub is a physical star but logical bus (broadcasts to all). A switch is a physical star AND logical star (unicast to destination only). Switches are far more efficient.
4. Tree vs Mesh Redundancy: Tree topology has NO redundant paths. If a parent node fails, all its children lose connectivity. Mesh has redundant paths. Don't assume "more cables = more reliable" without checking the topology structure.
5. Hybrid Is Not a Fixed Type: Hybrid is any combination — there is no standard "hybrid formula." Calculate links by breaking the hybrid into its component topologies and summing them up.
