OSI Model

Open Systems Interconnection — Complete Networking Reference

What is the OSI Model?

The Open Systems Interconnection (OSI) Model is a conceptual framework developed by ISO in 1984 that standardizes how network communications should be organized into seven distinct layers. Each layer has specific functions and communicates with the layers directly above and below it.

Key Principle:
Each layer provides services to the layer above and receives services from the layer below
Changes in one layer do not affect other layers as long as interfaces remain the same

Purpose

• Enable interoperability between different vendors

• Provide a common framework for networking

• Divide complex networking into manageable parts

Key Facts

• Developed by ISO (1984)

• 7 layers total

• Layers 1-4 are Host layers

• Layers 5-7 are Media layers

Layer 7 — Application

PDU: Data

The Application Layer is the closest layer to the end user. It provides network services directly to user applications. This layer establishes communication partners, determines resource availability, and synchronizes communication.

Functions

  • Network service access for applications
  • Resource availability identification
  • Communication partner authentication
  • Email and file transfer services

Protocols & Services

  • HTTP/HTTPS — Web browsing
  • FTP/SFTP — File transfer
  • SMTP — Email sending
  • POP3/IMAP — Email retrieval
  • DNS — Domain name resolution
  • SNMP — Network management
  • Telnet/SSH — Remote access

Devices

  • Computers (browsers, email clients)
  • Servers (web, email, DNS servers)
  • Firewalls (application-level filtering)

Layer 6 — Presentation

PDU: Data

The Presentation Layer acts as a translator between the application and the network. It handles data formatting, encryption/decryption, and compression/decompression to ensure data is in a usable format.

Functions

  • Data format translation (e.g., EBCDIC to ASCII)
  • Data encryption and decryption (SSL/TLS)
  • Data compression and decompression
  • Character code translation
  • Graphic format handling (JPEG, GIF, PNG)

Protocols & Standards

  • SSL/TLS — Encryption
  • JPEG, GIF, PNG — Image formats
  • MPEG, MIDI — Audio/Video formats
  • ASCII, EBCDIC, Unicode — Character encoding
  • XDR — External Data Representation

Key Concept

When you send an email, the Presentation Layer converts your message from the application's format into a format suitable for network transmission, and vice versa at the receiving end.

Layer 5 — Session

PDU: Data

The Session Layer establishes, manages, and terminates sessions (connections) between applications. It handles session checkpointing and recovery, ensuring that if a connection is interrupted, only data after the last checkpoint needs to be retransmitted.

Functions

  • Session establishment, maintenance, and termination
  • Dialog control (half-duplex or full-duplex)
  • Synchronization with checkpoints
  • Session recovery after interruption

Protocols

  • NetBIOS — Network Basic Input/Output System
  • RPC — Remote Procedure Call
  • PPTP — Point-to-Point Tunneling Protocol
  • SAP — Session Announcement Protocol
Checkpointing Example

When downloading a 1GB file, the Session Layer places checkpoints every 100MB. If the connection drops at 350MB, only data from the 300MB checkpoint needs to be retransmitted — not the entire file.

Layer 4 — Transport

PDU: Segment (TCP) / Datagram (UDP)

The Transport Layer provides reliable (or unreliable) end-to-end data delivery between applications on different hosts. It handles flow control, error correction, and data segmentation.

Functions

  • End-to-end message delivery
  • Segmentation and reassembly
  • Flow control (windowing)
  • Error detection and recovery
  • Connection-oriented or connectionless service

Protocols

  • TCP — Transmission Control Protocol (reliable, connection-oriented)
  • UDP — User Datagram Protocol (unreliable, connectionless)
  • SCTP — Stream Control Transmission Protocol
Port Numbers:
Well-known: 0-1023 | Registered: 1024-49151 | Dynamic: 49152-65535
Port numbers identify specific applications or services on a host

TCP Features

• Connection-oriented (3-way handshake)

• Reliable delivery with acknowledgments

• Flow control (sliding window)

• Error recovery (retransmission)

• Ordered delivery

Used by: HTTP, FTP, SMTP, SSH

UDP Features

• Connectionless

• No acknowledgments

• No flow control

• No error recovery

• Fast and lightweight

Used by: DNS, DHCP, VoIP, Gaming

Layer 3 — Network

PDU: Packet

The Network Layer handles logical addressing and routing. It determines the best path for data to travel from source to destination across multiple networks (internetworking).

Functions

  • Logical addressing (IP addresses)
  • Routing (path determination)
  • Packet forwarding
  • Fragmentation and reassembly
  • Quality of Service (QoS)

Protocols

  • IPv4 / IPv6 — Internet Protocol
  • ICMP — Internet Control Message Protocol (ping)
  • OSPF — Open Shortest Path First
  • BGP — Border Gateway Protocol
  • RIP — Routing Information Protocol
  • EIGRP — Enhanced Interior Gateway Routing Protocol

Devices

  • Routers — Forward packets between networks
  • Layer 3 Switches — Switching with routing capability
IP Address Classes:
Class A: 1.0.0.0 to 126.255.255.255 | Class B: 128.0.0.0 to 191.255.255.255 | Class C: 192.0.0.0 to 223.255.255.255

Layer 2 — Data Link

PDU: Frame

The Data Link Layer provides node-to-node data transfer on the same network segment. It handles MAC addressing, error detection, and media access control. This layer is divided into two sublayers: LLC and MAC.

Sublayers

  • LLC (Logical Link Control) — Error checking, flow control, multiplexing
  • MAC (Media Access Control) — Physical addressing, media access

Functions

  • Framing — organizing bits into frames
  • Physical addressing (MAC addresses)
  • Error detection (CRC, FCS)
  • Media access control
  • Flow control

Protocols & Standards

  • Ethernet (IEEE 802.3) — Wired LAN
  • Wi-Fi (IEEE 802.11) — Wireless LAN
  • PPP — Point-to-Point Protocol
  • HDLC — High-Level Data Link Control
  • Frame Relay — WAN protocol

Devices

  • Switches — Forward frames using MAC addresses
  • Bridges — Connect network segments
  • NICs — Network Interface Cards
MAC Address Format:
XX:XX:XX:XX:XX:XX (48 bits, 6 bytes, hexadecimal)
First 3 bytes = OUI (manufacturer), Last 3 bytes = device identifier

Layer 1 — Physical

PDU: Bits (0s and 1s)

The Physical Layer is responsible for transmitting raw binary data (bits) over a physical medium. It defines electrical, mechanical, and functional specifications for the physical link.

Functions

  • Bit transmission and reception
  • Electrical signal specifications
  • Physical topology (bus, star, ring, mesh)
  • Data rate (bandwidth)
  • Bit synchronization (clocking)
  • Transmission mode (simplex, half-duplex, full-duplex)

Physical Media

  • Copper cables — UTP (Cat5e, Cat6, Cat6a), STP
  • Fiber optics — Single-mode, Multi-mode
  • Wireless — Radio waves, microwaves, infrared

Devices & Standards

  • Hubs — Repeat signals to all ports
  • Repeaters — Regenerate and amplify signals
  • Modems — Modulate/demodulate signals
  • Cables — RJ-45, Fiber connectors

Transmission Modes

• Simplex — One direction only (TV broadcast)

• Half-duplex — Both directions, one at a time (walkie-talkie)

• Full-duplex — Both directions simultaneously (phone call)

Physical Topologies

• Bus — All devices share one cable

• Star — All devices connect to central hub/switch

• Ring — Devices form a circular loop

• Mesh — Every device connects to every other device

Data Encapsulation Process

As data moves down through the OSI layers, each layer adds its own header (and sometimes trailer) to the data. This process is called encapsulation. At the receiving end, each layer strips its header — this is called decapsulation.

Key Insight

Each layer can only communicate with its adjacent layers. When you send data, it flows DOWN (encapsulation). When you receive data, it flows UP (decapsulation). A router operates at Layers 1-3, a switch at Layers 1-2, and a firewall may operate up to Layer 7.

  • Layer 7 — Application
  • Layer 6 — Presentation
  • Layer 5 — Session
  • Layer 4 — Transport
  • Layer 3 — Network
  • Layer 2 — Data Link
  • Layer 1 — Physical

  • Layer 4 — Application
  • Layer 3 — Transport
  • Layer 2 — Internet

Important Distinction

OSI is a theoretical reference model used for understanding networking concepts. TCP/IP is the practical model that actually powers the Internet. In real-world networking, TCP/IP protocols are used, but OSI terminology is still the standard language for describing network functions.

OSI Strengths

• Clear separation of concerns

• Each layer has distinct functions

• Excellent for troubleshooting

• Universal reference language

TCP/IP Strengths

• Proven in real-world implementation

• Simpler 4-layer design

• Internet standard

• More efficient in practice

Common Mistakes & Warnings

Mistake 1: Confusing MAC and IP Addresses

Wrong: "MAC addresses are used for routing across the Internet."

Correct: MAC addresses (Layer 2) are used for local delivery on the same network segment. IP addresses (Layer 3) are used for routing across different networks. MAC addresses stay the same; IP addresses change at each hop.

Mistake 2: Confusing Hubs and Switches

Wrong: "Switches operate at the Network Layer."

Correct: Basic switches operate at Layer 2 (Data Link) and use MAC addresses. Routers operate at Layer 3 (Network) and use IP addresses. Layer 3 switches can do both.

Mistake 3: Misunderstanding PDU Names

Wrong: "All data at every layer is called a packet."

Correct: Each layer has a specific PDU name:

• Layers 7-5: Data

• Layer 4: Segment (TCP) or Datagram (UDP)

• Layer 3: Packet

• Layer 2: Frame

• Layer 1: Bits

Mistake 4: Thinking Layers Work Independently

Wrong: "Each layer can function without the others."

Correct: Layers work as a stack. A failure at any layer affects all layers above it. For example, a physical cable cut (Layer 1) prevents IP routing (Layer 3) and web browsing (Layer 7).

Mistake 5: OSI vs TCP/IP Layer Count

Wrong: "TCP/IP has 7 layers like OSI."

Correct: TCP/IP has 4 layers. The Application layer in TCP/IP combines OSI's Application, Presentation, and Session layers. The Network Access layer combines OSI's Data Link and Physical layers.

Mistake 6: Confusing Connection-Oriented vs Connectionless

Wrong: "TCP is connectionless and UDP is connection-oriented."

Correct: TCP is connection-oriented (3-way handshake, reliable). UDP is connectionless (no handshake, unreliable but fast).

Mistake 7: Forgetting Encapsulation Direction

Wrong: "Encapsulation happens when receiving data."

Correct: Encapsulation (adding headers) happens when sending data — going DOWN the layers. Decapsulation (removing headers) happens when receiving data — going UP the layers.
