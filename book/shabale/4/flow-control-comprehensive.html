Flow Control

Computer Networks — Complete Guide for Exam Preparation

Flow Control Basics

Flow control is a technique that manages the rate of data transmission between two nodes to prevent a fast sender from overwhelming a slow receiver. It ensures the receiver processes data at its own pace.

Flow Control Purpose:
Match sender rate ≤ Receiver processing rate
Without flow control, the receiver's buffer overflows and packets are dropped.

Flow Control Methods

Feedback-Based

• Receiver informs sender

• Stop & Wait

• Sliding Window

Rate-Based

• Sender estimates rate

• No feedback needed

• Used in ATM, FDDI

Flow Control vs Congestion Control

Feature Flow Control Congestion Control
Scope End-to-end (sender-receiver) Network-wide
Problem Fast sender, slow receiver Too much traffic in network
Location Data Link & Transport layers Network & Transport layers
Mechanism Window-based Window + rate limiting
Key Difference: Flow control is about the sender and receiver speeds. Congestion control is about the network capacity. Both are needed for reliable data transfer.

Sliding Window Protocol

Sliding window is the most common flow control mechanism. It allows multiple frames to be in transit simultaneously, improving efficiency. The window size determines how many frames can be sent without acknowledgment.

Sliding Window Principle:
Sender window ≤ Receiver buffer capacity
The window slides forward as ACKs are received, allowing new frames to be sent.

Window Concepts

Sender Window: [Sendable] [Sent, waiting ACK] [Not yet sendable] |←── Window ──→| |←── Remaining ──→| As ACKs received, window slides right: [Sendable] [Sent, waiting ACK] [Not yet sendable] |←── Window ──→|

Window Variables

Send Window

• Sf: First unacked frame

• Sn: Next frame to send

• Size: W = constant

Receive Window

• Rn: Expected frame

• Size: Usually 1 or W

• Buffers out-of-order

Example 1: Window Sliding

Window size = 4. Initially Sf=0, Sn=0. Show window after sending frames 0,1,2,3 and receiving ACK0, ACK1.

Answer:

Initial: [0,1,2,3] (all sendable)

Send 0,1,2,3: [] [0,1,2,3] (all sent, waiting ACK)

Receive ACK0, ACK1: [2,3,4,5] (window slid by 2)

Example 2: Window Full Scenario

Window size = 3. Sender has sent frames 0,1,2. What happens when it tries to send frame 3?

Answer:

Window is full (3 frames in flight)

Sender must wait for ACK before sending frame 3

Efficiency with Sliding Window:
η = min(W, 1 + 2a) where a = T_prop / T_frame
W = window size, a = ratio of propagation to transmission time
Example 3: Efficiency Calculation

Window = 5, T_frame = 1 ms, T_prop = 2 ms. Calculate efficiency.

Answer:

a = T_prop / T_frame = 2/1 = 2

1 + 2a = 1 + 4 = 5

η = min(5, 5) / (1 + 2a) = 5/5 = 100%

Window Management

Proper window management is crucial for protocol correctness. The window must not exceed the sequence number space to avoid ambiguity between new and retransmitted frames.

Window Size Constraints:
Stop & Wait: W = 1 | Go-Back-N: W ≤ 2^n - 1 | Selective Repeat: W ≤ 2^(n-1)
n = number of bits in sequence number field

Sequence Number Space

Protocol Sequence Numbers Max Window Example (3 bits)
Stop & Wait 0, 1 1 W = 1
Go-Back-N 0 to 2^n - 1 2^n - 1 W = 7
Selective Repeat 0 to 2^n - 1 2^(n-1) W = 4
Example 4: Window Size Selection

If the bandwidth-delay product is 100 KB and frame size is 1 KB, what window size is needed for 100% utilization?

Answer:

Window = Bandwidth × Delay / Frame size

Window = 100 KB / 1 KB = 100 frames

Example 5: Sequence Bits Required

What is the minimum number of sequence number bits for Go-Back-N with window size 15?

Answer:

2^n - 1 ≥ 15 → 2^n ≥ 16 → n ≥ 4 bits

Common Mistake: Selective Repeat requires a smaller window than Go-Back-N for the same number of sequence bits. This is because both sender and receiver windows must not overlap.

Worked Examples

Example 6: Bandwidth-Delay Product

Link: 100 Mbps, RTT = 50 ms. What is the bandwidth-delay product?

Answer:

BDP = Bandwidth × RTT = 100 × 10^6 × 50 × 10^-3 = 5 × 10^6 bits = 625 KB

Example 7: Optimal Window Size

For the above link, if frame size = 1500 bytes, what window size gives 100% utilization?

Answer:

Window = BDP / Frame size = 625 KB / 1.5 KB = 417 frames

Example 8: Protocol Efficiency

Stop & Wait on 100 Mbps link, RTT = 50 ms, frame = 1500 bytes. Calculate efficiency.

Answer:

T_frame = 1500 × 8 / 100 × 10^6 = 0.12 ms

T_prop = RTT/2 = 25 ms

a = T_prop / T_frame = 25 / 0.12 = 208.3

η = 1 / (1 + 2a) = 1 / 417.6 = 0.24%

Example 9: Sliding Window Improvement

Same link as above, but with sliding window W=417. Calculate efficiency.

Answer:

η = min(W, 1+2a) / (1+2a) = min(417, 417.6) / 417.6 = 99.9%

Example 10: Satellite Link

Satellite link: 10 Mbps, RTT = 540 ms, frame = 1000 bytes. What window size is needed?

Answer:

BDP = 10 × 10^6 × 0.54 = 5.4 × 10^6 bits = 675 KB

Window = 675 KB / 1 KB = 675 frames

Need 10 sequence bits (2^10 = 1024 > 675)

U = min(W, 1 + 2a) / (1 + 2a)
Where W = window size, a = T_prop / T_frame
Example 11: Protocol Selection Guide

Choose the best flow control protocol for:

(a) Short-distance, low-speed: Stop & Wait

(b) LAN with low errors: Go-Back-N

(c) WAN/satellite with errors: Selective Repeat

(d) Real-time applications: Rate-based

Key Insight: The optimal window size depends on the bandwidth-delay product. For 100% utilization, W ≥ 1 + 2a. Modern protocols like TCP dynamically adjust window size based on network conditions.

Advanced Concepts

Piggybacking

Piggybacking Definition:
ACKs carried in data frames (instead of separate ACK frames)
Reduces overhead by combining data and acknowledgments in one frame.

Without Piggybacking

• Data frame: [Data]

• ACK frame: [ACK]

• Two separate transmissions

With Piggybacking

• Combined frame: [Data + ACK]

• One transmission only

• 50% overhead reduction

Example: Piggybacking Benefit

Frame overhead = 50 bytes. How much overhead is saved with piggybacking for 100 data exchanges?

Answer:

Without piggybacking: 100 × 50 = 5000 bytes ACK overhead

With piggybacking: 0 bytes (ACKs in data frames)

Savings: 5000 bytes (100% ACK overhead eliminated)

Channel Utilization

Channel Utilization:
U = (Useful time) / (Total time) × 100%
Measures how efficiently the channel is used for actual data transmission.

Bandwidth-Delay Product (BDP)

BDP Formula:
BDP = Bandwidth × RTT
Maximum data "in flight" on the link. Window should be ≥ BDP for full utilization.
Example: BDP Calculation

Link: 1 Gbps, RTT = 100 ms. What is BDP?

Answer:

BDP = 1 × 10^9 × 0.1 = 10^8 bits = 12.5 MB

Key Insight: For high-speed long-distance links (like satellite), BDP can be very large, requiring large window sizes for efficient utilization.

X-ON / X-OFF (Software Flow Control)

Software Flow Control:
X-ON (DC1, 0x11) = Resume transmission
X-OFF (DC3, 0x13) = Pause transmission
In-band signaling characters used to control data flow between devices.

X-ON (Transmit On)

• Character: DC1 (0x11)

• Binary: 00010001

• Meaning: "I'm ready, send data"

• Sent by: Receiver

X-OFF (Transmit Off)

• Character: DC3 (0x13)

• Binary: 00010011

• Meaning: "Stop sending, buffer full"

• Sent by: Receiver

Example 12: X-ON/X-OFF Operation

Receiver buffer = 3000 bytes. Data rate = 10 Mbps. Processing rate = 2 Mbps. How much data arrives before X-OFF takes effect?

Answer:

Time for X-OFF to travel back: T_prop = 10 ms

Data in transit = (10 - 2) Mbps × 10 ms = 80,000 bits = 10,000 bytes

Total buffer needed = 3000 + 10,000 = 13,000 bytes

Key Limitation: X-ON/X-OFF is in-band signaling, meaning control characters are sent within the data stream. If the data itself contains X-OFF or X-ON characters, the protocol breaks. This is why it's mainly used for ASCII text communication, not binary data.

RTS/CTS (Request to Send / Clear to Send)

Hardware Flow Control:
RTS (Request to Send) → CTS (Clear to Send) → Data
Out-of-band signaling using separate hardware lines. Used in MAC protocols to solve hidden terminal problem.

RTS (Request to Send)

• Sent by: Sender

• Meaning: "I want to send data"

• Contains: Sender address, Receiver address, Data length

CTS (Clear to Send)

• Sent by: Receiver

• Meaning: "You may send data now"

• Clears channel for transmission

Example: RTS/CTS Handshake

Show the complete RTS/CTS handshake process for a wireless station.

Answer:

1. Sender → RTS → Receiver

2. Receiver → CTS → Sender

3. Sender → Data → Receiver

4. Receiver → ACK → Sender
