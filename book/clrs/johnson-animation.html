🎯 What Is This All About?

Imagine you have a map of cities connected by roads. Some roads have tolls (positive costs), and a few roads give you money (negative costs!). You want to find the cheapest route between every pair of cities. That's exactly what Johnson's algorithm does!

🧱 Building Blocks — What's a Graph?

A graph is just a collection of vertices (circles, also called nodes) connected by edges (arrows). Each edge has a weight (a number) that represents the cost of traveling along it. In our graph, the weight 3 on edge v₁→v₂ means "it costs 3 to go from v₁ to v₂".

The weight −2 on edge v₃→v₁ is negative — it's like getting a 2-unit reward for traveling that road. Negative weights make the problem tricky for most shortest-path algorithms.

🤔 The Challenge

There's a famous algorithm called Dijkstra's algorithm that finds shortest paths very efficiently — BUT it only works when all edge weights are non-negative (≥ 0). Negative weights can cause it to make mistakes!

Another algorithm called Bellman-Ford CAN handle negative weights, but it's slower. We'd need to run it once for every starting vertex, which would be too slow for large graphs.

💡 Johnson's Brilliant Idea

Johnson's algorithm combines the best of both:

Step 1: Add a fake city s with zero-cost roads to all cities.

Step 2: Run Bellman-Ford from s to figure out a "height" (called h(v)) for each city.

Step 3: Use these heights to recalculate every road's cost so that all costs become non-negative.

Step 4: Now that all costs are safe, run speedy Dijkstra from every starting city.

Step 5: Convert the results back to the original costs.

4 cities {v₁, v₂, v₃, v₄}, 6 one-way roads. One road has a negative cost:

Roads: v₁→v₂(3), v₁→v₄(5), v₂→v₃(1), v₂→v₄(2), v₃→v₁(−2), v₄→v₃(4)

The numbers in parentheses are the costs (weights). Negative cost = you gain that much by traveling the road.
