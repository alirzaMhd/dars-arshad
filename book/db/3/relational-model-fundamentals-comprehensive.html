RELATIONAL MODEL FUNDAMENTALS

Database Systems — Complete Guide for Exam Preparation

What is the Relational Model?

The relational model is a mathematical model for databases introduced by E.F. Codd in 1970. It represents data as relations (tables) where:

Relation (Table)

A two-dimensional structure consisting of rows and columns

Also called: relation, table, file

Tuple (Row)

A single record/entry in a relation

Also called: tuple, record, row

Attribute (Column)

A property or field of a relation

Also called: attribute, column, field

Domain

The set of allowed values for an attribute

Must be atomic (indivisible)

Formal Definition:
R(A₁, A₂, ..., Aₙ)
A relation R with n attributes A₁ through Aₙ. Each attribute has a domain Dom(Aᵢ).
Example 1: Simple Relation

Consider a Students relation:

StudentIDNameAgeMajor
101Alice20CS
102Bob22Math
103Carol21CS

Here: Relation = Students, Tuples = 3 rows, Attributes = StudentID, Name, Age, Major

Example 2: Domain Constraints

Each attribute has a domain:

  • StudentID: Domain = positive integers
  • Name: Domain = strings of characters
  • Age: Domain = positive integers (15-100)
  • Major: Domain = {'CS', 'Math', 'Physics', 'Engineering'}

Relation Schema and Instance

Relation Schema:
R = (A₁, A₂, ..., Aₙ)
The structure/header of a relation. Defines attribute names and their domains.
Relation Instance:
r(R) = {t₁, t₂, ..., tₘ}
A set of tuples (rows) that currently exist in the relation at a given time.
Example 3: Schema vs Instance

Schema: Employee(EmpID, Name, Salary, DeptID)

Instance:

EmpIDNameSalaryDeptID
E1John50000D1
E2Jane60000D2

Schema rarely changes; instance changes as data is inserted/deleted.

Important Properties of Relations:

1. Each relation has a unique name

2. Each attribute has a unique name within the relation

3. All values in a column come from the same domain

4. Each tuple is unique (no duplicate rows)

5. The order of tuples is insignificant

6. The order of attributes is insignificant

Degree and Cardinality

Degree (Arity)

The number of attributes in a relation

degree(R) = n

Example: Employee has degree 4

Cardinality

The number of tuples in a relation

|r(R)| = m

Example: Employee has cardinality 2

Key Properties of the Relational Model

1. Atomic Values (First Normal Form)

Each attribute value must be atomic (indivisible). No sets, lists, or composite values.

Example 4: Atomic vs Non-Atomic
Valid (Atomic)Invalid (Non-Atomic)
Age: 20Phones: {555-1234, 555-5678}
Name: "Alice"Skills: ["Java", "Python"]
Salary: 50000Addresses: "123 Main St; 456 Oak Ave"

2. Unique Tuple Constraint

No two tuples in a relation can be identical. This is enforced by primary keys.

3. NULL Values

The relational model allows NULL values to represent:

  • Unknown value
  • Not applicable
  • Missing information
NULL Complications:

NULL is not equal to any value, including itself. NULL comparisons require special handling with IS NULL / IS NOT NULL operators.

4. Order Insensitivity

The order of tuples and attributes does not matter. Two relations are equal if they contain the same tuples, regardless of order.

Example: Tuple Order Does Not Matter

These two relations are EQUAL:

Relation R1:

IDName
1Alice
2Bob

Relation R2:

IDName
2Bob
1Alice

R1 = R2 because they contain the same tuples, just in different order.

Example: Attribute Order Does Not Matter

These two relations are also EQUAL:

R(A, B):

AB
1x

R(B, A):

BA
x1

Attribute order is insignificant in the relational model.

Key Rules to Remember

✓ All attribute values must be atomic

✓ Each relation must have a unique name

✓ Each attribute must have a unique name within its relation

✓ No duplicate tuples allowed

✓ Order of tuples/attributes doesn't matter

✓ NULL represents unknown/missing values
