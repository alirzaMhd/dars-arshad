Enhanced Entity-Relationship (EER) Model

The EER model extends the basic ER model with concepts for specialization, generalization, and inheritance.

Superclass

The parent entity in an inheritance hierarchy

Contains common attributes

Subclass

The child entity in an inheritance hierarchy

Has specific attributes

ISA Relationship

Represents "is a" relationship between superclass and subclass

Also called: inheritance relationship

Example 1: EER Hierarchy

Consider a university database:

Person (Superclass)

Attributes: Name, Address, Phone

↓ ISA

Student (Subclass)

GPA, Major

Employee (Subclass)

Salary, Position

Specialization (Top-Down)

Specialization is the process of defining subclasses from a superclass based on distinguishing characteristics.

Process:
Superclass → Subclasses
Start with a general entity and divide into specialized subgroups.
Example 2: Specialization

Step 1: Start with Person entity

Step 2: Identify distinguishing characteristics

  • Some persons are Students (have GPA, enroll in courses)
  • Some persons are Employees (have salary, work in departments)

Step 3: Create subclasses Student and Employee

Attribute Inheritance

Subclasses inherit all attributes from superclass

Student has: Name, Address, Phone, GPA, Major

Specific Attributes

Subclasses can have additional attributes

Student adds: GPA, Major

Generalization (Bottom-Up)

Generalization is the process of combining multiple entity types into a single higher-level entity based on common features.

Process:
Subclasses → Superclass
Start with specific entities and abstract common features into a superclass.
Example 3: Generalization

Step 1: Observe Car, Truck, Motorcycle entities

Step 2: Identify common attributes: Make, Model, Year, Price

Step 3: Create Vehicle superclass with common attributes

Step 4: Car, Truck, Motorcycle become subclasses

Specialization vs Generalization:

• Specialization: Top-down (general → specific)

• Generalization: Bottom-up (specific → general)

• Both result in the same EER hierarchy

Inheritance in EER

Subclasses inherit all attributes and relationships from their superclass.

Inheritance Rule:
If A is superclass of B, then B has all attributes of A plus its own
Every instance of B is also an instance of A.
Example 4: Attribute Inheritance
EntityAttributes
Person (Superclass)Name, Address, Phone
Student (Subclass)Inherits: Name, Address, Phone; Adds: GPA, Major
Employee (Subclass)Inherits: Name, Address, Phone; Adds: Salary, Position
Example 5: Relationship Inheritance

If Person has a "Lives_At" relationship with Location:

  • Student inherits the Lives_At relationship
  • Employee inherits the Lives_At relationship
  • Both can participate in Lives_At without redefining it

Benefits of Inheritance

• Reduces redundancy

• Maintains consistency

• Simplifies design

Key Properties

• Subclass is a subset of superclass

• Every subclass instance is a superclass instance

• Multiple inheritance levels possible
