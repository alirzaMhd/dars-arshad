Database Systems — Relationships and Constraints for Exam Preparation

What is a Foreign Key?

A foreign key is an attribute (or set of attributes) in one relation that references the primary key of another relation.

Definition:
FK in R₂ references PK in R₁
If attribute A in relation R₂ is a foreign key referencing relation R₁, then every value of A in R₂ must either equal some value of the PK in R₁, or be NULL.

Referential Integrity Constraint

Referential integrity ensures that relationships between tables remain consistent.

Formal Definition:
∀t ∈ r₂, t[A] ∈ π_{PK}(r₁) ∪ {NULL}
Every foreign key value must either match a primary key value in the referenced relation, or be NULL (if allowed).
Example 2: Valid vs Invalid FK Values
Valid FK ValuesInvalid FK Values
DeptID = 'D1' (exists in Department)DeptID = 'D99' (doesn't exist)
DeptID = NULL (if allowed)DeptID = '' (empty string ≠ NULL)
Common Violations:

1. Inserting a tuple with FK value that doesn't exist in referenced relation

2. Deleting a tuple from referenced relation that is referenced by FK

3. Updating PK in referenced relation that is referenced by FK

Actions on Referential Integrity Violation

RESTRICT

Reject the operation that would cause violation

Safest option, most common

CASCADE

Propagate the change to dependent tuples

Delete/update related tuples automatically

SET NULL

Set FK to NULL in dependent tuples

Only if FK allows NULL values

SET DEFAULT

Set FK to default value

Default must exist in referenced relation

Example 3: CASCADE Delete

If we DELETE department D1 from Department table:

  • RESTRICT: Delete is rejected (employees still reference D1)
  • CASCADE: All employees with DeptID=D1 are also deleted
  • SET NULL: Employees with DeptID=D1 get DeptID=NULL
  • SET DEFAULT: Employees with DeptID=D1 get DeptID='D0'
Example 4: SQL Syntax
CREATE TABLE Employee (
  EmpID INT PRIMARY KEY,
  Name VARCHAR(50),
  DeptID INT,
  FOREIGN KEY (DeptID) REFERENCES Department(DeptID)
    ON DELETE CASCADE
    ON UPDATE CASCADE
);

NULL Propagation Rules:

✓ NULL compared with anything → UNKNOWN

✓ UNKNOWN in WHERE clause → row excluded

✓ UNKNOWN in NOT NULL check → constraint violated
