DATABASE CONSTRAINTS SUMMARY

Database Systems — Complete Reference of All Database Constraints for Exam Preparation

Types of Database Constraints

1. Intra-Relational Integrity

• Table structure integrity

• Each table has unique name

• Attribute names are unique within table

2. Entity Integrity

• Primary Key cannot be NULL

• PK uniquely identifies each tuple

3. Domain Integrity

• Data type validation

• Values must be from valid domain

4. Referential Integrity

• Foreign Key must reference valid PK

• Or FK must be NULL

The 4 Named Integrity Rules:

✓ Intra-Relational Integrity: Table structure is valid

✓ Entity Integrity: PK cannot be NULL

✓ Domain Integrity: Values must be valid data types

✓ Referential Integrity: FK must match valid PK

Key Constraints

Entity Integrity Rule:
PK ≠ NULL for all tuples
The primary key of a relation cannot contain NULL values.
Key TypePropertiesExample
Primary KeyUnique, NOT NULL, MinimalEmpID
Candidate KeyMinimal superkeyEmpID, SSN
SuperkeyUniquely identifies tuple{EmpID}, {EmpID, Name}
Foreign KeyReferences PK of another relationDeptID references Department
Example 1: Primary Key Constraint
CREATE TABLE EMPLOYEE (
  EmpID INT PRIMARY KEY, -- PK cannot be NULL
  Name VARCHAR(100) NOT NULL
);

EmpID must be unique and cannot be NULL for any tuple.

Referential Integrity

Referential Integrity Rule:
FK = NULL OR FK ∈ {PK values of referenced relation}
A foreign key must either be NULL or reference an existing primary key in the referenced relation.
Example 2: Referential Integrity

Given: Employee.DeptID references Department.DeptID

ValidInvalid
DeptID = 1 (exists in Department)DeptID = 99 (doesn't exist)
DeptID = NULL (if allowed)DeptID = 'abc' (wrong type)
Deletion/Update Rules:

✓ CASCADE: Delete/update referencing rows

✓ SET NULL: Set FK to NULL

✓ SET DEFAULT: Set FK to default value

✓ RESTRICT: Prevent deletion/update

Domain Constraints & NOT NULL

Domain Constraints

• Data type must match

• Range of values

• Format restrictions

• Default values

NOT NULL Constraint

• Mandatory field

• Cannot be NULL

• Enforced on INSERT/UPDATE

Example 3: Domain Constraints
CREATE TABLE EMPLOYEE (
  EmpID INT PRIMARY KEY,
  Name VARCHAR(100) NOT NULL,
  Salary DECIMAL(10,2) CHECK (Salary > 0),
  Age INT CHECK (Age >= 18 AND Age <= 65),
  Email VARCHAR(100) UNIQUE
);

SQL Constraint Examples

Example 4: Complete Table with All Constraints
CREATE TABLE EMPLOYEE (
  EmpID INT PRIMARY KEY, -- Key Constraint
  Name VARCHAR(100) NOT NULL, -- NOT NULL
  SSN CHAR(9) UNIQUE, -- Candidate Key
  DeptID INT, -- Foreign Key
  Salary DECIMAL(10,2) CHECK (Salary > 0), -- Domain
  FOREIGN KEY (DeptID) REFERENCES DEPARTMENT(DeptID)
    ON DELETE SET NULL -- Referential Integrity
);
Example 5: Complete S/P/SP Tables (From PDF)
-- S Table (Suppliers)
CREATE TABLE S (
  S# CHAR(5) PRIMARY KEY,
  Sname VARCHAR(50) NOT NULL,
  Status INT,
  City VARCHAR(50)
);

-- P Table (Parts)
CREATE TABLE P (
  P# CHAR(5) PRIMARY KEY,
  Pname VARCHAR(50) NOT NULL,
  Color VARCHAR(20),
  Weight DECIMAL(5,2)
);

-- SP Table (Shipments)
CREATE TABLE SP (
  S# CHAR(5),
  P# CHAR(5),
  QTY INT CHECK (QTY > 1 AND QTY < 1000),
  PRIMARY KEY (S#, P#),
  FOREIGN KEY (S#) REFERENCES S(S#)
    ON DELETE CASCADE ON UPDATE CASCADE,
  FOREIGN KEY (P#) REFERENCES P(P#)
    ON DELETE CASCADE ON UPDATE CASCADE
);

Example 6: Adding Constraints After Creation
-- Add NOT NULL
ALTER TABLE EMPLOYEE ALTER COLUMN Name SET NOT NULL;

-- Add CHECK constraint
ALTER TABLE EMPLOYEE ADD CONSTRAINT chk_salary CHECK (Salary > 0);

-- Add Foreign Key
ALTER TABLE EMPLOYEE ADD CONSTRAINT fk_dept
  FOREIGN KEY (DeptID) REFERENCES DEPARTMENT(DeptID);

Key Rules for Exam

✓ Entity Integrity: PK cannot be NULL

✓ Referential Integrity: FK must reference valid PK or be NULL

✓ Domain Constraint: Values must match data type

✓ NOT NULL: Field is mandatory

✓ UNIQUE: No duplicate values allowed

✓ CHECK: Value must satisfy condition

✓ DEFAULT: Provide default value if not specified
