CARDINALITY CONSTRAINTS

Database Systems — Limits on Entity Participation in Relationships for Exam Preparation

Cardinality Constraints Basics

Cardinality constraints specify the minimum and maximum number of entity instances that can participate in a relationship.

Definition:
Cardinality = (min, max) for each participating entity
Defines the allowed number of relationship instances per entity instance.

Binary Relationships

• 1:1 — One-to-One

• 1:N — One-to-Many

• M:N — Many-to-Many

Participation Types

• Total — Every entity must participate

• Partial — Some entities may not

Min-Max (min, max) Notation

Notation:
Entity ——(min, max)—— Relationship
min: minimum participation (0 = partial, 1 = total)
max: maximum participation (1 = at most one, N = many)
CardinalityNotationMeaning
1:1(1,1) —— R —— (1,1)Each entity participates exactly once
1:N(1,1) —— R —— (0,N)Left: exactly once; Right: zero or more
M:N(0,N) —— R —— (0,N)Both sides: zero or more
Total 1:N(1,1) —— R —— (1,N)Right side must participate at least once
Important Distinction:

min: 0 = partial participation, 1 = total participation

max: 1 = at most one, N = many

Worked Examples

Example 1: Employee Works For Department

Constraints:

  • Each Employee works for exactly one Department → Employee: (1,1)
  • Each Department has zero or more Employees → Department: (0,N)
Employee ——(1,1)—— WORKS_FOR ——(0,N)—— Department
Example 2: Student Enrolls In Course

Constraints:

  • A Student enrolls in zero or more Courses → Student: (0,N)
  • A Course has zero or more Students → Course: (0,N)
Student ——(0,N)—— ENROLLS_IN ——(0,N)—— Course
Example 3: Person Has Passport

Constraints:

  • A Person has at most one Passport → Person: (0,1)
  • A Passport belongs to exactly one Person → Passport: (1,1)
Person ——(0,1)—— HAS ——(1,1)—— Passport

Mapping Cardinality to Relations

Mapping Rules:
1:1 → FK on either side (or both)
1:N → FK on the N side
M:N → Junction table
FK placement depends on cardinality ratio and participation constraints.
Example 4: Mapping 1:N with Total Participation

Employee (1,1) —— WORKS_FOR —— (0,N) Department

CREATE TABLE Employee (
  EmpID INT PRIMARY KEY,
  DeptID INT NOT NULL, -- Total participation
  FOREIGN KEY (DeptID) REFERENCES Department(DeptID)
);

DeptID is NOT NULL because of total participation (min=1).

Key Rules to Remember

✓ min=0 → Partial participation (NULL allowed)

✓ min=1 → Total participation (NOT NULL)

✓ max=1 → At most one relationship

✓ max=N → Many relationships allowed

✓ M:N always requires junction table
