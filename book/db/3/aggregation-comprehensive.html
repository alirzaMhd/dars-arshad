AGGREGATION

Database Systems — Treating Relationships as Higher-Level Entities for Exam Preparation

What is Aggregation?

Aggregation is a conceptual abstraction that treats a relationship (and its participating entities) as a higher-level entity.

Definition:
Aggregation(R) = Relationship R + Participating Entities
The entire relationship becomes a single entity that can participate in other relationships.
Example 1: Why Aggregation?

Consider: Employee WORKS_ON Project

Now we want to track: Manager MANAGES the WORKS_ON relationship

Problem: Manager doesn't manage Employee or Project separately, but manages the assignment itself.

Solution: Aggregate WORKS_ON into a single entity

When to Use Aggregation

Use Aggregation When:

✓ Need to treat a relationship as an entity

✓ A relationship participates in another relationship

✓ Need to attach attributes to a relationship

Don't Use When:

✗ Simple many-to-many relationships

✗ Standard entity-relationship patterns

✗ Can be solved with attributes

Key Insight:

Aggregation allows relationships to participate in other relationships — this is NOT possible in basic ER diagrams without aggregation.

Worked Examples

Example 2: Project Assignment Management

Without Aggregation:

Employee —— WORKS_ON —— Project

✗ Cannot have Manager manage WORKS_ON


With Aggregation:

[Employee —— WORKS_ON —— Project] → Aggregated Entity

Manager —— MANAGES —— [Aggregated Entity]

✓ Manager manages the assignment

Example 3: Another Example - Contract Management
  • Supplier SUPPLIES Part (M:N relationship)
  • We want to track: Manager OVERSEES the SUPPLIES relationship
  • Aggregate SUPPLIES into a single entity
  • Manager OVERSEES the aggregated entity

Mapping Aggregation to Relations

Mapping Rule:
Create relation for aggregated relationship, then relate other entities to it
The aggregated relationship becomes a relation with its own primary key.
Example 4: Mapping Project Assignment
RelationAttributes
EmployeeEmpID (PK), Name
ProjectProjID (PK), ProjName
Works_OnEmpID (FK), ProjID (FK), Hours
ManagerMgrID (PK), MgrName
Manages_AssignmentMgrID (FK), EmpID (FK), ProjID (FK), StartDate

Manages_Assignment references the Works_On relationship via composite key.
