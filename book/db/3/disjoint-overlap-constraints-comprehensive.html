DISJOINT & OVERLAP CONSTRAINTS

Database Systems — ISA Constraint Types for Exam Preparation

Disjoint Constraint

The disjoint constraint specifies that an entity instance can belong to at most one subclass.

Rule:
∀x ∈ Superclass: x ∈ Subclass₁ XOR x ∈ Subclass₂
An entity cannot be in more than one subclass at a time.
Example 1: Disjoint ISA

Given: Person ISA with subclasses Student, Employee

Constraint: Disjoint

  • A person can be a Student OR an Employee, but not both
  • If John is a Student, he cannot also be an Employee
Disjoint Means:

✓ An entity can be in exactly one subclass (if total)

✓ An entity can be in at most one subclass (if partial)

✗ An entity cannot be in two or more subclasses

Overlap Constraint

The overlap constraint specifies that an entity instance can belong to multiple subclasses simultaneously.

Rule:
∀x ∈ Superclass: x ∈ Subclass₁ AND x ∈ Subclass₂ is allowed
An entity can be in more than one subclass at the same time.
Example 2: Overlapping ISA

Given: Person ISA with subclasses Student, Employee

Constraint: Overlap

  • A person can be a Student AND an Employee simultaneously
  • John can be both a student (studying) and an employee (working)

Key Rules to Remember

✓ Disjoint: at most one subclass

✓ Overlap: multiple subclasses allowed

✓ Disjoint uses symbol d in ISA triangle

✓ Overlap uses symbol o in ISA triangle

✓ These constraints are independent of Total/Partial
