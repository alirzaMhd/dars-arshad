ISA Relationship Basics

The ISA relationship (also called "is-a" relationship) represents inheritance between entity types.

Definition:
A ISA B means "A is a B"
Every instance of A is also an instance of B. A inherits attributes and relationships from B.
Example 1: ISA Relationships

Person ISA Entity

Every Person is an Entity


Student ISA Person

Every Student is a Person


Employee ISA Person

Every Employee is a Person

Properties

• Transitive: If A ISA B and B ISA C, then A ISA C

• Asymmetric: A ISA B doesn't imply B ISA A

Notation

• ISA shown as triangle symbol

• Or as arrow from subclass to superclass

ISA Constraints

Completeness Constraint

Total: Every superclass instance must be in a subclass

Partial: Superclass instances may not belong to any subclass

Disjointness Constraint

Disjoint: An instance can be in at most one subclass

Overlapping: An instance can be in multiple subclasses

Mapping ISA to Relations

Option 1: Multiple Relations
Create separate tables for superclass and each subclass
Subclass tables contain PK (which is also FK to superclass) plus specific attributes.
Example 3: Multiple Relations Mapping
Person
PersonID (PK)NameAddress
Student
PersonID (PK, FK)GPAMajor
Employee
PersonID (PK, FK)SalaryPosition
Option 2: Single Relation
One table with all attributes and a type discriminator
Use a "Type" column to indicate which subclass the tuple belongs to. NULLs for inapplicable attributes.

Worked Examples

Example 4: ISA with Constraints

Given: Vehicle ISA Entity, Car ISA Vehicle, Truck ISA Vehicle

Constraints: Total, Disjoint

Meaning: Every Vehicle must be either Car or Truck, but not both.

Mapping to Relations:

Vehicle
VehicleID (PK)MakeModelYear
Car
VehicleID (PK, FK)NumDoorsTrunkSize
Truck
VehicleID (PK, FK)LoadCapacityTowingCapacity
Example 5: Querying ISA Hierarchy

Find all students with GPA > 3.5:

SELECT P.Name, S.GPA
FROM Person P
JOIN Student S ON P.PersonID = S.PersonID
WHERE S.GPA > 3.5;

Key Rules to Remember

✓ ISA means "is a" relationship

✓ Subclass inherits all superclass attributes

✓ Total/Partial: must vs may be in subclass

✓ Disjoint/Overlapping: at most one vs multiple subclasses

✓ ISA is transitive: A ISA B, B ISA C → A ISA C
