KEY COMPUTATION FROM FUNCTIONAL DEPENDENCIES

Database Systems — Chapter 8: Finding All Candidate Keys from FDs

Candidate Key Computation Algorithm

Given a relation schema R and a set of FDs F, we can find all candidate keys using attribute closure. The key idea: a candidate key is a minimal set of attributes whose closure contains all attributes of R.

Definition:
K is a candidate key ⟺ K⁺ = R AND ∀A ∈ K, (K − {A})⁺ ≠ R
Closure of K is the whole relation, and removing any attribute breaks this property.
Step 1: Classify Attributes

Partition all attributes of R into four categories based on their appearance in FDs:

CategoryDefinitionSymbol
Left-only (L)Appears only on LHS of FDsL
Right-only (R)Appears only on RHS of FDsR
Both (B)Appears on both LHS and RHSB
Neither (N)Does not appear in any FDN
Step 2: Determine Mandatory Attributes

Attributes in categories N (neither) and L (left-only) MUST be part of every candidate key.

If an attribute never appears on the RHS of any FD, it can never be determined by other attributes → it must be in every key.

Step 3: Compute Closure of L ∪ N

Let X = L ∪ N. Compute X⁺.

If X⁺ = R, then X is the ONLY candidate key.

Otherwise, add attributes from B (both sides) one at a time to find all candidate keys.

Step 4: Systematic Search

For each subset S of B (both-side attributes):

• Compute (X ∪ S)⁺

• If (X ∪ S)⁺ = R, then X ∪ S is a superkey

• Check minimality: ensure no proper subset is also a superkey

Optimization — Order Matters
Try smaller subsets of B first (size 1, then 2, etc.)
To find all candidate keys, explore subsets of B minimally. When a superkey is found, any superset can be skipped.
Critical Rule

Attributes in categories L (left-only) and N (neither) are required in every candidate key. If you forget to include them, the closure can never equal R.

{B, C} is minimal ✓

Special Cases

Trivial FDs

FDs like A → A provide no information. They do not affect key computation.

Empty LHS

An FD ∅ → A means A has the same value in all tuples. This is rare and affects key analysis.

Cyclic Dependencies

Cycles like A → B, B → A create equivalence classes. Both A and B are in the B (both) category.

Understanding Candidate Keys

Candidate Key Definition:
K is a candidate key of R ⟺ K⁺ = R (superkey) and ∀A ∈ K, (K − {A})⁺ ≠ R (minimal)

Relationship with FDs

A candidate key is essentially a basis for all FDs: if K is a key, then K → A holds for every attribute A in R.

Finding keys = finding minimal LHS sets whose closure covers R.

Key vs. Superkey Closure Comparison

Given: R(A, B, C, D), F = {A → B, B → C, C → D}

SetClosureSuperkey?Candidate Key?
{A}{A,B,C,D}✓✓ (minimal)
{A, B}{A,B,C,D}✓✗ (A alone suffices)
{A, B, C}{A,B,C,D}✓✗ (A alone suffices)
{B}{B,C,D}✗✗ (not a superkey)
{B, C}{B,C,D}✗✗ (A missing from closure)
Key Finding Strategy

1. Start with the smallest possible set of mandatory attributes (L ∪ N)

2. If X⁺ = R, you're done — that's the only candidate key

3. Otherwise, try adding one B-attribute at a time, then groups of 2, 3, etc.

4. Skip supersets once you find a candidate key

5. Always verify minimality — removing any attribute should break the key property

Important Properties
|Candidate Keys| ≥ 1
Every relation must have at least one candidate key (otherwise it's not well-formed).
R-attribs are NEVER in any candidate key
Attributes that appear only on the RHS of FDs can never be part of a candidate key because they are always determined by others.

Problem 1

Given: R(A, B, C), F = {A → B, B → A, A → C}

Solution:

Problem 4 — Exam Style

Given: R(A, B, C, D, E, F, G), F = {A → B, B → C, C → A, D → E, E → F, F → D, AG → G}

Solution:

Note: AG → G is a trivial FD (RHS is subset of LHS). It provides no information and can be ignored.

AttrCat
AB (A → B, C → A)
BB (B → C, A → B)
CB (C → A, B → C)
DB (D → E, F → D)
EB (E → F, D → E)
FB (F → D, E → F)
GN (appears only in trivial FD)

L = {}, N = {G}, R = {}, B = {A, B, C, D, E, F}

X = {G}. G⁺ = {G} ≠ R.

We need to add attributes from B to cover the two cycles:

Cycle 1 (A-B-C): need at least one of {A,B,C}

Cycle 2 (D-E-F): need at least one of {D,E,F}

Try {A,D,G}: (A,D,G)⁺ = {A,B,C,D,E,F,G} = R → {A,D,G}

Try {A,E,G}: (A,E,G)⁺ = R → {A,E,G}

Try {A,F,G}: (A,F,G)⁺ = R → {A,F,G}

Try {B,D,G}: (B,D,G)⁺ = R → {B,D,G}

And so on... 3 × 3 = 9 candidate keys:

{A,D,G}, {A,E,G}, {A,F,G}, {B,D,G}, {B,E,G}, {B,F,G}, {C,D,G}, {C,E,G}, {C,F,G}

Practice Tips for Exams

✓ Always classify attributes first (L, R, B, N)

✓ Start with mandatory set X = L ∪ N

✓ Check if X⁺ = R — if yes, it's the only key

✓ Add minimal subsets of B to X

✓ Verify minimality by removing each attribute
