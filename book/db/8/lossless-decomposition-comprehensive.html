LOSSLESS DECOMPOSITION & DEPENDENCY PRESERVATION

Database Systems — Chapter 8: Decomposition Properties for Normalization

Lossless Join Decomposition

A decomposition D = {R₁, R₂, ..., Rₙ} of schema R is lossless if for every possible instance r of R:

Lossless Join Property:
r = πR₁(r) ⋈ πR₂(r) ⋈ ... ⋈ πRₙ(r)
The natural join of the projections must exactly reconstruct the original relation — no spurious tuples.
Why Lossless Matters

Without lossless join, a natural join of the decomposed relations would produce spurious tuples — tuples that were not in the original relation. This makes the decomposition invalid for preserving information.

Example: Lossy vs Lossless Decomposition

Original: Employee(EmpID, DeptID, DeptName)

EmpIDDeptIDDeptName
101D1Sales
102D2IT
103D1Sales

Lossy Decomposition: R₁(EmpID, DeptName), R₂(DeptID, DeptName)

R₁: EmpIDDeptName
101Sales
102IT
103Sales
R₂: DeptIDDeptName
D1Sales
D2IT

Join R₁ ⋈ R₂ produces 4 tuples (including spurious: 101-D2, 103-D2) instead of original 3!

Lossless Decomposition: R₁(EmpID, DeptID), R₂(DeptID, DeptName)

Join R₁ ⋈ R₂ produces exactly the original 3 tuples. Lossless!

Binary Decomposition Test (Crucial for Exams)
Decomposition of R into R₁, R₂ is lossless ⟺
(R₁ ∩ R₂) → R₁ OR (R₁ ∩ R₂) → R₂
The common attribute(s) must be a super key in at least one of the decomposed relations.

Sufficient Conditions for Lossless Join

1. Binary decomposition: R₁ ∩ R₂ is a key for R₁ or R₂

2. Chase algorithm: General method for n-ary decompositions

3. FD set implies: If F logically implies the lossless condition, the decomposition is lossless

Dependency Preservation

A decomposition D = {R₁, R₂, ..., Rₙ} is dependency-preserving if the union of the projections of F onto each Rᵢ is equivalent to F:

Dependency Preservation Definition:
(πR₁(F) ∪ πR₂(F) ∪ ... ∪ πRₙ(F))⁺ = F⁺
All FDs from F must be enforceable by checking individual decomposed relations.
Dependency Preservation Intuition

Preserved: If we can verify each FD by looking at a single decomposed relation without needing joins.

Not Preserved: If verifying an FD requires joining two or more decomposed relations together.

Projection of F onto Rᵢ
πRᵢ(F) = { X → Y ∈ F⁺ | XY ⊆ Rᵢ }
The set of FDs that involve only attributes of Rᵢ (and are implied by F).
Key Insight

Computing the full projection πRᵢ(F) is expensive because it requires computing F⁺. Instead, we use a membership test algorithm that checks each FD individually.

Example: Dependency Preservation Test

Given: R(A, B, C), F = {A → B, B → C}

Decomposition: R₁(A, B), R₂(A, C)

Check preservation of A → B:

Is A → B in πR₁(F) or πR₂(F)?

A, B ∈ R₁(A, B) → Yes, A → B is preserved in R₁.

Check preservation of B → C:

Is B → C in πR₁(F) or πR₂(F)?

B, C not both in R₁ and not both in R₂ → Need to check more carefully.

Using membership algorithm: compute B⁺ under πR₁(F) ∪ πR₂(F).

πR₁(F) = {A → B}, πR₂(F) = {} (A → C not in F⁺)

B⁺ = {B} (under {A → B}) → Does not contain C → NOT preserved.

Result: Decomposition {R₁, R₂} is NOT dependency-preserving (B → C is lost).

Dependency Preservation vs. Lossless Join

Lossless Join

Ensures data integrity upon reconstruction

No spurious tuples

Test: R₁ ∩ R₂ is super key in R₁ or R₂

Dependency Preservation

Ensures constraint enforceability

No costly joins for FD checking

Test: Use FD preservation algorithm

Trade-offs

• BCNF decomposition always produces lossless join but may NOT preserve dependencies

• 3NF decomposition always produces both lossless join AND dependency preservation

• Both properties are desirable in a good decomposition

Algorithm: Testing Lossless Join (Chase Algorithm)

Chase Algorithm — Input & Output
Input: R, D = {R₁, R₂, ..., Rₙ}, F
Output: Lossless ✓ or Lossy ✗
Step 1: Construct a table with n rows (one per Rᵢ) and one column per attribute of R.
Step 2: Fill the table: if attribute A ∈ Rᵢ, put aA (labeled subscript); otherwise put bij (i = row, j = attribute).
Step 3: Apply FDs: For each FD X → Y, if two rows agree on all attributes in X, make their Y-values equal. Use FD rules to equate symbols.
Step 4: Repeat until no changes. If any row becomes all a-values, the decomposition is lossless.
Chase Algorithm — Example Walkthrough

Given: R(A, B, C, D, E), D = {R₁(A, D), R₂(A, B), R₃(B, E), R₄(C, D, E)}

FDs: F = {A → BC, B → D, D → E}

Initial Table:

ABCDE
R₁(AD)a₁b₁₂b₁₃a₄b₁₅
R₂(AB)a₁a₂b₂₃b₂₄b₂₅
R₃(BE)b₃₁a₂b₃₃b₃₄a₅
R₄(CDE)b₄₁b₄₂a₃a₄a₅

Apply A → BC:

Rows with same A (a₁): R₁, R₂. Equalize B and C in those rows.

R₁.B = b₁₂ → set equal to R₂.B = a₂. R₁.C = b₁₃ → set equal to R₂.C = b₂₃.

Apply B → D:

Rows with same B (a₂): R₂, R₃. Equalize D.

R₃.D = b₃₄ → set equal to R₂.D = b₂₄.

Apply D → E:

Rows with same D (b₂₄): R₂, R₃ (and R₁ has a₄, R₄ has a₄ — different).

Wait — after applying D → E: need to track...

After full chase: R₂ row becomes (a₁, a₂, a₃, a₄, a₅) → all a-values!

Result: LOSSLESS decomposition.

Simplified Binary Decomposition Test
Lossless(R, R₁, R₂) ⟺ (R₁ ∩ R₂) → R₁ OR (R₁ ∩ R₂) → R₂
The intersection must be a superkey in at least one of the two schemas.

Algorithm: Testing Dependency Preservation

Step 1: For each FD X → Y in F, check if it is preserved.
Step 2: Compute result = X
Step 3: Repeat until result stabilizes:

For each Rᵢ in decomposition:

Compute result = result ∪ ((result ∩ Rᵢ)⁺ ∩ Rᵢ)

This adds attributes from Rᵢ that are functionally determined by attributes of result that fall within Rᵢ.

Step 4: If Y ⊆ result, then X → Y is preserved.
Pseudo-code: Dependency Preservation Test
function isPreserved(F, D): for each X → Y in F: result = X repeat for each Ri in D: T = (result ∩ Ri)⁺ ∩ Ri result = result ∪ T until result stabilizes if Y ⊈ result: return FALSE return TRUE
Dependency Preservation Test — Example

Given: R(A, B, C, D), F = {A → B, B → C, C → D}

Decomposition: R₁(A, B), R₂(A, C, D)

Check A → B:

result = {A}

R₁: result ∩ R₁ = {A}, A⁺ = {A,B,C,D}, (A⁺) ∩ R₁ = {A,B}, result = {A,B}

R₂: result ∩ R₂ = {A}, A⁺ = {A,B,C,D}, (A⁺) ∩ R₂ = {A,C,D}, result = {A,B,C,D}

B ⊆ result → Preserved ✓

Check B → C:

result = {B}

R₁: result ∩ R₁ = {B}, B⁺ = {B,C,D}, (B⁺) ∩ R₁ = {B}, result = {B}

R₂: result ∩ R₂ = {}, (result ∩ R₂)⁺ = ∅, result = {B}

result stabilizes at {B}, C ⊈ {B} → NOT preserved ✗

Result: Decomposition does NOT preserve B → C.

3NF Synthesis Algorithm (Using Canonical Cover)

Step 1: Compute canonical cover Fc of F.
Step 2: For each FD X → Y in Fc, create relation schema Rᵢ(X ∪ Y).
Step 3: If none of the Rᵢ contains a candidate key of R, add a relation with a candidate key.
Step 4: Remove redundant relations (if Rᵢ ⊆ Rⱼ, remove Rᵢ).
The 3NF synthesis algorithm guarantees both lossless join and dependency preservation.

Comprehensive Examples

Example 1: Binary Decomposition — Lossless + Dependency Preservation

Given: R(A, B, C), F = {A → B, B → C}

Decomposition: R₁(A, B), R₂(B, C)

Lossless Test (Binary):

R₁ ∩ R₂ = {B}

B⁺ = {B, C}. Is B → R₂? B → B, C. R₂ = (B, C). Yes, B → B, C holds.

Lossless ✓ (B is a superkey of R₂)

Dependency Preservation:

A → B: πR₁(F) contains A → B ✓

B → C: πR₂(F) contains B → C ✓

Dependency Preserving ✓

Example 2: Binary Decomposition — Lossless but NOT Dependency Preserving

Given: R(A, B, C), F = {A → B, B → C}

Decomposition: R₁(A, B), R₂(A, C)

Lossless Test:

R₁ ∩ R₂ = {A}

A⁺ = {A, B, C}. Is A → R₁? A → A, B. Yes.

Lossless ✓

Dependency Preservation:

A → B: πR₁(F) contains A → B ✓

B → C: B and C are never in the same relation → Check using algorithm.

result = {B}. R₁: (B ∩ R₁)⁺ = B⁺ = {B,C}. (B⁺) ∩ R₁ = {B}. result = {B}.

R₂: (B ∩ R₂)⁺ = ∅⁺ = ∅. result = {B}.

Stabilizes at {B}. C ⊈ {B}.

NOT Dependency Preserving ✗

Example 3: Full Chase Algorithm

Given: R(A, B, C, D), F = {A → B, BC → D}

Decomposition: R₁(A, B, C), R₂(A, C, D)

Binary Test:

R₁ ∩ R₂ = {A, C}

Is (A,C) a superkey in R₁? (A,C)⁺ = {A,B,C,D}. Contains R₁ = {A,B,C}? Yes!

Lossless ✓

Chase Table:

ABCD
R₁(ABC)a₁a₂a₃b₁₄
R₂(ACD)a₁b₂₂a₃a₄

Apply A → B:

Rows with same A (a₁): both rows. Equalize B: b₂₂ = a₂.

Apply BC → D:

Both rows have same B (a₂) and same C (a₃). Equalize D: b₁₄ = a₄.

R₁ row = (a₁, a₂, a₃, a₄) — all a-values! Lossless ✓

Example 4: Lossy Decomposition

Given: R(A, B, C), F = {A → B}

Decomposition: R₁(A, C), R₂(B, C)

Binary Test:

R₁ ∩ R₂ = {C}

C⁺ = {C} (no FD determines anything from C).

Is C → R₁ (A,C)? No. Is C → R₂ (B,C)? No.

Lossy ✗

Why it's lossy:

Consider instance: R = {(a₁, b₁, c₁), (a₂, b₂, c₁)}

πR₁ = {(a₁, c₁), (a₂, c₁)}, πR₂ = {(b₁, c₁), (b₂, c₁)}

Join = {(a₁, b₁, c₁), (a₁, b₂, c₁), (a₂, b₁, c₁), (a₂, b₂, c₁)} — 4 tuples!

Two spurious tuples: (a₁, b₂, c₁) and (a₂, b₁, c₁) were not in the original.

Example 5: 3NF Synthesis

Given: R(A, B, C, D, E), F = {A → BC, B → D, C → E}

Step 1: Canonical Cover

Fc = {A → B, A → C, B → D, C → E}

Step 2: Create Relations

A → B, A → C → R₁(A, B, C)

B → D → R₂(B, D)

C → E → R₃(C, E)

Step 3: Check Candidate Key

Is {A} a candidate key? A⁺ = {A,B,C,D,E} = R. Yes.

The relation R₁ contains A. No extra relation needed.

Step 4: Remove Redundancy

No relation is a subset of another.

Result: D = {R₁(A,B,C), R₂(B,D), R₃(C,E)}

Lossless ✓ (A is key of R₁, and A is in R₁)

Dep. Preserving ✓ (each FD maps to a relation)

Example 6: Preservation Test — Detailed Walkthrough

Given: R(A, B, C, D), F = {AB → C, C → A, BC → D}

Decomposition: R₁(A, C, D), R₂(B, C, D)

Check AB → C:

result = {A, B}

R₁: result ∩ R₁ = {A}, A⁺ = {A,C} (using C → A? No, compute: A⁺ = {A}C using C → A... actually A⁺ = {A} with available FDs). Compute properly:

Under full F = {AB → C, C → A, BC → D}: A⁺ = {A}, B⁺ = {B}.

Using πR₁ ∪ πR₂: We need to compute this carefully.

πR₁(F): Which FDs have all attrs in {A,C,D}?

C → A: {C,A} ⊆ {A,C,D} → included.

So πR₁ = {C → A}. Are there others? AB → C has B not in R₁. BC → D has B not in R₁.

πR₂(F): Which FDs have all attrs in {B,C,D}?

BC → D: {B,C,D} ⊆ {B,C,D} → included.

So πR₂ = {BC → D}.

G = πR₁ ∪ πR₂ = {C → A, BC → D}

Compute (AB)⁺ under G: {A, B}
Using C → A: need C first, not in result.
Using BC → D: need C, not in result.
(AB)⁺ = {A, B}. Does not contain C.

AB → C is NOT preserved ✗
