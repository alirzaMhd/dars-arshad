CANDIDATE KEYS & SUPERKEYS

Database Systems — Chapter 8: Key Concepts in Relational Database Design

Key Definitions

Key Hierarchy

Superkey superset Candidate Key superset Primary Key

Every candidate key is a superkey, but NOT every superkey is a candidate key.

Every primary key is a candidate key (the one chosen for the role).

Superkey:
K subset R is a superkey iff for all t1, t2 in r: t1[K] = t2[K] implies t1 = t2
A set of attributes that uniquely identifies a tuple. May contain extra attributes.
Candidate Key:
K subset R is a candidate key iff K is a superkey AND for all A in K, (K - {A}) is NOT a superkey
A minimal superkey — no proper subset is also a superkey.
Primary Key:
The candidate key chosen by the database designer as the main identifier.
Has constraints: NOT NULL + UNIQUE.

Key Constraints

Every relation must have at least one candidate key

A relation can have multiple candidate keys

Only one primary key per relation

Primary key cannot contain NULL values

Primary key values must be unique

Prime vs Non-prime Attributes

Definitions:
Prime attribute: A is prime iff A in some candidate key
Non-prime attribute: A is non-prime iff A not in any candidate key
Prime attributes are part of at least one candidate key. Non-prime attributes are in no candidate key.
Prime vs Non-prime Example

The classification of prime vs non-prime is critical for 2NF and 3NF definitions.

Normalization and Prime/Non-prime

1NF: All attributes are atomic (no relation to keys)

2NF: No non-prime attribute is partially dependent on any candidate key

3NF: No non-prime attribute is transitively dependent on any candidate key

BCNF: Every non-trivial FD X to Y must have X as a superkey

Superkey vs. Candidate Key

Superkey

Uniquely identifies tuples

May have redundant attributes

Every superset of a superkey is also a superkey

A relation can have many superkeys

Candidate Key

Minimal superkey

No redundant attributes

No proper subset is a superkey

A relation may have several candidate keys

Counting Superkeys (General Formula)
If K is the only candidate key and |K| = k, |R| = n:
Number of superkeys = 2^(n-k)
Every superset of K is a superkey. There are n-k attributes outside K, each either present or absent.
Counting Superkeys Example

For R with 4 attributes and single CK {A}:

Superkeys: {A}, {A,B}, {A,C}, {A,D}, {A,B,C}, {A,B,D}, {A,C,D}, {A,B,C,D}

Total: 2^(4-1) = 2^3 = 8 superkeys

Candidate Keys: Just {A} (only 1)

Exam Tip: Superkey Counting with Multiple CKs

For multiple candidate keys, use inclusion-exclusion principle to count superkeys (avoid double-counting supersets that contain multiple candidate keys).

Finding Candidate Keys Using FDs

Step 1: Attribute Classification

Classify each attribute into one of four categories based on the FD set:

CategorySymbolIn Every CK?
Left-only (only on LHS)LYES mandatory
Right-only (only on RHS)RNO never in CK
Both (LHS and RHS)BMaybe test subsets
Neither (no FD)NYES mandatory
Step 2: Start with Mandatory Set

Let X = L U N. Compute X+ using F.

If X+ = R then X is the only candidate key. Done.

Step 3: Add from Both-Side Attributes

For each subset S subset of B (start with size 1, then 2, etc.):

Compute (X U S)+

If (X U S)+ = R, then X U S is a superkey

Check minimality: verify no proper subset is also a superkey

Skip supersets of any already-found candidate key

Systematic Search Strategy
1. Classify attributes to L, R, B, N 2. mandatory = L U N 3. if mandatory+ == R then {mandatory} is the only CK 4. else: for size = 1 to |B|: for each subset S of B with |S| = size: if S contains a known CK: skip test = mandatory U S if test+ == R then test is a candidate key mark all supersets of test as covered

Given: R(A, B, C, D, E), F = {A to BC, CD to E, B to D, E to A}

Rules of Thumb

Attributes that are never on the RHS of any FD MUST be in every candidate key

Attributes that are never on the LHS of any FD CANNOT be in any candidate key

A candidate key with k attributes means no (k-1)-subset covers R

Always check minimality — it's the defining property of candidate keys

Example 1: Simple Candidate Key Identification

Given: R(EmpID, SSN, Name, Dept, Salary)

FDs: EmpID to Name,Dept,Salary; SSN to EmpID; SSN to Name,Dept,Salary

Classification:

EmpIDBLHS in EmpID to ..., RHS in SSN to EmpID
SSNLOnly on LHS of FDs

L = {SSN}, R = {Name,Dept,Salary}, B = {EmpID}, N = {}

Mandatory = {SSN}. SSN+ = {SSN,EmpID,Name,Dept,Salary} = R. Only CK: {SSN}

But wait — EmpID+ = {EmpID,Name,Dept,Salary} without SSN! EmpID is also a candidate key.

Let's reclassify: EmpID appears on both LHS and RHS, so B. EmpID+ = {EmpID,Name,Dept,Salary} not = R (no SSN).

SSN+ = {SSN,EmpID,Name,Dept,Salary} = R. CK: {SSN}

{EmpID,SSN}: superkey but superset of {SSN}.

Example 3: All-Key Relation

Given: R(A, B, C, D), F = {AB to CD, CD to AB}

Classification:

All attributes appear on both LHS and RHS. L = {}, N = {}, R = {}, B = {A,B,C,D}

Mandatory = {}. empty+ = {} not = R.

Size 1: A+ = {A} not = R. B+ = {B} not = R. C+ = {C} not = R. D+ = {D} not = R.

Size 2: {A,B}+ = {A,B,C,D} = R => CK {A,B}

{C,D}+ = {C,D,A,B} = R => CK {C,D}

{A,C}+ = {A,C} not = R. {A,D}+ = {A,D} not = R. {B,C}+ = {B,C} not = R. {B,D}+ = {B,D} not = R.

Candidate Keys: {A,B}, {C,D}

All four attributes are prime attributes since they belong to at least one candidate key.

Example 4: Superkey Counting Exercise

Given: R(A, B, C, D, E) with candidate keys {A,B} and {C,D}

Find all superkeys:

Any set containing {A,B} OR {C,D} (or both).

Method: Inclusion-Exclusion

Superkeys containing {A,B}: must include A and B. E can be absent/present.

Remaining attributes: C, D, E. 2^3 = 8 superkeys.

Superkeys containing {C,D}: must include C and D. E can be absent/present.

Remaining attributes: A, B, E. 2^3 = 8 superkeys.

Superkeys containing BOTH {A,B} AND {C,D}: must include A,B,C,D.

Remaining: E only. 2^1 = 2 superkeys.

Total:

|Superkeys| = 8 + 8 - 2 = 14

Total possible subsets of 5 attributes = 2^5 = 32. So 14 out of 32 are superkeys.
