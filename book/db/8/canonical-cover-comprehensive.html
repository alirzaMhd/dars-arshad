CANONICAL COVER (MINIMAL COVER)

Database Systems — Chapter 8: Functional Dependencies — Canonical Cover Fc

What is a Canonical Cover?

A canonical cover (also called minimal cover) of a set of functional dependencies F is a minimal set of functional dependencies Fc that is equivalent to F. That is, Fc⁺ = F⁺.

Definition:
Fc is a canonical cover of F ⟺ Fc⁺ = F⁺
Both sets have the same closure — they imply the same set of FDs.

Properties of a Canonical Cover Fc

1. Every FD in Fc has a single attribute on the right-hand side (RHS is singleton)

2. No FD in Fc has extraneous attributes on the left-hand side

3. No FD in Fc is redundant — removing it changes the closure

4. It is the smallest set of FDs equivalent to F

Intuitive Understanding

Think of a canonical cover as the "simplest form" of your functional dependency set. Just like simplifying a mathematical expression (e.g., 2x + 3x → 5x), a canonical cover eliminates redundancies and rewrites FDs in their most compact form.

If F = {A → BC, A → B, B → C}, then the canonical cover would simplify this to Fc = {A → B, B → C}.

Why Canonical Cover Matters

• Reduces the number of FDs checked during database design

• Eliminates redundancy before normalization

• Essential for BCNF and 3NF decomposition algorithms

• Simplifies dependency analysis and key computation

Key Terminology

FD Equivalence

Two FD sets F and G are equivalent if F⁺ = G⁺

They produce the same closures.

Extraneous Attribute

An attribute in an FD that can be removed without changing the closure of the FD set.

Redundant FD

An FD that can be inferred from the remaining FDs in the set.

Minimality

The smallest number of FDs needed to represent the same closure.

Canonical Cover Algorithm

The algorithm for computing Fc consists of three main steps:

Algorithm: Compute Canonical Cover Fc
Fc = F
REPEAT until no more changes
(1) Union: Merge FDs with same LHS
(2) Eliminate extraneous attributes from LHS
(3) Eliminate redundant FDs
Step 1: Union Rule (Merge Same LHS)

Replace all FDs of the form X → Y and X → Z with X → YZ

This combines FDs that share the same left-hand side.

Step 2: Remove Extraneous Attributes from LHS

For each FD X → Y and each attribute A ∈ X:

Check if A is extraneous in X:

• Compute (X − {A})⁺ using F

• If (X − {A})⁺ contains Y, then A is extraneous — remove it

Step 3: Remove Redundant FDs

For each FD f ∈ F:

• Remove f from F temporarily: F' = F − {f}

• Compute X⁺ using F' (without f)

• If X⁺ contains Y, then f is redundant — remove it permanently

Important Ordering Note

Steps 2 and 3 must be applied iteratively. Removing an extraneous attribute or a redundant FD may create new redundancies. The algorithm loops until no further changes occur.

Pseudo-code
Fc = F repeat // Step 1: Union for each X, combine all X → Y into X → Y₁Y₂...Yₙ // Step 2: Remove extraneous LHS attributes for each X → Y in Fc: for each A in X: compute (X−A)⁺ using Fc if Y ⊆ (X−A)⁺ then remove A from X // Step 3: Remove redundant FDs for each f: X → Y in Fc: remove f from Fc temporarily compute X⁺ using remaining Fc if Y ⊆ X⁺ then permanently remove f until no changes occur
Testing Extraneous Attributes — Formal Definition

An attribute A is extraneous in X → Y if:

CASE 1: A ∈ X (LHS): Let γ = X − {A}. If γ⁺ (using F) contains Y, then A is extraneous.

CASE 2: A ∈ Y (RHS): This is handled by ensuring RHS is singleton; extraneous attributes on RHS are typically removed by simplifying the FD.

Worked Examples

Example 1: Simple Canonical Cover

Given: F = {A → BC, B → C, A → B, AB → C}

Step 1: Union Rule

F = {A → BC, A → B, B → C, AB → C}

Combine A → BC and A → B → A → BC (BC already includes B)

After union: F = {A → BC, B → C, AB → C}

Step 2: Remove Extraneous Attributes

Check AB → C: Is A extraneous in AB?

Compute B⁺ = {B, C} → B⁺ contains C? YES. So A is extraneous in AB → C.

Remove A: AB → C becomes B → C

After step 2: F = {A → BC, B → C}

Step 3: Remove Redundant FDs

Check A → BC: Remove it. Compute A⁺ using {B → C} → A⁺ = {A}. Does A⁺ contain BC? NO. Keep A → BC.

Check B → C: Remove it. Compute B⁺ using {A → BC} → B⁺ = {B}. Does B⁺ contain C? NO. Keep B → C.

Result:

Fc = {A → BC, B → C}

Can also decompose RHS: Fc = {A → B, A → C, B → C}

Example 2: Complex Extraneous Attribute Removal

Given: F = {AB → CD, A → B, B → C, AC → D}

Step 1: Union

No FDs share the same LHS. F remains the same.

F = {AB → CD, A → B, B → C, AC → D}

Step 2: Extraneous Attributes (LHS)

Check AB → CD: Is A extraneous?

Compute B⁺ = {B, C} (using B → C). Does B⁺ contain CD? NO. Keep A.

Is B extraneous?

Compute A⁺ = {A, B, C, D} (using A → B, B → C, AC → D). Does A⁺ contain CD? YES.

So B is extraneous in AB → CD. Remove B: A → CD

Check AC → D: Is A extraneous?

Compute C⁺ = {C}. Does C⁺ contain D? NO. Keep A.

Is C extraneous?

Compute A⁺ = {A, B, C, D} (using A → B, B → C, A → CD). Does A⁺ contain D? YES.

So C is extraneous in AC → D. Remove C: A → D (but we already have A → CD)

After step 2: F = {A → CD, A → B, B → C, A → D}

Step 1 again: Union

Merge A → CD, A → B, A → D → A → BCD

F = {A → BCD, B → C}

Step 3: Remove Redundant FDs

Check A → BCD: Remove. Compute A⁺ using {B → C} → A⁺ = {A}. Does it contain BCD? NO. Keep.

Check B → C: Remove. Compute B⁺ using {A → BCD} → B⁺ = {B}. Does it contain C? NO. Keep.

Result:

Fc = {A → BCD, B → C}

Example 3: Redundant FD Elimination

Given: F = {A → B, B → C, A → C}

Step 1: Union

No same LHS. F = {A → B, B → C, A → C}

Step 2: Extraneous Attributes

All LHS are single attributes → no extraneous attributes possible.

Step 3: Remove Redundant FDs

Check A → B: Remove. Compute A⁺ using {B → C, A → C} → A⁺ = {A, C}. Does A⁺ contain B? NO. Keep.

Check B → C: Remove. Compute B⁺ using {A → B, A → C} → B⁺ = {B}. Does B⁺ contain C? NO. Keep.

Check A → C: Remove. Compute A⁺ using {A → B, B → C} → A⁺ = {A, B, C}. Does A⁺ contain C? YES. Remove A → C.

Result:

Fc = {A → B, B → C}

A → C is redundant because it can be derived from A → B and B → C (transitivity).

Example 4: Comprehensive — Full Algorithm Walkthrough

Given: F = {ABC → DE, AB → D, BC → E, A → B, B → C}

Round 1 — Step 1: Union

No same LHS. F = {ABC → DE, AB → D, BC → E, A → B, B → C}

Round 1 — Step 2: Extraneous Attributes

Check ABC → DE: Is A extraneous?

Compute (BC)⁺ = {B, C, E} (using B → C, BC → E). Does it contain DE? NO. Keep A.

Is B extraneous?

Compute (AC)⁺ = {A, C, B, D, E} (using A → B, B → C, AB → D). Does it contain DE? YES. Remove B → ABC → DE becomes AC → DE

Is C extraneous?

Compute (AB)⁺ = {A, B, C, D, E} (using A → B, B → C, AB → D, BC → E). Does it contain DE? YES. Remove C → AC → DE becomes A → DE

Check AB → D: Is A extraneous?

Compute B⁺ = {B, C, E}. Does it contain D? NO. Keep A.

Is B extraneous?

Compute A⁺ = {A, B, C, D, E} (using A → B, B → C, A → DE). Does it contain D? YES. Remove B → AB → D becomes A → D

Check BC → E: Is B extraneous?

Compute C⁺ = {C}. Does it contain E? NO. Keep B.

Is C extraneous?

Compute B⁺ = {B, C}. Does it contain E? NO. Keep C.

Round 1 — Step 3: Remove Redundant FDs

F = {A → DE, A → D, BC → E, A → B, B → C}. Apply union first:

Union A → DE, A → D, A → B → A → BDE

F = {A → BDE, BC → E, B → C}

Check A → BDE: Remove. A⁺ using {BC → E, B → C} = {A}. Does it contain BDE? NO. Keep.

Check BC → E: Remove. (BC)⁺ using {A → BDE, B → C} = {B, C, D, E, A}. Contains E? YES. Remove BC → E.

Check B → C: Remove. B⁺ using {A → BDE} = {B}. Contains C? NO. Keep.

Result:

Fc = {A → BDE, B → C}

Final canonical cover has only 2 FDs from original 5.

Properties of Canonical Cover

Essential Properties

✓ Equivalence: Fc⁺ = F⁺ (same closure)

✓ Singleton RHS: Every FD in Fc has exactly one attribute on the right

✓ No Extraneous LHS: No attribute can be removed from any left-hand side without changing the closure

✓ No Redundant FDs: No FD can be removed from Fc without changing the closure

Uniqueness Note
Fc is NOT unique
A given set F may have multiple canonical covers depending on the order of processing extraneous attributes and redundant FDs.
Non-Uniqueness Example

Given: F = {AB → C, A → B, B → C}

Two possible canonical covers:

Cover 1: {A → B, B → C} (if we check AB → C first and remove A)

Cover 2: {A → C, A → B} (if we first remove B from AB → C then union)

Both are valid canonical covers with the same closure.

Relationship to Normalization

3NF Decomposition

The canonical cover Fc is used directly in the 3NF synthesis algorithm. Each FD in Fc becomes a relation schema.

BCNF Decomposition

While BCNF uses a different algorithm, having a canonical cover helps reduce the number of violations to check.

Key Discovery

A canonical cover simplifies the process of computing candidate keys by eliminating redundant dependencies.

Dependency Preservation

Fc helps verify whether a decomposition preserves dependencies efficiently.

Common Mistakes

• Forgetting to re-apply union after removing extraneous attributes — the set must be re-merged after each change

• Checking redundant FDs before extraneous attributes — extraneous attributes must be removed first

• Assuming Fc is unique — different processing orders can yield different minimal covers

• Not using the updated set — when computing closures for extraneous attribute checks, always use the current version of Fc
