What is the Closure of an FD Set?

The closure of a set F of functional dependencies, denoted F+, is the set of all functional dependencies that are logically implied by F.

Formal Definition
F+ = { X rarr; Y | F ⊨ X rarr; Y }
The set of all FDs that hold in every relation instance satisfying F.

In other words, F+ contains every FD that can be derived from F using Armstrong's Axioms.

Key Insight

Important Relationship
F+ is usually much larger than F
The closure of F typically contains many more FDs than F itself.
Example

F = { A rarr; B, B rarr; C }

F+ contains at least: A rarr; A, B rarr; B, C rarr; C, A rarr; B, B rarr; C, A rarr; C, A rarr; BC, AB rarr; A, AB rarr; B, AB rarr; C, AB rarr; BC, AB rarr; ABC, ...

The number of FDs in F+ can be exponential in |R|.

Understanding F+

F+ can be thought of as the transitive closure of the FD set under Armstrong's inference rules.

F+ Generation
F+ = { X rarr; Y | Y ⊆ X+(w.r.t. F) }
For every possible X ⊆ R, compute X+. Then every subset Y of X+ gives an FD X rarr; Y in F+.
The total number of FDs in F+ is exponential in |R|.

Properties of F+

F ⊆ F+

Inclusion

Every FD in the original set is trivially implied

(F+)+ = F+

Idempotence

Applying closure twice yields the same result

F ⊆ G ⇒ F+ ⊆ G+

Monotonicity

Larger FD sets have larger closures

F+ = G+ ⟺ F ≡ G

Equivalence

Two FD sets are equivalent if they have the same closure

Equivalence of FD Sets

Two sets of functional dependencies F and G are equivalent (denoted F ≡ G) if they imply exactly the same set of FDs.

Equivalence Condition
F ≡ G ⟺ F+ = G+
F and G are equivalent iff every FD in F is implied by G and vice versa.

To check equivalence without computing F+ and G+ explicitly, we use the membership test:

  • For each FD X rarr; Y in F, check if it is in G+ (i.e., Y ⊆ X+ under G)
  • For each FD X rarr; Y in G, check if it is in F+ (i.e., Y ⊆ X+ under F)

Algorithm: Checking Equivalence

Algorithm: CheckEquivalence(F, G)

1. For each FD X rarr; Y in F:

    Compute X+ using G (not F!)

    If Y ⊈ X+, return FALSE

2. For each FD X rarr; Y in G:

    Compute X+ using F (not G!)

    If Y ⊈ X+, return FALSE

3. Return TRUE

It is critical to compute X+ using the OTHER set, not the same one. This checks cross-implication.

Example 1: Equivalent FD Sets

F = { A rarr; BC, B rarr; C, A rarr; B }   G = { A rarr; BC, B rarr; C }

Check if F ≡ G:

Step 1 — Check F in G:

  • A rarr; BC: A+ under G = A → A→BC → ABC. BC ⊆ ABC. OK
  • B rarr; C: B+ under G = B → B→C → BC. C ⊆ BC. OK
  • A rarr; B: A+ under G = A → A→BC → ABC. B ⊆ ABC. OK

Step 2 — Check G in F:

  • A rarr; BC: A+ under F = A → A→BC → ABC. BC ⊆ ABC. OK
  • B rarr; C: B+ under F = B → B→C → BC. C ⊆ BC. OK

F ≡ G. The FD A rarr; B is redundant in F (it is implied by G).

Example 2: Non-Equivalent FD Sets

F = { A rarr; B, B rarr; C }   G = { A rarr; C, B rarr; C }

Check if F ≡ G:

Step 1 — F in G:

  • A rarr; B: Compute A+ under G. A + = {A} → A→C → {A,C}. Stop. B ∉ A+. FAIL!

F is NOT equivalent to G. G does not imply A rarr; B.

Counterexample: A=1, B=x, C=p and A=2, B=x, C=p. This satisfies G but not F.

Example 3: Complex Equivalence Check

F = { AB rarr; C, A rarr; B, B rarr; C }   G = { AB rarr; C, A rarr; B }

Check F ≡ G

Step 1 — F in G:

  • AB rarr; C: (AB)+ under G = {A,B} (A→B gives B, but no B→C). So C ∉ (AB)+. FAIL!

F is NOT equivalent to G. The FD B rarr; C in F is essential for deriving AB rarr; C.

Example 4: Redundant FDs Detection

F = { A rarr; B, B rarr; C, A rarr; C }

Is A rarr; C redundant (implied by the other FDs)?

Let F' = F minus {A rarr; C} = { A rarr; B, B rarr; C }

Compute A+ under F': A → A→B → AB → B→C → ABC. C ⊆ ABC. YES

A rarr; C is redundant. F is equivalent to {A rarr; B, B rarr; C}.

Example 5: Finding Minimal Cover

F = { A rarr; BC, AB rarr; C, B rarr; C, C rarr; A }

Step 1 — Decompose RHS: A → B, A → C, AB → C, B → C, C → A

Step 2 — Check redundancy:

  • A rarr; B: Remove A→B. A+ = {A} → A→C → AC → C→A → AC. B ∉ A+. Keep.
  • A rarr; C: Remove A→C. A+ = {A} → A→B → AB. C ∉ A+. Keep.
  • AB rarr; C: Remove AB→C. (AB)+ = {A,B} → A→B, A→C → ABC. C ⊆ ABC. REDUNDANT. Remove.
  • B rarr; C: Remove B→C. B+ = {B}. C ∉ B+. Keep.
  • C rarr; A: Remove C→A. C+ = {C}. A ∉ C+. Keep.

Step 3 — Minimize LHS: All LHS are singletons. Already minimal.

Minimal Cover = { A → B, A → C, B → C, C → A }

Since computing the full F+ is exponential, we use attribute closure as the building block for all practical tasks.

Algorithm 1: FD Membership Test

Algorithm: IsImplied(F, X rarr; Y)

1. Compute X+ using F and the closure algorithm

2. If Y ⊆ X+, return TRUE

3. Else return FALSE

Example

F = { A rarr; B, AB rarr; C, C rarr; D }

Is A rarr; D implied?

A+ = {A} → A→B → {A,B} → AB→C → {A,B,C} → C→D → {A,B,C,D}

D ⊆ A+. YES, A rarr; D ∈ F+.

Algorithm 2: Checking Equivalence

Algorithm: IsEquivalent(F, G)

1. For each FD X rarr; Y in F:

   Compute X+ using G. If Y ⊈ X+, return FALSE.

2. For each FD X rarr; Y in G:

   Compute X+ using F. If Y ⊈ X+, return FALSE.

3. Return TRUE

Example: F = { A rarr; BC, B rarr; C } and G = { A rarr; B, B rarr; C, A rarr; C }

F in G: A→BC: A+(G) = {A,B,C}. BC OK. B→C: B+(G) = {B,C}. C OK.

G in F: A→B: A+(F) = {A,B,C}. B OK. B→C: B+(F) = {B,C}. C OK. A→C: A+(F) = ABC. C OK.

F ≡ G

Algorithm 3: Computing Minimal Cover

A minimal cover of F is a set G such that:

  • G is equivalent to F (G+ = F+)
  • Every FD in G has a single attribute on the RHS
  • No FD in G can be removed without changing G+
  • No attribute can be removed from LHS of any FD in G without changing G+

Algorithm: MinimalCover(F)

1. Decompose RHS: Replace X rarr; YZ with X rarr; Y, X rarr; Z

2. Remove redundant FDs: For each FD f, check if implied by F minus {f}

3. Minimize LHS: For each FD X rarr; Y, check if any attribute in X can be removed

4. Return the resulting set

Step order matters! Decompose first, then remove redundant FDs, then minimize LHS.

Example: Computing Minimal Cover

F = { AB rarr; CD, A rarr; B, B rarr; C, AC rarr; D }

Step 1 — Decompose RHS: AB→C, AB→D, A→B, B→C, AC→D

Step 2 — Remove redundant FDs:

  • AB→C: (AB)+ without it: {A,B} → A→B (done), B→C → ABC. C ⊆ result. REMOVE.
  • AB→D: (AB)+ without it: {A,B} → A→B, B→C → ABC. D ∉ result. KEEP.
  • A→B: A+ without it: {A}. B ∉ result. KEEP.
  • B→C: B+ without it: {B}. C ∉ result. KEEP.
  • AC→D: (AC)+ without it: {A,C} → A→B → ABC. D ∉ result. KEEP.

After Step 2: AB→D, A→B, B→C, AC→D

Step 3 — Minimize LHS:

  • AB→D: Remove A? B+ = {B,C}. D ∉ B+. Keep A. Remove B? A+ = {A,B,C}. D ∉ A+. Keep B.
  • AC→D: Remove A? C+ = {C}. D ∉ C+. Keep A. Remove C? A+ = {A,B,C}. D ∉ A+. Keep C.

Minimal Cover = { AB→D, A→B, B→C, AC→D }

Algorithm 4: Projecting FDs onto a Subschema

Given a relation R with FDs F, and a decomposition of R into R1, R2, ..., we need to find which FDs hold in each subschema Ri.

Algorithm: ProjectFDs(F, Ri)

1. Initialize result = empty set

2. For each subset X of attributes in Ri:

   Compute X+ using F

   For each attribute A in (Ri intersect X+):

     Add X rarr; A to result

3. Compute minimal cover of result

4. Return the minimal cover

This algorithm is exponential in |Ri|, but Ri is usually small in practice.

Decompose into R1(A, B, C) and R2(C, D). Find FDs for R1.
