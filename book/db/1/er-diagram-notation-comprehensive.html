Entity Types & Symbols

An entity is a distinguishable object in the real world with its own set of properties. In ER diagrams, entities are represented using rectangular boxes.

Strong Entity

Student

Rectangle — single border, solid lines

Has its own primary key. Can exist independently.

Weak Entity

Dependent

Double Rectangle — two borders

No primary key of its own. Depends on an owner entity for identification.

Strong vs Weak Entity:
Strong: Has its own PK | Weak: Partial key + owner PK
Example: PERSON (strong) vs DEPENDENT (weak, owned by PERSON)

Attribute Types & Symbols

Attributes describe the properties of entities. Each type of attribute has a distinct oval notation in ER diagrams.

Simple Attribute

Age

Single Oval — single border, solid

Cannot be divided further (atomic value).

Key Attribute

SSN

Single Oval + Underlined Text

Uniquely identifies each entity instance.

Multi-valued Attribute

Phones

Double Oval — two borders

Can hold multiple values for one entity (e.g., multiple phone numbers).

Derived Attribute

Age

Dashed Oval — dashed border

Value computed from other attributes (e.g., Age derived from DOB).

Composite Attribute

Address
Street
City
Zip

Oval connected to sub-ovals

Can be divided into smaller sub-parts.

Attribute Notation Rules:
Oval = Simple | Underlined = Key | Double = Multi-valued | Dashed = Derived
Key attribute uniquely identifies an entity. Derived attribute is calculated, not stored.

Relationship Symbols

Relationships describe how entities interact. They are represented as diamonds connected to the participating entities.

Regular Relationship

Enroll

Single Diamond — single border

Standard association between entities.

Identifying Relationship

Has

Double Diamond — two borders

Connects weak entity to its owner entity.

Common Notation Mistakes

Mistake 1: Confusing Entity and Relationship Shapes

Entities are ALWAYS rectangles. Relationships are ALWAYS diamonds. Never swap them.

Mistake 2: Forgetting Total Participation

If every entity instance must participate in a relationship, use a double line. Forgetting this loses important constraint information.

Mistake 3: Mixing Up (min,max) Notation

(1,1) on both sides = one-to-one. (1,1) : (0,N) = one-to-many. (0,N) : (0,N) = many-to-many. Don't confuse min with max.

Mistake 4: Weak Entity Without Identifying Relationship

A weak entity MUST be connected to its owner entity through a double diamond (identifying relationship).

Mistake 5: Multi-valued Attributes in Relational Model

Multi-valued attributes become a separate table in the relational schema with a foreign key. Do NOT store arrays in a column.

Step-by-Step Guide to Drawing ER Diagrams

1
Identify Entities: Read the problem statement. Find all nouns that represent real-world objects (e.g., Student, Course, Employee).
2
Identify Attributes: For each entity, list its properties. Determine which are key (unique), multi-valued, derived, or composite.
3
Identify Relationships: Find verbs connecting entities. Draw diamond for each relationship. Determine cardinality (1:1, 1:N, M:N).
4
Check for Weak Entities: Does any entity depend on another for identification? If so, use double rectangle and double diamond.
5
Add Participation Constraints: For each relationship, check if participation is total (double line) or partial (single line).
6
Verify Completeness: Check every entity has a key attribute. Verify all relationships have correct cardinality. Ensure all constraints are shown.

ER to Relational Schema Mapping

Mapping Rules:
Entity → Table | Relationship → Table or FK | Multi-valued → Separate Table
Strong entity becomes a table with its attributes. Relationships become tables (for M:N) or foreign keys (for 1:N). Weak entities include owner's PK.
