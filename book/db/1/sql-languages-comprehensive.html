SQL Implementation Languages

DDL, DML, DCL — Complete Guide for Exam Preparation

SQL Command Categories

Database implementation uses 3 types of SQL commands to interact with the database system.

DDL
Data Definition Language

Define/modify structure
CREATE, DROP, ALTER

DML
Data Manipulation Language

Manipulate data
INSERT, SELECT, UPDATE, DELETE

DCL
Data Control Language

Control access
GRANT, REVOKE

SQL Command Summary

Category Full Name Purpose Commands Affects
DDL Data Definition Language Structure creation/modification CREATE, DROP, ALTER Schema
DML Data Manipulation Language Content modification INSERT, SELECT, UPDATE, DELETE Data
DCL Data Control Language Security/access control GRANT, REVOKE Permissions

DSL Formula

Data Sub-Language (DSL)
DSL = DDL + DML + DCL
DSL is also called Query Language (QL). It is the complete set of SQL commands used to interact with a database.
Alternative Name
DSL = QL (Query Language)
Both terms refer to the same thing: the complete language used to define, manipulate, and control a database.

Example 1: Complete Database Setup

All Three Categories Working Together
-- DDL: Create the structure CREATE TABLE Suppliers ( S# CHAR(5) PRIMARY KEY, Sname CHAR(20), City CHAR(15), Status INT ); -- DML: Add and query data INSERT INTO Suppliers VALUES ('S1', 'Smith', 'London', 20); INSERT INTO Suppliers VALUES ('S2', 'Jones', 'Paris', 10); INSERT INTO Suppliers VALUES ('S3', 'Blake', 'Paris', 30); SELECT * FROM Suppliers WHERE City = 'Paris'; UPDATE Suppliers SET Status = 25 WHERE S# = 'S2'; DELETE FROM Suppliers WHERE S# = 'S3'; -- DCL: Control access GRANT SELECT ON Suppliers TO user1; GRANT ALL ON Suppliers TO admin1; REVOKE DELETE ON Suppliers FROM user1;

All three categories work together to build and maintain a database.

Example 3: Category Impact

What Each Category Changes
DDL Changes Schema: CREATE TABLE → New table exists ALTER TABLE → Table structure changed DROP TABLE → Table removed DML Changes Data: INSERT → New rows added UPDATE → Existing rows modified DELETE → Rows removed SELECT → Data read (no change) DCL Changes Permissions: GRANT → User gains access REVOKE → User loses access
⚠ DDL affects ALL users. DML affects only the specific data. DCL affects specific users.

Example 4: Transaction Example

Bank Transfer Using All Categories
-- DDL (already done) CREATE TABLE Accounts ( AccountID INT PRIMARY KEY, Balance DECIMAL(10,2) ); -- DML: Transfer $100 from Account 1 to Account 2 BEGIN TRANSACTION; UPDATE Accounts SET Balance = Balance - 100 WHERE AccountID = 1; UPDATE Accounts SET Balance = Balance + 100 WHERE AccountID = 2; COMMIT; -- DCL (already set up) GRANT SELECT ON Accounts TO bank_teller; GRANT UPDATE ON Accounts TO bank_manager;
DML handles the actual data changes in a transaction.

Data Definition Language (DDL)

DDL is used for structure creation and modification. It defines the container that holds data.

DDL Purpose
DDL = Define/Modify Database Structure
Creates tables, modifies schema, defines constraints. Affects the database schema, not data.

DDL Commands

Command Purpose Syntax
CREATE TABLE Create new table CREATE TABLE name (columns...);
ALTER TABLE Modify table structure ALTER TABLE name ADD/DROP column;
DROP TABLE Delete table completely DROP TABLE name;
CREATE INDEX Create index for speed CREATE INDEX name ON table(column);

Example 1: CREATE TABLE

Creating Tables with Constraints
-- Basic table creation CREATE TABLE Suppliers ( S# CHAR(5) PRIMARY KEY, Sname CHAR(20) NOT NULL, City CHAR(15), Status INT DEFAULT 0 ); -- Table with multiple constraints CREATE TABLE Orders ( OrderID INT PRIMARY KEY AUTO_INCREMENT, CustomerID INT NOT NULL, OrderDate DATE DEFAULT CURRENT_DATE, TotalAmount DECIMAL(10,2) CHECK (TotalAmount > 0), Status VARCHAR(20) IN ('Pending', 'Shipped', 'Delivered'), FOREIGN KEY (CustomerID) REFERENCES Customers(CustomerID) ); -- Table with composite primary key CREATE TABLE OrderItems ( OrderID INT, ProductID INT, Quantity INT NOT NULL, Price DECIMAL(10,2), PRIMARY KEY (OrderID, ProductID), FOREIGN KEY (OrderID) REFERENCES Orders(OrderID), FOREIGN KEY (ProductID) REFERENCES Products(ProductID) );

PRIMARY KEY, NOT NULL, DEFAULT, CHECK, FOREIGN KEY are all constraints defined in DDL.

Example 2: ALTER TABLE

Modifying Table Structure
-- Add a new column ALTER TABLE Suppliers ADD COLUMN Phone VARCHAR(15); -- Drop a column ALTER TABLE Suppliers DROP COLUMN Phone; -- Modify column data type ALTER TABLE Suppliers MODIFY COLUMN Sname VARCHAR(50); -- Add constraint ALTER TABLE Suppliers ADD CONSTRAINT chk_status CHECK (Status >= 0 AND Status <= 100); -- Drop constraint ALTER TABLE Suppliers DROP CONSTRAINT chk_status; -- Rename table ALTER TABLE Suppliers RENAME TO Vendors;

Example 3: DROP TABLE

Removing Tables
-- Simple drop DROP TABLE Suppliers; -- Drop if exists (avoids error) DROP TABLE IF EXISTS Suppliers; -- Cascade drop (removes dependent objects) DROP TABLE Suppliers CASCADE; ⚠ Warning: DROP TABLE permanently removes: - Table structure - All data in the table - All indexes on the table - All constraints - All views referencing the table This is IRREVERSIBLE without backup!
⚠ Always backup data before DROP TABLE. There is no UNDO for this command!

Example 4: CREATE INDEX

Creating Indexes for Performance
-- Single column index CREATE INDEX idx_city ON Suppliers(City); -- Unique index (enforces uniqueness) CREATE UNIQUE INDEX idx_sname ON Suppliers(Sname); -- Composite index (multiple columns) CREATE INDEX idx_city_status ON Suppliers(City, Status); -- Drop index DROP INDEX idx_city ON Suppliers; Benefits of Indexes: ✓ Faster SELECT queries ✓ Enforces uniqueness (UNIQUE index) ✓ Improves JOIN performance Costs of Indexes: ✗ Slower INSERT/UPDATE/DELETE ✗ Uses additional disk space ✗ Requires maintenance

Example 5: DDL Complete Example

University Database DDL
-- Create database CREATE DATABASE University; -- Use database USE University; -- Create Students table CREATE TABLE Students ( StudentID INT PRIMARY KEY AUTO_INCREMENT, FirstName VARCHAR(30) NOT NULL, LastName VARCHAR(30) NOT NULL, Email VARCHAR(100) UNIQUE, EnrollmentDate DATE DEFAULT CURRENT_DATE ); -- Create Courses table CREATE TABLE Courses ( CourseCode VARCHAR(10) PRIMARY KEY, CourseName VARCHAR(50) NOT NULL, Credits INT CHECK (Credits > 0 AND Credits <= 6) ); -- Create Enrollments table CREATE TABLE Enrollments ( StudentID INT, CourseCode VARCHAR(10), Semester VARCHAR(10), Grade CHAR(2), PRIMARY KEY (StudentID, CourseCode, Semester), FOREIGN KEY (StudentID) REFERENCES Students(StudentID), FOREIGN KEY (CourseCode) REFERENCES Courses(CourseCode) ); -- Add index for faster queries CREATE INDEX idx_student_name ON Students(LastName, FirstName);

Data Manipulation Language (DML)

DML is used for content modification of tables. It manipulates the actual data stored in the database.

DML Purpose
DML = Read/Write Data in Tables
INSERT adds data, SELECT reads data, UPDATE modifies data, DELETE removes data.

DML Commands

Command Purpose Returns
SELECT Query/read data Result set
INSERT Add new rows Rows affected
UPDATE Modify existing rows Rows affected
DELETE Remove rows Rows affected

Example 1: SELECT Queries

Reading Data from Tables
-- Simple select SELECT * FROM Suppliers; -- Select specific columns SELECT Sname, City FROM Suppliers; -- Select with condition (WHERE) SELECT * FROM Suppliers WHERE City = 'London'; -- Select with multiple conditions SELECT * FROM Suppliers WHERE City = 'Paris' AND Status > 15; -- Select with ORDER BY SELECT * FROM Suppliers ORDER BY Sname; -- Select with LIMIT SELECT * FROM Suppliers LIMIT 10; -- Select with alias SELECT Sname AS Name, City AS Location FROM Suppliers; -- Aggregate functions SELECT City, COUNT(*) AS NumSuppliers, AVG(Status) AS AvgStatus FROM Suppliers GROUP BY City HAVING COUNT(*) > 1;

Example 2: INSERT Data

Adding New Records
-- Insert single row (all columns) INSERT INTO Suppliers VALUES ('S1', 'Smith', 'London', 20); -- Insert with column specification INSERT INTO Suppliers (S#, Sname, City) VALUES ('S2', 'Jones', 'Paris'); -- Insert multiple rows INSERT INTO Suppliers VALUES ('S3', 'Blake', 'Paris', 30), ('S4', 'Clark', 'London', 20), ('S5', 'Adams', 'Athens', 30); -- Insert from another table INSERT INTO SupplierBackup SELECT * FROM Suppliers WHERE City = 'London'; -- Insert with subquery INSERT INTO Archive (S#, Sname) SELECT S#, Sname FROM Suppliers WHERE Status < 15;

Example 3: UPDATE Data

Modifying Existing Records
-- Update single column UPDATE Suppliers SET City = 'Rome' WHERE S# = 'S1'; -- Update multiple columns UPDATE Suppliers SET City = 'Rome', Status = 25 WHERE S# = 'S1'; -- Update all rows (⚠ dangerous!) UPDATE Suppliers SET Status = 0; -- Update with calculation UPDATE Suppliers SET Status = Status + 5 WHERE City = 'London'; -- Update with subquery UPDATE Suppliers SET Status = (SELECT AVG(Status) FROM Suppliers) WHERE City = 'Paris'; ⚠ Warning: Without WHERE clause, UPDATE affects ALL rows!
⚠ Always test UPDATE with a SELECT first to verify which rows will be affected!

Example 4: DELETE Data

Removing Records
-- Delete specific row DELETE FROM Suppliers WHERE S# = 'S5'; -- Delete with condition DELETE FROM Suppliers WHERE City = 'Athens' AND Status < 20; -- Delete all rows (⚠ dangerous!) DELETE FROM Suppliers; -- Delete with subquery DELETE FROM Suppliers WHERE S# IN (SELECT S# FROM Shipments WHERE Qty < 100); -- Delete with JOIN DELETE s FROM Suppliers s JOIN Shipments sh ON s.S# = sh.S# WHERE sh.Qty = 0; ⚠ Warning: DELETE without WHERE removes ALL rows! ⚠ Warning: DELETE cannot be undone without transaction log!
⚠ TRUNCATE TABLE is faster than DELETE for removing all rows, but cannot be rolled back in some DBMS.

Example 5: DML in Application

Real-World DML Usage
-- E-commerce application queries -- Product search SELECT ProductName, Price, Stock FROM Products WHERE Category = 'Electronics' AND Price BETWEEN 100 AND 500 ORDER BY Price; -- Add to cart (insert) INSERT INTO Cart (UserID, ProductID, Quantity) VALUES (101, 505, 2); -- Update cart quantity UPDATE Cart SET Quantity = 3 WHERE UserID = 101 AND ProductID = 505; -- Remove from cart DELETE FROM Cart WHERE UserID = 101 AND ProductID = 505; -- Checkout (move cart to orders) INSERT INTO Orders (UserID, OrderDate, Total) SELECT UserID, CURRENT_DATE, SUM(Price * Quantity) FROM Cart c JOIN Products p ON c.ProductID = p.ProductID WHERE UserID = 101 GROUP BY UserID;

Data Control Language (DCL)

DCL is used for security and access control. It determines who can access what data.

DCL Purpose
DCL = Grant/Revoke Access Permissions
Controls who can read, modify, or administer database objects.

DCL Commands

Command Purpose Effect
GRANT Give permissions User gains access
REVOKE Remove permissions User loses access

Example 1: Basic GRANT

Granting Permissions
-- Grant SELECT permission GRANT SELECT ON Suppliers TO user1; -- Grant multiple permissions GRANT SELECT, INSERT, UPDATE ON Suppliers TO user1; -- Grant all permissions GRANT ALL ON Suppliers TO admin1; -- Grant to multiple users GRANT SELECT ON Suppliers TO user1, user2, user3; -- Grant with column-level permission GRANT SELECT (Sname, City) ON Suppliers TO user1; -- user1 can only see Sname and City, not Status or S# -- Grant with GRANT OPTION (user can grant to others) GRANT SELECT ON Suppliers TO user1 WITH GRANT OPTION;

Example 2: REVOKE Permissions

Removing Permissions
-- Revoke specific permission REVOKE DELETE ON Suppliers FROM user1; -- Revoke all permissions REVOKE ALL ON Suppliers FROM user1; -- Revoke from multiple users REVOKE SELECT ON Suppliers FROM user1, user2; -- Revoke GRANT OPTION REVOKE GRANT OPTION ON Suppliers FROM user1; -- Revoke CASCADE (removes permissions granted by user) REVOKE SELECT ON Suppliers FROM user1 CASCADE;

Example 3: Permission Matrix

Typical Permission Setup
Table Admin Manager Employee Guest
Employees ALL SELECT, UPDATE SELECT (own) None
Salaries ALL SELECT None None
Projects ALL ALL SELECT SELECT (public)
-- Implementation GRANT ALL ON Employees TO 'admin'; GRANT SELECT, UPDATE ON Employees TO 'manager'; GRANT SELECT ON Employees TO 'employee';

Example 4: Role-Based Security

Using Roles for Permission Management
-- Create roles CREATE ROLE 'read_only'; CREATE ROLE 'read_write'; CREATE ROLE 'full_access'; -- Grant permissions to roles GRANT SELECT ON *.* TO 'read_only'; GRANT SELECT, INSERT, UPDATE, DELETE ON *.* TO 'read_write'; GRANT ALL PRIVILEGES ON *.* TO 'full_access'; -- Assign roles to users GRANT 'read_only' TO 'guest_user'@'localhost'; GRANT 'read_write' TO 'app_user'@'localhost'; GRANT 'full_access' TO 'admin_user'@'localhost'; -- Remove role from user REVOKE 'read_write' FROM 'app_user'@'localhost';
Roles simplify permission management — assign permissions to role, then assign role to users.

Example 5: Security Best Practices

DCL Security Guidelines
Principle of Least Privilege

Give users only the minimum permissions they need to do their job

Use Roles

Group permissions into roles, assign roles to users

Regular Audits

Review permissions periodically, remove unused access

⚠ Never grant ALL privileges to end users. Always use GRANT with specific permissions.

DSL / QL (Data Sub-Language / Query Language)

The union of DDL + DML + DCL = DSL, also called QL (Query Language).

DSL Composition
DSL = DDL + DML + DCL
DSL is the complete SQL language. QL is an alternative name for DSL.

Two Types of Data Languages

Embedded/Nested
Must be hosted in 3GL

SQL embedded in Visual Basic, C#, Java
Requires host language

Standalone
No host language needed

Access, FoxPro, SQL*Plus
Runs independently

Example 1: Embedded SQL

SQL in Visual Basic (3GL Host)
' Visual Basic with Embedded SQL ' Connection string Dim conn As New SqlConnection( "Server=myServer;Database=myDB;User Id=user;Password=pass;" ) ' Open connection conn.Open() ' Embedded SELECT query Dim cmd As New SqlCommand( "SELECT Sname, City FROM Suppliers WHERE Status > 20", conn ) ' Execute and read results Dim reader As SqlDataReader = cmd.ExecuteReader() While reader.Read() Console.WriteLine(reader("Sname") & " - " & reader("City")) End While ' Embedded INSERT query Dim insertCmd As New SqlCommand( "INSERT INTO Suppliers (S#, Sname, City) VALUES (@s, @name, @city)", conn ) insertCmd.Parameters.AddWithValue("@s", "S6") insertCmd.Parameters.AddWithValue("@name", "New Supplier") insertCmd.Parameters.AddWithValue("@city", "New York") insertCmd.ExecuteNonQuery() conn.Close()
SQL is "embedded" within the Visual Basic code — this is Embedded/Nested DML.

Example 2: Standalone SQL

SQL in Access/FoxPro
-- Standalone SQL (no host language needed) -- Microsoft Access query SELECT Suppliers.Sname, Suppliers.City, Shipments.Qty FROM Suppliers INNER JOIN Shipments ON Suppliers.S# = Shipments.S# WHERE Shipments.Qty > 100; -- FoxPro query SELECT * FROM Suppliers WHERE City = 'London'; -- SQL*Plus (Oracle standalone) SELECT Sname, City, Status FROM Suppliers WHERE Status = (SELECT MAX(Status) FROM Suppliers); Standalone features: ✓ No programming language needed ✓ Direct database interaction ✓ Quick queries and reports ✓ End-user friendly
