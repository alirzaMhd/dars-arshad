Data Analysis Model

ER Model & Relational Calculus — Complete Guide

Analysis Model Components

The analysis model (also called conceptual design or conceptual view) models the real world in human-understandable terms. It has two main components:

1. Entity Analysis

• Uses ER Model (Entity-Relationship)

• Identifies entities and relationships

• Performed by DA (Data Administrator)

2. Query Analysis

• Uses Relational Calculus

• Defines queries mathematically

• Two types: Tuple and Domain

Key Concept:
Analysis Model = ER Model (Entities) + Relational Calculus (Queries)
The analysis model is model-independent and abstract, focusing on WHAT data exists and WHAT questions to ask.
Important: The analysis model is written in human language (conceptual), while the design model maps to machine language (implementation).

Entity-Relationship (ER) Model

The ER Model identifies entities, their attributes, and relationships in the operational environment.

Key Concepts

Entity

• A real-world object or concept

• Example: Supplier, Part, Student

• Represented as rectangles in ERD

Attribute

• Properties of an entity

• Example: S#, Sname, City

• Represented as ovals in ERD

Relationship

• Association between entities

• Example: Supplier supplies Part

• Represented as diamonds in ERD

Example: Parts/Suppliers ER Model

Entities identified:

• Supplier (S): S#, Sname, City

• Part (P): P#, Pname, Color

• Shipment (SP): S#, P#, QTY (relationship between S and P)

Note: The ER Model is covered in detail in the ER Model chapter of the textbook.

Relational Calculus

Relational calculus is a formal query language that defines what data to retrieve without specifying how. It has two types:

Tuple Relational Calculus

• Variables range over tuples (rows)

• Uses tuple variables

• Example: {t | t ∈ S ∧ t[City] = 'C2'}

Domain Relational Calculus

• Variables range over domains (columns)

• Uses domain variables

• Example: { | ∃s ( ∈ S ∧ city = 'C2')}

Tuple Relational Calculus Syntax:
{t | Condition(t)}
Read as: "The set of all tuples t such that condition(t) is true"
Common Operators:
∈ ( belongs to ), ∧ ( AND ), ∨ ( OR ), ¬ ( NOT ), ∃ ( exists ), ∀ ( for all )
These logical operators are used to build conditions in relational calculus.

Worked Examples

Example 1: Find names of suppliers in city C2
Tuple RC: {t | t ∈ S ∧ t[City] = 'C2'}
Result: {Sn2, Sn3}

Select all tuples from Supplier relation where City attribute equals 'C2'.

Example 2: Find part numbers supplied by supplier S1
Tuple RC: {t | t ∈ SP ∧ t[S#] = 'S1'}
Result: {P1, P2}

Select all tuples from Shipment relation where S# equals 'S1'.

Example 3: Find suppliers who supply part P1
Tuple RC: {t | t ∈ SP ∧ t[P#] = 'P1'}
Result: {S1, S2}

Select all tuples from Shipment relation where P# equals 'P1'.

Example 4: Find names of suppliers who supply red parts
Tuple RC: {t | t ∈ S ∧ ∃p (p ∈ P ∧ p[Color] = 'Red' ∧ ∃sp (sp ∈ SP ∧ sp[S#] = t[S#] ∧ sp[P#] = p[P#]))}
This requires joining S, P, and SP tables.

This query uses nested existential quantifiers to join three tables.

Example 5: Domain Relational Calculus version
Find suppliers in city C2:
{sname | ∃snum,city (snum,sname,city ∈ S ∧ city = 'C2')}
Result: {Sn2, Sn3}

Domain RC uses column names instead of tuple variables.
