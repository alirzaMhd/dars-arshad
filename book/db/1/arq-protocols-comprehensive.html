ARQ Protocols

Computer Networks — Complete Guide for Exam Preparation

ARQ Overview

Automatic Repeat reQuest (ARQ) is an error-control method for data transmission that uses acknowledgments and timeouts to achieve reliable data transmission. When the sender doesn't receive an acknowledgment within a timeout period, it retransmits the frame.

ARQ Principle:
Send → Wait for ACK → Timeout? Retransmit → Success? Send next
ARQ combines error detection (CRC) with retransmission for reliable delivery.

ARQ Types

Stop & Wait ARQ

• Simplest form

• Send one frame at a time

• Low efficiency

Go-Back-N ARQ

• Multiple frames in flight

• Rejects all after error

• Moderate efficiency

Selective Repeat ARQ

• Multiple frames in flight

• Rejects only erroneous frame

• Highest efficiency

Key Concept: All ARQ protocols require sequence numbers to detect duplicates and reordered frames. The sequence number space determines the maximum window size.

Stop & Wait ARQ

Stop & Wait ARQ is the simplest ARQ protocol. The sender transmits one frame and waits for an acknowledgment before sending the next frame. If no ACK is received within the timeout period, the frame is retransmitted.

Stop & Wait Operation:
Send frame 0 → Wait ACK → Send frame 1 → Wait ACK → ...
Sequence numbers alternate between 0 and 1 (1-bit sequence number).

Protocol Steps

Sender: 1. Send frame with sequence number (SN) 2. Start timer 3. Wait for ACK 4. If ACK received with correct SN → Send next frame 5. If timeout → Retransmit current frame 6. If ACK with wrong SN → Ignore Receiver: 1. Receive frame 2. Check CRC 3. If OK → Send ACK with SN, deliver to upper layer 4. If error → Discard frame (no ACK sent)
Example 1: Normal Operation

Show Stop & Wait operation for 3 frames without errors.

Answer:

Sender: Frame0 → Receiver: ACK0

Sender: Frame1 → Receiver: ACK1

Sender: Frame2 → Receiver: ACK0

(Sequence numbers alternate: 0, 1, 0, 1, ...)

Example 2: Timeout Scenario

Show Stop & Wait operation when Frame1 is lost.

Answer:

Sender: Frame0 → Receiver: ACK0 ✓

Sender: Frame1 → (Lost!) → Timeout

Sender: Frame1 (retransmit) → Receiver: ACK1 ✓

Sender: Frame2 → Receiver: ACK0 ✓

Efficiency Formula:
η = T_frame / (T_frame + 2 × T_prop)
T_frame = transmission time, T_prop = propagation delay
Example 3: Efficiency Calculation

Frame size = 1000 bits, Bandwidth = 1 Mbps, Propagation delay = 1 ms. Calculate efficiency.

Answer:

T_frame = 1000 / 1,000,000 = 1 ms

T_prop = 1 ms

η = 1 / (1 + 2×1) = 1/3 = 33.3%

Problem: Stop & Wait is very inefficient on high-bandwidth, long-distance links because the sender is idle most of the time waiting for ACKs.

Go-Back-N ARQ

Go-Back-N ARQ allows multiple frames to be in transit simultaneously. When an error is detected, the receiver rejects all frames starting from the erroneous one, and the sender must retransmit all frames from that point.

Go-Back-N Operation:
Window size W ≤ 2^n - 1 (n = sequence number bits)
Sender can transmit W frames before waiting for ACK.

Protocol Behavior

Sender: 1. Maintain send window (SN_min to SN_min + W - 1) 2. Send all frames in window 3. If ACK received → Advance window 4. If timeout for frame k → Retransmit frames k, k+1, ..., k+W-1 Receiver: 1. Accept frames in order 2. If frame in order → Send ACK, deliver to upper layer 3. If frame out of order → Reject (send ACK for last correct frame) 4. Duplicate frames are discarded
Example 4: Go-Back-N Operation

Window size = 4. Show operation when Frame 2 is corrupted.

Answer:

Sender: F0, F1, F2, F3 (all in window)

Receiver: ACK0, ACK1, (F2 corrupted → reject), (F3 rejected)

Sender: Timeout for F2 → Retransmit F2, F3, F4, F5

Example 5: Window Size Calculation

If sequence numbers use 3 bits, what is the maximum window size?

Answer:

W ≤ 2^3 - 1 = 8 - 1 = 7

Example 6: Efficiency

Calculate efficiency for Go-Back-N with window size 7, frame time 1 ms, propagation 1 ms.

Answer:

η = W × T_frame / (T_frame + 2 × T_prop)

η = 7 × 1 / (1 + 2) = 7/3 = 233% (limited to 100%)

Since 233% > 100%, efficiency = 100% (link fully utilized)

Drawback: Go-Back-N retransmits all frames after an error, even if some were received correctly. This wastes bandwidth on links with high error rates.

Selective Repeat ARQ

Selective Repeat ARQ is the most efficient ARQ protocol. It retransmits only the erroneous frames, not all frames after the error. The receiver buffers out-of-order frames until the missing frame arrives.

Selective Repeat Operation:
Window size W ≤ 2^(n-1) (n = sequence number bits)
Stricter window size requirement to avoid ambiguity.

Protocol Behavior

Sender: 1. Maintain send window 2. Send all frames in window 3. If ACK received → Mark frame as acknowledged 4. If timeout for frame k → Retransmit ONLY frame k Receiver: 1. Accept any frame within receive window 2. Buffer out-of-order frames 3. Send ACK for each correctly received frame 4. Deliver frames to upper layer in order
Example 7: Selective Repeat Operation

Window size = 4. Show operation when Frame 2 is corrupted.

Answer:

Sender: F0, F1, F2, F3 (all in window)

Receiver: ACK0, ACK1, (F2 corrupted → discard), ACK3 (F3 buffered)

Sender: Timeout for F2 → Retransmit ONLY F2

Receiver: F2 arrives → Deliver F2, F3 in order

Example 8: Window Size Limit

If sequence numbers use 3 bits, what is the maximum window size for Selective Repeat?

Answer:

W ≤ 2^(3-1) = 2^2 = 4

(Compare to Go-Back-N: W ≤ 7)

Example 9: Efficiency Calculation

Calculate efficiency for Selective Repeat with W=4, frame time 1 ms, propagation 1 ms.

Answer:

η = W × T_frame / (T_frame + 2 × T_prop)

η = 4 × 1 / (1 + 2) = 4/3 = 133% (limited to 100%)

Example 10: Buffer Requirement

What is the receiver buffer requirement for Selective Repeat vs Go-Back-N?

Answer:

Go-Back-N: 1 frame (rejects out-of-order)

Selective Repeat: W frames (buffers out-of-order)

Example 11: Protocol Selection

Choose the best ARQ protocol for: (a) Simple link, (b) Satellite, (c) High-speed LAN

Answer:

(a) Stop & Wait (simple, low cost)

(b) Selective Repeat (high bandwidth-delay product)

(c) Go-Back-N (low error rate, simple receiver)

Key Trade-off: Selective Repeat is most efficient but requires more receiver buffering and complex implementation. Go-Back-N is simpler but wastes bandwidth on retransmissions. Stop & Wait is simplest but least efficient.

Timing & Formulas

Total Delay Formula

Total Delay (Stop & Wait):
T_total = T_frame + 2×T_prop + T_ACK + 2×T_process
T_frame = frame transmission time, T_prop = propagation delay, T_ACK = ACK transmission time, T_process = processing time

ACK Time Calculation

ACK Transmission Time:
T_ACK = L_ACK / R
L_ACK = ACK frame length (bits), R = link bandwidth (bps)

Round Trip Time (RTT)

RTT Definition:
RTT = 2 × T_prop + T_process
Time from sending frame until receiving ACK (excluding transmission time)
Example: Total Delay Calculation

Frame = 1000 bits, ACK = 100 bits, Bandwidth = 1 Mbps, Propagation = 5 ms, Processing = 1 ms. Calculate total delay.

Answer:

T_frame = 1000 / 1,000,000 = 1 ms

T_ACK = 100 / 1,000,000 = 0.1 ms

T_prop = 5 ms

T_process = 1 ms

T_total = 1 + 2×5 + 0.1 + 2×1 = 13.1 ms

Timer Management

Timeout Value

• Must be ≥ RTT

• Too short: unnecessary retransmissions

• Too long: slow error recovery

Timer Types

• Retransmission timer

• ACK timer

• Idle timer

Sequence Number Wrapping

Sequence Number Space:
Numbers wrap around: 0, 1, 2, ..., 2^n - 1, 0, 1, 2, ...
Window must not exceed half the sequence space to avoid ambiguity.
IDLE ARQ: Another name for Stop & Wait ARQ. The sender is "idle" while waiting for ACK.
Selective Reject: Another name for Selective Repeat ARQ. The receiver rejects (NACKs) only the erroneous frame.
