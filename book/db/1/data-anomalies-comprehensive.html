Data Anomalies — Insertion, Update, Deletion

Database Systems — Complete Guide for Exam Preparation

What are Data Anomalies?

Data anomalies are problems that arise from improper data redundancy in unnormalized databases. They cause data inconsistency, waste, and integrity issues.

Root Cause
Anomalies = f(Redundancy)
Anomalies exist because of natural data redundancy in unnormalized tables.

Three Types of Anomalies

1. Insertion Anomaly

Cannot insert data without other data

Need unrelated data to add a record

2. Update Anomaly

Must update in multiple places

Data becomes inconsistent if not all copies updated

3. Deletion Anomaly

Deleting one record loses other data

Unintentional data loss occurs

The Solution: Normalization

Normalization
Decompose → Eliminate Redundancy → Remove Anomalies
Split unnormalized tables into smaller, related tables to eliminate natural redundancy and anomalies.
Anomalies can only exist if there is natural redundancy. If you normalize properly, anomalies are eliminated.

Insertion Anomaly — Definition

An insertion anomaly occurs when you cannot insert data about one entity without also providing data about another unrelated entity.

Problem
Cannot add Entity A without Entity B
The table design forces you to include unrelated data to insert a record.

Example 1: Cannot Add College Without Student

Unnormalized Table: studclg
StudentID Name CollegeName CollegeCode
101 Ahmed Computer 12
102 Sara Engineering 15

Problem: If a new college "Medicine" (code 20) is created but has no students yet, we cannot insert it because StudentID (primary key) cannot be NULL.

We are forced to wait until a student enrolls before we can record the college.

Example 2: Cannot Add Instructor Without Course

Unnormalized Table: course_inst
CourseID CourseName InstructorName InstructorOffice
CS101 Intro CS Dr. Lee Room 101
CS102 DB Dr. Kim Room 205

Problem: A newly hired instructor "Dr. Patel" cannot be added until they are assigned a course.

Instructor data depends on course data — this is the insertion anomaly.

Example 3: Cannot Add Department Without Employee

Unnormalized Table: emp_dept
EmpID EmpName DeptName DeptBudget
E1 Ali HR 50000
E2 Fatima IT 80000

Problem: A new department "Marketing" (budget 60000) cannot be created until at least one employee is assigned to it.

Example 4: Cannot Add Product Without Sale

Unnormalized Table: sale_product
SaleID Date ProductName Price
S1 2024-01-15 Laptop 1000
S2 2024-01-16 Phone 500

Problem: A new product "Tablet" (price 300) cannot be added to the catalog until someone purchases it.

Example 5: Cannot Add City Without Customer

Unnormalized Table: cust_city
CustomerID Name City Country
C1 John New York USA
C2 Ali Dubai UAE

Problem: A new city "London" in "UK" cannot be stored until a customer from that city is registered.

Update Anomaly — Definition

An update anomaly occurs when the same data value must be updated in multiple places. If any copy is missed, the data becomes inconsistent.

Problem
Update in 1 place ≠ Update in all places
If you forget to update one copy, the database has inconsistent data.

Example 1: College Code Change

Unnormalized Table: studclg
StudentID Name CollegeName CollegeCode
101 Ahmed Computer 12
102 Sara Computer 12
103 Ali Computer 12

Problem: If College Code changes from 12 to 120, you must update ALL rows for Computer students. Missing one row creates inconsistency.

After partial update: Row 101 has code 120, but row 102 still has 12 — inconsistent!

Example 2: Instructor Office Change

Unnormalized Table: course_inst
CourseID CourseName Instructor Office
CS101 Intro CS Dr. Lee Room 101
CS102 DB Dr. Lee Room 101
CS103 Networks Dr. Lee Room 101

Problem: Dr. Lee moves to Room 305. You must update ALL rows where Dr. Lee appears.

Example 3: Department Budget Change

Unnormalized Table: emp_dept
EmpID Name Dept Budget
E1 Ali IT 80000
E2 Sara IT 80000
E3 Fatima IT 80000

Problem: IT budget increases to 100000. All 3 rows must be updated. If E3's row is missed, budget shows 80000 for that employee.

Example 4: Product Price Change

Unnormalized Table: order_product
OrderID Date Product Price
O1 2024-01 Laptop 1000
O2 2024-02 Laptop 1000
O3 2024-03 Laptop 1000

Problem: Laptop price changes to 1200. All historical orders must also be updated — but should they? This creates logical inconsistency.

Historical data should remain unchanged. This anomaly shows why price should be separate from orders.

Example 5: City Name Change

Unnormalized Table: cust_city
CustomerID Name City Country
C1 John Bombay India
C2 Priya Bombay India

Problem: "Bombay" was renamed to "Mumbai". All customer rows with "Bombay" must be updated to "Mumbai".

Deletion Anomaly — Definition

A deletion anomaly occurs when deleting one record unintentionally causes the loss of other unrelated data.

Problem
Delete Entity A → Lose Entity B
Removing one piece of data causes unintended loss of other data.

Example 1: Deleting Last Student Loses College Info

Unnormalized Table: studclg
StudentID Name CollegeName CollegeCode
101 Ahmed Computer 12
102 Sara Engineering 15

Problem: If we delete student Sara (the only Engineering student), we also lose all information about the Engineering college.

College data (name, code) is stored only in student rows. Deleting the student deletes the college.

Example 2: Deleting Course Loses Instructor Info

Unnormalized Table: course_inst
CourseID CourseName Instructor Office
CS101 Intro CS Dr. Lee Room 101
CS102 DB Dr. Kim Room 205

Problem: If CS101 is cancelled (deleted), we also lose Dr. Lee's information (name, office).

Example 3: Deleting Employee Loses Department Data

Unnormalized Table: emp_dept
EmpID Name DeptName DeptBudget
E1 Ali HR 50000
E2 Sara IT 80000

Problem: If employee Ali (the only HR employee) is deleted, the HR department information (name, budget) is also lost.

Example 4: Deleting Sale Loses Product Info

Unnormalized Table: sale_product
SaleID Date Product Price
S1 2024-01 Laptop 1000
S2 2024-02 Phone 500

Problem: If sale S1 is deleted, the Laptop product information is also removed from the system.

Example 5: Deleting Customer Loses City Data

Unnormalized Table: cust_city
CustomerID Name City Country
C1 John New York USA
C2 Ali Dubai UAE

Problem: If customer Ali (the only customer from Dubai) is deleted, the city information "Dubai, UAE" is also lost from the system.

All Three Anomalies in One Table

Complete Example: studclg Table
StudentID StudentName CollegeName CollegeCode
101 Ahmed Computer 12
102 Sara Computer 12
103 Ali Engineering 15

Insertion Anomaly: Cannot add college "Medicine" (code 20) without a student.

Update Anomaly: Changing College Code 12→120 requires updating rows 101 and 102.

Deletion Anomaly: Deleting student Ali (103) loses all Engineering college information.

Normalized Solution

After Normalization

Table 1: Students

StudentID StudentName CollegeID (FK)
101 Ahmed 12
102 Sara 12
103 Ali 15

Table 2: Colleges

CollegeID CollegeName
12 Computer
15 Engineering
20 Medicine

Anomalies Resolved:

  • Insertion: Can now add Medicine college without a student
  • Update: College Code change only needs one update in Colleges table
  • Deletion: Deleting a student does not affect college data
