Database Schema

Definition and Types — Complete Guide for Exam Preparation

What is a Schema?

A schema (also called "structure" or "template") is the collection of designed structures in a database. It is independent of actual data stored.

Schema Definition
Schema = Blueprint of Database Structure
Defines tables, columns, data types, relationships — but NOT the actual data.

Key Characteristics

Structure

Defines tables, columns, data types

Independent

Does not depend on actual data

Design Phase

Created during database design

Rare Changes

Schema changes are infrequent

Schema vs Instance

Aspect Schema Instance
Definition Blueprint/structure Actual data at a moment
Changes Rarely Frequently
When Created Design phase When data is inserted
Example Table with 4 columns 100 rows of data
Analogy Cookie cutter shape Actual cookies made

Schema = Everything defined in CREATE TABLE statements.

Schema Definition

A schema is the collection of designed structures in a database, created during the design phase.

Schema Creation
Schema = CREATE TABLE + Constraints + Relationships
Schema is defined using DDL commands, primarily CREATE TABLE.

Schema Elements

Tables

Named collections of related data

Columns

Attributes with specific data types

Data Types

CHAR, INT, VARCHAR, DATE, etc.

Constraints

PRIMARY KEY, FOREIGN KEY, NOT NULL

Example 1: Complete Schema

University Database Schema
-- SCHEMA DEFINITION -- Students table schema CREATE TABLE Students ( StudentID INT PRIMARY KEY AUTO_INCREMENT, FirstName VARCHAR(30) NOT NULL, LastName VARCHAR(30) NOT NULL, Email VARCHAR(100) UNIQUE, DateOfBirth DATE, EnrollmentDate DATE DEFAULT CURRENT_DATE ); -- Courses table schema CREATE TABLE Courses ( CourseCode VARCHAR(10) PRIMARY KEY, CourseName VARCHAR(50) NOT NULL, Credits INT CHECK (Credits > 0 AND Credits <= 6), Department VARCHAR(30) ); -- Enrollments table schema CREATE TABLE Enrollments ( StudentID INT, CourseCode VARCHAR(10), Semester VARCHAR(10) NOT NULL, Grade CHAR(2), PRIMARY KEY (StudentID, CourseCode, Semester), FOREIGN KEY (StudentID) REFERENCES Students(StudentID), FOREIGN KEY (CourseCode) REFERENCES Courses(CourseCode) ); Schema includes: ✓ 3 table definitions ✓ Column names and data types ✓ PRIMARY KEY constraints ✓ FOREIGN KEY relationships ✓ CHECK constraints ✓ NOT NULL constraints ✓ DEFAULT values

Example 2: Schema with Relationships

Suppliers-Parts Database Schema
-- Three tables with relationships CREATE TABLE Suppliers ( S# CHAR(5) PRIMARY KEY, Sname CHAR(20) NOT NULL, City CHAR(15), Status INT CHECK (Status >= 0 AND Status <= 100) ); CREATE TABLE Parts ( P# CHAR(5) PRIMARY KEY, Pname CHAR(20) NOT NULL, Color CHAR(10), Weight DECIMAL(5,1) CHECK (Weight > 0), City CHAR(15) ); CREATE TABLE Shipments ( S# CHAR(5), P# CHAR(5), Qty INT CHECK (Qty > 0), Date DATE DEFAULT CURRENT_DATE, PRIMARY KEY (S#, P#), FOREIGN KEY (S#) REFERENCES Suppliers(S#), FOREIGN KEY (P#) REFERENCES Parts(P#) ); Relationships in schema: Suppliers S# ←── Shipments →── Parts P# (One-to-Many from Suppliers to Shipments) (One-to-Many from Parts to Shipments)

Schema vs Instance

Understanding the difference between schema and instance is critical for exams.

Key Difference
Schema = Structure | Instance = Data
Schema is the blueprint; instance is the actual data at a given moment.

Detailed Comparison

Aspect Schema Instance
What it is Blueprint/structure Actual data snapshot
Also called Structure, Template, Intension State, Snapshot, Extension
Created when Design phase Data insertion
Changes when ALTER TABLE, CREATE/DROP INSERT, UPDATE, DELETE
Frequency of change Rare Very frequent
Storage Data dictionary Data files
Example (Relational) Table definitions Table rows

Example 2: Exam Question

Common Exam Scenario
Question: "After inserting 100 new records, which changed: schema or instance?" Answer: INSTANCE changed! - Schema (structure) stayed the same - Instance (data) got 100 new rows Question: "After adding a Phone column, which changed: schema or instance?" Answer: SCHEMA changed! - Table structure was modified - All existing data needs to accommodate new column

Example 3: Number of Rows

Row Count is Instance, Not Schema
Statement Affects Schema? Affects Instance?
INSERT INTO Suppliers... No Yes (new row)
UPDATE Suppliers SET... No Yes (modified data)
DELETE FROM Suppliers... No Yes (removed row)
ALTER TABLE ADD column... Yes No (structure changed)
CREATE TABLE... Yes No (new structure)
⚠ Number of rows is part of INSTANCE, not SCHEMA. Schema only defines what columns exist and their types.

Example 4: Real-World Analogy

Cookie Cutter Analogy
Cookie Cutter = Schema - Defines shape (star, circle, square) - Independent of how many cookies you make - Changes rarely (buy new cutter) Cookies = Instance - Actual cookies produced - Changes every time you bake - Can have 10 or 1000 cookies - Each batch is a different "instance" Schema: The cutter shape Instance: The cookies at any moment New cutter = Schema change (rare) New batch of cookies = Instance change (frequent)

Example 5: Multiple Instances

Same Schema, Different Instances
Schema: Suppliers(S#, Sname, City, Status) Instance Monday: S1|Smith|London|20 S2|Jones|Paris|10 Instance Tuesday (after INSERT): S1|Smith|London|20 S2|Jones|Paris|10 S3|Blake|Paris|30 Instance Wednesday (after DELETE): S1|Smith|London|20 Same schema, three different instances! Each instance is a snapshot at a specific time.

Exam Key Points Summary

Schema vs Instance - Quick Review
Key Facts for Exams: 1. Schema = Structure/Blueprint - Table names, columns, data types - Defined in CREATE TABLE - Changes rarely 2. Instance = Data at a moment - Actual rows of data - Changes with INSERT/UPDATE/DELETE - Changes frequently 3. Number of rows is part of INSTANCE - NOT part of schema 4. Schema changes require DDL - ALTER TABLE, CREATE TABLE, DROP TABLE 5. Instance changes require DML - INSERT, UPDATE, DELETE 6. Same schema can have many instances - Different data at different times
