Data Administrator (DA)

The DA has a managerial role focused on business requirements, not technical implementation.

DA Focus
WHAT data to store → NOT HOW to store it
DA defines business requirements and data policies, leaving technical implementation to DBA.

DA Responsibilities

Policy Setting

• Defines security policies
• Sets access levels
• Establishes data governance

Requirements Analysis

• Interviews stakeholders
• Documents business needs
• Identifies data requirements

ER Model Analysis

• Creates ER diagrams
• Defines entities/attributes
• Establishes relationships

Query Specification

• Uses relational calculus
• Specifies WHAT data needed
• Declarative approach

Example 1: DA in Banking

Bank DA Responsibilities
DA Performs: 1. Security Policy - "Only tellers can access account balances" - "Managers can access all customer data" - "Auditors get read-only access to logs" 2. Data Requirements - "We need to track: Customers, Accounts, Transactions" - "Each customer can have multiple accounts" - "We need 7-year transaction history" 3. ER Diagram [Customer] ──── [Account] ──── [Transaction] 4. Relational Calculus Query "What is the total balance for each customer?" π(cust_name, Σ(balance))(Customer ⨝ Account)
DA specifies WHAT data is needed using business language and formal models.

Database Administrator (DBA)

The DBA is the technical person who implements the DA's decisions and manages the database system.

DBA Focus
HOW to store data → Implements DA's WHAT
DBA translates business requirements into technical database design and implementation.

DBA Responsibilities

Database Creation

• Creates database structure
• Implements table design
• Sets up storage

Security Implementation

• Creates user accounts
• Configures permissions
• Implements encryption

Performance Tuning

• Optimizes queries
• Manages indexes
• Monitors resources

Staff Supervision

• Supervises DBP
• Reviews code
• Provides guidance

Example 1: DBA Implements DA Design

From ER Diagram to SQL
-- DA's ER Diagram: [Customer] ──── [Order] ──── [Product] -- DBA's Implementation: CREATE TABLE Customers ( CustID INT PRIMARY KEY, CustName VARCHAR(50), City VARCHAR(30) ); CREATE TABLE Orders ( OrderID INT PRIMARY KEY, CustID INT, OrderDate DATE, FOREIGN KEY (CustID) REFERENCES Customers(CustID) ); CREATE TABLE Products ( ProdID INT PRIMARY KEY, ProdName VARCHAR(50), Price DECIMAL(10,2) ); CREATE TABLE OrderDetails ( OrderID INT, ProdID INT, Quantity INT, PRIMARY KEY (OrderID, ProdID), FOREIGN KEY (OrderID) REFERENCES Orders(OrderID), FOREIGN KEY (ProdID) REFERENCES Products(ProdID) );
DBA converts conceptual ER model into physical relational tables.

Example 2: DBA Security Setup

User Account Management
-- Create user accounts CREATE USER 'app_user'@'localhost' IDENTIFIED BY 'password123'; CREATE USER 'admin_user'@'localhost' IDENTIFIED BY 'admin456'; -- Grant permissions based on DA's policy -- (DA said: "Tellers can read accounts, Managers can do everything") GRANT SELECT ON bank.accounts TO 'app_user'@'localhost'; GRANT ALL PRIVILEGES ON bank.* TO 'admin_user'@'localhost'; -- Revoke if needed REVOKE DELETE ON bank.accounts FROM 'app_user'@'localhost'; -- View current permissions SHOW GRANTS FOR 'app_user'@'localhost';

Database Programmer (DBP)

The DBP is the developer who writes SQL code and builds applications that interact with the database.

DBP Focus
Write Code → Build Applications → Implement Queries
DBP translates DBA's design into working SQL and application code.

DBP Responsibilities

DDL Implementation

• CREATE TABLE
• ALTER TABLE
• DROP TABLE

DML Implementation

• SELECT queries
• INSERT/UPDATE/DELETE
• Complex joins

DCL Implementation

• GRANT permissions
• REVOKE access
• Security controls

Application Development

• User interfaces
• Business logic
• Error handling

Example 1: DDL Implementation

Creating Database Structure
-- DBP implements DBA's design using DDL -- Create main tables CREATE TABLE Students ( StudentID INT PRIMARY KEY AUTO_INCREMENT, FirstName VARCHAR(30) NOT NULL, LastName VARCHAR(30) NOT NULL, Email VARCHAR(100) UNIQUE, EnrollDate DATE DEFAULT CURRENT_DATE ); CREATE TABLE Courses ( CourseID VARCHAR(10) PRIMARY KEY, CourseName VARCHAR(50) NOT NULL, Credits INT CHECK (Credits > 0) ); CREATE TABLE Enrollments ( StudentID INT, CourseID VARCHAR(10), Semester VARCHAR(10), Grade CHAR(2), PRIMARY KEY (StudentID, CourseID, Semester), FOREIGN KEY (StudentID) REFERENCES Students(StudentID), FOREIGN KEY (CourseID) REFERENCES Courses(CourseID) ); -- Modify structure if needed ALTER TABLE Students ADD COLUMN Phone VARCHAR(15); ALTER TABLE Students DROP COLUMN Phone;

Example 2: DML Queries

Data Manipulation Examples
-- INSERT: Add new records INSERT INTO Students (FirstName, LastName, Email) VALUES ('John', 'Doe', 'john.doe@university.edu'); INSERT INTO Enrollments VALUES (1, 'CS101', 'Fall2024', 'A'); -- SELECT: Query data -- Simple query SELECT * FROM Students WHERE LastName = 'Doe'; -- Join query SELECT s.FirstName, s.LastName, c.CourseName, e.Grade FROM Students s JOIN Enrollments e ON s.StudentID = e.StudentID JOIN Courses c ON e.CourseID = c.CourseID WHERE e.Semester = 'Fall2024'; -- Aggregate query SELECT CourseID, AVG(CASE Grade WHEN 'A' THEN 4 WHEN 'B' THEN 3 WHEN 'C' THEN 2 WHEN 'D' THEN 1 ELSE 0 END) as GPA FROM Enrollments GROUP BY CourseID; -- UPDATE: Modify existing records UPDATE Students SET Email = 'j.doe@uni.edu' WHERE StudentID = 1; -- DELETE: Remove records DELETE FROM Enrollments WHERE StudentID = 1 AND CourseID = 'CS101';

Example 3: DCL Security

Implementing Access Control
-- DBP implements DBA's security requirements -- Create roles CREATE ROLE 'student_role'; CREATE ROLE 'faculty_role'; CREATE ROLE 'admin_role'; -- Grant permissions to roles GRANT SELECT ON university.Students TO 'student_role'; GRANT SELECT, INSERT, UPDATE ON university.Enrollments TO 'faculty_role'; GRANT ALL PRIVILEGES ON university.* TO 'admin_role'; -- Assign roles to users GRANT 'student_role' TO 'student_user'@'localhost'; GRANT 'faculty_role' TO 'professor_user'@'localhost'; -- Revoke if needed REVOKE INSERT ON university.Students FROM 'student_role';

Example 4: Embedded DML

SQL in Host Language (Visual Basic)
' DBP embeds DML in Visual Basic application ' Connection setup Dim conn As New SqlConnection("Server=myServer;Database=myDB;User Id=user;Password=pass;") conn.Open() ' Execute query Dim cmd As New SqlCommand("SELECT * FROM Students WHERE StudentID = @id", conn) cmd.Parameters.AddWithValue("@id", studentId) Dim reader As SqlDataReader = cmd.ExecuteReader() While reader.Read() MessageBox.Show("Name: " & reader("FirstName") & " " & reader("LastName")) End While ' Insert data Dim insertCmd As New SqlCommand( "INSERT INTO Students (FirstName, LastName, Email) VALUES (@first, @last, @email)", conn) insertCmd.Parameters.AddWithValue("@first", firstName) insertCmd.Parameters.AddWithValue("@last", lastName) insertCmd.Parameters.AddWithValue("@email", email) insertCmd.ExecuteNonQuery() conn.Close()
This is "Embedded DML" — SQL is embedded within a host language (3GL).

End Users

End users are the people who use applications to interact with the database. They have the most limited access.

⚠ Critical Rule: End users CANNOT access the database directly. They MUST go through application programs provided by DBP.

End User Characteristics

Access Method

Through applications only
No direct DB access

SQL Knowledge

None required
Uses forms and buttons

Technical Skills

Low
Domain expertise only

DBMS Interaction

Indirect
Through DBMS only

Security Through Application
