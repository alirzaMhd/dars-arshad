SQL Command Categories

SQL provides three categories of commands to interact with the database:

Category Full Name Purpose Commands
DDL Data Definition Language Define/modify structure CREATE, DROP, ALTER
DML Data Manipulation Language Manipulate data content INSERT, SELECT, UPDATE, DELETE
DCL Data Control Language Control access/security GRANT, REVOKE
DSL (Data Sub-Language) Formula
DSL = DDL + DML + DCL
DSL is also called Query Language (QL). It is the complete set of SQL commands.

Example 1: Complete Database Setup

Setting up a Supplier Database
-- DDL: Create table structure CREATE TABLE Suppliers ( S# CHAR(5) PRIMARY KEY, Sname CHAR(20), City CHAR(15) ); -- DML: Insert data INSERT INTO Suppliers VALUES ('S1', 'Smith', 'London'); INSERT INTO Suppliers VALUES ('S2', 'Jones', 'Paris'); -- DML: Query data SELECT * FROM Suppliers WHERE City = 'London'; -- DCL: Control access GRANT SELECT ON Suppliers TO user1;

This example shows all three SQL categories working together to build a functional database.

Hardware Components

Hardware refers to the physical equipment used to store and process data. It forms the foundation of any database system.

Storage Hardware
Primary Storage

Hard disks, SSDs, RAID arrays — where data physically resides

CPU
Central Processing Unit

Processes queries, executes operations, manages memory

Communication
Network Equipment

Routers, switches, NICs — enables client-server communication

Storage Hardware Details

Storage Type Speed Cost Use Case
HDD (Hard Disk) Slow (5-10 ms) Low Large data archival
SSD (Solid State) Fast (0.1 ms) Medium Active databases
NVMe SSD Very Fast (0.02 ms) High High-performance DB
RAID Array Varies High Redundancy & speed

Example 1: Storage Configuration

RAID Setup for Database Server
RAID Level 0: Striping (no redundancy) - Performance: High - Risk: Data loss if any disk fails RAID Level 1: Mirroring - Performance: Medium - Redundancy: Full copy on second disk RAID Level 5: Striping with parity - Performance: Good - Redundancy: Can survive 1 disk failure RAID Level 10: Mirroring + Striping - Performance: Very High - Redundancy: Best for databases

Most enterprise databases use RAID 10 for the best balance of performance and redundancy.

Warning: Hardware Considerations

⚠ Critical Hardware Factors for Databases:
  • Insufficient RAM causes excessive disk I/O, slowing queries
  • No RAID protection risks complete data loss
  • Slow network creates bottlenecks for client-server apps
  • Single CPU limits concurrent query processing

Software Components

Software in a database environment includes all programs that manage data, from the DBMS to user applications.

Application Software
End-user programs

Forms, reports, web interfaces that users interact with

DBMS
Database Management System

Core software that manages all database operations

Operating System
System Software

Provides foundation services for DBMS to run

DBMS Capabilities

The DBMS provides three core capabilities:

Capability SQL Category Description Example
Define DDL Create/modify database structure CREATE TABLE, ALTER TABLE
Modify DML Manipulate data content INSERT, UPDATE, DELETE
Control DCL Manage security and access GRANT, REVOKE

Example 1: DBMS-OS Relationship

How DBMS Uses Operating System
DBMS Request → Operating System → Hardware Example Operations: 1. File Management - DBMS asks OS to create/open/close files - OS manages file system on disk 2. Memory Management - DBMS requests RAM allocation - OS handles virtual memory, paging 3. Process Management - DBMS creates processes for queries - OS schedules CPU time 4. I/O Operations - DBMS reads/writes data - OS manages disk I/O queue

The DBMS relies on the OS for all hardware interactions.

Data Component

Data represents the actual information stored in the database about various entities in the operational environment.

Entity-Attribute-Relationship
Data = Entities + Attributes + Relationships
Data is organized into entities (things we store info about), attributes (properties), and relationships (connections between entities).

Example 1: Suppliers and Parts

Classic Database Example
-- Entity: Suppliers CREATE TABLE Suppliers ( S# CHAR(5) PRIMARY KEY, -- Attribute: Supplier Number Sname CHAR(20), -- Attribute: Supplier Name City CHAR(15), -- Attribute: City Status INT -- Attribute: Status Rating ); -- Entity: Parts CREATE TABLE Parts ( P# CHAR(5) PRIMARY KEY, -- Attribute: Part Number Pname CHAR(20), -- Attribute: Part Name Color CHAR(10), -- Attribute: Color Weight DECIMAL(5,1), -- Attribute: Weight City CHAR(15) -- Attribute: City ); -- Relationship: Shipments (links Suppliers and Parts) CREATE TABLE Shipments ( S# CHAR(5), -- FK to Suppliers P# CHAR(5), -- FK to Parts Qty INT, -- Attribute: Quantity PRIMARY KEY (S#, P#) );

Three entities with clear relationships between them.

Database Users

There are 4 types of users in a database environment, each with specific roles and responsibilities.

DA
Data Administrator

Managerial role, decides WHAT to store

DBA
Database Administrator

Technical role, implements the database

DBP
Database Programmer

Writes SQL and application code

End User
Application User

Uses applications to access data

Access Levels

⚠ Critical Rule: Only DA, DBA, and DBP can access data WITHOUT going through the DBMS. End users MUST go through the DBMS and its applications.

Example 1: DA Responsibilities

Data Administrator Tasks
DA Performs: 1. Decides WHAT data to store - Analyzes business requirements - Identifies entities and attributes 2. Sets security policies - Determines who can access what - Defines access levels 3. ER Model Analysis - Creates Entity-Relationship diagrams - Defines business rules 4. Relational Calculus Queries - Specifies WHAT data is needed (not HOW) - Uses declarative queries
DA focuses on business logic, not technical implementation.

Example 2: DBA Responsibilities

Database Administrator Tasks
DBA Performs: 1. Creates database - Implements DA's design - Designs relational model tables 2. Implements security - Sets up user accounts - Configures permissions 3. Performance tuning - Optimizes queries - Manages indexes 4. Supervises DBP - Reviews code - Provides technical guidance
DBA bridges the gap between DA's requirements and DBP's implementation.

Example 3: DBP Responsibilities

Database Programmer Tasks
DBP Performs: 1. DDL Implementation CREATE TABLE Students ( ID INT PRIMARY KEY, Name VARCHAR(50) ); 2. DML Implementation SELECT * FROM Students WHERE ID = 101; 3. DCL Implementation GRANT SELECT ON Students TO user1; 4. Embeds DML in host language // Visual Basic example Dim cmd As New SqlCommand( "SELECT * FROM Students", connection );
