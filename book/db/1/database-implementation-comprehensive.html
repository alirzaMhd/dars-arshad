DDL and DML in SQL — Complete Guide

SQL Command Categories

Database implementation uses SQL commands, which are divided into three categories:

DDL

Data Definition Language

Structure & Schema

• Create Table

• Drop Table

• Alter Table

DML

Data Manipulation Language

Data Content

• Insert

• Select

• Update

• Delete

DCL

Data Control Language

Security

• Grant

• Revoke

Union of all SQL commands:
DSL = DDL + DML + DCL
DSL (Data Sub Language) is also called QL (Query Language). It encompasses all SQL commands.

Data Definition Language (DDL)

DDL commands define the structure and schema of the database. They create, modify, and delete database objects.

Key Commands

CREATE TABLE

• Creates a new table

• Defines columns and data types

• Sets constraints

DROP TABLE

• Deletes a table

• Removes structure and data

• Cannot be undone

ALTER TABLE

• Modifies existing table

• Add/remove columns

• Change data types

Example: Create Suppliers Table
CREATE TABLE S (
  S# char(5),
  Sname char(20),
  City char(15),
  PRIMARY KEY (S#)
);
Example: Create Shipments Table with Constraints
CREATE TABLE SP (
  S# char(5),
  P# char(5),
  QTY numeric(10),
  PRIMARY KEY (S#, P#),
  FOREIGN KEY (S#) REFERENCES S(S#)
    ON DELETE CASCADE ON UPDATE CASCADE,
  FOREIGN KEY (P#) REFERENCES P(P#)
    ON DELETE CASCADE ON UPDATE CASCADE,
  CHECK (QTY > 1 AND QTY < 1000)
);

Data Manipulation Language (DML)

DML commands manipulate the data content of tables. They insert, retrieve, update, and delete data.

Key Commands

INSERT

• Adds new rows

• INSERT INTO table VALUES (...)

SELECT

• Retrieves data

• SELECT columns FROM table WHERE condition

UPDATE

• Modifies existing data

• UPDATE table SET column=value WHERE condition

DELETE

• Removes rows

• DELETE FROM table WHERE condition

Example: SELECT query
SELECT Sname FROM S WHERE City = 'C2';

This retrieves names of all suppliers who live in city C2.

Data Control Language (DCL)

DCL commands control security and access permissions for database objects.

Key Commands

GRANT

• Gives access rights

• GRANT privilege ON object TO user

REVOKE

• Removes access rights

• REVOKE privilege ON object FROM user

Example: Grant and Revoke
GRANT SELECT ON S TO user1;
REVOKE SELECT ON S FROM user1;

First grants SELECT permission on table S to user1, then revokes it.

Worked Examples

Example 1: Complete DDL for Parts/Suppliers
-- Create Suppliers table
CREATE TABLE S (
  S# char(5) PRIMARY KEY,
  Sname char(20),
  City char(15)
);

-- Create Parts table
CREATE TABLE P (
  P# char(5) PRIMARY KEY,
  Pname char(20),
  Color char(10)
);
Example 2: INSERT data
INSERT INTO S VALUES ('S1', 'Sn1', 'C1');
INSERT INTO S VALUES ('S2', 'Sn2', 'C2');
INSERT INTO P VALUES ('P1', 'Pn1', 'Red');
INSERT INTO SP VALUES ('S1', 'P1', 10);
Example 3: SELECT with conditions
-- Find all suppliers in C2
SELECT * FROM S WHERE City = 'C2';

-- Find names of suppliers in C2
SELECT Sname FROM S WHERE City = 'C2';

-- Find parts with quantity > 20
SELECT P# FROM SP WHERE QTY > 20;
Example 4: UPDATE and DELETE
-- Update supplier city
UPDATE S SET City = 'C3' WHERE S# = 'S1';

-- Delete a shipment
DELETE FROM SP WHERE S# = 'S1' AND P# = 'P1';
Example 5: Foreign key behavior
-- With ON DELETE CASCADE:
-- Deleting supplier S1 from S table
-- automatically deletes all SP rows with S#='S1'

-- With ON UPDATE CASCADE:
-- Updating S# from 'S1' to 'S10' in S table
-- automatically updates all SP rows with S#='S1'
