Two Aspects of a Software Product

Every software product, including database systems, is created through a development process that includes analysis, design, implementation, and testing.

Core Formula:
Software Product = Data Structure + Functionality
A complete software product consists of two fundamental aspects: where data is stored (data structure) and what operations are performed (functionality).

1. Data Structure

• Where operational data is stored

• Data is organized in tables

• Focus of database courses

2. Functionality

• Programs and instructions

• Application programs that process data

• Focus of software engineering courses

Key Point: In database courses, we focus on the DATA STRUCTURE aspect (how data is organized in tables), not the functionality aspect (application programs).

Data Structure Aspect

The data structure aspect deals with how data is organized and stored in the database. In relational databases, data is stored in tables (also called relations).

Key Characteristics

Tables

• Data organized in rows and columns

• Each table represents an entity type

• Columns define attributes

Relationships

• Links between tables

• Primary keys and foreign keys

• Enforce referential integrity

Constraints

• Data types (char, numeric, etc.)

• Primary key constraints

• Check constraints

Example: Parts/Suppliers Database Structure
Table S (Suppliers): S#, Sname, City
Table P (Parts): P#, Pname, Color
Table SP (Shipments): S#, P#, QTY

Three tables store all data about suppliers, parts, and their relationships.

Functionality Aspect

The functionality aspect deals with the application programs and instructions that process the data. These are covered in software engineering courses.

Key Points

Application Programs

• User-facing software

• Business logic implementation

• User interface design

Data Processing

• CRUD operations

• Report generation

• Data validation

Exam Tip: The functionality aspect is NOT covered in database courses. Focus on data structure when studying databases.

Worked Examples

Example 1: Identifying the Two Aspects

Consider a banking system:

• Data Structure: Tables for Accounts, Customers, Transactions

• Functionality: Programs for deposit, withdrawal, transfer

Example 2: Hospital Management System

• Data Structure: Tables for Patients, Doctors, Appointments, Rooms

• Functionality: Programs for scheduling, billing, records

Example 3: University Database

• Data Structure: Tables for Students, Courses, Enrollments, Grades

• Functionality: Programs for registration, grade entry, transcript generation

Example 4: Parts/Suppliers System

• Data Structure: Tables S (Suppliers), P (Parts), SP (Shipments)

• Functionality: Programs for ordering, inventory tracking

Example 5: E-commerce System

• Data Structure: Tables for Products, Customers, Orders, OrderItems

• Functionality: Programs for shopping cart, checkout, order tracking
