Data Link Layer (LLC & MAC)

Computer Networks — Complete Guide for Exam Preparation

Data Link Layer Overview

The Data Link Layer is Layer 2 of the OSI model. It provides reliable data transfer across the physical link by converting the raw transmission facility into a reliable, error-free channel for the network layer above.

Layer Position:
Layer 3 (Network) ← Data Link Layer → Layer 1 (Physical)
The Data Link Layer sits between the Network Layer and Physical Layer, providing an interface between them.

Primary Functions

Framing

• Divides data from network layer into frames

• Adds headers and trailers for control

• Defines frame boundaries

Error Detection

• Detects errors introduced during transmission

• Uses parity, checksum, CRC

• May request retransmission

Flow Control

• Prevents fast sender from overwhelming slow receiver

• Uses sliding window protocols

• Manages buffer allocation

Addressing

• MAC addresses for local delivery

• 48-bit unique hardware addresses

• Unicast, multicast, broadcast

Warning: The Data Link Layer provides node-to-node (hop-to-hop) delivery, NOT end-to-end delivery. End-to-end delivery is handled by the Transport Layer.

Logical Link Control (LLC) Sublayer

The LLC sublayer is the upper sublayer of the Data Link Layer. It provides an interface to the network layer and handles flow control and error control at the logical level.

LLC Position:
Network Layer → LLC → MAC → Physical Layer
LLC sits above MAC and provides services to the network layer.

LLC Services (IEEE 802.2)

Service Type Description Connection Acknowledgment
Type 1 Unacknowledged connectionless Connectionless No ACK
Type 2 Connection-oriented Connection-oriented ACK required
Type 3 Acknowledged connectionless Connectionless ACK for each frame

LLC Frame Format

DSAP | SSAP | Control | Data

DSAP = Destination Service Access Point, SSAP = Source Service Access Point

Example 1: LLC Service Selection

A file transfer application needs reliable delivery. Which LLC service type should be used?

Answer: Type 2 (Connection-oriented) because it provides acknowledgments and ensures reliable delivery through retransmission.

Example 2: LLC vs MAC Responsibilities

Which sublayer handles: (a) MAC addressing? (b) Flow control? (c) Error detection?

Answer: (a) MAC sublayer, (b) LLC sublayer, (c) Both - MAC handles detection, LLC handles recovery.

Media Access Control (MAC) Sublayer

The MAC sublayer is the lower sublayer of the Data Link Layer. It controls how devices on the network gain access to the medium and permission to transmit data.

MAC Address Format:
XX:XX:XX:XX:XX:XX (48 bits = 6 bytes)
First 3 bytes = OUI (manufacturer), Last 3 bytes = device identifier

MAC Address Types

Unicast

• First bit of first byte = 0

• Identifies single device

• One-to-one communication

Multicast

• First bit of first byte = 1

• Identifies group of devices

• One-to-many communication

Broadcast

• All bits = 1 (FF:FF:FF:FF:FF:FF)

• All devices on network

• One-to-all communication

IEEE MAC Standards

Standard Speed Medium Access Method
802.3 10 Mbps Coaxial/Twisted Pair CSMA/CD
802.5 4/16 Mbps Token Ring Token Passing
802.11 11-600 Mbps Wireless CSMA/CA
Example 3: MAC Address Identification

Given MAC address: 00:1A:2B:3C:4D:5E

Answer: First byte = 00 (binary 00000000), first bit = 0, so this is a unicast address.

Example 4: Broadcast Address

What is the broadcast MAC address?

Answer: FF:FF:FF:FF:FF:FF (48 bits all set to 1). This address causes the frame to be received by all devices on the local network segment.

Worked Examples

Example 5: Frame Delivery Path

Data travels from Host A (Network 1) to Host B (Network 2) through a router. How many times is the Data Link Layer header added?

Answer: Twice - once for each hop: (1) A→Router, (2) Router→B. Each hop has its own Data Link Layer frame.

Example 6: LLC Service Selection

A streaming video application sends data continuously. Should it use Type 1 or Type 2 LLC service?

Answer: Type 1 (Unacknowledged connectionless) - Streaming video tolerates some loss but cannot tolerate delays from retransmissions.

Example 7: MAC Address Calculation

A network card has OUI 00:55:80. If the manufacturer assigns sequential device IDs starting from 00:00:01, what is the MAC address of the 256th card?

Answer: 00:55:80:00:01:00 (256 in hex = 01:00)

Example 8: Sublayer Responsibilities

Match the function to the correct sublayer: (a) Bit stuffing, (b) Logical link establishment, (c) CSMA/CD, (d) Error recovery

Answer: (a) MAC, (b) LLC, (c) MAC, (d) LLC

Example 9: Address Recognition

A network interface card receives a frame with destination address 01:00:5E:00:00:01. What type of address is this?

Answer: Multicast - First byte = 01 (binary 00000001), first bit = 1 indicates multicast.

MAC Address Classes

Class First Byte Pattern First Bit Purpose
Unicast Even number 0 Single device
Multicast Odd number 1 Group of devices
Broadcast FF 1 All devices
Common Mistake: MAC addresses are burned into the NIC hardware (usually), but can be spoofed in software. They are used for local delivery only - routers strip MAC addresses at each hop.

MAC Address Structure (48-bit)

MAC Address Format:
6 bytes = 48 bits = 12 hex digits
First 3 bytes (24 bits) = OUI (Vendor ID) | Last 3 bytes (24 bits) = Device ID
Byte Position Bits Purpose
1st byte, Bit 0 0 Unicast (individual)
1st byte, Bit 0 1 Multicast (group)
1st byte, Bit 1 0 Globally Unique (UAA)
1st byte, Bit 1 1 Locally Administered (LAA)
Example: MAC Address Breakdown

Analyze MAC address: 00:55:80:00:00:00

Answer:

• OUI: 00:55:80 (Intel Corporation)

• Device: 00:00:00

• Bit 0 = 0 → Unicast

• Bit 1 = 0 → Globally Unique

RTS/CTS Protocol (MAC Layer)

RTS/CTS Handshake:
Station A → RTS → Station B | Station B → CTS → Station A
Used to solve the hidden terminal problem in wireless networks.

Hidden Terminal Problem

• Two stations can't hear each other

• Both send to same access point

• Collisions occur undetected

RTS/CTS Solution

• RTS reserves the channel

• CTS broadcasts reservation

• All stations defer transmission

Key Insight: RTS/CTS adds overhead but is essential for wireless networks. RTS frames are short, so collisions during RTS are less costly than collisions during long data frames.
