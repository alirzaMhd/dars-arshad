First Normal Form (1NF)

Database Normalization — اولین فرم نرمال | Complete Guide for 20/20 Exam

What is 1NF?

A table is in First Normal Form (1NF) if and only if:

  • Each column contains atomic (indivisible) values
  • There are no repeating groups or arrays in any column
  • A primary key is defined to uniquely identify each row
  • All entries in a column are of the same data type
1NF Definition
∀ cell ∈ Table : cell contains exactly one value (atomicity)
Every row-column intersection must hold a single, indivisible value. No lists, sets, or nested tables.
1NF is the Foundation

Every relational table must be in 1NF. A table not in 1NF is not even considered a proper relational table. All higher normal forms (2NF, 3NF, BCNF, etc.) require the table to first satisfy 1NF.

Atomic Values

An atomic value means the value cannot be broken down further for the purposes of the database. What counts as "atomic" depends on the application context.

Atomic (Good)

• "Ali" — single name

• "09121234567" — single phone

• "Tehran" — single city

• CSE201 — single course code

Non-Atomic (Bad)

• "Ali, Sara, Reza" — multiple names

• "09121234567, 09131234567" — multiple phones

• "Tehran, Shiraz" — multiple cities

• "CSE201, CSE301" — multiple courses

Repeating Groups

A repeating group occurs when a table has multiple columns that store the same kind of data, typically with names like Phone1, Phone2, Phone3 — or when a single column stores multiple values separated by commas.

Before 1NF: Table with Repeating Groups
StudentIDNameCourse1Course2Course3
101AliDBMSOSAI
102SaraDBMSNetworksNULL

Problems: Course1, Course2, Course3 form a repeating group. Adding a 4th course requires schema change. NULLs are wasted space.

Rule 1: Atomic Columns

Every column must contain only atomic (single, indivisible) values. No arrays, lists, comma-separated strings, or JSON objects that store multiple values.

Violation Example
-- Table: Student_Phones -- Violation: Phones column contains multiple values StudentID | Name | Phones 101 | Ali | 09121234567, 09131234567 102 | Sara | 09141234567 -- Correct 1NF version: StudentID | Name | Phone 101 | Ali | 09121234567 101 | Ali | 09131234567 102 | Sara | 09141234567

Rule 2: No Repeating Groups

Do not use multiple columns to store multiple values of the same category (e.g., Phone1, Phone2, Phone3). Instead, create a separate child table with one row per value.

Repeating Groups Fix
-- Bad design: Repeating group columns StudentID | Name | Phone1 | Phone2 | Phone3 101 | Ali | 09121234567 | 09131234567 | NULL -- Good design (1NF): Separate table -- Table: Student StudentID | Name 101 | Ali -- Table: Student_Phone StudentID | Phone 101 | 09121234567 101 | 09131234567

Rule 3: Primary Key Required

Every 1NF table must have a primary key — a column or combination of columns that uniquely identifies each row. Without a primary key, duplicate rows are possible, and there is no way to reference specific records.

Primary Key Requirement
∃ PK ⊆ Attributes : ∀ rows r1, r2 : PK(r1) ≠ PK(r2)
There must exist a subset of attributes such that every pair of distinct rows has different values for those attributes.
Composite Primary Keys

When no single column can uniquely identify rows, a composite primary key (combination of two or more columns) must be used. Composite keys are common in junction/enrollment tables.

Rule 4: Same Data Type per Column

All values in a column must be of the same data type. Mixing integers and strings in the same column violates the relational model and 1NF.

Data Type Violation
-- Violation: Mixing text and numbers in "Value" column ItemID | Value 1 | 42 2 | "Forty-two" 3 | 3.14 -- Different types mean different semantics → should be separate columns

Example 1: Converting to 1NF

Original table (not in 1NF) — note the multi-valued skills column and repeating groups:

Unnormalized Table: Employee_Projects

E01AliJava, SQLDB_AppWeb_App
E02SaraPython, MLAI_ModelNULL

Violations:

  • Skills column contains multiple values (Java, SQL)
  • Project1, Project2 are repeating groups

Step 1: Fix Skills (atomic values) — split into separate rows:

EmpIDNameSkillProject1Project2
E01AliJavaDB_AppWeb_App
E01AliSQLDB_AppWeb_App
E02SaraPythonAI_ModelNULL
E02SaraMLAI_ModelNULL

Now each cell is atomic, but repeating groups (Project1, Project2) remain. Also rows with duplicate EmpID+Name suggest further normalization is needed (2NF/3NF).

Example 2: Full 1NF Decomposition

Better solution: decompose into three separate tables, each in 1NF:

Employee Table

EmpID (PK) | Name E01 | Ali E02 | Sara

Employee_Skill

EmpID (FK) | Skill E01 | Java E01 | SQL E02 | Python E02 | ML

Employee_Project

EmpID (FK) | Project E01 | DB_App E01 | Web_App E02 | AI_Model

All three tables are now in 1NF — each cell is atomic, no repeating groups, and each has a primary key.

Common 1NF Violations

These are the most frequent violations of 1NF found in real-world database designs:

Comma-Separated Values

Storing multiple items in a single string like "Java, SQL, Python" violates atomicity. Difficult to query, index, or join.

JSON/Array Columns

Using JSON arrays or nested data structures. While some databases support this, it still violates the strict definition of 1NF.

Repeating Columns

Phone1, Phone2, Phone3 or similar patterns. Limiting the number of values and wasting space with NULLs.

Missing Primary Key

Tables without a primary key allow duplicate rows, breaking the relational model's fundamental guarantee.

Is 1NF Always Required?

Modern Databases and 1NF

Some modern database systems (PostgreSQL with JSONB, MongoDB, etc.) intentionally allow non-1NF structures for flexibility. However, for relational database design and exam purposes, 1NF is mandatory and assumed.

Always normalize to 1NF first before checking higher normal forms. A table must be in 1NF before it can be evaluated for 2NF, 3NF, or BCNF.

1NF Quick Reference

  • ▸ Core Rule: Every cell contains exactly one atomic value
  • ▸ No repeating groups (Phone1, Phone2, Phone3 pattern)
  • ▸ Primary key must be defined
  • ▸ All column values must share the same data type
  • ▸ Violation symptoms: comma-separated values, JSON arrays, repeating columns
  • ▸ Fix: Decompose into separate tables + separate rows per atomic value
  • ▸ 1NF is prerequisite for all higher normal forms
  • ▸ Codd's original definition (1970) — foundation of relational model
