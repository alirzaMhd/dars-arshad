3NF and Beyond

At 3NF, any transitive dependencies (like Instructor Office depending on Instructor) would be separated. At BCNF, overlapping candidate keys are checked. At 4NF, if Instructor and Course are independent (MVD exists), they are split further. At 5NF, any ternary join dependencies are resolved.

Decision Guide: Which Normal Form Do You Need?

Choosing the right normal form depends on your application requirements. Use this decision tree as a guide.

START: Is your data in atomic form (no repeating groups)? | +-- No --> Normalize to 1NF first, then continue | +-- Yes --> Check for partial dependencies (non-key attr depends on part of composite key) | +-- Exist --> Normalize to 2NF | +-- None --> Check for transitive dependencies (non-key attr depends on another non-key attr) | +-- Exist --> Normalize to 3NF | +-- None --> Check for non-key FDs (determinant not a candidate key) | +-- Exist --> Normalize to BCNF | +-- None --> Check for MVDs (independent multi-valued facts) | +-- Exist --> Normalize to 4NF | +-- None --> Check for JDs (lossless 3+ way decomposition) | +-- Exist --> Normalize to 5NF | +-- None --> Already in 5NF!

Practical Decision Guide

Most Applications

Target: 3NF

Sufficient for eliminating the common anomalies. Dependency-preserving BCNF decomposition may not always be possible.

Data Warehousing

Target: Star Schema (Denormalized)

Deliberately denormalize for analytical query performance. Fact tables + dimension tables.

High-Integrity Systems

Target: BCNF or higher

Financial, medical, or safety-critical systems need maximum data integrity with minimal redundancy.

Complex Relationships

Target: 4NF or 5NF

When entities have independent multi-valued attributes or complex ternary relationships.

Decision Rule of Thumb:

Start with 3NF for all designs. If you encounter overlapping candidate keys, move to BCNF. If independent multi-valued attributes exist, move to 4NF. Only consider 5NF if you have ternary relationships that decompose into three or more binary projections.

Summary of All Normal Forms

1NF - First Normal Form

Rule: Atomic values only

Violation: Multi-valued attributes, composite columns

Fix: Create separate rows or separate tables

Key property: Every cell holds exactly one value.

2NF - Second Normal Form

Rule: Full FD on primary key

Violation: Non-key attr depends on part of composite key

Fix: Decompose into separate tables for each partial dependency

Key property: Every non-key attr depends on the whole key.

3NF - Third Normal Form

Rule: No transitive dependencies

Violation: Non-key attr determines another non-key attr

Fix: Decompose to separate the transitive dependency

Key property: Nothing but the key.

BCNF - Boyce-Codd Normal Form

Rule: Every FD determinant is a superkey

Violation: FD where X is not a superkey (even if all attrs are prime)

Fix: Decompose on violating FD

Key property: Stronger than 3NF for overlapping keys.

4NF - Fourth Normal Form

Rule: No non-trivial MVDs with non-superkey determinant

Violation: Independent multi-valued attributes in same table

Fix: Split into separate tables for each independent set

Key property: Each fact is truly independent.

5NF - Fifth Normal Form

Rule: Every JD is implied by candidate keys

Violation: Lossless 3+ way decomposition exists

Fix: Decompose on the violating JD

Key property: No further lossless decomposition possible.

Key Formulas to Remember

1NF:
All attribute values are atomic (no repeating groups)
2NF:
1NF AND for every non-key A and every key K: K fully determines A
3NF:
2NF AND no transitive FD: X --> Y where Y is non-key and X is not a key
BCNF:
3NF AND for every FD X --> Y: X is a superkey
4NF:
BCNF AND for every MVD X -->--> Y: X is a superkey
5NF:
4NF AND every JD is implied by candidate keys

Final Checklist by Normal Form

Is Your Database Properly Normalized?

1NF: All columns contain atomic values, primary key identified

2NF: All non-key columns depend on the full primary key

3NF: All non-key columns depend only on the primary key

BCNF: All functional dependency determinants are superkeys

4NF: All multi-valued dependency determinants are superkeys

5NF: All join dependencies are implied by candidate keys
