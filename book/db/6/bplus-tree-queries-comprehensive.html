B+ TREE QUERIES

Point Query & Range Query — Complete Guide for 20/20 Exam

Point Query Algorithm

A point query searches for an exact match of a key in the B+ Tree. It follows a single path from root to leaf.

Algorithm Overview:
Start at root → Compare keys → Follow pointer → Reach leaf → Search leaf
At each internal node, determine which child to follow based on key comparison

Time Complexity

• Tree height: O(log_t n)

• Cost per level: O(t) (binary search)

• Total: O(t · log_t n)

• If t constant: O(log n)

Space Complexity

• Extra space: O(1)

• Uses only pointers

• No recursion stack needed

Step-by-Step Point Query Process

1 Start at Root

Begin at the root node. The root contains index keys that partition the search space.

↓
2 Compare with Internal Keys

At each internal node, compare the search key with the node's keys:

Decision Rule:
key < K₁ → follow P₀
Kᵢ ≤ key < Kᵢ₊₁ → follow Pᵢ
key ≥ Kₙ → follow Pₙ
↓
3 Follow Pointer to Child

Follow the appropriate child pointer down to the next level. Repeat until reaching a leaf node.

↓
4 Search Leaf Node

At the leaf node, perform a linear or binary search for the key. The leaf contains actual data pointers.

Leaf Search:
For i = 0 to leaf.n-1: if leaf.keys[i] == key → FOUND
If key not found after searching all keys → NOT FOUND
↓
5 Return Result

If found, return the data pointer associated with the key. If not found, return NULL or "not found".

Search path for key 25:

[10 | 20 | 30]

↑ 25 ≥ 20 and 25 < 30 → follow P₂


[5 | 8]

⚠ Key Observation
In a B+ Tree, ALL searches end at a leaf node. Internal nodes only contain copies of keys for routing. Even if a key exists in an internal node, you must go to the leaf to get the data pointer.

Range Query Algorithm

A range query searches for all keys in the range [a, b]. It uses the leaf-level linked list for efficient sequential access.

Algorithm Overview:
Point Query(a) → Find first leaf with key ≥ a → Follow leaf pointers → Stop when key > b
Combines point query with sequential leaf traversal

Time Complexity

• Point query part: O(log_t n)

• Leaf traversal: O(k)

• Total: O(log_t n + k)

• k = number of results

Advantage over B-Tree

• No backtracking

• Sequential access pattern

• Cache-friendly (leaf nodes linked)

• Better for range queries

Step-by-Step Range Query Process

1 Find Starting Point

Use point query algorithm to find the first leaf node containing a key ≥ a. This gives the starting position for the range scan.

Goal:
Find leaf with first key ≥ a
Follow same path as point query, but stop at first key ≥ a
↓
2 Scan Leaf Forward

Starting from the position found in step 1, scan forward in the leaf, collecting all keys ≤ b.

In current leaf:
For each key from position to end: if key ≤ b → add to result
↓
3 Follow Leaf Pointer

If the current leaf's last key ≤ b, follow the next pointer to the next leaf. Continue scanning.

↓
4 Stop Condition

Stop when you reach a leaf where the first key > b, or when the next pointer is NULL (end of leaves).

Stop when:
leaf.keys[0] > b OR leaf.next == NULL
All keys in range have been collected
↓
5 Return Result Set

Return all collected keys as the result set. Keys are already in sorted order due to B+ Tree structure.

Step 1: Find first leaf with key ≥ 15

[10 | 20 | 30]

15 ≥ 10 and 15 < 20 → follow P₁

[35 | 40]

Why B+ Tree is Superior for Range Queries

B+ Tree (Linked Leaves)

• Point query to start: O(log_t n)

• Then follow links: O(k)

• No backtracking needed

• Sequential access pattern

B-Tree (No Links)

• Must find each key separately

• Each search: O(log_t n)

• k searches = O(k · log_t n)

• Much slower for ranges

Performance Comparison:
B+ Tree: O(log_t n + k) vs B-Tree: O(k · log_t n)
For large ranges (k >> 1), B+ Tree is significantly faster

Point Query Pseudocode

1: function POINT_QUERY(root, key): 2: if root is NULL: 3: return NULL 4: 5: // Start at root 6: current = root 7: 8: // Step 1: Traverse to leaf 9: while current is not leaf: 10: // Find correct child pointer 11: i = 0 12: while i < current.n and key > current.keys[i]: 13: i = i + 1 14: // Follow pointer to child 15: current = current.children[i] 16: 17: // Step 2: Search leaf node 18: i = 0 19: while i < current.n: 20: if current.keys[i] == key: 21: return current.data[i] // FOUND 22: i = i + 1 23: 24: return NULL // NOT FOUND

Range Query Pseudocode

1: function RANGE_QUERY(root, low, high): 2: results = empty list 3: 4: // Step 1: Find first leaf with key >= low 5: leaf = FIND_FIRST_LEAF(root, low) 6: 7: // Step 2: Scan leaves forward 8: while leaf is not NULL: 9: for i = 0 to leaf.n - 1: 10: if leaf.keys[i] >= low and leaf.keys[i] <= high: 11: results.add(leaf.keys[i]) 12: if leaf.keys[i] > high: 13: return results // Done 14: leaf = leaf.next // Follow link 15: 16: return results 17: 18: 19: function FIND_FIRST_LEAF(root, low): 20: current = root 21: 22: // Traverse to leaf 23: while current is not leaf: 24: i = 0 25: while i < current.n and low > current.keys[i]: 26: i = i + 1 27: current = current.children[i] 28: 29: // Find first key >= low 30: i = 0 31: while i < current.n and current.keys[i] < low: 32: i = i + 1 33: 34: // If no key >= low, try next leaf 35: if i == current.n: 36: current = current.next 37: i = 0 38: 39: return current

Optimized Range Query (with Binary Search)

1: function RANGE_QUERY_OPT(root, low, high): 2: results = empty list 3: 4: // Step 1: Find first leaf with key >= low 5: leaf = FIND_FIRST_LEAF(root, low) 6: 7: // Step 2: Scan leaves with binary search 8: while leaf is not NULL: 9: // Binary search for start position 10: start = BINARY_SEARCH(leaf.keys, low, 0, leaf.n - 1) 11: 12: // Add all valid keys from start position 13: for i = start to leaf.n - 1: 14: if leaf.keys[i] <= high: 15: results.add(leaf.keys[i]) 16: else: 17: return results // Done 18: 19: leaf = leaf.next // Follow link 20: 21: return results 22: 23: 24: function BINARY_SEARCH(keys, target, low, high): 25: while low <= high: 26: mid = (low + high) / 2 27: if keys[mid] < target: 28: low = mid + 1 29: else: 30: high = mid - 1 31: return low

Quick Reference Card

Point Query Summary

• Start at root, traverse to leaf
• Compare key with internal node keys
• Follow appropriate child pointer
• Search leaf for exact match
• Return data pointer or NULL
• Time: O(log_t n)

Range Query Summary

• Use point query to find first key ≥ a
• Scan leaf forward, collecting keys ≤ b
• Follow leaf next pointers
• Stop when key > b or end of leaves
• Result is already sorted!
• Time: O(log_t n + k)

Key Differences: Point vs Range

• Point query: single path, one leaf
• Range query: single path + leaf traversal
• Point query doesn't use leaf links
• Range query exploits leaf linking
• Point: O(log n) | Range: O(log n + k)

Decision Rules for Traversal

• key < K₁: follow P₀ (leftmost child)
• Kᵢ ≤ key < Kᵢ₊₁: follow Pᵢ
• key ≥ Kₙ: follow Pₙ (rightmost child)
• At leaf: linear search for exact match

⚠ Why B+ Tree Wins for Range Queries
B-Tree must search from root for EACH key in range → O(k log n). B+ Tree traverses leaves sequentially → O(log n + k). For large ranges, B+ Tree is orders of magnitude faster.

Top 5 Exam Tips for Queries

1. Always start at root
Never start at an internal node or leaf directly. Every search begins at the root.
2. Follow decision rules exactly
key < K₁ → P₀ | Kᵢ ≤ key < Kᵢ₊₁ → Pᵢ | key ≥ Kₙ → Pₙ
3. Point query ends at leaf
Even if key exists in internal node, you MUST go to leaf. Data pointers are ONLY in leaves.
4. Range query uses leaf links
After finding start, follow leaf.next pointers. Don't go back to root!
5. Result is automatically sorted
B+ Tree leaves are linked in sorted order. Range query results come out sorted for free.
