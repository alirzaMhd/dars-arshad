B+ Tree Splitting Rules

Database Indexing — Complete Guide for 20/20 Exam

B+ Tree Parameters

A B+ tree of order t (sometimes called minimum degree) has these capacity rules:

Leaf Nodes

Minimum keys: t - 1

Maximum keys: 2t - 1

Minimum children: N/A (leaf)

Maximum children: N/A (leaf)

Each key has a data pointer to the actual row.

Intermediate (Internal) Nodes

Minimum children: t

Maximum children: 2t

Minimum keys: t - 1

Maximum keys: 2t

Each key separates child subtrees; each child has a pointer.

Splitting Trigger:
Split when node reaches maximum capacity (overflow)
Leaf: splits at 2t - 1 keys. Intermediate: splits at 2t children (2t keys).
Height of B+ Tree:
h = log_t(n+1) — 1
For n total keys and minimum degree t. Very shallow tree: 1M keys with t=100 needs only height 2.

Why Split?

When a node overflows (reaches its maximum capacity), it must be split to maintain the B+ tree properties. Splitting propagates upward — a leaf split may cause its parent to split, which may cause the grandparent to split, and so on up to the root.

Key Difference: In leaf nodes, the middle key stays in the right node. In intermediate nodes, the middle key moves UP to the parent. This is the most critical distinction to remember for exams.
Critical Rule: If the root itself overflows, the tree grows taller by one level. The root splits and a new root is created with a single key (the promoted middle key).

Leaf Node Splitting — Step by Step

When a leaf node has 2t - 1 keys and a new key is inserted, the node overflows and must split.

Step 1: Detect Overflow

Leaf node has 2t - 1 keys (maximum capacity). A new key arrives that belongs in this node.

The node is now full. We cannot insert without violating the maximum key constraint.

↓
Step 2: Create a New Node

Create a new empty leaf node to the right of the current node.

This new node will hold the upper half of the keys.

↓
Step 3: Distribute Keys

After temporary insertion of all 2t keys:

• Left node keeps the first t keys

• Right node gets the last t - 1 keys

• The middle key stays in the right node (this is different from intermediate splitting!)

↓
Step 4: Update Linked List

Both leaf nodes are in a doubly-linked list:

• Left node's next pointer → Right node

• Right node's prev pointer → Left node

• Maintain existing neighbors' pointers to include new node

↓
Step 5: Copy Middle Key to Parent

Copy the first key of the right node (the middle key) UP to the parent.

This key is COPIED, NOT moved — it remains in the leaf node as well.

This is the key difference from intermediate splitting: leaf middle key is copied, not moved.

Visual Example: Leaf Split (t = 2)

Maximum keys per leaf: 2t - 1 = 3. Split occurs at 3 keys.

BEFORE split (insert key 7): [ ... ] | ┌───────┴───────┐ | | [1, 3, 5] [8, 10, 12] | (overflow! 3 keys + new 7 = 4 > max 3) AFTER split: [ ... ] | ┌───────┼───────┐ | | | [1, 3] [5, 7] [8, 10, 12] \ / linked list pointers (bidirectional)

What happened:

  • Original leaf had [1, 3, 5] → insert 7 → temporary [1, 3, 5, 7]
  • Left node keeps first t = 2 keys: [1, 3]
  • Right node gets remaining t - 1 = 1 keys: [5, 7]
  • Middle key 5 stays in right node AND is copied to parent
  • Parent now has key 5 as separator: left subtree < 5, right subtree ≥ 5

Leaf Split — Detailed Example (t = 3)

Maximum keys per leaf: 2t - 1 = 5. Split occurs when inserting into a node with 5 keys.

BEFORE: Insert key 22 into full leaf Leaf node: [10, 15, 18, 20, 25] ← 5 keys (MAX) After inserting 22 (temporarily): [10, 15, 18, 20, 22, 25] ← 6 keys (overflow!) AFTER split: Left leaf: [10, 15, 18] ← t = 3 keys Right leaf: [20, 22, 25] ← t - 1 = 2 keys (20 was middle, stays here) Parent gets copy of 20: [..., 20, ...] / \ [10,15,18] [20,22,25] Key point: 20 is in BOTH the parent and the right leaf!

Leaf Splitting Rules Summary

  • Trigger: Leaf has 2t - 1 keys and new key arrives
  • Distribution: Left gets t keys, right gets t - 1 keys
  • Middle key: Stays in right node (COPIED to parent)
  • Linked list: Update prev/next pointers for both nodes
  • Parent: Gets a copy of the right node's first key
  • No removal: The middle key is NOT removed from the leaf

Intermediate Node Splitting — Step by Step

When an intermediate (internal) node has 2t children and a new child must be added, the node overflows and must split.

Step 1: Detect Overflow

Intermediate node has 2t children (maximum). A new child pointer must be inserted.

Intermediate nodes hold keys + child pointers. Max children = 2t, max keys = 2t (one extra key from parent insertion context).

↓
Step 2: Create a New Node

Create a new empty intermediate node.

This node will hold the upper half of the children and keys.

↓
Step 3: Distribute Keys and Children

After temporary insertion of all 2t keys and 2t+1 children:

• Left node keeps first t keys and t children

• The middle key is MOVED UP to the parent (removed from this level)

• Right node gets last t - 1 keys and t children

↓
Step 4: Update Parent

The middle key is inserted into the parent along with a pointer to the new right node.

The parent may now overflow, triggering a recursive split!

↓
Step 5: Handle Recursive Split (if needed)

If the parent also overflows, apply the same splitting rule to the parent.

This can propagate all the way up to the root.

If the root splits, the tree height increases by 1 (new root created).

Visual Example: Intermediate Split (t = 2)

Maximum children: 2t = 4. Split occurs at 4 children (3 keys).

BEFORE (inserting new child): [5, 10, 15] / | | \ [1,3] [7,8] [12] [18,20] ← 4 children (MAX) | new child with key 6 arrives (5 has 4 children + 1 new = 5, overflow!) AFTER split: [10] / \ [5] [15] / | / | \ [1,3] [7,8] [12] [18,20] | [6] (new child) | Note: 10 was the middle key, MOVED UP to parent. Parent lost 10 from its key list. Left node has [5] with 2 children. Right node has [15] with 2 children.

What happened:

  • Original node had children: [1,3], [7,8], [12], [18,20] with keys [5, 10, 15]
  • New child [6] inserted between [1,3] and [7,8]
  • After redistribution, middle key 10 is MOVED UP to parent
  • Left node: key [5], children [1,3] and [7,8]
  • Right node: key [15], children [12] and [18,20]
  • Parent now has [10] with two child pointers

Intermediate Split — Detailed Example (t = 3)

Maximum children: 2t = 6. Split occurs when node has 6 children (5 keys).

BEFORE: Insert new child (key 30) into full intermediate node Intermediate node: keys [10, 20, 35, 45, 50], children: 6 Children: [C1] [C2] [C3] [C4] [C5] [C6] After inserting key 30 (temporarily): keys [10, 20, 30, 35, 45, 50], 7 children Overflow! 7 children > max 6. AFTER split: Middle key = 30 (index 3 of 6 keys) Left node: Keys: [10, 20] ← t - 1 = 2 keys Children: [C1][C2][C3] ← t = 3 children Middle key 30: MOVED UP to parent Right node: Keys: [35, 45, 50] ← t - 1 = 2 keys (Wait: t = 3, so 5 - 3 = 2 keys, 3 children) Children: [C4][C5][C6] ← t = 3 children Result: [30] / \ [10, 20] [35, 45, 50] / | \ / | \ C1 C2 C3 C4 C5 C6 Key point: 30 is ONLY in the parent, NOT in the intermediate children!

Leaf vs Intermediate Splitting — Side by Side

Leaf Node Split

  • Overflow at: 2t - 1 keys
  • Left keeps: t keys
  • Right gets: t - 1 keys
  • Middle key: STAYS in right node
  • Parent action: Gets a COPY of middle key
  • Linked list: Updated (prev/next pointers)
  • Recursive? Only if parent overflows
  • Data pointers: Keys have data pointers

Intermediate Node Split

  • Overflow at: 2t children (2t keys)
  • Left keeps: t - 1 keys, t children
  • Right gets: t - 1 keys, t children
  • Middle key: MOVED UP to parent
  • Parent action: Gets the key (removed from child)
  • Linked list: None (not applicable)
  • Recursive? Yes, may cascade up to root
  • Data pointers: Keys separate child subtrees
The #1 Exam Mistake: Confusing COPY vs MOVE. For leaf splits, the middle key is COPIED (stays in leaf + copied to parent). For intermediate splits, the middle key is MOVED (removed from child + placed in parent). Mixing these up is the most common error.

Complete Comparison Table

Property Leaf Split Intermediate Split
Overflow condition 2t - 1 keys (full) 2t children / 2t keys (full)
Temporary keys before split 2t (inserted into full node) 2t + 1 (2t existing + 1 new child)
Left node keeps t keys t - 1 keys, t children
Right node gets t - 1 keys t - 1 keys, t children
Middle key behavior Copied to parent (stays in leaf) Moved to parent (removed from node)
Parent receives Key + pointer to right node Key + pointer to right node
Linked list update Yes (prev/next) No
Recursive splitting Only if parent overflows Common — cascades up

Contains Data pointers to rows Child pointers to subtrees
Traversal All leaves at same level (bottom) Root to leaf path (internal)

Quick Reference Cards

Leaf Splitting — Quick Reference

  • When: 2t - 1 keys → insert → overflow
  • Split into: t keys (left) + t - 1 keys (right)
  • Middle key: COPIED to parent (remains in right leaf)
  • Update: doubly-linked list pointers
  • Formula: After split, left has t keys, right has t - 1 keys, parent gains 1 key

Intermediate Splitting — Quick Reference

  • When: 2t children → insert → overflow
  • Split into: t - 1 keys + t children (left) + t - 1 keys + t children (right)
  • Middle key: MOVED up to parent (removed from this level)
  • Update: parent key list + child pointer
  • Recursive: parent may also split → cascade upward

Worked Examples

Example 1: Leaf Split with t = 2 (Insert 7)

Setup: B+ tree of order t=2. Max keys per leaf = 2t-1 = 3.

State: Leaf has keys [1, 3, 5], parent has key [10].

Step 1: Insert 7 into leaf [1, 3, 5] Result: [1, 3, 5, 7] — 4 keys, overflow! Step 2: Split [1, 3, 5, 7] Middle position = index 2 (0-indexed) Middle key = 5 Step 3: Distribute Left leaf: [1, 3] — t = 2 keys Right leaf: [5, 7] — t - 1 = 1 key (5 stays here) Step 4: Update linked list [...] ↔ [1, 3] ↔ [5, 7] ↔ [...] Step 5: Copy 5 to parent Parent was: [..., 10, ...] Parent now: [..., 5, 10, ...] / \ [1, 3] [5, 7]

Key takeaway: 5 is in BOTH the parent AND the right leaf (copied, not moved).

Example 2: Intermediate Split with t = 2 (Insert key 15)

Setup: B+ tree of order t=2. Max children = 2t = 4.

State: Intermediate node has keys [10, 20, 30] with 4 children: A, B, C, D.

Step 1: Need to insert new child E with key 15 between B and C Intermediate: keys [10, 20, 30], children [A, B, E, C, D] — 5 children, overflow! Step 2: After temporary insertion: keys [10, 15, 20, 30], 5 children Middle key = 20 (index 2 of 4 keys) Step 3: Distribute Left node: keys [10], children [A, B, E] — t-1 = 1 key, t = 2 children Middle key 20: MOVED UP to parent (removed from this level) Right node: keys [30], children [C, D] — t-1 = 1 key, t = 2 children Step 4: Parent receives 20 Parent was: [..., 20, ...] Parent now: [..., 20, ...] with new pointer to right node [..., 20, ...] / | \ [10] [20 promoted] [30] / | \ / \ / \ A B E C D

Key takeaway: 20 is REMOVED from the intermediate node and placed ONLY in the parent.

Example 3: Cascading Split (Root Split)

Setup: B+ tree where root has max keys (2t = 4 for t=2).

State: Root has keys [5, 10, 15, 20] with 5 children.

Step 1: Insert new child → root overflow (5 keys, max 4) Step 2: Split root Middle key = 15 (moved UP) Left root: [5, 10] with 3 children Right root: [20] with 2 children Step 3: Create NEW root (tree height increases!) New root: [15] with 2 children / \ [5, 10] [20] / | \ / \ (children) (children) BEFORE: Height 1 (root only) AFTER: Height 2 (new root created)

Key takeaway: When the root splits, the tree grows taller. This is how B+ trees increase in height.

Example 4: Full Insertion Sequence (t = 2)

Build a B+ tree by inserting: 10, 20, 30, 40, 50, 25, 35

Insert 10: [10] Insert 20: [10, 20] Insert 30: [10, 20, 30] — full (max 3 keys) Insert 40: Overflow! Split [10, 20, 30, 40] Left: [10] — t = 1 key? (t=2: left gets 2 keys) Actually for t=2: left gets t=2 keys, right gets t-1=1 key Left: [10, 20] Right: [30, 40] — 30 copied to parent Root: [30] / \ [10, 20] [30, 40] Insert 50: Goes to right leaf [30, 40, 50] — full! Split [30, 40, 50]: Left: [30] Right: [40, 50] — 40 copied to parent Root was: [30] Root now: [30, 40] / | \ [10, 20] [30] [40, 50] Insert 25: Goes to left leaf [10, 20, 25] — full! Split [10, 20, 25]: Left: [10] Right: [20, 25] — 20 copied to parent Root was: [30, 40] Root now: [20, 30, 40] — still OK (max 3 keys) / | | \ [10] [20,25] [30] [40,50] Insert 35: Goes to [30] leaf → [30, 35] — OK (2 keys, max 3) Final tree: [20, 30, 40] / | | \ [10] [20,25] [30,35] [40,50]

Note: Each leaf split copies the middle key up. The tree grows only when the root splits.

Example 5: Exam-Style Question — Count Keys After Splits

Question: A B+ tree has t = 3. A leaf node has 5 keys (2t-1 = 5, full). One more key is inserted, causing a split. How many keys end up in the left leaf, right leaf, and parent?

Given: t = 3 Max keys per leaf: 2t - 1 = 5 After insertion: 6 keys temporarily (overflow) Split distribution: Left leaf: t = 3 keys Right leaf: t - 1 = 2 keys Parent: +1 key (copy of middle key) Answer: Left leaf: 3 keys Right leaf: 2 keys Parent: gains 1 key (the middle key, copied) Total keys in leaves: 3 + 2 = 5 (correct: 6 - 1 = 5, because middle key counted once in leaf, once in parent)
Exam Tip: Always count carefully. After a leaf split with 2t keys temporarily:
• Left has t, right has t-1, parent gains 1.
• Total unique key count: t + (t-1) = 2t-1 (middle key exists in right leaf AND parent, but is the same key).
