B+ Tree Structure

Data Structures — Complete Guide for 20/20 Exam

What is a B+ Tree?

A B+ Tree is a self-balancing tree data structure that maintains sorted data and allows searches, sequential access, insertions, and deletions in logarithmic time. It is widely used in databases and file systems for indexing.

Unlike a regular B-Tree, a B+ Tree stores all actual data in the leaf nodes, while internal (intermediate) nodes store only index keys used for navigation.

Key Difference from B-Tree

In a B-Tree, data pointers exist in both internal and leaf nodes. In a B+ Tree, all data pointers are only in leaf nodes. Internal nodes contain only copies of keys for routing.

B+ Tree Parameter
t = order of the B+ Tree
t determines the minimum and maximum number of keys and children each node can have. All capacity constraints are expressed in terms of t.

Root Node

The root node is the entry point of the B+ Tree. It can be either an internal node (if the tree has more than one level) or a leaf node (if the entire tree fits in one node).

Root as Internal Node

• Minimum keys: 1

• Maximum keys: 2t

• Minimum children: 2

• Maximum children: 2t

Root as Leaf Node

• Minimum keys: 0 (empty tree)

• Maximum keys: 2t - 1

• Contains data pointers

• No children

Root Exception

The root node is the only node that can have fewer than t keys (minimum 1 key for internal, 0 for leaf). This exception allows the tree to grow gradually.

Intermediate (Internal) Nodes

Intermediate nodes exist between the root and the leaves. They store only index keys — no data pointers. These keys act as routing information to direct searches to the correct leaf.

Intermediate Node Constraints
t ≤ keys ≤ 2t
Each intermediate node must have at least t keys and at most 2t keys (except the root).
Children Constraint
t + 1 ≤ children ≤ 2t + 1
A node with k keys has k+1 children. So min children = t+1, max children = 2t+1.
Example: Intermediate Node (t = 2)

With t = 2, an intermediate node can have:

  • Minimum 2 keys, maximum 4 keys
  • Minimum 3 children, maximum 5 children
   [10 | 20 | 30]      ← 3 keys
  /   |    |    \
 ↓    ↓    ↓     ↓     ← 4 children

Leaf Nodes

Leaf nodes store the actual data records or pointers to data records. Every key in the B+ Tree must appear at least once in a leaf node. Leaf nodes are linked together via a doubly linked list for efficient range queries.

Leaf Node Constraints
t - 1 ≤ keys ≤ 2t - 1
Each leaf node must have at least t-1 keys and at most 2t-1 keys.

Leaf Node Properties

• Contains actual data pointers

• All data is at the leaf level

• Keys may be duplicated across leaves

• Sorted order maintained

Leaf Node Links

• Forward pointer → next leaf

• Backward pointer ← previous leaf

• Enables sequential scan

• Range queries: O(log n + k)

Example: Leaf Node (t = 3)

With t = 3, a leaf node can hold between 2 and 5 keys:

   ↑ backward    ↑

Doubly Linked Leaf List

All leaf nodes in a B+ Tree are connected through a doubly linked list. This is one of the most important structural features that distinguishes B+ Trees from B-Trees.

  ┌──────────────────────────────────────────────────┐
  │                                                  │
  ↓                                                  │
[1 3 5] ↔ [8 12 15] ↔ [20 25] ↔ [30 35 40] ↔ null
  ↑                                              │
  └──────────────────────────────────────────────┘

Forward Pointer

• Points to the next leaf node

• Used for sequential scans

• Enables ORDER BY queries

Backward Pointer

• Points to the previous leaf

• Enables reverse scans

• Bidirectional traversal

Range Query Efficiency

Without leaf linking, a range query would require traversing the tree for every key in the range — O(k × log n). With leaf linking, after finding the first key, we simply follow the linked list: O(log n + k).

Range Query Complexity
O(log_t(n) + k)
Where n = total keys, k = number of results. The log n part finds the starting leaf; the k part scans the linked list.
Example: Range Query [12, 35]

Step 1: Search for key 12 → traverse tree, reach leaf [8, 12, 15]

Step 2: Follow leaf links forward, collecting all keys ≤ 35:

  • [8, 12, 15] → keep 12, 15
  • [20, 25] → keep 20, 25
  • [30, 35, 40] → keep 30, 35 (stop at 35)

Result: 12, 15, 20, 25, 30, 35 — scanned 3 leaf nodes, no tree traversal needed!

Leaf Splitting During Insertion

When a leaf node overflows (exceeds 2t - 1 keys), it splits into two leaves. The middle key is copied up (not promoted) to the parent. The two resulting leaves are re-linked in the doubly linked list.

Copy Up vs. Push Up

Leaf split: The key is copied up — it remains in the leaf AND appears in the parent.

Internal split: The key is pushed up — it is moved (not copied) to the parent.

Leaf Split Example (t = 2, max 3 keys per leaf)

Before: Leaf [5, 8, 12, 15] — overflow (4 keys > max 3)

// Split leaf at middle key (index = ceil(4/2) = 2) Left leaf: [5, 8] // first half Right leaf: [12, 15] // second half Copied up: 12 // middle key goes to parent // Leaf links updated: [5,8] ↔ [12,15] ↔ [next leaf]

Insertion Algorithm

Insertion in a B+ Tree follows these steps: find the correct leaf, insert the key, and split nodes if overflow occurs.

function BPlusTreeInsert(tree, key, data): // Step 1: Find the correct leaf node leaf = findLeaf(tree.root, key) // Step 2: Insert key into leaf in sorted order insertIntoLeaf(leaf, key, data) // Step 3: Check for overflow if leaf.numKeys > MAX_LEAF_KEYS: splitLeaf(leaf) function splitLeaf(leaf): // Create new leaf newLeaf = createLeaf() // Split: first half stays, second half moves to new leaf mid = ceil(leaf.numKeys / 2) for i = mid to leaf.numKeys: moveKey(leaf, newLeaf, i) // Copy middle key up to parent parentKey = newLeaf.keys[0] insertIntoParent(leaf.parent, parentKey, newLeaf) // Update leaf links newLeaf.next = leaf.next leaf.next = newLeaf newLeaf.prev = leaf

Internal Node Splitting

When an internal node overflows (exceeds 2t keys), it splits. The middle key is pushed up to the parent — it is NOT kept in the split node.

function splitInternal(node): // Create new internal node newNode = createInternal() // Middle key pushes up to parent mid = ceil(node.numKeys / 2) pushUpKey = node.keys[mid] // Split: first half stays, second half moves for i = mid+1 to node.numKeys: moveKeyAndChild(node, newNode, i) node.numKeys = mid // remove middle key from node // Insert pushed-up key into parent insertIntoParent(node.parent, pushUpKey, newNode)
Copy Up vs Push Up — Critical Difference

Leaf split → Copy Up: The middle key is copied to the parent AND stays in the right leaf.

Internal split → Push Up: The middle key is moved to the parent and does NOT remain in either child node.

Root Splitting

If the root node overflows, a new root is created. This is the only case where the tree grows taller.

function splitRoot(root): newRoot = createInternal() newNode = createInternal() mid = ceil(root.numKeys / 2) pushUpKey = root.keys[mid] // Move second half to newNode for i = mid+1 to root.numKeys: moveKeyAndChild(root, newNode, i) root.numKeys = mid // New root gets the pushed-up key newRoot.keys[0] = pushUpKey newRoot.children[0] = root newRoot.children[1] = newNode root.parent = newRoot newNode.parent = newRoot tree.root = newRoot // tree grows taller

Worked Example 1: Basic B+ Tree (t=2)

Build a B+ Tree with t=2 by inserting keys: 10, 20, 30, 40, 50

Step-by-Step Insertion
// Insert 10: Root: [10] // Insert 20: Root: [10, 20] // Insert 30: Root: [10, 20, 30] // Insert 40: Root overflows (4 keys > max 2t-1=3 for leaf root) // Split leaf, copy up middle key [30] / \ [10|20] [30|40] // 30 copied up AND stays in right leaf // Insert 50: Goes to right leaf [30] / \ [10|20] [30|40|50]

Worked Example 2: Internal Split (t=2)

Continue from Example 1. Insert 60, 70, 80:

Step-by-Step
// Insert 60: Right leaf overflows [30 | 50] // 50 copied up / | \ [10|20] [30|40] [50|60] // Insert 70: Goes to last leaf [30 | 50] / | \ [10|20] [30|40] [50|60|70] // Insert 80: Last leaf overflows → split → internal may overflow [30 | 50 | 70] / | | \ [10|20] [30|40] [50|60] [70|80]

Worked Example 3: Search Operation

Search for key 50 in this tree:

Search Path
Tree: [30 | 50 | 70] / | | \ [10|20] [30|40] [50|60] [70|80] // Step 1: Start at root, compare 50 with keys 50 ≥ 50, so go to 3rd child // Step 2: At intermediate node [30|50|70] 50 ≥ 50, so go to child after 50 // Step 3: Reach leaf [50, 60] Found 50! Return data pointer // Total: 2 node accesses (height = 2)

Search complexity: O(log_t(n)) = O(log_2(n))

Worked Example 4: Range Query

Find all keys in range [25, 65]:

Range Query Execution
// Step 1: Search for lower bound 25 Root [30|50|70]: 25 < 30, go to 1st child Leaf [10,20]: 25 not found, but 25 > 20 → start from next leaf [30,40] // Step 2: Scan leaf linked list from [30,40] Leaf [30,40]: keep 30, 40 (both ≤ 65) Leaf [50,60]: keep 50, 60 (both ≤ 65) Leaf [70,80]: 70 > 65 → STOP // Result: 30, 40, 50, 60 // Accessed: 1 root + 1 leaf (search) + 3 leaves (scan) = 5 nodes

Range query: O(log_t(n) + k) where k = number of results

Worked Example 5: Deletion

Delete key 30 from the tree:

Deletion Process
Before: [30 | 50 | 70] / | | \ [10|20] [30|40] [50|60] [70|80] // Step 1: Find and remove 30 from leaf Leaf becomes: [40] Still valid (≥ t-1 = 1 key) → DONE After: [30 | 50 | 70] / | | \ [10|20] [40] [50|60] [70|80]

If the leaf had only 1 key and we deleted it, we'd need to merge or redistribute with siblings.

Quick Reference Card

  • ▸ Root: min 1 key, max 2t keys, min 2 children, max 2t children
  • ▸ Internal: min t keys, max 2t keys, min t+1 children, max 2t+1 children
  • ▸ Leaf: min t-1 keys, max 2t-1 keys, linked list, stores data
  • ▸ Leaf split → Copy Up (key stays in leaf AND goes to parent)
  • ▸ Internal split → Push Up (key moves to parent only)
  • ▸ Root split → tree grows taller (only time height increases)
  • ▸ Search: O(log_t(n)) — follow path from root to leaf
  • ▸ Range query: O(log_t(n) + k) — use leaf linked list
  • ▸ Insert: O(log_t(n)) — find leaf + possible splits
  • ▸ Delete: O(log_t(n)) — find leaf + possible merges
