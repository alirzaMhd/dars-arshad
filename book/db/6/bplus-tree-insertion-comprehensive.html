B+ TREE INSERTION ALGORITHM

Data Structures — Complete Guide for 20/20 Exam

B+ Tree Insertion Overview

A B+ Tree of order t has the following properties:

Node Capacity

• Each node has at most 2t - 1 keys

• Each node has at most 2t children

• Root has at least 1 key

Leaf Properties

• All leaves at same level

• Leaf contains data pointers

• Leaves linked via next pointers

7-Step Insertion Process

1 Find the Target Leaf

Start at the root. At each internal node, compare the key with index values to determine which child pointer to follow. Continue until you reach a leaf node.

Decision Rule:
If key < K₁, follow P₀
If Kᵢ ≤ key < Kᵢ₊₁, follow Pᵢ. If key ≥ Kₙ, follow Pₙ
↓
2 Insert Key into Leaf (Sorted Order)

Insert the new key into the leaf node while maintaining sorted order. Shift existing keys to make room for the new key.

Condition Check:
Leaf keys < 2t - 1 ?
If YES → insert and finish. If NO → proceed to step 3 (split)
↓
3 Detect Overflow (Node Full)

After insertion, if the leaf node has 2t - 1 keys, it is full. This triggers a split operation.

⚠ Critical Point
Overflow is detected AFTER insertion, not before. The node temporarily holds 2t keys before splitting.
↓
4 Split the Full Node

Create a new node. Distribute keys between the old node and the new node. Each node gets exactly t keys.

Split Rule for Leaf:
Left: keys[0..t-1] | Right: keys[t..2t-1]
The middle key stays in the right node (leaf split rule)
↓
5 Copy Middle Key to Parent

For leaf split: copy the middle key up to the parent. For internal split: move the middle key up (it's removed from the split node).

Leaf vs Internal Split:
Leaf: copy up | Internal: move up
Leaf keeps a copy; internal node doesn't keep the middle key
↓
6 Insert into Parent

Insert the promoted key and the new child pointer into the parent node. Maintain sorted order in the parent.

↓
7 Propagate Split Upward

If the parent overflows, repeat steps 4-6 for the parent. Continue propagating upward until no overflow occurs. If the root splits, create a new root (tree grows taller).

Termination:
Stop when no overflow occurs
Worst case: split propagates to root, creating new root (height increases by 1)

Insertion Pseudocode

1: function INSERT(root, key): 2: if root is NULL: 3: root = new LeafNode() 4: root.keys[0] = key 5: root.n = 1 6: return root 7: 8: // Step 1: Find the target leaf 9: leaf = FIND_LEAF(root, key) 10: 11: // Step 2: Check if key already exists 12: if key in leaf.keys: 13: return root // No duplicates 14: 15: // Step 3: Insert key in sorted order 16: i = leaf.n - 1 17: while i >= 0 and leaf.keys[i] > key: 18: leaf.keys[i+1] = leaf.keys[i] 19: i = i - 1 20: leaf.keys[i+1] = key 21: leaf.n = leaf.n + 1 22: 23: // Step 4: Check for overflow 24: if leaf.n == 2t - 1: 25: SPLIT_LEAF(leaf, key) 26: 27: return root

Split Functions Pseudocode

1: function SPLIT_LEAF(leaf, new_key): 2: // Create new right sibling 3: right = new LeafNode() 4: mid = t // Split position 5: 6: // Copy upper half to right node 7: for j from 0 to t - 1: 8: right.keys[j] = leaf.keys[mid + j] 9: right.n = t 10: right.next = leaf.next 11: leaf.next = right 12: leaf.n = t 13: 14: // Copy middle key UP to parent (not move) 15: parent_key = leaf.keys[mid] 16: INSERT_INTO_PARENT(leaf.parent, parent_key, right) 17: 18: 19: function SPLIT_INTERNAL(internal): 20: // Create new right sibling 21: right = new InternalNode() 22: mid = t - 1 // Split position 23: 24: // Move middle key UP (remove from split node) 22: parent_key = internal.keys[mid] 23: 24: // Copy upper half to right node 25: for j from 0 to t - 2: 26: right.keys[j] = internal.keys[mid + 1 + j] 27: right.n = t - 1 28: 29: // Copy upper child pointers 30: for j from 0 to t - 1: 31: right.children[j] = internal.children[mid + 1 + j] 32: internal.n = t - 1 33: 34: INSERT_INTO_PARENT(internal.parent, parent_key, right)

Helper Function: Insert into Parent

1: function INSERT_INTO_PARENT(parent, key, right_child): 2: if parent is NULL: 3: // Create new root 4: root = new InternalNode() 5: root.keys[0] = key 6: root.children[0] = left_child 7: root.children[1] = right_child 8: root.n = 1 9: return root 10: 11: // Insert key in sorted order 12: i = parent.n - 1 13: while i >= 0 and parent.keys[i] > key: 14: parent.keys[i+1] = parent.keys[i] 15: parent.children[i+2] = parent.children[i+1] 16: i = i - 1 17: parent.keys[i+1] = key 18: parent.children[i+2] = right_child 19: parent.n = parent.n + 1 20: 21: // Check for overflow 22: if parent.n == 2t - 1: 23: SPLIT_INTERNAL(parent)

Leaf Split vs Internal Node Split

🍃 Leaf Split Rule

• Split point: position t

• Left node: keys[0..t-1] → t keys

• Right node: keys[t..2t-1] → t keys

• Middle key: COPIED up (stays in right)

🏠 Internal Split Rule

• Split point: position t-1

• Left node: keys[0..t-2] → t-1 keys

• Right node: keys[t..2t-2] → t-1 keys

• Middle key: MOVED up (removed)

⚠ Common Mistake
Students often confuse "copy up" vs "move up". In leaf splits, the middle key is COPIED to the parent (leaf keeps a copy). In internal splits, the middle key is MOVED to the parent (internal node loses it).

⚠ Chain Split Warning
A single insertion can cause O(log_t n) splits if every ancestor is full. This is why B+ Trees remain balanced — splits propagate upward maintaining balance.

Quick Reference Card

B+ Tree Properties (order t)

• Max keys per node: 2t - 1
• Max children per node: 2t
• Min keys (non-root): t - 1
• Min children (non-root): t
• Root min keys: 1
• All leaves at same level: YES
• Keys in leaves: Sorted, linked
• Keys in internal: Copies for routing

Insertion Algorithm Summary

1. Find target leaf (traverse from root)
2. Insert key in sorted order
3. If overflow (2t-1 keys), split
4. Leaf split: copy middle up
5. Internal split: move middle up
6. Propagate splits upward
7. If root splits, create new root

Split Rules Cheat Sheet

Leaf split point: position t (0-indexed)
Leaf left keys: t keys [0..t-1]
Leaf right keys: t keys [t..2t-1]
Leaf middle key: COPIED up (stays in right)
Internal split point: position t-1
Internal left keys: t-1 keys [0..t-2]
Internal right keys: t-1 keys [t..2t-2]
Internal middle key: MOVED up (removed)

Complexity Quick Reference

• Insertion: O(t · log_t n)
• If t constant: O(log n)
• Space per key: O(1) in leaf
• Space per key: O(1) in internal (copy)
• Tree height: O(log_t n)
• Worst case splits: O(log_t n) per insert
⚠ Top 5 Exam Mistakes
1. Confusing "copy up" (leaf) vs "move up" (internal)
2. Wrong split position: t vs t-1
3. Forgetting to link leaf nodes after split
4. Not handling root split (create new root)
5. Confusing B+ Tree with B-Tree (B+ has all data in leaves)
