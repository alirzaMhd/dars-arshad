ENTITIES IN DATABASE DESIGN

Strong & Weak Entities — Complete Guide for Exam

What is an Entity?

Definition:
Entity = A thing or object in the real world that is distinguishable from all other objects
Entities can be tangible (Student, Car) or intangible (Course, Reservation)

Key Concepts

Entity Type

A collection of entities that share the same attributes

e.g., All Students are one entity type

Entity Set

The collection of all entities of a particular type at any point in time

e.g., All currently enrolled students

Strong Entity

Can exist independently, has its own key attribute

Notation: Rectangle

Example: Student Entity

Entity Type: Student

Attributes: Student_ID, Name, Major, GPA

Key Attribute: Student_ID (uniquely identifies each student)

Each student is a unique entity with distinct attribute values

Types of Entities

Strong vs Weak Entities

Feature Strong Entity Weak Entity
Existence Independent Dependent
Primary Key Has its own Does not have
Notation Rectangle Double Rectangle
Relationship Regular Diamond Double Diamond (Identifying)
Partial Key No Yes (dashed underline)
Example Employee, Student Dependent, Section
Weak Entity Formula:
Partial Key + Owner's Primary Key = Complete Identification
Weak entity needs owner entity to be uniquely identified
Identifying Relationship

The relationship connecting a weak entity to its owner is called the identifying relationship and is shown with a double diamond.

Examples & Common Mistakes

Example 1: University System

Strong Entities: Student, Course, Professor

Weak Entity: Section (depends on Course)

Relationship: Course --||----||-- Section (identifying)

Section cannot exist without Course. Section's partial key is Section_Number.

Example 2: Company System

Strong Entities: Employee, Department, Project

Weak Entity: Dependent (depends on Employee)

Relationship: Employee --||----||-- Dependent (identifying)

Dependent (family member) cannot exist without Employee.

Example 3: Hospital System

Strong Entities: Patient, Doctor, Department

All entities are strong - each can exist independently

Common Mistakes

Mistake 1

Confusing Entity Type with Entity Set. Entity Type is the definition; Entity Set is the actual collection of instances.

Mistake 2

Assuming all entities must have a primary key. Weak entities do NOT have their own primary key.

Mistake 3

Forgetting that weak entities have existence dependency. If owner is deleted, weak entity is also deleted.
