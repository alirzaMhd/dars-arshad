ATTRIBUTES IN DATABASE DESIGN

Types, Notation & Domains — Complete Guide for Exam

What is an Attribute?

Definition:
Attribute = A property or characteristic that describes an entity
Attributes store the actual data values for each entity instance

Key Concepts

Key Attribute

Uniquely identifies each entity

Notation: Underlined in ER diagram

e.g., Student_ID, SSN

Domain

The set of allowed values for an attribute

e.g., Age: Integer (0-150)

NULL Value

Missing or unknown value

Not the same as 0 or empty string

Attribute Types

Type Definition Example Notation
Simple Cannot be divided further Age, Gender Single Oval
Composite Can be divided into sub-parts Name → First, Last Oval with sub-ovals
Multi-valued Can have multiple values Phone_Numbers Double Oval
Derived Computed from other attributes Age (from DOB) Dashed Oval
Stored Value stored explicitly Date_of_Birth Single Oval
Key Uniquely identifies entity Student_ID Oval with underline
Derived Attribute Formula:
Age = Current_Year - Year_of_Birth
Derived attributes are computed, not stored directly

Domains & Constraints

Domain Types

Integer

Whole numbers

e.g., Age, Quantity

String

Text characters

e.g., Name, Address

Date

Calendar dates

e.g., Birth_Date

Boolean

True/False values

e.g., Is_Active

Constraint Types

  • NOT NULL: Attribute must have a value
  • UNIQUE: All values must be different
  • DEFAULT: Automatic value if none specified
  • CHECK: Value must satisfy a condition
NULL Pitfall

NULL is not 0, not empty string, not false. It means "unknown" or "not applicable". Be careful with NULL in comparisons!

Examples & Comparison

Example 1: Student Entity

Simple: Student_ID, Age, Gender

Composite: Name (First_Name, Middle_Name, Last_Name)

Multi-valued: Phone_Numbers

Derived: Age (from Date_of_Birth)

Key: Student_ID (underlined)

Example 2: Employee Entity

Composite: Address (Street, City, State, Zip)

Multi-valued: Skills

Derived: Years_of_Service (from Hire_Date)

Stored: Date_of_Birth (for computing Age)

Example 3: Product Entity

Key: Product_ID

Multi-valued: Colors, Sizes

Derived: In_Stock (from Quantity_On_Hand)

Common Mistakes

Mistake 1

Confusing Multi-valued with Composite. Multi-valued = multiple instances of same type; Composite = different types combined.

Mistake 2

Storing derived attributes when you can compute them. Only store if performance requires it.
