DATABASE DESIGN OVERVIEW

Entity-Relationship Modeling — Complete Guide for Exam

What is Database Design?

Definition:
Database Design = Process of producing a detailed data model of a database
The logical structure of the database that satisfies user information requirements

Three-Level Schema Architecture

External Level

User views and interfaces

How users see the data

Conceptual Level

Entire database structure

What data is stored & relationships

Internal Level

Physical storage details

How data is actually stored

Purpose of Database Design

  • Minimize data redundancy (duplicate data)
  • Ensure data integrity and consistency
  • Optimize query performance
  • Support multiple user views
  • Enforce business rules and constraints

ER Model Overview

ER Model (Peter Chen, 1976):
Entities + Attributes + Relationships = ER Diagram
Conceptual model for database design, implementation-independent

Three Main Components

Entities

Objects in real world

Notation: Rectangle

e.g., Student, Course, Employee

Attributes

Properties of entities

Notation: Oval

e.g., Name, Age, ID

Relationships

Associations between entities

Notation: Diamond

e.g., Enrolls_In, Works_For

Common Exam Mistake

ER model is conceptual and implementation-independent. It can be converted to any DBMS (Relational, Object, etc.)

Design Process Steps

Step-by-Step Database Design Process
  1. Gather Requirements: Interview users, understand business rules
  2. Identify Entities: Find objects (Student, Course, etc.)
  3. Identify Attributes: Properties of each entity (Name, ID, etc.)
  4. Determine Relationships: How entities relate (Enrolls_In, Teaches, etc.)
  5. Draw ER Diagram: Visual representation of the design
  6. Verify with Users: Check if design meets requirements
  7. Convert to Relational Schema: Map ER to tables
  8. Implement in DBMS: Create actual database
Key Point

Steps 1-6 are Conceptual Design (ER Model). Steps 7-8 are Logical/Physical Design (Relational Model).

Examples & Comparison

Example 1: University System

Entities: Student, Course, Professor, Department

Relationships: Student Enrolls_In Course, Professor Teaches Course, Professor Works_In Department

Each entity has attributes: Student(Name, ID, Major), Course(Code, Title, Credits), etc.

Example 2: Hospital System

Entities: Patient, Doctor, Department, Appointment

Relationships: Doctor Treats Patient, Doctor Works_In Department, Patient Has Appointment

Comparison of Database Models

Model Structure Complexity Use Case
ER Model Entities, Relationships Simple Conceptual Design
Relational Tables (Rows, Columns) Moderate Most DBMS
Hierarchical Tree Structure Complex Legacy Systems
Network Graph Structure Complex Complex Relationships
