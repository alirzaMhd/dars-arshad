Entity Symbols

Entity Notation

Strong Entity

ENTITY

Single rectangle

Weak Entity

WEAK ENTITY

Double rectangle

Examples

Strong: Student, Course, Employee, Department

Weak: Dependent (of Employee), Section (of Course)

Key Point

Weak entities always have an identifying relationship (double diamond) connecting them to their owner entity.

Complete ER Diagram Examples

Example 1: University System

Entities: Student (rectangle), Course (rectangle), Professor (rectangle)

Attributes: Student_ID (underline), Name, Course_Code (underline), Title

Relationships:

  • Student --Enrolls_In-- Course (m:n, with Grade attribute)
  • Professor --Teaches-- Course (1:n)
Example 2: Hospital System

Entities: Patient, Doctor, Department

Relationships:

  • Doctor --Treats-- Patient (m:n)
  • Doctor --Works_In-- Department (n:1)
Example 3: Company System (with Weak Entity)

Entities: Employee (rectangle), Department (rectangle), Dependent (double rectangle)

Relationships:

  • Employee --Works_In-- Department (n:1)
  • Employee --Has-- Dependent (identifying, 1:n)

Dependent is a weak entity with partial key Dependent_Name

Step-by-Step: Drawing ER Diagrams

  1. Identify all entities (rectangles)
  2. Identify all attributes (ovals)
  3. Mark key attributes (underline)
  4. Identify relationships (diamonds)
  5. Connect entities to relationships (lines)
  6. Add cardinality labels (1, n, m)
  7. Mark participation (single/double lines)
  8. Identify weak entities (double rectangles)
Common Mistakes

1. Forgetting to underline key attributes

2. Not using double lines for total participation

3. Confusing entity attributes with relationship attributes

4. Not marking weak entities with double rectangles
