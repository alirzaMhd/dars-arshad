WEAK ENTITIES

Existence Dependency & Partial Keys — Complete Guide for Exam

What is a Weak Entity?

Definition:
Weak Entity = An entity that cannot be uniquely identified by its own attributes alone
Depends on an identifying (owner) entity for existence and identification

Key Concepts

Owner Entity

The strong entity on which the weak entity depends

e.g., Employee (for Dependent)

Partial Key

Attribute that uniquely identifies within the owner entity

e.g., Dependent_Name (for Employee's dependents)

Identifying Relationship

Connection between weak and owner entity

Notation: Double Diamond

Classic Example: Employee → Dependent

Weak Entity: Dependent (family member of employee)

Owner Entity: Employee

Partial Key: Dependent_Name

Why weak? Two employees can have dependents with the same name. Need Employee_ID to uniquely identify.

Characteristics of Weak Entities

Key Characteristics

  • No primary key of its own - cannot be uniquely identified alone
  • Has a partial key (discriminator) - shown with dashed underline in ER
  • Existence dependency - cannot exist without the owner entity
  • Cascading delete - if owner is deleted, weak entity is also deleted
  • Double rectangle notation in ER diagrams
  • Double diamond for identifying relationship
Complete Identification:
Partial Key + Owner's Primary Key = Complete Identification
e.g., Dependent_Name + Employee_ID uniquely identifies a dependent
Existence Dependency

Weak entities have TOTAL participation in the identifying relationship. They MUST be connected to an owner entity.

Weak vs Strong Entities

Feature Strong Entity Weak Entity
Primary Key Has its own Does not have
Existence Independent Dependent
Notation Rectangle Double Rectangle
Relationship Regular Diamond Double Diamond (Identifying)
Partial Key No Yes (dashed underline)
Deletion Can exist without related Cannot exist without owner
Example Employee, Student Dependent, Section
Golden Rule

If an entity cannot be uniquely identified without referencing another entity, it is a weak entity.

Examples & Conversion

Example 1: Employee → Dependent

Weak Entity: Dependent

Owner: Employee

Partial Key: Dependent_Name

Relational: Dependent(Employee_ID, Dependent_Name, Relationship, Age)

Example 2: Course → Section

Weak Entity: Section

Owner: Course

Partial Key: Section_Number

Relational: Section(Course_ID, Section_Number, Semester, Instructor)

Example 3: Building → Room

Weak Entity: Room

Owner: Building

Partial Key: Room_Number

Relational: Room(Building_ID, Room_Number, Capacity, Type)

Example 4: Order → Order_Item

Weak Entity: Order_Item

Owner: Order

Partial Key: Item_Number

Relational: Order_Item(Order_ID, Item_Number, Product_ID, Quantity, Price)

Common Mistakes

Mistake 1

Confusing weak entity with many-to-one relationship. Weak entity has existence dependency and partial key.

Mistake 2

Forgetting to include owner's PK in weak entity's primary key during relational conversion.
