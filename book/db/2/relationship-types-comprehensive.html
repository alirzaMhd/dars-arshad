RELATIONSHIP TYPES

Cardinality Ratios (1:1, 1:n, m:n) — Complete Guide for Exam

One-to-One (1:1) Relationships

Definition:
Each instance of A is associated with at most one instance of B, and vice versa
Notation: 1 ---- 1 or (1,1)

Real-World Examples

Person ↔ Passport

Each person has one passport

Each passport belongs to one person

Employee ↔ Department

Each department has one manager

Each manager manages one department

Student ↔ Student_ID

Each student has one ID

Each ID belongs to one student

Relational Conversion:
Option 1: Merge into one table
Option 2: Foreign key with UNIQUE constraint

One-to-Many (1:n) Relationships

Definition:
Entity A can be associated with many instances of B, but each B is associated with at most one A
Notation: 1 ---- n or (1,n)

Real-World Examples

Department → Employees

One department has many employees

Each employee works in one department

Customer → Orders

One customer places many orders

Each order belongs to one customer

Author → Books

One author writes many books

Each book has one author (simplified)

Relational Conversion:
Foreign key in the "many" side table
Employee table gets Department_ID as FK

Many-to-Many (m:n) Relationships

Definition:
Each instance of A can be associated with many instances of B, and vice versa
Notation: m ---- n or (m,n)

Real-World Examples

Student ↔ Course

Student enrolls in many courses

Course has many students

Doctor ↔ Patient

Doctor treats many patients

Patient has many doctors

Actor ↔ Movie

Actor acts in many movies

Movie has many actors

Relational Conversion:
Create a new junction/bridge table
Enrollment(Student_ID, Course_ID, Grade)
Important

Always create a junction table for m:n relationships. Never try to put a foreign key in one of the entity tables.

Examples & Comparison

Example 1: University System

Student Enrolls_In Course: m:n (many students, many courses)

Student Has_One Advisor: 1:n (one advisor, many students)

Department Has_One Head: 1:1 (one head, one department)

Example 2: Company System

Employee Works_In Department: n:1 (many employees, one department)

Employee Manages Department: 1:1 (one manager per department)

Employee Works_On Project: m:n (many employees, many projects)

Quick Decision Guide

How to determine relationship type:
Read both directions: "A has [how many] B" AND "B has [how many] A"
1:1 = one on both sides, 1:n = one then many, m:n = many on both
Exam Tip

When in doubt, write out the business rules. "Each student can take many courses, and each course can have many students" = m:n.
