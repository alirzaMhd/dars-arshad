DDL Commands (CREATE, ALTER, DROP)

1. CREATE DATABASE

Creates a new database container for tables, views, and other objects.

CREATE DATABASE SchoolDB;

2. CREATE TABLE

Creates a new table with specified columns and constraints.

2.1 Syntax

CREATE TABLE TableName (
    Column1    DataType    [Constraints],
    Column2    DataType    [Constraints],
    ...
    TableConstraints
);
Example 1 — Full CREATE TABLE
CREATE TABLE Employees (
    EmpID       INT         PRIMARY KEY,
    FirstName   VARCHAR(30) NOT NULL,
    LastName    VARCHAR(30) NOT NULL,
    Salary      DECIMAL(10,2) DEFAULT 0.00,
    HireDate    DATE        DEFAULT CURRENT_DATE,
    DeptID      INT,
    CONSTRAINT fk_dept FOREIGN KEY (DeptID) REFERENCES Departments(DeptID)
        ON DELETE SET NULL
        ON UPDATE CASCADE
);

3. Constraints

3.1 Constraint Types

ConstraintPurposeExample
PRIMARY KEYUnique identifier for each rowID INT PRIMARY KEY
FOREIGN KEYLinks to another table's PKDeptID INT REFERENCES Departments(DeptID)
NOT NULLColumn cannot be emptyName VARCHAR(50) NOT NULL
UNIQUEAll values in column are differentEmail VARCHAR(100) UNIQUE
CHECKValues must satisfy conditionCHECK (Age >= 18)
DEFAULTDefault value if none specifiedStatus VARCHAR(10) DEFAULT 'Active'

3.2 Foreign Key ON DELETE / ON UPDATE Actions

ActionBehavior
CASCADEDelete/update referencing rows automatically
SET NULLSet foreign key to NULL in referencing rows
SET DEFAULTSet foreign key to its default value
NO ACTIONReject the delete/update (default)
Example 2 — Foreign Key Actions
-- When DeptID is deleted from Departments:
-- All employees in that dept get DeptID set to NULL
FOREIGN KEY (DeptID) REFERENCES Departments(DeptID)
    ON DELETE SET NULL
    ON UPDATE CASCADE;

3.3 Composite Primary Key

CREATE TABLE Enrollment (
    StudentID   INT,
    CourseID    INT,
    Grade       DECIMAL(3,2),
    PRIMARY KEY (StudentID, CourseID)
);
A table can have only ONE PRIMARY KEY, but it can have MULTIPLE UNIQUE constraints. Primary key cannot contain NULL values.

4. CREATE VIEW

Creates a virtual table based on a SELECT query. The data is not stored physically — it's computed when accessed.

4.1 Syntax

CREATE VIEW ViewName AS
SELECT columns
FROM tables
WHERE conditions;
Example 3 — Simple View
CREATE VIEW HighGPA_Students AS
SELECT StudentID, Name, GPA
FROM Students
WHERE GPA > 3.5;

-- Use the view like a table
SELECT * FROM HighGPA_Students;
Example 4 — View with JOIN
CREATE VIEW StudentCourseInfo AS
SELECT S.Name, C.CourseName, E.Grade
FROM Students S
JOIN Enrollment E ON S.StudentID = E.StudentID
JOIN Courses C ON E.CourseID = C.CourseID;

SELECT * FROM StudentCourseInfo WHERE Grade > 3.0;
Views are updatable only if:
• Based on a single table
• No aggregate functions (SUM, COUNT, etc.)
• No DISTINCT, GROUP BY, HAVING
• No joins (in most systems)
• No subqueries in SELECT list

5. CREATE INDEX

Creates an index to speed up data retrieval. Indexes are used by the database engine to find data quickly.

5.1 Types

TypeSyntaxPurpose
Unique IndexCREATE UNIQUE INDEX idx ON T(col)Enforces uniqueness
Non-unique IndexCREATE INDEX idx ON T(col)Speeds up searches
Composite IndexCREATE INDEX idx ON T(col1, col2)Multi-column search
Example 5 — Create Index
-- Speed up searches on LastName
CREATE INDEX idx_lastname ON Employees(LastName);

-- Unique constraint via index
CREATE UNIQUE INDEX idx_email ON Employees(Email);

6. ALTER TABLE

Modifies an existing table structure.

6.1 Operations

OperationSyntax
Add columnALTER TABLE T ADD ColName DataType;
Drop columnALTER TABLE T DROP COLUMN ColName;
Modify columnALTER TABLE T ALTER COLUMN ColName NewType;
Add constraintALTER TABLE T ADD CONSTRAINT Name CHECK(...);
Drop constraintALTER TABLE T DROP CONSTRAINT Name;
Example 6 — ALTER TABLE Operations
ALTER TABLE Employees ADD PhoneNumber VARCHAR(15);
ALTER TABLE Employees DROP COLUMN PhoneNumber;
ALTER TABLE Employees ALTER COLUMN FirstName VARCHAR(50);
ALTER TABLE Employees ADD CONSTRAINT chk_salary CHECK (Salary > 0);

7. DROP TABLE vs TRUNCATE TABLE

FeatureDROP TABLETRUNCATE TABLE
RemovesStructure + DataData only
StructureGonePreserved
WHERE clauseN/ANot allowed
RollbackNoSome systems: yes
TriggersNoNo
Identity resetN/AYes (counter resets)
Example 7 — DROP vs TRUNCATE
DROP TABLE Students;       -- table no longer exists
TRUNCATE TABLE Students;   -- table exists, but empty

8. CREATE ASSERTION (SQL Standard)

Creates a named constraint that can span multiple tables.

CREATE ASSERTION CheckSalaryRange
CHECK (
    NOT EXISTS (
        SELECT * FROM Employees WHERE Salary < 0 OR Salary > 1000000
    )
);

9. CREATE DOMAIN

Creates a named data type with constraints.

CREATE DOMAIN EmailType AS VARCHAR(100)
CHECK (VALUE LIKE '%@%.%');

-- Use the domain
CREATE TABLE Contacts (
    Email EmailType
);

10. CREATE TYPE

Creates a composite (structured) data type.

CREATE TYPE Address AS (
    Street  VARCHAR(100),
    City    VARCHAR(50),
    ZipCode VARCHAR(10)
);

-- Use the type
CREATE TABLE Customers (
    Name    VARCHAR(50),
    Home    Address,
    Work    Address
);

12. Exam Tips

Key points for exams:
• One table can have only ONE PRIMARY KEY
• PRIMARY KEY = NOT NULL + UNIQUE
• FOREIGN KEY can reference any UNIQUE column (not just PK)
• ON DELETE CASCADE deletes child rows when parent is deleted
• ON DELETE SET NULL sets FK to NULL when parent is deleted
• Views are virtual tables (no physical storage)
• TRUNCATE ≠ DROP (structure preserved in TRUNCATE)
• CREATE INDEX speeds up SELECT but slows down INSERT/UPDATE
