SQL Constraints

1. Overview

Constraints enforce rules on data to maintain referential integrity and data quality. They prevent invalid data from being inserted into the database.

ConstraintEnforcesNULL Allowed?
PRIMARY KEYUnique identifierNo
FOREIGN KEYReferential integrityYes (unless NOT NULL)
NOT NULLColumn cannot be emptyNo
UNIQUEAll values differentYes (one NULL in most systems)
CHECKValues satisfy conditionDepends on condition
DEFAULTDefault value if none specifiedN/A

2. PRIMARY KEY

Uniquely identifies each row in a table. A table can have only one primary key.

2.1 Rules

  • Must be UNIQUE
  • Cannot contain NULL values
  • Only one per table
  • Can be single column or composite (multiple columns)
Example 1 — Single Column PK
CREATE TABLE Students (
    StudentID   INT PRIMARY KEY,
    Name        VARCHAR(50)
);
Example 2 — Composite PK
CREATE TABLE Enrollment (
    StudentID   INT,
    CourseID    INT,
    Grade       DECIMAL(3,2),
    PRIMARY KEY (StudentID, CourseID)
);
-- A student can enroll in many courses, but only once per course
Example 3 — Named PK Constraint
CREATE TABLE Employees (
    EmpID       INT,
    Name        VARCHAR(50),
    CONSTRAINT pk_employee PRIMARY KEY (EmpID)
);

3. FOREIGN KEY

Links a column in one table to the PRIMARY KEY (or UNIQUE) of another table. Enforces referential integrity.

3.1 Rules

  • Referenced column must be PRIMARY KEY or UNIQUE
  • Foreign key can have duplicate values
  • Foreign key can be NULL (unless NOT NULL specified)
  • Referenced table must exist before FK is created
Example 4 — Foreign Key
CREATE TABLE Orders (
    OrderID     INT PRIMARY KEY,
    CustomerID  INT,
    OrderDate   DATE,
    FOREIGN KEY (CustomerID) REFERENCES Customers(CustomerID)
);

3.2 ON DELETE / ON UPDATE Actions

ActionON DELETEON UPDATE
CASCADEDelete child rows when parent deletedUpdate child rows when parent updated
SET NULLSet FK to NULL when parent deletedSet FK to NULL when parent updated
SET DEFAULTSet FK to default when parent deletedSet FK to default when parent updated
NO ACTIONReject delete (default)Reject update (default)
Example 5 — FK with Actions
CREATE TABLE Orders (
    OrderID     INT PRIMARY KEY,
    CustomerID  INT,
    FOREIGN KEY (CustomerID) REFERENCES Customers(CustomerID)
        ON DELETE CASCADE
        ON UPDATE CASCADE
);
-- If CustomerID=5 is deleted from Customers,
-- all orders with CustomerID=5 are also deleted
Example 6 — FK with SET NULL
CREATE TABLE Employees (
    EmpID       INT PRIMARY KEY,
    DeptID      INT,
    FOREIGN KEY (DeptID) REFERENCES Departments(DeptID)
        ON DELETE SET NULL
);
-- If DeptID=3 is deleted, employees in that dept get DeptID=NULL
ON DELETE CASCADE is dangerous — deleting a parent can delete thousands of child rows. Use SET NULL or NO ACTION when in doubt.

4. NOT NULL

Prevents NULL values in a column. Every row must have a value.

Example 7 — NOT NULL
CREATE TABLE Users (
    UserID      INT PRIMARY KEY,
    Username    VARCHAR(30) NOT NULL,
    Email       VARCHAR(100) NOT NULL,
    Bio         TEXT          -- CAN be NULL
);
PRIMARY KEY = NOT NULL + UNIQUE (always)

5. UNIQUE

Ensures all values in a column (or combination of columns) are different.

5.1 Rules

  • Allows NULL values (most systems allow one NULL)
  • Multiple UNIQUE constraints per table allowed
  • Can be single column or composite
Example 8 — UNIQUE
CREATE TABLE Employees (
    EmpID       INT PRIMARY KEY,
    Email       VARCHAR(100) UNIQUE,
    SSN         CHAR(11) UNIQUE,
    Phone       VARCHAR(15)
);

6. CHECK

Ensures values satisfy a specific condition. If the condition evaluates to FALSE, the row is rejected.

Example 9 — CHECK Constraints
CREATE TABLE Students (
    StudentID   INT PRIMARY KEY,
    Name        VARCHAR(50),
    Age         INT CHECK (Age >= 18 AND Age <= 120),
    GPA         DECIMAL(3,2) CHECK (GPA >= 0 AND GPA <= 4.0),
    Email       VARCHAR(100) CHECK (Email LIKE '%@%.%')
);
Example 10 — Named CHECK
CREATE TABLE Products (
    ProductID   INT PRIMARY KEY,
    Price       DECIMAL(10,2),
    Quantity    INT,
    CONSTRAINT chk_price CHECK (Price > 0),
    CONSTRAINT chk_quantity CHECK (Quantity >= 0)
);
CHECK constraints are not supported by all databases (e.g., MySQL ignores them until version 8.0.16). Always check your DBMS documentation.

7. DEFAULT

Provides a default value when none is specified during INSERT.

Example 11 — DEFAULT
CREATE TABLE Orders (
    OrderID     INT PRIMARY KEY,
    OrderDate   DATE DEFAULT CURRENT_DATE,
    Status      VARCHAR(20) DEFAULT 'Pending',
    Priority    INT DEFAULT 0
);

8. Constraint Naming Best Practice

Always name your constraints for easier maintenance:

Example 12 — Named Constraints
CREATE TABLE Employees (
    EmpID       INT,
    Name        VARCHAR(50) NOT NULL,
    Email       VARCHAR(100),
    DeptID      INT,
    Salary      DECIMAL(10,2),
    
    CONSTRAINT pk_employee PRIMARY KEY (EmpID),
    CONSTRAINT uq_email UNIQUE (Email),
    CONSTRAINT fk_department FOREIGN KEY (DeptID) 
        REFERENCES Departments(DeptID)
        ON DELETE SET NULL,
    CONSTRAINT chk_salary CHECK (Salary > 0)
);

9. Complete Example Schema

Example 13 — Full Schema with All Constraints
CREATE TABLE Customers (
    CustomerID  INT PRIMARY KEY,
    Name        VARCHAR(50) NOT NULL,
    Email       VARCHAR(100) UNIQUE NOT NULL,
    Phone       VARCHAR(15),
    CreatedAt   TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE Products (
    ProductID   INT PRIMARY KEY,
    Name        VARCHAR(100) NOT NULL,
    Price       NUMERIC(10,2) NOT NULL CHECK (Price > 0),
    Stock       INT DEFAULT 0 CHECK (Stock >= 0)
);

CREATE TABLE Orders (
    OrderID     INT PRIMARY KEY,
    CustomerID  INT NOT NULL,
    ProductID   INT NOT NULL,
    Quantity    INT NOT NULL CHECK (Quantity > 0),
    OrderDate   DATE DEFAULT CURRENT_DATE,
    
    FOREIGN KEY (CustomerID) REFERENCES Customers(CustomerID)
        ON DELETE CASCADE,
    FOREIGN KEY (ProductID) REFERENCES Products(ProductID)
        ON DELETE RESTRICT,
    
    UNIQUE (CustomerID, ProductID, OrderDate)
);

10. Exam Tips

Key points for exams:
• PRIMARY KEY = NOT NULL + UNIQUE
• One PK per table, multiple UNIQUE constraints
• FOREIGN KEY references PK or UNIQUE column
• ON DELETE CASCADE deletes children when parent is deleted
• ON DELETE SET NULL sets FK to NULL when parent is deleted
• CHECK validates values against a condition
• DEFAULT provides value when none specified
• NULLs are allowed in UNIQUE columns (one per column)
