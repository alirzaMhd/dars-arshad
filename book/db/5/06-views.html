SQL Views

1. What is a View?

A view is a virtual table based on the result set of a SELECT statement. It contains no data itself — data is fetched from underlying tables when the view is queried.

View = Stored SELECT query that appears as a table
Base Table = The actual table(s) the view references

2. CREATE VIEW Syntax

CREATE VIEW ViewName [(Column1, Column2, ...)] AS
SELECT columns
FROM tables
[WHERE conditions]
[GROUP BY columns]
[HAVING conditions];
Example 1 — Simple View
CREATE VIEW HighGPA_Students AS
SELECT StudentID, Name, GPA
FROM Students
WHERE GPA > 3.5;

-- Query the view like a table
SELECT * FROM HighGPA_Students;
Example 2 — View with Column Aliases
CREATE VIEW StudentSummary (Student, Course, GradePoints) AS
SELECT S.Name, C.CourseName, E.Grade
FROM Students S
JOIN Enrollment E ON S.StudentID = E.StudentID
JOIN Courses C ON E.CourseID = C.CourseID;

SELECT * FROM StudentSummary WHERE GradePoints > 3.0;

3. View with JOINs

Example 3 — Multi-Table View
CREATE VIEW EmployeeDepartment AS
SELECT 
    E.Name AS EmployeeName,
    E.Salary,
    D.DeptName AS Department,
    D.Location
FROM Employees E
JOIN Departments D ON E.DeptID = D.DeptID;

SELECT * FROM EmployeeDepartment WHERE Location = 'Tehran';
Example 4 — View with Aggregation
CREATE VIEW DeptStats AS
SELECT 
    DeptID,
    COUNT(*) AS EmployeeCount,
    AVG(Salary) AS AvgSalary,
    MAX(Salary) AS MaxSalary
FROM Employees
GROUP BY DeptID;

SELECT * FROM DeptStats WHERE AvgSalary > 50000;

4. Modifying Data Through Views

4.1 INSERT Through Views

You can INSERT data through a view if:

  • The view is based on a single table
  • The view includes all NOT NULL columns without defaults
  • No aggregate functions, GROUP BY, HAVING, DISTINCT
Example 5 — Insert Through View
CREATE VIEW CS_Students AS
SELECT StudentID, Name, Major, GPA
FROM Students
WHERE Major = 'CS';

-- This works (single table, all required columns)
INSERT INTO CS_Students (StudentID, Name, Major, GPA)
VALUES (101, 'Reza', 'CS', 3.7);

-- This may fail (missing NOT NULL column)
INSERT INTO CS_Students (StudentID, Name)
VALUES (102, 'Maryam');  -- Error: Major is NOT NULL

4.2 UPDATE Through Views

Example 6 — Update Through View
-- Update GPA for CS students
UPDATE CS_Students 
SET GPA = 3.9 
WHERE StudentID = 101;

-- This updates the underlying Students table

4.3 DELETE Through Views

Example 7 — Delete Through View
DELETE FROM CS_Students WHERE StudentID = 101;

-- Deletes from underlying Students table

5. Updatable vs Non-Updatable Views

UpdatableNon-Updatable
Based on single tableBased on multiple tables (JOIN)
No aggregate functionsHas SUM, COUNT, AVG, etc.
No GROUP BY / HAVINGUses GROUP BY or HAVING
No DISTINCTUses DISTINCT
No subqueries in SELECTHas subqueries in SELECT list
All NOT NULL cols includedMissing required columns
JOIN views are generally NOT updatable in most database systems. You can READ from them, but not INSERT/UPDATE/DELETE.

6. DROP VIEW

DROP VIEW ViewName;

Removing a view does not affect the underlying tables.

7. REPLACE / ALTER VIEW

-- Some systems support CREATE OR REPLACE
CREATE OR REPLACE VIEW HighGPA_Students AS
SELECT StudentID, Name, GPA, Major
FROM Students
WHERE GPA > 3.5;

-- Others require ALTER
ALTER VIEW HighGPA_Students AS
SELECT StudentID, Name, GPA, Major
FROM Students
WHERE GPA > 3.5;

8. WITH CHECK OPTION

Ensures that INSERT/UPDATE through the view only affects rows that satisfy the view's WHERE clause.

Example 8 — WITH CHECK OPTION
CREATE VIEW HighSalary_Employees AS
SELECT EmpID, Name, Salary
FROM Employees
WHERE Salary > 50000
WITH CHECK OPTION;

-- This FAILS (new salary would not be visible in view)
INSERT INTO HighSalary_Employees (EmpID, Name, Salary)
VALUES (1, 'Ali', 40000);  -- Error: violates CHECK OPTION

-- This works
UPDATE HighSalary_Employees 
SET Salary = 60000 
WHERE EmpID = 1;

9. Materialized Views

Unlike regular views, materialized views store the result physically. Useful for complex queries that run frequently.

FeatureRegular ViewMaterialized View
Data storageVirtual (no storage)Physical storage
Query speedRe-runs query each timeFaster (pre-computed)
Update speedAlways currentNeeds refresh
Use caseSimple queriesComplex aggregations
CREATE MATERIALIZED VIEW DeptStats_MV AS
SELECT DeptID, COUNT(*) AS EmpCount, AVG(Salary) AS AvgSal
FROM Employees
GROUP BY DeptID;

-- Refresh when data changes
REFRESH MATERIALIZED VIEW DeptStats_MV;

10. Benefits of Views

  • Simplicity: Hide complex queries behind a simple name
  • Security: Restrict access to specific rows/columns
  • Consistency: Ensure consistent data access across applications
  • Independence: Application code doesn't break if table structure changes
Example 9 — Security View
-- Users can only see their own orders
CREATE VIEW UserOrders AS
SELECT OrderID, ProductID, Quantity
FROM Orders
WHERE CustomerID = CURRENT_USER_ID;

-- Application always queries the view, not the table

11. Exam Tips

Key points for exams:
• Views are virtual tables (no physical data stored)
• Views based on single tables are usually updatable
• JOIN views are generally NOT updatable
• WITH CHECK OPTION prevents rows outside the view's WHERE
• Materialized views store data physically
• DROP VIEW doesn't affect underlying tables
• Views simplify complex queries and enhance security
