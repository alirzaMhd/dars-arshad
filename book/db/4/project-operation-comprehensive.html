PROJECT OPERATION (π)

Database Systems — Projection Operation Complete Guide

What is Projection?

The Project operation (π) is a unary operation that selects specific attributes (columns) from a relation. It produces a vertical subset of the relation by discarding unwanted columns.

Definition:
π_L(R) = { t[L] | t ∈ R }
Returns tuples projected onto attribute list L from relation R
Notation:
π_A₁,A₂,...,Aₖ(R)
π is the project operator, A₁...Aₖ are the attributes to keep, R is the input relation

Characteristics

Unary Operation

Operates on single relation

Column Filter

Selects attributes (columns) not tuples

Vertical Subset

Produces a vertical subset of the relation

Duplicate Removal

May eliminate duplicates (set semantics)

Key Concepts

Duplicate Elimination

Relational algebra uses set semantics, meaning duplicates are automatically removed. This is different from SQL which uses bag semantics by default.

Duplicate Elimination Example

Given: Relation with City column: {C1, C2, C2, C3}

π_City(R): {C1, C2, C3} — duplicates removed

Attribute Ordering

The order of attributes in the result follows the order specified in the projection list.

Attribute Ordering
π_City,S#(R) — City first, then S#
π_S#,City(R) — S# first, then City

These produce relations with same data but different column ordering

Core Formulas

Projection Formula:
π_L(R) where L = list of attributes from R
Returns only the specified attributes from each tuple in R
Degree Property:
deg(π_L(R)) = |L| ≤ deg(R)
Degree of result equals number of projected attributes (≤ original degree)
Cardinality Property:
card(π_L(R)) ≤ card(R)
Cardinality can only decrease or stay the same (due to duplicate removal)

Idempotency

Idempotent Property:
π_L(π_L(R)) = π_L(R)
Projecting the same attributes twice produces the same result

Composition of Projections

Successive Projections:
π_L₂(π_L₁(R)) = π_L₂(R) where L₂ ⊆ L₁
When projecting, the second list must be a subset of the first
Equivalent Form:
π_L₁(π_L₂(R)) = π_L₂(R) where L₂ ⊆ L₁
The result is determined by the innermost projection's attribute list

Commutativity

Not Commutative (in general):
π_L₁(π_L₂(R)) ≠ π_L₂(π_L₁(R)) if L₁ ⊄ L₂
Order matters when attribute lists are different
Exception - Commutative When:
π_L₁(π_L₂(R)) = π_L₂(π_L₁(R)) if L₁ = L₂
Only when both lists are identical

Composition with Selection

Selection After Projection:
σ_q(π_L(R)) — condition q uses attributes in L
First project, then select from the result
Projection After Selection:
π_L(σ_q(R)) — condition q uses attributes in R (may include non-projected ones)
First select, then project from the result
Commutativity with Selection:
π_L(σ_q(R)) = σ_q(π_L(R)) if all attributes in q are in L
Can swap order when selection condition uses only projected attributes

Algorithm Pseudocode

Algorithm: PROJECT(R, attributeList)
Input: Relation R, list of attributes L = [A₁, A₂, ..., Aₖ]
Output: Relation with only attributes in L, no duplicates

result ← empty relation
result.schema ← L // new degree = |L|
seen ← empty set // for duplicate detection

FOR EACH tuple t IN R DO
  projected ← t[L] // extract attributes in L
  IF projected NOT IN seen THEN
    ADD projected TO result
    ADD projected TO seen
  END IF
END FOR

RETURN result

Time Complexity

O(n × k) where n = card(R), k = |L|

Must extract k attributes for each of n tuples

Space Complexity

O(m × k) where m = unique projected tuples

Worst case: O(n × k) if no duplicates

Common Mistakes:
1. Projection filters COLUMNS (attributes), not rows
2. Duplicates are automatically removed in relational algebra
3. Don't confuse π (Project) with σ (Select)
4. π_L₁(π_L₂(R)) requires L₁ ⊆ L₂, otherwise error

Composition of Select and Project

The real power of relational algebra comes from combining operations. Select and Project are commonly used together.

Case 1: Select then Project

Pattern:
π_L(σ_q(R))
First filter rows, then keep only certain columns
Example: Suppliers in Tehran - Names Only

Query: π_Sname(σ_City='Tehran'(SUPPLIER))

Step 1: σ_City='Tehran'(SUPPLIER) → {S1,Alpha,Tehran; S3,Gamma,Tehran}

Step 2: π_Sname → {Alpha; Gamma}

Result: {Alpha, Gamma}

Case 2: Project then Select

Pattern:
σ_q(π_L(R))
First keep certain columns, then filter rows from the result
Example: Filter on Projected Result

Query: σ_Sname='Alpha'(π_S#,Sname(SUPPLIER))

Step 1: π_S#,Sname(SUPPLIER) → {S1,Alpha; S2,Beta; S3,Gamma}

Step 2: σ_Sname='Alpha' → {S1,Alpha}

Result: {S1, Alpha}

When Can We Swap Order?

Commutativity Condition:
π_L(σ_q(R)) = σ_q(π_L(R)) if all attributes in q are in L
Only when selection condition uses attributes that exist in the projected relation
Example: Order Matters!

Query 1: π_S#(σ_City='Tehran'(SUPPLIER)) = {S1, S3}

Query 2: σ_City='Tehran'(π_S#(SUPPLIER)) = ERROR! (City not in projected relation)

Cannot select on City after projecting only S# — City attribute no longer exists!

Complex Composition Example

Example: Multiple Conditions

Query: Find S# of suppliers in Tehran with S# > 'S1'

π_S#(σ_City='Tehran' ∧ S#>'S1'(SUPPLIER))

Step 1: σ_City='Tehran' ∧ S#>'S1'(SUPPLIER) → {S3,Gamma,Tehran}

Step 2: π_S# → {S3}

Result: {S3}

Composition with Other Operations

Select on Union:
σ_q(R ∪ S) = σ_q(R) ∪ σ_q(S)
Project on Union:
π_L(R ∪ S) = π_L(R) ∪ π_L(S)
Both R and S must have same attributes in L
Select on Cartesian Product:
σ_q(R × S) where q may use attributes from both R and S
This is the basis for join operations
Example: Natural Join via Selection on Product

Join R(A,B) and S(B,C) on attribute B:

π_A,R.B,C(σ_R.B=S.B(R × S))

This is equivalent to the natural join R ⨝ S
