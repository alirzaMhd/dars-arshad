UNION OPERATION

Relational Algebra - Set Theory Foundation

Definition

The Union operation (denoted by ∪) combines two relations that share the same schema (same number of attributes with compatible domains). It returns all tuples that appear in either R₁, R₂, or both.

Formal Definition
R₃ = R₁ ∪ R₂
R₁ and R₂ must be union-compatible: same degree (number of attributes) and compatible domains for each attribute position.

The result relation R₃ contains every tuple that belongs to R₁, R₂, or both. Duplicate tuples are eliminated — the result is a set, not a multiset.

Requirements for Union

Same Degree
Both relations must have the same number of attributes
Compatible Domains
Corresponding attributes must have the same or compatible data types
Set Semantics
Duplicate tuples are removed in the result

Algorithm / Pseudocode

Algorithm Union(R₁, R₂):
  Input: Two union-compatible relations R₁ and R₂
  Output: Relation R₃ = R₁ ∪ R₂

  R₃ ← empty relation
  FOR EACH tuple t IN R₁:
    INSERT t INTO R₃
  FOR EACH tuple t IN R₂:
    IF t NOT IN R₃ THEN:
      INSERT t INTO R₃
  RETURN R₃

Core Formulas

Union Definition
R₃ = R₁ ∪ R₂
Result contains all tuples from R₁ and R₂ (duplicates removed).
Degree of Union Result
deg(R₃) = deg(R₁) = deg(R₂)
All three relations have the same degree (number of attributes).
Cardinality — General Case
card(R₃) = card(R₁) + card(R₂) − k
Where k = number of tuples common to both R₁ and R₂ (tuples that appear in both relations).
Cardinality — Disjoint Relations
If R₁ ∩ R₂ = ∅, then card(R₃) = card(R₁) + card(R₂)
When no tuples are shared, k = 0, so cardinality is simply the sum.
Cardinality — Identical Relations
If R₁ = R₂, then card(R₃) = card(R₁) = card(R₂)
When both relations are identical, the union equals either one.
Cardinality — Subset Case
If R₁ ⊆ R₂, then card(R₃) = card(R₂)
When R₁ is a subset of R₂, the union is just R₂.

Key Constraint Formulas

Candidate Key of Union Result
C.K.(R₃) = All key
The candidate key of the union result is the concatenation of ALL attributes from both R₁ and R₂. This is because a tuple from R₁ and a different tuple from R₂ could share the same key values, so all attributes are needed to uniquely identify tuples.
Important: The candidate key of R₃ is NOT simply the key of R₁ or R₂. Since tuples come from two different sources, all attributes from both relations are needed to form the composite key.

Selection + Union Composition

Selection then Union
σc=6(R₁ ∪ R₂) = σc=6(R₁) ∪ σc=6(R₂)
Selection distributes over union: you can select first then union, or union first then select — the result is the same.
Generalized Distribution
σP(R₁ ∪ R₂) = σP(R₁) ∪ σP(R₂)
For any selection condition P, selection distributes over union.

Algebraic Properties

Commutative Law
R₁ ∪ R₂ = R₂ ∪ R₁
Order of operands does not matter.
Associative Law
(R₁ ∪ R₂) ∪ R₃ = R₁ ∪ (R₂ ∪ R₃)
Grouping does not matter when performing multiple unions.
Idempotent Law
R ∪ R = R
Union of a relation with itself returns the same relation.
Identity Element
R ∪ ∅ = R
Union with the empty relation returns the original relation.

Set-Theoretic Laws

Commutative Law (Set Theory)
R₁ ∪ R₂ = R₂ ∪ R₁
Associative Law (Set Theory)
(R₁ ∪ R₂) ∪ R₃ = R₁ ∪ (R₂ ∪ R₃)
Idempotent Law (Set Theory)
R ∪ R = R

Distribution Laws

Union distributes over Intersection
R₁ ∪ (R₂ ∩ R₃) = (R₁ ∪ R₂) ∩ (R₁ ∪ R₃)
Union distributes over intersection, but intersection does NOT distribute over union.
Warning: Intersection does NOT distribute over union in general:
R₁ ∩ (R₂ ∪ R₃) ≠ (R₁ ∩ R₂) ∪ (R₁ ∩ R₃) — this is NOT always true.

Common Mistakes

Mistake 1: Attempting to union relations with different schemas. Both relations MUST have the same number of attributes with compatible domains.
Mistake 2: Forgetting that duplicates are eliminated. The result is a SET, not a bag/multiset. If R₁ has (2,1) twice and R₂ has (2,1) once, the result still has (2,1) only once.
Mistake 3: Assuming the candidate key of R₃ is the same as R₁ or R₂. The candidate key of the union is "All key" — the concatenation of all attributes.
Mistake 4: Confusing union with concatenation. Union combines tuples as sets (removing duplicates), while concatenation would keep all tuples including duplicates.
