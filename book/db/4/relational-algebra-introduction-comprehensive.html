RELATIONAL ALGEBRA

Database Systems — Complete Introduction Guide

What is Relational Algebra?

Relational algebra is a procedural query language that takes instances of relations as input and yields instances of relations as output. It forms the theoretical foundation of relational databases and SQL.

Definition:
Relational Algebra = A set of operations that take one or two relations as input and produce a new relation as output
Operations are performed on relations to retrieve or modify data

Key Characteristics

Procedural

Specifies how to obtain the result, not just what the result is

Closed System

Output of one operation can be input to another operation

Formal Foundation

Basis for SQL and other query languages

Set-Based

Operations work on sets of tuples (no duplicates by default)

Relation Basics

A relation is a table with rows (tuples) and columns (attributes). Each relation has a schema that defines its structure.

Notation:
R(A₁, A₂, ..., Aₙ)
R is the relation name, A₁ through Aₙ are attribute names
Degree (arity):
deg(R) = n
Number of attributes (columns) in relation R
Cardinality:
card(R) = |R|
Number of tuples (rows) in relation R
Example: Supplier Relation S
S#SnameCity
S1Sn1C1
S2Sn2C2
S3Sn3C2

deg(S) = 3 attributes (S#, Sname, City)

card(S) = 3 tuples (rows)

Basic Relational Algebra Operations

1. Select (σ)

Unary - filters rows

Selects tuples satisfying a condition

σ_condition(R)

2. Project (π)

Unary - filters columns

Selects specific attributes

π_attributes(R)

3. Union (∪)

Binary - combines relations

All tuples in either relation

R ∪ S

4. Set Difference (-)

Binary - removes tuples

Tuples in R but not in S

R - S

5. Cartesian Product (×)

Binary - all combinations

Every tuple of R with every tuple of S

R × S

Additional Operations

6. Intersection (∩)

Binary - common tuples

Tuples in both R and S

R ∩ S

7. Rename (ρ)

Unary - renames

Renames relation or attributes

ρ_S(R) or ρ_B←A(R)

Key Properties

Union Compatibility (Type Compatibility)

Two relations are union compatible if:

Same Degree

Both relations have the same number of attributes

deg(R) = deg(S)

Compatible Domains

Corresponding attributes have compatible domains

Same data types for each position

Important: Union, Set Difference, and Intersection require union-compatible relations!

Closure Property

Closure:
Output of relational algebra operation is always a relation
This allows chaining operations: the result of one operation can be input to another

Worked Examples

Example 1: Basic Operation Classification

Question: Classify the following operations and determine if they require union compatibility:

1. σ_age>25(Employee)   2. π_name(Employee)   3. Employee ∪ Contractor

Solution:

1. Select: Unary, No union compatibility needed

2. Project: Unary, No union compatibility needed

3. Union: Binary, Union compatibility REQUIRED (same degree, compatible domains)

Example 2: Degree and Cardinality

Given: Relation R(A,B,C) with 5 tuples, Relation S(D,E) with 3 tuples

Calculate:

deg(R) = 3, card(R) = 5

deg(S) = 2, card(S) = 3

deg(R × S) = 3 + 2 = 5

card(R × S) = 5 × 3 = 15

Example 3: Closure Property

Question: Can we compute σ_city='Tehran'(π_name(Employee))?

Solution: Yes!

Step 1: π_name(Employee) produces a relation with attribute 'name'

Step 2: σ_city='Tehran' is applied to the result

Note: This query would fail at step 2 because 'city' is not in the projected relation. The closure property holds, but the query is semantically invalid.

Example 4: Set Operations

Given:

R(A,B)S(A,B)
1, 22, 3
3, 43, 4

Results:

R ∪ S = {(1,2), (3,4), (2,3)} — 3 tuples

R - S = {(1,2)} — 1 tuple

R ∩ S = {(3,4)} — 1 tuple

Example 5: Rename Operation

Question: Rename relation R to T, and rename attribute A to X

Solution:

ρ_T(R) — Renames relation R to T
ρ_X←A(R) — Renames attribute A to X in R
ρ_T(X,Y)(R) — Renames R to T, and attributes to X and Y
