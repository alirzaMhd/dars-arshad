SELECT OPERATION (σ)

Database Systems — Selection Operation Complete Guide

What is Selection?

The Select operation (σ) is a unary operation that filters tuples (rows) from a relation based on a condition. It examines each tuple and includes it in the result only if the condition evaluates to TRUE.

Definition:
σ_q(R) = { t | t ∈ R AND q(t) = TRUE }
Selects all tuples t from relation R where predicate q is true
Notation:
σ_condition(R)
σ is the select operator, condition is the predicate, R is the input relation

Characteristics

Unary Operation

Operates on single relation

Row Filter

Selects tuples (rows) not attributes

Horizontal Subset

Produces a horizontal subset of the relation

Degree Preserved

Output has same degree as input

Core Formulas

Selection Formula:
σ_q(R) where q is a selection condition
Returns all tuples from R that satisfy condition q
Degree Property:
deg(σ_q(R)) = deg(R)
Selection does not change the degree (number of attributes) of the relation
Cardinality Property:
card(σ_q(R)) ≤ card(R)
Selection can only reduce or maintain the number of tuples (never increases)

Commutativity

Commutative Property:
σ_p(σ_q(R)) = σ_q(σ_p(R))
The order of applying selection conditions does not matter
Equivalent Form:
σ_p ∧ q(R) = σ_p(σ_q(R)) = σ_q(σ_p(R))
AND conditions can be split and applied in any order

Idempotency

Idempotent Property:
σ_p(σ_p(R)) = σ_p(R)
Applying the same selection twice produces the same result as applying it once

Composition with Other Operations

Composition with Union:
σ_q(R ∪ S) = σ_q(R) ∪ σ_q(S)
Selection distributes over union
Composition with Intersection:
σ_q(R ∩ S) = σ_q(R) ∩ σ_q(S)
Selection distributes over intersection
Composition with Set Difference:
σ_q(R - S) = σ_q(R) - σ_q(S)
Selection distributes over set difference
Composition with Cartesian Product:
σ_q(R × S) — condition may involve attributes from both R and S
Selection on Cartesian product can filter combinations

Algorithm Pseudocode

Algorithm: SELECT(R, condition)
Input: Relation R, predicate condition
Output: Relation with tuples satisfying condition

result ← empty relation
result.schema ← R.schema // same degree

FOR EACH tuple t IN R DO
  IF condition(t) = TRUE THEN
    ADD t TO result
  END IF
END FOR

RETURN result

Time Complexity

O(n) where n = card(R)

Must examine every tuple once

Space Complexity

O(k) where k = number of matching tuples

Worst case: O(n) if all tuples match

Worked Examples

Example 1: Simple Selection

Given: Relation SUPPLIER(S#, Sname, City)

S#SnameCity
S1AlphaTehran
S2BetaIsfahan
S3GammaTehran
S4DeltaShiraz

Query: σ_City='Tehran'(SUPPLIER)

Result:

S#SnameCity
S1AlphaTehran
S3GammaTehran

deg = 3 (unchanged), card = 4→2 (reduced)

Example 2: Compound Condition (AND)

Query: σ_City='Tehran' ∧ S#>'S2'(SUPPLIER)

Step 1: Apply σ_City='Tehran' → {(S1,Alpha,Tehran), (S3,Gamma,Tehran)}

Step 2: Apply σ_S#>'S2' on result → {(S3,Gamma,Tehran)}

Result:

S#SnameCity
S3GammaTehran
Example 3: Compound Condition (OR)

Query: σ_City='Tehran' ∨ City='Shiraz'(SUPPLIER)

Result: Tuples where City is either Tehran or Shiraz

S#SnameCity
S1AlphaTehran
S3GammaTehran
S4DeltaShiraz
Example 4: Chained Selections

Query: σ_S#>'S1'(σ_City='Tehran'(SUPPLIER))

Using commutativity: σ_City='Tehran'(σ_S#>'S1'(SUPPLIER))

Both produce same result:

S#SnameCity
S3GammaTehran

This demonstrates the commutative property of selection

Example 5: Selection with Negation

Query: σ¬(City='Tehran')(SUPPLIER)

Result: All suppliers NOT in Tehran

S#SnameCity
S2BetaIsfahan
S4DeltaShiraz
Common Mistakes:
1. Selection filters ROWS (tuples), not columns
2. The result always has the same schema as the input
3. Don't confuse σ (Select) with π (Project)
4. String comparisons in SQL use single quotes: City='C2'
