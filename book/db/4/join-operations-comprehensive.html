JOIN OPERATIONS

Database Systems — Relational Algebra Complete Guide

1. What is a Join?

A Join is a binary operation that combines tuples from two relations based on a related condition. It is the most commonly used operation in relational databases for combining data from multiple tables.

All join operations can be expressed as:

Fundamental Relationship:
Join = Cartesian Product + Selection
Every join is essentially a filtered Cartesian product

Types of Joins:

  • Theta Join (⋈θ): General condition join
  • Equi Join: Join with equality condition
  • Natural Join (⋈): Join on common attributes with equality
  • Outer Joins: Left, Right, and Full outer joins

2. Why Joins are Important

Joins allow us to:

  • Combine data from normalized tables
  • Answer queries that span multiple entities
  • Enforce relationships between data
  • Retrieve meaningful information from distributed data
Key Insight: Without joins, relational databases would be limited to single-table queries. Joins are what make the relational model powerful.

Theta Join (⋈θ)

The Theta Join is the most general form of join. It combines tuples from two relations where a condition θ (theta) is satisfied. The condition can use any comparison operator.

Definition:
R ⋈θ S = σθ(R × S)
Theta join is a Cartesian product followed by a selection with condition θ
Degree:
deg(R ⋈θ S) = deg(R) + deg(S)
All attributes from both relations are included
Cardinality:
card(R ⋈θ S) ≤ card(R) × card(S)
At most the size of Cartesian product (usually much smaller)

Comparison Operators in θ:

OperatorMeaningExample
=EqualR.a = S.b
≠Not equalR.a ≠ S.b
<Less thanR.a < S.b
>Greater thanR.a > S.b
≤Less or equalR.a ≤ S.b
≥Greater or equalR.a ≥ S.b
Example: Theta Join

Given: R₁(a,b) and R₂(c,d)

Query: R₁ ⋈R₁.b > R₂.c R₂

Only pairs tuples where R₁.b is greater than R₂.c

Equi Join

An Equi Join is a special case of Theta Join where the condition uses only equality (=). It is the most common type of join in practice.

Definition:
R ⋈R.a = S.b S = σR.a = S.b(R × S)
Equi join combines tuples where attribute values are equal
Degree:
deg(R ⋈R.a = S.b S) = deg(R) + deg(S)
All attributes from both relations
Cardinality:
card(R ⋈R.a = S.b S) ≤ card(R) × card(S)
At most the Cartesian product size
Important: In equi join, both join attributes appear in the result. In natural join, the common attribute is merged into one.
Example: Equi Join

Given:

S (Suppliers)SP (Shipments)
S#CityS#P#QTY
S1C1S1P1100
S2C2S1P2200
S2P1150

Query: S ⋈S.S# = SP.S# SP

Result:

S.S#CitySP.S#P#QTY
S1C1S1P1100
S1C1S1P2200
S2C2S2P1150

Natural Join (⋈)

The Natural Join is the most commonly used join in relational algebra. It automatically joins on all common attributes with equality, and merges the common attributes into a single column in the result.

Definition:
R ⋈ S = πunique_attrs(σcommon_attrs_equal(R × S))
Natural join = Cartesian product + selection on common attributes + projection to remove duplicates
Degree:
deg(R ⋈ S) = deg(R) + deg(S) - |common attributes|
Common attributes appear only once in result
Cardinality:
card(R ⋈ S) ≤ card(R) × card(S)
At most Cartesian product (usually much smaller)

Natural Join vs Equi Join:

Outer Joins

Standard joins only return tuples that have matches in both relations. Outer joins preserve unmatched tuples by filling missing values with NULL.

1. Left Outer Join (⟕)

Definition:
R ⟕ S = (R ⋈ S) ∪ (R - πcommon(R ⋈ S)) × {NULL...}
All tuples from R, plus matched tuples from S. Unmatched R tuples get NULL for S attributes

2. Right Outer Join (⟖)

Definition:
R ⟖ S = S ⟕ R
All tuples from S, plus matched tuples from R. Unmatched S tuples get NULL for R attributes

3. Full Outer Join (⟗)

Definition:
R ⟗ S = (R ⟕ S) ∪ (R ⟖ S)
All tuples from both R and S. Unmatched tuples from either side get NULLs

Semi Joins

A Semi Join returns tuples from one relation that have matching tuples in another relation, but only includes attributes from the first relation. It is useful for checking existence without duplicating columns.

1. Left Semi Join (⋉)

Definition:
R ⋉ S = πattrs(R)(R ⋈ S)
Returns tuples from R that have a match in S, with only R's attributes
Alternative Definition:
R ⋉ S = R - (R - πattrs(R)(R ⋈ S))
Equivalent using set difference
Using Division:
R ⋉ S = πattrs(R)(R) - (πattrs(R)(R) ÷ πcommon(S))
Can also be expressed using division

2. Right Semi Join (⋊)

Definition:
R ⋊ S = S ⋉ R
Returns tuples from S that have a match in R, with only S's attributes
Key Difference from Regular Join: Semi joins do NOT include attributes from the second relation. They only check for existence of a match.
Example: Left Semi Join

Given:

S (Suppliers)SP (Shipments)
S#CityS#P#
S1C1S1P1
S2C2S1P2
S3C1

Query: S ⋉ SP (suppliers who have shipments)

Result:

S#City
S1C1
S2C2

S3 is excluded because it has no matching shipment. Notice P# column is NOT included.

Example: Right Semi Join

Query: S ⋊ SP (shipments that have valid suppliers)

Result:

S#P#
S1P1
S1P2

Returns only SP tuples where S# exists in S relation

-- Left Semi Join using EXISTS
SELECT * FROM S WHERE EXISTS (
  SELECT * FROM SP WHERE SP.S# = S.S#
)

-- Left Semi Join using IN
SELECT * FROM S WHERE S.S# IN (SELECT S# FROM SP)

-- Right Semi Join using EXISTS
SELECT * FROM SP WHERE EXISTS (
  SELECT * FROM S WHERE S.S# = SP.S#
)

When to Use Each:

Cartesian Product

When you need all combinations (rarely used directly)

Theta Join

When join condition is not equality (e.g., range joins)

Equi Join

When joining on specific equal attributes

Natural Join

When common attributes have same names (most common)

Outer Join

When you need to preserve unmatched tuples

Semi Join

When checking existence without duplicating columns

Common Mistakes to Avoid:
  • Confusing equi join with natural join
  • Forgetting that natural join merges common attributes
  • Not considering outer joins when preserving unmatched tuples
  • Ignoring the impact of duplicate attribute names
  • Using Cartesian product when a join would be more efficient

Time Complexity:

Nested Loop Join:
O(card(R) × card(S))
Worst case: check all pairs
With Index/Hashing:
O(card(R) + card(S))
Best case with proper indexing

-- Left Outer Join
SELECT * FROM R LEFT JOIN S ON R.a = S.b
