INTERSECT OPERATION

Relational Algebra - Finding Common Tuples

Definition

The Intersect operation (denoted by ∩) returns tuples that appear in both relations. Like union, both relations must be union-compatible (same degree, compatible domains).

Formal Definition
R₃ = R₁ ∩ R₂
R₁ and R₂ must be union-compatible. The result contains only tuples present in BOTH R₁ and R₂.

Intersection is the dual of union — while union gathers all tuples from both relations, intersection keeps only those that are shared. It can also be expressed using set difference:

Equivalent Expression
R₁ ∩ R₂ = R₁ − (R₁ − R₂)
Intersection can be derived from set difference operations.

Requirements for Intersection

Same Degree
Both relations must have the same number of attributes
Compatible Domains
Corresponding attributes must have compatible data types
Set Semantics
Result is a set (no duplicates)

Algorithm / Pseudocode

Algorithm Intersect(R₁, R₂):
  Input: Two union-compatible relations R₁ and R₂
  Output: Relation R₃ = R₁ ∩ R₂

  R₃ ← empty relation
  FOR EACH tuple t IN R₁:
    IF t IN R₂ THEN:
      INSERT t INTO R₃
  RETURN R₃

Where n₁ = card(R₁) and n₂ = card(R₂).

Core Formulas

Intersect Definition
R₃ = R₁ ∩ R₂
Result contains only tuples present in both R₁ and R₂.
Degree of Intersect Result
deg(R₃) = deg(R₁) = deg(R₂)
All relations have the same degree.
Cardinality — General Case
card(R₃) = k
Where k = number of tuples common to both R₁ and R₂.
Cardinality Bounds
0 ≤ card(R₃) ≤ min(card(R₁), card(R₂))
The intersection can never be larger than the smaller relation.
Cardinality — Disjoint Relations
If R₁ ∩ R₂ = ∅, then card(R₃) = 0
When no tuples are shared, intersection is empty.
Cardinality — Identical Relations
If R₁ = R₂, then card(R₃) = card(R₁) = card(R₂)
When both relations are identical, intersection equals either one.
Cardinality — Subset Case
If R₁ ⊆ R₂, then card(R₃) = card(R₁)
When R₁ is a subset of R₂, the intersection is R₁ itself.

Key Constraint Formulas

Candidate Key of Intersect Result
C.K.(R₃) = C.K.(R₁) OR C.K.(R₂)
The candidate key of the intersection result is the key of R₁ OR the key of R₂ (whichever is applicable). Since the result is a subset of both relations, its key must be a key of at least one of them.
Important: Unlike union (where the key becomes "All key"), intersection preserves the key from at least one of the input relations. This is because every tuple in R₃ exists in both R₁ and R₂, so keys from either relation remain valid.

Selection + Intersect Composition

Selection distributes over Intersect
σP(R₁ ∩ R₂) = σP(R₁) ∩ σP(R₂)
Selection distributes over intersection: select first then intersect, or intersect first then select — same result.
Relationship to Set Difference
R₁ ∩ R₂ = R₁ − (R₁ − R₂)
Intersection can be expressed using two set difference operations.

Algebraic Properties

Commutative Law
R₁ ∩ R₂ = R₂ ∩ R₁
Order of operands does not matter.
Associative Law
(R₁ ∩ R₂) ∩ R₃ = R₁ ∩ (R₂ ∩ R₃)
Grouping does not matter when performing multiple intersections.
Idempotent Law
R ∩ R = R
Intersection of a relation with itself returns the same relation.
Identity Element
R ∩ ∅ = ∅
Intersection with the empty relation always yields the empty relation.

Distribution Laws

Intersection distributes over Union
R₁ ∩ (R₂ ∪ R₃) = (R₁ ∩ R₂) ∪ (R₁ ∩ R₃)
Intersection distributes over union.
Warning: Union does NOT distribute over intersection in general:
R₁ ∪ (R₂ ∩ R₃) ≠ (R₁ ∪ R₂) ∩ (R₁ ∪ R₃) — this IS always true actually. But be careful with other combinations.

Relationship to Other Operations

Expressed via Set Difference
R₁ ∩ R₂ = R₁ − (R₁ − R₂)
Intersection can be computed using two set difference operations.
Expressed via Union and Difference
R₁ ∩ R₂ = (R₁ ∪ R₂) − ((R₁ − R₂) ∪ (R₂ − R₁))
Alternative expression using union and symmetric difference.

Common Mistakes

Mistake 1: Assuming intersection can work on incompatible relations. Like union, both relations MUST be union-compatible.
Mistake 2: Confusing intersection with inner join. Intersection compares entire tuples for equality, while join matches on specific attributes and combines columns.
Mistake 3: Forgetting that the result cardinality is bounded by min(card(R₁), card(R₂)). The intersection can never be larger than the smaller input.
Mistake 4: Assuming the candidate key of R₃ is "All key." Unlike union, intersection preserves the key from at least one input relation.
