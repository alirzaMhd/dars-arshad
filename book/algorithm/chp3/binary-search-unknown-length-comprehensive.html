BINARY SEARCH IN UNKNOWN LENGTH ARRAYS

Data Structures — Complete Guide for 20/20 Exam

The Problem

We want to search for element x in a sorted array A[1..?] where the array length is unknown. We cannot directly find the middle element because we don't know where the array ends.

Key Challenge:
Cannot compute mid = ⌊(L+U)/2⌋ without knowing U!
Array length is not given

Solution Approach

• Start with small bounds

• Exponentially increase bounds

• Find range containing target

• Then apply standard binary search

Two-Phase Strategy

Phase 1: Find bounds [i, 2i]

Phase 2: Binary search in [i, 2i]

• Phase 1: O(log i) where i is answer index

• Phase 2: O(log i)

Algorithm

Algorithm Pseudocode:
binary_search_unknown_length(x) { // Phase 1: Find bounds i = 1 while (A[i] != NIL and A[i] < x) i = i * 2 // Phase 2: Binary search in [i/2, min(i, n)] L = i / 2 U = min(i, n) return binarysearch(L, U, x) }
First find bounds, then binary search

Phase 1: Finding Bounds

1. Start with i = 1

2. Check A[1], A[2], A[4], A[8], ...

3. Stop when A[i] ≥ x or A[i] = NIL

4. Target is in range [i/2, i]

Phase 2: Binary Search

1. Set L = i/2, U = min(i, n)

2. Standard binary search in [L, U]

3. Return result

Worked Examples

Example 1: Search for x = 20 in unknown length array

Array: [5, 8, 12, 15, 18, 20, 25, 30, ...] (length unknown)

Phase 1: Find bounds

• i=1: A[1]=5 < 20 → continue

• i=2: A[2]=8 < 20 → continue

• i=4: A[4]=15 < 20 → continue

• i=8: A[8]=30 ≥ 20 → stop

Target in range [4, 8]

Phase 2: Binary search in [4, 8]

• mid=6, A[6]=20 → Found at index 6!

Example 2: Search for x = 35 (not in array)

Array: [5, 8, 12, 15, 18, 20, 25, 30, 40, ...]

Phase 1: Find bounds

• i=1: A[1]=5 < 35 → continue

• i=2: A[2]=8 < 35 → continue

• i=4: A[4]=15 < 35 → continue

• i=8: A[8]=30 < 35 → continue

• i=16: A[16]=NIL → stop

Target in range [8, 16]

Phase 2: Binary search in [8, 16]

• Eventually determines x not in array → Not found (NIL)

Example 3: Search for first element

Array: [3, 7, 10, 15, 20, ...]

Phase 1: Find bounds

• i=1: A[1]=3 = 3 → stop immediately

Target in range [1, 1]

Phase 2: Binary search in [1, 1]

• Found at index 1!

Time & Space Complexity

Time Complexity:
O(log i) where i is the index of answer
Not O(log n)! Depends on position of target
Space Complexity:
O(1)
Only uses constant extra space

Analysis

• Phase 1: O(log i) to find bounds

• Phase 2: O(log i) for binary search

• Total: O(log i)

• If i << n, much faster than O(log n)

Comparison

• Standard binary search: O(log n)

• This method: O(log i)

• Advantage when target is near beginning

• Disadvantage: two phases needed
