BINARY SEARCH ON ROTATED SEQUENCES

Data Structures — Complete Guide for 20/20 Exam

What is a Rotated Sequence?

A sequence x₁, x₂, ..., xₙ is rotationally sorted if the smallest element is at some unknown position i, and the sequence xᵢ, xᵢ₊₁, ..., xₙ, x₁, x₂, ..., xᵢ₋₁ is sorted in ascending order.

Definition:
x₁, x₂, ..., xₙ is rotationally sorted if ∃ i: xᵢ, xᵢ₊₁, ..., xₙ, x₁, ..., xᵢ₋₁ is ascending
The minimum element can be at any position
Example of Rotated Sequence

Original sorted: [10, 15, 20, 22, 30, 40, 50]

Rotated: [30, 40, 50, 10, 15, 20, 22]

Minimum element is 10 at index 4

The rotated sequence [30, 40, 50, 10, 15, 20, 22] is rotationally sorted

Key Insight

• If k < m and xₖ < xₘ: minimum cannot be in range [k, m]

• If k < m and xₖ > xₘ: minimum must be in range [k, m]

• This allows binary search approach!

Goal

• Find the minimum element

• In O(log n) time

• Similar to standard binary search

Finding Minimum in Rotated Array

Algorithm:
find_minimum_rotated(L, U) { while (L < U) { mid = ⌊(L + U) / 2⌋ if (A[mid] < A[U]) U = mid else L = mid + 1 } return L }
Compare A[mid] with A[U] to decide which half to search

Key Comparison

• Compare A[mid] with A[U]

• If A[mid] < A[U]: minimum is in left half [L..mid]

• If A[mid] > A[U]: minimum is in right half [mid+1..U]

Why This Works

• If A[mid] < A[U]: right half is sorted, minimum must be left

• If A[mid] > A[U]: left half is sorted, minimum must be right

• Each step halves the search space

Worked Examples

Example 1: Find minimum in [30, 40, 50, 10, 15, 20, 22]

Array: [30, 40, 50, 10, 15, 20, 22]

Step 1: L=1, U=7, mid=4, A[4]=10, A[7]=22

10 < 22 → U = 4 (search left half)

Step 2: L=1, U=4, mid=2, A[2]=40, A[4]=10

40 > 10 → L = 3 (search right half)

Step 3: L=3, U=4, mid=3, A[3]=50, A[4]=10

50 > 10 → L = 4

Step 4: L=U=4 → Minimum at index 4 (value = 10)

Example 2: Find minimum in [50, 10, 20, 30, 40]

Array: [50, 10, 20, 30, 40]

Step 1: L=1, U=5, mid=3, A[3]=20, A[5]=40

20 < 40 → U = 3

Step 2: L=1, U=3, mid=2, A[2]=10, A[3]=20

10 < 20 → U = 2

Step 3: L=1, U=2, mid=1, A[1]=50, A[2]=10

50 > 10 → L = 2

Step 4: L=U=2 → Minimum at index 2 (value = 10)

Example 3: Already sorted array [10, 20, 30, 40, 50]

Array: [10, 20, 30, 40, 50] (no rotation)

Step 1: L=1, U=5, mid=3, A[3]=30, A[5]=50

30 < 50 → U = 3

Step 2: L=1, U=3, mid=2, A[2]=20, A[3]=30

20 < 30 → U = 2

Step 3: L=1, U=2, mid=1, A[1]=10, A[2]=20

10 < 20 → U = 1

Step 4: L=U=1 → Minimum at index 1 (value = 10)

Works correctly even when array is not rotated!

Time & Space Complexity

Time Complexity:
O(log n)
Same as standard binary search - halves search space each step
Space Complexity:
O(1)
Iterative version uses only constant extra space

Analysis

• Each comparison eliminates half the elements

• Maximum number of comparisons = ⌊log₂ n⌋

• Same efficiency as standard binary search

Comparison with Linear

• Linear search: O(n) - must check all elements

• Binary search: O(log n) - much faster

• For n=1,000,000: ~20 vs 1,000,000 comparisons

⚠ Key Insight: The algorithm works because at least one half must be sorted at any point!
