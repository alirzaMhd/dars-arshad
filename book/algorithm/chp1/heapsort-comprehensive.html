What is Heapsort?

Heapsort is a comparison-based sorting algorithm that uses a binary heap data structure. It works in two phases: build a max-heap, then repeatedly extract the maximum element.

Time Complexity

Best: O(n lg n)

Average: O(n lg n)

Worst: O(n lg n)

Space Complexity

In-place: O(1)

Stable: No

Core Idea:
Build max-heap → Extract max repeatedly → Sorted array (ascending)
In a max heap, the root always contains the maximum element. By placing this maximum at the end of the array and re-heapifying, we build the sorted array from back to front.
Array-Heap Relationship (1-indexed):
parent(i) = ⌊i/2⌋, left(i) = 2i, right(i) = 2i + 1
For node at index i: parent at ⌊i/2⌋, left child at 2i, right child at 2i+1.

Heapsort Pseudocode

HEAPSORT(A) BUILD-MAX-HEAP(A) for i ← A.length downto 2 do exchange A[1] ↔ A[i] A.heap-size ← A.heap-size - 1 MAX-HEAPIFY(A, 1)

Step-by-Step Explanation

Step 1: Call BUILD-MAX-HEAP to transform the array into a max-heap. After this, A[1] contains the maximum element.

Step 2: Iterate from i = n down to 2.

Step 3: Swap A[1] (current max) with A[i] (last element in heap). The max is now in its final sorted position.

Step 4: Decrease heap-size by 1 (exclude the sorted element from the heap).

Step 5: Call MAX-HEAPIFY(A, 1) to restore the heap property on the reduced heap.

Why it works:
Each iteration places the current maximum at position i (its final sorted position)
After n-1 iterations, all elements are in their correct positions. The array is sorted in ascending order.
After swapping A[1] with A[i], the heap-size is reduced to i-1. The element at A[i] is now in its FINAL position and is excluded from future heap operations.

MAX-HEAPIFY (Sift-Down)

Used by Heapsort to restore the heap property after each extraction.

MAX-HEAPIFY(A, i) l ← left(i) r ← right(i) largest ← i if l ≤ A.heap-size and A[l] > A[i] largest ← l if r ≤ A.heap-size and A[r] > A[largest] largest ← r if largest ≠ i exchange A[i] ↔ A[largest] MAX-HEAPIFY(A, largest)
Precondition:
Subtrees at left(i) and right(i) are valid max-heaps, but A[i] may violate the heap property
MAX-HEAPIFY sifts A[i] down to its correct position by swapping with the larger child.

BUILD-MAX-HEAP

BUILD-MAX-HEAP(A) A.heap-size ← A.length for i ← ⌊A.length/2⌋ downto 1 do MAX-HEAPIFY(A, i)
Key Insight:
Start from the last non-leaf node (⌊n/2⌋) and work backwards to the root
Leaf nodes (indices ⌊n/2⌋+1 to n) are trivially valid heaps. Only internal nodes need heapification.

Time Complexity Analysis

Total Time = Build Heap + (n-1) × (Extract-Max + Heapify)
T(n) = O(n) + (n-1) × O(lg n) = O(n lg n)

BUILD-MAX-HEAP: O(n)

Formula:
Σ(h=0 to ⌊lg n⌋) ⌈n/2^(h+1)⌉ × O(h) = O(n)
Most nodes have small height. A node of height h has at most ⌈n/2^(h+1)⌉ nodes. The sum converges to O(n) because the geometric series dominates.

Extract-Max + Heapify: O(lg n) each

Formula:
Each MAX-HEAPIFY takes O(lg n) = O(height of heap)
The height of a heap with n nodes is ⌊lg n⌋. In the worst case, we sift down from root to leaf.
Total for n-1 extractions:
(n-1) × O(lg n) = O(n lg n)

Space Complexity

In-Place Sorting:
O(1) extra space
Heapsort rearranges elements within the original array. No auxiliary array is needed (unlike Merge Sort). The only extra space is for temporary swap variables.
The recursive version of MAX-HEAPIFY uses O(lg n) stack space. An iterative version achieves true O(1) extra space. For exam purposes, Heapsort is considered O(1) space.

Special Case: All Elements Equal

When all elements are equal:
Θ(n) — linear time!
When every element has the same value, MAX-HEAPIFY never needs to swap (no child is strictly greater). Each heapify check returns immediately in O(1).

Heapsort Advantages

+ Guaranteed O(n lg n) worst case

+ In-place (O(1) space)

+ No worst-case degradation

Heapsort Disadvantages

- Unstable sort

- Poor cache performance

- Slower than Quick Sort in practice

Cache Behavior: Heapsort accesses array elements in a non-sequential pattern (jumping between parent and child nodes), leading to poor cache locality. This makes it slower than Quick Sort in practice despite having the same asymptotic complexity.

Example 1: Sort [4, 10, 3, 5, 1]

Step 1: Build Max Heap
Initial Array: [4, 10, 3, 5, 1] (n=5) Start from i=⌊5/2⌋=2 down to 1: i=2 (val=10): children at 4(5), 5(1). 10 > 5 and 10 > 1. No swap. i=1 (val=4): children at 2(10), 3(3). 10 > 4, swap. Array: [10, 4, 3, 5, 1] Heapify at i=2: children at 4(5), 5(1). 5 > 4, swap. Array: [10, 5, 3, 4, 1] Max Heap: 10 / \ 5 3 / \ 4 1
Step 2: Sort Phase (Extract Max repeatedly)
--- Pass 1 --- Swap A[1]=10 with A[5]=1: [1, 5, 3, 4, |10] Heapify root (heap size=4): 1 vs children 5,3 → swap with 5 5 vs children 4,1 → 5 > 4, done Result: [5, 4, 3, 1, |10] --- Pass 2 --- Swap A[1]=5 with A[4]=1: [1, 4, 3, |5, 10] Heapify root (heap size=3): 1 vs children 4,3 → swap with 4 Result: [4, 1, 3, |5, 10] --- Pass 3 --- Swap A[1]=4 with A[3]=3: [3, 1, |4, 5, 10] Heapify root (heap size=2): 3 vs child 1 → 3 > 1, done Result: [3, 1, |4, 5, 10] --- Pass 4 --- Swap A[1]=3 with A[2]=1: [1, |3, 4, 5, 10] Heap size=1, done. Final Sorted Array: [1, 3, 4, 5, 10]

Key Formulas

HEAPSORT Total Work:
O(n) + (n-1) × O(lg n) = O(n lg n)
BUILD-MAX-HEAP O(n) + (n-1) extractions each with O(lg n) heapify.
Comparison Count (approximate):
2n lg n + O(n) comparisons
BUILD-MAX-HEAP uses ~2n comparisons. Each extraction uses ~2 lg n comparisons. Total ≈ 2n lg n.
Common Exam Mistakes:
  • Forgetting that Heapsort is UNSTABLE — use Merge Sort if stability needed
  • Starting BUILD-MAX-HEAP from index 1 instead of ⌊n/2⌋
  • Forgetting to DECREASE heap-size after each swap
  • Using 0-indexed formulas with 1-indexed array (or vice versa)
  • Confusing BUILD-MAX-HEAP (O(n)) with repeated INSERT (O(n lg n))
  • Thinking the heap is sorted — it only has parent-child ordering!
  • Forgetting that the final array is ascending (max-heap gives descending extraction)

When to Use Heapsort

Use Heapsort When

• Guaranteed O(n lg n) is required

• O(1) space is needed

• Worst-case matters (real-time systems)

• No extra memory available

Avoid Heapsort When

• Stability is required (use Merge Sort)

• Cache performance matters (use Quick Sort)

• Average-case speed is priority (use Quick Sort)

• Nearly sorted data (use Insertion Sort)
