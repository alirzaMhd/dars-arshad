AVL TREE

Data Structures — Complete Guide for 20/20 Exam

AVL Tree Definition

An AVL tree is a self-balancing Binary Search Tree where the balance factor of every node is in {-1, 0, +1}.

Balance Factor:
BF(x) = height(left[x]) - height(right[x])
An AVL tree requires |BF(x)| ≤ 1 for every node x

Node Structure

Node {
  key      // value
  left    // left child
  right   // right child
  p      // parent
  height  // height of subtree rooted at this node
}

Minimum Nodes for Height h

What is the minimum number of nodes N(h) in an AVL tree of height h?

Recurrence:
N(0) = 1, N(1) = 2, N(h) = N(h-1) + N(h-2) + 1
Base case: height 0 has 1 node, height 1 has 2 nodes

Small Values

h012345
N(h)12471220
N(h) grows like Fibonacci numbers. This ensures the tree is always balanced.

Height Bound

Height of AVL tree with n nodes:
h < 1.44 * lg(n + 2) - 0.328
AVL trees are guaranteed O(lg n) height, hence all operations are O(lg n)

Key Guarantee

All operations are O(lg n) time

vs Unbalanced BST

Worst case BST: O(n)

AVL worst case: O(lg n)

WARNING: Height h is NOT floor(lg n). AVL height is bounded by ~1.44 * lg n, not lg n. This constant factor matters in tight analysis.

Right Rotation (Clockwise)

Rotates node x down and its left child y up.

RIGHT-ROTATE(T, x):
  y = left[x]        // y is x's left child
  left[x] = right[y]  // y's right subtree becomes x's left
  if right[y] != NIL:
    p[right[y]] = x
  p[y] = p[x]       // link y to x's parent
  if p[x] == NIL:
    T.root = y
  elif x == left[p[x]]:
    left[p[x]] = y
  else:
    right[p[x]] = y
  right[y] = x     // x becomes y's right child
  p[x] = y
  update heights of x and y

Before/After

BEFORE:         AFTER:
   x                  y
  / \               / \
  y  C            B  x
 / \              / \
 A  B          A  C

Left Rotation (Counter-clockwise)

Symmetric to right rotation. Rotates x down and its right child y up.

LEFT-ROTATE(T, x):
  y = right[x]      // y is x's right child
  right[x] = left[y] // y's left subtree becomes x's right
  if left[y] != NIL:
    p[left[y]] = x
  p[y] = p[x]
  if p[x] == NIL:
    T.root = y
  elif x == left[p[x]]:
    left[p[x]] = y
  else:
    right[p[x]] = y
  left[y] = x
  p[x] = y
  update heights of x and y

Before/After

BEFORE:         AFTER:
   x                  y
  / \               / \
  A  y            x  C
    / \          / \
   B  C        A  B
WARNING: Rotations preserve BST property but change tree structure. Heights must be updated AFTER rotation. Always recalculate height of the lower node first, then the upper node.

4 Rebalancing Cases After Insert

After inserting node z, the first ancestor x with |BF(x)| = 2 is the critical node. There are 4 cases based on where z was inserted relative to x.

Key Variables:
x = first unbalanced node, y = child of x on path to z, z = grandchild of x on path to z
y is the child of x that is heavier (BF = +1 or -1), z is the child of y on the insertion path

Case 1: Left-Left (LL)

Condition

z is in left subtree of left child of x

BF(x) = +2, BF(y) = +1

Fix

Right rotate x

Single rotation

Case 2: Right-Right (RR)

Condition

z is in right subtree of right child of x

BF(x) = -2, BF(y) = -1

Fix

Left rotate x

Single rotation

Case 3: Left-Right (LR)

Condition

z is in right subtree of left child of x

BF(x) = +2, BF(y) = -1

Fix

Left rotate y, then right rotate x

Double rotation

Case 4: Right-Left (RL)

Condition

z is in left subtree of right child of x

BF(x) = -2, BF(y) = +1

Fix

Right rotate y, then left rotate x

Double rotation

WARNING: Case 3 (LR) and Case 4 (RL) are double rotations. Do NOT just do a single rotation — it won't fix the imbalance. The first rotation "straightens" the path, the second fixes the balance.

AVL Insert

AVL-INSERT(T, z):
  // Step 1: Standard BST insert
  BST-INSERT(T, z)
  z.height = 0

  // Step 2: Walk up from z, check balance factors
  y = z.p
  while y != NIL:
    update y.height
    x = y.p          // ancestor
    if BF(x) == 2 or BF(x) == -2:
      rebalance(x)  // one of 4 cases
      break
    y = y.p
Insert Complexity:
O(lg n) time
BST insert O(lg n) + walking up O(lg n) + at most 2 rotations O(1)

AVL Delete

AVL-DELETE(T, z):
  // Step 1: Standard BST delete
  BST-DELETE(T, z)

  // Step 2: Walk up from deletion point
  y = parent of affected node
  while y != NIL:
    update y.height
    x = y.p
    if |BF(x)| == 2:
      rebalance(x)
    y = y.p
Delete Complexity:
O(lg n) time
BST delete O(lg n) + walking up O(lg n) + rebalancing O(lg n) (may need multiple rebalances)
WARNING: AVL delete may require rebalancing at multiple ancestors (unlike insert which fixes at the first unbalanced node). After rebalancing at one node, ancestors above may also become unbalanced.

Example 1: Insert Sequence (LL Case)

Insert 3, 2, 1 into an empty AVL tree.

Step 1: Insert 3. Tree: 3. BF(3)=0. OK.

Step 2: Insert 2. 2 < 3, goes left. Tree: 3(2). BF(3)=1. OK.

Step 3: Insert 1. 1 < 3, 1 < 2, goes left of 2. Tree: 3(2(1)).

BF(3) = 2, BF(2) = 1. LL Case!

Fix: Right rotate at 3.

Final tree: 2 with left=1, right=3. All balance factors in {-1,0,+1}.

Example 2: Insert Sequence (LR Case)

Insert 3, 1, 2 into an empty AVL tree.

Step 1: Insert 3. Tree: 3. OK.

Step 2: Insert 1. 1 < 3, goes left. Tree: 3(1). BF(3)=1. OK.

Step 3: Insert 2. 2 < 3, 2 > 1, goes right of 1. Tree: 3(1(NIL, 2)).

BF(3) = 2, BF(1) = -1. LR Case!

Fix: Left rotate 1, then right rotate 3.

After left rotate 1: tree becomes 3(2(1)).

After right rotate 3: tree becomes 2(1, 3).

Final tree: 2 with left=1, right=3.

Example 3: Insert Sequence (RR Case)

Insert 1, 2, 3 into an empty AVL tree.

Step 1: Insert 1. Tree: 1. OK.

Step 2: Insert 2. 2 > 1, goes right. Tree: 1(2). BF(1)=-1. OK.

Step 3: Insert 3. 3 > 1, 3 > 2, goes right of 2. Tree: 1(NIL, 2(NIL, 3)).

BF(1) = -2, BF(2) = -1. RR Case!

Fix: Left rotate at 1.

Final tree: 2 with left=1, right=3.

Example 4: Insert Sequence (RL Case)

Insert 1, 3, 2 into an empty AVL tree.

Step 1: Insert 1. Tree: 1. OK.

Step 2: Insert 3. 3 > 1, goes right. Tree: 1(NIL, 3). BF(1)=-1. OK.

Step 3: Insert 2. 2 > 1, 2 < 3, goes left of 3. Tree: 1(NIL, 3(2)).

BF(1) = -2, BF(3) = +1. RL Case!

Fix: Right rotate 3, then left rotate 1.

After right rotate 3: tree becomes 1(2(3)).

After left rotate 1: tree becomes 2(1, 3).

Final tree: 2 with left=1, right=3.

Example 5: Height Calculation

Problem: Verify that an AVL tree with 7 nodes has height at most 3.

Solution:

Using N(h) = N(h-1) + N(h-2) + 1:

N(0) = 1, N(1) = 2, N(2) = 4, N(3) = 7

With 7 nodes, we can have height 3 (since N(3) = 7 exactly).

Check height bound: 1.44 * lg(7+2) - 0.328 = 1.44 * 3.17 - 0.328 ≈ 4.24

h < 4.24, so h ≤ 3. Verified!
