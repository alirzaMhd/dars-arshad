BINOMIAL HEAP

Data Structures — Complete Guide for 20/20 Exam

Binomial Tree Definition

A binomial tree B_i is defined recursively. It is the key building block of a binomial heap.

Recursive Definition:
B_0 = single node
B_i is formed by linking two copies of B_{i-1}. One becomes the leftmost child of the other.
Construction Rule:
B_i = link(B_{i-1}, B_{i-1})
Linking two B_{i-1} trees: the root with smaller key becomes the new root, and the other root becomes the leftmost child.

Binomial Heap Structure

A binomial heap H is a collection of binomial trees that satisfy two properties:

Property 1 — Min-Heap Order (or Max-Heap Order):
Each tree follows the heap property: parent.key <= child.key (min-heap)
Or parent.key >= child.key for max-heap. Every binomial tree in the heap is heap-ordered.
Property 2 — Unique Degrees:
No two trees in H have the same degree (order).
If H has n nodes, then it contains exactly the binomial trees B_k where the k-th bit of n in binary is 1.

Binary Representation Connection

n = 13 in binary = 1101

Bit positions (from LSB): 0=1, 1=0, 2=1, 3=1

Binomial trees present: B_0, B_2, B_3

Nodes: 2^0 + 2^2 + 2^3 = 1 + 4 + 8 = 13 ✓

Binomial Heap Representation

The binomial trees are stored in a linked list of roots, ordered by degree.

Root Node Fields

• key: priority value

• degree: tree order i

• parent: pointer to parent

• child: pointer to leftmost child

• sibling: pointer to next root

Heap Structure

• Head pointer to root list

• Trees ordered by degree

• min(root.key) = min-heap key

Key Property — Binomial Heap of n nodes:
At most floor(lg n) + 1 binomial trees
Since n can be represented with at most lg n + 1 bits, there are at most lg n + 1 trees in the heap.
Exam Trap: A binomial heap with n nodes has at most O(lg n) roots. This is why root-level operations take O(lg n) — you may need to traverse the root list.

LINK Operation (Core)

LINK joins two binomial trees of the same degree into one of degree one higher.

LINK(y, z)
1 y.parent = z
2 y.sibling = z.child
3 z.child = y
4 z.degree = z.degree + 1
LINK Time:
O(1) — constant time pointer operations
Just rewire 3 pointers and increment degree.

MERGE (Union) Operation

Merges two binomial heaps H1 and H2 into a single binomial heap. This is the foundation for insert and extract-min.

MERGE(H1, H2)
1 H = empty binomial heap
2 head = Merge root lists of H1 and H2
3 (sorted by degree, like merge of sorted lists)
4 if head == nil, return H
5 prev = nil
6 x = head
7 next = x.sibling
8 while next != nil
9 if (x.degree != next.degree) or
10 (next.sibling != nil and
11 next.sibling.degree == x.degree)
12 prev = x
13 x = next
14 else
15 if x.key <= next.key
16 x.sibling = next.sibling
17 LINK(next, x)
18 else
19 if prev == nil
20 head = next
21 else
22 prev.sibling = next
23 LINK(x, next)
24 x = next
25 next = x.sibling
26 H.head = head
27 return H
Merge Complexity:
O(lg n)
Root lists are merged in O(lg n) time. There are at most O(lg n) trees in each heap. The while loop runs at most O(lg n) iterations.
Critical: MERGE does NOT yet call HEAPIFY. It only links trees of same degree. The heap property must already hold in H1 and H2. After linking, the min-heap property is maintained because we always make the smaller key the parent.

INSERT Operation

Insert a new element x into binomial heap H.

INSERT(H, x)
1 H' = new binomial heap
2 H'.head = x (single node = B_0)
3 H = MERGE(H, H')
Insert Complexity:
O(lg n) worst case, O(1) amortized
Creating H' is O(1). MERGE is O(lg n). Amortized analysis shows O(1) average.

EXTRACT-MIN Operation

Removes and returns the element with the minimum key from H.

EXTRACT-MIN(H)
1 Find root x with minimum key in root list
2 Remove x from root list
3 Reverse order of x's children (make a new root list)
4 H' = new binomial heap with that reversed child list
5 H = MERGE(H, H')
6 return x.key
Extract-Min Complexity:
O(lg n)
Finding min: O(lg n) scan of root list. Reversing children: O(lg n) since x has at most lg n children. MERGE: O(lg n). Total: O(lg n).

DECREASE-KEY Operation

Decrease the key of node x to new value k (k < current key).

DECREASE-KEY(H, x, k)
1 if k > x.key, error
2 x.key = k
3 y = x.parent
4 while y != nil and x.key < y.key
5 swap x.key and y.key
6 x = y
7 y = x.parent
Decrease-Key Complexity:
O(lg n)
Bubble up through ancestors. Height of tree is at most lg n. Worst case: O(lg n).

DELETE Operation

Delete element x from heap H.

DELETE(H, x)
1 DECREASE-KEY(H, x, -∞)
2 EXTRACT-MIN(H)
Delete Complexity:
O(lg n)
Decrease-key O(lg n) + Extract-min O(lg n) = O(lg n).

Worked Example 1: Building a Binomial Heap

Insert keys: 12, 7, 25, 15, 28, 33, 41 in order.

Step-by-Step Insertions

Insert 12: Heap = {B_0(12)}

Insert 7: Heap = {B_0(7)} + {B_0(12)} → MERGE → {B_1(7, 12)}

B_1: root 7 → child B_0(12)

Insert 25: Heap = {B_1(7)} + {B_0(25)} → {B_1(7), B_0(25)}

Insert 15: Heap = {B_1(7), B_0(25)} + {B_0(15)}

→ MERGE: {B_1(7), B_0(25), B_0(15)} → link B_0(25) and B_0(15): 15 < 25, so B_1(15, 25)

→ Now: {B_1(7), B_1(15, 25)} → same degree! → link: 7 < 15, so B_2 root=7

B_2: root 7 → child B_1(15, 25) → B_0(12)

     └→ B_1(7) ← wait, this needs care

After MERGE: {B_2(7)} where B_2 has root 7, children B_1(15, 25) and B_0(12)

Insert 28: {B_2(7)} + {B_0(28)} → {B_2(7), B_0(28)}

Insert 33: {B_2(7), B_0(28)} + {B_0(33)} → {B_2(7), B_0(28), B_0(33)}

→ link B_0(28) and B_0(33): B_1(28, 33)

→ {B_2(7), B_1(28, 33)} → degrees differ, stop

Insert 41: {B_2(7), B_1(28, 33)} + {B_0(41)} → {B_2(7), B_1(28, 33), B_0(41)}

Final heap (n=7, binary 111): {B_2(7), B_1(28, 33), B_0(41)}

Worked Example 2: Merge Two Binomial Heaps

Merge H1 = {B_0(3), B_2(7)} and H2 = {B_0(5), B_1(6), B_3(1)}

1. Merge root lists (sorted by degree):

H1 roots: B_0(3), B_2(7) → degree 0, 2

H2 roots: B_0(5), B_1(6), B_3(1) → degree 0, 1, 3

Combined sorted: B_0(3), B_0(5), B_1(6), B_2(7), B_3(1)

2. Process root list:

→ B_0(3) and B_0(5): same degree → LINK: 3 < 5, so B_1(3, 5)

Current: B_1(3, 5), B_1(6), B_2(7), B_3(1)

→ B_1(3, 5) and B_1(6): same degree → LINK: 3 < 6, so B_2(3, 6, 5)

Current: B_2(3, 6, 5), B_2(7), B_3(1)

→ B_2(3, ...) and B_2(7): same degree → LINK: 3 < 7, so B_3(3, 7, 6, 5)

Current: B_3(3, 7, 6, 5), B_3(1)

→ B_3(3, ...) and B_3(1): same degree → LINK: 1 < 3, so B_4(1, 3, 7, 6, 5)

Final result: {B_4(1)} — a single B_4 tree rooted at 1

n = 16 nodes. B_4 has 2^4 = 16 nodes. Binary of 16 = 10000, so only B_4 exists.

Worked Example 3: EXTRACT-MIN

Extract min from H = {B_0(8), B_1(3, 5), B_2(7, 9, 6, 4)}

1. Find min in root list: roots are 8, 3, 7. Minimum = 3 (root of B_1).

2. Remove B_1(3, 5) from root list. Remaining: {B_0(8), B_2(7, 9, 6, 4)}

3. Reverse B_1's children to form new root list:

B_1(3, 5) had child B_0(5). Reversed: single node B_0(5).

4. Create H' = {B_0(5)}.

5. MERGE H and H':

{B_0(8), B_2(7, ...)} + {B_0(5)}

Combined sorted: B_0(8), B_0(5), B_2(7, ...)

→ Link B_0(8) and B_0(5): 5 < 8, so B_1(5, 8)

Current: B_1(5, 8), B_2(7, ...)

Degrees differ → stop

Final: {B_1(5, 8), B_2(7, 9, 6, 4)}

Min = 5 (root of B_1).

Worked Example 4: INSERT with Carry

Insert into H = {B_2(4, ...), B_3(2, ...)} — n=12, binary 1100

Insert key 6:

1. Create H' = {B_0(6)}

2. MERGE: {B_2(4,...), B_3(2,...)} + {B_0(6)}

Combined: B_0(6), B_2(4,...), B_3(2,...)

→ No degree conflicts → done

Result: {B_0(6), B_2(4,...), B_3(2,...)} — n=13, binary 1101 ✓

Now insert key 1:

1. Create H' = {B_0(1)}

2. MERGE: {B_0(6), B_2(4,...), B_3(2,...)} + {B_0(1)}

Combined: B_0(6), B_0(1), B_2(4,...), B_3(2,...)

→ Link B_0(6) and B_0(1): 1 < 6 → B_1(1, 6)

Current: B_1(1, 6), B_2(4,...), B_3(2,...)

→ No more conflicts → done

Result: {B_1(1, 6), B_2(4,...), B_3(2,...)} — n=14, binary 1110 ✓

Worked Example 5: DECREASE-KEY

Decrease key of node 9 to 0 in B_2(4, 9, 7, 6)

Original B_2: root 4 → children: B_1(9, 6) and B_0(7)

Tree structure:

     4

  /     \\

9 → 6     7

1. Set node 9's key to 0:

     4

  /     \\

0 → 6     7

2. Bubble up: 0 < 9's parent(4)? Yes → swap 0 and 4

     0

  /     \\

4 → 6     7

3. 0 is now the root → parent is nil → done

Final: Root changed from 4 to 0. Min-heap property restored.

Key Advantage of Binomial Heap over Binary Heap:
MERGE operation is O(lg n) vs O(n) for binary heap
Binary heap merge requires rebuilding the entire heap. Binomial heap merge is just linking trees of same degree.
Exam Trap: Binomial heap FIND-MIN is O(lg n) worst case (scan all roots). To get O(1), you must maintain a separate pointer to the minimum root. Binary heap FIND-MIN is always O(1) (root).

Space Complexity

Binomial Heap

Space: O(n)

Each node: key + degree + parent + child + sibling pointers

Overhead: O(lg n) pointers for root list

Binary Heap

Space: O(n)

Array-based, no pointer overhead

More cache-friendly

When to Use Binomial Heap over Binary Heap:
When you need efficient MERGE (Union) operations
If your algorithm frequently merges two priority queues (e.g., certain graph algorithms), binomial heap is superior. For just insert/extract, binary heap is simpler and faster in practice.
