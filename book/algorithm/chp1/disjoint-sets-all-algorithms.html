DISJOINT SETS (UNION-FIND)

Data Structures — Complete Algorithm Guide with Worked Examples

1. Disjoint Set Data Structure

A disjoint-set maintains a collection of disjoint dynamic sets. Each set is identified by a representative (the root element).

Core Properties:
Each element belongs to exactly one set
Sets are either identical or disjoint — no partial overlap allowed

Tree Representation

Each set is a rooted tree. Every node stores a pointer to its parent. The root's parent is itself.

   Set A: {0, 1, 2, 3}       Set B: {4, 5, 6}

        0 (root)                  4 (root)
       / \                       / \
      1   2                     5   6
       \
        3

   Parent pointers:            Parent pointers:
   P[0]=0, P[1]=0              P[4]=4, P[5]=4
   P[2]=0, P[3]=1              P[6]=4

Array Representation

Store in array P[] where P[i] = parent of element i. Root if P[i] == i.

Index: 0 1 2 3 4 5 6 P[i]: 0 0 0 1 4 4 4 ^ ^ ^ ^ ^ root root root root root
⚠ Common Mistake: P[i] stores the parent of i, NOT which set i belongs to. To find the set, follow parent pointers to the root!

2. MAKE-SET(x)

Creates a new set containing only element x. Makes x its own parent (root of a singleton tree).

MAKE-SET(x): P[x] = x // x is its own parent (root) Rank[x] = 0 // height = 0 (optional, for union by rank)
Time Complexity:
O(1) — constant time
Just one array assignment

3. FIND(x) — Basic

Returns the representative (root) of the set containing x. Follows parent pointers until reaching a root.

FIND(x): while x ≠ P[x]: x = P[x] return x
Time Complexity:
O(n) worst case — no optimization
May traverse entire chain (e.g., linked list shape)

Example 1: Simple Find (No Compression)

Given: P = [2, 3, 2, 3, 3, 4, 5] — Find the set of element 4
    Tree structure:
          2 (root)
         /
        3
       / \
      1   4
         / \
        0   5
           /
          6

FIND(4):

P[4] = 3 ≠ 4 → move to 3

P[3] = 2 ≠ 3 → move to 2

P[2] = 2 = 2 → root found! Return 2

Path: 4 → 3 → 2 (3 steps). Element 4 belongs to set {2} (represented by root 2).

Example 2: Find in Chain (Worst Case)

Given: P = [1, 2, 3, 4, 5, 5] — Find the set of element 0
    Chain structure:
    0 → 1 → 2 → 3 → 4 → 5 (root)

FIND(0):

P[0] = 1 ≠ 0 → move to 1

P[1] = 2 ≠ 1 → move to 2

P[2] = 3 ≠ 2 → move to 3

P[3] = 4 ≠ 3 → move to 4

P[4] = 5 ≠ 4 → move to 5

P[5] = 5 = 5 → root found! Return 5

⚠ O(n) time! Chain of length 6 requires 5 pointer dereferences. This is why we need path compression!

Example 3: Find Multiple Elements

Given: P = [0, 0, 0, 1, 4, 4, 4] — Find(3), Find(6), Find(5)
    Tree A: {0,1,2,3}     Tree B: {4,5,6}
        0 (root)              4 (root)
       / \                   / \
      1   2                 5   6
       \
        3

FIND(3): P[3]=1≠3 → P[1]=0≠1 → P[0]=0 → Return 0

FIND(6): P[6]=4≠6 → P[4]=4 → Return 4

FIND(5): P[5]=4≠5 → P[4]=4 → Return 4

FIND(3) = 0, FIND(6) = FIND(5) = 4. Elements 5 and 6 are in the same set.

4. UNION(a, b) — Naive

Merges the sets containing a and b. Makes one root point to the other root.

UNION(a, b): rootA = FIND(a) rootB = FIND(b) if rootA ≠ rootB: P[rootA] = rootB // make rootA a child of rootB
Time Complexity:
O(n) per UNION (due to FIND)
FIND can be O(n) in worst case; union itself is O(1)
⚠ Danger: Naive union can create degenerate trees (chains). After n unions, FIND can take O(n) time!

Example 1: Sequential Naive Union

Problem: UNION(0,1), UNION(1,2), UNION(2,3), UNION(3,4) with naive union

Initial: P = [0,1,2,3,4] — five singleton sets

UNION(0,1): FIND(0)=0, FIND(1)=1. P[0]=1

P = [1,1,2,3,4] — Set: {0,1}

UNION(1,2): FIND(1)=1, FIND(2)=2. P[1]=2

P = [1,2,2,3,4] — Set: {0,1,2}

UNION(2,3): FIND(2)=2, FIND(3)=3. P[2]=3

P = [1,2,3,3,4] — Set: {0,1,2,3}

UNION(3,4): FIND(3)=3, FIND(4)=4. P[3]=4

P = [1,2,3,4,4] — Set: {0,1,2,3,4}

    Final tree (chain!):
    0 → 1 → 2 → 3 → 4 (root)

    FIND(0) now takes O(5) = O(n) time!

⚠ Worst case: a sequence of n-1 unions creates a chain of length n.

Example 2: Naive Union with Finds

Problem: Process UNION(0,1), UNION(2,3), FIND(0), FIND(3), UNION(1,2), FIND(0)

Initial: P = [0,1,2,3]

UNION(0,1): P[0]=1 → P = [1,1,2,3]

UNION(2,3): P[2]=3 → P = [1,1,3,3]

FIND(0): P[0]=1≠0, P[1]=1 → Return 1

P = [1,3,3,3]

FIND(0): P[0]=1≠0, P[1]=3≠1, P[3]=3 → Return 3

Now FIND(0) takes 3 steps: 0→1→3

Example 3: Building a Degenerate Tree

Problem: UNION(0,1), UNION(0,2), UNION(0,3), UNION(0,4) — always attach to existing root

Initial: P = [0,1,2,3,4]

UNION(0,1): Root(0)=0, Root(1)=1. P[1]=0 → P = [0,0,2,3,4]

UNION(0,2): Root(0)=0, Root(2)=2. P[2]=0 → P = [0,0,0,3,4]

    Final tree (star shape — best case for naive!):
            0 (root)
           /|\ \ 
          1 2 3 4

    FIND(1) = O(1), FIND(4) = O(1)

When we always attach smaller trees to the same root, we get a star (good). But naive union doesn't guarantee this!

5. UNION by Rank

Always attach the shorter tree under the root of the taller tree. Rank is an upper bound on height.

MAKE-SET(x): P[x] = x Rank[x] = 0 UNION(a, b): rootA = FIND(a) rootB = FIND(b) if rootA = rootB: return if Rank[rootA] < Rank[rootB]: P[rootA] = rootB // rootA becomes child elif Rank[rootA] > Rank[rootB]: P[rootB] = rootA // rootB becomes child else: // equal ranks P[rootB] = rootA // make one child Rank[rootA]++ // rank increases by 1
Guarantee:
Tree height ≤ lg(n)
Rank only increases when two equal-rank trees merge. A node's rank can increase at most lg(n) times.

Example 1: Union by Rank — Building a Balanced Tree

Problem: UNION(0,1), UNION(2,3), UNION(0,2), UNION(4,5), UNION(6,7), UNION(4,6), UNION(0,4)

Initial: P = [0,1,2,3,4,5,6,7], Rank = [0,0,0,0,0,0,0,0]

UNION(0,1): Rank[0]=Rank[1]=0. P[1]=0, Rank[0]++

P = [0,0,2,3,4,5,6,7], Rank = [1,0,0,0,0,0,0,0]

UNION(2,3): Rank[2]=Rank[3]=0. P[3]=2, Rank[2]++

P = [0,0,2,2,4,5,6,7], Rank = [1,0,1,0,0,0,0,0]

UNION(0,2): Rank[0]=1, Rank[2]=1. Equal! P[2]=0, Rank[0]++

P = [0,0,0,2,4,5,6,7], Rank = [2,0,1,0,0,0,0,0]

UNION(4,5): Rank[4]=Rank[5]=0. P[5]=4, Rank[4]++

P = [0,0,0,2,4,4,6,7], Rank = [2,0,1,0,1,0,0,0]

UNION(6,7): Rank[6]=Rank[7]=0. P[7]=6, Rank[6]++

P = [0,0,0,2,4,4,6,6], Rank = [2,0,1,0,1,0,1,0]

UNION(4,6): Rank[4]=1, Rank[6]=1. Equal! P[6]=4, Rank[4]++

P = [0,0,0,2,4,4,4,6], Rank = [2,0,1,0,2,0,1,0]

UNION(0,4): Rank[0]=2, Rank[4]=2. Equal! P[4]=0, Rank[0]++

P = [0,0,0,2,0,4,4,6], Rank = [3,0,1,0,2,0,1,0]

    Final tree (height 3, but balanced):
                 0 (root, rank=3)
               /   \
              1     4 (rank=2)
             /     / \
            2     5   6 (rank=1)
           /         /
          3         7

    Height = 3 = lg(8). Much better than chain of 7!

Example 2: Union by Rank vs Naive

Compare: Same unions with naive vs union by rank

Naive union (UNION(0,1), UNION(1,2), UNION(2,3), UNION(3,4)):

Creates chain: 0→1→2→3→4. Height = 4.

FIND(0) takes 4 steps.

Union by rank (same operations):

UNION(0,1): rank equal → P[1]=0, Rank[0]=1

UNION(0,2): Rank[0]=1 > Rank[2]=0 → P[2]=0

UNION(0,3): Rank[0]=1 > Rank[3]=0 → P[3]=0

UNION(0,4): Rank[0]=1 > Rank[4]=0 → P[4]=0

    Union by Rank result:
          0 (root, rank=1)
         /|\ \ 
        1 2 3 4

    Height = 1. FIND(0) takes 1 step!

Union by rank: height lg(n) vs naive: height O(n)

Example 3: Rank Tie-Breaking

Demonstrate: What happens when ranks are equal vs different

Case 1: Rank[rootA] < Rank[rootB]

Example: Rank[3]=1, Rank[5]=2 → P[3]=5 (smaller tree goes under)

Rank[5] stays 2 (no change)

Case 2: Rank[rootA] > Rank[rootB]

Example: Rank[2]=2, Rank[7]=1 → P[7]=2 (smaller tree goes under)

Rank[2] stays 2 (no change)

Case 3: Rank[rootA] = Rank[rootB]

Example: Rank[1]=1, Rank[4]=1 → P[4]=1, Rank[1]++ = 2

Only equal-rank merges increase the rank!

Rank only increases when two trees of EQUAL rank merge. This guarantees height ≤ lg(n).

6. Path Compression

During FIND, make every node on the path point directly to the root. This flattens the tree permanently.

FIND(x): if x ≠ P[x]: P[x] = FIND(P[x]) // path compression (recursive) return P[x]
Effect:
After FIND(x), all nodes on path point to root
Future FINDs on those nodes become O(1)
⚠ Important: Path compression is applied only during FIND, NOT during UNION. It permanently modifies the tree structure.

Example 1: Path Compression on a Chain

Given: P = [1,2,3,4,5,5] — Perform FIND(0)
    BEFORE FIND(0):
    0 → 1 → 2 → 3 → 4 → 5 (root)

FIND(0) — Recursive:

FIND(0): P[0]=1≠0, call FIND(1)

FIND(1): P[1]=2≠1, call FIND(2)

FIND(2): P[2]=3≠2, call FIND(3)

FIND(3): P[3]=4≠3, call FIND(4)

FIND(4): P[4]=5≠4, call FIND(5)

FIND(5): P[5]=5 → return 5 (root)

Backtrack: P[4]=5, P[3]=5, P[2]=5, P[1]=5, P[0]=5

    AFTER FIND(0):
    0 → 5 (root)
    1 → 5
    2 → 5
    3 → 5
    4 → 5

    P = [5,5,5,5,5,5]
    All nodes now point directly to root!

FIND(0) now takes O(1) for any subsequent call!

Example 2: Path Compression on a Tree

Given: Tree with root 1 — Perform FIND(7)
    BEFORE FIND(7):
          1 (root)
         / \
        2   3
       / \   \
      4   5   6
     /     \
    7       8

Path from 7 to root: 7 → 4 → 2 → 1

AFTER FIND(7): Nodes 7, 4, 2 all point directly to root 1

    AFTER FIND(7):
          1 (root)
         /|\
        2 3 4    ← 2 and 4 now point to 1
       / \ \
      7   5 6    ← 7 now points to 1
           \
            8

Node 5 and 8 are NOT on the path, so they're unchanged. Only nodes on the find path get compressed.

Example 3: Multiple FINDs with Compression

Start: P = [1,2,3,4,5,5] — Perform FIND(0), then FIND(1), then FIND(2)

Initial: P = [1,2,3,4,5,5] — chain 0→1→2→3→4→5

FIND(0): Path 0→1→2→3→4→5. After: P = [5,5,5,5,5,5]

All nodes 0-4 now point to 5

FIND(1): P[1]=5 → O(1)! Return 5

No compression needed (already compressed)

FIND(2): P[2]=5 → O(1)! Return 5

No compression needed (already compressed)

After first FIND(0) costs O(n), all subsequent FINDs on those nodes are O(1)!

7. Union by Rank + Path Compression

Using both optimizations together gives near-constant amortized time per operation.

MAKE-SET(x): P[x] = x Rank[x] = 0 FIND(x): if x ≠ P[x]: P[x] = FIND(P[x]) // path compression return P[x] UNION(a, b): rootA = FIND(a) rootB = FIND(b) if rootA = rootB: return if Rank[rootA] < Rank[rootB]: P[rootA] = rootB elif Rank[rootA] > Rank[rootB]: P[rootB] = rootA else: P[rootB] = rootA Rank[rootA]++

Example 1: Complete Sequence with Both Optimizations

Problem: Process 8 elements with UNION(0,1), UNION(2,3), UNION(4,5), UNION(6,7), UNION(0,2), UNION(4,6), UNION(0,4), then FIND(7)

Initial: P = [0,1,2,3,4,5,6,7], Rank = [0,0,0,0,0,0,0,0]

UNION(0,1): Rank equal → P[1]=0, Rank[0]=1

UNION(2,3): Rank equal → P[3]=2, Rank[2]=1

UNION(4,5): Rank equal → P[5]=4, Rank[4]=1

UNION(6,7): Rank equal → P[7]=6, Rank[6]=1

UNION(0,2): Rank[0]=1 = Rank[2]=1 → P[2]=0, Rank[0]=2

UNION(4,6): Rank[4]=1 = Rank[6]=1 → P[6]=4, Rank[4]=2

UNION(0,4): Rank[0]=2 = Rank[4]=2 → P[4]=0, Rank[0]=3

    BEFORE FIND(7):
                 0 (rank=3)
               /   \
              1     4 (rank=2)
                    / \
                   5   6 (rank=1)
                       /
                      7

    Path from 7: 7 → 6 → 4 → 0

FIND(7) with path compression:

FIND(7): P[7]=6≠7, call FIND(6)

FIND(6): P[6]=4≠6, call FIND(4)

FIND(4): P[4]=0≠4, call FIND(0)

FIND(0): P[0]=0 → return 0

Backtrack: P[4]=0, P[6]=0, P[7]=0

    AFTER FIND(7):
                 0 (rank=3)
               / | \ \
              1  4  6 7   ← 4, 6, 7 now point to 0
                 |
                 5

    P = [0,0,0,2,0,4,0,0]

Path compression flattened the right side. FIND(6) and FIND(7) are now O(1)!

Example 2: Kruskal's MST with Union-Find

Problem: Use union-find to detect cycles while building MST

Edges (sorted by weight): (0,1,1), (2,3,1), (0,2,2), (1,3,2), (0,3,3)

Edge (0,1): FIND(0)=0, FIND(1)=1. Different → UNION. Add to MST.

Edge (2,3): FIND(2)=2, FIND(3)=3. Different → UNION. Add to MST.

Edge (0,2): FIND(0)=0, FIND(2)=2. Different → UNION. Add to MST.

Edge (1,3): FIND(1)=0, FIND(3)=0. Same! CYCLE — skip edge

Edge (0,3): FIND(0)=0, FIND(3)=0. Same! CYCLE — skip edge

    MST: (0,1), (2,3), (0,2) — total weight = 4
    Cycle edges rejected: (1,3), (0,3)

Union-find efficiently detects cycles: if FIND(u) == FIND(v), adding edge (u,v) creates a cycle.

Example 3: Connected Components

Problem: Find connected components in graph with edges (0,1), (1,2), (3,4), (4,5), (2,5)

Initial: 6 singleton sets: {0}, {1}, {2}, {3}, {4}, {5}

Edge (0,1): UNION(0,1) → {0,1}, {2}, {3}, {4}, {5}

Edge (1,2): UNION(1,2) → {0,1,2}, {3}, {4}, {5}

8. Complexity Analysis

Inverse Ackermann Function:
α(n) = min{i ≥ 1 : A(i, 1) ≥ n}
A(i,j) is the Ackermann function. For all practical n, α(n) ≤ 4.

Example: Comparing Approaches

Problem: 1 million operations on 1 million elements

Naive: O(m·n) = O(10^6 × 10^6) = O(10^12) — too slow!

Union by rank: O(m·lg n) = O(10^6 × 20) = O(2×10^7) — fast!

Both optimizations: O(m·α(n)) = O(10^6 × 4) = O(4×10^6) — essentially constant!

Space:

9. Applications of Union-Find

Kruskal's MST

Detect cycles when adding edges. If FIND(u) == FIND(v), edge (u,v) creates a cycle.

Connected Components

Merge vertices as edges are processed. FIND(u) == FIND(v) means u and v are connected.

Equivalence Relations

Maintain equivalence classes. UNION(a,b) means a ≡ b.

Percolation

Model fluid flow through porous material. Connect top/bottom to detect percolation.

Image Processing

Connected component labeling in binary images.

Network Connectivity

Dynamic connectivity queries: are two nodes connected?

Find MST of graph with edges: (0,1,4), (0,2,8), (1,2,11), (1,3,8), (2,4,7), (3,4,1), (3,5,4), (4,5,6)

Sorted edges: (3,4,1), (0,1,4), (3,5,4), (4,5,6), (2,4,7), (0,2,8), (1,3,8), (1,2,11)

Edge (3,4,1): FIND(3)=3, FIND(4)=4. Different → UNION. MST: {(3,4)}

Edge (0,1,4): FIND(0)=0, FIND(1)=1. Different → UNION. MST: {(3,4), (0,1)}

Edge (3,5,4): FIND(3)=3, FIND(5)=5. Different → UNION. MST: {(3,4), (0,1), (3,5)}

Edge (4,5,6): FIND(4)=3, FIND(5)=3. Same → CYCLE, skip

Edge (2,4,7): FIND(2)=2, FIND(4)=3. Different → UNION. MST: {(3,4), (0,1), (3,5), (2,4)}

Edge (0,2,8): FIND(0)=0, FIND(2)=3. Different → UNION. MST: {(3,4), (0,1), (3,5), (2,4), (0,2)}

Edge (1,3,8): FIND(1)=0, FIND(3)=0. Same → CYCLE, skip

Edge (1,2,11): FIND(1)=0, FIND(2)=0. Same → CYCLE, skip

MST: {(3,4,1), (0,1,4), (3,5,4), (2,4,7), (0,2,8)} — Total weight = 24

Application 2: Dynamic Connectivity

Process: UNION(0,1), UNION(2,3), FIND(0,3), UNION(1,2), FIND(0,3)

UNION(0,1): Sets: {0,1}, {2}, {3}

UNION(2,3): Sets: {0,1}, {2,3}

Query: Are 0 and 3 connected? FIND(0)=0, FIND(3)=2. Different → NO

UNION(1,2): Sets: {0,1,2,3}

Query: Are 0 and 3 connected? FIND(0)=0, FIND(3)=0. Same → YES!

Union-find answers connectivity queries in near-constant time after each update.

Application 3: Percolation Problem

Model: N×N grid, cells can be open or blocked. System percolates if top connects to bottom.

Setup: Create virtual top node (N²) and virtual bottom node (N²+1)

Open cell (i,j): UNION with all adjacent open cells

Top row cells: UNION with virtual top node

Bottom row cells: UNION with virtual bottom node

Percolates? FIND(virtual top) == FIND(virtual bottom)?

Union-find efficiently tracks connectivity as cells open dynamically.

Application 4: Equivalence Classes

Problem: Process equivalences: (a,b), (b,c), (d,e), (c,d). Find all equivalence classes.

Initial: {a}, {b}, {c}, {d}, {e}

(a,b): UNION(a,b) → {a,b}, {c}, {d}, {e}

(b,c): UNION(b,c) → {a,b,c}, {d}, {e}

(d,e): UNION(d,e) → {a,b,c}, {d,e}

(c,d): UNION(c,d) → {a,b,c,d,e}

All elements are equivalent — one equivalence class.
