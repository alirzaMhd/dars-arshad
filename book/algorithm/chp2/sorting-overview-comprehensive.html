Sorting Algorithms Overview

Algorithm Design — Complete Guide for 20/20 Exam

Sorting Algorithm Classification

By Stability

Stable

Elements with equal keys maintain their relative order in the output.

Example: [3a, 1, 3b, 2] → [1, 2, 3a, 3b]

Bubble Sort, Insertion Sort, Merge Sort

Unstable

Equal elements may be rearranged in the output.

Example: [3a, 1, 3b, 2] → [1, 2, 3b, 3a]

Selection Sort, Quick Sort, Heap Sort

By Space Usage

In-Place

Uses constant extra space O(1) beyond input.

Selection, Bubble, Insertion, Quick, Heap Sort

Out-of-Place

Requires additional memory proportional to n.

Merge Sort, Counting Sort, Radix Sort

Comparison-Based Sorting Algorithms

These algorithms work by comparing pairs of elements. The main operation is comparison between elements.

Bubble Sort Θ(n) Θ(n²) Θ(n²) O(1) Yes Yes
Insertion Sort Θ(n) Θ(n²) Θ(n²) O(1) Yes Yes

Key Properties to Remember

Important Facts:

1. All comparison-based sorts have a lower bound of Ω(n lg n) in the average/worst case.

2. If array is already sorted: Insertion Sort and Bubble Sort run in Θ(n).

3. If all elements are equal: Bubble, Insertion, Heap Sort run in Θ(n), but Quick Sort degrades to Θ(n²).

4. Maximum comparisons for Bubble, Insertion, Quick Sort: n(n-1)/2

5. Maximum comparisons for Selection Sort: n(n-1)/2 (always)

6. Maximum swaps for Selection Sort: n-1 (always)

7. Maximum swaps for Bubble/Insertion Sort: n(n-1)/2

When to Use Each Algorithm

Insertion Sort

• Small arrays (n ≤ 25)

• Nearly sorted arrays

• Online sorting

Quick Sort

• General purpose

• Average case performance

• Cache-friendly

Merge Sort

• Guaranteed O(n lg n)

• Stable sorting needed

• External sorting

Heap Sort

• Guaranteed O(n lg n)

• In-place required

• Priority queue operations

Complexity Bounds

Lower Bound for Comparison Sorts:
Ω(n lg n)
Proven using decision tree model - any comparison sort must make at least n! leaf comparisons
Decision Tree Height:
h ≥ ⌈lg(n!)⌉
Minimum number of comparisons needed in worst case
Stirling's Approximation:
lg(n!) ≈ n lg n - n lg e
Used to show lg(n!) = Θ(n lg n)

Non-Comparison Based Sorts

These algorithms can beat the Ω(n lg n) lower bound by not using comparisons. All three are stable and out-of-place.

Algorithm Time Space Stable In-Place Constraint
Counting Sort Θ(n + k) O(k) Yes No Integers in range [1..k]
Radix Sort Θ(d(n + r)) O(n + r) Yes No d digits, base r
Bucket Sort Θ(n) average O(n) Yes No Uniform distribution

Chapter Summary — Key Formulas & Facts

Finding Min / Max

Finding Min (or Max) alone:
n − 1 comparisons
Each element (except the first) must be compared once
Finding Min AND Max together:
⌈3n/2⌉ − 2 comparisons
n even: 3n/2 − 2  |  n odd: (3n − 3)/2
Achieved by the pairwise (pairing) method: form ⌊n/2⌋ pairs, compare each pair, then compare winners

Finding Second Minimum

Minimum comparisons for 2nd smallest:
n + ⌈lg n⌉ − 2
Tournament method: n−1 comparisons for the minimum, then at most ⌈lg n⌉−1 among elements that lost to the minimum

Finding k-th Smallest

Lower bound for k-th smallest:
n + (k−1)·⌈lg k⌉ − 2k
Generalization of the tournament method. For k = 1 (minimum) reduces to n−1. For k = 2 (second min) reduces to n + ⌈lg n⌉ − 2.
Select algorithm (Median of Medians):
Θ(n) worst-case
Groups of 5, find median of medians as pivot, guarantees at most 7n/10 + 6 elements in recursive call

When All Elements Are Equal

Algorithm Complexity Reason
Bubble Sort Θ(n) No swaps needed after one pass
Insertion Sort Θ(n) Each element ≥ previous, no inner loop swaps
Heap Sort Θ(n) Build-heap O(n), no swaps during extract (all equal)
Quick Sort Θ(n²) Worst-case partitioning (all elements go to one side)

Non-Comparison Sorts

Counting Sort, Radix Sort, Bucket Sort are all:

• Stable — equal elements preserve original order

• Out-of-Place — require auxiliary arrays

• Non-Comparison — can beat Ω(n lg n) lower bound
