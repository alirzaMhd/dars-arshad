Radix Sort Algorithm

A non-comparison based sorting algorithm that sorts integers by processing individual digits. It sorts from least significant digit (LSD) to most significant digit (MSD) using a stable sort (usually Counting Sort).

radixsort(A[1..n], d, r)
{
  // d = number of digits, r = base (radix)
  for (i = 1 to d)
  {
    // Sort by i-th digit using stable sort
    countingsort(A, r, digit i);
  }
}
Key Parameters:
d = number of digits, r = base (radix)
For decimal numbers: r = 10. For binary: r = 2.
Important: The intermediate sort MUST be stable. Counting Sort is typically used because it's stable and efficient for small ranges (0 to r-1).
Note: Radix Sort uses Counting Sort as its stable inner subroutine. For each digit position i, Counting Sort is called on the digit values (range 0 to r−1), taking Θ(n + r) time. This is repeated for all d digit positions, giving the total Θ(d(n + r)) complexity.

How Radix Sort Works

Step-by-Step Process

1. Start with the least significant digit (rightmost)

2. Sort the array by this digit using a stable sort

3. Move to the next digit (one position left)

4. Sort by this digit, maintaining stability

5. Repeat until all digits are processed

Why LSD to MSD?
Processing LSD first ensures correctness
When we sort by a higher digit, the lower digit order is already correct (due to stability)
Why LSD-first works:

Sorting from least significant digit to most significant digit is correct because each pass uses a stable sort (Counting Sort). Stability ensures that if two numbers have the same digit in the current position, their relative order from previous (lower) digit passes is preserved. This means the partial order established by earlier passes is never destroyed — it is refined by each subsequent pass.

Example with 3-digit numbers

Numbers: 209, 158, 098, 029, 109, 123

Step 1: Sort by ones digit → [123, 158, 098, 209, 029, 109]

Step 2: Sort by tens digit → [209, 109, 123, 029, 158, 098]

Step 3: Sort by hundreds digit → [029, 098, 109, 123, 158, 209]

Example 4: Choosing Optimal Base

n = 1000 numbers, max value = 10^6

With base 10: d = 6 digits, each digit in [0..9]

Time: 6 × (1000 + 10) = 6060

With base 1000: d = 2 digits, each digit in [0..999]

Time: 2 × (1000 + 1000) = 4000

Using base n is often optimal: d ≈ log_n(max value)

Example 5: Numbers in Range [0, n4 − 1] — Comparing Strategies

Given n numbers in the range [0, n4 − 1], analyze the time complexity of different sorting approaches:

(a) Counting Sort directly:

k = n4 (the range size), so time = Θ(n + k) = Θ(n + n4) = Θ(n4)

Counting Sort is terrible here because k = n4 is enormous.

(b) Radix Sort with base r = 10:

Number of digits: d = ⌈log10(n4)⌉ = ⌈4·log10(n)⌉

Time = Θ(d·(n + r)) = Θ(4·log10(n)·(n + 10)) = Θ(n·lg n)

Better than Θ(n4), but still super-linear due to the log factor.

(c) Radix Sort with optimal base r = n:

Number of digits: d = ⌈logn(n4)⌉ = 4 digits

Time = Θ(d·(n + r)) = Θ(4·(n + n)) = Θ(n)

LINEAR TIME! Choosing base r = n gives d = 4 constant digits, making Radix Sort run in Θ(n).

Key Insight: Choosing the right base r is critical. The optimal base balances d (number of digits) and r (range per digit). Setting r = n minimizes d = ⌈logn(max)⌉ while keeping each Counting Sort pass at Θ(n + n) = Θ(n).

Time Complexity Analysis

For each digit:
Θ(n + r)
Time for one Counting Sort pass
Total Time:
d × Θ(n + r) = Θ(d(n + r))
d passes, each takes Θ(n + r)
Space Complexity:
O(n + r)
For the Counting Sort auxiliary arrays

Special Cases

Base n

If r = n:

d = ⌈log_n(max)⌉

Time: O(d × 2n) = O(dn)

Fixed Range

If max value is constant:

d is constant

Time: O(n)

When is Radix Sort efficient?

When d × (n + r) < n lg n

This happens when numbers have few digits relative to lg n

Properties of Radix Sort

Stable

Yes

Uses stable sort for each digit

In-Place

No

Requires O(n + r) extra space

Comparison-Based

No

Digit-based, not comparison-based

Constraint

Integers with bounded digits

Advantages:

• Can be faster than O(n lg n) for integers

• Stable sort

• Simple to implement

Disadvantages:

• Only works for integers (or strings)

• Not efficient for floating point numbers

• Performance depends on choice of base r
