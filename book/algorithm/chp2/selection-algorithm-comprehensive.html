Selection Algorithm (Select)

Algorithm Design — Complete Guide for 20/20 Exam

What is the Selection Problem?

The selection problem is one of the fundamental problems in computer science and algorithm design. Given an unsorted array A of n elements, your task is to find the k-th smallest element in that array. This element is also known as the k-th order statistic. The selection problem appears frequently in real-world applications such as finding the median salary, the top-k scores, or the 90th percentile in a dataset.

Formal Problem Statement:
Find the k-th minimum in array A[1..n]
k is the rank we're looking for (1 ≤ k ≤ n). The k-th smallest element means there are exactly k-1 elements smaller than it and n-k elements larger than it in the array.
Concrete Example:

Consider the array A = [7, 10, 4, 3, 20, 15]. If k = 3, we want the 3rd smallest element. First, let's sort: [3, 4, 7, 10, 15, 20]. The 3rd smallest is 7. Notice that there are exactly 2 elements smaller than 7 (namely 3 and 4) and 3 elements larger than 7 (namely 10, 15, 20). This confirms that 7 is indeed the 3rd smallest element.

Special Cases

• k = 1: Find the minimum element in the array. This is the smallest element overall.

• k = n: Find the maximum element in the array. This is the largest element overall.

• k = ⌈n/2⌉: Find the median. This is the middle element that splits the array into two equal halves.

• k = ⌊n/4⌋: Find the lower quartile (25th percentile).

• k = ⌊3n/4⌋: Find the upper quartile (75th percentile).

Naive Approach (Sorting)

• Sort the entire array using any comparison-based sorting algorithm (e.g., merge sort, quicksort, heap sort).

• Return the element at position A[k] in the sorted array.

Time: O(n lg n) — this is dominated by the sorting step.

Space: O(n) if using merge sort, or O(1) if in-place like heapsort.

Problem: We're doing much more work than necessary. We only need ONE element, but sorting computes ALL order information.

Why Not Just Sort?

Sorting the entire array to find one element is like reading an entire encyclopedia to answer one question. While it works, it's wasteful. The sorting approach costs O(n lg n) time, but we can do much better. The goal of the selection problem is to find the k-th smallest element WITHOUT fully sorting the array, ideally in linear O(n) time. The Select algorithm achieves exactly this — it finds the k-th smallest element in guaranteed Θ(n) time, which is optimal for comparison-based selection.

Applications of Selection

• Finding the median: Used in statistics, robust estimation, and as a pivot in quickselect.

• Order statistics: Finding the 90th percentile of test scores, the top-10% of earners, etc.

• Divide-and-conquer algorithms: Many algorithms need the median to partition data evenly.

• Computational geometry: Finding the median x-coordinate to split point sets.

• Load balancing: Finding the median task length to balance workloads.

• Network routing: Selecting median latency for routing decisions.

The Select Algorithm — Detailed Explanation

The Select algorithm is a clever divide-and-conquer algorithm that finds the k-th smallest element in an unsorted array in guaranteed Θ(n) linear time. It was designed by Blum, Floyd, Pratt, Rivest, and Tarjan in 1973. The key idea is to use a "median of medians" pivot selection strategy that guarantees the pivot is reasonably close to the true median, ensuring that the recursion makes sufficient progress on every call.

High-Level Strategy:

The algorithm works by selecting a "good" pivot element, partitioning the array around that pivot, and then recursively searching only one side of the partition. The genius of the algorithm is in how it chooses the pivot: it uses the "median of medians" technique to guarantee that the pivot is always in the middle 30% of the array (between ranks 3n/10 and 7n/10), which ensures that each recursive call reduces the problem size by at least a constant fraction.

sel(A[L..u], k)
{
  n = u - L + 1; // Compute array size
  if (n ≤ 25) use brute force! // Base case: sort and return A[L+k-1]
  else {
    m = ⌈n/5⌉; B[1..m] // m = number of groups of 5
    /* Step 1: Find medians of groups of 5 */
    for (i = 1 to m)
      B[i] = sel(A[5i-4 .. 5i], 3); // Find median of i-th group
    /* Step 2: Find median of medians */
    x = sel(B[1..m], ⌈m/2⌉); // Recursively find median of B
    /* Step 3: Partition around x */
    j = partition(A[L..u], x); // Partition array around pivot x
    i = j - L + 1; // i = rank of pivot x
    /* Step 4: Check position and recurse */
    if (k == i) return A[j]; // x is the k-th smallest
    else if (k < i) return sel(A[L..j-1], k); // k-th is in left part
    else return sel(A[j+1..u], k-i); // k-th is in right part
  }
}
Step-by-Step Breakdown:

Step 1 — Divide into groups of 5: The array A[L..u] of size n is divided into ⌈n/5⌉ groups, each containing exactly 5 elements (except possibly the last group which may have fewer). For each group, we find its median using any method (even brute-force sorting of 5 elements takes constant time Θ(1)). We store all these medians in a new array B[1..m] where m = ⌈n/5⌉.

Step 2 — Find median of medians: We recursively call sel(B[1..m], ⌈m/2⌉) to find the median of the medians array B. This gives us a pivot element x. The crucial property is that x is guaranteed to be between ranks 3n/10 and 7n/10 in the original array.

Step 3 — Partition around pivot x: We partition the original array A around x using a standard partition procedure (similar to quicksort's partition). After partitioning, all elements to the left of x are ≤ x, and all elements to the right are > x. Let j be the final position of x in the array.

Step 4 — Recurse on the correct side: We compute i = j - L + 1, which is the rank of x in the current subarray. If k == i, then x is our answer. If k < i, we recurse on the left subarray A[L..j-1] looking for the k-th smallest. If k > i, we recurse on the right subarray A[j+1..u] looking for the (k-i)-th smallest (since i elements are to the left of x).

Key Insight — Why groups of 5? The choice of group size 5 is NOT arbitrary. Groups of 5 are the smallest odd group size that guarantees linear time. Groups of 3 yield Θ(n lg n) (no better than sorting), while groups of 5 yield Θ(n). Any group size ≥ 5 works, but 5 gives the smallest constants. The critical property: with groups of 5, at least 3n/10 elements are guaranteed to be ≤ the median of medians, ensuring the larger partition is at most 7n/10, which gives the recurrence T(n) = T(n/5) + T(7n/10) + Θ(n) with solution Θ(n).
Why threshold 25 for brute force? For very small arrays (n ≤ 25), the overhead of the recursive algorithm (partitioning, finding medians, etc.) is actually MORE expensive than just sorting the array and picking the k-th element. The constant factors in the recursive calls (function call overhead, partitioning passes) make brute force more efficient for small n. The threshold 25 is a practical choice — some implementations use 15 or 50. The key point is that the base case handles small inputs directly.
The Partition Procedure (Lomuto or Hoare):

The partition procedure rearranges array elements around a pivot x. After partitioning:

• All elements in positions L to j-1 are ≤ x (less than or equal to the pivot)

• Element at position j equals x (the pivot is placed here)

• All elements in positions j+1 to u are > x (greater than the pivot)

• j is the final rank of x in the current subarray

Partition takes Θ(n) time — just one pass through the array. This is the same partition used in quicksort. The partition is stable if using Lomuto's scheme, and in-place (no extra array needed).

Why Does This Algorithm Work?

The algorithm works because of the "progress guarantee" — at every level of recursion, the problem size decreases by a constant fraction. Specifically:

• The median of medians step (T(n/5)) ensures we find a good pivot in time proportional to n/5.

• The good pivot guarantees that at least 3n/10 elements are on each side, so the larger recursive call is at most T(7n/10).

• Since 1/5 + 7/10 = 9/10 < 1, the total work decreases geometrically, giving Θ(n) overall.

• Without the median of medians pivot selection, we could get unlucky and always pick the worst pivot, leading to O(n²) like naive quickselect.

Median of Medians — Deep Dive Analysis

The "median of medians" is the heart of the Select algorithm. This technique guarantees that the pivot we choose is always a "good" pivot — one that falls in the middle 30% of the array. Understanding why this works requires careful analysis of each step and how the bounds propagate through the array.

Step 1: Divide into groups of 5

Array A of size n is divided into ⌈n/5⌉ groups, each containing exactly 5 elements (except possibly the last group which may have fewer than 5 elements). This step is straightforward — we simply walk through the array and group consecutive elements. No sorting or comparison is needed here, just the grouping. Time: Θ(n) — we scan through the array exactly once, assigning each element to a group.

For example, if n = 17, we get ⌈17/5⌉ = 4 groups: [A[1..5]], [A[6..10]], [A[11..15]], [A[16..17]] (the last group has only 2 elements).

Step 2: Find median of each group

For each group of 5 elements, we find the median (the 3rd smallest element). We can do this by sorting each group and picking the middle element. Since each group has at most 5 elements, sorting takes Θ(1) constant time per group. There are ⌈n/5⌉ groups, so the total time for this step is Θ(n/5) = Θ(n). We store all these medians in a new array B[1..m] where m = ⌈n/5⌉.

Why is finding the median of 5 elements constant time? Because 5 is a fixed constant — the number of comparisons needed to sort 5 elements is at most 7 (using an optimal sorting network). This doesn't depend on n, so it's Θ(1) per group.

Step 3: Recursively find median of B

We now have an array B of m = ⌈n/5⌉ medians. We recursively call sel(B[1..m], ⌈m/2⌉) to find the median of these medians. Let's call this element x. The time for this step is T(⌈n/5⌉) — a recursive call on a problem of size n/5. This is the "median of medians" — the element x that will serve as our pivot.

Recurrence for Steps 1-3:
T(n/5)
Finding the median of ⌈n/5⌉ medians requires a recursive call on a problem of size n/5. This is the "cost of choosing a good pivot."

Step 4: Partition and recurse on the correct side

Now we partition the original array A around the pivot x. After partitioning, we know exactly where x sits in the array. The crucial question is: how large can the larger side be? This is where the 3n/10 bound comes in — the median of medians guarantees that at least 3n/10 elements are ≤ x and at least 3n/10 elements are ≥ x. Therefore, the larger side has at most 7n/10 elements.

Worst case for Step 4:
T(7n/10 + 6)
At most 7n/10 + 6 elements on one side of x. The +6 accounts for edge cases: the last group (may have <5 elements) and the group containing x itself. These edge cases can reduce the guaranteed bound by at most 6 elements.
Precise Recurrence (with boundary constants):
T(n) = T(⌈n/5⌉) + T(7n/10 + 6) + Θ(n)
The total recurrence includes: T(n/5) for finding the median of medians, T(7n/10 + 6) for recursing on the larger partition side, and Θ(n) for the partitioning step and the group median computations.

Detailed 3n/10 Bound Derivation — Why At Least 3n/10 Elements ≤ x

This is the most critical part of the analysis. We need to prove that the median of medians x guarantees at least 3n/10 elements are ≤ x (and by symmetry, at least 3n/10 are ≥ x). This ensures that x is in the "middle 30%" of the array.

Step-by-Step Bound Proof:

Step A — Count the medians: There are m = ⌈n/5⌉ groups, each producing one median. So there are ⌈n/5⌉ medians in array B.

Step B — Median of medians property: x = sel(B[1..m], ⌈m/2⌉) is the median of B. By definition of median, at least ⌈m/2⌉ medians in B are ≤ x. Since m = ⌈n/5⌉, we have ⌈m/2⌉ = ⌈⌈n/5⌉/2⌉ = ⌈n/10⌉. So at least ⌈n/10⌉ medians are ≤ x.

Step C — Each median contributes 3 elements: For each median that is ≤ x, that median is the 3rd smallest in its group of 5. In its group, there are exactly 2 elements smaller than or equal to it (the 1st and 2nd smallest in the group). So each such group contributes at least 3 elements ≤ x: the 2 elements smaller than the median, plus the median itself.

Step D — Total count: Total elements ≤ x ≥ 3 × ⌈n/10⌉ ≥ 3n/10. This is because ⌈n/10⌉ ≥ n/10, so 3 × n/10 = 3n/10.

Step E — Symmetry argument: By the same logic applied to the "greater than" side, at least 3n/10 elements are ≥ x. (The median of medians is also the "median of medians from the top" — if we flip the comparison, the same bound holds.)

Step F — Final conclusion: Since at least 3n/10 elements are ≤ x and at least 3n/10 are ≥ x, the rank of x is between 3n/10 and n - 3n/10 + 1 = 7n/10 + 1. Therefore, the larger recursive side has at most n - 3n/10 = 7n/10 elements.

Precise Bound (with group edge cases)

For a tighter analysis considering edge cases (the last group may have fewer than 5 elements, and one group contains x itself):

Refined Counting:

• There are ⌈n/5⌉ medians found in Step 1.

• Excluding the last group (which may have a deficit — fewer than 5 elements) and the group containing x (which is handled separately since x is the pivot) → at least ⌈n/10⌉ − 2 groups contribute fully.

• In each such group, 3 elements are ≤ x (the median + 2 smaller elements in the group).

• So at least 3(⌈n/10⌉ − 2) ≥ 3n/10 − 6 elements are guaranteed to be ≤ x.

• Hence at most n − (3n/10 − 6) = 7n/10 + 6 elements are on the larger side.

• This yields the recurrence: T(n) = T(⌈n/5⌉) + T(7n/10 + 6) + Θ(n)

Key Point — The 3n/10 Bound is the Magic: The bound 3n/10 comes from this chain of reasoning: ⌈n/10⌉ medians ≤ x → each contributes 3 elements (median + 2 smaller) → 3⌈n/10⌉ ≥ 3n/10. This is the MINIMUM guarantee. In practice, the bound is often better, but the worst-case guarantee of 3n/10 is what makes the algorithm work. Without this guarantee, the algorithm could degrade to O(n²).
Visual Intuition:

Imagine the array divided into columns of 5:

Group 1: [a1, a2, a3, a4, a5] — median is a3 (rank 3 in group)

Group 2: [b1, b2, b3, b4, b5] — median is b3

Group 3: [c1, c2, c3, c4, c5] — median is c3

... and so on.

When x = median of medians, at least half the group medians (a3, b3, c3, ...) are ≤ x. For each such group, at least 3 elements (the median + the 2 smaller ones) are ≤ x. So if we have ⌈n/10⌉ such groups, we get at least 3⌈n/10⌉ ≥ 3n/10 elements ≤ x.

This is like having a grid where x is the "king" and we can guarantee at least 30% of the grid is "below" x.

Worked Examples — Detailed Step-by-Step Traces

These examples trace through the Select algorithm step by step, showing exactly how the median of medians pivot selection works, how partitioning proceeds, and how the recursion narrows down to the answer. Understanding these traces is essential for exam preparation.

Example 1: Find 3rd smallest in A = [19, 5, 1, 11, 15, 26, 59, 61, 48, 37]

n = 10, k = 3. We want the 3rd smallest element.

Step 1 — Divide into groups of 5: Group 1: [19, 5, 1, 11, 15]. Group 2: [26, 59, 61, 48, 37]. We have ⌈10/5⌉ = 2 groups.

Step 2 — Find median of each group: Sort Group 1: [1, 5, 11, 15, 19] → median = 11 (3rd element). Sort Group 2: [26, 37, 48, 59, 61] → median = 48 (3rd element). So B = [11, 48].

Step 3 — Find median of medians: sel(B[1..2], ⌈2/2⌉) = sel([11, 48], 1) → the 1st smallest of [11, 48] is 11. So x = 11 is our pivot.

Step 4 — Partition around 11: We rearrange A so all elements ≤ 11 come first, then 11, then elements > 11. After partition: [5, 1, 11, 19, 15, 26, 59, 61, 48, 37]. The pivot 11 is at position j = 3 (1-indexed).

Step 5 — Check rank: i = j - L + 1 = 3 - 1 + 1 = 3. Since k = 3 = i, the pivot 11 IS the 3rd smallest element. We return 11.

Why this worked: The median of medians (11) happened to be exactly the element we were looking for. In general, we might need to recurse, but the good pivot guaranteed that even if we needed to recurse, we'd only recurse on at most 7n/10 = 7 elements.

Example 2: Find 5th smallest in A = [3, 1, 4, 1, 5, 9, 2, 6]

n = 8, k = 5. We want the 5th smallest element.

Step 1 — Divide into groups of 5: Group 1: [3, 1, 4, 1, 5]. Group 2: [9, 2, 6] (only 3 elements). We have ⌈8/5⌉ = 2 groups.

Step 2 — Find median of each group: Sort Group 1: [1, 1, 3, 4, 5] → median = 3. Sort Group 2: [2, 6, 9] → median = 6 (middle of 3). So B = [3, 6].

Step 3 — Find median of medians: sel(B[1..2], ⌈2/2⌉) = sel([3, 6], 1) → the 1st smallest of [3, 6] is 3. So x = 3 is our pivot.

Step 4 — Partition around 3: After partition: [1, 1, 2, 3, 4, 5, 9, 6]. The pivot 3 is at position j = 4 (1-indexed).

Step 5 — Check rank: i = j - L + 1 = 4 - 1 + 1 = 4. Since k = 5 > i = 4, we need the 5th smallest but the pivot is only the 4th smallest. So we recurse on the RIGHT side: sel(A[5..8], k - i) = sel([4, 5, 9, 6], 5 - 4) = sel([4, 5, 9, 6], 1).

Recursive call — sel([4, 5, 9, 6], 1): Find the 1st smallest (minimum) in [4, 5, 9, 6]. n = 4 ≤ 25, so use brute force. Minimum = 4. Return 4.

Why we recursed right: After partitioning around 3, we knew that 3 was the 4th smallest. Since we wanted the 5th smallest, it must be somewhere to the right of 3. The offset k - i = 5 - 4 = 1 accounts for the 4 elements we've already "used up" (the 4 elements ≤ 3).

Example 3: Find minimum (k=1) — Special Case

For k = 1, we want the smallest element. While the general Select algorithm works, there's a simpler optimal approach.

Simple approach: Scan through the array once, keeping track of the minimum seen so far. This requires exactly n - 1 comparisons.

Why n - 1 is optimal: Every element except one must be compared at least once. If any element is never compared, we cannot determine whether it's the minimum or not. So n - 1 is a lower bound, and the simple scan achieves it.

Select algorithm for k=1: The Select algorithm also works, but is overkill. It would still find the minimum in Θ(n) time, but with higher constant factors due to the median of medians overhead. For k = 1 or k = n, simple scanning is preferred in practice.

Key insight: The selection problem is trivially solvable in Θ(n) for k = 1 and k = n (just scan). The challenge is for general k, especially k = ⌈n/2⌉ (the median), where the Select algorithm shines.

Example 4: Find median of [7, 10, 4, 3, 20, 15]

n = 6, k = 3 (lower median) or k = 4 (upper median). For even n, there are two medians.

Sorted array: [3, 4, 7, 10, 15, 20]. The two middle elements are 7 and 10.

Lower median (k=3): The 3rd smallest = 7. This is the element at position ⌊n/2⌋ = 3 in the sorted array.

Upper median (k=4): The 4th smallest = 10. This is the element at position ⌈n/2⌉ = 4 in the sorted array.

Average median: Sometimes "median" for even n is defined as the average of the two middle elements: (7 + 10)/2 = 8.5. But for selection algorithms, we typically return one of the two middle elements, not their average.

Select algorithm trace for k=3: Groups of 5: [7, 10, 4, 3, 20] → median = 7, [15] → median = 15. B = [7, 15]. Median of medians: sel([7, 15], 1) = 7. Partition around 7: [4, 3, 7, 10, 20, 15]. j = 3, i = 3 = k → return 7.

Example 5: Detailed Partition Trace — pivot = 26

A = [26, 5, 37, 1, 61, 11, 59, 15, 48, 19], n = 10. Pivot = A[1] = 26.

Partition procedure (Lomuto scheme): Initialize j = 1 (the pivot position). Scan i from 2 to 10:

• i = 2: A[2] = 5 < 26 → j++ → j = 2 → swap(A[2], A[2]) → no change. Array: [26, 5, 37, 1, 61, 11, 59, 15, 48, 19]

• i = 3: A[3] = 37 > 26 → skip. Array unchanged.

• i = 4: A[4] = 1 < 26 → j++ → j = 3 → swap(A[4], A[3]) → swap(1, 37). Array: [26, 5, 1, 37, 61, 11, 59, 15, 48, 19]

• i = 5: A[5] = 61 > 26 → skip.

• i = 6: A[6] = 11 < 26 → j++ → j = 4 → swap(A[6], A[4]) → swap(11, 37). Array: [26, 5, 1, 11, 61, 37, 59, 15, 48, 19]

• i = 7: A[7] = 59 > 26 → skip.

• i = 8: A[8] = 15 < 26 → j++ → j = 5 → swap(A[8], A[5]) → swap(15, 61). Array: [26, 5, 1, 11, 15, 37, 59, 61, 48, 19]

• i = 9: A[9] = 48 > 26 → skip.

• i = 10: A[10] = 19 < 26 → j++ → j = 6 → swap(A[10], A[6]) → swap(19, 37). Array: [26, 5, 1, 11, 15, 19, 59, 61, 48, 37]

Final swap: swap(A[1], A[j]) = swap(A[1], A[6]) → swap(26, 19). Array: [19, 5, 1, 11, 15, 26, 59, 61, 48, 37]

Result: Pivot 26 is at position j = 6. All elements in positions 1-5 are ≤ 26, all in positions 7-10 are > 26. Pivot rank = 6. If k = 6 → return 26. If k < 6 → recurse left. If k > 6 → recurse right with k - 6.

Example 6: Groups of 3 — What If We Use Groups of 3 Instead of 5?

Given n = 12, find the 8th smallest in A = [35, 12, 8, 27, 3, 42, 19, 5, 30, 15, 22, 10] using groups of 3.

Step 1 — Groups of 3: [35,12,8] → sort: [8,12,35] → median = 12. [27,3,42] → sort: [3,27,42] → median = 27. [19,5,30] → sort: [5,19,30] → median = 19. [15,22,10] → sort: [10,15,22] → median = 15.

Step 2 — Medians: B = [12, 27, 19, 15]. Find median of B: sort [12, 15, 19, 27] → median = 15 (2nd element). So x = 15.

Step 3 — Partition around 15: [12, 8, 3, 5, 10, 15, 35, 27, 42, 19, 30, 22]. j = 6 (15 at position 6). k = 8 > 6 → recurse right on [35,27,42,19,30,22] with k = 8-6 = 2.

Recursive call on right side: [35,27,42] → median = 35. [19,30,22] → sort: [19,22,30] → median = 22. B = [35, 22]. Median of medians = 22. Partition around 22: [19, 22, 42, 35, 30]. j = 2, k = 2 = j → return 22.

Note: This example used groups of 3, which gives Θ(n lg n) worst-case (not Θ(n)). The group-of-3 version may give unbalanced partitions, but in this case it happened to work well. In the worst case, groups of 3 can degrade significantly.

Time Complexity Analysis — Complete Derivation

The time complexity of the Select algorithm is one of the most elegant results in algorithm design. The algorithm achieves Θ(n) — linear time — for the selection problem, which is optimal for comparison-based algorithms. Understanding WHY this is linear requires careful analysis of the recurrence relation and its solution.

Recurrence Relation:
T(n) = T(n/5) + T(7n/10) + Θ(n)
T(n/5) = cost of finding median of medians (recursive call on n/5 elements). T(7n/10) = cost of recursing on the larger partition side (at most 7n/10 elements). Θ(n) = cost of partitioning + finding group medians + other linear work.
Where Each Term Comes From:

T(n/5): In Step 2, we recursively find the median of ⌈n/5⌉ medians. This is a recursive call on a problem of size n/5.

T(7n/10): In Step 4, after partitioning, we recurse on the larger side. The median of medians guarantees at least 3n/10 elements are on each side, so the larger side has at most 7n/10 elements. In the worst case, we recurse on this larger side.

Θ(n): The partitioning step takes Θ(n) time (one pass through the array). Finding the medians of ⌈n/5⌉ groups also takes Θ(n) total (each group median takes Θ(1), and there are n/5 groups). Other overhead (computing indices, etc.) is also Θ(n).

Solution:
T(n) = Θ(n)
Since 1/5 + 7/10 = 9/10 < 1, the recurrence solves to linear time. The sum of the fractions is less than 1, meaning the total work at each level of recursion decreases geometrically.
Why 1/5 + 7/10 = 9/10 < 1 Implies Θ(n):

This is a standard result from the theory of divide-and-conquer recurrences. For a recurrence of the form T(n) = T(αn) + T(βn) + Θ(n) where α + β < 1, the solution is Θ(n). Here's the intuition:

• At the top level, we do Θ(n) work.

• At the next level, the total work is Θ(αn) + Θ(βn) = Θ((α+β)n) = Θ(0.9n).

• At the level after that, the total work is Θ((α+β)²n) = Θ(0.81n).

• This forms a geometric series: n + 0.9n + 0.81n + ... = n × (1 + 0.9 + 0.81 + ...) = n × 1/(1-0.9) = 10n = Θ(n).

• Since α + β = 9/10 < 1, the series converges, giving Θ(n) total.

This is exactly Case 3 of the Akra-Bazzi method (or can be proved by induction). The key insight: if the sum of fractions is less than 1, the geometric series converges to a constant, giving linear time.

Best Case

Time: Θ(n)

When the pivot happens to be the exact k-th smallest element, we find it immediately without recursing. The median of medians might find the answer in one pass. Even in the best case, we still do Θ(n) work for the partitioning and group median computations.

Average Case

Time: Θ(n)

Same as worst case! This is a remarkable property of the Select algorithm. Unlike quicksort where the average case is much better than worst case, Select achieves Θ(n) in ALL cases. The median of medians pivot selection eliminates the randomness dependency.

Worst Case

Time: Θ(n)

Guaranteed linear. Even in the absolute worst case (adversary picks the worst possible input), the algorithm still runs in Θ(n). This is because the median of medians always guarantees a good pivot, preventing the O(n²) degradation that naive quickselect suffers from.

Space

Space: O(lg n)

Recursion stack depth. The recursion depth is O(lg n) because at each level, the problem size decreases by a constant factor (at least 10%). The recursion tree has depth O(lg n), and each level uses O(1) stack space. The algorithm is in-place — no extra arrays are needed beyond the input.

Why Not Just Use Naive Quickselect?

Naive quickselect (without median of medians) picks a random pivot and partitions. On AVERAGE, it runs in Θ(n) time. But in the WORST case, if the adversary always picks the worst pivot (e.g., always the smallest or largest element), quickselect degrades to O(n²). This is because each partition only removes ONE element, requiring n recursive calls of decreasing size: n + (n-1) + (n-2) + ... + 1 = O(n²).

The Select algorithm fixes this by using median of medians to GUARANTEE a good pivot. The cost is higher constant factors (about 2-3x slower in practice), but the worst-case guarantee is worth it for applications that need guaranteed performance.

Practical Considerations:

Constant factors: The Select algorithm has higher constant factors than naive quickselect. In practice, naive quickselect (or randomized quickselect) is often faster because the average case is the same Θ(n) but with smaller constants. The Select algorithm is preferred when worst-case guarantees are critical.

Cache performance: The partitioning step is cache-friendly (sequential access), but the median of medians step introduces some random access patterns. For very large arrays, cache effects can matter.

Implementation complexity: The Select algorithm is more complex to implement correctly than naive quickselect. The base case threshold (25) needs tuning, and the partition procedure must handle edge cases.

Key Point: The Select algorithm is optimal for worst-case selection. No comparison-based algorithm can do better than Θ(n) in the worst case (this follows from the Ω(n) lower bound for comparison-based selection). The Select algorithm matches this lower bound, making it asymptotically optimal.
Lower Bound Argument:
Ω(n) is a lower bound for selection
Any comparison-based algorithm must examine at least n elements to find the k-th smallest. If any element is never examined, we cannot determine whether it's smaller or larger than the k-th smallest. Therefore, Ω(n) comparisons are necessary. The Select algorithm achieves Θ(n), matching this lower bound exactly.

Analysis with Groups of 3 (Instead of 5) — Deep Dive

An important exam question: what if we divide into groups of 3 instead of groups of 5? This changes the recurrence from Θ(n) to Θ(n lg n). Understanding WHY groups of 3 fail while groups of 5 succeed is crucial for mastering the selection algorithm. The difference comes down to a single mathematical fact: whether the sum of the fractions is less than 1 or equal to 1.

Recurrence with Groups of 3:
T(n) = T(n/3) + T(2n/3) + Θ(n)
T(n/3) = find median of ⌈n/3⌉ medians (recursive call on n/3 elements). T(2n/3) = worst-case size of larger partition side (at most 2n/3 elements). Θ(n) = partitioning + group median computations.
Solution:
T(n) = Θ(n lg n)
Since n/3 + 2n/3 = 1, the recurrence falls into Case 2 of the Master Theorem: Θ(n lg n). This is NO BETTER than simply sorting the array and picking the k-th element!
Why Groups of 3 Give 2n/3 (Not 7n/10):

With groups of 3, each group has 3 elements and we find the 2nd smallest (median). When we compute the median of medians x:

• There are ⌈n/3⌉ groups, each producing one median.

• x = median of these ⌈n/3⌉ medians → at least ⌈n/6⌉ medians are ≤ x.

• Each median of 3 has exactly 1 element smaller than it in its group (the smallest element).

• So each group contributes at least 2 elements ≤ x (the smallest + the median).

• Total elements ≤ x ≥ 2 × ⌈n/6⌉ ≥ n/3.

• Therefore, at most n − n/3 = 2n/3 elements are on the larger side.

This gives the worst-case recurrence T(n) = T(n/3) + T(2n/3) + Θ(n), where the larger side is 2n/3 instead of 7n/10.

Why Groups of 5 but Not 3?

Groups of 5 — Works!

Recurrence: T(n/5) + T(7n/10) + Θ(n)

Fraction sum: 1/5 + 7/10 = 2/10 + 7/10 = 9/10

Since 9/10 < 1 → Θ(n)

The geometric series converges: n × (1 + 0.9 + 0.81 + ...) = 10n = Θ(n).

Linear time guaranteed because the total work decreases by 10% at each recursion level.

Groups of 3 — Fails!

Recurrence: T(n/3) + T(2n/3) + Θ(n)

Fraction sum: 1/3 + 2/3 = 1

Since 1 = 1 → Θ(n lg n)

The geometric series diverges: n × (1 + 1 + 1 + ...) = n × lg n = Θ(n lg n).

No better than sorting! Each recursion level does the SAME total work, not less.

Groups of 7 — Also Works!

Recurrence: T(n/7) + T(5n/7) + Θ(n)

Fraction sum: 1/7 + 5/7 = 6/7

Since 6/7 < 1 → Θ(n)

Works like groups of 5, but with larger constants (more work per group).

Groups of 5 are preferred because they give the smallest constant factors.

Derivation of the 2n/3 Upper Bound — Full Proof

Bound analysis for groups of 3 — Step by step:

Step 1 — Divide: Divide A into ⌈n/3⌉ groups, each containing at most 3 elements. Find the median (2nd smallest) of each group. Time: Θ(n) — each group median takes Θ(1) and there are n/3 groups.

Step 2 — Recurse for pivot: Recursively find the median x of the ⌈n/3⌉ medians. Time: T(⌈n/3⌉). This is the "cost of choosing a good pivot."

Step 3 — Partition: Partition A around x. Time: Θ(n) — one pass through the array.

Step 4 — Bound analysis: We need to show at least n/3 elements are ≤ x.

— Half of the ⌈n/3⌉ medians are ≤ x (by definition of median) → at least ⌈n/6⌉ medians.

— Each median of 3 has exactly 1 element smaller than it in its group (the smallest element in the group).

— So each such group contributes at least 2 elements ≤ x: the smallest element and the median itself.

— Total elements ≤ x ≥ 2 × ⌈n/6⌉ ≥ 2 × (n/6) = n/3.

— Hence at most n − n/3 = 2n/3 elements are on the larger side.

— Worst-case recurrence: T(n) = T(n/3) + T(2n/3) + Θ(n)

Why 3 Groups are Insufficient for Linearity — The Critical Difference

Master Theorem Analysis: For T(n) = T(αn) + T(βn) + Θ(n) with α + β = c:

• If c < 1: The solution is Θ(n). The work decreases geometrically at each level.
• If c = 1: The solution is Θ(n lg n). The work is the same at each level, giving lg n levels of height n.
• If c > 1: The solution is Θ(n^c) or worse. The work increases at each level.

Groups of 5 give α = 1/5, β = 7/10, sum = 9/10 < 1 → Θ(n).
Groups of 3 give α = 1/3, β = 2/3, sum = 1 → Θ(n lg n).
Groups of 7 give α = 1/7, β = 5/7, sum = 6/7 < 1 → Θ(n).
Geometric Series Intuition:

Consider the total work at each level of the recursion tree:

Groups of 5 (sum = 9/10 < 1):

Level 0: n work

Level 1: 0.9n work

Level 2: 0.81n work

Level 3: 0.729n work

... This is a geometric series with ratio 0.9 < 1. Total = n × 1/(1-0.9) = 10n = Θ(n).

Groups of 3 (sum = 1):

Level 0: n work

Level 1: n work (1/3 + 2/3 = 1)

Level 2: n work

Level 3: n work

... This series does NOT converge. Each level does n work, and there are Θ(lg n) levels. Total = n × lg n = Θ(n lg n).

The critical threshold is whether α + β < 1 (geometric convergence → linear) or α + β = 1 (no convergence → n lg n).

Worked Example with Groups of 3

Full trace: n = 9, find 5th smallest in A = [29, 14, 3, 42, 7, 21, 35, 18, 11]

Level 1:

Groups of 3: [29,14,3] → sort [3,14,29] → median = 14. [42,7,21] → sort [7,21,42] → median = 21. [35,18,11] → sort [11,18,35] → median = 18.

B = [14, 21, 18], m = 3. Find median of B: sort [14, 18, 21] → median = 18. x = 18.

Partition around 18: [14, 3, 7, 11, 18, 29, 42, 21, 35] → j = 5 (18 at position 5). k = 5 = j → return 18.

Lucky case: balanced partition found answer immediately.

Worst-case scenario (k=9): If k=9 (maximum), after partition the right side has 4 elements [29,42,21,35]. Groups of 3: [29,42,21] → sort [21,29,42] → median = 29. [35] → median = 35. Medians [29,35], x = 29. Partition right around 29: [21, 29, 42, 35] → j = 2. k − 5 = 4 > 2 → recurse right on [42,35] with k = 4−2 = 2.

This gives T(9) = T(3) + T(6) + Θ(9), illustrating the Θ(n lg n) behavior — the larger side is 6 = 2/3 × 9, not 7/10 × 9 = 6.3.

The General Formula for Group Size g (odd):

For groups of size g (where g is odd):

• We find the median (the (g+1)/2-th smallest) of each group.

• At least ⌈n/(2g)⌉ medians are ≤ x (the median of medians).

• Each such group contributes at least (g+1)/2 elements ≤ x.

• Total elements ≤ x ≥ ((g+1)/2) × ⌈n/(2g)⌉ ≥ (g+1)/(4g) × n.

• So the larger side has at most n - (g+1)/(4g) × n = (3g-1)/(4g) × n elements.

• For g = 3: (3×3-1)/(4×3) = 8/12 = 2/3. For g = 5: (3×5-1)/(4×5) = 14/20 = 7/10.

• The recurrence becomes T(n) = T(n/g) + T((3g-1)/(4g) × n) + Θ(n).

• This is Θ(n) when 1/g + (3g-1)/(4g) < 1, i.e., when (3g+3)/(4g) < 1, i.e., when g > 3.

So any odd group size g ≥ 5 gives Θ(n), but g = 3 gives Θ(n lg n).

Exam Tip: Groups of 3 is the classic counterexample showing why groups of 5 are the smallest odd group size that yields linear time. Always verify: if α + β = 1 → Θ(n lg n). If α + β < 1 → Θ(n). The critical threshold is exactly at group size 3. This is a very common exam question — be prepared to derive the recurrence and explain why groups of 3 fail.
Key Takeaways for the Exam:

1. The Select algorithm uses groups of 5 (not 3) to achieve Θ(n) time.

2. Groups of 3 give Θ(n lg n) because the fraction sum equals 1 (not less than 1).

3. The 3n/10 bound is what makes groups of 5 work — it guarantees the larger side is at most 7n/10.

4. The Master Theorem or geometric series argument proves that α + β < 1 implies Θ(n).

5. Any odd group size ≥ 5 works, but 5 gives the smallest constant factors.

6. The lower bound for comparison-based selection is Ω(n), and the Select algorithm matches it.
