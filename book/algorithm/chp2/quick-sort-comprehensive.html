Algorithm Design — Complete Guide for 20/20 Exam

Quick Sort Algorithm

A divide-and-conquer algorithm that uses partitioning to sort elements. Picks a pivot, partitions around it, then recursively sorts the two partitions.

quicksort(A[L..U])
{
  if (L < U)
  {
    // Step 1: Partition around pivot
    j = partition(A[L..U]);
    // Step 2: Sort left partition
    quicksort(A[L..j-1]);
    // Step 3: Sort right partition
    quicksort(A[j+1..U]);
  }
}
Recurrence Relation:
T(n) = T(k) + T(n-k-1) + Θ(n)
k = number of elements in left partition, Θ(n) = partition time

The Partition Operation

Partitions the array around a pivot element. After partitioning, all elements ≤ pivot are on the left, and all elements > pivot are on the right.

partition(A[L..U])
{
  pivot = A[L];
  i = L;
  for (j = L+1 to U)
  {
    if (A[j] ≤ pivot)
    {
      i++;
      swap(A[i], A[j]);
    }
  }
  swap(A[L], A[i]);
  return i;
}

Partition Example

Partition A = [3, 8, 2, 5, 1, 4, 7, 6] with pivot = 3

Initial: [3, 8, 2, 5, 1, 4, 7, 6], pivot = 3, i = 0

j=1: 8 > 3, skip

j=2: 2 ≤ 3, i=1, swap A[1] and A[2] → [3, 2, 8, 5, 1, 4, 7, 6]

j=3: 5 > 3, skip

j=4: 1 ≤ 3, i=2, swap A[2] and A[4] → [3, 2, 1, 5, 8, 4, 7, 6]

j=5: 4 > 3, skip

j=6: 7 > 3, skip

j=7: 6 > 3, skip

Final swap: swap A[0] and A[2] → [1, 2, 3, 5, 8, 4, 7, 6]

Return j = 2 (pivot position)

Worked Examples

Example 1: Sort A = [10, 80, 30, 90, 40, 50, 70]

Step 1: Partition around 10 → [10, 80, 30, 90, 40, 50, 70]

Step 2: Partition left of 10 (empty)

Step 3: Partition right of 10 → [80, 30, 90, 40, 50, 70]

Continue until fully sorted: [10, 30, 40, 50, 70, 80, 90]

Example 2: Worst Case - Already Sorted Array

A = [1, 2, 3, 4, 5], pivot = first element

Partition 1: pivot=1, left=[], right=[2,3,4,5] → j=0

Partition 2: pivot=2, left=[], right=[3,4,5] → j=1

Partition 3: pivot=3, left=[], right=[4,5] → j=2

Partition 4: pivot=4, left=[], right=[5] → j=3

Total comparisons: 4+3+2+1 = 10 = n(n-1)/2

This is Θ(n²) - worst case!

Example 3: Best Case - Balanced Partition

A = [4, 2, 6, 1, 3, 5], pivot divides evenly

Each partition roughly halves the problem

Depth of recursion: lg n

Work at each level: n

Total: Θ(n lg n)

Example 4: Randomized Quick Sort

Instead of always picking first element, pick a random pivot.

For any input, the probability of worst case is very low.

Expected time: Θ(n lg n)

Example 5: Using Median as Pivot

If we always pick the median as pivot, partitions are perfectly balanced.

T(n) = 2T(n/2) + Θ(n) = Θ(n lg n)

This eliminates worst case but adds O(n) time to find median.

Time Complexity Analysis

Worst Case (k=0):
T(n) = T(n-1) + Θ(n) = Θ(n²)
When partition is maximally unbalanced (already sorted)
Best Case (k=n/2):
T(n) = 2T(n/2) + Θ(n) = Θ(n lg n)
When partition is perfectly balanced
Average Case:
T(n) = Θ(n lg n)
Average over all possible pivots

Average Case Derivation

Sum all possible cases and divide by n:

Sum of all cases:
n·T(n) = Σ(T(k) + T(n-k-1) + n) for k=0 to n-1
Simplified:
n·T(n) = 2·Σ(T(k)) + n²
After substitution T(n)/(n+1):
T(n)/(n+1) = T(n-1)/n + 2n/(n+1)
Solution:
T(n) = 2(n+1)·H_n - 4n ≈ 2n·ln(n)
Where H_n is the harmonic series ≈ ln(n)

Quick Sort Variants

1. Randomized Quick Sort

Choose pivot randomly from the subarray. Expected time is always Θ(n lg n) regardless of input.

2. Median-of-Three

Choose pivot as median of first, middle, and last elements. Avoids worst case for sorted inputs.

3. Three-Way Partition

Handles duplicate elements efficiently. Partitions into three parts: less than, equal to, and greater than pivot.

Key Points to Remember:

• Quick Sort is in-place (O(lg n) stack space)

• Quick Sort is NOT stable

• In practice, Quick Sort is often faster than Merge Sort

• For nearly sorted data, Quick Sort performs poorly

• Maximum comparisons: n(n-1)/2 (worst case)

• Maximum swaps: n(n-1)/2 (worst case)
