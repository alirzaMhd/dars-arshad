Expression Trees

Data Structures — Complete Guide for 20/20 Exam

What is an Expression Tree?

An expression tree is a binary tree that represents a mathematical expression. Operators are stored in internal nodes, and operands are stored in leaf nodes.

Structure Rule:
Internal nodes = operators, Leaf nodes = operands/constants
Unary operators have one child; binary operators have two children.
Example: Expression Tree for a + b
+ / \ a b

The operator '+' is the root, with operands 'a' and 'b' as children.

Example: Expression Tree for (a + b) * (c - d)
* / \ + - / \ / \ a b c d

The '*' operator is the root because it has the lowest precedence (evaluated last).

Types of Expression Trees

Binary Operators

+ - * / ^

Two children (left and right operands)

Unary Operators

- (negation), not

One child (operand)

Operands

a, b, c, 1, 2, 3...

Leaf nodes (no children)

Building Expression Trees

Algorithm:
1. Find operator with LOWEST precedence (evaluated last)
2. Make it the root
3. Recursively build left subtree from left operands
4. Recursively build right subtree from right operands
Parentheses have highest precedence. Operators inside parentheses are evaluated first.
Example: Build Tree for + - a b (* c (/ d e))

Expression: (a - b) + (c * (d / e))

Step 1: Lowest precedence operator is '+' (outermost)

Step 2: Left subtree: (a - b), Right subtree: (c * (d / e))

Step 3: Build left subtree: '-' is root, a and b are children

Step 4: Build right subtree: '*' is root, c and (d/e) are children

+ / \ - * / \ / \ a b c / / \ d e
⚠ When building from postfix: push operands onto stack. When you encounter an operator, pop two operands, create a node with the operator as root, and push the node back.
Build from Postfix Expression: 1. Create empty stack 2. For each symbol in postfix: a. If operand: create node, push to stack b. If operator: - pop right operand - pop left operand - create node with operator - push node to stack 3. Stack top is the root of expression tree

Expression Tree Traversals

Key Relationship:
Preorder traversal = Prefix notation
Inorder traversal = Infix notation
Postorder traversal = Postfix notation
Example: + - a b * c d
+ / \ - * / \ / \ a b c d

Preorder (DLR): + - a b * c d → Prefix: + - a b * c d

Inorder (LDR): a - b + c * d → Infix: a - b + c * d

Postorder (LRD): a b - c d * + → Postfix: a b - c d * +

⚠ Inorder traversal may need parentheses for correct interpretation. The expression tree structure ensures correct evaluation order regardless of notation.

Prefix to Expression Tree

Example: Build tree from prefix: * + a b - c d

Solution:

1. Read '*' → operator, needs two operands

2. Read '+' → operator (left child of '*')

3. Read 'a' → operand (left child of '+')

4. Read 'b' → operand (right child of '+')

5. Read '-' → operator (right child of '*')

6. Read 'c' → operand (left child of '-')

7. Read 'd' → operand (right child of '-')

* / \ + - / \ / \ a b c d

Operator Precedence

When building expression trees, operator precedence determines the tree structure. Lower precedence operators appear higher in the tree (closer to the root).

PrecedenceOperatorsDescription
1 (Highest)()Parentheses
2^ (power)Exponentiation
3* /Multiplication, Division
4 (Lowest)+ -Addition, Subtraction
Building Rule:
Operator with LOWEST precedence becomes the ROOT
This ensures the expression is evaluated in the correct order.
Example: + - a b (* c (/ d e))

Expression: (a - b) + (c * (d / e))

Analysis:

• '+' has lowest precedence → root of tree

• '-' and '*' have next lowest → children of '+'

• '/' has highest precedence → deepest in tree

+ ← Lowest precedence (root) / \ - * ← Medium precedence / \ / \ a b c / ← Highest precedence / \ d e
Example: Complex Expression

Expression: a * b + c / d - e

Analysis:

• '-' has lowest precedence → root

• Left subtree: a * b + c / d ( '+' is root)

• Right subtree: e

- / \ + e / \ * / / \ / \ a b c d

Prefix: - + * a b / c d e

Postfix: a b * c d / + e -

Worked Examples

Example 1: Build Tree from Infix

Build an expression tree for: (a + b) * (c - d) / e

Solution:

Lowest precedence: '/' → root

Left: (a+b)*(c-d), Right: e

Left subtree root: '*' (next lowest)

/ / \ * e / \ + - / \ / \ a b c d

Prefix: / * + a b - c d e

Postfix: a b + c d - * e /

Example 2: Build from Postfix

Postfix: a b + c d - *

Solution:

1. Push a, Push b

2. Read '+': pop b, pop a, create '+' node, push

3. Push c, Push d

4. Read '-': pop d, pop c, create '-' node, push

5. Read '*': pop '-' node, pop '+' node, create '*' node, push

* / \ + - / \ / \ a b c d
Example 3: Evaluate Expression Tree

Evaluate the tree for: + - 3 1 * 2 4

+ / \ - * / \ / \ 3 1 2 4

Solution:

• Left subtree: 3 - 1 = 2

• Right subtree: 2 * 4 = 8

• Root: 2 + 8 = 10

Example 4: Expression with Unary Operator

Expression: a * (-b + c)

* / \ a + / \ - c | b

The '-' node has only one child (b), making it a unary operator.

Example 5: Prefix to Expression

Prefix: - + a * b c d

Solution:

1. '-' is root (binary)

2. Left: '+ a * b c' (another expression)

3. Right: 'd' (operand)

- / \ + d / \ a * / \ b c

Infix: (a + b * c) - d

Postfix: a b c * + d -

Example 6: Unary Operator Node Count Property

An expression tree has 30 nodes. Which statement is correct about the expression?

Solution:

• Total nodes = 30 (operators + operands)

• Internal nodes = operators, Leaf nodes = operands

• If ALL operators are binary: n₀ = n₂ + 1 (full binary tree property)

• If there are unary operators: the tree is NOT a full binary tree

Key insight: If the total node count is ODD, the expression MUST contain at least one unary operator.

Reasoning:

• Binary operators: 2 children each → contribute 2 to total children count

• Unary operators: 1 child each → contribute 1 to total children count

• For n nodes with all binary operators: n = 2k + 1 (odd)

• If n is even (like 30), there must be at least one unary operator

Option 4: The expression has at least one unary operator ✓
