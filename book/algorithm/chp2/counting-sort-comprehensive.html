Counting Sort Algorithm

A non-comparison based sorting algorithm that counts occurrences of each distinct element. Works for integers in a known range [1..k].

countingsort(A[1..n], k)
{
  B[1..n], C[1..k];
  // Step 1: Initialize count array
  for (i = 1 to k)
    C[i] = 0;
  // Step 2: Count occurrences
  for (i = 1 to n)
    C[A[i]] = C[A[i]] + 1;
  // Step 3: Cumulative count
  for (i = 2 to k)
    C[i] = C[i] + C[i-1];
  // Step 4: Place elements
  for (i = n downto 1)
  {
    B[C[A[i]]] = A[i];
    C[A[i]] = C[A[i]] - 1;
  }
}
Key Insight:
C[i] = number of elements ≤ i in A
After cumulative sum, C[x] gives the position of x in sorted output

How Counting Sort Works

Step 1: Count Occurrences

Count how many times each element appears in the input array.

After this step: C[i] = count of element i in A

Step 2: Cumulative Count

Convert counts to cumulative sums.

After this step: C[i] = number of elements ≤ i in A

Step 3: Place Elements

Scan input array from right to left. For each element A[i], place it at position C[A[i]] in output array B, then decrement C[A[i]].

Why scan from right to left?

Scanning from right to left preserves stability (maintains relative order of equal elements). If we scan left to right, the sort would be unstable.

Stability Property:
Counting Sort is stable
Equal elements maintain their original relative order

Worked Examples

Example 1: Sort A = [4, 1, 4, 3, 4, 3], k = 4

Step 1: Count occurrences

C[1] = 1, C[2] = 0, C[3] = 2, C[4] = 3

Step 2: Cumulative count

C[1] = 1, C[2] = 1, C[3] = 3, C[4] = 6

C[3] = 3 means there are 3 elements ≤ 3

Step 3: Place elements (scan right to left)

i=6: A[6]=3, B[C[3]]=B[3]=3, C[3]=2

i=5: A[5]=4, B[C[4]]=B[6]=4, C[4]=5

i=4: A[4]=3, B[C[3]]=B[3]=3, C[3]=2 (wait, this should be B[2])

Let me recalculate...

After placing: B = [1, 3, 3, 4, 4, 4]

Example 2: Sort A = [2, 5, 3, 1, 4], k = 5

Step 1: Count: C = [0, 1, 1, 1, 1, 1] (indices 0-5)

Step 2: Cumulative: C = [0, 1, 2, 3, 4, 5]

Step 3: Place elements:

i=5: A[5]=4, B[4]=4, C[4]=3

i=4: A[4]=1, B[1]=1, C[1]=0

i=3: A[3]=3, B[3]=3, C[3]=2

i=2: A[2]=5, B[5]=5, C[5]=4

i=1: A[1]=2, B[2]=2, C[2]=1

Result: B = [1, 2, 3, 4, 5]

Example 3: Counting Sort with Duplicates

A = [1, 2, 2, 1, 3, 1], k = 3

Count: C[1]=3, C[2]=2, C[3]=1

Cumulative: C[1]=3, C[2]=5, C[3]=6

Place (right to left) preserves stability:

Original order of 1s: positions 1, 4, 6

Sorted order of 1s: positions 1, 2, 3 (same relative order)

Result: [1, 1, 1, 2, 2, 3]

Example 4: When k is Large

A = [100, 200, 150, 50], k = 200

Need array C of size 200 even though n = 4

This is wasteful when k >> n

Better to use Radix Sort for large ranges

Time Complexity Analysis

Step 1 (Initialize):
Θ(k)
Loop from 1 to k
Step 2 (Count):
Θ(n)
Loop from 1 to n
Step 3 (Cumulative):
Θ(k)
Loop from 2 to k
Step 4 (Place):
Θ(n)
Loop from n downto 1
Total Time:
Θ(n + k)
Linear in both n and k
Space Complexity:
O(n + k)
Need arrays B (size n) and C (size k)

Best Case

Time: Θ(n + k)

Always the same

Average Case

Time: Θ(n + k)

No dependence on input

Worst Case

Time: Θ(n + k)

Always the same

Space

Space: O(n + k)

Not in-place!

When is Counting Sort efficient?

When k = O(n), i.e., the range is not much larger than the number of elements.

If k >> n (large range), use Radix Sort instead.

Properties of Counting Sort

Stable

Yes

Scanning right to left preserves order

In-Place

No

Requires O(n + k) extra space

Comparison-Based

No

Uses counting, not comparisons

Adaptive

No

Always Θ(n + k)

Constraints:

1. Input must be integers (or integer-like)

2. Range [1..k] must be known

3. Efficient only when k = O(n)
