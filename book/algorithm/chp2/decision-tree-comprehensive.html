Decision Tree

Algorithm Design — Complete Guide for 20/20 Exam

What is a Decision Tree?

A decision tree is a binary tree that models the execution of a comparison-based sorting algorithm. Each internal node represents a comparison between two elements, and each leaf represents a possible sorted output.

Internal Nodes

Represent comparisons: "Is A[i] ≤ A[j]?"

Left child: Yes (A[i] ≤ A[j])

Right child: No (A[i] > A[j])

Leaf Nodes

Represent possible outcomes (sorted permutations)

Each leaf is a unique sorted arrangement

Number of Leaves:
n! (for sorting n distinct elements)
Each permutation of n elements is a possible sorted output
Key Insight: The height of the decision tree represents the minimum number of comparisons needed in the worst case for any comparison-based sorting algorithm.

Decision Tree Properties

Internal Nodes

Each internal node represents a comparison between two elements

Leaves

Each leaf represents a possible outcome (a sorted permutation)

Root-to-Leaf Path

A path from root to leaf = one complete execution of the algorithm

Tree Height

The height h is the minimum number of comparisons needed in the worst case

Height for Sorting n Distinct Elements:
h ≥ ⌈lg(n!)⌉
Any comparison-based sorting algorithm requires at least ⌈lg(n!)⌉ comparisons in the worst case

Proving the Ω(n lg n) Lower Bound

Step 1: Count the Leaves

Number of leaves:
L ≥ n!
At least n! leaves (one for each permutation)

Step 2: Relate Height to Leaves

For a binary tree:
h ≥ ⌈lg L⌉
Height must be at least logarithm of number of leaves

Step 3: Combine

Minimum height:
h ≥ ⌈lg(n!)⌉
Minimum comparisons needed in worst case

Step 4: Use Stirling's Approximation

Stirling's Approximation:
lg(n!) = n lg n - n lg e + O(lg n)
Approximation for lg(n!)
Result:
h ≥ n lg n - O(n) = Ω(n lg n)
Therefore, any comparison-based sort requires Ω(n lg n) comparisons in the worst case
Conclusion: No comparison-based sorting algorithm can do better than Ω(n lg n) in the worst case. This is a fundamental lower bound!

Worked Examples

Example 6: Decision Tree for Sorting 3 Elements A[1..3]

Construct the decision tree for sorting A[1], A[2], A[3] using pairwise comparisons:

Root: Compare A[1] vs A[2] │ ├─ A[1] ≤ A[2]: │ └─ Compare A[2] vs A[3] │ ├─ A[2] ≤ A[3]: leaf → [A[1], A[2], A[3]] │ └─ A[2] > A[3]: │ └─ Compare A[1] vs A[3] │ ├─ A[1] ≤ A[3]: leaf → [A[1], A[3], A[2]] │ └─ A[1] > A[3]: leaf → [A[3], A[1], A[2]] │ └─ A[1] > A[2]: └─ Compare A[1] vs A[3] ├─ A[1] ≤ A[3]: leaf → [A[2], A[1], A[3]] └─ A[1] > A[3]: └─ Compare A[2] vs A[3] ├─ A[2] ≤ A[3]: leaf → [A[2], A[3], A[1]] └─ A[2] > A[3]: leaf → [A[3], A[2], A[1]]

Number of leaves = 6 = 3! (each leaf is a distinct permutation)

Height h = 3 = ⌈lg 6⌉ = ⌈2.58⌉ = 3

Minimum worst-case comparisons: 3

Example 1: Decision Tree for 3 Elements [a, b, c]

n = 3, so n! = 6 leaves (6 possible sorted outputs)

Root: Compare a vs b

Left (a ≤ b): Compare b vs c

  Left (b ≤ c): Compare a vs c → leaf [a, b, c]

  Right (b > c): leaf [a, c, b]

Right (a > b): Compare a vs c

  Left (a ≤ c): leaf [b, a, c]

  Right (a > c): Compare b vs c → leaf [b, c, a] or [c, b, a]

Height h = 3 = ⌈lg 6⌉ = ⌈2.58⌉ = 3

Minimum comparisons needed: 3

Example 2: Lower Bound for n=4

n! = 24 leaves

h ≥ ⌈lg 24⌉ = ⌈4.58⌉ = 5

Minimum comparisons needed: 5

Example 7: Merging Two Sorted Lists — Decision Tree Leaves

Merge sorted list L1 = [x1, x2, x3] (3 elements) and L2 = [y1, y2, y3, y4] (4 elements)

Total elements = 7, so there are 7! = 5040 possible arrangements if all elements could be freely rearranged.

However, elements within each list are already sorted and cannot be rearranged with each other:

• x1 must appear before x2 before x3 → divide by 3!

• y1 must appear before y2 before y3 before y4 → divide by 4!

Number of leaves in the merge decision tree: 7!/(3!·4!) = 5040/(6·24) = 35

Minimum comparisons needed (height): ⌈lg 35⌉ = ⌈5.13⌉ = 6

This matches the optimal merge: at most m + n − 1 = 6 comparisons.

Example 4: Compare with Actual Algorithms

n = 1000

Lower bound: ⌈lg(1000!)⌉ ≈ 8530 comparisons

Merge Sort: ≈ 10000 comparisons

Quick Sort (average): ≈ 10000 comparisons

All good algorithms are within a constant factor of the lower bound!

Applications of Decision Trees

1. Proving Lower Bounds

Decision trees provide a framework for proving that no algorithm can do better than a certain bound.

2. Analyzing Sorting Algorithms

We can visualize any comparison-based sort as a decision tree and analyze its worst case.

3. Optimizing Algorithms

By understanding the decision tree, we can design algorithms that approach the lower bound.

Sorting

Lower bound: Ω(n lg n)

Optimal: Merge Sort, Heap Sort

Finding Minimum

Lower bound: n - 1 comparisons

Optimal: Linear scan

Finding Both Min and Max

Lower bound: ⌈3n/2⌉ - 2

Optimal: Pairwise comparison

Important: The decision tree model only applies to comparison-based sorts. Non-comparison sorts (Counting, Radix, Bucket) can be faster because they don't use comparisons!

Key Results to Remember

Sorting n elements Ω(n lg n) Merge Sort, Heap Sort
Finding minimum n - 1 Linear scan
Finding maximum n - 1 Linear scan
Finding min and max ⌈3n/2⌉ - 2 Pairwise comparison

⌈3n/2⌉ - 2 comparisons
If n is even: 3n/2 - 2, if n is odd: 3(n-1)/2

n + min(n, k)·lg k - 2k (approximately)
