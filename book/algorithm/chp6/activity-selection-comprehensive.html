Activity Selection Problem

Greedy Algorithms — Complete Guide for 20/20 Exam

Problem Definition

Given a set of n activities S = {1, 2, ..., n} that all want exclusive use of a shared resource, select the maximum number of compatible activities.

Activity Representation:
Activity i = [ si , ei )    where si ≤ ei
Each activity i runs in a half-open interval starting at si and ending at ei
Compatibility Condition:
si ≥ ej   OR   sj ≥ ei
Two activities i and j are compatible if their intervals do not overlap. While one activity runs, no other can execute.
Optimization Goal:
Maximize |A|   where A ⊆ S and ∀ i,j ∈ A : si ≥ ej ∨ sj ≥ ei
Find the largest subset of mutually compatible activities

Key Properties

• Optimal substructure — optimal solution contains optimal solutions to subproblems

• Greedy-choice property — locally optimal choice leads to globally optimal solution

• Activities are non-preemptive — once started, an activity runs to completion

Real-World Applications

• Scheduling meetings in a conference room

• CPU process scheduling

• Booking a shared resource (lab equipment, venue)

• Airline gate assignment

⚠ Important Assumption: For the greedy algorithm to work correctly, activities must be sorted by finish time in ascending order (e1 ≤ e2 ≤ ... ≤ en). If not presented pre-sorted, sorting adds O(n log n) overhead.

Formal Definition

  • Input: A set S = {1, 2, ..., n} of n activities with start times si and finish times ei
  • Constraint: For any two activities i, j in the solution, si ≥ ej or sj ≥ ei
  • Output: A maximum-cardinality subset A ⊆ S of mutually compatible activities

The Greedy Algorithm

Core Idea: Earliest Finish Time First

The optimal strategy is to always select the activity with the earliest finish time among the remaining compatible activities. This leaves the maximum remaining time for scheduling other activities.

Pseudocode

Activity_Selection(S, e)
{
  // Assumes S sorted by finish time e in ascending order
  A = {1}                                 // Select first activity
  j = 1                                    // Index of last selected activity
  for i = 2 to n do
  {
    if s[i] ≥ e[j] then                   // Compatible?
    {
      A = A ∪ {i}                         // Select it
      j = i                                   // Update last selected
    }
  }
  return A
}

Complexity Analysis

Time (pre-sorted): O(n)

Time (not sorted): O(n log n)

Space: O(1)

Correctness Intuition

By choosing the activity that finishes earliest, we maximize the remaining time for other activities. This is proven via an exchange argument — any optimal solution can be transformed to include the earliest-finishing activity without reducing cardinality.

Why Earliest Finish Time Works

Exchange Argument (Proof Sketch)

  1. Let A be an optimal solution sorted by finish time, and let a1 be its first activity.
  2. Let b1 be the activity with the globally earliest finish time (selected by greedy).
  3. Since eb1 ≤ ea1, activity b1 finishes no later than a1.
  4. Therefore b1 is compatible with all activities that a1 is compatible with.
  5. Replace a1 with b1 in A — still optimal and starts with the greedy choice.
  6. By induction, the greedy algorithm produces an optimal solution.
Key Insight: The earliest-finishing activity is always part of some optimal solution. This is the greedy-choice property — making the locally optimal choice (earliest finish) leads to a globally optimal solution.

Why Other Greedy Strategies Fail

The Activity Selection problem is a classic case where the correct greedy choice is earliest finish time. Other seemingly reasonable strategies produce suboptimal results.

Strategy 1: Earliest Start Time First

Idea: Pick the activity that starts earliest, then the next compatible one with the earliest start, and so on.

Why It Fails

An activity that starts very early may also have a very long duration, blocking many other activities that could have been scheduled.

Counterexample

Activity123
si012
ei1034

Earliest Start Time picks: {1} [0,10) → only 1 activity.

Earliest Finish Time picks: {2, 3} [1,3),[2,4) → 2 activities (optimal).

Lesson: Starting early does not guarantee finishing early. Long activities consume the resource and reduce the total count.

Strategy 2: Shortest Duration First

Idea: Pick the activity with the smallest interval length (ei - si), then the next shortest compatible one.

Why It Fails

The shortest activity might be positioned in the middle of the timeline, overlapping with two activities on either side that are compatible with each other but not with the short one.

Counterexample

Activity123
si014
ei426
Duration412

Shortest Duration picks: {2} [1,2) → then activity 1 and 3 overlap with 2. Only 1 activity.

Earliest Finish Time picks: {1, 3} [0,4),[4,6) → 2 activities (optimal).

Lesson: A short activity that sits in the gap between two non-overlapping longer activities can block both, resulting in fewer total activities.

Strategy 3: Latest Start Time First

Idea: Pick the activity that starts the latest (i.e., closest to the end of the timeline), working backwards.

Why It Fails

Similar to earliest start time, a late-starting activity may have a very long duration extending even further, or it may be positioned such that it blocks many activities that could have been scheduled before it.

Counterexample

Activity123
si132
ei357

Latest Start Time picks: {2} [3,5) first (latest start = 3) → then activity 1 is compatible [1,3) → {2, 1} = 2 activities. But wait — if the ordering were different...

A better counterexample:

Activity1234
si0123
ei2546

Latest Start Time picks: {4} (start=3), then {1} (start=0, compatible with 4) → 2 activities.

Earliest Finish Time picks: {1, 3, 4} [0,2),[2,4),[3,6) → 3 activities (optimal).

Strategy Greedy Choice Optimal? Time Complexity Counterexample Pattern

Earliest Start Time Activity with smallest si ✗ No O(n) or O(n log n) Long activity starts early, blocks many
Shortest Duration Activity with min (ei - si) ✗ No O(n) or O(n log n) Short activity sits between two compatible ones

Minimum Overlap Activity with fewest conflicts ✗ No O(n²) Many specific configurations

Summary: Why Earliest Finish Time Is Optimal

Intuition

Finishing early maximizes remaining resource time for other activities. No other strategy guarantees this property.

Exchange Argument

The earliest-finishing activity can always replace the first activity in any optimal solution without reducing the total count. This is the greedy-choice property.

Optimal Substructure

After selecting the earliest-finishing activity, the remaining problem is an independent subproblem on the remaining compatible activities. The same greedy choice applies recursively.

⚠ Critical Warning: The greedy algorithm assumes activities are sorted by finish time. If you forget to sort, or sort by the wrong criterion (e.g., start time), the algorithm will produce incorrect results. Always verify: e1 ≤ e2 ≤ ... ≤ en.
