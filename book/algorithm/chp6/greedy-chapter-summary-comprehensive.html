❶ Kruskal's Algorithm

Problem: Minimum Spanning Tree (MST)

Greedy Criterion: Pick smallest weight edge

Approach: Sort edges + Union-Find

Time Complexity: O(E log V)

Space Complexity: O(V + E)

Optimality: ✅ Always minimum spanning tree

❷ Prim's Algorithm

Problem: Minimum Spanning Tree (MST)

Greedy Criterion: Extend S with cheapest edge

Approach: Priority Queue (Min-Heap)

Time Complexity: O(E log V)

Space Complexity: O(V)

Optimality: ✅ Always minimum spanning tree

MSTO(E log V)Min-Heap
❸ Dijkstra's Algorithm

Problem: Single-Source Shortest Path

Greedy Criterion: Pick vertex with smallest distance

Approach: Relaxation + Min-Heap

Time Complexity: O((V+E) log V)

Space Complexity: O(V)

Optimality: ✅ Non-negative edges only

❹ Fractional Knapsack

Problem: Maximize value with weight limit

Greedy Criterion: Value-to-weight ratio (v/w)

Approach: Sort by v/w descending

Time Complexity: O(n log n) / O(n) with median

Space Complexity: O(1)

Optimality: ✅ Always optimal (unlike 0/1)

O(n log n)Greedy⚠ Fractional, not 0/1
❺ Huffman Coding

Problem: Optimal Prefix-Free Code

Greedy Criterion: Merge two lowest-frequency nodes

Approach: Min-Heap (Priority Queue)

Time Complexity: O(n log n)

Space Complexity: O(n)

Optimality: ✅ Minimum-length prefix code

🧮 Important Formulas & Theorems

🔹 Sorting — Foundation of most greedy algorithms
T(n) = O(n log n)
Fundamental step in Kruskal, Fractional Knapsack, Activity Selection, Deadline Scheduling
🔹 Kruskal — Sorting + Union-Find
T(E,V) = O(E log E) + O(E α(V)) = O(E log V)
Sort edges, then check with Union-Find (α is inverse Ackermann)
🔹 Prim — Min-Heap with keys
T(V,E) = O((V+E) log V)
Each vertex Extract-Min once, each edge Decrease-Key once
🔹 Dijkstra — Relaxation + Min-Heap
T(V,E) = O((V+E) log V)
Similar to Prim but with weight instead of key. Optimality condition: no negative edges
🔹 Fractional Knapsack — Sort descending by v/w
T(n) = O(n log n) \quad \text{or} \quad O(n) \ (\text{with median})
Regular sorting O(n log n) — can achieve O(n) with divide & conquer and median
🔹 Huffman — Min-Heap for merging
T(n) = O(n log n)
n-1 merges, each with two Extract-Min and one Insert on Min-Heap
🔹 Activity Selection — Sort by fi
T(n) = O(n log n) + O(n) = O(n log n)
Sort by finish time (fi), then linear scan
🔹 Deadline Scheduling — Sort by profit
T(n) = O(n²) \quad \text{or} \quad O(n \log n \cdot \alpha(n))
Basic version O(n²) for feasibility checks. With Union-Find for fast placement, O(n log n α(n))

📐 Theorems & Lemmas

Theorem 1 — Kruskal Optimality (Cut Property)

If edge e is the lightest edge in a cut, it belongs to all MSTs.

Theorem 2 — Prim Optimality

If S is the set of selected vertices, the lightest edge from S to V\S is in the MST.

Theorem 3 — Dijkstra Optimality

If all edges are non-negative, Dijkstra finds the shortest path from source to all vertices.

Theorem 4 — Fractional Knapsack Optimality

By selecting items in descending value-to-weight ratio (v/w), the optimal solution is obtained.

Theorem 5 — Huffman Optimality

Huffman coding tree has the minimum average code length among all prefix-free codes.

Theorem 6 — Activity Selection Optimality (Exchange Argument)

If activity am has the earliest finish, there exists an optimal solution containing am.

Theorem 7 — Deadline Scheduling Optimality

Sorting jobs by descending profit and assigning each to the latest possible deadline guarantees maximum profit.

⚠️ Common Mistakes & Exam Tips

🚫 Mistake #1: Forgetting Initial Sorting
  • Most greedy algorithms require initial sorting
  • Without sorting, greedy selection may not work correctly
  • Example: Kruskal, Fractional Knapsack, Activity Selection, Deadline Scheduling
🚫 Mistake #2: Using Greedy for 0/1 Knapsack
  • Fractional Knapsack is optimal with greedy, but 0/1 Knapsack is not!
  • For 0/1 Knapsack, use Dynamic Programming (DP)
  • In the exam, carefully check if the problem is fractional or 0/1
🚫 Mistake #3: Dijkstra with Negative Edges
  • Dijkstra only works with non-negative edges
  • With negative edges, the algorithm fails — use Bellman-Ford instead
  • If all edges are positive, Dijkstra is very efficient
🚫 Mistake #4: Wrong Greedy Criterion for Activity Selection
  • Correct criterion: Earliest Finish Time
  • Wrong criteria: earliest start, shortest duration, least conflicts
  • Earliest Finish gives both optimal size and high speed
🚫 Mistake #5: Forgetting No-Cycle Condition in MST
  • In Kruskal, only select edges that do not create cycles
  • Union-Find is used exactly for cycle detection
  • In Prim, by selecting edges from tree to outside, cycles never occur
🚫 Mistake #6: Deadline Scheduling — Ordering
  • Sort jobs by descending profit, not by deadline
  • For each job, assign the latest empty slot before its deadline
  • Union-Find speeds up finding empty slots
💡 Golden Exam Tips
  • ★ MST algorithms (Kruskal, Prim) and Shortest Path (Dijkstra) are the most popular exam questions
  • ★ Prove the greedy criterion is correct: use Exchange Argument or Greedy Stays Ahead
  • ★ Complexity: Kruskal vs Prim — dense graphs (Prim better), sparse (Kruskal better)
  • ★ In Huffman, always merge the two smallest frequencies and push result back to heap
  • ★ Fractional Knapsack O(n) with median is an advanced point — may appear on the exam!
  • ★ In Deadline Scheduling with Union-Find, don't forget α(n) (inverse Ackermann)
  • ★ All algorithms are O(n log n) or better — sorting is usually the bottleneck

🔍 When to Use Greedy

✅ Signs Greedy is Appropriate
  • The problem has Optimal Substructure
  • Local choice leads to the Global Optimum
  • The problem is optimization, not discrete decision-making
  • Can prove greedy correctness with Exchange Argument
  • The problem is a Matroid or similar
❌ Signs Greedy is Inappropriate
  • Problem requires Dynamic Programming (DP) (e.g., 0/1 Knapsack, Longest Path)
  • Local choice may eliminate better future options
  • Problem has interconnected states (mutual influence of choices)
  • Cannot prove correctness with Exchange Argument

🧪 Greedy vs DP vs Divide & Conquer

Criterion Greedy Dynamic Programming Divide & Conquer
Decision Making One-time decision Considers all states Divide and solve separately
Optimality Depends on the problem ✅ Guaranteed Usually yes
Main Use MST, Shortest Path, Scheduling 0/1 Knapsack, LCS, Edit Distance Merge Sort, Quick Sort, Binary Search
Speed Fast (O(n log n)) Moderate (O(n²) typical) Fast (O(n log n))
Implementation Complexity ✅ Simple Moderate Moderate
Need for Proof ✗ High Less Low
Quick Decision: Greedy or DP?

Greedy If the greedy choice at each step is independent of the future and depends only on the current state.

DP If the current choice affects future choices and requires storing subproblems.

Mixed Sometimes sort greedily then solve with DP (e.g., Weighted Interval Scheduling).

✏️ Quick Practice Problems

Problem 1 — Minimum Spanning Tree

Question: We have a graph with 6 vertices and the following edges. Find the MST using Kruskal.

Edges: (1,2,4), (1,3,2), (2,3,1), (2,4,5), (3,4,8), (3,5,10), (4,5,2), (4,6,6), (5,6,3)

Hint: Sort by weight first. Add edges in order unless they create cycles.
Answer: Selected edges: (2,3,1), (1,3,2), (4,5,2), (5,6,3), (1,2,4) — Total weight: 12

Problem 3 — Activity Selection

Question: Consider the following activities. Find the maximum number of compatible activities using the greedy algorithm.

Activities (start, finish): (1,4), (3,5), (0,6), (5,7), (3,8), (5,9), (6,10), (8,11), (8,12), (2,13)

Hint: Sort by finish time (fi). Select the first activity with the smallest f.
Answer: (1,4) → (5,7) → (8,11) — 3 activities

📌 Greedy Problem-Solving Pattern for Exams
  1. Identify: Does the problem require initial sorting?
  2. Choose Criterion: What is the best local choice? (smallest weight, earliest finish, highest ratio, ...)
  3. Execute: Select step by step and update
  4. Prove: Use Exchange Argument or Greedy Stays Ahead to prove optimality
  5. Complexity: O(n log n) for sorting + O(n) or O(log n) per selection
📝 Greedy Optimality Condition

If OPT includes the greedy choice and the remaining subproblem is optimal → Greedy is optimal

Sufficient condition: Greedy Choice Property + Optimal Substructure
