Fractional Knapsack Problem

Greedy Algorithms — Complete Guide for 20/20 Exam

Problem Definition

A thief has a knapsack with maximum capacity M. There are n items, each with a weight wi and a profit pi. Unlike the 0/1 version, the thief may take fractions of any item (0 ≤ xi ≤ 1). The goal is to maximize total profit without exceeding capacity M.

Objective Function:
Maximize Σ (pi × xi)  for i = 1 to n
Total profit = sum of (profit of item i × fraction taken of item i)
Constraint:
Σ (wi × xi) ≤ M  for i = 1 to n
Total weight placed in knapsack must not exceed capacity M
Domain Constraint:
0 ≤ xi ≤ 1  for all i
Each xi represents the fraction of item i taken (0 = none, 1 = all)
▸ wi = weight of item i ▸ pi = profit of item i ▸ xi = fraction taken (0 ≤ xi ≤ 1) ▸ M = maximum capacity ▸ n = number of items

Key Properties

• Items are divisible

• Greedy choice property holds

• Optimal substructure exists

• Always optimal via ratio heuristic

Contrast: 0/1 Knapsack

• Items are indivisible

• xi ∈ {0, 1} only

• Greedy fails

• Requires DP (pseudo-polynomial)

Complexity

Time: O(n log n) sorting

Time: O(n) via median

Space: O(1) auxiliary

⚠ Why Only Ratio Heuristic is Optimal
The profit/weight ratio (pi/wi) measures "profit per unit weight." Taking items with the highest ratio first ensures every unit of capacity yields maximum value. Sorting by profit alone ignores weight cost; sorting by weight alone ignores profit yield. Only the ratio captures both dimensions simultaneously, guaranteeing optimality for the fractional case.

Three Greedy Heuristics — Comparison

Consider M = 20, w = [18, 15, 10], p = [25, 24, 15]

Heuristic Sorting Key x = [x1, x2, x3] Total Profit Optimal?
(a) Highest Profit First pi ↓ [1, 2/15, 0] 28.2 ✗
(b) Smallest Weight First wi ↑ [0, 10/15, 1] 31.0 ✗
(c) Highest pi/wi First pi/wi ↓ [0, 1, 1/2] 31.5 ✓

Heuristic (a): Highest Profit

Ratios: 25/18=1.39, 24/15=1.60, 15/10=1.50

Order: item 1 (p=25) → item 3 (p=15) → item 2 (p=24)

x1=1 (w=18, rc=2), x2=2/15, x3=0

Profit = 25 + 24×(2/15) = 28.2

Picks expensive item first, but it is heavy. Leaves little room.

Heuristic (b): Smallest Weight

Ratios: same as above

Order: item 3 (w=10) → item 2 (w=15) → item 1 (w=18)

x3=1 (w=10, rc=10), x2=10/15, x1=0

Profit = 15 + 24×(10/15) = 31.0

Better than (a) but still suboptimal.

Heuristic (c): Highest Ratio ✓

Ratios: p2/w2=1.60, p3/w3=1.50, p1/w1=1.39

Order: item 2 → item 3 → item 1

x2=1 (w=15, rc=5), x3=1/2 (w=10×0.5=5), x1=0

Profit = 24 + 15×(1/2) = 31.5

Optimal — every unit of capacity earns the best possible profit.

Profit/Weight Ratio (the key):
ri = pi / wi
Profit earned per unit weight of item i. Optimal strategy: take items with largest ri first.
⚠ Critical Exam Note
Only the profit/weight ratio heuristic is guaranteed optimal for the fractional knapsack problem. The other two heuristics (highest profit first, smallest weight first) can produce arbitrarily bad results. Proof: at each step, the ratio heuristic selects the item with maximum "value density," which is optimal because the objective and constraints are linear.

Greedy Algorithm — Pseudocode

The algorithm first sorts items by profit/weight ratio in descending order, then greedily takes whole items until the remaining capacity cannot fit the next item, at which point it takes a fraction.

Knapsack(p[1..n], w[1..n], x[1..n], M) { // Sort items by p[i]/w[i] descending pwsort(p, w, n) // Initialize fractions to 0 for (i = 1 to n) x[i] = 0 rc = M // remaining capacity for (i = 1 to n) { if (w[i] > rc) break // cannot fit whole item x[i] = 1 rc = rc - w[i] } // Take fraction of current item if (i <= n) x[i] = rc / w[i] }

Variables

p[1..n] — profit array

w[1..n] — weight array

x[1..n] — fraction taken

M — knapsack capacity

rc — remaining capacity

Complexity

Sorting: O(n log n)

Greedy loop: O(n)

Total: O(n log n)

Space: O(1)

Step-by-Step Trace

M=20, w=[18,15,10], p=[25,24,15], sorted by ratio: items 2→3→1

Initial: rc = 20, x = [0, 0, 0]
i=1 (w=15, p=24, ratio=1.60): w[1] ≤ rc → x[1]=1, rc=20-15=5
i=2 (w=10, p=15, ratio=1.50): w[2] > rc → break
i=2 ≤ n: x[2] = 5/10 = 0.5
Result: x = [1, 0.5, 0], profit = 24 + 15×0.5 = 31.5

Linear-time Solution using Median

Sorting takes O(n log n). By using a median-finding approach, we can solve the fractional knapsack in O(n) time using a divide-and-conquer strategy.

Algorithm (Divide & Conquer)

FKSelect(p[1..n], w[1..n], M) { // 1. Find median m of ratios p[i]/w[i] in O(n) m = median(p, w, n) // 2. Partition into three groups: G = { i | p[i]/w[i] > m } // greater E = { i | p[i]/w[i] = m } // equal L = { i | p[i]/w[i] < m } // less // 3. Compute total weights GW = Σ w[i] for i ∈ G EW = Σ w[i] for i ∈ E if (GW > M) return FKSelect(G, M) // recurse on high group // Take all of G take all G items fully M = M - GW if (M ≤ EW) fill remaining from E proportionally return // Take all of E, recurse on L take all E items fully M = M - EW return FKSelect(L, M) // recurse on low group }
Recurrence Relation:
T(n) ≤ T(n/2) + O(n)
Each recursive call processes at most half the items. Median finding and partitioning take O(n). By the Master Theorem, T(n) = O(n).

Key Steps

1. Find median of ratios (O(n))

2. Partition into G, E, L (O(n))

3. Compute weight sums (O(n))

4. Recurse or fill (≤ n/2 items)

Why O(n) not O(n log n)?

• Median found in O(n) via select algorithm

• Each recursion halves problem size

• T(n) = T(n/2) + O(n) = O(n)

• No full sort needed!

Median Trace: M=20, w=[18,15,10], p=[25,24,15]
Ratios: r = [25/18=1.39, 24/15=1.60, 15/10=1.50]
Median m: sorted ratios [1.39, 1.50, 1.60] → median = 1.50
G (r > 1.50): item 2 (w=15) → GW=15
E (r = 1.50): item 3 (w=10) → EW=10
L (r < 1.50): item 1 (w=18)
GW=15 ≤ M=20: take all of G, M = 20-15 = 5
M=5 ≤ EW=10: fill from E: take 5/10 = 0.5 of item 3
Result: item 2=1, item 3=0.5, profit = 24+7.5 = 31.5

Worked Examples — Full Step-by-Step

Example 1: Basic Case

M = 20, n = 4
w = [6, 10, 3, 5], p = [12, 20, 15, 10]

Step 1: Compute ratios
r1 = 12/6 = 2.00
r2 = 20/10 = 2.00
r3 = 15/3 = 5.00
r4 = 10/5 = 2.00
Step 2: Sort by ratio descending
Order: item 3 (5.00) → item 1 (2.00) → item 2 (2.00) → item 4 (2.00)
Step 3: Greedy selection
rc = 20
i=1 (item 3, w=3): w ≤ rc → take all, rc = 20-3 = 17
i=2 (item 1, w=6): w ≤ rc → take all, rc = 17-6 = 11
i=3 (item 2, w=10): w ≤ rc → take all, rc = 11-10 = 1
i=4 (item 4, w=5): w=5 > rc=1 → take fraction: x = 1/5 = 0.2
Step 4: Total profit
Profit = 15 + 12 + 20 + 10×(0.2) = 15 + 12 + 20 + 2 = 49
x = [1, 1, 1, 0.2]
Total weight = 3 + 6 + 10 + 1 = 20 ✓
Example 2: All items fit exactly

M = 15, n = 3
w = [4, 7, 4], p = [8, 14, 12]

Step 1: Compute ratios
r1 = 8/4 = 2.00
r2 = 14/7 = 2.00
r3 = 12/4 = 3.00
Step 2: Sort by ratio descending
Order: item 3 (3.00) → item 1 (2.00) → item 2 (2.00)
Step 3: Greedy selection
rc = 15
i=1 (item 3, w=4): take all, rc = 15-4 = 11
i=2 (item 1, w=4): take all, rc = 11-4 = 7
i=3 (item 2, w=7): w=7 ≤ rc=7 → take all, rc = 0
Step 4: Total profit
Profit = 12 + 8 + 14 = 34
x = [1, 1, 1] (no fractions needed)
All items fit exactly into the knapsack. No fraction required.

r1 = 60/10 = 6.00
r2 = 100/20 = 5.00
r3 = 120/30 = 4.00
r4 = 45/15 = 3.00
r5 = 10/5 = 2.00

rc = 50
i=1 (item 1, w=10): take all, rc = 50-10 = 40
i=2 (item 2, w=20): take all, rc = 40-20 = 20

Profit = 60 + 100 + 120×(2/3) = 60 + 100 + 80 = 240

Order: item 3 (120) → item 2 (100) → item 1 (60) → ...

Order: item 5 (5) → item 1 (10) → item 4 (15) → item 2 (20) → item 3 (30)

Example 4: Single Item Fraction

M = 5, n = 2
w = [10, 8], p = [100, 40]

Ratios
r1 = 100/10 = 10.00
r2 = 40/8 = 5.00
Selection
Sort: item 1 (10.0) → item 2 (5.0)
rc = 5

Summary

Criterion Fractional Knapsack 0/1 Knapsack
Item divisibility Divisible (0 ≤ xi ≤ 1) Indivisible (xi ∈ {0, 1})
Optimal approach Greedy (ratio) Dynamic Programming
Time complexity O(n log n) or O(n) O(nM) pseudo-polynomial
Greedy works? Always optimal Not guaranteed
⚠ Exam Tips
• Always compute pi/wi ratios first
• Sort in descending order of ratio
• Take whole items until capacity is insufficient
• Take a fraction of the next item to fill remaining capacity
• The median-based O(n) method is an advanced topic — show recurrence T(n) = T(n/2) + O(n)
• Remember: greedy fails for 0/1 knapsack!
