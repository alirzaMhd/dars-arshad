Scheduling with Deadlines

Greedy Algorithms — Complete Guide with Worked Examples

Problem Definition

Given a set of n jobs, where each job has a deadline and a profit, we must schedule a subset of jobs on a single processor to maximize total profit. Each job takes exactly 1 unit of time to process.

⚠ Important Assumption: Each job takes exactly 1 unit of time. This is a key constraint — without it, the greedy approach discussed here would not apply directly.
Formal Definition
Given: J = { (d₁, p₁), (d₂, p₂), ..., (dₙ, pₙ) }
dᵢ = deadline (job must finish at or before time dᵢ)
pᵢ = profit (earned only if job completed by its deadline)
Each job requires 1 time unit. Find subset S ⊆ J maximizing Σpᵢ where S is feasible.

Feasibility Condition

A set of jobs is feasible if there exists a schedule (ordering) such that every job finishes by its deadline. Since each job takes 1 unit, a set of k jobs is feasible iff after sorting jobs by ascending deadline, we have:

Feasibility Test
deadline(i) ≥ i   for all i = 1, 2, ..., k
Where jobs are sorted by deadline and i is the position in the schedule.

Key Properties

Single Processor

Only one job at a time. No parallel execution.

Unit Processing Time

Every job takes exactly 1 time unit, regardless of job.

Deadline Constraint

Job must complete at or before its deadline (time ≤ dᵢ).

Profit Maximization

Goal: maximize sum of profits of scheduled jobs.

Optimal Substructure

If J is an optimal feasible set of jobs, then J − {j} (removing any job) is also an optimal feasible set for the remaining jobs. This property enables greedy construction of the solution.

Greedy Algorithm with Feasibility Checking

Algorithm Overview

The greedy algorithm builds a feasible job set incrementally. It processes jobs in decreasing order of profit. For each job, it tentatively adds it to the selected set and checks feasibility. If the set remains feasible, the job is kept; otherwise, it is discarded.

Important: To check feasibility of a set, we only need to examine jobs sorted by ascending deadline. There is no need to check all possible permutations — the deadline-sorted order is the canonical feasible order.

Pseudocode

function SCHEDULE_WITH_DEADLINES(J, d, p):
   Sort jobs by decreasing profit → list L
   S ← ∅ ▷ Selected feasible set
   for each job j in L:
      S' ← S ∪ {j}
      if IS_FEASIBLE(S') then
         S ← S'
      end if
   end for
   return S
 
function IS_FEASIBLE(S):
   Sort jobs in S by ascending deadline
   for i = 1 to |S|:
      if deadline(S[i]) < i then
         return false
      end if
   end for
   return true

Why Only One Feasibility Check?

For a given set of jobs, if any schedule orders them by deadline and this order is feasible, then the set is feasible. This is because:

  • If there exists some feasible schedule, sorting by deadlines always yields a feasible schedule
  • The deadline-sorted order minimizes the completion time of each job, giving the highest chance of feasibility
  • No other permutation can satisfy deadlines if the deadline-sorted order fails

Step-by-Step Feasibility Check

Given a candidate set S, the feasibility check works as follows:

  1. Sort jobs in S by ascending deadline
  2. Assign job[1] to time 1, job[2] to time 2, ..., job[k] to time k
  3. If for any job[i], deadline[i] < i, the set is infeasible
Feasibility Example

Suppose S has jobs with deadlines {3, 1, 2}.

Sorted by deadline: [d=1, d=2, d=3]

At position 1: deadline 1 ≥ 1 ✓
At position 2: deadline 2 ≥ 2 ✓
At position 3: deadline 3 ≥ 3 ✓

→ Feasible ✓

Suppose S has jobs with deadlines {1, 1, 3}.

Sorted by deadline: [d=1, d=1, d=3]

At position 1: deadline 1 ≥ 1 ✓

Union-Find Optimization

Motivation

The basic greedy algorithm checks feasibility from scratch each time (O(k) per job, O(n²) total). Using a Union-Find (Disjoint Set Union) data structure, we can reduce this to nearly O(1) per job.

Core Idea

Instead of checking deadlines for the entire set, we maintain time slots from 1 to the maximum deadline. For each job (processed in decreasing profit order):

  1. Find the latest free time slot ≤ deadline of the job
  2. If a free slot exists, assign the job to that slot
  3. Merge the assigned slot with the slot immediately before it (so future lookups skip occupied slots)

Data Structure

We maintain an array parent[] where parent[t] points to the next available slot before t. Initially, parent[t] = t for all t. When slot t is occupied, we set parent[t] = find(t-1).

Union-Find Operations
find(t) = latest free slot ≤ t
If slot t is free, returns t. Otherwise, recursively finds an earlier free slot.
After occupying slot t: union(t, t-1) so parent[t] points to t-1's parent.

Optimized Algorithm

function SCHEDULE_UF(J, d, p):
   Sort jobs by decreasing profit
   m ← max deadline among all jobs
   parent[0..m] initialized: parent[t] = t
   slot[1..m] ← empty
   total_profit ← 0
 
   for each job j in sorted order:
      t ← find(min(d[j], m))
      if t > 0:
         slot[t] ← j ▷ Assign job to slot t
         total_profit ← total_profit + p[j]
         parent[t] ← find(t - 1) ▷ Merge with previous
      end if
   end for
   return slot[1..m], total_profit

Path Compression

With path compression, each find operation runs in nearly O(1) time (amortized inverse Ackermann function α(n)). The entire scheduling becomes O(n log n + n α(m)) = O(n log n).

When to Use Each

  • Basic Greedy (O(n²)): Suitable when n ≤ 10³, or when simplicity and readability matter more than performance.
  • Union-Find (O(n log n)): Essential when n is large (10⁵+), or when jobs have a wide range of deadlines.
Note: α(n) is the inverse Ackermann function, which grows extremely slowly. For all practical values of n (even up to 10⁹), α(n) ≤ 5. This makes Union-Find operations effectively O(1) in practice.

Proof of Optimality (Sketch)

The greedy algorithm is optimal for the scheduling-with-deadlines problem under the 1-unit time assumption. The proof uses an exchange argument:

  1. Let G be the greedy solution and O be any optimal solution.
  2. Sort both sets by deadline. Let the first position where they differ be k.
  3. Greedy chose a higher-profit job at position k than any feasible alternative could.
  4. By swapping jobs, O can be transformed into G without decreasing profit.
  5. Therefore, G is at least as good as O → G is optimal.
