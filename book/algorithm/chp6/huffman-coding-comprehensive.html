Huffman Coding

Data Compression — Optimal Prefix-Free Codes for 20/20 Exam

Fixed-Length vs Variable-Length Codes

Fixed-Length Code Size:
bits per character = ⌈log₂(n)⌉
For n characters, fixed-length encoding requires ⌈log₂(n)⌉ bits per character

Fixed-Length

• Every character uses the same number of bits

• 26 English letters → 5 bits each

• a = 00000, b = 00001, c = 00010, ...

• Easy to decode (fixed boundaries)

• Wastes space on frequent characters

Variable-Length (Huffman)

• Frequent characters get short codes

• Rare characters get longer codes

• Must satisfy prefix-free property

• Harder to decode (no fixed boundaries)

• Achieves optimal compression

Prefix-Free Property

No codeword may be a prefix of any other codeword. This ensures unambiguous decoding.

Valid Example: a = 00, b = 101, c = 1000
No code is a prefix of another ✓
INVALID Example: a = 00, b = 001
"00" is a prefix of "001" → ambiguous decoding ✗

Why Prefix-Free?

Without it, a bitstream like "001" could decode as "a b" (00 + 1...) or "b" (001) — ambiguous!

Huffman uses a full binary tree where characters are leaves, guaranteeing the prefix-free property.

Compression Ratio

Fixed: n × ⌈log₂(|Σ|)⌉ bits

Huffman: Σ f(c) × L(c) bits

L(c) = code length, f(c) = frequency

Huffman Algorithm using Min-Heap

HUFFMAN(C) { // C is alphabet set with n characters Q = C // build min-heap from frequencies, O(n) for (i = 1 to n-1) { allocate new node z left[z] = x = EXTRACT_MIN(Q) // O(log n) right[z] = y = EXTRACT_MIN(Q) // O(log n) f[z] = f[x] + f[y] INSERT(Q, z) // O(log n) } return EXTRACT_MIN(Q) // root of Huffman tree }

Optimality:
Huffman codes achieve the minimum possible average code length for a given frequency distribution
Average length = Σ p(c) × L(c), where p(c) = f(c) / total frequency
Key Insight: The greedy choice of merging the two smallest frequencies at each step guarantees global optimality. This is proven via the exchange argument — any optimal prefix-free code can be transformed into a Huffman code without increasing the average code length.

Properties & Edge Cases

Key Property:
No node in a Huffman tree has exactly one child
If a node had a single child, the code could be shortened, contradicting optimality

Full Binary Tree

Huffman trees are full binary trees — every internal node has exactly two children.

For n leaf characters, there are exactly n-1 internal nodes.

Optimal Prefix Code

Huffman produces an optimal prefix-free code for a given frequency distribution.

No other prefix-free code can achieve a smaller average code length.

Greedy Choice Property

Merging the two smallest frequencies is always safe — it leads to a globally optimal solution.

Entropy Bound

Average code length L satisfies: H ≤ L < H + 1

Where H = Σ p(c) × log₂(1/p(c)) is the Shannon entropy.

Edge Case: Near-Uniform Distribution

Exercise Hint: If max_frequency / min_frequency < 2, Huffman offers no advantage over fixed-length codes.

Explanation: When frequencies are nearly equal, the Huffman tree becomes balanced and all codes have similar length. The overhead of storing the code table outweighs any compression benefit. Fixed-length codes are simpler and achieve the same or better compression in this scenario.

Edge Case: Single Character

If there is only one character, no encoding is needed. The Huffman algorithm still produces a valid tree with just a root node.

In this degenerate case, the code length is 0 bits.

Edge Case: Power of Two Frequencies

When frequencies follow a power-of-two ratio (e.g., 32, 16, 8, 4, 2, 1), Huffman produces codes identical to fixed-length codes in terms of length distribution, but achieves the theoretical entropy limit.

D-ary Huffman Coding (Extension to Base-3)

Textbook Exercise: Generalize Huffman coding to base-3 (ternary) using symbols {0, 1, 2}.
D-ary Huffman Condition
(n - 1) mod (d - 1) = 0
For d-ary Huffman with n characters. If not satisfied, add dummy characters with frequency 0 until it holds. For binary (d=2): always satisfied. For ternary (d=3): (n-1) must be even.
Ternary Huffman Example

Characters: a=5, b=9, c=12, d=13, e=16, f=45 (n=6)

Check: (6-1) mod (3-1) = 5 mod 2 = 1 ≠ 0 → add 1 dummy char with freq 0

Merge 3 smallest at each step instead of 2. The algorithm otherwise works identically to binary Huffman.
