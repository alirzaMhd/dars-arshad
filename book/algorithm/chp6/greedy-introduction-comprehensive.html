Introduction to Greedy Methods

Algorithms — Comprehensive Reference for Exam Preparation

Definition of Greedy Methods

A greedy algorithm repeatedly makes the best local choice at each step without considering past or future choices. It is conceptually simple and widely used for optimization problems.

Core Principle:
"Take the best available option right now"
No backtracking, no look-ahead, no global reconsideration

General Structure

A greedy algorithm operates on three key components:

  • C — A set of candidate choices available for selection
  • S — A solution set (initially empty) that grows incrementally
  • select(C) — Picks the "best" element from C according to a greedy criterion
  • feasible(S ∪ {x}) — Checks whether adding x produces a valid partial solution
  • solution(S) — Checks whether S constitutes a complete valid solution

Key Properties

• Greedy choice property: local optimum leads to global optimum

• Optimal substructure: optimal solution contains optimal sub-solutions

⚠ Not all problems satisfy these!

When to Use

✔ Problems with optimal substructure

✔ Problems where greedy choice is safe

✗ Fails when local choices lead to dead ends

General Greedy Pseudocode

Greedy(C)
{
  // C = set of candidates, S = solution set
  S = Ø
  while (!solution(S) && C ≠ Ø)
  {
    x = select(C)
    C = C – {x}
    if (feasible(S ∪ {x}))
      S = S ∪ {x}
  }
  if (solution(S)) return S
  else return Ø
}

Common Greedy Algorithms

Fractional Knapsack

Pick items by value/weight ratio

Time: O(n log n)

Huffman Coding

Merge two smallest frequency nodes

Time: O(n log n)

Activity Selection

Pick next earliest finish time

Time: O(n log n)

Min Completion Time

Schedule shortest processing time first

Time: O(n log n)

Scheduling Deadlines

Sequence jobs by earliest deadline

Time: O(n²)

Kruskal / Prim

Pick minimum weight edge (Kruskal) or vertex (Prim)

Time: O(E log V)

Dijkstra

Expand shortest distance vertex

Time: O(V²) or O(E log V)

Time Complexity Analysis

The complexity of a greedy algorithm depends on:

  • Selection cost — How select(C) is implemented (often sorting dominates: O(n log n))
  • Feasibility check — How fast feasible() runs (often O(1) or O(n))
  • Number of iterations — How many candidates are processed (typically O(n))

Overall: O(n log n) for most greedy algorithms (dominated by sorting). Some achieve O(n) when selection is O(1).

Worked Examples

Example 1: Coin Change — Canonical US Coins (Optimal Case)

Coins available: {25, 10, 5, 1}  |  Amount: 36

Step 1: select(25 ≤ 36), remaining = 11, coins = {25}
Step 2: select(10 ≤ 11), remaining = 1, coins = {25, 10}
Step 3: select(5 > 1) → infeasible, skip 5
Step 4: select(1 ≤ 1), remaining = 0, coins = {25, 10, 1}

Result: {25, 10, 1} → 3 coins (OPTIMAL)

Greedy succeeds: the canonical coin system is designed so greedy gives the optimal answer.
Example 2: Coin Change — Non-Canonical Coins (Suboptimal Case)

Coins available: {12, 10, 5, 1}  |  Amount: 16

Greedy approach:
Step 1: select(12 ≤ 16), remaining = 4, coins = {12}
Step 2: select(10 > 4) → infeasible, skip
Step 3: select(5 > 4) → infeasible, skip
Step 4: select(1 ≤ 4), repeat 4 times, remaining = 0, coins = {12, 1, 1, 1, 1}

Greedy result: {12, 1, 1, 1, 1} → 5 coins

Optimal: {10, 5, 1} → 3 coins  |  Greedy is 67% worse!

⚠ Greedy fails! The local optimum (12) leads to a worse global solution. This demonstrates that greedy does not always yield the optimal answer.
Example 3: Activity Selection — Maximize Number of Activities

Activities with (start, finish) times:

ActivityA₁A₂A₃A₄A₅A₆
Start130585
Finish456799
Greedy rule: select activity with earliest finish time that is compatible.
Step 1: Sort by finish: A₁(1,4), A₂(3,5), A₃(0,6), A₄(5,7), A₅(8,9), A₆(5,9)
Step 2: Pick A₁ (finish=4). Next compatible: start ≥ 4 → A₂(3,5): start=3<4, skip. A₃(0,6): start=0<4, skip. A₄(5,7): start=5≥4 → pick.
Step 3: Pick A₄ (finish=7). Next compatible: A₅(8,9): start=8≥7 → pick.
Step 4: Pick A₅ (finish=9). No more compatible activities.

Selected: {A₁, A₄, A₅} → 3 activities (OPTIMAL)

Activity selection is a classic problem where greedy (earliest finish time) is provably optimal.
Example 4: Fractional Knapsack — Maximizing Value

Knapsack capacity: 50

ItemWeightValueValue/Weight
A10606.0
B201005.0
C301204.0

Greedy: sort by value/weight descending → A (6.0), B (5.0), C (4.0)

Step 1: Take A entirely (w=10, v=60). Remaining capacity: 40
Step 2: Take B entirely (w=20, v=100). Remaining capacity: 20
Step 3: Take C fractionally (20/30 × 120 = 80). Remaining: 0

Total value: 60 + 100 + 80 = 240 (OPTIMAL)

Fractional knapsack satisfies the greedy choice property because we can take fractions. This is always optimal.
Example 5: Coin Change — Another Non-Canonical Set

Coins available: {9, 6, 5, 1}  |  Amount: 11

Greedy: select(9 ≤ 11), remaining = 2, coins = {9}; select(1), remaining = 1; select(1), remaining = 0 → {9, 1, 1} = 3 coins
Optimal: {6, 5} = 2 coins

Greedy gives 3 coins but optimal is 2 coins. Again, greedy fails because the largest-first strategy is not globally optimal for arbitrary coin systems.

⚠ WARNING: Greedy is NOT Always Optimal

A greedy algorithm chooses the best local option without considering future consequences. This approach works only when the problem has the greedy choice property (a local optimum leads to a global optimum) and optimal substructure (an optimal solution contains optimal solutions to subproblems). When these properties do not hold, greedy may produce suboptimal or even useless results.

Always prove correctness or verify with counterexamples before deploying a greedy solution.

Necessary Conditions for Greedy Optimality

1. Greedy Choice Property

A globally optimal solution can be obtained by making locally optimal choices. The first greedy choice leads to an optimal solution; no reconsideration is needed.

Proof method: Exchange argument

2. Optimal Substructure

An optimal solution to the whole problem contains within it optimal solutions to each subproblem. This property is shared with dynamic programming.

Proof method: Cut-and-paste argument

💡 Key Insight

Both greedy and DP exploit optimal substructure. The difference: greedy makes one choice then solves the remaining subproblem (top-down, no branching). DP explores all possible choices and combines results. If the greedy choice property holds, greedy is vastly more efficient. If not, DP is necessary.
