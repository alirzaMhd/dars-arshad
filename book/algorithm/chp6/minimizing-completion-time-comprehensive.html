Minimizing Total Completion Time

Scheduling — Shortest Job First (SJF) for Optimal Turnaround

Problem Definition

We are given N processes (or jobs) to run sequentially on a single processor. Each process i has a known processing time pi. The goal is to find an ordering of the processes that minimizes the sum of completion times (also called total turnaround time).

Objective Function:
Minimize Σi=1N Ci
Where Ci is the completion time of process i in the chosen order.
Completion Time Definition:
Ck = Σj=1k pj
The completion time of the k-th process is the sum of its processing time plus all preceding processes.

Key Variables

SymbolMeaning
NNumber of processes to schedule
piProcessing time of process i
CiCompletion (turnaround) time of process i
ΣCiTotal completion time (the objective to minimize)
⚠ Common Mistake: Do not confuse turnaround time (completion time) with response time. Turnaround time measures the total time from submission to completion (Ci). Response time measures the time until the process first gets the CPU. In batch scheduling where all processes arrive at time 0, these can differ — but for total completion time we always use completion time, not response time.

Assumptions

• Single processor

• All processes arrive at time 0

• No preemption

• Processing times known in advance

Complexity

Time: O(n log n)

Space: O(n)

Optimal solution is just sorting

Optimal Strategy: Sort processes by processing time in ascending order — the Shortest Job First (SJF) rule. This yields the minimum possible sum of completion times.

Optimality Proof Intuition

Exchange Argument

Suppose we have an optimal schedule S. If there exist two adjacent processes i and j in S such that pi > pj (a longer job before a shorter one), swapping them produces a new schedule S' whose total completion time is smaller or equal — contradicting the optimality of S. Therefore, in any optimal schedule, processes must appear in non-decreasing order of processing time.

Proof (pairwise exchange):
Δ = (Ci + Cj)before - (Ci + Cj)after = (pi + pi+pj) - (pj + pj+pi) = pi - pj
If pi > pj, then Δ > 0, meaning the swap reduces total completion time.

Since any permutation can be obtained through adjacent swaps, the only permutation with no "inversions" (long before short) is the sorted-by-processing-time order — proving SJF is optimal.

Algorithm

Algorithm: MINIMIZE_TOTAL_COMPLETION(P, n) │ Input: Array P[1..n] of processing times │ Output: Minimum total completion time and optimal schedule sort(P) ◄ O(n log n) total ← 0 cumulative ← 0 for i ← 1 to n do cumulative ← cumulative + P[i] total ← total + cumulative end for return total, P

Algorithm Steps

1. Sort processing times ascending

2. Compute cumulative sums

3. Sum cumulative sums

4. Return total and schedule

Complexity

Sorting: O(n log n)

Summation pass: O(n)

Overall: O(n log n)

Key Insight: The algorithm itself is simply sorting. No complex data structures needed. The sorting is the scheduling algorithm.

Takeaway

• The penalty for poor ordering grows with variance in processing times.

• With a very large job and many small ones, the difference can be enormous.

• SJF always achieves the theoretically optimal total completion time.
