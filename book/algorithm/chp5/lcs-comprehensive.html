Longest Common Subsequence (LCS)

Dynamic Programming — Algorithm Design (Hadi Yousefi)

Problem Definition

Given two sequences X = ⟨x₁, x₂, ..., xₘ⟩ and Y = ⟨y₁, y₂, ..., yₙ⟩, find the longest sequence Z that is a subsequence of both X and Y.

Subsequence Definition:
Z = ⟨z₁, z₂, ..., zₖ⟩ is a subsequence of X if ∃ indices i₁ < i₂ < ... < iₖ with zⱼ = x_{iⱼ} ∀ j
A subsequence is obtained by deleting zero or more elements (not necessarily contiguous).
⚠ LCS is different from longest common substring! Subsequence does NOT require consecutiveness — elements can be non-adjacent in the original sequence.
Example: LCS vs Longest Common Substring

X = "ABCDEF", Y = "ACDF"

TypeResultExplanation
LCS (subsequence)"ACDF" (length 4)Characters don't need to be adjacent
Common substring"CD" (length 2)Must be contiguous in both strings

LCS is more general. "A", "C", "D", "F" appear in order in X though not consecutively.

Brute Force Approach

The naive solution enumerates all 2m subsequences of X and checks each against Y in O(n) time. Total: O(2m · n), which is exponential.

Input

• Sequence X (length m)

• Sequence Y (length n)

Output

• Length of LCS

• One LCS sequence

Applications

• DNA sequence alignment

• Version control (diff)

• Plagiarism detection

Dynamic Programming Solution

Recurrence Relation

Define C[i][j] = length of LCS of prefixes X[1..i] and Y[1..j].

Base Case (empty prefix):
C[0][j] = 0   and   C[i][0] = 0   ∀ i, j
LCS with an empty sequence always has length 0.
Characters Match (xᵢ = yⱼ):
C[i][j] = C[i-1][j-1] + 1
Extend the LCS by one character. Direction: diagonal ↖.
Characters Differ (xᵢ ≠ yⱼ):
C[i][j] = max( C[i-1][j] , C[i][j-1] )
Take the best of skipping xᵢ or skipping yⱼ. Direction: ↑ or ←.
Final Answer:
C[m][n]
Length of the LCS of the full sequences X and Y.

Optimal Substructure

The LCS of X and Y contains the LCS of X[1..m-1] and Y[1..n-1] as a sub-problem — if the last characters match, they extend the LCS of the prefixes. If they don't match, the LCS of the full strings equals the LCS of one prefix pair.

Overlapping Subproblems

The same subproblem C[i][j] is referenced by multiple larger subproblems. DP computes each subproblem once and stores it, avoiding redundant recomputation.

Algorithm: LCS-LENGTH

LCS-LENGTH(X, Y, m, n) let C[0..m][0..n], B[1..m][1..n] for i ← 0 to m C[i][0] ← 0 for j ← 0 to n C[0][j] ← 0 for i ← 1 to m for j ← 1 to n if X[i] = Y[j] C[i][j] ← C[i-1][j-1] + 1 B[i][j] ← "↖" // diagonal else if C[i-1][j] ≥ C[i][j-1] C[i][j] ← C[i-1][j] B[i][j] ← "↑" // up else C[i][j] ← C[i][j-1] B[i][j] ← "←" // left return C[m][n], B

Algorithm: PRINT-LCS (Backtracking)

PRINT-LCS(B, X, i, j) if i = 0 or j = 0 return if B[i][j] = "↖" PRINT-LCS(B, X, i-1, j-1) print X[i] else if B[i][j] = "↑" PRINT-LCS(B, X, i-1, j) else PRINT-LCS(B, X, i, j-1)

Complexity Analysis

Time Complexity

O(mn)

Filling the m×n table with constant work per cell. Backtracking takes O(m+n).

Space Complexity

O(mn)

C table (m+1)×(n+1) and B table m×n. Can be reduced to O(min(m,n)) for length only.

Hirschberg's Algorithm

Computes LCS in O(mn) time and O(min(m,n)) space using divide and conquer.
