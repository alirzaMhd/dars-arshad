Traveling Salesman Problem (TSP)

Dynamic Programming — Algorithm Design (Hadi Yousefi)

Problem Definition

Given a complete directed graph with n vertices and a cost matrix c[i][j] (cost of traveling from city i to city j), find a Hamiltonian cycle (tour) of minimum total cost that visits each city exactly once and returns to the starting city.

Objective:
min   c[1][i₂] + c[i₂][i₃] + ... + c[iₙ][1]
Minimize the sum of edge costs along a cycle visiting all vertices exactly once.
⚠ TSP is NP-hard — DP solution O(n²·2ⁿ) is still exponential but much better than O((n-1)!) brute force!

Brute Force Approach

The naive solution enumerates all possible permutations of cities. For n cities, there are (n-1)! possible tours (fixing city 1 as the start).

Dynamic Programming Solution (Held-Karp Algorithm)

Recurrence Relation

Define g(i, S) = minimum cost of a path starting from city 1, visiting all cities in set S exactly once, and ending at city i, where i ∈ S and 1 ∉ S.

Base Case (S has one element):
g(i, {i}) = c[1][i]   for i = 2...n
Cost of going directly from city 1 to city i.
Recurrence (|S| > 1):
g(i, S) = min_{j ∈ S, j ≠ i} ( c[j][i] + g(j, S - {i}) )
For each possible previous city j in S (j ≠ i).
Final Answer:
Answer = min_{i = 2...n} ( g(i, V - {1}) + c[i][1] )
Return to city 1 from the last visited city.

Bitmask Representation

Subsets S are represented using bitmasks. For n cities, a mask of n-1 bits (excluding city 1) represents which cities are in the set. Bit j-2 corresponds to city j (j ≥ 2).

Example for n = 4: S = {2, 4} → mask = 101 (binary) = 5 Bits indexed from right (bit 0 = city 2, bit 1 = city 3, bit 2 = city 4)

Algorithm: TSP DP with Bitmask

TSP-DP(c, n) let g[n+1][2^(n-1)] be a 2D array for i ← 2 to n g[i][0] ← c[1][i] // base case: direct from city 1 for mask ← 1 to 2^(n-1)-1 for i ← 2 to n if bit i is set in mask g[i][mask] ← ∞ let prevMask ← mask with bit i cleared for each j ∈ cities in prevMask g[i][mask] ← min(g[i][mask], c[j][i] + g[j][prevMask]) answer ← ∞ fullMask ← 2^(n-1)-1 for i ← 2 to n answer ← min(answer, g[i][fullMask] + c[i][1]) return answer

Complexity Analysis

Time Complexity

O(n² · 2ⁿ)

For each of the 2ⁿ subsets, we compute up to n entries, each considering up to n possible previous cities.

Space Complexity

O(n · 2ⁿ)

Storage of g(i,S) for each city i and each subset S. The table has n × 2ⁿ⁻¹ entries.

vs Brute Force

Brute force: O((n-1)!)

n=20: DP ≈ 400M vs BF ≈ 10¹⁷ operations
