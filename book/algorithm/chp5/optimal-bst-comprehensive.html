Optimal Binary Search Tree (OBST)

Dynamic Programming — Algorithm Design (Hadi Yousefi)

Problem Definition

Given n keys k₁, k₂, ..., kₙ with search probabilities p₁, p₂, ..., pₙ (where Σ pᵢ = 1), construct a binary search tree that minimizes the expected search cost.

Expected Search Cost:
Cost(T) = Σ_{i=1}^{n} pᵢ · (depth(kᵢ) + 1)
Weighted sum of all key depths, where depth is the number of comparisons required to find the key.
⚠ High-probability keys should be near the root to minimize expected search cost!

BST Properties

In a BST, for any node: all keys in its left subtree are smaller, and all keys in its right subtree are larger. The tree must maintain this ordering property.

Example: 3 Keys with Probabilities

Keys: k₁=10 (p₁=0.5), k₂=20 (p₂=0.3), k₃=30 (p₃=0.2)

Input

• n sorted keys k₁...kₙ

• Probabilities p₁...pₙ

Output

• Minimum expected search cost

• The optimal BST structure (roots)

Constraints

• BST ordering must hold

• Probabilities sum to 1

Dynamic Programming Solution

Recurrence Relation

Define A[i][j] = minimum expected search cost for the subproblem with keys kᵢ...kⱼ (where i ≤ j).

Define R[i][j] = index of the root chosen for the optimal BST for keys kᵢ...kⱼ (used for reconstruction).

Base Case (single key):
A[i][i] = pᵢ   and   R[i][i] = i
A tree with one key has cost equal to its probability.
Recurrence (i < j):
A[i][j] = min_{i ≤ m ≤ j} ( A[i][m-1] + A[m+1][j] ) + Σ_{t=i}^{j} p_t
For each possible root m in keys i..j:
• A[i][m-1] = cost of left subtree (keys i..m-1)
• A[m+1][j] = cost of right subtree (keys m+1..j)
• Add all probabilities because each key's depth increases by 1 when a root is added above
• If i > m-1 or m+1 > j, the empty subtree cost = 0
Final Answer:
A[1][n]
Minimum expected search cost for the complete set of n keys.

Algorithm: Optimal BST DP

OPTIMAL-BST(p, n) let A[1..n+1][0..n], R[1..n][1..n] for i ← 1 to n A[i][i] ← p[i] R[i][i] ← i A[i][i-1] ← 0 // empty subtree A[n+1][n] ← 0 // empty right subtree for key n for d ← 1 to n-1 // diagonal (chain length - 1) for i ← 1 to n-d j ← i + d A[i][j] ← ∞ sumP ← Σ_{t=i}^{j} p[t] for m ← i to j cost ← A[i][m-1] + A[m+1][j] + sumP if cost < A[i][j] A[i][j] ← cost R[i][j] ← m return A[1][n], R

Tree Reconstruction from R Matrix

BUILD-TREE(R, i, j) if i > j return null r ← R[i][j] node = new Node(key[r]) node.left = BUILD-TREE(R, i, r-1) node.right = BUILD-TREE(R, r+1, j) return node

Complexity Analysis

Time Complexity

O(n³)

For each of O(n²) subproblems, we try O(n) possible roots. Total O(n³) operations.

Space Complexity

O(n²)

Two n×n tables: A for costs, R for roots. The R matrix can reconstruct the full tree.

Knuth Optimization

For OBST, the root choice is monotonic: R[i][j-1] ≤ R[i][j] ≤ R[i+1][j]. This reduces to O(n²) by limiting root search range.

Problem Setup

Given n keys with known search probabilities, find the BST that minimizes the expected search cost.

Keys and dummy keys (gaps) have associated probabilities. The cost accounts for both successful and unsuccessful searches.

Key Formula

e[i][j] = min over k=i..j of { e[i][k-1] + e[k+1][j] + w[i][j] }

w[i][j] = sum of all probabilities in subtree i..j. Adding w[i][j] accounts for the extra depth of every node.

Base case: e[i][i-1] = q[i-1] (cost of an empty subtree = dummy key probability).
