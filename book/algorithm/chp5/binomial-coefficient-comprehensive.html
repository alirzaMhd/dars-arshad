Binomial Coefficient C(n,k)

The binomial coefficient C(n,k) represents the number of ways to choose k elements from a set of n distinct elements, without regard to order. It is also called "n choose k".

Mathematical Definition:
C(n,k) = n! / (k! × (n-k)!)
For 0 ≤ k ≤ n, with C(n,k) = 0 for k < 0 or k > n
Pascal's Identity (Recurrence Relation):
C(n,k) = C(n-1,k-1) + C(n-1,k)
for 1 ≤ k ≤ n-1, with base cases C(n,0) = C(n,n) = 1
Pascal's Triangle Structure:
n=0: 1
n=1: 1 1
n=2: 1 2 1
n=3: 1 3 3 1
n=4: 1 4 6 4 1
n=5: 1 5 10 10 5 1
Each entry is the sum of the two entries directly above it

Combinatorial Meaning

C(n,k) answers: "How many ways can we select k items from n items?"

  • Choosing a committee of k people from n candidates
  • Number of k-element subsets of an n-element set
  • Number of paths in a grid from (0,0) to (k, n-k) moving only right and up

Properties

• Symmetry: C(n,k) = C(n, n-k)

• Sum: Σk=0n C(n,k) = 2n

• Binomial theorem: (x+y)n = Σ C(n,k) xn-k yk

Range of Values

C(n,k) grows quickly:

C(10,5) = 252

C(20,10) = 184,756

C(30,15) = 155,117,520

Dynamic Programming Solution

Approach 1: 2D DP Table (Standard)

Build a table where dp[i][j] = C(i,j). Use Pascal's identity to fill the table row by row.

int binomialCoeff(int n, int k) {
  int dp[n+1][k+1];
  for (int i = 0; i <= n; i++) {
    for (int j = 0; j <= min(i, k); j++) {
      if (j == 0 || j == i)
        dp[i][j] = 1;
      else
        dp[i][j] = dp[i-1][j-1] + dp[i-1][j];
    }
  }
  return dp[n][k];
}
Complexity:
Time: O(nk), Space: O(nk)

Approach 2: Space-Optimized 1D Array

Since C(i,j) only depends on the previous row, we can use a single 1D array and update from right to left.

int binomialCoeffOpt(int n, int k) {
  int dp[k+1];
  dp[0] = 1;
  for (int i = 1; i <= n; i++) {
    for (int j = min(i, k); j > 0; j--)
      dp[j] = dp[j] + dp[j-1];
  }
  return dp[k];
}
Complexity:
Time: O(nk), Space: O(k)

Naive Divide & Conquer (Recursive)

The naive recursive approach directly implements Pascal's identity but recomputes subproblems exponentially.

int binomialNaive(int n, int k) {
  if (k == 0 || k == n) return 1;
  return binomialNaive(n-1, k-1) + binomialNaive(n-1, k);
}
Complexity:
Time: O(2n), Space: O(n) recursion stack
Warning: Number of recursive calls for naive approach = 2 × C(n,k) - 1, which grows exponentially. For C(30,15), this is over 300 million calls!

For C(10,5), the recursive tree makes 503 total calls, but only 66 distinct subproblems exist (all C(i,j) for 0 ≤ i ≤ 10, 0 ≤ j ≤ min(i,5)).

The DP table fills exactly these 66 entries once each, eliminating 437 redundant computations.

Extrapolation for larger values:

  • C(20,10): DP needs 165 entries vs ~369,000 recursive calls
  • C(30,15): DP needs 345 entries vs ~300+ million recursive calls

Conclusion: DP is dramatically more efficient, reducing exponential O(2n) to polynomial O(nk).

Exam Tip: When asked about binomial coefficient in exams, always consider:
• Base cases: C(n,0) = C(n,n) = 1
• The DP table only needs to compute up to column k (since C(n,k) = C(n,n-k), choose the smaller k)
• Space optimization: update 1D array from right to left to avoid overwriting needed values
