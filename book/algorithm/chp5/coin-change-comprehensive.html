Coin Change Problem (Minimum Number of Coins)

Given a set of coin denominations d1, d2, ..., dn (with unlimited supply of each) and a target amount M, find the minimum number of coins needed to make exactly amount M. If it is not possible, return infinity (or -1).

Problem Formulation:
Given: denominations D = {d1, d2, ..., dn}, target M
Find: min number of coins whose sum = M
Each coin can be used any number of times (unlimited supply)

Input

• Coin denominations: d1, d2, ..., dn

• Target amount: M

• Unlimited supply of each coin

Output

• Minimum number of coins

• Which coins to use (via backtracking)

Unbounded Knapsack Analogy:
This is the "unbounded knapsack" variant where each item (coin) can be taken unlimited times
Differs from 0/1 knapsack where each item can be taken at most once
Warning: Greedy does NOT always give optimal solution for coin change! For denominations {1, 3, 4} and amount 6, greedy gives 3 coins (4+1+1) but optimal is 2 coins (3+3). Always verify with DP.

Greedy vs DP Comparison

Criterion Greedy Approach DP Approach
Strategy Pick largest coin first Try all possibilities
Optimality Only for canonical systems Always optimal
Time O(n) or O(M) O(nM)
Space O(1) O(M) (optimized)
Works for {1,4,6}, M=8? No (gives 4+1+1+1+1=5 coins) Yes (4+4=2 coins)

Dynamic Programming Solution

Recurrence Relation

Let c[i][j] = minimum number of coins needed to make amount j using first i coin denominations.

Recurrence:
c[i][j] = min(c[i-1][j], c[i][j-di] + 1)   if j ≥ di
c[i][j] = c[i-1][j]                          if j < di
c[i-1][j] = don't use coin i
c[i][j-di] + 1 = use coin i (unlimited supply, so stay on row i)
Base Cases:
c[1][j] = j / d1   (if d1 = 1, or divisibility holds)
c[i][0] = 0   for all i
c[0][j] = ∞   for all j > 0
Answer is c[n][M] (or ∞ if impossible)

Algorithm

COIN-CHANGE(d, n, M):
  let c[0..n][0..M] be 2D array
  for j = 1 to M: c[0][j] = ∞
  for i = 0 to n: c[i][0] = 0
  for i = 1 to n:
    for j = 1 to M:
      if j < d[i]:
        c[i][j] = c[i-1][j]
      else:
        c[i][j] = min(c[i-1][j], c[i][j-d[i]] + 1)
  return c[n][M]

Space-Optimized Version (1D Array)

Since c[i][j] only depends on c[i-1][j] and c[i][j-di], we can use a 1D array updated left-to-right.

COIN-CHANGE-1D(d, n, M):
  let dp[0..M] = ∞
  dp[0] = 0
  for i = 1 to n:
    for j = d[i] to M:
      dp[j] = min(dp[j], dp[j-d[i]] + 1)
  return dp[M]
Complexity:
Time: O(nM), Space: O(M) with 1D optimization

Coin Tracking (Backtracking)

To find which coins form the optimal solution, maintain a separate array used[i][j] that records which decision was made at each step.

TRACK-COINS(used, d, n, M):
  i = n, j = M
  while j > 0:
    if used[i][j] == "take":
      print d[i]
      j = j - d[i]
    else:
      i = i - 1

Worked Examples

Example 1: Coins {1, 4, 6}, Amount = 8 — Greedy Fails

Greedy approach: Pick largest coin first.

Step 1: Pick 6 (remaining = 2)
Step 2: Pick 1 (remaining = 1)
Step 3: Pick 1 (remaining = 0)
Coins used: 6, 1, 1 → 3 coins

DP approach: Build the table c[i][j]:

i\j012345678
0 (none)0∞∞∞∞∞∞∞∞
1 (d=1)012345678
2 (d=4)012312342
3 (d=6)012312122

c[3][8] = 2 (use two coins of 4).

DP result: 2 coins (4 + 4) — better than greedy's 3 coins!

The greedy algorithm fails because a larger coin (6) forces small coins to fill the remainder, while two medium coins (4+4) sum to 8 perfectly.

Example 2: Coins {1, 3, 4}, Amount = 6 — Full DP Table

Build the DP table:

i\j0123456
1 (d=1)0123456
2 (d=3)0121232
3 (d=4)0121122

Step-by-step for c[3][6]:

c[3][6] = min(c[2][6], c[3][6-4] + 1) = min(2, c[3][2] + 1)
c[3][2] = c[2][2] = 2 (since d3=4 > 2)
c[3][6] = min(2, 2+1) = 2

Result: 2 coins (3 + 3). Greedy would give 3 coins (4 + 1 + 1).

Backtracking: c[3][6] came from c[2][6] (don't use coin 4). c[2][6] = min(c[1][6], c[2][3] + 1) = min(6, 1+1) = 2, using c[2][3]. c[2][3] uses one coin 3. Then c[2][3-3] = c[2][0] = 0. So coins: 3, 3.

Example 3: Coins {2, 5, 10}, Amount = 14 — Find Which Coins

DP Table:

i\j01234567891011121314
1 (d=2)0∞1∞2∞3∞4∞5∞6∞7
2 (d=5)0∞1∞21324324354
3 (d=10)0∞1∞21324313243

c[3][14] = 3 coins

Backtracking to find the coins:

We need a tracking matrix. Let's trace manually:

c[3][14] = min(c[2][14], c[3][4] + 1) = min(4, 2 + 1) = 3
So we take one coin of 10 (d3). Remaining: 14-10 = 4.

c[3][4] = c[2][4] = 2 (d3=10 > 4, so can't use coin 10).
c[2][4] = min(c[1][4], c[2][-1]) — j < d2=5, so c[2][4] = c[1][4] = 2 (two coins of 2).

Now trace back: c[2][4] came from c[1][4]. c[1][4] uses 4/2 = 2 coins of 2.

Optimal coins: 10 + 2 + 2 = 14 (3 coins)

Note: 5 + 5 + 2 + 2 = 14 (4 coins) is suboptimal. The DP correctly finds 3 coins as the minimum.

Exam Tip: Key points for exam problems:
• The recurrence c[i][j] = min(c[i-1][j], c[i][j-di] + 1) uses c[i][...] (same row) because of unlimited supply
• Unlike 0/1 knapsack where we use c[i-1][j-wi], unbounded knapsack uses c[i][j-di]
• Initialize with c[0][j] = ∞ for j > 0 and c[i][0] = 0 for all i
• When d1 = 1, all amounts are achievable, but the DP still finds the minimum
