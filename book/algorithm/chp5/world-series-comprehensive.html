World Series (Tournament) Problem

The World Series problem is a classic dynamic programming problem that models a competitive series between two teams. Two teams, A and B, are playing a series of games until one team reaches a predetermined number of wins. Team A needs i more wins to win the championship, and team B needs j more wins. Each game is independent with a fixed probability p that team A wins and q = 1-p that team B wins. The goal is to find the probability that team A eventually wins the championship.

Understanding the Problem Intuition

This problem captures the essence of competitive advantage in a structured format. Imagine you're watching a playoff series where two evenly matched teams compete. At any point in the series, you can describe the state by how many wins each team still needs. The key insight is that the probability of A winning the series from a given state depends only on the current state (i,j), not on how we got there. This memoryless property makes it perfect for dynamic programming.

Problem Parameters:
i = number of wins A still needs to win the championship
j = number of wins B still needs to win the championship
p = probability A wins any single game (0 ≤ p ≤ 1)
q = 1 - p = probability B wins any single game
Goal: Find P(i,j) = probability A wins the series starting from state (i,j). The final answer is P(n,n) for a "best-of-(2n-1)" series where n wins are needed.

What Does State (i,j) Represent?

The state (i,j) represents a critical moment in the series: A needs i more wins and B needs j more wins. This means:

  • If i = 0, A has already won the series (regardless of j)
  • If j = 0, B has already won the series (regardless of i)
  • If both i > 0 and j > 0, the series is still ongoing
  • The total number of games that could still be played ranges from min(i,j) to i+j-1
Boundary Conditions (Base Cases):
P(0,j) = 1   for j ≥ 1   (A already has enough wins — A has won the series)
P(i,0) = 0   for i ≥ 1   (B already has enough wins — B has won the series)
P(0,0) = undefined (this state is impossible — the series cannot be ongoing when both have enough wins)
These boundary conditions are the foundation of our recurrence. They represent the absorbing states of our Markov chain — once we reach them, the series is over.

Why P(0,j) = 1 and P(i,0) = 0?

This is crucial to understand:

  • P(0,j) = 1: When A needs 0 more wins, it means A has already accumulated enough wins to win the series. No matter how many wins B still needs, A has already won. The probability of A winning is 1 (certainty).
  • P(i,0) = 0: When B needs 0 more wins, it means B has already accumulated enough wins to win the series. A cannot win anymore because the series is over. The probability of A winning is 0 (impossibility).
  • P(0,0) is undefined: This represents a state where both teams have already won the series, which is logically impossible in a well-defined series. This state should never be reached during computation.

Real-World Analogy and Applications

This models any best-of series where two opponents compete until one reaches a target number of wins:

  • World Series (best-of-7, n=4) — Major League Baseball championship
  • NBA Finals (best-of-7, n=4) — National Basketball Association championship
  • Stanley Cup Finals (best-of-7, n=4) — National Hockey League championship
  • MLB Division Series (best-of-5, n=3) — earlier playoff rounds
  • Tennis Grand Slam finals (best-of-5 sets for men, best-of-3 for women)
  • Esports tournament finals (various formats)
  • Any two-player competition with a target win count

Series Formats

• Best-of-3: n=2 (first to 2 wins, max 3 games)

• Best-of-5: n=3 (first to 3 wins, max 5 games)

• Best-of-7: n=4 (first to 4 wins, max 7 games)

• Best-of-9: n=5 (first to 5 wins, max 9 games)

Note: "best-of-(2n-1)" means first to n wins, with at most 2n-1 games played

Key Assumptions

• Games are independent (no momentum effect)

• p is fixed for all games (no changing conditions)

• No draws or ties (every game has a winner)

• Both teams play the same number of games (no home-field advantage in probability)

These assumptions are critical — if violated, the model gives incorrect results

The State Space

The state space consists of all possible (i,j) pairs where 0 ≤ i ≤ n and 0 ≤ j ≤ n. This gives us (n+1) × (n+1) = O(n²) total states. However, we never need to compute P(0,0), so the effective number of states is O(n²) - 1.

For a best-of-7 series (n=4), the state space includes:

  • States where the series is over: P(0,j) for j=1,2,3,4 and P(i,0) for i=1,2,3,4
  • States where the series is ongoing: P(i,j) for i,j = 1,2,3,4
  • Total: 8 boundary states + 16 internal states = 24 states (plus undefined P(0,0))

Why Dynamic Programming?

This problem has two key properties that make it suitable for DP:

  • Optimal Substructure: The probability P(i,j) can be computed from P(i-1,j) and P(i,j-1). The solution to the larger problem contains solutions to smaller subproblems.
  • Overlapping Subproblems: When computing P(i,j), we need P(i-1,j) and P(i,j-1). These same subproblems appear when computing other states, so we can store and reuse their solutions.

Without DP, we would need to enumerate all possible sequences of games, which could be up to 2n-1 games long. The number of sequences grows exponentially, making brute force infeasible for large n.

Warning: This model only works when each game is independent with a fixed probability p! In real sports, factors like home-field advantage, player injuries, fatigue, momentum, and psychological pressure invalidate this assumption. Use this model only when the independence assumption holds. For example, in baseball, the home team wins about 54% of games, so games are not truly independent if the series alternates home-field advantage.

Connection to Probability Theory

The World Series problem is equivalent to computing the probability that A wins at least n games before B wins n games in a sequence of independent Bernoulli trials. This is related to the negative binomial distribution and the gambler's ruin problem. The DP approach provides an efficient way to compute this probability without having to sum over all possible game sequences.

Dynamic Programming Solution

The dynamic programming solution to the World Series problem is elegant and efficient. It breaks down the complex problem of computing series-winning probabilities into smaller, manageable subproblems. The key insight is that the probability of A winning from state (i,j) depends only on the probabilities from the two possible next states.

The Intuition Behind the Recurrence

Consider a moment in the series where A needs i wins and B needs j wins. The next game will be played, and one of two things can happen:

  • A wins the next game (probability p): The state transitions to (i-1,j). A now needs one fewer win to clinch the series.
  • B wins the next game (probability q): The state transitions to (i,j-1). B now needs one fewer win to clinch the series.

Since these are the only two possible outcomes, and they are mutually exclusive, we can use the law of total probability to write the recurrence. The probability of A winning from state (i,j) is the weighted average of the probabilities from the two possible next states, weighted by the probabilities of reaching those states.

Recurrence Relation

From state (i,j) where A needs i wins and B needs j wins, A can win the next game (probability p) moving to state (i-1,j), or lose (probability q) moving to state (i,j-1).

Recurrence (for i, j ≥ 1):
P(i,j) = p × P(i-1,j) + q × P(i,j-1)
p × P(i-1,j): A wins this game, needs 1 fewer win — multiplied by probability of winning from that new state
q × P(i,j-1): A loses this game, B needs 1 fewer win — multiplied by probability of winning from that new state

Why This Recurrence Works

The recurrence is based on the law of total probability. We condition on the outcome of the next game:

  • With probability p, A wins and we move to state (i-1,j). From there, the probability of A winning the series is P(i-1,j).
  • With probability q, B wins and we move to state (i,j-1). From there, the probability of A winning the series is P(i,j-1).

Since these are the only two possibilities, and they are mutually exclusive, the total probability is the sum of the two cases weighted by their probabilities. This is a direct application of conditional probability.

Computing P(i,j): Step by Step

To compute P(i,j), we need:

  1. P(i-1,j) — the probability when A needs one fewer win
  2. P(i,j-1) — the probability when B needs one fewer win

This means we need to compute smaller subproblems first. The natural order is to compute P(i,j) for increasing values of i+j (the total wins still needed by both teams).

Boundary Conditions (Base Cases):
P(0,j) = 1   for j ≥ 1   (A already has enough wins — series is over, A wins)
P(i,0) = 0   for i ≥ 1   (B already has enough wins — series is over, B wins)
P(0,0) is undefined (impossible state — both teams cannot have won simultaneously)
For all i ≥ 1 and j ≥ 1, compute using the recurrence. These base cases anchor the computation.

Why P(0,j) = 1 and P(i,0) = 0?

Let's think about this carefully:

  • P(0,j) = 1: If A needs 0 wins, A has already won the series. No matter what happens next (even if B wins all remaining games), A has already clinched the championship. So the probability of A winning is 1.
  • P(i,0) = 0: If B needs 0 wins, B has already won the series. A cannot win anymore because the series is over. So the probability of A winning is 0.

These base cases are absorbing states — once we reach them, the series is decided and no further games matter.

Algorithm: World Series DP (2D Version)

WORLD-SERIES(n, p):
  // n = wins needed to win the series
  // p = probability A wins a single game
  let P[0..n][0..n] be 2D array
  q = 1 - p
  // Initialize boundary conditions
  for i = 0 to n:
    P[i][0] = 0   // P(i,0) = 0 for all i (B has won)
  for j = 0 to n:
    P[0][j] = 1   // P(0,j) = 1 for all j (A has won)
  // Fill the DP table using the recurrence
  for i = 1 to n:
    for j = 1 to n:
      P[i][j] = p * P[i-1][j] + q * P[i][j-1]
  return P[n][n]

Understanding the Algorithm Execution

The algorithm works as follows:

  1. Initialization: Set up the boundary conditions. P[i][0] = 0 for all i (B wins if B needs 0 wins), and P[0][j] = 1 for all j (A wins if A needs 0 wins).
  2. Table Filling: Iterate through the table row by row (or column by column). For each cell (i,j) where i,j ≥ 1, compute P[i][j] using the recurrence.
  3. Order of Computation: We fill the table from top-left to bottom-right. This ensures that when we compute P[i][j], both P[i-1][j] and P[i][j-1] have already been computed.
  4. Result: P[n][n] contains the probability that A wins the series when both teams need n wins.

Space-Optimized Version (1D Array)

The 2D version uses O(n²) space. However, we can optimize this to O(n) space by observing that P(i,j) only depends on P(i-1,j) and P(i,j-1). When computing row i, we only need row i-1 (for P(i-1,j)) and the current row (for P(i,j-1)).

WORLD-SERIES-1D(n, p):
  // n = wins needed to win the series
  // p = probability A wins a single game
  let P[0..n] be 1D array
  q = 1 - p
  // Initialize: P[j] represents P(current_i, j)
  P[0] = 0  // P(i,0) = 0 for all i (B has won)
  for i = 1 to n: P[i] = 1  // P(0,j) = 1 for all j (A has won)
  // Fill the DP using 1D array
  for i = 1 to n:
    for j = 1 to n:
      // P[j] currently holds P(i-1, j) from previous iteration
      // P[j-1] holds P(i, j-1) from current iteration
      P[j] = p * P[j] + q * P[j-1]
  return P[n]

Why the 1D Optimization Works

In the 2D version, we have:

  • P[i][j] = p * P[i-1][j] + q * P[i][j-1]

When we process row i, we need:

  • P[i-1][j] — from the previous row (row i-1)
  • P[i][j-1] — from the current row (row i), already computed

If we use a 1D array and update it left to right:

  • Before updating P[j], it holds P[i-1][j] (from the previous iteration of the outer loop)
  • P[j-1] has already been updated to P[i][j-1] in the current iteration

So the update P[j] = p * P[j] + q * P[j-1] is equivalent to P[i][j] = p * P[i-1][j] + q * P[i][j-1].

Complexity Analysis

Time Complexity:
O(n²)
We fill an n × n table, with each cell requiring O(1) computation. The 2D version fills n² cells. The 1D version also does n² work (n iterations of outer loop, n iterations of inner loop). This is much better than the exponential time required by brute force.
Space Complexity:
O(n²) for 2D version, O(n) for 1D version
The 2D version stores the entire (n+1) × (n+1) table. The 1D version only stores a single row of n+1 elements. For large n, the 1D version is significantly more memory-efficient.

Understanding the Calculation: Row by Row

The DP table is filled row by row (or column by column). Each cell P(i,j) represents the probability of A winning the series starting from needing i wins while B needs j wins.

Key insight: P(i,j) is a weighted average of P(i-1,j) and P(i,j-1), weighted by p and q respectively. This means:

  • If p > 0.5 (A is stronger), P(i,j) tends to be larger than 0.5 when i is small relative to j
  • If p < 0.5 (B is stronger), P(i,j) tends to be smaller than 0.5 when i is small relative to j
  • If p = 0.5 (equal teams), P(i,j) is determined purely by the ratio of i to j

The Special Case: p = 0.5 (Equal Teams)

When p = 0.5 (equal teams), the recurrence simplifies to:

Equal Teams Formula:
P(i,j) = (P(i-1,j) + P(i,j-1)) / 2
Each state is the average of its two predecessor states. This creates a beautiful symmetry in the DP table.

When p = 0.5, the probability simplifies to P(i,j) = i / (i+j). This can be verified by induction. This formula has an elegant interpretation: the probability that A wins is proportional to the fraction of total wins still needed by A. If A needs i wins and B needs j wins, A's chance is i/(i+j).

This formula is intuitive: if A needs fewer wins than B (i < j), A has a better chance (P > 0.5). If A needs more wins (i > j), A has a worse chance (P < 0.5). If both need the same number (i = j), the chance is exactly 0.5.

Verification of the p = 0.5 Formula

Let's verify P(i,j) = i/(i+j) satisfies the recurrence:

  • P(i,j) = 0.5 * P(i-1,j) + 0.5 * P(i,j-1)
  • = 0.5 * (i-1)/(i-1+j) + 0.5 * i/(i+j-1)

We need to show this equals i/(i+j). This can be verified by algebra, confirming the formula is correct.

Anti-Symmetry Property (p = 0.5)

When p = 0.5, the DP table has a beautiful anti-symmetry property:

Anti-Symmetry:
P(i,j) + P(j,i) = 1   when p = 0.5
This makes sense: if A needs i wins and B needs j wins, then by symmetry, the probability that B wins (when B needs j and A needs i) is P(j,i). Since one of them must win, P(i,j) + P(j,i) = 1.

Also, when p = 0.5, P(i,i) = 0.5 for all i. Equal teams with equal wins needed have equal chances.

Step-by-Step Computation:

Step 1: Compute P(1,1)

P(1,1) = p × P(0,1) + q × P(1,0) = 0.6 × 1 + 0.4 × 0 = 0.6

Interpretation: When both teams need 1 win, A has a 60% chance of winning the next game and clinching the series. Since P(0,1)=1 (A wins if A gets that win) and P(1,0)=0 (A loses if B gets that win), the probability is simply p.

Step 2: Compute P(1,2)

P(1,2) = p × P(0,2) + q × P(1,1) = 0.6 × 1 + 0.4 × 0.6 = 0.6 + 0.24 = 0.84

Interpretation: A needs 1 win, B needs 2. A can win the next game (probability 0.6) and clinch immediately (P(0,2)=1), or lose (probability 0.4) and move to state (1,1) where A has 0.6 chance. So A's overall chance is 0.84.

Step 3: Compute P(2,1)

P(2,1) = p × P(1,1) + q × P(2,0) = 0.6 × 0.6 + 0.4 × 0 = 0.36

Interpretation: A needs 2 wins, B needs 1. A must win the next game (probability 0.6) to move to (1,1), then win from there (probability 0.6). If A loses (probability 0.4), B clinches (P(2,0)=0). So A's chance is 0.6 × 0.6 = 0.36.

Step 4: Compute P(2,2)

P(2,2) = p × P(1,2) + q × P(2,1) = 0.6 × 0.84 + 0.4 × 0.36 = 0.504 + 0.144 = 0.648

Interpretation: This is our final answer. When both teams need 2 wins, A has a 64.8% chance of winning the series. A's 60% per-game advantage compounds over the series.

A needs 3 wins, B needs 4. A is very likely to win.

Key Observations:

  • Longer series favor the stronger team: As n increases, P(n,n) approaches 1 for p > 0.5 and approaches 0 for p < 0.5.

  • Asymptotic behavior: As n → ∞, P(n,n) → 1 if p > 0.5, P(n,n) → 0 if p < 0.5, and P(n,n) → 0.5 if p = 0.5.

Example 5: Edge Case Analysis

Let's examine some edge cases to deepen understanding:

Edge Case 1: p = 1 (A always wins)

If p = 1 (A always wins every game), then P(i,j) = 1 for all i,j where i > 0. A will always win the series because A will eventually get the wins needed.

Verification: P(i,j) = 1 × P(i-1,j) + 0 × P(i,j-1) = P(i-1,j). Since P(0,j) = 1, this means P(i,j) = 1 for all i,j.

Edge Case 2: p = 0 (B always wins)

If p = 0 (B always wins every game), then P(i,j) = 0 for all i,j where j > 0. B will always win the series.

Verification: P(i,j) = 0 × P(i-1,j) + 1 × P(i,j-1) = P(i,j-1). Since P(i,0) = 0, this means P(i,j) = 0 for all i,j.

Edge Case 3: n = 1 (Single game)

If n = 1 (first to 1 wins, i.e., a single game), then P(1,1) = p. This makes sense: A wins with probability p.

Verification: P(1,1) = p × P(0,1) + q × P(1,0) = p × 1 + q × 0 = p.

Edge Case 4: One team very close to winning

If A needs 1 win and B needs 100 wins, P(1,100) ≈ 1. A is almost certain to win because A needs just one more win while B needs 100.

Similarly, if A needs 100 wins and B needs 1 win, P(100,1) ≈ 0. B is almost certain to win.

Exam Tips and Key Observations:

1. Boundary Conditions: Always start by setting P(0,j) = 1 and P(i,0) = 0. These are the foundation of the recurrence.

2. Anti-Symmetry (p = 0.5): When p = 0.5, P(i,j) + P(j,i) = 1. This is a powerful check for your calculations.

3. Diagonal Property (p = 0.5): When p = 0.5, P(i,i) = 0.5 for all i.

4. The DP is essentially computing a weighted sum over all possible game sequences. Each path from (n,n) to a boundary state has a probability, and P(n,n) is the sum of probabilities of all paths that end at P(0,j) states.

5. For large n, the table grows as O(n²), but only half needs to be computed (by symmetry when p = 0.5).

6. The problem demonstrates optimal substructure: the probability from state (i,j) depends only on states one win away.

7. Memory optimization: since we only need the previous row, a 1D array suffices. This reduces space from O(n²) to O(n).

8. Common mistakes:
• Confusing P(i,j) with P(j,i) — remember i is wins A needs, j is wins B needs
• Forgetting to set boundary conditions before filling the table
• Mixing up the recurrence: it's P(i,j) = p × P(i-1,j) + q × P(i,j-1), NOT p × P(i,j-1) + q × P(i-1,j)
• Assuming P(i,j) = i/(i+j) for all p — this formula only works when p = 0.5

9. Time complexity: O(n²) — we fill an n × n table with O(1) work per cell.

10. Space complexity: O(n²) for 2D version, O(n) for 1D version.

11. The answer is always P(n,n) for a "best-of-(2n-1)" series where n wins are needed.

12. When p > 0.5, longer series favor the stronger team. This is why the World Series is best-of-7 (n=4) — it reduces the chance of an upset.
