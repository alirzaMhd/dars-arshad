0-1 Knapsack Problem

Dynamic Programming — Algorithm Design (Hadi Yousefi)

Problem Definition

Given a set of n items, each with a weight wi and a profit pi, and a knapsack with capacity M, select a subset of items such that the total weight does not exceed M and the total profit is maximized.

Constraint:
max Σ pixi   subject to   Σ wixi ≤ M   where xi ∈ {0,1}
Each item can be taken at most once (0-1 decision).
⚠ Greedy fails for 0-1 Knapsack! Example: w=[5,10,20], p=[50,60,140], M=30. Greedy by value/weight picks items 1 and 2 (value=110), but optimal is item 3 alone (value=140).

Why Greedy Fails

The greedy strategy (take highest value/weight ratio) fails because the 0-1 constraint means we cannot take fractions of items. A seemingly "efficient" item may block the space for a combination of other items that yields higher total profit.

Input

• n items with (wi, pi) pairs

• Knapsack capacity M

Output

• Maximum total profit

• Selected items (backtracking)

Brute Force

• 2n subsets to check

• Impractical for large n

Dynamic Programming Solution

Recurrence Relation

Define c[i][m] = maximum profit achievable using items 1..i with capacity m.

Base Case:
c[0][m] = 0   and   c[i][0] = 0   ∀ i, m
No items or zero capacity yields zero profit.
Item i cannot fit:
c[i][m] = c[i-1][m]   if wi > m
Current item weight exceeds remaining capacity, skip it.
Item i can fit (choose max):
c[i][m] = max( c[i-1][m] , pi + c[i-1][m-wi] )   if wi ≤ m
Either skip item i or take it and add its profit.
Final Answer:
c[n][M]
Maximum profit for all n items with full capacity M.

Principle of Optimality

The 0-1 Knapsack problem satisfies the principle of optimality: an optimal solution to the full problem contains within it optimal solutions to subproblems. If item i is selected in the optimal solution, the remaining capacity M - wi must be optimally filled with items 1..i-1.

Algorithm: 0-1 Knapsack DP

01-KNAPSACK(w, p, n, M) let c[0..n][0..M] be a new table for m ← 0 to M c[0][m] ← 0 for i ← 1 to n c[i][0] ← 0 for m ← 1 to M if w[i] > m c[i][m] ← c[i-1][m] else c[i][m] ← max(c[i-1][m], p[i] + c[i-1][m-w[i]]) return c[n][M]

Algorithm: Backtracking to Find Selected Items

FIND-ITEMS(c, w, n, M) m ← M for i ← n down to 1 if c[i][m] ≠ c[i-1][m] print "Item", i, "selected" m ← m - w[i]

Backtracking:

c[4][10]=50 ≠ c[3][10]=44 → pick item 4, m=10-2=8

Selected items: {2,3,4}. Weight = 3+4+2=9. Profit = 14+20+8=42. Wait — c[4][10]=50 but our backtracking gives 42? Let me verify the table...

Correction: The correct optimal is items {1,4}: weight 6+2=8, profit 30+8=38, OR items {2,3,4}: weight 3+4+2=9, profit 42. Let's verify c[3][8]: with items 1-3, capacity 8, max profit is 34 (item 1+3? 6+4=10>8... item 1 alone=30, item 2+3=34). So c[4][10] = max(c[3][10]=44, 8+c[3][8]=8+34=42) = 44. So answer is 44, selected items = {2,3}.

Example 4: Edge Case — All Items Exceed Capacity

Items: w=[15,20,25], p=[100,200,300], M=10

Every item's weight exceeds M=10. The DP table will show:

c[i][m]01-10

i=1 (w=15)00

This counterintuitive result shows the 0-1 constraint is strict — partial items are not allowed, unlike fractional knapsack.

Complexity Analysis

Time Complexity

O(nM)

Filling the n×M table with constant work per cell.

Space Complexity

O(nM)

Can be reduced to O(M) by keeping only previous row.

Pseudo-Polynomial

O(nM) is not polynomial in input size because M is a number, not the bit-length. True polynomial time is unlikely (NP-complete).

Optimizations & Advanced Topics

Space Optimization

The DP table c[n×M] can be reduced to O(M) by storing only the previous row, since c[i][*] only depends on c[i-1][*].

Space-Optimized Recurrence:
c'[m] = max(c'[m], p[i] + c'[m - w[i]]) for m = M down to w[i]
Iterate m backwards to avoid reusing the same item multiple times.
Optimization: Backtracking with O(nM) → O(n + M)

Idea: Instead of storing the full c table, store only:

• The last row of c (size M)

• A boolean choice table of size n×M indicating if item i was selected at capacity m

This gives O(min(n², nM)) time using branch-and-bound techniques, though the theoretical bound remains pseudo-polynomial.

Algorithm Variations

• Standard DP: O(nM) time, O(nM) space

• Space-optimized: O(nM) time, O(M) space

• Meet-in-the-Middle: O(n·2^(n/2)) for small n, large M

• Branch & Bound: Practical for moderate n

When to Use Each

• n ≤ 100, M ≤ 10⁵: Standard DP

• n ≤ 40, M huge: Meet-in-the-Middle

• n ≤ 1000, M ≤ 10⁴: Space-optimized DP
