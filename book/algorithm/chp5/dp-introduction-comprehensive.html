What is Dynamic Programming?

Dynamic Programming (DP) is a powerful algorithmic paradigm that solves complex problems by breaking them into overlapping subproblems and storing their results to avoid redundant computation. It is applicable when a problem exhibits optimal substructure and overlapping subproblems.

Core Idea
Optimal Solution = Optimal Solutions of Subproblems + Combination Rule
DP builds solutions bottom-up from the smallest subproblems, storing each result exactly once.

DP vs Divide & Conquer

Divide & Conquer

• Partition into independent subproblems

• Solve recursively

• Combine results

• No overlapping subproblems

• E.g., Merge Sort, Quick Sort

Dynamic Programming

• Partition into overlapping subproblems

• Solve each once, store results

• Combine from stored values

• Memoization or tabulation

• E.g., Fibonacci, Matrix Chain

Two Approaches

Top-Down (Memoization)

• Start from the original problem

• Recursively break into subproblems

• Cache results in a table

• Only solves needed subproblems

• Recursive + storage

Bottom-Up (Tabulation)

• Start from smallest subproblems

• Build solution iteratively

• Fill table in increasing order

• Solves all subproblems up to n

• Iterative + array

Properties for DP Applicability

PropertyDescription
Optimal SubstructureOptimal solution contains optimal solutions to subproblems
Overlapping SubproblemsSame subproblems appear multiple times
Principle of OptimalityDecision at each stage depends only on current state, not on how it was reached
Warning: Not all problems with optimal substructure are good DP candidates. The subproblems must overlap significantly for DP to be beneficial over divide and conquer.

The Principle of Optimality

The Principle of Optimality, formulated by Richard Bellman, states: "An optimal policy has the property that whatever the initial state and decisions are, the remaining decisions must constitute an optimal policy with regard to the state resulting from the first decision."

Definition
If P is an optimal path from A to C, then any sub-path of P (from A to B or B to C) must also be optimal.
This property must hold for DP to be applicable.

Example: Shortest Path (Principle Holds)

Shortest Path Problem

Consider a directed graph with vertices A, B, C, D, E. Suppose the shortest path from A to E is A→B→D→E with total cost 12.

By the Principle of Optimality, any subpath must also be optimal:

• A→B→D must be the shortest path from A to D

• B→D→E must be the shortest path from B to E

Proof via cut-and-paste: If a shorter path from A to D existed, we could replace A→B→D with it and get a shorter A→E path — contradiction.

Result: Principle holds → DP works for shortest paths.

Example: Longest Path (Principle Fails)

Longest Simple Path Problem

Consider a graph where the longest simple path from A to D is A→B→C→D with length 10. However, the subpath A→B→C may NOT be the longest path from A to C.

Why? Because the longest A→C path might visit D, which then cannot be used in the remaining path C→D (simple path constraint).

Result: Principle fails → DP does not work for longest simple paths.

Key Insight: The Principle of Optimality holds for problems where the objective function is additive and subproblems are independent of future decisions.

Formal Condition

The Principle of Optimality holds when the optimal solution can be defined recursively as:

opt(x) = min/max { cost(decision) + opt(next_state) }

where opt(next_state) depends only on the state, not on the sequence of decisions that led to it.

Worked Examples

Example 1: Solving T(n) = T(n-1) + 3, T(1) = 2

Problem: Solve the recurrence T(n) = T(n-1) + 3 with base case T(1) = 2 using both top-down and bottom-up DP.

Recurrence: T(n) = T(n-1) + 3, T(1) = 2

Top-Down (Memoization):

function solveTD(n, memo): if n == 1: return 2 if memo[n] exists: return memo[n] memo[n] = solveTD(n-1, memo) + 3 return memo[n]

Bottom-Up (Tabulation):

function solveBU(n): dp[1] = 2 for i = 2 to n: dp[i] = dp[i-1] + 3 return dp[n]

Trace for n = 5:

i12345
dp[i]2581114

Result: T(5) = 14. Closed form: T(n) = 3n - 1

Example 2: Solving T(n) = T(n-1) + n, T(0) = 0

Problem: Solve T(n) = T(n-1) + n with base case T(0) = 0 using DP approach.

Recurrence: T(n) = T(n-1) + n, T(0) = 0

Bottom-Up DP:

function sumDP(n): dp[0] = 0 for i = 1 to n: dp[i] = dp[i-1] + i return dp[n]

Trace for n = 6:

i0123456
dp[i]0136101521

Result: T(6) = 21. Closed form: T(n) = n(n+1)/2

Example 3: Principle of Optimality — Holds vs Fails

Scenario: Consider a city grid from (0,0) to (m,n). Moving only right or down, find the minimum-cost path.

Why Principle holds: Any subpath of the optimal path must be optimal for its endpoints. If an optimal path from (0,0) to (2,2) goes through (1,1), then the (0,0)→(1,1) segment must be the optimal path to (1,1).

DP Recurrence:

Grid Path DP
dp[i][j] = cost[i][j] + min(dp[i-1][j], dp[i][j-1])
Minimum cost to reach (i,j) from (0,0) moving only right or down.

Counterexample where Principle fails:

In a graph with negative cycles, the shortest path problem violates the Principle because you could loop around the negative cycle to arbitrarily reduce the cost. The optimal path is ill-defined (unbounded below).

Key takeaway: Always verify no negative cycles exist before applying DP to shortest paths.

Complexity Summary

Time: Varies by problem

Space: Trades space for time

Key insight: DP reduces exponential → polynomial

When to Use DP

• Problem can be divided into overlapping subproblems

• Optimal substructure exists

• Principle of Optimality holds

• Brute force is exponential

Important: DP is not always the best approach. If subproblems don't overlap significantly, divide and conquer or greedy algorithms may be more efficient.
