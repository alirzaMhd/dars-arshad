Tree Sort Algorithm

A sorting algorithm that uses a Binary Search Tree (BST). First inserts all elements into a BST, then performs an inorder traversal to get sorted output.

treesort(A[1..n]) { // Step 1: Build BST root = null; for (i = 1 to n) insert(root, A[i]); // Step 2: Inorder traversal inorder(root); }
Key Insight:
Inorder traversal of BST gives sorted order
Left subtree → Root → Right subtree
Important: The time complexity depends on the shape of the BST. For a balanced BST, it's O(n lg n). For an unbalanced BST, it degrades to O(n²).

BST Insert and Inorder

Insert Operation

insert(root, key) { if (root == null) return new Node(key); if (key < root.key) root.left = insert(root.left, key); else if (key > root.key) root.right = insert(root.right, key); // Ignore duplicates return root; }

Inorder Traversal

inorder(node) { if (node ≠ null) { inorder(node.left); print(node.key); inorder(node.right); } }
Insert Time (per element):
O(h) where h = height of tree
h = lg n for balanced, h = n for unbalanced
Inorder Traversal:
Θ(n)
Visits each node exactly once

Worked Examples

Example 1: Sort [5, 3, 7, 1, 4]

Step 1: Build BST

Insert 5: root = 5

Insert 3: 3 < 5, go left → 3 is left child of 5

Insert 7: 7 > 5, go right → 7 is right child of 5

Insert 1: 1 < 5, go left; 1 < 3, go left → 1 is left child of 3

Insert 4: 4 < 5, go left; 4 > 3, go right → 4 is right child of 3

BST Structure:

    5
   /  \
  3    7
 / \
1   4

Step 2: Inorder traversal → 1, 3, 4, 5, 7

Result: [1, 3, 4, 5, 7]

Example 2: Worst Case - Sorted Input

Insert [1, 2, 3, 4, 5] into BST

This creates a degenerate tree (linked list): 1 → 2 → 3 → 4 → 5

Height h = n = 5

Total insert time: 0 + 1 + 2 + 3 + 4 = 10 = n(n-1)/2

This is Θ(n²)

Example 3: Best Case - Balanced Input

Insert [3, 1, 5, 2, 4] into BST

Creates a balanced tree with height ≈ lg n

Each insert takes O(lg n), Total: O(n lg n)

Example 4: Using AVL Tree

Instead of plain BST, use a self-balancing AVL tree.

Guarantees height = O(lg n) after each insert.

Total time: O(n lg n) always!

Example 5: Degenerate BST on Sorted Input

Insert [1, 2, 3, 4, 5] in sorted order:

1
 \
  2
   \
    3
     \
      4
       \
        5

Height h = n = 5

Insert costs: 0 + 1 + 2 + 3 + 4 = 10 = n(n-1)/2

Total time: O(n²)

Time Complexity Analysis

Build BST (n inserts):
O(n × h)
h = height of the resulting tree
Inorder Traversal:
Θ(n)
Always linear - visits each node once
Best Case (Balanced Tree):
O(n lg n)
h = lg n, total insert time = O(n lg n)
Worst Case (Degenerate Tree):
O(n²)
h = n, total insert time = O(n²)

Best Case

Time: O(n lg n)

Balanced BST (use AVL)

Average Case

Time: O(n lg n)

Random insertions create roughly balanced tree

Worst Case

Time: O(n²)

Already sorted input

Space

Space: O(n)

Needs space for tree nodes

Properties of Tree Sort

Stable

No

BST insertion doesn't guarantee relative order of equal keys

In-Place

No

Requires O(n) space for tree nodes

Adaptive

No

Performance depends on input order

Online

Yes

Can sort elements as they arrive

Using AVL Tree:

If we use an AVL tree instead of a plain BST:

• Height is always O(lg n)

• Insert is always O(lg n)

• Total time is always O(n lg n)

• But space is still O(n)
