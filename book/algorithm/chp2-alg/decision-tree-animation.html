What is a Decision Tree?

A decision tree is a binary tree that models a comparison-based sorting algorithm. Each internal node represents a comparison, each leaf represents a sorted output.

Internal Nodes

Comparisons: "Is A[i] ≤ A[j]?"

Left: Yes | Right: No

Leaf Nodes

Possible outcomes (sorted permutations)

Each leaf is a unique sorted arrangement

Number of Leaves:
n! (for sorting n distinct elements)
Each permutation is a possible sorted output

Decision Tree Properties

Internal Nodes

Each = a comparison

Leaves

Each = a sorted permutation

Root→Leaf Path

One complete execution

Height h

Worst-case comparisons

Height for Sorting n Distinct Elements:
h ≥ ⌈lg(n!)⌉
Any comparison-based sort needs at least ⌈lg(n!)⌉ comparisons worst-case

Proving the Ω(n lg n) Lower Bound

Step 1: Count the Leaves

Number of leaves:
L ≥ n!

Step 2: Relate Height to Leaves

For a binary tree:
h ≥ ⌈lg L⌉

Step 3: Combine

Minimum height:
h ≥ ⌈lg(n!)⌉

Step 4: Use Stirling's Approximation

Stirling's Approximation:
lg(n!) = n lg n - n lg e + O(lg n)
Result:
h ≥ n lg n - O(n) = Ω(n lg n)
Any comparison-based sort requires Ω(n lg n) comparisons worst-case
Conclusion: No comparison-based sorting algorithm can beat Ω(n lg n) in the worst case. This is a fundamental lower bound!

Worked Examples

Decision Tree for Sorting 3 Elements [a, b, c]
Root: Compare a vs b │ ├─ a ≤ b: │ └─ Compare b vs c │ ├─ b ≤ c: [a, b, c] │ └─ b > c: │ └─ Compare a vs c → [a, c, b] or [c, a, b] │ └─ a > b: └─ Compare a vs c ├─ a ≤ c: [b, a, c] └─ a > c: └─ Compare b vs c → [b, c, a] or [c, b, a]

Leaves = 6 = 3! Height h = 3 = ⌈lg 6⌉ = 3

Minimum worst-case comparisons: 3

Lower Bound for n=4

n! = 24 leaves. h ≥ ⌈lg 24⌉ = ⌈4.58⌉ = 5

Merging Two Sorted Lists

L1=[x1,x2,x3] (3), L2=[y1,y2,y3,y4] (4)

7! total permutations, but internal order preserved: 7!/(3!·4!) = 35 leaves

Height: ⌈lg 35⌉ = 6 = m + n − 1 comparisons

n = 1000

Lower bound: ⌈lg(1000!)⌉ ≈ 8530 comparisons

Merge Sort: ≈ 10000 comparisons — within constant factor of optimal!

Applications of Decision Trees

1. Proving Lower Bounds

Decision trees provide a framework for proving that no algorithm can beat a certain bound.

2. Analyzing Sorting Algorithms

Any comparison-based sort can be visualized as a decision tree.

3. Optimizing Algorithms

Understanding the decision tree helps design algorithms that approach the lower bound.

Sorting

Bound: Ω(n lg n)

Optimal: Merge/Heap Sort

Finding Minimum

Bound: n - 1

Optimal: Linear scan

Min and Max

Bound: ⌈3n/2⌉ - 2

Optimal: Pairwise

Important: Decision tree model only applies to comparison-based sorts. Non-comparison sorts (Counting, Radix, Bucket) can be faster!

Problem Setup

For sorting n=3 elements [a, b, c], any comparison-based sorting algorithm can be modeled as a decision tree.

Each internal node compares two elements. Each leaf represents a sorted permutation.

There are 3! = 6 possible permutations → at least 6 leaves needed.

Tree height h satisfies: 2h ≥ 6 → h ≥ ⌈log₂ 6⌉ = 3

Ω(log n!) = Ω(n log n)
