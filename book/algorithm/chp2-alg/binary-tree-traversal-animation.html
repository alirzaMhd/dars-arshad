What is a Binary Tree?

A binary tree is a rooted tree where every node has at most 2 children, called the left child and right child. The left and right children are distinguished — they are NOT interchangeable.

⚠ Key distinction: A binary tree is NOT the same as a general tree. In a binary tree, order matters — left child ≠ right child even if they contain the same data.
a ← Root / \ b c ← b is left child, c is right child / \ \ d e f ← d is left child of b, e is right child of b ← f is right child of c (no left child)

Formal Definition

A binary tree is either:

1. Empty (null/nil), or

2. A node with a left subtree (binary tree) and a right subtree (binary tree)

Recursive Definition:
BinaryTree = ∅ | Node(Data, BinaryTree, BinaryTree)
A binary tree is either empty or a node containing data and two binary tree subtrees.

Number of Possible Binary Trees

Unlabeled Binary Trees (Structural):
Catalan(n) = C(2n, n) / (n+1) = (2n)! / ((n+1)! · n!)
The number of structurally different binary trees with n nodes.
Labeled Binary Trees:
n! × Catalan(n)
The number of binary trees with n distinct keys (labeled nodes).
Example: Binary Trees with 3 Nodes

Catalan(3) = 5 structural forms.

If nodes are labeled {a, b, c}, there are 3! × 5 = 30 different trees.

Special Types of Binary Trees

Full Binary Tree

A binary tree where every internal node has exactly 2 children.

a ← Full: both children present / \ b c ← b: 2 children, c: leaf / \ d e ← d,e: both leaves
Full Binary Tree:
n₀ = n₂ + 1 (leaves = 2-children + 1)
Total nodes = 2·n₂ + 1 (always odd).

Complete Binary Tree

All levels are completely filled except possibly the last level, which is filled from left to right.

a ← Complete: levels 0,1 full / \ b c ← Level 1 full / \ / \ d e f g ← Level 2 full
Height Formula:
Height = ⌊log₂(n)⌋
Number of levels = ⌊log₂(n)⌋ + 1.

Perfect Binary Tree

A binary tree that is both full and complete. All levels are completely filled.

a / \ b c / \ / \ d e f g

Skewed Binary Tree

Every node has only one child — worst case for operations.

Left-Skewed

a \ b \ c \ d

Right-Skewed

d / c / b / a
⚠ For a skewed tree with n nodes: height = n - 1 (maximum possible) — essentially a linked list!

Array Representation of Binary Trees

Binary trees (especially complete binary trees) can be efficiently stored in an array using level-order indexing.

Index Formulas (1-based indexing):
Parent(i) = ⌊i/2⌋
LeftChild(i) = 2i (if 2i ≤ n)
RightChild(i) = 2i + 1 (if 2i + 1 ≤ n)
For a node at index i: parent at ⌊i/2⌋, left child at 2i, right child at 2i+1.
Example: Complete Binary Tree → Array

Tree

a(1) / \ b(2) c(3) / \ / d(4)e(5)f(6)

Array

Idx123456
Valabcdef

Parent(4)=⌊4/2⌋=2 → d's parent is b ✓

LeftChild(2)=2×2=4 → b's left child is d ✓

Array Size Requirements:
Complete tree with n nodes: size = n
Skewed tree with n nodes: size = 2^n - 1
⚠ Array representation is efficient ONLY for COMPLETE binary trees. For skewed trees, it wastes exponential space!
Example: Skewed Tree Array Size

A left-skewed tree with n=4 nodes:

a(1) \ b(3) \ c(7) \ d(15)

Array size: 15 (2^4 - 1). Only 4 of 15 positions used → 73% wasted!

Linked Representation of Binary Trees

The most common representation: each node has three fields — data, left pointer, and right pointer.

Node Structure (C/C++):
struct node { int data; struct node *left; struct node *right; };
Memory Usage:
n nodes → n × (data_size + 2 × pointer_size)
For 4-byte int and 8-byte pointers: n × (4 + 16) = 20n bytes.

Worked Examples

Example 1: Counting Structural Trees

How many structurally different binary trees with 4 nodes?

Solution: Catalan(4) = C(8,4)/5 = 70/5 = 14

Labeled: 4! × 14 = 24 × 14 = 336

Example 2: Null Pointer Derivation

Why does a tree with n nodes have exactly n+1 null pointers?

Total pointers = 2n. Non-null = n-1. Null = 2n - (n-1) = n + 1

Example 3: Complete Tree Height

A complete binary tree has 1000 nodes. What is its height?

Height = ⌊log₂(1000)⌋ = 9 (since 2⁹=512, 2¹⁰=1024)

Height = 9, so 10 levels needed

Example 4: Finding Missing Nodes from Array

Given array [_, A, B, _, C, _, D], reconstruct the tree.

A / B \ C \ D

Index 1: A (root), 2: B, 3: _ (no right child), 5: C, 7: D
