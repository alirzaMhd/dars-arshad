Counting Sort Algorithm

A non-comparison based sorting algorithm that counts occurrences of each distinct element. Works for integers in a known range [1..k].

countingsort(A[1..n], k) { B[1..n], C[1..k]; // Loop 1: Initialize count array (Θ(k)) for (i = 1 to k) C[i] = 0; // Loop 2: Count frequencies (Θ(n)) for (i = 1 to n) C[A[i]] = C[A[i]] + 1; // Loop 3: Cumulative sum (Θ(k)) for (i = 2 to k) C[i] = C[i] + C[i-1]; // Loop 4: Place elements (scan right-to-left for stability) (Θ(n)) for (i = n downto 1) { B[C[A[i]]] = A[i]; C[A[i]] = C[A[i]] - 1; } }
Key Insight:
C[i] = number of elements ≤ i in A
After cumulative sum, C[x] gives the position of x in sorted output

How Counting Sort Works — 4 Loops

Counting sort uses 4 sequential loops (no nested loops), each with a distinct purpose:

Loop 1: Initialize Count Array (Θ(k))

Set all entries of the count array C[1..k] to zero.

Loop 2: Count Occurrences (Θ(n))

Count how many times each element appears in the input array. After this loop: C[i] = frequency of element i in A.

Loop 3: Cumulative Sum (Θ(k))

Convert frequencies to cumulative sums: C[i] = C[i] + C[i-1]. After: C[i] = number of elements ≤ i in A.

Loop 4: Place Elements (Θ(n))

Scan input array from right to left. For each element A[i], place it at position C[A[i]] in output B, then decrement C[A[i]]. Scanning right-to-left ensures stability.

Why scan from right to left? Scanning right-to-left ensures stability. Since C[x] gives the position of the last occurrence of x in the output, processing from right to left places later occurrences at higher positions first, preserving original relative order of equal elements.
Stability Property:
Counting Sort is stable
Equal elements maintain their original relative order

Worked Examples

Example 1: Sort A = [4, 1, 4, 3, 4, 3], n = 6, k = 4

Loop 2: Count frequencies

C = [-, 1, 0, 2, 3] (indices 1..4)

Loop 3: Cumulative sum

C = [-, 1, 1, 3, 6]

Loop 4: Place elements (right to left)

i=6: A[6]=3, B[C[3]]=B[3]=3, C[3]=2

i=5: A[5]=4, B[C[4]]=B[6]=4, C[4]=5

i=4: A[4]=3, B[C[3]]=B[2]=3, C[3]=1

i=3: A[3]=4, B[C[4]]=B[5]=4, C[4]=4

i=2: A[2]=1, B[C[1]]=B[1]=1, C[1]=0

i=1: A[1]=4, B[C[4]]=B[4]=4, C[4]=3

Result: B = [1, 3, 3, 4, 4, 4]

Example 2: Sort A = [2, 5, 3, 1, 4], k = 5

Count: C = [0, 1, 1, 1, 1, 1]

Cumulative: C = [0, 1, 2, 3, 4, 5]

Place (right to left): B = [1, 2, 3, 4, 5]

Result: [1, 2, 3, 4, 5]

Example 3: Counting Sort with Duplicates

A = [1, 2, 2, 1, 3, 1], k = 3

Count: C[1]=3, C[2]=2, C[3]=1

Cumulative: C[1]=3, C[2]=5, C[3]=6

Place (right to left) preserves stability. Result: [1, 1, 1, 2, 2, 3]

Example 4: When k is Large

A = [100, 200, 150, 50], k = 200

Need array C of size 200 even though n = 4. Wasteful when k >> n. Better to use Radix Sort.

When is Counting Sort efficient? When k = O(n), i.e., the range is not much larger than the number of elements. If k >> n, use Radix Sort instead.
