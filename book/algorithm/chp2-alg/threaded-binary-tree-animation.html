Why Threaded Binary Trees?

In a standard binary tree with n nodes, there are n+1 NULL pointers (wasted space). A threaded binary tree replaces these NULL pointers with threads — pointers to the inorder predecessor or successor.

Pointer Count:
Total pointers: 2n
Non-NULL pointers: n - 1
NULL pointers: n + 1
These n+1 NULL pointers are wasted space. Threaded trees reuse them!
Thread Definition:
A thread links a node to its inorder predecessor or successor
Instead of NULL, store a reference to the next/previous node in inorder.
⚠ Threaded binary trees allow O(1) inorder traversal without a stack or recursion — just follow the threads!

Benefits

✓ Advantages

• No stack needed

• No recursion overhead

• Faster inorder traversal

• Better cache perf

✗ Disadvantages

• More complex nodes

• Harder insert/delete

• Only for inorder

Node Structure

Each node has two boolean flags (Lthread and Rthread) to distinguish between normal pointers and threads.

Node Definition (C/C++):
struct Node { bool Lthread; Node* Lchild; int data; Node* Rchild; bool Rthread; };

Thread Rules

FlagValueMeaning
LthreadtrueLchild → inorder PREDECESSOR
LthreadfalseLchild → left child (normal)
RthreadtrueRchild → inorder SUCCESSOR
RthreadfalseRchild → right child (normal)
Example (inorder: d b g e h a c f): a / \ [d]←b→[g] [c]←→[f] / \ / \ d e nil f [nil] [h] [nil] | h
First inorder node (leftmost) has Lthread=true → dummy. Last node has Rthread=true → dummy.

Inorder Traversal with Threads

Key advantage: no stack needed. Just follow threads to find the next node.

// Find inorder successor function insucc(t): temp := t.Rchild if (t.Rthread != TRUE) while (temp.Lthread != TRUE) temp := temp.Lchild return temp // Full inorder traversal procedure inorder(root): t := root while (t.Lthread != TRUE) // find leftmost t := t.Lchild while (t != NIL) visit(t) t := insucc(t)
Complexity:
Time: O(n), Space: O(1)
Each node visited once. No stack needed!
Trace: Inorder Traversal

For threaded tree with inorder: d b g e h a c f

1. Start at root 'a', go left to 'b', then left to 'd' (leftmost)

2. Visit 'd' → Rthread → 'b'

3. Visit 'b' → go right to 'e', then left to 'g'

4. Visit 'g' → Rthread → 'e'

5. Visit 'e' → Rthread → 'h'

6. Visit 'h' → Rthread → 'a'

7. Visit 'a' → go right to 'c'

8. Visit 'c' → Rthread → 'f'

9. Visit 'f' → Rthread → NIL (end)

Preorder and Postorder Threading

Threading works for any traversal order using the same principle.

Inorder Threading

Lthread → inorder predecessor

Rthread → inorder successor

Traversal: LDR

Preorder Threading

Lthread → preorder predecessor

Rthread → preorder successor

Traversal: DLR

Postorder Threading

Lthread → postorder predecessor

Rthread → postorder successor

Traversal: LRD

How to Thread a Binary Tree

Algorithm: 1. Perform inorder traversal 2. For each node with NULL left pointer: - Set Lthread = true, Lchild = inorder predecessor 3. For each node with NULL right pointer: - Set Rthread = true, Rchild = inorder successor
Threading Example
Original (inorder: d b e a c): a / \ b c / d \ e Step 1: Inorder = d, b, e, a, c Step 2: Thread NULL pointers: d.left → dummy, d.right → b e.left → b, e.right → a c.left → a, c.right → dummy

Threading Algorithm (C/C++)

void inorderThread(Node* node, Node** prev) { if (!node) return; inorderThread(node->left, prev); if (!node->left) { node->Lthread = true; node->Lchild = *prev; } if (*prev && !(*prev)->right) { (*prev)->Rthread = true; (*prev)->Rchild = node; } *prev = node; inorderThread(node->right, prev); }
