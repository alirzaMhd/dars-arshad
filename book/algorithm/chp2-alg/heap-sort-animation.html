Heap Sort Algorithm

A comparison-based sorting algorithm that uses a binary heap data structure. It first builds a max heap from the input, then repeatedly extracts the maximum element.

heapsort(A[1..n]) { // Step 1: Build max heap for (i = ⌊n/2⌋ downto 1) maxheapify(A, i, n); // Step 2: Extract elements for (i = n downto 2) { swap(A[1], A[i]); maxheapify(A, 1, i-1); } }
Max Heap Property:
A[parent(i)] ≥ A[i]
Parent node is always greater than or equal to its children
Array Representation:
parent(i) = ⌊i/2⌋, left(i) = 2i, right(i) = 2i+1
For node at index i (1-based indexing)

Heap Operations

Max Heapify Operation

Maintains the max heap property for a subtree rooted at index i.

maxheapify(A, i, n) { left = 2*i; right = 2*i + 1; largest = i; if (left ≤ n and A[left] > A[i]) largest = left; if (right ≤ n and A[right] > A[largest]) largest = right; if (largest ≠ i) { swap(A[i], A[largest]); maxheapify(A, largest, n); } }

Build Max Heap

Converts an arbitrary array into a max heap by calling maxheapify from the bottom up.

Time to Build Heap:
O(n)
Linear time - not O(n lg n) as one might expect!
Key Insight: Building a heap is O(n) because most nodes are near the bottom of the tree and require little work. The sum converges to a linear function.

Worked Examples

Example 1: Sort A = [4, 10, 3, 5, 1]

Step 1: Build max heap

Array: [4, 10, 3, 5, 1]

Start from i = ⌊5/2⌋ = 2

maxheapify(A, 2): A[2]=10, children are A[4]=5 and A[5]=1. 10 is largest, no swap.

maxheapify(A, 1): A[1]=4, children are A[2]=10 and A[3]=3. 10 > 4, swap → [10, 4, 3, 5, 1]

maxheapify(A, 2): A[2]=4, children are A[4]=5 and A[5]=1. 5 > 4, swap → [10, 5, 3, 4, 1]

Max heap: [10, 5, 3, 4, 1]

Step 2: Extract elements

swap A[1] and A[5]: [1, 5, 3, 4, 10]

maxheapify(A, 1, 4): [5, 4, 3, 1, 10]

swap A[1] and A[4]: [1, 4, 3, 5, 10]

maxheapify(A, 1, 3): [4, 1, 3, 5, 10]

swap A[1] and A[3]: [3, 1, 4, 5, 10]

maxheapify(A, 1, 2): [3, 1, 4, 5, 10]

swap A[1] and A[2]: [1, 3, 4, 5, 10]

Result: [1, 3, 4, 5, 10]

Example 2: Build Heap from [3, 1, 6, 5, 2, 4]

n = 6, start from i = 3

i=3: A[3]=6, children A[6]=4. 6 > 4, no swap.

i=2: A[2]=1, children A[4]=5 and A[5]=2. 5 > 1, swap → [3, 5, 6, 1, 2, 4]

i=1: A[1]=3, children A[2]=5 and A[3]=6. 6 > 3, swap → [6, 5, 3, 1, 2, 4]

maxheapify(A, 3): A[3]=3, child A[6]=4. 4 > 3, swap → [6, 5, 4, 1, 2, 3]

Max heap: [6, 5, 4, 1, 2, 3]

Example 3: All Elements Equal

A = [5, 5, 5, 5, 5]

Build heap: no swaps needed (property already satisfied)

Extract phase: n-1 swaps, each maxheapify takes O(1)

Total time: Θ(n) - best case for Heap Sort!

Time Complexity Analysis

Build Heap:
O(n)
Sum of heights converges to linear
Extract Phase:
O(n lg n)
n-1 extractions, each maxheapify takes O(lg n)
Total Time:
O(n) + O(n lg n) = O(n lg n)
Same in best, average, and worst cases

Why Build Heap is O(n)

Most nodes are leaves (n/2 nodes). Leaves need no work. Nodes at height h need O(h) work. The sum of heights converges to O(n).

Best Case

Time: Θ(n lg n)

All elements distinct

Time: Θ(n lg n)

Properties of Heap Sort

Stable

No

Relative order of equal elements may change

In-Place

Yes

Only O(1) extra space needed

Adaptive

No

Always Θ(n lg n), doesn't benefit from sorted input

Online

No

Needs all elements before sorting

Advantages:

• Guaranteed O(n lg n) in all cases

• In-place sorting - O(1) extra space

• Good for priority queue implementations

• Better than Quick Sort for worst-case guarantees

Disadvantages:

• Not stable

• Slower than Quick Sort in practice (poor cache performance)

• More complex to implement than simpler sorts
