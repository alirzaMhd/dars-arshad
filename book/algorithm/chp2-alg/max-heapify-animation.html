MAX-HEAPIFY Algorithm

Maintains the max-heap property for a subtree rooted at index i. Assumes left and right subtrees are already max-heaps.

MAX-HEAPIFY(A, i, n) { left = 2i right = 2i + 1 largest = i if (left ≤ n and A[left] > A[i]) largest = left if (right ≤ n and A[right] > A[largest]) largest = right if (largest ≠ i) { swap(A[i], A[largest]) MAX-HEAPIFY(A, largest, n) } }
Array Index Relations (1-based):
parent(i) = ⌊i/2⌋, left(i) = 2i, right(i) = 2i+1
Max-Heap Property:
A[parent(i)] ≥ A[i]
Parent must be ≥ both children
Key Insight: MAX-HEAPIFY lets a single violation "sink down" until the heap property is restored. The element moves downward along a path, swapping with larger children.

Worked Example

MAX-HEAPIFY at i=2 in [16, 4, 10, 14, 7, 9, 3, 2, 8, 1]

Array: [16, 4, 10, 14, 7, 9, 3, 2, 8, 1]

A[2]=4 violates the max-heap property (children are A[4]=14 and A[5]=7).

Step 1: Compare A[2]=4 with A[4]=14. 14 > 4. Largest = A[4].

Step 2: Compare A[4]=14 with A[5]=7. 7 < 14. Largest stays at A[4].

Step 3: Swap A[2] and A[4]. Array: [16, 14, 10, 4, 7, 9, 3, 2, 8, 1]

Step 4: Recurse to i=4. Compare A[4]=4 with A[8]=2. 2 < 4. Largest = A[4].

Step 5: Compare A[4]=4 with A[9]=8. 8 > 4. Largest = A[9].

Step 6: Swap A[4] and A[9]. Array: [16, 14, 10, 8, 7, 9, 3, 2, 4, 1]

Step 7: Recurse to i=9. No children (2·9=18 > 10). Heap property holds.

Result: [16, 14, 10, 8, 7, 9, 3, 2, 4, 1]

Time Complexity

Time per call:
O(h) = O(log n)
h is the height of the subtree rooted at i. In the worst case, the violation sinks from root to leaf, visiting O(log n) nodes.
Worst Case:
Θ(log n)
When the element at root is the smallest in the heap, it sinks all the way to a leaf, traversing the full height.
Best Case:
Θ(1)
When the node already satisfies the heap property. No swaps, immediate termination.

Why O(log n)?

The recursion follows a single path from the root of the subtree down to a leaf. Each level does O(1) work (comparisons and a possible swap). The height of a complete binary tree with n nodes is ⌊log₂n⌋.

Properties

Recursive

Yes

May call itself recursively on the child that was swapped.

Tail-Recursive

Yes

The recursive call is the last operation — can be optimized to iteration.

In-Place

Yes

Operates directly on the array, no extra storage.

Building Block

Essential

Used in BUILD-MAX-HEAP and HEAP-SORT.

Usage:

• Building a max-heap: run MAX-HEAPIFY from ⌊n/2⌋ down to 1

• Heap Sort: after extracting max, call MAX-HEAPIFY at root

• Priority queues: restore heap after extract or insert

Iterative Version

MAX-HEAPIFY-ITERATIVE(A, i, n) { while (true) { left = 2i; right = 2i+1; largest = i if (left ≤ n and A[left] > A[i]) largest = left if (right ≤ n and A[right] > A[largest]) largest = right if (largest == i) break swap(A[i], A[largest]) i = largest } }

The iterative version avoids recursion overhead and is preferred in practice.
