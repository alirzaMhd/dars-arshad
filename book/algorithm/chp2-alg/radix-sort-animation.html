Radix Sort Algorithm

A non-comparison based sorting algorithm that sorts integers by processing individual digits. It sorts from least significant digit (LSD) to most significant digit (MSD) using a stable sort (usually Counting Sort).

radixsort(A[1..n], d, r) { // d = number of digits, r = base (radix) for (i = 1 to d) { // Sort by i-th digit using stable sort countingsort(A, r, digit i); } }
Key Parameters:
d = number of digits, r = base (radix)
For decimal numbers: r = 10. For binary: r = 2.
Important: The intermediate sort MUST be stable. Counting Sort is typically used because it's stable and efficient for small ranges (0 to r-1).
Radix Sort uses Counting Sort as its stable inner subroutine. For each digit position i, Counting Sort is called on the digit values (range 0 to r-1), taking Θ(n + r) time per pass.

How Radix Sort Works

Step-by-Step Process

1. Start with the least significant digit (rightmost)

2. Sort the array by this digit using a stable sort

3. Move to the next digit (one position left)

4. Sort by this digit, maintaining stability

5. Repeat until all digits are processed

Why LSD to MSD?
Processing LSD first ensures correctness
When we sort by a higher digit, the lower digit order is already correct (due to stability)
Why LSD-first works: Sorting from LSD to MSD is correct because each pass uses a stable sort (Counting Sort). Stability ensures that if two numbers have the same digit in the current position, their relative order from previous (lower) digit passes is preserved.

Example with 3-digit numbers

Numbers: 209, 158, 098, 029, 109, 123

Step 1: Sort by ones → [123, 158, 098, 209, 029, 109]

Step 2: Sort by tens → [209, 109, 123, 029, 158, 098]

Step 3: Sort by hundreds → [029, 098, 109, 123, 158, 209]

Step 2 (tens): [802, 2, 24, 45, 66, 170, 75, 90]

Example 3: Binary Radix Sort

Sort [5, 3, 7, 1] in binary (base 2): 101, 011, 111, 001

Step 1 (bit 0): [5, 3, 7, 1]

Step 2 (bit 1): [3, 1, 5, 7]

Step 3 (bit 2): [1, 3, 5, 7]

Example 4: Choosing Optimal Base

n = 1000 numbers, max value = 106

Base 10: d = 6, time = 6 × (1000 + 10) = 6060

Base 1000: d = 2, time = 2 × (1000 + 1000) = 4000

Using base n is often optimal: d ≈ logn(max value)

Example 5: Numbers in Range [0, n4 − 1]

(a) Counting Sort: k = n4, time = Θ(n + n4) = Θ(n4)

(b) Radix Sort (base 10): d = ⌈4·log10(n)⌉, time = Θ(n lg n)

(c) Radix Sort (base n): d = 4, time = Θ(4·(n + n)) = Θ(n) linear!

Choosing base r = n gives d = 4 constant digits, making Radix Sort run in Θ(n).

Time Complexity Analysis

For each digit:
Θ(n + r)
Time for one Counting Sort pass
Total Time:
d × Θ(n + r) = Θ(d(n + r))
d passes, each takes Θ(n + r)
Space Complexity:
O(n + r)
For the Counting Sort auxiliary arrays

Special Cases

Base n

If r = n, d = ⌈logn(max)⌉, time = O(dn)

Fixed Range

If max value is constant, d is constant, time = O(n)

When is Radix Sort efficient? When d × (n + r) < n lg n. This happens when numbers have few digits relative to lg n.

Properties of Radix Sort

Stable

Yes

Uses stable sort for each digit

In-Place

No

Requires O(n + r) extra space

Comparison-Based

No

Digit-based, not comparison-based

Constraint

Integers with bounded digits

Advantages:

• Can be faster than O(n lg n) for integers

• Stable sort

• Simple to implement

Disadvantages:

• Only works for integers (or strings)

• Not efficient for floating point numbers

• Performance depends on choice of base r
