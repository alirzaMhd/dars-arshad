Insertion Sort Algorithm

Insertion Sort builds the sorted array one element at a time. It takes each unsorted element and inserts it into its correct position among the previously sorted elements, shifting larger elements right as needed.

Pseudocode

insertionSort(A[0..n-1]) { for (i = 1 to n-1) { key = A[i]; j = i - 1; while (j >= 0 and A[j] > key) { A[j+1] = A[j]; // Shift right j--; } A[j+1] = key; // Place key } }

How It Works

1. Start with position 0 as the trivially sorted region (single element).

2. Pick the next element (key = A[i]) from the unsorted region.

3. Compare the key with elements in the sorted region, moving right to left.

4. Shift each larger element one position right to create a gap.

5. Insert the key into the gap when the correct position is found.

6. The sorted region grows by one. Repeat until all elements are processed.

Insertion Sort is like arranging a hand of playing cards — each new card is inserted into its proper place among already-sorted cards.

Time & Space Complexity

Best Case:
Θ(n)
Array already sorted — each key is immediately larger than the previous sorted element, so no shifting occurs.
Average Case:
Θ(n²)
Random order — on average, half the sorted elements must be shifted for each insertion.
Worst Case:
Θ(n²)
Reverse sorted — each key must be compared with all previous elements and shifted to the front.
Space Complexity:
O(1)
Sorts in-place using only a constant amount of extra memory (one variable for key and one for shifting).

Comparison & Shift Counts

Maximum Comparisons:
n(n−1)/2
Maximum Shifts (moves):
n(n−1)/2

Properties of Insertion Sort

Stable

Yes

Equal elements are not shifted past each other (only shifts when A[j] > key).

In-Place

Yes

Uses only O(1) extra space.

Adaptive

Yes

Best case O(n) when already sorted; benefits from partial ordering.

Online

Yes

Can sort as elements arrive one at a time.

Key Facts:

• Best case O(n) when array is already sorted — only n-1 comparisons

• When all elements are equal, Insertion Sort runs in Θ(n) — no shifting needed

• Maximum comparisons: n(n−1)/2

• Maximum shifts: n(n−1)/2

• For n ≤ 25, Insertion Sort is often faster than more complex algorithms

When to Use Insertion Sort

• Small arrays (n ≤ 25) — low overhead

• Nearly sorted data — runs in near-linear time

• Online sorting — data arrives incrementally

• As the final step in Hybrid Sorts (e.g., Introsort, Timsort)
