Bellman-Ford Algorithm

Single-Source Shortest Paths with Negative Edges — Complete Guide for 20/20 Exam

What is the Bellman-Ford Algorithm?

Bellman-Ford finds the shortest paths from a single source vertex to all other vertices in a weighted directed graph. Unlike Dijkstra's algorithm, it handles negative edge weights and can detect negative cycles.

Problem:
δ(s,v) = min{ w(p) : p is a path from s to v }
Shortest path weight from source s to vertex v

Key Features

  • Works with negative edge weights
  • Detects negative cycles reachable from the source
  • Returns TRUE if no negative cycle, FALSE otherwise
  • Slower than Dijkstra but more general
Runtime (Adjacency List):
Θ(V · E)
V-1 iterations, each relaxing all E edges
Runtime (Adjacency Matrix):
Θ(V³)
V-1 iterations, each scanning V² matrix entries

The RELAX Operation

The core operation: check if going through vertex u gives a shorter path to v.

RELAX(u, v, w):
if d[v] > d[u] + w(u,v): update d[v] = d[u] + w(u,v), π[v] = u
If the path s→...→u→v is shorter than current d[v], update

Edge Relaxation

d[v] > d[u] + w(u,v)

Update found: path through u is better

No Change

d[v] ≤ d[u] + w(u,v)

Current d[v] is already optimal

Negative Cycle

d[v] > d[u] + w(u,v) after V-1 passes

Cycle detected!

Algorithm & Pseudocode

Algorithm Steps

  1. Initialize: d[s] = 0, d[v] = ∞ for all other v, π[v] = NIL
  2. Repeat |V|-1 times: Relax EVERY edge (u,v) in the graph
  3. Check for negative cycles: For each edge (u,v), if d[v] > d[u] + w(u,v), then a negative cycle exists ⇒ return FALSE
  4. Return TRUE if no negative cycle found

Pseudocode

INITIALIZE(G, s) 1. for each vertex v ∈ V: 2. d[v] ← ∞ 3. π[v] ← NIL 4. d[s] ← 0 RELAX(u, v, W) 1. if d[v] > d[u] + W(u, v): 2. d[v] ← d[u] + W(u, v) 3. π[v] ← u BELLMAN-FORD(G, W, s) 1. INITIALIZE(G, s) 2. for i ← 1 to |V| - 1: 3. for each edge (u, v) ∈ E: 4. RELAX(u, v, W) 5. for each edge (u, v) ∈ E: 6. if d[v] > d[u] + W(u, v): 7. return FALSE // negative cycle detected 8. return TRUE // shortest paths found

Why |V|-1 Iterations?

A shortest path can have at most |V|-1 edges (no cycles). After k iterations, the algorithm has found all shortest paths using at most k edges. So after |V|-1 iterations, all shortest paths are found.

Iteration Bound:
longest shortest path has at most |V| - 1 edges
No shortest path contains a cycle (positive or zero cycles can be removed, negative cycles make paths undefined)

Edge Order Independence

Important: The edges can be processed in any order within each iteration. The final distances after |V|-1 iterations will be correct regardless of order. However, the order may affect intermediate values and how quickly convergence happens.

Exam Tip: The Bellman-Ford algorithm returns TRUE/FALSE (whether a negative cycle exists), but the distances d[v] are only valid when TRUE is returned.

Negative Cycle Detection

After |V|-1 relaxation passes, if any edge can still be relaxed, then a negative cycle exists that is reachable from the source. In that case, shortest paths are undefined (they can be made arbitrarily negative by traversing the cycle repeatedly).

Negative Cycle Condition:
∃(u,v) ∈ E: d[v] > d[u] + w(u,v) after |V|-1 passes
If true, shortest paths are undefined (value = -∞ for vertices reachable from the cycle)
Example 4: Detecting a Negative Cycle

Graph with 4 vertices, source = s. Contains a negative cycle: s→a→b→s.

Edges: (s,a)=2, (a,b)=1, (b,s)=-4, (a,c)=3

The cycle s→a→b→s has total weight = 2+1+(-4) = -1 (NEGATIVE!)

After |V|-1 = 3 passes, check each edge:

  • Check (b,s): d[s] = -2, d[b]+w(b,s) = 2+(-4) = -2. d[s] ≤ -2 ⇒ OK
  • Wait — actually we need to check further...

On the 4th pass (i.e., the V-th iteration):

  • Relax (s,a): d[a] = -2 + 2 = 0 ⇒ still updated
  • Relax (a,b): d[b] = 0 + 1 = 1 ⇒ still updated
  • Relax (b,s): d[s] = 1 + (-4) = -3 ⇒ STILL UPDATING!

The distances keep decreasing with each pass! The algorithm returns FALSE because a negative cycle reachable from s exists.

Important: When a negative cycle exists, the shortest paths to vertices reachable from the cycle are undefined (they go to -∞). Bellman-Ford does NOT compute meaningful distances in this case — it only detects the cycle and returns FALSE.

Graph with 5 vertices, source = s. A negative cycle exists but is NOT reachable from s.

Edges: (s,a)=3, (a,b)=2, (c,d)=1, (d,e)=-3, (e,c)=1

The cycle c→d→e→c has total weight = 1+(-3)+1 = -1 (negative!) but it is NOT reachable from s.

Bellman-Ford only detects negative cycles reachable from the source. Unreachable negative cycles are harmless.

When to Use Bellman-Ford?

Use Bellman-Ford

• Negative edge weights exist

• Need to detect negative cycles

• Graph is small (V < 1000)

• Exam asks for it specifically

Don't Use Bellman-Ford

• All weights are non-negative (use Dijkstra)

• Graph is a DAG (use DAG-SP Θ(V+E))

• Graph is very large (O(VE) is too slow)

Common Mistakes

Mistake 1: Forgetting that Bellman-Ford returns TRUE/FALSE. The distances are only valid when the return value is TRUE.
Mistake 2: Thinking edges must be processed in a specific order. Any order works — the algorithm converges after |V|-1 passes regardless.
Mistake 3: Confusing the runtime: O(VE) for adjacency lists, O(V³) for adjacency matrices. Make sure to identify which representation is used.
Mistake 4: Assuming Bellman-Ford can handle positive cycles. It can — positive cycles are harmless (they never improve distances). The issue is only with negative cycles.
Mistake 5: The negative cycle must be reachable from the source to cause problems. An unreachable negative cycle is ignored.
