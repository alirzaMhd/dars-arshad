Dijkstra's Algorithm

Single-Source Shortest Paths — Non-Negative Weights

Problem Definition

Given a directed or undirected graph G = (V, E) with a weight function w: E → ℝ⁺ (non-negative reals) and a source vertex s ∈ V, find the shortest path from s to every other vertex v ∈ V.

Shortest Path Distance:
δ(s, v) = min{ w(p) : p is a path from s to v }
where w(p) is the sum of edge weights along path p. If no path exists, δ(s, v) = ∞.
Triangle Inequality (Optimal Substructure):
δ(s, v) ≤ δ(s, u) + w(u, v)
For any edge (u, v), the shortest path to v cannot be longer than the shortest path to u plus the edge weight.

Core Concepts

Distance Array d[·]

d[v] = current estimate of shortest path from s to v

Initially: d[s] = 0, d[v] = ∞ for v ≠ s

Converges: d[v] → δ(s, v)

Processed Set A

Vertices whose shortest distance is finalized

Greedy choice: pick u with smallest d[u] from V \ A

Once extracted, d[u] = δ(s, u) is permanent

Priority Queue

Min-heap keyed by d[v] values

EXTRACT-MIN: O(log V) with binary heap

DECREASE-KEY: O(log V) with binary heap

Relaxation

if d[u] + w(u, v) < d[v]:

  d[v] = d[u] + w(u, v)

  π[v] = u

Algorithm Pseudocode

DIJKSTRA(G, w, s) // Initialization for each vertex v ∈ V d[v] = ∞ π[v] = NIL d[s] = 0 // Build priority queue Q = V // min-heap keyed by d[v] // Main loop while Q ≠ ∅ u = EXTRACT-MIN(Q) A = A ∪ {u} for each vertex v ∈ Adj[u] RELAX(u, v, w) RELAX(u, v, w) if d[u] + w(u, v) < d[v] d[v] = d[u] + w(u, v) π[v] = u DECREASE-KEY(Q, v, d[v])

After execution, d[v] = δ(s, v) and the shortest path can be reconstructed by following π[v] pointers back to s.

Variable Definitions

  • G = (V, E) — Graph with vertex set V and edge set E
  • w(u, v) — Non-negative weight of edge (u, v)
  • s — Source vertex
  • d[v] — Current shortest distance estimate from s to v
  • π[v] — Predecessor of v on the shortest path
  • Q — Min-priority queue of unprocessed vertices
  • A — Set of vertices with finalized shortest distances
  • Adj[u] — Adjacency list of vertex u
  • δ(s, v) — Actual shortest distance from s to v

Quick Reference Card

• Dijkstra solves single-source shortest paths for non-negative weights

• Greedy: always extract vertex with smallest d value

• Invariant: when u is extracted, d[u] = δ(s, u) is final

• Priority queue keyed by d[v] values

• Relaxation updates neighbors' distances

• Fails with negative edge weights!

Dijkstra's Algorithm FAILS with Negative Edges

The correctness of Dijkstra's algorithm rests on the invariant: when u is extracted from Q, d[u] = δ(s, u) is finalized. This holds only if all edge weights are non-negative. With negative edges, a later vertex might find a shorter path to an already-extracted vertex.

Why the proof breaks:
d[u] ≤ d[v]  does NOT imply  δ(s, u) ≤ δ(s, v)
when negative edges exist, because the path s → … → v → … → u may have a very small total weight even though d[v] is large.
Negative Edge Failure — Concrete Example
s ---5---> x | | | | 0---->-10-->y

Corrected graph to show the standard counterexample:

s --5--> x | | | 2 | v +--(-3)-> y

Now with better labeling:

A --5--> B | | -3 1 | v +------> C
Step 1: Extract A (d=0), relax B: d[B]=5, relax C: d[C]=-3
Step 2: Extract C (d=-3), relax B: d[B] = min(5, -3+1=-2) = -2, π[B]=C
Step 3: Extract B (d=-2) — done
✅ Dijkstra actually works here because C is extracted before B (d[C] = -3 < d[B] = 5)
⚠ WARNING: True Failure Case
A --10--> B | | 5 2 v v C --(-5)--> D

What Dijkstra does:

Step 1: Extract A (d=0), relax B: d[B]=10, relax C: d[C]=5

Step 2: Extract C (d=5), relax D: d[D] = 5+(-5) = 0

Step 3: Extract D (d=0), relax B: d[B] = min(10, 0+2=2) = 2, π[B]=D

Step 4: Extract B (d=2) — done

✅ This still works because D gets extracted before B (d[D]=0 < d[B]=10).

The true counterexample needs the negative edge to reach an already extracted vertex:

A --5--> B | | 4 -3 v | C <-------+

Step 1: Extract A (d=0), relax B: d[B]=5, relax C: d[C]=4

Step 2: Extract C (d=4 < d[B]=5), relax B: d[B] = min(5, 4+(-3)=1) = 1, π[B]=C

Step 3: Extract B (d=1)

✅ Still OK because B wasn't extracted yet when we found the shorter path.

⚠ TRUE Dijkstra Failure

Dijkstra fails when a negative edge from a later-extracted vertex could shorten the path to an already-extracted vertex. Since Dijkstra finalizes vertices upon extraction, it cannot update them. Use Bellman-Ford for graphs with negative edges.

A --2--> B | | | | -3 | v +---1---> C

Dijkstra's execution:

Step 1: Extract A (d=0), relax B: d[B]=2, relax C: d[C]=1

Step 2: Extract C (d=1 < d[B]=2). C is finalized with d[C]=1.

Step 3: But C can reach B with weight -3, so d[B] should be min(2, 1+(-3)=-2) = -2.

Step 4: Extract B (d=2) — WRONG! Should be -2.

❌ Dijkstra output: d[B]=2. Correct answer: d[B]=-2 (via A→C→B).

This happens because C was extracted (finalized) before we realized it could shorten B's distance via a negative edge.

When to use which algorithm

• All weights ≥ 0 → Use Dijkstra (O(E log V))

• Negative weights, no negative cycles → Use Bellman-Ford (O(VE))

• Negative cycles present → Bellman-Ford detects them

• All-pairs shortest paths → Floyd-Warshall or Johnson's

Dijkstra vs. Prim's Algorithm

While both algorithms use a greedy strategy with a min-priority queue, they solve fundamentally different problems and use different key values.

Key Difference:
Dijkstra:  key[v] = d[v] = shortest distance from source s
Prim:      key[v] = min{ w(u, v) : u ∈ tree, v ∉ tree } = min edge to tree

Same Graph, Different Results

Consider graph with vertices A, B, C:

A—(5)—B, A—(3)—C, B—(2)—C

AlgorithmResultValue
Dijkstra (source=A)d[A]=0, d[C]=3, d[B]=5Shortest paths from A

Dijkstra finds A→B length 5 (direct). Prim finds the tree with edges (A,C), (C,B) weight=5. Same numbers, different meanings!

⚠ Common Mistake

Students often confuse Dijkstra and Prim because both use EXTRACT-MIN from a priority queue and look superficially similar. Remember: Dijkstra's key is cumulative distance from source; Prim's key is individual edge weight to tree. Dijkstra computes paths; Prim computes a tree. They are NOT interchangeable.

Proof of Correctness (Non-Negative Weights)

Invariant:
For every vertex u ∈ A, d[u] = δ(s, u)
When a vertex is extracted from Q and added to A, its distance is final.

Proof by induction:

  1. Base: A = ∅, invariant holds vacuously.
  2. Step: Suppose invariant holds for all vertices in A. Let u be the vertex with minimum d[u] among V \ A. Suppose for contradiction that the true shortest path to u uses some vertex x ∉ A before reaching u.
  3. Since all weights ≥ 0, the subpath s → … → x has distance ≤ δ(s, u). But d[x] ≤ δ(s, u) ≤ d[u], contradicting u being minimal in Q. Therefore no such x exists, and d[u] = δ(s, u).

The key insight: the greedy choice works because non-negative weights ensure that the shortest path to any vertex cannot go through an unprocessed vertex with larger distance.
