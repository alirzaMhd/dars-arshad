EDGE CLASSIFICATION IN DFS

Data Structures — Complete Guide for 20/20 Exam

Four Edge Types

When running DFS on a graph, every edge (u, v) encountered during exploration falls into exactly one of four categories based on the color of v when the edge is examined.

Tree Back Forward Cross
Edge Type Color of v when (u, v) examined Relationship In DFS Forest Directed?
Tree Edge WHITE v is an undiscovered neighbor v becomes child of u Both
Back Edge GRAY v is an ancestor of u (in recursion stack) Connects node to ancestor Both
Forward Edge BLACK, d[u] < d[v] v is a non-child descendant of u Non-tree edge to descendant Directed only
Cross Edge BLACK, d[u] > d[v] No ancestor relationship Connects different branches Directed only
Color-Based Classification (Algorithmic Rule)
color[v] == WHITE  → Tree Edge
color[v] == GRAY   → Back Edge
color[v] == BLACK:  d[u] < d[v] → Forward Edge
                       d[u] > d[v] → Cross Edge
This is how we classify edges during DFS — by checking the color and timestamps of the destination vertex.

Detailed Edge Descriptions

Tree Edges

Edges that belong to the DFS forest. When DFS-VISIT(u) explores neighbor v and finds it WHITE, it recursively visits v. The edge (u, v) becomes a tree edge, and u becomes the parent of v (π[v] = u).

Number of tree edges: V − k, where k = number of DFS trees (connected components in undirected graphs).

Back Edges

Edges that connect a vertex u to an ancestor v in the DFS tree. The target v is GRAY because it is still on the recursion stack. Back edges are the cycle indicators.

In undirected graphs: every non-tree edge is a back edge.

Cycle detection: graph has a cycle ⟺ DFS produces at least one back edge.

Forward Edges

Edges that connect a vertex u to a descendant v that is NOT a direct child. The target v is BLACK (already finished) but d[u] < d[v], confirming v is a descendant. Forward edges are directed only.

Forward edges cannot exist in undirected graphs because an undirected edge from ancestor to descendant would also be an edge from descendant to ancestor, which would be a back edge.

Cross Edges

Edges that connect vertices in different branches of the DFS tree (or different DFS trees). The target v is BLACK and d[u] > d[v], meaning v was discovered and finished before u. Cross edges are directed only.

In undirected graphs: a cross edge in one direction would be a tree/back/forward edge in the other direction.

Quick Reference: Timestamp Rules

Given edge (u, v) examined during DFS-VISIT(u):

Edge Type d[u] vs d[v] f[u] vs f[v] color[v]
Tree d[u] < d[v] f[u] > f[v] WHITE
Back d[v] < d[u] f[v] > f[u] GRAY
Forward d[u] < d[v] f[u] > f[v] BLACK
Cross d[v] < d[u] f[v] < f[u] BLACK
Common Mistake: Don't confuse forward and tree edges! Both have d[u] < d[v] and f[u] > f[v]. The difference: tree edges lead to WHITE targets (new descendants), while forward edges lead to BLACK targets (already-processed descendants).

DAG Characterization

DAG Condition (No Cycles)
G is a DAG ⟺ DFS(G) produces NO back edges
A directed graph is acyclic iff its DFS traversal has zero back edges. Only tree, forward, and cross edges are permitted.

In a DAG, topologically sorting by decreasing finish time gives a valid linear ordering.

Edge Classification in Undirected Graphs

For undirected graphs, edge classification is simpler: there are only tree edges and back edges.

Classification in Undirected Graphs
Every edge is either: Tree Edge or Back Edge
Forward and cross edges cannot exist in undirected graphs

Why? Consider an undirected edge {u, v}. Suppose during DFS, u is discovered first. When exploring u → v:

  • If v is WHITE → (u, v) is a tree edge
  • If v is GRAY → (u, v) is a back edge (v is ancestor of u)
  • If v is BLACK → This cannot happen! Since u was discovered first, and the edge is undirected, v would have been visited from u and finished. But when v's DFS explored the same edge back to u, u would already be visited. Let's trace: if u discovered before v, then v becomes descendant of u. When v finishes, u is still GRAY. So when exploring from u, we'd encounter v as GRAY (back edge), not BLACK.
Key insight: For an undirected edge {u, v}, the first time DFS encounters one endpoint, it either creates a tree edge (if the other is WHITE) or finds a back edge (if the other is GRAY). The second time the edge is encountered (from the other direction), the target is always BLACK and is simply ignored.

Cycle Detection in Undirected Graphs

Cycle Detection — Undirected
Undirected graph has a cycle ⟺ DFS produces a back edge
Since only tree and back edges exist, any non-tree edge is a back edge, which implies a cycle.
Undirected Graph with Cycle

Graph: V = {a, b, c, d}, edges: a-b, b-c, c-a, a-d

DFS from a (adjacency alphabetical):

d[a]=1, a→b (W), DFS-VISIT(b)
d[b]=2, b→a (G) → back edge! (but skip since parent)
      b→c (W), DFS-VISIT(c)
d[c]=3, c→a (G) → back edge! (cycle detected: a-c-a)
      c→b (G) → back edge (skip, parent)
finish c, f[c]=4
finish b, f[b]=5
back to a, a→c (B, skip), a→d (W), DFS-VISIT(d)
d[d]=6, finish d, f[d]=7
finish a, f[a]=8

Back edges found: (b, a) — but this is actually the parent edge. The real cycle comes from (c, a): c → a is a back edge since a is GRAY (ancestor of c).

Result: Graph has a cycle (a-b-c-a).

Handling the Parent Edge

In undirected graphs, when exploring u → v where π[u] = v (v is the parent of u), we must skip this edge. It appears as a back edge (v is GRAY) but it's not a cycle.

Modified DFS for Undirected Cycle Detection
If color[v] == GRAY and v ≠ π[u]:  → True cycle (back edge)
Skip the edge to the parent to avoid false cycle detection
Common Mistake: In undirected graphs, forgetting to exclude the parent edge will cause false cycle detection! Every non-root vertex has a tree edge to its parent that looks like a back edge.

Comparison: Directed vs Undirected

Property Directed Graphs Undirected Graphs

Back edges Yes (ancestor → descendant) Yes (also ancestor → descendant)
Forward edges Possible Impossible
Cross edges Possible Impossible
Cycle ⟺ back edge Yes Yes (excluding parent)

Worked Example 5: Edge Classification Algorithm Implementation

Example 5 — Pseudocode for Edge Classification

Below is the modified DFS that classifies and counts each edge type:

DFS-CLASSIFY(G): for each u ∈ G.V: color[u] = WHITE π[u] = NIL time = 0 for each u ∈ G.V: if color[u] == WHITE: DFS-VISIT-CLASSIFY(u) DFS-VISIT-CLASSIFY(u): color[u] = GRAY time += 1; d[u] = time for each v ∈ Adj[u]: if color[v] == WHITE: print(u + "→" + v + ": TREE EDGE") π[v] = u DFS-VISIT-CLASSIFY(v) else if color[v] == GRAY: print(u + "→" + v + ": BACK EDGE (CYCLE!)") else: // color[v] == BLACK if d[u] < d[v]: print(u + "→" + v + ": FORWARD EDGE") else: print(u + "→" + v + ": CROSS EDGE") color[u] = BLACK time += 1; f[u] = time

Running this on a directed graph with 5 edges classified correctly is a common exam question. The key is tracking color and timestamps.

Implementation note: In undirected graphs, add a check: if v == π[u] then skip (it's the parent tree edge seen from the child side).
