Minimum Spanning Tree (MST)

Kruskal & Prim Algorithms — Complete Guide for 20/20 Exam

What is a Minimum Spanning Tree?

Given a connected, undirected, weighted graph G = (V, E), a spanning tree is a subgraph that is a tree (connected, acyclic) and includes all vertices of G. A Minimum Spanning Tree (MST) is a spanning tree with the minimum possible total edge weight.

In simpler terms: an MST connects all vertices with the minimum total cost, without any cycles. Think of it as the cheapest way to connect all cities with roads, where edge weights represent construction costs.

Applications: Network design (telecommunications, power grids), clustering (single-linkage clustering), approximation algorithms (TSP), image segmentation, and circuit design.

MST Definition:
MST(G) = argmin { w(T) : T is a spanning tree of G }
Where w(T) = sum of edge weights in tree T
Total weight of MST:
w(T) = ∑ w(u,v) ∀ (u,v) ∈ T
Sum of all edge weights in the spanning tree

Key Properties

  • A graph with n vertices has exactly n-1 edges in any spanning tree — this is because a tree on n vertices must have exactly n-1 edges to remain connected without cycles. If you have fewer edges, the graph is disconnected; if more, there's a cycle.
  • If all edge weights are distinct, the MST is unique — no ambiguity in selection. The cut property guarantees that the minimum-weight edge crossing any cut is always the same when weights are unique.
  • If duplicate weights exist, multiple MSTs may exist (all with same total weight) — the total weight remains the same because the same set of weight values are used, just in different positions.
  • MST has no cycles by definition (it is a tree) — any cycle would allow removing an edge to get a lighter tree, contradicting the MST property.
  • The MST minimizes the total weight among all possible spanning trees — this is useful in network design (telecommunications, power grids, transportation) where minimizing cost is essential.
Spanning Tree Edge Count:
|EMST| = |V| - 1
A spanning tree on n vertices always has exactly n-1 edges

Cut Property

For any cut (partition of V into two disjoint sets S and V\S), the lightest edge crossing the cut is safe (belongs to some MST). This is the fundamental theorem that justifies both Kruskal's and Prim's algorithms.

A "cut" divides vertices into two non-empty groups. Edges between the groups "cross" the cut. The cut property guarantees that the minimum-weight crossing edge must be in some MST. Why? Because if you include this edge, you can always remove a heavier edge from the other side to form a valid MST.

Cut Property:
(u,v) = argmin{ w(x,y) : x ∈ S, y ∈ V \ S } ⇒ (u,v) ∈ MST
The minimum-weight edge crossing any cut is always part of some MST

Kruskal's Algorithm

A greedy algorithm that builds the MST by repeatedly adding the smallest-weight edge that does not form a cycle. Uses the Union-Find (Disjoint Sets) data structure to detect cycles efficiently.

Think of Kruskal's as "global" — it looks at ALL edges at once, sorted by weight, and greedily picks the cheapest. It works by maintaining a forest of disjoint trees and gradually merging them. The key insight: adding the cheapest edge that doesn't form a cycle always leads to an optimal solution (cut property).

Algorithm Steps

  1. Sort all edges by weight in non-decreasing order — this is the key step that makes the greedy choice possible
  2. Initialize: each vertex is its own disjoint set — represents a forest of |V| single-vertex trees
  3. For each edge (u,v) in sorted order:
    - If find(u) ≠ find(v): add edge to MST, union(u,v) — this connects two components
    - Otherwise: reject edge (it would form a cycle) — u and v are already in the same component
  4. Stop when MST has |V|-1 edges (or all edges processed) — we've connected all vertices

Pseudocode

KRUSKAL(G, W) 1. A ← ∅ 2. for each vertex v ∈ V: 3. MAKE-SET(v) 4. Sort edges E by non-decreasing weight W 5. for each (u, v) ∈ E in sorted order: 6. if FIND(u) ≠ FIND(v): 7. A ← A ∪ {(u, v)} 8. UNION(u, v) 9. return A
Note: Borůvka's (Sollin's) algorithm is a third MST algorithm. It works in phases: each phase adds the cheapest edge from each component to any other component. Runs in O(E log V) and is well-suited for parallel computation.

Time Complexity

Standard Runtime:
O(E log E) = O(E log V)
Sorting dominates: O(E log E). Since log E = O(log V), we write O(E log V)
Runtime Breakdown:
O(n) [init] + O(e log e) [sort] + O(e · α(n)) [union-find ops]
Initialization O(n), sorting O(e log e), union-find operations O(e α(n)), total = O(e log e) = O(e log n)
If Edges Pre-Sorted:
O(E · α(V))
α(n) is the inverse Ackermann function, ≤ 4 for all practical n
If weights in [1..n] (counting sort):
O(E · α(V))
Counting sort in O(n+E) = O(E), then union-find dominates

Cycle Detection with Union-Find

Initially each vertex is its own set. When edge (u,v) is examined:

  • FIND(u) ≠ FIND(v) ⇒ u and v are in different components, edge is safe — adding it won't create a cycle because it connects two separate trees
  • FIND(u) = FIND(v) ⇒ u and v are already connected, edge would create a cycle — they're in the same tree, so adding an edge creates a loop
  • After adding a safe edge, UNION(u,v) merges the two components — this updates the structure so future FIND operations reflect the merged component

Union-Find with path compression and union by rank gives amortized O(α(n)) per operation, where α is the inverse Ackermann function (≤ 4 for all practical n). This makes Kruskal's nearly linear time.

Warning! Kruskal's algorithm processes edges in sorted order. If you process in any other order, the greedy property is lost and you may not get an MST. The sorted order is what makes the greedy choice optimal — always sort first!

Prim's Algorithm

A greedy algorithm that grows the MST one vertex at a time. Starts from an arbitrary root and always adds the lightest edge connecting a visited vertex to an unvisited vertex.

Think of Prim's as "local" — it maintains a frontier of visited vs. unvisited vertices and always picks the cheapest edge crossing this frontier. This is similar to Dijkstra's shortest path algorithm, but Prim uses edge weights directly (not cumulative path weights). Prim is better suited for dense graphs because it avoids sorting all edges.

Algorithm Steps

  1. Start with any vertex r. Set key[r] = 0, key[v] = ∞ for other vertices
  2. Insert all vertices into a min-priority queue keyed by key values
  3. While queue is not empty:
    - Extract min vertex u
    - For each neighbor v of u:
      If v is in queue and w(u,v) < key[v]: update key[v], set π[v] = u
  4. MST edges are (π[v], v) for v ≠ r

Pseudocode

PRIM(G, W, r) 1. for each vertex v ∈ V: 2. key[v] ← ∞, π[v] ← NIL 3. key[r] ← 0 4. Q ← V // min-priority queue keyed by key[] 5. while Q ≠ ∅: 6. u ← EXTRACT-MIN(Q) 7. for each v ∈ Adj[u]: 8. if v ∈ Q and w(u,v) < key[v]: 9. π[v] ← u 10. key[v] ← w(u,v) 11. return A = {(π[v], v) : v ≠ r}

Warning! Prim's algorithm requires the graph to be connected. If the graph is disconnected, Prim will only produce an MST for the component containing the start vertex. For disconnected graphs, use Kruskal's to find the minimum spanning forest.

When to Use Which?

Choose Kruskal

• Sparse graphs (E ≈ V) — sorting is cheap

• Edges can be sorted efficiently — when edge list is readily available

• Parallel processing desired — edges are independent, easy to parallelize

• Disconnected graph (forest) — naturally finds minimum spanning forest

• When you have an edge list, not adjacency structure

Choose Prim

• Dense graphs (E ≈ V²) — O(V²) with matrix beats O(E log V)

• Adjacency matrix available — avoids sorting all edges

• Sequential growth preferred — when you need to extend from a specific starting point

• Connected graph guaranteed — always produces one tree

• When you want to grow the tree incrementally

Correctness Theorems

Cut Property (for correctness):
If (u,v) is the minimum-weight edge crossing cut (S, V\S), then (u,v) is in some MST
Both algorithms rely on this property to safely add edges. Proof: If (u,v) is not in MST T, adding it creates a cycle. This cycle must cross the cut again at some edge (x,y). Since w(u,v) ≤ w(x,y), replacing (x,y) with (u,v) gives a lighter tree, contradicting T being an MST.
Cycle Property:
If (u,v) is the maximum-weight edge in some cycle, then (u,v) is NOT in any MST
Used by some algorithms to reject heavy edges. Proof: If (u,v) were in MST T, removing it splits T into two components. The cycle provides another edge (x,y) crossing this cut with w(x,y) ≤ w(u,v). Replacing (u,v) with (x,y) gives a lighter or equal tree.
Minimum Spanning Forest:
If G is disconnected, MST algorithms find a Minimum Spanning Forest (MSF) — one MST per connected component
Kruskal's naturally handles this; Prim's only finds the MST for the component containing the start vertex.

Common Mistakes

Mistake 1: Forgetting that Kruskal requires edges to be sorted. If edges are not sorted, the algorithm fails and may produce a suboptimal tree. Always sort by non-decreasing weight before processing.
Mistake 2: Assuming Prim's binary-heap version is always O(E log V). With adjacency matrix, Prim is O(V²), which is different. The implementation matters — always specify which data structure you're using when stating complexity.
Mistake 3: Forgetting that MST = |V|-1 edges. If you have more, there's a cycle; if fewer, the graph isn't connected. This is a quick way to verify your MST is correct.
Mistake 4: The MST is unique ONLY if all edge weights are distinct. With equal weights, multiple MSTs exist with the same total weight. Don't claim uniqueness without checking for duplicate weights.
Mistake 5: Confusing MST with shortest path. MST minimizes total edge weight; shortest path (Dijkstra) minimizes path from source to each vertex. These are different problems with different solutions.

Consider the graph with vertices {a, b, c, d, e} and the following edges (sorted by weight):

Example 3: Unique MST with Distinct Edge Weights

Graph with 6 vertices. All edge weights are distinct (no two edges share the same weight).

Edges: (1,2):2, (1,3):4, (2,3):7, (2,4):5, (3,4):1, (3,5):8, (4,5):3, (4,6):6, (5,6):9

Step 1: Sort edges by weight: (3,4):1, (1,2):2, (4,5):3, (1,3):4, (2,4):5, (4,6):6, (2,3):7, (3,5):8, (5,6):9

Step 2 (Kruskal):

  • Add (3,4):1 — sets merge {3,4}
  • Add (1,2):2 — sets merge {1,2}
  • Add (4,5):3 — sets merge {3,4,5}
  • Add (1,3):4 — FIND(1)≠FIND(3) ⇒ ADD. Sets: {1,2,3,4,5}
  • Add (4,6):6 — FIND(4)≠FIND(6) ⇒ ADD. Sets: {1,2,3,4,5,6}

MST: (3,4):1, (1,2):2, (4,5):3, (1,3):4, (4,6):6 → Total = 16

Since all weights are distinct, this MST is the unique minimum spanning tree.

Key Insight: With distinct weights, the MST is unique because at every step, the cut property picks a unique minimum-weight edge. No ties means no ambiguity. This is important because it means any MST algorithm will find the same tree.

How to Trace MST Algorithms on Exams

Kruskal Trace

1. Sort all edges by weight

2. Track disjoint sets: {a}{b}{c}...

3. For each edge, check FIND(u) ≠ FIND(v)

4. If safe: ADD edge, UNION sets

5. Stop at |V|-1 edges

Prim Trace

1. Start vertex: key=0, others=∞

2. Extract min from priority queue

3. Update neighbors' keys if cheaper

4. Track parent pointers π[v]

5. MST edges: (π[v], v) for v ≠ r
