Topological Sort

Linear Ordering in Directed Acyclic Graphs | Complete Guide for 20/20 Exam

Definition

A topological sort of a directed acyclic graph (DAG) G = (V, E) is a linear ordering of all vertices such that for every directed edge (u, v) ∈ E, vertex u appears before vertex v in the ordering.

Topological Sort Condition:
For every edge (u,v) ∈ E :   u precedes v in the linear order
If there is a path from u to v, then u must come before v in the topological order
⛔ Critical Constraint: Topological sort is only possible on DAGs (Directed Acyclic Graphs). If the graph contains a cycle, no topological ordering exists — a cycle would require u before v and v before u simultaneously.

Properties of Topological Sort

Key Properties

• Only defined for DAGs

• Multiple valid orderings possible

• Not necessarily unique

• Every DAG has at least one ordering

Real-World Analogy

Course prerequisites:

If course A requires course B (B → A), then B must be taken before A. A topological sort gives a valid course sequence.

⚠ Exam Tip: The DFS-based approach is the standard textbook method. The order is the reverse of DFS finish times. Intuitively: the vertex that finishes last in DFS appears first in topological order.

DFS-Based Topological Sort Pseudocode

TopologicalSort(G): // Call DFS to compute finish times for each vertex u ∈ G.V: u.color = WHITE u.π = NIL time = 0 stack = ∅ // stores vertices in reverse finish order for each vertex u ∈ G.V: if u.color == WHITE: DFS-Visit(G, u, stack) return stack.reverse() // topological order DFS-Visit(G, u, stack): time = time + 1 u.d = time // discovery time u.color = GRAY for each v ∈ G.Adj[u]: if v.color == WHITE: v.π = u DFS-Visit(G, v, stack) else if v.color == GRAY: // Cycle detected! Graph is not a DAG return "ERROR: cycle detected" u.color = BLACK time = time + 1 u.f = time // finish time stack.push(u) // push when finished

The Key Insight

Topological Order = Decreasing Finish Time:
Order: <v : v∈V> sorted by decreasing f[v]
If u appears before v in topological order, then f[u] > f[v] (u finished later in DFS)
Correctness Proof Outline:
For any edge (u,v) ∈ E,   f[v] < f[u]
When DFS explores (u,v), if v is WHITE it becomes a descendant of u (v finishes before u). If v is BLACK, it already finished (f[v] < f[u]). If v is GRAY, there is a cycle — contradiction. Therefore f[v] < f[u] always, so u (higher finish time) must come before v in the topological order.

Cycle Detection in Topological Sort

IsDAG(G): // Returns True if G is a DAG Run TopologicalSort(G) if cycle detected: return False return True

In the DFS-based algorithm, a back edge (detected when v is GRAY) indicates a cycle. This means the graph is NOT a DAG and no topological sort exists.

⛔ Cycle Detection: During DFS, if we encounter an edge (u,v) where v is GRAY (currently on the recursion stack), the graph contains a directed cycle. Topological sort is impossible.

Kahn's Algorithm (Alternative)

KahnTopologicalSort(G): // Compute in-degrees for each vertex u ∈ G.V: for each v ∈ G.Adj[u]: in-degree[v] = in-degree[v] + 1 Q = ∅ // queue of vertices with in-degree 0 for each vertex u ∈ G.V: if in-degree[u] == 0: Enqueue(Q, u) result = [] count = 0 while Q ≠ ∅: u = Dequeue(Q) result.append(u) count = count + 1 for each v ∈ G.Adj[u]: in-degree[v] = in-degree[v] - 1 if in-degree[v] == 0: Enqueue(Q, v) if count ≠ |V|: return "ERROR: cycle detected" return result

DFS-based Pros

• Natural extension of DFS

• Also computes discovery/finish times

• Useful for other graph problems

Kahn's Pros

• No recursion (no stack overflow)

• Easier to understand

• Naturally handles disconnected DAGs

Example 4: Detecting a Cycle (Invalid Graph)

A → B → C ↑ ↓ ————D
⛔ This graph has a cycle: A → B → C → D → A

During DFS: Discover A (d=1). Go to B (d=2). Go to C (d=3). Go to D (d=4). From D, edge D→A: A is GRAY (still on recursion stack). Cycle detected!

No topological ordering exists because A must come before D (A→B→C→D) AND D must come before A (D→A). This is a contradiction.

Time & Space Complexity

DFS-Based Topological Sort:
T(V,E) = Θ(V + E)
DFS visits each vertex once (Θ(V)) and examines each edge once (Θ(E)). The stack operations are O(1) per vertex.
Kahn's Algorithm:
T(V,E) = Θ(V + E)
Computing in-degrees: Θ(E). Processing vertices with in-degree 0: each vertex enqueued/dequeued once (Θ(V)), each edge examined once (Θ(E)).

Space Complexity

Adjacency list: Θ(V+E)

Color/visited array: Θ(V)

Stack/queue: Θ(V)

Result array: Θ(V)

Total auxiliary: Θ(V)

Comparison

DFS-based: Θ(V+E)

Kahn's: Θ(V+E)

Both are asymptotically optimal

Choice depends on context

Common Mistakes & Exam Tips

⛔ Common Mistake 1: Applying topological sort to a graph with cycles. Always check if the graph is a DAG first.
⚠ Common Mistake 2: Confusing topological order with DFS discovery order. Topological order uses finish times (f), not discovery times (d).
⚠ Common Mistake 3: Forgetting that topological order is reverse of finish order. The vertex that finishes last comes first.
⚠ Common Mistake 4: Assuming the topological ordering is unique. Many DAGs have multiple valid orderings.

Summary: Key Formulas

Topological Sort Condition:
Graph G must be a DAG (no directed cycles)
Equivalently: G has no back edges in DFS
DFS-Based Order:
Topological order = vertices sorted by decreasing f[v]
For any edge (u,v): f[v] < f[u], so u appears before v
Runtime:
T(V,E) = Θ(V + E)
Both DFS-based and Kahn's algorithms are optimal
