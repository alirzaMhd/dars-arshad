Adjacency Matrix Definition

An adjacency matrix represents a graph G = (V, E) with |V| = n using an n × n matrix A, where:

Adjacency Matrix — Unweighted Graph
A[i][j] = 1 if (i, j) ∈ E,   0 otherwise
For undirected graphs: A[i][j] = A[j][i] (symmetric). For directed: A[i][j] may differ from A[j][i].
Adjacency Matrix — Weighted Graph
A[i][j] = w(i, j) if (i, j) ∈ E,   ∞ or 0 otherwise
Store the edge weight directly. Use 0 or ∞ (a large sentinel) for non-edges.
Memory Complexity
Memory = Θ(n²)
Fixed size regardless of number of edges. Always n² entries.

Visual Example — Undirected Graph (n = 4)

Graph: V = {1,2,3,4}, E = { {1,2}, {1,3}, {2,3}, {3,4} }

Adjacency Matrix (symmetric):
   1 2 3 4
1: 0 1 1 0
2: 1 0 1 0
3: 1 1 0 1
4: 0 0 1 0
Common Mistake: The adjacency matrix for an undirected graph MUST be symmetric. If A[i][j] = 1, then A[j][i] must also be 1. Forgetting to set both entries is a frequent bug.

Operations on Adjacency Matrix

Operation Time Complexity How
Check adjacency (u, v) Θ(1) Look up A[u][v]
List all neighbors of u Θ(n) Scan entire row A[u][1..n]
Add edge (u, v) Θ(1) Set A[u][v] = 1 (and A[v][u] = 1 for undirected)
Remove edge (u, v) Θ(1) Set A[u][v] = 0 (and A[v][u] = 0 for undirected)
DFS/BFS traversal (entire graph) Θ(n²) Must check all n² entries to find edges
Key Insight: The adjacency matrix is ideal when the graph is dense (many edges) because the Θ(n²) memory is unavoidable, and edge checks are constant time.

Weighted Graphs with Matrix

For weighted graphs, each entry stores the weight instead of 0/1:

Weighted directed graph: 1 → 2 (w=5), 1 → 3 (w=2), 3 → 2 (w=1)

Matrix (∞ = no edge, 0 on diagonal):
   1   2   3
1: 0   5   2
2: ∞   0   ∞
3: ∞   1   0

Adjacency Lists Definition

An adjacency list representation stores, for each vertex v ∈ V, a list (or array) of all vertices adjacent to v.

Adjacency Lists — Representation
Adj[v] = list of neighbors of v (linked list or dynamic array)
For each v ∈ V, store a collection of its neighbors
Memory Complexity
Memory = Θ(n + e)
n slots for the array/header + 2e references for undirected, e references for directed

Visual Example — Same Undirected Graph (n = 4)

Graph: V = {1,2,3,4}, E = { {1,2}, {1,3}, {2,3}, {3,4} }

Adjacency Lists:
1 → [2, 3]
2 → [1, 3]
3 → [1, 2, 4]
4 → [3]
Common Mistake: For undirected graphs, each edge appears TWICE in adjacency lists — once in each endpoint's list. For directed graphs, each edge appears ONCE (in the source's list).

Operations on Adjacency Lists

Operation Time Complexity How
Check adjacency (u, v) O(deg(u)) Scan Adj[u] for v
List all neighbors of u Θ(deg(u)) Iterate over Adj[u]
Add edge (u, v) O(1) (with linked list) Push to front of Adj[u] (and Adj[v] for undirected)
Remove edge (u, v) O(deg(u)) Must find v in the list
DFS/BFS traversal Θ(n + e) Visit each vertex and each neighbor exactly once
Key Insight: Adjacency lists are memory-efficient for sparse graphs and are the most common representation for real-world graphs (social networks, web graphs, road networks).

Implementation Options

Implementation Add Edge Check Adjacency Traverse Neighbors Memory Overhead
Linked List O(1) O(deg) O(deg) High (pointer overhead)
Dynamic Array (ArrayList) O(1) amortized O(deg) O(deg) Medium
Hash Set O(1) expected O(1) expected O(deg) High
Sorted Array O(deg) O(log deg) O(deg) Low

Weighted Graphs with Lists

Each element in the adjacency list stores a pair (neighbor, weight):

Weighted directed graph: 1 → 2 (w=5), 1 → 3 (w=2), 3 → 2 (w=1)

Adjacency Lists (with weights):
1 → [(2, 5), (3, 2)]
2 → []
3 → [(2, 1)]
Note: The order of vertices in the adjacency matrix rows/columns and in adjacency lists does not matter. Any permutation of vertices yields an equivalent representation — only the adjacency relationships matter.

Comparison Table: Matrix vs Lists

Property Adjacency Matrix Adjacency Lists
Memory Θ(n²) Θ(n + e)
Check edge (u, v) Θ(1) O(deg(u))
List all neighbors of u Θ(n) Θ(deg(u))
Add edge Θ(1) Θ(1)
Remove edge Θ(1) O(deg(u))
DFS/BFS time Θ(n²) Θ(n + e)
Transpose (directed) Θ(n²) (transpose matrix) O(n + e) (build reversed lists)
Weighted graph Store weight in cell Store (neighbor, weight) pairs
Best for dense Yes No (wasted memory per vertex)
Best for sparse No (wasted memory) Yes
Guideline for Choosing Representation
If e > n² / log n, use matrix; otherwise use lists
Common heuristic: dense enough that matrix memory is worth the speed benefit

Worked Example 1: Both Representations

Example 1 — Directed Graph with n = 5

Graph: V = {1,2,3,4,5}, E = {1→2, 1→4, 2→3, 2→5, 3→1, 3→5, 4→2, 5→4}

Adjacency Matrix (5×5):

1 2 3 4 5 1: 0 1 0 1 0 2: 0 0 1 0 1 3: 1 0 0 0 1 4: 0 1 0 0 0 5: 0 0 0 1 0

Memory: 5² = 25 entries (25 bytes if byte-sized)

Adjacency Lists:

1 → [2, 4] 2 → [3, 5] 3 → [1, 5] 4 → [2] 5 → [4]

Memory: 5 references (array) + 8 edges = 13 units

Check edge (1,4): Matrix: A[1][4] = 1 → O(1). Lists: scan Adj[1] = [2,4] → found in 2 steps → O(deg(1)).

List neighbors of 5: Matrix: scan row 5 → 4 steps → O(n). Lists: Adj[5] = [4] → 1 step → O(deg(5)).

Worked Example 2: Sparse Graph Analysis

Example 2 — Social Network (Sparse)

Scenario: A social network with n = 1,000,000 users, each having ~100 friends on average. e ≈ 50,000,000 (undirected).

Metric Adjacency Matrix Adjacency Lists
Memory 1,000,000² = 10¹² ≈ 1 TB (impossible) 1,000,000 + 100,000,000 ≈ ~400 MB (feasible)
List friends of user O(n) = 1,000,000 steps O(100) steps
Check if A is friends with B O(1) O(100) expected

Conclusion: Adjacency lists are the only feasible choice for large sparse graphs.

Worked Example 3: Dense Graph Analysis

Example 3 — Complete Graph with n = 50

Scenario: K₅₀, every pair of 50 vertices is connected. |E| = 50×49/2 = 1,225 edges.

Metric Adjacency Matrix Adjacency Lists
Memory 2500 entries ≈ 2.5 KB 50 + 2×1225 = 2500 ~same
Check adjacency O(1) O(49) — slow
DFS/BFS traversal Θ(n²) = 2500 Θ(n+e) = 2500 ~same

Conclusion: For dense graphs, the matrix is often preferable due to O(1) adjacency checks and simpler implementation.

Worked Example 4: Building Representations

Example 4 — Converting Edge List to Both Representations

Problem: Given the edge list of an undirected graph: (1,5), (2,3), (2,4), (2,6), (3,5), (4,5), (5,6), with n = 6, build both representations.

Adjacency Matrix (6×6):

1 2 3 4 5 6 1: 0 0 0 0 1 0 2: 0 0 1 1 0 1 3: 0 1 0 0 1 0 4: 0 1 0 0 1 0 5: 1 0 1 1 0 1 6: 0 1 0 0 1 0

Adjacency Lists:

1 → [5] 2 → [3, 4, 6] 3 → [2, 5] 4 → [2, 5] 5 → [1, 3, 4, 6] 6 → [2, 5]

Verification: Each edge appears twice (e.g., (2,3) in Adj[2] and Adj[3]). Total list entries = 2|E| = 14. Count: 1+3+2+2+4+2 = 14 ✓

Worked Example 5: Time to Check All Edges

Example 5 — Edge Existence Check Performance

Problem: An undirected graph has n = 1000 vertices and e = 5000 edges. How long does it take to check whether every possible edge (i, j) exists? Compare for both representations.

Total possible edges: n(n−1)/2 = 1000×999/2 = 499,500

Approach Matrix Lists (naive) Lists (with hash sets)
Method Scan all n² entries For each (i,j), scan Adj[i] For each (i,j), check hash set
Time Θ(n²) = 10⁶ ∑ ∑ deg(i) ~ O(n² × avg deg) = 5000 × 10 = 5×10⁶ ≈ 499,500 hash lookups

Analysis: The matrix is competitive because scanning n² entries (10⁶) is faster than 499,500 hash lookups with overhead. The list-naive approach (5×10⁶) is the slowest.

Answer: Matrix takes ~10⁶ time units, hash-set lists ~5×10⁵, naive lists ~5×10⁶. The hash-set list wins for checking a subset of edges; matrix wins for scanning all possible edges.
