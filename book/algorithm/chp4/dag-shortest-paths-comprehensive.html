Shortest Paths in Directed Acyclic Graphs (DAGs)

A Directed Acyclic Graph (DAG) is a directed graph with no cycles. Because there are no cycles, there can never be a negative cycle, so negative edge weights are allowed without any issue.

Definition:
DAG: directed graph G = (V,E) with ∃ topological ordering
A DAG is a directed graph that can be topologically sorted (linear ordering respecting edge directions)

Key Insight

In a DAG, shortest paths can be found in linear time Θ(V+E) by processing vertices in topological order and relaxing all outgoing edges from each vertex. This is the fastest possible shortest path algorithm.

Runtime:
Θ(V + E)
Topological sort: Θ(V+E) + One pass of relaxations: Θ(E) = Θ(V+E)

Why Only One Pass Works?

  • Processing vertices in topological order guarantees that when we relax edges from vertex u, the shortest path to u has already been finalized
  • Every path from s to v goes through vertices that appear before v in topological order
  • Unlike Bellman-Ford which needs |V|-1 passes, DAG shortest paths need exactly one pass

Algorithm & Pseudocode

Algorithm Steps

  1. Topologically sort the DAG (using DFS or Kahn's algorithm)
  2. Initialize: d[s] = 0, d[v] = ∞ for all others
  3. For each vertex u in topological order:
    - For each outgoing edge (u,v) from u:
      RELAX(u,v): if d[v] > d[u] + w(u,v), update d[v] and π[v]

Pseudocode

DAG-SHORTEST-PATHS(G, W, s) 1. Topologically sort the vertices of G 2. INITIALIZE(G, s) 3. for each vertex u taken in topological order: 4. for each vertex v ∈ Adj[u]: 5. RELAX(u, v, W) INITIALIZE(G, s) 1. for each vertex v ∈ V: 2. d[v] ← ∞ 3. π[v] ← NIL 4. d[s] ← 0 RELAX(u, v, W) 1. if d[v] > d[u] + W(u, v): 2. d[v] ← d[u] + W(u, v) 3. π[v] ← u

Topological Sort Refresher

Topological sort of a DAG produces a linear ordering of vertices such that for every edge (u,v), u comes before v in the ordering.

Topological Sort (DFS-based):
Run DFS; output vertices in reverse order of finish times f[v]
The vertex with the largest finish time is placed first in topological order
Topological Sort (Kahn's algorithm):
Repeatedly remove vertices with in-degree = 0
Also Θ(V+E) — uses a queue of zero-indegree vertices
Warning! The DAG shortest path algorithm only works on DAGs. If the graph has cycles, the shortest paths may be incorrect because a later vertex in topological order might have an edge back to an earlier one (which would be ignored).

Exam Tip: This example shows that DAG shortest paths can handle negative edges naturally. Bellman-Ford also handles them but is slower. Dijkstra would fail on this graph.

Key point: The topological order placing p,q,r before s does not mean they are reachable from s. The relaxation of edge (r,s) does not establish a path from s to r. The algorithm only computes distances from s, not to s.

Practice & Edge Cases

Key Properties & Intuition

Correctness Invariant:
When processing u in topological order, d[u] = δ(s,u)
The distance to u is already the shortest possible distance, because all predecessors of u have already been processed
Path Bound in DAG:
maximum |V| - 1 edges in any path ≤ |V| - 1
The longest simple path in a DAG has at most V-1 edges (no cycles)

Edge Cases

Edge Case 1: Source Not First in Topological Order

If the source s is not the first vertex in topological order, vertices that appear before s will have d = ∞ when processed. Their relaxations may set distances for other pre-s vertices but will never affect distances from s because there is no path from s to vertices appearing before it in topological order.

This is handled naturally: the algorithm still works correctly. Pre-s vertices remain at ∞ (unreachable from s).

Edge Case 2: DAG with All Negative Weights

Even if all edges have negative weights, the algorithm works correctly. Consider a DAG with edges: (s,a)=-2, (a,b)=-3, (b,c)=-1. Topological order: s, a, b, c.

Processing: s: d[a]=-2, a: d[b]=-5, b: d[c]=-6.

Final: s:0, a:-2, b:-5, c:-6

All distances are negative except the source. This is perfectly valid.

Edge Case 3: Disconnected DAG

A DAG may have multiple components all unreachable from the source. The distances for vertices in other components remain at ∞. No problem — the algorithm processes them but their d values stay ∞.

Edge Case 4: Source with No Outgoing Edges

If the source has no outgoing edges, the algorithm just initializes d[s]=0 and all others stay at ∞. No relaxations occur from s. Result: only s is reachable.

Common Mistakes

Mistake 1: Applying DAG-SP to a graph that is not a DAG. If the graph has cycles, the topological ordering does not exist, and the algorithm fails.
Mistake 2: Thinking DAG-SP cannot handle negative edges. It can! Since there are no cycles, there cannot be negative cycles, so negative edges are perfectly safe.
Mistake 3: Forgetting that topological sort is required as a first step. The algorithm does not work without it.
Mistake 4: Confusing Θ(V+E) with O(V+E). The DAG-SP algorithm processes every vertex and every edge exactly once, so it's Θ(V+E), not just O(V+E).
Mistake 5: Thinking the topological sort contributes extra complexity. Topological sort is also Θ(V+E), so the total remains Θ(V+E).
