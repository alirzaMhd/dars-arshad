Strongly Connected Components (SCC)

Kosaraju's Algorithm | Complete Guide for 20/20 Exam

Definition

A strongly connected component (SCC) of a directed graph G = (V, E) is a maximal set of vertices C ⊆ V such that for every pair of vertices u, v ∈ C, both u is reachable from v AND v is reachable from u.

SCC Mutual Reachability Condition:
u →* v   AND   v →* u     ∀ u,v ∈ C
For any two vertices in the same SCC, there must be directed paths in both directions

Properties

• SCCs partition the vertex set

• Each SCC is maximal

• Component graph GSCC is a DAG

• Every vertex belongs to exactly one SCC

Real-World Applications

• Web graph analysis (link structure)

• Social network communities

• Program call graph optimization

• Circuit analysis & verification

Equivalence Relation

Define relation R on vertices: u R v iff u is reachable from v and v is reachable from u. R is an equivalence relation:

PropertyDefinitionProof
Reflexiveu R uEvery vertex can reach itself (path of length 0)
SymmetricIf u R v then v R uBy definition of R
TransitiveIf u R v and v R w then u R wConcatenate paths: u→v→w and w→v→u

The equivalence classes of R are precisely the strongly connected components.

Why Component Graph is a DAG

Proof by Contradiction:

Suppose GSCC had a cycle C1 → C2 → ... → Ck → C1. Then for any u ∈ Ci, v ∈ Cj:

• u can reach v (follow cycle edges + internal paths)

• v can reach u (go the other way around)

Thus all vertices in ∪Ci are mutually reachable → they form one larger SCC, contradicting maximality of each Ci. Hence GSCC has no cycles.

Kosaraju's Algorithm Outline

Three phases:

  1. Pass 1: Run DFS on G, record finish times f[v] for each vertex
  2. Transpose: Compute GT by reversing all edges of G
  3. Pass 2: Run DFS on GT in decreasing order of f[v]. Each DFS tree = one SCC
Transpose Graph Definition:
GT = (V, ET)   where   ET = {(v,u) : (u,v) ∈ E}
G and GT have the same SCCs, but the direction of edges between SCCs is reversed

Pseudocode

KosarajuSCC(G): // Pass 1: DFS on G to compute finish times for each u ∈ G.V: u.color = WHITE time = 0 finishStack = ∅ for each u ∈ G.V: if u.color == WHITE: DFS-Finish(G, u, time, finishStack) // Compute transpose graph GT = Transpose(G) // Reset colors for each u ∈ G.V: u.color = WHITE sccId = 0 // Pass 2: DFS on G^T in decreasing finish time while finishStack ≠ ∅: u = finishStack.pop() if u.color == WHITE: sccId = sccId + 1 component = ∅ DFS-Collect(GT, u, component) print("SCC", sccId, ":", component) return sccId DFS-Finish(G, u, time, stack): u.color = GRAY time = time + 1 u.d = time for each v ∈ G.Adj[u]: if v.color == WHITE: DFS-Finish(G, v, time, stack) u.color = BLACK time = time + 1 u.f = time stack.push(u) DFS-Collect(GT, u, comp): u.color = GRAY comp.add(u) for each v ∈ GT.Adj[u]: if v.color == WHITE: DFS-Collect(GT, v, comp) u.color = BLACK

Why It Works — Key Lemma

Highest Finish Time Property:
The SCC with the maximum finish time in a DFS of G has no outgoing edges to any other SCC
This SCC is a source component in GSCC (no incoming edges from other SCCs). When edges are reversed (GT), it becomes a sink component (no outgoing edges), so DFS on GT cannot leave it.

Intuition

1. Pass 1 orders SCCs: source components finish last

2. GT reverses edges between SCCs

3. Processing highest f first = processing sources first

4. In GT, these become sinks → DFS stays inside

Formal Justification

For SCCs C and C' with edge C→C' in GSCC:

• max f[C] > max f[C']

• In GT, edge is C'→C

• Processing C first, DFS cannot reach C'

• Each DFS tree in GT = exactly one SCC

Theorem: SCC Ordering

Finish Time Ordering of SCCs:
If there is an edge (u,v) in G where u ∈ C, v ∈ C', and C ≠ C', then max f[C] > max f[C']
The maximum finish time in the source SCC is always greater than the maximum finish time in the destination SCC

Component Graph Construction

Given SCCs C1, C2, ..., Ck, the condensation (component graph) GSCC = (VSCC, ESCC) is:

Component Graph:
VSCC = {C1, C2, ..., Ck}
ESCC = {(Ci, Cj) : i ≠ j and ∃ u∈Ci, v∈Cj with (u,v)∈E}
Edge between SCCs if any vertex in one has an edge to a vertex in the other (excluding self-loops)
⚠ Important: GSCC is always a DAG. This follows from the maximality of SCCs — a cycle in GSCC would merge all SCCs in the cycle into one.

Common Mistakes

⚠ Mistake 1: Thinking that an undirected graph's connected components are the same as SCCs. In undirected graphs, connectivity is simpler (just one undirected connection). SCCs are specifically for directed graphs.
⚠ Mistake 2: Forgetting to reset colors between Pass 1 and Pass 2 of Kosaraju. Pass 2 requires all vertices to be WHITE initially.
⚠ Mistake 3: Confusing transpose with complement. Transpose GT reverses every edge. Complement G' has edges where G does not.
⚠ Mistake 4: Thinking a single vertex without self-loops cannot be an SCC. Every single vertex forms a trivial SCC (since a vertex can reach itself by a path of length 0).
