Articulation Points & Bridges

Cut Vertices and Cut Edges in Undirected Graphs | Complete Guide for 20/20 Exam

Definition

An articulation point (or cut vertex) in an undirected graph is a vertex whose removal increases the number of connected components of the graph.

Articulation Point Condition:
vertex v is an articulation point ⇔ comp(G - {v}) > comp(G)
Removing v increases the number of connected components
Intuitive Example

In a tree, every non-leaf vertex is an articulation point. Removing any internal vertex splits the tree into multiple components.

A --- B --- C --- D | | E F

Here, B and C are articulation points. Removing B disconnects E from the rest. Removing C disconnects D and F. A, D, E, F are leaves (not articulation points).

Properties

Key Facts

• A leaf in a tree is never an articulation point

• Root of DFS tree with ≥2 children is an articulation point

• A biconnected graph has no articulation points

• Every 2-connected graph has ≥2 vertex-disjoint paths

Applications

• Network reliability analysis

• Finding critical servers/routers

• Power grid vulnerability assessment

• Social network influence analysis

DFS-Based Detection Rules

During a DFS traversal (building a DFS tree with discovery times disc[]):

Rule 1 — Root of DFS Tree:
root is an articulation point ⇔ root has ≥ 2 children in the DFS tree
Multiple children of the root are disconnected from each other (no cross edges in undirected DFS)
Rule 2 — Non-Root Vertex:
u (non-root) is an articulation point ⇔ ∃ child v such that low[v] ≥ disc[u]
No back edge from v's subtree reaches a proper ancestor of u. Removing u disconnects v's subtree.

Definition

A bridge (or cut edge) in an undirected graph is an edge whose removal increases the number of connected components of the graph.

Bridge Condition:
edge e is a bridge ⇔ comp(G - {e}) > comp(G)
Removing e increases the number of connected components
Intuitive Example
A --- B --- C --- D | | E F

Here, A—B and C—D are bridges. Removing A—B disconnects A. Removing C—D disconnects D (and F).

But B—C is NOT a bridge — even after removing it, B can reach C via B—E—??? No, E is only connected to B. So B—C is a bridge too!

Actually in this graph: Every edge is a bridge because the original graph is a tree. In a tree, every edge is a bridge.

Bridge Detection Rule

Bridge Detection (DFS-based):
edge (u,v) is a bridge ⇔ low[v] > disc[u]
If v is a child of u in the DFS tree, and no back edge from v's subtree reaches u or any ancestor of u, then (u,v) is a bridge. Strict inequality: low[v] == disc[u] means a back edge reaches u, so (u,v) is NOT a bridge.
⚠ Important: For articulation points, the condition is low[v] ≥ disc[u]. For bridges, the condition is low[v] > disc[u]. The difference is subtle but critical:
  • low[v] ≥ disc[u]: v's subtree cannot reach above u → u is articulation point
  • low[v] > disc[u]: v's subtree cannot reach u or above → edge (u,v) is a bridge

Properties of Bridges

Key Facts

• A bridge is always a tree edge in DFS (back edges can never be bridges)

• Every edge in a tree is a bridge

• If an edge is on a cycle, it cannot be a bridge

• A graph with no bridges is 2-edge-connected

Bridges vs Articulation Points

• Not every bridge endpoint is an articulation point

• Example: leaf of a bridge may not be articulation point

• Graphs can have bridges without articulation points (cycle + pendant tree)

Low-Link Values: Definition

The low-link value low[v] is the smallest discovery time reachable from v using the DFS tree edges and at most one back edge.

Low-Link Value Definition:
low[v] = min{ disc[v], disc[w] : ∃ back edge (x,w) where x is in the subtree of v }
The earliest-discovered vertex reachable from v through its subtree and at most one back edge
Low-Link Update Rule:
low[v] = min( disc[v], min{ low[child] }, min{ disc[ancestor] where (v,ancestor) is a back edge } )
For tree edge (v,child): low[v] = min(low[v], low[child]). For back edge (v,ancestor): low[v] = min(low[v], disc[ancestor]).

Example 3: Graph with Both AP and Bridge

Graph: A --- B --- C --- D | | E F --- G

Edges: A-B, B-C, C-D, B-E, C-F, F-G

Also add: C—F back to make it interesting. Actually no C—F is already there. Let's add a cycle: F—B to create a cycle B-C-F-B.

With added edge F—B:
A --- B --- C --- D | \ | | \ | E F --- G

Edges: A-B, B-C, C-D, B-E, C-F, F-G, B-F

Now B-C-F-B is a triangle cycle. Edges in the cycle cannot be bridges.

Bridges: A-B (only path to A), B-E (only path to E), C-D (only path to D), F-G (only path to G).

Articulation points:

  • B: Removing B disconnects A and E from {C,D,F,G}.
  • C: Removing C disconnects D from {A,B,E,F,G}.
  • F: Removing F disconnects G from {A,B,C,D,E}.

So B, C, F are articulation points. A, D, E, G are not.

Note: Bridge endpoints B (A-B, B-E) and C (C-D) and F (F-G) are articulation points. But A (end of bridge A-B) is not an AP because removing A only removes A itself.

Example 4: Graph with Cycles (No Bridges)

Graph: A --- B | \ | | \ | C --- D

Edges: A-B, A-C, A-D, B-D, C-D

Every edge is on at least one cycle. No bridges exist.

Is there any articulation point? Removal of A leaves B-C-D triangle intact (B-D, C-D, and... B-C? No, no direct B-C edge. So B-C connectivity: B can reach C via B-D-C. After removing A, B, C, and D remain connected via B-D-C. So A is an articulation point? Let's check: removing A, can each vertex still reach every other? B→D→C works. So removal of A leaves one component {B,C,D}. A is NOT an articulation point!

Actually, since the graph is the complete graph K4 minus edge B-C, every vertex has degree 3 except... Let me check B: connected to A and D. C: connected to A and D. A: B, C, D. D: A, B, C. Removing A: B—D—C stays connected. All other vertices: removing any non-A vertex leaves A connected to the rest via at least 2 other paths. So no articulation points!

This shows: a graph can have no articulation points and no bridges (2-connected and 2-edge-connected).

Time & Space Complexity

DFS-Based Detection:
T(V,E) = O(V + E)
Single DFS traversal. Each vertex visited once, each edge examined once. Low-link values computed during backtracking.

Space Complexity

disc[]: O(V)

low[]: O(V)

parent[]: O(V)

Recursion stack: O(V)

Adjacency list: O(V+E)

Runtime Breakdown

DFS traversal: O(V+E)

Low computation: O(1) per edge

Cut checks: O(1) per vertex

Overall: O(V+E)

Common Mistakes

⛔ Mistake 1: Using &≥ instead of > for bridge detection. Bridges require low[v] > disc[u] (strict inequality). If low[v] == disc[u], a back edge reaches u, so (u,v) is not a bridge.
⚠ Mistake 2: Forgetting to check the root separately. The root of the DFS tree is an articulation point only if it has ≥2 children in the DFS tree (not the original graph).
⚠ Mistake 3: Confusing disc[u] with low[u] in the conditions. The condition for articulation points is low[child] ≥ disc[u], not low[u] ≥ disc[parent].
⚠ Mistake 4: In back edge handling, using low[v] instead of disc[v] when updating low[u]. The formula is: low[u] = min(low[u], disc[v]) for back edge (u,v), NOT low[u] = min(low[u], low[v]).
⚠ Mistake 5: Treating the edge to parent as a back edge. In undirected DFS, we must skip the immediate parent when checking for back edges, otherwise low[u] would always be set to disc[parent] = disc[u]-1.

Summary: Key Formulas

Low-Link Value:
low[v] = min( disc[v], min{low[child]}, min{disc[w] : (v,w) is a back edge} )
Articulation Point (non-root):
∃ child v of u : low[v] ≥ disc[u]
Articulation Point (root):
root has ≥ 2 children in the DFS tree
Bridge:
(u,v) is a bridge ⇔ low[v] > disc[u] (where v is child of u)
Runtime:
O(V + E)  —  single DFS pass
