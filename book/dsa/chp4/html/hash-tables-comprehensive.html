What is a Hash Table?

When the universe of keys U is large, direct addressing becomes impractical. Hash tables use a hash function to compute an index into an array of slots, from which the desired value can be found.

Hash Function:
h: U → {0, 1, ..., m-1}
Maps keys from universe U to slots in table T[0..m-1]
Storage:
Store element with key k in slot h(k)
T[h(k)] contains the element with key k
Satellite Data:
Each element contains: key + satellite data
Key is used for search/storage; satellite data is the actual information (e.g., name, grades, etc.)
Hash tables can only store one element per slot. When two keys hash to the same slot, a collision occurs.
Example: Satellite Data Storage

Keys are student IDs (could be large numbers), but we only need to store 100 students.

Universe U = {0, 1, ..., 999999999}

Table size m = 100

Hash function: h(k) = k mod 100

Student ID 25 → slot 25

Student ID 10003 → slot 3

Hash Functions

Division Method

Formula:
h(k) = k mod m
m should not be a power of 2 (choose prime not close to power of 2)

Multiplication Method

Formula:
h(k) = ⌊m(kA mod 1)⌋
A is a constant (0 < A < 1), often A ≈ (√5 - 1)/2 ≈ 0.618

Mid-Square Method

Formula:
h(k) = middle digits of k²
Square the key, extract middle r digits as the hash value

Folding Method

Formula:
h(k) = sum of digits of k (split into equal parts)
Split key into equal parts, add them together

Collision

A collision occurs when two different keys hash to the same slot: h(k₁) = h(k₂) but k₁ ≠ k₂.

Example: Collision

Hash function: h(k) = k mod 7

Keys: 25 and 5

h(25) = 25 mod 7 = 4

h(5) = 5 mod 7 = 5

No collision here. But if we had keys 25 and 32:

h(25) = 25 mod 7 = 4

h(32) = 32 mod 7 = 4

Collision! Both keys map to slot 4

Collision resolution is essential for hash table performance. Two main approaches: Chaining and Open Addressing.

Worked Examples

Example 1: Simple Hash Table

Keys: {12, 25, 37, 48}, Table size m = 10

Hash function: h(k) = k mod 10

h(12) = 2, h(25) = 5, h(37) = 7, h(48) = 8

T[2]=12, T[5]=25, T[7]=37, T[8]=48

Example 2: Multiple Keys Same Slot

Keys: {10, 24, 38}, Table size m = 7

Hash function: h(k) = k mod 7

h(10) = 3, h(24) = 3, h(38) = 3

All three keys hash to slot 3!

Need collision resolution (chaining or open addressing)

Example 3: Mid-Square Hashing

Key: 4321, Table size: 100 (2 digits)

k² = 4321² = 18671041

Take middle 2 digits: 67

h(4321) = 67

Example 4: Division Method Choice

Want to store ~1000 elements

Choose m = 1007 (prime, not near power of 2)

Hash function: h(k) = k mod 1007

Good choice because 1007 is prime

Example 5: Multiplication Method

Key: 12345, m = 1000, A = 0.6180339887

k × A = 12345 × 0.6180339887 = 7628.999...

0.999... × 1000 = 999

h(12345) = 999

Complexity Analysis

Average Case

Insert: O(1)

Search: O(1)

Delete: O(1)

Worst Case

Insert: O(n)

Search: O(n)

Delete: O(n)

Load Factor:
α = n/m
n = number of elements, m = number of slots

When to Use Hash Tables

Scenario Recommendation
Small universe, all keys used Direct Addressing
Large universe, few keys Hash Table
Need ordered operations BST or Balanced BST
Memory constrained Hash Table with good α
