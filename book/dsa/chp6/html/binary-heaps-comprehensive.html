BINARY HEAPS & HEAPSORT

Data Structures — Complete Guide for 20/20 Exam

Before You Begin — The Absolute Basics

If you have never studied binary heaps (or trees, or arrays), start here. We will build up from scratch using simple analogies. Everything you need is right here — no prior knowledge assumed.

1. What is a "Tree" in Computer Science?

A tree is a structure where items (called nodes) are connected by links (called edges). It is called a tree because it branches — one item at the top (the root) connects to items below it, which connect to more items below them, and so on.

Analogy: A Family Tree

Think of a family tree. One ancestor at the top (the root) has children. Each child can have their own children. The tree keeps branching downward. In computer science, we actually draw trees upside down — the root is at the top and the "leaves" (nodes with no children) are at the bottom.

      Grandparent     ← root (the top)
       /       \
   Parent1   Parent2   ← children of Grandparent
   /    \      /   \
Child1 Child2 C3   C4   ← leaves (no children below)

2. What is a Binary Tree?

"Binary" means "two". In a binary tree, each node can have at most 2 children — a left child and a right child. Some nodes may have 0, 1, or 2 children.

Analogy: A Tournament Bracket

In a sports tournament, each match pits two players against each other. One match (the parent) leads to the next round. Each match has exactly two participants (the children). That is like a binary tree — every node connects to at most two nodes below it.

            A              ← parent of B and C, child of nobody (root)
           / \
          B   C            ← children of A; B is also a parent
         / \
        D   E              ← children of B; D and E are leaves (no children)

A has two children (B and C). B has two children (D and E). C has no children — it is a leaf.

3. What is a Complete Binary Tree?

A complete binary tree is a binary tree where every row (level) is completely filled, except possibly the last row. The last row must be filled from left to right with no gaps.

Analogy: A Theater with Rows of Seats

Imagine a theater. Every row of seats is completely full except maybe the back row. In the back row, people sit starting from the leftmost seat and fill toward the right. No one leaves an empty seat in the middle of a row. That is a "complete" theater — and it is exactly how a complete binary tree works.

Complete ✓ (every level fully filled) 
          1
         / \
        2   3
       / \ / \
      4  5 6  7
Complete ✓ (last level filled left to right) 
          1
         / \
        2   3
       / \ / \
      4  5 6  _     ← 6 is filled before leaving 7 empty
Not Complete ✗ (gap on left side of last level) 
          1
         / \
        2   3
       / \ / \
      _  5 6  7    ← the leftmost spot is empty — violates rule!
Why does completeness matter? A complete binary tree can be stored in a plain array with no wasted space. The array indices line up perfectly with tree positions. This is the core trick that makes binary heaps efficient.

4. What is an Array?

An array is simply a numbered list of storage slots. Think of a row of numbered mailboxes:

Index:   1    2    3    4    5    6    7
       ┌────┬────┬────┬────┬────┬────┬────┐
Value: │ 10 │ 5  │ 8  │ 2  │ 7  │ 3  │ 1  │
       └────┴────┴────┴────┴────┴────┴────┘

We write A[3] = 8 to mean "at index 3, the value stored is 8".

In binary heaps, we usually start counting from index 1 (not index 0). Index 0 is left unused (a "sentinel" or placeholder).

5. Tree Vocabulary — The Family Terms

Root

The topmost node (always at index 1). Has no parent. The "grandparent" of the whole tree.

Parent

A node that has children below it. Found at index floor(i/2).

Child

A node directly below another node. Left child at index 2i, right child at 2i+1.

Leaf

A node with no children (at the bottom). Leaves are indices floor(n/2)+1 through n.

Internal Node

A node that has at least one child. Indices 1 through floor(n/2).

Height

The number of levels in the tree. Equals floor(lg n). A tree with 10 nodes has height 3.

6. What is Height (Levels)?

The height of a tree is the number of rows (levels) it has, counting from 0 at the root.

  • Level 0: just the root node (1 node)
  • Level 1: at most 2 nodes
  • Level 2: at most 4 nodes
  • Level h: at most 2h nodes
Height = 2 (3 levels, counting from 0)
           1             ← level 0
          / \
         2   3           ← level 1
        / \ / \
       4  5 6  7         ← level 2 (leaf level)

A tree with n nodes has height floor(lg n). For n=7: floor(lg 7) = floor(2.8) = 2.

7. What Does "lg n" Mean?

lg n means "log base 2 of n". It answers: "How many times can I divide n by 2 before reaching 1?"

Step-by-step examples:

n = 8: 8 → 4 → 2 → 1 (three divisions) → lg 8 = 3

n = 16: 16 → 8 → 4 → 2 → 1 (four divisions) → lg 16 = 4

n = 10: 10 → 5 → 2.5 → 1.25 (about 3.32 divisions) → lg 10 ≈ 3.32, floor(lg 10) = 3

Why logarithms matter for heaps: The height of a heap with n nodes is floor(lg n). This means when n doubles (from 1000 to 2000 nodes), the height only increases by 1. Heap operations travel from root to a leaf (or leaf to root), so they take at most (height + 1) steps. That is why heap operations are so fast — the number of steps grows very slowly as the data grows.

8. What is Big O Notation?

Big O describes how much time an operation takes as the input size (n) grows. Think of it as the "growth rate" of the work needed:

  • O(1) — "Constant time". Takes the same amount of work no matter how large n is. Like checking the first mailbox — instant, always.
  • O(lg n) — "Logarithmic time". Grows very slowly. Doubling n adds just 1 extra step. Heap operations are usually O(lg n).
  • O(n) — "Linear time". If n doubles, the work doubles. Like looking at every mailbox one by one.
  • O(n lg n) — "Linearithmic time". Slightly more than linear. Heapsort runs in O(n lg n) time — as good as sorting gets.
  • O(n²) — "Quadratic time". If n doubles, work quadruples. Slow. Bubble sort is O(n²).
Growth comparison (n = 1 million):

O(1) → 1 operation (instant)

O(lg n) → about 20 operations (very fast)

O(n) → 1,000,000 operations (moderate)

O(n lg n) → about 20,000,000 operations (reasonable)

O(n²) → 1,000,000,000,000 operations (impractical!)

9. What is a "Heap" in Simple Terms?

A binary heap is a complete binary tree stored in an array, with one special rule:

  • Max-heap rule: Every parent is ≥ its children. The biggest value sits at the root (top).
  • Min-heap rule: Every parent is ≤ its children. The smallest value sits at the root (top).
Analogy: A Company Hierarchy

Think of a company. In a max-heap, the CEO (root) earns the most. Every manager earns at least as much as their direct reports. The rule flows down: each parent ≥ each child. This makes it easy to find the highest salary — it is always at the CEO's desk (index 1).

Binary Heap Definition

A binary heap is a complete binary tree that satisfies the heap property. It is typically implemented as an array.

Complete Binary Tree:
Every level is fully filled, except possibly the last level, which is filled from left to right.
This ensures the tree can be represented efficiently as an array with no gaps.

Min-Heap Property

Min-Heap:
A[parent(i)] ≤ A[i] for all nodes i (except root)
Every parent node is less than or equal to its children. The minimum element is always at the root.

Max-Heap Property

Max-Heap:
A[parent(i)] ≥ A[i] for all nodes i (except root)
Every parent node is greater than or equal to its children. The maximum element is always at the root.
Key Distinction: Min-heap → minimum at root, Max-heap → maximum at root. The heap property applies to all parent-child relationships, not just siblings.
Beginner Tip: Think of it as a Family Rule

Imagine a family where the rule is: "Every parent must be older than their children." That is a max-heap (parent ≥ children). The oldest person (maximum value) is always at the top of the family tree (the root). If the rule was "every parent must be younger than their children", that would be a min-heap (parent ≤ children), and the youngest person (minimum value) would be at the root.

This rule flows down the entire tree. A grandparent must be older than their children AND their grandchildren. Every parent follows the rule with their own children. But two siblings can be in any order — the rule does not apply between siblings.

Min-Heap Example:
        1
       / \
      3   2
     / \ / \
    7  4 5  6
Parent ≤ Children: 1≤3, 1≤2, 3≤7, 3≤4, 2≤5, 2≤6 ✓
Max-Heap Example:
        7
       / \
      6   5
     / \ / \
    3  4 2  1
Parent ≥ Children: 7≥6, 7≥5, 6≥3, 6≥4, 5≥2, 5≥1 ✓

Array Representation

A binary heap is stored as an array. Level-order traversal gives the array indices.

Tree:          1
             /   \
            2     3
           / \   / \
          4   5 6   7

Array: [_, 1, 2, 3, 4, 5, 6, 7]
Index:   1  2  3  4  5  6  7
Parent of node at index i (1-indexed):
parent(i) = ⌊i/2⌋
For i = 2,3,...,n. The root at index 1 has no parent.
Left child of node at index i:
left(i) = 2i
For i = 1,2,...,⌊n/2⌋. Returns 0 or >n if no left child exists.
Right child of node at index i:
right(i) = 2i + 1
For i = 1,2,...,⌊n/2⌋. Returns 0 or >n if no right child exists.
0-indexed arrays: If using 0-indexed arrays: parent(i) = ⌊(i-1)/2⌋, left(i) = 2i+1, right(i) = 2i+2. Most textbooks (CLRS) use 1-indexed.
Beginner Tip: How to Memorize the Formulas

The formulas come from how a complete binary tree fills up level by level:

Left child = 2 × parent: When you double the index, you jump to the next "row" of the tree, landing on the left side.

Right child = 2 × parent + 1: Same as left child, but one spot to the right.

Parent = floor(i / 2): To go up one level, divide by 2 and round down. This reverses the child formulas.

Try it on paper: Draw a tree of 7 nodes, label each node 1-7 in level order. Now check: is node 1's left child at 2×1=2? Is its right child at 2×1+1=3? Yes! Works every time.

Heap Size vs Array Length

Critical Distinction: heap-size (or heap.length) is the number of elements currently in the heap. array.length is the total allocated size of the array. heap-size ≤ array.length always.
Relationship:
1 ≤ heap-size ≤ array.length
When heap-size = array.length, the heap uses all array slots. Operations only access A[1..heap-size].
Example: Heap Size Management

Array A has length 10. Initially heap-size = 10 (full heap).

After HEAPSORT extracts 3 elements: heap-size = 7.

Extracted elements occupy A[8], A[9], A[10] (sorted in ascending order).

Active heap: A[1..7]

MAX-HEAPIFY Operation

Restores the max-heap property at index i, assuming the subtrees at left(i) and right(i) are already max-heaps.

Precondition:
left(i) and right(i) are valid max-heaps, but A[i] may be smaller than children
MAX-HEAPIFY lets A[i] "float down" to its correct position.
Beginner Tip: The "Sink Down" Analogy

Imagine a group of people standing in a pyramid formation (like a human pyramid). The rule is: the tallest person must be at the top. But someone short is standing at the top right now.

MAX-HEAPIFY is the process of fixing this: look at the person at the top and their two neighbors below. Who is the tallest among the three? If it is not the person at the top, swap them. Now the tallest of those three is at the top. But the person who got swapped down might still be shorter than people below them. So repeat: compare them with their new neighbors below, swap if needed, and keep going until the rule is satisfied. The short person "sinks down" level by level until they find their proper place.

This is exactly what MAX-HEAPIFY does — it takes one "out-of-place" element and sinks it down to its correct position.

Pseudocode

MAX-HEAPIFY(A, i) l ← left(i) r ← right(i) largest ← i if l ≤ A.heap-size and A[l] > A[i] largest ← l if r ≤ A.heap-size and A[r] > A[largest] largest ← r if largest ≠ i exchange A[i] ↔ A[largest] MAX-HEAPIFY(A, largest)
Complexity:
Time: O(lg n) — at most 2 comparisons per level, height = ⌊lg n⌋
Space: O(lg n) recursive, O(1) iterative. Each call moves one level down the tree.
Example: MAX-HEAPIFY on A[2]

Array: [_, 16, 4, 10, 14, 7, 9, 3, 2, 8, 1]

Step 0:      16              ← A[2]=4 violates max-heap
            /  \
          [4]   10          ← 4 < 14 and 4 < 7
         /  \  /  \
        14  7  9   3
       / \ / \
      2  8 1  -

l=4 (A[4]=14), r=5 (A[5]=7). largest = 4 (since 14 > 4 and 14 > 7).

Exchange A[2]=4 ↔ A[4]=14. Recurse on i=4.

Step 1:      16
            /  \
         [14]   10         ← 4 now at index 4
         /  \  /  \
       [4]  7  9   3       ← 4 < 2? No. 4 < 8? Yes.
       / \ / \
      2  8 1  -

l=8 (A[8]=2), r=9 (A[9]=8). largest = 9 (since 8 > 4 and 8 > 2).

Exchange A[4]=4 ↔ A[9]=8. Recurse on i=9 (leaf). Done.

Final:       16
            /  \
          14   10
         /  \ /  \
        8   7 9   3
       / \ / \
      2  4 1  -
Example 2: Single Swap Case

Array: [_, 20, 15, 8, 10, 5, 3]

        20
       /  \
     [15]   8
     / \   /
   10  [5] 3

MAX-HEAPIFY(A, 2): l=4(A[4]=10), r=5(A[5]=5). largest=4 (10 > 15? No, 10 > 5? Yes, but 15 > 10).

Wait: A[2]=15, A[4]=10, A[5]=5. 15 > 10 and 15 > 5 → no swap needed. Heap property already holds.

Key Insight

MAX-HEAPIFY sifts down one element. At each step: compare parent with two children, swap with largest, repeat.

Why O(lg n)?

Height of heap = ⌊lg n⌋. Each recursive call moves one level down. Maximum recursion depth = height.

BUILD-MAX-HEAP

Converts an arbitrary array into a max-heap.

Method 1: Repeated Insertion

BUILD-MAX-HEAP-INSERT(A) A.heap-size ← 1 for i ← 2 to A.length do MAX-HEAP-INSERT(A, A[i])
Complexity (Method 1):
O(n lg n) — n insertions, each O(lg n)
Each INSERT sifts up the element, worst case O(lg n) per insertion.

Method 2: Bottom-Up Construction (Optimal)

BUILD-MAX-HEAP(A) A.heap-size ← A.length for i ← ⌊A.length/2⌋ downto 1 do MAX-HEAPIFY(A, i)
Complexity (Method 2):
O(n) — Linear time!
Process internal nodes from bottom to top. Most nodes are near the bottom with small heights.
Why O(n) and not O(n lg n)? Most nodes have small height. A node of height h has at most ⌈n/2^(h+1)⌉ nodes. Sum: Σ(h=0 to lg n) h·n/2^(h+1) = O(n).
Beginner Intuition: Why Bottom-Up is Fast

Imagine you are organizing a stack of papers. You could do it top-down: start at the top and fix each paper one by one, but every time you fix one, you might mess up papers below, so you have to re-fix them too. That is slow (O(n lg n)).

Now try bottom-up: start at the bottom (the leaves — papers with nothing below them). Leaves already follow the rule (they have no children to compare with). Move up one level: now each paper only has to fix things below it, and once fixed, the layer above can rely on it staying fixed. You work your way up to the root, fixing each layer once, building on the already-correct layers below. Most of the work happens near the bottom where the tree is widest, so the total work is O(n), not O(n lg n).

Example 1: Build Max-Heap (Method 2)

Array: [_, 4, 1, 3, 2, 16, 9, 10, 14, 8, 7]

n = 10, process i = 5, 4, 3, 2, 1 (internal nodes from bottom up)

i=5: A[5]=16. Children: A[10]=7. 16 > 7 → no change.

i=4: A[4]=2. Children: A[8]=14, A[9]=8. largest=8. Swap 2↔14.

i=3: A[3]=3. Children: A[6]=9, A[7]=10. largest=7. Swap 3↔10.

i=2: A[2]=1. Children: A[4]=14, A[5]=16. largest=5. Swap 1↔16. Recurse...

i=1: A[1]=4. Children: A[2]=16, A[3]=10. largest=2. Swap 4↔16. Recurse...

Final max-heap: [_, 16, 14, 10, 8, 7, 9, 3, 2, 4, 1]

Example 2: Why Bottom-Up is O(n)

n = 7 nodes. Heights of nodes:

        h=2         1            ← 1 node of height 2
       / \
      h=1  h=1     2, 3         ← 2 nodes of height 1
     / \  / \
    h=0 h=0 h=0 h=0  4,5,6,7    ← 4 nodes of height 0

Sum = 1×2 + 2×1 + 4×0 = 4 operations. For n=7: 2+2+0+0+0+0+0 = 4.

This is O(n), not O(n lg n).

Method Algorithm Time Complexity When to Use
Method 1 Repeated INSERT O(n lg n) When elements arrive one at a time
Method 2 Bottom-up HEAPIFY O(n) When all elements available upfront (preferred)

HEAPSORT Algorithm

Sorts an array in ascending order using a max-heap.

HEAPSORT(A) BUILD-MAX-HEAP(A) for i ← A.length downto 2 do exchange A[1] ↔ A[i] A.heap-size ← A.heap-size - 1 MAX-HEAPIFY(A, 1)
Complexity:
Time: O(n lg n) — BUILD-MAX-HEAP O(n) + n-1 extractions each O(lg n)
Space: O(1) — in-place sorting. Stable: No.
How it works: After BUILD-MAX-HEAP, the largest element is at A[1]. Swap it to A[n] (its final position). Reduce heap size and restore heap property. Repeat until sorted.
Beginner Tip: The "Pick the Biggest, Put It at the End" Strategy

Heapsort uses a simple strategy that you use every day:

1. Look at your items. Find the biggest one. (With a max-heap, the biggest is always right at the top — easy!)
2. Put the biggest item at the end of your list — it is done, in its final position.
3. Now you have a smaller list (everything before that last item). But the heap property might be broken at the top. Fix it with one MAX-HEAPIFY.
4. Repeat: find the new biggest (again at the top), put it just before the already-sorted items at the end, fix the heap, repeat.

Each round, the sorted section at the end grows by one, and the heap section shrinks by one. After n-1 rounds, everything is sorted. It is like repeatedly picking the largest unsorted item and moving it to where it belongs.

Example: HEAPSORT Step by Step

Input: [_, 4, 1, 3, 2, 16, 9, 10]

Step 1: BUILD-MAX-HEAP

Result: [_, 16, 4, 10, 2, 1, 9, 3]

        16
       /  \
      4    10
     / \   / \
    2   1 9   3

Step 2: Extract max (swap A[1]↔A[7])

[_, 3, 4, 10, 2, 1, 9, | 16]

MAX-HEAPIFY(A,1) on [_, 3, 4, 10, 2, 1, 9]:

        10              10
       /  \    →      /  \
      4    9         4    9
     / \            / \
    2   1          2   1

Result: [_, 10, 4, 9, 2, 1, | 16]

Step 3: Extract max (swap A[1]↔A[6])

[_, 1, 4, 9, 2, | 10, 16]

MAX-HEAPIFY(A,1) on [_, 1, 4, 9, 2]:

        9              9
       / \    →      / \
      4   2         4   2
     /
    1

Result: [_, 9, 4, 2, 1, | 10, 16]

Step 4: Extract max (swap A[1]↔A[5])

[_, 1, 4, 2, | 9, 10, 16]

MAX-HEAPIFY(A,1): swap 1↔4, then 1↔2.

Result: [_, 4, 2, 1, | 9, 10, 16]

Step 5: Extract max (swap A[1]↔A[4])

[_, 1, 2, | 4, 9, 10, 16]

MAX-HEAPIFY: swap 1↔2.

Result: [_, 2, 1, | 4, 9, 10, 16]

Step 6: Extract max (swap A[1]↔A[3])

[_, 1, | 2, 4, 9, 10, 16]

Heap size = 1, done.

Sorted array: [1, 2, 4, 9, 10, 16]

Priority Queue (Min-Heap)

A data structure where each element has a priority. Elements are served by priority, not insertion order.

MIN-PRIORITY-QUEUE Operations: INSERT(S, x, key) S.heap-size ← S.heap-size + 1 S[S.heap-size] ← +∞ DECREASE-KEY(S, S.heap-size, key) EXTRACT-MIN(S) min ← S[1] S[1] ← S[S.heap-size] S.heap-size ← S.heap-size - 1 MIN-HEAPIFY(S, 1) return min DECREASE-KEY(S, i, key) A[i] ← key while i > 1 and A[parent(i)] > A[i] exchange A[i] ↔ A[parent(i)] i ← parent(i)

INSERT

O(lg n)

Add element at end, sift up to restore heap property

EXTRACT-MIN/MAX

O(lg n)

Remove root, move last element to root, sift down

DECREASE-KEY

O(lg n)

Reduce key value, sift up to restore heap property

FIND-MIN/MAX

O(1)

Return root element A[1]

Max-Priority Queue: Use max-heap. INSERT with key, EXTRACT-MAX, INCREASE-KEY (for decreasing priority).
Example 1: Priority Queue Operations

Min-priority queue operations on empty heap:

1. INSERT(A, task1, 4) → A=[_, 4]

2. INSERT(A, task2, 2) → A=[_, 2, 4]

3. INSERT(A, task3, 7) → A=[_, 2, 4, 7]

4. INSERT(A, task4, 1) → A=[_, 1, 2, 7, 4]

5. EXTRACT-MIN(A) → returns 1, A=[_, 2, 4, 7]

6. EXTRACT-MIN(A) → returns 2, A=[_, 4, 7]

Example 2: DECREASE-KEY

Max-heap: [_, 20, 15, 8, 10, 5, 3]

DECREASE-KEY(A, 5, 25): Set A[5]=25, sift up.

Before:      20          After:      25
            /  \                   /  \
          15    8               20    8
         / \   /               / \   /
       10 [5] 3             10  15 3
                              ↑ 5 became 25, sifted up to root
Example 3: Heap-Sort with Priority Queue

To sort [5, 3, 8, 1, 2] using priority queue:

1. Insert all: PQ = [1, 2, 8, 3, 5] (as min-heap)

2. Extract-MIN repeatedly: 1, 2, 3, 5, 8

Total time: O(n lg n)

Worked Examples

Example 1: Build Heap from Array (Complete)

Array: [_, 3, 1, 6, 5, 2, 4] (n=6)

Internal nodes: i = 3, 2, 1 (⌊6/2⌋ = 3)

Step 1: i=3, A[3]=6

        3              3
       / \            / \
     [6]  5    →     6   5      (6 > 4, no change)
     / \            / \
    2   4          2   4

Step 2: i=2, A[2]=1

        3              3
      [1]  5    →     5   1      (swap 1↔5)
      / \            / \
     2   4          2   4

Step 3: i=1, A[1]=3

       [3]             5
       / \     →      / \
      5   1          3   1      (swap 3↔5)
      / \            / \
     2   4          2   4

Final max-heap: [_, 5, 3, 1, 2, 4]

Verify: 5≥3, 5≥1, 3≥2, 3≥4? No! 3<4. Need to continue HEAPIFY on index 2.

       [5]             5
       / \     →      / \
     [3]  1          4   1      (swap 3↔4)
      / \            / \
     2  [4]         2   3

Correct max-heap: [_, 5, 4, 1, 2, 3]

Example 2: Complete HEAPSORT Trace

Array: [_, 5, 3, 8, 1, 2] (n=5)

BUILD-MAX-HEAP: [_, 8, 3, 5, 1, 2]

        8
       / \
      3   5
     / \
    1   2

Round 1: Swap A[1]↔A[5]: [_, 2, 3, 5, 1, | 8]

MAX-HEAPIFY(A,1): swap 2↔5, then 2↔1.

Result: [_, 5, 3, 2, 1, | 8]

Round 2: Swap A[1]↔A[4]: [_, 1, 3, 2, | 5, 8]

MAX-HEAPIFY(A,1): swap 1↔3.

Result: [_, 3, 1, 2, | 5, 8]

Round 3: Swap A[1]↔A[3]: [_, 2, 1, | 3, 5, 8]

MAX-HEAPIFY(A,1): swap 2↔1.

Result: [_, 2, 1, | 3, 5, 8]

Round 4: Swap A[1]↔A[2]: [_, 1, | 2, 3, 5, 8]

Heap size = 1, done.

Sorted: [1, 2, 3, 5, 8]

Example 3: MAX-HEAPIFY Detailed Trace

Array: [_, 27, 17, 3, 16, 13, 10, 1, 5, 7, 12]

        27
       /  \
     17    3
     / \  / \
   16 13 10  1
   /\  /
  5  7 12

MAX-HEAPIFY(A, 3): A[3]=3, left=A[6]=10, right=A[7]=1.

largest = 6 (10 > 3 and 10 > 1). Swap A[3]↔A[6].

        27
       /  \
     17   [10]         ← 3 moved down
     / \  / \
   16 13 [3] 1
   /\  /
  5  7 12

Recurse on i=6. A[6]=3, left=A[12]=none. Stop.

Done. A[3] now contains 10.

Example 5: Height Calculation

n = 1000 nodes

Height = ⌊lg 1000⌋ = ⌊9.97⌋ = 9

n = 1024 = 2^10 nodes

Height = ⌊lg 1024⌋ = 10 (perfect binary tree)

n = 1023 = 2^10 - 1 nodes

Height = ⌊lg 1023⌋ = 9 (still one less level)

Algorithms at a Glance

MAX-HEAPIFY(A, i): Compare A[i] with children, swap with largest, recurse if swapped BUILD-MAX-HEAP(A): for i = ⌊n/2⌋ downto 1: MAX-HEAPIFY(A, i) HEAPSORT(A): BUILD-MAX-HEAP(A) for i = n downto 2: swap A[1]↔A[i], heap-size--, MAX-HEAPIFY(A,1)

Key Formulas

BUILD-MAX-HEAP (Method 2) Analysis:
Σ(h=0 to ⌊lg n⌋) ⌈n/2^(h+1)⌉ × h = O(n)
Sum of heights of all nodes. Most nodes have height 0 or 1.
HEAPSORT Total Work:
O(n) + (n-1) × O(lg n) = O(n lg n)
BUILD-MAX-HEAP + (n-1) extractions with heapify.
Exam Tips:
  • BUILD-MAX-HEAP is O(n), NOT O(n lg n) — common exam question!
  • Process internal nodes from ⌊n/2⌋ downto 1 (bottom-up)
  • MAX-HEAPIFY assumes children are already heaps
  • Heap is NOT a sorted array — only parent-child ordering guaranteed
  • Leaves are indices ⌊n/2⌋+1 to n
  • Height is ⌊lg n⌋, not ⌈lg n⌉

Common Pitfalls

  • Confusing min-heap and max-heap (opposite properties)
  • Using 0-indexed formulas with 1-indexed array (or vice versa)
  • Forgetting heap-size ≤ array.length
  • Assuming heaps support efficient search — they don't!
  • Thinking BUILD-MAX-HEAP is O(n lg n) — it's O(n)!
  • Not processing nodes in correct order (bottom-up for BUILD)
