Min-Max Heap Comprehensive Study Guide

What is a Min-Max Heap?

📖 Before You Begin — Tree Basics

A tree is like a family tree: one root node at the top, with branches to children below it. A binary tree means every node has at most 2 children (left and right). A complete binary tree fills every level from left to right — like seats in a theater being filled row by row, left to right, no gaps.

Depth (or level) is how far down a node is from the root. The root is depth 0, its children are depth 1, grandchildren depth 2, and so on.

Descendants = children + grandchildren + great-grandchildren + ... everything below a node. This is different from just children (the immediate ones).

The heap is stored in an array by reading top-to-bottom, left-to-right. For a node at array index i: parent is at (i-1)/2, left child at 2i+1, right child at 2i+2.

Formal Definition

A Min-Max Heap is a complete binary tree that satisfies the min-max property: nodes at even depths (0, 2, 4, ...) are min-levels, and nodes at odd depths (1, 3, 5, ...) are max-levels.

Depth d is even (d ≡ 0 mod 2) → Min-Level
Depth d is odd  (d ≡ 1 mod 2) → Max-Level

Min-Max Property — Plain English

Think of the tree as having alternating "floors" in a building:

  • Even-numbered floors (0, 2, 4, ...) are "Minimum Floors" — the person on that floor must be the smallest compared to everyone below them on that branch.
  • Odd-numbered floors (1, 3, 5, ...) are "Maximum Floors" — the person on that floor must be the largest compared to everyone below them on that branch.

And "everyone below" means all descendants (children, grandchildren, great-grandchildren, ...) — not just the immediate children. This is the key difference from a regular heap!

Min-Level node (even depth): value ≤ ALL descendants
Max-Level node (odd depth): value ≥ ALL descendants

Simple Example

Imagine this tree:

       2   ← depth 0 (min-level): 2 ≤ all below it ✓
      / \
    10  15  ← depth 1 (max-level): each ≥ all below it
    / \  / \
  3  5 7 8  ← depth 2 (min-level): each ≤ all below it

Check: 10 ≥ 3,5 ✓ (10 is max-level, 3 and 5 are below). 15 ≥ 7,8 ✓. Root 2 ≤ 10,15,3,5,7,8 ✓.

Notice: 10 and 15 don't have to be in any order with each other — they're siblings, not parent-child!

⚠ Key Distinction: The min-max property is defined relative to all descendants, not just immediate children. This is unlike a standard min-heap where each parent ≤ its children (checking only one level down).

💡 Key Insight: The root is at depth 0 (min-level) → the root is always the minimum of the entire heap. The root's children are at depth 1 (max-level) → the maximum is always one of the root's children (at most 2 comparisons).

Array Representation

Like any complete binary tree, a Min-Max Heap is stored as an array with these index relationships:

Parent of i:    ⌊(i - 1) / 2⌋
Left child of i:   2i + 1
Right child of i: 2i + 2

Key Properties & Relationships

Property 1: Root is Always the Minimum

Since root is at depth 0 (a min-level), and it must be ≤ all its descendants, the root of the Min-Max Heap is the global minimum.

Property 2: Maximum is Among Root's Children

Root's children are at depth 1 (max-level). The global maximum must be one of the root's children. With at most 2 comparisons, you can find the maximum.

Property 3: Grandparent Relationship

For any node at depth d:

  • If d is even (min-level): node ≤ all descendants → node ≤ all grandchildren's subtrees
  • If d is odd (max-level): node ≥ all descendants → node ≥ all grandchildren's subtrees

Property 4: Alternating Levels (Like a Zebra Pattern)

Each path from root to leaf alternates between min and max levels — like black and white stripes:

Root (min) → Child (max) → Grandchild (min) → Great-grandchild (max) → ...

This zebra pattern is what gives the Min-Max Heap its superpower: both the minimum and maximum can be found instantly (O(1)). The minimum is always at the very top (root, depth 0 = min), and the maximum is always one of the root's two children (depth 1 = max).

Visual Example: Level Alternation

2 ← Depth 0: MIN LEVEL (root = global min) / \ 15 9 ← Depth 1: MAX LEVEL (max is 15 or 9) / \ / \ 3 5 7 8 ← Depth 2: MIN LEVEL (each ≤ descendants below) / \ / \ / \ 10 12 4 6 11 13 ← Depth 3: MAX LEVEL (each ≥ descendants below)

How to Read This Tree

  • Root 2 is at depth 0 (min-level). Is 2 ≤ all its descendants (15,9,3,5,7,8,10,12,4,6,11,13)? Yes ✓
  • Node 15 is at depth 1 (max-level). Is 15 ≥ all its descendants (3,5,10,12)? Yes ✓ (15 ≥ 3,5,10,12)
  • Node 9 is at depth 1 (max-level). Is 9 ≥ all its descendants (7,8,11,13)? Yes ✓
  • Node 3 is at depth 2 (min-level). Is 3 ≤ all its descendants (10,12)? Yes ✓

Notice that 10 and 12 (grandchildren of 15) are checked against 15, not just 3! This is the "all descendants" rule at work.

⚠ Common Exam Confusion: The min-max property applies to all descendants, not just children. For example, the root (2) must be ≤ 10, 12, 4, 6, 11, 13 — not just 15 and 9. And node 15 at a max-level must be ≥ 3, 5, 10, 12 — which includes grandchildren (10, 12), not just children (3, 5).

Complete Binary Tree Property

The tree must be a complete binary tree. Think of filling a theater row by row:

  • Row 1: 1 seat (root)
  • Row 2: 2 seats (children)
  • Row 3: 4 seats (grandchildren)
  • Row 4: 8 seats (great-grandchildren)
  • ... Each row doubles in size.
  • The last row might not be full, but any empty seats must be on the right side (filled left to right).

This guarantees O(log n) height — very shallow! For 1 million elements, the tree is only about 20 levels deep.

Array Storage — How the Tree Lives in Memory

To store the tree in an array, read top-to-bottom, left-to-right:

Tree:         Array (index: value):
   2          [0] = 2
  / \         [1] = 15, [2] = 9
 15  9        [3] = 3,  [4] = 5, [5] = 7, [6] = 8
/ \ / \       ...
3 5 7 8

To navigate: if you're at index i, your parent is at (i-1)/2, left child at 2i+1, right child at 2i+2.

Core Operations

1 Find Minimum — O(1)

The minimum is always at the root (index 0).

FindMin(heap):
    return heap[0]   // Root is always the minimum

2 Find Maximum — O(1)

The maximum is one of the root's children (at most 2 comparisons).

FindMax(heap):
    if heap.size == 1:
        return heap[0]
    if heap.size == 2:
        return heap[1]
    return max(heap[1], heap[2])  // Compare left and right child

3 Insert — O(log n)

Place element at next available position (end of array), then bubble up alternating between min and max levels.

Insert(heap, value):
    heap.append(value)                    // Add at end (maintains complete tree)
    i = heap.size - 1
    BubbleUp(heap, i)                    // Restore min-max property upward

BubbleUp(heap, i):
    depth = floor(log2(i + 1))         // Even = min-level, odd = max-level

    if depth is even:                    // MIN LEVEL (node should be ≤ descendants)
        if i has parent (i > 0):
            p = (i - 1) / 2
            if heap[i] > heap[p]:           // Violates parent's max-level?
                swap(heap[i], heap[p])     // Swap with parent
                BubbleUpMax(heap, p)         // Continue at max-level
                return
        BubbleUpMin(heap, i)               // Check grandparent chain

    else:                                 // MAX LEVEL (node should be ≥ descendants)
        if i has parent (i > 0):
            p = (i - 1) / 2
            if heap[i] < heap[p]:           // Violates parent's min-level?
                swap(heap[i], heap[p])     // Swap with parent
                BubbleUpMin(heap, p)           // Continue at min-level
                return
        BubbleUpMax(heap, i)               // Check grandparent chain

BubbleUpMin(heap, i):
    // i is at min-level. While value is smaller than grandparent, swap up.
    while i has grandparent (i ≥ 3):
        gp = (i - 3) / 4               // Grandparent of i
        if heap[i] < heap[gp]:
            swap(heap[i], heap[gp])
            i = gp
        else: break

BubbleUpMax(heap, i):
    // i is at max-level. While value is larger than grandparent, swap up.
    while i has grandparent (i ≥ 3):
        gp = (i - 3) / 4               // Grandparent of i
        if heap[i] > heap[gp]:
            swap(heap[i], heap[gp])
            i = gp
        else: break
💡 Insert Logic Summary (for beginners):
  1. Add element at end of array (keeps the tree complete — no gaps).
  2. Check current depth: even → min-level, odd → max-level.
  3. First, check parent (the level above): if the parent's property is violated, swap with parent and continue upward as the opposite level.
  4. If parent check passes, then check grandparent: keep swapping up through same-level ancestors (min→min or max→max) until the property is satisfied.
  5. Stop when no more violations or reaching root.

Think of it like a new student joining a school: first they check their immediate teacher (parent). If the teacher says they belong in a different class, they swap. Otherwise, they go up to the principal (grandparent) to make sure everything is in order.

4 Delete Minimum — O(log n)

Remove root (minimum), replace with last element, then bubble down alternating.

DeleteMin(heap):
    min = heap[0]
    heap[0] = heap[heap.size - 1]
    heap.size--
    TrickleDown(heap, 0)
    return min

TrickleDown(heap, i):
    depth = floor(log2(i + 1))

    if depth is even:  // MIN LEVEL
        TrickleDownMin(heap, i)
    else:  // MAX LEVEL
        TrickleDownMax(heap, i)

TrickleDownMin(heap, i):
    while i has children:
        m = index of smallest among children & grandchildren of i
            // Examine up to 2 children + 4 grandchildren = 6 nodes
            // (or fewer near the bottom of the tree)

        if m is a grandchild:
            if heap[m] < heap[i]:
                swap(heap[i], heap[m])
                if heap[m] > heap[parent(m)]:
                    swap(heap[m], heap[parent(m)])
                i = m
            else:
                break  // Heap property satisfied
        else:  // m is a child
            if heap[m] < heap[i]:
                swap(heap[i], heap[m])
            break

TrickleDownMax(heap, i):
    // Symmetric: find largest descendant, swap down on max-level
    (analogous to TrickleDownMin but comparing for maximum)

5 Delete Maximum — O(log n)

Remove the maximum (at root's children), replace with last, then bubble down from that position.

DeleteMax(heap):
    if heap.size == 1:
        return DeleteMin(heap)

    // Find which child is the maximum
    maxIdx = 1
    if heap.size > 2 and heap[2] > heap[1]:
        maxIdx = 2

    maxVal = heap[maxIdx]
    heap[maxIdx] = heap[heap.size - 1]
    heap.size--
    TrickleDown(heap, maxIdx)
    return maxVal
⚠ TrickleDown Complexity: On a min-level, you may need to examine up to 7 nodes (children + grandchildren) to find the smallest descendant. On a max-level, same for the largest. This is constant work per level, giving O(log n) overall.

Worked Example 1: Insert Sequence

Insert the elements: [5, 3, 8, 1, 9, 2, 7, 4, 6] one by one into an empty Min-Max Heap.

Step-by-step Insertions

1 Insert 5

5 ← Depth 0: Min-Level

Root only. No bubbling needed.

Array: [5]

2 Insert 3

5 ← Min-Level / 3 ← Max-Level

Added as left child of 5. Parent (5) is at min-level. 3 < 5 on max-level? No swap needed — 3 is a child of min-level 5, and min-level 5 ≤ all descendants is satisfied (5 ≤ 3? No!). We need to check.

Bubble up: 3 is at depth 1 (max-level). No grandparent. Parent is 5 at depth 0. Since 3 < 5, but 5 is at min-level, the min-level property says 5 should be ≤ descendants. 5 is NOT ≤ 3. Swap!

3 ← Min-Level (was 5) / 5 ← Max-Level (was 3)

Array: [3, 5]

3 Insert 8

3 / \ 5 8 ← Max-Level

8 added as right child. 8 > 5 (max-level), and 3 ≤ both. All good.

Array: [3, 5, 8]

4 Insert 1

3 / \ 5 8 / 1 ← Min-Level (depth 2)

1 at depth 2 (min-level). Grandparent: 3 (depth 0). 1 < 3 → violation! Swap with grandparent 3.

1 ← Min-Level / \ 5 8 / 3 ← Min-Level

Array: [1, 5, 8, 3]

5 Insert 9

9 goes as the right child of 5 (index 4, depth 2 = min-level).

BubbleUp check — parent first: 9's parent is 5 at max-level. Max-level nodes must be ≥ all descendants. 5 ≥ 9? NO! Violation detected: swap 9 with its parent 5.

1 / \ 9 8 ← 9 swapped up, 5 moved down / \ 3 5 ← 5 is now at min-level (child of 9)

Now continue at max-level: 9 is at depth 1 (max-level), no grandparent. Done.

Let's verify: Root 1 (min-level) ≤ all ✓. 9 (max-level) ≥ descendants 3,5 ✓. 8 (max-level) ≥ none ✓. 3 (min-level) ≤ none ✓. 5 (min-level) ≤ none ✓.

Array: [1, 9, 8, 3, 5]

6 Insert 2

1 / \ 9 8 / \ / \ 3 5 2 ← 2 at depth 2 (min-level)

2 at index 5, depth 2 (min-level). Parent check: parent is 8 at max-level. 8 ≥ 2? Yes ✓. No swap. Grandparent check: grandparent is 1 (min-level). 2 < 1? No. Done.

Array: [1, 9, 8, 3, 5, 2]

7 Insert 7

7 at index 6, depth 2 (min-level). Parent: 8 (max-level). 8 ≥ 7 ✓. Grandparent: 1 (min-level). 7 < 1? No. Done.

Array: [1, 9, 8, 3, 5, 2, 7]

8 Insert 4

1 / \ 9 8 / \ / \ 3 5 2 7 / 4 ← Max-Level (depth 3)

4 at index 7, depth 3 (max-level). Parent check: parent is 3 (min-level). 3 ≤ 4 ✓. No swap. Grandparent check: grandparent is 9 (max-level). 4 > 9? No. Done.

Array: [1, 9, 8, 3, 5, 2, 7, 4]

9 Insert 6

6 at index 8, depth 3 (max-level). Parent check: parent is 3 (min-level). 3 ≤ 6 ✓. Grandparent check: grandparent is 9 (max-level). 6 > 9? No. Done.

Array: [1, 9, 8, 3, 5, 2, 7, 4, 6]

Final Heap

1 ← MIN (depth 0) / \ 9 8 ← MAX (depth 1) — max is max(9,8) = 9 / \ / \ 3 5 2 7 ← MIN (depth 2) / \ / 4 6 ← MAX (depth 3)

Verification (check each level)

  • Find Min: 1 at root ✓
  • Find Max: max(9, 8) = 9 ✓ (always among root's 2 children!)
  • Root 1 (min-level) ≤ all descendants: 1 ≤ 9,8,3,5,2,7,4,6 ✓
  • Node 9 (max-level) ≥ descendants: 9 ≥ 3,5,4,6 ✓
  • Node 8 (max-level) ≥ descendants: 8 ≥ 2,7 ✓
  • Node 3 (min-level) ≤ descendants: 3 ≤ 4,6 ✓

Worked Example 2: Delete Min

Starting from the heap built in Example 1, perform DeleteMin (remove the smallest element).

Starting Heap

1 / \ 9 8 / \ / \ 3 5 2 7 / \ / 4 6

Array: [1, 9, 8, 3, 5, 2, 7, 4, 6]

💡 How Delete Min works: Take the root (always the minimum), replace it with the last element in the array (to keep the tree complete), then trickle down — the new root "sinks" down through the tree until the min-max property is restored. Imagine removing the top brick from a stack and placing a new one on top, then watching it settle into place.

1 Remove Minimum

Root (1) is the minimum. Remove it and replace with the last element (6). The tree stays complete (no gaps).

6 ← Temporarily at root (depth 0, min-level) / \ 9 8 / \ / \ 3 5 2 7 / 4

Array: [6, 9, 8, 3, 5, 2, 7, 4]

But now the root is 6, which violates the min-level property (root must be ≤ all descendants). We must fix this.

2 Trickle Down from Root

6 is at depth 0 (min-level). We use TrickleDownMin: find the smallest among its children AND grandchildren, then swap if needed.

Children of root (index 0): 9 (index 1), 8 (index 2)

Grandchildren: 3 (index 3), 5 (index 4), 2 (index 5), 7 (index 6)

Smallest descendant: min(9, 8, 3, 5, 2, 7) = 2 at index 5 (a grandchild).

Since 2 < 6, swap 6 and 2. Now 2 becomes the new root, and 6 moves to where 2 was.

2 ← New root (min-level) — much better! / \ 9 8 / \ / \ 3 5 6 7 / 4

After-swap check: 6 at index 5 (depth 2 = min-level). Its parent is 8 at index 2 (max-level). Does 8 ≥ 6? Yes ✓. So no swap-back needed.

Now continue trickle down from index 5 (where 6 ended up).

3 Continue Trickle Down at Index 5

6 at index 5 (depth 2 = min-level). Does it have children? Children would be at index 2×5+1=11 and 2×5+2=12. Heap size is 8, so no children → stop.

Final Heap after DeleteMin

2 ← New minimum! / \ 9 8 / \ / \ 3 5 6 7 / 4

Array: [2, 9, 8, 3, 5, 6, 7, 4]

Verification

  • Find Min: 2 at root ✓
  • Find Max: max(9, 8) = 9 ✓
  • Root 2 (min-level) ≤ all: 2 ≤ 9,8,3,5,6,7,4 ✓
  • Node 9 (max-level) ≥ descendants: 9 ≥ 3,5,4 ✓
  • Node 8 (max-level) ≥ descendants: 8 ≥ 6,7 ✓
  • Node 3 (min-level) ≤ descendants: 3 ≤ 4 ✓

Worked Example 3: Delete Max

Starting from the heap built in Example 1, perform DeleteMax (remove the largest element).

💡 How Delete Max works: The maximum is always one of the root's two children (depth 1 = max-level). Compare them, pick the larger, remove it, replace with the last array element, then trickle down from that position to restore the min-max property.

Starting Heap

1 / \ 9 8 / \ / \ 3 5 2 7 / \ / 4 6

Array: [1, 9, 8, 3, 5, 2, 7, 4, 6]

1 Find and Remove Maximum

Max is at root's children: compare 9 (index 1) and 8 (index 2). Maximum is 9 at index 1.

Remove 9, replace with the last element (6). Heap size becomes 8.

1 / \ 6 8 ← 6 replaced 9 at index 1 / \ / \ 3 5 2 7 / 4

Array: [1, 6, 8, 3, 5, 2, 7, 4]

Now 6 is at index 1 (max-level, depth 1). Check if it violates the max-level property.

2 Trickle Down from Index 1

6 is at depth 1 (max-level). Use TrickleDownMax: find the largest among children AND grandchildren.

Children of index 1: 3 (index 3), 5 (index 4)

Grandchildren of index 1: 4 (index 7) — that's the only one (heap size is 8)

Largest descendant: max(3, 5, 4) = 5 (a child at index 4).

Check: is 5 > 6? No (5 < 6). That means 6 already satisfies the max-level property: 6 ≥ 3 ✓, 6 ≥ 5 ✓, 6 ≥ 4 ✓.

Since the largest descendant is not greater than the current node, the max-level property is satisfied. No swap needed. (If it were a grandchild that was larger, we'd swap and then check the min-level parent.)

Final Heap after DeleteMax

1 / \ 6 8 / \ / \ 3 5 2 7 / 4

Array: [1, 6, 8, 3, 5, 2, 7, 4]

Verification

  • Find Min: 1 at root ✓
  • Find Max: max(6, 8) = 8 ✓
  • Root 1 (min-level) ≤ all: 1 ≤ 6,8,3,5,2,7,4 ✓
  • Node 6 (max-level) ≥ descendants: 6 ≥ 3,5,4 ✓
  • Node 8 (max-level) ≥ descendants: 8 ≥ 2,7 ✓
  • Node 3 (min-level) ≤ descendants: 3 ≤ 4 ✓

Why O(log n) for Insert?

  1. The tree is a complete binary tree → height = ⌊log₂ n⌋
  2. Insert adds element at the end (leaf), then bubbles up
  3. At each level, we do at most 2 comparisons (grandparent, then parent)
  4. At most log₂ n levels to traverse
  5. Total: O(log n) × O(1) per level = O(log n)

Why O(log n) for Delete?

  1. Remove root, replace with last element
  2. Trickle down: at each level, examine up to 7 nodes (2 children + 4 grandchildren, or fewer near leaves)
  3. At most log₂ n levels
  4. Total: O(log n) × O(1) per level = O(log n)
Summary:
All operations: O(log n) except Find Min/Max which are O(1)
Space: O(n)

When to Use Min-Max Heap?

  • Double-ended priority queue: Need both min and max operations efficiently
  • Interval scheduling: Need to access both endpoints quickly
  • Median maintenance: Combined with other structures
  • Real-time systems: Need guaranteed O(1) for both min and max

Advantages of Min-Max Heap

  • Single data structure (vs. maintaining two separate heaps)
  • No synchronization overhead
  • Cache-friendly (stored as single array)
  • Simple implementation compared to deaps

Disadvantages

  • Slightly more complex than a standard heap
  • Trickle-down must find min or max among up to 7 descendants
  • Not as widely implemented in standard libraries

BubbleUp Rules (Correct Algorithm)

  1. At min-level (even depth):
    • First check parent: If value > parent (violates parent's max-level) → swap with parent, then BubbleUpMax at parent level.
    • If parent is OK: check grandparent chain via BubbleUpMin — while value < grandparent, swap up.
  2. At max-level (odd depth):
    • First check parent: If value < parent (violates parent's min-level) → swap with parent, then BubbleUpMin at parent level.
    • If parent is OK: check grandparent chain via BubbleUpMax — while value > grandparent, swap up.

TrickleDown Rules

  1. At min-level (even depth):
    • Find the smallest among children AND grandchildren (up to 6 nodes).
    • If smallest is a grandchild and < current → swap. Then check if grandchild > its (new) parent → swap back (this fixes the max-level property).
    • If smallest is a child and < current → swap, then stop (children aren't at min-level, so no further trickle needed).
  2. At max-level (odd depth):
    • Find the largest among children AND grandchildren (up to 6 nodes).
    • If largest is a grandchild and > current → swap. Then check if grandchild < its (new) parent → swap back (fixes the min-level property).
    • If largest is a child and > current → swap, then stop.

Key Properties to Remember

  1. Root is always the global minimum
  2. Root's children contain the global maximum (at most 2 comparisons)
  3. Min-max property applies to all descendants, not just children
  4. Alternating levels: even depth = min, odd depth = max
  5. Complete binary tree structure → array storage, O(log n) height
  6. Insert: append + bubble up (check grandparent first, then parent)
  7. Delete: replace with last + trickle down (find extreme among descendants)
  8. All mutations: O(log n) time
