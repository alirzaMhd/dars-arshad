Binary Search Tree (BST) Definition

Data Structures — Complete Guide for 20/20 Exam

What is a Binary Search Tree?

Formal Definition:
BST is a binary tree where each node has a key, and for every node:
1. All keys in left subtree are less than the node's key
2. All keys in right subtree are greater than the node's key
3. Both left and right subtrees are also BSTs
Important: Keys must be distinct (no duplicates) in a standard BST. However, some implementations allow duplicate keys.
Visual Example
20 / \ 10 30 / \ / \ 5 15 25 35

• Node 20: Left subtree {5, 10, 15} all < 20, Right subtree {25, 30, 35} all > 20

• Node 10: Left subtree {5} < 10, Right subtree {15} > 10

• This property holds for ALL nodes in the tree

Node Structure

• key: The value stored

• left: Pointer to left child

• right: Pointer to right child

• parent: Pointer to parent (optional)

Key Property

For any node with key k:

• All keys in left subtree < k

• All keys in right subtree > k

• This enables efficient searching

BST Properties & Complexity

Number of Distinct BSTs with n keys:
C(n) = C(0) × C(n-1) + C(1) × C(n-2) + ... + C(n-1) × C(0)
This is the Catalan number formula. C(n) = (2n)! / ((n+1)! × n!)
Example 1: How many BSTs with 3 keys?

For keys {1, 2, 3}:

C(3) = C(0)×C(2) + C(1)×C(1) + C(2)×C(0)

C(3) = 1×2 + 1×1 + 2×1 = 5 distinct BSTs

Height Properties

• Maximum height: n - 1 (skewed tree)

• Minimum height: ⌊lg n⌋

• Height is O(lg n) on average

Complexity Summary

• Search: O(h)

• Insert: O(h)

• Delete: O(h)

Where h = height of tree

Worst Case: If tree is skewed (like a linked list), all operations become O(n). This is why we need balanced BSTs like AVL trees.

Inorder Traversal Property

Key Property:
Inorder traversal of BST produces sorted sequence (ascending order)
This is the fundamental property that makes BST useful for sorting and searching
Example: Inorder Traversal
20 / \ 10 30 / \ / \ 5 15 25 35

Inorder traversal: 5 → 10 → 15 → 20 → 25 → 30 → 35

The sequence is in ascending order!

Why This Matters

If inorder traversal does NOT give sorted order, then the tree is NOT a valid BST.

This property can be used to verify if a binary tree is a BST.

Common Mistake: A tree can have the BST property at each node but still not be a valid BST if the property doesn't hold globally. Always check the entire tree, not just individual nodes.

Worked Examples

Example 1: Build BST from keys 20, 10, 30, 5, 15, 25, 35

Insert in given order:

Step 1: Insert 20 Step 2: Insert 10 Step 3: Insert 30 20 20 20 / / \ 10 10 30 Step 4: Insert 5 Step 5: Insert 15 Step 6: Insert 25 20 20 20 / \ / \ / \ 10 30 10 30 10 30 / / \ / \ 5 5 15 25 35

Final tree has inorder: 5, 10, 15, 20, 25, 30, 35 (sorted!)

Example 2: Verify if this is a valid BST
20 / \ 10 30 / \ / \ 5 35 25 15

Check inorder: 5 → 10 → 35 → 20 → 25 → 15 → 30

NOT sorted! This is NOT a valid BST because 35 is in left subtree of 20.

Example 3: Count BSTs with keys {a, b, c}

Using Catalan number: C(3) = 5

The 5 possible BSTs are:

1. Root a, right subtree {b, c}

2. Root b, left {a}, right {c}

3. Root c, left subtree {a, b}

And 2 more configurations...

Quick Reference Card

Definition

Binary tree where for each node:

• Left subtree keys < node key

• Right subtree keys > node key

Key Properties

• Inorder gives sorted sequence

• Height: O(lg n) to O(n)

• Operations: O(h) time

When to Use

• Dynamic set operations

• Insert/Delete/Search

• Range queries

When NOT to Use

• If tree becomes skewed

• Use AVL or Red-Black instead

• For guaranteed O(lg n)

Catalan Number Formula:
C(n) = (2n)! / ((n+1)! × n!) = Σ C(k) × C(n-1-k) for k=0 to n-1
Gives number of distinct BSTs with n distinct keys
