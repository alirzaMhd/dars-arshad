Binary Search Tree (BST)

Data Structures — Complete Guide for 20/20 Exam

BST Definition

A Binary Search Tree (BST) is a binary tree where every node has a key, and for each node:

Left Subtree

All keys in the left subtree are strictly less than the node's key.

Right Subtree

All keys in the right subtree are strictly greater than the node's key.

Distinct Keys

Keys are typically distinct. Some sources allow duplicates (inserted to left or right).

Warning: In-order traversal of a BST does NOT always produce a sorted ascending sequence. Consider a BST where 37 is the parent and 35 is in its left subtree — while 35 < 37 is true, the in-order traversal may not be ascending if the tree structure is not carefully maintained.

Number of Distinct BSTs

Catalan Number Formula:
C(n) = (2n)! / ((n+1)! * n!) = C_n
Number of structurally different BSTs with n distinct keys
Recursive Relation:
C(n) = Σ C(k) * C(n-1-k) for k = 0 to n-1
If key k is root, left subtree has k keys (C(k) ways), right has n-1-k keys (C(n-1-k) ways)
Example: Distinct BSTs with 3 keys

Keys: {1, 2, 3}

Root = 1: Left subtree empty (C(0)=1), right has {2,3} (C(2)=2) → 1×2 = 2 trees

Root = 2: Left has {1} (C(1)=1), right has {3} (C(1)=1) → 1×1 = 1 tree

Root = 3: Left has {1,2} (C(2)=2), right empty (C(0)=1) → 2×1 = 2 trees

Total = 2 + 1 + 2 = 5 distinct BSTs

Example: Distinct BSTs with 4 keys

C(4) = C(0)C(3) + C(1)C(2) + C(2)C(1) + C(3)C(0)

= 1×5 + 1×2 + 2×1 + 5×1 = 5 + 2 + 2 + 5 = 14

Height Properties

Worst Case

Height = n - 1

Degenerate (skewed) tree — one node per level

Best Case

Height = ⌊lg n⌋

Perfectly balanced tree

Average Case

Height = Θ(lg n)

Hard to prove formally

Minimum Levels (Height):
Minimum levels = ⌊lg n⌋ + 1
A complete binary tree with n nodes has ⌊lg n⌋ + 1 levels

Traversal

Use parent pointer p for implementation. The parent pointer allows upward traversal in the tree.

In-order traversal of BST: 1. Traverse left subtree 2. Visit root 3. Traverse right subtree Note: In-order traversal does NOT always give ascending order in a BST. The property is that for any node x, all nodes in left subtree have keys < x.key, and all nodes in right subtree have keys > x.key.

BST Search

Search for key k starting from root. Compare k with current node's key.

Iterative Search

ITERATIVE-SEARCH(x, k) while x ≠ NIL and k ≠ key[x] if k < key[x] x = left[x] else x = right[x] return x

Recursive Search

REC-SEARCH(x, k) if x = NIL or k = key[x] return x if k < key[x] return REC-SEARCH(left[x], k) else return REC-SEARCH(right[x], k)
Time Complexity:
O(h)
Where h is the height of the tree. Worst case Θ(n), average/best case Θ(lg n)
Example: Search for k=22 in BST

BST: 20 → 25 → 37 → 35

1. Compare 22 with 20 → 22 > 20, go right

2. Compare 22 with 25 → 22 < 25, go left

3. Compare 22 with 37 → 22 < 37, go left

4. Compare 22 with 35 → 22 < 35, go left

5. Left child is NIL → Search unsuccessful

Example: Search for k=32 in BST

BST: 20 → 25 → 37 → 35

1. Compare 32 with 20 → go right

2. Compare 32 with 25 → go right

3. Compare 32 with 37 → go left

4. Compare 32 with 35 → go left

5. Left child is NIL → Search unsuccessful

Keys checked: 20, 25, 37, 35

Search Property Test

Key Property: For a sequence to be a valid in-order traversal of a BST, for every element x in the sequence, all elements after x must be either ALL smaller than x or ALL larger than x.
Test: Which sequence can represent in-order of BST with root=925?

Option 1: 363, 245, 912, 240, 911, 202, 925

Root = 925. After 925, all elements must be smaller (left subtree).

First element after root = 202 < 925 ✓

But 911 comes after 202, and 911 > 202 but 911 is in left subtree... need to check BST property carefully.

Option 1 is NOT valid (911 should not appear after 202 in left subtree traversal)

BST Insert

Insert key k into BST. First search for k — if not found, insert new node at the position where search terminated.

BST-INSERT(T, z) y = NIL x = root[T] while x ≠ NIL y = x if key[z] < key[x] x = left[x] else x = right[x] parent[z] = y if y = NIL root[T] = z // Tree was empty else if key[z] < key[y] left[y] = z else right[y] = z
Time Complexity:
O(h)
Depends on tree height. Insert does NOT change relative order of existing elements.
Important: Insert operation does NOT swap existing elements. The relative order of keys already in the tree remains unchanged. Only the new key is added at a leaf position.
Example: Insert keys 30, 10, 40, 5, 15, 35, 45

Step 1: Insert 30 → root = 30

Step 2: Insert 10 → 10 < 30, left child of 30

Step 3: Insert 40 → 40 > 30, right child of 30

Step 4: Insert 5 → 5 < 30 → 5 < 10, left child of 10

Step 5: Insert 15 → 15 < 30 → 15 > 10, right child of 10

Step 6: Insert 35 → 35 > 30 → 35 < 40, left child of 40

Step 7: Insert 45 → 45 > 30 → 45 > 40, right child of 40

Example: Different insertion orders produce different trees

Keys: {22, 25, 37, 35, 40, 20}

Order 1: 22, 25, 37, 35, 40, 20 → balanced-ish tree

Order 2: 20, 22, 25, 35, 37, 40 → degenerate (right-skewed) tree

Same keys, completely different tree shapes!

Insert Complexity Analysis

Worst Case

Time: Θ(n)

Tree is degenerate (skewed)

Average Case

Time: Θ(lg n)

Random insertion order

Best Case

Time: Θ(lg n)

Tree is balanced

BST Delete

Delete node z from BST. Three cases based on number of children.

Case 1: z is a leaf (no children)

Simply remove z by setting parent's pointer to NIL
Example: Delete leaf node 40

Before: ... → 40 (leaf)

After: ... → NIL

Case 2: z has one child

Replace z with its child (splice out z) - If z has only left child: parent[z] → left → child[z] - If z has only right child: parent[z] → right → child[z]
Example: Delete node 10 (has only right child 15)

Before: 30 → left → 10 → right → 15

After: 30 → left → 15

Case 3: z has two children

Find z's successor y (minimum of right subtree) - If y is z's right child: replace z with y - Otherwise: replace y with its own right child, then replace z with y
Example: Delete node 20 (has left child 10 and right child 30)

Successor of 20 = minimum of right subtree = 30 (if 30 has no left child)

Replace 20 with 30, and 30's right subtree becomes child of 20's parent

Time Complexity:
O(h)
Delete does NOT change relative order of remaining elements
Important: When deleting a node with two children, you can use either the successor (smallest in right subtree) OR the predecessor (largest in left subtree) as the replacement. Both are valid, but the resulting tree may differ.

Delete Algorithm

BST-DELETE(T, z) if left[z] = NIL or right[z] = NIL y = z // y is the node to be deleted else y = TREE-SUCCESSOR(z) // y is z's successor if left[y] ≠ NIL x = left[y] else x = right[y] if x ≠ NIL parent[x] = parent[y] if parent[y] = NIL root[T] = x else if y = left[parent[y]] left[parent[y]] = x else right[parent[y]] = x if y ≠ z key[z] = key[y] // Copy y's data to z // Copy other satellite data if needed

Finding Minimum

MINIMUM(x) while left[x] ≠ NIL x = left[x] return x

Follow left links from root until NIL. The leftmost node is the minimum.

Example: Find minimum in BST

BST: 30 → 10 → 5 → NIL

Start at 30, go left to 10, go left to 5, left is NIL

Minimum = 5

Finding Maximum

MAXIMUM(x) while right[x] ≠ NIL x = right[x] return x

Follow right links from root until NIL. The rightmost node is the maximum.

Example: Find maximum in BST

BST: 30 → 40 → 45 → NIL

Start at 30, go right to 40, go right to 45, right is NIL

Maximum = 45

Time Complexity:
O(h)
Both MINIMUM and MAXIMUM run in O(h) time

In-order Successor

The successor of node x, denoted succ(x), is the node with the smallest key greater than x.key.

SUCC(x) if right[x] ≠ NIL return MINIMUM(right[x]) // Min of right subtree else y = parent[x] while y ≠ NIL and x = right[y] x = y y = parent[y] return y
Example: Find successor

In BST with inorder: 20, 25, 35, 37, 40

succ(25) = 35 (next in inorder)

succ(37) = 40 (next in inorder)

succ(40) = NIL (no successor, 40 is maximum)

In-order Predecessor

The predecessor of node x, denoted pred(x), is the node with the largest key smaller than x.key.

PRED(x) if left[x] ≠ NIL return MAXIMUM(left[x]) // Max of left subtree else y = parent[x] while y ≠ NIL and x = left[y] x = y y = parent[y] return y
Example: Find predecessor

In BST with inorder: 20, 25, 35, 37, 40

pred(35) = 25 (previous in inorder)

pred(40) = 37 (previous in inorder)

pred(20) = NIL (no predecessor, 20 is minimum)

In-order Traversal Example

Example: In-order traversal of BST

BST with keys: 20, 22, 25, 35, 37, 40 (left to right)

succ(d) = succ(h) = succ(f) = succ(b) = pred(e) = pred(c) = ...

Inorder: 20, 22, 25, 35, 37, 40

succ(20) = 22, succ(22) = 25, succ(25) = 35, succ(35) = 37, succ(37) = 40

pred(40) = 37, pred(37) = 35, pred(35) = 25, pred(25) = 22, pred(22) = 20

Successor Algorithm Analysis

SUCC(x): If x has right subtree → minimum of right subtree If x has no right subtree → walk up from parent until coming from a left child Example with tree d h f b a e i g j c: - succ(d): right subtree exists → min of right subtree = h - succ(h): right subtree exists → min of right subtree = i (if exists) - succ(f): no right subtree → walk up: f is right child of h, h is right child of d → d is the answer (or NIL)

Building BST from Sorted Keys

Two methods to construct a BST from n sorted keys.

Method 1: Insert Keys in Order

Sort keys, then insert one by one: 1. Insert first key as root 2. Insert second key (compare with root, go left or right) 3. Continue for all keys
Complexity:
Worst case: O(n²), Average case: O(n lg n)
If keys are already sorted, produces a degenerate (right-skewed) tree

Method 2: Middle Element First

BUILD-BST(keys, lo, hi) if lo > hi return NIL mid = ⌊(lo + hi) / 2] z = new node with key = keys[mid] left[z] = BUILD-BST(keys, lo, mid-1) right[z] = BUILD-BST(keys, mid+1, hi) return z
Complexity:
T(n) = 2T(n/2) + Θ(1) = Θ(n lg n)
Produces a balanced BST with height Θ(lg n)

Comparison of Methods

PropertyMethod 1 (Sorted Insert)Method 2 (Middle First)
Time ComplexityO(n²) worst, O(n lg n) avgΘ(n lg n)
Tree HeightO(n) worst, O(lg n) avgΘ(lg n)
Balanced?No (if sorted input)Yes
SpaceO(n)O(n)
Example: Build BST from {10, 20, 30, 40, 50}

Method 1 (sorted insert): 10 → 20 → 30 → 40 → 50 (right-skewed, height 4)

Method 2 (middle first): Root=30, left={10,20}, right={40,50}, balanced (height 2)

Note: Method 2 only works if all keys are available at once. If keys arrive one by one, you must use Method 1 (or a self-balancing tree like AVL/Red-Black).

Counting Distinct BSTs with 4 Keys

Question: How many distinct BSTs can be built with 4 keys a < b < c < d?

Answer: C(4) = 14

But the question asks for number of valid insertion orders that produce the SAME BST shape.

For a balanced BST with root=b or c, the insertion orders must maintain the BST property.

Key insight: the root must always be inserted first. For keys {a,b,c,d}:

If root = b: valid orders include bacd, bcad, bcda, etc.

Total distinct BSTs = 14 (Catalan number)

Worked Example 1: Build BST from Sorted Keys

Build BST from keys: 1, 2, 3, 10, 12, 15, 30, 35

Method 1 (insert in order):

Insert 1: root = 1

Insert 2: 2 > 1, right child of 1

Insert 3: 3 > 1 → 3 > 2, right child of 2

...continues right-skewed

Result: Right-skewed tree (degenerate), height = 7

Method 2 (middle first):

Keys: [1, 2, 3, 10, 12, 15, 30, 35]

Root = keys[3] = 10

Left subtree: [1, 2, 3] → root = 2

Right subtree: [12, 15, 30, 35] → root = 15

Result: Balanced tree, height = 3

Worked Example 2: BST Operations

Operations on BST with keys: 20, 22, 25, 35, 37, 40

Search for 37: 20 → right → 25 → right → 37. Found! ✓

Search for 32: 20 → right → 25 → right → 37 → left → 35 → left → NIL. Not found.

Minimum: Follow left from 20 → 20 is minimum (leftmost)

Maximum: Follow right from 20 → 40 is maximum (rightmost)

Successor of 25: Right subtree min = 35

Predecessor of 37: Left subtree max = 35

Worked Example 3: Delete Operations

Delete nodes from BST: 20, 10, 30, 5, 15, 25, 35

Delete 5 (leaf): Simply remove. 10's left child becomes NIL.

Delete 10 (one child): 10 has only right child 15. Replace 10 with 15.

Delete 20 (two children):

- Successor of 20 = minimum of right subtree = 25

- Replace 20 with 25

- 25's right child (if any) replaces 25 in its original position
