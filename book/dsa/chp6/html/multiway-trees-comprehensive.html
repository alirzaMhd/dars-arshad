Multi-Way Trees: 2-3-4 & B-Trees

Data Structures — Complete Exam-Ready Guide

2-3-4 Tree — Definition

A 2-3-4 tree (also called a 2-4 tree) is a self-balancing multi-way search tree where every internal node has 2, 3, or 4 children. It is isomorphic to a Red-Black tree.

Key Property:
All leaves are at the same level
The tree is perfectly balanced — every path from root to leaf has equal length.

Node Types

1. 2-Node

Keys
1 key
Children
2 children
k₁

Left child: keys < k₁. Right child: keys > k₁.

[ k₁ ] / \ c₁ c₂

2. 3-Node

Keys
2 keys
Children
3 children
k₁
k₂

c₁: keys < k₁ | c₂: k₁ < keys < k₂ | c₃: keys > k₂

[ k₁ | k₂ ] / | \ c₁ c₂ c₃

3. 4-Node

Keys
3 keys
Children
4 children
k₁
k₂
k₃

Each key divides a range. 4 children separate the 4 ranges.

[ k₁ | k₂ | k₃ ] / | | \ c₁ c₂ c₃ c₄

Properties

Node Types
2-node: 1 key, 2 children
3-node: 2 keys, 3 children
4-node: 3 keys, 4 children
Balance
All leaves at same level
Perfectly balanced — no empty levels
Search Order
Keys in sorted order
Each node's keys are sorted
Height
h = ⌈log₄(n+1)⌉
Maximum height with n keys

Search Operation

Search(T, k): if T is empty: return NOT FOUND x = T.root while x ≠ leaf: i = number of keys in x while i ≥ 1 AND k < x.key[i]: i = i - 1 if i ≥ 1 AND k = x.key[i]: return (x, i) // found in node x else: x = x.child[i + 1] // descend to child // x is a leaf — check its keys i = number of keys in x while i ≥ 1 AND k < x.key[i]: i = i - 1 if i ≥ 1 AND k = x.key[i]: return (x, i) else: return NOT FOUND
Search Complexity:
O(log n)
At each level, compare with at most 3 keys (4-node). Height is O(log₄ n), so total comparisons = O(3 × log₄ n) = O(log n).

Height Bound

Maximum Height:
h ≤ ⌈log₄((n+1)/2)⌉
A 2-3-4 tree with n keys has height at most log₄(n). Each level has at least 2× more nodes than the previous (worst case all 2-nodes), and at most 4× (all 4-nodes).
Minimum Height:
h ≥ ⌈log₄(n+1)⌉
When all nodes are 4-nodes (maximum branching).

Insert Operation

Insertion in a 2-3-4 tree maintains balance by splitting full nodes on the way down.

⚠ Key Rule: Split Before Descending

Always split 4-nodes before descending into them. This ensures we never insert into a full node. Splitting pushes the middle key up to the parent.

Insert Pseudocode
procedure INSERT(T, k): if T.root is a 4-node AND T.root is full: splitRoot(T) // split before descending x = T.root while x is not leaf: if x is a 4-node: splitNode(x) // split before descending move to appropriate child else: move to appropriate child insertKey(x, k) // insert at leaf

Split Operation (4-Node → Two 2-Nodes)

When a 4-node is full, we split it and push the middle key up to the parent.

Splitting a 4-Node

Before split: [ k₁ | k₂ | k₃ ] ← full 4-node / | | \ c₁ c₂ c₃ c₄ After split: [ k₂ ] / \ [ k₁ ] [ k₃ ] ← two 2-nodes / \ / \ c₁ c₂ c₃ c₄
Split Operation:
Move middle key UP, split remaining into two 2-nodes
The middle key (k₂) goes to the parent. Left half (k₁) becomes a 2-node. Right half (k₃) becomes a 2-node. Children redistribute accordingly.

[ 20 | 40 ] / | \ [ 10 ] [ 30 ] [ 50 | 60 | 70 ]

B-Tree — Definition

A B-Tree of order (or degree) t is a balanced multi-way search tree designed for efficient disk-based storage. Every node satisfies specific constraints on the number of keys and children.

B-Tree of Degree t (t ≥ 2):
Every node has at most 2t − 1 keys
A node with the maximum 2t−1 keys is called a full node.

B-Tree Properties

Maximum Keys
2t − 1 keys per node
Maximum Children
2t children per node
Root Minimum
≥ 1 key
Other Nodes Minimum
≥ t − 1 keys
Children Count
m keys → m+1 children
Balance
All leaves at same level
⚠ B-Tree Properties (Exam Summary)

1. Every node has at most 2t−1 keys (and at most 2t children).
2. The root has at least 1 key.
3. Every non-root node has at least t−1 keys.
4. Every node with m keys has m+1 children.
5. All leaves at the same level.

B-Tree Node Structure

struct BTreeNode: int n; // current number of keys int keys[2t-1]; // sorted keys BTreeNode children[2t]; // child pointers bool leaf; // true if leaf node
B-Tree of degree t=3 (max 5 keys, 6 children per node): [ 10 | 20 | 30 | 40 ] / | | | \ [ 5 ] [ 15 ] [25] [35] [45] Each node: 1 ≤ n ≤ 5 keys (2t−1 = 5) Each non-root: t−1 = 2 minimum keys

Search Operation

BTreeSearch(x, k): i = 1 while i ≤ x.n AND k > x.keys[i]: i = i + 1 if i ≤ x.n AND k = x.keys[i]: return (x, i) // found at position i in node x else if x.leaf: return NOT FOUND else: DiskRead(x.children[i]) // descend to child return BTreeSearch(x.children[i], k)
Search Complexity:
O(t · log_t n)
At each level, scan up to 2t−1 keys = O(t). Height h ≤ log_t((n+1)/2). Total = O(t × log_t n).

Height Bounds

Upper Bound on Height:
h ≤ log_t((n+1)/2)
When all nodes are minimal (t−1 keys each), the tree is tallest. Starting from root with 1 key, each level multiplies by t: n ≥ 1 + 2(t−1) · (1 + t + t² + ... + t^{h−1}).
Lower Bound on Height:
h ≥ log_{2t}((n+1)/2)
When all nodes are full (2t−1 keys each), the tree is shortest.

Height Derivation

Derivation of h ≤ log_t((n+1)/2)
// Minimum keys at level 0 (root): 1 // Minimum keys at level 1: 2(t−1) // Minimum keys at level 2: 2(t−1)·t // ... // Minimum keys at level i: 2(t−1)·t^{i−1} Total keys n ≥ 1 + Σ(i=1 to h) 2(t−1)·t^{i−1} ≥ 1 + 2(t−1) · (t^h − 1)/(t − 1) ≥ 1 + 2(t^h − 1) ≥ 2t^h − 1 So: 2t^h ≤ n + 1 t^h ≤ (n+1)/2 h ≤ log_t((n+1)/2)

Complexity Summary

O(t · log_t n)
Search, Insert, and Delete in a B-Tree of degree t with n keys
Search
O(t · log_t n)
Scan keys at each level, descend to child
Insert
O(t · log_t n)
Find leaf, insert, split if full
Delete
O(t · log_t n)
Find key, remove, merge/borrow if underflow
Height
O(log_t n)
Logarithmic in base t

B-Tree Insert — Strategy

B-Tree insertion follows the same principle as 2-3-4 trees: split full nodes on the way down, then insert at the leaf.

Insert Pseudocode
procedure BTreeInsert(T, k): root = T.root if root.n = 2t − 1: // root is full s = NEWNODE() T.root = s s.leaf = false s.n = 0 s.children[1] = root BTreeSplitChild(s, 1) // split old root BTreeInsertNonFull(s, k) else: BTreeInsertNonFull(root, k)

BTreeSplitChild — Split a Full Child

Split Child Pseudocode
procedure BTreeSplitChild(x, i): // x is parent, i is index of full child to split y = x.children[i] // full child (has 2t−1 keys) z = NEWNODE() z.leaf = y.leaf z.n = t − 1 // Copy last t−1 keys of y to z for j = 1 to t−1: z.keys[j] = y.keys[j + t] // Copy last t children of y to z (if not leaf) if not y.leaf: for j = 1 to t: z.children[j] = y.children[j + t] y.n = t − 1 // Shift x's children right to make room for z for j = x.n + 1 downto i + 1: x.children[j + 1] = x.children[j] x.children[i + 1] = z // Shift x's keys right, insert middle key from y for j = x.n downto i: x.keys[j + 1] = x.keys[j] x.keys[i] = y.keys[t] // middle key moves up x.n = x.n + 1

BTreeInsertNonFull — Insert into Non-Full Node

Insert Non-Full Pseudocode
procedure BTreeInsertNonFull(x, k): i = x.n if x.leaf: // Shift keys right, insert k in sorted position while i ≥ 1 AND k < x.keys[i]: x.keys[i + 1] = x.keys[i] i = i − 1 x.keys[i + 1] = k x.n = x.n + 1 else: // Find child to descend into while i ≥ 1 AND k < x.keys[i]: i = i − 1 i = i + 1 // Split child if full before descending if x.children[i].n = 2t − 1: BTreeSplitChild(x, i) if k > x.keys[i]: i = i + 1 BTreeInsertNonFull(x.children[i], k)

Worked Example 6: B-Tree Search Trace

Search for key 37 in B-Tree (t=2)
[ 20 | 40 | 60 ] / | | \ [ 10 ] [ 30 ] [ 50 ] [ 70 ]

Trace:

1. Start at root [20|40|60].

2. Compare 37 with keys: 37 > 20 ✓, 37 < 40 ✗ → go to child[2] (between 20 and 40).

3. Arrive at node [30]. Compare: 37 > 30 ✓. But 37 ≠ 30 and node is leaf.

4. Key 37 NOT FOUND.

Search for key 50 in same tree

1. Root [20|40|60]: 50 > 40, 50 < 60 → go to child[3].

2. Node [50]: 50 = 50 → FOUND at position (50, 1).

Complexity: 2 disk reads (root + leaf), 4 comparisons total.

Worked Example 7: Height Calculation

Find maximum height of B-Tree with n=1,000,000 keys, t=100
Given:
n = 1,000,000, t = 100
Height Upper Bound:
h ≤ log_t((n+1)/2) = log₁₀₀(500,001)
Calculation:
100¹ = 100, 100² = 10,000, 100³ = 1,000,000 > 500,001
So h ≤ 3. The tree has at most 3 levels (height 2 or 3).

Answer: Maximum height = 3 (with t=100, a million keys fit in just 3 levels!)

Find height for n=1,000,000, t=2 (min degree)
Calculation:
h ≤ log₂(500,001) ≈ 18.9
2¹⁹ = 524,288 > 500,001. So h ≤ 19.

Answer: Maximum height = 19 with t=2.

Worked Example 8: Maximum Keys in B-Tree

How many keys can a B-Tree of height 3, t=3 hold at maximum?
Maximum keys formula:
n_max = (2t−1) · (1 + 2t + (2t)² + ... + (2t)^{h−1})
For t=3, h=3: each level multiplies by 6 (2t = 6).
Calculation:
n_max = 5 · (1 + 6 + 36) = 5 × 43 = 215

Maximum keys = 215 for a B-Tree of height 3, t=3.

Minimum keys at height 3, t=3
Minimum keys formula:
n_min = 1 + 2(t−1) · (1 + t + t² + ... + t^{h−1})
Calculation:
n_min = 1 + 4 · (1 + 3 + 9) = 1 + 4 × 13 = 53

Minimum keys = 53 for B-Tree of height 3, t=3.

When to Use Which?

2-3-4 Tree

• Conceptual model for Red-Black trees

• Simple implementation

• Fixed branching factor (4)

• Good for in-memory structures

B-Tree

• Database indexing (MySQL, PostgreSQL)

• File system indexing (NTFS, ext4)

• Tunable t for disk block size

• Optimal for disk-based storage

Relationship to Red-Black Trees

Isomorphism:
2-3-4 Tree ↔ Red-Black Tree
Every 2-3-4 tree has a corresponding Red-Black tree. 2-node → black node, 3-node → black + red child, 4-node → black + 2 red children. This is why 2-3-4 trees are important for understanding Red-Black tree balancing.

Node Types

  • 2-node: 1 key, 2 children

  • All leaves at same level

B-Tree Quick Reference Card

Properties (degree t)

  • Max keys: 2t − 1
  • Max children: 2t
  • Root min keys: 1
  • Other min keys: t − 1
  • m keys → m+1 children
  • All leaves at same level

  • Search: O(t · log_t n)
  • Insert: O(t · log_t n)
  • Delete: O(t · log_t n)

  • Upper: h ≤ log_t((n+1)/2)

Warning Box — Common Exam Mistakes

⚠ Exam Pitfalls

1. Forgetting: root has minimum 1 key, not t−1.
2. Confusing 2-3-4 tree (t=2) with general B-Tree.
3. Not splitting before descending (split on way DOWN, not up).
4. Thinking B-Trees are binary — they are multi-way.
5. Height formula: it's log_t, not log_2.
6. B-Tree height is O(log_t n), not O(log n) — the base matters for constants!
7. A 4-node split produces two 2-nodes, not one 3-node.

💡 Exam Tips

1. Always state the degree t when analyzing a B-Tree.
2. Draw the split operation step-by-step in your answer.
3. Show the height calculation with actual numbers.
4. Mention that 2-3-4 tree = B-Tree with t=2.
5. Quote the exact bounds: O(t · log_t n) for all operations.

Key Takeaway

2-3-4 Trees are the conceptual foundation. B-Trees generalize them for disk-based storage. Both achieve O(log n) search, insert, and delete with all leaves at the same level — perfect balance.
