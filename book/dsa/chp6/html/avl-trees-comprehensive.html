AVL Trees

Self-Balancing BST — Complete Exam Guide

AVL Tree Definition

An AVL tree is a self-balancing Binary Search Tree invented by Georgy Adelson-Velsky and Evgenii Landis in 1962.

Name Origin:
AVL = Adelson-Velsky and Landis
Named after its inventors, who published the first self-balancing BST.
Key Rule: An AVL tree is a BST that maintains an additional balance property: for every node, the height difference between its left and right subtrees is at most 1.

The Two Properties

BST Property

For every node x, all keys in x's left subtree are less than x.key, and all keys in x's right subtree are greater than x.key.

Balance Property

For every node x, the heights of x.left and x.right differ by at most 1.

Balance Condition (for every node x):
|height(x.left) - height(x.right)| ≤ 1
This is the defining property that distinguishes AVL from ordinary BST.

Height Convention

Height of a node = length of longest path from node to a leaf.

Empty tree (NIL)

Height = -1

Single node (leaf)

Height = 0

Tree with 3 nodes

Root height = 1

Note: Some textbooks use height = number of nodes on longest path (1 for single node). The formulas below use the edge-count convention (0 for single node). Always check which convention your exam uses!

Why AVL Trees?

A regular BST can degenerate to a linked list with height O(n). AVL trees guarantee O(lg n) height.

Problem: BST Degeneration

Insert keys 1, 2, 3, 4, 5 into a regular BST (always going right):

1 \ 2 \ 3 \ 4 \ 5 ← Height = 4, Search takes O(n)!
Solution: AVL Tree

Same keys with AVL balancing:

3 ← Height = 2, Search takes O(lg n)! / \ 2 4 / \ 1 5

Balance Factor

Definition:
BF(x) = height(x.left) - height(x.right)
Balance factor of node x = height of left subtree minus height of right subtree.
Valid Values:
BF(x) ∈ { -1, 0, +1 } for every node x
If any node has BF = ±2 or beyond, the tree is unbalanced and needs rotation.

BF = +1 (Left-heavy)

Left subtree is 1 level taller. Valid.

BF = 0 (Balanced)

Both subtrees same height. Perfectly balanced.

BF = -1 (Right-heavy)

Right subtree is 1 level taller. Valid.

BF = ±2 (Unbalanced!)

Height difference > 1. Needs rotation!

Example: Computing Balance Factors
30 (BF = +1) ← h(L)=2, h(R)=1 / \ 20 (BF=0) 40 (BF=-1) ← 20: h(L)=0,h(R)=0; 40: h(L)=0,h(R)=1 / \ \ 10 25 50 ← All leaves: BF = 0

Check: BF(30) = 2 - 1 = +1 ✓

Check: BF(20) = 1 - 1 = 0 ✓

Check: BF(40) = 0 - 1 = -1 ✓

All nodes have BF ∈ {-1, 0, +1} → Valid AVL tree!

Minimum Nodes for Height h

What is the minimum number of nodes N(h) needed to build an AVL tree of height h?

Recurrence Relation:
N(h) = N(h-1) + N(h-2) + 1
Root + left subtree of height h-1 (minimum) + right subtree of height h-2 (minimum). To minimize nodes, make subtrees as small as possible while maintaining balance.
Base Cases:
N(0) = 1, N(1) = 2
Height 0 tree: single node (1 node). Height 1 tree: root + one child (2 nodes).

Height Bound: h ≤ 2·lg(n+1) - 2

From the minimum nodes formula, we derive the maximum height of an AVL tree with n nodes.

Lower Bound on N(h):
N(h) ≥ 2^(h/2) - 1
This can be proved by induction. Since N(h) grows at least as fast as 2^(h/2), the tree cannot be too tall.
Derivation:
n ≥ N(h) ≥ 2^(h/2) - 1
n + 1 ≥ 2^(h/2) → lg(n+1) ≥ h/2 → h ≤ 2·lg(n+1)
Final Height Bound:
h ≤ 2·lg(n+1) - 2
For large n, this simplifies to h ≈ 2·lg(n). The AVL tree height is O(lg n).
Example: Maximum height for n = 1,000,000

h ≤ 2·lg(1,000,001) - 2 ≈ 2 × 20 - 2 = 38

Compare: degenerate BST would have height 999,999. AVL keeps it under 40!

Summary: Height of AVL Trees

Height:
Θ(lg n)
An AVL tree with n nodes always has height Θ(lg n), guaranteed by the balance property.
Tight Bound:
lg(n+1) - 1 ≤ h ≤ 1.44 · lg(n+2) - 0.328
The lower bound is for a complete binary tree. The upper bound uses the golden ratio φ ≈ 1.618.

Why Rotations?

After insertion or deletion, some node may become unbalanced (|BF| = 2). We use rotations to restore balance while maintaining the BST property.

Key Fact: At most 1 or 2 rotations are needed to fix any imbalance after insertion. After deletion, up to O(lg n) rotations may be needed.

Identifying the Problem Nodes

Three Important Nodes:
x = nearest ancestor with BF = ±2
x is the first unbalanced node encountered when walking up from the newly inserted node.
y = child of x on the insertion path
y is the child of x that is closer to the newly inserted node.
z = newly inserted node (or the node that caused the imbalance)
z is the node that was just inserted, or in deletion, the node that was removed.
Example: Identifying x, y, z
Before inserting z=30: 50 (x) ← x: first unbalanced ancestor (BF=+2) / 30 (y) ← y: child of x on insertion path / z=30 ← z: newly inserted node

After insertion of 30: BF(50) = 2 (unbalanced!). x=50, y=30, z=30.

Four Rotation Cases

The type of rotation depends on where y and z are relative to x.

Case 1: Left-Left (LL) — Single Right Rotation

Condition: y is LEFT child of x, z is LEFT child of y

Fix: Right rotate(x)

x y / \ / \ y C → A x / \ / \ A B B C BF(x)=+2, BF(y)=+1 → after right rotate(x): balanced

Think: "z is left of y, y is left of x" → everything is left-leaning → push x down to the right.

Case 2: Right-Right (RR) — Single Left Rotation

Condition: y is RIGHT child of x, z is RIGHT child of y

Fix: Left rotate(x)

x y / \ / \ A y → x C / \ / \ B C A B BF(x)=-2, BF(y)=-1 → after left rotate(x): balanced

Think: "z is right of y, y is right of x" → everything is right-leaning → push x down to the left.

Case 3: Right-Left (RL) — Double Rotation

Condition: y is RIGHT child of x, z is LEFT child of y

Fix: Right rotate(y), then Left rotate(x)

x x z / \ / \ / \ A y → A z → x y / \ / \ / \ / \ z C B y A B C C' / \ / \ B D D C' Step 1: Right rotate y | Step 2: Left rotate x

Think: "y is right of x, z is left of y" → zig-zag pattern → two rotations needed.

Case 4: Left-Right (LR) — Double Rotation

Condition: y is LEFT child of x, z is RIGHT child of y

Fix: Left rotate(y), then Right rotate(x)

x x z / \ / \ / \ y C → z C → y x / \ / \ / \ / \ A z y D A B C D / \ / \ B D A B Step 1: Left rotate y | Step 2: Right rotate x

Think: "y is left of x, z is right of y" → zig-zag pattern → two rotations needed.

Rotation Comparison Table

Case Name Condition Rotation When
1 LL y = LEFT of x, z = LEFT of y Right rotate(x) Insert into left subtree of left child
2 RR y = RIGHT of x, z = RIGHT of y Left rotate(x) Insert into right subtree of right child
3 RL y = RIGHT of x, z = LEFT of y Right rotate(y), Left rotate(x) Insert into left subtree of right child
4 LR y = LEFT of x, z = RIGHT of y Left rotate(y), Right rotate(x) Insert into right subtree of left child

How to Determine the Case

Decision Tree:
Look at y's position relative to x, then z's position relative to y:
y is LEFT of x? y is RIGHT of x? / \ / \ YES NO YES NO | | | | z LEFT of y? z RIGHT of y? z LEFT of y? z RIGHT of y? / \ / \ / \ / \ YES NO YES NO YES NO YES NO | | | | | | | | LL LR RL* RR RL RR* LL* RR * = impossible (BST property violation)
Only 4 valid cases exist: LL, RR, RL, LR. The "impossible" cases would violate the BST ordering property.

AVL Insert Algorithm

Insert works in two phases: standard BST insert, then fix imbalances walking back up.

AVL-INSERT(T, z) // Phase 1: Standard BST insert 1. Insert z following BST rules (search for position, attach as leaf) 2. Set height[z] = 0 3. Set BF[z] = 0 // Phase 2: Fix imbalances 4. x = parent[z] 5. while x ≠ NIL: a. Update height[x] and BF[x] b. if |BF[x]| > 1: // Found unbalanced node! Determine y (child of x toward z) Determine case (LL/RR/RL/LR) Apply rotation(s) return // After fix, tree is balanced x = parent[x]

Left Rotate Operation

LEFT-ROTATE(T, x) y = right[x] // y is x's right child right[x] = left[y] // y's left subtree becomes x's right if left[y] ≠ NIL parent[left[y]] = x parent[y] = parent[x] // Link y to x's parent if parent[x] = NIL root[T] = y else if x = left[parent[x]] left[parent[x]] = y else right[parent[x]] = y left[y] = x // x becomes y's left child parent[x] = y // Update heights height[x] = max(height[left[x]], height[right[x]]) + 1 height[y] = max(height[left[y]], height[right[y]]) + 1

Right Rotate Operation

RIGHT-ROTATE(T, x) y = left[x] // y is x's left child left[x] = right[y] // y's right subtree becomes x's left if right[y] ≠ NIL parent[right[y]] = x parent[y] = parent[x] if parent[x] = NIL root[T] = y else if x = left[parent[x]] left[parent[x]] = y else right[parent[x]] = y right[y] = x // x becomes y's right child parent[x] = y // Update heights height[x] = max(height[left[x]], height[right[x]]) + 1 height[y] = max(height[left[y]], height[right[y]]) + 1

Insert Pseudocode (Complete)

AVL-INSERT(T, z) // BST insert y = NIL; x = root[T] while x ≠ NIL: y = x if key[z] < key[x] x = left[x] else x = right[x] parent[z] = y if y = NIL root[T] = z else if key[z] < key[y] left[y] = z else right[y] = z height[z] = 0 BF[z] = 0 // Walk up and fix current = parent[z] while current ≠ NIL: h_left = if left[current] ≠ NIL then height[left[current]] else -1 h_right = if right[current] ≠ NIL then height[right[current]] else -1 height[current] = max(h_left, h_right) + 1 BF[current] = h_left - h_right if BF[current] = 2: if BF[left[current]] ≥ 0: // LL case RIGHT-ROTATE(T, current) else: // LR case LEFT-ROTATE(T, left[current]) RIGHT-ROTATE(T, current) return if BF[current] = -2: if BF[right[current]] ≤ 0: // RR case LEFT-ROTATE(T, current) else: // RL case RIGHT-ROTATE(T, right[current]) LEFT-ROTATE(T, current) return current = parent[current]

Important Properties of AVL Insert

At Most 1 Imbalance

Insertion creates at most one unbalanced node on the path up. After fixing it, the tree is balanced.

At Most 2 Rotations

Fixing requires at most 2 rotations (for RL and LR cases). LL and RR need only 1 rotation.

O(lg n) Time

BST insert is O(lg n), fix-up walks up O(lg n) nodes, each taking O(1). Total: O(lg n).

Key Difference from BST: In a regular BST, all operations are O(n) worst case. In AVL, they are all O(lg n) worst case — guaranteed by the balance property.

Space Complexity

Per Node:
Extra space: O(1) per node
Each node stores: key, left, right, parent pointers, height, balance factor. This is constant extra space per node compared to a regular BST.
Total Space:
O(n)
Same as any binary tree with n nodes. The AVL overhead is only the height and BF fields.

Rotation Cost Analysis

Insert Rotations

At most 1 rotation (single) or 2 rotations (double). Each rotation is O(1). Total rotation cost: O(1).

Delete Rotations

In the worst case, deletion may require O(lg n) rotations because rebalancing can propagate up to the root.

Why at most 1 imbalance for insert?

After inserting a node, walking up from that node:

1. All ancestors above the first unbalanced node have their heights unchanged.

2. After rotation, the subtree height returns to what it was before the insertion.

Therefore, fixing one imbalance restores the entire tree to balance!
