RED-BLACK TREES

Self-Balancing BST — Complete Guide for 20/20 Exam

What is a Red-Black Tree?

A Red-Black Tree (RBT) is a self-balancing Binary Search Tree where each node stores an extra bit of information: its color (RED or BLACK). The coloring rules ensure the tree remains approximately balanced during insertions and deletions.

Core Idea:
BST + Color Property = Red-Black Tree
A BST that maintains balance through node coloring constraints
Node Structure
struct RBNode { key // data value color // RED or BLACK left // left child pointer right // right child pointer parent // parent pointer }

The Five Red-Black Properties

These properties MUST hold for every Red-Black tree at all times.

Property 1: Every node is either RED or BLACK.
Property 2: The root is BLACK.
Property 3: Every leaf (NIL) is BLACK.
Property 4: If a node is RED, then both its children are BLACK. (No two consecutive red nodes on any path)
Property 5: For each node, all simple paths from the node to descendant leaves contain the same number of BLACK nodes.
⚠ EXAM TIP
Property 5 defines the black height of a node. Properties 1-4 ensure that no path is more than twice as long as any other path, guaranteeing O(log n) operations.

Visual Example

            13
           /    \
      8        17
     /  \      /  \
  1    11  15    25
       /          /  \
    6          22    27

Black nodes: 13, 1, 11, 15, 25 | Red nodes: 8, 17, 6, 22, 27

Black Height — bh(x)

Definition:
bh(x) = number of black nodes on any path from x (not counting x) to a leaf
By Property 5, this is the same for ALL paths from x
Example: Calculating Black Height
            13  bh = 2
           /    \
      8        17
     /  \      /  \
  1    11  15    25  bh = 1 (each)
  NIL  NIL NIL  NIL  NIL  NIL  NIL  NIL  bh = 0

bh(13): Path 13→8→1→NIL has 2 black nodes (1, NIL). bh = 2.

bh(8): Path 8→1→NIL has 1 black node (NIL). bh = 1.

bh(1): Path 1→NIL has 0 black nodes (not counting 1). bh = 0.

Key Bounds — Must Memorize

Minimum Nodes with bh = h:
n >= 2^h - 1
A tree with black height h has at least 2^h - 1 internal nodes
Maximum Height:
h <= 2 * lg(n + 1)
The height of a Red-Black tree with n nodes is at most 2*log base 2 of (n+1)
Black Node Ratio:
At least half of all nodes on any path are black
Since no two red nodes are consecutive (Property 4), at least every other node is black
Proof Sketch: Maximum Height

Let bh = h (black height).

From Property 4: No two consecutive reds → at most h red nodes on any path.

Total nodes on longest path: h black + h red = 2h.

From minimum nodes: n >= 2^h - 1 → h <= lg(n+1).

Maximum height = h + h = 2h <= 2*lg(n+1)

If bh = 0

Min nodes: 2^0 - 1 = 0

Just a single black leaf (NIL)

If bh = 1

Min nodes: 2^1 - 1 = 1

One black root with NIL children

If bh = 2

Min nodes: 2^2 - 1 = 3

Black root, 2 black children

If bh = 3

Min nodes: 2^3 - 1 = 7

Full black tree of height 3

Why These Bounds Matter

The maximum height of 2*lg(n+1) means all operations (search, insert, delete) are O(log n). This is the KEY advantage of Red-Black trees over regular BSTs.

RB-INSERT Overview

Insertion in a Red-Black tree has two phases:

  • Phase 1: Standard BST insert, but new node is colored RED
  • Phase 2: Fix any Red-Black property violations using RB-INSERT-FIXUP
⚠ Why insert as RED?
Inserting as RED may violate Property 4 (red node can't have red children) but never violates Property 5 (black height). Property 4 is easier to fix than Property 5.

RB-INSERT Pseudocode

Performs a standard BST insert, then colors the new node RED and calls FIXUP to restore Red-Black properties.

RB-INSERT(T, z) y ← T.nil // y will track the parent of the new node x ← T.root // x traverses down to find insertion point while x ≠ T.nil // walk down until we reach a leaf y ← x // save current node as potential parent if z.key < x.key // go left if new key is smaller x ← x.left else // go right otherwise x ← x.right z.parent ← y // link new node to its parent if y = T.nil // tree was empty T.root ← z // new node becomes root else if z.key < y.key // new node is left child y.left ← z else // new node is right child y.right ← z z.left ← T.nil // set new node's left child to NIL z.right ← T.nil // set new node's right child to NIL z.color ← RED // color new node RED (may violate Prop 4) RB-INSERT-FIXUP(T, z) // fix any Red-Black violations

RB-INSERT-FIXUP — Three Cases

When we insert a RED node z, if z.parent is also RED, we have a violation. Let y = z's uncle.

Case 1: Uncle y is RED

Action: Recolor parent (z.p) and uncle (y) to BLACK, grandparent (z.p.p) to RED.

Then: Move z up to grandparent and repeat.

z.p.color = BLACK y.color = BLACK z.p.p.color = RED z = z.p.p // move up
Case 2: Uncle y is BLACK, z is RIGHT child

Action: Left rotate on z's parent to convert to Case 3.

z = z.p LEFT-ROTATE(T, z) // now falls into Case 3
Case 3: Uncle y is BLACK, z is LEFT child

Action: Right rotate on grandparent, recolor parent and grandparent.

z.p.color = BLACK z.p.p.color = RED RIGHT-ROTATE(T, z.p.p)
⚠ FIXUP Loop
The loop continues while z.p.color == RED. When done, always set T.root.color = BLACK (Property 2).

RB-INSERT-FIXUP Pseudocode

Restores Red-Black properties after inserting a RED node. Handles three cases based on the uncle's color and the node's position. Loops until the parent is no longer RED.

RB-INSERT-FIXUP(T, z) while z.p.color = RED // while parent is RED (violation exists) if z.p = z.p.p.left // parent is LEFT child of grandparent y ← z.p.p.right // y = uncle (right child of grandparent) if y.color = RED // CASE 1: uncle is RED z.p.color ← BLACK // color parent BLACK y.color ← BLACK // color uncle BLACK z.p.p.color ← RED // color grandparent RED z ← z.p.p // move z up to grandparent (loop continues) else // uncle is BLACK if z = z.p.right // CASE 2: z is RIGHT child (zig-zag) z ← z.p // move z up to parent LEFT-ROTATE(T, z) // left rotate → converts to Case 3 // CASE 3: z is LEFT child (zig-zig) z.p.color ← BLACK // color parent BLACK z.p.p.color ← RED // color grandparent RED RIGHT-ROTATE(T, z.p.p) // right rotate on grandparent → done else // symmetric: parent is RIGHT child y ← z.p.p.left // y = uncle (left child of grandparent) if y.color = RED // CASE 1 (symmetric): uncle is RED z.p.color ← BLACK y.color ← BLACK z.p.p.color ← RED z ← z.p.p else // uncle is BLACK if z = z.p.left // CASE 2 (symmetric): z is LEFT child z ← z.p RIGHT-ROTATE(T, z) // right rotate → converts to Case 3 // CASE 3 (symmetric): z is RIGHT child z.p.color ← BLACK z.p.p.color ← RED LEFT-ROTATE(T, z.p.p) // left rotate on grandparent → done T.root.color ← BLACK // Property 2: root must always be BLACK

LEFT-ROTATE Pseudocode

Rotates node x down to the left, making its right child y the new subtree root. Preserves the BST ordering property.

LEFT-ROTATE(T, x) y ← x.right // y is x's right child (will become new root of subtree) x.right ← y.left // move y's left subtree to be x's right subtree if y.left ≠ T.nil // if y's left child exists y.left.parent ← x // update the parent pointer of that child y.parent ← x.parent // y takes x's position in the tree if x.parent = T.nil // if x was the root T.root ← y // y becomes the new root else if x = x.parent.left // if x was a left child x.parent.left ← y // update parent's left pointer to y else // if x was a right child x.parent.right ← y // update parent's right pointer to y y.left ← x // x becomes y's left child x.parent ← y // update x's parent to y

Search

Time: O(log n)

Same as standard BST, but guaranteed O(log n)

Insert

Time: O(log n)

BST insert + at most 2 rotations in fixup

Delete

Time: O(log n)

BST delete + at most 3 rotations in fixup

Space

Space: O(n)

Extra color bit per node + parent pointers

When to Use Red-Black Trees?

Best Use Cases

• Dictionaries / Maps

• Priority Queues

• OS schedulers

• Memory allocators

• Java TreeMap, TreeMap

Advantages

• Guaranteed O(log n)

• Fewer rotations than AVL

• Good for insert/delete heavy

• Only 1 extra bit per node

Quick Reference Card

Properties

1. Every node is RED or BLACK

2. Root is BLACK

3. All leaves (NIL) are BLACK

4. RED node → children are BLACK

5. Same black count on all paths

Key Formulas

bh(x) = black nodes from x to leaf

Min nodes: 2^h - 1

Max height: 2*lg(n+1)

At least 50% nodes are black

Insert Steps

1. BST insert as RED

2. Run FIXUP if violation

3. Color root BLACK at end

FIXUP Cases

Case 1: Uncle RED → Recolor

Case 2: Uncle BLACK, z right → Rotate

Case 3: Uncle BLACK, z left → Rotate + Recolor

Complexity

Search: O(log n)

Insert: O(log n)

Delete: O(log n)

Space: O(n)

Rotations

Insert: At most 2

Delete: At most 3

Total: O(1) amortized

Common Exam Mistakes

Mistake 1: Forgetting to color root BLACK

After RB-INSERT-FIXUP, always set T.root.color = BLACK. This is required by Property 2.

Mistake 2: Confusing uncle color with node color

The uncle y is z.p.p's other child (not z's sibling). Check y.color, not z.p.p.color.

Mistake 3: Forgetting NIL nodes are BLACK

Property 3 says ALL leaves (NIL sentinels) are BLACK. Don't count them as "no node".

Mistake 4: Confusing Case 2 and Case 3

Case 2 converts to Case 3 via left rotation. They're not separate solutions — Case 2 is a setup for Case 3.
