BST Construction Methods

Data Structures — Complete Guide for 20/20 Exam

Method 1: Sequential Insertion

BUILD_BST_1(keys) T = empty tree for each key k in keys INSERT(T, k) return T
Algorithm:
Insert keys one by one in the given order
1. Start with empty tree
2. Insert first key as root
3. Insert remaining keys using standard BST insert
4. Result depends on input order
Example: Build BST from keys 30, 10, 40, 5, 15
Insert 30: Insert 10: Insert 40: 30 30 30 / / \ 10 10 40 Insert 5: Insert 15: 30 30 / \ / \ 10 40 10 40 / / \ 5 5 15

Final inorder: 5, 10, 15, 30, 40

Time Complexity

• Per insertion: O(h)

• Total: O(n × h)

• Best case: O(n lg n)

• Worst case: O(n²)

When to Use

• When input order is random

• When you don't have all keys upfront

• Simple implementation

Method 2: Balanced Construction

BUILD_BST_2(keys) sort(keys) // O(n lg n) return BUILD_BALANCED(keys, 0, n-1) BUILD_BALANCED(keys, start, end) if start > end return NIL mid = (start + end) / 2 node = new Node(keys[mid]) node.left = BUILD_BALANCED(keys, start, mid-1) node.right = BUILD_BALANCED(keys, mid+1, end) return node
Algorithm:
Sort keys, then pick middle as root recursively
1. Sort all keys first
2. Pick middle element as root
3. Recursively build left subtree from left half
4. Recursively build right subtree from right half
Example: Build balanced BST from sorted keys [5, 10, 15, 20, 25]
Step 1: Pick 20 as root 20 Step 2: Left subtree from [5, 10, 15], right from [25] 20 / \ 10 25 / \ 5 15 Step 3: Complete tree 20 / \ 10 25 / \ 5 15

Height = ⌊lg 5⌋ = 2 (optimal!)

Time Complexity

• Sorting: O(n lg n)

• Building: O(n)

• Total: O(n lg n)

When to Use

• When all keys are known upfront

• When you need guaranteed balance

• For optimal search performance

Key Advantage: This method guarantees a balanced tree with height O(lg n), ensuring O(lg n) for all operations.

Method Comparison

Aspect Method 1 (Sequential) Method 2 (Balanced)
Time Complexity O(n²) worst, O(n lg n) average O(n lg n) always
Resulting Height Depends on input order Always O(lg n)
Requires Sorting No Yes
Online/Offline Online (can insert one by one) Offline (need all keys first)
Implementation Simpler More complex
Exam Tip: If the question asks for "optimal" BST construction, use Method 2. If it asks for "simple" or "online", use Method 1.

Worked Examples

Example 1: Build BST from keys [1, 2, 3, 4]

Method 1 (Insert in order 1, 2, 3, 4):

1 \ 2 \ 3 \ 4 Height = 3 (WORST CASE!)

Method 2 (Balanced):

2 / \ 1 3 \ 4 Height = 2 (OPTIMAL!)
Example 2: Count possible BSTs with 4 keys

Using Catalan number: C(4) = 14

Method 1 can produce any of these 14 trees depending on insertion order.

Method 2 always produces the same balanced tree.

Example 3: Build balanced BST from [10, 20, 30, 40, 50, 60, 70]
Sorted: [10, 20, 30, 40, 50, 60, 70] Middle = 40 (root) 40 / \ 20 60 / \ / \ 10 30 50 70 Height = ⌊lg 7⌋ = 2 (optimal)

BST with Duplicate Keys

Handling Duplicates:
When duplicate keys are allowed, the number of distinct BSTs changes
For n keys where key i appears nᵢ times, the number of distinct BSTs is different from Catalan number
Example 1: 4 keys with duplicates

Keys: {a, a, b, c} where a appears twice

How many distinct BSTs?

• The inorder traversal must be sorted: a, a, b, c

• But the two 'a's can be interchanged → no new BST

• Total distinct BSTs = C(4) / 2! = 14 / 2 = 7

General Formula:

For n keys with duplicates:
Distinct BSTs = C(n) / (n₁! × n₂! × ... × nₖ!)
Where nᵢ is the frequency of each distinct key
Example 2: 7 keys with one duplicate

Keys: {a₁, a₁, a₂, a₃, a₅, a₆, a₇} where a₁ appears twice

Counting valid input orderings:

• Total permutations of 7 elements: 7!

• Divide by 2! for the duplicate a₁

• Valid orderings = 7! / 2! = 5040 / 2 = 2520

But not all produce distinct BSTs!

• The two a₁'s can be inserted in different positions

• If a₁ is always inserted before a₁, we get the same tree

• So distinct BSTs = 2520 / 2 = 1260

Key Insight:
For n keys with nᵢ duplicates of each key:
1. Total permutations = n! / (n₁! × n₂! × ... × nₖ!)
2. Each permutation can produce a BST
3. But some permutations produce the SAME BST
4. The number of distinct BSTs is less than the permutation count
Exam Tip: When the question says "keys can be repeated", use the permutation formula n!/(n₁!×n₂!×...×nₖ!) to count valid input sequences, NOT the Catalan number!
