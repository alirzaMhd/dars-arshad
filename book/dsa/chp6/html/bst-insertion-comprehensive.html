BST Insert Algorithm

INSERT(T, z) y = NIL x = root[T] while x ≠ NIL y = x if key[z] < key[x] x = left[x] else x = right[x] parent[z] = y if y = NIL root[T] = z else if key[z] < key[y] left[y] = z else right[y] = z
How It Works:
Search for NULL position, then insert new node as leaf
1. Start at root, track parent node
2. Compare new key with current node
3. Go left if smaller, right if larger
4. When NULL is reached, insert new node there
Important: BST does NOT allow duplicate keys. If the key already exists, the insertion is ignored (or handled differently based on implementation).

Step-by-Step Insertion Process

Inserting key k=25 into this BST:
20 / \ 10 30 / \ / \ 5 15 25 35

Step 1: Compare 25 with 20 → 25 > 20, go RIGHT

Step 2: Compare 25 with 30 → 25 < 30, go LEFT

Step 3: Compare 25 with 25 → 25 = 25 → Key already exists!

Result: No insertion (duplicate key)

Inserting key k=22 into this BST:
Before: After: 20 20 / \ / \ 10 30 10 30 / \ / \ / \ / \ 5 15 25 35 5 15 25 35 / 22

Step 1: 22 > 20 → go RIGHT

Step 2: 22 < 30 → go LEFT

Step 3: 22 < 25 → go LEFT

Step 4: NULL reached → Insert 22 as left child of 25

Worked Examples

Example 1: Insert keys 30, 10, 40, 5, 15, 35, 45
Step 1: Insert 30 Step 2: Insert 10 Step 3: Insert 40 30 30 30 / / \ 10 10 40 Step 4: Insert 5 Step 5: Insert 15 Step 6: Insert 35 30 30 30 / \ / \ / \ 10 40 10 40 10 40 / / \ / \ 5 5 15 35 45

Final inorder: 5, 10, 15, 30, 35, 40, 45

Example 2: Insert keys in REVERSE order

Keys: 45, 40, 35, 30, 15, 10, 5

This creates a SKEWED tree (linked list): 45 \ 40 \ 35 \ 30 \ 15 \ 10 \ 5

This is the WORST CASE! Height = n-1, all operations become O(n)

Insertion Order Matters!

Same keys, different order → different trees

Keys: {1, 2, 3, 4}

Order 1: 2, 1, 4, 3

2 / \ 1 4 / \ 3 NIL

Order 2: 3, 2, 4, 1

3 / \ 2 4 / 1
Number of possible BSTs with n keys:
C(n) = (2n)! / ((n+1)! × n!)
For n=4: C(4) = 14 different possible BSTs
Key Insight: The shape of BST depends on insertion order. This is why balanced BSTs (AVL, Red-Black) are preferred - they maintain balance regardless of insertion order.

Quick Reference Card

Algorithm

while x ≠ NIL y = x if key[z] < key[x] x = left[x] else x = right[x] insert z as child of y

Key Points

• New node always inserted as leaf

• No duplicates allowed

• Order of insertion matters

• O(h) time complexity

Time Complexity

• Best: O(1)

• Average: O(lg n)

• Worst: O(n)

Space Complexity

• Iterative: O(1)

• Recursive: O(h)

• New node: O(1)
