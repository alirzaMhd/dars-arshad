HUFFMAN CODING

Variable-Length Prefix-Free Encoding — Complete Guide for 20/20 Exam

1. What Is Huffman Coding?

Huffman coding is a lossless data compression algorithm that assigns variable-length binary codes to input characters based on their frequencies. Characters that appear more often get shorter codes, and characters that appear less often get longer codes.

Core Idea:
Total Encoding Length = Σ (frequency[i] × code_length[i])
Minimize this sum by assigning shorter codes to higher-frequency characters.
Key Property: Prefix-Free Codes

Huffman coding produces prefix-free (also called prefix codes): no codeword is a prefix of another codeword. This property allows unambiguous decoding without separators.

Why Prefix-Free Matters

If a=0 and b=01, then the string "01" could decode as "ab" or "b" — ambiguous!

With prefix-free codes like a=0, b=10, c=11, every bitstream has exactly one valid decode.

2. The Huffman Tree

Huffman codes are derived from a binary tree (the Huffman tree). Each leaf node is a character; each internal node is the sum of its children's frequencies.

Tree Structure:
Left edge → bit 0  |  Right edge → bit 1
The code for any character is the sequence of 0s and 1s on the path from root to that leaf.
⚠ Common Mistake

Huffman tree is NOT a Binary Search Tree (BST). There is no ordering property — left child is NOT smaller than parent. The tree structure depends purely on frequencies.

3. Binary vs Ternary Huffman

Binary Huffman

Uses symbols: 0, 1

Each internal node has 2 children

Most common variant

Extract 2 minimums per step

Ternary Huffman

Uses symbols: 0, 1, 2

Each internal node has 3 children

Requires n-1 ≡ 0 (mod 2) for clean construction

Extract 3 minimums per step

⚠ Ternary Huffman Padding

For ternary Huffman, if (number of characters - 1) is not divisible by 2, you must add dummy characters with frequency 0 to make it work. You need (n-1) % 2 == 0.

4. Goal: Minimize Total Encoding Length

Objective Function:
minimize Σ f(i) × l(i)
where f(i) is the frequency of character i, and l(i) is the length of its Huffman code (in bits).
Total bits in encoded file:
Total = Σ (freq[i] × code_length[i]) bits
This is the weighted external path length of the Huffman tree.

5. Greedy Algorithm — Step by Step

Huffman's algorithm is a greedy algorithm that builds the tree bottom-up using a min-heap (priority queue).

Huffman(C): n = |C| Q = min-heap of leaf nodes (each with char and frequency) for i = 1 to n - 1: left = Extract-Min(Q) // remove node with smallest freq right = Extract-Min(Q) // remove node with second smallest create new internal node z z.freq = left.freq + right.freq z.left = left z.right = right Insert(Q, z) // insert z back into heap return Extract-Min(Q) // root of Huffman tree
Algorithm Invariant

At every step, the two smallest-frequency nodes in the heap are combined. This greedy choice is provably optimal — no other pairing can produce a shorter total encoding.

6. Step-by-Step Walkthrough

Step 1: Create a leaf node for each character with its frequency. Insert all into a min-heap.
Step 2: While heap has more than 1 node:
Step 3: Extract two nodes with minimum frequency (call them left and right).
Step 4: Create a new internal node with frequency = left.freq + right.freq. Set left and right as children.
Step 5: Insert the new internal node back into the heap.
Step 6: The remaining node in the heap is the root of the Huffman tree.
Step 7: Assign codes by traversing: left edge = 0, right edge = 1. Read path from root to each leaf.

7. Complexity Analysis

Time Complexity

O(n lg n)

n = number of distinct characters

Each of n-1 iterations does 2 Extract-Min + 1 Insert = O(lg n) each

Space Complexity

O(n)

Store n leaf nodes + n-1 internal nodes

Min-heap uses O(n) space

Detailed Breakdown:
(n - 1) iterations × [2 × O(lg n) + O(lg n)] = O(n lg n)
Extract-Min: O(lg n) on a binary heap. Insert: O(lg n). Total iterations: n - 1.

9. Optimality of Huffman Codes

Theorem: Huffman codes are optimal among prefix-free codes.

No other prefix-free binary code can achieve a shorter average code length than the Huffman code for a given set of character frequencies.

⚠ Important Caveat

Huffman is optimal only among prefix-free codes. Arithmetic coding can sometimes achieve better compression by encoding entire messages as single numbers, bypassing the integer-bit-per-symbol limitation.

Lower Bound (Shannon Entropy):
H = -Σ p(i) × lg₂(p(i))  ≤  average code length < H + 1
Huffman's average code length is within 1 bit of the Shannon entropy H, which is the theoretical minimum for any prefix-free code.
Proof Sketch (Greedy Choice Property)

1. The two lowest-frequency characters must have the longest codes in any optimal prefix-free code.

2. They can be placed as siblings (both at maximum depth) without loss of optimality.

3. Replacing them with a single combined node reduces the problem by one character.

4. By induction, the greedy algorithm produces an optimal code.

11. Binary Huffman (d-ary with d=2)

Standard Huffman coding uses binary symbols {0, 1}. Each internal node has exactly 2 children.

Binary Huffman Algorithm: Q = min-heap of leaf nodes while |Q| > 1: left = Extract-Min(Q) right = Extract-Min(Q) z = new node(freq = left.freq + right.freq) z.left = left; z.right = right Insert(Q, z) return Extract-Min(Q)
Key Point

For binary Huffman, you always need exactly n-1 merge operations, each combining 2 nodes. No padding required.

12. Ternary Huffman (d-ary with d=3)

Ternary Huffman uses symbols {0, 1, 2}. Each internal node has 3 children.

⚠ Padding Requirement

For ternary Huffman, you need (n - 1) mod 2 = 0, where n = number of characters. If not satisfied, add dummy characters with frequency 0 until it is.

Formula: add dummy_count = (2 - (n-1) % 2) % 2 dummy characters.

Ternary Huffman Algorithm: Q = min-heap of leaf nodes // Pad with dummy chars if needed while (|Q| - 1) % 2 != 0: Insert(Q, dummy_char with freq 0) while |Q| > 1: a = Extract-Min(Q) b = Extract-Min(Q) c = Extract-Min(Q) z = new node(freq = a.freq + b.freq + c.freq) z.children = [a, b, c] Insert(Q, z) return Extract-Min(Q)
Ternary Example: 4 characters {a=5, b=9, c=12, d=13}

n = 4, (n-1) = 3, 3 mod 2 = 1 → need 1 dummy character (freq=0)

Characters: a(5), b(9), c(12), d(13), dummy(0)

Iteration 1: Extract dummy(0), a(5), b(9) → create [14]. Heap: c(12), d(13), [14]

Iteration 2: Extract c(12), d(13), [14] → create [39] (root).

[39] / | \ c(12) d(13) [14] / | \ a(5) b(9) dummy(0) Codes: c = 0 (length 1) d = 1 (length 1) a = 20 (length 2) b = 21 (length 2) dummy = 22 (not transmitted) Total: 12×1 + 13×1 + 5×2 + 9×2 = 12+13+10+18 = 53 ternary symbols

13. General d-ary Huffman

General Rule for d-ary Huffman:
Pad so that (n - 1) mod (d - 1) = 0
For binary (d=2): (n-1) mod 1 = 0 → always satisfied. For ternary (d=3): (n-1) mod 2 = 0. For quaternary (d=4): (n-1) mod 3 = 0.
d (alphabet size) Mod condition Extract per step
2 (binary) (n-1) mod 1 = 0 (always true) 2 nodes
3 (ternary) (n-1) mod 2 = 0 3 nodes
4 (quaternary) (n-1) mod 3 = 0 4 nodes
d (n-1) mod (d-1) = 0 d nodes

Exercise 2: 256-Character File

A file contains 256 distinct characters, each appearing exactly once (uniform distribution).

⚠ Key Insight

When all frequencies are equal, Huffman coding provides no benefit over fixed-length codes. Each character gets a code of the same length.

Analysis:

• 256 distinct characters, each with frequency 1

• Fixed-length code needs ⌈log₂(256)⌉ = 8 bits per character

• Huffman will also produce codes of length 8 for all characters (since all frequencies are equal)

• Total file size: 256 × 8 = 2048 bits = 256 bytes

What If Distribution Is Skewed?

If some characters appear much more frequently than others, Huffman coding shines. For example, if character 'e' appears 50% of the time, it gets a very short code (perhaps 1-2 bits), while rare characters get longer codes.

Real-world example:
English text: ~4.5 bits/char with Huffman vs 8 bits/char fixed
English letter frequencies are highly skewed (e=13%, t=9%, a=8%, ...), so Huffman achieves roughly 45% compression.

Common Mistakes to Avoid

Mistake 1: Confusing Huffman Tree with BST

Huffman tree has no ordering property. Left child is NOT smaller than parent. The structure depends only on frequencies.

Mistake 2: Forgetting Ternary Padding

For ternary Huffman with n characters, you must pad so (n-1) is even. Without padding, you'll get stuck with an odd number of nodes.

Mistake 3: Assuming Huffman is Optimal for All Codes

Huffman is optimal only among prefix-free codes. Arithmetic coding can sometimes do better by not restricting to integer bit lengths.

Mistake 4: Not Using a Min-Heap

Always use a min-heap (priority queue), not a max-heap. Extract the two smallest frequencies, not the largest.

Mistake 5: Equal Frequencies = No Compression

If all characters have equal frequency, Huffman produces fixed-length codes. There's no advantage over naive encoding.
