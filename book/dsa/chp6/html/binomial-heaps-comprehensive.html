Binomial Trees

Definition of Binomial Tree Bk

A binomial tree Bk is defined recursively:

Base Case B0 = a single node (a trivial tree with one vertex)
Recursive Case Bk = two copies of Bk-1 linked together — the root of one becomes the leftmost child of the other
Think of linking as grafting one tree onto the other. The new root adopts the old root as its leftmost child.

Visual Construction of B0 through B3

B₀ (k=0) B₁ (k=1) B₂ (k=2) B₃ (k=3) ● ● ● ● / \ / \ /|\ /|\ (1 node) ● ● ● ● ● ● ● ● ● / \ \ /|\ | \ (4 nodes) ● ● ● ● ● ● ● (8 nodes)

How Linking Works

To form Bk from two Bk-1 trees:

  1. Take two independent Bk-1 trees
  2. Make the root with larger key a child of the root with smaller key
  3. The new root's degree increases by 1
  4. The grafted tree becomes the leftmost child of the adopting root
The root with the LARGER key becomes the CHILD (to maintain min-heap property). The root with the SMALLER key becomes the new root.

Binomial Heap

Definition

A binomial heap H is a collection (set) of binomial trees that satisfies two properties:

  1. Min-heap property: For every node, the key of the node is ≥ the key of its parent
  2. Unique degrees: Each tree in H has a distinct degree (at most one tree of each degree)

Representation

A binomial heap is stored as a linked list of root nodes, sorted by increasing degree.

Each root node has fields: key, parent, child, sibling, degree

Number of nodes = n If n = 13 then binary representation is 1101₂ → heap contains B₃ + B₂ + B₀
The binary representation of n directly tells you which binomial trees are present. Each bit position k tells you if Bk exists.

A binomial heap can have at most one binomial tree of each degree. If two trees of the same degree exist, they MUST be merged during the next operation.

Children of Root in Bk

The root of Bk has exactly k children. Reading from right to left, they are:

Right-to-Left Children Order B0, B1, B2, ..., Bk-1

This means:

  • The rightmost child of the root is B0 (a single node)
  • The leftmost child of the root is Bk-1
  • The children are linked together via sibling pointers forming a linked list

Children of Root in B3

Root of B₃ │ ▼ (leftmost child = B₂) ●───────●───────● B₂ B₁ B₀ B₂ has height 2 (4 nodes) B₁ has height 1 (2 nodes) B₀ has height 0 (1 node) Total: 4 + 2 + 1 = 7 children + root = 8 = 2³ ✓

Key Structural Properties

  • Binomial tree Bk has a root with k children, each of which is the root of a distinct Bi
  • The number of nodes at depth d is C(k, d) — the binomial coefficients! (Hence the name "binomial" tree)
  • Bk has exactly 2k nodes — doubling with each level of recursion
  • The root has the minimum key in the tree (min-heap property)
  • Each child subtree is itself a valid binomial tree
The binomial coefficients C(k, i) count nodes at depth i in Bk. This is THE defining property that gives the binomial tree its name. Exam questions frequently test this.
If Bk has 2k nodes, the sum of all binomial coefficients: Σi=0k C(k,i) = 2k. This is the binomial theorem with x=1, y=1.

Node Size

Each node uses O(1) space for the 5 fields. A binomial tree Bk has 2k nodes, so Bk uses O(2k) space.

A binomial heap with n nodes contains trees Bk₁, Bk₂, ..., Bkm where k₁ < k₂ < ... < km.

Total Nodes n = 2k₁ + 2k₂ + ... + 2km → binary representation of n
The sibling pointer forms a singly-linked list of roots sorted by degree. This is the "head" of the binomial heap. The child pointer points to the leftmost child; siblings are linked via their sibling pointers.
Invariant: In a valid binomial heap, no two roots have the same degree. The roots are sorted by degree when traversing via sibling pointers.

All operations are O(lg n) because a binomial heap with n nodes has at most ⌊lg n⌋ + 1 trees. The maximum height of any tree is ⌊lg n⌋.

Operation 1: Merge (Union)

The Core Idea: Binary Addition

Merging two binomial heaps is analogous to binary addition:

  • Each binomial tree Bk represents a "1" in bit position k
  • When two trees of the same degree meet → carry (link them into Bk+1)
  • At most ⌊lg n⌋ + 1 carries in any single merge
Analogy Heap A: 10110₂ (= B₄ + B₂ + B₁) + Heap B: 01011₂ (= B₃ + B₁ + B₀) = Binary addition with carries

Operation 2: Insert

Strategy

  1. Create a new singleton binomial tree (B0) containing the new key
  2. Merge this singleton into the existing heap using the Merge operation
Complexity O(lg n) — merge of singleton takes at most O(lg n) time

Operation 3: Find Minimum

Strategy

Scan through the linked list of root nodes. The minimum key among all roots is the overall minimum.

Complexity O(lg n) — there are at most ⌊lg n⌋ + 1 roots to examine

Operation 4: Delete Minimum (Extract-Min)

Strategy

  1. Find the root r with minimum key among all roots
  2. Remove r from the heap
  3. The children of r become separate binomial trees (each Bi for i = 0, 1, ..., degree(r)-1)
  4. Create a new heap H' from these children
  5. Merge the original heap (minus r) with H'
Complexity O(lg n) — finding r is O(lg n), creating H' is O(lg n), merging is O(lg n)

Operation 5: Decrease Key

Strategy

  1. Decrease the key of node x to new value
  2. Cut x from its parent, make it a new root
  3. Repeat "bubble up": while x violates min-heap property with parent, cut x from parent
  4. Merge all cut roots back into heap
Complexity O(lg n) — at most ⌊lg n⌋ cuts (height of tree)

Operation 6: Delete

Strategy

  1. Decrease key of target node to -∞ (or minimum possible value)
  2. Call Extract-Min to remove it
Complexity O(lg n) — decrease key O(lg n) + extract-min O(lg n) = O(lg n)

Example 3: Extract-Min from a Binomial Heap

Problem

Extract the minimum from a heap H = {B2(root=4), B1(root=7), B0(root=3)}

Original Heap H: B₀(3) → B₁(7) → B₂(4) B₂ tree (root=4, degree=2): 4 / \ 6 5 / 9 B₁ tree (root=7, degree=1): 7 / 8 B₀ tree (root=3, degree=0): 3
1
Find minimum: Scan roots: 3, 7, 4. Minimum is 3 (in B0).
2
Remove B0(root=3): B0 has no children, so nothing to add back.
3
Remaining heap: H' = {B1(root=7), B2(root=4)}
4
Merge result: No duplicate degrees. Final = {B1(root=7), B2(root=4)} with min key = 4.
After Extract-Min: B₁(7) → B₂(4) B₂: 4 / \ 6 5 / 9 B₁: 7 / 8 Minimum of remaining heap = 4

Example 4: Decrease-Key Operation

Problem

Decrease the key of node with key 9 to key 1 in the B2 subtree from Example 3.

Before Decrease-Key: 4 / \ 6 5 / 9 ← target (decrease to 1)
1
Change key: Node's key changes from 9 to 1.
2
Check heap property: Parent has key 6. 1 < 6 → VIOLATION!
3
Cut node from parent: Node (key=1) becomes a new root. Parent (key=6) is now a leaf.
4
Check parent's parent: Parent (key=6) has parent (key=4). 6 ≥ 4 → OK. Stop bubbling.
After Decrease-Key: 4 / \ 6 5 + new B₀ tree: 1 Node (key=1) cut from (key=6), made a new root. Heap now has duplicate degree-0 trees. Next merge will resolve.
After decrease-key, the heap may temporarily have multiple trees of the same degree. The cut operation may create new B0 trees. A subsequent merge resolves all duplicates.

Example 5: Insert Operation

Problem

Insert key 10 into heap H = {B1(root=5), B0(root=8)}

1
Create singleton: New heap H' = {B0(root=10)}
2
Merge H and H':
  • Degree 0: H has B₀(root=8), H' has B₀(root=10) → Carry! Link: 8 < 10, so B₀(10) becomes child of B₀(8). Result: B₁(root=8)
  • Degree 1: H has B₁(root=5), new carry gives B₁(root=8) → Carry! Link: 5 < 8, so B₁(8) becomes child of B₁(5). Result: B₂(root=5)
3
Result: Heap = {B2(root=5)} with 4 nodes total.
Before: H = {B₁(5), B₀(8)} (3 nodes) B₁: 5 B₀: 8 / 8 After inserting 10: H' = {B₂(5)} (4 nodes) B₂: 5 / \ 8 10 (B₁ and B₀ linked as children)

Operation Pseudocode

Merge (Union) — The Core Operation

BINOMIAL-MERGE(H1, H2):
  H ← EMPTY-HEAP()
  x ← H1.head
  y ← H2.head
  while x ≠ NULL or y ≠ NULL:
    if x = NULL: x ← y; y ← y.sibling; continue
    if y = NULL: y ← x; x ← x.sibling; continue
    if x.degree < y.degree:
      prev ← x; x ← x.sibling
    elif y.degree < x.degree:
      prev ← y; y ← y.sibling
    else: // same degree → link (carry)
      if x.key > y.key: SWAP(x, y)
      LINK(y, x) // y becomes child of x
      x.degree ← x.degree + 1
      // continue with x (carry)
  return H

Link Operation

LINK(y, x):
  // Make y a child of x
  y.parent ← x
  y.sibling ← x.child
  x.child ← y
  x.degree ← x.degree + 1

Insert

BINOMIAL-INSERT(H, key):
  x ← CREATE-NODE(key)
  H' ← EMPTY-HEAP()
  H'.head ← x
  H ← BINOMIAL-MERGE(H, H')
  return H

Find Minimum

BINOMIAL-FIND-MIN(H):
  min ← ∞
  x ← H.head
  while x ≠ NULL:
    if x.key < min:
      min ← x.key
    x ← x.sibling
  return min

Extract Minimum

BINOMIAL-EXTRACT-MIN(H):
  // Find min root and its predecessor
  min_prev ← NULL
  min_node ← H.head
  min_key ← min_node.key
  prev ← NULL
  x ← H.head
  while x ≠ NULL:
    if x.key < min_key:
      min_key ← x.key
      min_node ← x
      min_prev ← prev
    prev ← x
    x ← x.sibling
  
  // Remove min_node from root list
  if min_prev = NULL:
    H.head ← min_node.sibling
  else:
    min_prev.sibling ← min_node.sibling
  
  // Reverse children of min_node into new heap H'
  H' ← EMPTY-HEAP()
  child ← min_node.child
  while child ≠ NULL:
    next ← child.sibling
    child.sibling ← H'.head
    child.parent ← NULL
    H'.head ← child
    child ← next
  
  // Merge H and H'
  H ← BINOMIAL-MERGE(H, H')
  return min_node.key

Decrease Key

BINOMIAL-DECREASE-KEY(H, x, new_key):
  if new_key > x.key: error "New key is larger"
  x.key ← new_key
  y ← x.parent
  while y ≠ NULL and x.key < y.key:
    CUT(H, x, y)
    x ← y
    y ← y.parent

Cut Operation

CUT(H, x, y):
  // Remove x from children of y
  if y.child = x:
    y.child ← x.sibling
  else:
    prev ← y.child
    while prev.sibling ≠ x: prev ← prev.sibling
    prev.sibling ← x.sibling
  x.parent ← NULL
  x.sibling ← H.head
  H.head ← x
The merge operation is the fundamental building block. Insert, extract-min, decrease-key, and delete all ultimately call merge. Master merge and you master binomial heaps.

When to Use What?

  • Binary Heap: Default choice. Simple, fast in practice. Use when merge is rarely needed.
  • Binomial Heap: When you need guaranteed O(lg n) merge AND worst-case guarantees.
  • Fibonacci Heap: When you need many decrease-key operations (e.g., Dijkstra's, Prim's). Better asymptotic bounds but complex.
  • Pairing Heap: Practical alternative to Fibonacci. Simpler implementation with similar amortized performance.

Exam Tips:
  • Always check the binary representation of n to determine which trees are in the heap
  • For merge, think "binary addition" — same degree = carry
  • For extract-min, remember to REVERSE the children list before merging
  • Binomial coefficients C(k,i) = nodes at depth i is THE most tested property
  • The merge of two heaps is like adding two binary numbers — carries propagate
  • At most ⌊lg n⌋ + 1 trees in the heap — this is why all operations are O(lg n)
