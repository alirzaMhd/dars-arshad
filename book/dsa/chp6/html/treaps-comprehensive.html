What is a Treap?

A Treap is a data structure that combines the properties of a BST (Binary Search Tree) and a Heap. The name "Treap" is a portmanteau of "Tree" and "Heap".

Key Property (BST)

For every node: left.key < node.key < right.key

Priority Property (Heap)

For every node: parent.priority ≤ child.priority

(Min-heap property on priorities)

Mintree Property:
For all nodes v: v.priority ≤ parent(v).priority
Every node's priority is less than or equal to its parent's priority (min-heap)
Important: The BST property applies to keys, while the heap property applies to priorities. These are two different values stored in each node!
Example: Treap with keys A,B,C,D,E and priorities 5,3,7,1,4

Node structure: (key, priority)

Root: (D, 1) — smallest priority

Left child of D: (A, 5) — key A < D, priority 5 > 1 ✓

Right child of D: (C, 3) — key C > D... wait, that's wrong.

Let me reassign: Root = (C, 1), left = (A, 3), right = (E, 4), etc.

Both BST and heap properties must hold simultaneously!

Node Structure

Node { key // BST property key priority // Heap property priority left // Left child pointer right // Right child pointer }

Each node stores two values: a key (for BST ordering) and a priority (for heap ordering).

Why Use Treaps?

BST Problem

Degenerate trees have O(n) height. Sorted input → worst case.

Treap Solution

Random priorities prevent degenerate trees. Expected O(lg n) height regardless of input order.

Advantage

Simpler to implement than AVL or Red-Black trees. No complex balancing logic.

Expected Height

Expected Height:
E[height] = Θ(lg n)
Analysis Sketch

The treap structure is equivalent to a random BST where the insertion order is determined by priority order.

If priorities are i.i.d. random variables, the expected height is Θ(lg n).

This is true regardless of the key insertion order!

Sorted Keys Analysis

Key Insight: Even if keys are inserted in sorted order (1, 2, 3, ..., n), if priorities are random, the expected height is still Θ(lg n). This is because the treap structure depends on priority ordering, not key ordering.
Example: Keys 1,2,3,4,5 with random priorities

If priorities happen to be: 3, 1, 5, 2, 4

The treap will be balanced because priority ordering determines tree shape.

Expected height = Θ(lg 5) ≈ 2.3

Tree Rotations in Treaps

Treaps use the same rotations as AVL trees. A rotation preserves the BST property while changing the tree structure.

LEFT-ROTATE(x): y = x.right x.right = y.left y.left = x // Update priorities (unchanged) return y RIGHT-ROTATE(x): y = x.left x.left = y.right y.right = x return y
Rotation Property:
In-order traversal is preserved after rotation
Example: Rotation preserves BST property

Before: Root=30, left=20, right=40

In-order: 20, 30, 40

After right rotate on 30: Root=20, right=30, right's right=40

In-order: 20, 30, 40 ✓ (same sequence)

Insertion into Treap

TREAP-INSERT(T, key, priority): // Step 1: BST search for insertion position z = new node(key, priority) y = NIL x = root[T] while x ≠ NIL y = x if key[z] < key[x] x = left[x] else x = right[x] // Step 2: Attach new node parent[z] = y if y = NIL root[T] = z else if key[z] < key[y] left[y] = z else right[y] = z // Step 3: Rotate up until heap property satisfied while parent[z] ≠ NIL and priority[z] < priority[parent[z]] if z = left[parent[z]] RIGHT-ROTATE(parent[z]) else LEFT-ROTATE(parent[z]) // Step 4: Ensure root is black (optional) // (Not needed for basic treap, but some variants use it)
Insertion Complexity:
Expected O(lg n)
Key Point: The rotation step moves the newly inserted node UP the tree until its priority is greater than or equal to its parent's priority. This maintains the min-heap property on priorities.

Step-by-Step Insertion

Insert A(5): A is root. No parent, done.

Insert B(3): B > A, go right. Attach as right child of A. B.priority=3 < A.priority=5 → Left rotate on A.

After rotation: B is root, A is left child of B.

Insert C(7): C > B, go right. C > A, go right. Attach as right child of A. C.priority=7 > A.priority=5 → No rotation needed.

Insert D(1): D > B, go right. D > A, go right. D > C, go right. Attach as right child of C. D.priority=1 < C.priority=7 → Left rotate on C. D.priority=1 < A.priority=5 → Left rotate on A. D.priority=1 < B.priority=3 → Left rotate on B.

After rotations: D is root.

Insert E(4): E > D, go right. E > B, go right. E > A, go right. E < C, go left. Attach as left child of C. E.priority=4 < C.priority=7 → Right rotate on C. E.priority=4 < A.priority=5 → Right rotate on A. E.priority=4 > D.priority=1 → Stop.

Final treap: D(1) root, B(3) left, E(4) right, A(5) left of B, C(7) left of E

Example 2: Sorted Keys

Keys: 1,2,3,4,5 with random priorities

Even though keys are sorted (worst case for BST), random priorities produce a balanced tree.

Suppose priorities are: 3, 1, 5, 2, 4

Insert 1(3): Root = 1

Insert 2(1): 2 > 1, right child. Priority 1 < 3 → rotate. 2 becomes root.

Insert 3(5): 3 > 2, right child. Priority 5 > 1 → no rotation.

Insert 4(2): 4 > 2, right. 4 > 3, right. Priority 2 < 5 → rotate on 3. Priority 2 > 1 → stop.

Insert 5(4): 5 > 2, right. 5 > 4, right. Priority 4 > 2 → no rotation.

Height = Θ(lg 5) ≈ 2.3, balanced despite sorted keys!

When to Use Treaps

Use Treaps When

• Simple implementation is desired

• Expected O(lg n) is sufficient

• Random priorities are acceptable

Avoid Treaps When

• Worst-case guarantee needed

• Adversarial input possible

• Space is critical (extra priority field)

Common Exam Mistakes

Mistake 1: Confusing key ordering with priority ordering. BST property uses keys, heap property uses priorities.
Mistake 2: Thinking treaps guarantee O(lg n) worst case. They only guarantee O(lg n) EXPECTED with random priorities.
Mistake 3: Forgetting that rotations preserve the in-order traversal (BST property).
