Tree Rotations

Data Structures — Complete Guide for 20/20 Exam

What are Tree Rotations?

Definition:
A rotation is an operation that changes the structure of a BST without changing the inorder traversal
Rotations preserve the BST property while changing the tree's height
Key Property:
Inorder traversal remains the SAME after rotation
This means the sorted order of keys is preserved
Why Rotations Matter

Rotations are used to:

• Balance trees (AVL, Red-Black trees)

• Reduce height from O(n) to O(lg n)

• Maintain O(lg n) operations

Important: Rotations are O(1) operations that only change a few pointers. They are the foundation of all balanced BST implementations.

Left Rotation (LR)

LEFT_ROTATE(T, x) y = right[x] right[x] = left[y] if left[y] ≠ NIL parent[left[y]] = x parent[y] = parent[x] if parent[x] = NIL root[T] = y else if x = left[parent[x]] left[parent[x]] = y else right[parent[x]] = y left[y] = x parent[x] = y
What Left Rotate Does:
Rotates x down to the left, bringing right child y up
1. y becomes new root of this subtree
2. x becomes left child of y
3. y's left subtree becomes x's right subtree
Visual: Left Rotate on node x
Before: After: x y / \ / \ A y x C / \ / \ B C A B

• x moves down-left

• y moves up

• B becomes x's right child

• Inorder preserved: A, x, B, y, C

Right Rotation (RR)

RIGHT_ROTATE(T, y) x = left[y] left[y] = right[x] if right[x] ≠ NIL parent[right[x]] = y parent[x] = parent[y] if parent[y] = NIL root[T] = x else if y = left[parent[y]] left[parent[y]] = x else right[parent[y]] = x right[x] = y parent[y] = x
What Right Rotate Does:
Rotates y down to the right, bringing left child x up
1. x becomes new root of this subtree
2. y becomes right child of x
3. x's right subtree becomes y's left subtree
Visual: Right Rotate on node y
Before: After: y x / \ / \ x C A y / \ / \ A B B C

• y moves down-right

• x moves up

• B becomes y's left child

• Inorder preserved: A, x, B, y, C

Worked Examples

Example 1: Left Rotate on node 20
Before: 20 / \ 10 30 / \ 25 35 After LEFT_ROTATE(20): 30 / \ 20 35 / \ 10 25

Inorder before: 10, 20, 25, 30, 35

Inorder after: 10, 20, 25, 30, 35 (same!)

Height changed from 2 to 2 (same in this case)

Example 2: Right Rotate on node 30
Before: 20 / \ 10 30 / \ 25 35 After RIGHT_ROTATE(30): 20 / \ 10 25 \ 30 \ 35

Inorder before: 10, 20, 25, 30, 35

Inorder after: 10, 20, 25, 30, 35 (same!)

Example 3: Left-Right (LR) Rotation
Step 1: Left Rotate on 10 30 30 / / \ 10 → 15 35 \ / 15 10 Step 2: Right Rotate on 30 30 15 / \ / \ 15 35 → 10 30 / \ 10 35

LR rotation is used when tree is "right-left" skewed

Rotation Sequence Tests

Key Concept:
Converting one BST shape to another using rotations
Given two BSTs with the same keys but different shapes, find the sequence of rotations to convert one to the other
Test 4: Convert left-skewed to right-skewed

Problem: Convert this left-skewed tree to right-skewed using only Left Rotations (L):

Before (left-skewed): 5 / 4 / 3 / 2 / 1 After (right-skewed): 1 \ 2 \ 3 \ 4 \ 5

Solution: Apply Left Rotation (L) at each node from top to bottom

Sequence: L(5), L(4), L(3), L(2) = LLLL

Test 4 Options:

1. LLLLL (5 rotations) → Converts left-skewed to right-skewed

2. LLLLR (5 rotations) → Not valid

3. LLLRR (5 rotations) → Not valid

4. LRLLL (5 rotations) → Not valid

Answer: Option 1 (LLLLL)

Test 5: Minimum rotations for balanced tree

Problem: What is the minimum number of rotations to convert a right-skewed tree with n nodes to a balanced BST?

Formula:
T(n) = T(⌊n/2⌋) + T(⌈n/2⌉) + ⌊n/2⌋
This gives the minimum rotations needed for optimal balancing

Example with n=7 (right-skewed):

T(7) = T(3) + T(4) + 3

T(3) = T(1) + T(2) + 1 = 0 + 1 + 1 = 2

T(4) = T(2) + T(2) + 2 = 1 + 1 + 2 = 4

T(7) = 2 + 4 + 3 = 9 rotations

Maximum Rotations Formula

Converting ANY BST to ANY other BST:
Maximum rotations needed = 2n - 2
To convert any BST with n nodes to any other BST with the same keys
Why 2n - 2?

Upper bound analysis:

• First, convert to a right-skewed tree: at most n-1 rotations

• Then, convert to target tree: at most n-1 rotations

• Total: (n-1) + (n-1) = 2n - 2 rotations

Example: n=5 nodes

Maximum rotations = 2(5) - 2 = 8 rotations

Test 6: Which rotations reduce height from 5 to 3?

• Single rotation reduces height by at most 1

• To reduce by 2, need at least 2 rotations

• LR or RL rotations (double rotations) can reduce by 2

Answer: Options 1 and 3 (LRb then LRd, or LRd then LRb)

Key Formulas

• Max rotations (any→any): 2n - 2

• Max rotations (skewed→balanced): O(n lg n)

• Single rotation height change: ≤ 1

Rotation Properties

• Each rotation is O(1)

• Rotations preserve inorder

• LR/RL can reduce height by 2

• LL/RR can reduce height by 1

Key Insight: The 2n-2 formula is the WORST CASE. In practice, many conversions require fewer rotations, especially if the trees are similar.

Quick Reference Card

Left Rotate (LR)

• Right child moves up

• Current node moves down-left

• Used for right-heavy trees

Right Rotate (RR)

• Left child moves up

• Current node moves down-right

• Used for left-heavy trees

Rotation Types

• RR: Single right rotation

• LL: Single left rotation

• LR: Left then right

• RL: Right then left

Complexity

• Time: O(1)

• Space: O(1)

• Preserves inorder

• Changes height

Rotation Formulas:
Left Rotate: x → y, y's left becomes x's right
Right Rotate: y → x, x's right becomes y's left
Both rotations are inverses of each other
Key Insight: A single rotation can reduce height by at most 1. To reduce height by k, you may need k rotations.
