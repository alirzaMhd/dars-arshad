TREE ROTATIONS

Balancing Operations in BSTs — Complete Guide for Exam

What is a Tree Rotation?

A tree rotation is an operation that changes the structure of a binary search tree (BST) without altering the in-order traversal of its nodes. Rotations are fundamental to self-balancing BSTs like AVL trees and Red-Black trees.

Key Properties of Rotation
  • Rotation is O(1) — only pointer changes, no data movement
  • Rotation preserves BST property (in-order traversal unchanged)
  • Rotation changes tree height — reduces height by 1 in the affected subtree
  • Rotation does not change the set of keys in the tree
Rotation Cost:
Time: O(1) | Space: O(1)
Only 3 pointer changes are needed per rotation. No node creation, deletion, or data copying.

LEFT-ROTATE Algorithm

Left rotation on node x promotes its right child y to take x's position. Node x becomes the left child of y.

Before: After: x y / \ / \ a y → x c / \ / \ b c a b
LEFT-ROTATE(T, x) 1 y ← x.right // y is x's right child 2 x.right ← y.left // Step 1: move y's left subtree to x's right 3 if y.left ≠ NIL // Step 2: update parent of y's old left child 4 y.left.p ← x 5 y.p ← x.p // Step 3: link y to x's parent 6 if x.p = NIL // x was root 7 T.root ← y 8 elseif x = x.p.left // x was left child 9 x.p.left ← y 10 else // x was right child 11 x.p.right ← y 12 y.left ← x // Step 4: make x the left child of y 13 x.p ← y // Step 5: update x's parent pointer
Left Rotation Summary (3 pointer changes):
Change 1: x.right ← y.left (y's old left child becomes x's new right child)
Change 2: y.left ← x (x becomes y's left child)
Change 3: y.p ← x.p (y takes x's position in the tree)
After left rotation, y is the new root of the subtree, and x is y's left child.

RIGHT-ROTATE Algorithm

Right rotation on node x promotes its left child y to take x's position. Node x becomes the right child of y.

Before: After: x y / \ / \ y c → a x / \ / \ a b b c
RIGHT-ROTATE(T, x) 1 y ← x.left // y is x's left child 2 x.left ← y.right // Step 1: move y's right subtree to x's left 3 if y.right ≠ NIL // Step 2: update parent of y's old right child 4 y.right.p ← x 5 y.p ← x.p // Step 3: link y to x's parent 6 if x.p = NIL // x was root 7 T.root ← y 8 elseif x = x.p.left // x was left child 9 x.p.left ← y 10 else // x was right child 11 x.p.right ← y 12 y.right ← x // Step 4: make x the right child of y 13 x.p ← y // Step 5: update x's parent pointer
Right Rotation Summary (3 pointer changes):
Change 1: x.left ← y.right (y's old right child becomes x's new left child)
Change 2: y.right ← x (x becomes y's right child)
Change 3: y.p ← x.p (y takes x's position in the tree)
After right rotation, y is the new root of the subtree, and x is y's right child.

The Three Pointer Changes — Detailed

Every rotation (left or right) performs exactly 3 pointer changes. Understanding these precisely is critical for exams.

Universal Pointer Change Pattern:
1. Parent of x → becomes parent of y
2. y's "inner" child → becomes x's "outer" child
3. x → becomes y's "outer" child
For left rotation: "inner" = left, "outer" = right. For right rotation: "inner" = right, "outer" = left.

Left Rotation: 3 Pointer Changes

Rotating left on node x with right child y:

Step 0 (Before): x is the node being rotated x y is x's right child / \ a, b, c are subtrees a y / \ b c
Change 1: Parent of x becomes parent of y
y.p ← x.p

Node y takes x's position as a child of x's parent. If x was the root, y becomes the new root.

Change 2: y's old left child becomes x's new right child
x.right ← y.left

Subtree b (y's left child) moves from being y's left child to being x's right child. Update b.p ← x if b ≠ NIL.

Change 3: x becomes y's left child
y.left ← x

Node x becomes the left child of y. Set x.p ← y.

Step 1 (After): y / \ x c / \ a b
Common Mistake

Forgetting to update the parent pointer of subtree b in Change 2. Always check: if y.left ≠ NIL then y.left.p ← x

Right Rotation: 3 Pointer Changes

Rotating right on node x with left child y:

Step 0 (Before): x is the node being rotated x y is x's left child / \ a, b, c are subtrees y c / \ a b
Change 1: Parent of x becomes parent of y
y.p ← x.p

Node y takes x's position as a child of x's parent.

Change 2: y's old right child becomes x's new left child
x.left ← y.right

Subtree b (y's right child) moves from being y's right child to being x's left child. Update b.p ← x if b ≠ NIL.

Change 3: x becomes y's right child
y.right ← x

Node x becomes the right child of y. Set x.p ← y.

Step 1 (After): y / \ a x / \ b c

Side-by-Side Comparison

Aspect Left Rotation on x Right Rotation on x

Change 1 y.p ← x.p y.p ← x.p

Example 1: Left Rotation on Node 7

Given a BST with in-order traversal: 20, 25, 35, 37, 40

Original Tree (right-skewed at 37): 40 / 37 / \ 35 (nil) / 25 / 20 In-order: 20, 25, 35, 37, 40
Step 1: Identify the rotation

Node 37 is right-heavy. We perform left rotation on 37.

x = 37, y = x.right = 40 (but 40 has no left child, so y.left = nil)

Step 2: Apply 3 pointer changes (left rotation on 37)
x = 37, y = 40 Change 1: y.p ← x.p → 40.p ← 35 (40 takes 37's position as 35's right child) Change 2: x.right ← y.left → 37.right ← nil (40 had no left child) Change 3: y.left ← x → 40.left ← 37
After left rotation on 37: 40 / 37 / 35 / 25 / 20 Wait — this didn't help! Let's rotate higher.
Key Insight

Left rotation on 37 didn't improve balance because the imbalance is in the left subtree of 37. We need to rotate at a higher node.

Step 3: Try left rotation on 40
x = 40, y = x.left = 37 (this is a RIGHT rotation on 40) Change 1: y.p ← x.p → 37.p ← nil (37 becomes root) Change 2: x.left ← y.right → 40.left ← nil (37 had no right child) Change 3: y.right ← x → 37.right ← 40
After right rotation on 40: 37 / \ 35 40 / 25 / 20 In-order: 20, 25, 35, 37, 40 (preserved!) Height reduced: 5 → 4

Example 2: Left Rotation on Node x in a Balanced Tree

Original Tree: 50 / \ 30 70 / \ / \ 20 40 60 80 In-order: 20, 30, 40, 50, 60, 70, 80
Step 1: Left rotation on node 50

x = 50, y = x.right = 70

Change 1: y.p ← x.p → 70.p ← nil (50 was root, 70 becomes root) Change 2: x.right ← y.left → 50.right ← 60 (70's left child 60 moves to 50's right) Change 3: y.left ← x → 70.left ← 50
After left rotation on 50: 70 / \ 50 80 / \ 30 60 / \ 20 40 In-order: 20, 30, 40, 50, 60, 70, 80 (preserved!) The tree structure changed but all keys remain in sorted order.

Example 3: Right Rotation on Node 30

Original Tree (left-heavy at 50): 50 / \ 30 70 / \ 20 40 / 10 In-order: 10, 20, 30, 40, 50, 70
Step 1: Right rotation on node 30

x = 30, y = x.left = 20

Change 1: y.p ← x.p → 20.p ← 50 (20 takes 30's position) Change 2: x.left ← y.right → 30.left ← nil (20 had no right child) Change 3: y.right ← x → 20.right ← 30
After right rotation on 30: 50 / \ 20 70 / \ 10 30 / 40 In-order: 10, 20, 30, 40, 50, 70 (preserved!)
Step 2: Continue: Right rotation on node 50

x = 50, y = x.left = 20

Change 1: y.p ← x.p → 20.p ← nil (20 becomes root) Change 2: x.left ← y.right → 50.left ← 30 (20's right child 30 moves to 50's left) Change 3: y.right ← x → 20.right ← 50
After right rotation on 50: 20 / \ 10 50 / \ 30 70 \ 40 In-order: 10, 20, 30, 40, 50, 70 (still preserved!) Height went from 4 to 3

Example 4: Maximum Rotations — Skew to Skew Conversion

Converting a right-skewed tree of n nodes to a left-skewed tree requires exactly n - 2 rotations.

Right-skewed tree with n=5 nodes: 1 \ 2 \ 3 \ 4 \ 5 In-order: 1, 2, 3, 4, 5
Rotation 1: Left rotate on 3
x=3, y=4: 4.p←2, 3.right←nil, 4.left←3 Result: 1→2→4→3→5 (height reduced)
Rotation 2: Left rotate on 2
x=2, y=3: 3.p←1, 2.right←nil, 3.left←2 Result: 1→3→2→4→5
Rotation 3: Left rotate on 1
x=1, y=2: 2.p←nil(root), 1.right←nil, 2.left←1 Result: 2→1→3→4→5
Left-skewed tree (after n-2 = 3 rotations): 5 / 4 / 3 \ 2 \ 1 In-order: 1, 2, 3, 4, 5 (preserved!) Total rotations: 5 - 2 = 3 ✓
Formula for Maximum Rotations:
Rotations = n - 2
To convert a completely right-skewed tree of n nodes to completely left-skewed (or vice versa), exactly n-2 rotations are needed. Each rotation reduces the height by 1.

Rotation Properties — Exam Points

In-order Preservation

ALWAYS preserved

Left rotation: inorder(a) + x + inorder(b) + y + inorder(c) stays the same.

Right rotation: same set, same order.

BST Property

ALWAYS preserved

After any rotation, for every node: left subtree keys < node key < right subtree keys.

Height Change

CHANGED

Rotation reduces the height of one subtree by 1 and increases the other by 1. Net effect: overall height may decrease.

Node Count

UNCHANGED

No nodes are created or destroyed. Only pointer relationships change.

In-Order Traversal Preservation — Proof

Consider a subtree rooted at x with left child a, right child y, and y's left child b, right child c.

Before Left Rotation:
Inorder = inorder(a), x, inorder(b), y, inorder(c)
After Left Rotation (y is new root):
Inorder = inorder(a), x, inorder(b), y, inorder(c)
Identical! The rotation rearranged the structure but the left-to-right order of all keys is unchanged.
Exam Tip

If a question asks "Does rotation preserve in-order?" the answer is YES, always. This is the fundamental property that makes rotations safe for BSTs.

Maximum Rotations Formula

Right-skewed → Left-skewed (or vice versa):
Rotations needed = n - 2
Where n is the number of nodes in the tree. Each rotation reduces height by exactly 1.

Common Mistakes to Avoid

Mistake 1: Forgetting parent pointer updates

After rotation, the promoted node y must have its parent pointer set to x's old parent. Also, if y had a child subtree (b), that subtree's parent pointer must be updated to x.

Mistake 2: Confusing left and right rotation direction

Left rotation on x: x goes LEFT, y (right child) goes UP.
Right rotation on x: x goes RIGHT, y (left child) goes UP.
Remember: the direction name refers to where x moves.

Mistake 3: Assuming rotation changes the set of keys

Rotation NEVER adds or removes nodes. It only restructures the tree. The same n keys exist before and after.

Mistake 4: Thinking rotation always reduces height

A single rotation may not always reduce the overall tree height. It reduces the height of one subtree. Multiple rotations may be needed to balance a tree.

Exam-Style Questions

Q1: How many pointer changes in a single rotation?

3 pointer changes. Each rotation modifies exactly 3 pointers (parent pointer of y, one child pointer of x, and one child pointer of y).

Q2: What is the time complexity of a rotation?

O(1) time, O(1) space. Only constant work is done regardless of tree size.

Q3: Does rotation preserve BST property?

Yes. Rotation preserves both the BST property and the in-order traversal. The relative ordering of all keys remains unchanged.

Q4: Maximum rotations to convert right-skewed to left-skewed tree of n nodes?

n - 2 rotations. Each rotation reduces height by 1.
