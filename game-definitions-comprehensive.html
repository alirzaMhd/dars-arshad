Game Definitions

Formal Framework for Adversarial Search — Complete Guide for 20/20 Exam

Initial State (State)

The initial state defines the starting configuration of the game and determines which player's turn it is.

Initial State Components:
State = (Board Configuration, Player to Move)
Includes all pieces/positions and whose turn it is to play.
Example 1: Tic-Tac-Toe Initial State

For a standard 3×3 Tic-Tac-Toe game:

  • Board: Empty 3×3 grid (9 empty cells)
  • Player: X always moves first
  • State Representation: Could be a string " " or 2D array
Initial State: [ ][ ][ ] [ ][ ][ ] [ ][ ][ ] Player to move: X
Example 2: Chess Initial State

Standard chess starting position:

  • Board: 8×8 grid with pieces in standard arrangement
  • Player: White moves first
  • Additional Info: Castling rights, en passant availability, move count

Simple Games

• Tic-Tac-Toe: 1 state

• Connect Four: 1 state

• Nim: 1 state per configuration

Complex Games

• Chess: Many initial states

• Go: Many initial states

• Backgammon: Many initial states

Successor Function (Move)

The successor function returns a set of (move, state) pairs representing all legal moves from the current state.

Successor Function:
SUCCESSORS(state) = {(move₁, state₁), (move₂, state₂), ...}
Returns all legal moves and resulting states from current position.
Example 3: Tic-Tac-Toe Successors

From initial empty board:

Current State: [ ][ ][ ] [ ][ ][ ] [ ][ ][ ] Legal Moves (9 possible): 1. Place X at (0,0) → New State 2. Place X at (0,1) → New State 3. Place X at (0,2) → New State 4. Place X at (1,0) → New State 5. Place X at (1,1) → New State 6. Place X at (1,2) → New State 7. Place X at (2,0) → New State 8. Place X at (2,1) → New State 9. Place X at (2,2) → New State
Example 4: Chess Successors

A typical chess position might have 20-40 legal moves:

  • Each pawn: 1-2 moves forward, diagonal captures
  • Each piece: Various movement patterns
  • Castling: Special king-rook moves
  • En passant: Special pawn capture

The branching factor varies dramatically between games.

Low Branching Factor

• Tic-Tac-Toe: 9 → 8 → 7...

• Checkers: ~7 average

• Othello: ~10 average

High Branching Factor

• Chess: ~35 average

• Go: ~250 average

• Backgammon: ~40 average

Terminal Test

The terminal test determines whether the game has ended. States where the game ends are called terminal states.

Terminal Test:
TERMINAL-TEST(state) → Boolean
Returns TRUE if game is over, FALSE otherwise.
Example 5: Tic-Tac-Toe Terminal Conditions

Game ends when any of these occur:

  • Win: Three X's or O's in a row (horizontal, vertical, or diagonal)
  • Loss: Opponent achieves three in a row
  • Draw: All 9 cells filled with no winner
Terminal State Example: [X][O][X] [O][X][O] [O][X][O] Game Over: Draw (no winner)
Example 6: Chess Terminal Conditions

Chess has several ways to end:

  • Checkmate: King under attack with no escape
  • Stalemate: No legal moves but king not in check
  • Draw by Agreement: Both players agree
  • Draw by Repetition: Same position occurs 3 times
  • 50-Move Rule: 50 moves without pawn move or capture
  • Insufficient Material: Not enough pieces to checkmate
Key Point: Terminal states have no successors—the game tree ends at these nodes.

Utility Function (Payoff Function)

The utility function assigns a numerical value to terminal states, representing the outcome for each player.

Utility Function:
UTILITY(terminal_state) → Real Number
Also called objective function or payoff function.
Example 7: Tic-Tac-Toe Utility Values

From the perspective of player X (maximizer):

  • X wins: +1
  • O wins: -1
  • Draw: 0
Utility Values: Terminal State with X win → +1 Terminal State with O win → -1 Terminal State with Draw → 0
Example 8: Backgammon Utility Values

Backgammon has a wider range of outcomes:

  • Normal Win: +1 to +12 points
  • Gammon (double): +2 to +24 points
  • Backgammon (triple): +3 to +36 points
  • Losing: Negative of winner's points

Utility range: -192 to +192 in tournament play.

Binary Outcomes

• Win/Lose: ±1

• Draw: 0

• Simple games

Graduated Outcomes

• Range of values

• Partial wins

• Complex scoring

Game Tree Structure

The combination of initial state and legal moves forms a game tree, where nodes are states and edges are moves.

Game Tree:
Tree = (States, Moves, Parent-Child Relationships)
Root is initial state, leaves are terminal states, internal nodes are intermediate positions.
Example 9: Tic-Tac-Toe Game Tree (Partial)
Root (Empty Board) ├── X at (0,0) │ ├── O at (0,1) │ │ ├── X at (0,2) │ │ ├── X at (1,0) │ │ └── ... │ └── O at (1,1) │ ├── X at (0,1) │ └── ... └── X at (1,1) ├── O at (0,0) └── ...

Full tree has 9! = 362,880 possible games (without early termination).

Example 10: Chess Game Tree Complexity

Chess demonstrates the explosion of possibilities:

  • Average branching factor: ~35
  • Average game length: ~80 moves
  • Theoretical game tree size: 35⁸⁰ ≈ 10¹²³
  • Actual positions: ~10⁴⁷ (due to transpositions)

This is why brute-force search is impossible for complex games.

Tree Properties

• Root: Initial state

• Internal nodes: Non-terminal states

• Leaves: Terminal states

• Depth: Game length

Search Strategy

• Minimax explores entire tree

• Alpha-beta prunes branches

• Heuristics limit depth

• Evaluation functions estimate

Critical Insight: The game tree is too large to explore completely for most interesting games. This necessitates heuristic methods and approximate solutions.
