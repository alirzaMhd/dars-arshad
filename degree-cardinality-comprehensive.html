DEGREE & CARDINALITY

Database Relational Algebra - Comprehensive Guide

What is Degree?

Degree (also called arity) refers to the number of attributes (columns) in a relation. It defines the schema or structure of the relation.

Example: Degree of Relations

Relation R(a, b, c) has degree 3
Relation S(b, c, d) has degree 3
Result R ⋈ S has degree 4 (a, b, c, d)

Key Points

  • Degree is determined by the schema definition, not the data
  • Operations combine or reduce attributes, affecting degree
  • Degree is always a non-negative integer
  • An empty relation still has a degree (based on its schema)

What is Cardinality?

Cardinality refers to the number of tuples (rows) in a relation. It represents the amount of data stored in the relation at a given time.

Example: Cardinality of Relations

Relation R with 5 tuples has cardinality 5
Relation S with 3 tuples has cardinality 3
After R ∪ S, cardinality is between max(5,3) and 8

Key Points

  • Cardinality changes as data is inserted or deleted
  • Operations produce results with specific cardinality bounds
  • Cardinality can be zero (empty relation)
  • Used for query optimization and performance estimation

Impact on Operations

Different relational algebra operations have specific effects on degree and cardinality:

Selection (σ)
Same degree, reduced cardinality
Projection (π)
Reduced degree, same or reduced cardinality
Cartesian Product (×)
Sum of degrees, product of cardinalities
Join (⋈)
Sum minus common, ≤ product of cardinalities

Degree Formulas

Selection Degree
deg(σcondition(R)) = deg(R)
Selection does not change the degree (number of attributes)
Projection Degree
deg(πattributes(R)) = |attributes|
Degree equals the number of projected attributes
Cartesian Product Degree
deg(R × S) = deg(R) + deg(S)
Degree is the sum of both relations' degrees
Natural Join Degree
deg(R ⋈ S) = deg(R) + deg(S) - |common attributes|
Degree is sum minus number of common attributes (they merge)
Outer Join Degree
deg(R ⟕ S) = deg(R) + deg(S) - |common attributes|
Same as natural join (NULLs fill missing attributes)

Cardinality Formulas

Selection Cardinality
0 ≤ card(σcondition(R)) ≤ card(R)
Result cardinality is between 0 and the original cardinality
Projection Cardinality
0 ≤ card(πattributes(R)) ≤ card(R)
Projection may eliminate duplicates, reducing cardinality
Cartesian Product Cardinality
card(R × S) = card(R) × card(S)
Every tuple in R pairs with every tuple in S
Natural Join Cardinality
0 ≤ card(R ⋈ S) ≤ card(R) × card(S)
Upper bound is the product, but actual size depends on matching values
Union Cardinality
max(card(R), card(S)) ≤ card(R ∪ S) ≤ card(R) + card(S)
Lower bound is the larger relation, upper is sum (if no duplicates)
Intersection Cardinality
0 ≤ card(R ∩ S) ≤ min(card(R), card(S))
Cannot exceed the smaller relation
Difference Cardinality
0 ≤ card(R - S) ≤ card(R)
Result is a subset of R

Outer Join Cardinality

Left Outer Join
card(R ⟕ S) ≥ card(R)
All R tuples appear at least once (with NULLs if no match)
Right Outer Join
card(R ⟖ S) ≥ card(S)
All S tuples appear at least once (with NULLs if no match)
Full Outer Join
card(R ⟗ S) ≥ max(card(R), card(S))
All tuples from both relations appear at least once

Types of Outer Joins

Left Outer Join (⟕)
All tuples from R, matched tuples from S, NULLs where no match
Right Outer Join (⟖)
All tuples from S, matched tuples from R, NULLs where no match
Full Outer Join (⟗)
All tuples from both R and S, NULLs where no match
Cross Outer Join
Not standard; typically just full outer join

Left Outer Join Formula

Definition
R ⟕ S = (R ⋈ S) ∪ (R × {NULL})
Natural join plus unmatched R tuples with NULLs for S attributes
Formal Definition
R ⟕ S = {r | r ∈ R} ∪ {r ⋈ s | r ∈ R, s ∈ S, match(r, s)}
All R tuples, plus matched pairs from R and S
Using NULL Extension
R ⟕ S = (R ⋈ S) ∪ (πR-schema(R - πR-schema(R ⋈ S)) × {NULL, NULL, ...})
Join result plus unmatched R tuples padded with NULLs

Right Outer Join Formula

Definition
R ⟖ S = S ⟕ R
Right outer join is equivalent to left outer join with operands swapped
Using NULL Extension
R ⟖ S = (R ⋈ S) ∪ ({NULL, NULL, ...} × πS-schema(S - πS-schema(R ⋈ S)))
Join result plus unmatched S tuples padded with NULLs

Full Outer Join Formula

Definition
R ⟗ S = (R ⟕ S) ∪ (R ⟖ S)
Union of left and right outer joins
Alternative Definition
R ⟗ S = (R ⋈ S) ∪ (unmatched R with NULLs) ∪ (unmatched S with NULLs)
Natural join plus all unmatched tuples from both relations

Common Mistakes

Mistake 1: Confusing Degree with Cardinality

Degree = columns, Cardinality = rows. A relation with 10 columns and 5 rows has degree 10, cardinality 5.

Mistake 2: Forgetting Common Attributes in Join Degree

When calculating degree of R ⋈ S, you must subtract the number of common attributes. deg(R ⋈ S) = deg(R) + deg(S) - |common|, NOT deg(R) + deg(S).

Mistake 3: Assuming Outer Join Always Increases Cardinality

Left outer join cardinality ≥ card(R), but it can be exactly card(R) if all R tuples match. It doesn't always increase.

Mistake 4: NULL Handling in Aggregates

NULLs in outer joins can affect aggregate functions. COUNT includes NULLs, but SUM, AVG, etc., may ignore them depending on the SQL dialect.

Mistake 5: Union Compatibility Requirements

For UNION, INTERSECT, and DIFFERENCE, relations must be union-compatible: same degree AND same attribute types in same order.
