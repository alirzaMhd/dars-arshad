8-Queens Problem

AI Problem Solving — Complete Guide

Problem Definition

Place 8 queens on an 8×8 chessboard such that no two queens attack each other. A queen attacks along rows, columns, and diagonals.

Attack Condition:
Two queens at (r₁, c₁) and (r₂, c₂) attack iff:
r₁ = r₂   (same row)  |  c₁ = c₂   (same column)  |  |r₁ − r₂| = |c₁ − c₂|   (diagonal)

Chessboard Representation

An 8×8 board with rows and columns indexed 0–7. Each queen occupies one square. A valid solution is a placement where all three attack conditions are false for every pair of queens.

Problem Characteristics

• Fully observable — entire board visible

• Deterministic — placement has single outcome

• Discrete — finite set of squares

• Static — environment doesn't change

Solution Criteria

• No two queens share a row

• No two queens share a column

• No two queens share a diagonal

Common Mistake: Forgetting diagonal attacks. Two queens on the same diagonal attack each other even if rows and columns differ. Always check both main and anti-diagonals.

Incremental Formulation

Start with an empty board. Each action adds one queen to a square. The process continues until 8 queens are placed with no attacks.

Naive Formulation

Each new queen can be placed on any of the remaining empty squares. The state space is the number of ways to choose 8 squares in order from 64:

Naive State Space Size:
P(64, 8) = 64! / (64 − 8)! = 64 × 63 × 62 × ... × 57 ≈ 1.8 × 10¹⁴
64 squares, choose 8 in sequence — over 178 trillion states
Warning: The naive formulation is computationally infeasible. Even if we could expand 10⁶ nodes per second, exploring all states would take over 5 years.

Improved Formulation

Key insight: place queens column by column, left to right. Each new queen goes in the leftmost empty column, and only on a row where no existing queen can attack it.

Improved State Space Size:
Only 2,057 distinct states
By restricting placement to the leftmost empty column and filtering illegal rows, the state space collapses from 10¹⁴ to ~2000

State Definition (Improved):
State = arrangement of k queens in the k leftmost columns with no attacks
k ranges from 0 (empty board) to 8 (goal state). Each action adds one queen to column k.

Complete-State Formulation

Start with all 8 queens already on the board (one per column). Then move queens to resolve conflicts.

Initial State (Complete-State):
8 queens placed arbitrarily, one per column
Example: place each queen on a random row in its column. Most configurations will have attacks.

How It Works

Each action moves a single queen to a different row within its own column. The goal is to reach a configuration with zero attacks. This is often solved using local search algorithms like min-conflicts.

Complete-State Approach Steps

Step 1: Initialize — place one queen in each column at a random row.

Step 2: Evaluate — count conflicts (attacks) for each queen.

Step 3: Select — pick a queen involved in conflicts.

Step 4: Move — relocate it to the row with fewest conflicts in its column.

Step 5: Repeat — until no conflicts or iteration limit reached.

Special-Purpose Algorithms

• Min-conflicts heuristic solves million-queens in seconds

• Explicit solutions exist for n ≥ 4

• Pattern-based construction for any n not divisible by 2 or 3

The n-queens family is a go-to test problem for new search algorithms

Why It's a Good Test Problem

• Adjustable difficulty — scale n from small to huge

• Clear goal — objective check is O(n)

• Known solutions — verify correctness easily

• Multiple formulations — test different search strategies

Warning: State Space Explosion. For n=100, the naive formulation has more states than atoms in the universe. Even the improved formulation requires heuristic search. Never attempt exhaustive search for n > 20.

Worked Examples

Example 1: Counting Naive States for 6-Queens

Problem: How many states does the naive formulation produce for placing 6 queens on a 6×6 board?

Solution:

Naive count = P(36, 6) = 36 × 35 × 34 × 33 × 32 × 31

= 36 × 35 = 1,260

= 1,260 × 34 = 42,840

= 42,840 × 33 = 1,413,720

= 1,413,720 × 32 = 45,239,040

= 45,239,040 × 31 = 1,402,410,240 ≈ 1.4 × 10⁹

The improved formulation for 6-queens has just 2 states. The reduction factor is ~700 million.

Example 2: Checking a Partial Configuration

Problem: Three queens are placed at (0,0), (1,2), (3,3) on an 8×8 board. Are any queens attacking each other? If so, which?

Solution:

Check Q₁(0,0) vs Q₂(1,2): Row diff=1, Col diff=2, Not same row/col. Diagonal? |0−1|=1, |0−2|=2 → 1≠2. No attack.

Check Q₁(0,0) vs Q₃(3,3): Row diff=3, Col diff=3. Same diagonal? |0−3|=3, |0−3|=3 → 3=3. Attack on main diagonal!

Check Q₂(1,2) vs Q₃(3,3): Row diff=2, Col diff=1. Diagonal? |1−3|=2, |2−3|=1 → 2≠1. No attack.

Result: Queens at (0,0) and (3,3) attack diagonally. This configuration is invalid.

Example 4: Valid Solution Verification

Problem: A candidate solution for 8-queens has queens at: (0,0), (1,4), (2,7), (3,5), (4,2), (5,6), (6,1), (7,3). Is this valid?

Solution:

Check rows: all distinct (0−7) ✓

Check columns: all distinct (0,4,7,5,2,6,1,3) ✓

Check diagonals (|r₁−r₂| = |c₁−c₂|):

(0,0) vs (1,4): |0−1|=1, |0−4|=4 → 1≠4 ✓

(0,0) vs (2,7): |0−2|=2, |0−7|=7 → 2≠7 ✓

(0,0) vs (3,5): |0−3|=3, |0−5|=5 → 3≠5 ✓

(0,0) vs (4,2): |0−4|=4, |0−2|=2 → 4≠2 ✓

(0,0) vs (5,6): |0−5|=5, |0−6|=6 → 5≠6 ✓

(0,0) vs (6,1): |0−6|=6, |0−1|=1 → 6≠1 ✓

(0,0) vs (7,3): |0−7|=7, |0−3|=3 → 7≠3 ✓

(1,4) vs (2,7): |1−2|=1, |4−7|=3 → 1≠3 ✓

(1,4) vs (3,5): |1−3|=2, |4−5|=1 → 2≠1 ✓

... (continue for all 28 pairs) ...

All 28 pair checks pass. This is a valid solution.

Example 5: Search Tree Size

Problem: In the improved incremental formulation, at depth k (k queens placed), how many rows are typically available for the next queen in the worst case?

Solution:

For the k-th queen in column k:

• k rows are blocked by existing queens (same row)

• Some additional rows blocked by diagonals (at most 2k)

Worst-case available rows ≈ 8 − k (rough estimate)

Total nodes in search tree ≈ Σₖ₌₀⁷ Πᵢ₌₀ᵏ (8 − i)

= 1 + 8 + 8×7 + 8×7×6 + ... + 8!

= 1 + 8 + 56 + 336 + 1,680 + 6,720 + 20,160 + 40,320 + 40,320

= 109,601 nodes explored

This is far less than 1.8×10¹⁴, demonstrating why improved formulation is essential.
