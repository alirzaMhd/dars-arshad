Framing Techniques

Computer Networks — Complete Guide for Exam Preparation

Framing Methods Overview

Framing techniques define how receivers identify the beginning and end of frames in a continuous bit stream. The Data Link Layer must clearly delimit frames so the receiver can correctly extract them.

Main Framing Approaches

Character Count

• Header contains frame length

• Simple but fragile

• Single error corrupts entire stream

Flag Bytes

• Special delimiter character

• Example: 01111110 (HDLC)

• Requires byte stuffing

Byte Stuffing

• Escape character inserted

• Handles data transparency

• Used in PPP, SLIP

Bit Stuffing

• Extra bit inserted in data

• More efficient than byte stuffing

• Used in HDLC, SDLC

Character Count Method:
[Count][Data...][Next Count][Data...]...
Count field specifies number of bytes in frame (including itself and trailer).
Problem with Character Count: If the count field is corrupted during transmission, the receiver loses frame synchronization and cannot recover until a new frame begins. This is why more robust methods are preferred.

Bit Stuffing

Bit stuffing is a technique used in protocols like HDLC and SDLC. After every five consecutive 1-bits in the data, a 0-bit is inserted. The flag pattern 01111110 (six consecutive 1-bits) is never duplicated in the data.

Bit Stuffing Rule:
After five consecutive 1-bits, insert a 0-bit
This ensures the flag pattern 01111110 never appears in the data payload.

Bit Stuffing Process

Original Data: 011011111111100 After Stuffing: 0110111110111100 (0 added after five 1s)

Bit Destuffing Process

Received: 0110111110111100 After Destuffing: 011011111111100 (0 removed after five 1s)
Example 1: Bit Stuffing Application

Apply bit stuffing to: 11111011111101111111

Answer:

Original: 11111 0 11111 1 0 11111 1 1

Stuffed: 111110 0 111110 1 0 111110 1 1

Insert 0 after each group of five 1s.

Example 2: Overhead Calculation

Calculate bit stuffing overhead for a 1000-bit frame with 200 groups of five consecutive 1-bits.

Answer:

Bits inserted = 200 (one 0-bit per group)

Overhead = (200 / 1000) × 100 = 20%

Example 3: Worst Case Overhead

What is the worst-case overhead for bit stuffing?

Answer: 20% - Maximum overhead occurs when every 5th bit is a 1, requiring a 0 to be inserted after each group. For every 5 data bits, 1 extra bit is added.

Byte Stuffing

Byte stuffing (also called character stuffing) uses an escape character to handle special characters in the data. When the escape character appears in the data, it is doubled. When the flag character appears, it is preceded by the escape character.

Byte Stuffing Rule:
FLAG = 01111110, ESC = 01111101
Insert ESC before FLAG in data. Double ESC when it appears in data.

Common Characters

Character Binary Purpose
FLAG 01111110 Frame delimiter
ESC (DLE) 01111101 Escape character

Byte Stuffing Process

Original Data: A DLE B FLAG C DLE DLE D After Stuffing: A DLE ESC B DLE FLAG C DLE ESC DLE ESC D
Example 4: Byte Stuffing Application

Apply byte stuffing to: DLE STX DATA ETX

Answer:

Result: DLE STX DATA ETX

(No stuffing needed since DLE only appears once at the beginning)

Example 5: Overhead Calculation

Calculate byte stuffing overhead for 1000 bytes with 50 ESC characters and 30 FLAG characters in data.

Answer:

Bytes inserted = 50 (for ESC) + 30 (for FLAG) = 80 bytes

Overhead = (80 / 1000) × 100 = 8%

Common Mistake: Byte stuffing doubles the escape character when it appears in data, but only adds ONE escape character before the flag character, not two.

Worked Examples

Example 6: Bit Stuffing with Flags

Show complete HDLC frame with data 11111111 using bit stuffing.

Answer:

Flag + Stuffed Data + Flag

01111110 + 11111011110 + 01111110

(After five 1s, insert 0, then remaining bits)

Example 7: Destuffing Verification

Verify destuffing: 01111110 11111011110 01111110

Answer:

Remove flags: 11111011110

Destuff: 11111111 (remove 0 after five 1s)

Original data: 11111111

Example 8: Byte Stuffing Sequence

Apply byte stuffing to: DATA DLE FLAG DATA

Answer:

Result: DATA DLE ESC FLAG DATA

(DLE before FLAG becomes DLE ESC, FLAG becomes DLE FLAG)

Example 9: Overhead Comparison

Compare overhead of bit stuffing vs byte stuffing for 1000-byte data with worst-case patterns.

Answer:

Bit stuffing worst case: 20% (200 extra bits)

Byte stuffing worst case: 100% (every byte could need escaping)

Example 10: Protocol Selection

Which framing method is used in: (a) HDLC, (b) PPP, (c) Ethernet?

Answer:

(a) Bit stuffing

(b) Byte stuffing

(c) Length field (no stuffing needed)

HDLC Protocol

High-Level Data Link Control (HDLC) is a bit-oriented synchronous data link layer protocol. It uses bit stuffing for frame delimiting and supports both connection-oriented and connectionless modes.

HDLC Frame Format:
Flag (8) | Address (8) | Control (8/16) | Data (0+) | FCS (16/32) | Flag (8)
All fields in bits. Flag = 01111110. Minimum frame size: 32 bits (no data).

HDLC Frame Types

Type Control Field Purpose
I-Frame 0xxxxxxx Information (data transfer)
S-Frame 10xxxxxx Supervisory (control)
U-Frame 11xxxxxx Unnumbered (management)

HDLC vs Other Protocols

HDLC

• Bit-oriented

• Bit stuffing

• 16-bit CRC

PPP

• Byte-oriented

• Byte stuffing

• 16-bit CRC

Ethernet

• Byte-oriented

• Length field

• 32-bit CRC

Key Difference: HDLC uses bit stuffing while PPP uses byte stuffing. This is because HDLC is bit-oriented (data is treated as a stream of bits) while PPP is byte-oriented (data is treated as a sequence of bytes).

Control Characters (ASCII)

Character Code Purpose
SYNCH 0x16 Synchronous idle - maintains sync when no data
STX 0x02 Start of Text - marks beginning of data
ETX 0x03 End of Text - marks end of data
DLE 0x10 Data Link Escape - modifies next character's meaning
ACK 0x06 Acknowledgment - positive response
NAK 0x15 Negative Acknowledgment - negative response
EOT 0x04 End of Transmission - marks end of message
Byte Stuffing with DLE:
Original: [STX][A][DLE][B][ETX][C]
Stuffed: [STX][A][DLE][DLE][B][ETX][C]
DLE in data is doubled. Flag after DLE becomes DLE + Flag.
Example: Control Character Sequence

Show byte stuffing for: A DLE B DLE DLE C DLE FLAG D

Answer:

Result: A DLE ESC B DLE ESC DLE ESC C DLE ESC DLE FLAG D

(Each DLE in data becomes DLE ESC, DLE before FLAG becomes DLE ESC, FLAG becomes DLE FLAG)

Asynchronous vs Synchronous Transmission

Feature Asynchronous Synchronous
Timing Start/Stop bits per character Clock synchronization
Data Format Character-by-character Block of characters
Overhead 20-30% (start/stop/parity bits) 5-10% (SYNCH, framing)
Speed Low (110-9600 bps) High (up to Mbps)
Cost Cheap More expensive
Use Case Terminal-to-computer Computer-to-computer
Asynchronous Overhead Formula:
Overhead = (Start + Stop + Parity) / (Data + Start + Stop + Parity) × 100%
Example: 1 start + 1 stop + 8 data = 2/10 = 20% overhead
Synchronous Overhead Formula:
Overhead = (SYNCH + Flags + FCS) / (Total Frame Size) × 100%
Example: 8 SYNCH + 8 FLAG + 16 FCS + 1000 data = 32/1032 ≈ 3.1% overhead

BSC/Bisync Protocol (Byte-Oriented)

BSC Frame Format:
[SYNCH][STX][Data][ETX][FCS]
Binary Synchronous Communication - IBM's byte-oriented synchronous protocol.

BSC Features

• Byte-oriented (character-based)

• Uses control characters

• Half-duplex operation

• Stop-and-wait ARQ

BSC Limitations

• Binary transparency issues

• Requires DLE stuffing

• Not full-duplex capable

• Replaced by HDLC

Key Insight: BSC was widely used in mainframe environments but has been largely replaced by HDLC and other modern protocols. Understanding BSC helps explain why byte stuffing was developed and why HDLC's bit-oriented approach was superior.
