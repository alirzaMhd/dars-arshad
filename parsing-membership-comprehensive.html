Parsing & Membership

Algorithms for String Recognition — Complete Guide

Parsing Overview

Parsing (or membership testing) determines whether a string w belongs to L(G) — the language of grammar G.

Two Approaches:
1. Top-Down Parsing: Build tree from root (S) to leaves (w)
2. Bottom-Up Parsing: Build tree from leaves (w) to root (S)
Key Concepts:
Parsing = finding a derivation of w from S in grammar G
If such a derivation exists, w ∈ L(G). If not, w ∉ L(G).

Top-Down vs Bottom-Up

FeatureTop-DownBottom-Up
DirectionRoot → LeavesLeaves → Root
Derivation OrderLeftmostReverse of rightmost
ConstructionExpand variablesReduce terminals to variables
Common AlgorithmsLL parsing, recursive descentLR parsing, shift-reduce

Top-Down Parsing

Start with S and try to derive w by expanding the leftmost variable at each step.

Example: Top-Down Derivation of w = a³b³d²

G: S → AB, A → aA | a, B → dB | d

Leftmost Derivation:

S ⇒ AB ⇒ aAB ⇒ aaAB ⇒ aaaAB ⇒ aaaB ⇒ aaadB ⇒ aaadd

w = a³b³d² = aaadd ✓ (wait, this should be a³d² based on the grammar)

Exhaustive Search (Brute Force)

The simplest top-down algorithm tries ALL possible derivations level by level (like BFS):

  1. Start with S at level 0
  2. At each level, expand the leftmost variable using all applicable rules
  3. Check if any derived string matches w
  4. If yes → w ∈ L(G). If exhausted all levels without match → w ∉ L(G)
Termination Issue: The exhaustive search algorithm may not terminate if w ∉ L(G) AND the grammar has ε-productions or unit productions. It only guarantees termination for non-contracting grammars (where |α| ≥ |A| for all rules A → α).

Bottom-Up Parsing

Start with w and try to reduce it back to S by applying rules in reverse.

Example: Bottom-Up Parsing of w = a³b³d²

G: S → AB, A → aA | a, B → dB | d

Bottom-Up (reverse rightmost derivation):

aaadd ← aaadB ← aaaB ← aaAB ← aAB ← AB ← S

Successfully reduced to S → w ∈ L(G) ✓

Bottom-Up Algorithm

  1. Start with the input string w
  2. At each step, find a substring that matches the RHS of some rule
  3. Replace that substring with the LHS variable (reduction)
  4. Repeat until we reach S (success) or no more reductions are possible (failure)

Complexity Analysis

Exhaustive Search Time:
N = |P| + |P|² + |P|³ + ... + |P|^|w| = O(|P|^|w|)
This is EXPONENTIAL in the length of the input string — very inefficient!
Complexity Calculation

For a grammar with |P| rules and input string of length n:

Level 1: at most |P| sentential forms

Level 2: at most |P|² sentential forms

Level k: at most |P|^k sentential forms

Max height: O(n) (for non-contracting grammars)

Total: O(|P|^n) — exponential time!

Better Algorithms

For specific classes of CFGs, efficient O(n³) algorithms exist:

  • CYK Algorithm: O(n³) for any CFG in Chomsky Normal Form
  • LL(k) parsing: O(n) for LL(k) grammars
  • LR(k) parsing: O(n) for LR(k) grammars
  • Simple grammars: O(n) membership testing
Key Result:
For simple grammars, membership testing can be done in O(n) time
This is a significant improvement over the general exponential algorithm.
