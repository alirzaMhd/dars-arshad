Problem Formulation

AI Search - Complete Guide for 20/20 Exam

What Is Problem Formulation?

Problem formulation is the process of defining a real-world task in terms that an AI search algorithm can understand. It requires specifying the initial state, possible actions, goal test, and path cost function without modeling every irrelevant detail.

Core Definition:
A search problem is a tuple (S, A, T, G, C) where S is the state space, A is the action space, T is the transition function, G is the goal test, and C is the path cost function.
Warning: Formulation that is too detailed wastes memory and time. Formulation that is too abstract may miss necessary actions. Abstraction is the art of removing irrelevant details while preserving solvability.

Standard Formulation Components

Every search problem must define five core components. Missing any one of them makes the problem ill-posed for automated solving.

Initial State

The configuration where the agent starts before any actions are taken. Example: In(Arad) for the Romania problem.

Actions / Successor Function

Returns the set of legal actions available in a given state. Defines what the agent can do next.

Goal Test

Determines whether a given state satisfies the mission. Example: At(Bucharest).

Path Cost Function

Assigns a numeric cost to each path. Usually additive: cost(path + a) = cost(path) + step-cost(a).

Path Cost Notation:
c(s, a, s') = step cost from state s to successor s' via action a
The total cost of a path is the sum of step costs along that path.

Abstraction

Abstraction removes unnecessary details from a real-world description so that planning and search remain computationally feasible.

Example 1 - Romania Route

Real world: Includes passenger companions, window scenery, rest stops, road conditions, weather, and fuel level.

Abstracted formulation: Only current city matters. All other details are irrelevant to route finding and are therefore omitted.

Result: State space reduces from a massive continuous description to 20 discrete cities.

Example 2 - Chess

Abstracted goal: Reach checkmate. Exact board positions of every past move are irrelevant.

Result: Search focuses on future moves, not history.

Example 3 - Vacuum Cleaner

Real world: Dirt type, suction power, battery level, room dimensions.

Abstracted: Agent location and clean/dirty status of each square only.

Result: 8 belief states instead of infinite continuous configurations.

Validity Criteria: An abstraction is valid if every abstract solution can be expanded back into a real-world solution. It is useful if actions are easier to perform in the abstract space than in the full real space.

Worked Examples

Example 1 - Route Finding

States: Locations (Arad, Sibiu, Bucharest, etc.)

Initial State: In(Arad)

Actions: Drive from current city to neighbor

Goal Test: In(Bucharest)

Path Cost: Sum of distances in kilometers

Solution: Arad → Sibiu → Fagaras → Bucharest with total cost 280 km.

Example 2 - Vacuum World

States: Agent location + dirt status of each square

Initial State: Any of the 8 possible configurations

Actions: MoveLeft, MoveRight, Suck

Goal Test: Both squares clean

Path Cost: 1 per action

Solution: e.g., Suck, MoveRight, Suck from state (4, dirty, dirty).

Example 3 - 8-Puzzle

States: Position of 8 numbered tiles + blank

Initial State: Any permutation

Actions: Slide blank Up, Down, Left, Right

Goal Test: Tiles ordered 1–8, blank at bottom-right

Path Cost: 1 per move

Note: Exactly half of the 9! = 362,880 permutations are solvable.

Example 4 - 8-Queens

States: Arrangement of 0–8 queens

Initial State: No queens on board

Actions: Add a queen to any non-attacked square

Goal Test: 8 queens placed with no attacks

Path Cost: 0 (only final state matters)

Note: Incremental formulation starts with 0 queens and adds one at a time.
