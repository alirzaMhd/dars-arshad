Inference & Model Checking

Artificial Intelligence — Logical Agents

What is Inference?

Inference in propositional logic is the process of determining whether a logical sentence (the query α) is entailed by a knowledge base (KB). Entailment means that in every model (possible world) where the KB is true, α is also true.

Entailment Definition
KB ⊧ α ⟺ M(KB) ⊆ M(α)
M(KB) = set of all models where KB evaluates to true. If all KB-models are also α-models, α is entailed.

Model Checking Intuition

Model checking enumerates every possible model (assignment of truth values to proposition symbols) and verifies the entailment condition directly. In the Wumpus World, an agent uses model checking to decide whether a square is safe or contains a pit.

Entailment vs. Inference

ConceptDefinitionSymbol
EntailmentKB logically implies α; α is a logical consequence of KBKB ⊧ α

SoundnessIf KB ⊢ α then KB ⊧ α (procedure proves only true entailments)—
CompletenessIf KB ⊧ α then KB ⊢ α (procedure finds all entailments)—
TT-ENTAILS is both sound and complete for propositional logic because it enumerates all models without approximation.

TT-ENTAILS: Complete Algorithm

Algorithm — Model Checking via Depth-First Enumeration
function TT-ENTAILS?(KB, α) returns true/false symbols ← list of proposition symbols in KB and α return TT-CHECK-ALL(KB, α, symbols, {})
function TT-CHECK-ALL(KB, α, symbols, model) returns true/false if EMPTY?(symbols) then if PL-TRUE?(KB, model) then return PL-TRUE?(α, model) else return true else P ← FIRST(symbols) rest ← REST(symbols) return TT-CHECK-ALL(KB, α, rest, EXTEND(P, true, model)) and TT-CHECK-ALL(KB, α, rest, EXTEND(P, false, model))

Key Functions

FunctionPurpose
TT-ENTAILS?(KB, α)Top-level: extracts symbols, initiates recursive check
TT-CHECK-ALL(KB, α, symbols, model)Recursive DFS: assigns T/F to each symbol, evaluates base case
PL-TRUE?(sentence, model)Evaluates a logical sentence given a full model (truth assignment)
EXTEND(P, value, model)Creates new model with symbol P set to given truth value
EMPTY?(list)Checks if all symbols have been assigned

How It Works Step by Step

  1. Collect all proposition symbols appearing in KB and α
  2. Call TT-CHECK-ALL to explore a binary tree of assignments
  3. At each leaf (all symbols assigned), evaluate KB in that model
  4. If KB is false in that model, return true (model is irrelevant for entailment check)
  5. If KB is true, check if α is also true—if α is false in this model, entailment fails
  6. The AND of all recursive calls ensures α holds in all KB-models
Critical Insight: Returning true when KB is false means "this branch doesn't disprove entailment." Only when both KB and ¬α hold does the algorithm fail.

Why P₁,₂ Is Definitively Safe

In all three models where KB holds, P₁,₂ is false (no pit). Therefore KB ⊧ ¬P₁,₂. The agent can safely move to [1,2]. In contrast, P₂,₂ is true in M₁ but false in M₂ and M₃, so the agent cannot be certain.

Wumpus World KB Rules

Key sentences that define the Wumpus KB:

  • R₁: ¬P₁,₁ (no pit in starting square)
  • R₂: B₁,₁ ⇔ (P₁,₂ ∨ P₂,₁) (breeze adjacent to pits)
  • R₃: B₁,₂ ⇔ (P₁,₁ ∨ P₂,₂ ∨ P₁,₃)
  • R₄: B₂,₁ ⇔ (P₁,₁ ∨ P₂,₂ ∨ P₃,₁)
  • Observation: ¬B₁,₁ is known (no breeze at [1,1])

From these, the agent infers ¬P₁,₂ is entailed while P₂,₂ is not. This is a direct model-checking result over the 128 possible worlds.

Example 4: Contradiction in KB

Result: KB is unsatisfiable — no model makes KB true. So in all 0 KB-models, Q holds vacuously. TT-ENTAILS returns true.

⟨Ex falso sequitur quodlibet⟩ — from falsehood, anything follows.

Example 5: Wumpus-Style Reasoning

KB: {¬A, A ⇒ B, B ⇒ C, C ⇒ ¬D}
α: ¬D

With 4 symbols = 16 models. KB is true only when A=F, B=(whatever), C=(whatever), and — actually B is determined by A, etc. Following chain: ¬A forces B to be unconstrained (¬A makes A⇒B true regardless). Let's check systematically:

KB = ¬A ∧ (A⇒B) ∧ (B⇒C) ∧ (C⇒¬D). When ¬A is T, A⇒B is T always. Then B⇒C constrains, C⇒¬D constrains. KB true in models: A=F, B=F, C=F, D=T (1 model). Also A=F, B=F, C=F, D=F: then C⇒¬D is T⇒T=T, so KB=T. Actually wait — let me trace carefully.

When A=F: (A⇒B)=T. When B=F: (B⇒C)=T. When C=F: (C⇒¬D) = (F⇒¬D)=T. So ANY D works. So KB is true in models where A=F, B=F, C=F, D=T/F = 2 models. In both, ¬D? D=T → ¬D=F, D=F → ¬D=T. So ¬D holds in 1 of 2 KB-models → not entailed.

Result: not entailed. This illustrates that chain reasoning requires careful tracking.

SAT and the NP-Completeness Connection

Entailment Complexity
SAT → NP-complete ⟹ Entailment (α ⊧ β) → co-NP-complete
Determining if α is satisfiable (SAT) is NP-complete. Determining if KB ⊧ α is co-NP-complete because the complementary problem (finding a countermodel) is NP-complete.
SAT (NP-complete)
Is there a model where α is true?
Cook-Levin theorem (1971): first NP-complete problem
TAUTOLOGY (co-NP-complete)
Is α true in all models?
Complement of SAT: iff ¬α is unsatisfiable
ENTAILMENT (co-NP-complete)
Is α true in all KB-models?
KB ⊧ α iff (KB ∧ ¬α) is unsatisfiable
