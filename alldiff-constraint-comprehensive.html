Alldiff Constraint

Specialized Handling for "All Values Distinct" Constraints

The Alldiff Constraint

Alldiff is a higher-order constraint that requires all variables in a set to take distinct values. It is one of the most common and useful constraints in real-world CSPs.

Alldiff Definition:
Alldiff(X1, X2, ..., Xm) ⟺ ∀i≠j: Xi ≠ Xj
All m variables must have different values

Why a Specialized Algorithm?

Converting Alldiff to binary inequalities (Xi ≠ Xj for all pairs) creates O(m²) binary constraints. However, a specialized algorithm can detect inconsistencies much faster by looking at the global relationship between variables and values.

Examples of Alldiff

• Cryptarithmetic letters must be distinct

• N-Queens: all queens in different rows

• Sudoku: digits in a row/column/box

• Scheduling: overlap detection

Key Property

Alldiff with m variables and n distinct values:

If m > n → the constraint cannot be satisfied

This is the basis for fast inference!

Alldiff Inference Algorithm

Simple Consistency Algorithm

function INFER-ALLDIFF(variables, domains) returns updated domains // Given an Alldiff constraint over a set of variables // Step 1: Remove assigned variables for each variable X with |domain| = 1 do remove X from Alldiff set remove its value from all other variables' domains // Step 2: Check count condition m ← number of remaining variables in Alldiff n ← number of distinct values in union of remaining domains if m > n then return INCONSISTENT // Alldiff is impossible // Step 3: Repeat until no changes while a variable with |domain| = 1 exists do repeat Step 1 return updated domains

How It Catches Inconsistencies

For the Australia example with WA=red and NSW=red assigned:

  • • The Alldiff involves {NT, SA, Q} (NT has {green, blue}, SA has {green, blue}, Q has {green, blue})
  • • m = 3 variables remaining, n = 2 values ({green, blue})
  • • m > n → Inconsistency detected!

The Alldiff inference is more efficient than running arc consistency on O(m²) binary ≠ constraints.

Worked Examples

Example 1: Cryptarithmetic Alldiff Detection

Variables: {F, T, U, W, R, O, Y} with domains {0...9}

Alldiff: All 7 letters must have distinct digits.

Inference: Initially all have 10 values. No inference possible — m=7 ≤ n=10.

After partial assignment: Suppose F=9, T=8, O=7 → remove these values from remaining domains.

Remaining: {U, W, R, Y} with domain sizes 7 each. m=4 ≤ n=7 → still ok.

Alldiff inference progressively strengthens as assignments are made.

Example 2: N-Queens Row Alldiff

In the N-Queens problem, each queen's row must be distinct.

Alldiff constraint: All Q1, Q2, ..., Qn must have distinct rows.

This is exactly the row constraint. With n queens and n rows, m=n.

If after partial assignment, 3 queens are placed in rows {1, 4, 7}, and the remaining 2 queens must go into {2, 3, 5, 6, 8}: m=2 ≤ n=5 → ok.

But with diagonal constraints added, the effective domain reduces further.

Alldiff + diagonal constraints together make N-Queens solvable efficiently

Example 3: Australia Alldiff Inconsistency

State: WA=red, NSW=red already assigned.

Remaining variables in Alldiff: NT, SA, Q

Domains: NT={green, blue}, SA={green, blue}, Q={green, blue}

Union of domains: {green, blue} — only 2 distinct values

Count check: m=3 > n=2 → INCONSISTENT!

The Alldiff constraint correctly detects that 3 variables cannot all be different with only 2 values available.

Example 4: Forward Checking vs Alldiff Inference

Problem: 3 variables {A, B, C} with domains {1, 2}, Alldiff(A, B, C)

Forward checking (with binary ≠ constraints):

• A=1 → removes 1 from B and C → B={2}, C={2}

• B=2 (the only choice) → removes 2 from C → C={} → inconsistency detected.

Alldiff inference:

• m=3, union of domains = {1,2}, n=2. m > n → immediate detection!

Alldiff inference detects the inconsistency before any assignment rather than after exploring branches.

Alldiff inference is more powerful than simple arc consistency on pairwise constraints!

Quick Reference

Alldiff Detection

• m = number of variables

• n = number of distinct values

• If m > n: impossible!

Algorithm Steps

1. Remove singleton-variable values

2. Count m vs n

3. Repeat until stable

4. Return inconsistency if m > n

Advantage

More efficient than O(m²) binary constraints for m > 2. Also detects inconsistencies earlier than pairwise arc consistency.
