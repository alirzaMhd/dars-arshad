Backtracking Search for CSP

Depth-First Search with Variable Assignment

Backtracking Search Concept

Backtracking search is a depth-first search specifically adapted for CSPs. It assigns values to one variable at a time and backtracks when a constraint is violated.

Commutativity in CSP

CSPs have the important property of commutativity: the order of applying actions does not affect the outcome. Assigning WA=red then NT=green is the same as NT=green then WA=red.

Key Insight: Because of commutativity, all CSP algorithms assign only one variable at each level of the search tree. This reduces branching factor from nd to just d.
Branching Factor Comparison:
Naive: (nd) · (n-1)d · (n-2)d · ... → n·dn leaves
With commutativity: d · d · d · ... (n times) → dn leaves
An enormous reduction! Example: n=10, d=10 → naive = 10·1010, commutativity = 1010

Formulations

Incremental Formulation

Start with empty assignment

Add one variable at a time

Goal: Complete assignment

Cost: 1 per step

Complete-State Formulation

Start with full assignment

Modify one variable at a time

Goal: No constraints violated

Used with local search

The Backtracking Algorithm

Algorithm:
function BACKTRACKING-SEARCH(csp) returns a solution or failure return RECURSIVE-BACKTRACKING({}, csp) function RECURSIVE-BACKTRACKING(assignment, csp) returns a solution or failure if assignment is complete then return assignment var ← SELECT-UNASSIGNED-VARIABLE(VARIABLES[csp], assignment, csp) for each value in ORDER-DOMAIN-VALUES(var, assignment, csp) do if value is consistent with assignment given CONSTRAINTS[csp] then add {var = value} to assignment result ← RECURSIVE-BACKTRACKING(assignment, csp) if result ≠ failure then return result remove {var = value} from assignment return failure

Algorithm Features

  • • Depth-first: explores one branch fully before backtracking
  • • Incremental: builds assignment step by step
  • • Commutativity-aware: assigns one variable per level
  • • Backtracking: on constraint violation
  • • Complete: finds a solution if one exists

Worked Examples

Example 1: Australia Map — Backtracking Trace

Order: WA, NT, Q, NSW, V, SA, T (static order)

Steps:

1. Assign WA=red ✓

2. Assign NT=green ✓ (≠ red)

3. Assign Q=red ✓ (≠ green)

4. Assign NSW=green ✓ (≠ red, conflict with Q? No)

5. Assign V=red ✓ (≠ green)

6. Assign SA: only blue remains ✓ (≠ red, green)

7. Assign T=any color ✓

✓ Solution found without backtracking!

Example 2: When Backtracking is Needed

Order: WA, NT, Q, SA, NSW, V, T

Steps:

1. WA=red ✓

2. NT=green ✓

3. Q=blue ✓

4. SA: no color left (neighbors WA=red, NT=green, Q=blue have all 3 colors) → BACKTRACK

5. Change Q from blue to... but Q=red/green also cause issues. Continue backtracking.

This demonstrates that variable ordering matters greatly for efficiency!

Example 3: 4-Queens as CSP

Variables: Q1, Q2, Q3, Q4 (queens in columns 1-4)

Domains: {1, 2, 3, 4} (rows)

Backtracking trace:

• Q1=1 ✓ → Q2=3 ✓ → Q3=? (all conflict with Q1=1, Q2=3) → backtrack to Q2

• Q2=4 ✓ → Q3=2 ✓ → Q4=? (conflicts) → backtrack...

• Eventually: Q1=2, Q2=4, Q3=1, Q4=3 → solution!

Found after exploring many branches with backtracking

Example 4: Impact of Variable Ordering

For the 4-Queens problem:

Bad ordering: Q1 first (least constrained) → many branches explored

Good ordering: Most constrained column first → fewer branches

The difference can be exponential in problem size!

Quick Reference

Key Properties

• Depth-first search

• Assigns one variable per level

• Complete and optimal

• Handles commutativity

• dn leaves (not n·dn)

Algorithm Components

• SELECT-UNASSIGNED-VARIABLE: choose next variable

• ORDER-DOMAIN-VALUES: order values to try

• Consistency check: verify constraints

• Recursive backtracking: undo on failure

Limitations

• Naive backtracking is blind

• Thrashing on repeated failures

• No constraint propagation

• Needs heuristics for efficiency

Common Mistake: Using BFS for CSP. BFS would require O(dn) space vs DFS which uses O(n) space. Always use depth-first (backtracking) for CSP!
