Applications of Formal Languages

Practical Uses in Programming Languages & Compilers — Complete Guide

Regular Languages in Practice

Regular languages are used extensively in computer science for pattern matching and lexical analysis.

Lexical Analysis (Compilers)

Tokens in Programming Languages:
Identifiers, numbers, keywords, operators → all regular
Lexical analyzers use regular expressions to define token patterns, then compile them to DFAs for efficient scanning.
Example: Token Patterns

Identifier: [a-zA-Z][a-zA-Z0-9]*

Integer: [0-9]+

Float: [0-9]+\.[0-9]+([eE][+-]?[0-9]+)?

Keyword: if|else|while|for|return|...

Operator: +|-|\*|/|==|!=|<=|>=|&&|\|\|

Text Processing Tools

  • grep/egrep: Search files using regular expressions
  • sed/awk: Stream editing with RE patterns
  • Lexer generators: flex, lex — generate scanners from RE specifications
  • Search engines: Pattern matching in documents

Protocol Specification

Modeling Communication Protocols

Message sequences can be described with regular expressions:

Protocol: (open·data*·close)* · timeout?

Finite automata model the state machine of the protocol.

Context-Free Languages in Practice

CFLs describe syntactic structures that require matching (like balanced parentheses).

Syntax Analysis (Parsing)

CFL Applications in Compilers:
Expression grammar, statement structure, nested blocks → all context-free
Context-free grammars define the syntax of programming languages. Parsers verify that source code conforms to the grammar.
Why Regular Languages Aren't Enough

Balanced parentheses: {ⁿ(ⁿ)ⁿ : n ≥ 0}

This language requires counting/matching, which finite automata cannot do.

Context-free grammars can handle nested, recursive structures.

Programming Language Syntax

C Language Grammar (partial)

<statement> ::= <while-statement> | <if-statement>

<while-statement> ::= while <expression> <statement>

<if-statement> ::= if <expression> <statement>

| if <expression> <statement> else <statement>

This is a CFL — it handles nested if-else, while loops, etc.

XML/HTML Parsing

Nested Tags

<html><body><p>Hello</p></body></html>

The matching of opening and closing tags is a context-free structure.

XML parsers use CFL recognition algorithms.

BNF (Backus-Naur Form)

BNF is a notation for writing context-free grammars, commonly used for programming language specifications.

BNF Syntax:
<symbol> ::= expression | expression2 | ...
<> encloses non-terminals, ::= means "is defined as", | means "or"
BNF Example: Arithmetic Expressions

<expr> ::= <expr> + <term> | <term>

<term> ::= <term> * <factor> | <factor>

<factor> ::= ( <expr> ) | a | b | c

This unambiguous grammar enforces operator precedence (* before +) and left associativity.

BNF Example: C-like Language Statements

<statement> ::= <while-statement> | <if-statement>

<while-statement> ::= while <expression> <statement>

<if-statement> ::= if <expression> <statement> | if <expression> <statement> else <statement>

This grammar describes the structure of while-loop and if-else statements in a C-like language.

Why BNF?
BNF notation helps avoid limitations of English letters and case sensitivity.
Grammars in BNF form can be easily stored in files and processed by computers (compilers, parser generators).

Extended BNF (EBNF)

EBNF Extensions

{ } → zero or more repetitions (Kleene star)

[ ] → optional (zero or one)

( ) → grouping

<identifier> ::= <letter> { <letter> | <digit> }

This is equivalent to: <letter>(<letter>|<digit>)*

Key Takeaways

Formal Language Theory in Practice:
• Regular languages → Lexical analysis (first phase of compiler)
• Context-free languages → Syntax analysis (second phase of compiler)
• Context-sensitive languages → Semantic analysis (type checking)
• The Chomsky hierarchy maps directly to compiler phases!

Limits of Regular Languages

What regular languages CANNOT describe:
  • Balanced parentheses: {(ⁿ)ⁿ : n ≥ 0}
  • Matching tags: {aⁿbⁿ : n ≥ 0}
  • Palindromes: {wwᴿ : w ∈ {a,b}*}
  • Prime number of a's: {aᵖ : p is prime}

All of these require "memory" or "counting" beyond what finite automata can provide.

Exercise 5-1: Find the Language of Each Grammar

(a) S → abSba

L = {aⁿb²ⁿaⁿ : n ≥ 0}

Each application of the rule adds one 'a' on each side and two 'b's in the middle.

(b) S → SS | a | b

L = {all strings of a's and b's with length ≥ 1} = {a,b}⁺

S generates any non-empty concatenation of single a's or b's.

(c) S → SS | aa | ab

L = {strings made of aa and ab concatenated together}

Every string starts with a, has at least one a, and ends in a or b.

(d) S → aaSb | bbSa

L = {a²ⁿb²ᵐ : n,m ≥ 0} (strings with even number of a's followed by even number of b's)

(e) S → AB, A → aS | bB | λ, B → bSaA | λ

L is a complex language involving balanced patterns of a's and b's.

A and B can derive ε, so S = AB can produce strings from A and B independently.

(f) S → aA | bS | bλ, A → aB | bA, B → aS | bB | a

L is a complex language — strings over {a,b} with specific structural constraints.

(g) S → aB | bA, A → a | aS | bAA, B → b | bS | aBB

L is a complex language — symmetric structure with a's and b's.

(h) S → XSX | A, A → aBb | bBa, B → XBXX | λ, X → ab

L is a complex language — X always produces 'ab', creating structured strings.

(i) S → aab | ba

L = {aab, ba}

Only two possible strings in the language.

(j) S → AA, A → SaSa | λ, A → 0A0 | 1, B → 0B00 | 1

L is a complex language involving nested structures with 0's and 1's.

Exercise 5-2: Design CFGs

(a) {a^(2m+3) · b^(2m+1) : m ≥ 0}

S → aaaSb | aab

For m=0: a³b¹, for m=1: a⁵b³, etc. Each iteration adds 2 a's and 2 b's.

(b) {a^(3m+1) · b^(2m) : m ≥ 0}

S → aaaSbb | a

For m=0: a¹, for m=1: a⁴b², etc. Each iteration adds 3 a's and 2 b's.

(c) {aⁱbʲcᵏdᵐ : i,j,k,m ≥ 0, i≠m or j≠k}

S → S₁ | S₂ where S₁ handles i≠m, S₂ handles j≠k

The complement of {aⁱbⁱcⁱdⁱ : i ≥ 0} is not CFL, but this language (requiring only ONE condition to fail) IS CFL.

(d) {aⁱbʲcᵏdᵐ : i+j = k+m}

S → aSd | bSc | X, X → cXd | λ

Count a's and b's against d's and c's using matching.

(e) {aᵐbⁿ : m = 3n or n = 3m}

S → S₁ | S₂, S₁ → aaaS₁b | λ (m=3n), S₂ → aS₂bbb | λ (n=3m)

(f) {avbw : v,w ∈ {a,b}*, |v| = |w|}

S → aAa | aBb | bAb | bBa, A → aAa | aBb | bAb | bBa | λ, B → ...

Strings where a and b are separated by equal-length substrings.

(g) Strings where first and last character are equal

S → aAa | bAb | a | b, A → aA | bA | λ

First and last characters match, anything can be in between.

(h) Empty set

S → S (no terminal-generating rule)

A grammar with no way to derive any terminal string generates L = ∅.

(i) Complement of {aⁿbⁿ : n ≥ 0}

NOT CFL — the complement of {aⁿbⁿ} is not context-free (requires two counter conditions).

However, {aⁱbʲ : i ≠ j} IS CFL: S → aSb | A, A → aA | bA | λ

(j) {aⁿbᵐcᵏ : k ≠ n + m}

S → S₁ | S₂, S₁ → aS₁c | bS₁c | A₁ (k > n+m), S₂ → aS₂ | bS₂ | cS₂c | A₂ (k < n+m)

(k) {aⁿbᵐcᵏ : m ≠ k}

S → S₁ | S₂, S₁ → aS₁ | B₁, S₂ → aS₂ | B₂

B₁ handles m > k, B₂ handles m < k.

(l) {aⁿbᵐcᵏ : m > n + k}

S → aSb | cSb | B, B → bB | b

Each a or c consumes one b, then extra b's remain.

(m) {a²ⁿwwᴿb²ⁿ : w ∈ {a,b}*, n ≥ 0}

S → aaSbb | A, A → wAwᴿ | λ (for all w ∈ {a,b}*)

This is NOT CFL — it requires matching a²ⁿ with b²ⁿ AND wwᴿ simultaneously, which requires two independent counters.
