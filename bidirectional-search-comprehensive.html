Bidirectional Search Algorithm

Bidirectional search runs two simultaneous searches: one forward from the initial state and one backward from the goal state. When the two search frontiers meet, a solution is constructed by joining the two paths.

function Bidirectional-Search(problem) returns solution or failure
forward-fringe ← Make-Queue(Make-Node(Initial-State))
backward-fringe ← Make-Queue(Make-Node(Goal-State))
loop do
if Empty?(forward-fringe) or Empty?(backward-fringe) then return failure
forward-fringe ← Expand-Front(forward-fringe)
backward-fringe ← Expand-Back(backward-fringe)
if Intersection(forward-fringe, backward-fringe) ≠ ∅ then
return Concatenate-Paths(forward, backward)
Meeting Condition:
Intersection(forward-fringe, backward-fringe) ≠ ∅
When a node generated by the forward search matches a node in the backward search frontier, the two partial paths are joined to form the complete solution.

Time and Space Complexity

If both searches proceed at the same speed and meet at the middle, each search explores only half the depth. The total nodes expanded is roughly b^(d/2) + b^(d/2) = 2*b^(d/2).

Time Complexity:
O(b^(d/2))
Each direction explores depth d/2. The square root of BFS's node count.
Space Complexity:
O(b^(d/2))
Each fringe stores nodes up to depth d/2. The dominant term is the larger of the two fringes.
Example - Speedup Factor

If d = 20 and b = 10: BFS needs 10^20 nodes. Bidirectional needs 2*10^10 = 20 billion nodes. This is a factor of 10^10 speedup, making previously impossible searches feasible.

Properties

Property Bidirectional (both BFS)
Complete? Yes, with proper implementation
Optimal? Yes, if both sides use BFS and step costs equal
Time Complexity O(b^(d/2))
Space Complexity O(b^(d/2))
Key Challenge Computing predecessors efficiently
Backward Search Difficulty: Computing predecessors requires applying inverse actions. In some problems (like checkmate in chess), the goal is an implicit description, making backward search difficult. A dummy start node connected to all goal states can sometimes help.
Intersection Check: Checking if two large frontiers intersect naively is expensive. Use a hash table for O(1) membership testing.

Worked Examples

Example 1 - Simple Tree

Tree of depth 6, b=2. Forward from root, backward from goal at depth 6. They meet at depth 3. Forward expands 1+2+4 = 7 nodes. Backward expands 1+2+4 = 7 nodes. Total = 14 vs BFS's 127 nodes.

Space reduction: From 64 nodes at depth 6 to 8 nodes at depth 3 per side.

Example 2 - Romania Problem

Forward from Arad, backward from Bucharest. If Bucharest has neighbors Pitesti, Giurgiu, Urziceni, Fagaras, the backward search starts from all four. The frontiers meet somewhere in the middle, perhaps at Sibiu or Rimnicu.

Example 3 - Multiple Goal States

Goal is "any of {G1, G2, G3}". Create a dummy backward start node with edges to all three goal states. Backward search treats this dummy as the single backward root.

Example 4 - When It Fails

If the goal is implicit (e.g., checkmate in chess), computing predecessors is hard. Bidirectional search may require more effort to define backward actions than it saves in search time.
