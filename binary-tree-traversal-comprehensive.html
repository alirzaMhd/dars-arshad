Binary Tree Traversal

Data Structures — Complete Guide for 20/20 Exam

What is Tree Traversal?

Tree traversal is the process of visiting every node in a binary tree exactly once in a systematic order. The goal is to access data in each node in a specific sequence.

Two Main Categories

Depth-First Traversal

Explores as deep as possible along each branch before backtracking.

Uses stack (recursion or explicit stack)

6 types: DLR, LDR, LRD, RLD, RDL, DRL

Level-Order Traversal

Visits nodes level by level, from left to right.

Uses queue

Also called breadth-first traversal

Reference Tree for All Examples: a / \ b c / \ \ d e f / \ g h

Traversal Naming Convention

Using D = visit node (data), L = traverse left subtree, R = traverse right subtree:

⚠ The three most important traversals are DLR (preorder), LDR (inorder), and LRD (postorder). The reverse versions (RLD, RDL, DRL) visit nodes in reverse order of their standard counterparts.

Preorder Traversal (DLR)

Order:
Visit Root → Traverse Left → Traverse Right
Visit the current node first, then recursively visit the left subtree, then the right subtree.
preorder(node) { if (node == NIL) return; visit(node); // D: Visit root preorder(node.left); // L: Traverse left preorder(node.right); // R: Traverse right }
Preorder Example
a → Visit a first / \ b c → Then traverse b's subtree, then c's subtree / \ \ d e f / \ g h

Result: a, b, d, e, g, h, c, f

Explanation: Visit a → left to b → left to d → back to b → right to e → left to g → back to e → right to h → back to a → right to c → right to f

Preorder Applications

• Creating a copy of the tree

• Generating prefix expressions from expression trees

• Serializing a tree structure

Inorder Traversal (LDR)

Order:
Traverse Left → Visit Root → Traverse Right
Traverse the left subtree first, then visit the current node, then traverse the right subtree.
inorder(node) { if (node == NIL) return; inorder(node.left); // L: Traverse left visit(node); // D: Visit root inorder(node.right); // R: Traverse right }
Inorder Example
a / \ b c / \ \ d e f / \ g h

Result: d, b, g, e, h, a, c, f

Explanation: Go left to d → visit d → back to b → visit b → right to e → left to g → visit g → back to e → visit e → right to h → visit h → back to a → visit a → right to c → visit c → right to f → visit f

Inorder Applications

• For BSTs, inorder gives sorted order

• Generating infix expressions from expression trees

• Most common traversal for BST operations

Postorder Traversal (LRD)

Order:
Traverse Left → Traverse Right → Visit Root
Traverse the left subtree first, then the right subtree, then visit the current node.
postorder(node) { if (node == NIL) return; postorder(node.left); // L: Traverse left postorder(node.right); // R: Traverse right visit(node); // D: Visit root }
Postorder Example
a / \ b c / \ \ d e f / \ g h

Result: d, g, h, e, b, f, c, a

Explanation: Left subtree of b → d → g → h → e → b → Right subtree of a → f → c → finally visit a

Postorder Applications

• Deleting a tree (delete children before parent)

• Generating postfix expressions from expression trees

• Evaluating expressions in expression trees

Recursive vs Iterative Traversal

All three depth-first traversals can be implemented recursively (simple) or iteratively using an explicit stack.

Recursive

• Simple and clean code

• Uses call stack implicitly

• Risk of stack overflow for deep trees

O(n) time, O(h) space

Iterative (with stack)

• More complex code

• Explicit stack control

• No stack overflow risk

O(n) time, O(h) space

Traversal Complexity:
Time: O(n), Space: O(h)
Every node is visited exactly once → O(n) time. Space depends on tree height h (stack depth).

Level-Order Traversal

Process:
Visit nodes level by level, left to right at each level
Uses a queue (FIFO) to maintain the order of visitation.
Levelorder(root) { Q = empty queue addq(Q, root) while (not empty(Q)) { node = delq(Q) visit(node) if (left(node) != NIL) addq(Q, left(node)) if (right(node) != NIL) addq(Q, right(node)) } }
Level-Order Example
Level 0: a / \ Level 1: b c / \ \ Level 2: d e f / \ Level 3: g h

Result: a, b, c, d, e, f, g, h

Step-by-step:

1. Enqueue a → Queue: [a]

2. Dequeue a, visit → Queue: [], Enqueue b, c → Queue: [b, c]

3. Dequeue b, visit → Queue: [c], Enqueue d, e → Queue: [c, d, e]

4. Dequeue c, visit → Queue: [d, e], Enqueue f → Queue: [d, e, f]

5. Dequeue d, visit → Queue: [e, f], No children → Queue: [e, f]

6. Dequeue e, visit → Queue: [f], Enqueue g, h → Queue: [f, g, h]

7. Dequeue f, visit → Queue: [g, h], No children → Queue: [g, h]

8. Dequeue g, visit → Queue: [h]

9. Dequeue h, visit → Queue: []

Complexity:
Time: O(n), Space: O(w)
w = maximum width of tree. For a complete binary tree, w = 2^h where h is the height.
⚠ Level-order traversal requires a QUEUE, while depth-first traversals use a STACK (recursion). This is a common exam distinction!

Reverse Traversals

These traversals visit nodes in the opposite order of their standard counterparts.

RLD (Reverse Preorder)

Order:
Traverse Right → Visit Root → Traverse Left
Mirror of preorder. Visits right subtree first.

RDL (Reverse Inorder)

Order:
Traverse Right → Visit Root → Traverse Left
Mirror of inorder. For BSTs, gives reverse sorted order.

DRL (Reverse Postorder)

Order:
Visit Root → Traverse Right → Traverse Left
Mirror of postorder.
All 6 Traversals Compared

LDR (Inorder)L-D-Rd, b, g, e, h, a, c, f
LRD (Postorder)L-R-Dd, g, h, e, b, f, c, a
RLD (Rev Preorder)R-D-La, c, f, b, e, h, g, d
RDL (Rev Inorder)R-D-Lf, c, a, h, e, g, b, d
DRL (Rev Postorder)D-R-La, c, f, b, e, h, g, d
⚠ Important: Leaf nodes appear in the SAME order for DLR, LDR, and LRD (left to right). For RLD, RDL, and DRL, leaves appear in reverse order (right to left).

Worked Examples

Example 1: Basic Traversal

Given the tree below, find all 6 traversal orders:

a / \ b c / / \ d e f

Solution:

DLR: a, b, d, c, e, f

LDR: d, b, a, e, c, f

LRD: d, b, e, f, c, a

Example 2: Number of Function Calls

How many times is the preorder function called for a tree with n nodes?

Solution:

For n nodes, the function is called 2n + 1 times (once per node visit + once for each NIL pointer).

For the reference tree (8 nodes): 2(8) + 1 = 17 calls

Example 3: Identify Tree from Traversals

Given DLR = faeckdghb and LDR = eakcfgdhb, find LRD.

Solution:

1. First in DLR is always root: f is root

2. In LDR, elements left of f are left subtree: {e, a, k, c}

3. Elements right of f are right subtree: {g, d, h, b}

4. In DLR, second element is root of left subtree: a

5. In LDR, elements left of a in left subtree: {e}, right: {k, c}

6. Continue recursively...

7. Final LRD: e, k, c, a, b, h, g, d, f

Example 4: How Many Trees from Traversals?

Given inorder = a b c, how many different binary trees exist?

Solution:

For n nodes with inorder traversal, the number of possible trees = Catalan(n) = C(2n,n)/(n+1)

For n=3: Catalan(3) = 5

Example 5: Skewed Tree Traversals

What are the traversals for a right-skewed tree: a → b → c → d?

Solution:

DLR: a, b, c, d

LDR: a, b, c, d (same as DLR!)

LRD: d, c, b, a

⚠ For right-skewed trees: DLR = LDR. For left-skewed trees: LDR = LRD.
Example 6: Building Tree from Traversals

Given LRD = CBEGHFDA and LDR = BCDAEDGFH, build the tree.

Solution:

1. Last in LRD is root: A

2. In LDR: BC left of A, EDGFH right of A

3. Left subtree: LRD = CB, LDR = BC

4. Last of CB is B (root), C is left child

5. Right subtree: LRD = EGHFD, LDR = EDGFH

6. Last of EGHFD is D (root), continue...

A / \ B D / / \ C E F / \ G H
Example 7: Building Tree from Preorder + Known Leaves

Given preorder = a b d e g h c f and leaves = {d, e, g, h, c, f}, build the tree using a stack.

Algorithm:

1. Read preorder left to right

2. If node is NOT a leaf → push to stack (it will be a parent)

3. If node IS a leaf → pop from stack to assign as right child

Step-by-step:

StepPreorderActionStack
1aNot leaf → push[a]
2bNot leaf → push[a, b]
3dLeaf → pop b, assign d as b's left[a]
4eLeaf → pop b, assign e as b's right[a]
5gLeaf → pop a, assign g as a's left... wait, need to track...

Corrected approach: When a non-leaf is popped, its left child is the next preorder element, and right child is the element after that.

Result: a / \ b c / \ \ d e f / \ g h

Preorder: a, b, d, e, g, h, c, f ✓

Example 8: Uniqueness from Preorder + Postorder

Given preorder and postorder, when is the tree unique?

Theorem:

• If preorder and postorder have NO single-child nodes, the tree is uniquely determined

• If there are k single-child nodes, there are 2^k possible trees

Example: preorder = abdehicfg, postorder = dhibfgca

Single-child nodes: e (only left child d), h (only left child i), f (only right child g)

Number of single-child nodes = 3

Number of possible trees = 2^3 = 8

Common Exam Patterns

Given DLR + LDR → Unique tree can be constructed
Root is first in DLR. Split LDR by root position. Recurse on subtrees.
Given LRD + LDR → Unique tree can be constructed
Root is last in LRD. Split LDR by root position. Recurse on subtrees.
Given DLR + LRD → NOT always unique
Only unique if tree has 0 or 1 children per node (full binary tree).
