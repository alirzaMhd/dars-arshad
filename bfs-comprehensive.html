Breadth-First Search (BFS)

AI Search - Complete Guide for 20/20 Exam

BFS Algorithm

Breadth-first search expands the shallowest unexpanded node first. It uses a FIFO queue so that nodes at depth d are expanded before nodes at depth d+1.

function BFS(problem) returns solution or failure
fringe ← Make-Queue(Make-Node(Initial-State[problem]))
loop do
if Empty?(fringe) then return failure
node ← Remove-First(fringe)
if Goal-Test[problem](State[node]) then return Solution(node)
fringe ← Insert-All(Expand(node, problem), fringe)
Node Expansion Order:
All nodes at depth d are expanded before any node at depth d+1

Time and Space Complexity

BFS explores the search tree level by level. In the worst case, it must store all nodes at the deepest level.

Time Complexity:
O(b^(d+1))
b = branching factor, d = depth of shallowest goal node. Each node generates b children, and BFS explores every node up to depth d.
Space Complexity:
O(b^(d+1))
All nodes at depth d+1 must be stored in the fringe simultaneously.
Example - Exponential Growth

If b = 10 and d = 8, BFS may need to store 10^9 nodes in memory, requiring terabytes of RAM. For d = 12, the time required exceeds practical limits even with 10,000 nodes/second generation speed.

Properties

Property BFS
Complete? Yes, if b is finite
Optimal? Yes, if all step costs are equal
Time Complexity O(b^(d+1))
Space Complexity O(b^(d+1))
Queue Type FIFO
Warning: BFS is complete and optimal only when all step costs are identical. If step costs vary, BFS finds the shallowest goal but not necessarily the cheapest path. Use Uniform Cost Search for varying costs.

Worked Examples

Example 1 - Romania Problem

Starting from Arad, BFS explores all cities at distance 1 (Sibiu, Timisoara, Zerind), then all at distance 2, and so on. If Bucharest is at depth 4, BFS will find it after exploring all nodes at depths 0 through 3.

Order of expansion: Arad → Sibiu, Timisoara, Zerind → (all depth-2 cities) → Bucharest.

Example 2 - Binary Tree

Given a binary tree with root S, BFS visits nodes in level order: S, then A, B, then children of A, then children of B. Goal node at depth 3 is found after exploring all nodes at depths 0, 1, and 2.

Example 3 - 8-Puzzle

With branching factor ~2.7 on average, BFS explores all positions at depth 0, then 1, then 2, etc. For optimal solution at depth 10, BFS must store roughly 2.7^10 ≈ 20,000 nodes.

Space becomes the bottleneck before time for large b.

Example 4 - Why BFS Fails on Deep Solutions

If the goal is at depth 14 and b = 10, BFS needs to store 10^14 nodes. At 1000 bytes per node, this requires 10^17 bytes = 100 petabytes. BFS is therefore impractical for deep goals with high branching factors.
