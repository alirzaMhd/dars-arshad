Breadth-First Search (BFS)

Uninformed Search Strategy — Complete Guide

BFS Algorithm Overview

Breadth-First Search expands nodes level by level, always expanding the shallowest unexpanded node first. It explores all nodes at depth d before moving to depth d+1.

Core Principle:
Expand shallowest unexpanded node first
BFS explores the state space in layers, guaranteeing the shortest path (in edges) to the first goal found, provided all step costs are uniform.

How It Works

BFS uses a FIFO (First-In-First-Out) queue. When a node is expanded, all its successors are added to the back of the queue. This ensures that nodes are processed in the order they are discovered, level by level.

Data Structure

• FIFO Queue

• New successors → back

• Dequeue from front

Key Properties

• Level-by-level expansion

• Complete if b,d finite

• Optimal for uniform costs

Pseudocode

function BFS(problem) returns solution or failure node ← Node(State: problem.INITIAL, Parent: nil, Action: nil, Path-Cost: 0) if problem.GOAL-TEST(node.State) then return SOLUTION(node) frontier ← FIFO-queue containing node explored ← empty set loop do if EMPTY?(frontier) then return failure node ← POP(frontier) // remove from front add node.State to explored for each action in problem.ACTIONS(node.State) do child ← CHILD-NODE(problem, node, action) if child.State not in explored and child.State not in frontier then if problem.GOAL-TEST(child.State) then return SOLUTION(child) frontier ← INSERT(child, frontier) // add to back

Node Expansion Order

For a tree with branching factor b = 2, BFS expands nodes in the following order:

Level 0: Root Level 1: Node[0], Node[1] (first layer) Level 2: Node[0,0], Node[0,1], Node[1,0], Node[1,1] (second layer) Level 3: Node[0,0,0], ... ...
Each level contains bd nodes. The queue grows exponentially with depth.

Completeness of BFS

A search algorithm is complete if it always finds a solution when one exists.

Completeness Condition:
BFS is complete if b is finite and d is finite
If the branching factor b is finite and the shallowest goal depth d is finite, BFS will eventually reach every node at depth d and find the goal.
Why BFS is Complete

BFS explores nodes in non-decreasing order of depth. If a goal exists at depth d, BFS will exhaustively explore all nodes at depths 0, 1, 2, ..., d-1 before reaching the goal at depth d. Since the number of nodes at each depth is finite (b is finite), this process terminates.

Optimality of BFS

Optimality Condition:
BFS is optimal if step costs are uniform
When every step has the same cost (e.g., cost = 1 for each action), the first goal found by BFS is guaranteed to be the shallowest, and thus the cheapest.
Warning: BFS is NOT always optimal

If step costs vary (non-uniform), the shallowest goal is not necessarily the cheapest. For example, a path with depth 5 and total cost 10 may be cheaper than a path with depth 2 and total cost 50. BFS only guarantees shallowest, not cheapest.

Graph-Search Version

BFS with a closed list (explored set) is also optimal for uniform costs. The explored set prevents re-expanding nodes, reducing overhead while preserving completeness and optimality.

Uniform Costs ✓

• BFS is optimal

• First goal = cheapest

• Tree & Graph search

Non-Uniform Costs ✗

• BFS not optimal

• May find costlier path

• Use UCS instead

Time & Space Complexity

BFS has identical time and space complexity because every generated node must stay in memory — either in the fringe or as an ancestor. This is BFS's major weakness.

Total Nodes Generated (worst case):
b + b² + b³ + ... + bd + (bd+1 − b) = O(bd+1)
Where b = branching factor, d = depth of shallowest goal. The final term accounts for nodes at depth d+1 that are generated but not expanded.
Time Complexity:
O(bd+1)
Number of nodes generated before finding the goal.
Space Complexity:
O(bd+1)
Every generated node is retained in memory (fringe + explored set). This is often the limiting factor.
Warning: Memory is the Bottleneck

For BFS, memory requirements grow even faster than time in practice. A problem that takes 31 hours to solve might require 1TB of RAM — far beyond typical available memory. Space is BFS's critical weakness.

Worked Examples

Example 1: Trace BFS on a Small Binary Tree

Problem: A binary tree (b = 2) with depth 3. Goal is at the rightmost leaf of level 3 (node "RR"). Trace BFS step by step.

Tree: Root → L, R → LL, LR, RL, RR (LR is expanded first in left-to-right order). Goal = "RR".

Step-by-step trace:

StepFringe (front → back)Node ExpandedAction
1[Root]—Initialize with Root
2[L, R]RootExpand Root → L, R added to back
3[R, LL, LR]LExpand L → LL, LR added to back
4[LL, LR, RL, RR]RExpand R → RL, RR added to back
5[LR, RL, RR]LLLL has no children (leaf)
6[RL, RR]LRLR has no children (leaf)
7[RR]RLRL has no children (leaf)
8[]RR ✓RR is goal! Solution found.

BFS expanded 7 nodes before reaching goal. Total nodes generated: 7 (all nodes at depth 0,1,2,3).

Example 2: Calculate Nodes Generated

Problem: A search tree has branching factor b = 3. The shallowest goal is at depth d = 4. How many nodes does BFS generate in the worst case?

Solution: Use the formula for total nodes:

Total = b + b² + b³ + b⁴ + (b⁵ − b) = 3 + 9 + 27 + 81 + (243 − 3) = 360

Breakdown:

• Level 1: 3 nodes

• Level 2: 9 nodes

• Level 3: 27 nodes

• Level 4: 81 nodes (goal found here, all expanded)

• Level 5: 240 nodes generated but not expanded before goal found

Total nodes generated: O(b⁵) = O(3⁵) = 243, but exact count is 360 including the root.

Example 3: Memory Requirements Comparison

Problem: Compare BFS memory requirements for two scenarios: (a) b = 4, d = 6 vs (b) b = 2, d = 12. Assume 1KB per node.

Scenario (a): b = 4, d = 6

Nodes ≈ 4⁷ − 4 = 16384 − 4 = 16380 → Memory ≈ 16.4 MB

Scenario (b): b = 2, d = 12

Nodes ≈ 2¹³ − 2 = 8192 − 2 = 8190 → Memory ≈ 8.2 MB

Despite depth being double, the smaller branching factor makes (b) more memory-efficient. Branching factor has a greater impact than depth on BFS complexity.

Example 4: BFS on a Graph with Cycles

Problem: A graph has nodes A, B, C, D, E. Edges: A→B, A→C, B→D, C→D, D→E, E→B. Goal is E. Use BFS with an explored set (graph search).

StepFringeExploredExpanded
1[A]——
2[B, C]{A}A
3[C, D]{A, B}B
4[D]{A, B, C}C
5[E]{A, B, C, D}D
6[]{A, B, C, D, E}E ✓

The cycle B→D→E→B is handled by the explored set — E would add B again but B is already explored, so it is skipped. BFS finds shortest path: A→C→D→E (3 steps).
