TCP RTT Estimation & Timeout

Computer Networking — Comprehensive Guide for 20/20 Exam

Round-Trip Time (RTT) Estimation

TCP uses a timeout/retransmit mechanism to recover from lost segments. The timeout interval must be larger than the connection's RTT, but estimating RTT is challenging due to network congestion variability.

SampleRTT

SampleRTT
SampleRTT = time from segment sent → ACK received
Measured for only ONE unacknowledged segment at a time (once per RTT). Never computed for retransmitted segments.

One Sample at a Time

At any point, only one segment is being timed. A new SampleRTT is obtained approximately once every RTT.

No Retransmitted Samples

TCP never computes SampleRTT for retransmitted segments (Karn's algorithm) — ambiguous whether ACK is for original or retransmission.

EstimatedRTT (Exponential Weighted Moving Average)

EstimatedRTT Formula (EWMA)
EstimatedRTT = (1 - α) × EstimatedRTT + α × SampleRTT
α = 0.125 (1/8). Recent samples get more weight; old samples decay exponentially.
// Pseudocode for EstimatedRTT update // α = 0.125 EstimatedRTT = 0.875 * EstimatedRTT + 0.125 * SampleRTT;

The EWMA smooths out short-term fluctuations. A small α makes the estimate less sensitive to transient spikes.

Timeout Calculation

DevRTT — RTT Variation

DevRTT Formula
DevRTT = (1 - β) × DevRTT + β × |SampleRTT - EstimatedRTT|
β = 0.25. Measure of how much SampleRTT deviates from EstimatedRTT.

Low Fluctuation

If SampleRTT is consistently close to EstimatedRTT, DevRTT is small.

High Fluctuation

If SampleRTT varies widely, DevRTT is large, requiring a larger safety margin.

TimeoutInterval

TimeoutInterval Formula
TimeoutInterval = EstimatedRTT + 4 × DevRTT
Adds 4 standard deviations of deviation as a safety margin.

Timeout Management Rules

RuleValueRationale
Initial TimeoutInterval1 secondConservative start before any RTT samples
After timeout (exponential backoff)Timeout × 2Avoid retransmission storm during congestion
After new ACK arrivesRecompute from EstimatedRTT + 4×DevRTTReset to current network conditions
⚠ Common Mistake: Doubling the TimeoutInterval on timeout is separate from the formula above. The exponential backoff is triggered by the timeout event, not by normal ACK processing.

Algorithm Pseudocode

// When a new SampleRTT is obtained: EstimatedRTT = 0.875 * EstimatedRTT + 0.125 * SampleRTT; DevRTT = 0.75 * DevRTT + 0.25 * |SampleRTT - EstimatedRTT|; TimeoutInterval = EstimatedRTT + 4 * DevRTT; // When a timeout occurs: TimeoutInterval = TimeoutInterval * 2; // (retransmit oldest unacknowledged segment, restart timer) // On receiving ACK (non-duplicate): // Recompute TimeoutInterval from latest EstimatedRTT and DevRTT

Worked Examples

Example 1: Initial RTT Estimation Sequence

Given: Initial EstimatedRTT = 100 ms, DevRTT = 10 ms.

SampleRTT values: 120 ms, 90 ms, 110 ms, 130 ms.

Step 1 — SampleRTT = 120 ms:

EstimatedRTT = 0.875 × 100 + 0.125 × 120 = 87.5 + 15 = 102.5 ms

DevRTT = 0.75 × 10 + 0.25 × |120 - 102.5| = 7.5 + 4.375 = 11.875 ms

Timeout = 102.5 + 4 × 11.875 = 102.5 + 47.5 = 150 ms

Step 2 — SampleRTT = 90 ms:

EstimatedRTT = 0.875 × 102.5 + 0.125 × 90 = 89.6875 + 11.25 = 100.9375 ms

DevRTT = 0.75 × 11.875 + 0.25 × |90 - 100.9375| = 8.90625 + 2.734 = 11.64 ms

Timeout = 100.9375 + 4 × 11.64 = 100.9375 + 46.56 = 147.5 ms

Step 3 — SampleRTT = 110 ms:

EstimatedRTT = 0.875 × 100.9375 + 0.125 × 110 = 88.32 + 13.75 = 102.07 ms

DevRTT = 0.75 × 11.64 + 0.25 × |110 - 102.07| = 8.73 + 1.98 = 10.71 ms

Timeout = 102.07 + 4 × 10.71 = 102.07 + 42.84 = 144.91 ms

Step 4 — SampleRTT = 130 ms:

EstimatedRTT = 0.875 × 102.07 + 0.125 × 130 = 89.31 + 16.25 = 105.56 ms

DevRTT = 0.75 × 10.71 + 0.25 × |130 - 105.56| = 8.03 + 6.11 = 14.14 ms

Timeout = 105.56 + 4 × 14.14 = 105.56 + 56.56 = 162.12 ms

Observe how the timeout adapts: when RTT increases, DevRTT grows, making the timeout margin larger.

Example 2: Exponential Backoff on Timeout

Given: EstimatedRTT = 80 ms, DevRTT = 5 ms.

TimeoutInterval = 80 + 4 × 5 = 100 ms

Timeout occurs: No ACK received within 100 ms.

TCP retransmits and sets: TimeoutInterval = 100 × 2 = 200 ms

Second timeout occurs: 200 ms later, still no ACK.

TimeoutInterval = 200 × 2 = 400 ms

Third timeout: TimeoutInterval = 400 × 2 = 800 ms

Finally ACK arrives: TimeoutInterval is recomputed from latest EstimatedRTT and DevRTT (resets to formula-based value).

Backoff prevents network from being flooded with retransmissions during congestion.

Example 3: Impact of a Spike in RTT

Given: EstimatedRTT = 50 ms, DevRTT = 8 ms, Timeout = 50 + 32 = 82 ms.

Network becomes congested: SampleRTT jumps to 200 ms.

New EstimatedRTT = 0.875 × 50 + 0.125 × 200 = 43.75 + 25 = 68.75 ms

New DevRTT = 0.75 × 8 + 0.25 × |200 - 68.75| = 6 + 32.81 = 38.81 ms

New Timeout = 68.75 + 4 × 38.81 = 68.75 + 155.24 = 224 ms

The timeout increases dramatically to accommodate the new variability. Without DevRTT, the timeout would only be ~68.75 + small margin, causing premature timeouts.

DevRTT prevents unnecessary retransmissions when RTT suddenly increases.
