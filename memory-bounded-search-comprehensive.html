Memory-Bounded Search (IDA*, RBFS, SMA*) - Comprehensive

Informed Search Algorithms — Chapter 3

Overview

Iterative Deepening A* (IDA*) reduces the memory footprint of A* by using depth-first search with an increasing cost threshold. It never stores more than a single path, so memory use is linear in path length. It is particularly useful when the search tree is very large and memory is limited.

Common Mistake: IDA* explores nodes in best-first order only within a threshold. Do not confuse it with full A*, which uses a priority queue and can revisit states.

Core Concept: f-Limit Contour

IDA* performs a series of depth-first searches. In each iteration, a threshold C limits the maximum f-value allowed along the current path. Only paths whose f-cost exceeds the threshold generate successors; otherwise they are pruned.

Evaluation function:
f(n) = g(n) + h(n)
g(n) = path cost from root to n; h(n) = heuristic estimate from n to goal.
Threshold progression:
C_{i+1} = min { f(n) | n is a cutoff node in iteration i }
The next threshold is the minimum f-value among pruned frontier nodes.

Each contour is the set of nodes whose f-value equals or exceeds the current threshold. IDA* expands all nodes with f-value below or equal to the threshold before raising it.

Common Mistake: If heuristics are inconsistent, IDA* may re-expand states. Use consistent or monotonic heuristics to avoid duplicates, or add a visited set.

Pseudocode

function IDA*(root): threshold = h(root) while true: result, next_threshold = DFS(root, 0, threshold) if result == FOUND: return solution if next_threshold == INF: return FAILURE threshold = next_threshold function DFS(node, g, threshold): f = g + h(node) if f > threshold: return FAILURE, f if node is goal: return FOUND, null min_next = INF for each child of node: stat, child_threshold = DFS(child, g + cost(node, child), threshold) if stat == FOUND: return FOUND, null min_next = min(min_next, child_threshold) return FAILURE, min_next

Worked Examples

Example 1: Simple 3-Node Expansion Tree

Consider four states: Start (S), A, B, and Goal (G). Edge costs: S→A = 1, S→B = 2, A→G = 2, B→G = 10. Heuristics: h(S)=4, h(A)=2, h(B)=6, h(G)=0.

Iteration 1, threshold 4:

  • Expand S: f(S) = 0+4 = 4 → within threshold. Expand children.
  • A: f(A) = 1+2 = 3 → within threshold. Not goal, continue.
  • From A, G: f(G) = 1+2+0 = 3 → not goal? Actually g(G)=3, h(G)=0, so f(G)=3 < 4. Goal reached within threshold.

Result: Solution path S→A→G with cost 3. Only nodes on the solution path are opened.

Example 2: Multiple Contours in Same Iteration

Same graph but with h(A)=7, h(B)=1. Then f(A)=8, f(B)=3. Threshold starts at h(S)=4.

Iteration 1, threshold 4:

  • Expand S. Child A has f=8 > 4, so A becomes a cutoff with candidate next threshold 8.
  • Child B has f=3 ≤ 4. Expand B. B→G gives g=2+10=12, h=0 → f=12 > 4, cutoff for next threshold 8.

Iteration 2, threshold 8:

  • Expand S. A has f=8 ≤ threshold, so expand A→G. f(G)=1+2+0=3 ≤ 8. Goal.

Result: Two iterations; the first prunes A and B→G, raising threshold to 8.

Example 3: Pathological Case with Repeated States in DFS Tree

Tree: S has child A; A has child S again. h(S)=2. g(S→A)=1, g(A→S)=1, costs remain consistent.

Threshold=2. Expand S, A: f(A)=1+0=1? Wait if h(A)=0 and A not goal assume h(A)=1, then f=2. Expand S→A→S'. f(S')=1+1+2=4 > threshold, cutoff 4. Next threshold 4, expand A→S', S'→A'... loops unless we track path.

Result: Without a visited-set along the current path, cycles can occur. IDA* with a path-based duplicate check handles this safely.

Example 4: Cost Progression Over Several Iterations

Linear chain: n0 (start) → n1 → n2 → n3 (goal). Costs: 2 per edge. Heuristics: h(n0)=6, h(n1)=4, h(n2)=2, h(n3)=0.

Threshold = 6. f(n0)=0+6=6. Expand n1: f(n1)=2+4=6. Expand n2: f(n2)=4+2=6. Expand n3: f(n3)=6+0=6. Goal.

Result: Every layer f-cost equals 6; algorithm finds goal in a single iteration without changing thresholds.

Example 5: Many Cutoff Nodes and Threshold Selection

Branching factor 3, depth 3. g-values: 0,1,2,3. h-values: 7,5,3,0 respectively on every child. Threshold starts at h(root)=7.

At depth 1, children have f=8; 8 > threshold, so min cutoff = 8. At depth 2, deeper nodes have f higher. Next threshold 8 expands those depth-1 nodes. Their children inside the threshold lead to goal at depth 3.

Result: Demonstrates why next_threshold picks the minimum discarded f-cost across all pruned frontier nodes.

Key Properties

Time

Worst case is exponential: O(b^d) in depth d with branching factor b, similar to depth-first A*.

Space

O(d) because it maintains only a single path plus siblings on the current stack.

Optimality

Optimal when h(n) is admissible (never overestimates true cost to goal).

Completeness

Complete on infinite trees when every step has a positive minimum cost and h is admissible.

Overview

Recursive Best-First Search (RBFS) explores the search tree recursively while remembering only the best alternative path available at each level. It uses linear space and still behaves like best-first search by always pursuing the node with the smallest f-value.

Core Idea: Best-Node Tracking with Backtracking

RBFS operates on the current path and, for each node, keeps an f-limit representing the best alternative path not yet expanded. If the current child's f exceeds that alternative, RBFS backs up and switches to the better alternative. It therefore performs implicit reevaluation of previously generated siblings.

RBFS update rule:
f(n) = min{ f(n), min_{child∈children(n)} f(child) }
The stored f-value of n is recursively replaced if a descendant offers a cheaper continuation.

Because RBFS only stores nodes along the current path and one alternative per level, its memory consumption is linear in depth d.

Common Mistake: Do not permanently discard regenerated successors. RBFS may revisit subtrees under different f-limits; that is expected and keeps behavior best-first.

Pseudocode

function RBFS(node, f_limit): if node is goal: return SOLUTION, f(node) if node has no children: return FAILURE, f(node) for each child in node.children: child.f = max(g(child) + h(child), node.f) while true: best = child with smallest f alternative = child with second smallest f if best.f > f_limit: return FAILURE, best.f result, best.f = RBFS(best, min(f_limit, alternative.f)) if result != FAILURE: return result, best.f return FAILURE, best.f

Worked Examples

Example 1: Two-Way Branch with Single Backtrack

Root R has children A and B. g(A)=1, h(A)=4 => f(A)=5. g(B)=2, h(B)=1 => f(B)=3. Start with f_limit = ∞.

best = B (f=3), alternative = A (f=5). Recurse on B. At B the goal is found. RBFS returns success upward. No explicit storing of A required beyond f-value.

Result: Memory only kept one path and one alternative f-value; no priority queue needed.

Example 2: Forced Backtrack When Cheaper Path Found Deeper

Root R with child X. X gives g=1, h=5, f=6. X also has sibling Y under same parent? Reconstruct: R has two children X and Y. Suppose X leads left deeper, Y is local best f=4.

Expanding X: X generates child Z with g=2, h=6, f=8. Compare alternative Y (f=4) vs Z (f=8). Since 8 > current f_limit (initially ∞ or lower bound 6), backtrack and pursue Y.

Result: RBFS discards deeper but more expensive branch automatically.

Example 3: Memory Profile Over Depth

Test depth 5, branching factor 2. At any time RBFS stores the path plus at most 1 sibling f-value per depth, totaling ≤ 2d nodes.

Suppose we go down left spine to depth 5. Each activation stores the right sibling info only at decision points. At depth 5, call stack depth = 6 and sibling info ≤ 6.

Result: Confirms linear space: O(d).

Example 4: Repeated State Without Caching

Tree contains cycle root→A→root. RBFS from root goes to A, then A sees child root again.

Without duplicate detection, RBFS may rebuild from root again. Because it uses recursion, cycles inflate runtime but still eventually prune by f-limits if goal unreachable.

Result: RBFS benefits from adding a closed list when states can repeat; otherwise pure RBFS may loop.

Example 5: Simulating Continuous f-Limit at Parent

For node n with children f-values 9, 10, 14, parent current f=8. best child f updates to max(g+ h, parent.f). Let child f be 9. Path goes down to child. sibling alternative returns 10. min(current f_limit=∞, alternative.f) keeps exploring 9. Child returns failure 17. Next iteration picks alternative child 10.

Result: Parent automatically updates the next candidate using 10 instead of revisiting unavailable child.

Key Properties

Time

Worst-case exponential: O(b^d), but often behaves better than iterative deepening by reordering near-best-first.

Space

O(d) because only a single path plus recursive stack is stored.

Optimality

Optimal if heuristic h is admissible.

Completeness

Complete under same conditions as A*: positive step costs and finite branching.

Overview

Simplified Memory-bounded A* (SMA*) is a general-purpose bounded-memory search that expands the most promising leaf nodes first, but when memory is exhausted it forgets the worst leaf and backtracks to continue from the best remembered sibling.

Key Concepts

SMA* keeps a priority queue of frontier nodes and increments path cost information upwards. Once memory is full, the least promising leaf node is removed. Its parent may then resume expansion from another child if available.

Key heuristic for forgetting:
worst(n) = f-value of worst leaf in subtree rooted at n
SMA* stores this at every internal node while children are loaded.
Leaf choice rule:
choose leaf n with minimal f(n); prune worst leaf when memory bound exceeded
removing that leaf updates parent's remembered best continuation.

How SMA* Selects Which Node to Forget

When the memory limit is exceeded, SMA* evaluates all current leaf nodes and removes the one with highest f-value. If multiple leaves share that value, it removes the one whose subtree contains the most expensive forgotten continuation, because that removal loses the least globally useful information. The parent node instead remembers the cost of the forgotten subtree so that resumption is possible.

If the currently expanding node is itself removed, SMA* backtracks to its parent and continues with the next-best child.

Common Mistake: SMA* does not discard arbitrary nodes; always forgets the *worst* leaf first. If you forget a better leaf, you lose optimality.

Pseudocode

function SMA*(memory): open = PriorityQueue() insert root into open while open not empty: node = pop(open) # lowest f-node if node is goal: return solution if node is leaf with untried actions: for each child generated: child.f = max(g(child) + h(child), node.f) insert child into open update node.remembered_f = max( node.remembered_f, min(child.f) ) else: # expand remembered best continuation regenerate best available child of node if open is full: worst = leaf with highest f remove worst from open update worst.parent.remembered_f from next-best child return NO_PATH_FOUND

Worked Examples

Example 1: Memory Bound Exceeded at Leaf Level

Memory allows only 3 stored nodes. Tree: Root→A (f=4), Root→B (f=6), B→C (f=7). Insert root, then A and B (open size 3). While expanding B, generate C. Open size 4 > 3, so prune highest-f leaf C (f=7).

Result: B remains, but its remembered continuation updates to reflect that C was pruned. If future exploration requires B, it resumes from the cached f-value of 7 or alternative.

Example 2: Backtracking After Forgetting Best Leaf

Left subtree has inexpensive goal at f=5; right subtree has nodes f=8,9,12. Memory allows 2 nodes. Open starts with root + left child. Expanding left pushes its parent to reopen right child at f=8. Memory is tight and requires removal of some leaf.

Result: SMA* sacrifices right-side leaves at f=12, then backtracks to evaluate cheaper siblings, still arriving optimally because no cheaper path existed.

Example 3: Interaction Between Remembered f-values and Pruning

Parent P has children C1 (f=6) and C2 (f=9). P stores worst leaf value = 9 from C2. Memory fills. Because C2 is more expensive, when pruning begins, SMA* removes subtrees containing C2's leaves before removing C1's. This means search directions tied to lower cost survive longer.

Result: Remembered worst-leaf values enforce search direction biased toward low-cost frontiers.

Example 4: Pathological Memory Exhaustion with Goal on Forbidden Side

Goal lies behind a problematic high-cost branch; low-cost subtree is long but memory-limited. SMA* remembers the better f continuation at every memory-limit hit, saving the path cost at pruned nodes. Once memory becomes available again, it can restore the best-forgotten branch and proceed.

Result: Shows SMA* can degrade gracefully by suspending the expensive subtree and resuming it later.

Example 5: Optimal Efficiency Under Memory Constraints

Given depth 8, branching 4, memory = 20 nodes. A* with full queue cannot run. SMA* expands all nodes with f-cost less than or equal to the optimal solution path, plus at most one additional node per layer. This is the best possible given limited memory because every other node must be deferred.

Result: Because SMA* never discards a node with f less than a kept node, it is optimal among memory-limited strategies.

Key Properties

Time

Worst case exponential like IDA* and RBFS: O(b^d). In some problems, time is comparable to A*.

Space

Bounded by user-specified limit O(k), where k is memory.

Optimality

Optimal if heuristic is admissible; it never expends more time than any other bounded-memory algorithm.

Completeness

Complete when a solution exists, memory ≥ 1 and step costs > 0.

Space vs Time Tradeoffs

A* stores the entire frontier, giving the fewest node reexpansions but the largest memory usage. IDA*, RBFS, and SMA* trade memory for extra work. IDA* is simplest and cheapest to implement, but may rebuild nodes many times. RBFS improves upon IDA* by keeping one alternative per level, reducing redundant regeneration. SMA* explicitly manages the frontier with user-defined memory, making it the only algorithm here with a hard guarantee to succeed in bounded hardware.

IDA* Pros

  • Minimal memory
  • Simple implementation
  • No priority queue

IDA* Cons

  • Reexpansions every iteration
  • Weakness without good heuristics

RBFS Pros

  • Best-first like A*
  • Linear memory
  • Fewer duplicates than IDA*

RBFS Cons

  • Recursion overhead
  • Struggles with noise in h

SMA* Pros

  • Hard memory bound
  • Optimal under memory limits
  • Resumes forgotten nodes

SMA* Cons

  • Complex bookkeeping
  • Higher constant factor

Optimal Efficiency Under Memory Constraints

Optimal efficiency means no memory-bounded algorithm expands fewer nodes than SMA* for a given memory bound. SMA* ensures this because every node it discards has f-value worse than every kept node. Any algorithm that discards a node with lower f-value would therefore be strictly inferior on at least one instance.

Optimal efficiency guarantee:
For any memory-bound algorithm B, number of nodes expanded by SMA* ≤ nodes expanded by B
Assuming both use the same admissible heuristic and face the same problem instance and memory limit.

Completeness Conditions Summary

  • Branching factor must be finite.
  • Minimum step cost > 0.
  • Heuristic admissible (never overestimates actual cost to goal).
  • For IDA*, tree must be infinite-depth safe when step costs positive; duplicity can be addressed by remembering a path set or relying on monotonic heuristics.
  • For SMA*, memory bound must be at least 1 node.
Common Exam Pitfall: Optimism does not guarantee finite completion. Even with perfect heuristic, infinite graphs require infinite or at least sufficient time; positive costs ensure progress toward goal depth.

Important Pseudocode Quick Reference

IDA*: threshold = h(start) repeat threshold += next_min until goal found RBFS: recurse best child; track alternative; back up best f on return SMA*: queue lowest-f frontier nodes; if full, free worst leaf and propagate cost upward

What to Remember for Exams

  • IDA* uses threshold iterations based on f = g + h.
  • RBFS is recursive, best-first, and linear in memory.
  • SMA* is the optimal algorithm under an explicit memory bound through forgetting worst leaves.
  • Optimality across all three requires an admissible heuristic.
  • Completeness needs finite branching and positive step cost.
  • Space is the defining difference: IDA*/RBFS use O(d), SMA* is user-limited.
  • Time remains exponential in the worst case for all three algorithms.
