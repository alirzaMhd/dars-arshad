Backward Chaining

Artificial Intelligence — Logical Agents Chapter

Goal-Directed Reasoning

Backward chaining is a goal-directed inference algorithm for Horn clauses. Instead of starting from known facts and deriving new conclusions (like forward chaining), it starts from the query and works backward to find supporting facts.

Core Idea
KB ⊨ q ?
To determine if query q is entailed by the knowledge base, start with q and work backward through implications until reaching known facts.

How Backward Chaining Works

Step 1
Start with query q

The algorithm begins with the goal we want to prove.

Step 2
Find rules with head = q

Search KB for Horn clauses whose conclusion is q.

Step 3
Prove all premises

For each such clause, recursively try to prove all premises.

Step 4
Reach facts

If all premises are facts in KB, query is proved true.

Example 1: Simple Chain
KB: A ∧ B ⇒ L
A ∧ P ⇒ L
L ∧ M ⇒ P
P ⇒ Q
A, B (facts)

Query: Q?

Trace:
1. To prove Q, need P (from P ⇒ Q)
2. To prove P, need L and M (from L ∧ M ⇒ P)
3. To prove L, need A and B (from A ∧ B ⇒ L)
4. A and B are facts → L proved
5. Need M... (no rule gives M from known facts)
6. Try alternative: To prove P, need A and P (circular - dead end)
7. Backtrack, try other paths...

In this example, the algorithm explores the AND-OR graph backward from Q.

Backward Chaining Algorithm

function PL-BC-ASK(KB, q) returns a substitution or false
inputs: KB, the knowledge base (set of definite clauses)
q, the query (a proposition symbol)

return BC-AND-OR-SEARCH(KB, q, {})

function BC-AND-OR-SEARCH(KB, goal, θ) returns a substitution or false
if θ = failure then return failure
if goal is a fact in KB then return θ
for each rule (P₁ ∧ ... ∧ Pₖ ⇒ goal) in KB do
θ' ← BC-AND-OR-SEARCH(KB, P₁, θ)
for j = 2 to k do
θ' ← BC-AND-OR-SEARCH(KB, Pⱼ, θ')
return θ'
return false
Important: Backward chaining can encounter infinite loops if there are circular dependencies in the knowledge base. The algorithm must track visited goals to avoid re-proving the same goal repeatedly.

AND-OR Graph Representation

Backward chaining traverses an AND-OR graph, where:

AND Branches
Conjunction of premises

All premises must be proved (connected by arc in graph). Represents rules like A ∧ B ⇒ C.

OR Branches
Multiple rules for same conclusion

Any one rule suffices (no arc between edges). Multiple ways to prove the same goal.

Leaves
Known facts

Terminal nodes that are already known to be true in the KB.

Example 2: AND-OR Graph Traversal
Knowledge Base:
R₁: A (fact)
R₂: B (fact)
R₃: A ∧ B ⇒ L
R₄: A ∧ P ⇒ L
R₅: L ∧ M ⇒ P
R₆: P ⇒ Q

AND-OR Graph for proving Q:

Q
|
[P] ← R₆ (need P)
/ \
AND OR
/ \ \
L M (A ∧ P ⇒ L)
/ \ / \
A B A P (circular!)
| |
facts

Result: Q is provable via path Q ← P ← L ← A ∧ B

Worked Examples

Example 3: Wumpus World Query
KB (relevant rules):
¬P₁,₁ (no pit at [1,1])
B₁,₁ ⇔ (P₁,₂ ∨ P₂,₁) (breeze iff adjacent pit)
¬B₁,₁ (no breeze at [1,1])

Query: ¬P₁,₂ (no pit at [1,2])?

Backward chaining trace:
1. To prove ¬P₁,₂, look for rules with P₁,₂ in head
2. From B₁,₁ ⇔ (P₁,₂ ∨ P₂,₁):
- If B₁,₁ is false, then (P₁,₂ ∨ P₂,₁) must be false
- So P₁,₂ is false AND P₂,₁ is false
3. We know ¬B₁,₁ (fact)
4. Therefore ¬P₁,₂ and ¬P₂,₁ are proved

Result: KB ⊨ ¬P₁,₂ ✓
Example 4: Multiple Rule Paths
KB:
R₁: Cold ⇒ Jacket
R₂: Rain ⇒ Jacket
R₃: Snow ⇒ Cold
R₄: Snow (fact)

Query: Jacket?

Two possible paths (OR branches):

Path 1: Jacket ← Cold ← Snow ← fact ✓
Path 2: Jacket ← Rain ← ? (no fact for Rain)

Backward chaining finds Path 1:
1. To prove Jacket, try R₁: need Cold
2. To prove Cold, try R₃: need Snow
3. Snow is a fact → Cold proved → Jacket proved

Result: KB ⊨ Jacket ✓
Example 5: Failed Proof
KB:
R₁: A ⇒ B
R₂: C ⇒ D
A (fact)

Query: D?

Backward chaining trace:
1. To prove D, look for rules with D in head
2. Found R₂: C ⇒ D, need C
3. To prove C, look for rules with C in head
4. No rules found, C is not a fact
5. No other rules can prove D

Result: KB ⊭ D (cannot prove)

Forward vs Backward Chaining

Feature Forward Chaining Backward Chaining
Direction Data-driven (facts → conclusions) Goal-directed (query → supporting facts)
Start Point Known facts in KB Query/goal to prove
Traversal Bottom-up through implications Top-down through implications
When to Use Many facts, few queries Few facts, many queries
Completeness Complete for Horn clauses Complete for Horn clauses
Time Complexity O(n) - linear O(n) - linear
Irrelevant Facts May derive irrelevant conclusions Only touches relevant facts
Best For Deriving all possible conclusions Answering specific questions
Time Complexity
O(n) for Horn clauses
Both forward and backward chaining run in linear time relative to the size of the knowledge base when dealing with Horn clauses.

When to Use Each Approach

Forward Chaining
Best when:

• Agent receives continuous percepts
• Need to derive all possible conclusions
• Want to precompute everything
• Examples: sensor data processing, monitoring systems

Backward Chaining
Best when:

• Agent needs to answer specific questions
• Many possible queries, few facts
• Want to avoid irrelevant inferences
• Examples: diagnostic systems, question answering

Hybrid Approach
Combine both:

• Use forward chaining for initial inference
• Use backward chaining for specific queries
• Share work between both directions
• Most practical systems use this

Warning: Backward chaining is NOT complete for non-Horn clauses. If the knowledge base contains clauses with disjunctions in the head (non-Horn), backward chaining may fail to find valid proofs. For general propositional logic, use DPLL or other complete algorithms.
Example 6: Practical Comparison
Scenario: Medical Diagnosis System

Forward Chaining Approach:
- Input: Patient symptoms (facts)
- Derive: All possible conditions
- Result: Complete list of potential diagnoses
- Pro: Doesn't miss anything
- Con: May derive irrelevant conditions

Backward Chaining Approach:
- Input: Specific disease to check
- Find: Supporting symptoms and test results
- Result: Whether evidence supports diagnosis
- Pro: Focused, efficient
- Con: May miss unexpected conditions

Best Practice: Use forward chaining for initial screening, backward chaining for specific inquiries.

Quick Reference Cards

Algorithm
PL-BC-ASK

1. Start with query q
2. Find rules with head = q
3. Prove all premises
4. Recurse until facts reached

Properties
Sound & Complete

• Sound: Only derives true statements
• Complete: Derives all entailed atoms
• Linear time for Horn clauses
• Basis for logic programming (Prolog)

Limitations
Watch Out For

• Infinite loops (circular rules)
• Non-Horn clauses (incomplete)
• Redundant computations
• Need memoization for efficiency
