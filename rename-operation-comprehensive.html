RENAME OPERATION

Database Systems — Relational Algebra Complete Guide

1. Definition

The Rename operation (denoted by ρ, Greek letter rho) is a unary operation in relational algebra that changes the name of a relation, its attributes, or both. It is essential for resolving naming conflicts and enabling self-joins.

The rename operation can be used in three ways:

  • Rename the relation: ρr(R) — renames relation R to r
  • Rename attributes: ρ(a₁, a₂, ...)(R) — renames attributes of R
  • Both: ρr(a₁, a₂, ...)(R) — renames both relation and attributes
Important: The Rename operation does NOT change the data — it only changes the names. The result has the same tuples as the original relation.

2. Why Rename is Needed

Rename is crucial in several scenarios:

Scenario 1: Self-Join

When joining a relation with itself, you need different names to distinguish the two instances:

ρSX(S) — creates a copy of S named SX

This allows: S ⋈S.City = SX.City SX

Scenario 2: Attribute Name Conflicts

When two relations have same-named attributes that aren't join attributes:

ρ(a, b)(R) — renames attributes to avoid conflicts
Scenario 3: Readability

Making query results more readable by using meaningful attribute names:

ρResult(StudentID, StudentName)(σcity='NYC'(S))

Core Formulas

Basic Rename (Relation):
ρr(R)
Renames relation R to r; schema and data remain unchanged
Rename Attributes:
ρ(a₁, a₂, ..., aₙ)(R)
Renames attributes of R to a₁, a₂, ..., aₙ (in order)
Rename Both:
ρr(a₁, a₂, ..., aₙ)(R)
Renames relation R to r AND renames its attributes
Assignment Operation:
r ← E
Assigns the result of expression E to temporary relation r (GIVING keyword in some notations)

Properties

Idempotency:
ρr(ρr(R)) = ρr(R)
Renaming to the same name is idempotent
Degree Preservation:
deg(ρr(R)) = deg(R)
Rename does not change the number of attributes
Cardinality Preservation:
card(ρr(R)) = card(R)
Rename does not change the number of tuples

Worked Examples

Example 1: Rename Relation

Given: Relation S (Suppliers)

S#SnameCity
S1Sn1C1
S2Sn2C2
S3Sn3C2

Operation: ρSX(S)

Result:

S#SnameCity
S1Sn1C1
S2Sn2C2
S3Sn3C2

Same data, but now the relation is named SX instead of S

Example 2: Rename Attributes

Given: Relation S (Suppliers)

Operation: ρ(ID, Name, Location)(S)

Result:

IDNameLocation
S1Sn1C1
S2Sn2C2
S3Sn3C2

Attributes renamed from (S#, Sname, City) to (ID, Name, Location)

Example 3: Self-Join with Rename

Find: Suppliers in the same city

Step 1: Create a renamed copy

SX ← ρSX(S)

Step 2: Join with condition

σS.City = SX.City AND S.S# ≠ SX.S#(S × SX)

Result: Pairs of different suppliers in the same city

Example 4: Rename in Complex Query

Find: Names of suppliers who supply part P1

ρTemp(S#, P#)(σP# = 'P1'(SP))
⋈ ρ(S#, Sname, City)(S)
→ Project on Sname

Rename helps clarify the intermediate results

Example 5: Rename with Assignment

Query: Find all parts supplied by supplier S1

S1_Parts ← ρP#(σS# = 'S1'(SP))
Result ← S1_Parts ⋈ P

Assignment creates temporary relations for step-by-step evaluation

Applications of Rename

1. Self-Joins

The most common use case — joining a relation with itself requires renaming to distinguish the two instances.

Find pairs of suppliers in the same city
SX ← ρSX(S)
Result ← σS.City = SX.City AND S.S# ≠ SX.S#(S × SX)
→ πS.S#, SX.S#(Result)

2. Recursive Queries

Find employees who work for the same manager:

Find coworkers (same manager)
E2 ← ρE2(ID, Name, Mgr)(E)
Result ← σE.Mgr = E2.Mgr AND E.ID ≠ E2.ID(E × E2)

3. Attribute Disambiguation

When joining relations with same-named non-join attributes:

Join S and SP when both have S#
ρ(s_no, sname, city)(S) ⋈s_no = S# SP

4. Creating Temporary Views

Breaking complex queries into named steps:

Step-by-step query
Active_Suppliers ← ρActive(πS#(SP))
Supplier_Info ← Active_Suppliers ⋈ S
Result ← πSname, City(Supplier_Info)

Common Mistakes to Avoid:
  • Forgetting to rename when doing self-joins
  • Renaming attributes in wrong order
  • Confusing rename with projection (π removes columns, ρ just renames)
  • Not using rename when attribute names conflict in joins

Time Complexity:

Time Complexity:
O(card(R))
Must visit each tuple once to rename (or just rename metadata in practice)
Space Complexity:
O(card(R))
Result has same size as input

SQL Equivalent:

-- Rename relation
SELECT * FROM S AS SX

-- Rename attributes
SELECT S# AS ID, Sname AS Name, City AS Location FROM S

-- Table alias (self-join)
SELECT S.City FROM S, S AS SX WHERE S.City = SX.City
