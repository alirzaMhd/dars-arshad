Inference Rules in Propositional Logic

Artificial Intelligence — Logical Agents

What Are Inference Rules?

Inference rules are patterns that produce new sentences (conclusions) from existing sentences (premises). A proof is a sequence of sentences where each sentence is either a premise (from KB) or derived by applying an inference rule to earlier sentences.

Inference Rule Schema
Premises ⊢ Conclusion
If you have the premises (left side), you may derive the conclusion (right side). The symbol ⊢ means "derives" or "proves."

Soundness of Inference Rules

An inference rule is sound if its conclusion is logically entailed by its premises. All inference rules listed here are sound for propositional logic. A proof using only sound rules guarantees that the conclusion is entailed by the premises.

Soundness
If premises are true, conclusion must be true
Completeness
Every entailment can be proven
Proof = Search
Finding proofs is a search problem

Propositional logic with a complete set of inference rules (e.g., resolution) is both sound and complete. However, not all inference rules work in both directions — for example, from P ⇒ Q you cannot derive P (affirming the consequent is invalid).

Core Inference Rules

Modus Ponens (MP)
α ⇒ β, α ⊢ β
If implication holds and antecedent is true, conclude consequent.
Modus Tollens (MT)
α ⇒ β, ¬β ⊢ ¬α
If implication holds but consequent is false, antecedent must be false too.
And-Elimination (AE)
α ∧ β ⊢ α
α ∧ β ⊢ β
From a conjunction, derive either conjunct separately.
And-Introduction (AI)
α, β ⊢ α ∧ β
From two sentences, derive their conjunction.
Or-Introduction (OI)
α ⊢ α ∨ β
β ⊢ α ∨ β
From a sentence, derive any disjunction that includes it.
Unit Resolution (UR)
l₁ ∨ l₂ ∨ ... ∨ lₖ, m ⊢ l₁ ∨ ... ∨ lᵢ₋₁ ∨ lᵢ₊₁ ∨ ... ∨ lₖ
where m is the negation of lᵢ. Remove the complementary pair.

Modus Ponens vs. Affirming the Consequent

Correct (Modus Ponens): If it rains, the ground gets wet. It rains. ∴ The ground gets wet. ✓

Fallacy (Affirming Consequent): If it rains, the ground gets wet. The ground is wet. ∴ It rained. ✗ (Sprinklers could cause it)

Using Equivalences: Convert to CNF

Convert (P ⇒ Q) ⇒ R to CNF:

(P ⇒ Q) ⇒ R ≡ ¬(P ⇒ Q) ∨ R (Imp elimination) ≡ ¬(¬P ∨ Q) ∨ R (Imp elimination again) ≡ (¬¬P ∧ ¬Q) ∨ R (De Morgan) ≡ (P ∧ ¬Q) ∨ R (Double negation) ≡ (P ∨ R) ∧ (¬Q ∨ R) (Distributivity) → CNF: (P ∨ R) ∧ (¬Q ∨ R)

Constructing Proofs

A proof is a sequence where each step is justified by an inference rule or equivalence applied to previous steps. Finding a proof is like searching — you can search forward (from premises to conclusion) or backward (from conclusion to premises).

Example 1: Simple Proof

Prove: {P ⇒ Q, Q ⇒ R, P} ⊢ R

StepSentenceJustification
1P ⇒ QPremise
2Q ⇒ RPremise
3PPremise
4QModus Ponens (1, 3)
5RModus Ponens (2, 4)

Proof complete: R is derived.

Example 2: Using Multiple Rules

Prove: {P ∨ Q, ¬P} ⊢ Q

StepSentenceJustification
1P ∨ QPremise
2¬PPremise
3P ∨ Qis equivalent to ¬P ⇒ Q
4¬P ⇒ QImplication Elim (3)
5QModus Ponens (2, 4)

Alternative: Unit resolution of P∨Q and ¬P gives Q directly (disjunctive syllogism).

Example 3: Proof Using Contraposition

Prove: {P ⇒ Q, ¬Q} ⊢ ¬P

StepSentenceJustification
1P ⇒ QPremise
2¬QPremise
3¬Q ⇒ ¬PContraposition (1)
4¬PModus Ponens (2, 3)

This is the Modus Tollens inference rule.

Example 4: Using De Morgan

Prove: {¬(P ∨ Q)} ⊢ ¬P

StepSentenceJustification
1¬(P ∨ Q)Premise
2¬P ∧ ¬QDe Morgan (1)
3¬PAnd-Elimination (2)

¬P derived. Similarly we can derive ¬Q.

Example 5: Chain of Equivalences

Show: P ⇒ (Q ⇒ R) ≡ P ∧ Q ⇒ R

P ⇒ (Q ⇒ R) ≡ ¬P ∨ (Q ⇒ R) Implication elimination ≡ ¬P ∨ (¬Q ∨ R) Implication elimination ≡ (¬P ∨ ¬Q) ∨ R Associativity ≡ ¬(P ∧ Q) ∨ R De Morgan (reverse) ≡ (P ∧ Q) ⇒ R Implication elimination (reverse)

Equivalence proved: they are identical in meaning (exportation law).

Wumpus World Proof: ¬P₁,₂

We prove that the wumpus agent can conclude there is no pit in square [1,2] using the KB rules.

KB Sentences (already established)

  • R₁: ¬P₁,₁ (known)
  • R₂: B₁,₁ ⇔ (P₁,₂ ∨ P₂,₁)
  • R₃: B₁,₂ ⇔ (P₁,₁ ∨ P₂,₂ ∨ P₁,₃)
  • R₄: B₂,₁ ⇔ (P₁,₁ ∨ P₂,₂ ∨ P₃,₁)
  • Observation: ¬B₁,₁ (no breeze at start)

Proof of ¬P₁,₂

StepSentenceJustification
1B₁,₁ ⇔ (P₁,₂ ∨ P₂,₁)R₂ (premise)
2(B₁,₁ ⇒ (P₁,₂ ∨ P₂,₁)) ∧ ((P₁,₂ ∨ P₂,₁) ⇒ B₁,₁)Biconditional Elim (1)
3(P₁,₂ ∨ P₂,₁) ⇒ B₁,₁And-Elimination (2)
4¬B₁,₁Observation
5¬(P₁,₂ ∨ P₂,₁)Modus Tollens (3, 4)
6¬P₁,₂ ∧ ¬P₂,₁De Morgan (5)
7¬P₁,₂And-Elimination (6)

Proof shows KB ⊢ ¬P₁,₂. The agent knows [1,2] is safe.

Can We Prove P₂,₂?

Attempting to prove or disprove P₂,₂ fails:

AttemptRuleResult
From B₁,₂ or ¬B₁,₂?No observation about [1,2]No constraint

P₂,₂ is not entailed! The agent remains uncertain about [2,2].

Forward vs. Backward Search in Proofs

Forward Chaining
Start from premises, apply rules to derive new facts
Good for: data-driven reasoning, monitoring
Backward Chaining
Start from goal, work backward using rules as reduction
Good for: goal-directed reasoning, question-answering

Monotonicity of Logic

Monotonicity Property
if KB ⊧ α then KB ∧ β ⊧ α for any β
Adding new knowledge never retracts old conclusions. Logical entailment only grows (or stays the same) as the KB grows.

Why It Matters

  • Propositional logic: Monotonic ✓ — proved facts remain proved
  • First-order logic: Monotonic ✓ — same property
  • Probabilistic logic: NOT monotonic ✗ — new evidence can change probabilities
  • Default logic: NOT monotonic ✗ — default assumptions can be defeated
Monotonicity Example

KB₁: {If it's raining, the grass is wet. It's raining.}

KB₁ ⊧: The grass is wet.

KB₂ = KB₁ ∪ {The sprinklers are on.}

KB₂ ⊧: The grass is wet. (Still entailed! Monotonicity holds.)

In non-monotonic logic, the conclusion "the grass is wet because it rained" might be retracted when "sprinklers are on" is added because the explanation changes. But the truth of "grass is wet" itself remains entailed in classical logic — only the causal explanation is non-monotonic.

Monotonicity in Wumpus World

After proving ¬P₁,₂ from the initial KB, the agent explores [1,2] and perceives a breeze (new observation: B₁,₂). Adding this to the KB:

KB_new = KB_old ∧ B₁,₂

The previous conclusion ¬P₁,₂ is still entailed (monotonicity). Additionally, the agent can now conclude new facts about P₂,₂ and P₁,₃.

Key Insight: Monotonicity is why inference rules work so well for logical agents. Once a conclusion is proved, it remains valid no matter what new information arrives. This simplifies agent design — no need to retract beliefs.
