Naive String Matching

Algorithm:
for i = 0 to n - m: j = 0 while j < m and T[i+j] == P[j]: j++ if j == m: print("Match found at position", i)

Time Complexity

Best Case

O(n)
When first character doesn't match

⚠ Problem: Naive algorithm wastes comparisons!

When mismatch occurs at position j, we know T[i..i+j-1] matches P[0..j-1]

We can use this information to skip unnecessary comparisons

KMP (Knuth-Morris-Pratt) Algorithm

Key Insight:
Precompute failure function to avoid redundant comparisons
When mismatch occurs, we know exactly where to continue matching
Algorithm
// Precompute failure function function computeFailure(pattern): m = length(pattern) failure = array of size m failure[0] = 0 len = 0 i = 1 while i < m: if pattern[i] == pattern[len]: len++ failure[i] = len i++ else: if len != 0: len = failure[len-1] else: failure[i] = 0 i++ return failure // KMP Search function kmpSearch(text, pattern): n = length(text) m = length(pattern) failure = computeFailure(pattern) i = 0 // text index j = 0 // pattern index while i < n: if text[i] == pattern[j]: i++ j++ if j == m: print("Match at", i - j) j = failure[j-1] elif i < n and text[i] != pattern[j]: if j != 0: j = failure[j-1] else: i++
Example: KMP Search

Text: ABABDABABCABABCABAB

Pattern: ABABCABAB

Failure Function: [0,0,1,2,0,1,2,3,4]

O(n + m)
Linear time! Much better than naive

Space Complexity

O(m)
For storing failure function

Failure Function (Prefix Function)

Definition:
failure[i] = length of longest proper prefix of P[0..i] that is also a suffix
"How much of the pattern can we reuse after a mismatch?"
