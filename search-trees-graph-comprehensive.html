Search Tree Fundamentals

A search tree is a conceptual structure built during the search process. It is distinct from the state space (the underlying graph of all possible states).

Key Distinction:
State Space ≠ Search Tree
The state space has a fixed number of states (e.g., 20 cities in Romania). The search tree can have infinite nodes because the same state can be reached via different paths.
PropertyState SpaceSearch Tree
DefinitionAll possible world statesPaths explored by search
SizeFixed (e.g., 20 Romanian cities)Potentially infinite
Nodes vs StatesEach state is uniqueMultiple nodes can have same state
CyclesPresent in graphEliminated by tracking visited states

Tree Construction

The root of the search tree is the initial state. Expanding a node means applying the successor function to generate all possible next states.

Expansion:
Expand(node) = { child₁, child₂, ..., childₙ } where each child = (action, result_state)
The successor function maps a state → set of (action, state) pairs

Romanian Example

• State space: 20 cities

• Root: Arad

• Expand Arad → Sibiu, Timisoara, Zerind

• Expand Sibiu → Oradea, Fagaras, Rimnicu Vilcea, Arad (back!)

Search tree grows even though the state space is fixed

Key Insight

A node in the search tree is a path to a state, not the state itself. Two different paths can lead to the same state, producing two distinct nodes.

Romania search tree expansion:
Level 0: Arad (root)
Level 1: Sibiu, Timisoara, Zerind
Level 2: from Sibiu → Oradea, Fagaras, Rimnicu Vilcea, Arad
Level 2: from Timisoara → Lugoj, Arad
Level 2: from Zerind → Oradea, Arad
Level 3: from Oradea → ... (note: Oradea appears twice in tree)
Warning: Infinite Paths. Because Arad appears as a child of Sibiu, and Sibiu can be reached from Arad, the search tree can grow forever with cycles (Arad → Sibiu → Arad → Sibiu → ...). Graph search prevents this by tracking visited states.

Node Structure

Every node in the search tree is a data structure containing 5 key fields.

Node Representation:
Node = { State, Parent-Node, Action, Path-Cost, Depth }
These 5 fields define every node in the tree
FieldTypeDescription
StateState objectThe world state this node represents
Parent-NodeNode referencePointer to the node that generated this one
ActionActionThe action taken to reach this node from parent
Path-CostNumberTotal cost from root to this node
DepthIntegerNumber of steps from root (root depth = 0)
Path-Cost Calculation:
Path-Cost[s] = Path-Cost[node] + Step-Cost(node, action, s)
where s is the new state reached by applying action to node.State
Depth Calculation:
Depth[s_node] = Depth[node] + 1
Root has depth 0. Each expansion increments depth by 1.
Node Structure Example — Romania

Node for Fagaras (reached from Sibiu via road E81):

State = Fagaras

Parent-Node = Node{Sibiu}

Action = "Drive Sibiu → Fagaras (E81)"

Path-Cost = 140 + 99 = 239 km (Arad→Sibiu + Sibiu→Fagaras)

Depth = 2

If Fagaras is also reached from Bucharest via a different path, that's a different node with the same state.

Node vs State

State = a configuration of the world

Node = a data structure containing a state plus bookkeeping info (parent, action, cost, depth)

Two nodes can have the same state (reached via different paths)

Why Parent Matters

Parent pointers enable solution extraction: once a goal node is found, follow parent links back to root to reconstruct the action sequence.

Fringe & Queue Operations

The fringe (also called frontier) is the set of leaf nodes — nodes that have been generated but not yet expanded. The fringe is managed as a queue.

Fringe Definition:
Fringe = { nodes that have been generated but not yet expanded }
These are the "frontier" of the search — the boundary between explored and unexplored regions

Queue Operations

OperationDescription
Make-Queue(elements)Create a new queue with initial elements
Empty?(queue)Check if queue has no elements
First(queue)Return the first element without removing it
Remove-First(queue)Remove and return the first element
Insert(element, queue)Add a single element to queue
Insert-All(elements, queue)Add a list of elements to queue
TREE-SEARCH(problem): fringe ← Make-Queue(Make-Node(problem.Initial-State)) loop do if Empty?(fringe) then return failure node ← Remove-First(fringe) if problem.Goal-Test(node.State) then return Solution(node) fringe ← Insert-All(Expand(node, problem), fringe)
EXPAND(node, problem): successors ← empty list for each (action, result) in problem.Successor-Fn(node.State) do s ← new Node s.State ← result s.Parent-Node ← node s.Action ← action s.Path-Cost ← node.Path-Cost + problem.Step-Cost(node.State, action, s.State) s.Depth ← node.Depth + 1 add s to successors return successors

Queue Strategy = Search Algorithm

The order of Insert/Remove-First determines the search strategy:

• Stack (LIFO) = Depth-First Search

• Queue (FIFO) = Breadth-First Search

• Priority Queue = Uniform-Cost / A* Search

Tree-Search vs Graph-Search

Tree-Search: Generates new nodes for every state, even if already visited. May loop forever on cyclic graphs.

Graph-Search: Maintains a "closed set" of visited states. Only adds unseen states to fringe. Guarantees termination on finite state spaces.

Warning: Repeated States. In Tree-Search on the Romanian graph, Arad appears as a child of both Sibiu and Timisoara. Without tracking visited states, the tree grows exponentially with cycles. Graph-Search solves this but uses more memory.

Worked Examples

Example 1: Trace Tree-Search on a Small Graph

Problem: Consider a state space with 4 states: A (initial), B, C, D (goal). Transitions: A→B, A→C, B→D, C→D. Trace Tree-Search up to depth 2.

Solution:

Initialize fringe = [Node(A)]
Iteration 1: Remove-First = Node(A). Not goal. Expand: → Node(B), Node(C). fringe = [B, C]
Iteration 2: Remove-First = Node(B). Not goal. Expand: → Node(D) via B. fringe = [C, D_B]
Iteration 3: Remove-First = Node(C). Not goal. Expand: → Node(D) via C. fringe = [D_B, D_C]
Iteration 4: Remove-First = Node(D_B). Is goal! Return solution path: A → B → D

Notice that state D is reached via two different paths, producing two distinct nodes in the tree. Tree-Search explores both. Graph-Search would skip the second D.

Example 3: Expand Different Nodes — Compare Outcomes

Problem: From Arad in Romania, what happens if we expand Sibiu first vs Timisoara first?

Solution:

Scenario A — Expand Sibiu first:

Iteration 1: fringe = [Arad]. Remove Arad. Expand → Sibiu, Timisoara, Zerind. fringe = [Sibiu, Timisoara, Zerind]
Iteration 2: Expand Sibiu → Oradea, Fagaras, Rimnicu Vilcea, Arad. fringe = [Timisoara, Zerind, Oradea, Fagaras, Rimnicu Vilcea, Arad₂]

Scenario B — Expand Timisoara first:

Iteration 1: fringe = [Arad]. Remove Arad. Expand → Sibiu, Timisoara, Zerind. fringe = [Sibiu, Timisoara, Zerind]
Iteration 2: Remove Timisoara. Expand → Lugoj, Arad. fringe = [Sibiu, Zerind, Lugoj, Arad₂]

The order of expansion (determined by queue strategy) dramatically changes which nodes are explored next.

Example 4: Count Fringe Growth

Problem: For a state space with branching factor b=3 and depth d=4, what is the fringe size after expanding all nodes at depth 0, 1, and 2?

Solution:

Depth 0: 1 node (root). Fringe after expansion = 3 nodes.

Depth 1: 3 nodes. Each expands to 3 children. Fringe after expansion = 3×3 = 9 nodes.

Depth 2: 9 nodes. Each expands to 3 children. Fringe after expansion = 9×3 = 27 nodes.

Cumulative fringe after depth 2 = 27 nodes

In general, after expanding to depth k, fringe ≈ bᵏ⁺¹ nodes. For b=3, d=4, the final fringe is 3⁵ = 243 nodes.

Example 5: Tree-Search vs Graph-Search Comparison

Problem: Consider a graph with states {S, A, B, G} and edges: S→A, S→B, A→B, B→A, A→G, B→G. How many nodes does Tree-Search vs Graph-Search generate when searching from S to G?

Solution:

Tree-Search (FIFO queue, i.e., BFS):

S → A, B generated (fringe: A, B)
A → B, G generated (fringe: B, B₂, G)
B → A, G generated (fringe: B₂, G, A₂, G₂)
B₂ → A₃, G₃ generated ... (continues growing)

Graph-Search (with visited set):

S → A, B generated. Visited: {S}. fringe: [A, B]
A → B (B visited → skip), G generated. Visited: {S, A}. fringe: [B, G]
B → A (A visited → skip), G (skip if goal test catches it first)
G: goal found! Graph-Search generates 5 nodes. Tree-Search generates infinitely many.
