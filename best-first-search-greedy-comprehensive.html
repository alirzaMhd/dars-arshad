Best-First Search & Greedy BFS - Comprehensive

Informed Search Algorithms — Chapter 3

Overview & Definition

Evaluation Function (general form):
f(n) = g(n) + h(n)
Where g(n) represents the actual path cost from the start node to node n, and h(n) represents the estimated cheapest cost from node n to the goal node. The evaluation function f(n) estimates the total path cost through node n.

What Is Best-First Search?

Best-First Search is a general framework for informed search algorithms. Instead of expanding nodes uniformly (as in BFS) or randomly (as in DFS), Best-First Search uses an evaluation function f(n) to rank nodes on the fringe. The node with the smallest (or largest, depending on formulation) f-value is always selected for expansion next.

The Fringe as a Priority Queue

The fringe (also called the frontier or open list) is maintained as a priority queue. Rather than FIFO (as in BFS) or LIFO (as in DFS), the priority queue orders nodes by their f-value. This allows the algorithm to always expand the most promising node first according to the heuristic.

Key Properties of the General Framework

Informed

Uses domain-specific knowledge

The heuristic function h(n) encodes problem-specific information to guide the search toward promising regions of the state space.

Flexible

Strategy is parameterized by f(n)

Different choices of g(n) and h(n) yield different algorithms. Greedy BFS uses only h(n), while A* uses g(n) + h(n).

State Space

Graph or tree exploration

Best-First Search can operate on graphs (with a closed set to avoid re-expansion) or trees (without a closed set).

Optimality-Dependent

Criteria determine guarantees

Optimality and completeness are not inherent to Best-First Search. They depend entirely on how the evaluation function is defined.

Pseudocode: General Best-First Search

function BestFirstSearch(problem) returns a solution path
  node ← MakeNode(InitialState(problem))
  fringe ← PriorityQueue ordered by f(n)
  fringe.Insert(node)

  while fringe is not empty do
    node ← fringe.Pop()        // lowest f-value first
    if GoalTest(problem, node) then
      return Solution(node)
    for each action in Actions(problem, node) do
      child ← ChildNode(problem, node, action)
      fringe.Insert(child)
  return Failure
Key Distinction: Best-First Search is the umbrella name for any search strategy that selects the fringe node with the best evaluation function value. Greedy Best-First Search and A* are specific instantiations of this general framework.

Evaluation Function Components

Component Definition Example in Greedy BFS Example in A*
g(n) Actual cost from start to n Ignored (weight = 0) Used directly
h(n) Estimated cost from n to goal Used exclusively Used directly
f(n) Total estimated cost through n f(n) = h(n) f(n) = g(n) + h(n)
Note: In many textbooks, the evaluation function is written as f(n). Do not confuse it with the variable f(n) used specifically for Greedy Best-First Search where f(n) = h(n). The general framework allows any combination of g(n) and h(n).

Greedy Best-First Search

Greedy Evaluation Function:
f(n) = h(n)
The node with the smallest heuristic value is expanded first. The algorithm ignores the actual path cost g(n) completely, relying solely on the estimated distance to the goal.

Why Is It Called "Greedy"?

The algorithm earns the label "greedy" because at every decision point it selects the neighbor that looks best right now — the node with the smallest h(n) — without considering whether that choice might lead to a longer overall path later. A greedy algorithm makes the locally optimal choice at each step with the hope of finding a global optimum, but there is no guarantee.

Warning - Not Optimal: Greedy Best-First Search is not optimal by default. It can easily select a path that appears close to the goal initially but forces a long detour later. Only if the heuristic is perfect (h(n) equals true cost for all nodes) does greedy become optimal.
Warning - Completeness: Greedy Best-First Search can get stuck in loops or fail to find a solution even when one exists. If the heuristic leads the search into a cycle or a local minimum region, the algorithm may never reach the goal.

Consider finding a route from Arad to Bucharest in Romania. The heuristic hSLD is the straight-line distance to Bucharest.

Bucharest 0 Goal node
Oradea 380 Less promising detour

Step-by-Step Romania Example

Step 1: Start at Arad. Neighbors: Zerind (h=374), Sibiu (h=253), Timisoara (h=329). Greedy picks Sibiu (lowest h).
Step 2: From Sibiu, neighbors: Arad (h=366, visited), Fagaras (h=178), Rimnicu Vilcea (h=193), etc. Greedy picks Fagaras (lowest h).
Step 3: From Fagaras, neighbors: Sibiu (h=253), Bucharest (h=0). Greedy picks Bucharest — goal reached.
Observation: In this case greedy finds a path efficiently. However, if the road from Fagaras to Bucharest were closed, greedy might backtrack inefficiently. The heuristic's accuracy is critical to performance.

Common Mistakes with Greedy

Mistake 1: Assuming Greedy is Optimal
Many students assume that following the shortest estimated distance to the goal always produces the shortest path. This is false. Greedy BFS finds a solution, but not necessarily the cheapest one.
Mistake 2: Confusing Greedy with A*
Because both use a priority queue, students often conflate them. Remember: A* uses f(n) = g(n) + h(n) (optimal with admissible h), while Greedy uses f(n) = h(n) alone.
Mistake 3: Ignoring Local Maxima
Greedy can become trapped in a local minimum — a region where all neighboring nodes have higher h-values, yet the actual shortest path goes through a node with a temporarily higher h(n).
Mistake 4: Forgetting Directionality
A good heuristic must estimate cost to the goal in the correct direction. A heuristic that looks at distance from the start instead of distance to the goal will cause the algorithm to expand nodes randomly from the start.

Worked Examples

All examples below are original. They do not copy textbook examples and illustrate Greedy Best-First Search behavior in different domains.

Example 1: Campus Navigation — Finding the Quickest Path to the Library

Scenario: A student is at Student Center and needs to reach the Science Library. Greedy BFS uses the straight-line distance to the library as h(n).

Step Current Node Frontier (sorted by h) Action
1 Student Center Engineering Hall (120), Quad (85), Cafeteria (100) Expand Quad (h=85)
2 Quad Engineering Hall (120), Cafeteria (100), Science Library (30) Expand Science Library (h=30)
3 Science Library GOAL REACHED —
Observation: Greedy found the goal in only 2 expansions. However, the actual path cost from Student Center → Quad → Science Library is 85 + 30 = 115 units. The direct route Student Center → Engineering Hall → Science Library has an actual cost of 120 + 40 = 160 units. In this case greedy was lucky, but the student should verify no shorter path exists if optimality matters.

Example 2: Maze Solving — The T-Junction Trap

Scenario: A robot must escape a maze. The goal is the Exit at the top right. The heuristic is Manhattan distance to the exit.

Step 1: The robot starts at (2,2). It can move to (1,2), (2,1), (2,3), or (3,2). Greedy sees (1,2) and (2,3) both have Manhattan distance 2 to the exit at (0,4). It picks (1,2) first.
Step 2: From (1,2), the robot moves to (0,2), (1,1), or (1,3). The exit is at (0,4), so (0,2) has h=2 and (1,3) has h=1. Greedy picks (1,3).
Step 3: From (1,3), the robot can reach (0,3) (h=1) and expands toward the exit.
Step 4: From (0,3), the robot reaches (0,4) and the maze is solved. The path was: (2,2) → (1,2) → (1,3) → (0,3) → (0,4).
T-Junction Trap Variation: Imagine a wall blocks (1,3). Now from (1,2), greedy would still pick a promising-looking neighbor but might circle indefinitely. This demonstrates why greedy is not complete under certain conditions — walls or loops can block progress.

Example 3: Network Packet Routing — Finding the Lowest-Latency Path

Scenario: A data packet starts at Router A and must reach Router D. The heuristic h(n) is the straight-line distance (or estimated latency) to Router D.

Node h(n) to D Neighbors & Costs
A 50 B (cost 30), C (cost 10)
B 20 C (cost 5), D (cost 40)
C 15 D (cost 10)
D 0 Goal
Step 1: At A, neighbors are B (h=20) and C (h=15). Greedy picks C (lower h).
Step 2: From C, reach D directly. Total path cost: 10 + 0 = 10.
Result: Greedy found the optimal path A → C → D with cost 10. Compare to A* which would also consider the g-costs and might explore B as well, but both find this optimal route. However, if the cost from A to B were 5 and B to D were 5, greedy would still choose C first (h=15 vs B's h=20), resulting in a non-optimal 10-cost path when a 10-cost path via B also exists — or if costs differed, true suboptimality appears.

Example 4: Decision Tree Search — Selecting the Best Branch

Scenario: An automated tutor searches a decision tree to find the simplest explanation for a mistake. Heuristic h(n) = expected confusion level of the student after reaching node n (lower is better).

Step 1: Root node (h=100) has three branches: Basic Review (h=70), Advanced Topic (h=50), Practice Problem (h=60). Greedy selects Advanced Topic (lowest h).
Step 2: Advanced Topic branches into: Concept A (h=40), Concept B (h=35), Concept C (h=45). Greedy selects Concept B.
Step 3: Concept B has a child node with h=30. Greedy expands it. Eventually, greedy may find an explanation with h=15 — but if the student actually needs to review basics first, the direct Advanced Topic path may increase confusion.
Critical Insight: The heuristic represents estimated simplicity. If the heuristic is inaccurate (e.g., underestimates the difficulty of advanced topics), greedy will push students toward harder concepts first, causing frustration. This demonstrates why heuristic accuracy is crucial for greedy search quality.

Example 5: Warehouse Robot Navigation — Avoiding Obstacles

Scenario: A warehouse robot starts at Bay 1 and must reach Shipping Dock. The floor has temporary obstacles. The heuristic h(n) = Manhattan distance to Shipping Dock.

Node Manhattan h(n) Actual Path Cost
Bay 1 20 Start
Bay 2 18 Bay 1 → Bay 2 costs 2
Bay 5 12 Bay 1 → Bay 5 blocked by obstacle!
Bay 3 15 Bay 1 → Bay 3 costs 4
Step 1: From Bay 1, greedy sees Bay 2 (h=18), Bay 3 (h=15), and Bay 5 (h=12). It picks Bay 5 (lowest h). But Bay 5 is blocked!
Step 2: Greedy backtracks and next tries Bay 3 (h=15).
Step 3: From Bay 3, the robot navigates to Shipping Dock with h=0 eventually. Path: Bay 1 → Bay 3 → ... → Dock.
Observation: Because Bay 5 was blocked, greedy wasted an expansion. However, with a closed set (graph search), once Bay 5 is marked visited, the algorithm won't re-expand it. Without a closed set, greedy could cycle among blocked cells indefinitely.

Comparison & Complexity

Comparison Table: Greedy Best-First vs. A* vs. Uniform-Cost Search

Property Greedy Best-First A* Search Uniform-Cost (UCS)
Evaluation Function f(n) = h(n) f(n) = g(n) + h(n) f(n) = g(n)
Optimality No (unless h is perfect) Yes (if h admissible & consistent) Yes
Completeness No (can loop or get stuck) Yes (finite branching, step cost ≥ ε) Yes
Time Complexity O(b^m) O(b^d) or O(b^(m*)) O(b^(C*/ε))
Space Complexity O(b^m) O(b^m) O(b^(C*/ε))
Heuristic Required Yes (can be inaccurate) Yes (must be admissible) No
Speed (best case) Very fast Fast Slow

b = branching factor, m = maximum depth of search tree, d = depth of optimal solution, m* = maximum depth of search tree, C* = cost of optimal solution, ε = minimum step cost.

Time and Space Complexity

Best-First Search (General)

Time: O(b^m)

In the worst case, nodes are memorized along a single path to depth m.

Space: O(b^m)

All generated nodes are kept in the priority queue.

Greedy Best-First Search

Time: O(b^m)

In the worst case (bad heuristic), behaves like DFS and explores down a long path.

Space: O(b^m)

Can generate many nodes before reaching the goal, especially in wide state spaces.

When Greedy Excels

Practical use cases:

Real-time navigation, routing when a rough path is acceptable, and anytime algorithms where speed matters more than optimality. The heuristic guides expansion toward the goal region, drastically reducing the search space compared to DFS/BFS in forward-chaining problems.

Impact of Heuristic Quality

Heuristic Quality Effect on Greedy BFS
Perfect (h(n) = actual cost) Always finds optimal path, runs in O(d)
Accurate (close to true cost) Finds near-optimal paths quickly, low branching explored
Inaccurate (h(n) misleading) Wastes expansions, may miss optimal or even any solution
Random (h(n) unrelated) Reduces to random search, behaves like DFS or BFS randomly

Quick Reference Card

Greedy Core Formula:
f(n) = h(n)
Nodes expanded in order of increasing heuristic value.

When to Use Greedy

• Approximate answers are acceptable

• Speed is critical and optimality is not required

• A good heuristic is available

• Search space is huge, and you need a "best guess" quickly

When to Avoid Greedy

• Optimal solutions are mandatory

• The heuristic is unreliable or noisy

• The state space has traps or local minima

• Completeness guarantees are required by specification

Summary of Common Mistakes

Mistake Consequence Correction
Using greedy when optimality is required Got suboptimal or no solution Use A* with admissible h(n)
Confusing h(n) behavior with BFS/DFS Wrong algorithm choice Remember: greedy ignores depth and path cost entirely
Overestimating h(n) (inadmissible for A*, harmful for greedy) Greedy chooses distant-looking but actually far nodes Design h(n) to reflect actual remaining cost accurately
Forgetting to track visited states in graph search Algorithm loops or re-expands nodes Always implement a closed set for graph-based problems
Using h(start) instead of h(n) Static ordering, not informed Recompute h(n) for every generated child node
Final Warning: Greedy Best-First Search trades optimality for speed. It is a valuable tool in the informed search toolkit, but it should never be chosen when finding the best solution is a hard requirement. For optimality, use A* with an admissible heuristic. For completeness, ensure your problem has no infinite paths that the heuristic can trap the search in.
