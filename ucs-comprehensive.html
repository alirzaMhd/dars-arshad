Uniform-Cost Search (UCS)

Optimal Uninformed Search for Non-Uniform Costs

UCS Algorithm Overview

Uniform-Cost Search expands the node with the lowest path cost g(n) first. It is a generalization of BFS that works correctly when step costs are not all equal.

Selection Criterion:
Expand node n with minimum g(n)
Where g(n) = total accumulated cost from the initial state to node n along the current path.

Pseudocode

function UCS(problem) returns solution or failure node ← Node(State: problem.INITIAL, Parent: nil, Action: nil, Path-Cost: 0) frontier ← PRIORITY-QUEUE ordered by Path-Cost, containing node explored ← empty set loop do if EMPTY?(frontier) then return failure node ← POP(frontier) // node with lowest g(n) if problem.GOAL-TEST(node.State) then return SOLUTION(node) add node.State to explored for each action in problem.ACTIONS(node.State) do child ← CHILD-NODE(problem, node, action) if child.State not in explored and child.State not in frontier then frontier ← INSERT(child, frontier) else if child.State in frontier with higher Path-Cost then replace frontier node with child // keep cheaper path

Data Structure

• Priority Queue (min-heap)

• Key: g(n) path cost

• Extract minimum cost node

Key Insight

• First goal popped = optimal

• Handles non-uniform costs

• Generalizes BFS

UCS checks for goal when a node is selected for expansion (popped from queue), not when generated. This ensures the first goal found has the minimum cost path.

Completeness of UCS

Completeness Condition:
UCS is complete if ε > 0 and all step costs ≥ ε
If every action has a minimum positive cost ε, then path costs increase monotonically along any path, ensuring the search does not loop indefinitely.
Danger: Zero-Cost Actions

If an action has cost 0 (e.g., a Noop "do nothing" action), UCS can get stuck in an infinite loop. The agent could repeatedly take the zero-cost action, accumulating no additional cost, and the search would never terminate.

Example: If action A has cost 0, the sequence A, A, A, ... has the same total cost as doing nothing. UCS would keep generating longer and longer paths with the same cost, never converging.

Optimality of UCS

Optimality Property:
The first goal node selected for expansion has the minimum path cost
When UCS pops a goal node from the priority queue, its g(n) value is ≤ the g-value of every other node in the frontier. Since all remaining unexplored paths have cost ≥ the smallest frontier g-value, the found goal is optimal.
Why UCS is Optimal: Proof Sketch

Let G be the first goal popped from the frontier. Its path cost is g(G). Any other node N in the frontier has g(N) ≥ g(G) (because the priority queue returns minimum first).

Any alternative path to a goal G' must pass through some frontier node N'. The path cost to G' is at least g(N') ≥ g(N) ≥ g(G). Therefore g(G) is the minimum possible.

Time & Space Complexity

UCS complexity depends on the actual path costs, not just the branching factor and depth. This is fundamentally different from BFS.

Time & Space Complexity:
O(b1 + ⌊C* / ε⌋)

Where:

• C* = cost of the optimal solution

• ε = minimum step cost (all actions have cost ≥ ε)

• b = branching factor

• ⌊x⌋ = floor function (largest integer ≤ x)

Understanding the Exponent

The exponent 1 + ⌊C*/ε⌋ represents the maximum number of steps UCS might explore. If the optimal solution costs C* = 15 and each step costs at least ε = 3, then ⌊15/3⌋ = 5, so the maximum depth explored is 1 + 5 = 6 levels.

UCS vs BFS Complexity

FactorBFS (O(bd+1))UCS (O(b1+⌊C*/ε⌋))
Based onDepth d (number of steps)Path cost C* and min cost ε
When costs equalO(bd+1)O(bd+1) — same
Cheap actions existUnaffectedMuch worse — large exponent
Expensive actionsUnaffectedBetter — fewer steps explored
Warning: Cheap Actions Hurt UCS

When many cheap actions exist (small ε), the ratio C*/ε becomes large, dramatically increasing the search space. UCS can be much worse than BFS when the minimum step cost is very small.

Worked Examples

Example 1: Trace UCS on a Small Graph

Problem: Graph with nodes S, A, B, C, G. Edges: S→A (cost 2), S→B (cost 5), S→C (cost 10), A→G (cost 9), B→G (cost 6), C→G (cost 2). Goal is G. Trace UCS step by step.

StepFrontier (node: g(n))ExpandedAction
1[S:0]—Initialize with S(0)
2[A:2, B:5, C:10]SPop S(0), expand → A(2), B(5), C(10)
3[B:5, C:10, G:11]APop A(2), expand → G(11)
4[G:11, C:10, G:11]BPop B(5), expand → G(11)
5[G:11, G:12]CPop C(10), expand → G(12)
6[G:11, G:12]—Pop G(11) — goal! Check if it's the minimum.

Optimal path: S→A→G, cost = 11. UCS correctly finds the cheapest path (S→C→G costs 12, S→B→G costs 11 — wait, S→B→G = 5+6 = 11 as well, tie!). Both cost 11 paths are optimal.

Example 2: UCS vs BFS on Non-Uniform Costs

Problem: Graph: S→A (cost 1), S→B (cost 100), A→G (cost 100), B→G (cost 1). Goal is G.

BFS trace: BFS explores by depth. S→A→G has depth 2, S→B→G has depth 2. BFS finds A→G first (assuming left-to-right), total cost = 1 + 100 = 101. Not optimal!

UCS trace:

StepFrontierExpandedAction
1[S:0]—Initialize
2[A:1, B:100]SExpand S
3[B:100, G:101]APop A(1), expand → G(101)
4[G:101, G:101]BPop B(100), expand → G(101)
5[G:101, G:101]—Both G nodes have cost 101, pick one

Wait — both paths have cost 101? No! S→A→G = 1+100 = 101, S→B→G = 100+1 = 101. Both optimal! UCS found optimal cost 101.

Example 3: UCS with Zero-Cost Action (Danger)

Problem: State space: S, A, G. Actions: S→A (cost 5), A→A (cost 0 — Noop self-loop), A→G (cost 10). Goal is G.

Trace:

StepFrontierAction
1[S:0]Initialize
2[A:5]Pop S, expand to A(5)
3[G:15, A:5]Pop A(5), expand to A(5+0=5) and G(15)

The problem: Since action A→A has cost 0, node A is re-inserted into the frontier with g(A) = 5 (same cost). UCS will keep popping A, generating another A(5), forever. The goal G(15) is never popped because the frontier always contains A(5) which has lower priority!

Infinite Loop!

Zero-cost actions (like Noop) cause UCS to generate identical-cost nodes indefinitely. The search never terminates because the minimum-cost node is perpetually re-generated. Solution: detect and eliminate zero-cost cycles.

Example 4: Comparing UCS and BFS with Different Step Costs

Problem: A 4-node graph with non-uniform costs. S→A (cost 1), S→B (cost 2), A→C (cost 10), B→C (cost 1), C→G (cost 1). Goal is G.

BFS solution: BFS explores by depth. Depths: S(d=0), A/B(d=1), C(d=2), G(d=3). BFS finds S→A→C→G. Total cost = 1 + 10 + 1 = 12.

UCS trace:

StepFrontierExpandedAction
1[S:0]—Init
2[A:1, B:2]SPop S, expand
[B:2, C:11]APop A(1), expand to C(11)
3[C:3, C:11]BPop B(2), expand to C(3)
4[C:3, C:11]—C(3) is now cheaper! Removed C(11), keep C(3)
5[G:4, C:11]CPop C(3), expand to G(4)
6[G:4, C:11]—Pop G(4) — goal found!

UCS finds optimal path: S→B→C→G, total cost = 2 + 1 + 1 = 4. BFS found S→A→C→G (cost 12). UCS is optimal, BFS is not when costs are non-uniform.
