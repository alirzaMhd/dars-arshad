HEAP SORT

Algorithm Design & Analysis - Complete Guide

What is Heap Sort?

Heap Sort is a comparison-based sorting algorithm that uses a binary heap data structure. It works by first transforming the input array into a max heap, then repeatedly extracting the maximum element and placing it at the end of the array.

Time Complexity

Best: O(n lg n)

Average: O(n lg n)

Worst: O(n lg n)

Space Complexity

In-place: O(1)

Stable: No

Key Properties

Core Idea:
Build max heap → Extract max repeatedly
A max heap is a complete binary tree where every parent node is greater than or equal to its children.

Why It Works

In a max heap, the root always contains the maximum element. By placing this maximum at the end of the array and re-heapifying, we build the sorted array from back to front.

Array-Heap Relationship (1-indexed):
parent(i) = i/2, left(i) = 2i, right(i) = 2i+1
For node at index i: parent at floor(i/2), left child at 2i, right child at 2i+1
Array-Heap Relationship (0-indexed):
parent(i) = (i-1)/2, left(i) = 2i+1, right(i) = 2i+2
Alternative indexing used in many implementations

Heap Sort Pseudocode

heapsort(A) { build_maxheap(A) for i = n downto 2 { swap(A[1], A[i]) max_heapify(A, 1, i-1) } }

Step-by-Step Explanation

Step 1: Call build_maxheap to transform the array into a max heap.

Step 2: Iterate from the last element down to the second element.

Step 3: Swap the root (maximum) with the current last element.

Step 4: Call max_heapify on the root to restore the heap property on the reduced heap.

max_heapify

max_heapify(A, i, n) { largest = i left = 2 * i right = 2 * i + 1 if (left <= n && A[left] > A[largest]) largest = left if (right <= n && A[right] > A[largest]) largest = right if (largest != i) { swap(A[i], A[largest]) max_heapify(A, largest, n) } }

What It Does

max_heapify assumes that the binary trees rooted at left(i) and right(i) are already max heaps, but A[i] might be smaller than its children. It "sifts down" A[i] to its correct position.

build_maxheap

build_maxheap(A) { for i = floor(n/2) downto 1 max_heapify(A, i, n) }
Key Insight:
Start from the last non-leaf node and work backwards
Leaf nodes (indices floor(n/2)+1 to n) are trivially valid heaps. We only need to heapify internal nodes.
Common Mistake: Do NOT start build_maxheap from index 1. Start from floor(n/2) going down to 1. Starting from index 1 would process leaf nodes unnecessarily.

Visual: How Heap Sort Works

Consider the array [4, 10, 3, 5, 1].

Step 1: Build Max Heap
Input Array: [4, 10, 3, 5, 1] After build_maxheap: 10 / \ 5 3 / \ 4 1 Array: [10, 5, 3, 4, 1]
Step 2: Extract Max (swap root with last)
Swap A[1] and A[5]: 10 <-> 1 Array: [1, 5, 3, 4, |10] Heapify root (size=4): 5 / \ 4 3 / 1 Array: [5, 4, 3, 1, |10]
Step 3: Extract Max again
Swap A[1] and A[4]: 5 <-> 1 Array: [1, 4, 3, |5, 10] Heapify root (size=3): 4 / \ 1 3 Array: [4, 1, 3, |5, 10]
Continue until sorted...
Final sorted array: [1, 3, 4, 5, 10]

Time Complexity Analysis

Total Time = Build Heap + (n-1) x (Extract-Max + Heapify)
T(n) = O(n) + (n-1) x O(lg n) = O(n lg n)

Build Max Heap: O(n)

Formula:
Sum from h=0 to lg(n) of ceil(n / 2^(h+1)) x O(h) = O(n)
Although it looks like O(n lg n), the sum of all heapify calls across all levels converges to O(n). Most nodes are near the bottom and require very few swaps.

Extract-Max + Heapify: O(lg n) each

Formula:
Each max_heapify takes O(lg n) = O(height of heap)
The height of a heap with n nodes is floor(lg n). In the worst case, we sift down from root to leaf.
Total for n-1 extractions:
(n-1) x O(lg n) = O(n lg n)

Space Complexity

In-Place Sorting:
O(1) extra space
Heap Sort rearranges elements within the original array. No auxiliary array is needed (unlike Merge Sort). The only extra space is for a few temporary variables.
Note: The recursive version of max_heapify uses O(lg n) stack space. An iterative version can achieve true O(1) extra space.

Special Case: All Elements Equal

When all elements are equal:
Theta(n) - linear time!
When every element has the same value, max_heapify never needs to swap (no child is strictly greater). The heapify operation simply checks and returns immediately.

This is a rare best-case scenario for Heap Sort. The build phase is still O(n), and each heapify becomes O(1), giving total O(n).

Why Choose Heap Sort?

Advantages

+ Guaranteed O(n lg n)

+ In-place (O(1) space)

+ No worst-case degradation

Disadvantages

- Unstable sort

- Poor cache performance

- Slower than Quick Sort in practice

Cache Behavior: Heap Sort accesses array elements in a non-sequential pattern (jumping between parent and child nodes), leading to poor cache locality. This makes it slower than Quick Sort in practice despite having the same asymptotic complexity.

Common Mistakes & Warnings

Mistake 1: Forgetting that Heap Sort is unstable. If you need to preserve the relative order of equal elements, use Merge Sort instead.
Mistake 2: Starting build_maxheap from index 1 instead of floor(n/2). Processing leaves is wasteful since they are trivially valid heaps.
Mistake 3: Using 0-indexed formulas with 1-indexed arrays (or vice versa). Be consistent with your indexing convention.
Mistake 4: Forgetting that max_heapify's "n" parameter shrinks each iteration. After swapping the max to position i, the heap size is i-1, not the original n.
Mistake 5: Confusing build_maxheap with insert-based heap construction. Build_maxheap runs bottom-up in O(n). Inserting n elements one-by-one takes O(n lg n).
