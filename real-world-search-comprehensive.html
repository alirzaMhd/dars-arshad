Travel Planning

Travel planning involves finding routes using scheduled transportation (flights, trains, buses). This is a classic real-world search problem with practical constraints.

State

(current_location, current_time)

Location = city/airport. Time = clock time.

Actions

TakeFlight(city_from, city_to, departure, arrival)

Must wait at airport until departure time

Goal Test

Arrive at destination city

May have time constraints

Path Cost

Total travel time or monetary cost

May combine multiple factors

Example: Multi-City Flight Planning

Initial state: (New York, 08:00)

Available flights:

NYC→London (09:00-21:00), NYC→Paris (10:00-22:00), London→Paris (22:30-23:30), London→Berlin (08:00+1-10:00+1), Paris→Berlin (23:00-00:30+1)

Goal: (Berlin, any time)

Possible paths:

Path 1: NYC→London(09:00-21:00) → London→Berlin(08:00+1-10:00+1) = arrives 10:00 next day (cost = 26h)

Path 2: NYC→Paris(10:00-22:00) → Paris→Berlin(23:00-00:30+1) = arrives 00:30 next day (cost = 14.5h)

Path 2 is shorter despite the second flight being later — the connection timing matters.

Touring Problems

Touring problems require visiting specific locations (each at least once) before reaching the goal.

Touring Problem State
State = (current_location, visited_set)
visited_set tracks which locations have been visited so far. Size of set = number of cities.

TSP (Traveling Salesperson)

Visit each city exactly once

Return to start (closed tour) or end anywhere (open)

Complexity: NP-Hard

Touring (Relaxed)

Visit each city at least once

Can revisit cities if needed

Simpler than TSP (can use shortest paths)

TSP State Space Complexity
|S| = n! × 2n
For n cities: n! permutations of visit order, times 2n possible visited subsets. For n=20: ~2.4 × 1018 states.
Example: Courier Delivery Routing

Scenario: A courier must deliver packages to 5 locations in a city (A, B, C, D, E) and return to the depot (O).

State: (current_location, {visited set})

Initial state: (O, ∅)

Goal test: location = O ∧ visited = {A, B, C, D, E}

Path cost: Travel distance between locations.

Search space: The courier must find the shortest Hamiltonian cycle through 6 nodes (O, A, B, C, D, E). Brute force: 5! = 120 possible tours. With heuristic search, the optimal can be found faster.

Time Complexity of Travel Problems

Simple Travel

O(bd)

b = flights per city, d = connections

Touring

O(n! × 2n)

n = number of cities to visit

TSP (optimal)

O(n!) or O(2n) with DP

NP-hard, no polynomial solution

VLSI Circuit Design

Very Large-Scale Integration (VLSI) design involves placing millions of components on a silicon chip and routing connections between them. This is a massive search problem.

Cell Layout

Place standard cells (gates, flip-flops) on a 2D grid to minimize area and wire length.

Hundreds of thousands of cells

Channel Routing

Connect cells with wires without crossing or violating design rules.

Multiple metal layers add complexity

Example: Simplified Chip Floorplanning

Problem: Place 4 components (A, B, C, D) on a 3×3 grid such that wire length is minimized. Component dimensions: A=1×1, B=2×1, C=1×2, D=1×1.

Actions: Place component at (x, y) if space available.

Goal test: All components placed, no overlaps.

Path cost: Sum of Manhattan distances between connected components + unused area penalty.

Constraints: Components cannot overlap, all must fit within the 3×3 grid. Only certain placements are valid. The search space includes all valid arrangements.

Modern VLSI design handles millions of cells, not 4. Hierarchical decomposition and heuristic search are essential.

Robot Navigation

Robot navigation involves moving a robot through a continuous or discrete environment while avoiding obstacles.

Continuous State Space

Robot position = (x, y, θ)

Infinite possible states

Continuous Actions

Velocity v and steering angle φ

Infinite possible actions

Real-World Noise

Sensor error, motor slippage, friction

Non-deterministic transitions

Example: Warehouse Robot Navigation

Scenario: A warehouse robot must navigate from charging station (5.2, 3.8) to shelf (12.0, 9.5) through aisles.

Abstraction: Discretize the continuous warehouse floor into a grid or graph of waypoints.

Actions: Move from waypoint to adjacent waypoint. At finer granularity: turn(angle), move_forward(distance).

Goal test: Robot position within threshold distance of target shelf.

Path cost: Travel distance (or time, considering turns slow the robot down).

Real robots also handle dynamic obstacles (humans, other robots) and sensor noise. These make the problem partially observable and non-deterministic.

Automated Assembly Sequencing

Assembly sequencing finds the correct order to assemble parts into a final product. Each step adds or attaches a component.

Assembly State
State = (assembled_parts_set, current_partial_assembly)
Every valid assembly sequence corresponds to a topological ordering of the assembly dependency graph.
Example: Furniture Assembly

Components: Tabletop (T), 4 legs (L1-L4), 8 screws (S1-S8).

Constraints: A leg cannot be attached without screws. The tabletop must be flipped before attaching all legs.

Actions: Attach(part, to, using_tool).

Goal: All parts assembled into final product.

Search: Find a valid sequence respecting all constraints. This is like finding a topological ordering of a directed acyclic graph of dependencies.

Protein Design

Protein design involves finding an amino acid sequence that folds into a desired 3D structure. This is a grand challenge in computational biology.

Protein Design State Space
|S| = 20n
For a protein of length n, each position can be one of 20 amino acids. For n=100: 20100 ≈ 1.27 × 10130 possibilities.

State

Amino acid sequence of length n

Each position: 1 of 20 possibilities

Goal

Sequence folds into target 3D shape

Determined by energy minimization

Actions

Mutate a specific position to another amino acid

Search over sequence space

Example: Optimizing a Short Peptide

Target: A short 5-amino-acid peptide that folds into a stable alpha helix.

Search space: 205 = 3,200,000 possible sequences.

Goal test: Does the sequence, when folded (simulated), achieve the target 3D structure with low free energy?

Approach: Start with a random sequence. Use iterative search (e.g., hill climbing with mutations) to minimize the energy gap from the target fold.

For real proteins (300+ amino acids), the search space is astronomically large. Modern approaches use deep learning to predict folds and guide search.

Internet Search Agents

The web can be modeled as a graph where nodes are web pages and edges are hyperlinks. Search agents crawl and index this graph.

State

A web page (URL)

Identified by its content and URL

Actions

Follow a hyperlink to another page

Each page contains many outgoing links

Goal

Find pages matching a user query

Relevance measured by ranking algorithm

Example: Focused Web Crawl

Task: Find all pages about "machine learning" starting from a seed page.

Search: BFS from the seed URL, following links. For each page encountered, check if it contains relevant keywords.

Challenges:

• The web graph is massive (> 1 billion pages per search engine)

• Many pages are irrelevant — need efficient pruning

• Links may form cycles — need visited set to avoid loops

• Dynamic content changes over time — need re-crawling

Modern search engines use sophisticated ranking (PageRank, neural embeddings) combined with inverted indices to avoid exhaustive search.

Worked Examples

Example 1: Airport Transfer Problem

Scenario: A passenger must fly from Boston (BOS) to Singapore (SIN) with at most 2 layovers. Available flights:

DepartureArrivalDep TimeArr TimeCost
BOSLHR08:0020:00$600
BOSFRA09:0021:30$550
BOSDXB07:0023:00$700
LHRSIN22:0018:00+1$400
FRASIN23:0017:00+1$450
DXBSIN00:3012:00+1$350

Formulation:

State: (location, time). Initial state: (BOS, 06:00) — passenger at airport before first flight.

Actions: Take any flight from current location if current time ≤ departure time.

Goal test: location = SIN.

Path cost: Total ticket price.

Possible solutions:

1. BOS→LHR ($600) + LHR→SIN ($400) = $1,000, arrives 18:00+1

2. BOS→FRA ($550) + FRA→SIN ($450) = $1,000, arrives 17:00+1

3. BOS→DXB ($700) + DXB→SIN ($350) = $1,050, arrives 12:00+1

Minimum cost = $1,000 (routes 1 or 2). Minimum time = route 3 (arrives 12:00+1, earliest) but costs more. The optimal choice depends on whether the agent minimizes cost or time.

Example 2: Restaurant Inspection Tour

Scenario: A health inspector must visit 4 restaurants (R1, R2, R3, R4) in one day. Starting at the office (O) at 08:00, must return to office by 17:00. Travel times (minutes):

OR1R2R3R4
O015253020
R1150103525
R2251002015
R3303520010
R4202515100

Each inspection takes 30 minutes. Must visit each restaurant exactly once.

State: (current_location, visited_set, current_time).

Branching factor: at most 4 (unvisited restaurants) + 1 (return to office if all visited).

Goal test: location = O ∧ visited = {R1, R2, R3, R4} ∧ time ≤ 17:00.

One valid solution: O→R1 (15min) + inspect (30) → R2 (10min) + inspect (30) → R3 (20min) + inspect (30) → R4 (10min) + inspect (30) → O (20min). Total = 15+30+10+30+20+30+10+30+20 = 195 min = 3h15m. Start 08:00, end 11:15. Feasible.

This is a small TSP instance with 4 cities. All 4! = 24 permutations can be brute-force checked. For n=20, heuristic search (approximation) would be needed since 20! is too large.

Example 3: Warehouse Robot with Obstacles

Scenario: A robot in a 10m × 8m warehouse must move from (1.5, 1.2) to (8.3, 7.5). Obstacles include shelves at [(2,2)-(4,4)] and [(6,3)-(7,5)].

Abstraction: Discretize the continuous space into a 0.5m grid (20 × 16 = 320 cells). Each cell is walkable or blocked.

State: (cell_x, cell_y). Initial state: (3, 2) — robot at (1.5,1.2) rounds to nearest cell.

Actions: Move to adjacent walkable cell (up, down, left, right, or with diagonals).

Goal test: cell = (16, 15) — corresponds to (8.3, 7.5) rounded.

Path cost: Euclidean distance between cell centers.

Search: BFS finds shortest path in number of moves. A* with straight-line distance heuristic finds optimal path faster.

Continuous space would be infinite. The 0.5m grid abstraction makes the problem tractable but may miss narrow passages narrower than 0.5m (a common pitfall in abstraction design).
