QUICK SORT

Comprehensive Algorithm Analysis & Examples

What is Quick Sort?

Quick Sort is a divide-and-conquer sorting algorithm. It works by selecting a pivot element and partitioning the array around it so that:

  • All elements ≤ pivot come before the pivot
  • All elements > pivot come after the pivot

The left and right partitions are then recursively sorted.

Key Property
Quick Sort sorts in-place (no extra array needed) and typically outperforms Merge Sort in practice due to better cache performance and lower constant factors.

The Algorithm (Pseudocode)

quicksort(A[L..U]) { if (L < U) { j = partition(A[L..U]) quicksort(A[L..j-1]) quicksort(A[j+1..U]) } }
partition(A[L..U]) { p = A[L] // pivot = first element i = L j = U + 1 while (true) { do i++ while A[i] ≤ p and i ≤ U do j-- while A[j] > p if (i ≥ j) break swap(A[i], A[j]) } swap(A[L], A[j]) return j }

When to Use Quick Sort

Use Quick Sort When:
  • Average-case performance matters most
  • Cache efficiency is important
  • In-place sorting is needed
  • Memory is limited
Avoid Quick Sort When:
  • Worst-case guarantee is required
  • Array is already sorted (naive pivot)
  • Stability is needed
  • Many duplicate keys (without 3-way partition)

The Partition Operation

The partition is the core of Quick Sort. Given an array A[L..U] and a chosen pivot, it reorders the array so that:

  • All elements in A[L..j-1] are ≤ pivot
  • A[j] is the pivot (in its final sorted position)
  • All elements in A[j+1..U] are > pivot

Partition runs in Θ(n) time (linear scan).

Lomuto Partition Scheme (Standard)

The standard textbook version uses Lomuto partition: pivot = last element. A pointer i tracks the boundary of the "small" region.

partition(A, L, U) { pivot = A[U] i = L - 1 for (j = L; j < U; j++) { if (A[j] ≤ pivot) { i++ swap(A[i], A[j]) } } swap(A[i+1], A[U]) return i + 1 }

Hoare Partition Scheme (Classic)

Hoare's original version uses two pointers moving inward. It is faster in practice (fewer swaps) and is used in the pseudocode shown in the Overview tab.

partition(A, L, U) { pivot = A[L] i = L - 1 j = U + 1 while (true) { do { i++ } while A[i] < pivot do { j-- } while A[j] > pivot if (i ≥ j) return j swap(A[i], A[j]) } }

Partition Walkthrough

Array: [8, 3, 1, 5, 9, 2, 7, 4, 6], pivot = 8 (first element)

Step-by-step with Hoare-style partition
0. [8, 3, 1, 5, 9, 2, 7, 4, 6] — pivot = 8, i = -1, j = 9
1. i++ finds 8 ≥ 8? No, 8 = pivot. i stops at 0. j-- finds 6 ≤ 8? Yes. j stops at 8.
2. i=0 < j=8: swap A[0],A[8] → [6, 3, 1, 5, 9, 2, 7, 4, 8]
3. i++ finds 3 < 8, i=1. i finds 1 < 8, i=2. i finds 5 < 8, i=3. i finds 9 ≥ 8, stop at 4.
4. j-- finds 4 ≤ 8, j=7. j finds 7 ≤ 8, j=6. j finds 2 ≤ 8, j=5. j finds 9 > 8, stop at 5.
5. i=4 < j=5: swap A[4],A[5] → [6, 3, 1, 5, 2, 9, 7, 4, 8]
6. i++ finds 9 ≥ 8, stop at 5. j-- finds 7 ≤ 8, j=6. j finds 2 ≤ 8, j=5.
7. i=5 ≥ j=5: STOP. Return j=5.
8. Final: [6, 3, 1, 5, 2] | 8 | [9, 7, 4, 6]
The pivot 8 is now in position index 5 (its final sorted position). Left subarray has all elements ≤ 8, right has all elements > 8.

3-Way Partition (Dutch National Flag)

For arrays with many duplicate keys, a 3-way partition splits into three regions:

Three Regions
A[L..lt-1] < pivot | A[lt..gt] = pivot | A[gt+1..U] > pivot
All elements equal to the pivot are grouped in the middle, never touched again.
When to Use 3-Way Partition
When there are many duplicate keys, 3-way Quick Sort degrades to Θ(n) instead of Θ(n²). This is the basis of the Dutch National Flag Quick Sort.

Recurrence Relation

After partition, the pivot is in its final position. Suppose k elements land in the left partition (all ≤ pivot).

General Recurrence
T(n) = T(k) + T(n - k - 1) + Θ(n)
T(k) = sort left, T(n-k-1) = sort right, Θ(n) = partition cost

Best Case Analysis

Pivot always splits the array perfectly in half: k = n/2.

Best Case Recurrence
T(n) = 2T(n/2) + Θ(n)

By the Master Theorem (Case 2: a=2, b=2, f(n)=Θ(n)):

T(n) = Θ(n lg n)
Since logba = log22 = 1 = c where f(n) = Θ(nc), we get Θ(n lg n).
The recursion tree has lg n + 1 levels, each with total work Θ(n). Total = Θ(n lg n).

Worst Case Analysis

Pivot is always the smallest or largest element: k = 0.

Worst Case Recurrence
T(n) = T(n - 1) + Θ(n)

Expanding by substitution:

T(n) = T(n-1) + cn T(n-1) = T(n-2) + c(n-1) ... T(2) = T(1) + c(2) T(1) = c Summing all: T(n) = c(1 + 2 + 3 + ... + n) = c · n(n+1)/2 = cn²/2 + cn/2
T(n) = Θ(n²)
This happens when the array is already sorted and the first element is always chosen as pivot.
Warning: If the input is already sorted (ascending or descending) and the pivot is the first (or last) element, Quick Sort runs in Θ(n²). This is the most dangerous case!

Average Case Analysis (Detailed Derivation)

Assume every position is equally likely to be the pivot. For each of the n possible pivot positions, the left partition size k ranges from 0 to n-1 with equal probability 1/n.

Step 1: Write the sum over all cases

Average Case Recurrence
nT(n) = Σk=0n-1 [T(k) + T(n-k-1) + cn]
Multiply both sides by n to account for all n equally likely partition positions.

Step 2: Simplify the summation

Key Observation
Σk=0n-1 T(k) = Σk=0n-1 T(n-k-1)
These two sums are identical (just reversed order). Each equals T(0) + T(1) + ... + T(n-1).
nT(n) = 2 · Σk=0n-1 T(k) + n · cn
Simplify: the cn term summed n times gives cn². We write n(n-1)/2 × 2 = n(n-1) for the sum of partition costs (more precisely, the sum of all sub-problem sizes).
Simplified
nT(n) = 2 · Σk=0n-1 T(k) + n(n-1)

Step 3: Write the equation for n-1

For n-1:
(n-1)T(n-1) = 2 · Σk=0n-2 T(k) + (n-1)(n-2)

Step 4: Subtract the two equations

Subtracting: nT(n) - (n-1)T(n-1)
nT(n) - (n-1)T(n-1) = 2T(n-1) + 2(n-1)
The summations telescope: only T(n-1) remains from the left side.

Step 5: Rearrange

Rearranging
nT(n) = (n+1)T(n-1) + 2(n-1)
T(n)/(n+1) = T(n-1)/n + 2/(n+1)

Step 6: Unroll the recursion

T(n)/(n+1) = T(n-1)/n + 2/(n+1) T(n-1)/n = T(n-2)/(n-1) + 2/n T(n-2)/(n-1) = T(n-3)/(n-2) + 2/(n-1) ... T(3)/4 = T(2)/3 + 2/4 T(2)/3 = T(1)/2 + 2/3

Summing all these (telescoping):

T(n)/(n+1) = T(1)/2 + 2[1/3 + 1/4 + ... + 1/(n+1)]

Step 7: Evaluate the harmonic series

Harmonic Series
H(n+1) = 1 + 1/2 + 1/3 + ... + 1/(n+1) = ln(n+1) + Θ(1)
Final Result
T(n)/(n+1) = Θ(lg n)
T(n) = Θ((n+1) lg n) = Θ(n lg n)
The average case of Quick Sort is Θ(n lg n), matching Merge Sort asymptotically.
Summary of Average Case
Even though the worst case is Θ(n²), the probability of hitting it with random pivot selection is astronomically low. The expected running time is Θ(n lg n).

Randomized Quick Sort

Instead of always choosing the first (or last) element as pivot, choose a random index from L to U and swap it with the first element before partitioning.

randomized-quicksort(A, L, U) { if (L < U) { r = random(L, U) swap(A[L], A[r]) // move random pivot to front j = partition(A, L, U) randomized-quicksort(A, L, j - 1) randomized-quicksort(A, j + 1, U) } }
Expected Running Time
E[T(n)] = O(n lg n)
No input dependence. The algorithm performs well on ALL inputs, not just random ones.
Why Randomization Works
The bad case (sorted input) becomes extremely unlikely. For a randomly chosen pivot, the probability that Quick Sort takes Ω(c · n²) time for any constant c is less than 1/nc. In practice, the probability of Θ(n²) is negligible.
Probability of Bad Case
Pr[T(n) ≥ c · n²] ≤ 1/nc-1
For c = 3 and n = 1000: probability ≤ 10-6 (one in a million).

Median-of-Three

Choose the pivot as the median of three elements: the first, middle, and last elements of the subarray.

median-of-three-pivot(A, L, U) { mid = (L + U) / 2 // Sort A[L], A[mid], A[U] among themselves if (A[L] > A[mid]) swap(A[L], A[mid]) if (A[L] > A[U]) swap(A[L], A[U]) if (A[mid] > A[U]) swap(A[mid], A[U]) // Now A[mid] is the median of three swap(A[L], A[mid]) return partition(A, L, U) }
Advantages of Median-of-Three
  • Guarantees O(n lg n) worst case for most inputs (combined with cutoff)
  • Eliminates the sorted-input degenerate case
  • Slightly more expensive per partition (≈3 extra comparisons) but far fewer total comparisons overall
  • Used in most practical Quick Sort implementations (C's qsort, Java's Arrays.sort for primitives)

Insertion Sort Cutoff

For small subarrays (n ≤ ~16-20), Insertion Sort is faster than Quick Sort due to lower overhead.

quicksort-with-cutoff(A, L, U) { if (U - L + 1 ≤ 16) { insertion-sort(A, L, U) return } j = partition(A, L, U) quicksort-with-cutoff(A, L, j - 1) quicksort-with-cutoff(A, j + 1, U) }
This optimization reduces the number of recursive calls by roughly 20-30% and improves real-world performance significantly.

Other Optimizations

Tail Recursion Elimination

Always recurse on the smaller partition first. This guarantees the recursion depth is at most O(lg n), even in the worst case.

Three-Way Partition

Groups equal elements together. Handles duplicate-heavy inputs in O(n) instead of O(n²).

Median-of-Medians

Find exact median in O(n) using groups-of-five. Guarantees Θ(n lg n) worst case, but high constant factor makes it impractical.

Intro Sort (Introsort)

Starts with Quick Sort, switches to Heap Sort if recursion depth exceeds 2lg(n). Used by C++ STL.

Warning: Common Pitfalls

Pitfall 1: Choosing first element on sorted input. This is the classic degenerate case. Always use randomized or median-of-three pivot selection.
Pitfall 2: Infinite recursion with duplicate keys. Standard partition may create unbalanced splits when many elements equal the pivot. Use 3-way partition for duplicate-heavy data.
Pitfall 3: Off-by-one errors in partition. The boundary conditions (i = L-1, j = U+1, or i = L, j = U) are critical. Test on arrays of size 1 and 2.
Pitfall 4: Stack overflow. Deep recursion (O(n) in worst case) can overflow the call stack. Use tail recursion elimination or a depth cutoff.

Example 1: Simple Array (5 elements)

Sort: [5, 3, 8, 1, 2]

Step-by-step (Lomuto partition, pivot = last element)
0. Initial: [5, 3, 8, 1, 2]
1. Partition [5, 3, 8, 1, 2]: pivot = 2
  Compare 5>2, 3>2, 8>2, 1≤2 → swap 5 and 1 → [1, 3, 8, 5, 2]
  Swap pivot 2 into position: [1, 2, 8, 5, 3] → pivot at index 1
2. Recurse left: [1] — base case, already sorted.
3. Recurse right: [8, 5, 3]
  Partition [8, 5, 3]: pivot = 3. Compare 8>3, 5>3 → pivot at index 0.
  Result: [3, 5, 8] → pivot at index 0
4. Recurse right of pivot: [5, 8]. Partition [5, 8]: pivot = 8. 5≤8 → pivot at index 1.
  Result: [5, 8]
5. Final sorted array: [1, 2, 3, 5, 8]

Example 2: Already Sorted Array (Worst Case)

Sort: [1, 2, 3, 4, 5] with pivot = first element.

Worst case: pivot is always minimum
1. [1, 2, 3, 4, 5] → pivot = 1, left = [], right = [2, 3, 4, 5]
2. [2, 3, 4, 5] → pivot = 2, left = [], right = [3, 4, 5]
3. [3, 4, 5] → pivot = 3, left = [], right = [4, 5]
4. [4, 5] → pivot = 4, left = [], right = [5]
5. [5] → base case
  Total comparisons: 4 + 3 + 2 + 1 = 10 = n(n-1)/2
  Recursion depth: 5 = n (not lg n)
This is why naive Quick Sort is dangerous on sorted data! Always use randomized or median-of-three pivot selection.

Demonstrating duplicate handling

Final Warning Box

Remember: Quick Sort's power lies in its practical speed (cache-friendly, in-place, low constants), not its theoretical guarantees. Always pair it with randomized or median-of-three pivot selection and a small-array cutoff (Insertion Sort for n≤16) for a production-quality implementation.
