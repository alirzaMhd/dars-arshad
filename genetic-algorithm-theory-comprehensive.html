1. Genetic Algorithm Full Pipeline

A Genetic Algorithm (GA) is a population-based search heuristic inspired by biological evolution. The algorithm iteratively improves a population of candidate solutions toward better fitness.

General GA Objective:
maximize f(x) subject to x ∈ search space
The GA searches for an individual x that maximizes a fitness function f.

1.1 Pseudocode — Complete GA with REPRODUCE

function GA(pop, fitness, population_size, crossover_rate, mutation_rate, generations):
  for each generation g from 1 to generations:
    new_pop ← []
    while len(new_pop) < population_size:
      parent1 ← SELECT(pop, fitness)
      parent2 ← SELECT(pop, fitness)
      child1, child2 ← REPRODUCE(parent1, parent2)
      if random() < crossover_rate:
        crossover(child1, child2)
      mutate(child1)
      mutate(child2)
      new_pop.extend([child1, child2])
    pop ← new_pop
    elitism(pop, fitness) // optionally preserve best individual
    evaluate all individuals in pop with fitness
    if termination_criterion(pop): break
  return best individual from pop

function REPRODUCE(p1, p2):
  return copy(p1), copy(p2)

1.2 Pipeline Components

1. Representation

Encode solutions as chromosomes: binary strings, real-valued vectors, permutations, trees, etc.

2. Initialization

Sample an initial population P₀ uniformly or heuristically from the search space.

3. Fitness Function

Evaluate each individual with f(x). Scale or rank if raw values are not suitable for selection.

4. Selection

Stochastically pick individuals according to fitness probability, biasing toward higher-fitness parents.

5. Crossover

Recombine genetic material from two parents to produce offspring that inherits partial solutions from both.

6. Mutation

Randomly flip bits or perturb values to maintain diversity and prevent premature convergence.

2. Schema Theorem & Building Blocks

2.1 Schemas, Order, and Defining Length

A schema (plural: schemata) is a template describing a subset of strings that share certain fixed symbols at certain positions.

Schema definition:
H = a₁ a₂ ... aₗ where aᵢ ∈ {0, 1, *}
'*' is a wildcard (don't care). A schema of order o has o fixed positions out of length l. Defining length δ(H) is the distance between first and last fixed positions.
SchemaFixed bits (order)Defining length δCompatible strings (l=5)
1*0*134 (pos 1 to 5)10001, 10101, 11001, 11101
**1**10All strings with bit 3 = 1
111**32 (pos 1 to 3)11100, 11101, 11110, 11111

2.2 Schema Theorem (Holland)

Schema survival estimate:
m(H, t+1) ≥ m(H, t) · f(H)/f̄ · (1 − p_c · δ(H)/l − p_m · o(H))
m(H, t) = observed instances of schema H at generation t. f(H) = average fitness of H. f̄ = average population fitness. p_c = crossover rate. p_m = mutation rate. o(H) = order of H. l = chromosome length.

2.3 Interpretation of the Schema Theorem

Fitness Bias Term

Schemas with f(H) > f̄ grow in expected frequency over time. Below-average schemas shrink toward extinction.

Crossover Destruction Term

Schemas with large δ(H) are more likely to be cut by crossover, reducing survival chance.

Mutation Destruction Term

Schemas with high order o(H) have many fixed positions that mutation can destroy.

2.4 Building Blocks Hypothesis

GA performance arises from combining short, low-order schemas that each contribute to fitness. These are called building blocks.

Key idea:
High fitness solutions ≈ combination of high-fitness short schemata
Crossover preserves building blocks by recombining them without breaking short schemas.

2.5 Position-Independent Linkage

Real-world problems often have epistatic interactions where variable A affects fitness only when coupled with variable B. Standard GAs still work because crossover can recombine building blocks regardless of position — but linkage learning and wrappers like messy GAs improve efficiency.

Warning: If important building blocks sit on opposite ends of a long chromosome with high δ, 1-point crossover destroys them. Consider 2-point or uniform crossover, or reorder bits so linked variables are adjacent.

2.6 Effect of Crossover vs Random Combinations

MechanismHow blocks are combinedExpected result

3.2 Encoding for 8-Queens: 8-digit vs 24-bit

The 8-queens problem illustrates how encoding choice changes search landscape and operator behavior.

EncodingGenome length lSearch Space |S|Behavior of Crossover
8-digit permutation8 positions (each digit 1-8)8! = 40,320PMX preserves permutation validity
24-bit (3 bits/queen)24 bits total2²⁴ ≈ 16.7MRaw bit crossover often creates invalid permutations; repair needed
Warning: The 24-bit plain binary encoding wastes most of the search space because many bit patterns do not correspond to valid permutations. A GA with this encoding must include a repair step or penalty, whereas an 8-digit permutation encoding with PMX crossover stays on the feasible set from the start.

3.3 Position-Independent Linkage (Extended)

When genes are epistatic, the fitness contribution of one allele depends on another. A powerful GA should still recombine properly:

  • Linkage disequilibrium: Non-random association of alleles at different loci.
  • Messy GA: Temporarily ignores fixed positions to identify useful building blocks and then specifies them.
  • mGA order: Tries variable orderings to find tight linkage groups and apply crossover locally.

3.4 Applications: VLSI Design & Scheduling

VLSI Placement

Encode module positions as a permutation. Crossover preserves partial layouts while mutation swaps nearby modules to reduce wire length and timing violations.

Job-shop Scheduling

Encode operation order. Fitness = makespan completion time. crossover recombines partial schedules; mutation alters operation precedence.

3.6 Common Pitfalls & Design Choices

Premature Convergence

Population loses diversity before reaching global optimum. Cause: high selection pressure + low mutation. Fix: increase mutation, tournament size tuning, or use niching.

Blinking Problem

Same best individual oscillates. Cause: too much randomness in offspring. Fix: reduce mutation, introduce elitism to retain good solutions.

Scaling Fitness

Raw fitness can cause overflow or collapse probability mass onto a few individuals. Fix: rank-based selection or linear/exponential fitness scaling.

Representation Mismatch

Operators do not respect semantic boundaries (e.g., binary crossover for permutations). Fix: choose operators consistent with representation.

4. Worked Examples & Applications

Example 1 — One-Point Crossover on Binary Strings

Problem

Parent 1: 10110

Parent 2: 00111

Crossover point: 3rd position (between index 2 and 3, 0-indexed)

Step 1 — split at cut point after position 3:

Parent 1 prefix: 101 suffix: 10

Parent 2 prefix: 001 suffix: 11

Step 2 — swap suffixes:

Child 1: 101 11 = 10111

Child 2: 001 10 = 00110

Note: if crossover point was chosen at position 1 instead, the same parents would yield much less mixing.

Example 2 — Tracing Fitness Across Generations

Problem

Goal: maximize f(x) = number of 1s in a 8-bit string (OneMax). Population size n = 4.

Generation 0:

00101101 → fitness = 4
11100010 → fitness = 5
10101010 → fitness = 4
00001111 → fitness = 4

Selection (Tournament k=2):

Pair A: 11100010 (5) vs 00101101 (4) → pick 11100010

Pair B: 00001111 (4) vs 10101010 (4) → pick either (we take 00001111)

Crossover at position 4 with probability p_c:

Parent 1: 1110|0010, Parent 2: 0000|1111

Child 1: 1110|1111 = 11101111 (fitness = 7)
Child 2: 0000|0010 = 00000010 (fitness = 1)

Mutation chance p_m on new offspring:

Flip a few bits randomly. After mutation the population shifts toward higher fitness.

Result: Best-so-far fitness improved from 5 in gen 0 to potentially 7 in gen 1.

Example 3 — Is a Schema’s Average Fitness Above Population Mean?

Problem

Population of 6 binary strings of l = 6. Consider schema H = 11*** with fitness function OneMax (count 1s).

Population:

110101 (has H) → fitness 4
111010 (has H) → fitness 4
110110 (has H) → fitness 4
101110 (... only 1st bit 1) → fitness 4
011011 (... only 2nd bit 1) → fitness 4
101111 (not in H) → fitness 5

All strings happen to have fitness 4 or 5 regardless of H membership. So f(H) = average of {110101, 111010, 110110} = 4.

Population mean f̄ = (4+4+4+4+4+5)/6 = 4.17.

Conclusion: f(H) = 4 < f̄ = 4.17, so according to the Schema Theorem, H will decrease in expected frequency and eventually be replaced by fitter schemata.

Example 4 — How Crossover Combines Building Blocks

Problem

Goal schema: H* = **1*1** — a building block requiring a 1 at position 3 and a 1 at position 5. Parents each cover one of the required bits.

Parent 1 carries block A: 10*0** (positions: 1=1 free, 2=0 free, 3=1 fixed, ...)

Parent 2 carries block B: *****1* (positions: ... 5=1 fixed)

Step 1 — selection: Both parents chosen because they individually satisfy part of the fitness landscape.

Step 2 — crossover at a neutral region (between pos 3 and 5):

Child 1: 10*0|*1* = 10*0*1* (now has both 1s: block A + block B)

Step 3 — if mutation accidentally flipped a required bit, crossover preserves the other parent's bit in the other child:

Child 2: acts as a backup that carries only one block, keeping genetic diversity.

Observation: When building blocks are short and well-placed in the population, crossover stochastically assembles them into a globally better solution faster than mutation alone.

Example 5 — Choosing Crossover Point to Preserve/Destroy Blocks

Problem

Assume we want to preserve building block 11*** (positions 1 and 2 tight — low defining length δ = 1). Parents both have this sibling block.

Parent 1: 110111 110111 = 11 0111 10111

Parent 2: 110111 110111 = 11 0111 10111

Case A: Crossover point = 2 (after block 11)

→ Both children keep prefix 11 intact. Block 11*** is fully preserved in both offspring.

Case B: Crossover point = 6 (inside back half)

→ Children swap tails but keep 11 prefix. So this point is also safe for a block at the head.

Case C: Crossover point = 1 (inside the block)

→ Prefix contains one of the block's bits. Because split is inside the element, children may still keep the pair if split didn't separate the pair, but with multi-bit crossover the risk rises. Extremely unlucky 1-point cut at position 1 splits 1|10111..., losing block preservation entirely in offspring with different second halves.

Warning: When you know which schemata are important, place them on low-δ regions and prefer uniform/2-point crossover if exact cut position is hard to control.
