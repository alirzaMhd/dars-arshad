SELECTION ALGORITHM (SELECT)

Finding the k-th Smallest Element in Linear Time

Problem Definition

Given an array A of n elements and an integer k (1 <= k <= n), find the k-th smallest element in A. This is known as the Selection Problem.

INPUT
Array A[1..n], integer k
k = 1 gives the minimum, k = n gives the maximum, k = ceil(n/2) gives the median.
OUTPUT
The element that would appear in position k if A were sorted
Note: We do NOT need to fully sort the array — just find one element.

Why Not Just Sort?

Sorting Approach

Sort array, return A[k]

Time: O(n log n)

Wasteful: we do n log n work just to find one element.

Select Algorithm

Divide and conquer with median-of-medians pivot

Time: O(n)

Optimal: any comparison-based selection requires at least O(n) comparisons.

Key Insight

The Selection Algorithm achieves guaranteed linear time by choosing a good pivot element. The pivot is the median of medians — a value guaranteed to be close to the true median, ensuring balanced partitions.

Common Mistake: Using a naive pivot (like first or last element) leads to O(n^2) worst case. The median-of-medians approach guarantees O(n).

Algorithm Family

Algorithm Worst Case Average Case Pivot Strategy
QuickSelect (naive) O(n^2) O(n) Random / first / last
Select (median-of-medians) O(n) O(n) Median of groups of 5
Median of medians (groups of 3) O(n log n) O(n) Median of groups of 3

Select Algorithm — Step by Step

The algorithm works in 4 main steps:

Step 1: Divide

Divide the array into groups of 5 elements each. There are ceil(n/5) groups.

Step 2: Find Medians

Find the median of each group of 5 (using brute force). Store in array B.

Step 3: Recursive Median

Recursively find the median x of the ceil(n/2) medians in B.

Step 4: Partition & Recurse

Partition around x. If x is at position k, done. Otherwise recurse on the appropriate side.

Pseudocode

sel(A[L..u], k) { n = u - L + 1; if (n <= 25) { // Base case: use brute force (insertion sort or similar) sort A[L..u]; return A[L + k - 1]; } else { m = ceil(n / 5); B[1..m]; // array to store medians // (1) Find median of each group of 5 for (i = 1 to m) B[i] = sel(A[5i-4 .. 5i], 3); // (2) Find median of medians x = sel(B[1..m], ceil(m/2)); // (3) Partition around pivot x j = partition(A[L..u], x); // (4) Recurse on the correct side if (k == j - L + 1) return x; // x is the k-th smallest else if (k < j - L + 1) return sel(A[L..j-1], k); else return sel(A[j+1..u], k - (j - L + 1)); } }

Why Groups of 5?

The group size is critical for the time complexity. Let's compare:

Groups of 3
T(n) = T(n/3) + T(2n/3) + Theta(n)
Guaranteed at least 1/4 of elements on one side.
Result: Theta(n log n) — NOT linear!
Groups of 5
T(n) = T(n/5) + T(7n/10) + Theta(n)
Guaranteed at least 3n/10 elements on each side.
Result: Theta(n) — LINEAR!
Why not groups of 3? With groups of 3, the recursive call on the larger partition is T(2n/3). Combined with T(n/3), this gives T(n) = T(n/3) + T(2n/3) + Theta(n), which solves to Theta(n log n) — the same as sorting!

Pseudocode — Partition Function

partition(A[L..u], pivot) { // Rearrange A[L..u] so that: // - All elements < pivot are on the left // - All elements = pivot are in the middle // - All elements > pivot are on the right // Returns the index j where pivot is placed swap pivot to A[L]; // or A[u] i = L; j = u; while (i < j) { while (i < j && A[j] >= pivot) j--; A[i] = A[j]; while (i < j && A[i] <= pivot) i++; A[j] = A[i]; } A[i] = pivot; return i; }

Recurrence Relation

MAIN RECURRENCE
T(n) = T(ceil(n/5)) + T(7n/10) + Theta(n)
T(ceil(n/5)): Recursive call to find median of ceil(n/2) medians (but we call on ceil(n/5) group medians).
T(7n/10): Recursive call on the larger partition after excluding at least 3n/10 elements.
Theta(n): Dividing into groups, finding group medians, and partitioning.

Why at Least 3n/10 Elements?

After finding the median of medians x:

Smaller than x

At least half of ceil(n/5) medians are <= x. Each of these medians has at least 2 elements in its group that are <= the median.

>= 3n/10 elements are <= x

Larger than x

At least half of ceil(n/5) medians are >= x. Each of these medians has at least 2 elements in its group that are >= the median.

>= 3n/10 elements are >= x

PARTITION GUARANTEE
After partitioning around x, the larger side has at most n - 3n/10 = 7n/10 elements
This ensures the recursive call on the larger partition is T(7n/10), not T(n-1).

Solving the Recurrence

T(n) = T(ceil(n/5)) + T(7n/10) + Theta(n) Assume T(n) <= cn for some constant c. T(n) <= c*ceil(n/5) + c*(7n/10) + an <= c*(n/5 + 1) + 7cn/10 + an <= cn/5 + c + 7cn/10 + an <= (2cn/10 + 7cn/10) + c + an <= 9cn/10 + c + an We need: 9cn/10 + c + an <= cn => an + c <= cn/10 => c >= 10a + 10a/n For n large enough, c = 20a works. Therefore T(n) = Theta(n).

Complexity Summary

Time Complexity

Worst case: Theta(n)

Average case: Theta(n)

Constant factor is larger than QuickSelect but guaranteed linear.

Space Complexity

Auxiliary: Theta(log n)

Due to recursion stack depth. Can be reduced to Theta(1) with iterative version.

Comparisons

At most: ~5.43n comparisons

Higher constant than QuickSelect but no worst-case blowup.

Recursion Depth

At most: Theta(log n)

Each recursive call reduces problem size by factor of at least 10/7.

Comparison: Group Sizes

Group Size Smaller Partition Larger Partition Recurrence Result
3 n/3 2n/3 T(n/3) + T(2n/3) + n O(n log n)
5 n/5 7n/10 T(n/5) + T(7n/10) + n Theta(n)
7 n/7 5n/7 T(n/7) + T(5n/7) + n O(n log n)
9 n/9 7n/9 T(n/9) + T(7n/9) + n O(n log n)
Key observation: Group size must satisfy 1/group_size + 1/2 < 1 for linear time. For group 5: 1/5 + 1/2 = 0.7 < 1 (works). For group 3: 1/3 + 1/2 = 0.833 > 1 (fails).

Precise Analysis

MORE PRECISE RECURRENCE
T(n) = T(ceil(n/5)) + T(7n/10 + 6) + Theta(n)
The "+6" accounts for the worst-case partition when the pivot is near the boundary. This doesn't change the asymptotic result: still Theta(n).

Approach

Divide into groups of 5, find median of medians as pivot, partition, recurse

Time

Theta(n) worst case

Theta(log n) recursion stack

T(n) = T(n/5) + T(7n/10) + Theta(n) = Theta(n)

When to Use What

Use Select (MoM) when:
  • Guaranteed linear time is required
  • Adversarial input is possible
  • Deterministic behavior is needed
  • Theoretical guarantees matter
Use QuickSelect when:
  • Practical speed matters more than worst case
  • Input is random or non-adversarial
  • Low constant factors are important
  • Simplicity of implementation matters

Common Mistakes to Avoid

1. Wrong group size: Using groups of 3 gives O(n log n), not O(n). Must use groups of 5 (or any size where 1/g + 1/2 < 1).
2. Off-by-one in indices: The recursive call adjusts k by subtracting the number of elements in the left partition. Be careful with 0-indexed vs 1-indexed arrays.
3. Forgetting the base case: Always handle small arrays (n <= 25) with brute force to avoid infinite recursion.
4. Wrong median calculation: The median of 5 elements is the 3rd smallest (index 2 in 0-indexed). Don't confuse with average of middle two.
5. Not adjusting k after partition: When recursing on the right side, k must be reduced by (j - L + 1) to account for elements eliminated on the left.

Quick Pseudocode Reference

sel(A[L..u], k): n = u - L + 1 if n <= 25: return brute_force(A[L..u], k) m = ceil(n/5) for i in 1..m: B[i] = sel(A[5i-4..5i], 3) x = sel(B[1..m], ceil(m/2)) j = partition(A[L..u], x) if k == j-L+1: return x elif k < j-L+1: return sel(A[L..j-1], k) else: return sel(A[j+1..u], k-(j-L+1))
