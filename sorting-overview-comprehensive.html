SORTING ALGORITHMS OVERVIEW

Comprehensive Study Guide - Comparison-Based and Non-Comparison-Based Sorts

How Sorting Algorithms Are Classified

Every sorting algorithm can be described along three independent dimensions. Understanding these categories helps you select the right algorithm for a given situation and predict its behavior.

1.1 Comparison-Based vs Non-Comparison-Based

Comparison-Based

The algorithm decides ordering by comparing pairs of elements using a comparator (usually <, >, or ==).

Lower Bound (Proven)
Omega(n log n)
No comparison-based sort can guarantee better than n log n comparisons in the worst case. This is proven via the decision tree model.

Examples: Merge Sort, Quick Sort, Heap Sort, Insertion Sort, Bubble Sort, Selection Sort.

Non-Comparison-Based

The algorithm uses properties of the keys themselves (e.g., digits, bits) rather than comparing elements directly.

Can Break the Lower Bound
O(n) possible
By exploiting the structure of the keys (e.g., integers in a known range), these algorithms can achieve linear time.

Examples: Counting Sort, Radix Sort, Bucket Sort.

1.2 Stable vs Unstable

Stable Sort

If two elements have equal keys, their relative order in the input is preserved in the output.

Stable: Bubble, Insertion, Merge Sort
Unstable Sort

Equal elements may appear in a different relative order after sorting.

Unstable: Selection Sort, Quick Sort (default)
Why Stability Matters

Suppose you have records sorted by name, and you now want to sort them by grade. A stable sort keeps students with the same grade in their original alphabetical order. An unstable sort could scramble that secondary ordering.

1.3 In-Place vs Out-of-Place

In-Place

The algorithm uses O(1) extra memory beyond the input array. It rearranges elements within the original array.

Examples: Selection Sort, Bubble Sort, Insertion Sort, Heap Sort.

Out-of-Place

The algorithm requires additional memory proportional to n (or more). It may allocate a second array.

Examples: Merge Sort (O(n) extra), Counting Sort, Radix Sort.

1.4 Decision Tree Lower Bound

Decision Tree Argument
Omega(n log n) comparisons in the worst case
A comparison sort can be modeled as a binary decision tree where each internal node compares two elements. There are n! possible permutations of n elements, so the tree must have at least n! leaves. A binary tree with L leaves has height at least log_2(L). Therefore, the worst-case number of comparisons is at least log_2(n!) which is Omega(n log n) by Stirling's approximation.

Selection Sort

Algorithm
Find minimum, place at front, repeat
Scan the unsorted portion to find the minimum element. Swap it with the first unsorted element. Move the boundary one position right. Repeat until sorted.
SELECTION-SORT(A, n): for i = 0 to n-2: min_idx = i for j = i+1 to n-1: if A[j] < A[min_idx]: min_idx = j swap A[i] with A[min_idx]
Time Complexity

Best: O(n^2)

Average: O(n^2)

Worst: O(n^2)

Always does (n-1) comparisons per pass regardless of input.

Key Property

Exactly (n-1) swaps, always.

Unstable, In-Place.

Each pass does exactly one swap. Total swaps = n-1.

Space

O(1) extra space

Only a few variables for indices and temp swap.

Bubble Sort

Algorithm
Compare adjacent, swap if out of order, bubble up
Walk through the array comparing adjacent elements. If they are in the wrong order, swap them. After each full pass, the largest unsorted element is in its final position. Optimized version stops early if no swaps occur in a pass.
BUBBLE-SORT(A, n): for i = 0 to n-2: swapped = false for j = 0 to n-2-i: if A[j] > A[j+1]: swap A[j] with A[j+1] swapped = true if not swapped: break // Already sorted
Time Complexity

Best: O(n) — optimized, already sorted

Average: O(n^2)

Worst: O(n^2) — reverse sorted

Key Properties

Stable, In-Place.

Optimized version detects sorted input in O(n).

The "swapped" flag is the key optimization.

Space

O(1) extra space

Only the swapped flag and loop variables.

Insertion Sort

Algorithm
Build sorted portion one element at a time
Take the next unsorted element and insert it into its correct position within the already-sorted portion by shifting larger elements to the right.
INSERTION-SORT(A, n): for i = 1 to n-1: key = A[i] j = i - 1 while j >= 0 and A[j] > key: A[j+1] = A[j] j = j - 1 A[j+1] = key
Time Complexity

Best: O(n) — already sorted

Average: O(n^2)

Worst: O(n^2) — reverse sorted

Key Properties

Stable, In-Place.

Adaptive: performs better on nearly-sorted data.

Excellent for small arrays (n < 50) or nearly-sorted data.

Space

O(1) extra space

Only the key variable and loop counters.

Properties Deep Dive

2.1 Stability Analysis

Algorithm Stable? Why / Why Not
Selection Sort Unstable Long-distance swaps can move an element past equal elements, changing their relative order.
Bubble Sort Stable Only adjacent swaps are used, and equal elements are never swapped.
Insertion Sort Stable Inserts equal elements after existing ones (uses > not >= in the shift condition).

2.2 In-Place Analysis

Algorithm In-Place? Extra Space
Selection Sort Yes O(1)
Bubble Sort Yes O(1)
Insertion Sort Yes O(1)

2.3 Adaptive Behavior

An algorithm is adaptive if it runs faster when the input is partially sorted.

Algorithm Adaptive? Explanation
Selection Sort No Always scans the entire unsorted portion. No early termination.
Bubble Sort (optimized) Yes The "swapped" flag detects when the array becomes sorted.
Insertion Sort Yes Nearly-sorted data means fewer shifts, approaching O(n).

2.4 Swaps and Comparisons

Algorithm Swaps (Worst) Comparisons (Worst)
Selection Sort n - 1 (always) n(n-1)/2
Bubble Sort n(n-1)/2 (worst) n(n-1)/2
Insertion Sort n(n-1)/2 (worst) n(n-1)/2 (worst)
Common Mistake: Selection Sort does the fewest swaps (n-1 always) but does the maximum number of comparisons every time. If writes are expensive (e.g., flash memory), selection sort may still be preferred despite O(n^2) time.
Common Mistake: Bubble Sort is often called the "slowest" sort, but optimized bubble sort can detect a sorted array in O(n) — making it faster than unoptimized O(n^2) algorithms on sorted input.

Decision Guide

Which Sort Should You Choose?
  • Data is nearly sorted? Use Insertion Sort — O(n) best case, adaptive.
  • Writes are expensive? Use Selection Sort — only n-1 swaps always.
  • Stability needed? Use Bubble or Insertion Sort — both stable.
  • Very small n (< 20)? Any of these work; Insertion Sort has smallest constant factors.
  • Need guaranteed O(n log n)? Use Merge Sort, Heap Sort, or Tim Sort (not covered here).
Important: All three basic sorts are O(n^2) in the worst/average case. For large datasets, use O(n log n) algorithms like Merge Sort or Quick Sort.

Worked Example 5: Lower Bound Application

How many comparisons does any comparison-based sort need for n = 1,000,000 elements in the worst case?

Lower Bound Formula
Omega(n log n)
log_2(1,000,000) = log_2(10^6) = 6 * log_2(10) = 6 * 3.3219 = 19.93
Minimum Comparisons
n * log_2(n) = 1,000,000 * 19.93 = 19,930,000
No comparison-based sort can guarantee fewer than ~19.9 million comparisons for n = 1 million. This is a mathematical lower bound — not a limitation of a particular algorithm.
Implication for Algorithm Choice

If you need to sort 1 million elements, expect at minimum ~20 million operations. Selection sort would do ~500 million comparisons (n^2/2), while Merge Sort does ~20 million (n log n). That's a 25x difference.
