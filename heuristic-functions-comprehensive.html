Heuristic Functions - Comprehensive

Informed Search Algorithms — Chapter 3

Design Principles

A heuristic h(n) estimates cost from n to goal. For A* with f(n)=g(n)+h(n), the heuristic must be admissible (never overestimates true cost) to guarantee optimality.

Admissibility:
h(n) ≤ h*(n)
h*(n) is the true cheapest cost to a goal. An admissible heuristic is optimistic.
Consistency/Monotonicity:
h(n) ≤ c(n,a,n') + h(n')
Triangle inequality along every edge. Every consistent heuristic is admissible. Guarantees non-decreasing f-values along paths.
8-Puzzle Heuristics

h1 (misplaced tiles): count tiles not in goal position. Admissible, consistent. h2 (Manhattan distance): sum of horizontal and vertical displacements. More informed, admissible, consistent. h2 dominates h1 because each misplaced tile needs at least 1 move, and Manhattan counts exact minimum moves.

Mistake: Do not use an inadmissible heuristic when optimality is required. Do not assume admissibility implies consistency for Graph-Search.

Relaxed Problems

A relaxed problem removes constraints from the original problem, creating a supergraph of the state space. The optimal solution cost of any relaxation is an admissible heuristic for the original problem.

Relaxed Problem Property:
Cost_optimal(relaxed) ≤ Cost_optimal(original)
Because every valid path in the original is valid in the relaxed problem, the relaxed optimum is a lower bound.

8-Puzzle Relaxations

  • Allow any tile to move to any adjacent square: yields Manhattan distance h2.
  • Allow any tile to move to any square if blank: yields Gaschnig heuristic h_GASC.
  • Allow any tile to move anywhere: yields misplaced tiles h1.
Composite Heuristic:
h(n) = max(h1(n), h2(n), ..., hk(n))
The max of admissible heuristics is admissible and dominates every component.
Warning: Only combine admissible heuristics. If you add total costs of overlapping subproblems, you overestimate and break admissibility.

Pattern Databases

A pattern database (PDB) stores exact optimal costs for subproblem configurations found by backward search from the goal. The heuristic h_DB(n) is a lookup of the current state's subproblem pattern.

PDB Heuristic:
h_DB(n) = C*(pattern of state n)
C* is the optimal cost to solve the subproblem from the current configuration.

Disjoint Pattern Databases

When tile sets are disjoint, you can sum their PDB values because each move affects only one subproblem. This avoids double-counting.

Disjoint PDB:
h(n) = h_DB1(n) + h_DB2(n) + ...

For the 15-puzzle, disjoint PDBs reduce expanded nodes by factor of 1000. For 24-puzzle, reduction reaches about 1,000,000.

Landmark & Differential Heuristics

Landmark Heuristic h_L:
h_L(n) = min_L [ C*(n, L) + C*(L, goal) ]
Differential Heuristic h_DH:
h_DH(n) = max_L | C*(n, L) - C*(goal, L) |
Common Error: Do not sum PDBs of overlapping subproblems. Use disjoint sets or max composite instead.

Examples & Comparisons

Worked Example: Admissibility Checks

5x5 Grid from (1,1) to (5,5)

h1(x,y) = |5-x| + |5-y| (Manhattan). h1(1,1)=8 = true cost, so admissible, consistent, perfect.

h2(x,y) = 2 * (|5-x| + |5-y|). h2(1,1)=16 > 8. Inadmissible. Using h2 with A* may return suboptimal paths.

h3(n)=0. Trivially admissible but useless; A* becomes uniform-cost search.

Effective Branching Factor

Formula:
N + 1 = 1 + b* + (b*)^2 + ... + (b*)^d

For A* with h2 on the 8-puzzle, b* ≈ 1.3-1.4. For h1, b* ≈ 1.5. A well-designed heuristic keeps b* close to 1.

Worked Example: Weighted A*

Road Network from A to Z

Optimal cost C* = 450. Weighted A* uses f(n)=g(n)+W*h(n). With W=2, solution cost is between C* and 2*C* (450 to 900). Node expansion reduces roughly by factor of W.
