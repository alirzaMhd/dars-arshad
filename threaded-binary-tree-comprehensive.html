Threaded Binary Trees

Data Structures — Complete Guide for 20/20 Exam

Why Threaded Binary Trees?

In a standard binary tree with n nodes, there are n+1 NULL pointers (wasted space). A threaded binary tree replaces these NULL pointers with threads — pointers to the inorder predecessor or successor.

Pointer Count:
Total pointers: 2n (each node has left and right)
Non-NULL pointers: n - 1 (only parent-to-child)
NULL pointers: 2n - (n-1) = n + 1
These n+1 NULL pointers are wasted space. Threaded trees reuse them!
Thread Definition:
A thread is a pointer that links a node to its inorder predecessor or successor
Instead of NULL, we store a reference to the next/previous node in inorder traversal.
⚠ Threaded binary trees allow O(1) inorder traversal without a stack or recursion — just follow the threads!

Benefits of Threading

✓ Advantages

• No stack needed for traversal

• No recursion overhead

• Faster inorder traversal

• Better cache performance

✗ Disadvantages

• More complex node structure

• Insertion/deletion more complex

• Only useful for inorder traversal

Node Structure

Each node in a threaded binary tree has two boolean flags (Lthread and Rthread) to distinguish between normal pointers and threads.

Node Definition (Pascal):
type TTree = ^Node;
Node = record
  Lthread: boolean;
  Lchild: TTree;
  Data: integer;
  Rchild: TTree;
  Rthread: boolean;
end;
Node Definition (C/C++):
struct Node {
  bool Lthread;
  Node* Lchild;
  int data;
  Node* Rchild;
  bool Rthread;
};

Thread Rules

FlagValueMeaning
LthreadtrueLchild points to inorder PREDECESSOR
LthreadfalseLchild points to left child (normal)
RthreadtrueRchild points to inorder SUCCESSOR
RthreadfalseRchild points to right child (normal)
Example Threaded Tree (inorder: d b g e h a c f): a (Lthread=false, Rthread=false) / \ [d]←b→[g] [c]←→[f] / \ / \ d e nil f [nil] [h] [nil] | h Legend: [x] = thread pointing to x → = normal child pointer ← = thread (inorder link)
⚠ The first node in inorder (leftmost) has Lthread=true and Lchild points to a dummy/header node. The last node has Rthread=true and Rchild points to the header.

Inorder Traversal with Threads

The key advantage: no stack needed. Just follow threads to find the next node in inorder.

// Find inorder successor of node t function insucc(t: TTree): TTree; var temp: TTree; begin temp := t^.Rchild; if (t^.Rthread <> TRUE) then // If right child exists, go to leftmost node while (temp^.Lthread <> TRUE) do temp := temp^.Lchild; insucc := temp; end; // Full inorder traversal procedure inorder(root: TTree); var t: TTree; begin t := root; // Find leftmost node (first in inorder) while (t^.Lthread <> TRUE) do t := t^.Lchild; while (t <> NIL) do begin visit(t); t := insucc(t); // Follow thread or find successor end; end;
Complexity:
Time: O(n), Space: O(1)
O(n) time because each node is visited once. O(1) space because no stack is needed!
Trace: Inorder Traversal

For threaded tree with inorder: d b g e h a c f

Step-by-step:

1. Start at root 'a', go left to 'b', then left to 'd' (Lthread=true)

2. Visit 'd' → follow Rthread → go to 'b'

3. Visit 'b' → go right to 'e' (normal), then left to 'g'

4. Visit 'g' → follow Rthread → go to 'e'

5. Visit 'e' → follow Rthread → go to 'h'

6. Visit 'h' → follow Rthread → go to 'a'

7. Visit 'a' → go right to 'c' (normal), leftmost is 'c'

8. Visit 'c' → follow Rthread → go to 'f'

9. Visit 'f' → follow Rthread → NIL (end)

Preorder and Postorder Threading

Threading is not limited to inorder traversal. We can also thread trees for preorder and postorder traversals using the same principle.

Inorder Threading

• Lthread → predecessor in inorder

• Rthread → successor in inorder

• Traversal: LDR order

Preorder Threading

• Lthread → predecessor in preorder

• Rthread → successor in preorder

• Traversal: DLR order

Postorder Threading

• Lthread → predecessor in postorder

• Rthread → successor in postorder

• Traversal: LRD order

1. Visit 'a' → go left to 'b'

2. Visit 'b' → go left to 'd'

3. Visit 'd' → Rthread=true → follow to 'e'

4. Visit 'e' → Rthread=true → follow to 'c'

5. Visit 'c' → Rthread=true → follow to dummy → END

4. Visit 'b' → go right to 'c' (then leftmost)

5. Visit 'c' → Rthread=true → follow to 'a'

6. Visit 'a' → Rthread=true → follow to dummy → END

Result: d, e, b, c, a ✓

⚠ Note: Only ONE type of threading can be used at a time. A tree threaded for inorder cannot simultaneously be threaded for preorder.

insucc Equivalent for Preorder

// Find preorder successor of node t function presucc(t: TTree): TTree; var temp: TTree; begin if (t^.Lthread = FALSE) then // Left child exists, it's the preorder successor presucc := t^.Lchild else // Follow thread to successor presucc := t^.Rchild; end;

insucc Equivalent for Postorder

// Find postorder successor of node t function postsucc(t: TTree): TTree; var temp: TTree; begin if (t^.Rthread = FALSE) then // Right child exists, it's the postorder successor postsucc := t^.Rchild else // Follow thread to successor postsucc := t^.Lchild; end;

How to Thread a Binary Tree

Algorithm to thread a binary tree: 1. Perform inorder traversal 2. For each node with NULL left pointer: - Set Lthread = true - Set Lchild = inorder predecessor 3. For each node with NULL right pointer: - Set Rthread = true - Set Rchild = inorder successor
Threading Example
Original tree (inorder: d b e a c): a / \ b c / d \ e Step 1: Inorder = d, b, e, a, c Step 2: Thread NULL pointers: - d.left = NULL → thread to predecessor (none/dummy) - d.right = NULL → thread to successor (b) - e.left = NULL → thread to predecessor (b) - e.right = NULL → thread to successor (a) - c.left = NULL → thread to predecessor (a) - c.right = NULL → thread to successor (none/dummy)

Threading Algorithm (C/C++)

void inorderThread(Node* node, Node** prev) { if (node == NULL) return; inorderThread(node->left, prev); // Thread left pointer if NULL if (node->left == NULL) { node->Lthread = true; node->Lchild = *prev; } // Thread right pointer of previous if NULL if (*prev != NULL && (*prev)->right == NULL) { (*prev)->Rthread = true; (*prev)->right = node; } *prev = node; inorderThread(node->right, prev); }

2n (n left + n right)

n - 1

When to Use Threaded Trees

✓ Use When:

• Frequent inorder traversals

• Memory is limited

• No recursion desired

✗ Avoid When:

• Frequent insertions/deletions

• Need other traversals

• Simple implementation needed
