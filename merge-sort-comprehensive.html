Merge Sort Algorithm

A divide-and-conquer algorithm that divides the array into two halves, recursively sorts each half, then merges the sorted halves.

mergesort(A[L..U])
{
  if (L < U)
  {
    mid = ⌊(L + U)/2⌋;
    // Step 1: Sort first half
    mergesort(A[L..mid]);
    // Step 2: Sort second half
    mergesort(A[mid+1..U]);
    // Step 3: Merge the two halves
    merge(A[L..mid], A[mid+1..U]);
  }
}
Recurrence Relation:
T(n) = 2T(n/2) + Θ(n)
2T(n/2) = two recursive calls, Θ(n) = merge operation
Solution:
T(n) = Θ(n lg n)
Using Master Theorem or recursion tree method

The Merge Operation

Given two sorted lists D[1..m] and E[1..n], produce a single sorted list F[1..m+n].

merge(D[1..m], E[1..n])
{
  i = 1; j = 1; k = 1;
  while (i ≤ m and j ≤ n)
  {
    if (D[i] ≤ E[j])
      F[k++] = D[i++];
    else
      F[k++] = E[j++];
  }
  // Copy remaining elements
  while (i ≤ m) F[k++] = D[i++];
  while (j ≤ n) F[k++] = E[j++];
}

Comparisons in Merge

Minimum Comparisons

min(m, n)

When one list is exhausted early

Maximum Comparisons

m + n - 1

When elements alternate

Key Insight: For merging two sorted lists of sizes ⌊n/2⌋ and ⌈n/2⌉, we need between ⌊n/2⌋ and n-1 comparisons.

Worked Examples

Example 1: Sort A = [20, 10, 7, 15]

Step 1: Divide into [20, 10] and [7, 15]

Step 2: Sort [20, 10] → [10, 20]

Step 3: Sort [7, 15] → [7, 15]

Step 4: Merge [10, 20] and [7, 15]

• Compare 10 and 7 → take 7

• Compare 10 and 15 → take 10

• Compare 20 and 15 → take 15

• Copy 20

Result: [7, 10, 15, 20]

Example 2: Sort A = [38, 27, 43, 3, 9, 82, 10]

Call Stack Trace:

mergesort([38, 27, 43, 3, 9, 82, 10])

→ mergesort([38, 27, 43, 3]) + mergesort([9, 82, 10])

→ ... (continues dividing)

Final merges produce: [3, 9, 10, 27, 38, 43, 82]

Example 3: Merge D = [10, 20, 30, 40] and E = [15, 25, 35, 45]

Comparisons and steps:

1. Compare 10 vs 15 → take 10 (F = [10])

2. Compare 20 vs 15 → take 15 (F = [10, 15])

3. Compare 20 vs 25 → take 20 (F = [10, 15, 20])

4. Compare 30 vs 25 → take 25 (F = [10, 15, 20, 25])

5. Compare 30 vs 35 → take 30 (F = [10, 15, 20, 25, 30])

6. Compare 40 vs 35 → take 35 (F = [10, 15, 20, 25, 30, 35])

7. Compare 40 vs 45 → take 40 (F = [10, 15, 20, 25, 30, 35, 40])

8. Copy 45

Total comparisons: 7 = m + n - 1

Example 4: Merge D = [10, 20, 30, 40] and E = [6, 8, 9]

1. Compare 10 vs 6 → take 6

2. Compare 10 vs 8 → take 8

3. Compare 10 vs 9 → take 9

E is now empty, copy all of D

Total comparisons: 3 = min(m, n)

Example 5: Count merge calls for n=10

T(1) = 1 (base case, one call)

T(2) = 2T(1) + 1 = 3

T(3) = T(1) + T(2) + 1 = 1 + 3 + 1 = 5

T(5) = T(2) + T(3) + 1 = 3 + 5 + 1 = 9

T(10) = T(5) + T(5) + 1 = 9 + 9 + 1 = 19

Time Complexity Analysis

Recurrence Relation:
T(n) = 2T(n/2) + Θ(n)
Master Theorem: a=2, b=2, f(n)=n → Case 2 → T(n) = Θ(n lg n)

Number of Comparisons

Maximum Comparisons (Worst Case):
n lg n - n + 1 (when k=2)
For n=2^k, maximum comparisons = n·k - n + 1
Minimum Comparisons (Best Case):
n lg n - 2^k + 1
When already sorted, fewer comparisons needed

Number of Merge Calls

Total Merge Calls:
T(n) = 2T(⌊n/2⌋) + 1, T(1) = 1
For n elements, total merge operations = 2n - 1 (when n is power of 2)

Best Case

Time: Θ(n lg n)

Always divides in half

Average Case

Time: Θ(n lg n)

Same as worst case

Worst Case

Time: Θ(n lg n)

Guaranteed performance

Space

Space: O(n)

Needs auxiliary array for merge

Properties of Merge Sort

Stable

Yes

Maintains relative order of equal elements

In-Place

No

Requires O(n) auxiliary space

Adaptive

No

Always Θ(n lg n), doesn't benefit from sorted input

Online

No

Needs entire array before sorting

Advantages:

• Guaranteed Θ(n lg n) in all cases

• Stable sort - good for linked lists

• Good for external sorting (large files)

• Parallelizable - independent subproblems

Disadvantages:

• Not in-place - requires O(n) extra space

• Slightly slower than Quick Sort in practice

• Recursive implementation has overhead
