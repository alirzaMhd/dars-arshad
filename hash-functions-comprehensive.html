Properties of Good Hash Functions

A good hash function should have the following properties:

Uniformity

Each key should have equal probability of hashing to any of the m slots

Independence

Hash value of one key should not affect hash value of another key

Efficiency

Should be computable in O(1) time

Deterministic

Same key always produces same hash value

Ideal Property:
h should be "approximately uniform independent"
Each key has equal probability of mapping to any slot, independent of other keys' positions
A hash function must be independent of the keys' patterns. If keys are not random, we need a good hash function to distribute them uniformly.

Division Method

Formula:
h(k) = k mod m
Divide key k by table size m and take the remainder

Choosing m (Table Size)

1. m should NOT be a power of 2 (otherwise h(k) only depends on least significant bits)

2. m should be prime (ideally not close to power of 2)

3. m should not have small factors

If m = 2^p, then h(k) = k mod 2^p only uses the p rightmost bits of k. This is bad because it ignores most of the key's bits!
Example: Division Method

m = 7 (prime)

h(123) = 123 mod 7 = 4

h(456) = 456 mod 7 = 1

h(789) = 789 mod 7 = 5

Good distribution with prime m

Example: Bad Choice of m

m = 8 (power of 2)

h(10) = 10 mod 8 = 2

h(18) = 18 mod 8 = 2 (collision!)

h(26) = 26 mod 8 = 2 (collision!)

Only LSB matters, poor distribution

Multiplication Method

Formula:
h(k) = ⌊m(kA mod 1)⌋
A is a constant (0 < A < 1), often A ≈ 0.6180339887

How it Works

1. Multiply key k by constant A

2. Take fractional part (kA mod 1)

3. Multiply by m and take floor

Example: Multiplication Method

m = 1000, A = 0.6180339887

Key k = 12345

k × A = 12345 × 0.6180339887 = 7628.999...

Fractional part = 0.999...

h(k) = ⌊1000 × 0.999...⌋ = 999

h(12345) = 999

The value A ≈ (√5 - 1)/2 ≈ 0.6180339887 is recommended by Knuth. It works well for any m.

Mid-Square Method

Formula:
h(k) = middle digits of k²
Square the key, extract r middle digits (where m = 10^r)

Steps

1. Square the key: k²

2. If k² has d digits and we need r digits, extract from position ⌊(d-r)/2⌋ + 1

3. The extracted r digits form the hash value

Example: Mid-Square Hashing

Key k = 4321, m = 100 (need 2 digits)

k² = 4321² = 18671041

8 digits, need 2 middle digits

Extract from position 4: 67

h(4321) = 67

Example: Different Key

Key k = 1234, m = 100

k² = 1234² = 1522756

7 digits, extract middle 2: 22

h(1234) = 22

Example: Choosing Table Size (from textbook)

n = 2000 elements, want average of 3 probes for unsuccessful search

For chaining: α = n/m = 3, so m = 2000/3 ≈ 667

Choose m = 701 (first prime near 667)

m = 701 is good because it's prime and close to n/3

When to Use

• Keys are numbers with some pattern

• Square eliminates patterns in original key

• Works well when keys are not uniformly distributed

Folding Method

Formula:
h(k) = sum of parts of k
Split key into equal parts, add them together

Two Variants

Shift Folding:
h(k) = P₁ + P₂ + ... + Pₙ
Split key into parts, add them directly
Folding at Boundaries:
h(k) = P₁ + P₂(reversed) + P₃ + P₄(reversed) + ...
Reverse every other part before adding
Example: Shift Folding

Key k = 12320324111220

Split into 3-digit parts: 123, 203, 241, 112, 20

h(k) = 123 + 203 + 241 + 112 + 20 = 699

h(12320324111220) = 699

Example: Folding at Boundaries

Key k = 12320324111220

Split: 123, 203, 241, 112, 20

Reverse every other: 123, 302, 241, 211, 20

h(k) = 123 + 302 + 241 + 211 + 20 = 897

h(12320324111220) = 897

When to Use

• Keys are long numbers (e.g., phone numbers, SSN)

• Need to distribute digits evenly

• Folding at boundaries reduces patterns

Comparison & Examples

Method Formula Best For Weakness
Division k mod m General use, simple m must be chosen carefully
Multiplication ⌊m(kA mod 1)⌋ Any m, good distribution Requires floating point
Mid-Square middle of k² Keys with patterns More computation
Folding sum of parts Long numeric keys Part size affects quality
Example: Choosing a Hash Function

Scenario 1: Simple integer keys, small range → Division method

Scenario 2: Keys not known in advance → Multiplication method

Scenario 3: Keys are phone numbers → Folding method

Scenario 4: Keys have patterns → Mid-square method

Example: Complete Hash Table Setup

n = 2000 elements, want α ≤ 0.7

m ≥ 2000/0.7 ≈ 2857, choose m = 2857 (prime)

Hash function: h(k) = k mod 2857 (division method)

Good setup for 2000 elements

No hash function is perfect for all cases. Choose based on key characteristics and use case.
